# AstralRecord リソースパック指示

このディレクトリは Java Edition と Bedrock Edition のダメージ数値、アクションリング、アイテムモデル、専用GUIを管理します。配布対象の装備は `item-models.json`、GUI専用モデルは `gui-icons.json` に登録します。GUIの対応範囲は `GUI_COVERAGE.md`、原画と利用条件は `gui-source/README.md` を確認します。旧アイテム・旧バニラ GUI・旧音声アセットは保管用です。現行の Java 版コンテナ GUI の差し替え画像は `java-gui-native` に置き、配布対象を `scripts/gui-assets.ps1` で指定します。保管用のアセットはユーザーの明示指示がある場合に編集・配布します。新規の効果音は `assets/astralrecord/sounds.json` に登録します。

## 必ず確認する情報

アセット、モデル、メタデータを編集する前に、存在する場合は以下のファイルを確認してください。

- `resourcepack.config.json`
- `README.md`
- `../10_plugin/AstralRecord/pom.xml`
- `../10_plugin/AstralRecord/src/main/resources/plugin.yml`
- `../40_filebase/config.yml`

参照先の管理には `resourcepack.config.json` を使います。基本はこのディレクトリからの相対パスを優先してください。相対パスで解決できない環境では、`resourcepack.config.json` の `absolutePathOverrides` を確認してください。

## Minecraft バージョン

対象 Minecraft バージョンは `../10_plugin/AstralRecord/pom.xml` から判断します。

現在確認済みの値:

- `paper-api`: `1.21.11-R0.1-SNAPSHOT`
- Minecraft Java Edition: `1.21.11`
- Java リソースパック形式: `75.0` から `97.1`（Java `26.3` のクライアント）

`pom.xml` のバージョンが変わった場合は、`pack.mcmeta` の `min_format` と `max_format` も更新が必要か確認してください。

## リソースパックの範囲

- 独自アセットには `astralrecord` 名前空間を使う。
- `minecraft` 名前空間は、バニラアセットを意図的に上書きする場合だけ使う。
- ファイル名とディレクトリ名は小文字で統一する。
- フォント識別子、クライアントエンティティ識別子、プロパティは、プラグインと Geyser 拡張の定義に合わせる。
- ユーザーが明示的に求めた場合、または作業に必要な場合を除き、大きなバイナリアセットは追加しない。

## 両版対応の着手条件

- リソースパック、テクスチャ、モデル、GUI、アニメーションなどの新規作成・変更は、Java Edition（JE）と Bedrock Edition（BE）の両方で依頼の要件を満たすことを前提とする。要件を満たせる範囲で、版ごとに異なるアセット形式や表示方法を使ってよい。
- 制作前に既存のパック構成と対象バージョンを調べ、両版それぞれの配布、登録、表示、検証の方法を確認する。必要に応じて Geyser 連携も確認する。片方だけに修正が必要な場合も、もう一方で依頼の要件を満たすか確認する。
- いずれかの版で要件を満たす見通しが立たないなど、両版への対応が難しいと判断した場合は、読み取り専用の調査までで止め、アセットや設定の作成・変更に着手しない。影響する版、満たすのが難しい要件、その理由を整理する。両版で使える代替表現や仕様調整などの対応策を検討し、各案の見た目・機能への影響と必要な前提をユーザーに伝える。ユーザーと対応方針を決めるまで制作は保留する。

## 検証

構造を変更した後は、以下を確認してください。

- `pack.mcmeta` が有効な JSON であること。
- モデルファイルが有効な JSON であること。
- マスターとアイテム台帳の番号・素材が一致し、両版のモデル、テクスチャ、アニメーション参照が解決すること。
- `scripts/build-resourcepack.ps1` で `dist/AstralRecordResourcePack.zip` と `dist/AstralRecordResourcePack.mcpack` を作成できること。両アーカイブに旧アセットが含まれず、同じ入力で再生成した SHA-256 が一致すること。

### 描画の確認

動作を伴うモブ・ギミックは、両版で通常経路の状態遷移を確認する。ボスでは待機・移動・予兆・発動・復帰を時系列で比べ、該当する場合は被弾・無敵の入りと解除も確認する。専用モデルが表示されている接続では、元のエンティティの描画や発光輪郭が出ないことを確かめる。非対応パックの接続では代替表示を確認する。静止画や通信だけの確認は、実クライアントの動作確認と分けて記録する。

地面に沿う攻撃演出は、上からの視点と地面に近い水平視点の両方で確認する。実際の表示倍率を反映し、予兆中は高さのある境界から危険範囲と安全範囲を区別できること、発動中は代表フレームを通して立体形状の動きが読めることを両版で確かめる。

見た目を変更した場合は、AI が自身の実行環境で独立して再現できる方法で、変更対象を画像に出力して確認する。ユーザーのデスクトップや既存セッションの画面取得・操作など、コンピュータユースによる描画確認は行わない。

- テクスチャ・アイコン・GUI・HUD は、配布用 PNG や描画定義を使い、Python の画像処理やヘッドレス Chromium の Canvas で確認用 PNG を作る。用途に応じて実寸での視認性、透過、重なり、配置を確認する。既存の GUI アイコン・パネルには、[パックの README](README.md) にある生成スクリプトの `--check --preview <PNGパス>` を使う。
- 立体モデルやアニメーションは、独立したヘッドレス Chromium 上の Blockbench Web や、対象形式を読み込めるオフスクリーンレンダラーで PNG を出力する。対象の版・視点・表示状態ごとに形状、テクスチャ、向きを確認し、アニメーションは代表フレームを並べて確認する。
- 手持ちの武器・道具は、柄軸まわりの反転を拾うため、両版で握り位置、柄の軸、刃先や作業面の向きを個別に確認する。
- アイテムのインベントリとホットバーは、両版の配布パックが選ぶ表示を枠込みの実寸で比較し、絵柄の片寄り、輪郭、余白を確認する。
- 実クライアント固有の描画は、隔離環境で対象クライアントを起動し、対象シーンとフレームをスクリプトで再現・取得できる場合に確認する。

検証結果は、プレビュー、静的検査・パケット検査、実クライアントの描画に分けて記録する。描画は対象の版・表示状態、入力（編集元または配布データ）、再現方法、確認できた範囲を記録する。確認手段がない描画や表示状態は、理由とともに未確認として記録する。

### 装備の見た目の合格条件

- スロットの原画は Java 版の論理 16 px と統合版で使う表示寸法で確認する。部位や武器種が輪郭で分かり、開口、主素材、その装備を区別する意匠が順に読めること。所持品・装備欄・ホットバーの背景に重ね、隣に並ぶ同部位や同系統の品とも見比べる。防具のスロットには両版で共用する専用アイコンを使い、手持ちと着用のモデルには同じ素材と識別点を反映する。
- 着用防具は素体に装備し、単品と組み合わせた姿を正面・斜め・背面から確認する。頭は両目と頬の開口、胴は首元と肩、脚は腰と膝、足は靴口とつま先を見て、体の向きと各部位が読めること。明るい縁、宝石、紋章が複数部位で競合する場合は、主役となる部位を定め、他の面を同系統の素材色に戻す。明暗の異なる素体でも顔と輪郭の区別を確かめる。
- 着用防具の奥行きは素材に合わせて作る。金属や骨の当て板には傾いた面と接合部に落ちる影、革には厚い帯と沈んだ継ぎ目、布には立体の襞と暗い谷を付ける。Java 版は標準の装備面にこれらを描き、統合版は識別点となる当て板や留め具を着用骨に沿う立体にする。混成装備と関節を曲げた姿でも、開口と各部位の動きが読めることを確認する。
- 着用を改修したら、閲覧者の「防具表示」ONとOFFで本人と他プレイヤーの4部位を確認する。ONで当て板を含む着用全体が出て、OFFで素体が見えること。どちらの設定でも同じアイコンと手持ちを参照することを、パックと表示経路の両方で確かめる。
- 手持ちモデルでは武器の刃・弦・石などの主材と、握り・接合部の副材を斜めから見分けられること。細かな彫刻は広い面と影が読める範囲に絞り、握りや接合部の奥行きが分かる箇所へ置く。一人称は手の位置と画角を再現し、待機・使用中に先端と主材の面が画面内に入り、照準周辺に余白があることを確認する。
- 装備の一括改修では、各 ID のスロットと該当する手持ち・着用を旧版と同じ倍率・視点で見比べる。描画画像に加えて、各 ID の識別点、修正した問題、確認した状態を残す。
