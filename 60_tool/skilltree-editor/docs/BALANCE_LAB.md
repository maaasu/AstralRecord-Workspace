# 戦闘・育成・経済の統合バランス検証ラボ

既存マスターデータエディタの「比較・成長グラフ」→「統合バランスラボ」で使います。装備比較・クラス成長グラフ・マスターの編集と参照は、従来の画面を引き続き使います。別アプリ、DB、稼働Pluginへの接続はありません。

## 検証の流れ

1. 職業、プレイヤーLv、クラスLv、装備、スキルを指定します。装備の必要Lvと職業条件も検査します。
2. 敵マスターとレベル、seed、試行回数、戦闘の時間上限を設定します。最初は「冒険者・簡素な武器・ミッドガルドのグラスボアLv1」の基本ケースを使用できます。
3. 厳密モードで実行し、未対応の診断が出た場合は条件を見直します。近似モードを明示して実行した場合は、省略した効果と仮定を結果で確認してください。
4. 討伐率、DPS、経過時間、死亡・時間切れ、MP/ENG、攻撃別寄与を確認します。複数ビルドは同じ敵・試行seedで比較します。
5. 装備・スキルの詳細JSONは欄からフォーカスを外すと検証・反映します。不正または未確定の原稿が残る間は実行・条件保存・条件出力を停止します。スキルは職業の`usableSkills`とサーバーの対応状況で絞り、名前・ID検索で選びます。選択済み一覧の↑↓で優先順位を変更できます。絞り込みを変えても選択は保持され、詳細JSONの`skillIds`順でも変更できます。売却候補は折りたたみ内で検索します。
6. 「調整案」で保存済みマスターのコピーを選び、JSONを編集して追加します。再実行すると現行と調整案を同じ条件で比較します。変更したマスターパスとJSON Pointer、値の差を追えます。
7. ブラウザ保存、条件JSON、結果JSON、試行CSV、ビルド集計CSVで条件と結果を保管します。サーバーを再起動した後は条件JSONまたはブラウザ保存から再実行します。保存条件は1スロット、複数条件の保管にはJSONを使います。

編集中の未保存原稿はラボには入りません。保存済みマスターの現在値、またはラボへ明示的に追加した調整案を使います。調整案からマスターを保存する機能はありません。

## 再現性と識別情報

- マスターの全入力ファイルはパスとSHA-256をmanifestに記録し、その集合の`masterHash`を結果へ保存します。コメントのみの変更でも識別します。
- PluginのJava/Kotlinソースと設定のSHA-256を記録します。移植モデルは`astral-balance/1.0.0`として識別します。
- 入力条件、seed、各試行seed、近似モード、前提、診断、調整案hashを結果JSONに含めます。
- 先頭試行は指定seedをそのまま使います。後続seedは`BalanceLabRunner.TrialSeed`の固定整数混合で決めます。Pluginの`ThreadLocalRandom`と同じ乱数列という意味ではありません。
- 保存条件と現在のマスター、モデル、Pluginソースの指紋が異なる場合は警告します。過去のマスター自体を自動復元する機能はありません。再現には対応するGit revisionまたは保存したマスターが必要です。

結果の`scenario`は入力条件、`masterHash`と`manifest`は実際に計算した入力です。元の識別情報が一致しない再実行では、警告と実際の識別情報を確認してください。

## 計算の境界

固定距離・停止・射程内・単独プレイヤー対単独Mobの条件実験です。20tick/秒で進めます。地形、移動、ノックバック後の距離、操作による回避、AIの判断、ネットワーク遅延、Paperの実負荷を完全再現しません。時刻が同じイベントの処理順序もモデルの契約です。

Plugin計算はJava/Kotlin、ラボはC#です。計算式を言語差を無視して共通化していません。戦闘の純計算・丸め・境界・tick処理は、テスト用JavaハーネスがPlugin実クラスから取得した固定期待値で照合します。固定ケースの通過は全ての戦闘条件や実サーバーでの実測一致を保証しません。

スキル、装備個体値、エンチャント、ルーン、セット、超越、バフなどの対応単位と入力形式は[戦闘モデルとPlugin照合](../tests/plugin-parity/README.md)を参照してください。未対応の効果を正確に再現した結果として表示しません。厳密モードでは実行を止め、近似モードでは省略した効果を診断へ残します。

`baseStats`の明示上書きや敵の攻撃間隔指定は実験の設定値です。プレイヤーデータの実測値ではありません。装備の乱数を平均値で置く場合も近似として識別します。

## 統計の読み方

- 平均DPSと平均経過時間は、討伐・死亡・時間切れを含む全ての有効試行を分母にします。
- 無効・未対応は正常な戦闘として平均へ入れず、件数を別表示します。全て無効なら平均と討伐率は未算出です。
- 経過時間は終了までの時間です。死亡が早ければ経過時間も短くなるため、その短さを強さと解釈しないでください。
- 討伐時間の中央値・90%点は、死亡・時間切れを無限時間として計算します。必要割合が討伐していなければ未到達です。
- 偶数件の中央値は中央2値の平均、90%点はnearest rank、DPSの標準偏差は母標準偏差です。
- HP/MP/ENG/シールドの曲線は、成功失敗を選別せず第1試行を表示します。最大301点に間引きます。全試行の成績と枯渇時刻は残します。

総合点による自動順位や自動最適化はありません。差分表の数値、攻撃別寄与、適用ステータス、マスター変更箇所を併せて判断します。

## 収集・強化・育成・Gold

[経済モデルの対応範囲と根拠](BALANCE_ECONOMY.md)を参照してください。ドロップはPluginの独立抽選と`pick`の間引き、強化は実在するオーブの成功率と失敗時遷移を扱います。レシピ記載だけで実行経路のない制作を、到達可能な経路として補完しません。

目標個数までの期待戦闘数、中央値、90%点を表示します。死亡・未討伐を含む討伐率を入れ、経験値やドロップを毎試行必ず得たものとして扱いません。期待値・分布の算出上限を超えた場合は診断します。

Goldは計算に含めた入金・支出を内訳に残します。素材、オーブ、装備の市場価格や未指定のショップ価格を架空の値で補いません。強化にGoldを直接消費しない経路でも、オーブ調達が無料という意味ではありません。

戦闘時間、移動時間、待機時間、補給時間を分けます。入力した討伐秒数は設定値、戦闘シミュレーションから得た秒数は推定値です。実測値を自動取得していません。異なる複数素材の同時ドロップ相関、ショップや別の敵を含む経路全体の最適化は対応範囲に含みません。

## 負荷とキャンセル

サーバープロセス当たり同時実行は1件です。最大4ビルド、500試行、1戦600秒、全体200万tick以内、実時間30秒までに制限します。上限は`catalog.limits`でも返します。条件が上限を超える場合は実行前に拒否します。

実行はHTTP処理と画面描画から分離しています。画面は進捗を取得でき、キャンセル要求で計算を止められます。キャンセルや実時間切れの部分試行を全体の成績として返しません。結果はメモリ上の直近8件、1結果16MBまでです。永続保管にはJSON/CSVを使用してください。タブ移動中もラボを保持し、リロード時はsessionStorageの実行IDから追跡を復旧します。一時的な通信失敗は再試行し、サーバー再起動等でIDが404になった場合は条件から再実行します。

## APIと所有権

| API | 用途 |
|---|---|
| `GET /api/balance-lab/catalog` | 既存parserで読み取ったマスター、指紋、診断、上限 |
| `POST /api/balance-lab/jobs` | JSON条件を渡して実験を開始（202） |
| `GET /api/balance-lab/jobs/{id}` | 進捗・状態・完了結果 |
| `DELETE /api/balance-lab/jobs/{id}` | 計算キャンセル |

`DELETE`が消すのはマスターではなく計算の継続です。これらのAPIは既存のloopback/Origin境界を通ります。`BalanceLabCatalog`は既存の`MasterDataService`/`MasterDataPaths`を読み取り専用で使い、保存・削除・バックアップを呼びません。`ApplyProposal`もメモリのdeep cloneだけを扱います。

## 保守と追加効果

1. Pluginの実処理、呼出元、マスター読込と既定値を追跡します。YAMLの名前だけから式を推測しません。
2. `BalanceCombat`/`BalanceEconomy`の対応判定を先に追加します。未対応を黙って0へ変換するfallbackは追加しません。
3. Javaハーネスへ実処理を呼ぶ入力ケースを追加し、期待値と追跡ソース指紋を更新します。ラボ側とテスト側へ同じ式をコピーした自己照合は使いません。
4. 丸め、上下限、適用順、tick境界、参照切れ、装備不可、到達不能、seed固定の再現性を検査します。確率の固定入力照合と分布の検査は分けます。
5. Clientはサーバーの計算結果を表示します。装備・成長の既存純表示関数、Minecraft表記、マスターの識別情報を再利用し、戦闘式をClientへ再実装しません。
6. この文書と照合READMEの対応表、モデル版を更新します。実測していない部分は未検証と記載します。

Plugin本体、マスターデータの契約、配置先はこの機能のために変更していません。マスターの自動最適化・自動更新・本番反映は対象外です。

## 起動と検証

通常の起動は `60_tool/05-master-data-editor.bat` です。作業ツリーでの確認は次のとおりです。

```powershell
cd <workspace>/60_tool/skilltree-editor/src/SkillTreeEditor.Client
npm ci
npm run lint
npm test -- --maxWorkers=1
npm run build
cd ../..
dotnet test SkillTreeEditor.slnx
dotnet build SkillTreeEditor.slnx
dotnet run --project src/SkillTreeEditor.Server --no-launch-profile -- --Kestrel:Endpoints:Http:Url=http://127.0.0.1:5291 --SkillTreeEditor:WorkspaceRoot=<workspace>
```

ブラウザで `http://127.0.0.1:5291` を開きます。実サーバー、実DB、プレイヤーデータを使った検証は行いません。実サーバーの実測値との照合は未検証です。
