# AstralRecord Master Data Editor

Filebase の YAML / JSON マスターと、スキルツリーのノード・配置・接続構造、Plugin の表示設定を編集する開発者専用ローカル Web アプリです。日本語フォーム、原稿編集、装備比較、クラス成長グラフを同じアプリで使えます。`30_web` には依存せず、ASP.NET Core がワークスペース内のファイルを直接扱います。起動入口は `05-master-data-editor.bat`、フロントエンドのビルド入口は `06-master-data-editor-build.bat` です。実装ディレクトリ・プロジェクト名・配置先は `skilltree-editor` のままです。

## 画面共通の操作

上部のナビゲーションから「マスターデータ」「スキルツリー」「比較・成長グラフ」「ワールド配置・編集」を切り替えます。選択中の画面は青緑の背景と下線、未保存のある画面は `●` で表示します。画面切替でも編集中の値を保持し、未保存内容がある場合は確認します。幅に応じてナビゲーションと操作を折り返し、ページ全体を横へはみ出させずに利用できます。

画面の見出し、暗色のパネル、入力欄、主要な保存操作、フォーカス表示は共通の色・余白・文字サイズを使います。マスターデータは編集モード・履歴・確認と保存をグループ別に配置し、ファイルの複製・書出・参照・再読込・削除は編集内容の上にまとめます。ファイル未選択時は、検索から編集、差分・検証・保存までの手順を表示します。

## 管理対象

ワールド配置の編集には「元に戻す」「やり直す」と保存前の変更件数を用意しています。「変更内容を確認」で表示条件外も含む追加・変更・削除の前後値を50件ずつ確認し、1配置だけを保存前へ戻せます。未確定の数値入力は比較に含めず、入力中の個別取消を停止して保持します。座標の空欄を0に変換せず、入力途中の値を保持します。一括選択は表示条件に合う全件の追加選択・全解除と、条件外を含む選択だけの一覧確認に対応します。合計と表示条件内外の件数を示し、有効・無効への一括変更を1操作で戻せます。条件外を含む有効状態変更とすべての削除は、専用の確認画面で合計・条件内外の件数、名前・実レベル・座標・ID・ワールド・変更後の状態を50件ずつ確認します。キャンセル・Escapeでは編集内容と選択を保持し、確認中に対象の前提が変わると実行を停止します。大量配置の一覧は50件ずつ表示し、地図には条件に合う全件を表示します。一覧は標準順、開始地点からの水平直線距離順、出現レベルの低い順・高い順、日本語名順に切り替えられます。検索条件の一括解除は検索・種類・有効状態・地域・スポナーマスター・レベル上下限だけを戻し、一括選択、編集中の原稿、並び順を保持します。詳細地形の取得は拡大時まで遅らせ、同じAI配置案は画面の往復でも再利用します。

「ワールド配置・編集」は保存済み Dev 配置の編集を既定で開きます。地図上のスポナー・NPC・道標を選択し、地図の横に表示するフォームで追加・編集・削除できます。スポナーの出現範囲は初期ONで、地図に表示中の全件を同時に表示し、Dev・AI両モードから表示を切り替えられます。円を色ごとにまとめ、地図描画をキャッシュして、大量配置のホバー時の再描画を抑えます。既定ONの「重複・未カバーを色で確認」で、安全な足場を含む測定済み陸地区画の中心点を0件・1件・2件以上で色分けします。Devの有効な表示対象とAI案は別々に計数し、未測定の地形や未取得の配置を未カバーと断定しません。追加前に日本語名でマスターを選択し、安全な地点をクリックします。「AI 配置案」ではコピーしたワールドの全域解析から作った地域別のモブ・レベル・スポナー配置案を閲覧できます。地形、推奨レベル、未配置理由の地図、32/48/64mの出現半径比較、地点詳細、提案JSONの保存に対応します。既存の配置は計算に使いません。共有マスタの公開は行いません。準備方法と判定の範囲は [ワールド配置計画](docs/SPAWNER_PLANNING.md) を参照してください。

## Filebase マスターの編集

釣りマスターは「釣り魚」「釣りエリア」「釣りルール」のカテゴリから編集します。新規作成では各カテゴリの JSON Schema から必須項目を生成できます。`worldId`・`rulesId`・`fishId`・釣果アイテムは日本語名付きの参照候補から選択できます。エリアの魚候補一覧には確率合計を表示し、保存前に合計 100%（許容差 0.000001）、同じレベル帯内の魚重複、両端を含むレベル帯の重複、同じワールドの有効なエリア重複を検証します。釣りレベルは釣り竿の `FISHING_LEVEL` を使用し、エリアに座標指定はありません。

上部の「マスターデータ」で、アイテム、クラス、スキル、モブ、スポナー、採集、ショップ、クエスト、ワールド、バフ、ドロップ報酬、レシピ、共有カタログなどのファイルを選びます。「スキルツリー」へ切り替えると従来のキャンバス編集を使えます。切替時も編集中の内容は保持されます。

- ファイル検索欄で下矢印またはEnterを押すと結果へ移動します。結果内は上下・Home・Endで移動し、Enterで開き、Escapeで検索欄へ戻れます。選択フォルダの検索が0件なら、同じ検索語と条件でFilebase全体へ範囲を広げられます。検索クリア後は検索欄へフォーカスを戻します。
- フォーム内検索も下矢印・Enterで結果へ移動し、上下・Home・End・Escapeで操作できます。日本語入力の変換中はこれらの移動を実行しません。検索結果、セクション、パンくずや設定カードから移動すると、移動先の入力欄または見出しへフォーカスを移します。入力途中の不正な数値があるときは従来どおり階層移動を止めます。
- フォーム内検索は100件ずつページを切り替えて全結果を確認できます。ページ切替後は先頭の結果へフォーカスを移し、検索語・原稿・定義が変わると先頭ページへ戻ります。検索結果は入力欄の上下の空きに合わせて表示し、検証欄などに隠れずスクロールできます。検索中は原稿・項目定義・Schemaから準備した検索用の名前と値を再利用し、検索語の変更やページ切替だけでは全項目を解析し直しません。原稿や定義の更新時には再解析します。
- 保存中は原稿の準備・検証・書込みの進行を表示し、Ctrl+Sの連打による重複保存を防ぎます。変更がなければCtrl+Sで再保存しません。検証失敗時はフォームの最初の問題箇所へ移動し、未存在の必須項目や原稿モードのエラーは検証結果へフォーカスを移します。失敗しても入力内容は保持され、修正や再試行ができます。
- 検証結果はエラー・警告の総数を常に表示し、種別とメッセージ・パス・コード・ファイル名の空白区切りAND検索で絞り込めます。入力途中の数値エラーも含め、一覧は50件ずつ描画します。検索・ページ操作を残して結果だけスクロールでき、パスから問題の項目へ移動します。検索欄の下矢印・Enter、結果内の上下・Home・End・Escapeで操作できます。検証結果や入力エラーが更新されたら条件とページを初期化して新しい問題を表示し、タブ切替では条件を保持します。軽量化の対象は結果の描画で、サーバー側の検証や結果全件の検索は省略しません。
- 画面はフォルダツリー、検索・結果一覧、編集内容の3列です。フォルダと結果は独立してスクロールし、検索範囲と件数を一覧の直上に表示します。ツリーはフォルダアイコン、採番、階層線、配下の件数を表示します。矢印部分は開閉、名前は選択です。上下キーで移動、左右キーで開閉、Home / End、Enter / Spaceで選択できます。カテゴリ定義のない中間フォルダは開閉専用です。
- 起動時は「アイテム共通」を選択し、親カテゴリの一覧には子フォルダも含めます。独立したセット効果定義はアイテム一覧から除きます。名前 / ID / パスを検索でき、空白区切りの複数語は各語がいずれかの項目に一致するAND検索です。「検索範囲」で選択フォルダ以下と Filebase 全体を切り替えます。最初の50件を表示し、「さらに表示」または一覧末尾へのスクロールで続きを追加します。フォルダ展開、検索、条件、一覧のスクロールはファイルのタブ切替でも保持します。
- ファイルを開くと上部にタブを追加します。開いているファイルをもう一度選ぶと、そのタブへ切り替えます。幅1100px以下では一覧から既存タブを選び直した場合もナビを閉じ、編集中の内容へ戻ります。フォーム・原稿の編集内容、入力途中の数値、Undo / Redo、選択した階層と検証結果はファイルごとに保持します。未保存のタブには `●` を表示し、タブを閉じるときは未保存内容の破棄を確認します。タブ列の左右矢印・Home・Endでも切り替えられます。新規作成・複製したファイルも新しいタブで開きます。
- アイテムの一覧では、名前・ID・パスで検索したモブまたは採集オブジェクトをドロップ元に指定できます。空白区切りの複数語は各語がいずれかの項目に一致するAND検索です。直接ドロップ、モブのレベル別ドロップ、共通のルートテーブル・プール経由のアイテムを、選択中のアイテムカテゴリ内で絞り込みます。スキルの一覧は共有タグでさらに絞り込めます。
- モブ・採集の一覧では「ドロップ品で絞り込み」でアイテム名・IDを検索し、ドロップするアイテムを選べます。空白区切りの複数語は各語が名前またはIDに一致するAND検索です。レベル別・共通ルートテーブル経由も対象です。「アイテムドロップの有無」は、この索引で検出したアイテムの有無で判定し、お金のみのドロップは「なし」とします。
- 「詳細フィルター」は専用ダイアログで、レベル・数値、種類・分類、取引・装備、タグ・ワールド・動作、ドロップ、ファイルの条件をグループ別に設定します。現在の対象ファイルに存在する条件だけを表示します。該当件数を確認し、「条件を適用」で一覧へ反映します。キャンセル・Escapeは変更を破棄し、適用済み条件を維持します。条件はANDで併用し、適用後の一覧上部で個別に解除、または「すべて解除」できます。
- 詳細フィルターのドロップ品候補は、候補欄と対象IDがある場合に、対象ファイル・索引・参照候補の更新時にIDと表示名を準備し、Minecraftの色・装飾コードを除いた表示名で日本語順に並べます。同名は索引の順序を保ち、候補検索中は準備済み一覧を再利用します。ドロップ元・ドロップ品・共有タグなどの候補と適用済み条件にも装飾コードを除いた名前を表示し、名前が空ならIDまたはパスを表示します。ドロップ元候補は索引全体から探し、検索語に合わない選択済み候補も残します。候補検索語だけの変更では該当件数を数え直さず、条件や一覧・索引が更新されると再計算します。
- モブは基礎 `level` と `levels[].level` の実値のいずれかが指定範囲内なら一致します。例えば定義レベルが1と20だけのモブは5〜15に一致しません。アイテムはトレード禁止（`unTradeable`）・売却禁止、装備の必要レベル、必要クラス、利き手、装備タグ、セット、売却額、最大スタック、初期の強化上限・エンチャント枠・耐久上限を指定できます。必要レベル未指定の装備は0として扱い、装備以外に必要レベル0を推定しません。初期条件は超越後の上書きや個体ごとの能力を含みません。
- 種別、共有タグ、レアリティ、装備スロット、エンティティ種別、クラス役割、必要な道具タグ、ワールド・ワールド種別、有効・無効、パッシブ設定、ファイル状態（編集可能・閲覧のみ・解析エラーあり）も指定できます。「パッシブ設定」はスキルの `passive` オブジェクトの有無です。
- カテゴリ変更・一覧再読込で存在しなくなった候補は解除します。ダイアログの設定途中に索引やファイルが変わり条件が無効になった場合は、適用を止めて再設定を案内します。索引を取得できない場合は索引を使う条件を解除し、一覧検索・形式・ファイル状態は継続して利用できます。検索対象は保存済みファイルで、編集中の未保存値は含めません。
- 一覧・タブ・見出し・参照候補は、空でない `displayName` → `name` → `title` の順で名前を表示します。ファイル名のバージョン接頭辞と拡張子を除いた部分がIDと一致する場合はIDの重複行を省略します。ファイル名とホバー時のフルパス・IDは確認できます。日本語名でも一覧を検索できます。
- 「日本語フォーム」は短い項目を編集領域の幅に合わせて横並びに表示します。左ペインはファイルを開いた後も一覧を表示し、カテゴリや検索を維持します。右上の「×」で閉じ、「ナビを表示」で戻せます。幅1100px以下ではファイルを開くとナビを閉じます。幅680px以下では「フォルダ」「ファイル・検索結果」を切り替えて使います。
- 編集領域上部の日本語セクションから Map / 配列へ直接切り替え、深い階層はパンくずで戻れます。基本情報の設定カードは全体を押して詳細へ移動できます。深い階層でも入力欄の幅は変わりません。「フォーム内検索」は日本語名・キー・値を検索し、結果から該当項目へ移動します。同じファイルを開き直すと、このアプリ内で最後に選んだ有効な階層を復元します。
- 定義書の項目名・型・必須条件と元のキーを併記します。ステータスの値とMapのキー、タグ、既知の列挙値は日本語名と元のIDを表示し、フォーム内検索も日本語名に対応します。保存するIDや未知の値は元のままです。短い説明と型変更・削除はカード内に表示し、長い説明・候補・参照元・定義書の開閉には対象名を付けます。定義済み任意項目や自由形式のキーは、各Mapの対象名付きの「項目を追加」から追加できます。
- 定義書で `challenge.entryLocation.x/y/z` や `yaw/pitch` のように同じ階層の項目をまとめた表記は、各キーへ展開してフォームと検証に使用します。座標は `x`・`y`・`z` ごとに数値型と必須条件を検証します。
- `lore` のような文字列配列は大きな入力欄で編集でき、1行をYAMLの1要素として保存します。文字列型の `description` は改行を含めても1つの文字列として保存します。装飾コード付きの文章と `color: #RRGGBB` には編集中のプレビューを表示します。
- オブジェクトの配列は要約と操作を表示し、25件ずつ一覧から選択した要素を編集します。追加・削除・複製・順序変更に対応します。配列要素内でUndo / Redoした場合は、位置変更後の別要素を誤編集しないよう配列の一覧へ戻ります。
- `implementationId`、RPC、固有 `params` のキーや参照 ID は元の表記で扱います。フォームで未定義のキーも保持し、「原稿 YAML / JSON」でコメントを含む全原稿を編集できます。元のYAMLの解析に失敗していても、原稿から修復できます。
- 「＋ 新規」は既存ファイルの原稿テンプレート、JSON Schema の必須項目生成、直接入力から作成します。「原稿を読込」でローカルのファイルを編集中の原稿または新規ファイルへ取り込めます。読込だけでは保存しません。
- 新規・複製・取込ダイアログの未保存原稿も、ページ再読込・終了時の確認対象です。キャンセル時や編集中の原稿をカテゴリ・テンプレート・Schema生成で置き換えるときは破棄を確認します。画面やタブの切替では原稿を保持します。Schema生成中は入力と作成をロックし、キャンセル後に届いた応答は破棄します。生成に失敗した場合は原稿を保持して再試行できます。
- 「保存済みファイルを複製」は保存済み原稿を新規ファイルの下書きにします。アイテムはID・ファイル名を自動採番でき、他のマスターは原稿内のIDと保存先を新しいものへ変更してから作成します。同じIDや保存先への作成は検証で拒否します。
- アイテムは `10.material` / `20.equipment` などのカテゴリに合わせて ID と `v<schemaVersion>.<id>.<slug>.yml` を自動生成します。通常の英字は `a` から繰り上げ、`z` はデバッグ用として別に指定します。クラスは `schemaVersion` / `order` / `id` からファイル名を生成できます。採番と保存先は作成成功時に確定します。

## 装備比較とクラス成長グラフ

同じ分析画面の「統合バランスラボ」で、職業・装備・スキル・敵を選び、seed付き戦闘試行、リソース推移、収集・強化・育成・Goldの試算、複数ビルドと隔離した調整案の比較を行えます。条件保存・再実行・JSON/CSV出力にも対応します。計算の対応範囲、未対応効果の停止、Plugin実処理との照合、負荷上限は [統合バランスラボ](docs/BALANCE_LAB.md) を参照してください。

「比較・成長グラフ」は保存済みマスターを使います。マスター変更後は「マスター再読込」で反映します。

装備の絞込・並び順と成長グラフは、それぞれの計算に関係する条件が変わるまで再利用します。確認Lvの移動は数値表だけを更新し、UUIDなど次回計算用の入力や別タブの検索では既存の成長グラフを再計算しません。「グラフを計算」で新しい結果を受け取った場合や、マスター再読込後の計算では更新します。

条件と結果を左右に並べ、幅が狭い場合は縦に並べます。計算方法と前提は必要に応じて開閉できます。比較表はフォーカスしてキーボードで横へスクロールでき、分析の種類のタブは左右矢印・Home・Endで移動できます。

- 「装備を比較」は要求プレイヤーLvの中心と前後幅、スロット、装備タグ、名前 / IDで絞り、下限〜上限の比較表とステータスの棒グラフを表示します。チェックした装備だけの比較とCSV出力に対応します。
- 強化Lvの差分を累積し、Plugin と同じく FLAT は加算、基礎 SCALAR は最後の定義を採用します。累積した強化 SCALAR があれば基礎 SCALAR を上書きし、FLAT に乗算します。SCALARだけのステータスは補正を持ちません。個体の乱数、エンチャント、ルーン、セット、超越、装備可否は比較計算に含めません。
- 「クラス成長」はアカウントUUID、開始プレイヤーLv、開始クラスLv、表示上限、比較する職業（最大12件）を指定して計算します。プレイヤーLvに対するクラスLv・累積クラスEXP・クラスのステータス補正を切り替え、指定Lvの数値表とCSVも確認できます。
- プレイヤー必要経験値のUUID由来の差、クラスの `expRate` / `maxLevel`、`baseStats` / `growthPerLevel` を反映します。通常育成・転生なし、開始Lv到達直後から同じEXPをプレイヤーと1職へ加算する仮定です。職業ごとの線は独立した育成シナリオで、転職条件や過去の育成履歴を含みません。「計算の根拠と前提」で式とPluginソースの対応を確認できます。

## 保存とバックアップ

- マスターの原稿保存は入力したキー順・コメント・改行を保持してUTF-8（BOMなし）で保存します。同内容は書き換えません。更新・削除前の原稿は `.backups/master-data/` へ保存します。
- YAMLフォームで構造が変わらず値だけを変更した場合は、元の原稿へ値を反映してコメント・順序・改行を保持します。キーや配列要素の追加などで全体を再生成する場合は、元のコメントを先頭へ移したことを画面に警告します。差分を確認し、コメントの位置を維持したい場合は原稿で編集してください。
- Filebase マスター画面の更新・削除は読込時のSHA-256 revisionを照合します。他のエディタや外部編集による変更があれば409で拒否するので、再読込して差分を確認してください。画面の複製は読込時の保存済み原稿から編集可能な新規原稿を作成するため、複製元を再読込してから実行すると最新の内容を使えます。workspace共通の排他と同一ディレクトリへの原子的なファイル置換を使用します。
- スキルツリーの既存ノード・構造・Plugin設定も読込時の版を確認します。GET / 作成 / 更新はETag、ノード・構造一覧はrevisionを返し、既存更新とノード削除にはIf-Matchが必須です。版がない、または別のエディタ・外部操作で変更された場合は日本語の409で拒否し、画面の編集原稿を保持します。再読込してから編集し直す場合は必要な原稿を先に書き出してください。
- 構造の検証・保存の待機中は配置・構造切替・履歴・自動配置を停止し、保存応答で後続の編集を失わないようにします。インスペクターの座標・ポイント、ノードフォームの数値、Plugin設定の中心座標を数値として読み取れない間はその入力を保持し、保存を停止します。配置座標は0.1単位・32bit範囲を満たす値をEnterまたはフォーカス移動で確定し、暗黙の丸め・クランプは行いません。インスペクターの未保存入力もノード変更・構造切替・詳細ペインを閉じる・再読込・終了時に保護します。
- スキルツリー画面で保存するJSONはノード・構造・配置・edge・effect・採番メタデータごとの固定された意味順にキーを並べ、未知の追加キーは辞書順に安定化します。UTF-8（BOMなし）、2スペースインデント、LF、末尾改行ありです。同一内容の再保存はファイルを書き換えません。
- node / structure / Plugin設定の更新はworkspace共通の排他内で再読込・検証・保存するため、並行リクエストや複数Editorプロセスがノード削除と構造保存を競合させても未知nodeId参照を正本へ残しません。
- 既存JSON、削除対象JSON、`config.yml` は変更前に `.backups/<category>/<filename>.<timestamp>.bak` へコピーします。
- nodeId採番時はWindows/Linux共通のファイル排他内でhigh-waterと既存ノードを再読込し、`node-id-sequence.json` を `.backups/node-id-sequence/` へ退避してから原子的にhigh-waterを進め、その後ノードJSONを作成します。複数Editorプロセスから同じworkspaceを開いてもhigh-waterを巻き戻しません。
- 一時ファイルを同一ディレクトリへ書いてから置換するため、書込み途中のファイルを正本にしません。
- `.backups/` はGit管理対象外です。不要になったバックアップは手動で削除してください。
- ワークスペース配下のシンボリックリンク・junctionを通じた読取・保存・削除・バックアップ・ロック・アイコンキャッシュ操作を拒否します。通常のGit worktreeは使用できます。
- `config.yml` は管理対象キーが欠けていても不足キーだけを追加し、既存の改行コード、コメント、未知のskilltree設定、他のトップレベル設定を維持し、`skilltree:` 内の管理対象値だけを更新します。`worldName` にYAMLで使用できない制御文字は保存できません。
- 設定画面が更新するのはリポジトリ上の `10_plugin/AstralRecord/src/main/resources/config.yml` です。稼働環境の `plugins/AstralRecord/config.yml` と filebase へデプロイまたは同期した後、サーバーで `/masterdata reload` を実行してください。このツールは稼働サーバーへ直接書き込みません。

## 操作メモ

- 未配置ノードを左ペインからキャンバスへドラッグして配置します。一覧の「配置」からX / Y / Zを指定して配置する操作もあり、一覧とキャンバスを同時に表示しない狭幅画面やキーボード操作でも使えます。座標は0.1単位・32bit範囲、同じnodeIdや同じ座標の重複を拒否し、配置はUndo / Redoの対象です。構造JSONへの書込みには従来どおり保存が必要です。未配置・配置済みの空の一覧は必要な高さだけを使います。
- キャンバスの空白を左ドラッグすると画面を移動します。Shiftを押しながら空白をドラッグすると範囲選択になります。
- キャンバスとノード一覧には、マスターの `icon` に指定したBukkit Materialの画像と、Minecraft装飾コードを除いた名前を表示します。タグは共有カタログの日本語名・説明、ステータス効果は日本語名と値、スキル効果は日本語名と種別をノードのホバー情報へ表示し、ノード一覧と詳細には概要も直接表示します。
- キャンバスでノードを選択すると、右側でX/Y/Z、名前、Material、ポイント、タグを直接編集できます。Effects、Schema、Raw JSONは「Effects・Schema・Raw JSONを編集」から編集します。
- ノード編集画面の「複製して新規作成」では、編集中の内容をすべて引き継ぎ、nodeIdだけを保存時に自動採番したノードを作成できます。基本ステータスなど、同一定義を複数ノードで使う場合に利用します。
- ノード一覧・ホバー・詳細には、ステータス効果などに加えてCP/PPの消費種別と消費量を色分けして表示します。`unlockCondition.classId` があるノードは、クラスマスターの表示名を使って `CP[クラス名] コスト` 形式で表示します。
- キャンバス上のノードを右クリックすると、マスター編集、ROOT設定、nodeIdコピー、接続削除、配置削除を選べます。複数選択中の配置削除にも対応します。
- ノードのハンドル間をドラッグしてedgeを追加します。
- Shift / Ctrl / Cmdで複数選択、Deleteで配置またはedgeを削除します。
- 構造選択とUndo / Redo・保存は上段、表示パネルと自動配置・表示設定・再読込はその下にまとめます。ヘッダーの「一覧」「キャンバス」「詳細」で各ペインを表示・非表示にでき、最後の1ペインは閉じられません。ペイン間の境界をドラッグすると幅を変更でき、境界のダブルクリックで初期幅へ戻ります。幅1150px以下では「ノード一覧」「キャンバス」「詳細・検証」を同じ領域で切り替えます。この切替ではペインを作り直さないため、インスペクターの入力途中の値を保持します。広い画面で閉じたペインもこの切替から表示できます。
- 「ゲーム内表示シミュレーション」を有効にすると、現在の職業とプレイヤーレベルを指定して、`unlockCondition` を満たすノードだけを一覧・キャンバスへ表示します。クラス条件は現在職から filebase の転職前提を再帰的に辿り、祖先職も成立扱いにします。edge は両端ノードが表示対象の場合だけ表示します。
- 表示シミュレーションの条件とノードサイズはキャンバスの実際の幅に合わせて折り返します。ペインの幅を手動変更した場合も操作を表示します。
- キャンバス上部の「ノードサイズ」で32～140pxへ変更できます。設定はブラウザのlocalStorageへ保持し、構造JSONの1ブロック単位座標には影響しません。72px未満では名前とコストを省略し、ホバーで詳細を確認します。
- Ctrl+Z / Ctrl+Y、またはヘッダーのボタンでUndo / Redoします。
- 「補助自動配置」はrootからのBFSレイヤー配置をX/Zへ明示反映します。通常の編集履歴に入るためUndoでき、結果は保存時に構造JSONの座標として確定します。
- ノードマスターはJSON Schemaから生成したフォームとRaw JSONの両方で編集できます。既存文書は `$schema` のファイル名から対応Schemaを選び、新規文書では最新の既定Schemaを選択できます。新しいSchema項目はフォームへ自動的に反映され、未対応の複雑な表現はRaw JSONで編集できます。
- `icon` は自由入力を維持しつつ、Paper 1.21.11でアイテムとして使用可能なMaterial候補を表示します。候補は `src/SkillTreeEditor.Client/src/data/minecraft-materials.1.21.11.json` に固定しているため、サーバーバージョンを変更するときに公式server data generatorの `generated/reports/items.json` から更新してください。タグとステータスは共有カタログから生成した日本語名・説明付き候補、スキルはfilebaseから読み取った日本語名・種別付き候補を表示しますが、JSONへ保存する値はいずれもIDです。
- 検証に成功するまで構造JSONは保存されません。

## Minecraftの色・装飾

- Filebase一覧、ファイル見出し、参照元、フォームの表示プレビュー・色付き参照候補、装備比較・クラス成長の名前にMinecraftの色を反映します。文字列入力・原稿・保存値は元のコードを保持します。
- `&` / `§` の16色、太字・斜体・下線・取消線・リセット、`&#RRGGBB` / `§#RRGGBB`、`&x&R&R&G&G&B&B` / `§x§R§R§G§G§B§B` に対応します。色の切替は装飾を解除します。不正コードやHTML風の文字列はテキストとして表示します。難読化（`k`）は固定のマスク表示とし、元の文字はアクセシビリティ用のラベルに保持します。
- フォームの色付き参照候補を開くと、入力中の値とは独立して全候補を確認できます。ID・日本語名の検索、件数表示、50件ごとのページ切替があり、候補を選択したときだけ入力値を変更します。閉じた候補のボタンは生成しません。ネイティブの入力補完は従来どおり入力値で絞り、最大100件のプレーンな名前を表示します。自由入力も維持します。スポナーの `spawnMobs[].mobId` はモブ候補を表示し、選択したIDに `mob:` を付けます。暗い色は元の色を保持し、暗色テーマ上で読めるよう輪郭を付けます。

## Minecraftアイコン

- Filebase一覧に保存済みの `icon` の画像を表示します。ファイル見出しではフォームの編集中の値をプレビューし、原稿モードでは保存済みのアイコンを表示します。
- 日本語フォームの `icon` には編集中の値のプレビューを表示し、「画像一覧から選択」で画像とMaterial IDを並べた選択ダイアログを開きます。ID検索、48件ごとのページ切替、選択中表示に対応します。
- スキルツリーのノード編集フォームと配置インスペクターでも同じ選択ダイアログを使えます。選択は編集中の原稿へ反映し、ファイルへの反映には従来どおり保存操作が必要です。
- キャンセル・Escapeでは値を変更しません。自由入力も可能です。「画像を再読込」は取得に失敗した画像の再試行に使います。

- アイコン画像は[MC Icons API](https://mc-icons.com/api)の `download/{id}/thumb` からASP.NET Core経由で取得します。取得できない場合は、[mc-assets のMinecraft 1.21.11固定版](https://github.com/Owen1212055/mc-assets/blob/551e4a68f23a59eecc84a310902f7e10864945f9/README.md) のゲーム内在庫表示画像を使用します。固定版の `item-assets/{MATERIAL}.png` は256×256のネイティブ描画で、現行の候補1,505件すべてに対応するファイルがあります。`50_resourcepack` は参照しません。
- `NETHER_STAR` や `minecraft:nether_star` はMC Icons用の `nether_star` に正規化され、初回取得後は `.cache/minecraft-icons/` のPNGを利用します。キャッシュはGit管理対象外です。
- 両方の取得先へ接続できない、またはMaterialに対応する画像がない場合も編集は継続でき、画面には `?` を表示します。取得済みの画像はローカルキャッシュから表示できます。接続を復旧してから「画像を再読込」を押してください。
- 主取得元は `appsettings.json` の `SkillTreeEditor:MinecraftIconsBaseUrl`、代替取得元は `SkillTreeEditor:MinecraftIconsFallbackBaseUrl` で設定します。主取得元は `download/{id}/thumb`、代替取得元は大文字の `{MATERIAL}.png` とPNG応答が必要です。代替URLを空にすると代替取得を無効化します。
- PaperのMaterial候補を更新するときは、代替画像の固定コミットも同じMinecraft版へ合わせて更新し、追加候補の画像を確認してください。
- 完全に取り直す場合はEditorを停止し、`.cache/minecraft-icons/` 内の対象PNGを削除してから再起動します。ノードマスターや構造JSONには影響しません。

## デプロイとリロード

このエディタが変更するのはリポジトリ内のfilebaseと `10_plugin/AstralRecord/src/main/resources/config.yml` です。稼働サーバーへは通常のデプロイ手順でfilebaseを反映し、その後Pluginで `/masterdata reload` を実行してください。Skill Treeもこの一括リロードに含まれます。

ソース側 `config.yml` の変更は既存のPlugin data folderへ自動コピーされません。表示ワールド・構造・中心座標を変えた場合は、稼働環境の `plugins/AstralRecord/config.yml` もデプロイまたは同期してからリロードしてください。エディタが稼働サーバーの設定へ直接書き込むことはありません。

JSON Schemaで表現できないBukkit MaterialやスキルIDとの実在照合はPluginロード時にも行われます。ステータス候補は共有ステータスカタログと`.\60_tool\generate-status-types.ps1`、タグ候補は共有タグカタログと`.\60_tool\generate-tag-types.ps1`で更新してください。タグ生成では全filebaseの未定義タグと用途不一致も検査します。`/masterdata reload` が返すエラーを修正してから運用へ反映してください。

## 定義変更時の保守

マスターのキー・型・必須・列挙・参照・命名、読込・変換、装備比較やレベル成長式を変更した場合は、定義とこのサイトを同じ変更で整合させます。対象スキルから [Filebase 編集サイトの同期規則](../../.codex/skills/_shared/filebase-editor-sync.md) を読み、影響するServer / Clientと検証を確認してください。

定義書やJSON Schemaから生成する項目は、元資料の変更と「一覧と定義メタデータを再読込」で反映を確認します。特殊な候補・参照・検証・採番は `MasterDataCatalog` / `MasterDataValidation` / `MasterDataService`、画面は `MasterDataForm` / `MasterDataEditor`、計算は `MasterAnalyticsService` / `masterAnalytics.ts` を更新します。個別マスターの性能値・名前・説明文を既存契約内で調整するだけなら、動的反映を確認し、重複した定義をサイトのコードへ追加しません。

## トラブルシューティング

### `A compatible .NET SDK was not found`

`global.json`と互換の.NET SDKが必要です。`skilltree-editor`フォルダー内で`dotnet --version`が成功することを確認してください。現在は10.0.302以降の互換Feature Bandが対象で、Runtimeや10.0.100だけの配置ではビルドできません。検出候補と実終了コードは、エラー画面に表示される診断ログで確認できます。

### `npm` / `node` が見つからない

`node` だけが見つかりnpmがない環境でも、Node.js 24 LTSのWindows ZIP版を展開して利用できます。`%LOCALAPPDATA%\AstralRecord\tools\node\node.exe`、同じディレクトリの `npm.cmd`、`node_modules\npm\bin\npm-cli.js` が揃うよう配置した後、`05-master-data-editor.bat` または `06-master-data-editor-build.bat` を実行してください。ユーザー・システムの `PATH` 変更は不要です。

別の配置先を使う場合は、起動するcmdで `set "ASTRALRECORD_NODE_HOME=C:\tools\node-v24.18.0-win-x64"`（または `NODE_HOME`）を指定します。BATはNode.jsのダウンロードやインストール、グローバルな環境変数変更を行いません。nvm利用時は本ディレクトリで `nvm use` を実行します。

### ASP.NET側で「frontend is not built」と表示される

`src/SkillTreeEditor.Client` で `npm ci` と `npm run build` を実行してください。開発時はASP.NETのURLではなくViteの `http://127.0.0.1:5173` を開きます。

### ワークスペースが見つからない

`ASTRALRECORD_WORKSPACE` または `SkillTreeEditor:WorkspaceRoot` に、`40_filebase`、`10_plugin`、`60_tool` を直接含むルートを指定してください。

### 保存が422になる

右側の検証パネルでエラーコードとJSON Pointerを確認します。nodeId変更、重複座標、無向edgeの逆順重複、rootから到達できないノードが代表例です。
