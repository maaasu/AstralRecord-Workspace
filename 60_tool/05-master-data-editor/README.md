# AstralRecord Master Data Editor

Filebase の YAML / JSON マスターと、スキルツリーのノード・配置・接続構造、Plugin の表示設定を編集する開発者専用ローカルアプリです。Windows デスクトップ版は ZIP を展開して `AstralRecordMasterEditor.exe` から起動し、03・01・09・12・16 の計画確認・実行・結果確認も同じ画面で扱います。[デスクトップ版の操作・実行条件](DESKTOP.md) を参照してください。日本語フォーム、原稿編集、装備比較、クラス成長グラフも引き継ぎます。`30_web` には依存せず、ASP.NET Core がワークスペース内のファイルを直接扱います。ブラウザ版の起動入口は従来の `05-master-data-editor.bat`、フロントエンドのビルド入口は `06-master-data-editor-build.bat` です。実装と配布物は `60_tool/05-master-data-editor/` にまとめています。

## デスクトップ版の配布ビルド

自分のAndroid端末で外出先からマスターを編集する手順は [Android版の接続と操作](ANDROID.md) を参照してください。データとGitは選択したPCのワークスペースに置きます。

PowerShell 7 から `./Publish-Desktop.ps1` を実行すると、フロントエンドと self-contained の Windows x64 EXE をビルドし、`dist/desktop/` に ZIP・SHA256・ビルドログを出力します。ビルドには Node.js 24 と global.json に適合する .NET 10 SDK が必要です。`-DotnetPath`・`-NpmPath`・`-OutputDirectory` で場所を指定できます。配布物にワークスペースのマスターやローカル接続設定を含めません。

操作ヘッダ中央の検索窓（Ctrl+P）から、Filebase全体のマスターを名前・ID・ファイル名・パスで検索できます。空白区切りの複数語はすべてに一致するファイルを表示し、上下キーで選択、Enterまたはクリックで保持タブとして開き、Escで閉じます。一覧パネルのフォルダやフィルターは保持します。候補は検索窓を開くたびに取得し直し、50件ずつ追加表示できます。

このワークスペースの日常起動先は、メイン作業ツリーの `60_tool/05-master-data-editor/dist/desktop/AstralRecordMasterEditor-win-x64/AstralRecordMasterEditor.exe` に固定します。既存のショートカットはこの EXE を `--workspace "C:\AstralRecord-Workspace"` 付きで起動します。更新時はエディタを閉じ、ZIP 内の同名フォルダーで既存のアプリフォルダーごと差し替えます。更新履歴は ZIP で保管し、ビルドごとの展開済みフォルダーは作業後に片付けます。

追加インストール不要の配布物は、Microsoft 公式の WebView2 Fixed Version Runtime x64 を展開し、`-WebView2RuntimeDirectory <msedgewebview2.exe のあるフォルダー>` を指定します。ランタイム全体を `webview2/` に同梱し、ホストはそのフォルダーを優先します。省略時はPCの Evergreen Runtime を利用します。Fixed Runtime は自己更新しないため、配布更新時に公式の安定版へ更新してください。[公式の配布手順](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution#the-fixed-version-runtime-distribution-mode)に従い、Windows 10 のパッケージ読み取り権限はホストが同梱フォルダーへ設定します。

EXE は同一プロセス内でエディタを起動します。デスクトップモードは固定ポート設定にかかわらず動的な loopback ポートへ限定し、ネイティブホストが付ける一時トークンを要求します。WebView2 の外部画面遷移・権限要求は制限します。ツール実行 API はデスクトップモード専用です。配置 API などの設定は選択ワークスペースの `src/SkillTreeEditor.Server/appsettings.local.json` を読み込み、配布フォルダーの同名設定、環境変数、起動引数の順で上書きできます。実行中のワーカーは独立して動き、アプリ再起動後も履歴から追跡できます。

## ChatGPT APIによるAIアシスト

「AIアシスト」は入力補完から開きます。マスターを編集しながら候補を確認し、必要なものを下書きに採用できます。

- **予測変換**: 日本語フォームの名前や説明文の欄をクリックするか文字を入力すると、既存マスターと入力履歴から候補を表示します。初期状態で有効で、APIキーは不要です。候補を選ぶと入力済みの文字の末尾に追記します。Tabで採用、Escで閉じ、Ctrl+Zで追記を取り消せます。Ctrl+Spaceでもローカル候補を開けます。日本語IMEの変換中は確定を待ちます。
- **Luna補完**: 「AIアシスト」の「入力補完」で「候補がないときにLunaで補完」をオンにします。文字を変更してローカル候補がない場合のみ、入力が止まってから対象欄のテキストと項目情報をOpenAIへ送信し、`gpt-6-luna` を推論なしで呼び出します。予測変換の設定と入力履歴は起動中だけ有効です。
- **作成**: カテゴリと参考にするマスターを選び、「中盤向けの氷属性の槍」などの指示から新規原稿を提案します。「アイテム共通」から参考なしで作成する場合も、素材・装備などの子カテゴリを指示に合わせて提案します。候補の作成先と内容を確認して通常の新規作成へ渡し、slugや保存先を確認して作成します。アイテムのIDは採用した子カテゴリの自動採番を使います。
- **一括編集**: 保存済みの対象ファイルを最大10件選び、自然言語で変更を指示します。変更前後の原稿と検証結果を確認し、採用する案を下書きとして開きます。各タブでUndoでき、保存は通常の検証・差分・保存操作を使います。対象の未保存編集や生成後の更新を検出した場合は上書きしません。

作成・一括編集では、操作に応じて対象や参考の原稿、関連する項目定義、参照候補をOpenAIへ送信します。

OpenAIを使う場合は、AIアシストの設定でAPIキーを指定します。画面から入力したキーは、この起動中だけローカルサーバーのメモリーに保持し、ブラウザーの保存領域や配布ZIPへ書き込みません。再起動後も使う場合は、エディタを起動する環境の`OPENAI_API_KEY`、またはGit管理外の`appsettings.local.json`の`SkillTreeEditor:Ai:ApiKey`に設定します。キーを共有設定の`appsettings.json`やGitへ記録しないでください。

作成・一括編集の既定モデルは`gpt-6.1-terra`です。画面の設定、または`SkillTreeEditor:Ai:Model`（環境変数では`SkillTreeEditor__Ai__Model`）で変更できます。接続先はOpenAIのResponses APIです。生成結果は操作別に構造と作成先を制約したJSONとして受け取り、エディタ側でも原稿・参照・識別子を検証します。通信失敗や途中で打ち切られた回答は、編集内容に適用しません。

設定例（APIキーの実値は各PCのGit管理外の設定だけに入力）:

```json
{
  "SkillTreeEditor": {
    "Ai": {
      "Model": "gpt-6.1-terra"
    }
  }
}
```

[Responses API](https://developers.openai.com/api/reference/resources/responses/methods/create)・[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)を使用し、`store: false`を指定します。この指定はOpenAI側のあらゆるデータ保持がなくなることを保証するものではありません。

## 画面共通の操作

デスクトップ版は Windows 標準の枠・タイトルバーと、その下の操作ヘッダで構成します。「編集ナビ」はサイドバーアイコン付きの専用表示切替です。「パネル」には閉じたビューの再表示と配置の初期化をまとめ、「ワークスペース」から作業フォルダーを変更できます。ビューのタブをドラッグして分割・結合・移動し、窓アイコンから別ウィンドウ化します。各パネルの「⋯」にはそのパネルの配置操作だけを並べます。マスターのフォルダ・ファイル・編集・検証も個別に移動できます。既存のビュー内のサイズ調整も引き続き使用できます。詳細は [作業領域のサイズ調整](docs/WORKSPACE_LAYOUT.md) を参照してください。

編集ナビと「パネル」メニューは、目的で入口を分けます。「データ・配置編集」にはマスターデータ、スキルツリー、ワールド配置・編集を並べ、「設計・分析」には装備・入手経路、比較・成長グラフを並べます。汎用フォーム・ノード図・配置地図はそれぞれの編集対象に合わせた入口で、装備・入手経路はビルド構成と依存関係の確認、比較・成長グラフは保存済みマスターの分析を担当します。各ボタンに操作内容のツールチップがあります。

グレーを基調とする固定配色で、選択中の画面には青を使い、未保存のある画面は `●` で表示します。レアリティ・表示名など意味のある色とアイコンは維持します。画面切替でも編集中の値を保持し、そのまま切り替えられます。マスターの変更を破棄する操作では、共通デザインの確認画面を表示します。キャンセルや Escape で編集を続けられます。幅に応じてナビゲーションと操作を折り返し、ページ全体を横へはみ出させずに利用できます。

画面の見出し、暗色のパネル、入力欄、主要な保存操作、フォーカス表示は共通の色・余白・文字サイズを使います。マスターデータは編集モード・履歴・確認と保存をグループ別に配置し、ファイルの複製・書出・参照・再読込・削除は編集内容の上にまとめます。ファイル未選択時は、検索から編集、差分・検証・保存までの手順を表示します。

## 管理対象

ワールド配置の編集には「元に戻す」「やり直す」と保存前の変更件数を用意しています。「変更内容を確認」で表示条件外も含む追加・変更・削除の前後値を50件ずつ確認し、1配置だけを保存前へ戻せます。未確定の数値入力は比較に含めず、入力中の個別取消を停止して保持します。座標の空欄を0に変換せず、入力途中の値を保持します。一括選択は表示条件に合う全件の追加選択・全解除と、条件外を含む選択だけの一覧確認に対応します。合計と表示条件内外の件数を示し、有効・無効への一括変更を1操作で戻せます。条件外を含む有効状態変更とすべての削除は、専用の確認画面で合計・条件内外の件数、名前・実レベル・座標・ID・ワールド・変更後の状態を50件ずつ確認します。キャンセル・Escapeでは編集内容と選択を保持し、確認中に対象の前提が変わると実行を停止します。大量配置の一覧は50件ごとのページで切り替え、地図には条件に合う全件を表示します。「選択中の配置のページへ」で現在の条件・並び順に応じた行へ移動できます。選択中の配置が一覧の条件外なら「表示条件を解除して選択中の配置を表示」で「一括選択だけ」の表示を解除し、必要な場合だけ地図と一覧の検索・詳細条件も解除して、現在の並び順の該当ページ・行へ移動します。一括選択と未保存の編集は保持し、自動保存・再読込は行いません。ページを変えても一括選択と原稿を保持し、一覧の表示行だけを50件以内に制限します。一覧は標準順、開始地点からの水平直線距離順、出現レベルの低い順・高い順、日本語名順に切り替えられます。検索条件の一括解除は検索・種類・有効状態・地域・スポナーマスター・レベル上下限だけを戻し、一括選択、編集中の原稿、並び順を保持します。詳細地形の取得は拡大時まで遅らせ、同じAI配置案は画面の往復でも再利用します。

配置の編集時は、変更されていない配置の地域判定・検索用文字列を再利用します。元に戻す・やり直すでも再利用し、地形解析やマスターが変わったときは作り直します。表示用一覧の全件走査、絞り込み、並び替え、地図描画は引き続き必要です。

保存済み配置は検索欄の↓・Enterで一覧へ移動し、↑↓・Home / Endでページをまたいで確認できます。Enter / Spaceで選択、Escapeで検索へ戻ります。フォーカス移動だけでは配置の選択や未保存入力を変更しません。

AI配置案の一覧は40件単位でページを切り替えます。「選択中の案を一覧に表示」で地図から選んだ案の行へ移動できます。検索条件外なら明示操作で一覧検索だけを解除し、選択案へフォーカスします。地図・地域条件・未保存のDev編集は保持します。

「ワールド配置・編集」では「表示ワールド」で取り込み済みの地図を切り替えます。未取り込みの地図は「地図の追加・更新」で手順を確認できます。「配置編集」でスポナー・NPC・道標を選び、「ボス・ダンジョン受付」でワールドと X・Z・高さ (Y) を指定します。受付地点は地図の取り込み前でも手入力できます。出現範囲と重複の表示は初期OFFで、「地図の表示・座標移動」で切り替えます。「その他の機能」の「AI 配置案」では、生成済みの地域別スポナー案を比較して JSON に保存できます。地図の取り込みと各機能の操作は [ワールド配置計画](docs/SPAWNER_PLANNING.md) を参照してください。

「テレポーター一覧」では、地図の取り込み状況にかかわらず、Dev に保存済みの道標を閲覧し、1 件ずつ設定を編集できます。名前・道標 ID で検索し、ワールド・有効状態で絞り込めます。ゲーム内で道標を登録した後や配置編集で変更を保存した後は、一覧の「再読込」を押してください。[テレポーター一覧の操作](docs/SPAWNER_PLANNING.md#テレポーター一覧)

## Filebase マスターの編集

カテゴリツリーの開閉矢印は同じ大きさのアイコンで表示します。フォルダの右クリック（キーボードではShift+F10またはメニューキー）から、フォルダ内の一覧表示、リポジトリ相対パス・実フォルダ名のコピー、配下の展開・折りたたみを操作できます。相対パスは `40_filebase/` から始まり、現在選択中のフォルダではなく右クリックしたフォルダが対象です。クリップボードに書き込めない場合は手動コピー欄を表示します。メニューは矢印キーで移動、Enterで実行、Escで閉じられます。

### ダンジョンの編集

ダンジョンの日本語フォームは、基本情報・入場地点・パーティー・挑戦ルール・出現モブ・クリア報酬・生成設定・外観テーマを縦に展開します。上部のセクション移動とフォーム内検索で目的の設定へ移動できます。省略されている設定は既定値を表示し、表示しただけでは原稿へ追加しません。

その他のマスターでも、設定済みの入れ子の項目と配列を展開し、その場で編集できます。「個別表示」は一つの項目に集中するときだけ使います。名前や説明は入力欄を常に表示し、カラーコードがある場合は表示プレビューを添えます。項目の追加や型の変更など、使用頻度の低い操作は補助メニューにまとめます。大量の配列は25件ずつ表示します。

ワールド・ボス・報酬テーブルなどの参照は名前と登録済みのアイコンを表示します。参照名や選択候補にカーソルを合わせるか、Tab キーでフォーカスすると、ID、説明文、モブのレベルや主な能力値、アイテムのレアリティなどを確認できます。「ファイルを再読込」は参照候補も更新します。通常モブは「＋ モブを追加」、報酬は「＋ アイテムを追加」から名前・IDで検索して選び、追加した行でレベル・重み・個数などを編集します。外観素材にも画像付きの選択画面を使います。保存する参照IDは従来の形式を保ちます。

### 装備・入手経路の設計

アカウント進行設定では、職業レベル、習得ノード、アクションリング、パッシブ、各スキルのレベルとシジルを編集できます。候補は名前・アイコン付きのダイアログから選び、選択中のチェックポイントへ装備とまとめて保存します。保存先は `40_filebase/90.shared.progression_preset` です。装備設計・進行設定・ゲーム内検証が共通で使う構成として、共有カテゴリに配置します。詳細は [アカウント進行プリセット設計](../../00_docs/50_Filebase設計書/feature/90-progression_preset.md) を参照してください。ノードの接続・必要ポイントなど、ゲーム内での適用可否は実行時にも検証されます。

ビルドは「新規ビルド」「複製」「名前・IDを編集」「削除」から管理できます。表示名は自由入力、ビルドIDは小文字英数字とアンダースコアです。新規登録ではLv.1の武器と1番枠のスキルを選び、必要ならスキルブック・習得ノードも設定します。新規・複製・削除は内容を確認してファイルへ反映し、未保存の下書きがある間は利用できません。名前・ビルドIDの変更は通常の下書きとして保存し、既存ファイルの保存用IDとパスは保持します。

レベル段階は1〜50を直接入力して移動・追加でき、現在の構成を複製して追加、適用開始レベルの変更、段階の削除もできます。重複するレベルは登録できず、基準となるLv.1は必須です。レベル編集は元に戻す・やり直すに対応し、装備や進行設定とまとめて確認・保存します。

図と右側の詳細欄の境界はスプリッターで調整でき、幅をブラウザに記憶します。フォーカスした境界は矢印キーで調整でき、Enterまたはダブルクリックで初期幅へ戻せます。狭い画面では上下配置に切り替わります。

「装備・入手経路」では、職業・ビルド・適用開始レベルを選び、通常装備6枠、スキルブック1枠、種類別アクセサリ9枠を設定できます。アクセサリはアミュレット1、タリスマン2、チャーム3、コア1、レリック2枠です。装備カードの選択で入手経路を表示し、「装備を変更」からアイコン・名前・必要レベル付きの一覧を開きます。名前とIDの複数語検索、カテゴリ、ページ切替、キーボード操作に対応します。部位・種類タグ・必要プレイヤーレベル・現在の職業と職業レベルを検査し、条件に合わない候補は理由付きで確認できます。保存時も同じ装備条件を検証します。選択したスキルブックの使用可能スキルは、その段階のアクティブ・パッシブ候補へ反映されます。

装備カードの「強化・付与」から強化値（＋値）と付与エンチャントを編集します。「＋ エンチャントを選択」では対応するオーブのアイコンと効果名を表示し、装備区分・付与枠数・重複効果・付与値の範囲を検証します。「下書きに反映」したあと、画面上部の「変更を確認して保存」でまとめて保存します。エンチャント付きプリセットを実ゲームで適用する前に、対応するPluginへ更新してください。Devは「01 Dev更新」で更新できます。

上部は「ビルドの装備」「アイテムから探す」「アカウント進行」を切り替えます。設定と入手経路の間の境界線で上下の高さを調整でき、「上部を折りたたむ」で図を広く使えます。設定が多い場合は上部だけをスクロールし、下部の図の高さを確保します。図と右側の詳細の幅も境界線で調整できます。

図は「入手先 → 素材 → 製作・交換 → 装備」で自動整列します。カードを選ぶと右側に詳細を表示し、素材数・獲得数・確率・抽選回数・通貨コストを変更できます。必要素材の追加・変更もアイコン付き一覧から選択します。「入手先を設定」ではモブ・採集・ダンジョンを選んで報酬を追加できます。モブのレベル別設定では、継承する基本ドロップを保持して追加します。直接定義した報酬は詳細欄から外せます。共有報酬を編集すると同じ定義の参照元にも影響します。

「アイテムから探す」では素材・報酬も起点にできます。「この素材を起点に図を見る」で、さらに上流の素材を調べられます。図は表示数に上限を設け、省略件数を表示します。すべての経路は詳細欄で選択でき、図と一覧を切り替えられます。拡大縮小、全体表示、背景のドラッグによる移動は表示だけの操作です。カードを自由配置してマスターデータを変更する操作はありません。

使い道にはショップ・レシピの素材、ビルドの装備、ワールドの入場条件を表示します。SHOP以外のレシピや利用先のないレシピ・共有報酬の定義は、利用可能な入手経路と区別します。図はマスター定義上の関係で、実ワールドの配置や最終的なドロップ確率を保証するものではありません。実配置は「ワールド配置・編集」、性能などの詳細は各カードの「定義を編集」「詳細」から確認します。

編集は保存前の図にも反映されます。「元に戻す」「やり直す」、画面切替時の保持、同じタブを再読込した際の下書き復元に対応します。「変更を確認して保存」（Ctrl+S）で変更ファイルを検証し、差分を確認して保存します。警告のある原稿は差分の確認が必要です。ファイルごとの保存のため、途中失敗時は保存済み件数を表示し、残りの下書きを保持します。外部更新は索引と原稿のrevisionで検出します。競合時は下書きを書き出してから最新原稿と照合してください。詳細編集へ移る前には、この画面の変更を保存します。

通常の一覧取得では、更新時刻とサイズが同じファイルの読込結果を一覧・絞り込み・参照候補で再利用します。
外部ツールが更新時刻を保持する場合は、ナビの「一覧と定義を再読込」で読み直してください。スキルツリーでは「再読み込み」、参照一覧では「参照元を更新」を使えます。

進行プリセットは「アカウント進行プリセット」カテゴリで編集します。レベル1から昇順にチェックポイントを記載し、装備・アクティブスキル・パッシブ・ノードをフォームまたはYAML原稿で指定できます。装備ごとに状態変化前の強化値を、アクティブ・パッシブごとにスキルレベルと装着シジルを指定できます。シジルは専用の参照候補から選択でき、保存前にスキルとの適合とスロット・グループの重複を検証します。参照候補を使うと保存形式に合うIDが入力されます。ファイル名はプリセットIDから `v1.<id>.yml` を提案します。

釣りマスターは「釣り魚」「釣りエリア」「釣りルール」のカテゴリから編集します。新規作成では各カテゴリの JSON Schema から必須項目を生成できます。`worldId`・`rulesId`・`fishId`・釣果アイテムは日本語名付きの参照候補から選択できます。エリアの魚候補一覧には確率合計を表示し、保存前に合計 100%（許容差 0.000001）、同じレベル帯内の魚重複、両端を含むレベル帯の重複、同じワールドの有効なエリア重複を検証します。釣りレベルは釣り竿の `FISHING_LEVEL` を使用し、エリアに座標指定はありません。

上部の「マスターデータ」で、アイテム、クラス、スキル、モブ、スポナー、採集、ショップ、クエスト、ワールド、バフ、ドロップ報酬、レシピ、共有カタログなどのファイルを選びます。「スキルツリー」へ切り替えると従来のキャンバス編集を使えます。切替時も編集中の内容は保持されます。

- ファイル一覧のシングルクリックでプレビュータブを開きます。別のファイルをシングルクリックすると未変更のプレビューを差し替えます。ダブルクリック、タブの保持操作、編集開始で通常タブとして保持します。プレビュータブには斜体の名前と「プレビュー」を表示します。
- ファイルはタブごとに読み込み、タブと編集欄に読込中の状態を表示します。読み込みを待つ間もフォルダ移動や別ファイルの表示ができ、読込中の新規タブを閉じるとその読込を中止します。読み込みに失敗したときは編集欄から再試行できます。
- アカウント進行プリセットではレベル一覧の「個別表示」で設定を編集できます。習得ノードは、その職業と段階のプレイヤーレベルに対応する実際のスキルツリー画面で選択し、下書きに反映します。「装備・入手経路」のアカウント進行設定にも同じ選択画面を使います。フォーム内検索や検証結果から数値入力の位置へ直接移動する操作も利用できます。
- ファイル検索欄で下矢印またはEnterを押すと結果へ移動します。結果内は上下・Home・Endで移動し、Enterで開き、Escapeで検索欄へ戻れます。選択フォルダの検索が0件なら、同じ検索語と条件でFilebase全体へ範囲を広げられます。検索クリア後は検索欄へフォーカスを戻します。
- フォーム内検索も下矢印・Enterで結果へ移動し、上下・Home・End・Escapeで操作できます。日本語入力の変換中はこれらの移動を実行しません。検索結果、セクション、パンくずや設定カードから移動すると、移動先の入力欄または見出しへフォーカスを移します。入力途中の不正な数値があるときは従来どおり階層移動を止めます。
- フォーム内検索は100件ずつページを切り替えて全結果を確認できます。ページ切替後は先頭の結果へフォーカスを移し、検索語・原稿・定義が変わると先頭ページへ戻ります。検索結果は入力欄の上下の空きに合わせて表示し、検証欄などに隠れずスクロールできます。検索中は原稿・項目定義・Schemaから準備した検索用の名前と値を再利用し、検索語の変更やページ切替だけでは全項目を解析し直しません。原稿や定義の更新時には再解析します。
- 保存中は原稿の準備・検証・書込みの進行を表示し、Ctrl+Sの連打による重複保存を防ぎます。変更がなければCtrl+Sで再保存しません。検証失敗時はフォームの最初の問題箇所へ移動し、未存在の必須項目や原稿モードのエラーは検証結果へフォーカスを移します。失敗しても入力内容は保持され、修正や再試行ができます。
- 検証結果はエラー・警告の総数を常に表示し、種別とメッセージ・パス・コード・ファイル名の空白区切りAND検索で絞り込めます。入力途中の数値エラーも含め、一覧は50件ずつ描画します。検索・ページ操作を残して結果だけスクロールでき、パスから問題の項目へ移動します。検索欄の下矢印・Enter、結果内の上下・Home・End・Escapeで操作できます。検証結果や入力エラーが更新されたら条件とページを初期化して新しい問題を表示し、タブ切替では条件を保持します。軽量化の対象は結果の描画で、サーバー側の検証や結果全件の検索は省略しません。
- 画面はフォルダツリー、検索・結果一覧、編集内容の3列です。フォルダと結果は独立してスクロールし、検索範囲と件数を一覧の直上に表示します。ツリーはフォルダアイコン、採番、階層線、配下の件数を表示します。矢印部分は開閉、名前は選択です。上下キーで移動、左右キーで開閉、Home / End、Enter / Spaceで選択できます。カテゴリ定義のない中間フォルダは開閉専用です。
- 起動時は「アイテム共通」を選択し、親カテゴリの一覧には子フォルダも含めます。独立したセット効果定義はアイテム一覧から除きます。名前 / ID / パスを検索でき、空白区切りの複数語は各語がいずれかの項目に一致するAND検索です。「検索範囲」で選択フォルダ以下と Filebase 全体を切り替えます。最初の50件を表示し、「さらに表示」または一覧末尾へのスクロールで続きを追加します。フォルダ展開、検索、条件、一覧のスクロールはファイルのタブ切替でも保持します。
- ナビの「編集中のファイルを一覧に表示」は、検索・詳細条件を解除して編集中のファイルを含む最も深いカテゴリへ移動し、対象行まで表示・フォーカスします。50件より後のファイルも必要な分を追加表示します。対応カテゴリがない場合はFilebase全体から表示します。タブ切替だけでは一覧条件を変えず、この操作でもファイルの再読込・保存は行わず未保存の原稿を保持します。一覧にないファイル、処理中・一覧再読込中は利用できません。
- 出現対象、ドロップ、ショップの商品・交換素材、レシピ素材、報酬、クエスト掲示板、抽選プール、釣れる魚などは名前とアイコンで選べます。参照先の名前やアイコンを押すと定義を別タブで開きます。数量・確率・価格などは一覧で編集し、個別の設定は「編集」から、参照先の変更や削除は行の「⋯」から操作します。
- 順序のある一覧は左端のつまみをドラッグするか、つまみにフォーカスして上下キーで並べ替えます。行の「⋯」にも移動操作があります。「売り場の配置」と「掲示板の配置」では、商品やクエストを4行×7列の空きマスへ移動できます。移動元を選んでページ番号を変えると、別のページや最後の次のページにも置けます。変更は原稿に反映され、元に戻せます。
- ファイルを開くと上部にタブを追加します。開いているファイルをもう一度選ぶと、そのタブへ切り替えます。幅1100px以下では一覧から既存タブを選び直した場合もナビを閉じ、編集中の内容へ戻ります。フォーム・原稿の編集内容、入力途中の数値、Undo / Redo、選択した階層と検証結果はファイルごとに保持します。未保存のタブには `●` を表示し、タブを閉じるときは未保存内容の破棄を確認します。タブ列の左右矢印・Home・Endでも切り替えられます。新規作成・複製したファイルも新しいタブで開きます。
- アイテムの一覧では、名前・ID・パスで検索したモブまたは採集オブジェクトをドロップ元に指定できます。空白区切りの複数語は各語がいずれかの項目に一致するAND検索です。直接ドロップ、モブのレベル別ドロップ、共通のルートテーブル・プール経由のアイテムを、選択中のアイテムカテゴリ内で絞り込みます。スキルの一覧は共有タグでさらに絞り込めます。
- モブ・採集の一覧では「ドロップ品で絞り込み」でアイテム名・IDを検索し、ドロップするアイテムを選べます。空白区切りの複数語は各語が名前またはIDに一致するAND検索です。レベル別・共通ルートテーブル経由も対象です。「アイテムドロップの有無」は、この索引で検出したアイテムの有無で判定し、お金のみのドロップは「なし」とします。
- 「詳細フィルター」は専用ダイアログで、レベル・数値、種類・分類、取引・装備、タグ・ワールド・動作、ドロップ、ファイルの条件をグループ別に設定します。現在の対象ファイルに存在する条件だけを表示します。該当件数を確認し、「条件を適用」で一覧へ反映します。キャンセル・Escapeは変更を破棄し、適用済み条件を維持します。条件はANDで併用し、適用後の一覧上部で個別に解除、または「すべて解除」できます。
- 詳細フィルターのドロップ品候補は、候補欄と対象IDがある場合に、対象ファイル・索引・参照候補の更新時にIDと表示名を準備し、Minecraftの色・装飾コードを除いた表示名で日本語順に並べます。同名は索引の順序を保ち、候補検索中は準備済み一覧を再利用します。ドロップ元・ドロップ品・共有タグなどの候補と適用済み条件にも装飾コードを除いた名前を表示し、名前が空ならIDまたはパスを表示します。ドロップ元候補は索引全体から探し、検索語に合わない選択済み候補も残します。候補検索語だけの変更では該当件数を数え直さず、条件や一覧・索引が更新されると再計算します。
- モブは基礎 `level` と `levels[].level` の実値のいずれかが指定範囲内なら一致します。例えば定義レベルが1と20だけのモブは5〜15に一致しません。アイテムはトレード禁止（`unTradeable`）・売却禁止、装備の必要レベル、必要クラス、利き手、装備タグ、セット、売却額、最大スタック、初期の強化上限・エンチャント枠・耐久上限を指定できます。必要レベル未指定の装備は0として扱い、装備以外に必要レベル0を推定しません。初期条件は超越後の上書きや個体ごとの能力を含みません。
- 種別、共有タグ、レアリティ、装備スロット、エンティティ種別、クラス役割、必要な道具タグ、ワールド・ワールド種別、有効・無効、パッシブ設定、ファイル状態（編集可能・閲覧のみ・解析エラーあり）も指定できます。「パッシブ設定」はスキルの `passive` オブジェクトの有無です。
- カテゴリ変更・一覧再読込で存在しなくなった候補は解除します。ダイアログの設定途中に索引やファイルが変わり条件が無効になった場合は、適用を止めて再設定を案内します。索引を取得できない場合は索引を使う条件を解除し、一覧検索・形式・ファイル状態は継続して利用できます。検索対象は保存済みファイルで、編集中の未保存値は含めません。
- 一覧・タブ・見出し・参照候補は、空でない `displayName` → `name` → `title` の順で名前を表示します。ファイル名のバージョン接頭辞と拡張子を除いた部分がIDと一致する場合はIDの重複行を省略します。ファイル名とホバー時のフルパス・IDは確認できます。日本語名でも一覧を検索できます。
- 「日本語フォーム」は短い項目を編集領域の幅に合わせて横並びに表示します。左ペインはファイルを開いた後も一覧を表示し、カテゴリや検索を維持します。右上の「×」で閉じ、「ナビを表示」で戻せます。幅1100px以下ではファイルを開くとナビを閉じます。幅680px以下では「フォルダ」「ファイル・検索結果」を切り替えて使います。
- 編集領域上部の日本語セクションから Map / 配列へ直接切り替え、深い階層はパンくずで戻れます。基本情報の設定カードは全体を押して詳細へ移動できます。深い階層でも入力欄の幅は変わりません。「フォーム内検索」は日本語名・キー・値を検索し、結果から該当項目へ移動します。同じファイルを開き直すと、このアプリ内で最後に選んだ有効な階層を復元します。
- フォームには項目名と入力欄を表示し、元のキー、型、説明、項目削除は見出し横の「⋯」で確認します。参照項目は「候補を選ぶ」か「IDを入力」から変更できます。真偽値はスイッチで切り替え、16進カラーコードは色見本からも選べます。定義済み任意項目や自由形式のキーは「項目を追加」から追加できます。
- 定義書で `challenge.entryLocation.x/y/z` や `yaw/pitch` のように同じ階層の項目をまとめた表記は、各キーへ展開してフォームと検証に使用します。座標は `x`・`y`・`z` ごとに数値型と必須条件を検証します。
- `lore` のような文字列配列は大きな入力欄で編集でき、1行をYAMLの1要素として保存します。文字列型の `description` は改行を含めても1つの文字列として保存します。装飾コード付きの文章と `color: #RRGGBB` には編集中のプレビューを表示します。
- オブジェクトの配列は要約と操作を表示し、25件ずつ一覧から選択した要素を編集します。追加・削除・複製・順序変更に対応します。配列要素内でUndo / Redoした場合は、位置変更後の別要素を誤編集しないよう配列の一覧へ戻ります。
- `implementationId`、RPC、固有 `params` のキーや参照 ID は元の表記で扱います。フォームで未定義のキーも保持し、「原稿 YAML / JSON」でコメントを含む全原稿を編集できます。元のYAMLの解析に失敗していても、原稿から修復できます。
- 「＋ 新規」は既存ファイルの原稿テンプレート、JSON Schema の必須項目生成、直接入力から作成します。「原稿を読込」でローカルのファイルを編集中の原稿または新規ファイルへ取り込めます。読込だけでは保存しません。
- 新規・複製・取込ダイアログの未保存原稿も、ページ再読込・終了時の確認対象です。キャンセル時や編集中の原稿をカテゴリ・テンプレート・Schema生成で置き換えるときは破棄を確認します。画面やタブの切替では原稿を保持します。Schema生成中は入力と作成をロックし、キャンセル後に届いた応答は破棄します。生成に失敗した場合は原稿を保持して再試行できます。
- 「保存済みファイルを複製」は保存済み原稿を新規ファイルの下書きにします。アイテムはID・ファイル名を自動採番でき、他のマスターは原稿内のIDと保存先を新しいものへ変更してから作成します。同じIDや保存先への作成は検証で拒否します。
- アイテムは `10.material` / `20.equipment` などのカテゴリに合わせて ID と `v<schemaVersion>.<id>.<slug>.yml` を自動生成します。通常の英字は `a` から繰り上げ、`z` はデバッグ用として別に指定します。クラスは `schemaVersion` / `order` / `id` からファイル名を生成できます。採番と保存先は作成成功時に確定します。
- 「差分」で保存済み原稿と編集中の原稿を比較し、「検証」でエラー箇所を確認してから明示保存します。Ctrl+S は選択中のタブを保存し、ツールバーの矢印はそのタブのUndo / Redoです。ファイルの再読込とページ終了は未保存の変更を確認します。どのタブに未保存の変更があってもページ終了を確認します。タブの右クリックまたは Shift+F10 で、閉じる・すべて・このタブ以外・右側・左側・保存済みのタブを閉じる操作を選べます。マウスの中クリックでも閉じられます。複数タブの未保存変更はまとめて破棄を確認し、キャンセル時はすべて保持します。処理中のタブを含む操作は無効です。タブの編集内容はこの画面を開いている間保持し、既存マスターファイルの未保存編集はワークスペース別のsessionStorageへ一時保存し、同じブラウザタブでのページ再読込後に「復元できる未保存の下書き」から明示復元できます。フォーム・原稿・不正数値の入力途中の文字を保持します。復元だけではファイルへ保存しません。最新の保存済み原稿が変わっていた場合は保存前の差分確認が必須で、この条件は再読込を繰り返しても保持します。明示保存、下書き破棄、確認済みのタブ閉じる・ファイル再読込でその下書きを削除します。新規・複製・取込ダイアログとスキルツリーの編集は、この再読込後の復元対象に含みません。ブラウザタブを閉じた後の復元や履歴100件の永続化は保証しないため、長期保管には原稿の書出を使います。
- 検証結果の項目パスを押すと、非表示の階層も開いて入力欄へ移動します。不正な数値の入力中は、入力が失われないよう別ノードへの移動とフォーム全体のUndo/Redoを止めます。数値を修正すると、移動や履歴操作を再開できます。入力欄内の標準のUndoは利用できます。
- 保存競合（409）では現在の編集を保持し、「最新原稿と比較」「この編集を維持して最新を基準にする」を表示します。基準更新後も保存前に最新原稿との差分確認が必要です。初回通信失敗からの再試行は未保存下書きを削除しません。
- 変更有無の判定では、保存済み内容の文字列と現在のフォーム比較結果をタブごとに再利用します。内容が変わらない画面の再描画では原稿全体を直列化・比較せず、内容・保存基準・編集モードが変わったときに再計算します。コメントなどの原稿文字列や未確定の数値入力の差分も即時に未保存として扱います。保持量は現在の保存済み内容の文字列1つと比較結果で、過去の版はキャッシュしません。実際の編集時に行う履歴生成・復元用下書きの保存や、初回の内容比較にかかる処理は残ります。
- タブ列の「タブを検索」では開いているファイルを、日本語名・ファイル名・パスの空白区切りAND検索や「未保存のみ」で絞り込めます。名前はフォームで編集中の表示名を使い、同名でもパスで区別できます。50件ごとに表示し、表示中・未保存・処理中を併記します。検索欄のEnterで現在のページの先頭結果へ切り替え、↓で結果へフォーカスします。結果内は上下キーでページをまたいで移動し、Home・Endで検索結果全体の先頭・末尾へ移動できます。最初の結果で↑を押すと検索欄へ戻り、Enter・Spaceでタブを切り替えます。フォーカス移動だけでは選択や編集中の内容を変えず、IME変換中や修飾キー付きの入力では一覧の移動・検索欄からの選択を実行しません。選択時は原稿・入力途中の値・履歴・階層を保持し、ファイルを再取得しません。Escapeで閉じると起動ボタンへ戻り、選択すると対象タブへフォーカスします。画面切替では検索ダイアログを閉じます。閉じたファイルを開き直す機能ではありません。
- 「参照一覧」は検出した参照元ファイルと項目を表示し、参照元へ移動できます。ID入力には既存マスターの名前付き候補を表示します。参照されているファイルは削除を拒否します。
- 参照一覧は、参照元ファイルのカテゴリで絞り込めます。現在のファイル一覧と定義メタデータから最も深いカテゴリを使い、該当する分類がなければ親ディレクトリ、ファイル一覧にない参照は「ファイル一覧外」と表示します。参照先の種類（モブなど）とは別の条件です。件数はファイル数ではなく参照箇所数です。
- 参照元の検索は、名前・参照ID・ファイルパス・項目パス・カテゴリ名を空白区切りのAND条件で探せます（例: `スポナー 森林狼`）。Minecraft装飾と英字の大文字小文字を無視し、各語は別の項目に一致しても構いません。検索・カテゴリ変更と解除は先頭50件へ戻り、編集原稿・選択タブ・保存対象は変えません。更新で選択カテゴリが消えた場合は0箇所の条件を保持し、「参照の条件を解除」で戻せます。
- 検索文字列とカテゴリは参照元・ファイル一覧・定義メタデータが変わったときに加工し、入力中は再利用します。閉じた一覧や非表示タブでは加工・一致判定を停止します。開いた一覧の検索では全参照の一致判定が必要で、表示は50件ずつです。
- 参照候補の一覧はキーボードでも選べます。展開すると検索欄へ移動し、↓またはEnterで表示中の先頭候補へ、↑↓・Home・Endで候補間を移動、Enterで選択します。Escapeで候補から検索欄へ戻り、検索欄のEscapeで一覧を閉じて起動元へ戻ります。ページ切替後も先頭候補へ移動します。IME変換中や修飾キー付き入力は横取りせず、検索や移動だけでは原稿を変更しません。読み取り専用・処理中の無効なフォームでは候補操作も無効です。候補は従来どおり1ページ50件だけを描画します。
- 参照一覧の「項目へ移動」は、参照元を開いて日本語フォームの該当入力欄へ移動します。深い配列・Mapや文字列配列に対応し、既存タブの未保存内容・Undo履歴を保持して再取得しません。読込・処理中や非表示のタブでは準備が整うまで待ち、同じ項目へ繰り返し移動できます。現在の原稿と参照一覧の値が一致しない、位置がない、パスが不正、未確定の数値入力・下書き復元待ち・原稿モードの場合は原稿を保ち、移動できない理由を表示します。原稿モードでは自動解析・切替をせず、日本語フォームへ切り替えてから再度移動します。同じ参照値を持つ配列要素同士の並べ替えまでは区別しません。ファイル名のリンクは従来どおり位置を指定せず開きます。Filebase外のPlugin設定など、ファイル一覧にない参照元はパスと案内を表示します。
- 参照元は「参照一覧」を開いたときに取得し、読込前や取得失敗を0件と表示しません。読込中も編集を続けられ、失敗時は「参照元を再試行」、取得後は「参照元を更新」で原稿を再読込せず更新できます。成功した結果は開閉で再利用します。保存・作成・削除後の一覧更新、一覧やファイルの再読込では全タブの結果を無効化し、表示中の参照一覧だけ再取得します。別のタブやエディタ画面を表示中の一覧は、戻ったときに取得します。外部のファイル編集は自動監視しないため、必要に応じて参照元を更新してください。対象は保存済みデータで、未保存原稿は含みません。サーバーでの削除時の参照検査は一覧の取得状態によらず実行します。
- 「現在の原稿を書出」は未保存の変更を含む原稿、「保存済みを書出」はディスク上の原稿をダウンロードします。「カテゴリ名の定義書」から定義資料のMarkdown原稿を確認できます。
- 保存前の差分は変更行と前後3行を表示し、それ以外の行を省略します。省略箇所ごとのボタンで展開・折りたたみでき、「全行を表示」で原稿全体を確認できます。変更がない場合もその旨を表示します。変更行自体が大量の場合や全行表示時は、表示行数による負荷は減りません。
- 保存前の差分の「前の変更」「次の変更」で、連続する追加・削除行を1箇所として順に移動できます。現在位置と総数を表示し、対象行の左端を強調します。初回は未選択で「次の変更」から開始し、端では循環しません。移動ボタンのフォーカスを保ち、差分欄だけをスクロールします。全行表示・省略行の展開でも選択位置を保持し、比較する原稿が変わるとリセットします。簡略化された比較では表示上のまとまった変更区間を数えます。変更箇所の索引は原稿が変わったときだけ計算し、移動で省略行を追加描画したり、保存・再読込したりしません。
- 差分計算は共通の先頭・末尾を先に除き、大きい原稿の離れた少数の変更も追跡します。小さい区間の比較行列は100万セルまで、大きい区間の探索は追加・削除256行分と200万回の探索処理までに制限します。上限に達した場合は中央の区間をまとめて削除・追加として表示し、変更のない行が件数に含まれる可能性を画面に明示します。どの比較方法でも原稿の行・行番号を保持し、「全行を表示」で全体を確認できます。計算上限は原稿の読込・結果行数・全行表示のメモリや描画量を制限するものではありません。

配置と開閉UIの検討には、[VS Codeのユーザーインターフェース](https://code.visualstudio.com/docs/getstarted/userinterface)、[WAI-ARIAのTree Viewパターン](https://www.w3.org/WAI/ARIA/apg/patterns/treeview/)、[GOV.UKのAccordion指針](https://design-system.service.gov.uk/components/accordion/)を参照しています。常用するフォルダ・検索・結果を常時表示し、詳細条件を独立させ、必要な情報を一律に折りたたまない構成にしています。

`*.schema.json` と `node-id-sequence.json` は読取専用です。Schemaの更新はリポジトリの変更として行い、定義と既存マスターを検証してください。ノードの新規作成・複製は自動採番を維持するため「スキルツリー」で行います。既存ファイルの `id` / `nodeId` / `structureId` は保存時に変更できません。IDの変更は新規ファイルとして作成し、参照元も整合させてください。

マスター保存は構文、定義書から読み取った型・必須、適用できるJSON Schema、カテゴリ・ID・ファイル名、同じマスター種別のID重複を検証します。スキルツリーには既存の構造検証も適用します。参照検出と汎用定義書の検証は、Plugin / API の全実装固有条件を代替するものではありません。運用へ反映するときは既存のFilebase検証・デプロイ・再読込も行ってください。

## 利用範囲と品質確認

通常のPC版は、各利用者が自分のPCのloopbackで起動し、指定したワークスペースを編集します。要求のHostはlocalhost / 127.0.0.1 / IPv6 loopbackに限定し、外部Origin・不正なFetch metadataは日本語403で拒否します。Originを送らないCLIと、別ポートのloopback Originを使うVite開発proxyは使用できます。Android接続を有効にすると、別のloopbackポートで、登録した端末に対するマスタ編集を受け付けます。PC版とAndroid版は、同じワークスペースの排他と版確認を共有します。

フォーム・ファイル操作・通信回復・保存競合・コメント維持・参照存在検査・ID採番・リンク拒否について回帰テストを行います。画面は日本語で表示し、保存契約のID・キー・JSON Pointerは元の表記を併記します。未知の追加キー、固有パラメータ、JSON Schemaやパーサーの技術詳細は元の表記で確認できます。新規作成・差分・定義書・ノード・設定ダイアログはEscape、キーボードのフォーカス移動と復帰、未保存原稿の破棄確認に対応します。

有料提供に必要な実際の複数ユーザーによる受入試験、配布・更新・問い合わせ対応の運用、外部アイコン提供元の配布条件は、このリポジトリの自動テストだけでは確認できません。販売可能という判断とは分けて扱います。既知の復元範囲は上記の編集手順に記載しています。

## 装備比較とクラス成長グラフ

同じ分析画面の「統合バランスラボ」で、職業・装備・スキル・敵を選び、seed付き戦闘試行、リソース推移、収集・強化・育成・Goldの試算、複数ビルドと隔離した調整案の比較を行えます。条件保存・再実行・JSON/CSV出力にも対応します。計算の対応範囲、未対応効果の停止、Plugin実処理との照合、負荷上限は [統合バランスラボ](docs/BALANCE_LAB.md) を参照してください。

「比較・成長グラフ」は保存済みマスターを使います。マスター変更後は「マスター再読込」で反映します。

装備の絞込・並び順と成長グラフは、それぞれの計算に関係する条件が変わるまで再利用します。確認Lvの移動は数値表だけを更新し、UUIDなど次回計算用の入力や別タブの検索では既存の成長グラフを再計算しません。「グラフを計算」で新しい結果を受け取った場合や、マスター再読込後の計算では更新します。

条件と結果を左右に並べ、幅が狭い場合は縦に並べます。計算方法と前提は必要に応じて開閉できます。比較表はフォーカスしてキーボードで横へスクロールでき、分析の種類のタブは左右矢印・Home・Endで移動できます。

- 「装備を比較」は要求プレイヤーLvの中心と前後幅、スロット、装備タグ、名前 / ID / パスで絞り、下限〜上限の比較表とステータスの棒グラフを表示します。検索は空白区切りのすべての語が、名前・ID・パスのいずれかに一致するAND検索です。例: `銀 剣`。語順・英字の大小・Minecraftの装飾コードは問いません。全角空白・タブも区切りになり、空白だけなら検索による絞り込みを解除します。他の条件とはANDで併用し、選択した装備は検索を変えても保持します。チェックした装備だけの比較とCSV出力に対応します。
- 選択した装備は検索・Lv・スロットなどの条件を変えても比較対象に残ります。「条件に一致する装備」で候補を追加し、「選択した装備」で確認・個別解除できます。標準の並び順では選択順です。表はどちらも50件ずつ、バーは対象ステータスを持つ先頭30件、CSVは比較対象全件です。条件や一覧表示を切り替えると先頭ページへ戻ります。「選択を解除」で条件一致の全装備比較へ戻ります。
- 装備比較CSVは既存の基本列とステータスの下限・上限の並びを維持し、その後ろに全ステータスの期待値列、指定強化Lv、ソースパスを追加します。期待値は画面の表示前の数値を出力し、算出されていない項目は空欄、期待値0は数値0です。指定強化Lvは画面で指定した共通値で、実際の計算には各装備の強化上限が適用されます。ソースパスは40_filebase基準の相対パスです。選択した比較対象・並び順を使い、ページや差分列表示による省略は行いません。CSVの作成は出力操作時だけ行い、マスターを変更しません。
- 比較条件の「条件一致を比較に追加」「条件一致の選択を解除」は、ページをまたぐ絞込結果すべてを一括操作します。ボタンには実際に追加・解除する件数を表示し、対象が0件なら無効になります。追加は既存の選択順を保ち、新しい対象を現在の並び順で末尾に加えます。条件外や現在見つからないマスターの選択は保持します。操作後は「選択した装備」の先頭ページを表示し、その表示切替ボタンへフォーカスを移します。一括解除で選択がなくなった場合も比較・CSVは0件のままです。
- 比較結果の「並び順」で名前・ID・要求Lv・進行度・グラフで選んだステータスの下限／上限を昇順・降順にできます。候補表・選択表・バー・CSVに共通で適用しますが、選択内容や選択した順序そのものは変えません。「標準」に戻すと、候補は要求Lv→ID、選択した装備は選択順に戻ります。同じ値は標準の順序を保ち、未定義の値は昇順・降順とも末尾です。グラフのステータスを持たない装備は従来どおりバーから除外します。名前・IDの明示的な並べ替えは装飾を除いた名前と数字を自然順で比較します。
- 並び順・方向を変えた場合と、下限／上限の並べ替え中に対象ステータス・強化Lvを変えた場合は先頭ページへ戻ります。強化Lvやマスター再読込では最新の値で並べ直します。標準の候補順は装備データ・強化Lvが変わったときに全装備で計算し、検索やLv・スロット・タグの絞り込みには再利用します。明示的な並べ替えは、絞り込み後の候補または選択済みの行だけを対象とし、対象行・並び順・方向・対象ステータスが変わったときに再計算します。絞り込み処理・表示用のメモリは引き続き必要です。
- 比較表の「差のあるステータスだけ」は、現在の候補表または選択表の全ページで下限・上限・期待値が異なる列だけを表示します。表示前の数値で比較し、未定義と0、期待値の有無を区別します。2件未満は全列、全件で同じ値なら装備名などの基本列だけを表示します。切替でも選択・ページ・並び順を保持し、グラフとCSVの項目は変更しません。強化・検索・選択・再読込で対象が変わると再判定し、並び順だけの変更では判定結果を再利用します。初期状態は全列表示です。
- 装備比較の「要求Lvで絞り込む」は初期ON（中心10・前後10）です。OFFでは全Lvを候補に含め、中心・幅の数値は保持して入力を無効化します。再びONにすると保持した範囲を使います。「装備の条件を解除」は名前・ID検索、スロット、タグ、要求Lvの絞り込みを解除し、候補一覧の先頭ページへ戻して検索欄にフォーカスします。比較選択（見つからない選択も含む）・強化Lv・グラフ項目・並び順・差分列表示は保持し、自動保存・再読込は行いません。比較選択がある場合、候補一覧を広げてもバーとCSVの対象は引き続き選択した装備です。
- 「選択した装備」が0件の間は比較・CSVの対象も0件です。最後の装備を個別解除しても全装備の比較には切り替わりません。選択が残っていない状態で「条件に一致する装備」に戻すと、条件一致の全装備を比較します。
- 強化Lv変更・マスター再読込では選択を維持したまま最新の値で計算します。削除・読込不能などで見つからない選択は件数を知らせ、比較とCSVから除外します。「見つからない選択を解除」でその選択だけを外せます。選択はこの分析画面の状態であり、マスターデータへは保存しません。
- 強化Lvの差分を累積し、Plugin と同じく FLAT は加算、基礎 SCALAR は最後の定義を採用します。累積した強化 SCALAR があれば基礎 SCALAR を上書きし、FLAT に乗算します。SCALARだけのステータスは補正を持ちません。個体の乱数、エンチャント、ルーン、セット、超越、装備可否は比較計算に含めません。
- 装備・職業の検索では、名前・ID・パスの装飾除去と小文字化を、必要になった文字列からカタログごとに再利用します。検索語の変更、装備の強化Lvや比較選択の変更では同じ文字列を加工し直しません。マスター再読込で対象カタログが変わると作り直します。空の検索では候補の加工を行いません。検索結果・並び順・通信は変わらず、全候補の一致判定、最初の加工とキャッシュ用メモリは引き続き必要です。
- 「クラス成長」はアカウントUUID、開始プレイヤーLv、開始クラスLv、表示上限、比較する職業（最大12件）を指定して計算します。プレイヤーLvに対するクラスLv・累積クラスEXP・クラスのステータス補正を切り替え、指定Lvの数値表とCSVも確認できます。グラフの凡例と線の説明には職業名とIDを表示し、同名の職業も識別できます。系列はIDで識別するため、再計算で順番や名前が変わっても正しい線・凡例を更新します。名前の装飾色は保持し、線の色は従来どおり結果の並び順で割り当てます。
- 成長グラフ用の職業マスター検索は、ステータス補正の表示時に職業ごとに1回だけ行います。クラスLv・累積クラスEXPの表示では行いません。補正グラフでは職業・ステータスごとの基礎値・成長値・最大Lvを1回だけ読み取り、各点で再利用します。グラフの種類・ステータス・計算結果・マスターが変わると作り直します。各グラフ点の補正計算と指定Lvの数値表の検索・値の読取りは引き続き必要です。計算式・通信・表示内容は変わりません。
- 職業候補は名前・ID・パスの空白区切りAND検索と「選択済みだけ表示」を併用できます。検索はMinecraftの装飾コード・英字の大小を区別しません。「職業の条件を解除」は表示条件だけを戻し、選択や計算条件を保持します。表示件数、条件外の選択件数、カタログにない選択IDを分けて案内します。タブ切替・マスター再読込でも検索と選択を保持し、計算は表示中の候補だけでなく選択したID全体（最大12件）を使います。選択済み表示でチェックを外した場合は次の候補、前の候補、検索欄の順にフォーカスを移します。
- カタログにない職業IDは、件数付きの「見つからない選択を解除」で比較の選択から外せます。検索で隠れた有効な職業・検索条件・計算条件は保持し、検索欄へフォーカスを戻します。マスター再読込中・失敗中は解除できず、成功後の最新カタログで対象を判断します。自動解除・自動再計算は行わないため、解除後は「グラフを計算」で更新してください。マスターファイルは変更しません。
- 成長結果を計算したときの入力と現在のUUID・開始Lv・表示上限・職業選択が異なる場合、結果欄に変更項目と「変更した条件で再計算」を表示します。表示中のグラフ・表・CSVは前回の成功結果を保持します。計算中に入力を変えた場合や再計算に失敗した場合も、実際に成功した要求の入力と比較します。元の条件へ戻すと案内が消えます。UUIDは表記の変更も対象ですが、職業の選択順、検索条件、グラフの種類・ステータス、確認Lvだけの変更は対象外です。マスター再読込では結果とその入力記録をまとめてクリアします。
- 「マスター再読込」は計算中の成長グラフの通信を中断し、結果をクリアします。再読込前の結果・エラーが遅れて届いても表示せず、新しい計算の状態にも反映しません。マスター取得中・取得失敗中は成長計算を止め、再読込が成功すると再開できます。入力条件と装備の比較選択は保持します。分析内のタブ切替では計算を継続し、通常の再計算が失敗した場合は直前の結果を残して再試行できます。
- プレイヤー必要経験値のUUID由来の差、クラスの `expRate` / `maxLevel`、`baseStats` / `growthPerLevel` を反映します。通常育成・転生なし、開始Lv到達直後から同じEXPをプレイヤーと1職へ加算する仮定です。職業ごとの線は独立した育成シナリオで、転職条件や過去の育成履歴を含みません。「計算の根拠と前提」で式とPluginソースの対応を確認できます。

## 保存とバックアップ

- マスターの原稿保存は入力したキー順・コメント・改行を保持してUTF-8（BOMなし）で保存します。同内容は書き換えません。更新・削除前の原稿は `.backups/master-data/` へ保存します。
- YAMLフォームで構造が変わらず値だけを変更した場合は、元の原稿へ値を反映してコメント・順序・改行を保持します。キーや配列要素の追加などで全体を再生成する場合は、元のコメントを先頭へ移したことを画面に警告します。差分を確認し、コメントの位置を維持したい場合は原稿で編集してください。
- Filebase マスター画面の更新・削除は読込時のSHA-256 revisionを照合します。他のエディタや外部編集による変更があれば409で拒否するので、再読込して差分を確認してください。画面の複製は読込時の保存済み原稿から編集可能な新規原稿を作成するため、複製元を再読込してから実行すると最新の内容を使えます。workspace共通の排他と同一ディレクトリへの原子的なファイル置換を使用します。
- スキルツリーの既存ノード・構造・Plugin設定も読込時の版を確認します。GET / 作成 / 更新はETag、ノード・構造一覧はrevisionを返し、既存更新とノード削除にはIf-Matchが必須です。版がない、または別のエディタ・外部操作で変更された場合は日本語の409で拒否し、画面の編集原稿を保持します。再読込してから編集し直す場合は必要な原稿を先に書き出してください。
- 構造の検証・保存の待機中は配置・構造切替・履歴・自動配置を停止し、保存応答で後続の編集を失わないようにします。インスペクターの座標・ポイント、ノードフォームの数値、Plugin設定の中心座標を数値として読み取れない間はその入力を保持し、保存を停止します。配置座標は0.1単位・32bit範囲を満たす値をEnterまたはフォーカス移動で確定し、暗黙の丸め・クランプは行いません。インスペクターの未保存入力もノード変更・構造切替・詳細ペインを閉じる・再読込・終了時に保護します。
- スキルツリー画面で保存するJSONはノード・構造・配置・edge・effect・採番メタデータごとの固定された意味順にキーを並べ、未知の追加キーは辞書順に安定化します。UTF-8（BOMなし）、2スペースインデント、LF、末尾改行ありです。同一内容の再保存はファイルを書き換えません。
- node / structure / Plugin設定の更新はworkspace共通の排他内で再読込・検証・保存するため、並行リクエストや複数Editorプロセスがノード削除と構造保存を競合させても未知nodeId参照を正本へ残しません。
- 既存JSON、削除対象JSON、`config.yml` は変更前に `.backups/<category>/<filename>.<timestamp>.bak` へコピーします。
- nodeId採番時はWindows/Linux共通のファイル排他内でhigh-waterと既存ノードを再読込し、`node-id-sequence.json` を `.backups/node-id-sequence/` へ退避してから原子的にhigh-waterを進め、その後ノードJSONを作成します。複数Editorプロセスから同じworkspaceを開いてもhigh-waterを巻き戻しません。
- 一時ファイルを同一ディレクトリへ書いてから置換するため、書込み途中のファイルを正本にしません。
- `.backups/` はGit管理対象外です。不要になったバックアップは手動で削除してください。
- ワークスペース配下のシンボリックリンク・junctionを通じた読取・保存・削除・バックアップ・ロック・アイコンキャッシュ操作を拒否します。通常のGit worktreeは使用できます。
- `config.yml` は管理対象キーが欠けていても不足キーだけを追加し、既存の改行コード、コメント、未知のskilltree設定、他のトップレベル設定を維持し、`skilltree:` 内の管理対象値だけを更新します。`worldName` にYAMLで使用できない制御文字は保存できません。
- 設定画面が更新するのはリポジトリ上の `10_plugin/AstralRecord/src/main/resources/config.yml` です。稼働環境の `plugins/AstralRecord/config.yml` と filebase へデプロイまたは同期した後、サーバーで `/masterdata reload` を実行してください。このツールは稼働サーバーへ直接書き込みません。

## 操作メモ

- ノード一覧は未配置・配置済みをそれぞれ50件ずつ表示し、「前へ」「次へ」で独立して切り替えます。検索・タグ・種類・構造・ゲーム内表示シミュレーションの条件を変えると先頭ページへ戻り、ページ操作時は一覧の先頭の編集ボタンへフォーカスします。種類は小ノード・主要ノード・キーストーン・道標・スキルで絞り込めます。検索・タグ・種類に一致する配置を地図上で青緑の輪で囲み、ほかの配置を薄く表示します。
- ノード一覧の検索はID・装飾を除いた名前・タグのIDと日本語名/説明・効果・CP/PPコスト・条件クラスの名前に対応します。空白（全角空白やタブを含む）で区切ると、すべての語を含むノードに絞ります。例: `火球 CP 冒険者`。タグ選択とも組み合わせられ、未配置/配置済みの区分と元の順序を保ちます。検索しても配置や編集中の値は変更しません。表示・検索用の情報はノード/スキル/クラスの入力が変わるまで再利用しますが、初回の準備、全件の一致判定、結果の描画は引き続き必要です。
- 未配置ノードを左ペインからキャンバスへドラッグして配置します。一覧の「配置」からX / Y / Zを指定して配置する操作もあり、一覧とキャンバスを同時に表示しない狭幅画面やキーボード操作でも使えます。座標は0.1単位・32bit範囲、同じnodeIdや同じ座標の重複を拒否し、配置はUndo / Redoの対象です。構造JSONへの書込みには従来どおり保存が必要です。未配置・配置済みの空の一覧は必要な高さだけを使います。
- キャンバスの空白を左ドラッグすると画面を移動します。Shiftを押しながら空白をドラッグすると範囲選択になります。
- キャンバス左下で拡大・縮小し、「起点へ」「選択へ」「全体表示」で移動できます。「グリッド」はX/Zの軸とブロック目盛りを表示します。縮小時は5ブロック間隔に切り替わります。グリッドのオン・オフはブラウザに保存され、ポインターのX/Z座標は左下に0.1ブロック単位で表示されます。右下のミニマップからも表示範囲を移動できます。
- 表示対象が150ノードを超える構造は、起点の周辺から表示し、画面外のノードの描画を省きます。ゲーム内表示シミュレーションで起点が隠れている場合は表示対象のノードから開きます。「全体表示」では表示対象全体を確認できます。
- 地図はWeb版と同じ星空の配色で、PPは丸、CPは角丸四角です。主要ノード・キーストーン・道標・起点は枠で区別し、接続はノードの中心を結ぶ方向に直線で表示します。選択またはホバーしたノードとその接続を強調します。進行プリセットの習得ノードは金色の枠とチェック印で表示します。
- ノード一覧は、アイコンと色付きの名前、ID・職業・コスト・種類、効果の順に表示します。効果は先頭2件を表示し、残りは件数を添えます。ノードをホバーすると地図右上に効果、必要レベル、接続先の要約が出ます。ステータス名はカテゴリ色で表示し、スキル効果はスキルの表示名を使います。
- 右の「ノード詳細」は、選択前に構造名、ノード・接続総数、職業・種類別の件数、座標範囲を表示します。選択後は種類・名前、解放コスト、効果、必要条件、接続先を確認できます。接続先のチップと一覧の「表示」は対象を選択して地図中央へ移動します。接続先がシミュレーションの範囲外の場合は、シミュレーションを解除して移動します。
- 「配置と編集」ではX/Y/Zと起点からの距離を確認でき、座標、起点、接続、名前、Material、ポイント、タグを編集できます。ノードのダブルクリック、または「効果・スキーマ・原稿 JSONを編集」からマスター編集を開きます。
- ノード編集画面の「複製して新規作成」では、編集中の内容をすべて引き継ぎ、nodeIdだけを保存時に自動採番したノードを作成できます。基本ステータスなど、同一定義を複数ノードで使う場合に利用します。
- キャンバス上のノードを右クリックすると、マスター編集、ROOT設定、nodeIdコピー、接続削除、配置削除を選べます。複数選択中の配置削除にも対応します。
- ノードの中央をドラッグして配置を移動し、端のハンドル間をドラッグして接続を追加します。複数選択したノードの移動量は共通で、0.1ブロック単位に揃えて元の間隔を保ちます。同じX/Zで高さが異なる配置は「重なり」の件数を表示し、ホバー時にほかのノード名を確認できます。一覧の「表示」と詳細の接続先チップから、それぞれのノードを選べます。
- Shift / Ctrl / Cmdで複数選択、Deleteで配置またはedgeを削除します。
- 構造選択とUndo / Redo・保存は上段、表示パネルと自動配置・表示設定・再読込はその下にまとめます。ヘッダーの「一覧」「キャンバス」「詳細」で各ペインを表示・非表示にでき、最後の1ペインは閉じられません。ペイン間の境界をドラッグすると幅を変更でき、境界のダブルクリックで初期幅へ戻ります。幅980px以下では「ノード一覧」「キャンバス」「詳細・検証」を同じ領域で切り替えます。この切替ではペインを作り直さないため、インスペクターの入力途中の値を保持します。広い画面で閉じたペインもこの切替から表示できます。
- 「ゲーム内表示シミュレーション」を有効にすると、現在の職業とプレイヤーレベルを指定して、`unlockCondition` を満たすノードだけを一覧・キャンバスへ表示します。クラス条件は現在職から filebase の転職前提を再帰的に辿り、祖先職も成立扱いにします。edge は両端ノードが表示対象の場合だけ表示します。
- キャンバス上部の表示バーは、シミュレーションの職業・レベル、配置ノードの表示件数、凡例を表示します。幅に合わせて操作を折り返します。
- 「最大ノードサイズ」は基本のノード寸法を32～140pxで調節し、ブラウザに保存します。実際の枠は周囲の間隔と種類に合わせて変わります。ノード下のラベルは名前とコストを表示します。画面上の間隔が90px未満の場合や、下の枠とラベルが重なる場合は、選択中・ホバー中のノードに絞ります。表示倍率45%未満ではラベルを隠し、ホバー要約に名前を表示します。
- Ctrl+Z / Ctrl+Y、またはヘッダーのボタンでUndo / Redoします。
- 「補助自動配置」はrootからのBFSレイヤー配置をX/Zへ明示反映します。通常の編集履歴に入るためUndoでき、結果は保存時に構造JSONの座標として確定します。
- ノードマスターはJSON Schemaから生成したフォームとRaw JSONの両方で編集できます。既存文書は `$schema` のファイル名から対応Schemaを選び、新規文書では最新の既定Schemaを選択できます。新しいSchema項目はフォームへ自動的に反映され、未対応の複雑な表現はRaw JSONで編集できます。
- `icon` は自由入力を維持しつつ、Paper 1.21.11でアイテムとして使用可能なMaterial候補を表示します。候補は `src/SkillTreeEditor.Client/src/data/minecraft-materials.1.21.11.json` に固定しているため、サーバーバージョンを変更するときに公式server data generatorの `generated/reports/items.json` から更新してください。タグとステータスは共有カタログから生成した日本語名・説明付き候補、スキルはfilebaseから読み取った日本語名・種別付き候補を表示しますが、JSONへ保存する値はいずれもIDです。
- 検証に成功するまで構造JSONは保存されません。

## Minecraftの色・装飾

- Filebase一覧、ファイル見出し、参照元、フォームの表示プレビュー・色付き参照候補、装備比較・クラス成長の名前にMinecraftの色を反映します。文字列入力・原稿・保存値は元のコードを保持します。
- `&` / `§` の16色、太字・斜体・下線・取消線・リセット、`&#RRGGBB` / `§#RRGGBB`、`&x&R&R&G&G&B&B` / `§x§R§R§G§G§B§B` に対応します。色の切替は装飾を解除します。不正コードやHTML風の文字列はテキストとして表示します。難読化（`k`）は固定のマスク表示とし、元の文字はアクセシビリティ用のラベルに保持します。
- フォームの色付き参照候補を開くと、入力中の値とは独立して全候補を確認できます。ID・日本語名の検索、件数表示、50件ごとのページ切替があり、候補を選択したときだけ入力値を変更します。閉じた候補のボタンは生成しません。ネイティブの入力補完は従来どおり入力値で絞り、最大100件のプレーンな名前を表示します。自由入力も維持します。スポナーの `spawnMobs[].mobId` はモブ候補を表示し、選択したIDに `mob:` を付けます。暗い色は元の色を保持し、暗色テーマ上で読めるよう輪郭を付けます。
- 参照候補の検索用ID・装飾を除いた名前は、必要になった候補から加工して再利用します。入力補完は100件一致した時点で探索を止め、閉じた候補一覧では全件検索を行いません。閉じても検索語・ページを保持し、再読込で候補が減った場合は再展開時に有効なページへ戻します。候補一覧を開いた検索では正確な件数を数えるため全候補の一致判定が必要です。候補が更新されたときはキャッシュも作り直します。

## Minecraftアイコン

- Filebase一覧と参照候補に保存済みのアイコンを表示します。ファイル見出しとフォームのアイコン欄では編集中の値をプレビューし、原稿モードの見出しは保存済みの値を表示します。採集定義に `icon` がなければ `displayBlock` を使います。
- 日本語フォームと道標の素材アイコン欄では、素材 ID を直接入力するか、「画像一覧から選択」で素材 ID と画像を見ながら選べます。編集中の値をプレビューし、ダイアログは ID 検索、48件ごとのページ切替、選択中表示に対応します。
- スキルツリーのノード編集フォームと配置インスペクターでも同じ選択ダイアログを使えます。選択は編集中の原稿へ反映し、ファイルへの反映には従来どおり保存操作が必要です。
- キャンセル・Escapeでは値を変更しません。自由入力も可能です。「画像を再読込」は取得に失敗した画像の再試行に使います。

- `icon` と `customModelData` が `50_resourcepack/item-models.json` に一致する場合、リソースパックのインベントリ用PNGを表示します。専用PNGが使えない場合、`PLAYER_HEAD` は `iconTexture` で指定された Minecraft の頭部画像を表示し、それ以外は通常の素材アイコンに戻ります。画像選択ダイアログは素材の一覧です。
- 通常の素材アイコンは[MC Icons API](https://mc-icons.com/api)の `download/{id}/thumb` からASP.NET Core経由で取得します。取得できない場合は、[mc-assets のMinecraft 1.21.11固定版](https://github.com/Owen1212055/mc-assets/blob/551e4a68f23a59eecc84a310902f7e10864945f9/README.md) のゲーム内在庫表示画像を使用します。
- `NETHER_STAR` や `minecraft:nether_star` はMC Icons用の `nether_star` に正規化され、初回取得後は `.cache/minecraft-icons/` のPNGを利用します。キャッシュはGit管理対象外です。
- 両方の取得先へ接続できない、またはMaterialに対応する画像がない場合も編集は継続でき、画面には `?` を表示します。取得済みの画像はローカルキャッシュから表示できます。接続を復旧してから「画像を再読込」を押してください。
- 主取得元は `appsettings.json` の `SkillTreeEditor:MinecraftIconsBaseUrl`、代替取得元は `SkillTreeEditor:MinecraftIconsFallbackBaseUrl` で設定します。主取得元は `download/{id}/thumb`、代替取得元は大文字の `{MATERIAL}.png` とPNG応答が必要です。代替URLを空にすると代替取得を無効化します。
- PaperのMaterial候補を更新するときは、代替画像の固定コミットも同じMinecraft版へ合わせて更新し、追加候補の画像を確認してください。ブロック素材欄の候補 `minecraft-block-materials.<版>.json` は、同じ版の Paper API で `javap org.bukkit.block.BlockType` に表示される `public static final BlockType.Typed` の定数名を、既存のアイテム候補と照合してアイテム候補の順序で抽出した一覧です。
- ダンジョンの床・壁・門などの候補 `minecraft-solid-block-materials.<版>.json` は、同じ版の展開済みPaperサーバーJARとAPI・ライブラリをクラスパスに入れ、`SharedConstants.tryDetectVersion()`、`Bootstrap.bootStrap()`、`CraftRegistry.setMinecraftRegistry(RegistryAccess.fromRegistryOfRegistries(BuiltInRegistries.REGISTRY))` の順で登録を初期化して抽出します。`Material.values()` のうち `!isLegacy() && isBlock() && !isAir() && isSolid()` を満たす名前を昇順で出力してください。照明欄は通常のブロック候補から空気を除いた一覧、柱の階段欄は固体候補のうち名前が `_STAIRS` で終わる一覧を使います。
- 完全に取り直す場合はEditorを停止し、`.cache/minecraft-icons/` 内の対象PNGを削除してから再起動します。ノードマスターや構造JSONには影響しません。

## デプロイとリロード

このエディタが変更するのはリポジトリ内のfilebaseと `10_plugin/AstralRecord/src/main/resources/config.yml` です。稼働サーバーへは通常のデプロイ手順でfilebaseを反映し、その後Pluginで `/masterdata reload` を実行してください。Skill Treeもこの一括リロードに含まれます。

ソース側 `config.yml` の変更は既存のPlugin data folderへ自動コピーされません。表示ワールド・構造・中心座標を変えた場合は、稼働環境の `plugins/AstralRecord/config.yml` もデプロイまたは同期してからリロードしてください。エディタが稼働サーバーの設定へ直接書き込むことはありません。

JSON Schemaで表現できないBukkit MaterialやスキルIDとの実在照合はPluginロード時にも行われます。ステータス候補は共有ステータスカタログと`.\60_tool\07-generate-status-types.bat`、タグ候補は共有タグカタログと`.\60_tool\08-generate-tag-types.bat`で更新してください。タグ生成では全filebaseの未定義タグと用途不一致も検査します。`/masterdata reload` が返すエラーを修正してから運用へ反映してください。

## 定義変更時の保守

マスターのキー・型・必須・列挙・参照・命名、読込・変換、装備比較やレベル成長式を変更した場合は、定義とこのサイトを同じ変更で整合させます。対象スキルから [Filebase 編集サイトの同期規則](../../.codex/skills/_shared/filebase-editor-sync.md) を読み、影響するServer / Clientと検証を確認してください。

定義書やJSON Schemaから生成する項目は、元資料の変更と「一覧と定義メタデータを再読込」で反映を確認します。特殊な候補・参照・検証・採番は `MasterDataCatalog` / `MasterDataValidation` / `MasterDataService`、画面は `MasterDataForm` / `MasterDataEditor`、計算は `MasterAnalyticsService` / `masterAnalytics.ts` を更新します。個別マスターの性能値・名前・説明文を既存契約内で調整するだけなら、動的反映を確認し、重複した定義をサイトのコードへ追加しません。

## トラブルシューティング

### `A compatible .NET SDK was not found`

`global.json`と互換の.NET SDKが必要です。`05-master-data-editor`フォルダー内で`dotnet --version`が成功することを確認してください。現在は10.0.302以降の互換Feature Bandが対象で、Runtimeや10.0.100だけの配置ではビルドできません。検出候補と実終了コードは、エラー画面に表示される診断ログで確認できます。

### `npm` / `node` が見つからない

`node` だけが見つかりnpmがない環境でも、Node.js 24 LTSのWindows ZIP版を展開して利用できます。`%LOCALAPPDATA%\AstralRecord\tools\node\node.exe`、同じディレクトリの `npm.cmd`、`node_modules\npm\bin\npm-cli.js` が揃うよう配置した後、`05-master-data-editor.bat` または `06-master-data-editor-build.bat` を実行してください。ユーザー・システムの `PATH` 変更は不要です。

別の配置先を使う場合は、起動するcmdで `set "ASTRALRECORD_NODE_HOME=C:\tools\node-v24.18.0-win-x64"`（または `NODE_HOME`）を指定します。BATはNode.jsのダウンロードやインストール、グローバルな環境変数変更を行いません。nvm利用時は本ディレクトリで `nvm use` を実行します。

### ASP.NET側で「frontend is not built」と表示される

`src/SkillTreeEditor.Client` で `npm ci` と `npm run build` を実行してください。開発時はASP.NETのURLではなくViteの `http://127.0.0.1:5173` を開きます。

### ワークスペースが見つからない
