# 地形解析とスポナー配置プレビュー

ワールドのコピーから地表を読み取り、既存のスポナーマスタを使った再配置案と未配置理由をローカルWebで比較するツールです。配置・削除・マスタ更新の実行機能はありません。既存配置にそのまま追加する案ではありません。

## 初回の対象

`eriva_supercontinent`（エリヴァ超大陸）の南西、X `[-1536,-768)` / Z `[1088,1856)` の768m四方。開始地点と最低レベルはworldマスタから取得します。現在はLv.15の草原・森林マスタを選定し、地形・バイオームのルールで振り分けます。LLMへの外部送信や常時AI呼出しは行いません。

## 準備・解析

1. `scanner/README.md` に従い補助プラグインをビルドします。
2. コピー元のDevを正常停止します。稼働中の `session.lock` が開いている場合、準備ツールは停止します。
3. `prepare-server.ps1` へ `-SourceServer`、`-SourceWorld`、`-ServerRoot`、`-ScannerJar` の絶対パスを渡します。ターゲットはPythonの `.venv` 以外が空であることを必須とし、既存サーバーは上書き・再利用しません。サーバーJAR、既存同意済みEULA、必要なライブラリとワールドだけをコピーします。DB/API認証設定やAstralRecord本体はコピーしません。
4. 解析先のJava 21で `java -Xms1G -Xmx3G -jar server.jar nogui` を実行します。既定の接続先は `127.0.0.1:25579`。補助プラグインが `analysis/terrain.json` を出力して正常停止します。元サーバーはコピー後に再開できます。コピー先でのサーバー起動時の保存・更新は元ワールドへ影響しません。
5. ワールド再解析時は解析サーバーが停止済みであることを確認し、同じ起動コマンドを使います。地形JSONは完了時にだけ置換します。

準備ツールは地表解析用の独立サーバーを作成します。AstralRecordの戦闘・API・ログイン統合を再現するサーバーではありません。既存worldの `uid.dat` / `xaeromap.txt` はコピー内で保持します。新旧world名の移行は `../world-identity-migration/README.md` を参照してください。

## Webの起動

Python 3.11以上の仮想環境を作り、`python -m pip install -r requirements.txt` を実行します。

```powershell
python server.py --terrain C:/server/AstralRecord-CodexDev/analysis/terrain.json --filebase C:/AstralRecord-Workspace/40_filebase --existing C:/server/AstralRecord-CodexDev/analysis/mob_spawners.source.yml
```

`http://127.0.0.1:8765` を開きます。`--policy` / `--port` で設定を切り替えられます。`--export <絶対JSONパス>` は既定の半径48mの配置案を保存して終了します。Webはloopbackにだけbindし、静的な3ファイルと読取データ・計画計算のAPIだけを公開します。外部ライブラリ・地図サービスの通信はありません。

- 地形、生息環境、配置・未配置理由のレイヤー切替。
- 地図の移動・拡大、開始地点への移動、クリックで地点の詳細。
- 既存配置の重ね合わせ、新配置の一覧とモブ・レベル・半径の確認。
- 半径32/48/64m、配置数上限1〜500の比較とJSONダウンロード。

## 判断と出力の契約

解析JSONは指定範囲の全4m区画を一度ずつ含むことを必須とします。未生成・読込失敗はunknownとし、欠落した区画を成功扱いにしません。各区画は16列を調べ、支持面と足・頭の空間を測定します。葉・幹を除く地表を上面から最大32ブロック下まで探索します。洞窟や屋内の網羅的解析ではありません。

配置の対象は安全列数8以上、区画内高低差4以下、選定済み生息環境、開始地点付近から足場接続のある区画です。接続の探索は各区画の16列を展開し、1ブロック隣接・足元高度差1以下で辿ります。開始位置と同じX/Z柱・高さ差1以内の実測足場を起点とし、配置候補の列まで到達できたかを確認します。地表から32ブロック下までの追加床も接続に使うため、開始地点の屋根下や浅い立体交差を扱えます。起点が読み取れない場合は接続不明として残し、近くの別地域へ自動で飛び越えません。細い橋や道は8列未満でも通過できます。道・階段・ハーフブロックも支持面として調べますが、人工床は森林バイオーム内でも配置環境へ分類しません。足場接続はプレイヤーの幅、ジャンプ・飛行・水泳、Mobの大きさや経路探索の証明ではありません。自然材質を使った人工建築の判定にも限界があります。開始地点の48m以内は保護対象です。新スポナーの出現円全体が保護範囲と解析境界を侵さないことを確認します。

候補中心は実測した足場のブロック中心です。被覆は区画の四隅が出現円内に入り、足元Yが現行探索の `原点Y-3` 〜 `原点Y+半径` に入り、環境が一致する場合だけ数えます。12mごとの候補から未カバー区画を多く覆うものを順に選びます。最小個数の数学的保証はありません。全区画へ結果を割り当て、候補制約や件数上限で残った場所を未カバーとして明示します。

カバー率の分母は上記条件を満たす地表であり、全ワールドではありません。既存配置は比較用に保存し、新案の被覆へ合算しません。新案は既存の高レベルMob、時間帯や報酬構成の再現ではなく、開始地域向けLv.15の再配置案です。半径の拡大は同じIDを使う全配置に影響し得るため、マスタ変更は別途検討します。円内の他環境への実スポーン、移動・アグロ範囲、クライアント上の戦闘、負荷は未検証です。

出力には地形SHA-256、ポリシー、既存配置、決定的な提案ID、座標、マスタID、半径差分、全区画の理由、被覆率、同時存在上限の単純合計を記録します。同じ入力・条件の再計算は同じ結果になります。`previewOnly: true` は必須で、適用データと誤認しないでください。

## 検証

既存配置との比較は件数と地図上の重ね合わせです。旧配置の被覆率・適性・バランス同等性は計算していません。

`python -m unittest -v test_planner.py` で人工地形を使い、全区画の結果・境界・保護円・不完全入力拒否・再実行・接続不明の扱いを検証します。本番マスタの整合確認とコピーした実ワールドの解析は別に実施します。
