# Plugin Docs Prompt

## 読むタイミング

- `E:\AstralRecord-Workspace\00_docs\10_プラグイン設計書\` 配下の Markdown 設計書を作成・改修するとき
- feature 設計書の採番、命名、分割、章構成を変更するとき
- ユーザー依頼が設計書編集かどうかを判断するとき

## 自動入力ルール

設計書編集を開始する前に、次を必ず読む。

1. `E:\AstralRecord-Workspace\00_docs\10_プラグイン設計書\README.md`（採番・命名・構造の正本）
2. `E:\AstralRecord-Workspace\00_docs\10_プラグイン設計書\feature\<feature>\NN_README.md`（対象 feature が特定できる場合）
3. 対応する実装コード（推測記述を避けるため）

## 実行ルール

1. `E:\AstralRecord-Workspace\00_docs\10_プラグイン設計書\README.md` の採番カテゴリ（`0/1/2/3/4/5/9`）を優先する。
2. 各カテゴリは原則ディレクトリ化し、`[機能番号] カテゴリ番号.詳細番号-名称.md` の採番で構成する。
3. メソッド仕様は `3-メソッド仕様/` 配下へレイヤー別（`[01] 3.01-イベント.md` / `[01] 3.02-サービス.md` / `[01] 3.03-コマンド.md` / `[01] 3.04-リポジトリ.md`）で記載する。
4. 1ファイルが長大な場合はカテゴリ内で詳細番号を増やして分割する。
5. 実装と一致しない情報は推測で埋めず、`90-*` に未確定事項として分離する。
6. 改修時は対象 feature の README 目次も同時更新する。
7. 参照は Obsidian の `[[参照]]` を使用する。

## 出力チェックリスト

- 更新ファイル一覧を提示したか
- 新規採番の理由を説明したか
- `docs/README.md` ルールからの逸脱有無を明記したか
