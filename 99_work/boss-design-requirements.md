# ボス機能 設計要件メモ

## 1. 目的

このメモは、AstralRecord のボス機能について正式なプラグイン設計書を作成する前に、設計対象となる要件を整理するための作業用資料である。

ボス機能は、既存の mob 機能における `BOSS` カテゴリを前提にしつつ、通常 Mob とは別にボス専用の挑戦管理、戦闘制御、インスタンスワールド制御を扱う。

## 2. 全体構成

ボス機能は大きく以下の 2 部構成とする。

| 区分 | 主な責務 |
|---|---|
| プレイヤーロジック | ボス挑戦中のプレイヤー状態、挑戦条件、死亡制御、制限時間、戦闘結果表示を管理する |
| ワールドロジック | ボスフィールドのコピー、インスタンス生成、パーティーのボスフィールド入場フローを管理する |

プレイヤーロジックは「誰が、どの条件で、どの状態としてボスに挑戦しているか」を管理し、ワールドロジックは「どのボスフィールドを、どのパーティー用に、どのように生成・破棄するか」を管理する。

## 3. プレイヤーロジック概要

プレイヤーロジックでは、ボス挑戦に参加するプレイヤー単位またはパーティーメンバー単位の状態を扱う。

### 3.1 ボスロジック実装

- ボスごとのフェーズ遷移、攻撃パターン、専用ギミックを定義する。
- ボス固有のロジックは通常 Mob の AI と切り分け、ボス専用実装として管理する。
- ボス個体ごとに現在フェーズ、行動クールダウン、ギミック状態を保持する。
- ボス戦開始、進行、討伐、失敗、強制終了のライフサイクルを定義する。

### 3.2 挑戦条件

- ボス挑戦ごとに制限時間を設定する。
- ボス挑戦ごとに死亡可能回数、またはパーティー全体のデスカウント上限を設定する。
- 参加可能なプレイヤー、パーティー人数、リーダー権限、参加中状態を検証する。
- 条件を満たさない場合は、挑戦を開始せずプレイヤーへ理由を表示する。

### 3.3 挑戦条件の表示

- ボス挑戦前に、制限時間、デスカウント、参加条件をプレイヤーへ表示する。
- 挑戦中は、残り時間、残りデスカウント、ボス HP、現在フェーズなどを表示対象とする。
- 表示方法は、チャット、タイトル、ボスバー、GUI のいずれを使うか設計書で定義する。

### 3.4 プレイヤー死亡制御

- ボス挑戦中の死亡を通常死亡と区別して扱う。
- 死亡時にデスカウントを加算または残機数を減算する。
- デスカウント上限に達した場合は、挑戦失敗として扱う。
- 死亡後に復帰させる場合は、復帰地点、復帰待機時間、復帰時の状態を定義する。
- 復帰させない場合は、観戦、退場、またはパーティー全体失敗のいずれにするかを定義する。

### 3.5 討伐結果表示

- ボス討伐時に、パーティー全体の合計ダメージを表示する。
- プレイヤー別の与ダメージ、死亡回数、貢献度などを表示対象とする。
- 結果表示の対象は、参加プレイヤー、観戦者、全体通知のどれにするかを定義する。
- 討伐成功、時間切れ、デスカウント超過、強制終了を区別して結果を表示する。

## 4. ワールドロジック概要

ワールドロジックでは、ボス戦を行う専用フィールドをパーティー単位で生成し、挑戦終了後に破棄する。

### 4.1 ボスフィールドコピー

- ボスごとに元となるテンプレートワールドまたはテンプレート領域を定義する。
- 挑戦開始時にテンプレートをコピーし、パーティー専用のボスフィールドインスタンスを生成する。
- インスタンス名、保存先、コピー元、コピー先、生成失敗時の扱いを設計書で定義する。
- コピー処理はサーバー負荷を考慮し、同期処理と非同期処理の境界を明確にする。

### 4.2 インスタンス生成・破棄

- ボスフィールドインスタンスは、挑戦開始から終了までの一時的なワールドとして扱う。
- インスタンスには、参加パーティー、対象ボス、開始時刻、制限時間、状態を紐づける。
- 挑戦終了時は、プレイヤー退場、Mob 破棄、ワールドアンロード、コピー先削除の順序を定義する。
- サーバー停止、プラグイン無効化、例外発生時の残存インスタンス掃除を定義する。

### 4.3 パーティー入場フロー

- パーティーリーダーがボス挑戦を開始する。
- 参加メンバーに挑戦条件を表示し、必要に応じて参加確認を行う。
- 条件を満たしたメンバーをボスフィールドインスタンスへ転送する。
- 転送完了後にボスをスポーンし、挑戦状態を開始する。
- 転送失敗、途中離脱、ログアウト、パーティー解散が発生した場合の扱いを設計書で定義する。

## 5. 想定フロー

1. パーティーリーダーがボス挑戦を選択する。
2. プレイヤーロジックが参加条件、制限時間、デスカウント条件を確認する。
3. ワールドロジックがボスフィールドテンプレートをコピーし、インスタンスを生成する。
4. パーティーメンバーをインスタンスへ転送する。
5. ボスをスポーンし、挑戦を開始する。
6. 挑戦中は、残り時間、デスカウント、与ダメージ、ボス状態を更新する。
7. 討伐、時間切れ、デスカウント超過、強制終了のいずれかで挑戦を終了する。
8. 結果表示を行い、報酬処理または失敗処理へ連携する。
9. プレイヤーを退場させ、ボスフィールドインスタンスを破棄する。

## 6. 正式設計書化時の分割候補

正式な `00_docs/10_プラグイン設計書` 配下へ移す場合は、以下の観点で分割する。

| 設計書カテゴリ | 記載対象 |
|---|---|
| 概要 | ボス機能の目的、既存 mob / party / world との関係 |
| モデル定義 | ボス挑戦、参加プレイヤー、ボスインスタンス、ボスフィールドインスタンス |
| ユースケース | 挑戦開始、入場、死亡、討伐、失敗、退出、強制終了 |
| メソッド仕様 | サービス、イベント、コマンド、GUI、タスク、キャッシュ |
| 統合フロー | パーティーからボス挑戦開始、インスタンス生成、戦闘終了、破棄 |
| 例外・ログ・運用 | コピー失敗、転送失敗、残存ワールド掃除、サーバー停止時処理 |
| 未決事項 | 仕様判断が必要な挑戦条件、報酬、観戦、途中参加、ログアウト対応 |

## 7. 値の出所

ボス機能で参照する値は、以下の場所を正とする。

| 値 | 取得元 | 方針 |
|---|---|---|
| ボス ID | ボスマスター | 既存の boss YAML `id` を使用する |
| ボス表示名 | ボスマスター | 既存の boss YAML `name` / `title` を使用する |
| ボス基礎 HP | ボスマスター | 既存の `baseStats[].status = MAX_HEALTH` を使用する |
| ボス基礎攻撃力 | ボスマスター | 既存の `baseStats[].status = ATTACK` を使用する |
| ボスドロップ | ボスマスター | 既存の `drops` を使用する |
| ボス経験値 | ボスマスター | 既存の `drops.exp` を使用する |
| 制限時間 | ボスマスターに追加 | `challenge.timeLimitSeconds` として定義する |
| デスカウント上限 | ボスマスターに追加 | `challenge.deathLimit` として定義する |
| ボス挑戦座標 | ボスマスターに追加 | `challenge.entryLocation` として定義する |
| ボス挑戦判定半径 | ボスマスターに追加 | `challenge.entryRadiusMeters` として定義し、初期値は `2.0` とする |
| ボスフィールド | ボスマスターに追加 | `challenge.battleWorldId` として WorldMasterData の `id` を参照する |
| ボススポーン座標 | ボスマスターに追加 | `challenge.bossSpawnLocation` として定義する |
| プレイヤー入場座標 | ボスマスターに追加 | `challenge.playerSpawnLocation` として定義する |
| ボス待機ハブ | `config.yml` | `boss.hubWorldId` として WorldMasterData の `id` を定義する |
| インスタンス生成元 | WorldMasterData | `baseWorldPath` を使用する |
| インスタンス生成先 | WorldMasterData | `instanceRootPath` を使用する |
| インスタンス可否 | WorldMasterData | `worldType = BOSS_FIELD` かつ `instanceEnabled = true` を要求する |

ボスマスターは既存の `40_filebase/40.features.mob/boss/*.yml` を拡張する想定とする。ボスの戦闘定義と挑戦定義を分離した別マスターは作らず、1 つのボス定義から戦闘・報酬・入場条件を解決できる形にする。

追加する `challenge` 定義のイメージは以下とする。

```yaml
challenge:
  entryLocation:
    worldId: v1.central_base
    x: 100.5
    y: 64.0
    z: -32.5
    yaw: 0.0
    pitch: 0.0
  entryRadiusMeters: 2.0
  hubMessage: "&eパーティーメンバーの集合を待機しています"
  battleWorldId: v1.dark_dragon_field
  playerSpawnLocation:
    x: 0.5
    y: 80.0
    z: 0.5
    yaw: 180.0
    pitch: 0.0
  bossSpawnLocation:
    x: 0.5
    y: 80.0
    z: -20.5
    yaw: 0.0
    pitch: 0.0
  timeLimitSeconds: 600
  deathLimit: 5
  scaling:
    hpPerAdditionalMemberRate: 0.45
    attackPerAdditionalMemberRate: 0.15
```

`config.yml` 側には以下を追加する想定とする。

```yaml
boss:
  hubWorldId: "v1.boss_hub"
```

## 8. 報酬仕様

### 8.1 討伐成功時

- ボス討伐成功時の報酬は、ボスマスターの `drops` に設定されたドロップアイテム、lootTable、経験値、お金を使用する。
- ドロップ抽選、経験値付与、所持品付与は通常 Mob と同じ処理を使用する。
- 報酬条件は参加プレイヤーごとに変更しない。
- 与ダメージ量、参加時間、職業、役割による報酬差は付けない。
- サポート職やタンク職など、与ダメージが低くなるビルドを予定しているため、参加メンバーには同じ条件で報酬を付与する。
- ボス討伐時は通常 Mob より豪華な討伐演出を行う。
  - 通常 Mob の死亡エフェクトを置き換えるか、ボス討伐時だけ追加エフェクトを重ねる。
  - エフェクト内容はパーティクル、サウンド、タイトル表示を組み合わせる。
  - 報酬抽選ロジック自体は通常 Mob と同一にする。

### 8.2 失敗時

- 時間切れ、デスカウント超過、全参加者ログアウト、管理者強制終了はボス挑戦失敗として扱う。
- ボスを討伐していないため、ドロップ、経験値、お金は発生しない。
- 失敗時は結果表示だけを行い、報酬処理へは進めない。

### 8.3 報酬対象

- ボス報酬は、ボス挑戦インスタンスに参加しているパーティーメンバーだけを対象とする。
- パーティー外プレイヤーには報酬を付与しない。
- ボス挑戦開始後にパーティーへ参加したプレイヤーは、ボスフィールドへ入場できず、報酬対象にもならない。
- ボスに限らず通常 Mob のドロップでも、報酬対象プレイヤーは対象 Mob が討伐されたワールドにいることを必須条件とする。
- ダメージを与えたプレイヤーであっても、討伐時に対象 Mob と同じワールドにいない場合は報酬対象外とする。
- パーティーメンバー共有報酬でも、対象 Mob と同じワールドにいないメンバーは報酬対象外とする。

## 9. ボス挑戦開始フロー

### 9.1 挑戦座標

- ボスマスターの `challenge.entryLocation` に、ボス挑戦座標を定義する。
- `challenge.entryRadiusMeters` は既定 `2.0` とする。
- ボス挑戦座標の半径 `entryRadiusMeters` の円をパーティクルで表示する。
- プレイヤーが円内でスニークした場合、ボス挑戦受付として扱う。
- 円外でのスニークや、バニラコマンド等によるハブワールドへの直接移動はボス挑戦受付として扱わない。

### 9.2 待機フラグ

- ボス挑戦座標からハブワールドへ移動したプレイヤーに、ボス単位の待機フラグを付与する。
- 待機フラグは `bossId`、`partyId`、`playerId`、受付時刻、対象ハブワールド ID を保持する。
- 待機フラグがないプレイヤーは、同じハブワールドにいてもボス待機中とは判定しない。
- 待機フラグは、ボスフィールド転送、挑戦キャンセル、ログアウト、挑戦終了時に解除する。

### 9.3 ソロ挑戦

- プレイヤーがパーティーに所属していない場合は、1 人パーティー相当のボス挑戦として扱う。
- プレイヤーを `config.yml` の `boss.hubWorldId` で定義されたハブワールドへ転送する。
- ハブ転送後、すぐにボスフィールドインスタンス作成を開始する。
- インスタンス作成完了後、自動でボスフィールドへ転送して挑戦を開始する。

### 9.4 パーティー挑戦

- プレイヤーがパーティー所属中の場合、所属パーティー全体をボス挑戦単位とする。
- ボス挑戦受付はパーティーリーダーに限定する。
- 受付後、パーティーメンバー全員を対象として待機状態を作る。
- 各メンバーはボス挑戦座標からハブワールドへ移動した時点で待機フラグを持つ。
- パーティーメンバー全員がハブワールドに集合するまで、ボスフィールドの作成が完了していても挑戦は開始しない。
- ハブワールドで待機中のプレイヤーには、パーティーメンバーの集合待ちであることをタイトルバーで表示する。
- 全員集合後、自動でボスフィールドへ転送して挑戦を開始する。

### 9.5 途中参加・再入場

- 途中参加は許可しない。
- 再入場は許可しない。
- ボス挑戦開始後にパーティーへ参加したプレイヤーは、待機フラグを持たず、ボスフィールドにも転送されない。
- ボス挑戦中にパーティー外のプレイヤーが同じパーティーへ参加しても、そのプレイヤーは報酬対象外とする。

## 10. インスタンス生成・掃除

### 10.1 生成

- ボスフィールドは、ボスマスターの `challenge.battleWorldId` から WorldMasterData を取得して生成する。
- 対象 WorldMasterData は `worldType = BOSS_FIELD` かつ `instanceEnabled = true` であることを必須とする。
- コピー元は WorldMasterData の `baseWorldPath`、コピー先ルートは `instanceRootPath` とする。
- インスタンス名は `boss_<bossId>_<partyId>_<timestamp>` のように、ボス ID とパーティー ID から一意に生成する。
- コピー処理は可能な限り非同期で行う。
- Bukkit API が必要なワールドロード、テレポート、Mob スポーンはメインスレッドで実行する。
- インスタンス生成に時間がかかってもよく、生成中はプレイヤーをハブワールドで待機させる。

### 10.2 破棄

- 挑戦終了後は、参加プレイヤー退場、ボス Mob 破棄、ワールドアンロード、コピー先フォルダ削除の順に処理する。
- 挑戦終了理由は、討伐成功、時間切れ、デスカウント超過、全参加者不在、管理者強制終了に分類する。
- 破棄失敗時はログを残し、次回起動時の掃除対象に回す。

### 10.3 起動時掃除

- サーバークラッシュやプラグイン無効化でコピー先ワールドが残る可能性がある。
- プラグインロード時に WorldMasterData をロードした後、`worldType = BOSS_FIELD` かつ `instanceEnabled = true` の `instanceRootPath` 配下をインスタンスワールドとして削除対象にする。
- 削除対象は WorldMasterData に定義された `instanceRootPath` 配下に限定する。
- 管理者コマンドによる残存ワールド掃除は不要とする。

## 11. 戦闘中のパーティー・ログアウト制御

### 11.1 ログアウト

- ボス挑戦中にパーティーメンバーがログアウトしても、残りメンバーがいる限り挑戦状態は変更しない。
- ログアウトしたプレイヤーはボスフィールドから離脱した扱いとなり、再入場できない。
- ログアウトしたプレイヤーが最後の参加者だった場合、ボス挑戦失敗として扱い、フィールドを削除する。
- パーティーリーダーがログアウトした場合は、既存の party feature に従ってリーダーが切り替わるだけで、ボス挑戦は継続する。
- パーティーに後から加入したメンバーが別ワールドに残っているだけの場合、そのメンバーはボス挑戦中の参加者として扱わない。
- 例として、3 人でボス挑戦開始後に 4 人目がパーティーへ参加し、挑戦中の 3 人が全員ログアウトした場合、パーティー自体に 4 人目が残っていてもボス挑戦は失敗として終了する。

### 11.2 パーティー解散・離脱

- ボス挑戦中は自発的なパーティー解散を抑制する。
- ボス挑戦中は、パーティー GUI やコマンドからの解散操作をエラーにする。
- パーティーメンバーがログアウトにより全員不在になった場合のみ、party feature 側の通常処理としてパーティーが空になる。
- ボス挑戦側は、パーティー全体ではなく「ボスフィールドにいる参加者」が 0 人になったことを見て挑戦失敗を確定する。

## 12. ボススケーリング

- ボスの HP と攻撃力は、挑戦開始時の参加人数に応じて補正する。
- 補正対象人数は、ボス挑戦開始時にボスフィールドへ転送される参加者数とする。
- 途中参加は許可しないため、挑戦開始後に人数補正は変化させない。
- 基礎値はボスマスターの `baseStats` を使用する。
- 初期案として以下の計算式を採用する。

```text
補正HP = 基礎HP * (1 + max(0, 参加人数 - 1) * challenge.scaling.hpPerAdditionalMemberRate)
補正攻撃力 = 基礎攻撃力 * (1 + max(0, 参加人数 - 1) * challenge.scaling.attackPerAdditionalMemberRate)
```

- 初期値は `hpPerAdditionalMemberRate = 0.45`、`attackPerAdditionalMemberRate = 0.15` とする。
- この値はボスマスターに定義し、ボスごとに調整可能にする。

## 13. ダメージ集計

- ボス挑戦中は、参加プレイヤーごとの与ダメージを統計する。
- 集計はダメージ共通制御で行う。
- 既存実装では `DamageService` が custom combat のダメージ適用を一元化しているため、正式実装時はこの境界でボス挑戦中かを判定し、対象ボスの参加者別ダメージへ加算する。
- 集計対象は、実際に HP またはシールドへ反映されたダメージとする。
- 無敵状態の Mob は共通ダメージ処理内で最終ダメージが `0` になる想定のため、無敵フェーズ中の攻撃は与ダメージとして加算されない。
- オーバーキルは共通ダメージ処理内で残り HP を上限に丸める。
- 例として、残り HP が `100` のボスへ `500` ダメージを与えた場合、集計値は `100` とする。
- 召喚、継続ダメージ、スキルによるダメージも共通ダメージ処理を通す前提とし、同じ集計規則を適用する。

## 14. 管理者コマンド

- 強制開始コマンドは不要とする。
- 強制終了コマンドを用意する。
- インスタンス一覧コマンドを用意する。
- 残存ワールド掃除コマンドは不要とする。

想定コマンドは以下とする。

| コマンド | 用途 |
|---|---|
| `/boss instances` | 現在稼働中のボス挑戦インスタンス一覧を表示する |
| `/boss stop <partyId>` | 指定パーティーのボス挑戦を強制終了する |

`/boss instances` では、partyId、bossId、状態、参加者数、ワールド名、開始時刻、残り時間を表示する。

`/boss stop <partyId>` は、対象パーティーがボス挑戦中の場合だけ成功し、終了理由を管理者強制終了として記録する。

## 15. 結果表示

- 討伐成功時は、ボス名、討伐時間、残りデスカウント、パーティー合計ダメージ、プレイヤー別与ダメージを表示する。
- 失敗時は、失敗理由、経過時間、パーティー合計ダメージ、プレイヤー別与ダメージを表示する。
- 結果表示はボスフィールドに参加していたプレイヤーを対象にする。
- ログアウト済みプレイヤーには表示しない。
- 結果表示後に報酬処理、退場処理、インスタンス破棄へ進む。

## 16. カウント管理

### 16.1 参加者カウント

- ボス挑戦受付時点のパーティーメンバーを参加予定者として固定する。
- ソロ挑戦の場合は参加予定者数 `1` とする。
- 参加予定者数は、ハブ集合待ち表示、ボススケーリング、挑戦開始時の参加者検証に使用する。
- ボス挑戦受付後にパーティーへ参加したプレイヤーは参加予定者数に含めない。
- ボス挑戦開始後にログアウトしたプレイヤーは、結果表示や報酬対象からは除外されるが、開始時参加者としてダメージ統計や終了判定の履歴には残す。

### 16.2 ハブ集合カウント

- ハブ集合カウントは、参加予定者のうち、対象ボスの待機フラグを持ち、`config.yml` の `boss.hubWorldId` で定義されたハブワールドにいるオンラインプレイヤー数とする。
- タイトルバーには `集合待ち: <集合済み>/<参加予定者数>` のように表示できる形にする。
- ボスフィールドインスタンス作成が完了していても、集合済み人数が参加予定者数に達するまでは自動転送しない。
- 参加予定者がログアウトした場合は、そのプレイヤーを集合待ちから除外せず、ログアウトとして扱う。
- 参加予定者が全員ログアウトした場合は挑戦失敗として終了する。

### 16.3 デスカウント

- デスカウント上限はボスマスターの `challenge.deathLimit` を正とする。
- デスカウントはパーティー全体で共有する。
- ボス挑戦中に参加者が死亡した回数を `currentDeathCount` として挑戦インスタンスに保持する。
- `currentDeathCount >= challenge.deathLimit` になった時点で、デスカウント超過による挑戦失敗とする。
- プレイヤー別死亡回数は結果表示用の統計として保持する。
- ボス挑戦外の通常死亡はボスのデスカウントへ加算しない。

### 16.4 制限時間カウント

- 制限時間はボスマスターの `challenge.timeLimitSeconds` を正とする。
- 制限時間の開始時刻は、全参加予定者をボスフィールドへ転送し、ボスをスポーンして挑戦状態を `IN_PROGRESS` にした時点とする。
- ハブ待機中やインスタンス作成中は制限時間を進めない。
- 残り時間は `challenge.timeLimitSeconds - (現在時刻 - startedAt)` で算出する。
- 残り時間が `0` 以下になった時点で、時間切れによる挑戦失敗とする。

### 16.5 ボス HP カウント

- ボス HP は、ボスマスターの `baseStats.MAX_HEALTH` に参加者数補正を適用した値を最大 HP とする。
- 現在 HP はボス Mob インスタンス側の `currentHealth` を使用する。
- 結果表示や HUD 表示では、補正後最大 HP と現在 HP を使用する。
