# パーソナライズの記録と整理

メモの追加・更新・移動と、索引の整理をするときに参照します。

## 記録する内容

- 継続する要望としてユーザーが明示した内容や、確定済みで次回の判断を変える理由を記録します。ユーザーの指示と、実装・テストから確認した判断は、根拠が分かるように書きます。
- レビューからは、成立条件と採用する対応が確かめられ、今後も判断を誤りやすい理由を残します。既存のガイド・スキルで扱う手順は、正本へのリンクで示します。
- 各メモは一つの判断テーマを扱い、冒頭に適用する場面を書きます。判断と理由を短く記し、根拠・コード・テスト・正本資料への確認先を添えます。
- 作業経過や未確定の案は、その依頼の会話で扱います。更新履歴はGitから確認できます。

- 機能別の作業ルールは `00_docs/10_AIパーソナライズ/` の対象領域に置きます。`AGENTS.md` と `CLAUDE.md` はルートの入口として管理します。

## 追加・更新する手順

1. [索引](README.md)から対象領域を選び、既存の索引とメモを確認します。同じ判断は既存メモを更新し、複数の領域で使う判断は一つの正本に集約して適用場面を広げます。
2. 同じ話題を探す際は、対象領域に対して `rg -l --glob '*.md' '<語句>' <対象領域>` で候補のファイル名を絞り、該当ファイルを読みます。
3. 独立した話題は、対象領域の下へ内容が分かる日本語のファイル名で追加します。現在の分類は `共通/`、`プラグイン/`、`API/`、`ツール/`、`ゲームデザイン/`、`Web/`、`ファイルベース/`、`リソースパック/` です。新しい領域が必要になった時点で追加します。
4. 読む場面とリンクを、最も近い索引へ一行で登録します。複数領域に関係するメモは、各領域の索引から同じ正本へ案内します。機能別の作業ルールを追加・移動するときは [対象プロジェクト](対象プロジェクト.md) の `Read Next` と関係する案内も更新します。

## 更新時に整理する目安

整理は、新規記録・更新・移動の際に、今回触る領域で行います。

| 状態 | 行う整理 |
|---|---|
| 一つのメモが80行・4,000文字のいずれかを超える、または別々に読める話題が3件になる | 話題ごとに分割し、各メモの適用場面を明確にする |
| 領域内のメモが4件になる | その領域に `README.md` を設け、上位索引を領域の入口へまとめる |
| 一つの索引が8項目を超える、またはルート索引が40行を超える | 依頼の対象・操作で分かれる下位索引を設け、上位には分類と読む場面を置く |
| 同じ判断が複数のメモにある | 正本を一つにまとめ、参照元をその正本へ向ける |
| 所属する領域と実際の適用対象がずれる | 適切な領域へ移し、関係する索引の読む場面を更新する |
| 新しい確定事項で古い判断が置き換わる、または前提の機能が廃止される | 現行本文と索引を更新し、古い内容はGitの履歴で追える状態にする |

行数・文字数・件数は、必要な判断を一度に選べる分量に保つための目安です。関連する判断を一緒に読む必要があるかも確認して分割します。索引には、分類・読む場面・参照先を載せます。

## 整理後に確認すること

変更した領域の上位索引から各メモへ辿れることを確認します。移動・削除したパスをリポジトリ内で検索し、ガイド・スキル・資料からのリンクも更新します。重複した判断と、適用条件が失われた記述を対象領域で見直します。
