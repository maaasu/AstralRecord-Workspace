# AstralRecordのAIパーソナライズ

次の依頼でも使う開発上の希望や、機能をこの形にした理由を日本語で記録します。

## 読むとき

- [開発方針](開発方針.md)には、複数の依頼に共通するユーザーの要望を置きます。
- [機能の判断](機能の判断.md)には、機能を変更するときに判断を誤りやすい理由や前提を置きます。
- [APIの探し方](APIの探し方.md)には、内部APIの実装と呼び出し元への入口を置きます。
- 実装・レビュー・修正では、依頼の対象に関係する見出しだけを確認します。現在の挙動と具体的な条件は、参照先のコード・テスト・設定で確認します。今回の依頼に明示された条件を過去のメモより優先します。作業手順は `AGENTS.md` と該当スキルで確認します。

## 記録するとき

- 次の作業でも判断が変わるものを記録します。継続する要望として明示された内容や、採用した理由をユーザーの指示・実装・テストなどで確認できる決定が対象です。
- 既存の見出しを探し、同じ話題はそこを更新します。要望や決定、理由、確認できる根拠を短く書きます。詳細は元のコードやガイドへリンクします。
- レビューから記録するのは、指摘の成立条件と採用する対応が確かめられ、次回も判断を誤りやすい前提や理由があり、既存の方針やスキルと重複しない場合です。変更の中で直接防げる問題は、該当の実装や検証で扱います。
- 対象機能の見出しには、適用する場面、採用した判断と理由、確認先を書きます。ユーザーが明示した要望と、実装やテストから確認した判断は、根拠が分かるように記します。作業経過と未確定の案はその依頼で扱い、履歴はGitから追えます。
- 記録が探しにくくなったときは、関連する見出しをまとめてから、必要な話題だけをファイルへ分けます。索引には読む場面を一行で添えます。
