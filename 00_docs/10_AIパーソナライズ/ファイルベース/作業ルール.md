# AstralRecord Filebaseの作業ルール

対象は `40_filebase/` です。YAML・JSON のマスタデータを作成・修正するときに参照します。

## 役割

- YAML / JSON などの file 系マスタデータと、そのスキーマ資料を管理する。
- SQL Server の DB / テーブル定義は管理しない。DB 定義は [Database設計書](../../40_Database設計書/README.md) で管理する。

## 作業方針

- マスタデータを作成・修正する前に [Filebase設計書](../../50_Filebase設計書/README.md) を読み、同設計書の対象カテゴリ `feature/<number>-<category>.md` と `作成時チェックリスト.md` を確認する。
- file マスタを変更する場合は、Plugin と API の読み込み処理、Resource Pack の参照、関連ドキュメントへの影響を確認する。
- `40_filebase/config.yml` のパス解決ルールと、対象カテゴリの YAML スキーマ定義または JSON Schema を優先する。
- マスタデータの ID、カテゴリ、参照先が実装やリソースパックと矛盾しないか確認する。
- 本番向け YAML の先頭コメントへ、`00_docs/50_Filebase設計書/README.md` で定義された `motif` と `progression` を記載する。JSON はコメントを持てないため、対象 JSON Schema に設計メタデータが定義されている場合だけ、そのフィールドへ記載する。

## ゲーム進行フローの事前確認

- マスタデータの新規作成と進行に関わるリメイクでは、先に[ゲーム進行フロー](../../50_Filebase設計書/feature/95-game_flow.md)の案を作り、対象データ、作成・変更内容、進行の順序・条件・分岐を示す。未作成の参照先は、予定名と役割をメモノードに置く。
- 既存エディタの図を使ってキャプチャする。必要に応じて、フロー定義からローカルスクリプトで HTML や画像を出力する。図と作成・変更する内容をユーザーに提示し、承認を得てからマスタデータを実装する。
