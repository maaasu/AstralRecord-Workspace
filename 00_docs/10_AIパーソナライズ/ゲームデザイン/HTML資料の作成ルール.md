# ゲームデザイン設計書のHTML資料の作成ルール

`00_docs/20_ゲームデザイン設計書/` 以下でHTML資料を新規作成・修正するときに適用します。どの作業者が作っても同じ見た目・構成・書き方になることを目的とし、迷ったら基準HTMLの実装をそのまま使います。

## 1. 基準HTMLと共通部品

| 基準 | 参照する内容 |
|---|---|
| [DPS指標](../../20_ゲームデザイン設計書/01-DPS指標.html) | ページの骨格、1枚の大きなグラフ、レベル別の表、計算方法の章、基準値の帯 |
| [ステータス指標](../../20_ゲームデザイン設計書/02-ステータス指標.html) | 所有者・役割による章立て、章内目次、カード型のグラフと表、追従するレベル操作、状態の分類タグ付きの表 |

- 次の共通部品は**全HTMLで同一の内容**にします。新しい資料には基準HTMLから文字どおり複写し、資料ごとに書き換えません。
  - CSSの `/* ===== 共通: 資料タブ・目次・章番号・能力の色分け ===== */` から `/* ===== 共通ここまで ===== */` まで
  - `// 目次:` で始まる `<script>`（読んでいる章の強調、折りたたみ章を開く処理）
  - `.spot-slot` / `.spot-field` のスポットライト用CSSと `<script>`
  - 目次の前に共通のページ内検索（検索欄・CSS・スクリプト）を置きます。HTMLを直接開いて検索結果を選ぶと、一致箇所へ移動し、該当する語を強調します。
- 共通ブロックの `:where(#dps-stat-guide, #stat-guide, #stat-allocation-guide, #equipment-stat-guide)` には各資料の `main` のIDを並べます。資料を追加したら、全HTMLのこのセレクタに新しいIDを加えます。
- 資料固有のCSSクラスには資料ごとの接頭辞を付けます（DPS指標は `dg-`、ステータス指標は `st-`、配分基準は `sa-`、装備基準は `es-`）。共通部品のクラス名（`doc-` `toc-` `ch-` `cat` `fx-`）を資料固有の用途に流用しません。
- 共通デザインを変えるときは、このファイルと全HTMLを同じ変更でそろえます。各資料の指標・数値・計算式は、その資料の仕様に従います。

## 2. ファイル名と資料タブ

- ファイル名は `NN-資料名.html`。`NN` は2桁の連番で、欠番を作りません。
- ページ最上部の資料タブ（`.doc-nav`）に、全資料を番号付きで同じ順に並べます。表示中の資料に `aria-current="page"` を付けます。資料を追加したら全HTMLのタブに追加します。

次の `href` は、対象フォルダに置く各 HTML を基準に解決します。

```html
<nav class="doc-nav" aria-label="ゲームデザイン設計書">
  <a href="01-DPS指標.html" aria-current="page"><span class="doc-no">01</span>DPS指標</a>
  <a href="02-ステータス指標.html"><span class="doc-no">02</span>ステータス指標</a>
  <a href="03-ステータス配分基準.html"><span class="doc-no">03</span>ステータス配分基準</a>
  <a href="04-装備ステータス基準.html"><span class="doc-no">04</span>装備ステータス基準</a>
</nav>
```

## 3. ページの骨格

要素の順序は固定です。

```html
<main id="<資料のID>">
  <nav class="doc-nav">…資料タブ…</nav>
  <header><h1>資料名</h1></header>
  <div class="doc-lead">
    <p>何の資料かを1文で。</p>
    <div class="cat-key" aria-label="ステータスの分類">…7分類のタグ（5章）…</div>
  </div>
  <div class="doc-layout">
    <aside class="doc-toc" aria-label="目次">
      <p class="doc-toc-title">目次</p>
      <ol>…章と節…</ol>
    </aside>
    <div class="doc-body">
      …レベル操作（7章）…
      …本文の章…
      …付録の章（基準案など）…
      …計算方法の章（必ず最後）…
    </div>
  </div>
</main>
```

## 4. 章立てと目次

- 章は `1` `2` …、節は `1.1` `1.2` … と番号を振ります。章見出しは `<span class="ch-num">1</span>`、節見出しは `<span class="sub-num">1.1</span>` を見出し文字の前に置きます。
- 章は**所有者**（プレイヤー、標準モブなど）で分け、節は**役割**で分けます。例: 被弾時のステータス（HP・防御・耐性）、攻撃のステータス（通常攻撃）、特化ビルド。1つの節には同じ役割の指標だけを入れます。
- 左の目次（`.doc-toc`）には全章と全節を載せます。読んでいる位置は共通の目次スクリプトが強調します。1080px以下では章だけのボタン列になります。
- 所有者でまとめた章は、見出しと短い説明の直後に章内目次（`.ch-toc`）を置きます。1行に、節番号・節名・その節に含む指標・分類タグを並べます。

```html
<ol class="ch-toc" aria-label="2章の内容">
  <li><a href="#mob-defense"><span class="toc-num">2.1</span><span class="ch-toc-title">被弾時のステータス</span><span class="ch-toc-desc">最大HP・共通防御・追加防御・属性耐性</span><span class="cat-list">…分類タグ…</span></a></li>
</ol>
```

- 所有者の色は章にだけ使います。プレイヤーは青（`--blue`）、標準モブは金（`--gold`）です。章の `section` に `--actor` を設定し、章番号・節番号・章見出しの下線（2px）をその色にします。計算方法など所有者のない章は `--axis` にします。
- 各節は見出し（`h3`）と1文の説明の後にカードを並べます。カードは、上段に「攻撃側 → 被弾側｜条件」と分類タグ、続いて指標名（`h4`）、1文の注記、凡例、グラフ、表の順に置きます。

## 5. ステータスの分類と色

色分けは設計書共通の7分類と以下の配色にそろえます。各ステータスの分類は、ステータス指標に掲載する同じステータスの分類に合わせます。 [ステータス指標](../../20_ゲームデザイン設計書/02-ステータス指標.html)

| 分類 | クラス | 色（画面） | 主なステータス |
|---|---|---|---|
| リソース | `cat-resource` | `#98c379` | 最大HP・最大MP・最大ENG・最大シールド |
| 基本能力値 | `cat-primary` | `#d19a66` | 筋力・器用さ・知力・体力・敏捷性・幸運 |
| 攻撃 | `cat-offense` | `#e06c75` | 攻撃力・会心・超星会心・命中・攻撃速度・貫通・ライフスティール |
| 防御 | `cat-defense` | `#56b6c2` | 防御力・回避率・被ダメージ軽減率 |
| 属性 | `cat-element` | `#c678dd` | 属性ダメージ増加・属性耐性・属性貫通 |
| 状態異常 | `cat-condition` | `#e8a0c8` | 状態異常の付与確率・付与耐性・継続ダメージ |
| ユーティリティ | `cat-utility` | `#a8b0bd` | HP・MP・ENG回復力、移動速度、クールダウン短縮 |

- 分類タグは `<span class="cat cat-offense">攻撃</span>`。複数あるときは `<span class="cat-list">` でまとめます。
- タグを付ける場所: ページ上部の分類の凡例（7分類すべて）、各カードの右上、章内目次、計算式カードの右上、基準案などの表の行見出し。
- 計算式の変数チップや計算例の数値にも、同じ分類の色を使います（8章）。
- 分類の色は分類の表示にだけ使います。グラフの系列色（青・金・緑・紫）や所有者の色とは役割を分けます。
- 設計書の共通分類を追加するときは、全資料の共通ブロックとこの表を更新します。

## 6. 配色・文字・余白

| 項目 | ルール |
|---|---|
| 画面幅 | `main` は幅100%。PCでも狭い最大幅を設けない。左目次は212px、本文との間隔は40px |
| 外側の余白 | PCは上下28px・左右32px。760px以下は20px・16px、420px以下は18px・12px |
| 配色 | マスターデータエディタと同じチャコール系。背景 `#21252b`、パネル `#282c34`、表見出し `#303640`、本文 `#cdd3de`、補足 `#abb2bf`、罫線 `#3c424d`。選択は面 `#323e50` とアクセント `#8ab8eb`。OSのライト・ダーク設定によらずダーク配色 |
| フォント | `"Segoe UI", "Yu Gothic UI", Meiryo, sans-serif`。数値は `tabular-nums` で桁をそろえる |
| 文字 | 大見出し28〜36px・太さ600・字間を詰めない。章見出し18〜23px、節見出し19px、カード見出し17px。表・凡例15px、表見出し・吹き出し・注記14px、軸目盛り・補足13px、タグ12px |
| 枠 | パネルとカードは1pxの罫線と10pxの角丸。計算式の枠は8px、タグは4px |
| 表 | セルは1pxの罫線で区切り、見出しは `#303640`。選択行は `#323e50` の面と左端3pxの青線 |

## 7. 書き方と、使わない表現

### 書き方

- リード文は「何の資料か」を1文で書きます。例: 「同格の1対1で使う、プレイヤーと標準モブの設計値。」
- 操作方法を本文・注記・リードに書きません（「ホバーで拡大できます」「凡例で線を選択できます」「タップすると〜」など）。操作は見た目と挙動で伝えます。読み上げ用の補足（`.dg-sr` など画面に出ないもの）は例外です。
- である調・体言止めで、短く書きます。数値には単位を付けます。
- 戦闘の条件は「攻撃側 → 被弾側｜条件」と書きます。例: `標準モブ → プレイヤー｜被弾時`。
- **未決事項を書きません。** TODO、未確定、要調整、実装待ち、現行値と目標値の食い違いの指摘、中身の決まっていない項目は載せず、決まった値・式・条件だけを書きます。
- 比較用の案は、名前に「案」と付けて（例: 装備なし基準案）、値がそろっているものだけ載せます。設計目標・現行値・案は区別して書きます。

### 使わない表現

- 青文字に下線のリンク。リンクは見出しと同じ色で、下線を付けません。資料間の移動は資料タブ、章間の移動は目次で行います。
- 矢印記号の付いたリンク（`↓` `→`）。矢印は、戦闘方向の表記と計算の流れ図だけに使います。
- タイトルの上に置く小さなラベル、ピル型の装飾、色付きの左帯、色付きの背景を持つ見出しラベル（分類タグを除く）、カード上端の色線、グラデーション、絵文字。
- 吹き出しの中のミニグラフ。
- `letter-spacing` を負にした見出し。

## 8. 計算式の表し方

計算は文章で書かず、計算式カード（`.fx-card`）で見せます。計算方法の章は資料の最後に置き、1枚のカードに1つの指標をまとめます。

```html
<section class="fx-card" id="fx-mob-hp" aria-labelledby="fx-mob-hp-title">
  <div class="fx-card-head"><h3 id="fx-mob-hp-title"><span class="sub-num">4.4</span>標準モブの最大HP</h3><span class="cat-list"><span class="cat cat-resource">リソース</span></span></div>
  <div class="fx">
    <var class="fx-var cat-resource">最大HP</var><span class="fx-op">=</span>
    <var class="fx-var cat-offense">標準実効DPS<small>同格のプレイヤー</small></var><span class="fx-op">×</span><span class="fx-num">7秒</span>
  </div>
  <p class="fx-example"><span class="fx-lv" data-fx="lv">Lv.25</span><b class="c-offense" data-fx="dps">500</b> × 7 = <span class="fx-result" data-fx="mobHp">3,500</span></p>
  <ul class="fx-notes"><li>…決まっている補足だけ…</li></ul>
</section>
```

| 部品 | 使い方 |
|---|---|
| `.fx` | 式の行。PCでは1行に収め、760px以下では折り返す |
| `var.fx-var.cat-<分類>` | 変数。分類の色のチップにし、必要なら `<small>` で意味を添える |
| `.fx-op` / `.fx-paren` / `.fx-num` | 演算子、括弧、定数 |
| `.fx-frac` | 割り算。分子と分母を縦に積む（`÷` を文中に書かない） |
| `.fx-example` | 式の直下の計算例。先頭の `.fx-lv` にレベルまたは「例」「標準構成」を書き、代入した数値は変数と同じ分類色の `c-<分類>` にする |
| `.fx-chart` | 比例しない関係（防御で通る割合など）は小さな曲線で示し、基準点と選択中のレベルの位置を描く |
| `.fx-flow` / `.fx-step` / `.fx-arrow` | 逆算や複数段の手順は、段階を箱で並べた流れ図にする |
| `.fx-include` / `.fx-chip` | 合計に含めるもの、構成要素などの列挙 |
| `.fx-anchors` | 基準値の並び。選択レベルを含む区間（または基準値そのもの）を強調する |
| `.fx-notes` | 補足の箇条書き。2項目程度 |

- 計算例の数値は、選択中のレベルに連動させます。数値を入れる要素に `data-fx="<キー>"` を付け、レベル変更時に `updateFormulas(level)` で書き換えます。レベルに依存しない例は固定値で書きます。
- 計算方法の章の冒頭に「計算例は、〜で選んだレベルの値。」と1文添えます。

## 9. レベル選択とハイライト

- ページ内で選択中のレベルは1つです。選択が変わったら、レベル表示・凡例の値・グラフの選択点・表の選択行・計算例をすべて同時に更新します。
- 選択中であることを強調する要素は、**すべてクリック（タップ）でもそのレベルを選べる**ようにします。強調するだけで操作できない要素は作りません。
  - レベル別の表の行: クリックでそのレベルを選択します。表には `clickable-rows` を付けます。行はTabの移動先にしません（キーボードはスライダーで操作します）。
  - 基準値の帯（`.fx-anchors`）: 各基準値を `<button data-level>` にし、クリックとキーボードで選べるようにします。
- カードが複数ある資料では、レベル操作（`.st-tools`）を本文上部に追従させます。章へ移動したとき見出しが隠れないよう、章・節に `scroll-margin-top` を設定します（PC 84px、760px以下 124px）。
- 表は主要レベル（Lv.1・25・50・75・100）だけを表示し、「5レベル刻み」で全レベルに展開します。展開時は主要レベルの行を太字、その他の行を補足色にします。

## 10. グラフ

- 図表の部品は [マスターデータエディタの基本CSS](../../../60_tool/05-master-data-editor/src/SkillTreeEditor.Client/src/styles.css) と [マスターデータ用CSS](../../../60_tool/05-master-data-editor/src/SkillTreeEditor.Client/src/masterData.css) を参考にし、基準HTMLの配色を使います。
- 左と下の軸に短い目盛りを置き、横方向の目盛り線を罫線色（`--rule`）で引きます。単位は軸に、系列名は図の直前の凡例に表示します。
- 線は1.5〜2pxで、各観測点に記号を付けます。主系列は実線と丸、比較系列は破線とひし形、3本目以降は点線と三角、一点鎖線と四角です。主要レベルの点は大きく描き、DPS指標ではLv.75も主要点にします。
- 比較する系列は同じ図に重ね、率と実数など尺度が違う図は並べます。凡例にカーソルまたはキーボードフォーカスを合わせると他の線が薄くなり、タップで固定、再タップで解除します。
- 吹き出しには、カーソルまたはタップ位置の線の名前・レベル・値を1項目だけ表示し、図の中に収めます。線が重なる場合は凡例で固定した系列を優先します。
- 折れ線グラフのカードは、ホバー・タップ・キーボードフォーカスで拡大し、周囲を暗くします（共通のスポットライト）。拡大中も凡例・線・表を操作でき、画面端では横幅に収めます。動きを減らす設定のときはアニメーションを止めます。

## 11. 画面幅・印刷・アクセシビリティ

- 単一のHTMLファイルをブラウザで直接開いて使える構成にし、外部CDNやWebフォントに依存しません。
- 1080px以下で左目次を章ボタン列に、760px以下でカードを1列にします。320px幅でもページ全体が横にはみ出さないようにし、幅が必要な表は表の領域だけを横スクロールさせます。
- 入力にはラベル、図表には説明（`aria-label` や `title`/`desc`）を付け、キーボード操作時のフォーカス枠を見えるようにします。色だけでなく線種・記号・文字でも区別します。
- 印刷時は資料タブ・目次・操作部品・吹き出しを隠し、折りたたみの内容も表示します。

## 12. 各資料の正本

- [DPS指標](../../20_ゲームデザイン設計書/01-DPS指標.html) に総DPSの目標・育成上限・測定条件、[ステータス指標](../../20_ゲームデザイン設計書/02-ステータス指標.html) にプレイヤーと標準モブのステータスを記載します。同じ値を両方に書く場合は、正本の資料を明記して相互に参照します。
- [ステータス配分基準](../../20_ゲームデザイン設計書/03-ステータス配分基準.html) に標準構成と供給元別の配分、[装備ステータス基準](../../20_ゲームデザイン設計書/04-装備ステータス基準.html) に装備種別の役割と、配分を使った装備の設計値を記載します。
- 02の共通防御・体力の曲線は [v1.status_targets.yml](../../20_ゲームデザイン設計書/data/v1.status_targets.yml)、その他の目標値は02の `stat-model` ブロックで管理します。同期時は曲線を02に反映し、モデルを Node.js で評価してパネルと系列の表示名ごとにLv.1〜100の値を取得します。
- 03の表示名・対象系列・配分規則は [v1.status_allocation.yml](../../20_ゲームデザイン設計書/data/v1.status_allocation.yml)、04の装備プロファイルは [v1.equipment_stat_rules.yml](../../20_ゲームデザイン設計書/data/v1.equipment_stat_rules.yml) を正本とします。同期処理は全レベルの配分を検証して03に埋め込み、04の試算にも同じ配分を使います。
- PyYAML 6.0.3 と Node.js を利用できる環境で、リポジトリルートから次を実行します。

```sh
python "00_docs/20_ゲームデザイン設計書/data/refresh_stat_design.py"
python "00_docs/20_ゲームデザイン設計書/data/refresh_stat_design.py" --check
```

## 13. 変更後の確認

HTMLを変更したら、ブラウザで次を確認します。

- [ ] PC幅（1440px前後）、1080px以下、スマホ幅（375px）で表示が崩れず、ページ全体が横にはみ出さない。
- [ ] OSのライト・ダーク設定のどちらでも、エディタと同じダーク配色になる。
- [ ] 資料タブの番号と並びが全HTMLで同じ。共通ブロック・目次スクリプト・スポットライトが基準HTMLと一致している。
