# ゲームデザイン設計書のHTMLデザイン

`00_docs/20_ゲームデザイン設計書/` のHTMLを作成・修正するときに参照します。

ユーザーは、このフォルダのHTML資料のデザインを統一し、別のAIが作っても同じ見た目・書き方になるよう求めている。具体的な形式・部品・確認手順は [ゲームデザイン設計書のAGENTS.md](../../20_ゲームデザイン設計書/AGENTS.md) を正本とし、基準HTMLは [DPS指標](../../20_ゲームデザイン設計書/01-DPS指標.html) と [ステータス指標](../../20_ゲームデザイン設計書/02-ステータス指標.html) とする。

## ユーザーが示した要望と理由

| 要望 | 理由・背景 |
|---|---|
| AIが作ったように見える表現を避ける。本文に操作説明を書かず、色付きの帯・ラベル・ピル型などの装飾を重ねない | 生成物らしい見た目を避け、資料として読みやすくするため |
| 青文字に下線のリンクを使わない。資料間はタブ、章間は目次で移動する | 下線リンクはデザインとして見栄えが悪いため |
| 資料タブには採番した番号（01、02）を表示する | ファイルの連番と対応させて資料を探しやすくするため |
| 章番号を振り、所有者と役割（被弾時・攻撃など）で章を区切る。左の目次と章内目次を置く | 概要が並ぶだけでは、どこに何があるか分かりにくいため |
| 能力の色分けは、システムの公式7分類（リソース・基本能力値・攻撃・防御・属性・状態異常・ユーティリティ）に合わせる | 独自の4分類（攻撃・耐久・耐性・会心）ではステータスを網羅できず、ゲームデータの分類とも対応しなかったため |
| 計算式を文字だけで書かない。色付きの変数・分数・選択レベルの計算例・曲線・流れ図で見せる | 文字だけの式は分かりにくいため |
| ハイライトする要素は、クリックでもそのレベルを選べるようにする | 強調されているのに操作できないと不自然なため |
| 未決事項（TODO・要調整・実装待ちなど）を資料に含めない | 設計書には確定した値・式・条件だけを載せるため |
| 吹き出しの中のミニグラフは不要 | 吹き出しは系列名・レベル・値だけで足りるため |

グラフカードのスポットライト拡大は、ユーザーが以前に指定したルールとして維持している。
