# Item 設計

## 役割

Item は、プレイヤーが所持・移動・参照できるマスタの共通土台です。個別の用途は material、consumable、equipment、orb などのカテゴリで定義します。

## 設計方針

- 装備はスキルを付与せず、武器の通常攻撃は `equipment.tag` から Plugin がシステムスキルとして自動解決します。
- スキルジェムは生成せず、スキル習得・レベルアップ素材は skill master の required items から通常アイテムを参照します。シジルは `sigil` アイテムカテゴリとして定義します。
- 装備操作アイテムは `enhancement_material` ではなく `orb` カテゴリで定義し、操作内容は `orb.effect` に一つだけ持たせます。

- ID、表示名、カテゴリ、レアリティ、見た目、説明文の共通情報を持たせます。
- item 単体には、用途カテゴリで定義すべき性能を重複させません。
- レアリティは希少性と入手難度を表し、進行度そのものとして使用しません。
- 同じ進行度でも、用途と入手難度に応じて複数レアリティを許容します。

## progression

標準入手段階を記載します。素材・装備・消耗品などの派生カテゴリでは、そのカテゴリ文書の基準を優先します。

## IDとファイル名

アイテムIDは `{カテゴリ番号2桁}{英字1桁}{連番5桁}` の8文字固定とします。カテゴリ番号は `10=material`、`20=equipment`、`30=consumable`、`40=orb`、`50=bundle`、`60=rune`、`70=sigil`、`99=currency` です。通常採番は英字 `a` の `00001` から開始し、連番が `99999` に達した場合だけ英字を繰り上げます。`z` はデバッグアイテム専用です。

ファイル名は `v<schemaVersion>.<id>.<管理用slug>.yml` とし、例は `v1.20a00002.nox_sword.yml` です。管理用slugは検索用の補助名であり、YAMLの `id` が正本です。既存マスタは同一カテゴリ内の `progression` 昇順を基本に採番します。Plugin組み込み通貨は `99a00001` 以降を予約します。

カテゴリフォルダも `10.material`、`20.equipment` のように採番し、APIの読み込み時に番号付きフォルダ名を論理カテゴリへ正規化します。
