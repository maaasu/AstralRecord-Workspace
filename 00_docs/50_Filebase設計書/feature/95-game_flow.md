# ゲーム進行フロー

ゲーム進行を、マスター参照をノードにしたフロー図で設計・共有します。例えば「NPC → ショップ → 職業別の購入アイテム」のように、攻略・入手・交換の流れを矢印でつなぎます。人とAIの両方が同じファイルを読めることを目的にします。

- ノードは `dungeon:` / `shop:` / `item:` / `mob:` / `class:` / `world:` などの既存マスターを参照する。名前・アイコン・性能は通常、参照先に従う。操作や付箋、個別にアイコンを指定するノードは `nodes[].icon` を使う。
- 職業ごとに異なる進行は、ノードまたは矢印の `classes` で表す。未指定のノード・矢印は全職業共通とする。
- 1ファイルは1つの進行テーマにまとめ、巨大な全体図を1ファイルに詰め込まない。

保存先は `40_filebase/95.design.game_flow` です。ゲーム実行時のマスターではなく設計用データのため、`features` / `shared` と分けて `design` を名前に含め、既存カテゴリの後に並ぶ2桁番号を使います。`config.yml` の `database` へは登録せず、Plugin / API の runtime-filebase も読み込みません。

マスターデータエディタの「ゲーム進行フロー」で、ノードの配置、矢印の接続、参照先の選択、職業の割り当て、職業フィルタでの閲覧を行います。ショップのノードからは、そのショップの商品を購入アイテムのノードとして追加できます。装備マスターに `requiredClasses` がある商品は、その職業を初期値として割り当てます。「マスターデータ」の「ゲーム進行フロー」カテゴリでもフォーム・原稿編集を利用できます。

ノードの外形は種類を、中の画像は参照先や個別に設定したアイコンを表します。図に余白があれば、ノードの下に補足文の冒頭を表示します。全文と参照先は、ノードにポインターを重ねるかキーボードでフォーカスすると確認できます。

ノードや線をダブルクリックすると、図の上でラベルを編集できます。空白をダブルクリックすると、その場所にメモを書けます。Enter で確定、Esc で取り消し、付箋内では Shift+Enter で改行します。付箋を選び、右下のハンドルをドラッグすると表示範囲が広がります。プロパティの幅と高さを入力して寸法をそろえることもできます。

図の右クリックから追加や編集、プロパティや候補の右クリックから名前・参照・ファイルパスのコピーができます。ノードを選ぶと、既存マスターのつながりから次・前に置く候補を表示し、Tab / Shift+Tab でまとめて配置できます。候補の元は次のとおりです。スポナーはワールドを参照しないため、ワールドからそこに出現するモブは候補になりません。

| 起点 → 候補 | ラベル | 元データ |
|:--|:--|:--|
| モブ / 採集 / ダンジョン / ショップ / レシピ / 釣りエリア → アイテム | ドロップ / 採集 / クリア報酬 / 購入 / 製作 / 釣果 | 装備・入手経路と同じ入手元の索引（ルートテーブル経由を含む） |
| アイテム → ショップ / レシピ / ワールド | 素材 / 入場条件 | 交換素材・レシピ素材・ワールドの `requiredItemId` |
| バンドル → 開封で得られるアイテム | 開封 / 開封（抽選） | `bundle.items[].itemId` / `bundle.lootTableId` の抽選先アイテム |
| ワールド → ダンジョン | 入場 | ダンジョンの `entry.worldRef` |
| ダンジョン → モブ | 出現 / ボス | `encounter.normalMobPool` / `bossMobId` |
| スポナー → モブ / 採集、NPC → ショップ | 出現 / ショップ | `spawnMobs` / `spawnGatherings` / NPC の SHOP 操作 |

バンドルを選ぶと中身が次の候補に、開封で得られるアイテムを選ぶとバンドルが前の候補に出ます。直接受け取れるアイテムは「開封」、抽選で得るアイテムは「開封（抽選）」です。両方に含まれるアイテムは「開封」にまとめます。`bundle.gold` は所持金に加算されます。

## 章単位の全体フロー

[ゲーム進行の全体フロー](../../../40_filebase/95.design.game_flow/v1.game_progression_overview.yml)では、正式に作成した章ごとにクリア地点を一つのノードにまとめます。章内の手順は詳細フローに置き、クリアノードの `game_flow:<id>` から参照します。章の詳細フローに `icon` を設定すると、全体フローのクリアノードに表示されます。

- クリア地点のメモに、前提となる受け取り・購入などの条件と、その時点の想定所持品を書く。確定入手品と抽選ドロップを区別し、章報酬を含める場合は受取時点を示す。第1章の基準はクリア直後の報酬請求前とする。
- 職業・レベル・装備の構成は「装備・入手経路」の[進行プリセット](90-progression_preset.md)に保存し、クリア地点から `progression_preset:<id>` のノードをつなぐ。ノードには職業のアイコンを表示する。ビルドの表示名には職業と到達地点を含める（例「冒険者 チャプター1クリア」）。参照ノードの右クリックから「マスターを開く」で参照先を確認できる。

## 図の作成ルール

- 達成までの主な流れは、近いノード同士を横か縦につなぐ。折り返しは同列で上下につなぎ、長い斜線、矢印の交差、ノードを横切る線を避ける。接続面を固定する場合は `fromPort` / `toPort` で指定する。接点を共有しない線の直線部が交差すると、片方に小さな弧が表示される。
- ノード名と矢印ラベルは、操作や関係が一目で分かる短い語句にする。全体に共通する意味は `description` やメモに置き、同じラベルを各矢印に繰り返さない。
- マスター参照で表せない進行上の操作は `role: action` と `label` で表す。補足や条件は対応する `note`、または近くに置く付箋に書く。付箋には `label` で要点を記し、対象を示す場合は上下左右の接続点から短い注釈線で結ぶ。注釈線は矢じりのない破線で表示される。以前の図で付箋を手順として使っていた場合は、プロパティの「操作に変更」で既存の矢印ごと引き継げる。
- 店を開くNPCがいるショップは、実際の入口となるNPCを `mob:` 参照で置き、そのノードから `shop:` ノードへつなぐ。NPCマスターの `interactions` にある `type: SHOP` と `shopId` を照合し、図でもNPCだと見分けられる名前にする。
- 矢印が案内順だけを表す場合はその前提を図に示す。達成順の制約や全達成・報酬の条件は、実際のマスターと実装を照合して記載する。

AIへ渡す場合は YAML をそのまま読ませるか、エディタの「テキスト」表示で参照先の名前を解決した一覧を使います。定義形式は [YAMLスキーマ定義](../../../40_filebase/95.design.game_flow/docs.game_flow.YAMLスキーマ定義.md) を参照してください。

設計メタデータの `progression` は、進行に属さない設計用データとして `0` を記載します。
