# Guide 設計

## 役割

Guide は、ゲーム内 GUI で操作手順と達成状態を案内するチェックリストです。表示順は読みやすさのために保持しますが、達成判定は条件を満たした step を個別に記録します。

## 設計方針

- 1つの guide は1つの操作または判断目的に絞ります。例外として、冒険開始から最初の戦闘準備までを一貫して案内する導入ガイドは、連続した1つの目的として扱います。
- 1つのguideは1つ以上のstepを持ち、step は記載順に表示します。達成判定は記載順に依存せず、条件を満たした step を達成します。
- 各stepはPluginが解釈する宣言的なconditionを1つ持ちます。
- 各stepは必要に応じて具体的な操作方法を示す `details[]` と、クリック時の型付き `action` を持ちます。
- プレイヤー向けの短い `text` は敬語を避け、操作を表す「～する」形式で定義します。詳細は灰色、クリック動作は `action.description` のカラーコードで表示し、未指定時は灰色とします。スキルマネージャーを開くクリック動作は紫色で定義します。
- マスタ名は参照記法を使い、表示名を本文へ固定しません。
- Plugin の画面配置やページングを YAML 側へ重複定義しません。
- 実装済みの機能と参照先だけを案内します。
- プレイヤーごとの達成状態はSQL Serverへ保存し、マスターには保持しません。
- 導入ガイドのように連続した体験を扱う場合も、ログイン、受取、購入、戦闘、採集などの達成判定は実際に成功した操作だけを使用します。
- condition の `targetId` は単一対象、`targetIds` は複数候補を表し、`targetIds` はいずれか1つに一致した時点で達成します。両方を指定した場合も、いずれかの対象 ID に一致すれば達成します。
- `WAYSTONE_TELEPORTED` は、指定したウェイストーンへの実際のテレポートが成功したときだけ記録します。
- `ORB_USED` は、オーブによる装備更新・ルーン操作・シジル操作が API とローカル正本へ反映されたときだけ記録します。ルーン操作ではオーブ自体を消費しませんが、シジル操作では成功時にオーブを1個消費します。強化抽選の成否ではなく、オーブ使用の確定を達成条件とします。
- `DUNGEON_CLEARED` は、ボス部屋を攻略し、対象ダンジョンのクリア参加者として踏破記録を開始したときだけ記録します。
- `NAVIGATE_NPC` は同一ワールドの最寄り対象 NPC の座標通知と一時発光を行い、`OPEN_MENU` は指定した通常 GUI を開きます。
- 新規 DB を前提とし、旧ガイドスキーマや既存プレイヤー進行の移行・遡及再判定は行いません。

## progression

説明対象を初めて利用する直前の段階を基準にします。進行に依存しない常設ヘルプは `0` とします。
