# アカウント進行プリセット

開発環境で、プレイヤーレベル1〜50の戦闘状態を職業・ビルドごとに再現します。適用先は管理者権限を持つ実行者が選択中の通常プレイヤーアカウントです。

- 職業の成長と装備の更新は既存の成長曲線、装備条件、職業ごとの戦闘設計を基準にする。
- 上位職もレベル1から検証できるように、プリセットで選択し、前提職の進行を用意する。
- スキルツリーの接続、必要ポイント、装備条件、発動可能なスキルを同じ構成内で満たす。
- アクションリングの1番枠には適用直後に試せるアクティブスキルを登録する。Java版では適用後の最初の武器右クリックで発動する。
- 強化値とシジルは個体に適用する。装備の入手順と、渡航・転生を仮定する段階は [ゲーム進行順と装備の入手](../../60_戦闘バランス設計書/06-ゲーム進行順.md) に従う。
- 装備は通常6枠、スキルブック1枠、種類別アクセサリ9枠の最大16枠を同じ `equipment` 一覧に指定する。チェックポイント適用時は16枠を構成どおりに置換し、未指定枠は外す。各枠の装備条件とアクセサリの種類タグを検証し、既存個体を再利用できない場合は1枠につき1個体を付与する。前の装備はバッグへ戻す。
- スキルブックの装備条件を満たす場合、その `usableSkills` を同じチェックポイントで設定できるスキルに加える。

マスターデータエディタの「装備・入手経路」で、選択した職業・ビルド・適用開始レベルの装備とアカウント進行を一緒に編集します。職業レベル、習得ノード、アクティブ・パッシブの割り当て、スキルレベル、装着シジルは同じチェックポイントへ保存します。「マスターデータ」の「アカウント進行プリセット」カテゴリでもフォーム・原稿編集を利用できます。定義形式は [YAMLスキーマ定義](../../../40_filebase/90.shared.progression_preset/docs.progression_preset.YAMLスキーマ定義.md) を参照してください。

保存先は `40_filebase/90.shared.progression_preset` です。装備設計・アカウント進行の編集・ゲーム内での検証に共通して使う構成として、共有カテゴリに配置します。アイテム・スキル・ノードなどの個別マスターはIDで参照し、アカウント進行機能が構成を適用します。APIとプラグインのruntime-filebase、およびエディタの新規保存先もこのパスに統一します。

旧カテゴリからの更新は、旧パスの入力も読める新しいプラグインを先に配備し、続いてAPIとFilebaseを同時に更新します。APIは新パスだけを配信し、プラグインは新パスのプリセットを優先します。旧パスだけを配信するAPIへの接続時には旧カテゴリを読み込めます。既存のID、ファイル名、構成値は移動前から変更しません。

強化値・シジルを含む定義を配備するときは、それらを読めるプラグインと同じ更新で反映します。
