# 60_戦闘バランス設計書

## 目的

本設計書は、RPG 戦闘における数値目標、成長曲線、職業・敵・装備・skill の相対的な強さを定める。
個別の YAML 構造や ID、マスタの記述形式は定めない。ここで決めた基準値を、各 feature の filebase マスタへ一貫して反映するためのゲームデザイン上の正本とする。

## 設計書一覧

- [[01-戦闘計算]]: 現在実装されている戦闘・経験値計算式と参照元
- [[02-成長曲線]]: Lv.1～30 のプレイヤーと同格 Mob の基準値

## 他設計書との境界

| 対象 | 正本 |
|:--|:--|
| 戦闘の目標時間、成長曲線、数値配分 | 本設計書 |

| マスタカテゴリの役割・進行度の接続方針 | `00_docs/50_Filebase設計書/feature/` |

本設計書で `progression` をプレイヤーレベルとして扱わない。`progression` は、既存の Filebase 設計に従い、標準的な遭遇・入手・更新の順序を表す。

## 設計の基本単位

戦闘バランスは、個々のステータス値ではなく、次の結果で評価する。

| 指標 | 意味 |
|:--|:--|
| TTK | プレイヤーが敵を倒すまでの時間 |
| 耐久時間 | 敵から継続的に攻撃された場合にプレイヤーが倒れるまでの時間 |
| DPS | 実戦で継続して与えられるダメージ量 |
| リソース持続 | mana / energy 等を枯渇させずに戦える時間と回復余地 |
| 更新幅 | 装備・skill・レベル上昇によって得る戦闘性能の差 |

数値を変更するときは、少なくとも同格の通常敵に対する TTK と耐久時間への影響を確認する。

## 成長曲線の決め方

1. 代表レベルをアンカーとして先に定める。初期段階では Lv.1、Lv.10、Lv.20、Lv.30 を基準とする。
2. 各アンカーで、職業ごとの HP、想定 DPS、防御性能、リソース量を決める。
3. 同格の通常敵・強敵・ボスに対する目標 TTK と耐久時間を決める。
4. アンカー間の値は、class の基礎値とレベル成長、equipment の更新、skill の解放を合算して満たすように配分する。

現在の class YAML の `baseStats` と `growthPerLevel` は基礎成長を表す。大きな戦闘力の節目は、class の成長値だけへ集中させず、装備更新と skill の選択によって作る。

## マスタへの反映

| マスタカテゴリ | 本設計書から決めること | スキーマ・カテゴリ方針の正本 |
|:--|:--|:--|
| class | 初期性能、レベル成長、職業ごとの強みと弱み | `50_Filebase設計書/feature/20-class.md` |
| equipment / item | progression ごとの更新幅、職業別の性能配分 | 各 item 関連 feature と YAML スキーマ |
| skill | 主目的、実質 DPS、範囲・拘束・安全性とコストの交換条件 | `50_Filebase設計書/feature/30-skill.md` |
| mob / enemy / boss | 敵の役割、同格プレイヤーに対する HP・攻撃・耐久の目標 | 各 mob 関連 feature と YAML スキーマ |
| loot / recipe / shop | 更新品を得る時期と、攻略順を飛ばさない供給量 | 各 economy 関連 feature と YAML スキーマ |

個別マスタへ値を記載する前に、対象の `progression`、入手元、攻略対象、更新先を確認する。YAML へスキーマ未定義の戦闘バランス用プロパティは追加しない。

## 最初の検証範囲

最初は、Lv.1 から Lv.30 までを対象にする。

- class は `adventurer`、`swordsman`、`hunter`、`mage` を比較する。
- 敵は通常敵、耐久型、高火力型を各 1 種類以上用意する。
- 各職業について、通常攻撃、主力 skill、回復または防御手段を含む代表的な戦闘を確認する。
- 装備・skill・loot が想定した `progression` 順に更新されることを確認する。
