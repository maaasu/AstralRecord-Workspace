# 05_9.00-未決事項

## 1. BuffService の生成・ライフサイクル

現状 `BuffService` は `StatusService` のコンストラクタ内で `new BuffService()` されており、`AstralRecord#setupFeature` には登録されていない。  
他 feature から再利用したい場合や、`/buff` 系コマンドを追加する場合のために、プラグインライフサイクルへの登録要否を決定する必要がある。

## 2. 失効バフのログ整備

`LogId` は `5450-5499` の範囲で予約されているが、現状は `D_5451` のみ定義されている。  
バフ付与・解除・失効削除の各イベントをログ出力すべきかは未確定。

## 3. バフ補正の重複付与方針

`apply` は同一 `buffId` を 1 件に正規化する設計だが、`displayName` や `type` が同じで `buffId` が異なるバフの重複制御は行わない。  
将来的に「同種バフは最大強度のみ残す」「累積上限を設ける」などの方針を取る場合は、`BuffType` 側に区分キーを追加する必要がある。

## 4. アクティブバフの永続化

`AstPlayer.activeBuffs` はサーバ再起動・プレイヤー切断で初期化される。  
長時間バフや日次バフを扱う場合、`expiresAt` を含めた永続化方針（API / DB / ファイル）を定義する必要がある。

## 5. クライアントへの表示・通知

HUD・GUI・チャットなどへのバフ状態表示は本機能の責務外で扱う想定だが、表示主体（`player` / `hud` / 新規 view feature）が未確定。  
特に `isDebuff` の見せ分けやアイコン化のルールが未定義。
