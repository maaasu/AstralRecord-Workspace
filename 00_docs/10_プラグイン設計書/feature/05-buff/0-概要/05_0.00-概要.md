# 05_0.00-概要

## 1. 目的

`buff` 機能は、プレイヤーへ一時的に付与される能力補正（バフ / デバフ）を管理する。  
主目的は以下。

- バフ定義（`BuffType`）の API 取得・メモリキャッシュ管理
- プレイヤーへのバフ付与・解除・期限切れ整理
- ステータス再計算時に必要となるバフ補正合計値（FLAT / SCALAR）の提供

## 2. コンテキスト

- バフ定義は AstralRecord API (`/api/buff/{buffId}`) から取得し、`BuffService` の内部キャッシュに保持する。
- プレイヤーごとの「現在掛かっているバフ」は [[03_1.00-モデル定義]].プレイヤーキャッシュ 内の `AstPlayer.activeBuffs` に直接保持される（永続化なし、セッション中の状態）。
- バフ補正は [[05_3.02-サービス]].バフ補正合計取得 で `StatusType` 別に合算し、`StatusService` がステータス再計算時に呼び出す。
- 失効時刻は `durationTicks / 20` 秒として `LocalDateTime` で計算する。

## 3. 構成要素（実装単位）

- `service/BuffService`
  - バフ定義のキャッシュ管理、付与・解除・期限切れ整理、補正合計算出の業務制御を行う。
- `repository/BuffRepository`
  - `/api/buff/{buffId}` への HTTP リクエストを実行する。
- [[05_1.00-モデル定義]].バフタイプ, アクティブバフ, バフ補正, バフ補正タイプ
  - バフマスタ・付与中状態・補正単位を定義する（詳細は [[05_1.00-モデル定義]]）。

## 4. 依存関係

- 内部依存
  - `BuffService` -> `BuffRepository`
- 外部依存
  - AstralRecord API (`/api/buff/{buffId}`)
  - [[03_1.00-モデル定義]].プレイヤーキャッシュ.AstPlayer.activeBuffs を直接更新する

## 5. ライフサイクル登録点

- `StatusService` のコンストラクタ内で `new BuffService()` が生成される（`buff` 機能専用の `AstralRecord#setupFeature` 登録は無い）。
- 起動時の一括ロードは行わず、`BuffService.apply` の初回呼び出し時に該当バフを遅延ロードしてキャッシュへ登録する。
