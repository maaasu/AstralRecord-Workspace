# 05_5.00-例外・ログ・運用

## 1. 方針

`buff` 機能は最小構成で、API 取得結果をキャッシュして `AstPlayer.activeBuffs` を直接操作する。  
失敗時はサーバ全体を止めず、付与失敗・解除失敗は `boolean` の戻り値で呼び出し元に判断を委ねる。

## 2. 主なログポイント

- `BuffService`
  - キャッシュ登録（バフ詳細ロード）: `LogId.D_5451`
- `BuffRepository`
  - 現状ログ出力は行わない（200/404 はサイレント、その他は例外でのみ通知）

## 3. 例外処理の境界

- `Repository`
  - HTTP 異常時は `IOException` を送出し、呼び出し元の `BuffService.getOrLoad` へ伝播する。
  - `InterruptedException` は `Thread.currentThread().interrupt()` を実行のうえ `RuntimeException` でラップして再送出する。
- `Service`
  - `getOrLoad` で取得に失敗した場合は `null` を返却し、`apply` は `false` で正常終了する。
  - `apply` / `remove` / `purgeExpired` / `getTotalBonus` / `getActiveBuffs` の各メソッドは内部で例外を捕捉せず、リポジトリ例外はそのまま呼び出し元へ伝播する設計。

## 4. スレッド上の注意

- `BuffRepository.findById` は同期 HTTP のためメインスレッドでの初回呼び出しはブロックする可能性がある。
- 失効判定は `LocalDateTime.now()` を毎回計算するため、`purgeExpired` を頻繁に呼ぶ呼び出し側はステータス再計算粒度に合わせる。

## 5. プレイヤー向けメッセージ

`buff` 機能単独のプレイヤー向けメッセージは現時点で定義しない（コマンド未提供）。
