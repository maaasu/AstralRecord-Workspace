# 11_1.00-モデル定義

## 1. ドメインモデル

`player-setting` 機能の中心は、ユーザー単位の設定値スナップショット。  
AstralRecord API の `user_setting` レコード（[[03_1.00-モデル定義]].レスポンス）を、プラグイン側で扱いやすい型に変換して保持する。

## 2. プレイヤー設定モデル

物理名: `PlayerSettingModel`

API レスポンス 1 レコード分に対応する個別設定の表現。永続化情報を含む。

| 項目 | 説明 |
|---|---|
| `userSettingId` | 設定レコード UUID（API の `userSettingId`） |
| `userId` | 対象ユーザー UUID |
| `settingKey` | [[11_1.00-モデル定義]].プレイヤー設定キー |
| `settingValueJson` | 設定値 JSON 文字列（型は [[11_1.00-モデル定義]].プレイヤー設定キー の `値型` を参照） |
| `version` | 楽観ロック用バージョン |
| `createdAt`, `updatedAt` | 作成・更新日時 |
| `createdBy`, `updatedBy` | 作成・更新者 UUID |
| `isDeleted` | 論理削除フラグ |

## 3. プレイヤー設定スナップショット

物理名: `PlayerSettingSnapshot`

オンライン中の参照用に、設定キーごとの値を解釈済みの形で保持する。

| 項目 | 説明 |
|---|---|
| `userId` | 対象ユーザー UUID |
| `entries` | `Map<PlayerSettingKey, PlayerSettingEntry>` |

未登録のキーは、参照時に [[11_1.00-モデル定義]].プレイヤー設定既定値 から解決する。

## 4. プレイヤー設定エントリ

物理名: `PlayerSettingEntry`

スナップショット内の 1 エントリ。永続化情報（`userSettingId`・`version`）と解釈済み値を併せ持つ。

| 項目 | 説明 |
|---|---|
| `userSettingId` | 設定レコード UUID。未登録の場合は `null` |
| `settingKey` | [[11_1.00-モデル定義]].プレイヤー設定キー |
| `value` | 解釈済みの値（`Boolean`、[[11_1.00-モデル定義]].パーティクル密度 など） |
| `version` | 楽観ロック用バージョン。未登録の場合は `null` |

## 5. プレイヤー設定キー

物理名: `PlayerSettingKey`

| 物理名 | コード（API `settingKey`） | 論理名 | 値型 | 既定値 |
|---|---|---|---|---|
| `DAMAGE_LOG_DISPLAY` | `DAMAGE_LOG_DISPLAY` | ダメージ数値 TextDisplay 表示 | `Boolean` | `true` |
| `DAMAGE_LOG_MESSAGE` | `DAMAGE_LOG_MESSAGE` | ダメージ詳細メッセージ表示 | `Boolean` | `false` |
| `PARTICLE_DENSITY` | `PARTICLE_DENSITY` | パーティクル密度 | [[11_1.00-モデル定義]].パーティクル密度 | `NORMAL` |
| `DROP_LOG_DISPLAY` | `DROP_LOG_DISPLAY` | レアドロップログ表示 | `Boolean` | `true` |
| `PERFORMANCE_INFO_DISPLAY` | `PERFORMANCE_INFO_DISPLAY` | MSPT・Ping表示 | `Boolean` | `false` |

`DROP_LOG_DISPLAY` は Mob のレアドロップ全体通知を受信するかを制御する。`false` のプレイヤーだけ通知対象から除外し、他プレイヤーへの配信は継続する。

各キーは、`Boolean` 値の場合は `{"enabled": true|false}` 形式の JSON、列挙値の場合は `{"value": "<コード>"}` 形式の JSON として API へ保存する。
`DAMAGE_LOG_DISPLAY` と `DAMAGE_LOG_MESSAGE` は独立して変更できる。メッセージは戦闘頻度に比例してチャット量が増えるため既定値を `false` とする。

## 6. パーティクル密度

物理名: `ParticleDensity`

パーティクル表示の段階指定。`OFF` を含めた 6 段階で管理する。

| 物理名 | コード | 論理名 | 表示倍率 |
|---|---|---:|---:|
| `OFF` | `OFF` | 非表示 | `0.0` |
| `VERY_LOW` | `VERY_LOW` | 極低 | `0.25` |
| `LOW` | `LOW` | 低 | `0.5` |
| `NORMAL` | `NORMAL` | 標準 | `1.0` |
| `HIGH` | `HIGH` | 高 | `1.5` |
| `VERY_HIGH` | `VERY_HIGH` | 極高 | `2.0` |

表示倍率は、`ParticleDisplayService` 側で「基準パーティクル数 × 倍率」を粒子数に反映するための係数として使用する。共有演出は `spawnForNearbyViewers(...)` / `spawnForViewer(...)` 経由で受信プレイヤーごとに倍率を解決する。
`OFF` は粒子数 `0`、つまりパーティクル表示自体を抑止する。

## 7. プレイヤー設定既定値

物理名: `PlayerSettingDefaults`

未登録キーに対する初期値を提供する。  
値は [[11_1.00-モデル定義]].プレイヤー設定キー の `既定値` 列と一致させる。

## 8. プレイヤー設定キャッシュ

物理名: `PlayerSettingCache`

オンライン中の [[11_1.00-モデル定義]].プレイヤー設定スナップショット を `userId` キーで保持する。

| 項目 | 説明 |
|---|---|
| `snapshots` | `ConcurrentMap<UUID, PlayerSettingSnapshot>` |

## 9. プレイヤー設定メッセージID

物理名: `PlayerSettingMsgId`

プレイヤー向けメッセージキーを定義する enum。文言は `player.properties` で管理する。

## 10. プレイヤー設定変更要求

物理名: `PlayerSettingChangeRequest`

コマンド・GUI 双方から共通で呼び出すための変更要求オブジェクト。

| 項目 | 説明 |
|---|---|
| `userId` | 対象ユーザー UUID |
| `settingKey` | [[11_1.00-モデル定義]].プレイヤー設定キー |
| `newValue` | 新しい値（型は `settingKey` の `値型` に従う） |
| `requestedBy` | 操作者 UUID（基本的に `userId` と同一） |
