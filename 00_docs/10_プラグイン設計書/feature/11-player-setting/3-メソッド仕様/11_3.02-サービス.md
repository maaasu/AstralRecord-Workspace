# 11_3.02-サービス

## 1. service メソッド仕様

### プレイヤー設定読込

クラス名: `PlayerSettingService`  
物理名: `loadPlayerSettings`

処理内容:

1. [[11_3.05-リポジトリ]].設定一覧取得 で対象ユーザーの設定一覧を取得する

	| 項目 | 内容 |
	|---|---|
	| ID | `LogId.W_5310` |
	| レベル | `WARN` |
	| テンプレート | `プレイヤー設定の取得に失敗しました: user=%s, reason=%s` |
	| 出力条件 | API 取得失敗時 |
	| 引数 | ユーザー UUID, エラー要約 |

2. 取得した [[11_1.00-モデル定義]].プレイヤー設定モデル 一覧から、論理削除済みレコードを除外する
3. 設定キーごとに JSON 値を解釈し [[11_1.00-モデル定義]].プレイヤー設定エントリ を構築する
	- 解釈失敗キーは `LogId.W_5311` を記録してスキップし、既定値で補完する

	| 項目 | 内容 |
	|---|---|
	| ID | `LogId.W_5311` |
	| レベル | `WARN` |
	| テンプレート | `プレイヤー設定の値解釈に失敗しました: user=%s, key=%s, reason=%s` |
	| 出力条件 | `settingValueJson` を `値型` へ変換できない場合 |
	| 引数 | ユーザー UUID, 設定キー, エラー要約 |

4. 未登録のキーは [[11_1.00-モデル定義]].プレイヤー設定既定値 で補完する
5. [[11_1.00-モデル定義]].プレイヤー設定スナップショット を生成する
6. [[11_3.04-キャッシュ]].プレイヤー設定キャッシュ登録 を実行する

### プレイヤー設定更新

クラス名: `PlayerSettingService`  
物理名: `updatePlayerSetting`

処理内容:

1. [[11_1.00-モデル定義]].プレイヤー設定変更要求 から `userId`・`settingKey`・`newValue` を取り出す
2. [[11_3.04-キャッシュ]].プレイヤー設定キャッシュ取得 で現在のスナップショットを取得する
	- スナップショットが存在しない場合は `LogId.W_5312` を記録して処理を終了する

	| 項目 | 内容 |
	|---|---|
	| ID | `LogId.W_5312` |
	| レベル | `WARN` |
	| テンプレート | `プレイヤー設定の更新をスキップしました: user=%s, reason=%s` |
	| 出力条件 | キャッシュにスナップショットが存在しない |
	| 引数 | ユーザー UUID, `snapshot not cached` |

3. 対象キーの [[11_1.00-モデル定義]].プレイヤー設定エントリ を取得する
4. エントリの `userSettingId` が `null`（未登録）の場合は [[11_3.05-リポジトリ]].設定登録 を呼び出す
	- 登録結果の `userSettingId`・`version` をエントリに反映する
5. エントリの `userSettingId` が存在する場合は [[11_3.05-リポジトリ]].設定更新 を呼び出す（`expectedVersion` にキャッシュの `version` を渡す）
	- `409 Conflict` の場合は [[11_3.02-サービス]].プレイヤー設定再取得 を実行し、操作プレイヤーに `PlayerSettingMsgId.P_5320` を通知する

	| 項目 | 内容 |
	|---|---|
	| ID | `PlayerSettingMsgId.P_5320` |
	| レベル | - |
	| テンプレート | `設定が他で変更されていたため最新値に同期しました: %s` |
	| 出力条件 | API から `409 Conflict` を受信 |
	| 引数 | 設定キー論理名 |

6. キャッシュ上の値を新しい値に置き換える
7. 操作プレイヤーに `PlayerSettingMsgId.P_5321` で完了を通知する

	| 項目 | 内容 |
	|---|---|
	| ID | `PlayerSettingMsgId.P_5321` |
	| レベル | - |
	| テンプレート | `設定を更新しました: %s = %s` |
	| 出力条件 | 更新成功時 |
	| 引数 | 設定キー論理名, 新しい値の表示文字列 |

### プレイヤー設定再取得

クラス名: `PlayerSettingService`  
物理名: `reloadPlayerSettingKey`

処理内容:

1. [[11_3.05-リポジトリ]].設定一覧取得 で対象ユーザーの設定一覧を取得する
2. 引数の設定キーに該当する [[11_1.00-モデル定義]].プレイヤー設定モデル を抽出する
3. JSON 値を解釈し [[11_1.00-モデル定義]].プレイヤー設定エントリ を構築する
4. キャッシュ上の対象エントリを差し替える
5. 該当キーが API 側にも存在しない場合は、既定値で初期化したエントリに差し替える

### プレイヤー設定参照

クラス名: `PlayerSettingService`  
物理名: `getPlayerSetting`

処理内容:

1. [[11_3.04-キャッシュ]].プレイヤー設定キャッシュ取得 でスナップショットを取得する
2. スナップショットが存在しない場合は [[11_1.00-モデル定義]].プレイヤー設定既定値 から該当キーの値を返す
3. スナップショットに該当キーの [[11_1.00-モデル定義]].プレイヤー設定エントリ がある場合はその値を返す
4. 該当キーが未登録の場合は [[11_1.00-モデル定義]].プレイヤー設定既定値 から値を返す

備考: 戻り値は呼び出し側が期待する型（`Boolean`、[[11_1.00-モデル定義]].パーティクル密度 など）にキャスト済みの値とする。

### レアドロップログ表示判定

クラス名: `PlayerSettingService`
物理名: `isDropLogDisplayEnabled`

処理内容:

1. キャッシュ済みスナップショットから `DROP_LOG_DISPLAY` を取得する
2. キャッシュ未登録または型不正時は既定値 `true` にフォールバックし、通知処理から API 通信は行わない
3. Mob のレアドロップ全体通知は、オンライン受信者ごとに本判定を行う

### プレイヤー設定既定値解決

クラス名: `PlayerSettingDefaults`  
物理名: `resolveDefault`

処理内容:

1. [[11_1.00-モデル定義]].プレイヤー設定キー の `既定値` 列に従って値を返す
2. 値型が `Boolean` の場合は `true`/`false`、列挙値の場合は対応する enum 定数を返す
