## 3. 例外方針

- API 通信例外は `runSafely` パターンで握りつぶさず、`LogId.E_5313` で記録した上で操作プレイヤーに更新失敗を通知する。
- JSON 値の解釈失敗はログイン時の読込ループを継続する目的で `WARN` どまりとし、該当キーは既定値で補完する。
- `409 Conflict` は再同期メッセージのみを送り、`ERROR` ログには出さない。

## 4. 運用上の注意

- 設定キーを追加する際は、[[11_1.00-モデル定義]].プレイヤー設定キー、[[11_3.03-コマンド]]、[[11_3.07-GUI・View]] の 3 ヶ所を同時更新する。
- API 側 (`00_docs/20_API設計書/feature/03-player-setting/`) と DB 側 (`00_docs/40_Database設計書/AstralRecord/dbo.user_setting.md`) には影響しない（key/JSON value 形式のため）。ただし新しい既定値の運用判断はリリースノートに残す。
- パーティクル表示は `ParticleDisplayService` 側で「基準数 × `ParticleDensity` の表示倍率」を反映する。共有演出は受信プレイヤーごとに倍率を解決する。本 feature では表示倍率の参照点のみを提供する。
