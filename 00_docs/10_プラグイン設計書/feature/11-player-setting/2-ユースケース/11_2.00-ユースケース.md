# 11_2.00-ユースケース

## 1. ログイン時の設定読込

- 前提: プレイヤーがログインし、[[03_3.02-サービス]].プレイヤー参加反映 が完了している。
- 主シナリオ:
  1. [[11_3.02-サービス]].プレイヤー設定読込 が API から設定一覧を取得する。
  2. [[11_1.00-モデル定義]].プレイヤー設定スナップショット を生成する。
  3. [[11_3.04-キャッシュ]].プレイヤー設定キャッシュ登録 を実行する。
- 例外:
  - API 取得失敗時は [[11_1.00-モデル定義]].プレイヤー設定既定値 のみのスナップショットを構築し、警告ログを記録する。

## 2. ログアウト時のキャッシュ解放

- 前提: プレイヤーがログアウトする。
- 主シナリオ:
  1. [[03_3.02-サービス]].プレイヤー退出処理 から [[11_3.04-キャッシュ]].プレイヤー設定キャッシュ削除 を呼び出す。
- 備考: 設定変更は変更時点で API に保存しているため、ログアウト時の保存処理は持たない。

## 3. コマンドによる設定変更

- 前提: プレイヤーがオンラインで、[[11_1.00-モデル定義]].プレイヤー設定キャッシュ にスナップショットが存在する。
- 主シナリオ:
  1. プレイヤーが `/setting <key> <value>` を実行する。
  2. [[11_3.03-コマンド]].設定変更コマンド が [[11_1.00-モデル定義]].プレイヤー設定変更要求 を組み立てる。
  3. [[11_3.02-サービス]].プレイヤー設定更新 が呼び出される。
- 副シナリオ（確認）: 引数なしで `/setting` を実行した場合は、現在値の一覧を表示する。

## 4. GUI による設定変更

- 前提: プレイヤーがオンラインで、menu feature から [[11_3.07-GUI・View]].プレイヤー設定 GUI が開かれている。
- 主シナリオ:
  1. プレイヤーがスロットをクリックし、[[11_3.07-GUI・View]].プレイヤー設定 GUI が値を切り替える。
  2. [[11_3.02-サービス]].プレイヤー設定更新 が呼び出される。
  3. GUI が更新後の値を再描画する。

## 5. 他 feature からの設定参照

- 前提: 他 feature（HUD、ParticleDisplayService 等）が表示判定や粒子数決定を行う直前。
- 主シナリオ:
  1. 他 feature が [[11_3.02-サービス]].プレイヤー設定参照 を呼び出す。
  2. キャッシュにスナップショットがあれば該当値、なければ [[11_1.00-モデル定義]].プレイヤー設定既定値 を返す。
- 備考: 参照側は API 呼び出しを行わない。本 feature 経由でキャッシュのみを読み取る。

## 6. 楽観ロック競合の解消

- 前提: 同一ユーザーが複数クライアントから同時に設定変更した、もしくは管理ツールから直接更新された場合。
- 主シナリオ:
  1. [[11_3.02-サービス]].プレイヤー設定更新 が API から `409 Conflict` を受け取る。
  2. [[11_3.02-サービス]].プレイヤー設定再取得 で対象キーの最新値を取得し、キャッシュを差し替える。
  3. 操作プレイヤーに「設定が他で変更されていたため最新値に同期しました」旨を通知する。
