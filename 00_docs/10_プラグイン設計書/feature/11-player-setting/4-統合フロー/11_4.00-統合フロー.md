# 11_4.00-統合フロー

## 1. ログイン時の設定読込フロー

1. player feature: [[03_3.02-サービス]].プレイヤー参加反映 が完了する
2. player feature が [[11_3.02-サービス]].プレイヤー設定読込 を呼び出す（非同期スレッド）
3. [[11_3.05-リポジトリ]].設定一覧取得 で API から設定一覧を取得する
4. [[11_1.00-モデル定義]].プレイヤー設定スナップショット を構築し、[[11_3.04-キャッシュ]].プレイヤー設定キャッシュ登録 を実行する
5. 失敗時は既定値のみのスナップショットを登録する（ログイン自体は継続する）

## 2. ログアウト時のフロー

1. player feature: [[03_3.02-サービス]].プレイヤー退出処理 が呼ばれる
2. player feature が [[11_3.04-キャッシュ]].プレイヤー設定キャッシュ削除 を呼び出す

## 3. コマンドによる設定変更フロー

1. プレイヤーが `/setting <key> <value>` を実行する
2. [[11_3.03-コマンド]].設定変更コマンド が引数を検証し、[[11_1.00-モデル定義]].プレイヤー設定変更要求 を組み立てる
3. [[11_3.02-サービス]].プレイヤー設定更新 が呼ばれる
4. API 通信は非同期で実行し、完了後に Bukkit のメインスレッドへ戻してメッセージ送信・キャッシュ反映を行う
5. `409 Conflict` 時は [[11_3.02-サービス]].プレイヤー設定再取得 を実行し、再同期メッセージを送る

## 4. GUI による設定変更フロー

1. menu feature が [[11_3.07-GUI・View]].プレイヤー設定 GUI を開く
2. プレイヤーがスロットをクリックする
3. [[11_3.07-GUI・View]].スロットクリック処理 が新しい値を決定し、GUI 内の下書き状態へ反映する
4. Bukkit のメインスレッド上でスロットを再描画する
5. プレイヤーが GUI を閉じた時点で、変更があったキーのみ [[11_3.02-サービス]].プレイヤー設定更新 を呼ぶ
6. `409 Conflict` 時は [[11_3.02-サービス]].プレイヤー設定再取得 を実行し、競合メッセージを送る

## 5. 他 feature からの参照フロー

1. 参照側 feature（HUD のダメージログ・ドロップログ表示、`ParticleDisplayService` のパーティクル密度）が表示直前に [[11_3.02-サービス]].プレイヤー設定参照 を呼ぶ
   共有パーティクルは `ParticleDisplayService` が周囲プレイヤーごとに設定値を引いて配信する
2. `combat/DamageService` はダメージ TextDisplay の生成直前に [[11_3.02-サービス]].プレイヤー設定参照 を呼ぶ
3. 本 feature はキャッシュのみを参照して値を返す（API 呼び出しは行わない）
4. キャッシュ未登録の場合は [[11_1.00-モデル定義]].プレイヤー設定既定値 を返す

## 6. プラグイン停止時のフロー

1. プラグイン停止イベントを受け、[[11_3.04-キャッシュ]].全プレイヤー設定キャッシュ削除 を実行する
2. 設定変更は変更時点で API に永続化済みのため、停止時の保存処理は持たない
