# 04_2.00-ユースケース

## 1. 必要時にアイテムマスタを取得する

アクター:

- サーバー（コマンド・GUI・ルート抽選・インベントリ表示）

事前条件:

- AstralRecord API が疎通可能である
- 対象アイテム ID が呼び出し元で判明している

主シナリオ:

1. 呼び出し側が itemId を指定して `ItemService.resolveItem` 相当の取得処理を呼ぶ
2. サービスが用途別キャッシュを確認する
3. キャッシュ未保持または期限切れの場合、詳細 API（`/api/item/{itemId}`）を呼ぶ
4. 取得したアイテムを ID 単位でキャッシュへ登録する
5. 呼び出し側へアイテムモデルを返す

代替シナリオ:

- 個別アイテムの取得に失敗した場合は警告ログを記録し、`null` を返す
- API 失敗時はエラーログを記録し、呼び出し元の処理を中断する

事後条件:

- 取得できたアイテムが ID 単位の短命キャッシュに保持される

## 2. 管理者が単一アイテムをリロードする

アクター:

- 管理者プレイヤー（コマンド実行者）

事前条件:

- 対象アイテム ID が API 側に存在する

主シナリオ:

1. 実行者が `/item load <itemId>` を実行する
2. 詳細 API で対象アイテムを取得する
3. 取得結果を ID 単位キャッシュへ上書き登録する
4. 実行者へロード結果を通知する

代替シナリオ:

- 対象アイテムが見つからない場合はエラーメッセージを返して終了する

事後条件:

- 指定アイテムのキャッシュが最新の API 状態に同期される

## 3. プレイヤーが指定アイテムを受け取る

アクター:

- 管理者プレイヤー（コマンド実行者）

事前条件:

- AstralRecord API が疎通可能である

主シナリオ:

1. 実行者が `/item get <itemId> [amount]` を実行する
2. ID 単位キャッシュを確認し、未保持なら API から取得する
3. インベントリサービスへ付与を委譲する
4. 通貨カテゴリは GUI を再描画しない。その他のカテゴリは通常インベントリ GUI を再描画する
5. 実行者へ付与結果を通知する

代替シナリオ:

- API から対象アイテムを取得できない場合はエラーメッセージを返して終了する
- インベントリ空きがない場合はエラーメッセージを返して終了する

事後条件:

- 対象プレイヤーの該当インベントリにアイテムが追加される

## 4. プレイヤーが AstralRecord アイテムのバニラ操作を試みる

アクター:

- プレイヤー（PLAYER モード）

事前条件:

- プレイヤーが AstralRecord アイテムを所持・装着している

主シナリオ:

1. プレイヤーがクリック・消費・攻撃などのバニラ動作を行う
2. ハンドラがプレイヤーの [[02_1.00-モデル定義]].アカウントモード を判定する
3. PLAYER モードかつ AstralRecord アイテムを保持している場合、対象イベントをキャンセルする

事後条件:

- バニラの食事消費・ブロック使用・エンティティ攻撃などの効果は発生しない

## 4.1 ポーションを右クリックで使用する

アクター:

- プレイヤー

契機:

- PLAYER モードのプレイヤーが `CONSUMABLE` カテゴリの AstralRecord アイテムを右クリックする

主シナリオ:

1. `ItemInteractionBlockEventHandler` が右クリック対象の AstralRecord アイテムを解決する
2. アイテムカテゴリが `CONSUMABLE` であれば `PotionUseService.use` へ委譲する
3. `ItemConsumable.effects` の `rate` 判定に成功した効果だけを適用する
4. `RECOVER` 効果は `status` に応じて HP / MP / EN を回復する。`isPercent=true` の場合は対応する最大値に対する割合として扱う
5. `BUFF` 効果は `buffId` を `StatusService.applyBuff` へ渡し、バフ付与とステータス再計算を行う
6. 効果が 1 件以上適用された場合、`InventoryService.consumeHotbarItemInHand` で使用した手のホットバーアイテムを消費する
7. バフが新規獲得・再付与された場合、プレイヤー視界のより右下へバフ表示情報を数秒だけ表示し、表示中の残り時間を更新する

事後条件:

- バニラ消費イベントは発生せず、AstralRecord 側の効果適用とホットバー消費だけが行われる
- バフ獲得通知はプレイヤーごとに 1 件だけ表示し、別バフ獲得時は既存通知を差し替える

## 5. サーバーがクライアントへアイテムパケットを送信する

アクター:

- サーバー（ProtocolLib リスナー）
- クライアント

主シナリオ:

1. サーバが `SET_SLOT` または `WINDOW_ITEMS` パケットを送信する
2. アダプタがパケット内 `ItemStack` の PDC を読み取る
3. AstralRecord アイテムであれば icon Material / customModelData を解決して書き換える
4. 書き換え結果でパケットを差し戻す

代替シナリオ:

- AstralRecord アイテムでない場合は何もせず元のパケットを通過させる
- icon Material 解決に失敗した場合は警告ログを記録し、当該 ItemStack の書き換えをスキップする

事後条件:

- クライアントには icon 適用済みの ItemStack が表示される

## 6. 装備インスタンスを生成する

アクター:

- サーバー（ルート抽選・コマンド・GUI など）

主シナリオ:

1. 呼び出し側が `ItemService.createEquipmentInstance(equipmentId, accountId, source, createdBy)` を呼ぶ
2. リポジトリが `POST /api/equipment/instances` を発行する
3. API がステータスロールを解決し、作成済み装備インスタンスを返す
4. サービスが結果を呼び出し側へ返却する

代替シナリオ:

- 例外発生時はエラーログを記録し、`null` を返す

事後条件:

- API 側に新規装備インスタンスが作成され、呼び出し側はインスタンス ID を含む結果を取得する

## 7. ルーンインスタンスを生成する

アクター:

- サーバー（ルート抽選・コマンド・GUI など）

主シナリオ:

1. 呼び出し側が `ItemService.createRuneInstance(runeId, accountId, source, createdBy)` を呼ぶ
2. リポジトリが `POST /api/rune/instances` を発行する
3. API がステータスロールを確定し、作成済みルーンインスタンスを返す
4. サービスが結果を呼び出し側へ返却する

代替シナリオ:

- 例外発生時はエラーログを記録し、`null` を返す

事後条件:

- API 側に新規ルーンインスタンスが作成される
