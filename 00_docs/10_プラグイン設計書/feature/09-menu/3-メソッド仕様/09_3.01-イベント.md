# 09_3.01-イベント

## 1. クラフト準備ショートカット描画

イベント物理名: `PrepareItemCraftEvent`
クラス名: `MenuOpenEventHandler`
物理名: `onPrepareItemCraft`

責務:

プレイヤーインベントリのクラフト欄へメニューショートカットを描画する。

処理内容:

1. 対象 inventory がプレイヤークラフトインベントリでなければ終了する
2. view player が Player でなければ終了する
3. 対象プレイヤーが描画抑止中なら終了する
4. [[09_3.01-イベント]].クラフトショートカット再描画予約 を呼び出す
5. 例外時は runSafely で以下ログを記録する

    | 項目 | 内容 |
    |---|---|
    | ID | LogId.E_5700 |
    | レベル | ERROR |
    | テンプレート | メニュー系イベント処理に失敗しました: %s |
    | 出力条件 | runSafely で例外発生時 |
    | 引数 | プレイヤー名 |

## 2. インベントリオープン

イベント物理名: `InventoryOpenEvent`
クラス名: `MenuOpenEventHandler`
物理名: `onInventoryOpen`

責務:

インベントリを開いた直後にクラフト欄ショートカットを再描画し、カスタムGUIなら BAG 中央制御を閉じる表示へ変更する。

処理内容:

1. event player が Player の場合、クラフトショートカット再描画を予約する
2. 開いた inventory が menu 管理 GUI または crafting view の場合、inventory feature の hotbar shortcut mode を有効化する

## 3. インベントリクリック

イベント物理名: `InventoryClickEvent`
クラス名: `MenuOpenEventHandler`
物理名: `onInventoryClick`

責務:

menu 管理 GUI、クラフト欄ショートカット、メニュー表示中の BAG／ホットバークリックを処理する。

プラグイン管理 GUI の `InventoryClickEvent` は、個別 GUI ではなく共通入口で 5tick 相当のクリッククールタイムを適用する。クールタイム中のクリックはキャンセル済みとして扱い、各 GUI のクリックハンドラはキャンセル済みイベントを処理しない。

処理内容:

1. クリック実行プレイヤーから `AstPlayerCache` 経由で `AstPlayer` を取得する。未取得の場合は `GuiSound.DENY` を再生して終了する
2. top inventory が menu 管理 GUI の場合、まず [[09_3.01-イベント]].メニュー表示中プレイヤーインベントリクリック へ `AstPlayer` を渡して委譲する。処理済みなら終了する
3. menu 画面が `EQUIPMENT_GUI` の場合、装備操作は inventory feature 側へ委譲して終了する
4. menu 管理 GUI 内のその他クリックは menu 画面遷移処理へ `AstPlayer` を渡して委譲する
5. アカウントモードが `PLAYER` でなければ終了する
6. クラフト欄への NUMBER_KEY / SWAP_OFFHAND は拒否音で終了する
7. ビュー種別が CRAFTING でなければ終了する
8. クラフト成果物スロットならメインメニューを開く
9. 2x2 クラフトスロットなら対応ショートカット項目を実行する

備考:

- `AstPlayer` 取得は本メソッド先頭で一度だけ行い、以降の画面別ハンドラ・ショートカット実行・通貨 GUI クリック処理には引数で渡す。各ハンドラ内で再取得しない。

## 4. ショートカット項目実行

クラス名: `MenuOpenEventHandler`
物理名: `executeShortcutAction`

責務:

[[09_1.00-モデル定義]].メニューショートカット項目 に対応する画面遷移を実行する。

処理内容:

1. `NONE` は拒否音を再生する
2. `MAIN_MENU` はメインメニューを開く
3. `STATUS` はステータス画面を開く
4. 通貨 action は通貨 GUI を開く
5. `EQUIPMENT_GUI` は装備 GUI を開く
6. 未対応 action は拒否音を再生する

## 4.1 メインメニュー項目クリック

クラス名: `MenuOpenEventHandler`
物理名: `handleMainMenuClick`

責務:

メインメニュー各項目の遷移・実行を担当する。

処理内容:

1. status / 設定 / 装備 / ゴミ箱 / ガイド / バフ / スキル / メール / 冒険記録 / 通貨 / パーティー / プレイヤー一覧は既存 feature の GUI オープン処理へ委譲する
2. `RETURN_TO_BASE_SLOT` は `AstPlayer` を取得し、未取得なら拒否音で終了する
3. `RETURN_TO_BASE_SLOT` では選択音を再生し、メニュー GUI を閉じる
4. GUI クローズ後に world feature の `ReturnToBaseService.beginReturn` を呼び、参加時スポーン地点への帰還待機を開始する
5. 待機開始後、3 秒間移動がなければ帰還し、移動した場合はキャンセルする

## 8. インベントリドラッグ抑止

イベント物理名: `InventoryDragEvent`
クラス名: `MenuOpenEventHandler`
物理名: `onInventoryDrag`

責務:

menu 管理 GUI とクラフト欄ショートカット領域へのドラッグ操作を抑止する。

処理内容:

1. top inventory が menu 管理 GUI の場合、event をキャンセルし、操作プレイヤーへ拒否音を再生して終了する
2. 通常プレイヤーモードでなければ終了する
3. ドラッグ対象 raw slot にクラフト枠（成果物・2x2 ショートカット枠）が含まれる場合、クラフトショートカット再描画を予約する
4. 例外時は runSafely で [[09_5.00-例外・ログ・運用]] のメニュー系イベント失敗ログを記録する

## 8.1 クラフトショートカットダミーのドロップ抑止

イベント物理名: `PlayerJoinEvent` / `PlayerQuitEvent` / `PlayerChangedWorldEvent` / `PlayerDropItemEvent` / `ItemSpawnEvent` / `EntityPickupItemEvent`
クラス名: `MenuOpenEventHandler`
物理名: `onPlayerJoin` / `onPlayerQuit` / `onPlayerChangedWorld` / `onPlayerDropItem` / `onItemSpawn` / `onEntityPickupItem`

責務:

プレイヤークラフト欄に表示するメニューショートカット用ダミーアイテムが、参加・退出・ワールド移動・インベントリ同期などのタイミングで実体 Item Entity として残ったり、拾得でプレイヤーインベントリへ入ったりしないようにする。

処理内容:

1. クラフトショートカット用ダミーは `MenuView.isCraftShortcutItem` で判定し、通常の Mob ドロップ・採集報酬・プレイヤー所持品とは区別する。
2. `PlayerJoinEvent` では参加直後と 2 tick 後にクラフト欄・カーソル・プレイヤーインベントリ上のダミーを掃除してから、クラフトショートカット再描画を予約する。
3. `PlayerQuitEvent` と `PlayerChangedWorldEvent` ではクラフト欄・カーソル・プレイヤーインベントリ上のダミーを掃除し、ドロップ化し得る残留を先に除去する。
4. `PlayerDropItemEvent` でドロップ対象がクラフトショートカット用ダミーの場合、event を cancel し、生成済み Item Entity を remove する。
5. `ItemSpawnEvent` で spawn 対象がクラフトショートカット用ダミーの場合、event を cancel する。
6. `EntityPickupItemEvent` で拾得対象がクラフトショートカット用ダミーの場合、event を cancel し、対象 Item Entity を remove する。カスタムアイテム付与はこの経路では行わない。
7. 60 秒周期で全ワールドの Item Entity を走査し、クラフトショートカット用ダミーだけを remove する。
8. 上記の清掃中は対象プレイヤーのクラフトショートカット描画を一時抑止し、掃除した直後に再描画が割り込まないようにする。

## 9. メニュー表示中プレイヤーインベントリクリック

クラス名: `MenuOpenEventHandler`
物理名: `handleMenuHotbarShortcutClick`

責務:

menu 管理 GUI を開いている間にプレイヤーがホットバー領域（slot 0〜8）をクリックした場合、inventory feature の hotbar shortcut click 処理へ委譲する。

処理内容:

1. クリック対象が `PlayerInventory` のホットバー領域（slot 0〜8）でなければ未処理を返す
2. event をキャンセルする
3. `AstPlayer` を取得する。未取得、または hotbar shortcut mode が無効なら `GuiSound.DENY` を再生して処理済みを返す
4. `HOTBAR_SHORTCUT` のクリッククールタイムを取得できなければ、音を再生せず処理済みを返す
5. `InventoryService.handleHotbarShortcutClick` へ委譲する
6. 委譲結果が `false` の場合は `GuiSound.DENY` を再生する
7. BAG スクロール・閉じる・通常 BAG／ホットバー操作を処理し、結果に応じた GUI 音を再生する
8. 処理済みを返す

備考:

- menu を開いていない状態の BAG／ホットバークリックは inventory feature 側で処理する。menu 側はメニュー表示中のみの分岐ルーティングに責務を限定する。

## 10. 通貨 GUI クリック

クラス名: `MenuOpenEventHandler`
物理名: `handleCurrencyClick`

責務:

通貨 GUI 上の前後ページ・戻るクリックを処理する。閉じる操作はプレイヤーインベントリ側の共通ホットバー処理が担当する。

処理内容:

1. クリック raw slot が「戻る」スロットの場合、`GuiSound.SELECT` を再生しメインメニューを開いて終了する
2. 現在 inventory の `MenuInventoryHolder.pageIndex` と currency feature から取得した ItemStack 一覧を参照する
3. クリック raw slot が「前ページ」かつ前ページが存在するなら `GuiSound.SELECT` を再生し `MenuView.openCurrency(player, items, pageIndex - 1)` を呼ぶ
4. クリック raw slot が「次ページ」かつ次ページが存在するなら `GuiSound.SELECT` を再生し `MenuView.openCurrency(player, items, pageIndex + 1)` を呼ぶ
5. 上記いずれにも該当しない場合は `GuiSound.DENY` を再生する

備考:

- ページ番号の保持と再描画は `MenuInventoryHolder` と `MenuView.openCurrency` の責務とする。event handler はクリック種別を判定して再描画を依頼することに責務を限定する。

## 11. クラフトショートカット描画

クラス名: `MenuOpenEventHandler`
物理名: `renderCraftShortcuts`

責務:

現在の設定と表示インベントリ種別をもとにクラフト欄ショートカットを描画する。

処理内容:

1. 描画抑止フラグが立っているなら終了する
2. `AstPlayerCache` からセッションを取得し、アカウントモードが `PLAYER` でなければ終了する
3. 自プレイヤーの描画抑止フラグを一時的に立ててから以降の処理を実行し、`finally` で解除する
4. `MenuShortcutSettings.defaults()` から固定ショートカット設定を取得する
5. inventory feature から現在表示中インベントリ種別を取得する（アカウントモードが GUI 反映対象外の場合は `null` を渡す）
6. `MenuView.renderCraftShortcuts` を呼び出す

備考:

- 描画抑止フラグは `MenuOpenEventHandler` 内の `craftRenderSuppressed`（プレイヤー UUID 集合）で管理する。メインメニュー／通貨 GUI の遷移中は明示的に抑止し、遷移完了後に解除する。
- クラフト欄ショートカットはアイコン表示のみで、実際のクラフト処理は行わない。

## 追記（ゴミ箱GUIイベント）
### ゴミ箱GUIクリック
クラス名: TrashService
物理名: handleTrashClick
- ゴミ箱GUIでは通常スロット（0-44）へのアイテム移動を許可する。
- 下段制御スロット（前ページ/ガイド/戻る/廃棄/次ページ）は移動不可。
- 戻る押下時は確認画面を出さず、メインメニューへ戻る（廃棄しない、ゴミ箱内容は dict に保持して次回開いた際に復元する）。
- ゴミ箱GUI下の BAG／ホットバークリックも、通常の menu 管理 GUI と同じ共通処理へ委譲する。
- 廃棄ボタン（slot 51）押下時は廃棄確認GUIを表示する。
- プレイヤーインベントリ側のアイテムクリックは、`ClickType` に応じて転送個数を決定する。
  - `LEFT`: 1 個をゴミ箱へ送る。
  - `SHIFT_LEFT`: 対象スタックすべてをゴミ箱へ送る。
  - `RIGHT`: 対象スタックの半分（端数切り上げ）をゴミ箱へ送る。
  - 装備・ルーンなどインスタンス系アイテムはクリック種別に関わらず常に 1 インスタンス全量を送る。
  - `InventoryService.takeDisplayedItemAmount` で転送個数分をプレイヤーインベントリから取り出す。
  - 取り出した ItemStack は `trashItemsByPlayer` の保持リストへ加算し、`normalizeTrashItems` で通常の Minecraft スタック上限に従って再集約する。
  - 再集約後は GUI を開き直さず、現在開いているページの内容スロットとナビゲーションだけを再描画する。
- ゴミ箱GUI内コンテンツスロットのクリックは、対象スロットの ItemStack 量に対し同じ `ClickType` ルール（LEFT=1 / SHIFT_LEFT=全量 / RIGHT=半分切り上げ）で個数を決定し、`InventoryService.returnItemToOwnedInventory` でプレイヤーインベントリへ返却する。返却後は `trashItemsByPlayer` の保持リストを更新し、再集約した現在ページだけを再描画する。
- カーソルにアイテムを持った状態でゴミ箱コンテンツスロットをクリックした場合は拒否音を再生して無視する。

### ゴミ箱確認GUIクリック
クラス名: TrashService
物理名: handleTrashConfirmClick
- アイテム移動は常に不可。
- 廃棄アイコン押下で保持中アイテムを破棄する。
- ゴミ箱GUIに戻るアイコン押下で廃棄せず戻る。

### ゴミ箱系GUIクローズ
クラス名: TrashService
物理名: handleTrashClose
- ゴミ箱GUIを閉じた場合（ESC / X など、戻る／廃棄ボタン以外の経路）はゴミ箱内のアイテムを全件 `InventoryService.returnItemToOwnedInventory` でプレイヤーインベントリへ戻し、保持データ（`trashItemsByPlayer`）をクリアする。返却対象が 1 件以上ある場合は「ゴミ箱GUI内の○件のアイテムをインベントリに戻しました。」メッセージと GUI 選択音を送る。
- ゴミ箱GUIを「戻る」ボタン経由で閉じた場合は、現在ページのアイテムスナップショットを `trashItemsByPlayer` に保存し、メインメニューへ遷移する。
- ゴミ箱GUIを「廃棄」ボタン経由で閉じた場合は、廃棄確認GUI への遷移として扱い、`suppressTrashConfirmOnClose` で返却処理を抑止する。
- ゴミ箱確認GUIを閉じた場合は廃棄アイコン押下と同等の破棄処理を行う。廃棄件数が 1 件以上ある場合は「○件のアイテムを削除しました。」メッセージを送る。
- ページ跨ぎでアイテムが存在する状態で閉じた場合は、現在ページのスナップショットに加えて `trashItemsByPlayer` の他ページ分も合わせて返却対象に含める。

メッセージ:

| ID | テンプレート | 出力条件 | 引数 |
|---|---|---|---|
| `-` | `ゴミ箱GUI内の{0}件のアイテムをインベントリに戻しました。` | 通常 close で返却対象が 1 件以上ある場合 | `返却件数` |
| `-` | `{0}件のアイテムを削除しました。` | ゴミ箱確認 GUI の close または廃棄確定で廃棄対象が 1 件以上ある場合 | `廃棄件数` |
## 追記（2026-05-29）ゴミ箱GUIの集約スタック処理

- ゴミ箱GUIのコンテンツスロットでは、表示用プレースホルダーの `GRAY_STAINED_GLASS_PANE` を空スロットとして扱う。
- プレイヤーインベントリからゴミ箱GUIへ移動する際は、転送分を `trashItemsByPlayer` の保持リストへ加算してから `normalizeTrashItems` で通常の Minecraft スタック上限まで同一 itemId / itemCategory の ItemStack に集約する。装備・ルーンなど instanceId と紐づくアイテムは itemId だけでは集約しない。
- 同一 ItemStack で積み切れなかった余剰分は、保持リスト上で後続の ItemStack として分割する。
- 再描画は開いているゴミ箱GUIの現在ページに対して行い、アイテム追加・返却だけで GUI を開き直さない。
- ゴミ箱GUI内からアイテムを戻す際は、集約後の `amount` を基準に `LEFT=1 / SHIFT_LEFT=全量 / RIGHT=半分切り上げ` を適用する。

## 追記（2026-06-02）売却GUIイベント

### 売却GUIクリック
クラス名: SellService
物理名: handleSellClick
- 売却GUIはゴミ箱GUIと同じクリック仕様で、プレイヤーインベントリ側から `LEFT=1 / SHIFT_LEFT=全量 / RIGHT=半分切り上げ` の数量を売却枠へ移動する。
- 売却枠内では同種アイテムを通常の Minecraft スタック上限まで同一スロットへ優先マージする。表示用 lore は類似判定から除外する。
- `ItemModel.unSellable = true` または itemId を解決できないアイテムは売却枠へ移動せず、売却不可メッセージを送る。
- 売却枠内アイテムのクリックは同じ数量ルールで `InventoryService.returnItemToOwnedInventory` により元インベントリへ戻す。
- 確認ボタン押下時は売却確認GUIを表示する。戻るまたは通常クローズ時は売却枠内のアイテムを返却する。

メッセージ:

| ID | テンプレート | 出力条件 | 引数 |
|---|---|---|---|
| `-` | `このアイテムは売却できません。` | 売却 GUI へ移動しようとした item が売却不可または itemId 未解決の場合 | なし |

### 売却確認GUIクリック
クラス名: SellService
物理名: handleSellConfirmClick
- 確定アイコン押下で売却枠内アイテムを消費し、`saleValue * amount` の合計を `InventoryService.addGold` で通貨インベントリへ加算する。
- 戻るアイコン押下時は売却せず売却GUIへ戻る。

## 追記: 2026-06-13 クラスGUIの転職判定

- `MenuOpenEventHandler.handleClassClick` は GUI クリック時に `PlayerClassService.canChangeClass` を使って転職可否を判定する。
- 通常ユーザーは `unlockLevel` と `unlockClassLevel` の両方を満たした場合のみ転職できる。
- `acolyte` / `hunter` / `mage` / `swordsman` は filebase 定義どおり、`adventurer` Lv.10 を満たした場合のみ GUI から転職できる。
- 管理者権限ユーザーは GUI 上の表示では未達条件を通常ユーザーと同じく確認できるが、クリック時の転職実行では条件を無視して転職できる。
- 転職成功時はクラス変更メッセージ送信後に選択サウンドを再生し、クラス GUI を自動で閉じる。
- 転職条件未達で失敗した場合は、クラス変更も GUI クローズもサウンド再生も行わない。
- `/class` 系コマンドの実行権限は従来どおり ADMIN のままとする。
