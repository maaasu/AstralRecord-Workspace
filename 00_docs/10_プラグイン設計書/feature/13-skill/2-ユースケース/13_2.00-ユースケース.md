# 13_2.00-ユースケース

## 1. 起動時にスキル定義を同期する

- Plugin 起動時に API からスキル定義を全件取得する。
- `implementationId` ごとに実行クラスの登録有無を検査する。
- 取得成功分のみレジストリへ反映し、失敗内容はログへ残す。

## 2. プレイヤーがスキルを発動する

- プレイヤー入力またはクラス習得情報から対象スキル ID を解決する。
- `requiredLevel` / MP / cooldown / cast time を共通検証する。
- `implementationId` に対応する実行クラスへ処理を委譲する。

## 3. Mob がスキルを発動する

- Mob AI が `ai.combat.skills` からスキル ID を選択する。
- Mob 用コンテキストを生成し、プレイヤーと同じ共通制御を通して実行する。
- 個別ロジックはプレイヤー発動と同じ `SkillExecutor` を再利用する。

## 4. 同一ロジックを複数定義で使い分ける

- `fireball_a` / `fireball_b` のように同一 `implementationId` を共有する。
- 差分は `params` で与え、色・威力・速度・範囲などを切り替える。

## 5. 管理者が定義を再読み込みする

- 将来的に reload コマンドや起動時再同期で定義を更新する。
- `params` 不備や未登録 `implementationId` はスキル単位で隔離し、全体停止は避ける。
