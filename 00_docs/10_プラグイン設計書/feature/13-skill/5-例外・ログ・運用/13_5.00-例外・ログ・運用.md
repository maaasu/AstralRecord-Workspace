# 13_5.00-例外・ログ・運用

## 1. 共通エラー方針

| ステータス | 取り扱い | 備考 |
|---|---|---|
| API 取得失敗 | 起動継続可 | 既存キャッシュがあれば維持、なければ skill feature を無効化 |
| 実行クラス未登録 | 定義単位で無効化 | `implementationId` をログへ出す |
| `params` 型不正 | 定義単位で無効化 | 具体的な不足キー・型不一致をログへ出す |
| 発動時例外 | 発動失敗 | 発動者へ共通エラーメッセージを返す |

## 3. 運用上の方針

- `implementationId` と実装クラスの対応表は Plugin 側の責務とする。
- `params` の詳細定義は Plugin 実装ごとに持ち、API や filebase 共通スキーマには持ち込まない。
- 起動不能より部分無効化を優先し、不正定義はスキル単位で隔離する。
- reload 機構を追加する場合も、反映単位は検証後スワップを前提とする。
