# 13_3.02-サービス

## スキル定義同期
クラス名: `SkillService`
物理名: `reloadDefinitions`

1. [[13_3.04-リポジトリ]].スキル全件取得 を呼び出す
2. 一覧レスポンスの `id` ごとに [[13_3.04-リポジトリ]].スキル詳細取得 を呼び出す
3. 取得した各スキル定義について `implementationId` が空でないことを検証する
4. [[13_3.06-レジストリ・キャッシュ]].実行クラス解決 で `implementationId` に対応する実行クラスを確認する
5. `SkillExecutor.validateParams` を呼び出し、`params` 妥当性を検証する
6. 検証成功分だけを新しい定義一覧として構築し、[[13_3.06-レジストリ・キャッシュ]].スキル定義反映 でレジストリへ一括反映する
7. 一覧取得自体が失敗した場合はレジストリを置換せず、既存定義が 1 件以上あれば現在件数を維持して呼び出し元へ返す。既存定義が空の場合は skill feature を無効化し、以下ログを記録する

    | 項目 | 内容 |
    |---|---|
    | ID | LogId.E_5803 |
    | レベル | Error |
    | テンプレート | スキル定義の取得に失敗し、既存キャッシュも空のため skill feature を無効化しました: reason=%s |
    | 出力条件 | API 一覧取得失敗かつ既存定義が空の時 |
    | 引数 | 失敗理由 |

8. 未登録 `implementationId` または不正 `params` はスキップし、以下ログを記録する

    | 項目 | 内容 |
    |---|---|
    | ID | LogId.W_5801 |
    | レベル | Warning |
    | テンプレート | スキル定義を読み込みませんでした: skillId=%s, implementationId=%s, reason=%s |
    | 出力条件 | 実行クラス未登録または検証失敗時 |
    | 引数 | スキル ID、implementationId、理由 |

## スキル発動
クラス名: `SkillService`
物理名: `castSkill`

引数として発動者 / `skillId` / `SkillCastTrigger` / 発動位置 `castLocation` / 主対象 / 追加対象群を受け取る（発動位置を caster から取得せず引数で渡すことで、コマンド・AI など由来別のオフセット計算を呼び出し側で済ませる）。

1. `skillId` で [[13_3.06-レジストリ・キャッシュ]].スキル定義解決 を行う
2. 発動者のステータスから `requiredLevel` / `manaCost` を検証する
3. 発動者の現在クールダウンを確認し、未終了なら失敗結果を返す
4. `castTimeTicks` はモデルとして保持するが、現実装では詠唱ハンドリングは未実装
5. `onCastSound` が定義されている場合は共通サウンドを再生する
6. [[13_3.06-レジストリ・キャッシュ]].実行クラス解決 で `implementationId` を解決する
7. `SkillCastContext` を構築し、実行クラスへ委譲する
8. 戻り値 `SkillCastResult.success` が `true` の場合、`SkillCastResult.consumedMana` と `startedCooldownTicks` の値をそのまま共通適用する（MP 消費 / cooldown 開始は本サービスが実行し、実行クラス側では行わない。cooldown は本ファイル「クールダウン管理」の `startCooldown` を経由する）
9. 失敗結果の `messageId` が設定されている場合は `SkillCaster.notify(messageId, ...)` で発動者へ通知する
10. 失敗時は以下ログを記録する

    | 項目 | 内容 |
    |---|---|
    | ID | LogId.E_5802 |
    | レベル | Error |
    | テンプレート | スキル発動に失敗しました: skillId=%s, implementationId=%s |
    | 出力条件 | 実行クラスで例外発生時 |
    | 引数 | スキル ID、implementationId |

## 実行可否判定
クラス名: `SkillService`
物理名: `canCast`

1. `requiredLevel` を発動者レベルと比較する
2. `manaCost` を現在 MP と比較する
3. cooldown 状態を確認する
4. 判定結果を `SkillCastResult` で返す

## クールダウン管理
クラス名: `SkillService`

[[13_1.00-モデル定義]].スキル発動者 ではクールダウン状態を保持しない。`SkillService` が発動者 UUID と `skillId` の組み合わせで cooldown 終了時刻を集中管理する。

| 物理名 | 役割 |
|---|---|
| `startCooldown(caster, skillId, cooldownTicks)` | 発動成功時に呼び出され、内部の cooldown マップに終了時刻（`System.currentTimeMillis() + cooldownTicks * 50ms`）を記録する。`cooldownTicks <= 0` の場合は何もしない |
| `isOnCooldown(caster, skillId)` | 発動者ごとに記録された終了時刻と現在時刻を比較し、cooldown 中なら `true` を返す。expire 済みエントリは参照時に削除する |

運用上の寿命管理は [[13_5.00-例外・ログ・運用]] の運用方針に従う（プレイヤー退出時のキャッシュ解放など）。`skillId` は [[13_1.00-モデル定義]].識別子規約 に従い正規化したキーで保持する。
