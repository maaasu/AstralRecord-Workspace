# 13_3.02-サービス

## スキル定義読込

クラス名: `SkillService`
物理名: `reloadDefinitions`

1. [[13_3.04-リポジトリ]].スキル一覧取得 で API スキル一覧を取得する。
2. 一覧取得に成功した場合は、各 `id` ごとに [[13_3.04-リポジトリ]].スキル詳細取得 を呼び出す。
3. 詳細取得が `null` または例外の場合は対象 `skillId` のみ除外し、`LogId.W_5801` に `reason` を含めて記録する。
4. API スキル定義に加えて、plugin 内で定義する built-in スキル定義を結合する。
   - built-in 定義は API スキルマスタ未登録でも利用できる。
   - 通常攻撃用 built-in ID は `normal_attack_melee`、`normal_attack_bow`、`normal_attack_magic` とする。
5. API 詳細取得済み定義と built-in 定義を結合した候補全体に対して、`implementationId` の存在を検証する。
6. [[13_3.06-レジストリ・キャッシュ]].実装クラス解決 で `implementationId` に対応する実装クラスを解決する。
7. `SkillExecutor.validateParams` を呼び出し、`params` 入力整合性を検証する。
8. 読込成功した定義だけを新しい定義一覧として差し替え、[[13_3.06-レジストリ・キャッシュ]].スキル定義公開 でレジストリへ反映する。
9. API 一覧取得に失敗した場合でも、built-in 定義のみで継続する。

    | 項目 | 内容 |
    |---|---|
    | ID | `LogId.E_5801` |
    | レベル | ERROR |
    | テンプレート | スキル一覧の取得に失敗しました |
    | 出力条件 | API スキル一覧取得失敗時 |
    | 引数 | - |

10. 詳細取得失敗、未登録 `implementationId` または不正 `params` は対象スキルだけを除外し、以下ログを記録する。

    | 項目 | 内容 |
    |---|---|
    | ID | `LogId.W_5801` |
    | レベル | WARNING |
    | テンプレート | スキル定義を読み込めませんでした: skillId=%s, implementationId=%s, reason=%s |
    | 出力条件 | API スキル詳細取得失敗、実装クラス未登録または `params` 検証失敗時 |
    | 引数 | スキル ID、`implementationId`、理由 |

## スキル起動

クラス名: `SkillService`
物理名: `castSkill`

入力として `SkillCaster` / `skillId` / `SkillCastTrigger` / 起動位置 `castLocation` / 主対象位置 / 追加対象位置一覧を受け取る。

1. `skillId` で [[13_3.06-レジストリ・キャッシュ]].スキル定義解決 を行う。
2. 起動前に [[13_3.02-サービス]].起動可否判定 を実行する。
   - `requiredLevel` を満たすことを確認する。
   - `resourceType` と `resourceCost` に応じて必要 MP または EN を確認する。
   - `resourceType` 未設定時は `MANA` として扱う。
   - `resourceCost` 未設定時は `manaCost` を互換値として使用する。
3. 起動前に現在クールダウン状態を確認する。
4. `SkillCaster` がプレイヤーで、起動経路が `SkillCastTrigger.AUTO_ATTACK` 以外の場合は、現在の所持スキルに含まれることを確認する。未所持の場合は発動せず通知する。
5. `castTimeTicks > 0` の場合は、起動元種別ごとの詠唱状態を立ててから発動を遅延する。
   - プレイヤー起点では歩行速度を 50% に下げ、アクションバーに詠唱中表示を出す。詠唱中はドッジ、二段ジャンプ、壁張り付き、壁キックを実行できない。
   - Mob 起点では `MobInstance` に詠唱スキル名・総 tick・残 tick を保持し、頭上 TextDisplay の詠唱バー表示に使う。
6. 詠唱完了後、または `castTimeTicks = 0` の場合は即時に、起動可否判定を再実行する。
7. `onCastSound` が定義されている場合は共通起動サウンドを再生する。
8. [[13_3.06-レジストリ・キャッシュ]].実装クラス解決 で `implementationId` を解決する。
9. `SkillCastContext` を生成し、実装クラスへ委譲する。
10. `SkillCastResult.success = true` の場合のみ、`resourceType` に応じて MP または EN を消費する。
11. `SkillCastResult.success = true` かつスキル定義側 `cooldownTicks > 0` の場合は `startCooldown` を呼び出す。
   - 装備 feature 側で別途 `startCooldown` を呼ぶケースは、装備入力固有クールダウンの上書き用とする。
12. 失敗結果の `messageId` が設定されている場合は `SkillCaster.notify(messageId, ...)` で起動元へ通知する。
13. 例外時は以下ログを記録する。

    | 項目 | 内容 |
    |---|---|
    | ID | `LogId.E_5802` |
    | レベル | ERROR |
    | テンプレート | スキル起動に失敗しました: skillId=%s, implementationId=%s |
    | 出力条件 | `SkillExecutor.cast` で例外発生時 |
    | 引数 | スキル ID、`implementationId` |

## 起動可否判定

クラス名: `SkillService`
物理名: `canCast`

1. `requiredLevel` を起動元レベルと比較する。
2. `resourceType` が `MANA` の場合は現在 MP と比較する。
3. `resourceType` が `ENERGY` の場合は現在 EN と比較する。
4. cooldown 状態を確認する。
5. 判定結果を `SkillCastResult` で返す。

## クールダウン操作

クラス名: `SkillService`

[[13_1.00-モデル定義]].スキル起動条件 ではクールダウン状態を保持しない。`SkillService` が起動元 UUID と `skillId` の組み合わせでクールダウン状態を管理する。

| 物理名 | 役割 |
|---|---|
| `startCooldown(caster, skillId, cooldownTicks)` | 起動成功時に呼び出し、対象 `skillId` のクールダウン終了時刻を記録する。`cooldownTicks <= 0` の場合は何もしない。 |
| `isOnCooldown(caster, skillId)` | 記録済み終了時刻と現在時刻を比較し、クールダウン中なら `true` を返す。期限切れエントリは判定時に除去する。 |

詳細な運用は [[13_5.00-例外・ログ・運用]] を参照する。`skillId` は [[13_1.00-モデル定義]].識別子定義 に従う case-sensitive のまま扱う。

## パッシブ状態同期

クラス名: `PassiveSkillService`

パッシブスキルの有効状態は、所持スキル・バインドプリセット・スキルツリー解放状態から算出する。通常 tick では全オンラインプレイヤーを定期再評価せず、変更が発生したプレイヤーだけを dirty として扱う。

| 物理名 | 役割 |
|---|---|
| `markDirty(player/accountId)` | 装備・プリセットなど、所持スキルやバインド状態に影響する変更後に対象を再同期待ちへ入れる |
| `reconcileNow(player)` | プリセット切替や保存など、即時反映が必要な操作で対象プレイヤーをその場で再評価する |
| `reconcileSkillOwnershipDelta(player, addedSkillIds, removedSkillIds, statusAffected)` | スキルツリー由来など、差分が既知の変更だけを反映する |
| `getStatusBonus(player, statusType, baseValue)` | 未同期または dirty の場合だけ再評価してから、現在有効なパッシブ補正を返す |

`SkillTreeService` は解放済みノード由来の `skillIds` が増減した場合、`status_passive` などのステータス補正パッシブを即時反映できるよう `statusAffected=true` として `reconcileSkillOwnershipDelta` を呼び出す。

`tick` は dirty queue を 1 tick あたり少数ずつ処理し、時間経過処理が必要なパッシブだけ `SkillExecutor.onTick` へ配送する。ステータス補正のみのパッシブは通常 tick で呼び出さない。

## アクションリング表示可否

クラス名: `SkillActionRingService`
物理名: `resolveSlots`, `RingSession.tick`

1. アクションリングの各スキルスロットは `SkillService.canCast` の結果を使って、表示中も発動可否を再評価する。
2. 発動可能なスキルは通常色で表示し、選択対象に含める。
3. クールダウン中、MP 不足、EN 不足など発動できないスキルは元のスキルアイコンを維持し、ラベルを赤系にして理由を追記する。
   - クールダウン中: `CD`
   - MP 不足: `MP`
   - EN 不足: `ENG`
   - その他の共通ガード失敗: `NG`
4. 発動不可スロットは選択対象から外し、現在選択中のスロットが発動不可へ変化した場合は選択可能な先頭スロットへ戻す。
