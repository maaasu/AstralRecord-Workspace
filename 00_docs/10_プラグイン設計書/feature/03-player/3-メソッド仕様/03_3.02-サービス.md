# 03_3.02-サービス

## 1. service メソッド仕様

### プレイヤー参加データ読込

クラス名: `PlayerService`  
物理名: `loadPlayerJoinData`

処理内容:

1. [[01_3.02-サービス]].ユーザ取得 で [[01_1.00-モデル定義]].ユーザモデル を取得する
2. ユーザ取得結果が `null` の場合は `LogId.W_5070` を記録して `null` を返す

	| 項目 | 内容 |
	|---|---|
	| ID | `LogId.W_5070` |
	| レベル | `WARN` |
	| テンプレート | `プレイヤー参加データの取得をスキップしました: player=%s, reason=%s` |
	| 出力条件 | ユーザ取得結果が `null` |
	| 引数 | プレイヤー名, `user not found` |

3. [[02_3.01-サービス]].選択アカウント取得 で [[02_1.00-モデル定義]].アカウントモデル を取得する
4. 選択アカウント取得結果が `null` の場合は `LogId.W_5070` を記録して `null` を返す

	| 項目 | 内容 |
	|---|---|
	| ID | `LogId.W_5070` |
	| レベル | `WARN` |
	| テンプレート | `プレイヤー参加データの取得をスキップしました: player=%s, reason=%s` |
	| 出力条件 | 選択アカウント取得結果が `null` |
	| 引数 | プレイヤー名, `account not found` |

5. [[03_1.00-モデル定義]].プレイヤー参加データ を返す

### プレイヤー参加反映

クラス名: `PlayerService`  
物理名: `applyPlayerJoin`

処理内容:

1. プレイヤーがオンラインかつ未キャッシュであることを確認する
2. [[03_1.00-モデル定義]].プレイヤーセッション を生成する
3. [[03_3.04-キャッシュ]].プレイヤーキャッシュ登録 を実行する
4. アカウントモードが通常プレイヤーの場合、inventory feature へ GUI インベントリ反映を依頼する
5. [[07_3.02-サービス]].ステータス再計算 を実行する

### ログインボーナス表示

クラス名: `LoginBonusService`
物理名: `openAfterDataLoaded`

処理内容:

1. [[03_3.04-キャッシュ]].プレイヤーキャッシュ取得で [[03_1.00-モデル定義]].プレイヤーセッション を取得する
2. セッション未ロードまたはプレイヤーがオフラインの場合は何もせず終了する
3. アカウントIDごとに当日（Asia/Tokyo）の受け取り状態を確認する
4. 当日未受け取りであれば当日の日付を記録し、`gold` を `1000` 付与してからログインボーナス GUI を開く
5. 当日受け取り済みであれば `本日は受け取り済み` 表記のログインボーナス GUI を開く

### プレイヤー退出処理

クラス名: `PlayerService`  
物理名: `onPlayerQuit`

処理内容:

1. [[03_3.04-キャッシュ]].プレイヤーキャッシュ取得で [[03_1.00-モデル定義]].プレイヤーセッション を取得する
2. セッションがある場合、[[03_3.05-保存]].プレイヤー保存実行 を実行する（保存契機: `LOGOUT`）
3. [[03_3.04-キャッシュ]].プレイヤーキャッシュ削除を実行する

### ログイン履歴登録

クラス名: `PlayerService`  
物理名: `recordLoginHistory`

処理内容:

1. `eventType=PLAYER_LOGIN`、`source=PLUGIN`、`message=Player login: <playerName>` を組み立てる
2. [[01_3.02-サービス]].ユーザー履歴登録 を呼び出す

### ログアウト履歴登録

クラス名: `PlayerService`  
物理名: `recordLogoutHistory`

処理内容:

1. `eventType=PLAYER_LOGOUT`、`source=PLUGIN`、`message=Player logout: <playerName>` を組み立てる
2. [[01_3.02-サービス]].ユーザー履歴登録 を呼び出す

### 全オンラインプレイヤー保存

クラス名: `PlayerService`  
物理名: `saveAllOnlinePlayersAndClear`

処理内容:

1. [[03_3.04-キャッシュ]].全プレイヤーキャッシュ取得で全セッションを取得する
2. 各セッションに対し [[03_3.05-保存]].プレイヤー保存実行 を実行する（保存契機: `PLUGIN_DISABLE`）
3. [[03_3.04-キャッシュ]].プレイヤーキャッシュ全削除を実行する

### 地上ドッジ受付開始

クラス名: `DodgeService`
物理名: `beginSneakWindow`

処理内容:

1. 既存のドッジ受付状態をクリアする
2. 通常プレイヤー、オンライン、生存、地上であることを確認する
3. しゃがみ開始時刻・しゃがみ開始座標・ドッジ受付終了時刻を [[03_1.00-モデル定義]].プレイヤーセッション へ記録する
4. `hud` feature へドッジ受付バー表示を依頼する

### しゃがみ解除ドッジ判定

クラス名: `DodgeService`  
物理名: `tryTriggerOnSneakRelease`

処理内容:

1. ドッジ受付バーを解除し、HUD の ActionBar を通常のリソース表示へ戻す
2. しゃがみ開始時刻・しゃがみ開始座標を取り出し、[[03_1.00-モデル定義]].プレイヤーセッション 側はクリアする
3. ドッジ受付終了時刻をクリアする
4. しゃがみ開始時刻が記録されているか確認する
5. しゃがみ時間が `250ms` 未満か確認する
6. プレイヤーがオンラインかつ生存しており、現在も地上であることを確認する
7. エネルギー不足の場合は失敗音を再生して終了する
8. 条件を満たす場合はドッジを実行する

### ドッジ実行

クラス名: `DodgeService`  
物理名: `executeDodge`

処理内容:

1. [[07_3.02-サービス]].EN消費 でエネルギーを `15` 消費する
2. しゃがみ開始座標から現在座標への XZ ベクトルでドッジ方向を計算する（移動量が極小の場合は視線方向にフォールバックする）
3. Bukkit プレイヤーへ速度を設定する
4. [[03_1.00-モデル定義]].プレイヤーセッション のドッジ中フラグを `true` に更新する
5. 効果音・パーティクルを再生する
6. `8tick` 後にドッジ中フラグを解除する

### jump入力処理

クラス名: `AirActionService`
物理名: `handleJumpInput`

処理内容:

1. `PlayerInputEvent` の jump 押下状態を [[03_1.00-モデル定義]].プレイヤーセッション.isJumpInputPressed へ反映する
2. 地上なら [[03_1.00-モデル定義]].プレイヤーセッション.isAirJumpConsumed を解除して終了する
3. 空中で jump 押下が立ち上がった場合のみ、通常プレイヤー・生存・未消費・壁張り付き中でないことを確認する
4. 条件を満たす場合は二段ジャンプを実行する

### 壁張り付き開始

クラス名: `AirActionService`
物理名: `tryStartWallCling`

処理内容:

1. 通常プレイヤー、オンライン、生存、空中であることを確認する
2. 正面近距離のレイ判定で固体ブロックを検出し、壁方向ベクトルを得る
3. [[03_1.00-モデル定義]].プレイヤーセッション へ壁方向・壁張り付き終了時刻・壁張り付き中フラグを記録する
4. 重力を停止し、速度を `0` にしてその場で静止させる
5. `hud` feature へ壁張り付きバー表示を依頼する
6. `1 tick` 間隔タスクで、時間切れまたはスニーク解除まで静止状態を維持する

### 壁張り付き解除

クラス名: `AirActionService`
物理名: `releaseWallCling`

処理内容:

1. 壁張り付き中でなければ何もしない
2. 現在の視線方向と壁方向ベクトルの角度が `120度` 以上離れているか判定する
3. 壁張り付き維持タスクを停止し、重力停止・壁張り付き状態・壁張り付きバー表示を解除する
4. 条件を満たした場合のみ、現在の視線方向へ壁キックを実行する
