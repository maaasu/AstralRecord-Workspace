# 03_3.02-サービス

## 1. service メソッド仕様

### プレイヤー参加データ読込

クラス名: `PlayerService`  
物理名: `loadPlayerJoinData`

処理内容:

1. [[01_3.02-サービス]].ユーザ取得 で [[01_1.00-モデル定義]].ユーザモデル を取得する
2. ユーザ取得結果が `null` の場合は `LogId.W_5070` を記録して `null` を返す

	| 項目 | 内容 |
	|---|---|
	| ID | `LogId.W_5070` |
	| レベル | `WARN` |
	| テンプレート | `プレイヤー参加データの取得をスキップしました: player=%s, reason=%s` |
	| 出力条件 | ユーザ取得結果が `null` |
	| 引数 | プレイヤー名, `user not found` |

3. [[02_3.01-サービス]].選択アカウント取得 で [[02_1.00-モデル定義]].アカウントモデル を取得する
4. 選択アカウント取得結果が `null` の場合は `LogId.W_5070` を記録して `null` を返す

	| 項目 | 内容 |
	|---|---|
	| ID | `LogId.W_5070` |
	| レベル | `WARN` |
	| テンプレート | `プレイヤー参加データの取得をスキップしました: player=%s, reason=%s` |
	| 出力条件 | 選択アカウント取得結果が `null` |
	| 引数 | プレイヤー名, `account not found` |

5. [[03_1.00-モデル定義]].プレイヤー参加データ を返す

### プレイヤー参加反映

クラス名: `PlayerService`  
物理名: `applyPlayerJoin`

処理内容:

1. プレイヤーがオンラインかつ未キャッシュであることを確認する
2. [[03_1.00-モデル定義]].プレイヤーセッション を生成する
3. [[03_3.04-キャッシュ]].プレイヤーキャッシュ登録 を実行する
4. アカウントモードが通常プレイヤーの場合、inventory feature へ GUI インベントリ反映を依頼する
5. [[07_3.02-サービス]].ステータス再計算 を実行する

### プレイヤー退出処理

クラス名: `PlayerService`  
物理名: `onPlayerQuit`

処理内容:

1. [[03_3.04-キャッシュ]].プレイヤーキャッシュ取得で [[03_1.00-モデル定義]].プレイヤーセッション を取得する
2. セッションがある場合、[[03_3.05-保存]].プレイヤー保存実行 を実行する（保存契機: `LOGOUT`）
3. [[03_3.04-キャッシュ]].プレイヤーキャッシュ削除を実行する

### ログイン履歴登録

クラス名: `PlayerService`  
物理名: `recordLoginHistory`

処理内容:

1. `eventType=PLAYER_LOGIN`、`source=PLUGIN`、`message=Player login: <playerName>` を組み立てる
2. [[01_3.02-サービス]].ユーザー履歴登録 を呼び出す

### ログアウト履歴登録

クラス名: `PlayerService`  
物理名: `recordLogoutHistory`

処理内容:

1. `eventType=PLAYER_LOGOUT`、`source=PLUGIN`、`message=Player logout: <playerName>` を組み立てる
2. [[01_3.02-サービス]].ユーザー履歴登録 を呼び出す

### 全オンラインプレイヤー保存

クラス名: `PlayerService`  
物理名: `saveAllOnlinePlayersAndClear`

処理内容:

1. [[03_3.04-キャッシュ]].全プレイヤーキャッシュ取得で全セッションを取得する
2. 各セッションに対し [[03_3.05-保存]].プレイヤー保存実行 を実行する（保存契機: `PLUGIN_DISABLE`）
3. [[03_3.04-キャッシュ]].プレイヤーキャッシュ全削除を実行する

### しゃがみ解除ドッジ判定

クラス名: `DodgeService`  
物理名: `tryTriggerOnSneakRelease`

処理内容:

1. ドッジ受付バーを解除し、HUD の ActionBar を通常のリソース表示へ戻す
2. しゃがみ開始時刻・しゃがみ開始座標を取り出し、[[03_1.00-モデル定義]].プレイヤーセッション 側はクリアする
3. ドッジ受付終了時刻をクリアする
4. しゃがみ開始時刻が記録されているか確認する
5. しゃがみ時間が `250ms` 未満か確認する
6. プレイヤーがオンラインかつ生存しているか確認する
7. エネルギー不足の場合は失敗音を再生して終了する
8. 条件を満たす場合はドッジを実行する

### ドッジ実行

クラス名: `DodgeService`  
物理名: `executeDodge`

処理内容:

1. [[07_3.02-サービス]].EN消費 でエネルギーを `15` 消費する
2. しゃがみ開始座標から現在座標への XZ ベクトルでドッジ方向を計算する（移動量が極小の場合は視線方向にフォールバックする）
3. Bukkit プレイヤーへ速度を設定する
4. [[03_1.00-モデル定義]].プレイヤーセッション のドッジ中フラグを `true` に更新する
5. 効果音・パーティクルを再生する
6. `8tick` 後にドッジ中フラグを解除する
