# 14_5.00-例外・ログ・運用

## 1. ログ

| ID | レベル | テンプレート | 出力箇所 |
|---|---|---|---|
| LogId.E_5900 | Error | 戦闘ダメージ処理に失敗しました: %s | [[14_3.01-イベント]].エンティティ間ダメージ受信 の `runSafely` 例外時 |

ログ ID の範囲は `5900-5999` を `feature/combat/` に割り当てる（`logger.properties` 末尾セクション）。

## 2. プレイヤーメッセージ

| ID | 用途 |
|---|---|
| `PlayerMsgId.P_5350` | プレイヤーの与ダメージ詳細 |
| `PlayerMsgId.P_5351` | プレイヤー攻撃が回避された場合の詳細 |
| `PlayerMsgId.P_5352` | プレイヤーの被ダメージ詳細 |
| `PlayerMsgId.P_5353` | プレイヤーが回避した場合の詳細 |

メッセージ送信は `PlayerMessageService` を経由し、`DAMAGE_LOG_MESSAGE` が `true` のプレイヤーだけを対象とする。既定値は `false` とし、戦闘頻度に比例するチャット量を明示的な opt-in にする。

## 3. スレッド・I/O 制約

- `EntityDamageByEntityEvent` は Bukkit メインスレッドで処理されるため、`DamageService.handleEntityDamage` および `DamageCalculator.calculate` の処理時間は最小化する。
- SQL / YAML 読み込み等の重い I/O は本機能内で行わない。
- 必要な情報は事前にメモリへロード済みの状態（[[07-status]] のキャッシュ・装備バフ等）を参照する。
- 浮遊ダメージは TextDisplay 1 体のみを使用し、騎乗用 ArmorStand 等の追加エンティティは生成しない。
- animation 中の server-side teleport を避け、Display transformation のクライアント補間で移動 packet と entity tick 負荷を抑える。

## 4. 既存ハンドラとの整合

- [[03-player]] 配下 `PlayerVanillaDamageBlockEventHandler` がプレイヤー被弾時の `EntityDamageEvent` を `HIGHEST` 優先度でキャンセルしている。
- 同ハンドラは落下 (`FALL`) と炎 (`FIRE` / `FIRE_TICK`) についてはバニラ被ダメージ演出を再生せず、イベントキャンセルのみを行う。
- 本機能の `CombatDamageEventHandler` は `NORMAL` 優先度で動作するため、上記キャンセルより前に `event.setDamage(...)` を反映するが、`AstPlayer` が被弾者の場合は最終的に `setDamage(0.0)` でキャンセルされる。
- プレイヤーへの最終的な HP 反映は、将来 `DamageService` から `StatusService.consumeHp` を経由して行う（[[14_9.00-未決事項]] を参照）。
