# 14_0.00-概要

## 1. 位置づけ

`combat` 機能は、攻撃者・被弾者・攻撃種別・スキル補正・装備補正等を統合し、最終的な戦闘ダメージを確定する責務を持つ機能である。
Bukkit/Paper のダメージイベントを起点とし、スキル発動・Mob 攻撃などからも同一サービスを経由してダメージを確定させる。

## 2. 設計方針

- ダメージ確定処理は `combat` feature へ集約し、`status` feature の責務（HP/MP/エネルギーの実値更新・バフ適用）と分離する。
- ダメージ計算式は純粋ロジックとして [[14_1.00-モデル定義]].ダメージ計算器 に閉じ込め、Bukkit API への依存を最小化する。
- Bukkit イベントの受信は [[14_3.01-イベント]] に閉じ、計算式や HP 更新は記述しない。
- 攻撃者・被弾者は `AstEntity` に包み、`AstPlayer` / `MobInstance` / Bukkit エンティティの差異を `DamageService` の入口で吸収する。
- プレイヤー HP の実値更新は [[07-status]] 配下 `StatusService` を経由する。Mob HP は `MobInstance.currentHealth` を更新する。

## 3. コンテキスト

- 攻撃発生源はプレイヤー / Mob / 環境 / スキルを想定する。
- 攻撃種別は近接 / 間接 / 魔法の 3 種別を基本とする。
- ダメージ種別は物理 / 魔法 / 純粋（防御無視）の 3 種別を基本とする。
- ダメージ確定処理は Bukkit メインスレッドで実行される前提とし、SQL / YAML 等の重い I/O は行わない。
- 必要なステータス・装備・バフ情報は事前に [[07-status]] 系のキャッシュへロード済みの値を参照する。

## 4. 想定実装

- `service/DamageService`
  - イベント・スキル・Mob 攻撃からの入口。`AstEntity` から `DamageContext` を構築し、プレイヤー / Mob の HP へ計算結果を反映する。
- `service/DamageCalculator`
  - 攻撃力・防御力・クリティカル・属性補正等の純粋計算ロジック。Bukkit API 依存を持たない。
- `event/CombatDamageEventHandler`
  - `EntityDamageByEntityEvent` を受け取り `DamageService` へ委譲する。計算式は持たない。
- `model/AstEntity` / `model/AstEntityType` / `model/DamageContext` / `model/DamageResult` / `model/AttackType` / `model/DamageType`
  - ダメージ計算の入出力を表現するデータモデル。
