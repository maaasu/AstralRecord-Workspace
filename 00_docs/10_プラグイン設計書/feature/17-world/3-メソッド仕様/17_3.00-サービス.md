# World サービス仕様

## WorldRepository

API の `GET /api/world` と `GET /api/world/{worldId}` を呼び出し、`WorldMasterData` に変換する。

## WorldService

`WorldMasterData` の Plugin 側キャッシュとワールド移動を扱う。

| Method | Description |
|---|---|
| `loadAll()` | API から全 `WorldMasterData` を再読込し、ID 順でキャッシュを更新する。続けて `baseWorldPath` を起点に Bukkit ワールドのロードを試行する。絶対パスの world container 直下に加えて `worlds/<baseWorldPath>` と、既存ロード済みワールドの親ディレクトリ候補も探索する。 |
| `reloadFromYaml()` | MasterData Seeder API で filebase YAML を MasterDataDB へ反映し、その後 `loadAll()` を実行してキャッシュと Bukkit ロード状態を更新する。 |
| `getAll()` | キャッシュ済み `WorldMasterData` 一覧を返す。 |
| `showWorldChangeTitle(player)` | `PlayerChangedWorldEvent` 後に現在ワールドの表示名をタイトル表示する。`WorldMasterData` 未登録時は Bukkit ワールド名をそのまま使う。 |
| `getById(worldId)` | 指定 ID の `WorldMasterData` を返す。 |
| `resolveLoadedWorld(data)` | `baseWorldPath`、その末尾名、ワールドフォルダ実体、`data.id` の順で Bukkit ロード済みワールドを解決する。 |
| `findByBukkitWorld(world)` | Bukkit ワールドに対応する `WorldMasterData` をキャッシュから逆引きする。 |
| `resolveSpawnLocation(data)` | `resolveLoadedWorld(data)` と `data.spawnLocation` を組み合わせて `Location` を生成する。 |
| `teleportPlayerAsync(player, targetLocation, onSuccess)` | プレイヤー移動前に `TextDisplay` passenger を解除し、チャンクを事前ロードしてから `teleportAsync` を実行する。完了後は overhead display を遅延再開し、必要なら `onSuccess` を呼ぶ。 |
| `teleportToSpawnAsync(player, data)` | `resolveSpawnLocation(data)` の結果を `teleportPlayerAsync(...)` に委譲する。初期スポーンと `/world tp` はこの導線を使う。 |
| `applyRpgGameRules(world)` | Bukkit ワールドへ RPG 用 gamerule を適用する。Mob 自然スポーン、パトロール、wandering trader、mob griefing、mob loot、entity drop などを無効化し、`keepInventory` と `immediateRespawn` を有効化する。 |

## ReturnToBaseService

`joinSpawn.world` を拠点として扱い、menu feature からの帰還要求を処理する。

| Method | Description |
|---|---|
| `calculateGoldCost(playerLevel)` | 帰還コストを `100 x max(1, playerLevel)` で算出する。 |
| `beginReturn(astPlayer)` | 拠点スポーン `WorldMasterData` とスポーン座標を解決し、3 秒詠唱の帰還処理を開始する。詠唱中は title / subtitle / bossbar / particle / sound を表示し、移動した場合はキャンセルする。 |
| `cancelAll()` | プラグイン停止時などに進行中の帰還処理をすべて解除する。 |
