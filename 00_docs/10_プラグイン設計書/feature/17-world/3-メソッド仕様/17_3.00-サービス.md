# World サービス仕様

## WorldRepository

API の `GET /api/world` と `GET /api/world/{worldId}` を呼び出し、`WorldMasterData` に変換する。

## WorldService

`WorldMasterData` の Plugin 側キャッシュとワールド移動を管理する。

| Method | Description |
|---|---|
| `loadAll()` | API から全 `WorldMasterData` を再読込し、ID 順でキャッシュを更新する。続けて `baseWorldPath` を基準に Bukkit ワールドのロードを試行する。探索時は world container 直下に加えて `worlds/<baseWorldPath>` と、既存ロード済みワールドの親ディレクトリ候補も参照する。 |
| `reloadFromYaml()` | MasterData Seeder API で filebase YAML を MasterDataDB へ反映し、その後 `loadAll()` を実行してキャッシュと Bukkit ロード済みワールドを更新する。 |
| `getAll()` | キャッシュ済み `WorldMasterData` 一覧を返す。 |
| `getById(worldId)` | 指定 ID の `WorldMasterData` を返す。 |
| `resolveLoadedWorld(data)` | `baseWorldPath`、その末尾名、ワールドフォルダ実体一致、`data.id` の順で Bukkit ロード済みワールドを解決する。 |
| `findByBukkitWorld(world)` | Bukkit ワールドに対応する `WorldMasterData` をキャッシュから逆引きする。 |
| `resolveSpawnLocation(data)` | `resolveLoadedWorld(data)` の結果と `data.spawnLocation` を組み合わせて `Location` を構築する。 |
| `teleportPlayerAsync(player, targetLocation, onSuccess)` | プレイヤーテレポートの共通安全経路。頭上表示 `TextDisplay` passenger の再接続を一時停止し、passenger を外してから対象チャンク準備完了を待つ。さらに数 tick 待機後に `teleportAsync` を実行し、成功時だけ `onSuccess` を実行する。頭上表示の通常更新復帰は移動完了後さらに数 tick 遅らせる。 |
| `teleportToSpawnAsync(player, data)` | `resolveSpawnLocation(data)` の結果を `teleportPlayerAsync(...)` に委譲する。参加時スポーンと `/world tp` はこの経路を利用する。 |
| `applyRpgGameRules(world)` | Bukkit ワールドへ RPG マップ用 gamerule を適用する。Mob 自然スポーン、パトロール、襲撃、ウォーデン、wandering trader、mob griefing、mob loot、entity drop、火災拡散、時間と天候サイクルを無効化し、`keepInventory` と `immediateRespawn` を有効化する。 |

## ReturnToBaseService

`joinSpawn.world` を拠点として扱い、menu feature からの帰還待機と帰還実行を管理する。

| Method | Description |
|---|---|
| `calculateGoldCost(playerLevel)` | 帰還コストを `100 x max(1, playerLevel)` で返す。 |
| `beginReturn(astPlayer)` | 参加時スポーン先 `WorldMasterData` とスポーン地点を解決し、所持ゴールドが十分なら 3 秒待機の帰還処理を開始する。待機中は title / subtitle / bossbar / particle / sound を表示し、移動した場合はキャンセルする。 |
| `cancelAll()` | 停止中またはプラグイン無効化時に、進行中の帰還待機をすべて破棄する。 |
