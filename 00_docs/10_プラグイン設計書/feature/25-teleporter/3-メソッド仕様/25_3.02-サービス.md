# テレポーターサービス仕様

## ウェイストーン定義ロード

クラス名: `TeleporterService`
物理名: `loadDefinitions`

1. [[25_3.04-リポジトリ]].ウェイストーン定義一覧取得 を呼び出す。
2. `id`、`name`、`worldName`、座標、`unlockGold` の制約を検証する。
3. 同一ワールド内の同一ブロック座標重複を検証する。
4. 検証に成功した定義を ID 順でキャッシュする。
5. ロード件数を以下ログへ記録する。

    | 項目 | 内容 |
    |:--|:--|
    | ID | `LogId.I_5950` |
    | レベル | INFO |
    | テンプレート | `ウェイストーン定義をロードしました: %d件` |
    | 出力条件 | ロード成功時 |
    | 引数 | ロード件数 |

## ウェイストーン定義再読み込み

クラス名: `TeleporterService`
物理名: `reloadDefinitions`

1. [[#ウェイストーン定義ロード]] を呼び出す。
2. 全オンラインプレイヤーに対して [[25_3.07-GUI・View]].ウェイストーン表示同期 を呼び出す。
3. 実行者へ以下メッセージを送信する。

    | 項目 | 内容 |
    |:--|:--|
    | ID | `PlayerMsgId.P_5954` |
    | テンプレート | `ウェイストーン定義を再読み込みしました: {0}件` |
    | 出力条件 | reload 成功時 |
    | 引数 | ロード件数 |

## ウェイストーン登録

クラス名: `TeleporterService`
物理名: `createWaystone`

1. 実行者の現在ワールドと座標を取得する。
2. `name` が空文字でないことを検証する。
3. `lockEnabled` を boolean として解決する。
4. `unlockGold` が `0` 以上であることを検証する。
5. `lockEnabled=false` の場合は `unlockGold=0` に正規化する。
6. 内部 ID を `ws_yyyyMMdd_HHmmss_<shortRandom>` 形式で生成する。
7. [[25_3.04-リポジトリ]].ウェイストーン定義保存 を呼び出す。
8. キャッシュへ追加し、全オンラインプレイヤーの表示を再同期する。
9. 実行者へ以下メッセージを送信する。

    | 項目 | 内容 |
    |:--|:--|
    | ID | `PlayerMsgId.P_5950` |
    | テンプレート | `ウェイストーンを登録しました: {0} (id={1})` |
    | 出力条件 | 登録成功時 |
    | 引数 | 表示名、ウェイストーン ID |

## ウェイストーン削除

クラス名: `TeleporterService`
物理名: `removeWaystone`

1. 指定 ID の定義をキャッシュから取得する。
2. 存在しない場合は実行者へ以下メッセージを送信して終了する。

    | 項目 | 内容 |
    |:--|:--|
    | ID | `PlayerMsgId.P_5960` |
    | テンプレート | `ウェイストーンが見つかりません: {0}` |
    | 出力条件 | 指定 ID が存在しない場合 |
    | 引数 | ウェイストーン ID |

3. [[25_3.04-リポジトリ]].ウェイストーン定義削除 を呼び出す。
4. キャッシュから削除し、全オンラインプレイヤーの表示を再同期する。
5. 実行者へ以下メッセージを送信する。

    | 項目 | 内容 |
    |:--|:--|
    | ID | `PlayerMsgId.P_5951` |
    | テンプレート | `ウェイストーンを削除しました: {0}` |
    | 出力条件 | 削除成功時 |
    | 引数 | ウェイストーン ID |

## 解除状態取得

クラス名: `TeleporterService`
物理名: `loadUnlockState`

1. `AstPlayer` から選択中アカウント ID を取得する。
2. アカウント ID が取得できない場合は空の解除状態を返す。
3. [[25_3.04-リポジトリ]].アカウント別解除状態取得 を呼び出す。
4. 戻り値の `unlockedWaystoneIds` を `WaystoneUnlockState` としてキャッシュする。
5. API 取得失敗時は例外を呼び出し元へ返し、呼び出し元がロック表示へフォールバックする。

## ウェイストーン解除

クラス名: `TeleporterService`
物理名: `unlockWaystone`

1. 対象ウェイストーン定義を取得する。
2. `lockEnabled=false` の場合は解除済み扱いとして [[25_3.07-GUI・View]].テレポーター GUI 表示 を呼び出す。
3. 最新の解除状態を取得し、すでに解除済みの場合は GUI 表示へ進む。
4. 同一プレイヤー、同一ウェイストーンの解除処理が進行中の場合は二重実行を拒否する。
5. `CurrencyService` で `unlockGold` 以上のゴールドを所持しているか確認する。
6. ゴールド不足の場合、以下メッセージを送信して終了する。

    | 項目 | 内容 |
    |:--|:--|
    | ID | `PlayerMsgId.P_5955` |
    | テンプレート | `ウェイストーン解除には {0} ゴールド必要です。` |
    | 出力条件 | ゴールド不足時 |
    | 引数 | 必要ゴールド |

7. `CurrencyService` で `unlockGold` を消費する。
8. [[25_3.04-リポジトリ]].ウェイストーン解除登録 を呼び出す。
9. 解除状態キャッシュへ `waystoneId` を追加する。
10. 対象プレイヤーへ表示 packet を再送信する。
11. ウェイストーン中心に解除成功サウンドと共通パーティクル演出を再生する。
12. 以下メッセージを送信する。

    | 項目 | 内容 |
    |:--|:--|
    | ID | `PlayerMsgId.P_5956` |
    | テンプレート | `ウェイストーンを解除しました: {0}` |
    | 出力条件 | 解除成功時 |
    | 引数 | 表示名 |

13. API 登録に失敗した場合、消費済みゴールドの返金を試みる。
14. 返金にも失敗した場合は以下ログを記録する。

    | 項目 | 内容 |
    |:--|:--|
    | ID | `LogId.E_5952` |
    | レベル | ERROR |
    | テンプレート | `ウェイストーン解除失敗後の返金に失敗しました: player=%s, waystoneId=%s, gold=%d` |
    | 出力条件 | API 登録失敗後の返金失敗時 |
    | 引数 | プレイヤー名、ウェイストーン ID、返金額 |

## GUI 表示項目構築

クラス名: `TeleporterService`
物理名: `buildGuiEntries`

1. 起点ウェイストーンを取得する。
2. 起点と同じ `worldName` のウェイストーンだけを抽出する。
3. 起点ウェイストーン自身を除外する。
4. 対象プレイヤーの解除状態を取得する。
5. [[25_1.00-モデル定義]].テレポーター GUI 表示項目 を作成する。
6. 解除済みを先頭、未解除を後続に並べる。

## ウェイストーンテレポート

クラス名: `TeleporterService`
物理名: `teleportToWaystone`

1. GUI 起点と対象ウェイストーンが同じ `worldName` であることを検証する。
2. 対象ウェイストーンが解除済みであることを検証する。
3. 対象ワールドがロード済みであることを `WorldService` で検証する。
4. GUI を閉じる。
5. `WorldService.teleportPlayerAsync` を使って対象座標へ非同期テレポートする。
6. 成功時に以下メッセージを送信する。

    | 項目 | 内容 |
    |:--|:--|
    | ID | `PlayerMsgId.P_5957` |
    | テンプレート | `ウェイストーンへ移動しました: {0}` |
    | 出力条件 | テレポート成功時 |
    | 引数 | 表示名 |

7. 失敗時は以下メッセージを送信する。

    | 項目 | 内容 |
    |:--|:--|
    | ID | `PlayerMsgId.P_5959` |
    | テンプレート | `ウェイストーンへ移動できませんでした: {0}` |
    | 出力条件 | テレポート失敗時 |
    | 引数 | 表示名 |
