# 06_9.00-未決事項

## 1. 抽選処理の所在（2026-07-13 解消）

`loot` feature の `LootRollService` を抽選主体とする。bundle・Mob・採集は同じ独立ドロップ率判定と `pick` 上限制御を利用し、個別 feature に抽選アルゴリズムを重複実装しない。

## 2. 一覧 API での件数ログ

`LootRepository.findAll` 自体は件数ログを出さず、`LootService.loadAll` が `LogId.I_5300` でまとめてログ出力する。  
カテゴリ別件数（`ItemService` の `I_5202` 相当）を loot 機能でも揃えるかは未確定。

## 3. バンドル lore 未ロード時の挙動

`ItemStackFactory` のバンドルルートロア追加（[[04_3.02-サービス]].プロトタイプテンプレート構築 内の内部処理、物理名: `appendBundleLootLore`）は未ロード時に `(未ロード)` を 1 行表示するだけで、再取得や警告ログを出さない。  
運用時に頻発する場合の対処方針（自動リフェッチ、警告ログ、表示文言の変更）が未整理。

## 4. ルートテーブルのスキーマバージョニング

`LootModel.schemaVersion` は読み取り対応のみで、バージョン差分による分岐処理は実装されていない。  
将来的に互換性が崩れるスキーマ変更を行う際の取り扱い方針が未定義。

## 5. 2026-05-27 解消事項

- bundle lore の `(未ロード)` 表示が ID 形式差異だけで発生する問題は解消済み。
- plugin 側で API の table / pool 構造を結合して loot を解決する実装へ更新済み。
- bundle 右クリック開封は実装済みであり、loot の単体再取得にも対応済み。
