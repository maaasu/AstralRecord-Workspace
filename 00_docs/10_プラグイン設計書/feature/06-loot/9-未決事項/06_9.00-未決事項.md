# 06_9.00-未決事項

## 1. 抽選処理の所在

現状の `loot` 機能はテーブル定義のキャッシュ管理に閉じており、`LootEntry.weight` を用いた重み付きランダム抽選ロジックは実装されていない。  
抽選を行う主体（`loot` 機能内に専用サービスを追加するか、`item` または mob ドロップ側で実装するか）の決定が必要。

## 2. キャッシュの並行更新

`LootService` の内部キャッシュは `LinkedHashMap` であり、`ConcurrentHashMap` ではない。  
運用中の動的リロード（例えば管理コマンドからの `clearCache` → `loadAll`）を導入する場合、同時アクセス時の競合に対する保護方針が未確定。

## 3. 一覧 API での件数ログ

`LootRepository.findAll` 自体は件数ログを出さず、`LootService.loadAll` が `LogId.I_5300` でまとめてログ出力する。  
カテゴリ別件数（`ItemService` の `I_5202` 相当）を loot 機能でも揃えるかは未確定。

## 4. バンドル lore 未ロード時の挙動

`ItemStackFactory#appendBundleLootLore` は未ロード時に `(未ロード)` を 1 行表示するだけで、再取得や警告ログを出さない。  
運用時に頻発する場合の対処方針（自動リフェッチ、警告ログ、表示文言の変更）が未整理。

## 5. ルートテーブルのスキーマバージョニング

`LootModel.schemaVersion` は読み取り対応のみで、バージョン差分による分岐処理は実装されていない。  
将来的に互換性が崩れるスキーマ変更を行う際の取り扱い方針が未定義。
