# 06_2.00-ユースケース

## 1. 起動時に全ルートテーブルをロードする

アクター:

- サーバー（プラグイン初期化）

事前条件:

- AstralRecord API が疎通可能である

主シナリオ:

1. プラグインが非同期タスクで `LootService.loadAll` を呼ぶ
2. リポジトリが `GET /api/loot/table` で全ルートテーブル一覧を取得する
3. サービスが各 [[06_1.00-モデル定義]].ルートテーブル をキャッシュへ登録する
4. 件数を info ログに記録する

代替シナリオ:

- 例外発生時はエラーログを記録し、ロード件数 `0` を返す

事後条件:

- 取得できたルートテーブルが `LootService.loadedLoots` キャッシュに保持される
- 後続の `ItemService.loadAll` 実行時にバンドル lore 表示が即時利用可能となる

## 2. バンドルアイテム表示でルート内容を参照する

アクター:

- サーバー（`ItemStackFactory`）

事前条件:

- 対象 `lootTableId` のキャッシュロードが完了している

主シナリオ:

1. `ItemStackFactory` がバンドルアイテムの Lore を構築する
2. `appendBundleLootLore` が [[06_3.02-サービス]].ロード済みルート取得 を呼ぶ
3. ヒットすれば各 [[06_1.00-モデル定義]].ルートエントリ をエントリ表示として整形する
4. ヒットしない場合は `(未ロード)` 注記を 1 行表示する

事後条件:

- バンドルアイテムの Lore 上に Loot 内容（item ID / category / 数量 / 確率）が表示される

## 3. キャッシュ済みルートテーブル一覧を取得する

アクター:

- サーバー（将来的な管理コマンド・GUI 等）

主シナリオ:

1. 呼び出し側が [[06_3.02-サービス]].ロード済みルート一覧取得 を呼ぶ
2. サービスが `LinkedHashMap` 値の不変リストコピーを返す

事後条件:

- 呼び出し側はロード順に並んだルートテーブル一覧を取得する

## 4. ルートテーブルキャッシュをクリアする

アクター:

- サーバー（再ロード処理・テスト用途）

主シナリオ:

1. 呼び出し側が [[06_3.02-サービス]].キャッシュクリア を呼ぶ
2. `LootService.loadedLoots` の中身を全て削除する

事後条件:

- 以降のキャッシュ参照は `null` を返し、再ロードが必要となる
