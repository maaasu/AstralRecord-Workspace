# 06_3.02-サービス

## 1. `LootService`

- `loadAll`: API から全 loot table を取得し、ローカル Map の構築完了後にキャッシュ全体を一括公開して件数を返す。
- `getLoaded(lootId)`: 読み込み済み loot table を ID で取得する。未読み込み時は `null`。
- `getLoadedLoots`: 読み込み済み一覧のスナップショットを返す。
- `cacheLoot`: 現在の不変スナップショットをコピーし、取得した `LootModel` を追加した新スナップショットへ差し替える。
- `clearCache`: ロック内で空の不変 Map へ差し替える。

`loadedLoots` は `volatile Map` とし、公開後の Map は変更しない。非同期 `loadAll` とメインスレッドの `getLoaded`、ならびに `getLoadedOrFetch` / `clearCache` が競合しても、参照側には更新前または更新後の完全なスナップショットだけを見せる。

詳細ロードは `LogId.D_5301`、全件成功は `LogId.I_5300`、一括ロード失敗は `LogId.E_5301` を使用します。`D_5301` のメッセージテンプレートは `ルートテーブル詳細をロードしました: %s` です。API 通信・変換失敗時は構築中 Map を公開せず、直前の完全なキャッシュを維持します。

## 2. ルートテーブル抽選

クラス名: `LootRollService`
物理名: `roll`

処理内容:

1. `minRolls` / `maxRolls` の閉区間から実行時の roll 回数を抽選し、その回数だけ全 pool を順に評価する。`0` が選ばれた場合は空結果とする。
2. pool ごとに `minPick` / `maxPick` の閉区間から、その roll 内の最大採用件数を抽選する。`0` または空 pool は結果を生成しない。
3. 各 `contents[]` を互いに独立して `rate`% で判定する。`rate <= 0` は必ず失敗、`rate >= 100` は必ず成功とし、全件失敗する空振りを許容する。
4. 成功候補数が最大採用件数を超えた場合だけ、サーバー乱数で成功候補を無作為に並べ替え、上限件数へ絞る。
5. 採用候補ごとに `minAmount` と `maxAmount` を昇順に正規化し、閉区間の一様分布で数量を確定する。最大値が 0 以下なら結果へ追加しない。
6. item ID、確定数量、独立判定に使用した設定 `rate` を `LootRollResult` として返す。

入力:

- `lootModel`: 参照解決済みルートテーブル

出力:

- `List<LootRollResult>`: 選択順を維持した抽選結果

補足:

- 本サービスはステートレスであり、bundle・Mob・採集から共通利用する。
- `configuredRate` は設定ドロップ率として Mob の表示とレア判定へ渡す。
