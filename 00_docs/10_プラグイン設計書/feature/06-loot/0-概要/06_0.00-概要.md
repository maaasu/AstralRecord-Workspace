# 06_0.00-概要

## 1. 目的

`loot` 機能は、AstralRecord で扱うルートテーブル（ドロップ抽選定義）のマスタを管理する。  
主目的は以下。

- ルートテーブル定義（`LootModel`）の API 取得と起動時一括ロード
- メモリキャッシュ管理と即時参照の提供
- `item` 機能のバンドルアイテム表示でのルート内容参照

## 2. コンテキスト

- 本機能は起動時に `LootService.loadAll` で全ルートテーブルを API から一括取得する。
- 抽選自体（重み付き乱数で `LootEntry` を選択する処理）は本機能には実装されておらず、現状はテーブル定義のキャッシュ管理に閉じている。
- `item` 機能の `ItemStackFactory` がバンドル lore 構築時に [[06_3.02-サービス]].ロード済みルート取得 を参照する。
- API 経由のみで取得し、キャッシュは正規化済みキー（trim + 小文字）で `LinkedHashMap` に保持する。

## 3. 構成要素（実装単位）

- `service/LootService`
  - 起動時一括ロード、キャッシュ保持、参照・クリア処理を提供する。
- `repository/LootRepository`
  - `/api/loot/table`, `/api/loot/table/{tableId}` への HTTP リクエストを実行する。
- [[06_1.00-モデル定義]].ルートテーブル, ルートエントリ
  - ドロップテーブルとエントリの表現を定義する（詳細は [[06_1.00-モデル定義]]）。

## 4. 依存関係

- 内部依存
  - `LootService` -> `LootRepository`
- 外部依存
  - AstralRecord API (`/api/loot/table`, `/api/loot/table/{tableId}`)
- 利用側
  - `ItemStackFactory`（[[04_3.02-サービス]].プロトタイプテンプレート構築 内の `appendBundleLootLore`）

## 5. ライフサイクル登録点

- `AstralRecord#onLoad` で `LootService` を生成
- `AstralRecord#setupFeature` の非同期タスクで `lootService.loadAll()` を実行（`itemService.loadAll()` より先に実行される）
- コマンド・イベントの登録は行わない
