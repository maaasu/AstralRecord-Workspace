# 12_3.02-サービス

## 1. MobService メソッド仕様

`MobService` はテンプレートキャッシュ、`MobInstance` キャッシュ、Bukkit 実体 Mob との対応、頭上 packet display 用 viewer キャッシュを管理する。

### テンプレート全件ロード

クラス名: `MobService`
物理名: `loadAll`

1. [[12_3.04-リポジトリ]].Mob 一覧取得 を呼ぶ。
2. 取得した `MobTemplate` を id キーの `LinkedHashMap` に保持する。
3. `LogId.I_5700` を記録し、ロード件数を返す。

### テンプレート取得

クラス名: `MobService`
物理名: `findTemplate`

1. `templates` キャッシュから `mobId` を取得する。
2. 未ヒット時は [[12_3.04-リポジトリ]].Mob 取得 を呼び、取得できた場合のみキャッシュへ登録する。
3. 取得できない場合は `null` を返す。

### Mob スポーン

クラス名: `MobService`
物理名: `spawn`

1. テンプレートを解決する。未取得なら `LogId.W_5701` を記録して `null` を返す。
2. `UUID.randomUUID()` で `instanceId` を採番し、`MobInstance` を生成する。
3. `MobEntityController.spawn` を呼び、Bukkit/Paper の実体 `Mob` を生成する。
4. 実体生成時、`MobEntityController` は以下を行う。
   - `Bukkit.getMobGoals().removeAllGoals(mob)` で vanilla goal を全削除する。
   - `setAI(true)` / `setAware(true)` を維持し、Paper Pathfinder を利用可能にする。
   - `setInvulnerable(true)` によりバニラダメージでは HP を減らさない。
   - `setPersistent(false)` / `setRemoveWhenFarAway(false)` / `setCanPickupItems(false)` / `setCollidable(false)` / `setSilent(true)` を設定する。
   - PDC に `mob_instance_id` と `mob_template_id` を保持する。
   - `MobInstance.bindEntity` で `bukkitEntityId` / `entityId` / `currentLocation` を同期する。
5. 実体生成に失敗した場合は `LogId.W_5705` を記録して `null` を返す。
6. `instances`、`instanceByEntity`、`viewers` に登録し、`LogId.D_5701` を記録して `MobInstance` を返す。

### Mob 破棄

クラス名: `MobService`
物理名: `destroy`

1. `instances` から `instanceId` を削除する。
2. 対応する `viewers` と `instanceByEntity` を削除する。
3. `MobEntityController.remove` で Bukkit 実体 Mob を remove する。
4. 成功時は `LogId.D_5702` を記録し、破棄できたかどうかを返す。

### 全 Mob 破棄

クラス名: `MobService`
物理名: `destroyAll`

1. 全 `MobInstance` の実体 Mob を `MobEntityController.remove` で削除する。
2. `instances`、`instanceByEntity`、`viewers` をクリアする。
3. `LogId.I_5701` を記録し、破棄件数を返す。

### 表示対象 viewer 更新

クラス名: `MobService`
物理名: `updateViewers`

Mob 本体は Bukkit/Paper の entity tracking に任せる。本メソッドは頭上 packet display の viewer キャッシュだけを更新する。

1. 実体 Mob の現在位置を `MobEntityController.syncLocation` で `MobInstance.currentLocation` へ反映する。
2. 64 ブロック以内かつ同一ワールドのオンラインプレイヤー UUID を `viewers` へ登録する。
3. 範囲外またはオフラインのプレイヤー UUID を `viewers` から削除する。

### 視認距離外 enemy 破棄

クラス名: `MobService`
物理名: `destroyEnemiesOutsideViewDistance`

1. `category == ENEMY` の `MobInstance` を対象にする。`BOSS` / `NPC` は自動破棄対象外とする。
2. 実体位置を同期し、同一ワールドかつ 64 ブロック以内のオンラインプレイヤーが 1 人もいない enemy を抽出する。
3. 抽出した enemy は `MobService.destroy` で破棄する。プラグイン都合の削除のため、`MobCombatService.handleDeath` は呼ばず、ドロップ、討伐記録、リザルト TextDisplay は発生させない。

### Paper Pathfinder 移動要求

クラス名: `MobService`
物理名: `moveToward`

1. `MobEntityController.moveTo` へ `MobInstance`、目標 `Location`、AI 速度倍率、内部 tick を渡す。
2. `MobEntityController` は目標地点の移動量と `PATH_RECOMPUTE_INTERVAL_TICKS` により、毎 tick の経路再計算を避ける。
3. 目標付近に到達した場合は `stopPathfinding` で経路探索を停止する。

## 1.5. NpcPlacementService メソッド仕様

### NPC 配置ロード

クラス名: `NpcPlacementService`
物理名: `loadAll`

1. `npc_locations.yml` から NPC 配置一覧を読み込む。
2. 既存の管理対象 NPC 実体と location-key キャッシュを破棄し、最新配置へ入れ替える。
3. その時点で `Bukkit.getWorld(worldName)` が解決できる配置は即時スポーンする。
4. ワールドがまだ解決できない配置もメモリ上には保持し、後続の `spawnLoadedWorlds` / `spawnForWorld` で再試行できる状態を維持する。

### ロード済みワールド再スポーン

クラス名: `NpcPlacementService`
物理名: `spawnLoadedWorlds`

1. 現在ロード済みの全ワールドに対して、未スポーンの NPC 配置だけを再評価する。
2. `AstralRecord` の onEnable 完了後 1 tick 遅延起動、および `WorldLoadEvent` 後の再試行経路から呼び出し、起動順差で取りこぼした NPC を補完する。
3. すでに管理中の location-key は重複スポーンしない。

## 2. MobEntityController メソッド仕様

### 実体 Mob 生成

クラス名: `MobEntityController`
物理名: `spawn`

`World.spawnEntity(location, template.entityType())` で実体 Entity を生成し、`Mob` でない EntityType は即 remove して失敗扱いとする。

### 実体 Mob 設定

クラス名: `MobEntityController`
物理名: `configure`

vanilla goal 全削除、PDC 設定、独自名表示、不要挙動の抑止、Pathfinder のドア・浮遊設定を行う。

### 実体 Mob 取得

クラス名: `MobEntityController`
物理名: `getMob`

`MobInstance.bukkitEntityId` から `Bukkit.getEntity` で実体を解決する。無効・死亡済み・Mob 以外なら `null` を返す。

### 実体位置同期

クラス名: `MobEntityController`
物理名: `syncLocation`

有効な実体 Mob の `getLocation()` を `MobInstance.currentLocation` に反映する。

### 移動要求

クラス名: `MobEntityController`
物理名: `moveTo`

Paper Pathfinder の `moveTo(target, speed)` を呼び出す。以下の軽量化ルールを持つ。

- 目標まで 0.6 ブロック以内なら `stopPathfinding` する。
- 既存 path があり、目標地点の X/Z 変化が 1.5 ブロック未満で、再計算間隔未満なら再要求しない。
- `MOVEMENT_SPEED` と `idle.speed` から Pathfinder speed を算出し、`0.05` から `2.5` に丸める。

## 3. MobAiService メソッド仕様

### tick タスク開始 / 停止

クラス名: `MobAiService`
物理名: `start` / `stop`

`BukkitScheduler.runTaskTimer` で 1 tick 周期の AI ループを起動・停止する。開始時は `LogId.I_5702`、停止時は `LogId.I_5703` を記録する。

### AI tick 本体

クラス名: `MobAiService`
物理名: `tick`

1. 内部 tick を進め、`MobService.getInstances` のスナップショットを取得する。
2. 各インスタンスで実体位置を同期する。実体が存在しない場合はインスタンスを破棄する。
3. 100 tick ごとに脅威値を減衰する。
4. leashRange 超過なら `LEASHED` へ遷移する。
5. 状態別処理を行う。
   - `IDLE`: 10 tick 間隔でターゲット探索・徘徊目的地選定を行う。`NPC` かつ `idle.behavior = STATIONARY` の場合は path を停止したまま 64 ブロック以内の最寄りプレイヤーへ視線だけ向ける。
   - `AGGRO`: 5 tick 間隔で追跡対象の再評価と Pathfinder 目標設定を行う。
- `COMBAT`: 射程外または高低差超過なら `AGGRO` へ戻す。`RANGED` / `MAGIC` で理想距離より近すぎる場合は、その場停止せず後退して距離を取り直す。
   - `LEASHED`: 5 tick 間隔でスポーン地点へ Pathfinder 目標設定を行い、到達で `IDLE` へ戻す。
   - `DEAD`: `MobService.destroy` で破棄する。
6. 5 tick ごとに `MobService.updateViewers` を呼び、頭上 packet display の viewer キャッシュを更新する。
7. 同じ 5 tick 周期で `MobService.destroyEnemiesOutsideViewDistance` を呼び、どのプレイヤーの描画距離にも入っていない `ENEMY` をリザルトなしで破棄する。

### 軽量化ルール

- バニラ goal は spawn 直後に全削除し、不要な vanilla 行動 tick を発生させない。
- `setAI(false)` は使わない。Paper Pathfinder を利用するため `AI=true` を維持する。
- IDLE の探索は全 Mob 同時ではなく、`instanceId.hashCode + internalTick` で分散する。
- AGGRO / LEASHED の追跡判断は 5 tick 間隔に抑える。
- Pathfinder の `moveTo` は目標ドリフトと再計算間隔で制限する。
- Mob 本体の viewer 管理は Bukkit/Paper に任せ、プラグイン側 viewer は頭上表示用に限定する。

## 4. 設計上の制約

- すべての Bukkit/Paper API 操作はメインスレッドから呼び出す。
- 実体 Mob は永続化しない。サーバ停止時は `destroyAll` で remove する。
- バニラダメージイベントを Mob HP の正本にはしない。独自攻撃・combat/skill 側から `MobInstance.currentHealth` を更新する。
