# 12_3.02-サービス

## 1. MobService メソッド仕様

### テンプレート全件ロード

クラス名: `MobService`  
物理名: `loadAll`

責務:

API から Mob テンプレート一覧を取得し、`templates` キャッシュを置換する。

処理内容:

1. [[12_3.04-リポジトリ]].Mob 一覧取得 を呼ぶ
2. 取得した summary 一覧を id をキーとした `LinkedHashMap` に変換する
3. 既存 `templates` キャッシュを完全置換する
4. ロード結果を以下ログとして記録する

    | 項目 | 内容 |
    |---|---|
    | ID | `LogId.I_5501` |
    | レベル | `INFO` |
    | テンプレート | `Mob テンプレートを {0} 件ロードしました` |
    | 出力条件 | 置換完了時 |
    | 引数 | テンプレート件数 |

5. リポジトリ層から例外を受けた場合、以下ログを記録してから例外を再送出する

    | 項目 | 内容 |
    |---|---|
    | ID | `LogId.E_5502` |
    | レベル | `ERROR` |
    | テンプレート | `Mob テンプレートのロードに失敗しました: {0}` |
    | 出力条件 | リポジトリ層からの例外捕捉時 |
    | 引数 | 例外メッセージ |

入力:

- なし

出力:

- `int`: ロードしたテンプレート数

例外時挙動:

- リポジトリ層の例外は `LogId.E_5502` を記録のうえそのまま伝播する

### テンプレート取得

クラス名: `MobService`  
物理名: `findTemplate`

責務:

指定 ID のテンプレートをキャッシュから取得する。未ヒット時は API から遅延ロードする。

処理内容:

1. `templates.get(mobId)` を返す
2. ヒットしない場合は [[12_3.04-リポジトリ]].Mob 取得 を呼ぶ
3. 取得成功時は `templates.put(mobId, template)` してから返す。以下ログを記録する

    | 項目 | 内容 |
    |---|---|
    | ID | `LogId.D_5500` |
    | レベル | `DEBUG` |
    | テンプレート | `Mob テンプレートをキャッシュに登録しました mobId={0}` |
    | 出力条件 | 遅延ロード後のキャッシュ登録時 |
    | 引数 | テンプレート ID |

入力:

- `mobId`: テンプレート ID

出力:

- [[12_1.00-モデル定義]].Mob テンプレート（取得失敗時は `null`）

### 全テンプレート ID 一覧

クラス名: `MobService`  
物理名: `getLoadedMobIds`

責務:

`templates` に登録済みの ID 一覧を返す。

出力:

- `Collection<String>`（変更不可ビュー）

### Mob スポーン

クラス名: `MobService`  
物理名: `spawn`

責務:

指定テンプレート ID の Mob を指定座標に生成する。

処理内容:

1. [[12_3.02-サービス]].テンプレート取得 を呼ぶ。取得失敗時は以下ログを記録して `null` を返す

    | 項目 | 内容 |
    |---|---|
    | ID | `LogId.W_5504` |
    | レベル | `WARN` |
    | テンプレート | `Mob テンプレートが見つかりません mobId={0}` |
    | 出力条件 | テンプレート取得（リポジトリ含む）が `null` を返した時 |
    | 引数 | テンプレート ID |

2. インスタンス ID（`UUID.randomUUID()`）と仮想 Entity ID（`AtomicInteger` の `incrementAndGet`）を採番する
3. [[12_1.00-モデル定義]].Mob インスタンス を生成する
   | フィールド | 初期値 |
   |---|---|
   | `currentHealth` | `MAX_HEALTH` の `baseStat` 値（未指定時は 1.0） |
   | `state` | `IDLE` |
   | `target` | `null` |
   | `lastAttackTick` | `0` |
   | `lastAttackerUuid` | `null` |
   | `spawnLocation` | 引数の location のクローン |
   | `currentLocation` | 引数の location のクローン |
   | `wanderAnchor` | 引数の location のクローン |
   | `threatTable` | 空 |
   | `viewers` | 空 |
4. `instances` キャッシュへ登録する
5. 範囲内オンラインプレイヤーへ [[12_3.05-パケット表示]].Mob スポーンパケット送出 を呼ぶ
6. 以下ログを記録する

    | 項目 | 内容 |
    |---|---|
    | ID | `LogId.D_5503` |
    | レベル | `DEBUG` |
    | テンプレート | `Mob をスポーンしました mobId={0} instanceId={1}` |
    | 出力条件 | スポーン成功時 |
    | 引数 | テンプレート ID, インスタンス ID |

7. インスタンスを返す

入力:

- `templateId`: テンプレート ID
- `location`: スポーン位置

出力:

- [[12_1.00-モデル定義]].Mob インスタンス（テンプレート未取得時は `null`）

責務:

出力:

### コマンド指定 ID による Mob 破棄

クラス名: `MobService`
物理名: `destroyById`

責務:

コマンドで指定された ID から削除対象 Mob を解決し、該当インスタンスを破棄する。

処理内容:

1. ID が UUID として解釈できる場合はインスタンス ID として `destroy(UUID)` を呼ぶ。
2. UUID として解釈できない場合はテンプレート ID として `destroyByTemplateId(id)` を呼ぶ。
3. 破棄した Mob 数を返す。

入力:

- `id`: インスタンス UUID またはテンプレート ID

出力:

- `int`: 破棄したインスタンス数

### テンプレート ID による Mob 破棄

クラス名: `MobService`
物理名: `destroyByTemplateId`

責務:

指定テンプレート ID から生成された Mob インスタンスをすべて破棄する。

入力:

- `templateId`: テンプレート ID

出力:

- `int`: 破棄したインスタンス数

### 全 Mob 破棄

クラス名: `MobService`  
物理名: `destroyAll`

責務:

すべての Mob インスタンスのパケット表示を消し、`instances` キャッシュをクリアする。

処理内容:

1. `instances.values()` を反復
2. 各インスタンスについてオンライン全プレイヤーへ [[12_3.05-パケット表示]].Mob 破棄パケット送出 を呼ぶ
3. `instances` をクリアする
4. 以下ログを記録する

    | 項目 | 内容 |
    |---|---|
    | ID | `LogId.I_5506` |
    | レベル | `INFO` |
    | テンプレート | `Mob を {0} 件破棄しました` |
    | 出力条件 | 全破棄完了時 |
    | 引数 | 破棄件数 |

入力:

- なし

出力:

- `int`: 破棄したインスタンス数

### 個別 Mob 破棄

クラス名: `MobService`  
物理名: `destroy`

責務:

指定インスタンスを破棄する。

処理内容:

1. `instances.remove(instanceId)` で参照を抜き出す
2. 取得できた場合、オンライン全プレイヤーへ [[12_3.05-パケット表示]].Mob 破棄パケット送出 を呼ぶ
3. 取得できた場合は以下ログを記録する

    | 項目 | 内容 |
    |---|---|
    | ID | `LogId.D_5505` |
    | レベル | `DEBUG` |
    | テンプレート | `Mob を破棄しました instanceId={0}` |
    | 出力条件 | 個別破棄成功時 |
    | 引数 | インスタンス ID |

4. 破棄したかどうかを返す

入力:

- `instanceId`: インスタンス ID

出力:

- `boolean`: 破棄したかどうか

## 2. MobAiService メソッド仕様

### tick タスク開始

クラス名: `MobAiService`  
物理名: `start`

責務:

`BukkitScheduler.runTaskTimer` で 1 tick 周期の AI ループを起動する。  
重複起動を避けるため、既に起動済みなら何もしない。

処理内容:

1. `taskId != null` なら何もしない
2. `Bukkit.getScheduler().runTaskTimer(plugin, this::tick, 1L, 1L)` を実行
3. 戻り値の `BukkitTask` の id を保持
4. 以下ログを記録する

    | 項目 | 内容 |
    |---|---|
    | ID | `LogId.I_5520` |
    | レベル | `INFO` |
    | テンプレート | `Mob AI tick タスクを開始しました` |
    | 出力条件 | 新規起動成功時（既起動時は出力しない） |
    | 引数 | - |

入力:

- なし

出力:

- なし

### tick タスク停止

クラス名: `MobAiService`  
物理名: `stop`

責務:

起動中の tick タスクを停止する。

処理内容:

1. `taskId == null` なら何もしない
2. `Bukkit.getScheduler().cancelTask(taskId)` を呼ぶ
3. `taskId = null` に戻す
4. 以下ログを記録する

    | 項目 | 内容 |
    |---|---|
    | ID | `LogId.I_5521` |
    | レベル | `INFO` |
    | テンプレート | `Mob AI tick タスクを停止しました` |
    | 出力条件 | 停止成功時（未起動時は出力しない） |
    | 引数 | - |

### AI tick 本体

クラス名: `MobAiService`  
物理名: `tick`

責務:

すべての Mob インスタンスについて 1 tick の AI 処理を実行する。

処理内容:

1. 内部 tick カウンタを進める
2. [[12_3.02-サービス]].全インスタンス取得 で対象一覧を取得
3. 各インスタンスについて以下を順に判定
   1. 脅威値の減衰間隔に達していれば `MobThreatTable` を減衰する
   2. `LEASHED` 判定。超過したら `state = LEASHED` に遷移
   3. 状態別に駆動
      | 状態 | 処理 |
      |---|---|
      | `IDLE` | [[12_3.02-サービス]].待機行動駆動 を呼ぶ。`category` に `targeting` がある場合は `aggroRange` 内のプレイヤーを探す |
      | `AGGRO` | 既存ターゲットまたは新規ターゲットを解決し、水平距離が `preferredRange` 内かつ高低差が許容値内なら `COMBAT` 遷移。範囲外なら対象へ移動 |
      | `COMBAT` | 攻撃は行わず、射程内なら待機する。対象が水平射程外、または一段上など許容高低差を超えた場合は経路を破棄して `AGGRO` に戻る |
      | `LEASHED` | スポーン地点へ向かう位置補間。到達で `IDLE` 復帰 |
4. 範囲外プレイヤーへの破棄パケット送出（[[12_3.02-サービス]].表示範囲更新 を呼ぶ）
5. 個別インスタンスの処理で例外が発生した場合は捕捉し、該当インスタンスを破棄したうえで以下ログを記録する。tick 全体は継続する

    | 項目 | 内容 |
    |---|---|
    | ID | `LogId.W_5522` |
    | レベル | `WARN` |
    | テンプレート | `Mob AI tick の個別インスタンス処理で例外: instanceId={0}` |
    | 出力条件 | 個別インスタンス処理ステップで例外捕捉時 |
    | 引数 | インスタンス ID |

7. tick 全体で捕捉された例外（個別捕捉を超えた範囲のもの）は以下ログを記録する。tick タスク自体は次 tick も継続する

    | 項目 | 内容 |
    |---|---|
    | ID | `LogId.E_5523` |
    | レベル | `ERROR` |
    | テンプレート | `Mob AI tick 全体で例外が発生しました: {0}` |
    | 出力条件 | tick 全体の try/catch で例外捕捉時 |
    | 引数 | 例外メッセージ |

### 待機行動駆動

クラス名: `MobAiService`  
物理名: `tickIdle`

責務:

`IDLE` 状態の Mob を `idle.behavior` に従って動かす。

処理内容:

1. `behavior` を判定
   | 値 | 処理 |
   |---|---|
   | `STATIONARY` | 何もしない |
   | `WANDER` | `wanderAnchor` を中心に `wanderRadius` 内のランダム座標へ移動。目的地到達またはタイムアウト時は短時間停止してから次の目的地を選ぶ |
   | `PATROL` | 未実装。将来拡張。当面は `STATIONARY` と同じ扱い |
2. 移動計算は `MobAiCalculator` に委譲する
3. `MOVEMENT_SPEED` は `100` を標準値とし、標準値はバニラのゾンビに近い速度の 1.5 倍として扱う。`idle.speed` は AI 設定側の追加倍率として掛ける
4. 経路探索は X/Z だけでなく足元 Y もゴール条件に含め、ターゲットが高所にいる場合は 1 ブロック以下の上りで到達できる回り道を探索する
5. 移動先は Mob の表示幅を考慮した体クリアランスで判定する。判定にはブロック単位の占有ではなく Paper の collision shape を使用し、フェンスなどの細い衝突形状は実際に体ボックスと重なる場合のみ障害物として扱う
6. 立てる足場の判定は floor ブロックの整数高さではなく、collision shape の上面から実際の支持面 Y を算出する。これにより階段・ハーフブロック上でも足元高さを追従できる
7. カーペット・ロウソクなど足元付近の低い装飾ブロックは移動阻害として扱わず、足元・上半身が実衝突形状にめり込む位置へは移動しない
8. 段差上昇時はバニラ Mob の step-up に近づけるため、1 ブロック以内の上りは X/Z 移動と同時に足元 Y を即時補正する。1 ブロックを超える上りは詰まりとして扱う
9. 水平移動は次の waypoint までの距離を超えない範囲で短いサブステップに分割して判定し、薄い壁や角での貫通を防ぐ
10. 下方向はワールド下限まで立てる足場を探索し、落下段数による上限は設けない
11. ターゲットが自身より高い位置にいて、経路なし・体クリアランス不足などで約 8 tick 詰まった場合は、現在足場から 1 ブロック以内のジャンプ補助を行う。補助中も X/Z を目的方向へ進め、垂直方向だけで停止しない
12. 水中・溶岩中では水平移動を減速し、体クリアランスがある場合はゆっくり浮上させる
13. 移動が発生した場合、`currentLocation` を更新する

### 表示範囲更新

クラス名: `MobAiService`  
物理名: `updateViewers`

責務:

各インスタンスに対して、現在の表示プレイヤー集合を更新する。  
表示中プレイヤー UUID 集合は `MobInstance.viewers` がオーナーであり、本メソッドは tick 駆動でその差分を更新する責務を持つ。

処理内容:

1. 各インスタンスについて `MobInstance.viewers` を現在の表示中プレイヤー UUID 集合として参照する
2. 範囲内（既定 64.0 ブロック）のオンラインプレイヤー集合を計算
3. 範囲内かつ `viewers` 未登録のプレイヤーには [[12_3.05-パケット表示]].Mob スポーンパケット送出 を呼び、`viewers` に追加する
4. `viewers` 登録済みかつ範囲外（またはオフライン）になったプレイヤーには [[12_3.05-パケット表示]].Mob 破棄パケット送出 を呼び、`viewers` から除去する
5. 引き続き範囲内かつ `viewers` 登録済みのプレイヤーへは差分の位置・回転パケットを送る

## 3. 設計上の制約

- すべてのメソッドはメインスレッドからの呼び出しを前提とする。
- 例外的に [[12_3.04-リポジトリ]] の HTTP I/O はメインスレッドをブロックし得るため、`/mob load` などの管理者操作以外で初回ロードを発生させないこと。
- `MobAiService.tick` は 1 tick 内で全インスタンスを処理する。Mob 数が増えた場合のパフォーマンス対策は [[12_9.00-未決事項]] を参照。
