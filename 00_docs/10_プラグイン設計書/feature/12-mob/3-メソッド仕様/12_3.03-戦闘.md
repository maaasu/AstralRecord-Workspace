# 12_3.03-戦闘

戦闘・ダメージ・ノックバック・ヘイト・ドロップを管理するレイヤー。バニラ Bukkit のダメージイベント（`EntityDamageEvent`）と属性（`AttributeInstance`）には依存せず、すべて本機能内で計算する。

## 1. MobCombatService メソッド仕様

### ターゲット選定

クラス名: `MobCombatService`  
物理名: `selectTarget`

責務:

`targeting.strategy` に従って Mob のターゲットを選定する。

処理内容:

1. `aggroRange` 内のオンラインかつ生存しているプレイヤーを抽出する（同一ワールド・距離判定）
2. 候補が空なら `null` を返す
3. `strategy` 別に選定
   | 値 | 選定方法 |
   |---|---|
   | `NEAREST` | 距離が最小のプレイヤー |
   | `HIGHEST_THREAT` | [[12_1.00-モデル定義]].脅威値テーブル の `top()` をまず採用。`null` の場合は `NEAREST` にフォールバック |
   | `RANDOM` | 候補から `ThreadLocalRandom` で選出 |
   | `LOWEST_HP` | `AstPlayer.currentHealth` が最小のプレイヤー（同値時は最近接） |
4. 選定結果を `MobInstance.target` に設定する

入力:

- `instance`: 対象 Mob インスタンス

出力:

- `AstPlayer`（選定失敗時は `null`）

### 攻撃 tick

クラス名: `MobCombatService`  
物理名: `tickCombat`

責務:

`ai.combat.skills` 未設定の `COMBAT` 状態 Mob による従来の直接通常攻撃を 1 tick 分処理する。`ai.combat.skills` が設定されている Mob は `MobAiService` から skill feature の `SkillService.castSkill(..., SkillCastTrigger.MOB_AI, ...)` を呼び出して攻撃する。

処理内容:

1. `instance.target` が `null` または範囲外なら `AGGRO` 復帰
2. `serverTick - instance.lastAttackTick < attackIntervalTicks` なら何もしない
3. 命中判定: `roll < ACCURACY - target.EVASION`
   - `roll = ThreadLocalRandom.current().nextDouble(0.0, 100.0)`
4. 不命中なら回避ログ・回避演出を行い、`lastAttackTick = serverTick` を更新して終了
5. ダメージ計算（[[12_3.03-戦闘]].ダメージ計算 を呼ぶ）
6. 会心判定・超会心判定（[[12_3.03-戦闘]].会心判定 を呼ぶ）
7. ターゲットへダメージを適用（プレイヤー側 feature の API 経由でプレイヤーの HP を減算）
8. [[12_3.03-戦闘]].ノックバック適用 を呼ぶ
9. `instance.lastAttackTick = serverTick`

### AI スキル攻撃

クラス名: `MobAiService`
物理名: `castCombatSkill`

責務:

`COMBAT` 状態の Mob が `ai.combat.skills` に設定されたスキルを使ってプレイヤーへ攻撃する。

処理内容:

1. `combat.skills` が空の場合は [[12_3.03-戦闘]].攻撃 tick へフォールバックする。
2. Mob が詠唱中なら新しいスキル発動は行わない。
3. `internalTick - instance.lastAttackTick < attackIntervalTicks` なら何もしない。
4. `MobInstance.nextCombatSkillIndex` に基づいて `combat.skills` からスキル ID を選び、発動後に次インデックスへ進める。
5. `SkillService.castSkill(new MobSkillCaster(instance), skillId, SkillCastTrigger.MOB_AI, castOrigin(instance, target), target, List.of(target))` を呼ぶ。`castOrigin` は詠唱開始時の位置と向きを固定する。
6. 成功した場合だけ `lastAttackTick` を更新する。

### ダメージ計算

クラス名: `MobCombatService`  
物理名: `computeDamage`

責務:

Mob からターゲット（プレイヤー）への基礎ダメージを算出する。

処理内容:

1. `combat.style` に応じて攻撃力スケーリングを決定する
   | スタイル | 攻撃力ベース | 物理 / 魔法 |
   |---|---|---|
   | `MELEE` | `ATTACK * (1 + STRENGTH / 100)` | 物理 |
   | `RANGED` | `ATTACK * (1 + DEXTERITY / 100)` | 物理 |
   | `MAGIC` | `ATTACK * (1 + INTELLIGENCE / 100)` | 魔法 |
2. ターゲットの防御力を取得（物理は `DEFENSE`、魔法は `MAGIC_DEFENSE`）
3. 基礎ダメージ = `max(1, 攻撃力 - 防御力 * 0.5)`
4. レベル差補正は適用しない（本バージョン）

入力:

- `instance`: 攻撃側 Mob
- `target`: 防御側プレイヤー

出力:

- `double`: 基礎ダメージ

### 会心判定

クラス名: `MobCombatService`  
物理名: `applyCriticalMultiplier`

責務:

基礎ダメージに会心 / 超会心 倍率を適用する。

処理内容:

1. `roll < CRITICAL_RATE` なら会心成立
   - 会心ダメージ倍率 = `CRITICAL_DAMAGE / 100`
   - `roll < SUPER_CRITICAL_RATE` なら超会心も成立、追加倍率 `SUPER_CRITICAL_DAMAGE / 100` を乗算
2. 通常時は倍率 1.0
3. `damage * 倍率` を返す

入力:

- `instance`: 攻撃側
- `baseDamage`: 基礎ダメージ

出力:

- `double`: 会心適用後ダメージ

### 被ダメージ

クラス名: `MobCombatService`  
物理名: `applyDamage`

責務:

プレイヤーから Mob への被ダメージを処理する。  
ダメージ計算（プレイヤー側のスケーリング・装備補正）は呼び出し元の責務であり、本メソッドは確定済みダメージ量を受け取る。

処理内容:

1. `instance.state == DEAD` なら何もしない
2. `effectiveDamage = max(1, damage - DEFENSE/MAGIC_DEFENSE * 0.5)` で確定（防御は本機能で適用する）
3. `instance.currentHealth -= effectiveDamage`
4. `instance.threatTable.add(attackerUuid, effectiveDamage)` で脅威値加算
5. `instance.lastAttackerUuid = attackerUuid`（致死処理のフォールバック特定用）
6. [[12_3.03-戦闘]].ノックバック適用 を呼ぶ（攻撃方向）
7. `currentHealth <= 0` なら `instance.state = DEAD` に遷移し、致死処理キューへ。遷移時に以下ログを記録する

    | 項目 | 内容 |
    |---|---|
    | ID | `LogId.D_5703` |
    | レベル | `DEBUG` |
    | テンプレート | `Mob が致死状態に遷移しました mobId={0} instanceId={1} killerUuid={2}` |
    | 出力条件 | 本ステップで `state = DEAD` へ遷移した時 |
    | 引数 | テンプレート ID, インスタンス ID, 攻撃元 UUID |

8. `IDLE` 状態のときは `state = AGGRO` に遷移してターゲットを攻撃元に設定

入力:

- `instance`: 被ダメージ対象 Mob
- `attacker`: 攻撃元プレイヤー
- `damage`: 確定済みダメージ
- `damageType`: `PHYSICAL` / `MAGIC`

出力:

- `double`: 実際に与えたダメージ（防御適用後）

### 致死処理

クラス名: `MobCombatService`  
物理名: `handleDeath`

責務:

死亡が確定した Mob のドロップ・破棄を処理する。

処理内容:

1. キラーを決定する
   - [[12_1.00-モデル定義]].脅威値テーブル の `top()` を使用
   - 取得失敗時は `instance.lastAttackerUuid` をフォールバックとして使用
   - それでも `null` の場合は以下ログを記録してキラーなしで進める

    | 項目 | 内容 |
    |---|---|
    | ID | `LogId.W_5703` |
    | レベル | `WARN` |
    | テンプレート | `Mob のキラーを特定できませんでした instanceId={0}` |
    | 出力条件 | 脅威値テーブル `top()` と `lastAttackerUuid` の両方が `null` の時 |
    | 引数 | インスタンス ID |

2. [[12_3.03-戦闘]].ドロップ確定 を呼ぶ。例外が発生した場合は捕捉のうえ以下ログを記録し、ドロップは空として進める

    | 項目 | 内容 |
    |---|---|
    | ID | `LogId.E_5703` |
    | レベル | `ERROR` |
    | テンプレート | `Mob のドロップ抽選で例外が発生しました instanceId={0}: {1}` |
    | 出力条件 | ドロップ確定中の例外捕捉時 |
    | 引数 | インスタンス ID, 例外メッセージ |

3. キラーが見つかれば、ドロップ・経験値・金銭を払い出す
   - アイテム: `feature/inventory` の API 経由で追加
   - 経験値: `AccountService.grantExperienceCached` で即時にメモリ反映し、定期 flush で account API へまとめて保存する
   - 金銭: `feature/currency` の通貨加算経路で追加する
4. [[12_3.02-サービス]].個別 Mob 破棄 を呼ぶ

### ドロップ配布対象と演出

Mob 撃破時のドロップは、対象プレイヤーごとに個別抽選・個別表示・個別付与する。

配布対象:

1. 対象 Mob に 1 ダメージ以上の有効ダメージを与え、脅威テーブルに残っているオンラインプレイヤー
2. とどめを刺したプレイヤーのパーティーメンバーのうち、とどめを刺したプレイヤーと同一ワールドかつ 60m 以内のオンラインプレイヤー

処理:

1. `MobInstance.lastAttackerUuid` を優先してとどめを刺したプレイヤーを特定し、未設定時のみ `MobThreatTable.top()` にフォールバックする。
2. 配布対象を重複排除したうえで、各 `AstPlayer` を `MobDropService.roll` に渡して個別に抽選する。
3. 抽選結果は対象プレイヤーだけに見える TextDisplay のリザルトとして表示し、ドロップアイテム名と数量を含める。
4. 解決できたドロップアイテムのうち演出上限内のものだけ ItemDisplay を生成し、PDC を維持したまま icon Material を反映した表示用 ItemStack で描画する。
5. 装備 / ルーンはアニメーション開始と同時に非同期で instance API を呼び出し、通常アイテムは即時準備済み扱いにする。
6. ItemDisplay は上方から約 12 tick で着地する落下演出を行い、短い着地待機後に対象プレイヤーの位置へ自動回収される。回収終端では API 完了まで待機できる。
7. 回収到達時に、通常アイテムは `InventoryService.addItemToNormalInventory(..., "mob_drop")`、装備 / ルーンは事前生成済み instance を `InventoryService.addPreparedInstanceToNormalInventory(...)` で追加する。
8. 演出上限を超えたドロップは ItemDisplay を生成せず、同じ付与経路でインベントリへ追加する。
9. item ID を `ItemService` で解決できないドロップは表示・付与対象から除外する。

補足:

- 致死処理のうち Bukkit Entity の破棄、表示生成、アニメーション開始はメインスレッドで行う。
- 外部 API / 永続化 I/O を伴う経験値更新はメインスレッドを直接ブロックせず、account 単位の逐次非同期キューへ委譲する。

ダメージ成立時のノックバックは `DamageService` のダメージ結果処理から `MobKnockbackService.apply` を呼ぶ共通経路で適用する。

## 2. MobKnockbackService メソッド仕様

### ノックバック適用

クラス名: `MobKnockbackService`  
物理名: `apply`

責務:

攻撃方向にノックバックベクトルを算出し、対象へ送出する。

処理内容:

1. 攻撃元と対象の水平ベクトルを正規化する
2. 基本ノックバック量 `baseKnockback = 0.4`
3. `StatusType.KNOCKBACK_RESISTANCE` を 0-100% として読み、`multiplier * (1 - resistance / 100)` で軽減する。
4. 垂直成分 `verticalKick = 0.4`
5. 対象がプレイヤーなら `Player.setVelocity` で送出
6. 対象が Mob なら `MobEntityController.addVelocity` 経由で実体 Mob の速度へ反映する

入力:

- `source`: 攻撃元（Mob / Player）
- `target`: 被攻撃側（Mob / Player）
- `multiplier`: ノックバック倍率（既定 1.0）

出力:

- なし

## 3. MobThreatTable メソッド仕様

### 脅威値加算

クラス名: `MobThreatTable`  
物理名: `add`

責務:

指定プレイヤー UUID の脅威値に値を加算する。

処理内容:

1. `Map.merge(playerId, amount, Double::sum)` で加算
2. 値が 0 以下になった場合はエントリ削除

入力:

- `playerId`: プレイヤー UUID
- `amount`: 加算量

### 脅威値最大プレイヤー取得

クラス名: `MobThreatTable`  
物理名: `top`

責務:

最大脅威値を持つプレイヤー UUID を返す。

処理内容:

1. エントリが空なら `null`
2. `Map.Entry.comparingByValue` で最大値を取り、UUID を返す

### 脅威値減衰

クラス名: `MobThreatTable`  
物理名: `decay`

責務:

すべてのエントリに減衰係数を乗算する。

処理内容:

1. `factor` を `0.0 <= factor <= 1.0` にクランプ
2. 各エントリに `value * factor` を適用
3. 1.0 未満となったエントリは削除

呼び出し元: `MobAiService.tick` から定期的（例: 100 tick = 5 秒ごと）に呼ぶ。減衰係数の既定は 0.99。

## 4. MobDropService メソッド仕様

### ドロップ確定

クラス名: `MobDropService`  
物理名: `roll`

責務:

`drops` 設定に基づいてドロップ結果を抽選し、配布可能な形式に確定する。

処理内容:

1. `drops` が `null` なら空結果を返す
2. `drops.items[]` を順に評価
   | 項目 | 処理 |
   |---|---|
   | `rate` | 0-100 の乱数と比較。`rate >= 100` の場合は確定ヒット |
   | `luckAffected = true` | キラーの `LUCK` 値で `rate` に加算補正（既定 `LUCK * 0.05`） |
   | `amount` | `n` 形式は固定値、`a~b` 形式は `[a, b]` の一様分布 |
   | `hidden` | ドロップ結果には影響しない（図鑑表示用フラグ） |
3. `drops.lootTable` が指定されていれば、`loot` feature の参照解決を行い、抽選結果を結合
4. `drops.exp`, `drops.money.min~max` を結果に含める

入力:

- `template`: 撃破された Mob テンプレート
- `killer`: キラー（`AstPlayer`、`null` 許容）

出力:

- [[12_3.03-戦闘]].ドロップ結果（アイテム ID + 数量のリスト、合計 exp、合計 money）

### ドロップ結果

物理名（型）: `MobDropResult`

| 項目 | 型 | 説明 |
|---|---|---|
| `items` | `List<Map.Entry<String, Integer>>` | item ID と数量の組 |
| `exp` | `int` | 経験値合計 |
| `money` | `int` | 金銭合計 |

## 5. 設計上の制約

- ダメージ計算式は本ドキュメントが正本。改訂時は本ファイルと [[12_4.00-統合フロー]] を必ず更新する。
- 命中判定・会心判定・ドロップ抽選はすべてサーバーサイドで完結する（クライアント乱数を信用しない）。
- 致死処理はメインスレッドで実行する。ドロップ抽選で I/O が必要になった場合は非同期化を検討（[[12_9.00-未決事項]] 参照）。

## プレイヤー死亡中の戦闘除外

- `MobAiService.selectTarget(...)` は `Player#isDead()` が true のプレイヤーをターゲット候補に含めない。
- `MobAiService.resolveChaseTarget(...)` は現在 target が死亡中の場合、target を失効扱いにして再選定する。再選定できない場合は target を解除して `IDLE` へ戻す。
- `MobCombatService.applyDamage(...)` は攻撃者プレイヤーが死亡中の場合、Mob へダメージ、ノックバック、threat 加算を行わず `0.0` を返す。
- `MobCombatService.resolveDropRecipients(...)` / `addRecipient(...)` は死亡中プレイヤーをドロップ、経験値、討伐記録、演出付与の対象に含めない。
