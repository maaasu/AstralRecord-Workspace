# 12_0.00-概要

## 1. 目的

`mob` 機能は、AstralRecord における NPC・敵・ボスを表すカスタムエンティティ（パケットエンティティ）を管理する。  
バニラのエンティティ AI・属性・ダメージ処理には依存せず、当たり判定を除き **すべてプラグイン側で独自実装** する。

主目的は以下。

- Mob テンプレートの API 経由ロード・メモリキャッシュ管理
- ワールド上の Mob インスタンス（パケット表示）の生成・更新・破棄
- 独自の AI（待機・徘徊・ターゲティング・戦闘）の駆動
- 独自のダメージ計算・ノックバック処理・ヘイト管理
- 撃破時のドロップ・経験値・金銭の抽選と払い出し

## 2. コンテキスト

- Mob テンプレートは AstralRecord API（`/api/mob`, `/api/mob/{mobId}`）から取得し、`MobService` の内部キャッシュに保持する。
- ワールド上に存在する Mob インスタンス（`MobInstance`）はサーバセッション内のメモリでのみ管理する（永続化なし）。
- 表示は ProtocolLib のパケットエンティティで行う（バニラエンティティを Bukkit `World.spawnEntity` で生成しない）。
- 当たり判定（クリック検出・ヒットボックス推定）はバニラの EntityType と座標から推定するが、ダメージ授受は本機能内で完結する。
- ボス（`category = BOSS`）の **フェーズ遷移・スキルローテーション・専用ギミック** は本機能のスコープ外で、別途 plugin 側で個別実装する想定。
- スポーン管理（位置・頻度・条件）は本機能のスコープ外。本機能は「テンプレート + 任意座標を入力としたスポーン処理」のみ提供する。

## 3. 構成要素（実装単位）

- `command/MobCommand`, `command/MobTabCompleter`
  - `/mob load|list|spawn|delete` を提供。`spawn` はテンプレート ID と実行者の現在地から `MobInstance` を生成し、`delete` はインスタンス UUID またはテンプレート ID に一致する `MobInstance` を破棄する。
- `service/MobService`
  - テンプレートのロード・キャッシュ、インスタンスの生成・破棄、参照取得 API を提供する。
- `service/MobAiService`
  - tick 駆動の AI ルーパー。Idle / Targeting / Leash の状態遷移と表示更新を管理する。最低限実装では攻撃・ドロップ処理は実行しない。
- `service/MobAiCalculator`
  - Mob の AI 移動計算を担当する。`MOVEMENT_SPEED`、AI 速度倍率、経路追従、壁クリアランス、段差上昇、任意落下、上方ターゲットへの詰まり時ジャンプ補助、液体中の減速・浮上補正を扱う。
- `service/MobCombatService`
  - 攻撃判定・独自ダメージ計算・致死判定・ドロップ確定までの責務を持つ。
- `service/MobKnockbackService`
  - 攻撃を受けた Mob、または Mob から受けたプレイヤーへのノックバックベクトル算出と送出を行う。
- `service/MobThreatTable`
  - Mob 単位のヘイト（プレイヤー -> 脅威値）を保持し、`HIGHEST_THREAT` 戦略の入力を提供する。
- `service/MobDropService`
  - `drops.items` の確率抽選、`drops.lootTable` の参照解決、経験値・金銭の払い出しを行う。
- `repository/MobRepository`
  - `/api/mob` と `/api/mob/{mobId}` への HTTP リクエストを実行する。
- `view/PacketMobView`
  - ProtocolLib によるパケット送出（spawn / metadata / move / animation / destroy）を担当する。
- [[12_1.00-モデル定義]]
  - Mob テンプレート、インスタンス、AI 設定、ドロップ設定など。

## 4. 依存関係

- 内部依存
  - `MobService` -> `MobRepository`, `PacketMobView`, `MobAiService`
  - `MobAiService` -> `MobService`, `MobThreatTable`, `MobAiCalculator`
  - `MobAiCalculator` -> `MobNavigator`
  - `MobCombatService` -> `MobKnockbackService`, `MobDropService`, `MobThreatTable`
- 外部依存
  - AstralRecord API（`/api/mob`, `/api/mob/{mobId}`）
  - `feature/status` の `StatusType`
  - `feature/player` の `AstPlayer`（ターゲット・ダメージ授受の対象）
  - ProtocolLib（パケット送出）
  - Reflections（任意。コマンド自動登録に使用）

## 5. ライフサイクル登録点

- 起動時:
  - `MobService` をプラグイン初期化で生成する。
  - `MobAiService` の tick タスクを `BukkitScheduler.runTaskTimer`（メインスレッド）で起動する。tick 周期は 1 tick。
  - `MobCommand` / `MobTabCompleter` を `core` 側で登録する。
- 終了時:
  - `core` 側で `MobAiService.stop` を呼び、tick タスクを停止する。
  - 続けて `core` 側で `MobService.destroyAll` を呼び、全インスタンスのパケット破棄とキャッシュ破棄を行う。
  - tick 停止 → 全 Mob 破棄の順を守ること。`MobService.destroyAll` 自体は tick 停止を呼ばない。

起動時に `MobService.loadAll` で全件プリロードする。テンプレートは `/mob load` で再ロードでき、`spawn` の初回呼び出し時にも未キャッシュ ID を都度ロードする。

## 6. 必要ライブラリ

| ライブラリ | 用途 | 状態 |
|---|---|---|
| `net.dmulloy2:ProtocolLib:5.4.0` | パケット送出 | 既存 `pom.xml` に provided 登録済み |
| `com.google.code.gson:gson` | API レスポンスの JSON パース | 既存 `pom.xml` に provided 登録済み |
| `org.reflections:reflections` | コマンド・イベント自動登録 | 既存 `pom.xml` に登録済み |
| Bukkit Scheduler | tick 駆動 | Paper API 標準 |

追加で新規ライブラリは導入しない方針。経路探索（A\*）が必要になった場合は本機能の独自実装で対応する（[[12_9.00-未決事項]] 参照）。
