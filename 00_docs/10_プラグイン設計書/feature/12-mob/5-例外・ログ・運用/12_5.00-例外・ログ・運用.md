# 12_5.00-例外・ログ・運用

## 1. 方針

`mob` 機能はワールド上に生成される実体 Mob の管理を担うため、障害時もサーバを止めずに以下を維持する。

- 不正なテンプレートが 1 件あっても他テンプレートのロード・利用は継続する
- AI tick 中の例外は該当インスタンスのみ DEAD 扱いで除去し、他インスタンスへ波及させない
- API 通信失敗時はリポジトリ層が `IOException` を伝播し、`MobService` 側で握りつぶさない

ログ出力は `LogId` ベースで行う。本機能の採番範囲は `5700-5799`。
個別 ID 採番は本ファイル「2. 主なログポイント」を正本とし、各メソッド仕様（[[12_3.02-サービス]] / [[12_3.03-戦闘]] / [[12_3.04-リポジトリ]] / [[12_3.05-実体Mob制御]]）の処理番号直下にインライン表として記載する。
ID 命名は `LogId.<I|W|E|D>_<番号>` 形式に統一する（既存 feature と同じ命名規約）。

## 3. 例外処理の境界

- **Repository**
  - HTTP 異常時は `IOException` を送出
  - `InterruptedException` は割り込みフラグを立て直し `RuntimeException` でラップ
  - `GET` 系の `404` は `null` 返却のみで沈黙する（WARN ログを出さない）
- **Service (`MobService`)**
  - リポジトリ例外を握りつぶさず呼び出し元へ伝播
  - `spawn` でテンプレート未発見時は `null` を返す
  - `404` に伴う警告ログはサービス側で WARN として出力する（リポジトリ側との二重出力を避ける）
- **AiService (`MobAiService`)**
  - `tick` 全体は try/catch で個別インスタンスの例外を捕捉し、該当インスタンスを `DEAD` 扱いにする
  - tick タスク全体の例外は ERROR ログ後、tick を継続させる
- **CombatService**
  - 命中判定・ダメージ計算・会心判定は例外捕捉なし（呼び出し元 `MobAiService` で捕捉される）
  - 致死処理のドロップ抽選例外は ERROR ログのうえ、Mob 破棄は実行する（致死自体は確定）
- **EntityController (`MobEntityController`)**
  - 実体 Mob 生成に失敗した場合は `MobService.spawn` が WARN ログを記録し、インスタンスを登録しない

## 4. スレッド上の注意

- `MobRepository.findById` / `findAllSummaries` は同期 HTTP。メインスレッドでの呼び出しはブロックする可能性がある。
- 初回テンプレートロードは `/mob load` などの管理者操作で行うこと。Spawn 時の遅延ロードはイベントブロック量を増やす可能性があるため監視対象。
- `MobAiService.tick` と `MobEntityController` の Bukkit/Paper API 操作はメインスレッドで実行する。頭上 TextDisplay の spawn / passenger attach / destroy も同様。

## 5. プレイヤー向けメッセージ

| MsgId | 内容 | 出力タイミング |
|---|---|---|
| 未定義 | コマンド未承認時のエラー | 既存コマンドフレーム |

本機能ではプレイヤー向けメッセージを直接定義しない（コマンドは管理者向け）。  
被ダメージ・撃破などのプレイヤー通知は `feature/hud` 側で扱う想定。

## 6. 運用上の注意

- 永続化なし: サーバ再起動で全 Mob インスタンスは消滅する。長期保持が必要なら別途設計（[[12_9.00-未決事項]]）。
- メモリ使用量: インスタンス数の上限ガードは未実装。`/mob list` で件数を監視すること。
- 実体 Mob は永続化しない。サーバ終了時は `MobService.destroyAll` で remove する。
- Paper API の Pathfinder / MobGoals の挙動はサーババージョン更新時に確認する。
- 固定 TextDisplay 配置は `text_displays.yml` を正本として永続化する。表示エンティティ自体は停止時に破棄し、起動時またはワールドロード後に YAML から再生成する。
- 固定 TextDisplay のテキストでは `&` カラーコードを許容する。表示適用は plugin 共通の `ColorCodeUtil` 経由で行い、`ChatColor` は使用しない。
