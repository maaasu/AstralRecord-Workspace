# 12_5.00-例外・ログ・運用

## 1. 方針

`mob` 機能はワールド上に表示されるパケットエンティティの実体管理を担うため、障害時もサーバを止めずに以下を維持する。

- 不正なテンプレートが 1 件あっても他テンプレートのロード・利用は継続する
- AI tick 中の例外は該当インスタンスのみ DEAD 扱いで除去し、他インスタンスへ波及させない
- API 通信失敗時はリポジトリ層が `IOException` を伝播し、`MobService` 側で握りつぶさない

ログ出力は `LogId` ベースで行う。`5500-5599` を本機能用に予約する。

## 2. 主なログポイント

### MobService

| 物理名 | 内容 | レベル |
|---|---|---|
| `loadAll` | テンプレート一括ロード完了 | INFO |
| `loadAll` | 例外発生時 | ERROR |
| `findTemplate` | キャッシュ登録時 | DEBUG |
| `spawn` | スポーン成功（テンプレート ID, インスタンス ID） | DEBUG |
| `spawn` | テンプレート未発見 | WARN |
| `destroy` | 個別破棄 | DEBUG |
| `destroyAll` | 全破棄完了（件数） | INFO |

### MobAiService

| 物理名 | 内容 | レベル |
|---|---|---|
| `start` | tick タスク開始 | INFO |
| `stop` | tick タスク停止 | INFO |
| `tick` | 個別インスタンスの例外（インスタンス ID 付き） | WARN |
| `tick` | tick 全体の例外 | ERROR |

### MobCombatService

| 物理名 | 内容 | レベル |
|---|---|---|
| `applyDamage` | 致死判定（mobId, killerUuid） | DEBUG |
| `handleDeath` | キラー特定失敗 | WARN |
| `handleDeath` | ドロップ抽選例外 | ERROR |

### MobRepository

| 物理名 | 内容 | レベル |
|---|---|---|
| `findAllSummaries` | 200 以外のレスポンス | ERROR（例外送出前） |
| `findById` | 200/404 以外のレスポンス | ERROR（例外送出前） |

### PacketMobView

| 物理名 | 内容 | レベル |
|---|---|---|
| `spawn` / `destroy` / `move` | パケット送出失敗 | WARN |

## 3. 例外処理の境界

- **Repository**
  - HTTP 異常時は `IOException` を送出
  - `InterruptedException` は割り込みフラグを立て直し `RuntimeException` でラップ
- **Service (`MobService`)**
  - リポジトリ例外を握りつぶさず呼び出し元へ伝播
  - `spawn` でテンプレート未発見時は `null` を返す
- **AiService (`MobAiService`)**
  - `tick` 全体は try/catch で個別インスタンスの例外を捕捉し、該当インスタンスを `DEAD` 扱いにする
  - tick タスク全体の例外は ERROR ログ後、tick を継続させる
- **CombatService**
  - 命中判定・ダメージ計算・会心判定は例外捕捉なし（呼び出し元 `MobAiService` で捕捉される）
  - 致死処理のドロップ抽選例外は ERROR ログのうえ、Mob 破棄は実行する（致死自体は確定）
- **View (`PacketMobView`)**
  - パケット送出失敗は WARN ログ。プレイヤーへの通知は行わない

## 4. スレッド上の注意

- `MobRepository.findById` / `findAllSummaries` は同期 HTTP。メインスレッドでの呼び出しはブロックする可能性がある。
- 初回テンプレートロードは `/mob load` などの管理者操作で行うこと。Spawn 時の遅延ロードはイベントブロック量を増やす可能性があるため監視対象。
- `MobAiService.tick` はメインスレッドで実行する。ProtocolLib も同様。

## 5. プレイヤー向けメッセージ

| MsgId | 内容 | 出力タイミング |
|---|---|---|
| 未定義 | コマンド未承認時のエラー | 既存コマンドフレーム |

本機能ではプレイヤー向けメッセージを直接定義しない（コマンドは管理者向け）。  
被ダメージ・撃破などのプレイヤー通知は `feature/hud` 側で扱う想定。

## 6. 運用上の注意

- 永続化なし: サーバ再起動で全 Mob インスタンスは消滅する。長期保持が必要なら別途設計（[[12_9.00-未決事項]]）。
- メモリ使用量: インスタンス数の上限ガードは未実装。`/mob list` で件数を監視すること。
- ProtocolLib のバージョンに依存するため、サーバ側のバージョン変更時にパケットフィールド指定を見直すこと。
- `entityId` の採番は `AtomicInteger`（初期値 `2_000_000`）で行う。プロセス再起動でリセットされるため、再起動跨ぎでクライアントに残った Mob は表示崩れる可能性がある（自然消滅は次の表示範囲更新で）。
