# 22_5.00-例外・ログ・運用

## 1. プレイヤー向けメッセージ

| ID | 種別 | 内容 |
|:--|:--|:--|
| P_6200 | PlayerMsgId | `%s` にトレード申請を送信しました。 |
| P_6201 | PlayerMsgId | `%s` からトレード申請が届いています。`/trade accept` で開始できます。 |
| P_6202 | PlayerMsgId | トレード申請が見つかりません。 |
| P_6203 | PlayerMsgId | 対象プレイヤーは現在トレードできません。 |
| P_6204 | PlayerMsgId | このアイテムはトレードできません。 |
| P_6205 | PlayerMsgId | 相手の準備完了を待っています。もう一度押すと準備をキャンセルします。 |
| P_6206 | PlayerMsgId | トレード準備をキャンセルしました。 |
| P_6207 | PlayerMsgId | トレードが成立しました。 |
| P_6208 | PlayerMsgId | トレードを中止しました。 |
| P_6209 | PlayerMsgId | 相手のインベントリに空きがないため、トレードを開始できません。 |

クリック可能な申請メッセージは `P_6201` を本文として使用し、クリック実行コマンドに `/trade accept` を設定する。

## 2. ログ

| ID | レベル | 内容 |
|:--|:--|:--|
| E_6200 | ERROR | トレードGUIクリック処理に失敗しました: %s |
| E_6201 | ERROR | トレード成立処理に失敗しました: %s |
| W_6202 | WARN | トレードアイテム返却に失敗しました: %s |

## 3. 例外時の扱い

- 申請作成に失敗した場合、申請者へ失敗メッセージを送信し、セッションは作成しない。
- 取引成立処理中に検証失敗した場合、アイテム交換は行わず、双方の準備状態を未準備へ戻す。
- 取引成立処理中に例外が発生した場合、可能な限り提示アイテムを元の所有者へ返却し、セッションを `CANCELLED` として扱う。
- 返却に失敗したアイテムは inventory feature の返却失敗時ルールに従い、`W_6202` を記録する。
- 取引不可アイテムの GUI 移動はイベントをキャンセルし、元のインベントリ状態を維持する。

## 4. 運用

- トレードセッションと申請はメモリ上で管理し、サーバー停止時に永続化しない。
- サーバー停止時に未完了セッションが存在する場合、停止処理でキャンセル扱いにし、返却可能なアイテムを元の所有者へ戻す。
- 取引履歴の追跡が必要になった場合は、別途 DB / API 設計を追加する。
