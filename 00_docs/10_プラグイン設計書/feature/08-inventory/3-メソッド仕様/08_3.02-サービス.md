# 08_3.02-サービス

## 1. インベントリ確保

クラス名: `InventoryService`
物理名: `ensureInventory`

責務:

指定 accountId / inventoryType / profile のインベントリを取得し、存在しない場合は作成する。

処理内容:

1. キャッシュ内に条件一致するインベントリがあれば返す
2. 作成中の同一 accountId がある場合は pending task を再利用する
3. 一時 UUID の optimistic inventory を作成しキャッシュへ追加する
4. API 作成完了後、一時 UUID を API 採番 UUID に置換する

## 2. 通常インベントリアイテム追加

クラス名: `InventoryService`
物理名: `addItemToNormalInventory`

責務:

ItemModel と数量を、適切なプレイヤー所有インベントリへ追加する。

処理内容:

1. ItemModel から格納先 [[08_1.00-モデル定義]].インベントリ種別 を解決する
2. 装備・ルーン等の個体管理アイテムは個体 ID を生成し、1 個ずつエントリを追加する。スタック加算（処理 3）は経由せず、空き slotIndex 探索（処理 4）に進む
3. スタック可能アイテムは同一 itemId の既存エントリへ可能な限り数量加算する。残数が無くなればここで終了し、残数があれば処理 4 へ進む
4. 残数分の空き slotIndex を探索し新規エントリを追加する。空きが尽きた時点で追加を停止する
5. 追加先が表示中インベントリの場合は GUI を更新する
6. 要求数量に対し追加できなかった残数がある場合、対象プレイヤーへ以下メッセージを送信する

    | 項目 | 内容 |
    |---|---|
    | ID | PlayerMsgId.P_5241 |
    | テンプレート | インベントリに空きがありません。 |
    | 出力条件 | 要求数量の一部または全てが追加できなかった場合 |
    | 引数 | なし |

7. 実際に追加できた個数を返す

## 3. インベントリ GUI 反映

クラス名: `InventoryService`
物理名: `applyInventoryToGui`

責務:

指定 [[08_1.00-モデル定義]].インベントリ種別 の内容を Bukkit プレイヤーインベントリへ反映する。

処理内容:

1. accountId ごとの表示中インベントリ種別を更新する
2. 対象インベントリが存在しなければ確保する
3. slotted inventory のエントリから ItemStack 一覧を生成する
4. 管理対象 storage slot をクリアし、slotIndex に対応する Bukkit slot へ配置する
5. ホットバー、装備スロット、アクセサリスロットも必要に応じて再描画する
6. オフハンド・ホットバーの各スロットは既存 ItemStack と表示上同一（材質・数量・メタ）であれば再設置を抑止する

## 4. 装備 GUI 保存

クラス名: `InventoryService`
物理名: `saveEquipmentGui`

責務:

装備 GUI の ItemStack 群を EQUIP_SLOT / ACCESSORY_SLOT と有効装備プリセットへ保存する。

処理内容:

1. 頭・胴・脚・足の ItemStack を Bukkit 装備欄へ反映し、EQUIP_SLOT の metadataJson にスナップショット保存する
2. オフハンドを Bukkit オフハンドへ反映する
3. 有効装備プリセットがあれば loadout slot を upsert / delete する。`slotType` は `HEAD` / `CHEST` / `LEGS` / `FEET` / `ACCESSORY` のいずれかを使用する
4. 拡張アクセサリ 2〜7 の状態をプリセット側 `ACCESSORY` スロット（slotIndex 2〜7）へ同期する
5. Bukkit 現在装備状態を更新する

オフハンドは [[08_1.00-モデル定義]].装備種別 の `OFF_HAND` で表現し、ACCESSORY_SLOT 上では slot_index 1 を使う。拡張アクセサリは Bukkit に対応スロットを持たないため、表示と操作は専用 GUI 経由で行う。

## 5. 通常インベントリスナップショット保存

クラス名: `InventoryService`
物理名: `saveNormalInventorySnapshot`

責務:

プレイヤーの Bukkit 通常インベントリ領域（slot 9〜35）を `NORMAL` インベントリへ保存する。

処理内容:

1. 対象プレイヤーが GUI 反映対象モードでない場合は終了する
2. Bukkit インベントリの slot 9〜35 を読み取り ItemStack 配列を組み立てる
3. [[08_3.05-タスク・補助]].スナップショットエンコード・デコード で metadataJson 用の Base64 文字列へ変換する
4. accountId / `NORMAL` のインベントリを確保し、`metadataJson` を更新する形で [[08_3.04-リポジトリ]].インベントリ作成 もしくは更新系エンドポイントへ書き込む
5. 書き込みは非同期に発行し、保留中タスクとして登録する

## 6. 装備スロットスナップショット保存

クラス名: `InventoryService`
物理名: `saveEquipSlotSnapshot`

責務:

プレイヤーの Bukkit 防具スロット（slot 36〜39: 頭・胴・脚・足）の現在状態を `EQUIP_SLOT` インベントリの `metadataJson` へスナップショット保存する。オフハンドは本処理では対象外とし、[[08_3.02-サービス]].アクセサリスロットスナップショット保存 側で扱う。

処理内容:

1. 対象プレイヤーが GUI 反映対象モードでない場合は終了する
2. 頭・胴・脚・足の ItemStack を Bukkit インベントリから読み取り、slotIndex 配列（2=頭, 3=胴, 4=脚, 5=足）に格納する
3. accountId / `EQUIP_SLOT` のインベントリを確保する
4. [[08_3.05-タスク・補助]].スナップショットエンコード・デコード で配列を Base64 文字列へエンコードし、`metadataJson` を非同期更新する
5. 書き込みは保留中タスクとして登録する

## 7. アクセサリスロットスナップショット保存

クラス名: `InventoryService`
物理名: `saveAccessorySlotSnapshot`

責務:

`ACCESSORY_SLOT` インベントリへ、オフハンド（slot_index 1）と拡張アクセサリ（slot_index 2〜7）の装備状態を保存する。実態は現在装備状態の同期処理（装備プリセット側への反映）に委譲する。

処理内容:

1. 対象プレイヤーが GUI 反映対象モードでない場合は終了する
2. オフハンドは Bukkit インベントリから、拡張アクセサリは専用 GUI 状態（[[08_1.00-モデル定義]].アクセサリスロット種別 別）から取得する
3. accountId / `ACCESSORY_SLOT` のインベントリを確保する
4. 各 slot_index の ItemStack を ACCESSORY_SLOT エントリへ upsert / 未装備スロットは削除する
5. 有効装備プリセットがある場合、`ACCESSORY` slotType 側へも同期する（slotIndex は `OFF_HAND` を `0`、拡張アクセサリは `2`〜`7`）
6. 書き込みは [[08_3.04-リポジトリ]].インベントリエントリ作成・更新・削除 へ委譲し、保留中タスクとして登録する

## 8. ホットバースナップショット保存

クラス名: `InventoryService`
物理名: `saveHotbarSnapshot`

責務:

`HOTBAR` インベントリ（accountId 単位）が常時保持する entry を最新内容で再キャッシュし、ホットバー描画に使えるよう整える。HOTBAR の entry 自体は配置・操作の都度書き込まれており、本処理で Bukkit ホットバーから新規に取り込むことはしない。

処理内容:

1. 対象プレイヤーが GUI 反映対象モードでない場合は終了する
2. accountId / `HOTBAR` のインベントリを確保する
3. リポジトリから最新の entry 一覧を取得し、ホットバーキャッシュへ反映する
4. ホットバーショートカットモード中も HOTBAR entry が常に正であり、ショートカットアイコンは描画段階で差し替えるのみで entry には書き戻さない

## 8.1 通常インベントリスナップショット読み込み

クラス名: `InventoryService`
物理名: `loadNormalInventorySnapshot`

責務:

`NORMAL` インベントリの metadataJson から slot 9〜35 用の ItemStack 配列を復元し、呼び出し元へ返す。

処理内容:

1. accountId / `NORMAL` のインベントリを取得する
2. metadataJson が無い、または復元に失敗した場合は `null` を返す
3. [[08_3.05-タスク・補助]].スナップショットエンコード・デコード で ItemStack 配列を復元して返す
4. Bukkit インベントリへの反映は本メソッドでは行わず、呼び出し元の責務とする

## 8.2 装備スロットスナップショット読み込み

クラス名: `InventoryService`
物理名: `loadEquipmentSlotSnapshot`

責務:

`EQUIP_SLOT` インベントリの entry から、頭・胴・脚・足・オフハンドの ItemStack を [[08_1.00-モデル定義]].装備種別 別に返す。

処理内容:

1. accountId / `EQUIP_SLOT` のインベントリを取得する
2. インベントリまたは entry が無ければ空マップを返す
3. 各 entry の slotIndex から装備種別を解決し、[[08_3.05-タスク・補助]].ItemStack 解決 で ItemStack を生成する
4. Bukkit 装備スロットへの反映は呼び出し元の責務とする

## 8.3 アクセサリスロットスナップショット読み込み

クラス名: `InventoryService`
物理名: `loadAccessorySlotSnapshot`

責務:

`ACCESSORY_SLOT` インベントリの entry から、各 [[08_1.00-モデル定義]].アクセサリスロット種別 の ItemStack を返す。

処理内容:

1. accountId / `ACCESSORY_SLOT` のインベントリを取得する
2. インベントリまたは entry が無ければ空マップを返す
3. 各 entry の slotIndex からアクセサリスロット種別を解決し、[[08_3.05-タスク・補助]].ItemStack 解決 で ItemStack を生成する
4. アクセサリ装備 GUI / 拡張表示への反映は呼び出し元の責務とする

## 8.4 ホットバースナップショット読み込み

クラス名: `InventoryService`
物理名: `loadHotbarSnapshot`

責務:

`HOTBAR` インベントリの entry から、slot 0〜8 の ItemStack 配列を返す。

処理内容:

1. accountId / `HOTBAR` のインベントリを取得する
2. インベントリまたは entry が無ければ `null` を返す
3. 各 entry の slotIndex 0〜8 に [[08_3.05-タスク・補助]].ItemStack 解決 で生成した ItemStack を配置した配列を返す
4. Bukkit ホットバーへの反映は呼び出し元の責務とする

## 9. ホットバーショートカットモード設定

クラス名: `InventoryService`
物理名: `setHotbarShortcutMode`

責務:

menu feature の GUI 表示中に、ホットバーをインベントリ操作用ショートカット表示へ切り替える。

処理内容:

1. `on` の場合は accountId を hotbarShortcutMode に追加する
2. `off` の場合は hotbarShortcutMode から削除する
3. 状態に応じてホットバーを通常表示またはショートカットアイコンへ再描画する

## 10. 表示インベントリから装備 GUI への移動

クラス名: `InventoryService`
物理名: `moveDisplayedItemToEquipmentGui`

責務:

装備 GUI のプレイヤーインベントリ欄から装備したアイテムを、表示中インベントリの entry から除去し、入れ替え元があれば所有インベントリへ返却する。

処理内容:

1. source Bukkit slot に対応する表示中インベントリ entry を取得する
2. 入れ替え元 ItemStack がある場合、AstralRecord アイテムであることを確認する
3. 移動元 entry を削除し、移動元インベントリの slotIndex を詰め直す
4. 入れ替え元 ItemStack がある場合は既存インスタンス ID を維持して所有インベントリへ戻す
5. 管理インベントリの GUI 表示を即時と次 tick の両方で再描画する
6. entry の削除・追加・スロット詰めはプラグイン内の entry 一覧で先に確定し、API へは一括置換で同期する

## 11. 管理インベントリ UI 再描画

クラス名: `InventoryService`
物理名: `requestManagedInventoryUiRefresh`

責務:

表示中インベントリやホットバーの entry 変更後、Bukkit のイベント処理完了後にも最新状態が見えるよう再描画を予約する。

処理内容:

1. 表示中インベントリを即時に Bukkit storage slot へ反映する
2. 必要に応じて HOTBAR キャッシュをホットバーへ反映する
3. `Player#updateInventory` を即時実行する
4. 次 tick に同じ再描画と `updateInventory` を再実行する

## 12. インベントリ entry 一括同期

クラス名: `InventoryService`
物理名: `replaceEntriesOptimistically`

責務:

プラグイン内で確定したインベントリ entry 一覧を表示キャッシュへ即時反映し、裏で API の一括置換 endpoint へ同期する。

処理内容:

1. 置換後 entry 一覧から表示用 `InventoryEntryModel` を生成し、`entryCache` を即時置換する
2. 対象 inventoryId を同期中として記録し、同期中の API 再取得で古い entry に戻らないようにする
3. [[08_3.04-リポジトリ]].インベントリエントリ一括置換 を呼び出し、置換後 entry 一覧を API へ送信する
4. API 応答の正式 entryId を `entryCache` へ再反映する
5. 失敗時は `LogId.W_5252` でインベントリ同期失敗として記録する
