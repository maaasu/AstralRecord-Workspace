# 08_3.02-サービス

## 1. state 参照

クラス名: `InventoryService`  
対象メソッド: `getInventories`, `getInventory`, `getEntries`, `getPersistence`, `getStateRegistry`

説明

inventory feature の読み取り系は API を直接呼ばず、`PlayerInventoryStateRegistry` 上の state を参照する。

処理手順:

1. `accountId` から `PlayerInventoryState` を取得する
2. inventory 一覧、inventory 単体、entry 一覧を state から返す
3. state 未登録時は空一覧または `null` を返す

## 2. 通常インベントリアイテム追加

クラス名: `InventoryService`  
対象メソッド: `addItemToNormalInventory`

説明

取得アイテムを `NORMAL` / `EQUIPMENT` / `RUNE` のいずれかへ追加し、state を更新する。

処理手順:

1. item category から格納先 `InventoryType` を解決する
2. 対象 inventory が未存在なら `ensureInventory` で API に同期作成する
3. 装備・ルーンは必要に応じて instanceId を生成して新規 entry を追加する
4. 通常スタック可能アイテムは既存 entry へ加算するか、空き slot へ追加する
5. 追加成功時は `state.replaceEntries(...)` により dirty を立てる
6. 対象 inventory が表示中なら GUI を再描画する
7. 入りきらない場合は `PlayerMsgId.P_5241` を返す

## 3. ビルダーインベントリ保存・反映

クラス名: `InventoryService`  
対象メソッド: `saveBuilderInventorySnapshot`, `applyBuilderInventoryToGui`

説明

`InventoryProfile.BUILDER` 用 inventory を Bukkit 側 inventory と相互変換する。

## 4. 表示インベントリ GUI 反映

クラス名: `InventoryService`  
対象メソッド: `applyInventoriesToGui`, `applyInventoryToGui`, `getDisplayedInventoryType`, `clearGuiInventory`

説明

表示対象 inventory を Bukkit `PlayerInventory` の管理スロットへ反映する。

処理手順:

1. state 上の `displayedType` と対象 inventory を解決する
2. `InventoryItemStackResolver` で entry を `ItemStack` へ変換する
3. 管理対象スロットだけを書き換え、不要な再配置を避ける
4. GUI 反映対象 mode でない場合は何もしない

## 5. 装備ロードアウト取得・保証

クラス名: `InventoryService`  
対象メソッド: `getEquipmentLoadouts`, `getActiveEquipmentLoadout`, `ensureActiveEquipmentLoadout`

説明

装備ロードアウトは state を参照する。active loadout 未存在時のみ API に同期作成して state へ取り込む。

## 6. 現在装備同期

クラス名: `InventoryService`  
対象メソッド: `syncCurrentEquipmentState`

説明

Bukkit の現在装備状態を active loadout に同期する。

処理手順:

1. 頭 / 胴 / 脚 / 足 / オフハンドの `ItemStack` から装備インスタンス ID を読む
2. `PlayerInventoryState.upsertActiveLoadoutSlot(...)` で loadout slot を更新する
3. loadout 更新により dirty を立てる

## 7. 装備 GUI 保存

クラス名: `InventoryService`  
対象メソッド: `saveEquipmentGui`

説明

装備 GUI 上の ItemStack を `EQUIP_SLOT` / `ACCESSORY_SLOT` inventory と active loadout へ反映する。

処理手順:

1. GUI スロットの ItemStack を inventory entry へ変換する
2. 防具・アクセサリ inventory を `state.replaceEntries(...)` で置き換える
3. active loadout slot も同時に更新する
4. Bukkit 現在装備状態を更新する

## 8. 装備・ホットバー・アクセサリのスナップショット保存

クラス名: `InventoryService`  
対象メソッド: `saveEquipSlotSnapshot`, `saveHotbarSnapshot`, `saveAccessorySlotSnapshot`

説明

保存契機時に Bukkit 側の最新状態を state へ取り込む。いずれも `state.replaceEntries(...)` を呼ぶため dirty が立つ。

## 9. 装備・ホットバー・アクセサリの GUI 反映

クラス名: `InventoryService`  
対象メソッド: `applyEquipSlotInventoryToGui`, `applyHotbarInventoryToGui`, `applyAccessorySlotInventoryToGui`

説明

対応 inventory の entry 一覧を Bukkit 側へ反映する。

## 10. ホットバー操作

クラス名: `InventoryService`  
対象メソッド: `handleHotbarSlotClick`, `moveToHotbar`, `setHotbarShortcutMode`, `isHotbarShortcutMode`, `handleHotbarShortcutClick`, `hasHotbarEntry`

説明

ホットバー entry の選択、ショートカット表示切替、Bukkit スロット操作を扱う。
- 通常ホットバー表示時の slot `8` インベントリ切替アイコンは `displayedType` に応じて見た目を切り替える。
- 空スロット選択は「割当先選択」とみなし、呼び出し元ではクリック音を再生する。

## 11. 装備移動とアクセサリ移動

クラス名: `InventoryService`  
対象メソッド: `equipToSlot`, `moveDisplayedItemToEquipmentGui`, `moveToAccessorySlot`, `returnItemToOwnedInventory`, `compactInventoryEntries`

説明

表示中 inventory と装備 GUI / 防具スロット / アクセサリスロット間の移動を行う。

処理手順:

1. 移動元 entry または Bukkit `ItemStack` を解決する
2. 必要に応じて instanceId を保持したまま戻し先 inventory へ追加する
3. 移動後の inventory は `compactInventoryEntries(...)` で詰め直す
4. 変更結果を state に反映し、dirty を立てる
5. 必要に応じて表示中 inventory を自動切替し GUI を再描画する

## 12. metadata 更新

クラス名: `InventoryService`  
対象メソッド: `updateMetadataAsync`

説明

inventory の `metadataJson` を state 上で更新する。  
即時 API 書き込みは行わず、次回 save 時に反映される。

## 13. 旧 flush API の互換フック

クラス名: `InventoryService`  
対象メソッド: `flushPendingCoalescedWrites`, `awaitPendingWrites`

説明

旧 coalescer 実装との互換のために残しているフック。  
現行実装では `flushPendingCoalescedWrites` は no-op、`awaitPendingWrites` は `InventoryPersistence.awaitShutdown(...)` を呼ぶだけである。

即時整合性が必要な処理は `InventoryPersistence.saveNow(PlayerInventoryState)` を使う。

## 14. クリッククールタイム

クラス名: `InventoryClickGuard`  
対象メソッド: `tryAcquire`

説明

accountId と click action 単位で 100ms のクールタイムを持ち、重複クリックを無視する。
