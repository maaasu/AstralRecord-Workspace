# 08_5.00-例外・ログ・運用

## 1. ログ

| ID | レベル | テンプレート | 用途 |
|---|---|---|---|
| `LogId.W_5252` | WARN | `インベントリ同期に失敗しました: target=%s, reason=%s` | API への一括置換・metadataJson 更新・キャッシュ再取得などインベントリ同期処理の失敗（引数: 対象を識別する文字列（inventoryId / accountId / `shutdown` 等）と失敗理由メッセージ） |
| `LogId.E_5600` | ERROR | `メニューイベント処理に失敗しました: %s` | 装備 GUI・インベントリクリック等の inventory feature イベント処理失敗（runSafely で捕捉。引数: プレイヤー名） |

## 2. プレイヤーメッセージ

| ID | テンプレート | 用途 |
|---|---|---|
| `PlayerMsgId.P_5250` | `現在の mode では AstralRecord インベントリを反映しません。` | アカウントモードが GUI 反映対象外 |
| `PlayerMsgId.P_5251` | `無効なインベントリタイプです。指定可能: {0}` | `/inventory` の type が不正 |
| `PlayerMsgId.P_5252` | `InventoryService が初期化されていません。` | サービス未初期化 |
| `PlayerMsgId.P_5253` | `インベントリを切り替えました: {0}` | 表示インベントリ切替成功 |
| `PlayerMsgId.P_5241` | `インベントリに空きがありません。` | [[08_3.02-サービス]].通常インベントリアイテム追加 で要求数量の一部または全てが追加できなかった場合に inventory feature から送信 |

## 3. 例外方針

- イベント処理は `runSafely` で捕捉し、プレイヤー操作をサーバー全体の例外へ波及させない。
- API 通信中の `InterruptedException` は interrupt flag を復元して RuntimeException とする。
- API の 404 は、一覧取得では空リスト、単体取得では `null` として扱う。
- optimistic cache 反映後の API 書き込み失敗は、後続 refresh による復旧対象とする。

## 4. 運用注意

- `NORMAL`, `EQUIPMENT`, `RUNE` 以外を `/inventory` から直接切り替え可能にする場合は、[[08_1.00-モデル定義]] と [[08_3.03-コマンド]] を同時更新する。
- API エンドポイントの payload が変わる場合は、[[08_3.04-リポジトリ]] と `20_API設計書` 側を同時確認する。
- 装備スロット番号を変える場合は、menu feature の装備 GUI スロット配置と合わせて更新する。
