## 3. 例外方針

- イベント処理は `runSafely` で捕捉し、プレイヤー操作をサーバー全体の例外へ波及させない。
- API 通信中の `InterruptedException` は interrupt flag を復元して RuntimeException とする。
- API の 404 は、一覧取得では空リスト、単体取得では `null` として扱う。
- optimistic cache 反映後の API 書き込み失敗は、後続 refresh による復旧対象とする。
- インベントリ entry / metadata / 装備ロードアウトの API 書き込みは [[08_3.02-サービス]].インベントリ書き込み coalescer で既定 1 秒の debounce 窓に集約する。短時間に連続発火する装備入れ替え・ホットバー切替・装備スロット更新・スナップショット保存等は、最新状態を 1 回の API 呼び出しでまとめて送る。
- coalescer 集約の後、inventoryId / accountId 単位で書き込みを直列化する。後続書き込みが先に発行されていた場合、古い書き込みの応答は破棄し、`entryCache` / `equipmentLoadoutCache` を上書きしない。これにより、高速連打時に古い API 応答で楽観反映済みのキャッシュが巻き戻る事象を防ぐ。
- 楽観反映から coalesce flush 完了までの間は `pendingEntryReplaces` / loadout in-flight カウンタを保持し、`refreshEntries` / `refreshEquipmentLoadoutsAsync` の API 再取得を抑止する。
- ログアウト時は [[08_3.02-サービス]].coalesce 保留分の flush を `playerSaveCoordinator.save` より先に呼び、debounce 中の最新書き込みを確実に API へ送る。プラグイン停止時は `awaitPendingWrites` が `flushAll → 待機 → shutdown` を行う。
- インベントリ系クリックは [[08_3.02-サービス]].クリッククールタイム を通し、既定 100ms のクールタイム内に再入したクリックは音・メッセージを出さずに無視する（イベントは必要に応じてキャンセル）。

## 4. 運用注意

- `NORMAL`, `EQUIPMENT`, `RUNE` 以外を `/inventory` から直接切り替え可能にする場合は、[[08_1.00-モデル定義]] と [[08_3.03-コマンド]] を同時更新する。
- API エンドポイントの payload が変わる場合は、[[08_3.04-リポジトリ]] と `20_API設計書` 側を同時確認する。
- 装備スロット番号を変える場合は、menu feature の装備 GUI スロット配置と合わせて更新する。
