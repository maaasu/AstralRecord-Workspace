|---|---|---|---|
| `LogId.W_5252` | WARN | `インベントリ永続化に失敗しました: target=%s, reason=%s` | join 時ロード、inventory entry 一括置換、autosave / logout save など inventory 永続化系の失敗 |

## 3. 例外・運用方針

- `runSafely` で包んだ GUI 更新処理は例外をサーバーログへ出して処理継続する
- API 通信中の `InterruptedException` は interrupt flag を復元して RuntimeException とする
- API の 404 は、一覧取得では空レスポンス、単体取得では `null` として扱う
- join 時ロード失敗は WARN のみ残して処理継続する。state は空のまま生成され、必要な inventory は後続処理で補完する
- プレイ中の変更は `PlayerInventoryState` に集約し、`dirty` で保存要否を管理する
- autosave / logout save 失敗時は `PlayerInventoryState.restoreDirty()` により次回 save 対象へ戻す
- inventory entry 永続化は inventoryId 単位の `replaceEntries` で行い、loadout は前回保存との差分 slot のみ `upsertSlot` / `deleteSlot` する
- `InventoryAutoSaveTask` は 60 秒間隔で dirty state を保存する。1 人の失敗で他プレイヤー保存は止めない
- ログアウト時は旧 coalescer flush を使わず `InventorySaveTask` の通常 save に統合する。`flushPendingCoalescedWrites` / `awaitPendingWrites` は互換用スタブとして残す
- inventory クリックは [[08_3.02-サービス]].クリッククールタイム で抑止し、100ms のクールタイム中の重複操作は無視する

## 4. 運用メモ

- `/inventory` は統合所持品 BAG の再描画のみを行い、カテゴリ切替引数を持たない
- BAG が満杯の場合は追加数0として取得を拒否する。受取箱・一時保管は将来設計とし、本変更では扱わない
- API payload 変更が発生した場合は [[08_3.04-リポジトリ]] と `20_API設計書` 側も合わせて更新する
- 装備 GUI スロットやアクセサリ slotIndex を変更した場合は menu feature 側の表示仕様とも同期する
