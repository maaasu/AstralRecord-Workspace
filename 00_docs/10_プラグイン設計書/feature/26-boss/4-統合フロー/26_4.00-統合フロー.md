# 26_4.00-統合フロー

## 1. 挑戦受付から戦闘開始

1. `BossEntryParticleTask` がボス挑戦地点を表示する。
2. プレイヤーが円内でスニークする。
3. `BossEntryEventHandler` が `BossChallengeService.acceptChallenge` を呼び出す。
4. `BossChallengeService` がボスマスター、挑戦設定、パーティー状態、リーダー権限、進行中重複を検証する。
5. 受付時点の参加予定者を固定し、`BossChallengeInstance` と `BossWaitingFlag` を作成する。
6. 対象プレイヤーを `boss.hubWorldId` のハブワールドへ転送する。
7. `BossFieldInstanceService.startCreateField` が `challenge.battleWorldId` の `WorldMasterData` を使ってボスフィールドコピーを開始する。
8. コピー完了後、メインスレッドで Bukkit ワールドをロードし、フィールド状態を `READY` にする。
9. `BossHubWaitingDisplayTask` が集合人数を表示し、フィールド準備済みかつ全員集合済みになったら `BossChallengeService.tryEnterField` を呼び出す。
10. 参加予定者全員を `challenge.playerSpawnLocation` へ転送する。
11. `BossCombatService.startCombat` が `challenge.bossSpawnLocation` へボスをスポーンし、状態を `IN_PROGRESS` にする。

## 2. 戦闘中

1. `BossChallengeTickTask` が `IN_PROGRESS` の挑戦を定期確認する。
2. 残り時間、デスカウント、ボス HP、現在フェーズを表示する。
3. `DamageService` が対象ボスへダメージを反映する。
4. `BossDamageStatisticsService.recordDamage` が参加者別の有効与ダメージを加算する。
5. 参加者死亡時、`BossPlayerDeathEventHandler` がデスカウントを加算する。
6. `currentDeathCount >= challenge.deathLimit` の場合、終了理由 `DEATH_LIMIT` で挑戦を終了する。
7. 残り時間が `0` 以下の場合、終了理由 `TIME_LIMIT` で挑戦を終了する。
8. ボス HP が 0 以下の場合、終了理由 `DEFEATED` で挑戦を終了する。
9. ボスフィールド内の参加者が 0 人になった場合、終了理由 `NO_PARTICIPANTS` で挑戦を終了する。

## 3. 討伐成功終了

1. `BossChallengeService.endChallenge(DEFEATED)` が状態を `ENDING` にする。
2. `BossRewardService.grantRewards` が報酬対象者を確定する。
3. 通常 Mob と同じ報酬処理で `drops.items`、`drops.lootTable`、`drops.exp`、`drops.money` を付与する。
4. ボス討伐演出を再生する。
5. `BossResultViewService.showResult` が成功結果を表示する。
6. 参加者を退場先へ転送する。
7. `BossFieldInstanceService.destroyField` が Mob 破棄、ワールドアンロード、フォルダ削除を行う。
8. キャッシュと待機フラグを削除し、状態を `ENDED` にする。

## 4. 失敗終了

1. `BossChallengeService.endChallenge(<失敗理由>)` が状態を `ENDING` にする。
2. 報酬処理は実行しない。
3. `BossResultViewService.showResult` が失敗理由、経過時間、合計与ダメージ、プレイヤー別与ダメージ、死亡回数を表示する。
4. 参加者を退場先へ転送する。
5. `BossFieldInstanceService.destroyField` が Mob 破棄、ワールドアンロード、フォルダ削除を行う。
6. キャッシュと待機フラグを削除し、状態を `ENDED` にする。

## 5. ログアウトとパーティー制御

1. 挑戦中に参加者がログアウトした場合、対象参加者を非アクティブ化する。
2. 残り参加者がいる限り挑戦状態は変更しない。
3. 最後の参加者がログアウトした場合、終了理由 `NO_PARTICIPANTS` で失敗終了する。
4. パーティーリーダーがログアウトしても、party feature 側のリーダー切替に従い、ボス挑戦は継続する。
5. ボス挑戦中の自発的なパーティー解散・離脱は、party feature の要求イベントをキャンセルして抑制する。

## 6. 起動時掃除

1. プラグインロード時に `WorldMasterData` をロードする。
2. `BossFieldStartupCleanupTask` が `BOSS_FIELD` かつ `instanceEnabled = true` の `instanceRootPath` 配下を確認する。
3. 残存インスタンスワールドがあれば、ロード済みワールドをアンロードしたうえでフォルダ削除する。
4. 削除失敗時はログを残し、次回起動時の掃除対象に残す。
