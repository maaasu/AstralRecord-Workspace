# 26_5.00-例外・ログ・運用

## 1. 例外方針

| 場面 | 扱い |
|---|---|
| ボスマスターが存在しない | 挑戦開始不可。プレイヤーへ設定不備を表示する |
| `category != BOSS` | 挑戦開始不可。通常 Mob として扱う |
| `challenge` が存在しない | 挑戦開始不可。プレイヤーへ設定不備を表示する |
| `boss.hubWorldId` が解決できない | 挑戦開始不可。ログを残す |
| `battleWorldId` が解決できない | `FIELD_CREATE_FAILED` として失敗終了する |
| `worldType != BOSS_FIELD` | `FIELD_CREATE_FAILED` として失敗終了する |
| `instanceEnabled != true` | `FIELD_CREATE_FAILED` として失敗終了する |
| テンプレートコピー失敗 | `FIELD_CREATE_FAILED` として失敗終了し、ログを残す |
| Bukkit ワールドロード失敗 | `FIELD_CREATE_FAILED` として失敗終了し、ログを残す |
| 必須参加者転送失敗 | `TRANSFER_FAILED` として失敗終了する |
| ワールドアンロード失敗 | ログを残し、フォルダ削除を試みない |
| コピー先フォルダ削除失敗 | ログを残し、起動時掃除対象に回す |

## 2. ログ方針

ログ ID は実装時に `LogId` と `logger.properties` へ追加する。設計上の出力内容は以下を正とする。

| 場面 | レベル | テンプレート |
|---|---|---|
| ボス挑戦受付 | INFO | ボス挑戦を受け付けました: bossId=%s, partyId=%s, participants=%s |
| ボスフィールド生成開始 | INFO | ボスフィールド生成を開始しました: bossId=%s, partyId=%s, worldId=%s, instance=%s |
| ボスフィールド生成失敗 | ERROR | ボスフィールド生成に失敗しました: bossId=%s, partyId=%s, reason=%s |
| ボス戦開始 | INFO | ボス戦を開始しました: bossId=%s, partyId=%s, participants=%s |
| ボス挑戦終了 | INFO | ボス挑戦を終了しました: bossId=%s, partyId=%s, reason=%s |
| ボスフィールド破棄失敗 | ERROR | ボスフィールド破棄に失敗しました: instance=%s, path=%s, reason=%s |
| 起動時掃除失敗 | ERROR | 残存ボスフィールド掃除に失敗しました: path=%s, reason=%s |

## 3. プレイヤー向けメッセージ方針

メッセージ ID は実装時に `PlayerMsgId` と `player.properties` へ追加する。設計上の表示内容は以下を正とする。

| 場面 | 表示 |
|---|---|
| リーダー以外が受付 | ボス挑戦はパーティーリーダーだけが開始できます |
| 参加条件不備 | ボス挑戦を開始できません: %s |
| ハブ集合待ち | 集合待ち: %s/%s |
| フィールド生成中 | ボスフィールドを準備しています |
| フィールド生成失敗 | ボスフィールドの準備に失敗しました |
| 途中参加拒否 | 進行中のボス挑戦には途中参加できません |
| 再入場拒否 | このボス挑戦には再入場できません |
| パーティー解散拒否 | ボス挑戦中はパーティーを解散できません |
| パーティー離脱拒否 | ボス挑戦中はパーティーを離脱できません |
| 管理者強制終了 | 管理者によりボス挑戦が終了されました |

## 4. 運用コマンド

- `/boss instances`: 稼働中のボス挑戦一覧を表示する。
- `/boss stop <partyId>`: 指定パーティーのボス挑戦を `ADMIN_STOP` で終了する。

強制開始コマンドと残存ワールド掃除コマンドは用意しない。

## 5. 起動時掃除

- 掃除対象は `WorldMasterData.instanceRootPath` 配下に限定する。
- `WorldMasterData` に定義されていない任意パスは削除しない。
- 掃除処理はプラグインロード時に実行し、削除失敗時はログだけを残す。
- 管理者コマンドでの手動削除は不要とする。

## 6. plugin version

本設計書作成では plugin deliverable を変更しないため、`10_plugin/AstralRecord/pom.xml` の版番号更新は不要とする。実装時に plugin source / resources を変更する場合は、finalize 時に `$astralrecord-plugin-version` の対象になる。
