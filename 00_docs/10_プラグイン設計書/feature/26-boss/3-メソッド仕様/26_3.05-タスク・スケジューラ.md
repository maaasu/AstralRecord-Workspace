# 26_3.05-タスク・スケジューラ

## ボス挑戦地点表示タスク

クラス名: `BossEntryParticleTask`
物理名: `run`

1. ロード済みボスマスターの `challenge.entryLocation` を列挙する。
2. 対象 `WorldMasterData` に対応する Bukkit ワールドがロード済みの場合だけ処理する。
3. `entryRadiusMeters` の円をパーティクルで表示する。
4. 未ロードワールド、設定不備、対象外カテゴリはスキップする。

## ボスハブ待機表示タスク

クラス名: `BossHubWaitingDisplayTask`
物理名: `run`

1. `WAITING_IN_HUB` または `READY_TO_ENTER` の挑戦インスタンスを列挙する。
2. 参加予定者のうち、待機フラグを持ち、ハブワールドにいるオンラインプレイヤー数を数える。
3. ハブワールドにいる待機中プレイヤーへ `集合待ち: <集合済み>/<参加予定者数>` をタイトルバー表示する。
4. `fieldInstance.state = READY` かつ集合済み人数が参加予定者数に達した場合、[[26_3.02-サービス]].ボスフィールド入場判定 を呼び出す。

## ボス戦進行タスク

クラス名: `BossChallengeTickTask`
物理名: `run`

1. `IN_PROGRESS` の挑戦インスタンスを列挙する。
2. 残り時間を `challenge.timeLimitSeconds - (現在時刻 - startedAt)` で算出する。
3. 残り時間が `0` 以下の場合、[[26_3.02-サービス]].ボス挑戦終了 を `TIME_LIMIT` で呼び出す。
4. ボス HP、残りデスカウント、現在フェーズを表示対象へ反映する。
5. ボスフィールド内のアクティブ参加者が 0 人の場合、[[26_3.02-サービス]].ボス挑戦終了 を `NO_PARTICIPANTS` で呼び出す。

## 残存ボスフィールド掃除タスク

クラス名: `BossFieldStartupCleanupTask`
物理名: `run`

プラグインロード時に、前回クラッシュ等で残ったコピー先ワールドを削除する。

1. `WorldMasterData` をロードした後に実行する。
2. `worldType = BOSS_FIELD` かつ `instanceEnabled = true` の `instanceRootPath` を列挙する。
3. 削除対象は `WorldMasterData.instanceRootPath` 配下に限定する。
4. Bukkit ワールドとしてロード済みの場合はアンロードを試みる。
5. フォルダ削除に失敗した場合はログを残す。

管理者コマンドによる残存ワールド掃除は用意しない。

## フィールド準備スケジューリング

クラス名: `BossFieldInstanceService`
物理名: `createFieldAsync`

1. パス検証、ディレクトリ作成、テンプレートコピーは Bukkit 非同期タスクで行う。
2. `Bukkit.createWorld` と gamerule 適用はメインスレッドで行い、ワールド tick 中なら次の安全な scheduler task へ延期する。複数挑戦のロードは直列化し、各ロード間を最低 1 tick 空ける。
3. プレイヤー地点とボス地点の一意なチャンクだけを Paper の非緊急 chunk Future で準備し、各 Future 完了直後に ticket を取得する。
4. 全 Future 完了までハブ待機を継続し、`join` / `get` や Watchdog 時間延長で待たない。
5. 準備済みチャンクはボス生成または失敗時まで plugin chunk ticket で保持し、終了経路で必ず解除する。
