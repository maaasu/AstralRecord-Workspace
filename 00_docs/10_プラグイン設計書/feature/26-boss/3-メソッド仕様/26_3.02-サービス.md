# 26_3.02-サービス

## ボス挑戦受付

クラス名: `BossChallengeService`
物理名: `acceptChallenge`

指定プレイヤーのボス挑戦を受付し、参加予定者と待機フラグを作成する。

1. `bossId` から [[12_1.00-モデル定義]].Mob テンプレートを取得し、`category = BOSS` であることを確認する。
2. [[26_1.00-モデル定義]].ボス挑戦設定 が存在することを確認する。
3. `challenge.entryLocation` と `entryRadiusMeters` でプレイヤーの受付位置を確認する。
4. パーティー所属がある場合は受付者がリーダーであることを確認し、受付時点のメンバーを参加予定者として固定する。
5. パーティー所属がない場合は本人 1 人を参加予定者として固定し、ソロ用 `partyId` を発行する。
6. 同一パーティーが既にボス挑戦中または待機中でないことを確認する。
7. `boss.hubWorldId` からハブ `WorldMasterData` を解決し、対応する Bukkit ワールドをロードできることを確認する。ロードできない場合は挑戦を受理しない。
8. `BossChallengeInstance` を `ACCEPTED` として作成し、参加予定者へ `BossWaitingFlag` を作成する。
9. 対象プレイヤーをハブワールドへ転送し、状態を `WAITING_IN_HUB` にする。
10. ソロの場合、[[26_3.02-サービス]].ボスフィールド生成開始 を呼び出す。パーティーの場合も受付後に生成開始してよいが、全員集合までは入場させない。

## ボスフィールド生成開始

クラス名: `BossFieldInstanceService`
物理名: `startCreateField`

ボスマスターの `battleWorldId` から一時ワールドの生成を開始する。

1. `challenge.battleWorldId` から `WorldMasterData` を取得する。
2. `worldType = BOSS_FIELD` かつ `instanceEnabled = true` であることを確認する。
3. コピー元として `baseWorldPath`、コピー先ルートとして `instanceRootPath` を解決する。
4. インスタンス名を `boss_<bossId>_<partyId>_<timestamp>` 形式で生成する。
5. `BossFieldInstance` を `COPYING` として作成する。
6. 可能な限り非同期でテンプレートワールドをコピーする。
7. コピー完了後、メインスレッドで Bukkit ワールドをロードし、`READY` にする。
8. 生成失敗時は [[26_3.02-サービス]].ボス挑戦終了 を `FIELD_CREATE_FAILED` で呼び出す。

## ボスフィールド入場判定

クラス名: `BossChallengeService`
物理名: `tryEnterField`

ボスフィールド作成完了と参加予定者の集合状態を確認し、入場できる場合に転送する。

1. 挑戦状態が `WAITING_IN_HUB` または `READY_TO_ENTER` であることを確認する。
2. `fieldInstance.state = READY` であることを確認する。
3. 参加予定者のうち、対象ボスの待機フラグを持ち、`boss.hubWorldId` のハブワールドにいるオンラインプレイヤー数を数える。
4. 集合済み人数が参加予定者数未満の場合は何もしない。
5. 集合済み人数が参加予定者数に達した場合、参加予定者全員を `challenge.playerSpawnLocation` へ転送する。
6. 転送成功した参加者を `participants` に登録し、待機フラグを解除する。
7. 必須転送に失敗した場合、[[26_3.02-サービス]].ボス挑戦終了 を `TRANSFER_FAILED` で呼び出す。
8. 転送成功後、[[26_3.02-サービス]].ボス戦開始 を呼び出す。

## ボス戦開始

クラス名: `BossCombatService`
物理名: `startCombat`

ボスを生成し、制限時間カウントを開始する。

1. 参加者数を、ボスフィールドへ転送された `participants` の件数として固定する。
2. `baseStats.MAX_HEALTH` と `baseStats.ATTACK` に [[26_1.00-モデル定義]].ボススケーリング設定 を適用する。
3. `challenge.bossSpawnLocation` にボス Mob をスポーンし、`bossMobInstanceId` を保持する。
4. ボスフィールドを `IN_USE` にする。
5. 挑戦状態を `IN_PROGRESS` にし、`startedAt` を現在時刻にする。
6. 制限時間、デスカウント、ボス HP、現在フェーズの表示を開始する。

## ボスダメージ集計

クラス名: `BossDamageStatisticsService`
物理名: `recordDamage`

`DamageService` で対象ボスへ有効ダメージが反映された後に、参加者別ダメージを加算する。

1. 対象 Mob が `IN_PROGRESS` の `BossChallengeInstance.bossMobInstanceId` と一致するか確認する。
2. 攻撃者が参加者であり、同じボスフィールドワールドにいることを確認する。
3. HP またはシールドへ実際に反映されたダメージを取得する。
4. 無敵状態などで最終ダメージが `0` の場合は加算しない。
5. オーバーキル分は残り HP を上限に丸めた値だけ加算する。
6. `participants[playerId].damageDealt` と `statistics.playerDamages[playerId]` に加算し、`totalDamage` を更新する。

## ボス挑戦終了

クラス名: `BossChallengeService`
物理名: `endChallenge`

成功・失敗を問わず、ボス挑戦を終了処理へ進める。

1. 既に `ENDING` または `ENDED` の場合は重複終了を防ぐ。
2. `endReason` と `endedAt` を記録し、状態を `ENDING` にする。
3. 終了理由が `DEFEATED` の場合、通常 Mob と同じドロップ処理を維持し、状態を `RESULT_WAITING` にして 15 秒間フィールドを保持する。
4. 終了理由が `DEFEATED` 以外の場合、報酬処理へ進めない。
5. [[26_3.02-サービス]].ボス結果表示 を呼び出す。
6. `DEFEATED` の場合は、結果表示中に参加者を退場させず、通常ドロップ演出・付与が完了するための待機時間として扱う。
7. 15 秒経過後、または `DEFEATED` 以外の終了時に、参加者を退場先へ転送する。
8. [[26_3.02-サービス]].ボスフィールド破棄 を呼び出す。
9. 待機フラグとキャッシュを削除し、状態を `ENDED` にする。

## ボス報酬付与

クラス名: `BossRewardService`
物理名: `grantRewards`

討伐成功時に、ボスマスターの `drops` に基づいて参加者へ報酬を付与する。

1. 終了理由が `DEFEATED` であることを確認する。
2. 報酬対象者を、ボスフィールドに参加しており、オンラインで、討伐時に対象ボスと同じワールドにいる参加者に限定する。
3. `drops.items`、`drops.lootTable`、`drops.exp`、`drops.money` は通常 Mob と同じ処理を使用する。
4. 報酬条件は参加プレイヤーごとに変更しない。
5. 与ダメージ量、参加時間、職業、役割による報酬差は付けない。

## ボス結果表示

クラス名: `BossResultViewService`
物理名: `showResult`

ボス挑戦の結果を参加者へ表示する。

1. 結果表示対象を、ボスフィールドに参加していたオンラインプレイヤーに限定する。
2. ログアウト済みプレイヤーには表示しない。
3. 討伐成功時は、ボス名、退場までの残り秒数、パーティー合計ダメージ、プレイヤー別与ダメージ順位を TextDisplay で 15 秒間表示する。
4. 失敗時は、失敗理由、経過時間、パーティー合計ダメージ、プレイヤー別与ダメージ、死亡回数を表示する。

## ボスフィールド破棄

クラス名: `BossFieldInstanceService`
物理名: `destroyField`

挑戦終了後に一時ワールドを破棄する。

1. 参加プレイヤー退場を完了させる。
2. ボス Mob と残存 Mob を破棄する。
3. Bukkit ワールドをアンロードする。
4. コピー先フォルダを削除する。
5. 破棄失敗時はログを残し、次回起動時の掃除対象に回す。
