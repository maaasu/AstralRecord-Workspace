# ボス機能 理想サービス補足

## フィールド設定検証

クラス名: `BossChallengeService`
物理名: `acceptChallenge`

1. `worldService.getById(config.fieldWorldId())` でフィールド定義を取得する。
2. 未取得の場合は `PlayerMsgId.P_6507` を送信して終了する。
3. `fieldData.worldType() != WorldType.BOSS_FIELD` または `!fieldData.instanceEnabled()` の場合は受付しない。

    | 項目 | 内容 |
    |---|---|
    | ID | `PlayerMsgId.P_6522` |
    | テンプレート | `ボスフィールド設定が不正です。BOSS_FIELD かつ instanceEnabled=true のワールドを指定してください: {0}` |
    | 出力条件 | フィールド定義の種別または instance 設定が不正 |
    | 引数 | `config.fieldWorldId()` |

    | 項目 | 内容 |
    |---|---|
    | ID | `LogId.W_6502` |
    | レベル | WARN |
    | テンプレート | `Boss field WorldMasterData is invalid: worldId=%s, worldType=%s, instanceEnabled=%s` |
    | 出力条件 | フィールド定義の種別または instance 設定が不正 |
    | 引数 | worldId, worldType, instanceEnabled |

## フィールド作成

クラス名: `BossFieldInstanceService`
物理名: `createField`

1. `instanceRootPath` を解決し、存在しなければ作成する。
2. `baseWorldPath` を解決する。
3. `baseWorldPath` がディレクトリでない、または `level.dat` がない場合は `IOException` を送出する。
4. `uid.dat` と `session.lock` を除外してテンプレート world をコピーする。
5. `Bukkit.createWorld` でロードする。
6. ロード成功時は `WorldService.applyRpgGameRules` を適用し、`BossFieldInstance` を返す。

## フィールド入場

クラス名: `BossChallengeService`
物理名: `startField`

1. 挑戦状態が `PREPARING` でなければ何もしない。
2. オンライン参加者を取得する。
3. オンライン参加者が空なら `NO_PARTICIPANTS` で終了する。
4. 各参加者へ `worldService.teleportPlayerAsync` を実行し、Future を保持する。
5. `CompletableFuture.allOf` で全員分の完了を待つ。
6. 完了後は Bukkit メインスレッドで `finishFieldStartAfterTransfers` へ委譲する。

## 転送完了後戦闘開始

クラス名: `BossChallengeService`
物理名: `finishFieldStartAfterTransfers`

1. 挑戦状態が `PREPARING` でなければ何もしない。
2. Future に例外がある、または 1 件でも `false` の場合は `TRANSFER_FAILED` で終了する。

    | 項目 | 内容 |
    |---|---|
    | ID | `PlayerMsgId.P_6521` |
    | テンプレート | `{0} のフィールド転送に失敗したため挑戦を終了しました。` |
    | 出力条件 | 参加者のフィールド転送に失敗 |
    | 引数 | ボス表示名 |

3. 転送成功時はボスを `bossSpawnLocation` へ spawn する。
4. spawn 失敗時は `BOSS_SPAWN_FAILED` で終了する。
5. spawn 成功時は参加者数補正を適用して `IN_PROGRESS` に遷移する。

## 参加者数補正

クラス名: `BossChallengeService`
物理名: `applyParticipantScaling`

1. `scaling.enabled=false` の場合は何もしない。
2. 参加者数から追加人数を計算する。
3. HP 倍率を `MobInstance.currentHealth` に乗算する。
4. 攻撃倍率を `MobInstance.outgoingDamageMultiplier` に設定する。

## Mob 攻撃ダメージ計算

クラス名: `MobCombatService`
物理名: `computeDamage`

1. `MobTemplate` の `ATTACK` を取得する。
2. `MobInstance.outgoingDamageMultiplier` を乗算する。
3. 戦闘スタイルに応じて `STRENGTH` / `DEXTERITY` / `INTELLIGENCE` スケーリングを適用する。
4. プレイヤー防御を差し引き、最低 1.0 ダメージに丸める。

## 報酬確定

クラス名: `BossRewardService`
物理名: `grantRewards`

将来追加するサービス。通常 Mob 死亡処理をそのまま呼ぶのではなく、以下を満たす。

1. `participantIds` と討伐時同一 world 条件で報酬対象を固定する。
2. 対象ごとにドロップ抽選、経験値、通貨、図鑑、クエスト進行を行う。
3. アイテム演出は付与と分離し、演出失敗で報酬消失しない。
4. 非参加者、ログアウト済み、別 world、観戦者は対象外にする。
