# ボス機能 理想仕様の残課題

## 1. ボス専用報酬サービス

- `BossRewardService` を追加し、通常 Mob の受取人決定を使わず、挑戦参加者だけへ報酬を配る。
- `MobDropPresentationService` の演出失敗で報酬が消えないよう、付与確定と演出を分離する。
- 経験値、通貨、アイテム、図鑑、クエスト進行の再利用境界を決める。

## 2. 死亡/復帰仕様

- `deathLimit`、`reviveDelaySeconds`、復帰時 HP/MP/EN/Shield 回復量を `challenge` スキーマへ追加するか決める。
- 復帰待機 UI、観戦状態、復帰地点、全滅判定の詳細を決める。
- 既存 `PlayerDeathService` とボス挑戦内死亡の責務分離を決める。

## 3. UI 表示

- 戦闘中 UI は BossBar、Title、ActionBar、TextDisplay のどれを正本にするか決める。
- 残り時間、ボス HP、死亡回数、フェーズ、復帰待機を同時表示する時の優先順位を決める。

## 4. ボス固有ギミック

- ボス固有ロジックを `feature/boss` 配下の Java クラスで持つか、mob / skill filebase 定義に寄せるか決める。
- フェーズ閾値、スキルローテーション、ギミック状態の共通モデルを追加するか決める。

## 5. 起動時掃除

- `BossFieldStartupCleanupTask` を追加する。
- dry-run と execute の運用導線を `/boss cleanup` に寄せるか、起動時自動掃除だけにするか決める。

## 6. 永続戦績

- 討伐回数、最短討伐時間、個人最大ダメージ、パーティー構成などを DB に保存するか決める。
- 保存する場合は API/DB 設計書を追加する。
