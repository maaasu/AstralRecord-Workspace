# 26_2.00-ユースケース

## UC-01 ボス挑戦受付

### 目的

プレイヤーがボス挑戦地点でスニークし、ソロまたは所属パーティー単位のボス挑戦を受付する。

### 事前条件

- 対象ボスマスターが `MobCategory.BOSS` である。
- ボスマスターに [[26_1.00-モデル定義]].ボス挑戦設定 が存在する。
- プレイヤーが `challenge.entryLocation` の `entryRadiusMeters` 内にいる。

### 基本フロー

1. プレイヤーがボス挑戦座標の円内でスニークする。
2. ボス挑戦受付が、プレイヤーのパーティー所属を確認する。
3. パーティー所属なしの場合は、本人 1 人を参加予定者として固定する。
4. パーティー所属中の場合は、受付者がパーティーリーダーであることを確認し、受付時点のパーティーメンバー全員を参加予定者として固定する。
5. 参加条件を満たす場合、参加予定者へ待機フラグを作成する。
6. 対象プレイヤーを `boss.hubWorldId` のハブワールドへ転送する。

### 例外フロー

| 条件 | 挙動 |
|---|---|
| 円外でスニークした | ボス挑戦受付として扱わない |
| バニラコマンド等でハブへ直接移動した | 待機フラグがないためボス待機中とは扱わない |
| パーティー所属中でリーダーではない | 挑戦を開始せず、リーダーのみ受付可能である旨を表示する |
| 対象 WorldMasterData が不正 | 挑戦を開始せず、設定不備として表示する |

## UC-02 ソロ挑戦開始

### 基本フロー

1. ソロ挑戦の参加予定者数を `1` として固定する。
2. プレイヤーをハブワールドへ転送する。
3. ハブ転送後、ボスフィールドインスタンス作成を開始する。
4. インスタンス作成完了後、自動でボスフィールドへ転送する。
5. ボスをスポーンし、挑戦状態を `IN_PROGRESS` にする。

## UC-03 パーティー挑戦開始

### 基本フロー

1. パーティーリーダーがボス挑戦を受付する。
2. 受付時点のパーティーメンバーを参加予定者として固定する。
3. 各メンバーはボス挑戦座標からハブワールドへ移動した時点で待機フラグを持つ。
4. ハブワールドで待機中のプレイヤーには、タイトルバーで集合待ちを表示する。
5. ボスフィールドインスタンス作成完了時に、オンライン、同一パーティー所属、ハブ滞在を満たす参加予定者を最終参加者として確定する。
6. 待機中にログアウト、パーティー離脱、キック、またはハブ外へ移動したメンバーは最終参加者から除外し、途中参加と報酬受領を許可しない。
7. 最終参加人数が `partyMin` 以上なら全員をボスフィールドへ転送し、実参加人数でボスを補正する。`partyMin` 未満なら挑戦を終了する。
6. ボスをスポーンし、挑戦状態を `IN_PROGRESS` にする。

### 例外フロー

| 条件 | 挙動 |
|---|---|
| ボスフィールド作成が先に完了した | 参加予定者全員が集合するまで自動転送しない |
| 参加予定者がログアウトまたはパーティー離脱した | 最終参加者から除外し、残りメンバーの人数条件を確認する |
| 最終参加人数が `partyMin` 未満になった | ボスを生成せず挑戦を終了する |

## UC-04 途中参加・再入場拒否

- 途中参加は許可しない。
- 再入場は許可しない。
- ボス挑戦開始後にパーティーへ参加したプレイヤーは、待機フラグを持たず、ボスフィールドにも転送されない。
- ボス挑戦中にパーティー外のプレイヤーが同じパーティーへ参加しても、そのプレイヤーは報酬対象外とする。
- ログアウトした参加者はボスフィールドから離脱した扱いとなり、再入場できない。

## UC-05 挑戦中の死亡

### 基本フロー

1. 参加者がボス挑戦中に死亡する。
2. ボス挑戦死亡制御が通常死亡と区別して処理する。
3. `currentDeathCount` を加算し、参加者個人の死亡回数を加算する。
4. `currentDeathCount >= challenge.deathLimit` の場合、デスカウント超過として挑戦失敗にする。
5. 上限未満の場合、5 秒間の復帰待機後に HP / MP / EN / Shield を全回復し、`playerSpawnLocation` へ復帰させる。
6. 復帰待機中に他の参加者がボスを討伐した場合も、オンラインで挑戦から離脱していなければ報酬対象とする。復帰処理は終了処理へ切り替え、結果表示後にハブへ戻す。

## UC-06 討伐成功

### 基本フロー

1. 対象ボス Mob の HP が 0 以下になる。
2. 終了理由を `DEFEATED` として確定する。
3. ボス名、討伐時間、残りデスカウント、合計与ダメージ、プレイヤー別与ダメージ、死亡回数を表示する。
4. 報酬対象者を確定する。
5. ボスマスターの `drops` を使い、通常 Mob と同じドロップ抽選、経験値付与、所持品付与を実行する。
6. ボス討伐演出を再生する。
7. 参加者を 15 秒間ボスフィールドに留め、TextDisplay でパーティーメンバーのダメージ統計を確認できるようにする。
8. 待機時間経過後に参加者を退場させ、ボスフィールドインスタンスを破棄する。

### 報酬対象

- ボス報酬は、ボス挑戦インスタンスに参加しているパーティーメンバーだけを対象とする。
- パーティー外プレイヤーには報酬を付与しない。
- 討伐時に対象 Mob と同じワールドにいない参加者は報酬対象外とする。
- ログアウト済みプレイヤーには結果表示と報酬付与を行わない。
- 復帰待機中の死亡参加者は、オンラインかつ同じボスフィールドにいる限り報酬対象とする。
- 与ダメージ量、参加時間、職業、役割による報酬差は付けない。

## UC-07 挑戦失敗

### 失敗理由

- 時間切れ。
- デスカウント超過。
- 全参加者ログアウト。
- 管理者強制終了。
- フィールド生成失敗。
- 必須転送失敗。

### 基本フロー

1. 終了理由を失敗理由として確定する。
2. 失敗理由、経過時間、合計与ダメージ、プレイヤー別与ダメージ、死亡回数を表示する。
3. ボスを討伐していないため、ドロップ、経験値、お金は発生させない。
4. 報酬処理へ進めず、退場とインスタンス破棄へ進む。

## UC-08 管理者コマンド

| コマンド | 用途 |
|---|---|
| `/boss instances` | 現在稼働中のボス挑戦インスタンス一覧を表示する |
| `/boss stop <partyId>` | 指定パーティーのボス挑戦を強制終了する |

`/boss instances` では、`partyId`、`bossId`、状態、参加者数、ワールド名、開始時刻、残り時間を表示する。

`/boss stop <partyId>` は、対象パーティーがボス挑戦中の場合だけ成功し、終了理由を `ADMIN_STOP` として記録する。
