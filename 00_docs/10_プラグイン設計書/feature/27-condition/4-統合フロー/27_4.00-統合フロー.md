# 27_4.00-統合フロー

## 1. スキル命中から状態異常付与まで

1. `WeaponAttackSkillExecutor` または個別 skill executor が命中対象を `AstEntity` として解決する。
2. skill params に `conditions[]` があれば、命中後に `ConditionApplyRequest` を作成する。
3. `ConditionService.applyCondition` が対象ポリシー、確率、耐性、重複規則を処理する。
4. 付与成功時、`ConditionDisplayService.showApplied` が表示を開始する。
5. skill の直撃ダメージとは別に、DoT は `ConditionTickTask` の周期処理で発生する。

想定 skill params:

```yaml
params:
  attackType: MAGIC
  damageType: MAGIC
  damageElement: FIRE
  conditions:
    - type: BURNING
      chance: 35
      durationTicks: 100
      basePower: 2.0
      powerCoefficient: 0.25
      tickIntervalTicks: 20
```

## 2. DoT ダメージ適用

1. `ConditionTickTask` が active condition を走査する。
2. `ConditionTickService.tickCondition` が対象と付与元を復元する。
3. `snapshotPower` と stack から tick damage を確定する。
4. `DamageService.applyConditionDamage` へ以下を渡す。
   - source
   - target
   - baseDamage
   - `DamageType`
   - `DamageElement`
   - `ConditionType`
5. `DamageService` は `ConditionService.isDamageImmune` を確認する。
6. 無敵でなければ `DamageCalculator` で防御・属性補正・被ダメージ倍率を適用する。
7. HP/Shield、threat、boss damage statistics、death 処理は通常ダメージと同じ経路を使う。
8. `ConditionDisplayService.pulse` が DoT 発生時の粒子を表示する。

## 3. 属性ダメージ計算順序

`DamageCalculator.calculate` の適用順序は以下とする。

1. `DamageScaling` により基礎ダメージを解決する。
2. 会心・超会心を判定する。
3. `DamageType` に応じて物理防御 / 魔法防御 / 防御無視を適用する。
4. `DamageElement` に応じて属性耐性・弱点倍率を適用する。
5. `ConditionService.damageTakenMultiplier(victim)` を適用する。
6. `FINAL_DAMAGE_RATE` / `FINAL_DAMAGE_MULTIPLIER` を適用する。
7. 0 以上にクランプする。

初期実装で属性耐性データが未整備の場合、全 `DamageElement` の倍率は 1.0 とする。
それでも `DamageElement` を context に持たせ、表示・ログ・将来の耐性拡張に使える状態にする。

## 4. 行動制限の統合

1. 通常攻撃開始時、`ConditionService.canAttack(attacker)` を確認する。
2. スキル詠唱開始時、`ConditionService.canCastSkill(caster)` を確認する。
3. プレイヤー移動イベントで `ConditionService.canMove(player)` を確認する。
4. Mob AI tick で `ConditionService.canMove(mob)` / `canAttack(mob)` / `canCastSkill(mob)` を確認する。
5. false の場合は該当処理を中断し、表示だけ維持する。

## 5. 表示更新

1. `ConditionDisplayTask` が active condition を持つ対象を取得する。
2. 対象の近くに viewer がいる場合だけ recurring particle を表示する。
3. TextDisplay は頭上に追従し、残り時間とスタック数を更新する。
4. `BURNING` は plugin fire ticks を維持する。
5. `FROZEN` / `INVULNERABLE` は BlockDisplay を追従更新する。

## 6. 解除と掃除

1. duration 終了、死亡、despawn、logout、plugin disable のいずれかで `ConditionService.clearAll` または `removeCondition` を呼ぶ。
2. service は active condition を削除する。
3. display service は表示 entity と fire ticks を解除する。
4. cleanup task は orphan display が残っていないか定期確認する。
