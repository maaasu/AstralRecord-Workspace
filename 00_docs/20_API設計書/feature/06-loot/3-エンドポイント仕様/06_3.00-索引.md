## 1. ルートプール一覧取得

HTTPメソッド: `GET`
パス: `/api/loot/pool`
コントローラ: `LootController`
アクション物理名: `ListPools`

責務:

MasterDataDB 上の有効 LootPool を返す。

リクエスト:

| 種別 | 名前 | 型 | 必須 | 説明 |
|---|---|---|---|---|
| Header | `X-Api-Key` | string | ✓ | API キー |

レスポンス:

| ステータス | 内容 | ボディ |
|---|---|---|
| 200 OK | 取得成功 | [[06_1.00-モデル定義]].ルートプール の配列 |
| 401 Unauthorized | API キー未指定/無効 | なし |

---

## 2. ルートプール詳細取得

HTTPメソッド: `GET`
パス: `/api/loot/pool/{poolId}`
コントローラ: `LootController`
アクション物理名: `GetPool`

リクエスト:

| 種別 | 名前 | 型 | 必須 | 説明 |
|---|---|---|---|---|
| Header | `X-Api-Key` | string | ✓ | API キー |
| Path | `poolId` | string | ✓ | プール ID |

レスポンス:

| ステータス | 内容 | ボディ |
|---|---|---|
| 200 OK | 取得成功 | [[06_1.00-モデル定義]].ルートプール |
| 401 Unauthorized | API キー未指定/無効 | なし |
| 404 Not Found | 未定義 poolId | なし |

処理内容:

1. 認証パイプラインで `X-Api-Key` を検証する
2. MasterDataDB から `master_type = loot.pool` かつ `master_id = poolId` で検索する（取得失敗時は 404）
3. 200 で詳細を返す
