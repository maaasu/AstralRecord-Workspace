# リリースノート エンドポイント仕様

認証: API全体の `X-Api-Key` 認証を使用する。

### リリースノート公開登録

HTTPメソッド: `POST`
パス: `/api/release-notes/publish`
コントローラ: `ReleaseNoteController`
アクション物理名: `Publish`

リクエスト:

| 種別 | 名前 | 型 | 必須 | 説明 |
|---|---|---|---|---|
| Header | `X-Api-Key` | string | ✓ | APIキー |
| Body | `ReleaseNotePublishRequest` | object | ✓ | [[28_1.00-モデル定義]].リリースノート公開リクエスト |

レスポンス:

| ステータス | 内容 | ボディ |
|---|---|---|
| 200 OK | 登録成功または冪等再同期 | [[28_1.00-モデル定義]].リリースノート公開レスポンス |
| 400 Bad Request | slug、URL、ハッシュまたは日時が不正 | `{ error }` |
| 401 Unauthorized | APIキー未指定または無効 | なし |

処理内容:

1. 公開URL、slug、ソースパス、SHA-256、公開日時を検証する。
2. リポジトリでslugをキーにリリースノートをupsertする。
3. Discord通知対象で未登録のチャネルならOutboxをPendingで作成する。
4. 登録結果を返す。

### Discord通知再試行登録

HTTPメソッド: `POST`
パス: `/api/release-notes/{slug}/retry-notification`
コントローラ: `ReleaseNoteController`
アクション物理名: `RetryNotification`

リクエスト:

| 種別 | 名前 | 型 | 必須 | 説明 |
|---|---|---|---|---|
| Header | `X-Api-Key` | string | ✓ | APIキー |
| Path | `slug` | string | ✓ | 対象リリースノート |

レスポンス:

| ステータス | 内容 | ボディ |
|---|---|---|
| 200 OK | 再試行登録成功 | [[28_1.00-モデル定義]].Discord通知再試行レスポンス |
| 400 Bad Request | slug不正 | `{ error }` |
| 401 Unauthorized | APIキー未指定または無効 | なし |
| 404 Not Found | 未公開または未登録 | なし |

処理内容:

1. slug形式を検証する。
2. 公開済みリリースノートの対象OutboxをPendingへ戻す。
3. 次回送信日時を現在時刻に設定して結果を返す。
