# リリースノート 例外・ログ・運用

## Web

| レベル | テンプレート | 出力条件 |
|---|---|---|
| Error | `Release note could not be loaded: {FilePath}` | Markdownのfront matterまたはファイル読み込みが不正 |
| Warning | `Release note synchronization failed for {Slug}. StatusCode={StatusCode}, Response={Response}` | API登録が失敗 |

## API / Discord

| レベル | テンプレート | 出力条件 |
|---|---|---|
| Error | `Discord release notification token file could not be read: {TokenPath}` | token.txtを読めない |
| Warning | `Discord release notification failed. StatusCode={StatusCode}, Retryable={Retryable}` | Discord APIが失敗 |
| Error | `Release notification worker failed.` | Outbox処理で予期しない例外 |

運用値:

- APIのトークンファイル: API配置先の `token.txt`。Gitへ追加しない。
- Discord送信先: `1261962785026343043`。
- APIワーカーのポーリング間隔: 10秒。
- Discord APIの429はレスポンスHeaderと本文 `retry_after` の長い方を読み、指数バックオフとの最大値で再試行する。JSONを解析できない場合は指数バックオフへフォールバックする。
- Discord APIの401/403とtoken.txtの欠落・空ファイルは恒久的な失敗として再試行を停止する。設定修正後にretry endpointを手動実行する。
- Create Message APIにはOutbox IDごとの安定nonce（最大25文字）と `enforce_nonce=true` を指定する。これはDiscord側のnonce保持期間内の重複を抑止するが、ネットワーク障害時の配送保証はat-least-onceである。根拠: [Discord Message Resource - Create Message](https://docs.discord.com/developers/resources/message)
- 初回デプロイ前にAPI配置先へ `token.txt` を安全に配置し、空でないことを `10-release-management-deploy.bat` が検証する。デプロイバックアップにはtoken.txtを複製しない。トークン値はログ・Gitへ出さない。
- 通知を手動で再試行する場合は `POST /api/release-notes/{slug}/retry-notification` をAPIキー付きで呼び出す。
