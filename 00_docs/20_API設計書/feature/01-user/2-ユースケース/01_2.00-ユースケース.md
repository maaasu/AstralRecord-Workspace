# 01_2.00-ユースケース

API `user` 機能が想定する呼び出しシナリオを列挙する。  
プラグイン側のフロー詳細は [[01_4.00-統合フロー]]（プラグイン設計書）を参照する。

## 1. ログイン前ユーザ存在確認

呼び出し元: プラグイン [[01_3.02-サービス]].ログイン前検証

- 使用エンドポイント: [[01_3.01-取得系]].ユーザ取得
- 期待結果:
  - 200: 登録済み
  - 404: 未登録（プラグイン側で新規登録フローへ）

## 2. 新規ユーザ登録

呼び出し元: プラグイン [[01_3.02-サービス]].新規ユーザ登録

- 使用エンドポイント: [[01_3.02-登録系]].ユーザ登録
- 期待結果:
  - 201: 登録成功
  - 409: 既に登録済み（プラグイン側で WARN ログ）

## 3. 最終参加情報更新

呼び出し元: プラグイン [[01_3.02-サービス]].ログイン前検証 の最終参加情報更新

- 使用エンドポイント: [[01_3.03-更新系]].ユーザ更新
- 更新項目: `lastJoinDate`, `globalIp`, `accountId`, `updatedBy`
- 期待結果:
  - 200: 更新成功

## 4. 権限更新

呼び出し元: プラグイン [[01_3.02-サービス]].権限更新

- 使用エンドポイント: [[01_3.03-更新系]].ユーザ更新
- 更新項目: `permission`, `updatedBy`
- 期待結果:
  - 200: 更新成功
  - プラグイン側はその後再取得（[[01_3.01-取得系]].ユーザ取得）で最新値を取得する

## 5. BAN / Kick 制御（運用コマンド）

呼び出し元: プラグイン `BanCommand`（`/ban`）

- 使用エンドポイント: [[01_3.03-更新系]].ユーザ更新
- 対象ユーザー取得: [[01_3.01-取得系]].MCID指定ユーザ取得
- 更新項目: `banIndefinite`, `banDate`, `updatedBy`
- `banIndefinite = true` の場合は `banDate = null`、有期限 BAN の場合は指定日数後の日時を `banDate` に設定する
- 期待結果:
  - 200: BAN情報更新成功
  - 404: 対象ユーザー未登録または論理削除済み

## 6. 接続前同一IPユーザー照合

呼び出し元: プラグイン `UserService.onAsyncPreLogin`

- 使用エンドポイント: [[01_3.01-取得系]].同一グローバルIPの別ユーザー有無取得
- 入力: 接続元 `globalIp` と参加者 UUID
- 期待結果: 200 の boolean が `true` の場合だけ参加完了後の監視案内を表示する
- API一時障害: プラグインはログインを継続し、同一IP案内は表示しない
