# 01_3.03-更新系

## 1. 更新系エンドポイント仕様

### ユーザ更新

HTTPメソッド: `PUT`
パス: `/api/user/{uuid}`
コントローラ: `UserController`
アクション物理名: `UpdateUser`

責務:

[[01_1.00-モデル定義]].ユーザ更新リクエスト で指定された項目のみ更新する。
`null` 指定は「更新しない」を意味する。論理削除済みは更新対象外。

リクエスト:

| 種別 | 名前 | 型 | 必須 | 説明 |
|---|---|---|---|---|
| Header | `X-Api-Key` | string | ✓ | API キー |
| Header | `Content-Type` | string | ✓ | `application/json` |
| Path | `uuid` | GUID | ✓ | 更新対象UUID |
| Body | (全体) | [[01_1.00-モデル定義]].ユーザ更新リクエスト | ✓ | 更新内容 |

レスポンス:

| ステータス | 内容 | ボディ |
|---|---|---|
| 200 OK | 更新成功 | [[01_1.00-モデル定義]].ユーザレスポンス |
| 400 Bad Request | バリデーション失敗（`updatedBy` 欠落等） | エラーオブジェクト |
| 401 Unauthorized | API キー未指定または無効 | なし |
| 404 Not Found | 未登録または論理削除済み | なし |

処理内容:

1. 認証パイプラインで `X-Api-Key` を検証する

    | 項目 | 内容 |
    |---|---|
    | 検証主体 | `ApiKeyAuthenticationHandler` |
    | 失敗時 | 401 を返し、本処理は実行しない |

2. リクエスト Body のバリデーションを行う

    | 項目 | 内容 |
    |---|---|
    | 必須項目 | `updatedBy` |
    | `permission` | 指定時は `0`（プレイヤー）、`5`（寄付者）、`99`（管理者）のみ |
    | 失敗時 | 400 と共にバリデーションエラー一覧を返す |

3. 対象ユーザを取得する

    | 項目 | 内容 |
    |---|---|
    | 検索キー | `uuid` |
    | 取得対象 | `dbo.user` のうち `is_deleted = 0` |
    | 取得失敗 | 404 を返す |

4. 非 null 項目のみ Entity に反映する

    | 項目 | 内容 |
    |---|---|
    | 更新候補 | `mcid`, `lastJoinDate`, `globalIp`, `accountId`, `banIndefinite`, `banDate`, `kickIp`, `permission` |
    | スキップ条件 | リクエスト値が `null` |
    | 共通項目 | `updatedBy` は常に更新、`updatedAt` はサーバ現在日時で常に更新 |

5. リポジトリで更新を実行し、更新後の Entity を [[01_1.00-モデル定義]].ユーザレスポンス へマッピングして 200 を返す

6. 例外発生時は以下ログを記録して 500 を返す

    | 項目 | 内容 |
    |---|---|
    | レベル | Error |
    | テンプレート | `Failed to update user {Uuid}` |
    | 出力条件 | リポジトリ呼び出しで例外発生時 |
    | 引数 | `{Uuid}` = 更新対象UUID |
    | 出力例外 | キャッチした例外を `_logger.LogError(ex, ...)` で添付 |

入力:

- `uuid`: 更新対象UUID
- [[01_1.00-モデル定義]].ユーザ更新リクエスト

出力:

- [[01_1.00-モデル定義]].ユーザレスポンス（更新成功時）

例外時挙動:

- バリデーション失敗時は 400 のみ返す
- 該当レコードなし / 論理削除時は 404 のみ返す
- それ以外の例外は Error ログを記録し 500 を返す
