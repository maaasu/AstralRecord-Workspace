# 01_3.02-登録系

## 1. 登録系エンドポイント仕様

### ユーザ登録

HTTPメソッド: `POST`
パス: `/api/user`
コントローラ: `UserController`
アクション物理名: `CreateUser`

責務:

[[01_1.00-モデル定義]].ユーザ登録リクエスト を受け取り `dbo.user` に新規レコードを作成する。
`account_id` は常に `NULL` で登録し、選択アカウントID の確定はプラグイン側で別途 PUT する。

リクエスト:

| 種別 | 名前 | 型 | 必須 | 説明 |
|---|---|---|---|---|
| Header | `X-Api-Key` | string | ✓ | API キー |
| Header | `Content-Type` | string | ✓ | `application/json` |
| Body | (全体) | [[01_1.00-モデル定義]].ユーザ登録リクエスト | ✓ | 登録対象ユーザ |

レスポンス:

| ステータス | 内容 | ボディ |
|---|---|---|
| 201 Created | 登録成功 | [[01_1.00-モデル定義]].ユーザレスポンス |
| 400 Bad Request | バリデーション失敗 | エラーオブジェクト（[[01_5.00-例外・ログ・運用]] 参照） |
| 401 Unauthorized | API キー未指定または無効 | なし |
| 409 Conflict | 同 UUID が既に登録済み | なし |

処理内容:

1. 認証パイプラインで `X-Api-Key` を検証する

    | 項目 | 内容 |
    |---|---|
    | 検証主体 | `ApiKeyAuthenticationHandler` |
    | 失敗時 | 401 を返し、本処理は実行しない |

2. リクエスト Body のバリデーションを行う

    | 項目 | 内容 |
    |---|---|
    | 検証対象 | [[01_1.00-モデル定義]].ユーザ登録リクエスト 必須項目 |
    | 失敗時 | 400 と共にバリデーションエラー一覧を返す |

3. 同 UUID の存在を確認する

    | 項目 | 内容 |
    |---|---|
    | 検索キー | `uuid`（論理削除済みも含めて検索） |
    | 既存あり | 409 を返す |
    | 既存なし | 手順4へ |

4. リポジトリで新規ユーザを登録する

    | 項目 | 内容 |
    |---|---|
    | 登録対象 | [[01_1.00-モデル定義]].ユーザレスポンス 相当 |
    | `accountId` | 常に `NULL` |
    | `permission` | 既定値 `0` |
    | `isDeleted` | `false` |
    | `createdAt` / `updatedAt` | サーバ現在日時 |
    | `updatedBy` | リクエストの `createdBy` と同値 |

5. 登録結果を [[01_1.00-モデル定義]].ユーザレスポンス へマッピングし 201 を返す

6. 例外発生時は以下ログを記録して 500 を返す

    | 項目 | 内容 |
    |---|---|
    | レベル | Error |
    | テンプレート | `Failed to create user {Uuid}` |
    | 出力条件 | リポジトリ呼び出しで例外発生時 |
    | 引数 | `{Uuid}` = リクエストの `uuid` |
    | 出力例外 | キャッチした例外を `_logger.LogError(ex, ...)` で添付 |

入力:

- [[01_1.00-モデル定義]].ユーザ登録リクエスト

出力:

- [[01_1.00-モデル定義]].ユーザレスポンス（登録成功時）

例外時挙動:

- バリデーション失敗時は 400 のみ返す
- 重複時は 409 のみ返す
- それ以外の例外は Error ログを記録し 500 を返す
