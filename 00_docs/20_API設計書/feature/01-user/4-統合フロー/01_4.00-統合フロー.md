# 01_4.00-統合フロー

API `user` 機能における Controller → Repository → DB の流れと、プラグイン側との接続点を示す。

## 1. 内部レイヤー

```text
Plugin (UserRepository)
   │ HTTP + X-Api-Key
   ▼
ApiKeyAuthenticationHandler
   │ 認証成功
   ▼
UserController
   │ IUserRepository
   ▼
UserRepository
   │ EF Core
   ▼
SQL Server (dbo.user)
```

## 2. ログイン前検証フロー（横断シナリオ）

呼び出し元: プラグイン [[01_3.02-サービス]].ログイン前検証

1. プラグイン: [[01_3.01-取得系]].ユーザ取得 を呼び出す
2. 404 の場合、プラグインは新規ユーザ登録フローへ
   - プラグイン → [[01_3.02-登録系]].ユーザ登録
   - プラグイン → account API（`02-account` 設計書）
   - プラグイン → [[01_3.03-更新系]].ユーザ更新（`accountId` 反映）
3. 200 の場合、プラグインは最終参加情報を [[01_3.03-更新系]].ユーザ更新 で反映

詳細はプラグイン側の [[01_4.00-統合フロー]] を参照。

## 3. 権限更新フロー

呼び出し元: プラグイン [[01_3.02-サービス]].権限更新

1. プラグイン → [[01_3.03-更新系]].ユーザ更新（`permission`, `updatedBy`）
2. プラグイン → [[01_3.01-取得系]].ユーザ取得（更新後の状態を再取得）
3. プラグイン側でオンラインプレイヤーのキャッシュへ反映

## 4. DB との接続

- 対象テーブル: `dbo.user`（詳細は `40_database/AstralRecord/dbo.user/user.md`）
- 主な制約:
  - `uuid` 主キー
  - 論理削除 `is_deleted`
  - 監査列 `created_at` / `updated_at` / `created_by` / `updated_by`
