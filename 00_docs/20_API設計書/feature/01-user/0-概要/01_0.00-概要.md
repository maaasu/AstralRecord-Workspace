# 01_0.00-概要

## 1. 目的

API `user` 機能は、`dbo.user` テーブルへの CRUD 契約を REST として提供する。  
主目的は以下。

- プラグイン（および将来の Web）からのユーザ取得・登録・更新の窓口
- `dbo.user` の論理削除規則を保つ唯一の経路
- 認証ヘッダ（`X-Api-Key`）を介したアクセス制御

## 2. コンテキスト

- 本機能は ASP.NET Core の Controller として動作する。
- 呼び出し元は主にプラグインの `UserRepository`（[[01_3.04-リポジトリ]] 参照）。
- データアクセスは `IUserRepository` 経由とし、Controller から直接 DB を扱わない。
- 認証は `ApiKeyAuthenticationHandler` に委譲する。

## 3. 構成要素（実装単位）

- `Controllers/UserController`
  - エンドポイントのルーティングと DTO 受け渡しを行う。
- `Repositories/UserRepository`
  - `dbo.user` への EF Core クエリを実行する。
- `Models/UserCreateRequest`, `UserUpdateRequest`, `UserResponse`
  - 入出力 DTO（詳細は [[01_1.00-モデル定義]]）。
- `Data/Entities/User`
  - DB Entity（API 設計書本文では原則扱わない、`40_database` 参照）。

## 4. 依存関係

- 内部依存
  - `UserController` -> `IUserRepository`
  - `IUserRepository` -> `AppDbContext`（`dbo.user`）
- 外部依存
  - ASP.NET Core 認証パイプライン（`ApiKeyAuthenticationHandler`）
  - SQL Server `dbo.user`

## 5. ライフサイクル登録点

- `Program.cs` で `IUserRepository` を DI に登録
- `Program.cs` で `ApiKeyAuthenticationHandler` を認証スキームとして登録
- Controller は ASP.NET Core により自動検出
