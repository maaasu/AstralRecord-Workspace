# 22_0.00-概要（API）

## 目的

Plugin の両参加者が合意した item と Gold を、inventory membership、装備個体の `account_id`、Gold 額面を含めて単一 transaction で交換する。ルーンは通常スタック item として数量だけを移管する。

## 境界

- API は提示元 `inventory_entry_id` を正本で再検証し、GAME BAG/HOTBAR 以外の entry を移管しない。
- 装備個体は entry の移動と同じ transaction で owner を受取 account に変更する。ルーンは通常 stack entry の数量を移管する。
- API は受取 BAG の空き `slot_index` を推測せず、新規・移管 entry は未配置のまま transaction を確定する。API 成功後、Plugin は応答の affected entry ID を両 account の local state へ再同期し、BAG の通常容量内または容量外の slot を割り当てて保存・表示する。受取通常 item が既存同種 stack への加算で `maxStack` を超える場合は、超過分を別 entry へ分割し、通常容量に空きがなければ容量外 slot へ配置する。通常の取得は容量外 slot を新規配置先または stack 先にしない。
- API が明示する 4xx 業務拒否では DB を変更せず、Plugin の trade session は `OPEN` のまま再操作可能とする。送信後の通信喪失・応答解析失敗・5xx は API transaction 未確定を証明しないため、Plugin は同じ `operationId` の replay で terminal 応答を得るまで `COMMITTING` を維持する。成功応答後の Plugin 再同期・保存失敗も API commit を取り消さず同じ方法で回復する。

## 冪等性

`operationId` は Plugin session ID を使用する。保存済み operation と要求ハッシュが一致すると確定済み応答を再送し、異なる要求で同じ ID を再利用した場合は 409 を返す。
