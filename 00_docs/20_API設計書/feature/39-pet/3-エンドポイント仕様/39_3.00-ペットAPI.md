# ペットAPI エンドポイント・統合契約

全操作は既存のAPIキー認証を使用する。Pluginからのみ呼び出し、位置・NPC距離・討伐報酬資格はPluginが検証する。DBの動的正本は `pet_instance`、装備選択は `account_pet_state`、冪等台帳は `pet_operation`。

| Method | Path | 内容 |
|---|---|---|
| GET | `/api/pet/master` | `master_type=pet/master_id=pets` の単一定義。item参照は裸IDへ正規化 |
| GET | `/api/pet/accounts/{accountId}` | `accountId/equippedPetId/instances[]` |
| GET | `/api/pet/instances/{instanceId}?account_id={accountId}` | 所有者限定個体 |
| GET | `/api/pet/accounts/{accountId}/operations/{operationId}` | 冪等操作結果の再照会 |
| POST | `/api/pet/accounts/{accountId}/eggs` | `speciesId` の野生卵をBAGへ追加 |
| POST | `/api/pet/accounts/{accountId}/admin-grants` | Pluginで管理権限を検証した取得実行者から、`speciesId` の野生孵化直後のペットをBAGへ追加 |
| POST | `/api/pet/accounts/{accountId}/{instanceId}/hatch` | 施設照合と孵化素材消費、卵entryを同じIDでペットへ変更 |
| POST | `/api/pet/accounts/{accountId}/breed` | 成長済み同種のオス・メスを配合して卵追加。親保持 |
| POST | `/api/pet/accounts/{accountId}/{instanceId}/progress` | 経験値加算、HP・死亡・スキルCD保存、成長とスキル抽選。Plugin管理者コマンドは `adminTargetLevel` で現在より高い成長度を直接指定できる |
| POST | `/api/pet/accounts/{accountId}/{instanceId}/revive` | 復活素材またはオーブ消費 |
| PUT | `/api/pet/accounts/{accountId}/equipped` | `petId` のentryをGAME `EQUIP_SLOT` 7へ移動。nullでBAGへ解除 |
| POST | `/api/pet/accounts/{accountId}/{instanceId}/rename` | 孵化後の名前変更〈1〜24文字、制御文字と§は禁止〉 |

## 要求・応答契約

`admin-grants` は `PetEggCreateRequest` を受け、通常の野生孵化と同じ `PetGenetics.HatchWild` で未配合のWILD個体を生成する。成長度1・EXP0・HP満タンで、施設照合と素材消費は行わない。種別はPluginが取得アイテムの `petItemId` から解決する。管理権限・コンソール実行の許可とBAG容量予約は、既存の管理者アイテム取得と同じくPluginが検証し、APIは既存APIキー認証を要求する。受取対象は取得実行者と異なるアカウントでもよい。個体と数量1のPET entryを冪等台帳と同一transactionで追加し、同じ操作IDの再送では能力を再抽選しない。通常の卵作成・施設孵化の契約は変えない。

すべての変更要求に `operationId` と `updatedBy` の非空UUIDが必要。同じID・同じ要求は再実行しない。要求内容が違うID再利用は409 `operation_conflict`。素材消費・卵/個体変更・entry変更・台帳を同一transactionで確定する。SQL Serverのretry実行戦略の内側でuser、accountをUPDLOCK/HOLDLOCKし、inventory、entryの順でロックする。

管理編集ゲートは全ペット変更にも適用する。未退避DRAINING/RECOVERY_REQUIREDで行う最終progressだけ、[[39_1.00-モデル定義]]のserver/boot/account session/tokenで既存の正確なRPG保存権限を検証して許可する。`adminTargetLevel` を伴う管理者成長操作はこの例外に含めない。通常の期限切れをオフライン証明にしない。READY/APPLYINGでは旧sessionのprogressも変更できない。RPGは最終snapshotとpet flushの両方が成功した後にsessionを閉鎖してから退避ACKを送る。

操作応答は `{instance,equippedPetId,inventorySnapshot}`。`inventorySnapshot` は既存の所有者限定 `InventoryOperationSnapshotResponse` で、`coveredEntryIds` のうち `entries` にないIDは削除済み/所有外。再送応答は最新の所有者限定entryを再取得する。Pluginは対象IDだけreconcileし、ローカル全inventoryを置換しない。

ペット装備操作はGAME BAGの孵化済みPET entryを同じentry IDのままGAME `EQUIP_SLOT` の `slot_index=7` へ移動し、`account_pet_state` の選択も同一transactionで更新する。既存装備の解除・交換では `returnBagSlotIndex`（1始まり）が必須。Pluginは現在の実BAG容量に収まる返却先を予約してから要求し、APIはロック下で返却先が空きか、交換時に新ペットが占めるスロットかを検証する。BAGの `slot_capacity` はnullであり実容量はPluginのstateから導出するため、APIは実容量を再計算しない。返却先不足・占有・装備スロット不整合は409で変更しない。交換では旧PET entryをBAGへ、新PET entryを装備枠7へ移動し、両entry IDを `inventorySnapshot.coveredEntryIds` に含める。装備枠inventoryの容量は7以上にする。同じ `petId` の再指定は、旧形式の選択中PETがBAGに残る場合も装備枠へ移して修復する。GETは移行副作用を持たない。

卵・ペット共通個体応答は `instanceId/accountId/speciesId/itemId/isEgg/origin/tradeAllowed/version/createdAt/updatedAt`。**卵ではdetailsプロパティをJSONに出力しない**。名前・性別・サイズ・外見・能力・潜在・スキル・親スナップショット・CDは孵化前に取得できない。`origin=WILD` は移管可、`BRED` は卵から永久に移管禁止。孵化後だけ `details={name,sex,size,appearance,level,experience,healthRatio,isDead,breedAvailableAt,stats,skills,cooldowns}` を返す。`size`は基礎個体差で、見た目の成長倍率を掛けた値は保存しない。犬/猫の`appearance`は首輪色、猫は毛柄も持つ。既存個体で欠ける場合は個体IDから決定的に補い、GETではDBを書き換えない。

statsはキー `VITALITY/POWER/DEFENSE/EVASION/SUPPORT` ごとに `{tier,baseValue,potential,currentValue}`。skillsは最大3件 `{id,tier,slotIndex}`、slotIndex=0〜2。cooldownsはskillID→次回発動可能なUTC epoch milliseconds。progress要求は `expectedVersion/experience/adminTargetLevel/healthRatio/isDead/cooldowns`。experienceはPluginが独自活動式で計算した補正前の加算量、healthRatioは0〜1、CD=null/省略時は既存維持。`adminTargetLevel` は任意で、指定時はexperience=0かつ現在より高くマスター上限以下とし、残EXPを0にして指定成長度へ進め、スキル解放と能力を更新する。updatedByが対象account IDと一致し、対象accountの所有ユーザーが保存済みADMIN権限またはNetworkの最高権限を持つ場合だけ許可する。選択中かつ生存の個体だけ更新できる。死亡は通常progressで取り消せず、revive専用。

## 成長・遺伝

初期マスターは最大Lv100、slot解放1/20/50、配合Lv20、親それぞれ24時間CD。経験値はプレイヤーと同じ `500+Lv²×120+floor(Lv/10)×850+wave+5Lvごとの節目`。主人UUIDによる微小hash加算は用いない。Lv内経験値として保存し、Lv100で0へ固定。見た目は基礎個体サイズへ`rules.sizeGrowth`を掛け、Lv1で0.5倍からLv20で1.0倍まで線形に成長して以後固定する。全種の基本攻撃は`species[].basicAttack`、自律索敵距離は`rules.autonomousAttackRange`（1〜32）、PET攻撃のHP/Shield由来脅威倍率は`rules.threatMultiplier`（0〜1）で定める。

野生卵は孵化時だけ能力を抽選する。野生ステータスはT4まで、初期skillはT0。各ティア内整数の重みは `(max-value+1)^valueWeightPower`。配合卵は作成時に両親の基礎個体値をスナップショットし、能力ごとに高いティア、同ティアなら高い基礎値を継承。稀に+1ティア、上限T10。親の成長後現在値は継承しない。潜在は成長増分だけ×2。親の多い潜在数を基準にK−1/K/K+1を20/75/5で抽選、親の潜在項目を重く再抽選。両親0個なら野生と同じ低確率。

子の初期skillは親の習得済みskillの重複除去集合から均等抽選。1枠目T0/T1なら後続上限T1/T2、1枠目T2/T3なら両方T3を候補に含める。重複skillは取得しない。野生のみでT3には届かない。

## 周辺契約

inventoryは `itemCategory=pet/instanceType=PET` と `itemCategory=pet_egg/instanceType=PET_EGG`、数量1。generic inventoryとplayer-stateは所有個体のitemID・種別・数量を照合する。generic inventoryの更新・削除・一括置換とplayer-state保存は、選択中PETの装備枠7 entryを消去・移動・別itemへ変更できない。同じentryの識別属性を保つ更新は許可する。装備枠7に選択中PETがある間は、親GAME `EQUIP_SLOT` inventoryの無効化・プロファイル変更・容量7未満への縮小を拒否し、メタデータ更新時は容量7以上を保持する。野生由来だけトレード/マーケット移管可。装備中は移管不可。Webマーケット購入のメール保留も所有者を一度だけ移し、受取snapshotで本人とoriginを検証する。配合由来は全移管経路で拒否。

孵化/配合は `facilityId=pet_center`、復活は同施設の素材または `orbInventoryEntryId`。素材はGAME BAGからだけ原子消費する。配合する親は未装備でGAME BAG内にいる必要がある。復活する個体はGAME BAGまたは選択中のGAME装備枠7にいてよい。孵化費用はマスターのベルディアHARVESTINGツールLv2素材。卵は能力をinventory metadataへコピーしない。

アカウント複製は個体IDを新規採番し、inventoryと装備選択、所有内の親IDを再マップする。BRED出自は保持。削除時は選択を削除、所有個体を論理削除、操作台帳を保持する。SQL既存環境は `20261001_pet.sql` を適用する。

## 活動経験値率

進行要求の `experience` はPluginが活動ごとに `floor(base + max(1,対象レベル) × perLevel)` で計算して合算したペット独自の未補正EXP。討伐は `experience.combatGain`（初期値base=50/perLevel=25）、採集は `experience.gatheringGain`（初期値base=20/perLevel=10）を使い、プレイヤーの報酬EXP・レベル差・経験値獲得率は参照しない。釣り試作は経験値報酬を持たない。各gainは有限非負で、base/perLevelの少なくとも片方が正。最大のint対象レベルでもrawEXPをlongへ変換できるよう `base + perLevel × int.MaxValue < long.MaxValue` を満たす。

個体の成長補正は5能力それぞれについて、種の全ティアの最小minと最大maxから `q=clamp((baseValue-min)/(max-min),0,1)` を求め、`growthRate=1-(1-experience.growthRateMin)×average(q)` とする。初期のgrowthRateMinは0.25で、有限かつ0より大きく1未満。基礎能力が高いほど成長補正は低く、下限個体は100%、上限個体は25%。潜在・成長後currentValue・成長度は補正に含めない。APIは `floor(experience × activityRate × growthRate)` を一度だけ計算して個体EXPへ加える。同じoperationIdの再送では再加算しない。成長補正は既存statsとmasterから導出できるため、個体応答やDBに追加保存しない。能力増分と必要EXP曲線は維持する。
