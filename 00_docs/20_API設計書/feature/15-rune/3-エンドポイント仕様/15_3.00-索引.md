## 1. ルーンインスタンス作成

HTTPメソッド: `POST`
パス: `/api/rune/instances`
コントローラ: `RuneController`
アクション物理名: `CreateInstance`

責務:

YAML のルーン定義（[[04_README]] の `category: rune`）から個体を生成し、ランダム stat を解決して保存する。

リクエスト:

| 種別 | 名前 | 型 | 必須 | 説明 |
|---|---|---|---|---|
| Header | `X-Api-Key` | string | ✓ | API キー |
| Header | `Content-Type` | string | ✓ | `application/json` |
| Body | (全体) | [[15_1.00-モデル定義]].ルーンインスタンス作成リクエスト | ✓ | 生成内容 |

レスポンス:

| ステータス | 内容 | ボディ |
|---|---|---|
| 201 Created | 作成成功 | [[15_1.00-モデル定義]].ルーンインスタンスレスポンス |
| 400 Bad Request | バリデーション失敗 | エラーオブジェクト |
| 401 Unauthorized | API キー未指定/無効 | なし |
| 404 Not Found | `accountId` または `runeId` 未存在 | なし |

処理内容:

1. 認証パイプラインで `X-Api-Key` を検証する
2. リクエストのバリデーション（必須項目）
3. `accountId` の存在確認（[[02_README]]）。未存在は 404
4. `runeId` の存在確認（YAML マスタ、`category: rune`）。未存在は 404
5. ルーン個体を生成

    | 項目 | 内容 |
    |---|---|
    | `runeInstanceId` | `Guid.NewGuid()` |
    | `statRolls` | YAML の `rune.stats[]` の `value` を範囲指定なら乱数解決、固定なら固定値で確定 |

6. 結果を 201 で返す
7. 例外時は [[15_5.00-例外・ログ・運用]] のログを記録し 500 を返す

---

## 2. ルーンインスタンス取得

HTTPメソッド: `GET`
パス: `/api/rune/instances/{instanceId}`
コントローラ: `RuneController`
アクション物理名: `GetInstance`

リクエスト:

| 種別 | 名前 | 型 | 必須 | 説明 |
|---|---|---|---|---|
| Header | `X-Api-Key` | string | ✓ | API キー |
| Path | `instanceId` | GUID | ✓ | ルーン個体UUID |

レスポンス:

| ステータス | 内容 | ボディ |
|---|---|---|
| 200 OK | 取得成功 | [[15_1.00-モデル定義]].ルーンインスタンスレスポンス |
| 401 Unauthorized | API キー未指定/無効 | なし |
| 404 Not Found | 未登録/論理削除済み | なし |

処理内容:

1. 認証パイプラインで `X-Api-Key` を検証する
2. リポジトリで個体を取得（関連 `statRolls` を含む）。未存在は 404
3. 200 で返す
