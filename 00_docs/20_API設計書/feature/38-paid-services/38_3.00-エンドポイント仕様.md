# チャンネルブースト・有償サービス Web API

## チャンネルブースト

| Method | Path | 役割 |
|:--|:--|:--|
| GET | `/api/channel-boosts` | 全ゲームチャンネルの現在EXP/DROP倍率、期限、発動者と`eventCursor`を返す。各行は`displayName`と`networkBoostEnabled`を含み、未発動もnull状態で含む。 |
| GET | `/api/channel-boosts/events?after={cursor}` | 発動順に最大100件を返す。空のときcursorは進めない。 |
| POST | `/api/channel-boosts/{channelId}/activate` | `{operationId,accountId,inventoryEntryId,expectedUpdatedAt}`を受け、チケット消費・状態更新・通知イベントを単一transactionで確定する。 |

`channelId`は小文字化し、管理設定のゲームチャンネルだけ受け付ける。EXP/DROPは各系統の有効期間中に重複しない。SPECIALは両方空きの場合だけEXP/DROPを同時に2倍にする。使用可能チケットは `CHANNEL_EXP_BOOST`、`CHANNEL_DROP_BOOST`、`CHANNEL_SPECIAL_BOOST` 効果が1つ、`rate=100`、`isPercent=false`、`durationSeconds=3600`、`onUse.amount=1` のアイテム。発動は1時間後に失効し、次回取得時はnullで示す。異なる`operationId`での再送は別の使用とみなす。発動者のVIP種別はイベント作成時に保存する。

`activate`の成功は`{operationId,status:"COMPLETED",boost,eventCursor,inventorySnapshot}`。失敗はHTTP 409、`status:"REJECTED"`と`reason`を返し、アイテムを消費しない。イベント連番は単一行をtransaction中に更新してcommit順を固定する。Pluginは初回snapshotのcursorを記録し、その後のeventsをpollする。

snapshotの`networkBoostEnabled`は管理設定のゲームチャンネルで明示的に有効な場合だけtrueとする。未設定や削除済みチャンネルはfalse。TABはtrueの行だけを表示するが、Pluginの倍率計算にはfalseの行も必要なため状態一覧から除外しない。ゲーム内`activate`はこのフラグを条件にせず、`/server-info`でもゲーム内使用分を確認できる。snapshot以外の操作応答では表示用メタデータを省略でき、TABはsnapshotを正本にする。

## 有償ショップ

| Method | Path | 役割 |
|:--|:--|:--|
| GET | `/api/web/astrald-shop/catalog` | `astrald_shop`マスタの有償`99a00021`価格・効果と`networkBoostEnabled=true`のゲームチャンネルを返す。 |
| POST | `/api/web/astrald-shop/purchases?actor_user_uuid={uuid}` | `{operationId,accountId,itemId,expectedPricePaidAstrald,channelId?}`で本人の現在アカウントに購入する。 |
| GET | `/api/web/astrald-shop/purchases/{operationId}?actor_user_uuid={uuid}` | 本人の購入receipt取得。 |
| GET | `/api/web/astrald-shop/purchases/pending/{accountId}` | Pluginのオンライン保存境界用保留一覧。 |
| POST | `/api/web/astrald-shop/purchases/{operationId}/process` | Pluginが`{accountId,preparedOnline:true}`で保留を確定。 |

Web本人エンドポイントは`X-Donation-Web-Key`と`actor_user_uuid`を要求する。`dbo.user.account_id`に一致する本人アカウントだけ購入できる。価格はmasterと`expectedPricePaidAstrald`が一致する時だけ受け付け、価格・効果・対象チャンネルをledgerに固定する。通貨減算とVIP/優先回数/チャンネルブースト適用は同一transaction。未閉鎖のゲームセッションがある間は`PENDING`にし、Pluginの保存境界で`process`する。`COMPLETED`応答に`affectedInventoryEntryIds`、`inventorySnapshot`、適用後の`benefits`または`boost`を含む。同じoperationIdと同じ内容はreceiptを返し、異なる内容は`operation_conflict`。

ブースト購入は受付と保留の確定時に`networkBoostEnabled`を再確認する。無効・未設定・対象削除時は`network_boost_disabled`として課金・発動せず拒否する。設定変更前に確定した購入の再送は元の結果を返し、ブースト効果も期限まで維持する。

## 本人のメールとVIP

| Method | Path | 役割 |
|:--|:--|:--|
| GET | `/api/web/mail?actor_user_uuid={uuid}&account_id={accountId}` | 本人の現在アカウントの有効メール。`canClaimCurrency`と`currencyClaimed`を含む。 |
| POST | `/api/web/mail/{mailId}/claim-currency?actor_user_uuid={uuid}` | `{operationId,accountId}`で通貨の添付だけ受け取る。 |
| GET | `/api/web/mail/claims/{operationId}?actor_user_uuid={uuid}` | 本人の受取receipt。 |
| GET | `/api/web/mail/claims/pending/{accountId}` | Plugin保存境界用保留一覧。 |
| POST | `/api/web/mail/claims/{operationId}/process` | Pluginが`{accountId,preparedOnline:true}`で保留を確定。 |
| GET | `/api/web/account-benefits?actor_user_uuid={uuid}&account_id={accountId}` | 本人の現在アカウントのVIP種別、期限、残日数、優先接続回数、有償残高。 |
| GET | `/api/web/vip-supporters?actor_user_uuid={uuid}` | Web管理者だけの有効VIP一覧。 |

Web通貨受取は通常masterと個別deliveryの両方に対応する。混在メールでは通貨を台帳に記録して直接付与し、非通貨報酬を未読で残す。後続のメール一覧は受取済み通貨を報酬から除外する。通貨のみのメールは既読にもする。ゲーム内`player-state`の`mailClaim.currencyAlreadyClaimed`は台帳と一致しない古い表示からの受取を拒否する。Web受取は購入と同じくオンライン中は`PENDING`、Plugin保存境界で確定する。非通貨報酬はWeb APIから付与しない。

## 管理編集中の保留処理

有償購入・通貨受取の新規受付は管理編集ゲートで拒否する。開始前に受理済みのPENDINGは、未退避DRAINING/RECOVERY_REQUIREDで準備済みRPGの正確な保存権限を検証して確定できる。READY/APPLYINGでは新しい処理を許可しない。確定済みreceiptの再送は読み取り専用で返す。

両process要求は`accountId / preparedOnline`に加え、`serverId` string、`serverSessionId` GUID、`accountSessionId` GUID、`accountLeaseToken` string（64文字小文字hex）を持つ。旧要求は非編集中の互換性を保ち、編集中は全権限項目を要求する。ユーザー→account→operation順に直列化し、開始前の作成日時・captureされたRPG boot・未閉鎖session・tokenを照合する。tokenを画面やログに出さない。退避ACKは処理receiptの確定とローカル保存境界の解放を待つ。
