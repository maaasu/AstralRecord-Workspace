# 24_1.00-モデル定義

## 1. 発行

`WebLoginChallengeCreateRequest`: `userUuid`, `mcid`, `serverId`, `requestedAt`

`WebLoginChallengeCreateResponse`: `challengeId`, `loginCode`, `expiresAt`, `loginUrl`

## 2. 消費

`WebLoginChallengeConsumeRequest`: `loginCode`

`WebLoginChallengeConsumeResponse`: `userUuid`, `mcid`, `permission`, `webAdmin`, `currentAccountId`, `accountIds`

## 3. 永続化

`WebLoginChallengeEntity` は `challengeId`、`userId`、`loginCodeHash`、発行・期限・消費・失効時刻、失敗回数、発行元サーバー、作成時刻を保持します。

`WebSiteDB.dbo.web_user` はログイン成功後にのみ作成または更新します。主キーは `userUuid` で、`mcid`、`webAdmin`、`firstLoginAt`、`lastLoginAt` を保持します。`webAdmin` はゲーム側の `permission` と独立したWeb管理権限の正本です。

## 4. コンソール用プレイヤー解決

`WebLoginChallengeUserResolveResponse`: `userUuid`, `mcid`

コンソールからの `/web login <MCID>` 用に、登録済みプレイヤーを完全一致MCIDで検索します。検索結果が0件は `404`、複数件は `409` とし、Pluginはどちらも発行拒否します。

## 5. Web管理認可

`WebAuthorizationResponse`: `webAdmin`

Webサイトは認証済みCookieのuser UUIDを送信し、この応答を要求ごとに利用します。Cookie内のゲームpermissionや過去の認可結果はWeb管理の根拠にしません。
