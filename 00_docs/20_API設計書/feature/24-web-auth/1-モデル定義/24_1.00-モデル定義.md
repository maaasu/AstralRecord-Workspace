# 24_1.00-モデル定義

## 1. 発行

`WebLoginChallengeCreateRequest`: `userUuid`, `mcid`, `serverId`, `requestedAt`

`WebLoginChallengeCreateResponse`: `challengeId`, `loginCode`, `expiresAt`, `loginUrl`

## 2. 消費

`WebLoginChallengeConsumeRequest`: `loginCode`, 任意の`expectedUserUuid`。再認証時にCookieのUUIDを指定し、対象コードのUUIDが異なる場合は消費しない。

`WebLoginChallengeConsumeResponse`: `userUuid`, `mcid`, `permission`, `webAdmin`, `currentAccountId`, `accountIds`, `sessionVersion`。Webは`sessionVersion`を保護Cookieへ保存し、要求ごとにcredentials照会結果と一致することを確認する。

`WebPasswordLoginRequest`: `loginId`, `password`

`WebCredentialResponse`: `loginId`（未発行時はnull）, `enabled`, `sessionVersion`

`WebCredentialUpdateRequest`: `sessionVersion`, `action`（`enable`/`change`/`disable`）, 任意の`currentPassword`・`newPassword`・`codeAuthenticationProof`。本人UUID・sessionVersion・codeAuthenticationProofはWebが保護Cookieから導出し、フォーム値を採用しない。パスワードは入力フォームから取得する。

## 3. 永続化

`WebLoginChallengeEntity` は `challengeId`、`userId`、`loginCodeHash`、発行・期限・消費・失効時刻、失敗回数、発行元サーバー、作成時刻を保持します。

`ManagementPlayerEntity` は `ManagementDB.dbo.player` に保存します。主キーは `playerUuid`（物理列`player_uuid`）で、`mcid`、`webAdmin`、`createdAt`、`updatedAt`、任意の`firstWebLoginAt`・`lastWebLoginAt`を保持します。Webログイン時はコード検証後にupsertし、登録済みの管理権限と作成日時を維持します。Web未利用の管理レコードも保持でき、ゲームDBの削除とは独立しています。`webAdmin` はゲーム側の `permission` と独立したWeb管理権限の正本です。

`WebCredentialEntity` と試行回数記録はManagementDBに保存する。コード消費成功時に、無効状態・ランダム`sessionVersion`の認証行を作る。固定ログインIDは初回有効化時にAPIが生成し、無効化後も再利用されない。パスワードはPBKDF2-HMAC-SHA512（310,000 iterations）だけを保存する。

## 4. コンソール用プレイヤー解決

`WebLoginChallengeUserResolveResponse`: `userUuid`, `mcid`

コンソールからの `/web login <MCID>` 用に、登録済みプレイヤーを完全一致MCIDで検索します。検索結果が0件は `404`、複数件は `409` とし、Pluginはどちらも発行拒否します。

## 5. Web管理認可

`WebAuthorizationResponse`: `webAdmin`

Webサイトは認証済みCookieのuser UUIDを送信し、この応答を要求ごとに利用します。Cookie内のゲームpermissionや過去の認可結果はWeb管理の根拠にしません。

コード本人確認は、コード消費時にAPIが発行するData Protection証明 `codeAuthenticationProof` を検証する。証明は本人UUID・sessionVersion・元の認証日時に結び付き、5分以内だけ有効。現在時刻を自己申告するだけでは認証しない。コード成功応答とコード証明を使った設定更新応答は、表示用の `codeAuthenticatedAt` も返す。設定更新時の証明再発行では世代だけを変更し、元の認証日時を維持する。GET credentialsは証明を返さない。
