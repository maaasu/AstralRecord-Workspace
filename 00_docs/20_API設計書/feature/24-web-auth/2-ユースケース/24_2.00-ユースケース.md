# 24_2.00-ユースケース

## 1. Plugin からチャレンジを発行する

1. 必須項目と user UUID を検証する。
2. 対象ユーザーが存在し、削除されていないことを確認する。
3. 同じユーザーの未消費・未失効・期限内チャレンジを失効する。
4. 新しいコードを生成し、ハッシュだけを DB に保存する。
5. 平文コード、有効期限、ログイン URL を Plugin へ返す。

## 2. Web からチャレンジを消費する

1. コードから空白とハイフンを除去し、大文字へ正規化する。
2. SHA-256 ハッシュでチャレンジを検索する。
3. 未消費・未失効・期限内であることを検証する。
4. 同一行を状態条件付きで更新して消費時刻を記録する。条件に合う更新は1回だけ成功する。
5. ゲームDBの消費トランザクション内でManagementDBの `player` をupsertし、保存後に消費をcommitする。ManagementDB障害時は消費をrollbackして再試行を許可する。分散トランザクションは使わない。
6. ユーザー、アカウント、Web管理フラグを返す。

## 3. コンソールからMCIDを指定して発行する

1. Pluginが完全一致MCIDをAPIへ送る。
2. APIは削除されていない `dbo.user` を最大2件取得する。
3. 1件だけならUUIDとMCIDを返し、Pluginが通常の発行APIを呼ぶ。
4. 0件または複数件ならコードを発行しない。

## 4. Web管理機能を認可する

1. Webは認証Cookieのuser UUIDを使ってAPIへ照会する。
2. APIはManagementDBの `player.web_admin` だけを返す。
3. `true` の場合だけ管理画面を許可する。レコードなし、`false`、API障害はすべて拒否する。
