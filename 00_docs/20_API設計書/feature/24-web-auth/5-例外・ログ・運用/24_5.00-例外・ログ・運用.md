# 24_5.00-例外・ログ・運用

| 応答 | 条件 |
|---|---|
| `400 Bad Request` | 必須項目不足、コード不正、期限切れ、失効済み、消費済み |
| `404 Not Found` | 発行対象ユーザーが存在しない |
| `201 Created` | チャレンジ発行成功 |
| `200 OK` | チャレンジ消費成功 |
| `409 Conflict` | コンソール用MCID解決で同じMCIDが複数ある |
| `401 Unauthorized` | 認証情報更新時のsessionVersionが古い |
| `429 Too Many Requests` | 同じ固定ログインIDが15分間に10回失敗した |

## セキュリティ・運用

- 平文ログインコードを DB やログへ保存しない。
- 有効期限は `WebAuth:ChallengeMinutes`（最小 1 分）で管理する。
- ログイン URL は `WebAuth:LoginUrl` から返す。
- 同一ユーザーの有効チャレンジは常に最新 1 件へ集約する。
- `ConnectionStrings:Management` を設定できる。未設定時は `ConnectionStrings:SqlServer` の接続先DB名だけを `ManagementDB` に置換する。
- `ManagementDB/init.sql` は初回配置時に適用する。既存3DB固定のDB移行・再構築ツールはManagementDBを操作しない。
- APIを含む通常配置では`01-deploy-debug.bat`または`10-release-management-deploy.bat`が、API/Webの停止・コピー前にManagementDB専用runnerで`20260917_web_credentials.sql`と`20260920_trusted_admin_browser.sql`を適用し、認証情報・信頼済みブラウザのテーブルを検査する。単独の手動復旧時は`14-management-db-migrate.bat`を実行する。ゲーム用`db-migrate`はManagementDBを対象にしない。
- このmigration未適用で新APIを配置すると、既存のコードログイン消費も認証行作成時に失敗し、ゲームDB側の消費transactionはrollbackしてコードを再試行可能なまま残す。API先行配置をしない。
- `WebAuth:LoginUrl` の既定値は `https://astralrecord.com/Login`。
- Web管理認可はManagementDBを要求ごとに照会し、API障害時は拒否する。
- 固定パスワードはPBKDF2-HMAC-SHA512の310,000 iterationsでハッシュ化し、平文・ログ・例外応答へ出さない。パスワード文字列はtrimしない。
- ID単位の失敗試行はManagementDBへ永続化し、楽観ロックで競合更新を再試行する。Webは別途IP単位のrate limitを行う。
- `sessionVersion`はコードログイン・固定パスワードログインの応答へ返す。Webは保護Cookieの値を認証済み要求ごとにcredentials APIと照合し、不一致・無効・照会失敗でCookieを破棄する。
- Minecraftコードログインまたは再認証で「このブラウザを信頼する」を選んだ場合、APIはランダムトークンのハッシュだけをManagementDBへ保存し、Webはトークン本体をHttpOnly・Secure Cookieへ保存する。管理画面の要求ごとにWebがAPIで検証し、成功時に最終利用日時を更新する。管理画面の利用が7日間ない場合、トークンは失効してMinecraft再認証を要求する。
- 信頼済みブラウザは管理者専用画面・操作全体に適用し、重要度による認証要件の分割は行わない。認証情報の変更などで`sessionVersion`が更新された場合、旧世代の信頼済みブラウザは利用できない。

- 現在パスワードによる設定変更も同じIDの15分・10回制限を共有する。コード証明による復旧はこのロックを迂回し、成功時に試行情報を解除する。
- 不存在・無効IDにも同じPBKDF2方式のダミー照合を行い、応答時間差を抑える。
- APIのData Protection鍵は共有APIキーと分離する。application nameは `AstralRecordApi.WebAuthentication`、purposeは `AstralRecord.WebCodeProof.v1`。鍵リングを保持し、複数APIインスタンスでは同じ鍵リングを安全に共有する。鍵を失った場合はコードで再認証する。Web/APIの時計は同期する。
