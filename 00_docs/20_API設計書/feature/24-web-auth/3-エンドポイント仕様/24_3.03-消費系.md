# 24_3.03-消費系

## ログインチャレンジ消費

- HTTP メソッド: `POST`
- パス: `/api/web-auth/challenges/consume`
- 要求: `WebLoginChallengeConsumeRequest`
- 応答: `200 OK` と `WebLoginChallengeConsumeResponse`

空のコード、未知のコード、期限切れ、失効済み、消費済みは `400 Bad Request` とします。期限切れ等の既知チャレンジでは `failedAttempts` を増加させます。`expectedUserUuid`がある場合は、対象コードのUUIDが一致することを状態更新前に確認し、不一致なら消費せず400を返します。成功時は状態条件付き更新で `consumedAt` を設定し、ユーザー情報、`webAdmin`、削除されていないアカウント ID をスロット順、`sessionVersion`を返します。更新件数が0件なら成功させないため、同じコードを同時に消費しても1件だけが成功します。

ゲームDBの消費transaction内でManagementDBの `player` をupsertし、その成功後に消費をcommitします。初回は `webAdmin=false`、再ログイン時は既存 `webAdmin` を保持します。ManagementDBへの書込みが失敗した場合は消費をrollbackし、同じ有効コードで再試行できます。別DBへの保存は分散transactionではないため、Web利用者保存後にゲームDBのcommitが失敗した場合は利用者行を保持し、再試行時にupsertします。

## Web管理認可確認

- HTTP メソッド: `GET`
- パス: `/api/web-auth/users/{userUuid}/authorization`
- 応答: `200 OK` と `WebAuthorizationResponse`

`ManagementDB.dbo.player.web_admin` を返します。レコードがない場合は `webAdmin=false` です。APIキー認証済みのWebサーバーだけが使用します。

## 固定ID・パスワードログイン

- HTTP メソッド: `POST`
- パス: `/api/web-auth/password/login`
- 要求: `{ "loginId": "AR-…", "password": "…" }`
- 応答: `200 OK` と `WebLoginChallengeConsumeResponse`

成功時のDTOはコードログインと同一である。ID不在・無効・パスワード不正・ゲーム側で明示削除済みのユーザーはすべて`400 {"message":"login is invalid."}`とする。同一IDの10回連続失敗は15分間`429`とする。ゲームDBがリセットされユーザー行そのものがない場合はManagementDBのMCID、permission=0、空アカウントで成功する。

## Web認証情報照会・更新

- HTTP メソッド: `GET`
- パス: `/api/web-auth/users/{userUuid}/credentials`
- 応答: `200 { "loginId": string|null, "enabled": bool, "sessionVersion": guid }`、認証行なしまたはゲームDBに明示削除済みユーザー行がある場合は`404`。ゲームDBのユーザー行がないリセット状態はManagementDBの認証行を返す。

- HTTP メソッド: `POST`
- パス: `/api/web-auth/users/{userUuid}/credentials`
- 要求: `{ "sessionVersion": guid, "action": "enable|change|disable", "currentPassword": string|null, "newPassword": string|null, "codeAuthenticationProof": string|null }`
- 応答: `200`は上記認証情報DTO、CAS失敗は`401`、入力または認証不正は`400`。

このAPIはWebのAPIキー認証を前提とする。Webは`sessionVersion`と`codeAuthenticationProof`をフォーム入力から受け取らず、保護Cookieからのみ設定する。`enable`は常に5分以内のコード認証と新パスワードを要し、`change`と`disable`は同認証または現在パスワードを要する。更新成功時は全既存Cookieを失効させるため`sessionVersion`を必ず新規発行する。

コード本人確認は、コード消費時にAPIが発行するData Protection証明 `codeAuthenticationProof` を検証する。証明は本人UUID・sessionVersion・元の認証日時に結び付き、5分以内だけ有効。現在時刻を自己申告するだけでは認証しない。コード成功応答とコード証明を使った設定更新応答は、表示用の `codeAuthenticatedAt` も返す。設定更新時の証明再発行では世代だけを変更し、元の認証日時を維持する。GET credentialsは証明を返さない。
