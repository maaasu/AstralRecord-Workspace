# 24_3.03-消費系

## ログインチャレンジ消費

- HTTP メソッド: `POST`
- パス: `/api/web-auth/challenges/consume`
- 要求: `WebLoginChallengeConsumeRequest`
- 応答: `200 OK` と `WebLoginChallengeConsumeResponse`

空のコード、未知のコード、期限切れ、失効済み、消費済みは `400 Bad Request` とします。期限切れ等の既知チャレンジでは `failedAttempts` を増加させます。成功時は状態条件付き更新で `consumedAt` を設定し、ユーザー情報、`webAdmin`、削除されていないアカウント ID をスロット順で返します。更新件数が0件なら成功させないため、同じコードを同時に消費しても1件だけが成功します。

ゲームDBの消費transaction内でWebSiteDBの `web_user` をupsertし、その成功後に消費をcommitします。初回は `webAdmin=false`、再ログイン時は既存 `webAdmin` を保持します。WebSiteDBへの書込みが失敗した場合は消費をrollbackし、同じ有効コードで再試行できます。別DBへの保存は分散transactionではないため、Web利用者保存後にゲームDBのcommitが失敗した場合は利用者行を保持し、再試行時にupsertします。

## Web管理認可確認

- HTTP メソッド: `GET`
- パス: `/api/web-auth/users/{userUuid}/authorization`
- 応答: `200 OK` と `WebAuthorizationResponse`

`WebSiteDB.dbo.web_user.web_admin` を返します。レコードがない場合は `webAdmin=false` です。APIキー認証済みのWebサーバーだけが使用します。
