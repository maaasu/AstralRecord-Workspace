## レスポンスモデル

### runtime同期の追加契約

従来の`PUT .../view`は`SkillTreeEditorResponse`を返し続ける。`PUT .../view/ack`は同じowner/token、boot、世代、保存version、単調`viewSequence`を検証し、commit後に`{"accepted":true,"viewSequence":2}`だけ返す。Web編集viewの構築とexpiry/pending照会を実行しない。

`POST .../accounts/heartbeat`の入力は`{"items":[{"accountId":"...","session":{"serverSessionId":"...","accountSessionId":"...","accountLeaseToken":"...","definitionGenerationId":"..."},"view":{...既存view登録要求...},"viewUnchanged":false}]}`。同じbootの重複なし1〜32accountに限定する。`view`省略はsession更新だけを行う。sessionは取得済みであることが必須で、新しいsessionを作らず、終了・期限切れsessionを復活させない。入力全体の件数・識別子不備は400、専用runtimeキー不備は401。

各accountは個別Serializable transactionでuser→accountの順にロックし、runtime/世代、session/token/期限、管理編集の退避条件を従来のsession更新と同じ規則で照合する。許可されたsessionの期限を45秒へ延長する。viewのboot/session/世代/保存version/単調sequence不一致ではviewだけ拒否し、正当なsessionの更新は維持する。応答は入力順の`[{"accountId":"...","renewed":true,"viewAccepted":true,"operations":[]}]`。所有権が拒否されたaccountには`renewed:false`・`viewAccepted:false`・空operationsを返し、他accountの更新を妨げない。

`viewUnchanged:true`はview本文を省略し、`viewContentHash`へACK済みJSON全体のUTF-8 SHA-256を付ける。APIは保存viewのboot/account session/世代/version/fingerprint/編集可否と全体hashの一致を検証し、view本文を再保存せず`last_seen_utc`とsessionのsequence/期限だけ更新する。初回・再接続・位置や表示内容変更・hash不一致では全体viewが必要となる。lease検証をキャッシュで省略しない。

更新後の有効account sessionを再照合し、pendingを1 SQLで一括取得する。closed/expired session、差し替わったboot/世代、失効operationを配送しない。空pollでoperationのexpiry UPDATEを実行せず、Web照会・claim/保存の既存失効検証は維持する。claimは従来どおり別要求で再検証する。

Pluginはbulk HTTPを1要求に保ち、成功応答後のACK・claim・inflight解除をaccountごとの非同期taskで処理する。一方のclaim待機を他accountのACK・完了・次周期のrenewへ波及させない。重複claim抑制と、各accountのepoch/session照合は維持する。

Pluginは100tickの5秒周期を維持して10tick窓・最大32件にまとめる。通信中accountは次の周期へ保留する。停止・master公開開始で同期epochを進め、古い未送信capture/遅延ACKを採用しない。batch/ACKが404/405の旧APIでは従来のsession更新・全体view・pending経路へ戻り、1分後に追加経路を再確認する。最初の未対応検出時から旧経路はaccountごとの非同期taskで送信・ACK・失敗・inflight解除を行い、一方の遅延・500・timeoutで正常accountのrenewや次周期を止めない。他の権限拒否や通信障害はfallbackせず、次周期で再試行する。

- `accountSkillTreeStateId`: 保存済み行 ID。未保存状態は `null`
- `accountId`: 対象アカウント UUID
- `unlockedNodes`: 解放済みノード一覧
  - `nodeId`: filebase スキルツリーノード ID
  - `consumedClassId`: CP の消費元クラス ID。PP ノードは `null`
- `isSaved`: DB 保存済みなら `true`
- `version`: 保存済み行の更新バージョン。未保存状態は `0`
- `definitionGenerationId`: 検証済み世代。`null`はlegacy導入状態

## 保存リクエスト

- `unlockedNodes`: 保存する解放済みノードと CP 消費元クラスの一覧
- `updatedBy`: 監査用 UUID

## 構造不整合補修リクエスト

- `userId`: 補償メールを配信するアカウント所有ユーザー UUID
- `repairKey`: Plugin が現行のroot・配置済みnode ID・edgeから作る小文字 SHA-256。通信再試行時の二重配信を防止する
- `expectedVersion`: Plugin が構造不整合を判定したGET時点のスキルツリー状態version
- `expectedDefinitionGenerationId`: Pluginが構造不整合を判定した実ロード世代。現在stateと異なる場合は解除・補償をせず`409`
- `updatedBy`: 監査用 UUID

補修APIは、現在versionが`expectedVersion`と一致する場合だけスキルツリー状態を空の `unlockedNodes` へ置換し、同じ `(accountId, repairKey)` の配信済みメールがなければ、`skilltree_structure_reset_compensation` mailマスタを元にしたアカウント限定メールを `player_mail_delivery` へ同一トランザクションで追加します。version不一致は状態とメールを変更せず`409`を返します。同一キーの補修がすでに完了して空状態なら、古い`expectedVersion`による再試行も完了済み結果として扱い、メール再作成と状態更新を行いません。`userId` は所有者検証にだけ使用します。
空UUID、不正なSHA-256形式の`repairKey`、負の`expectedVersion`は`400`を返します。

## 補足

- スキルツリーノード定義は filebase `40_filebase/35.features.skilltree/nodes/*.json` を正本とする。
- 配置・接続構造は filebase `40_filebase/35.features.skilltree/structures/*.json` を正本とし、この API では扱わない。
- plugin は `GET` 結果をアカウント単位でメモリキャッシュし、ノード解放・解除クリックごとに同期通信しない。
- Pluginは進行状態の変更をdirtyとして保持し、既存player-state snapshotへ含めて保存する。旧PUTは未導入legacyだけの互換経路でありWebから呼ばない。
- CP 獲得量はクラスごとに `max(0, classLevel - 1)`、PP 獲得量は `max(0, max(playerLevel, highestLevel) - 1)` として導出する。残高自体は API / DB に保存しない。レベル訂正で現在レベルが下がっても最高到達レベル由来の獲得量を減らさない。
- generation付きstateへ旧`PUT`または旧player-state全置換を送ると`409`で拒否する。Plugin確定時だけsnapshot sectionのoperation receiptを同梱する。
- クラス条件付き CP ノードは条件クラスを `consumedClassId` とする。クラス条件のない CP ノードは解放 GUI で選択されたクラスを保存する。
- 解放済みskill effectはPluginが現在クラス条件を満たす場合だけ使用許可へ加える。再ロックまたは条件不一致で許可を失うが、習得個体・バインド値は削除しない。
- Plugin はプレイヤーデータロード時に、解放済みnodeが現在の定義・配置に存在し、rootから解放済みnodeだけを経由して全nodeへ到達できることを検証する。同一世代で不成立ならGET時のversionと参加権限を付けて補修APIを呼び、空状態だけをログインへ適用する。409競合時はGETからやり直して最新状態を再検証する。条件未達やポイント不足は一時的に効果を無効化する既存仕様のため、この補修条件には含めない。

## Runtimeの追加契約

runtime配下のPlugin登録・session・view・operationはPlugin/API間のruntime keyで保護する。定義確認と明示移行管理は別のmigration keyで保護する。editorのactor UUIDはWebの認証claimから設定し、APIが所有者照合する。

| HTTP | パス（`/api/skilltree`配下） | 契約 |
|:--|:--|:--|
| POST | `/runtime/servers/{serverId}/accounts/{accountId}/sessions` | server boot、account session ID、秘密token、実ロード世代で処理権限を取得/延長 |
| POST | `/runtime/servers/{serverId}/accounts/{accountId}/session-close` | 同じ権限と最終保存viewで退出を確定。古いcloseは新sessionを閉じない |
| GET | `/runtime/definitions/{generationId}` | 保管済み正規化snapshot取得。移行調査用 |
| GET | `/runtime/accounts/{accountId}/migration-state` | 管理用の保存世代・更新番号・解放集合取得 |
| POST | `/runtime/servers/{serverId}/accounts/{accountId}/migrations` | offline accountの明示移行preview/確定。自動修復と分離 |

server登録は`serverStartedAtUtc`、`publicationRevision`も比較する。遅延した旧boot/旧publicationの登録で新世代を上書きしない。runtime GETは保存済み`publicationRevision`も返す。Pluginはmaster再読込処理の完了ごとにrevisionを進めて再登録するため、定義世代IDが変わらない再読込も運用者が確認できる。個別activationの例外は警告扱いで再読込処理を継続するため、このrevisionは各activationの成功までは保証しない。viewは`accountSessionId`、`accountLeaseToken`、単調増加する`viewSequence`を持ち、過去の位置/残高通知を拒否する。

`GET /api/account-skilltree/{accountId}`は導入済みaccountに対して`X-SkillTree-Generation`、`X-SkillTree-Server`、`X-SkillTree-Boot`、`X-SkillTree-Account-Session`、`X-SkillTree-Account-Token`を要求する。世代不一致は409、状態は維持する。repairは同じ権限と`expectedDefinitionGenerationId`を要求し、導入済み非空legacyは修復せず明示移行へ送る。

`migrations`はoperation ID、from/to generation、expected state version、現在の全node ID baseline、remove node ID集合、`consumedClassAssignments`、`confirmLegacyBaseline`、`previewOnly`を取る。previewは未適用のWeb編集操作を取消さずに検証し、返還一覧を返す。確定は保存集合・世代・更新番号・移行結果台帳を同時保存し、対象accountの未適用の有効操作（`PENDING_ONLINE`、`PENDING_OFFLINE`、`CLAIMED`）を同じtransactionで`CANCELED`にする。offline、account session不在、保存状態などの検証に失敗した場合は取消さない。保持PP nodeの `playerLevel` 条件を完全に撤廃する変更だけ許可し、それ以外の保持nodeのコスト/条件変更、経路切断、CP返還先廃止は拒否する。新node追加や既存のCP消費元付替えをこのAPIで行わない。`consumedClassAssignments`は保存済み消費元がnullのCPノードに限り、旧新両定義の固定`unlockCondition.classId`と一致し、移行先class snapshotに存在する値だけを指定できる。previewでは保存行を変更せず、commit時に世代更新と同一transactionで補修する。既存値の上書き、PPノード、可変class条件、定義から一意に確定できない値は拒否する。

職業snapshotの比較は、対象ノードの消費元/返還先class IDの存続と固定class条件への適合に限定し、全職業定義の完全一致は要求しない。使用可能スキル・表示・能力などの変更や未参照職業の増減だけでは拒否しない。解放条件の表示専用 `classDisplayName` を比較対象から除外し、PP nodeの正の `playerLevel` を0へ完全に撤廃する変更だけ許可する。`classId`・未知の追加条件項目、CP nodeの `playerLevel`、PP nodeの条件追加や別の正値への変更は一致を要求する。node/経路・offline・保存状態・冪等性の検証は維持する。各検証の意図は [[20_5.00-安全編集の導入と検証#互換性の判定範囲]] を参照する。

定義確認、migration state、単体移行、runtime GET、候補取得、一括移行は`X-SkillTree-Migration-Key`を要求する。正本はAPIの`SkillTreeRuntime:MigrationKey`であり、Plugin用`SkillTreeRuntime:Key`および共通APIキーと同じ値は認証しない。Pluginのregister、heartbeat、session、view、operation処理は従来どおりruntime keyを使用し、世代移行の管理権限を持たない。

一括移行は単体移行の安全境界を変更しない。`migration-candidates`は`server_session_id`、`to_generation_id`、1始まりの`page`、1～500の`page_size`を取り、移行先runtimeがreadyかつ応答中で、sessionと世代が一致する場合だけ候補を返す。現在世代と異なる保存状態、および解放nodeを持つ世代未設定legacy状態を対象とする。世代未設定かつ解放nodeが空の状態はPlugin参加時に自動bindされるため除外する。候補応答にはaccount/user、元世代、state version、全解放node baselineを含む。候補取得後に状態が変わり得るため、候補応答だけで移行可否を保証しない。

`migrations/batch`は`server_session_id`と、`mode = PREVIEW | COMMIT`、1～100件の`items`を取る。各itemはaccount IDと既存`SkillTreeMigrationRequest`を持ち、account IDとoperation IDはbatch内で重複不可とする。APIはmodeを全itemの`previewOnly`へ適用し、入力順に既存の単体移行を逐次実行する。各accountは個別のserializable transaction、offline/session、state version、世代、baseline、snapshot互換性、冪等台帳を再検証する。未適用の有効操作はPREVIEWを妨げず、COMMIT時に世代更新と同時に取消す。1件の拒否で先行成功をrollbackせず、後続を継続してaccount別に`PREVIEW`、`APPLIED`、`REJECTED`を返す。同じoperation IDと同じcommit入力の再送は保存済み結果を返し、versionや返還を二重適用しない。

page、page size、mode、件数、必須ID、hash形式、baseline/remove重複、batch内account/operation ID重複、移行先世代混在など、処理開始前に判定できる入力不正は`400`とし、1件も適用しない。開始時runtime/session/世代の不一致は`409`、個別accountのoffline/session/state/version/baseline/snapshot条件不一致はHTTP `200`内の`REJECTED`として返す。

CP/PPは獲得量から解放nodeの消費分を引いて導出するため、明示除去による返還はnode消費分の除去として反映し、別の残高加算を行わない。Goldは変更しない。

## Runtimeセッションの排他

Runtimeのsession取得・更新・close・view公開とplayer-state保存権限確認では、account行の更新ロックを排他境界にする。SQL Serverのsession読取だけは`READCOMMITTEDLOCK`を使用して共有範囲ロックを文終了時に解放し、異なるaccountの更新とのデッドロックを防ぐ。runtimeのboot fence、45秒のsession有効期限、view sequence、旧session拒否条件は維持する。

管理編集時はuser行をaccountより先に直列化し、新規session取得を拒否する。未退避DRAINING/RECOVERY_REQUIREDの最終player-stateと初回session-closeだけ、captureされたRPG boot・開始前の未閉鎖session・token・保存世代を照合して通常期限後も完了できる。READY/APPLYINGではこの例外を許可しない。閉鎖済みの同一account/server/boot/session/tokenへのclose再送は読み取り専用成功とし、新view保存やsnapshot ACKを意味しない。詳細は[[40_0.00-概要]]を参照する。

## BATCH契約

operations POSTの`action=BATCH`、`nodeId=batch`、`changes[{action,nodeId,sourceClassId}]`が複数編集形式。changesは順序を持つ1〜512要素で、actionはUNLOCK/RELOCKだけ、同じnode IDを複数回含めない。費用/残高/条件結果は入力として採用しない。request hashはchanges全体を含む。同じoperation IDで内容を変えた再送は拒否する。GET/claim responseにもchangesを返す。

BATCHの受付とclaimはv2 runtimeのみ。editorの`supportsBatch`でWebへ互換性を通知する。v1は従来単件を継続できる。APPLIED receiptは全node変更と合計Goldを一つのplayer-state transactionで保存し、skilltree版数は一回だけ増える。途中成功のstatusは作らない。

DB更新は従来のsafe_editor migrationに続き`20260921_skilltree_batch_editor.sql`を適用する。API→Plugin→Webの順に更新し、既存player stateの移行は不要。旧Webの単件操作は新API/Pluginでも維持する。

## ログイン時のパッチ適用

`POST /api/skilltree/runtime/servers/{serverId}/patches/publish?server_session_id={boot}` はmigration専用キーで公開する。bodyは `{ "definitionGenerationId": "<64桁hash>" }`、200応答は `{ "definitionGenerationId": "<同じhash>", "patchVersion": 1 }`。readyな実ロード世代・起動sessionの一致を検証し、採番はDB上で直列化する。既公開世代には同じ番号を返し、プレイヤーデータは読み書きしない。古い未公開世代の再採番、起動session不一致、非readyは409。

`POST /api/skilltree/runtime/servers/{serverId}/accounts/{accountId}/login-patch` は通常APIキーとruntime専用キーを使用する。bodyは `serverSessionId`、`accountSessionId`、`accountLeaseToken`、`definitionGenerationId`、`apply`（既定false）、`expectedStateVersion`（apply時は直前の応答値）、`removeNodeIds`（apply時はpreviewの`removedNodeIds`をそのまま指定）。有効な所有session・対象世代・view sequenceが0の参加前状態を検証する。通常のログイン後に再利用できない。

200応答は `{ "status": "UPDATE_REQUIRED", "definitionGenerationId": "<移行先hash>", "patchVersion": 2, "stateVersion": 1, "removedNodeIds": [], "refunds": [] }`。statusは次のとおり。

| status | 処理 |
|---|---|
| CURRENT | 同世代、または世代未設定の空状態。変更せず通常ロードへ進む |
| UPDATE_REQUIRED | より新しい公開済み定義へ移行可能。Pluginは解除対象数を通知してパッチ適用中表示に切り替え、previewの解除集合をapply=trueで明示する |
| APPLIED | 世代とstate versionを原子的に更新済み。通常GETで読み直す |
| CHANNEL_OUTDATED | 保存世代の公開番号が参加先以上。進行を変えず参加拒否 |
| UNPUBLISHED | 参加先の定義が未公開。参加保留 |
| INCOMPATIBLE | 取得済みnode、コスト、許可されたPP必要レベル撤廃を除く条件、消費元、連結を維持できず、下記の限定解除でも安全に移行できない。別途管理移行が必要 |
| LEGACY_REQUIRES_REPAIR | 元世代不明の非空状態、または元世代が未公開。管理者による確認が必要 |

認証不備は401、入力形式不備は400、所有権・boot・有効期限・期待version・解除集合の不一致は409。previewは進行を変更しない。通常の保持検証に失敗した場合だけ、旧保存集合が旧定義で正常か確認し、新定義で定義または配置が削除された取得済みnodeと、孤立した取得済みnodeのうち自身の接続が変更されたものを解除候補にする。新定義のrootの定義・配置・取得状態は必須とし、旧定義のrootも自動解除しない。廃止nodeを経由して残るnodeへ到達したことにはしない。候補以外の孤立nodeや条件変更などが残ればINCOMPATIBLEとする。候補除去後の連結・消費元・返還先を再検証し、解除nodeのCP/PP返還を`refunds`に示す。applyはaccount行ロックの下で候補と明示集合を再検証し、対象nodeの解除と世代・version更新、未適用編集の取消、旧view削除、account session IDをoperation IDとする移行台帳を同一transactionで保存する。同じ要求の再送や再ログインで既に現世代ならCURRENTとなり二重更新しない。通常ロードの世代・保存権限検証は緩和しない。
