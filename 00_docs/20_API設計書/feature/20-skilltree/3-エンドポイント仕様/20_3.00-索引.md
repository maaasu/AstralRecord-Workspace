# 20_3.00-索引

`account-skilltree` API のエンドポイント仕様をまとめる。

## 一覧

| HTTPメソッド | パス | 概要 |
|:--|:--|:--|
| GET | `/api/account-skilltree/{accountId}` | アカウント単位のスキルツリー進行取得 |
| PUT | `/api/account-skilltree/{accountId}` | アカウント単位のスキルツリー進行保存 |
| POST | `/api/account-skilltree/{accountId}/repair-invalid-state` | Plugin が検出した構造不整合を全解除し、対象ユーザーへ補償メールを配信 |

## レスポンスモデル

- `accountSkillTreeStateId`: 保存済み行 ID。未保存状態は `null`
- `accountId`: 対象アカウント UUID
- `unlockedNodes`: 解放済みノード一覧
  - `nodeId`: filebase スキルツリーノード ID
  - `consumedClassId`: CP の消費元クラス ID。PP ノードは `null`
- `isSaved`: DB 保存済みなら `true`
- `version`: 保存済み行の更新バージョン。未保存状態は `0`

## 保存リクエスト

- `unlockedNodes`: 保存する解放済みノードと CP 消費元クラスの一覧
- `updatedBy`: 監査用 UUID

## 構造不整合補修リクエスト

- `userId`: 補償メールを配信するアカウント所有ユーザー UUID
- `repairKey`: Plugin が現行のroot・配置済みnode ID・edgeから作る小文字 SHA-256。通信再試行時の二重配信を防止する
- `updatedBy`: 監査用 UUID

補修APIは、スキルツリー状態を空の `unlockedNodes` へ置換し、同じ `(accountId, repairKey)` の配信済みメールがなければ、`skilltree_structure_reset_compensation` mailマスタを元にしたアカウント限定メールを `player_mail_delivery` へ同一トランザクションで追加します。配信済みならメールは再作成せず、すでに空状態なら状態更新もしません。`userId` は所有者検証にだけ使用します。

## 補足

- スキルツリーノード定義は filebase `40_filebase/35.features.skilltree/nodes/*.json` を正本とする。
- 配置・接続構造は filebase `40_filebase/35.features.skilltree/structures/*.json` を正本とし、この API では扱わない。
- plugin は `GET` 結果をアカウント単位でメモリキャッシュし、ノード解放・解除クリックごとに同期通信しない。
- plugin は進行状態の変更を dirty として保持し、`PUT` には `unlockedNodes` をまとめて非同期保存する。
- CP 獲得量はクラスごとに `max(0, classLevel - 1)`、PP 獲得量は `max(0, playerLevel - 1)` として導出する。残高自体は API / DB に保存しない。
- クラス条件付き CP ノードは条件クラスを `consumedClassId` とする。クラス条件のない CP ノードは解放 GUI で選択されたクラスを保存する。
- 解放済みskill effectはPluginが現在クラス条件を満たす場合だけ使用許可へ加える。再ロックまたは条件不一致で許可を失うが、習得個体・バインド値は削除しない。
- Plugin はプレイヤーデータロード時に、解放済みnodeが現在の定義・配置に存在し、rootから解放済みnodeだけを経由して全nodeへ到達できることを検証する。不成立なら補修APIを呼び、空状態だけをログインへ適用する。条件未達やポイント不足は一時的に効果を無効化する既存仕様のため、この補修条件には含めない。
