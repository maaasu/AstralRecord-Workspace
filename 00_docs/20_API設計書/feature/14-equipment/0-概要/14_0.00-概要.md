# 14_0.00-概要

## 1. 目的

装備の個体動的データを管理する。YAML マスタ（[[04_README]]）と組み合わせて以下を提供する。

- 装備インスタンスの作成・取得
- オーブによる強化・修理・状態変化・エンチャント、ルーン装着
- 装備プリセット（ロードアウト）の管理

## 2. 用語

- 装備インスタンス: `dbo.equipment_instance` レコード（個体）
- 状態変化（transcendence）: `transcendenceRank` を上げ、有効な強化上限・エンチャント枠・ルーン枠を切り替える
- 共通エンチャントマスタ: `master_type = 'enchant'` のYAML定義。`WEAPON` / `ARMOR` / `ACCESSORY` ごとに `effectId` 付き候補と重みを持つ
- エンチャントスロット: 装備側は `maxSlots` だけを定義し、付与済みレコードを `slotIndex` で管理する。同じ装備に同じ `effectId` は重複不可
- ルーンスロット: 装備個体に紐付くルーン装着スロット（最大数は YAML/状態変化に依存）
- ロードアウト: 装備プリセット（`GAME` / `ADMIN` の用途別）
- オーブ操作台帳: `operationId` ごとに支払い・抽選・装備更新の確定結果を保存し、再送時に同じ結果を返す `dbo.equipment_orb_operation`

## 3. 構成要素

- `Controllers/EquipmentController`: インスタンス・操作系
- `Controllers/EnchantController`: 共通エンチャントマスタ取得
- `Controllers/EquipmentLoadoutController`: ロードアウト系
- `Repositories/EquipmentRepository` / `EquipmentOrbOperationRepository` / `EquipmentLoadoutRepository`
- 関連エンティティ: `EquipmentInstance`, `EquipmentInstanceEnchant`, `EquipmentInstanceRune`, `EquipmentInstanceStatRoll`, `EquipmentLoadout`, `EquipmentLoadoutSlot`。旧 `EquipmentInstanceEnchantPool` は使用しない

## 4. ロードアウトのペイロードルール

- 同一アカウントの `equipmentInstanceId` のみ登録できる
- 同一プリセット内では同じ `slotType` + `slotIndex` を重複登録できない
- 同一プリセット内では同じ `equipmentInstanceId` を複数スロットへ登録できない
- 同じ `equipmentInstanceId` を複数のプリセットへ登録することは許可する
- `activate` は同一 `accountId` + `loadoutProfile` の他プリセットを無効化する
