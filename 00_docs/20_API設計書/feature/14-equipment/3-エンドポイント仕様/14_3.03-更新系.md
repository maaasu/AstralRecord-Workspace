# 14_3.03-更新系

## 1. 更新系エンドポイント仕様

### プリセット更新

HTTPメソッド: `PUT`
パス: `/api/equipment/loadouts/{loadoutId}`
コントローラ: `EquipmentLoadoutController`
アクション物理名: `UpdateLoadout`

リクエスト:

| 種別 | 名前 | 型 | 必須 | 説明 |
|---|---|---|---|---|
| Header | `X-Api-Key` | string | ✓ | API キー |
| Header | `Content-Type` | string | ✓ | `application/json` |
| Path | `loadoutId` | GUID | ✓ | 更新対象UUID |
| Body | (全体) | [[14_1.00-モデル定義]].4.3 ロードアウト更新リクエスト | ✓ | 更新内容 |

レスポンス:

| ステータス | 内容 | ボディ |
|---|---|---|
| 200 OK | 更新成功 | [[14_1.00-モデル定義]].ロードアウトレスポンス |
| 400 Bad Request | バリデーション失敗 | エラーオブジェクト |
| 401 Unauthorized | API キー未指定/無効 | なし |
| 404 Not Found | 未登録/論理削除済み | なし |

処理内容:

1. 認証検証
2. `loadoutProfile` 指定時は `GAME` または `ADMIN` を検証し、`loadoutName` 指定時は空白を拒否する。違反時は 400 を返す
3. 対象プリセットを取得し、未存在または論理削除済みなら 404 を返す
4. 非 null 項目のみ反映して 200 を返す

---

### スロット登録/更新

HTTPメソッド: `PUT`
パス: `/api/equipment/loadouts/{loadoutId}/slots`
コントローラ: `EquipmentLoadoutController`
アクション物理名: `UpsertSlot`

リクエスト:

| 種別 | 名前 | 型 | 必須 | 説明 |
|---|---|---|---|---|
| Header | `X-Api-Key` | string | ✓ | API キー |
| Header | `Content-Type` | string | ✓ | `application/json` |
| Path | `loadoutId` | GUID | ✓ | 対象プリセットUUID |
| Body | (全体) | [[14_1.00-モデル定義]].4.4 スロット登録/更新リクエスト | ✓ | 登録内容 |

レスポンス:

| ステータス | 内容 | ボディ |
|---|---|---|
| 200 OK | 登録/更新成功 | [[14_1.00-モデル定義]].ロードアウトレスポンス |
| 400 Bad Request | ペイロードルール違反 | エラーオブジェクト |
| 401 Unauthorized | API キー未指定/無効 | なし |
| 404 Not Found | プリセット or 装備個体未登録 | なし |

処理内容:

1. 認証検証
2. プリセット取得（未存在は 404）
3. ペイロードルール検証

    | 項目 | 内容 |
    |---|---|
    | 同一アカウント | 装備個体の `accountId` がプリセットの `accountId` と一致 |
    | 同一プリセット内ユニーク | 同じ `slotType` + `slotIndex` の重複不可 |
    | 同一プリセット内ユニーク | 同じ `equipmentInstanceId` を複数スロットへ登録不可 |
    | 違反時 | 400 を返す |

4. 既存スロットがあれば更新、無ければ作成（upsert）
5. 200 で返す
