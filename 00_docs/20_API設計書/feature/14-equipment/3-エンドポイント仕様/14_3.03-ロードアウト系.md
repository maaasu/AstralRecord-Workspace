# 14_3.03-ロードアウト系

装備プリセット（`dbo.equipment_loadout` / `dbo.equipment_loadout_slot`）を扱う。  
ペイロードルールは [[14_0.00-概要]].4 を参照。

## 1. プリセット一覧取得

HTTPメソッド: `GET`
パス: `/api/equipment/loadouts?account_id={accountId}&loadout_profile={profile}`
コントローラ: `EquipmentLoadoutController`
アクション物理名: `ListLoadouts`

リクエスト:

| 種別 | 名前 | 型 | 必須 | 説明 |
|---|---|---|---|---|
| Header | `X-Api-Key` | string | ✓ | API キー |
| Query | `account_id` | GUID | ✓ | アカウントUUID |
| Query | `loadout_profile` | string | ✓ | `GAME` / `BUILDER` |

レスポンス:

| ステータス | 内容 | ボディ |
|---|---|---|
| 200 OK | 取得成功 | [[14_1.00-モデル定義]].ロードアウトレスポンス の配列 |
| 400 Bad Request | クエリ欠落/不正 | エラーオブジェクト |
| 401 Unauthorized | API キー未指定/無効 | なし |

## 3. プリセット作成

HTTPメソッド: `POST`
パス: `/api/equipment/loadouts`
コントローラ: `EquipmentLoadoutController`
アクション物理名: `CreateLoadout`

リクエスト:

| 種別 | 名前 | 型 | 必須 | 説明 |
|---|---|---|---|---|
| Header | `X-Api-Key` | string | ✓ | API キー |
| Header | `Content-Type` | string | ✓ | `application/json` |
| Body | (全体) | [[14_1.00-モデル定義]].4.2 ロードアウト登録リクエスト | ✓ | 登録対象 |

レスポンス:

| ステータス | 内容 | ボディ |
|---|---|---|

| 400 Bad Request | バリデーション失敗 | エラーオブジェクト |

1. 認証検証

5. 201 で返す

## 6. プリセット有効化

HTTPメソッド: `POST`
パス: `/api/equipment/loadouts/{loadoutId}/activate`
コントローラ: `EquipmentLoadoutController`
アクション物理名: `ActivateLoadout`

責務:

指定プリセットを `isActive = true` にし、同一 `accountId` + `loadoutProfile` の他プリセットを `isActive = false` にする。

リクエスト:

| 種別 | 名前 | 型 | 必須 | 説明 |
|---|---|---|---|---|
| Header | `X-Api-Key` | string | ✓ | API キー |
| Path | `loadoutId` | GUID | ✓ | 対象プリセットUUID |
| Body | `updatedBy` | GUID | ✓ | 更新実行者UUID |

レスポンス:

| ステータス | 内容 | ボディ |
|---|---|---|
| 200 OK | 有効化成功 | [[14_1.00-モデル定義]].ロードアウトレスポンス |
| 401 Unauthorized | API キー未指定/無効 | なし |
| 404 Not Found | 未登録/論理削除済み | なし |

処理内容:

1. 認証検証
2. 対象プリセット取得（未存在は 404）
3. 同 `accountId` + `loadoutProfile` の他プリセットを `isActive = false` に一括更新（トランザクション）
4. 対象を `isActive = true` に更新
5. 200 で返す

## 8. スロット登録/更新

HTTPメソッド: `PUT`
パス: `/api/equipment/loadouts/{loadoutId}/slots`
コントローラ: `EquipmentLoadoutController`
アクション物理名: `UpsertSlot`

リクエスト:

| 種別 | 名前 | 型 | 必須 | 説明 |
|---|---|---|---|---|
| Header | `X-Api-Key` | string | ✓ | API キー |
| Header | `Content-Type` | string | ✓ | `application/json` |
| Path | `loadoutId` | GUID | ✓ | 対象プリセットUUID |
| Body | (全体) | [[14_1.00-モデル定義]].4.4 スロット登録/更新リクエスト | ✓ | 登録内容 |

レスポンス:

| ステータス | 内容 | ボディ |
|---|---|---|
| 200 OK | 登録/更新成功 | [[14_1.00-モデル定義]].ロードアウトレスポンス |
| 400 Bad Request | ペイロードルール違反 | エラーオブジェクト |
| 401 Unauthorized | API キー未指定/無効 | なし |
| 404 Not Found | プリセット or 装備個体未登録 | なし |

処理内容:

1. 認証検証
2. プリセット取得（未存在は 404）
3. ペイロードルール検証

    | 項目 | 内容 |
    |---|---|
    | 同一アカウント | 装備個体の `accountId` がプリセットの `accountId` と一致 |
    | 同一プリセット内ユニーク | 同じ `slotType` + `slotIndex` の重複不可 |
    | 同一プリセット内ユニーク | 同じ `equipmentInstanceId` を複数スロットへ登録不可 |
    | 違反時 | 400 を返す |

4. 既存スロットがあれば更新、無ければ作成（upsert）
5. 200 で返す
