# 14_3.02-登録系

## 1. 登録系エンドポイント仕様

### 装備インスタンス作成

HTTPメソッド: `POST`
パス: `/api/equipment/instances`
コントローラ: `EquipmentController`
アクション物理名: `CreateInstance`

責務:

MasterDataDB の `item` マスタの装備定義をもとに装備個体を生成して保存する。
ステータス乱数ロールは作成時に実値へ解決され、レスポンスには現在のエンチャント一覧も含まれる。

リクエスト:

| 種別 | 名前 | 型 | 必須 | 説明 |
|---|---|---|---|---|
| Header | `X-Api-Key` | string | ✓ | API キー |
| Header | `Content-Type` | string | ✓ | `application/json` |
| Body | (全体) | [[14_1.00-モデル定義]].装備インスタンス作成リクエスト | ✓ | 生成内容 |

レスポンス:

| ステータス | 内容 | ボディ |
|---|---|---|
| 201 Created | 作成成功 | [[14_1.00-モデル定義]].装備インスタンスレスポンス |
| 400 Bad Request | バリデーション失敗 | エラーオブジェクト |
| 401 Unauthorized | API キー未指定/無効 | なし |
| 404 Not Found | `accountId` または `equipmentId` が未存在 | なし |

処理内容:

1. 認証パイプラインで `X-Api-Key` を検証する
2. リクエストのバリデーション（必須項目）
3. `accountId` の存在確認

    | 項目 | 内容 |
    |---|---|
    | 検索対象 | `dbo.account`（`is_deleted = 0`） |
    | 未存在 | 404 を返す |

4. `equipmentId` の存在確認

    | 項目 | 内容 |
    |---|---|
    | 検索対象 | MasterDataDB の `master_data_entry`（`master_type = 'item'`） |
    | 未存在 | 404 を返す |

5. 装備個体を生成

    | 項目 | 内容 |
    |---|---|
    | `equipmentInstanceId` | `Guid.NewGuid()` |
    | `enhanceLevel` | 0 |
    | `transcendenceRank` | 0 |
    | `runeMaxSlots` | item マスタの `equipment.rune.maxSlots` を解決した値 |
    | `durabilityMax` / `durabilityValue` | item マスタの `durability.max` |
    | `statRolls` | item マスタの `stats[]` の `value` を範囲指定なら乱数解決、固定なら固定値で確定 |

6. 生成結果を 201 で返す
7. 例外時は [[14_5.00-例外・ログ・運用]].インスタンス系 のログを記録し 500 を返す

### エンチャント実施

HTTPメソッド: `POST`
パス: `/api/equipment/enchant`
コントローラ: `EquipmentController`
アクション物理名: `Enchant`

責務:

指定 `poolIndex` のプールから重み付き抽選で 1 エントリを選び、装備へエンチャントを付与する。
空きスロットがあればそこを使用し、上限到達時は既存エンチャントをランダムに 1 件上書きする。

リクエスト:

| 種別 | 名前 | 型 | 必須 | 説明 |
|---|---|---|---|---|
| Header | `X-Api-Key` | string | ✓ | API キー |
| Header | `Content-Type` | string | ✓ | `application/json` |
| Body | (全体) | [[14_1.00-モデル定義]].3.1 エンチャント実施 | ✓ | 実行内容 |

レスポンス:

| ステータス | 内容 | ボディ |
|---|---|---|
| 200 OK | 実施成功 | [[14_1.00-モデル定義]].装備インスタンスレスポンス（更新後） |
| 400 Bad Request | バリデーション失敗 | エラーオブジェクト |
| 401 Unauthorized | API キー未指定/無効 | なし |
| 404 Not Found | 装備個体未存在 / 指定 `poolIndex` がマスタ未定義 | なし |

処理内容:

1. 認証パイプラインで `X-Api-Key` を検証する
2. 装備個体を取得（[[14_3.01-取得系]].装備インスタンス取得 と同等）

    | 項目 | 内容 |
    |---|---|
    | 未存在 | 404 を返す |

3. MasterDataDB の `item` マスタから対象プールを解決

    | 項目 | 内容 |
    |---|---|
    | プール選択 | `poolIndex` に対応するエントリ集合 |
    | 抽選方式 | `weight` による重み付き抽選 |
    | 値の確定 | エントリの `value` が範囲なら乱数解決、固定なら固定値 |

4. スロット割り当て

    | 項目 | 内容 |
    |---|---|
    | 空きスロットあり | 未使用 `slotIndex` を使用 |
    | 上限到達 | 既存のエンチャントから 1 件をランダム選択し上書き |

5. 装備の `updatedBy` / `updatedAt` を更新し、更新後のレスポンスを 200 で返す
6. 例外時は [[14_5.00-例外・ログ・運用]].操作系 のログを記録し 500 を返す

### 強化実施

HTTPメソッド: `POST`
パス: `/api/equipment/enhance`
コントローラ: `EquipmentController`
アクション物理名: `Enhance`

責務:

装備を 1 段階、または指定レベルまで強化する。

リクエスト:

| 種別 | 名前 | 型 | 必須 | 説明 |
|---|---|---|---|---|
| Header | `X-Api-Key` | string | ✓ | API キー |
| Header | `Content-Type` | string | ✓ | `application/json` |
| Body | (全体) | [[14_1.00-モデル定義]].3.3 強化実施 | ✓ | 強化指示 |

レスポンス:

| ステータス | 内容 | ボディ |
|---|---|---|
| 200 OK | 強化成功 | [[14_1.00-モデル定義]].装備インスタンスレスポンス（更新後） |
| 400 Bad Request | `targetLevel` が現在値以下、最大値超過 | エラーオブジェクト |
| 401 Unauthorized | API キー未指定/無効 | なし |
| 404 Not Found | 装備個体未存在 | なし |

処理内容:

1. 認証検証
2. 装備個体取得（未存在は 404）
3. 強化上限の解決

    | 項目 | 内容 |
    |---|---|
    | 上限 | item マスタの `equipment.enhance.maxLevel`（`transcendenceRank` に応じて override） |
    | バリデーション | `targetLevel > 現在値 && targetLevel <= 上限` でなければ 400 |

4. 各レベルの `statIncrease`, `durabilityBonus` を反映
5. 更新後レスポンスを 200 で返す

### 状態変化実施

HTTPメソッド: `POST`
パス: `/api/equipment/transcendence`
コントローラ: `EquipmentController`
アクション物理名: `Transcend`

責務:

装備を次の状態変化ランク、または指定ランクへ更新する。
`targetRank` は現在の `transcendenceRank` より大きい値を指定する。

リクエスト:

| 種別 | 名前 | 型 | 必須 | 説明 |
|---|---|---|---|---|
| Header | `X-Api-Key` | string | ✓ | API キー |
| Header | `Content-Type` | string | ✓ | `application/json` |
| Body | (全体) | [[14_1.00-モデル定義]].3.4 状態変化実施 | ✓ | 状態変化指示 |

レスポンス:

| ステータス | 内容 | ボディ |
|---|---|---|
| 200 OK | 実施成功 | [[14_1.00-モデル定義]].装備インスタンスレスポンス（更新後） |
| 400 Bad Request | `targetRank` 不正（現在値以下、定義超過） | エラーオブジェクト |
| 401 Unauthorized | API キー未指定/無効 | なし |
| 404 Not Found | 装備個体未存在 | なし |

処理内容:

1. 認証検証
2. 装備個体取得（未存在は 404）
3. `targetRank` の妥当性検証

    | 項目 | 内容 |
    |---|---|
    | 条件 | `targetRank > 現在値` かつ item マスタの `equipment.transcendence[].rank` に定義あり |
    | 違反時 | 400 を返す |

4. `equipment.transcendence[].overrides` を適用し、`runeMaxSlots`, 強化上限等を再計算
5. 更新後レスポンスを 200 で返す

### ルーン装着

HTTPメソッド: `POST`
パス: `/api/equipment/rune`
コントローラ: `EquipmentController`
アクション物理名: `EquipRune`

責務:

ルーンを装着する。`slotIndex` 未指定時は空きスロットへ自動装着し、指定時はそのスロットを更新する。

リクエスト:

| 種別 | 名前 | 型 | 必須 | 説明 |
|---|---|---|---|---|
| Header | `X-Api-Key` | string | ✓ | API キー |
| Header | `Content-Type` | string | ✓ | `application/json` |
| Body | (全体) | [[14_1.00-モデル定義]].3.5 ルーン装着 | ✓ | 装着内容 |

レスポンス:

| ステータス | 内容 | ボディ |
|---|---|---|
| 200 OK | 装着成功 | [[14_1.00-モデル定義]].装備インスタンスレスポンス（更新後） |
| 400 Bad Request | `slotIndex` が範囲外 / ルーン要件未達 | エラーオブジェクト |
| 401 Unauthorized | API キー未指定/無効 | なし |
| 404 Not Found | 装備個体 or ルーン個体未存在 | なし |

処理内容:

1. 認証検証
2. 装備個体・ルーン個体（[[15_README]]）の取得（未存在は 404）
3. ルーン要件の検証

    | 項目 | 内容 |
    |---|---|
    | `targetSlots` | 装備の `equipment.slot` が許可リストに含まれるか |
    | `requiredEnhanceLevel` | 装備の `enhanceLevel` がルーン要求を満たすか |
    | `allowedRuneIds` | 装備側ホワイトリストに ruleItemId が含まれるか（空なら無制限） |
    | 違反時 | 400 を返す |

4. スロット選択

    | 項目 | 内容 |
    |---|---|
    | `slotIndex` 指定あり | そのスロットを上書き |
    | `slotIndex` 未指定 | 0 〜 `runeMaxSlots - 1` の最小空きを使用 |
    | 空き無し（未指定時） | 400 を返す |

5. 装着レコードを upsert し、更新後レスポンスを 200 で返す

### プリセット有効化

HTTPメソッド: `POST`
パス: `/api/equipment/loadouts/{loadoutId}/activate`
コントローラ: `EquipmentLoadoutController`
アクション物理名: `ActivateLoadout`

責務:

指定プリセットを `isActive = true` にし、同一 `accountId` + `loadoutProfile` の他プリセットを `isActive = false` にする。

リクエスト:

| 種別 | 名前 | 型 | 必須 | 説明 |
|---|---|---|---|---|
| Header | `X-Api-Key` | string | ✓ | API キー |
| Path | `loadoutId` | GUID | ✓ | 対象プリセットUUID |
| Body | `updatedBy` | GUID | ✓ | 更新実行者UUID |

レスポンス:

| ステータス | 内容 | ボディ |
|---|---|---|
| 200 OK | 有効化成功 | [[14_1.00-モデル定義]].ロードアウトレスポンス |
| 401 Unauthorized | API キー未指定/無効 | なし |
| 404 Not Found | 未登録/論理削除済み | なし |

処理内容:

1. 認証検証
2. 対象プリセット取得（未存在は 404）
3. 同 `accountId` + `loadoutProfile` の他プリセットを `isActive = false` に一括更新（トランザクション）
4. 対象を `isActive = true` に更新
5. 200 で返す
