# 14_5.00-例外・ログ・運用

ログ・メッセージはハードコーディング。LogId は使用しない。

## 1. 共通エラーレスポンス

| ステータス | 発生条件 | ボディ |
|---|---|---|
| 401 Unauthorized | API キー未指定/無効 | なし |
| 400 Bad Request | バリデーション失敗 / ペイロードルール違反 | `ProblemDetails` 互換 |
| 404 Not Found | 装備個体 / プリセット / 関連リソース未存在 | なし |
| 500 Internal Server Error | 上記以外の例外 | `ProblemDetails` 互換 |

### 2.2 操作系

`EquipmentController` / `EquipmentService` は専用loggerを注入していない。未処理例外は共通ASP.NET Core例外パイプラインへ渡す。
オーブの `NOT_ELIGIBLE` / `PAYMENT_UNAVAILABLE` / `NO_SLOT` / `NO_CANDIDATE` と、同じoperationIdのreplayは正常な200業務結果でありエラー扱いにしない。request hash不一致の `OPERATION_CONFLICT` は409で返す。

## 3. 運用上の注意

- 状態変化・強化・修理・エンチャントのオーブ操作とルーン装着は DB と YAML マスタの整合性に依存する。
  YAML 改修時は装備個体の整合性検証（既存個体への影響）も検討する。
- オーブ操作ではAPIが所有・現在配置・支払いを再検証し、成功抽選と `failAction`（`NONE` / `SET_LEVEL` / `DECREASE_ONE`）を一度だけ決定する。Pluginから目標値・抽選結果を受け付けない。
- `operationId` の同一requestは `dbo.equipment_orb_operation` の保存済み業務結果を再生する。対象を台帳accountが現在も所有しGAME BAG/HOTBARまたはactive loadoutに保持する場合だけ `targetAvailable=true` と現在の `equipment` を返し、譲渡・削除・membership欠落時はfalse/nullとする。異なるrequest hashは409、通信結果不明時はGET照会または同一POST再送で確定し、Plugin側で支払いを推測して返却しない。
