# 13_0.00-概要

## 1. 目的

`dbo.inventory` / `dbo.inventory_entry` への CRUD 契約を提供する。
インベントリ本体（コンテナ）とエントリ（中身）を別レイヤーで扱う。

## 2. 用途分離

- `inventoryProfile` で用途を分離する（`GAME` / `ADMIN`）。API はこの 2 値以外を受理しない。
- `inventoryType` の妥当性は API 単体ではマスタ参照しないため、呼び出し元の定義と合わせて扱う。

## 3. ペイロードルール

- スタックアイテム: `itemId` を使用
- インスタンス系アイテム: `instanceType` + `instanceId` を使用
- 個体entryにも `itemId` を併記できる。APIは同一accountが所有する装備個体の正本item IDと照合し、未指定なら補完する。DBは旧個体行のNULLも許容する。
- `quantity` は 1 以上
- entry の登録・更新・論理削除・一括置換・補正では、影響する親 `inventory.updatedAt` も更新前の値より最低 1 millisecond 進める。一括置換で entry を inventory 間移動する場合は移動元と移動先の両方を進める。

## 4. 構成要素

- `Controllers/InventoryController`
- `Repositories/InventoryRepository`
- `Models/InventoryModels.cs` 内の各 DTO
