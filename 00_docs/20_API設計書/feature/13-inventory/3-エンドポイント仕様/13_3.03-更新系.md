# 13_3.03-更新系

## 1. 更新系エンドポイント仕様

### インベントリ更新

HTTPメソッド: `PUT`
パス: `/api/inventory/{inventoryId}`
コントローラ: `InventoryController`
アクション物理名: `UpdateInventory`

リクエスト:

| 種別 | 名前 | 型 | 必須 | 説明 |
|---|---|---|---|---|
| Header | `X-Api-Key` | string | ✓ | API キー |
| Header | `Content-Type` | string | ✓ | `application/json` |
| Path | `inventoryId` | GUID | ✓ | 更新対象UUID |
| Body | (全体) | [[13_1.00-モデル定義]].インベントリ更新リクエスト | ✓ | 更新内容 |

レスポンス:

| ステータス | 内容 | ボディ |
|---|---|---|
| 200 OK | 更新成功 | [[13_1.00-モデル定義]].インベントリレスポンス |
| 400 Bad Request | バリデーション失敗 | エラーオブジェクト |
| 401 Unauthorized | API キー未指定/無効 | なし |
| 404 Not Found | 未登録/論理削除済み | なし |

処理内容:

1. 認証パイプラインで `X-Api-Key` を検証する
2. リクエスト Body のバリデーション（`updatedBy` 必須。`inventoryProfile` 指定時は `GAME` または `ADMIN`）
3. 対象インベントリを取得（`is_deleted = 0`）。なければ 404
4. 非 null 項目のみ反映し `updatedBy` / `updatedAt` を更新する
5. 200 を返す
6. 例外時は [[13_5.00-例外・ログ・運用]].更新系 のログを記録し 500 を返す

### エントリ一括置換

HTTPメソッド: `PUT`
パス: `/api/inventory/{inventoryId}/entries`
コントローラ: `InventoryController`
アクション物理名: `ReplaceEntries`

リクエスト:

| 種別 | 名前 | 型 | 必須 | 説明 |
|---|---|---|---|---|
| Header | `X-Api-Key` | string | ✓ | API キー |
| Header | `Content-Type` | string | ✓ | `application/json` |
| Path | `inventoryId` | GUID | ✓ | 置換対象インベントリUUID |
| Body | (全体) | [[13_1.00-モデル定義]].インベントリエントリ一括置換リクエスト | ✓ | 置換後 entry 一覧 |

レスポンス:

| ステータス | 内容 | ボディ |
|---|---|---|
| 200 OK | 置換成功 | [[13_1.00-モデル定義]].インベントリエントリレスポンス配列 |
| 400 Bad Request | バリデーション失敗 | エラーオブジェクト |
| 401 Unauthorized | API キー未指定/無効 | なし |
| 404 Not Found | 対象インベントリ未登録/論理削除済み | なし |

処理内容:

1. 認証パイプラインで `X-Api-Key` を検証する
2. `entries` の各要素で `itemId` と `instanceType`/`instanceId` の排他、および `quantity >= 1` を検証する
3. 対象インベントリを取得（`is_deleted = 0`）。なければ 404
4. 対象インベントリ配下の有効 entry をすべて論理削除する
5. リクエストされた entry 一覧を新規作成する
6. 作成後の entry 配列を 200 で返す
7. 例外時は [[13_5.00-例外・ログ・運用]].更新系 のログを記録し 500 を返す
