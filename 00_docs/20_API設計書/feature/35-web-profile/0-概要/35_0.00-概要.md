# Webプロフィール概要

- APIキー認証は既存の全API境界を維持する。Webは認証済みセッションclaims由来の`viewer_user_uuid`だけを渡す。未ログインの公開閲覧はこのクエリを省略できる。
- APIは各要求でManagementDBの`web_admin`を再照会する。ゲーム側の`permission`はWeb管理権限として使わない。
- 公開設定の既定値は`false`。更新対象はviewer本人のManagementDBレコードだけである。
- 一般一覧・詳細は公開済みだけを返す。`include_private=true`はManagementDBの`web_admin=true`の場合だけ非公開・ゲーム未ログイン登録者を含む。
- 一覧は非削除ゲームアカウントを1行ずつ返す。通常は公開設定済みuser配下、`include_private=true`かつWeb管理者では非公開・Web未ログインuser配下も含める。アカウントを持たないuserは一覧に含めない。
- 詳細の既定アカウントは`dbo.user.account_id`で決める。`account_id`指定時は対象user所有の非削除アカウントだけを表示し、他userのIDは返さない。Webの表示切替はゲーム状態を更新しない。
- Mob図鑑は `GET /api/web-bestiary` と `GET /api/web-bestiary/{mobId}` で提供する。いずれも認証済みWebセッションclaims由来の`viewer_user_uuid`が必須で、本人所有の非削除アカウントだけを対象にする。管理者バイパスと公開プロフィールからの遷移は設けない。討伐済みだけを返し、詳細は未討伐・削除済み・他人のアカウント指定を404とする。
- Mobの標準レベルはPluginの`resolveLevel(null)`と同じく、`levels[]`がある場合は最小の有効レベルプロファイルを共通定義へ上書きして使う。討伐記録には撃破時のレベルを保存しない。表示ドロップから`hidden=true`は除外し、LootTableの中身・IDは返さず追加ドロップの有無だけを返す。
- 図鑑のドロップ参照は`itemId: { ref: "item:<ID>" }`を裸のアイテムIDへ正規化してマスターの名前・アイコンを取得する。旧形式の裸IDと`item:<ID>`文字列も受理し、応答の`itemId`は裸IDとする。`item:`以外の参照種別をアイテムへ読み替えない。有効マスターが存在しない場合だけ「未登録のアイテム」と代替アイコンを返す。
- スキルツリーはPlugin設定と同じ`starter`構造にあるノードだけを返す。ノード定義・座標・edgeはfilebase JSON、解放状態は選択アカウントの`account_skilltree_*`から読む。CPノードは現職・祖先職とプレイヤーレベルの条件を満たすものだけを返す。PPノードはゲーム内と同様に条件未達でも保持し、`isConditionMet` と `requirementText` で必要条件を表示する。

- 所持金はGAME/CURRENCYの有効な正数量エントリを既存`GoldCurrencyBalanceSupport.TotalGold`で額面換算する。99a00001〜07と旧Gold額面を共通処理し、参照によってインベントリを書き換えない。
- 一覧はアカウント概要とクラス名を一括取得し、ノードファイル・通貨・クラス進行の詳細は取得しない。詳細画面だけで選択アカウントのスキルツリーを合成する。

## 既存環境への反映

API更新前にManagementDBへ `table-definitions/ManagementDB/migrations/20260915_management_player_profile_visibility.sql` を適用する。既存行は非公開で初期化し、再実行と同時実行を保護する。新規DBは更新済みinit.sqlを使用する。

`WebPlayerProfile:SkillTreeStructureId` は既定 `starter`。Pluginの `skilltree.structureId` を変更した環境では同じ値に設定する。
