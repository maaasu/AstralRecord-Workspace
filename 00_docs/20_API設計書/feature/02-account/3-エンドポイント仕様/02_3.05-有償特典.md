# 02_3.05-有償特典

アカウント単位のVIP・インスタンス優先接続回数を管理する。account.modeはPLAYER/ADMINだけで、旧ユーザー権限DONORは使わない。

| HTTP | パス | Controller / Action |
|---|---|---|
| GET | `/api/account/{accountId}/benefits` | AccountBenefitsController.Get |
| POST | `/api/account/{accountId}/benefits/consume-item` | ConsumeItem |
| POST | `/api/account/{accountId}/benefits/consume-priority` | ConsumePriority |
| POST | `/api/account/{accountId}/benefits/refund-priority` | RefundPriority |
| POST | `/api/account/{accountId}/benefits/login` | Login |
| GET | `/api/web/vip-supporters` | Supporters |

全APIは既存共通APIキー認証を必要とする。不存在/削除アカウントは404、要求不正は400、operationIdの異なる要求への再利用は409。

## 要求・応答

POST共通要求は `{ "operationId": "GUID" }`。consume-itemは `inventoryEntryId: GUID` と `expectedUpdatedAt: datetime` を追加する。Pluginは既存外部取引mutation gate内でdirty inventoryをflushしてから呼び、返却された現在のinventorySnapshotを反映する。通信結果不明時は同じoperationId・同じ要求を再送する。新しいIDで再試行しない。

GET benefitsの例:

```json
{"accountId":"00000000-0000-0000-0000-000000000001","instancePriorityUses":5,"vipTier":"ASTRALDER","vipExpiresAt":"2026-10-16T00:00:00Z","donerExpiresAt":"2026-10-31T00:00:00Z","astralderExpiresAt":"2026-10-16T00:00:00Z","remainingDays":20,"astralderDailyCreditsRemaining":20}
```

POST応答は `operationId`, `status` (`COMPLETED`/`REJECTED`), nullable `reason`, `benefits` (GET同型), `awardedPriorityUses`, nullable `inventorySnapshot`。拒否もHTTP200で確定し、reasonは `insufficient_priority_uses`, `inventory_conflict`, `invalid_benefit_item`, `reservation_cancelled` 等。inventorySnapshotは既存オーブ操作と同じ `accountId/coveredEntryIds/entries/currencyInventoryId/currencyEntries` であり、再送でも現在正本を返す。covered内にありentriesにないentryは削除扱い。

## 処理規則

1. consume-itemは所有する有効GAME BAG/HOTBARのスタック消耗品に限定し、timestampを一致確認する。masterの単一effectsが `INSTANCE_PRIORITY`/`VIP_DONER`/`VIP_ASTRALDER`、確定率100、非割合、正整数valueかつトレード/売却不可の場合だけ受理する。数量1減算と特典付与、台帳保存を同じtransactionで確定する。
2. 優先回数消費は待機発生時にパーティリーダーのアカウントを指定し、残高1以上で1回だけ減らす。取消は元のoperationIdで1回だけ返す。取消先着時も記録して後着消費を抑止する。
3. VIP期限はUTC実時間の排他的終了。DONER15日券は15日、ASTRALDER20日券は20日を加算。重ね掛け可能。ASTRALDERを先に消化し、その残期間中のDONER購入は後回し。DONER残期間中のASTRALDER追加はDONER期限も同日数延長する。
4. loginはASTRALDER有効時にJST暦日1日1回、優先回数1を付与。1券につき20回まで。未ログイン日の遡及なし。継続延長は上限も追加し、失効後の再購入は以前の未受取上限を破棄する。
5. VIP一覧は未削除かつ現在有効なアカウントの配列。各行は `accountId/displayName/vipTier/vipExpiresAt/remainingDays`。remainingDaysは残実時間日数の切り上げ。待機中DONERは現在のVIP種別には出さない。
6. アカウント削除は現在特典を削除し履歴台帳を保持。cloneには特典/履歴を含めない。

移行はゲームDBの `20260926_account_benefits.sql` をAPI更新前に適用する。旧permission=5を0にし、VIP期間を無償付与しない。
