# 02_3.04-削除系

## アカウント削除

HTTPメソッド: `DELETE`  
パス: `/api/account/{uuid}`  
コントローラ: `AccountController`  
アクション物理名: `Delete`

責務:

指定した未削除アカウントを論理削除し、アカウント専用の実行データを同一トランザクションで削除する。`is_deleted` を持つ実行データは論理削除し、履歴共有ではなく `is_deleted` を持たない従属行は子→親の順に物理削除する。マーケット取引・取引コミットなどの履歴および他アカウントと共有する記録は、削除済みアカウントを参照したまま保持する。

リクエスト:

| 種別 | 名前 | 型 | 必須 | 説明 |
|---|---|---|---|---|
| Header | `X-Api-Key` | string | ✓ | API キー |
| Path | `uuid` | GUID | ✓ | 削除対象アカウント UUID |
| Body | `deletedBy` | GUID | ✓ | 削除実行者 UUID |

レスポンス:

| ステータス | 内容 | ボディ |
|---|---|---|
| 200 OK | 削除成功 | `deletedAccountId`, `userId`, `deletedSlotIndex`, `selectedAccountId`, `createdReplacement` |
| 401 Unauthorized | API キー未指定/無効 | なし |
| 404 Not Found | 未登録または同一操作と判定できない論理削除済み | なし |

処理内容:

1. 認証パイプラインで `X-Api-Key` を検証する。
2. EF Core の実行戦略単位で `SERIALIZABLE` トランザクションを開始し、SQL Serverでは未削除状態に限らず対象 account を更新ロックで先に取得してから、トランザクション内で所有 user を取得する。これにより account 専用データを操作する保存処理と直列化する。SQL Server の一時的な障害時はトランザクション全体を再試行する。commit 結果が不明となって再試行された場合は、`account_delete_receipt` の確定台帳から初回削除時の成功応答を再構成し、後続のアカウント切替で `selectedAccountId` を変えずに 200 応答を返す。既存の論理削除行に台帳がない場合だけ、残存アカウントから旧データ互換の応答を再構成する。
3. アカウント専用データを削除し、削除対象 account を `is_deleted = 1`、`is_active = 0` に更新する。
4. 残存アカウントがあればスロット番号の昇順で選択し、なければ削除されたスロットに初期状態の replacement account を作成する。
5. `dbo.user.account_id` と選択中フラグを選択先へ更新してコミットする。

削除対象:

- インベントリ、インベントリエントリ、装備、装備ロードアウトとそれぞれの従属行
- 習得スキルとシジル、スキルバインド、スキルツリーと解放ノード、クエストと進行・完了・クールダウン、ウェイストーン、ガイド、ログインボーナス、アカウント別マーケット状態
- Mob / ダンジョン進行、クラス進行度

保持対象:

- マーケット取引・出品履歴・価格スナップショット
- 取引コミット、装備オーブ操作台帳

出品中のマーケット出品は `CANCELED` / `ACCOUNT_DELETED` に更新する。
