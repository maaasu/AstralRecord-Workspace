# 02_3.00-索引

API `account` のエンドポイント数は 3 件と少ないため、本ファイルに集約する。

## エンドポイント一覧

| HTTPメソッド | パス | 論理名 |
|---|---|---|
| GET | `/api/account/{uuid}` | アカウント取得 |
| POST | `/api/account` | アカウント登録 |
| PUT | `/api/account/{uuid}` | アカウント更新 |

---

## 1. アカウント取得

HTTPメソッド: `GET`
パス: `/api/account/{uuid}`
コントローラ: `AccountController`
アクション物理名: `GetAccount`

責務:

UUID をキーに `dbo.account` を取得する。論理削除済みは取得対象外。

リクエスト:

| 種別 | 名前 | 型 | 必須 | 説明 |
|---|---|---|---|---|
| Header | `X-Api-Key` | string | ✓ | API キー |
| Path | `uuid` | GUID | ✓ | アカウントUUID |

レスポンス:

| ステータス | 内容 | ボディ |
|---|---|---|
| 200 OK | 取得成功 | [[02_1.00-モデル定義]].アカウントレスポンス |
| 401 Unauthorized | API キー未指定/無効 | なし |
| 404 Not Found | 未登録または論理削除済み | なし |

処理内容:

1. 認証パイプラインで `X-Api-Key` を検証する
2. リポジトリで `dbo.account` を取得する

    | 項目 | 内容 |
    |---|---|
    | 検索キー | `uuid` |
    | 取得対象 | `is_deleted = 0` のみ |
    | 取得失敗 | 404 を返す |

3. 例外時は [[02_5.00-例外・ログ・運用]].取得系 のログを記録し 500 を返す

---

## 2. アカウント登録

HTTPメソッド: `POST`
パス: `/api/account`
コントローラ: `AccountController`
アクション物理名: `CreateAccount`

責務:

[[02_1.00-モデル定義]].アカウント登録リクエスト を受け取り、新規 account を作成する。
account UUID はサーバ側で `Guid.NewGuid()` により生成する。

リクエスト:

| 種別 | 名前 | 型 | 必須 | 説明 |
|---|---|---|---|---|
| Header | `X-Api-Key` | string | ✓ | API キー |
| Header | `Content-Type` | string | ✓ | `application/json` |
| Body | (全体) | [[02_1.00-モデル定義]].アカウント登録リクエスト | ✓ | 登録対象 |

レスポンス:

| ステータス | 内容 | ボディ |
|---|---|---|
| 201 Created | 登録成功 | [[02_1.00-モデル定義]].アカウントレスポンス |
| 400 Bad Request | バリデーション失敗 | エラーオブジェクト |
| 401 Unauthorized | API キー未指定/無効 | なし |

処理内容:

1. 認証パイプラインで `X-Api-Key` を検証する
2. リクエストのバリデーションを行う

    | 項目 | 内容 |
    |---|---|
    | 必須項目 | `userId`, `accountName`, `slotIndex`, `mode`, `createdBy` |
    | 失敗時 | 400 を返す |

3. 新規 account を登録する

    | 項目 | 内容 |
    |---|---|
    | `uuid` | `Guid.NewGuid()` でサーバ生成 |
    | `isActive` | 既定 `false`（選択は別途 PUT 経由） |
    | `menuShortcutsJson` | 既定値（実装依存） |
    | `createdAt` / `updatedAt` | サーバ現在日時 |
    | `updatedBy` | リクエストの `createdBy` と同値 |

4. 登録結果を [[02_1.00-モデル定義]].アカウントレスポンス へマッピングし 201 を返す
5. 例外時は [[02_5.00-例外・ログ・運用]].登録系 のログを記録し 500 を返す

---

## 3. アカウント更新

HTTPメソッド: `PUT`
パス: `/api/account/{uuid}`
コントローラ: `AccountController`
アクション物理名: `UpdateAccount`

責務:

[[02_1.00-モデル定義]].アカウント更新リクエスト で指定された項目のみ更新する。`null` は無更新。

リクエスト:

| 種別 | 名前 | 型 | 必須 | 説明 |
|---|---|---|---|---|
| Header | `X-Api-Key` | string | ✓ | API キー |
| Header | `Content-Type` | string | ✓ | `application/json` |
| Path | `uuid` | GUID | ✓ | 更新対象アカウントUUID |
| Body | (全体) | [[02_1.00-モデル定義]].アカウント更新リクエスト | ✓ | 更新内容 |

レスポンス:

| ステータス | 内容 | ボディ |
|---|---|---|
| 200 OK | 更新成功 | [[02_1.00-モデル定義]].アカウントレスポンス |
| 400 Bad Request | バリデーション失敗 | エラーオブジェクト |
| 401 Unauthorized | API キー未指定/無効 | なし |
| 404 Not Found | 未登録または論理削除済み | なし |

処理内容:

1. 認証パイプラインで `X-Api-Key` を検証する
2. リクエスト Body のバリデーションを行う（`updatedBy` 必須）
3. 対象 account を取得する（`is_deleted = 0`）
4. 非 null 項目のみ反映する

    | 項目 | 内容 |
    |---|---|
    | 更新候補 | `accountName`, `isActive`, `mode`, `menuShortcutsJson` |
    | 共通項目 | `updatedBy` / `updatedAt` は常に更新 |

5. 更新後の Entity をマッピングし 200 を返す
6. 例外時は [[02_5.00-例外・ログ・運用]].更新系 のログを記録し 500 を返す
