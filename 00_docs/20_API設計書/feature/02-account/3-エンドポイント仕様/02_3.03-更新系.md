# 02_3.03-更新系

## 1. 更新系エンドポイント仕様

### アカウント更新

HTTPメソッド: `PUT`
パス: `/api/account/{uuid}`
コントローラ: `AccountController`
アクション物理名: `UpdateAccount`

責務:

[[02_1.00-モデル定義]].アカウント更新リクエスト で指定された項目のみ更新する。`null` は無更新。

リクエスト:

| 種別 | 名前 | 型 | 必須 | 説明 |
|---|---|---|---|---|
| Header | `X-Api-Key` | string | ✓ | API キー |
| Header | `Content-Type` | string | ✓ | `application/json` |
| Path | `uuid` | GUID | ✓ | 更新対象アカウントUUID |
| Body | (全体) | [[02_1.00-モデル定義]].アカウント更新リクエスト | ✓ | 更新内容 |

レスポンス:

| ステータス | 内容 | ボディ |
|---|---|---|
| 200 OK | 更新成功 | [[02_1.00-モデル定義]].アカウントレスポンス |
| 400 Bad Request | バリデーション失敗 | エラーオブジェクト |
| 401 Unauthorized | API キー未指定/無効 | なし |
| 404 Not Found | 未登録または論理削除済み | なし |

処理内容:

1. 認証パイプラインで `X-Api-Key` を検証する
2. リクエスト Body のバリデーションを行う（`updatedBy` 必須。`mode` 指定時は `0` または `2`）
3. 対象 account を取得する（`is_deleted = 0`）
4. 非 null 項目のみ反映する

    | 項目 | 内容 |
    |---|---|
    | 更新候補 | `accountName`, `isActive`, `mode`, `menuShortcutsJson`, `level`, `totalExperience`, `classId`, `classLevel`, `classExperience`, `classProgresses` |
    | 整合条件 | `level` と `totalExperience` は片方のみ指定不可。`classLevel` と `classExperience` も片方のみ指定不可。`classProgresses[].classId` は空文字・重複不可 |
    | クラス別進行度 | `classProgresses` の各要素を (`account_id`, `class_id`) 単位で upsert する。互換フィールド `classLevel` / `classExperience` も選択対象クラスへ upsert する |
    | 転職 | `classId` 指定時は当該クラスの保存済み進行度を現在値へ復元する。行がなければ Lv.1 / EXP 0 を作成する |
    | 互換ミラー | 更新後の現在クラス行を `dbo.account.class_level` / `class_experience` に反映する |
    | 共通項目 | `updatedBy` / `updatedAt` は常に更新 |

   `isActive = true` の場合は、対象アカウントの所有 user と同一 user の未削除アカウントを同一 `SERIALIZABLE` トランザクション内で更新し、他アカウントを非アクティブ化したうえで `dbo.user.account_id` を対象 UUID に設定する。このトランザクションは SQL Server の実行戦略単位（`CreateExecutionStrategy().ExecuteAsync`）として実行する。

5. 更新後の Entity をマッピングし 200 を返す
6. 例外時は [[02_5.00-例外・ログ・運用]].更新系 のログを記録し 500 を返す
