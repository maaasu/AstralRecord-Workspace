# player-state snapshot 概要

`POST /api/player-state/snapshots` は inventory、loadout、dirty equipment と optional section を SQL Server の一 transaction で保存する。API は素材消費・抽選・報酬付与を再実行しない。

## 競合・所有権境界

- `snapshotId` は UUID の冪等キー。同一 request hash は保存済み ACK を返し、別 payload での再利用は `409`。
- inventory ごとの `expectedEntries[{inventoryEntryId,updatedAt}]` はロード時点の有効 entry 全集合と各 timestamp であり、同時追加・更新・省略削除を検出する。entry 移動は対象 parent 全ての所属を検証後、一括で旧配置を無効化してから最終配置する。
- 既存 inventory は `metadataDirty=false` なら `expectedUpdatedAt` を要求せず metadata を変更しない。dirty 時だけ parent timestamp を検証する。`inventory.isNew=true` は Plugin が採番した親と entry を同じ transaction 内で作成する。
- 既存 equipment / loadout は `expectedUpdatedAt` を検証する。`equipment.isNew=true` は Plugin が採番・抽選した装備個体と stat roll、`loadout.isNew=true` は Plugin が採番した loadout と slot を同じ transaction 内で新規作成する。snapshot と既存 API の enchant/rune child 更新はいずれも equipment 親の `updatedAt` を必ず更新する。active/suspended market listing の equipment は拒否する。
- account 進行度は `expectedProgressVersion` を検証する。`updatedAt` は位置や menu shortcut 更新と共有するため競合条件に使わない。`mode` は Plugin 正本で、dirty 時だけ optional `mode` を送る。
- mail claim／delete、ログインボーナス、クエスト状態は完成 inventory と同じ snapshot transaction で確定する。market / trade の外部 mutation は Plugin の `executeExclusiveAfterSave` 境界で save lane 完了後に実行する。API 側でも所有権、entry 集合、parent timestamps、market listing range lock を検証する。
- ガイド進捗は完了手順の集合、冒険記録は Mob 討伐・Dungeon 踏破の加算差分、player setting は user 単位の完全 state と各行の `expectedVersion` を optional section として保存する。これらも同じ account transaction と `snapshotId` 台帳に含める。
- core 配列が空の section-only snapshot では inventory、entry、equipment、loadout の照会・lock・ACK query を実行しない。高頻度のガイド、冒険記録、設定変更が無関係な inventory 行を占有しないようにする。

Plugin は player setting の個別 POST／PUT、ガイド完了 POST、冒険記録加算 POST を使用しない。初期読込・一覧表示の GET は各既存 API を使用できる。
