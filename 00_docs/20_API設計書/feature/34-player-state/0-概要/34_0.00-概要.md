# player-state snapshot 概要

`POST /api/player-state/snapshots` は inventory、loadout、dirty equipment と optional section を SQL Server の一 transaction で保存する。API は素材消費・抽選・報酬付与を再実行しない。

## 競合・所有権境界

- `snapshotId` は UUID の冪等キー。同一 request hash は保存済み ACK を返し、別 payload での再利用は `409`。
- inventory ごとの `expectedEntryIds` はロード時点の有効 entry ID 集合全体であり、同時追加や省略削除を検出する。entry 移動は対象 parent 全ての所属を検証後、一括で旧配置を無効化してから最終配置する。
- `metadataDirty=false` の inventory は `expectedUpdatedAt` を要求せず、metadata を変更しない。dirty 時だけ parent timestamp を検証する。
- equipment / loadout は `expectedUpdatedAt` を検証し、snapshot に child を保存した equipment 親は必ず `updatedAt` を更新する。active/suspended market listing の equipment は拒否する。
- account 進行度は `expectedProgressVersion` を検証する。`updatedAt` は位置や menu shortcut 更新と共有するため競合条件に使わない。`mode` は Plugin 正本で、dirty 時だけ optional `mode` を送る。
- market / trade / mail claim 等の外部 mutation は Plugin の `executeExclusiveAfterSave` 境界で save lane 完了後に実行する。API 側でも所有権、entry 集合、parent timestamps、market listing range lock を検証する。

`player-setting` は user 単位 API のままであり、本 snapshot に含めない。
