# player-state snapshot モデル

## Request root

| フィールド | 型 | 必須 | 説明 |
|:--|:--|:--:|:--|
| `snapshotId` | UUID | ○ | retry でも同じ値を使う冪等キー |
| `accountId` | UUID | ○ | 所有アカウント |
| `updatedBy` | UUID | ○ | 更新者 |
| `inventories` | array | ○ | 保存対象 inventory。空配列可 |
| `loadouts` | array | ○ | dirty loadout の完全 state。空配列可 |
| `equipment` | array | ○ | dirty equipment の完全 state（enchants/runes 含む）。空配列可 |
| `learnedSkills` / `skillBindPresets` / `skillTree` / `accountProgress` / `waystones` / `questState` / `loginBonusClaims` / `guideProgress` / `adventureRecords` / `playerSettings` / `mailClaim` / `mailDelete` | object | × | dirty section だけ送る。ACK は同名 property に metadata を返す |

## Core state

`inventories[]` は `inventoryId`, `isNew`, `metadataDirty`, `expectedUpdatedAt`, `metadataJson`, `entryMode`, `expectedEntries`, `deletedEntryIds`, `entries[]` を持つ。`entryMode="DELTA"` は変更行だけを送る新契約であり、未指定は旧 Plugin の完全置換契約として受理する。既存親は `isNew=false` とし、metadata dirty 時だけ `expectedUpdatedAt` を必須にする。新規親は `isNew=true`, `inventoryType`, `inventoryProfile`, `slotCapacity`, `isEnabled` を送り、`expectedUpdatedAt` と baseline の `expectedEntries` は空にする。`expectedEntries` は DELTA 時に変更・移動・削除する既存 entry のロード時 `{inventoryEntryId,updatedAt}` だけであり、API は親所有権と各 timestamp を照合する。`deletedEntryIds` は `expectedEntries` に含まれ、`entries[]` に含まれない明示削除である。移動では移動元の baseline と移動先 `entries[]` を同じ要求に入れる。`loadouts[]` の `slotMode="DELTA"` も同様に `slots[]` と `deletedSlots[]` の差分だけを適用し、未指定は完全置換として扱う。

`loadouts[]` は `equipmentLoadoutId`, `isNew`, `expectedUpdatedAt`, `slots[]` の完全 state。既存親は `isNew=false` と `expectedUpdatedAt`、新規親は `isNew=true`, `loadoutProfile`, `loadoutName`, `sortOrder`, `isActive`, `metadataJson` を送る。`equipment[]` は `equipmentInstanceId`, `isNew`, `itemId`, `expectedUpdatedAt`, enhancement/durability/rune state、`statRolls[]`, `enchants[]`, `runes[]` の完全 state。既存個体は `isNew=false` と `expectedUpdatedAt`、新規個体は `isNew=true` と `itemId`、Plugin 採番の child ID を送る。equipment に独立 version は追加せず、child 更新時にも親 `updatedAt` を更新する。

新規 equipment の `isNew` は SQL 未作成を表し、未強化を意味しない。初回保存前にローカル確定した強化レベル・超越ランク・耐久値・エンチャント・ルーンを含む完成状態を受理する。新規個体の `expectedUpdatedAt` は null、`itemId` は必須とし、作成時の `statRolls[]` も同梱する。既存個体の `statRolls[]` は空とする。どちらも非負値、耐久範囲、child の必須値・slot 範囲・ID/effect 重複の検証を適用する。

## Optional section

- `learnedSkills`: `{ accountId, clientRevision, skills, deletedSkills }`。`skills[]` は既存行に `expectedVersion`、新規行には未指定を使う。削除は省略だけで表さず、`deletedSkills:[{learnedSkillId,expectedVersion}]` で明示する。これにより並行更新された skill を誤って削除しない。
- `skillBindPresets`: `{ accountId, clientRevision, selectedPresetIndex, presets[] }`。各 preset は `expectedVersion` を持つ完全 state。
- `skillTree`: `{ accountId, clientRevision, expectedVersion, unlockedNodes[] }`。
- `accountProgress`: `{ accountId, clientRevision, expectedProgressVersion, level, totalExperience, classId, classLevel, classExperience, classProgresses, mode? }`。`mode` が absent/null のとき API は mode を変更しない。
- `waystones`: `{ clientRevision, unlockedWaystoneIds:[string] }`。既存 `WaystoneDefinition.id` / `dbo.account_waystone_unlock.waystone_id` と同じ `ws-...` 文字列 ID を使い、不足分だけ追加する。取消は行わず、すでに開放済みの ID は no-op。空文字・空白のみ・前後空白、101文字以上、大文字小文字を区別しない重複は `400`。
- `questState`: `{ accountId, clientRevision, expectedVersion, activeQuests, completions, cooldowns }`。クエスト状態全体を楽観ロック付きで置換し、報酬 inventory と同時確定する。
- `loginBonusClaims`: `{ clientRevision, claimDates }`。未受取日のみを追記し、既存日があれば snapshot 全体を `409` にする。
- `guideProgress`: `{ accountId, clientRevision, isFullSnapshot, completedStepKeys }`。各 key は `{guideId,stepId}`。不足分を追記し、`isFullSnapshot=true` の場合は DB にだけ存在する完了手順があれば `409` にする。Plugin は読込済み完全集合を送る。
- `adventureRecords`: `{ accountId, clientRevision, mobDefeatDeltas, dungeonClearDeltas }`。Mob 行は `{mobId,mobCategory,delta}`、Dungeon 行は `{dungeonId,delta}`。`delta` は 1 以上とし、API が現在 count へ加算する。同じ payload の再送は root の `snapshotId` 台帳で一度だけ適用する。
- `playerSettings`: `{ userId, clientRevision, settings }`。`settings[]` は user 単位の全有効行で、`{userSettingId,settingKey,settingValueJson,expectedVersion}` を持つ。既存行は `expectedVersion` 必須、新規行は null とする。DB にだけ存在する有効行、ID 所有権、版競合は snapshot 全体を `409` にする。
- `mailClaim`: `{ accountId, clientRevision, mailId }`。`clientRevision` は操作ごとに生成するUUID。配信中かつ未読のメールだけを既読化する。期限外、削除済み、既読済みは snapshot 全体を `409` にし、添付報酬 inventory も rollback する。
- `mailDelete`: `{ accountId, clientRevision, mailId }`。`clientRevision` は操作ごとに生成するUUID。配信中かつ未削除のメールをアカウント単位で論理削除し、未存在、期限外、削除済みは snapshot 全体を `409` にする。

## ACK

Core ACK の ID 名は固定する。

```json
{
  "snapshotId": "UUID",
  "accountId": "UUID",
  "entries": [{ "inventoryEntryId": "UUID", "updatedAt": "UTC", "isDeleted": false }],
  "inventories": [{ "inventoryId": "UUID", "updatedAt": "UTC" }],
  "loadouts": [{ "equipmentLoadoutId": "UUID", "updatedAt": "UTC" }],
  "equipment": [{ "equipmentInstanceId": "UUID", "updatedAt": "UTC" }],
  "learnedSkills": { "clientRevision": 12, "entries": [], "deletedIds": [] },
  "skillBindPresets": { "clientRevision": 12, "entries": [] },
  "skillTree": { "clientRevision": 12, "version": 4, "updatedAt": "UTC" },
  "accountProgress": { "clientRevision": 12, "progressVersion": 8, "updatedAt": "UTC" },
  "waystones": { "clientRevision": 12, "unlockedWaystoneIds": ["ws-20260906-eriva"] },
  "questState": { "clientRevision": 12, "version": 3, "updatedAt": "UTC" },
  "loginBonusClaims": { "clientRevision": 12, "claims": [{ "claimDate": "2026-09-05", "loginBonusClaimId": "UUID", "claimedAt": "UTC" }] },
  "guideProgress": { "clientRevision": 12, "completedStepKeys": [{ "guideId": "guide-id", "stepId": "step-id" }] },
  "adventureRecords": { "clientRevision": 12, "mobDefeats": [{ "mobId": "mob-id", "mobCategory": "ENEMY", "defeatCount": 8, "updatedAt": "UTC" }], "dungeonClears": [{ "dungeonId": "dungeon-id", "clearCount": 2, "updatedAt": "UTC" }] },
  "playerSettings": { "clientRevision": 12, "settings": [{ "userSettingId": "UUID", "settingKey": "ui.locale", "version": 3 }] },
  "mailClaim": { "clientRevision": "UUID", "mailId": "alpha-reward-mail", "version": 2, "readAt": "UTC" },
  "mailDelete": { "clientRevision": "UUID", "mailId": "alpha-reward-mail", "version": 3, "deletedAt": "UTC" }
}
```

ACK は state 本文を返さない。Plugin は snapshot ID、自身の revision、対象 ID 集合が一致する pending state にだけ metadata を merge する。冒険記録は捕捉量だけを未保存差分から減算し、player setting は ACK の ID・key・version を merge する。古い local state を ACK で置換しない。
