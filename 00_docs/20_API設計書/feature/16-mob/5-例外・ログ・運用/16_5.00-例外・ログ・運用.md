# 16_5.00-例外・ログ・運用

ログ・メッセージはハードコーディング。LogId は使用しない。

## 1. 共通エラーレスポンス

| ステータス | 発生条件 | ボディ |
|---|---|---|
| 400 Bad Request | `category` クエリが不正値 | `ProblemDetails` 互換 |
| 401 Unauthorized | API キー未指定/無効 | なし |
| 404 Not Found | mobId 未定義 | なし |
| 500 Internal Server Error | 上記以外の例外 | `ProblemDetails` 互換 |

## 2. ログ一覧

### 2.1 起動時 YAML ロード

YAML から MasterDataDB への取り込みは `MasterDataSeeder` 側で行う。`mob` 固有のロードログは持たない。  
`MasterDataSeeder` のログ仕様は `99-system/3-エンドポイント仕様/99_3.00-索引` を参照。

### 2.2 取得系

| 項目 | 内容 |
|---|---|
| レベル | Warning |
| テンプレート | `Invalid category query: {Category}` |
| 出力条件 | `GET /api/mob?category=...` で不正値を受領 |
| 引数 | `{Category}` = リクエスト値 |

| 項目 | 内容 |
|---|---|
| レベル | Error |
| テンプレート | `Failed to get mob list` |
| 出力条件 | `GetAll` 内の例外発生時 |
| 出力例外 | `_logger.LogError(ex, ...)` で添付 |

| 項目 | 内容 |
|---|---|
| レベル | Error |
| テンプレート | `Failed to get mob {MobId}` |
| 出力条件 | `GetById` 内の例外発生時 |
| 引数 | `{MobId}` = Mob テンプレート ID |
| 出力例外 | `_logger.LogError(ex, ...)` で添付 |

## 3. 運用上の注意

- 3 つの `master_type`（`mob.boss` / `mob.enemy` / `mob.npc`）を統合して扱うため、`category` でフィルタする場合は Repository 層で `master_type` のリストを構築する。
- MasterDataDB の同一 `master_id` が 2 つの `master_type` に存在することは想定しない（filebase 側で ID が重複した場合は Seeder が `InvalidOperationException` で失敗する）。
- ホットリロード未対応。filebase の変更を反映するには `POST /api/master-data/seed` を呼ぶ運用とする。
