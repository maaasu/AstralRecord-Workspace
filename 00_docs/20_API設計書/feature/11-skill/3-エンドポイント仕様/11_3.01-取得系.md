# 11_3.01 取得系

## GET `/api/skill`

スキル一覧を返します。

- Controller: `SkillController`
- Action: `GetAll`
- Header: `X-Api-Key` 必須

### 返却

- `200 OK`
  - `SkillSummaryResponse[]`
- `401 Unauthorized`
  - API キー不正

### 備考

- `dbo.master_data_entry` の `master_type = 'skill'` かつ `is_deleted = 0` を対象にします。
- `payload_json` を逆シリアライズし、一覧では `id / name / implementationId / icon / tags` を返します。

## GET `/api/skill/{skillId}`

スキル詳細を返します。

- Controller: `SkillController`
- Action: `GetById`
- Header: `X-Api-Key` 必須
- Path: `skillId`

### 返却

- `200 OK`
  - `SkillResponse`
- `401 Unauthorized`
  - API キー不正
- `404 Not Found`
  - 対象スキルなし

### 備考

- top-level `resourceType` / `resourceCost` を `SkillResponse` として返却します。
- 旧 `params.resourceType` / `params.resourceCost` / `manaCost` からの互換解決は plugin 側の責務です。
- `params` はネストを保持したまま返します。
- `conditionalLore` は `requiredSkillId` と `lines` を保持したまま返します。閲覧者の使用許可による表示判定は Plugin 側の責務です。
- `passive.bindRequired` を返却し、plugin 側はこれをパッシブ発動条件判定に使用します。
- `cooldownId`、`maxLevel`、`levels`、`sigilSlotsByLevel`、`allowedSigilIds`、`gem` を返します。
- active / passiveの最終分類と詳細ロジックは`implementationId`に対応するPlugin executorが担います。


## 詳細マスタの分割取得と共有キャッシュ

`GET /api/{kind}/details?offset=0&limit=100`（kindは `item` / `skill` / `class`）は有効な詳細を分割取得する。`X-Api-Key` は従来と同じ。`offset` は0以上、`limit` は1～100（既定100）。範囲違反は400。戻り値は `{"generation":"<APIプロセスの世代>","total":123,"items":[{"master":<単件詳細と同じDTO>,"responseBodySha256":"<単件MVC JSON本文のSHA256>"}]}`。2ページ目以降は最初の `generation` をqueryへ付け、世代不一致は409。offset以降に該当がなければitemsは空。並びはitemがcategory→master_id、skill/classがmaster_id順。削除済みシジルはページ/一覧に含めず、旧単件item APIだけで引き続き解決できる。

Item/Skill/Class/Buff/World/SetEffect/Enchantの変換済みマスタは、最初の参照時に種別単位でAPIプロセス共有キャッシュへ読み込む。同じ種別の同時初回取得は一度だけDB/変換を行う。任意の照会IDをキャッシュキーにしない。Item/Skill/ClassのHTTP取得はcache missのDB I/Oを非同期で行う。Seederのデータtransaction commit直後に全キャッシュ世代を失効させる（履歴の成功記録失敗時も、確定したデータは再読込する）。rollbackしたseedでは失効させない。失効前に開始したfillは旧値を公開せず再取得する。外部DB更新や別APIプロセスのseedは即時通知されないため、5分で共有世代を失効させて次の参照で反映する。複数プロセス間の即時通知は持たない。YAMLの意味・DTO変換ルールは従来どおり。
