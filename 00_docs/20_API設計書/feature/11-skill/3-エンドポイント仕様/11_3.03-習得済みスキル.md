# 11_3.03 習得済みスキル API

## GET `/api/account-skills/{accountId}`

アカウントが所有する有効な習得済みスキル個体をUUID単位で返す。同一skill IDを複数返せる。

ロード前に次をserializable transactionで整合する。

- 削除・ID変更済みskillの個体を論理削除する。
- 削除した個体UUIDをプリセットから除き、left-clickは武器通常攻撃へ戻す。
- 現masterで不正になった装着シジルを個体から削除し、同シジルを添付した動的お詫びメールを作る。
- masterの最大レベルが下がった場合は個体レベルを範囲内へ補正する。

## POST `/api/account-skills/{accountId}/learn`

skill master の `learnRequiredItems` をGAME inventoryの複数スタックから原子的に検証・消費し、Lv.1の新規UUID個体を作る。未指定ならアイテム消費なしで作る。同一skill IDの既存個体数は制限しない。

## POST `/api/account-skills/{accountId}/{learnedSkillId}/level-up`

選択個体のskill masterに定義された `levelUpRequiredItems` をGAME inventoryの複数スタックから原子的に検証・消費し、その個体だけを1レベル上げる。未指定ならアイテム消費なしで上げる。`maxLevel`到達済みは`409 Conflict`で消費しない。

## POST `/api/account-skills/{accountId}/{learnedSkillId}/sigils`

Pluginが操作確定時に通常アイテム共通消費順で解決した、指定個体に許可されたシジルentryと要求された `SIGIL_ATTACH` オーブentryを各1個、同一 serializable transaction で消費装着する。現在レベルの空きslot、`allowedSigilIds`、同一`equipGroupId`、オーブの効果種別と所有状態をtransaction内で検証する。条件不成立時はシジルもオーブも消費しない。

## POST `/api/account-skills/{accountId}/{learnedSkillId}/sigils/{learnedSkillSigilId}/detach`

指定個体の有効な装着行を論理削除し、Pluginが操作確定時に通常アイテム共通消費順で解決した `SIGIL_DETACH` オーブを1個消費して、対応するシジルを account の有効な `GAME` / `BAG` へ1個返却する。既存stackが`maxStack`未満なら加算し、なければslot未割当の通常entryを作る。オーブ消費、装着行削除、個体version更新、返却entry更新は同じserializable transactionで確定し、レスポンスは更新後個体と`returnedInventoryEntryId`を返す。条件不成立時はオーブを消費しない。

## POST `/api/account-skills/{accountId}/{learnedSkillId}/forget`

指定した習得済みスキル個体を論理削除する。装着済みシジルも論理削除するが、同じ個体UUIDを参照するバインドは保持する。保持されたバインドは Plugin 側で未習得スキルとして表示・発動拒否し、プレイヤーがバインドを解除した時点で空になる。`updatedBy` を更新者として保存し、成功時は忘却前の個体を返す。

## ステータス

| Status | 条件 |
|---|---|
| `200` | 取得・mutation成功 |
| `404` | account、個体、skill、sigil、指定した有効な装着行が存在しない |
| `409` | 不正素材、最大Lv、空き枠なし、非許可sigil、group重複、返却先GAME/BAG不在 |
| `401` | APIキー不正 |
