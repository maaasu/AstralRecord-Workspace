# 11_5.00-例外・ログ・運用

ログ・メッセージはハードコーディングし、LogId は使用しない。

## 1. 共通エラーレスポンス

| ステータス | 代表条件 | ボディ |
|---|---|---|
| 401 Unauthorized | API キー不正または不足 | なし |
| 404 Not Found | skillId 未定義 | なし |
| 409 Conflict | 習得・合成素材不正、最大Lv、シジル枠・group条件違反 | failure code |
| 500 Internal Server Error | 想定外例外 | `ProblemDetails` 想定 |

## 2. ログ一覧

| 項目 | 内容 |
|---|---|
| レベル | Information |
| テンプレート | `Loaded {Count} skills from filebase` |
| 出力条件 | アプリ起動時またはロード完了時 |
| 引数 | `{Count}` = 読み込まれたスキル数 |

| 項目 | 内容 |
|---|---|
| レベル | Error |
| テンプレート | `Failed to load skill YAML: {Path}` |
| 出力条件 | YAML パース失敗時 |
| 引数 | `{Path}` = 対象ファイルパス |
| 出力形式 | `_logger.LogError(ex, ...)` で記録 |

| 項目 | 内容 |
|---|---|
| レベル | Error |
| テンプレート | `Failed to get skill {SkillId}` |
| 出力条件 | 取得処理で例外発生時 |
| 引数 | `{SkillId}` = スキル ID |
| 出力形式 | `_logger.LogError(ex, ...)` で記録 |

## 3. 運用上の注意

- `implementationId` に対応するプラグイン側実装クラスの存在は API 単体では検証しない。
- Seederは`maxLevel`、level差分、シジル枠、許可シジル参照、`cooldownId`、クラス`usableSkills`参照、予約ジェムIDprefixを検証する。
- `resourceType` / `resourceCost` / tick / `requiredLevel`とexecutor固有`params`はPluginの定義ロードでも対象スキル単位に検証する。
- `params` のキー構成・型・必須条件は API 単体では検証しない。
- スキル定義の正本は `40_filebase/30.features.skill/` であり、API は Seeder 後の MasterDataDB を読み取る。
