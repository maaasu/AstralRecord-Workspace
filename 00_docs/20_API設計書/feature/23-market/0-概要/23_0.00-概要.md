# 23_0.00-概要

## 1. 目的

`market` API は、プレイヤー間マーケットの正本ロジックを API に集約し、Plugin と Web が同じ判定結果を利用できるようにする。

対象:

- アカウント単位の出品
- 出品数制限
- 出品価格の店売り価格下限チェック
- 相場算出と相場乖離チェック
- 装備・ルーンなどランダムステータス個体の価格評価
- 購入確定時のアイテム移転、通貨移転、約定履歴作成

## 2. 責務境界

| 領域 | 責務 |
|---|---|
| API | 出品可否、価格判定、相場算出、取引確定、出品数制限、DB 更新のトランザクション管理 |
| Plugin | ゲーム内 GUI、手元インベントリ表示、API 呼び出し、成功/失敗メッセージ表示 |
| Web | マーケット一覧、検索、相場確認、出品/購入/キャンセル画面、API 呼び出し |
| DB | 出品状態、約定履歴、相場スナップショット、アカウント別制限状態の永続化 |

Plugin と Web は、価格ガードや出品制限を独自実装しない。表示上の事前チェックを行う場合でも、最終判定は API の結果を正とする。

## 3. 出品単位

| 種別 | 出品単位 | 識別 |
|---|---|---|
| スタック品 | 数量指定 | `itemCategory` + `itemId` + `quantity` |
| 装備個体 | 1 個体 | `instanceType = EQUIPMENT` + `instanceId` |
| ルーン個体 | 1 個体 | `instanceType = RUNE` + `instanceId` |

装備・ルーンなど個体差があるものは、同じ `itemId` でも別商品として扱う。
相場算出時のみ、同等条件の取引履歴へ段階的に広げて参照する。

## 4. 出品価格ガード

出品作成時は次の順で API が検証する。

1. 所有権と出品可能状態を検証する。
2. アカウントの出品数上限を検証する。
3. `unitPrice` が item マスタの店売り単価以上であることを検証する。
4. 相場算出を実行し、価格が許容範囲内であることを検証する。
5. 合格した場合のみ、対象アイテムをマーケット escrow として確保し、出品を `ACTIVE` にする。

### 4.1 店売り価格下限

`unitPrice < sellPrice` の場合は出品を拒否する。
スタック品は単価、個体品は個体 1 個あたりの価格として判定する。

`sellPrice` は item マスタの `saleValue` を正として API が返す店売り単価。`saleValue` が未定義のアイテムは、マーケット出品不可を既定とする。

### 4.2 相場乖離チェック

API は相場レスポンスに以下を含める。

- 参照価格
- 参考データ件数
- 信頼度
- 許容下限
- 許容上限
- 判定結果

信頼度が `HIGH` または `MEDIUM` の場合、`unitPrice` が許容範囲外なら出品を拒否する。
信頼度が `LOW` の場合、相場だけでは拒否せず、店売り価格下限と低信頼時上限で制限する。

既定値:

| 信頼度 | 条件 | 許容下限 | 許容上限 |
|---|---|---|---|
| `HIGH` | 30 日内の同等条件約定が 20 件以上 | `max(sellPrice, median * 0.50, p25 - 1.5 * IQR)` | `min(median * 3.00, p75 + 2.0 * IQR)` |
| `MEDIUM` | 30 日内の同等条件約定が 5 件以上 | `max(sellPrice, median * 0.40, p25 - 2.0 * IQR)` | `min(median * 4.00, p75 + 3.0 * IQR)` |
| `LOW` | 参照データ不足 | `sellPrice` | `max(sellPrice * 50, suggestedPrice * 5)` |

`suggestedPrice` は item 基本価格と個体評価係数から API が計算する参考価格。算出できない場合は `sellPrice` を使用する。

## 5. ランダムステータス個体の相場

装備・ルーンは同じ `itemId` でもランダムステータス、強化、状態変化、エンチャント、ルーンスロットで価値が変わる。
API は個体ごとに `valuationSignature` と `rollQualityBucket` を作成し、相場参照範囲を段階的に広げる。

### 5.1 価格評価シグネチャ

`valuationSignature` は以下の要素から作成する。

| 要素 | 説明 |
|---|---|
| `itemCategory` | `equipment` / `rune` など |
| `itemId` | マスタ ID |
| `instanceType` | `EQUIPMENT` / `RUNE` |
| `enhanceLevel` | 強化値。対象外なら 0 |
| `transcendenceRank` | 状態変化ランク。対象外なら 0 |
| `runeSlotBucket` | ルーンスロット数の段階 |
| `enchantScoreBucket` | エンチャント価値段階 |
| `rollQualityBucket` | ランダムステータス品質段階 |

### 5.2 ランダムステータス品質

各ステータス値は、マスタ上の取り得る範囲に対する百分率へ正規化する。

```text
normalized = (actual - min) / (max - min)
```

ステータスごとの重みが定義されている場合は重み付き平均、未定義の場合は等重み平均を使う。
最終スコアは `0` から `100` とし、以下のバケットへ丸める。

| バケット | スコア範囲 |
|---|---|
| `D` | 0 以上 20 未満 |
| `C` | 20 以上 40 未満 |
| `B` | 40 以上 60 未満 |
| `A` | 60 以上 80 未満 |
| `S` | 80 以上 |

### 5.3 相場参照の拡張順

1. 同一 `valuationSignature`
2. 同一 `itemId` + 同一強化/状態変化 + 同一 `rollQualityBucket`
3. 同一 `itemId` + 同一 `rollQualityBucket`
4. 同一 `itemId`
5. item 基本価格 + 個体評価係数

どの段階を使ったかは `MarketPriceQuoteResponse.referenceScope` に出力する。

## 6. 出品数制限

出品数はアカウント単位で制限する。
`ACTIVE` と `SUSPENDED` の出品を現在出品数として数える。`SOLD` / `CANCELED` / `EXPIRED` は数えない。

取引数に応じて出品可能数を増やす。

| Tier | 累計成立取引数 | 最大同時出品数 |
|---|---:|---:|
| `T0` | 0 - 4 | 3 |
| `T1` | 5 - 19 | 5 |
| `T2` | 20 - 49 | 8 |
| `T3` | 50 - 99 | 12 |
| `T4` | 100 以上 | 20 |

成立取引数は購入・販売どちらも 1 件として加算する。
不正対策として、同一 seller/buyer ペアで短時間に繰り返された取引を Tier 加算対象外にする拡張を許可する。

## 7. 出品状態

| 状態 | 説明 |
|---|---|
| `ACTIVE` | 購入可能 |
| `SOLD` | 購入済み |
| `CANCELED` | 出品者がキャンセル済み |
| `EXPIRED` | 掲載期限切れ |
| `SUSPENDED` | API が異常価格・運用停止・監査対象として購入不可にした状態 |

状態変更は API のトランザクション内で実行する。Plugin / Web は状態を直接書き換えない。
