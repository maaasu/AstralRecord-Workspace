# 23_2.00-ユースケース

## 1. 相場確認

1. Plugin または Web が、対象アイテムと任意の出品予定価格を指定して相場見積を要求する。
2. API は item マスタ、個体状態、直近 30 日の約定履歴を参照して相場を算出する。
3. API は相場の参考価格帯、信頼度、店売り価格に基づく出品可否判定を返す。
4. Plugin または Web は `referenceUnitPrice` があればその値、なければ `suggestedUnitPrice` をおすすめ価格として表示する。参考価格帯の内外は出品可否に影響しない。

## 2. 出品

1. 出品者が Plugin または Web で BAG/HOTBAR の同種 stack を集計し、`sourceEntries`、出品価格、数量を入力する。
2. 呼び出し元は [[23_3.02-登録系]].マーケット出品作成 を呼び出す。
3. API は Gold 通貨、全 source entry の所有権、Tier 基本枠へマーケット拡張トークンの有効枠を加算した実効出品枠、取引不可、売値超過を検証する。売却不可フラグと売値 0 は出品対象外にしない。相場参考帯の外でも売値を上回れば出品できる。
4. API は対象アイテムを escrow として確保し、出品を `ACTIVE` にする。
5. 呼び出し元は作成された出品情報を表示する。

## 3. 購入

1. 購入者が Plugin または Web で `ACTIVE` 出品と購入数量（残数以下）を選択する。
2. 呼び出し元は [[23_3.02-登録系]].マーケット購入確定 を呼び出す。
3. API は出品状態、自己購入でないこと、購入数量、購入者の Plugin Gold 残高、購入者 BAG を検証する。
4. API は購入者 Gold を減算し、指定数量のアイテムを購入者へ移転する。出品者 Gold はまだ加算しない。
5. API は約定履歴を作成し、残数が 0 の場合だけ出品を `SOLD` にする。残数がある間は `ACTIVE` のままとする。
6. API は購入者再同期用の `affectedInventoryEntryIds` を返す。Plugin は保存 lane 上で三者マージする。

## 4. 売上受取

1. 出品者が自分の `SOLD` 出品をクリックする。
2. 呼び出し元は [[23_3.03-更新系]].マーケット売上受取 を呼び出す。
3. API は出品者本人であること、`SOLD`、未受取の約定売上があることを検証する。
4. API は約定売上合計を出品者 Gold へ加算し、出品を論理削除して枠を解放する。
5. Plugin は返却された `affectedInventoryEntryIds` を保存 lane で再同期する。

## 5. キャンセル

1. 出品者が自分の `ACTIVE` 出品をキャンセルする。
2. 呼び出し元は [[23_3.03-更新系]].マーケット出品キャンセル を呼び出す。
3. API は出品者本人であることと状態を検証する。
4. Plugin は返却先の所持品容量を確認時と保存 lane 内の API 呼出直前に再確認し、容量不足なら API を呼び出さず失敗にする。
5. API は未売却の escrow 中アイテムを出品者へ返却する。
6. 売上がなければ出品を `CANCELED` にして論理削除し、枠を解放する。部分売却済みなら `SOLD` の売上受取待ちとして残し、売上受取まで枠を使用する。

## 6. Web 参照

1. Web は [[23_3.01-取得系]].マーケット出品一覧取得 と [[23_3.01-取得系]].アカウントマーケット概要取得 を呼び出す。
2. Web は出品情報の `status`、`priceConfidence` と、相場見積 API の `referenceUnitPrice`、`suggestedUnitPrice`、`allowedMinUnitPrice`、`allowedMaxUnitPrice` を表示補助に使う。
3. Web は独自の価格判定・制限判定を持たない。

## 7. 期限切れ処理

1. API の定期処理が `expiresAt <= now` の `ACTIVE` 出品を `EXPIRED` に更新する。公開 `ACTIVE` 一覧は定期処理前でも期限切れを除外する。
2. 未売却品は出品者が自分の出品一覧から明示的に受け取るまで escrow に保持する。期限到来だけでは inventory を更新しない。
3. 出品者が `EXPIRED` 出品を選択して受取を確定すると、Plugin は所持品の先行保存・容量確認後、既存の冪等キャンセル処理で返却し、影響 entry を再同期する。容量不足なら `EXPIRED` のまま保管を続ける。
4. 返却が完了した売上のない出品は `EXPIRED` のまま論理削除する。部分売却済みの出品は未売却品の返却後に `SOLD` にし、売上受取経路を維持する。
5. 期限切れ出品は返却待ち中も出品枠の対象外とする。部分売却後の期限切れで `SOLD` に移った出品も、期限による枠解放を維持する。
