# 23_4.00-統合フロー

## 1. 出品作成フロー

1. `MarketController` が [[23_1.00-モデル定義]].マーケット出品作成リクエスト を受け取る。
2. `MarketListingLimitService` が出品数制限を判定する。
3. `MarketPriceService` が相場見積を作成する。
4. `MarketRepository` が DB トランザクションを開始する。
5. スタック品の場合は `inventory_entry` から出品数量を確保する。
6. 個体品の場合は `equipment_instance` または `rune_instance` の所有者と出品中でないことを検証する。
7. `market_listing` を作成する。
8. `market_price_snapshot` を作成する。
9. トランザクションを確定する。

## 2. 相場算出フロー

1. item マスタから `sellPrice` と基本価格を取得する。
2. 個体品の場合、装備/ルーン個体から評価対象属性を取得する。
3. `valuationSignature` と `rollQualityBucket` を作成する。
4. `market_transaction` を次の順で検索する。

    | 順序 | 参照範囲 |
    |---:|---|
    | 1 | 同一 `valuationSignature` |
    | 2 | 同一 `itemId` + 同一強化/状態変化 + 同一品質バケット |
    | 3 | 同一 `itemId` + 同一品質バケット |
    | 4 | 同一 `itemId` |

5. 検索結果から中央値、p25、p75、IQR を算出する。
6. 信頼度と許容価格帯を算出する。
7. `unitPrice` 指定時は `judgement` を返す。

## 3. 購入確定フロー

1. `market_listing` を更新ロック付きで取得する。
2. `ACTIVE` でなければ 409 を返す。
3. buyer と seller が異なることを検証する。
4. アイテムを buyer へ移転する。
5. `market_listing` を `SOLD` に更新する。
6. `market_transaction` を作成する。
7. `market_account_state` の成立取引数と Tier 情報を更新する。
8. 通貨残高の減算・加算は `Q-MARKET-001` の解決後に Currency API 内部サービスとして追加する。

## 4. 出品数制限フロー

1. `market_account_state.completed_trade_count` を取得する。
2. Tier 表から `maxActiveListingCount` を算出する。
3. `market_listing` の `ACTIVE` / `SUSPENDED` 件数を集計する。
4. 現在出品数が上限以上なら出品を拒否する。
5. 購入成立時に seller / buyer の成立取引数を加算し、次回出品から上限を反映する。

## 5. Escrow 方針

出品中アイテムは API 管理の escrow 状態として扱う。

| 種別 | 出品時 | キャンセル/期限切れ | 購入成立 |
|---|---|---|---|
| スタック品 | 出品数量を seller inventory から減算し、出品レコードに数量を保持 | seller inventory へ戻す | buyer inventory へ付与 |
| 装備個体 | inventory 表示対象から除外し、出品レコードに `instanceId` を保持 | seller の利用可能状態へ戻す | `equipment_instance.account_id` を buyer へ更新 |
| ルーン個体 | inventory 表示対象から除外し、出品レコードに `instanceId` を保持 | seller の利用可能状態へ戻す | `rune_instance.account_id` を buyer へ更新 |

二重消費を防ぐため、出品作成・購入・キャンセルは DB トランザクションと更新ロックを使う。
