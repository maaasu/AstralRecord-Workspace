# 23_3.02-登録系

## マーケット相場見積

HTTPメソッド: `POST`
パス: `/api/market/price-quote`
コントローラ: `MarketController`
アクション物理名: `CreatePriceQuote`

リクエスト:

| 種別 | 名前 | 型 | 必須 | 説明 |
|---|---|---|---|---|
| Body | `accountId` | GUID |  | 所有権確認対象アカウント |
| Body | `itemCategory` | string | ✓ | item カテゴリ |
| Body | `itemId` | string | ✓ | item マスタ ID |
| Body | `instanceType` | string |  | 個体品の種別 |
| Body | `instanceId` | GUID |  | 個体 UUID |
| Body | `quantity` | int | ✓ | 数量 |
| Body | `unitPrice` | long |  | 判定対象単価 |

レスポンス:

| ステータス | 内容 | ボディ |
|---|---|---|
| 200 OK | 見積成功 | [[23_1.00-モデル定義]].相場見積レスポンス |
| 400 Bad Request | 入力不正 | `ProblemDetails` 互換 |
| 401 Unauthorized | API キー未指定または無効 | なし |
| 404 Not Found | item または個体が存在しない | なし |

処理内容:

1. item マスタを取得する。
2. 個体品の場合は装備・ルーン個体を取得し、必要に応じて所有権を検証する。
3. 店売り価格と推奨価格を算出する。
4. 約定履歴から相場を算出する。
5. `unitPrice` が指定されている場合は価格ガード判定を行う。
6. 相場見積レスポンスを返す。

## マーケット出品作成

HTTPメソッド: `POST`
パス: `/api/market/listings`
コントローラ: `MarketController`
アクション物理名: `CreateListing`

リクエスト:

| 種別 | 名前 | 型 | 必須 | 説明 |
|---|---|---|---|---|
| Body | `sellerAccountId` | GUID | ✓ | 出品アカウント UUID |
| Body | `sourceInventoryEntryId` | GUID |  | スタック品の出品元 |
| Body | `itemCategory` | string | ✓ | item カテゴリ |
| Body | `itemId` | string | ✓ | item マスタ ID |
| Body | `instanceType` | string |  | 個体品の種別 |
| Body | `instanceId` | GUID |  | 個体 UUID |
| Body | `quantity` | int | ✓ | 出品数量 |
| Body | `currencyId` | string | ✓ | 支払い通貨 ID |
| Body | `unitPrice` | long | ✓ | 出品単価 |
| Body | `expiresAt` | DateTime |  | 掲載期限 |
| Body | `createdBy` | GUID | ✓ | 作成者 UUID |

レスポンス:

| ステータス | 内容 | ボディ |
|---|---|---|
| 201 Created | 出品作成成功 | [[23_1.00-モデル定義]].マーケット出品レスポンス |
| 400 Bad Request | 入力不正、価格ガード不合格、出品数上限超過 | `ProblemDetails` 互換 |
| 401 Unauthorized | API キー未指定または無効 | なし |
| 404 Not Found | アカウント、item、出品元が存在しない | なし |
| 409 Conflict | 所有権競合、既に出品中、楽観ロック競合 | `ProblemDetails` 互換 |

処理内容:

1. 出品者アカウントを検証する。
2. 出品数制限を検証する。

    | 項目 | 内容 |
    |---|---|
    | 現在出品数 | `ACTIVE` / `SUSPENDED` の出品数 |
    | 上限 | 累計成立取引数から算出した Tier 上限 |
    | 上限超過 | 400 を返し、出品は作成しない |

3. Serializable transactionを開始する。個体装備は `IX_market_listing_instance_active_status` の対象rangeを `UPDLOCK,HOLDLOCK` し、装備個体、GAME BAG/HOTBARまたはactive loadout membershipの順に更新ロックして、所有・現在保持・未出品を検証する。
4. 対象アイテムを escrow として確保する。
5. ロック取得後の個体値を使って相場見積を内部実行し、店売り価格下限と相場乖離を検証する。
6. `market_listing` を `ACTIVE` で作成する。
7. `market_price_snapshot` へ出品時見積を保存する。
8. 作成した出品を返す。
9. COMMIT結果不明でexecution strategyが再試行する場合は、試行外で固定した同じ`listingId`を先に照会する。確定済みなら同じ出品を成功応答として再生し、未確定の場合だけescrow確保以降を再実行する。

## マーケット購入確定

HTTPメソッド: `POST`
パス: `/api/market/listings/{listingId}/purchase`
コントローラ: `MarketController`
アクション物理名: `PurchaseListing`

リクエスト:

| 種別 | 名前 | 型 | 必須 | 説明 |
|---|---|---|---|---|
| Path | `listingId` | GUID | ✓ | 出品 UUID |
| Body | `buyerAccountId` | GUID | ✓ | 購入アカウント UUID |
| Body | `idempotencyKey` | string | ✓ | 二重購入防止キー |
| Body | `updatedBy` | GUID | ✓ | 更新者 UUID |

レスポンス:

| ステータス | 内容 | ボディ |
|---|---|---|
| 200 OK | 購入成功 | [[23_1.00-モデル定義]].マーケット取引レスポンス |
| 400 Bad Request | 自分の出品購入、受取不可 | `ProblemDetails` 互換 |
| 401 Unauthorized | API キー未指定または無効 | なし |
| 404 Not Found | 出品または購入者アカウントが存在しない | なし |
| 409 Conflict | 既に購入済み、状態競合、二重購入競合 | `ProblemDetails` 互換 |

処理内容:

1. `listingId` の出品を更新ロック付きで取得する。
2. 出品状態が `ACTIVE` であることを検証する。
3. 購入者が出品者と異なることを検証する。
4. 購入者の受取可否を検証する。
5. escrow 中のアイテムを購入者へ移転する。
6. 出品を `SOLD` に更新する。
7. `market_transaction` を作成する。
8. seller / buyer の `market_account_state.completed_trade_count` を更新する。
9. 取引レスポンスを返す。

補足:

- 通貨残高の減算・加算は `Q-MARKET-001` の API 正本化完了後に追加する。
- 初期実装では `market_transaction.totalPrice` / `sellerProceeds` に価格を記録する。
