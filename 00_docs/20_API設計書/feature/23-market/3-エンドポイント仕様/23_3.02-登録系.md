# 23_3.02-登録系

## マーケット相場見積

HTTPメソッド: `POST`
パス: `/api/market/price-quote`
コントローラ: `MarketController`
アクション物理名: `CreatePriceQuote`

リクエスト:

| 種別 | 名前 | 型 | 必須 | 説明 |
|---|---|---|---|---|
| Body | `accountId` | GUID |  | 所有権確認対象アカウント |
| Body | `itemCategory` | string | ✓ | item カテゴリ |
| Body | `itemId` | string | ✓ | item マスタ ID |
| Body | `instanceType` | string |  | 個体品の種別 |
| Body | `instanceId` | GUID |  | 個体 UUID |
| Body | `quantity` | int | ✓ | 数量 |
| Body | `unitPrice` | long |  | 判定対象単価 |

レスポンス:

| ステータス | 内容 | ボディ |
|---|---|---|
| 200 OK | 見積成功 | [[23_1.00-モデル定義]].相場見積レスポンス |
| 400 Bad Request | 入力不正 | `ProblemDetails` 互換 |
| 401 Unauthorized | API キー未指定または無効 | なし |
| 404 Not Found | item または個体が存在しない | なし |

処理内容:

1. item マスタを取得する。
2. 個体品の場合は装備個体を取得し、必要に応じて所有権を検証する。ルーンはスタック品として item マスタと出品数量だけを評価する。
3. 店売り価格と推奨価格を算出する。
4. 約定履歴から相場を算出する。
5. `unitPrice` が指定されている場合は価格ガード判定を行う。
6. 相場見積レスポンスを返す。

## マーケット出品作成

HTTPメソッド: `POST`
パス: `/api/market/listings`
コントローラ: `MarketController`
アクション物理名: `CreateListing`

リクエスト:

| 種別 | 名前 | 型 | 必須 | 説明 |
|---|---|---|---|---|
| Body | `sellerAccountId` | GUID | ✓ | 出品アカウント UUID |
| Body | `sourceEntries` | object[] | ✓ | `inventoryEntryId` と `quantity` を持つ escrow 元一覧。合計は出品数量と一致 |
| Body | `itemCategory` | string | ✓ | item カテゴリ |
| Body | `itemId` | string | ✓ | item マスタ ID |
| Body | `instanceType` | string |  | 個体品の種別 |
| Body | `instanceId` | GUID |  | 個体 UUID |
| Body | `quantity` | int | ✓ | 出品数量 |
| Body | `currencyId` | string | ✓ | `gold` 固定。Plugin 設定済み Gold 額面を使用する |
| Body | `unitPrice` | long | ✓ | 出品単価 |
| Body | `expiresAt` | DateTime |  | 掲載期限 |
| Body | `createdBy` | GUID | ✓ | 作成者 UUID |

レスポンス:

| ステータス | 内容 | ボディ |
|---|---|---|
| 201 Created | 出品作成成功 | [[23_1.00-モデル定義]].マーケット出品レスポンス |
| 400 Bad Request | 入力不正、価格ガード不合格、出品数上限超過 | `ProblemDetails` 互換 |
| 401 Unauthorized | API キー未指定または無効 | なし |
| 404 Not Found | アカウント、item、出品元が存在しない | なし |
| 409 Conflict | 所有権競合、既に出品中、楽観ロック競合 | `ProblemDetails` 互換 |

処理内容:

1. 出品者アカウントを検証する。
2. Serializable transaction 内で出品枠制限を検証する。

   `market_expansion_token_alpha`／`beta`／`gamma`／`delta` の所持数を CURRENCY inventory から再集計し、αは最大6、β／γ／δは各最大9として Tier 基本枠へ加算する。種類ごとの反映上限を超えた所持数は保持するが、枠には加算しない。

    | 項目 | 内容 |
    |---|---|
    | 使用済み出品枠 | `ACTIVE` / `SUSPENDED` / 売上未受取 `SOLD` の出品数 |
    | 上限 | 累計成立取引数から算出した Tier 基本枠 + GAME/CURRENCY inventory のマーケット拡張トークン有効枠 |
    | 上限超過 | 400 を返し、出品は作成しない |

3. 全 source entry を更新ロックして、seller の GAME BAG/HOTBAR 内で item／個体 identity と一致することを検証する。個体装備は active loadout 装備中なら拒否する。
4. item マスタが取引不可でなく、単価が売値を上回ることを検証する。売却不可フラグと売値 0 は出品対象外にしない。
5. 対象アイテムを escrow として確保する。スタックは source ごとに数量を減算し、個体品は source entry を削除状態にする。
6. ロック取得後の個体値を使って相場見積を内部実行し、相場乖離を検証する。
7. `market_listing` を `ACTIVE`、`remainingQuantity = quantity` で作成し、`market_listing_source` に source ごとの確保数量を保存する。
8. `market_price_snapshot` へ出品時見積を保存する。
9. `sellerAccountName` を含む作成した出品を返す。
10. COMMIT結果不明でexecution strategyが再試行する場合は、試行外で固定した同じ`listingId`を先に照会する。確定済みなら同じ出品を成功応答として再生し、未確定の場合だけescrow確保以降を再実行する。

## マーケット購入確定

HTTPメソッド: `POST`
パス: `/api/market/listings/{listingId}/purchase`
コントローラ: `MarketController`
アクション物理名: `PurchaseListing`

リクエスト:

| 種別 | 名前 | 型 | 必須 | 説明 |
|---|---|---|---|---|
| Path | `listingId` | GUID | ✓ | 出品 UUID |
| Body | `buyerAccountId` | GUID | ✓ | 購入アカウント UUID |
| Body | `quantity` | int | ✓ | 購入数量。出品残数以下、個体品は 1 |
| Body | `idempotencyKey` | string | ✓ | 二重購入防止キー。1〜100 文字 |
| Body | `updatedBy` | GUID | ✓ | 更新者 UUID |

レスポンス:

| ステータス | 内容 | ボディ |
|---|---|---|
| 200 OK | 購入成功 | [[23_1.00-モデル定義]].マーケット取引レスポンス |
| 400 Bad Request | 自分の出品購入、購入数量不正、Gold不足 | `ProblemDetails` 互換 |
| 401 Unauthorized | API キー未指定または無効 | なし |
| 404 Not Found | 出品または購入者アカウントが存在しない | なし |
| 409 Conflict | 購入可能残数不足、状態競合、二重購入競合 | `ProblemDetails` 互換 |

処理内容:

1. `listingId` の出品を更新ロック付きで取得する。
2. 出品状態が `ACTIVE` であることを検証する。
3. 購入者が出品者と異なることを検証する。
4. 購入数量が `remainingQuantity` 以下であることを検証する。
5. 購入者 Gold currency inventory を更新ロックし、購入者 Gold 不足を検証して指定数量分だけ減算する。出品者 Gold は加算しない。
6. escrow 中のアイテムを指定数量だけ購入者 BAG へ移転する。個体品は source entry を移し、個体所有者も更新する。
7. `remainingQuantity` を減算し、0 になった場合だけ出品を `SOLD` に更新する。
8. `market_transaction` を購入ごとに作成する。
9. seller / buyer の `market_account_state.completed_trade_count` を更新する。
10. 購入者の Gold・取得 item を含む `affectedInventoryEntryIds` を取引 receipt へ永続化し、レスポンスで返す。出品者売上は `SOLD` 後に売上受取 API で加算する。
11. 同じ出品・数量・`idempotencyKey` の再送は receipt を再生する。同じキーを別出品または別数量で使用した場合は 409 とする。

補足:

- Gold 額面は Plugin `GoldDenomination` と同じ `gold` / `gold_coin` / `gold_ingot` / `gold_block` / `gold_diamond` / `gold_diamond_block` / `yggdrasil_star_core`（互換 `ast_gold`）を API が正本として再構成する。
