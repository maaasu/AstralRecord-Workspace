# 23_3.01-取得系

## マーケット出品一覧取得

HTTPメソッド: `GET`
パス: `/api/market/listings`
コントローラ: `MarketController`
アクション物理名: `GetListings`

リクエスト:

| 種別 | 名前 | 型 | 必須 | 説明 |
|---|---|---|---|---|
| Query | `seller_account_id` | GUID |  | 出品者アカウントで絞り込み |
| Query | `item_category` | string |  | item カテゴリで絞り込み |
| Query | `item_id` | string |  | item ID で絞り込み |
| Query | `status` | string |  | 未指定時は `ACTIVE`。`ALL` 指定時は状態で絞り込まない（自分の出品一覧用） |
| Query | `min_price` | long |  | 最低単価 |
| Query | `max_price` | long |  | 最高単価 |
| Query | `sort` | string |  | `listed_desc` / `price_asc` / `price_desc` |
| Query | `page` | int |  | 1 始まり。未指定時は 1 |
| Query | `page_size` | int |  | 未指定時は 50、最大 100 |

レスポンス:

| ステータス | 内容 | ボディ |
|---|---|---|
| 200 OK | 取得成功 | [[23_1.00-モデル定義]].マーケット出品レスポンス配列 |
| 400 Bad Request | クエリ不正 | `ProblemDetails` 互換 |
| 401 Unauthorized | API キー未指定または無効 | なし |

処理内容:

1. クエリ条件を検証する。
2. `market_listing` から条件に一致する出品を取得する。
3. `status` 未指定時は `ACTIVE` のみ返す。`ALL` の場合は状態で絞り込まない。
4. ページングと並び順を適用する。
5. `account` の `account_name` と約定履歴からの未受取売上合計を各出品へ付加する。source entry ID は出品作成・キャンセル応答にだけ含める。アカウント UUID は内部識別用に保持し、公開表示には表示名を使用する。
6. `EQUIPMENT` の個体出品は、ページ内の instance ID をまとめて `equipment_instance`、stat roll、enchant、rune から取得し、強化値・ランダム値等を `equipmentInstance` として付加する。出品ごとの個別クエリは行わない。

## 公開マーケット取引履歴取得

HTTPメソッド: `GET`
パス: `/api/market/transactions`
コントローラ: `MarketController`
アクション物理名: `GetTradeHistory`

リクエスト:

| 種別 | 名前 | 型 | 必須 | 説明 |
|---|---|---|---|---|
| Query | `item_category` | string |  | item カテゴリの完全一致。最大50文字 |
| Query | `item_id` | string |  | item ID の完全一致。最大100文字 |
| Query | `page` | int |  | 1 始まり。未指定時は1、最大100000 |
| Query | `page_size` | int |  | 未指定時は50、最大100 |

レスポンス:

| ステータス | 内容 | ボディ |
|---|---|---|
| 200 OK | 取得成功 | [[23_1.00-モデル定義]].公開マーケット取引履歴ページレスポンス |
| 400 Bad Request | クエリ不正 | `ProblemDetails` 互換 |
| 401 Unauthorized | API キー未指定または無効 | なし |

処理内容:

1. `market_transaction` を `completed_at`、`transaction_id` の降順で取得する。
2. 指定された item カテゴリ、item ID の完全一致条件を適用する。
3. 公開画面には商品、数量、単価、総額、成立日時だけを返す。売主・買主のアカウント UUID、名前、手数料、売主受取額、冪等キー、inventory entry は返さない。
4. `page_size` は画面へ返す件数とする。API は内部で1件余分に取得し、余分な行を `items` へ含めず `hasNextPage` を判定する。`Skip` のページ幅には `page_size` を使用する。

## マーケット出品取得

HTTPメソッド: `GET`
パス: `/api/market/listings/{listingId}`
コントローラ: `MarketController`
アクション物理名: `GetListing`

リクエスト:

| 種別 | 名前 | 型 | 必須 | 説明 |
|---|---|---|---|---|
| Path | `listingId` | GUID | ✓ | 出品 UUID |

レスポンス:

| ステータス | 内容 | ボディ |
|---|---|---|
| 200 OK | 取得成功 | [[23_1.00-モデル定義]].マーケット出品レスポンス |
| 401 Unauthorized | API キー未指定または無効 | なし |
| 404 Not Found | 出品未登録または論理削除済み | なし |

処理内容:

1. `listingId` で出品を取得する。
2. 論理削除済みの場合は 404 を返す。
3. 出品者アカウントの `account_name` と `slot_index` を `sellerAccountName` / `sellerAccountSlotIndex` として付加する。
4. `EQUIPMENT` の個体出品は装備個体と stat roll／enchant／rune を取得し、`equipmentInstance` として付加する。Plugin は既存の装備 tooltip 生成へ使用し、Web は購入前性能として表示する。

## アカウントマーケット概要取得

HTTPメソッド: `GET`
パス: `/api/market/accounts/{accountId}/summary`
コントローラ: `MarketController`
アクション物理名: `GetAccountSummary`

リクエスト:

| 種別 | 名前 | 型 | 必須 | 説明 |
|---|---|---|---|---|
| Path | `accountId` | GUID | ✓ | アカウント UUID |

レスポンス:

| ステータス | 内容 | ボディ |
|---|---|---|
| 200 OK | 取得成功 | [[23_1.00-モデル定義]].アカウントマーケット概要レスポンス |
| 401 Unauthorized | API キー未指定または無効 | なし |
| 404 Not Found | アカウント未登録または論理削除済み | なし |

処理内容:

1. アカウント存在を検証する。
2. `market_account_state` を取得する。存在しない場合は初期状態を作成して返す。
3. `market_listing` から `ACTIVE` / `SUSPENDED` の現在出品数と、`ACTIVE` / `SUSPENDED` / 売上未受取 `SOLD` の使用済み出品枠数を集計する。
4. 成立取引数から Tier の基本枠を算出する。
5. `GAME` / `CURRENCY` inventory のマーケット拡張トークン所持数量を種類ごとの上限まで集計し、基本枠へ加算した `maxListingSlotCount` を返す。
