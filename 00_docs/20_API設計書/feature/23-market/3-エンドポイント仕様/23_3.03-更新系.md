# 23_3.03-更新系

## マーケット出品キャンセル

HTTPメソッド: `POST`
パス: `/api/market/listings/{listingId}/cancel`
コントローラ: `MarketController`
アクション物理名: `CancelListing`

リクエスト:

| 種別 | 名前 | 型 | 必須 | 説明 |
|---|---|---|---|---|
| Path | `listingId` | GUID | ✓ | 出品 UUID |
| Body | `sellerAccountId` | GUID | ✓ | 出品アカウント UUID |
| Body | `reason` | string |  | キャンセル理由 |
| Body | `idempotencyKey` | string | ✓ | 同一キャンセルの再送・結果照会で固定する冪等キー |
| Body | `updatedBy` | GUID | ✓ | 更新者 UUID |

レスポンス:

| ステータス | 内容 | ボディ |
|---|---|---|
| 200 OK | キャンセル成功、または同一要求の確定済み receipt 再生 | [[23_1.00-モデル定義]].マーケット出品レスポンス |
| 400 Bad Request | キャンセル不能状態 | `ProblemDetails` 互換 |
| 401 Unauthorized | API キー未指定または無効 | なし |
| 403 Forbidden | 出品者本人ではない | `ProblemDetails` 互換 |
| 404 Not Found | 出品が存在しない | なし |
| 409 Conflict | 状態競合、異なる要求による二重キャンセル、receipt 破損 | `ProblemDetails` 互換 |

処理内容:

1. `listingId` の出品を、論理削除済みキャンセル receipt を含めて更新ロック付きで取得する。
2. `sellerAccountId` が出品者と一致することを検証する。
3. 同じ `idempotencyKey` と要求ハッシュの receipt があれば、保存済みレスポンスを再生して 200 を返す。キーまたは要求内容が異なる確定済みキャンセルは 409 を返す。
4. 新規キャンセルでは出品状態が `ACTIVE` または `SUSPENDED` であることを検証する。
5. `market_listing_source` の未売却 `remainingQuantity` を seller inventory へ返却する。元 entry の slot が使用中なら slot 未指定にし、同じ inventory・item の有効な slot 未指定スタックが既にあれば更新ロックを取得してそこへ数量を加算する。
6. 売上がない場合は出品を `CANCELED` にして論理削除し、枠を解放する。
7. 部分売却済みの場合は返却後に `SOLD` の売上受取待ちとして残し、売上受取まで枠を使用する。
8. `sourceInventoryEntryIds` と、実際の返却先である `affectedInventoryEntryIds` を含むレスポンス、要求ハッシュ、完了日時を同じ SQL transaction の receipt として保存して返す。

## マーケット出品キャンセル結果照会

HTTPメソッド: `GET`
パス: `/api/market/listings/{listingId}/cancel-result`
コントローラ: `MarketController`
アクション物理名: `GetCancelResult`

リクエスト:

| 種別 | 名前 | 型 | 必須 | 説明 |
|---|---|---|---|---|
| Path | `listingId` | GUID | ✓ | 出品 UUID |
| Query | `sellerAccountId` | GUID | ✓ | 出品アカウント UUID |
| Query | `idempotencyKey` | string | ✓ | キャンセル POST と同じ冪等キー |

レスポンス:

| ステータス | 内容 | ボディ |
|---|---|---|
| 200 OK | 同じキーのキャンセルが SQL に確定済み | 保存済み [[23_1.00-モデル定義]].マーケット出品レスポンス |
| 400 Bad Request | GUID または冪等キーが不正 | `ProblemDetails` 互換 |
| 403 Forbidden | 出品者本人ではない | `ProblemDetails` 互換 |
| 404 Not Found | 出品または確定済みキャンセル receipt が存在しない | なし |
| 409 Conflict | 別キーの receipt、または receipt 破損 | `ProblemDetails` 互換 |

取消 transaction と同じ出品行の更新ロックを取得してから receipt を読む。POST の応答を失った呼び出し元は、この照会結果だけを操作確定の根拠にできる。

## マーケット売上受取

HTTPメソッド: `POST`
パス: `/api/market/listings/{listingId}/claim-proceeds`
コントローラ: `MarketController`
アクション物理名: `ClaimProceeds`

リクエスト:

| 種別 | 名前 | 型 | 必須 | 説明 |
|---|---|---|---|---|
| Path | `listingId` | GUID | ✓ | 売上受取対象の出品 UUID |
| Body | `sellerAccountId` | GUID | ✓ | 出品アカウント UUID |
| Body | `idempotencyKey` | string | ✓ | 同一出品の受取再送で固定する冪等キー |
| Body | `updatedBy` | GUID | ✓ | 更新者 UUID |

レスポンス:

| ステータス | 内容 | ボディ |
|---|---|---|
| 200 OK | 売上受取成功、または同一キーでの確定済み receipt 再生 | [[23_1.00-モデル定義]].売上受取リクエスト・レスポンス |
| 400 Bad Request | 未売却・受取不能状態 | `ProblemDetails` 互換 |
| 401 Unauthorized | API キー未指定または無効 | なし |
| 403 Forbidden | 出品者本人ではない | `ProblemDetails` 互換 |
| 404 Not Found | 出品が存在しない、または旧仕様で既に精算済み | なし |
| 409 Conflict | 売上なし、Gold 加算競合・上限超過、異なるキーでの二重受取 | `ProblemDetails` 互換 |

処理内容:

1. `listingId` の出品を、論理削除済み受取 receipt を含めて更新ロック付きで取得する。
2. `sellerAccountId` が出品者と一致することを検証する。
3. 論理削除済みで同じ `idempotencyKey` の receipt があれば、保存済みの金額と `affectedInventoryEntryIds` を再生して 200 を返す。別キーの受取済み receipt は 409 を返す。
4. 未受取出品では状態が `SOLD` であることと、当該出品の `market_transaction.seller_proceeds` 合計が 1 以上であることを検証する。
5. 出品者の Gold currency inventory へ合算額を加算する。
6. `idempotencyKey`、金額、更新済み通貨 entry ID、受取日時を出品へ receipt として保存し、出品を論理削除して枠を解放する。
7. 出品者通貨の `affectedInventoryEntryIds` を返す。
