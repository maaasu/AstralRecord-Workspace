# 23_3.03-更新系

## マーケット出品キャンセル

HTTPメソッド: `POST`
パス: `/api/market/listings/{listingId}/cancel`
コントローラ: `MarketController`
アクション物理名: `CancelListing`

リクエスト:

| 種別 | 名前 | 型 | 必須 | 説明 |
|---|---|---|---|---|
| Path | `listingId` | GUID | ✓ | 出品 UUID |
| Body | `sellerAccountId` | GUID | ✓ | 出品アカウント UUID |
| Body | `reason` | string |  | キャンセル理由 |
| Body | `updatedBy` | GUID | ✓ | 更新者 UUID |

レスポンス:

| ステータス | 内容 | ボディ |
|---|---|---|
| 200 OK | キャンセル成功 | [[23_1.00-モデル定義]].マーケット出品レスポンス |
| 400 Bad Request | キャンセル不能状態 | `ProblemDetails` 互換 |
| 401 Unauthorized | API キー未指定または無効 | なし |
| 403 Forbidden | 出品者本人ではない | `ProblemDetails` 互換 |
| 404 Not Found | 出品が存在しない | なし |
| 409 Conflict | 状態競合 | `ProblemDetails` 互換 |

処理内容:

1. `listingId` の出品を更新ロック付きで取得する。
2. `sellerAccountId` が出品者と一致することを検証する。
3. 出品状態が `ACTIVE` または `SUSPENDED` であることを検証する。
4. `market_listing_source` の escrow 元へ未売却の `remainingQuantity` を返却する。
5. 売上がない場合は出品を `CANCELED` にして論理削除し、枠を解放する。
6. 部分売却済みの場合は返却後に `SOLD` の売上受取待ちとして残し、売上受取まで枠を使用する。
7. `sellerAccountName`、`sourceInventoryEntryIds`、`pendingProceeds` を含む更新後の出品レスポンスを返す。

## マーケット売上受取

HTTPメソッド: `POST`
パス: `/api/market/listings/{listingId}/claim-proceeds`
コントローラ: `MarketController`
アクション物理名: `ClaimProceeds`

リクエスト:

| 種別 | 名前 | 型 | 必須 | 説明 |
|---|---|---|---|---|
| Path | `listingId` | GUID | ✓ | 売上受取対象の出品 UUID |
| Body | `sellerAccountId` | GUID | ✓ | 出品アカウント UUID |
| Body | `idempotencyKey` | string | ✓ | 同一出品の受取再送で固定する冪等キー |
| Body | `updatedBy` | GUID | ✓ | 更新者 UUID |

レスポンス:

| ステータス | 内容 | ボディ |
|---|---|---|
| 200 OK | 売上受取成功、または同一キーでの確定済み receipt 再生 | [[23_1.00-モデル定義]].売上受取リクエスト・レスポンス |
| 400 Bad Request | 未売却・受取不能状態 | `ProblemDetails` 互換 |
| 401 Unauthorized | API キー未指定または無効 | なし |
| 403 Forbidden | 出品者本人ではない | `ProblemDetails` 互換 |
| 404 Not Found | 出品が存在しない、または旧仕様で既に精算済み | なし |
| 409 Conflict | 売上なし、Gold 加算競合・上限超過、異なるキーでの二重受取 | `ProblemDetails` 互換 |

処理内容:

1. `listingId` の出品を、論理削除済み受取 receipt を含めて更新ロック付きで取得する。
2. `sellerAccountId` が出品者と一致することを検証する。
3. 論理削除済みで同じ `idempotencyKey` の receipt があれば、保存済みの金額と `affectedInventoryEntryIds` を再生して 200 を返す。別キーの受取済み receipt は 409 を返す。
4. 未受取出品では状態が `SOLD` であることと、当該出品の `market_transaction.seller_proceeds` 合計が 1 以上であることを検証する。
5. 出品者の Gold currency inventory へ合算額を加算する。
6. `idempotencyKey`、金額、更新済み通貨 entry ID、受取日時を出品へ receipt として保存し、出品を論理削除して枠を解放する。
7. 出品者通貨の `affectedInventoryEntryIds` を返す。
