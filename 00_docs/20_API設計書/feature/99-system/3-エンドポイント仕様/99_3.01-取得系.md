# 99_3.01-取得系

## 1. 取得系エンドポイント仕様

### 疎通確認

HTTPメソッド: `GET`
パス: `/api/health`
コントローラ: `HealthController`
アクション物理名: `Get`

責務:

API サーバーへの接続可否を判定するためのレスポンスを返す。
DB やマスタデータの可用性までは保証しない（単純な「アプリケーションが応答可能か」のみ）。

リクエスト:

| 種別 | 名前 | 型 | 必須 | 説明 |
|---|---|---|---|---|
| Header | `X-Api-Key` | string | ✓ | API キー |

レスポンス:

| ステータス | 内容 | ボディ |
|---|---|---|
| 200 OK | 接続成功 | HealthCheckResponse |
| 401 Unauthorized | API キー未指定/無効 | なし |

#### HealthCheckResponse

物理名: `HealthCheckResponse`

| フィールド | 型 | 説明 |
|---|---|---|
| `status` | string | 常に `"ok"` |
| `service` | string | サービス名（`AstralRecordApi`） |
| `timestamp` | DateTime (ISO 8601, UTC) | レスポンス生成時刻 |

処理内容:

1. 認証パイプラインで `X-Api-Key` を検証する
2. `status = "ok"` / `service = "AstralRecordApi"` / `timestamp = DateTime.UtcNow` を組み立てて 200 で返す

### Seeder 実行履歴取得

HTTPメソッド: `GET`
パス: `/api/master-data/seed-runs`
コントローラ: `MasterDataController`
アクション物理名: `GetSeedRuns`

責務:

MasterDataDB Seeder の実行履歴を新しい順で取得する。

リクエスト:

| 種別 | 名前 | 型 | 必須 | 説明 |
|---|---|---|---|---|
| Header | `X-Api-Key` | string | ✓ | API キー |
| Query | `limit` | int | 省略可 | 取得件数。1〜100 に丸める。既定値は 20 |

レスポンス:

| ステータス | 内容 | ボディ |
|---|---|---|
| 200 OK | 取得成功 | Seeder 実行履歴レスポンス の配列 |
| 401 Unauthorized | API キー未指定/無効 | なし |

#### Seeder 実行履歴レスポンス

物理名: `MasterDataSeedRunResponse`

| フィールド | 型 | 説明 |
|---|---|---|
| `seedRunId` | GUID | Seeder 実行 ID |
| `triggerType` | string | 実行契機（`STARTUP` / `SEEDER_API` / `MANUAL`） |
| `status` | string | 実行状態 |
| `sourceRootPath` | string | filebase ルートパス |
| `startedAt` | DateTime (ISO 8601) | 開始日時 |
| `finishedAt` | DateTime (ISO 8601)? | 終了日時 |
| `fileCount` | int | 処理ファイル数 |
| `upsertedCount` | int | 登録・更新件数 |
| `deletedCount` | int | 削除件数 |
| `skippedCount` | int | スキップ件数 |
| `errorMessage` | string? | エラー内容 |

処理内容:

1. 認証パイプラインで `X-Api-Key` を検証する
2. `limit` を 1〜100 に丸める
3. リポジトリで Seeder 実行履歴を取得して 200 で返す

### MasterDataDB 参照状態取得

HTTPメソッド: `GET`
パス: `/api/master-data/health`
コントローラ: `MasterDataController`
アクション物理名: `GetHealth`

責務:

MasterDataDB に有効なマスタエントリが存在し、最後の Seeder 成功状態を参照できるか確認する。

リクエスト:

| 種別 | 名前 | 型 | 必須 | 説明 |
|---|---|---|---|---|
| Header | `X-Api-Key` | string | ✓ | API キー |

レスポンス:

| ステータス | 内容 | ボディ |
|---|---|---|
| 200 OK | 取得成功 | MasterDataDB 参照状態レスポンス |
| 401 Unauthorized | API キー未指定/無効 | なし |

#### MasterDataDB 参照状態レスポンス

物理名: `MasterDataHealthResponse`

| フィールド | 型 | 説明 |
|---|---|---|
| `status` | string | `ok` / `empty` / `degraded` |
| `activeEntryCount` | int | 有効マスタエントリ数 |
| `lastSeedRunId` | GUID? | 直近 Seeder 実行 ID |
| `lastSeedRunStatus` | string? | 直近 Seeder 実行状態 |
| `lastSucceededAt` | DateTime (ISO 8601)? | 直近成功日時 |

処理内容:

1. 認証パイプラインで `X-Api-Key` を検証する
2. リポジトリで MasterDataDB の有効エントリ数と直近 Seeder 実行結果を取得する
3. 参照状態を 200 で返す
