# 99_3.02-登録系

## 1. 登録系エンドポイント仕様

### MasterDataDB 同期

HTTPメソッド: `POST`
パス: `/api/master-data/seed`
コントローラ: `MasterDataController`
アクション物理名: `Seed`

責務:

filebase の YAML を走査し、MasterDataDB の entry/reference へ差分反映する。
`mode=rebuild` 指定時は既存referenceを物理削除し、既存entryをtombstoneとして論理削除してから再投入する。同一type/idは既存entryを再利用し、再投入されなかった削除済みシジル定義は補償メール添付の解決用に保持する。

リクエスト:

| 種別 | 名前 | 型 | 必須 | 説明 |
|---|---|---|---|---|
| Header | `X-Api-Key` | string | ✓ | API キー |
| Query | `mode` | string | 省略可 | `diff`（既定）または `rebuild` |

レスポンス:

| ステータス | 内容 | ボディ |
|---|---|---|
| 200 OK | 同期成功 | Seeder 実行結果レスポンス |
| 401 Unauthorized | API キー未指定/無効 | なし |
| 422 Unprocessable Entity | YAML 構文エラーまたは必須参照未解決により同期失敗 | Seeder 実行結果レスポンス |

#### Seeder 実行結果レスポンス

物理名: `MasterDataSeedResultResponse`

| フィールド | 型 | 説明 |
|---|---|---|
| `seedRunId` | GUID | Seeder 実行 ID |
| `triggerType` | string | 実行契機。Seeder API からの実行は `SEEDER_API` |
| `status` | string | 実行状態。失敗時は `FAILED` |
| `sourceRootPath` | string | filebase ルートパス |
| `startedAt` | DateTime (ISO 8601) | 開始日時 |
| `finishedAt` | DateTime (ISO 8601)? | 終了日時 |
| `fileCount` | int | 処理ファイル数 |
| `upsertedCount` | int | 登録・更新件数 |
| `deletedCount` | int | 削除件数 |
| `skippedCount` | int | スキップ件数 |
| `errorMessage` | string? | エラー内容 |
| `warnings` | string[] | 失敗扱いにしない警告 |

処理内容:

1. 認証パイプラインで `X-Api-Key` を検証する
2. `mode` を同期モードへ変換する

    | 条件 | 同期モード |
    |---|---|
    | `mode = rebuild`（大小文字は区別しない） | Rebuild |
    | 上記以外 | Diff |

3. Seeder を `SEEDER_API` 契機で実行する
4. Seeder 実行結果の `status` が `FAILED` の場合は 422、それ以外は 200 で結果を返す
