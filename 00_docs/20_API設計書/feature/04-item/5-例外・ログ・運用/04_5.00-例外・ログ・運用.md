# 04_5.00-例外・ログ・運用

API `item` 機能の例外応答とログ。  
本機能のログ・メッセージはコード上にハードコーディングする。LogId は使用しない。

## 1. 共通エラーレスポンス

| ステータス | 発生条件 | ボディ |
|---|---|---|
| 401 Unauthorized | `X-Api-Key` 欠落 / 不一致 | なし |
| 404 Not Found | itemId 未定義 | なし |
| 500 Internal Server Error | 上記以外の例外 | `ProblemDetails` 互換 |

## 2. ログ一覧

### 2.1 起動時 YAML ロード

| 項目 | 内容 |
|---|---|
| レベル | Information |
| テンプレート | `Loaded {Count} items from filebase` |
| 出力条件 | アプリ起動時に YAML ロード完了 |
| 引数 | `{Count}` = 読み込まれたアイテム数 |

| 項目 | 内容 |
|---|---|
| レベル | Error |
| テンプレート | `Failed to load item YAML: {Path}` |
| 出力条件 | YAML パース失敗時 |
| 引数 | `{Path}` = 該当ファイルパス |
| 出力例外 | `_logger.LogError(ex, ...)` で添付 |

### 2.2 取得系

| 項目 | 内容 |
|---|---|
| レベル | Error |
| テンプレート | `Failed to get item {ItemId}` |
| 出力条件 | 例外発生時 |
| 引数 | `{ItemId}` = 対象アイテムID |
| 出力例外 | `_logger.LogError(ex, ...)` で添付 |

## 3. 運用上の注意

- YAML はアプリ起動時のみロードする。ホットリロードは未対応。
- インメモリでの保持となるため、データ追加・修正後はアプリ再起動が必要。
- カテゴリ別フィールドは `50_filebase` 側のスキーマと一致している必要がある。乖離は API 起動時のロードエラーで検知する。
