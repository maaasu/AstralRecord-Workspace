# 10_3.01-取得系

## 1. 取得系エンドポイント仕様

### クラス一覧取得

HTTPメソッド: `GET`
パス: `/api/class`
コントローラ: `ClassController`
アクション物理名: `GetAll`

責務:

MasterDataDB の `dbo.master_data_entry`（`master_type = 'class'`）から有効レコードを取得し、各 `payload_json` をデシリアライズして主要項目を返す。

リクエスト:

| 種別 | 名前 | 型 | 必須 | 説明 |
|---|---|---|---|---|
| Header | `X-Api-Key` | string | ✓ | API キー |

レスポンス:

| ステータス | 内容 | ボディ |
|---|---|---|
| 200 OK | 取得成功 | [[10_1.00-モデル定義]].クラス一覧レスポンス要素 の配列 |
| 401 Unauthorized | API キー未指定/無効 | なし |

処理内容:

1. 認証パイプラインで `X-Api-Key` を検証する
2. MasterDataDB から `master_type = 'class'` かつ `is_deleted = 0` の `payload_json` を取得する
3. 各 `payload_json` を [[10_1.00-モデル定義]].クラス詳細レスポンス へデシリアライズし、主要項目（`id` / `name` / `order` / `shortName` / `role`）に射影する。`order` の昇順、同値時は `id` の昇順で 200 の配列を返す
4. 例外時は [[10_5.00-例外・ログ・運用]] のログを記録し 500 を返す

---

### クラス詳細取得

HTTPメソッド: `GET`
パス: `/api/class/{classId}`
コントローラ: `ClassController`
アクション物理名: `GetById`

リクエスト:

| 種別 | 名前 | 型 | 必須 | 説明 |
|---|---|---|---|---|
| Header | `X-Api-Key` | string | ✓ | API キー |
| Path | `classId` | string | ✓ | クラス ID |

レスポンス:

| ステータス | 内容 | ボディ |
|---|---|---|
| 200 OK | 取得成功 | [[10_1.00-モデル定義]].クラス詳細レスポンス |
| 401 Unauthorized | API キー未指定/無効 | なし |
| 404 Not Found | 未定義 classId | なし |

処理内容:

1. 認証パイプラインで `X-Api-Key` を検証する
2. MasterDataDB から `master_type = 'class'` かつ `master_id = classId` で検索する（取得失敗時は 404）
3. `payload_json` を [[10_1.00-モデル定義]].クラス詳細レスポンス へデシリアライズし 200 で返す
4. 例外時は [[10_5.00-例外・ログ・運用]] のログを記録し 500 を返す


## 詳細マスタの分割取得と共有キャッシュ

`GET /api/{kind}/details?offset=0&limit=100`（kindは `item` / `skill` / `class`）は有効な詳細を分割取得する。`X-Api-Key` は従来と同じ。`offset` は0以上、`limit` は1～100（既定100）。範囲違反は400。戻り値は `{"generation":"<APIプロセスの世代>","total":123,"items":[{"master":<単件詳細と同じDTO>,"responseBodySha256":"<単件MVC JSON本文のSHA256>"}]}`。2ページ目以降は最初の `generation` をqueryへ付け、世代不一致は409。offset以降に該当がなければitemsは空。並びはitemがcategory→master_id、skill/classがmaster_id順。削除済みシジルはページ/一覧に含めず、旧単件item APIだけで引き続き解決できる。

Item/Skill/Class/Buff/World/SetEffect/Enchantの変換済みマスタは、最初の参照時に種別単位でAPIプロセス共有キャッシュへ読み込む。同じ種別の同時初回取得は一度だけDB/変換を行う。任意の照会IDをキャッシュキーにしない。Item/Skill/ClassのHTTP取得はcache missのDB I/Oを非同期で行う。Seederのデータtransaction commit直後に全キャッシュ世代を失効させる（履歴の成功記録失敗時も、確定したデータは再読込する）。rollbackしたseedでは失効させない。失効前に開始したfillは旧値を公開せず再取得する。外部DB更新や別APIプロセスのseedは即時通知されないため、5分で共有世代を失効させて次の参照で反映する。複数プロセス間の即時通知は持たない。YAMLの意味・DTO変換ルールは従来どおり。
