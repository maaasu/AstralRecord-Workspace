# 33_1.00-モデル定義

## Admissionレスポンス

物理名: `NetworkAdmissionResponse`

| フィールド | 型 | nullable | 説明 |
|---|---|---|---|
| `uuid` | GUID | ✗ | プレイヤーUUID |
| `mcid` | string | ✗ | 未登録時は空文字 |
| `registered` | bool | ✗ | 永続ユーザーの存在 |
| `admitted` | bool | ✗ | Lobby参加可否 |
| `denyReason` | string | ✓ | BAN時は`banned` |
| `permission` | int | ✗ | 未登録時は0。Proxy最高権限UUIDは永続値にかかわらず99 |
| `banIndefinite` | bool | ✗ | 無期限BAN |
| `banDate` | datetime | ✓ | 有期限BAN終了日時 |
| `accountId` | GUID | ✓ | 選択アカウント |
| `serverTimeUtc` | datetime | ✗ | API応答時刻 |
| `banReason` / `banExpiresAtUtc` | string / datetimeoffset | ✓ | 管理BAN理由とUTC解除日時 |
| `debugUser` / `whitelisted` | bool | ✗ | 対象チャンネルの登録状態 |
| `channelKnown` / `settingsInitialized` | bool | ✗ | 管理チャンネルの存在と設定初期化状態 |

## プレイヤー所在

物理名: `NetworkPlayerHeartbeatRequest` / `NetworkPlayerPresenceResponse`

UUID、MCID、serverId、channel、表示アカウント、レベル、クラス名、AFK状態を持つ。レスポンスは`lastSeenUtc`を追加する。

## サーバー状態

物理名: `NetworkServerHeartbeatRequest` / `NetworkServerPresenceResponse`

serverId、表示名、state、onlineCount、一般プレイヤーの基本上限`capacity`、寄付者追加枠`donorExtraPlayers`、管理者追加枠`adminExtraPlayers`を持つ。レスポンスは`lastSeenUtc`を追加する。管理者が利用できる追加枠は寄付者追加枠と管理者追加枠の合計とする。

## チャット

物理名: `NetworkChatPublishRequest` / `NetworkChatMessageResponse` / `NetworkChatBatchResponse`

messageId、source（`minecraft`または`discord`）、sourceServerId、authorName、message、kind（`chat`または`lifecycle`、省略時`chat`）を持つ。Minecraftプレイヤーの通常チャットおよびlifecycle通知では、Discordのスキンアイコン解決に使うnullableなauthorPlayerIdとauthorMinecraftNameも持つ。両項目は同時指定とし、旧クライアントおよびDiscord発言では省略できる。lifecycle通知のactionは`join`（ネットワーク参加）、`channel_connect`（チャンネル接続）、`leave`（ネットワーク退出）のいずれかで、新クライアントはプレイヤー識別情報とともに指定する。旧lifecycle通知のaction省略は互換性のため許可する。メッセージレスポンスはsequenceとcreatedAtUtcを追加する。差分取得はAPIプロセス起動ごとに変わるgenerationId、全source共通のlatestSequence、messagesを持つbatchを返す。クライアントは初回接続時にlatestSequenceをカーソルとして過去の中継履歴を再送せず、generationId変更時はcursorを0へ戻す。latestSequenceを返さない旧APIは中継開始条件を満たさないため、LobbyはDiscord送信を停止してAPI更新を待つ。

## サーバー最高権限

物理名: `NetworkAuthorityUpdateRequest`

旧移行互換の`uuids`一覧。ManagementDB初期化後はPUTで変更できない。現行の正本は`ManagedNetworkSettings.authorityUsers`とする。

## 管理ネットワーク設定

物理名: `ManagedNetworkSettings` / `ManagedNetworkChannel` / `NetworkManagedPlayer`

| フィールド | 型 | 契約 |
|---|---|---|
| `revision` | int | 0は未作成、保存ごとに増加。更新の期待版 |
| `lobbyServerId` | string | 非ゲームチャンネルの接続先ID |
| `transferCooldownSeconds` | int | 0以上、既定30 |
| `tabRefreshSeconds` | int | 1以上、既定2 |
| `presenceHeartbeatSeconds` | int | 1以上、既定10。所在TTLは30秒 |
| `authorityUsers` | GUID[] | 全体最高権限。nil不可、重複除去 |
| `channels` | channel[] | 1～128件、IDは大小文字を区別せず一意 |
| `players` | player[] | 応答専用のuserUuid/mcid。DBへ保存しない |

チャンネルは`serverId`（英数字始まり、以後英数字・`_`・`.`・`-`、最大64文字）、`displayName`（1～100文字）、`isGame`、非負intの`maxPlayers`・`donorExtraPlayers`・`adminExtraPlayers`、`discordEnabled`、`whitelistEnabled`、`debugUsers`・`whitelistUsers` UUID一覧を持つ。UUID一覧は各最大5000件。API接続情報は含めない。旧YAMLの`discord.excludedSourceServers`は対応チャンネルの`discordEnabled=false`へ変換する。

## チャンネルアクセス

`NetworkChannelAccessResponse`は`userUuid`、`serverId`、`channelKnown`、`isAuthority`、`debugUser`、`whitelisted`、`whitelistEnabled`、`allowed`、`permission`を返す。既知チャンネルで、whitelist無効または全体権限/debug/whitelist登録ならallowed=true。debug/whitelistはpermissionを変更しない。

## BAN

`NetworkBanStateResponse`は`userUuid`、`mcid`、`revision`、`isBanned`、`isActive`、`isIndefinite`、`expiresAtUtc`、`reason`、`serverTimeUtc`を返す。管理行未作成の旧BANはrevision=0。`isBanned`は保存状態、`isActive`は期限を考慮した現在の有効性を表す。

`NetworkBanUpdateRequest`は`expectedRevision`、`isBanned`、nullableな`expiresAtUtc`・`reason`を持つ。管理行が存在する限り、解除後または失効後に旧ゲームBANへ戻らない。
