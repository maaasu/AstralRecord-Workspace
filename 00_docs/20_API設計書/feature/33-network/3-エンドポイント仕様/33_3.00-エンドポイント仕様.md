# 33_3.00-エンドポイント仕様

## Admission取得

HTTPメソッド: `GET`
パス: `/api/network/admissions/{uuid}`
コントローラ: `NetworkController`
アクション物理名: `GetAdmission`

登録済みユーザーは無期限BAN、またはAPIローカル時刻より未来のbanDateをBAN中として`admitted=false`にする。未登録UUIDはRPG側の初回登録を許可するためpermission=0、`admitted=true`を返す。Proxy最高権限UUIDは登録有無や保存済みpermissionにかかわらずpermission=99を返すが、BANによる拒否は迂回しない。

## プレイヤー所在更新・削除・一覧取得

HTTPメソッド: `PUT` / `DELETE` / `GET`
パス: `/api/network/players/{uuid}` / `/api/network/players`
コントローラ: `NetworkController`
アクション物理名: `HeartbeatPlayer` / `RemovePlayer` / `GetPlayers`

PUTはpath UUIDとbody UUIDの一致および必須文字列を検証する。一覧は30秒を超えた所在を除外する。DELETEは対象不在でも204を返す。

## サーバー状態更新・一覧取得

HTTPメソッド: `PUT` / `GET`
パス: `/api/network/servers/{serverId}` / `/api/network/servers`
コントローラ: `NetworkController`
アクション物理名: `HeartbeatServer` / `GetServers`

PUTはpathとbodyのserverId一致、非負の人数・基本定員・寄付者追加枠・管理者追加枠を検証する。一覧は30秒を超えた状態を除外し、Lobbyは一覧をサーバー選択GUIの現在人数と閲覧者別最大人数へ反映する。

## チャット登録・差分取得

HTTPメソッド: `POST` / `GET`
パス: `/api/network/chat`
コントローラ: `NetworkController`
アクション物理名: `PublishChat` / `GetChat`

POSTはmessageId、source、送信元、authorName、message、kindを検証し、kindは`chat`または`lifecycle`だけを許可する。同じmessageIdの再送には既存sequenceを返す。GETはgenerationIdと、`afterSequence`より新しい最大200件をsourceで絞り込んだmessagesを返す。API再起動後などcursorが現在sequenceより大きい場合は0として扱い、クライアントもgenerationId変更時にcursorを0へ戻して取り直す。

## サーバー最高権限一覧

HTTPメソッド: `PUT` / `GET`
パス: `/api/network/authorities`
コントローラ: `NetworkController`
アクション物理名: `ReplaceAuthorities` / `GetAuthorities`

PUTは共通`X-Api-Key`に加えてProxy専用`X-Authority-Sync-Key`を要求し、Proxy設定由来のUUID一覧で現在値を全置換する。専用キーはAPI `Network:AuthoritySyncKey`とProxy `api.authoritySyncKey`を一致させ、通常backendへ配布しない。APIは専用キーが共通`ApiKey:Key`と同値の場合も401で拒否する。空GUIDを拒否する。GETは共通`X-Api-Key`だけで現在値をUUID順に返す。状態はAPIプロセス内だけに保持し、最終PUTから30秒で失効する。Proxyが所在heartbeat周期で再送する。

全エンドポイントは共通の`X-Api-Key`認証を要求し、最高権限一覧PUTだけはProxy専用キーも要求する。
