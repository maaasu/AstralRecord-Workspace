# 33_3.00-エンドポイント仕様

## Admission取得

HTTPメソッド: `GET`
パス: `/api/network/admissions/{uuid}`
コントローラ: `NetworkController`
アクション物理名: `GetAdmission`

任意の`serverId`クエリで接続先を指定する（省略時は管理設定のロビー）。ManagementDBのBANが存在すれば解除済み・失効済みも含めて正本とし、行がない場合だけ旧ゲームDBのBANをAPIローカル時刻からUTCへ変換して読む。無期限または期限が現在UTCより後なら`banned`で拒否し、全体権限でも迂回しない。管理設定初期化後は未知チャンネルを`unknown_channel`、有効なホワイトリストを通過できない場合を`not_whitelisted`で拒否する。未登録ユーザーはpermission=0とし、BAN/チャンネル条件を満たせばRPGの初回登録へ進める。

## プレイヤー所在更新・削除・一覧取得

HTTPメソッド: `PUT` / `DELETE` / `GET`
パス: `/api/network/players/{uuid}` / `/api/network/players`
コントローラ: `NetworkController`
アクション物理名: `HeartbeatPlayer` / `RemovePlayer` / `GetPlayers`

PUTはpath UUIDとbody UUIDの一致および必須文字列を検証する。一覧は30秒を超えた所在を除外する。DELETEは対象不在でも204を返す。

## サーバー状態更新・一覧取得

HTTPメソッド: `PUT` / `GET`
パス: `/api/network/servers/{serverId}` / `/api/network/servers`
コントローラ: `NetworkController`
アクション物理名: `HeartbeatServer` / `GetServers`

PUTはpathとbodyのserverId一致、非負の人数・基本定員・寄付者追加枠・管理者追加枠を検証する。一覧は30秒を超えた状態を除外し、Lobbyは一覧をサーバー選択GUIの現在人数と閲覧者別最大人数へ反映する。

## チャット登録・差分取得

HTTPメソッド: `POST` / `GET`
パス: `/api/network/chat`
コントローラ: `NetworkController`
アクション物理名: `PublishChat` / `GetChat`

POSTはmessageId、source、送信元、authorName、message、kindを検証し、kindは`chat`または`lifecycle`だけを許可する。Minecraftプレイヤーの通常チャットはauthorPlayerIdとauthorMinecraftNameを同時指定でき、LobbyがDiscordのスキンアイコンを解決する。旧クライアントとの互換性のため両項目の省略を許可する。同じmessageIdの再送には既存sequenceを返す。GETはgenerationId、全source共通のlatestSequenceと、`afterSequence`より新しい最大200件をsourceで絞り込んだmessagesを返す。Lobbyなど中継開始時のクライアントはlatestSequenceをカーソルとして既存履歴を再送しない。latestSequenceを持たない旧API応答ではLobbyは中継を開始しないため、APIを先に更新する。API再起動後などcursorが現在sequenceより大きい場合は0として扱い、既存クライアントはgenerationId変更時にcursorを0へ戻して取り直す。

## サーバー最高権限一覧

HTTPメソッド: `PUT` / `GET`
パス: `/api/network/authorities`
コントローラ: `NetworkController`
アクション物理名: `ReplaceAuthorities` / `GetAuthorities`

GETはManagementDBの最高権限UUIDを返す。設定初期化前だけ旧メモリ同期（30秒TTL）を読み、PUTも移行前互換として受け付ける。初期化後のPUTは409で拒否し、Proxyから定期送信しない。PUTは共通`X-Api-Key`に加えて`X-Authority-Sync-Key`を要求する。専用キーが未設定、不一致、共通キーと同値なら401、空GUIDは400とする。

## 永続設定と初期移行

- `GET /api/network/settings`: runtime設定を返す。未初期化は404。
- `POST /api/network/settings/bootstrap`: 共通キーとProxy専用`X-Authority-Sync-Key`を必須とする。初回は201、すでに保存済みなら入力で上書きせず現行設定を200で返す。
- `GET /api/network/channel-access/{uuid}?serverId=...`: チャンネルの存在、全体権限、debug/whitelist、入場可否と実効permissionを返す。未初期化・未知チャンネルはallowed=false。ID比較は大小文字を区別しない。全体権限だけがpermissionを99以上へ引き上げ、debug/whitelistはpermissionを変更しない。

## Web管理設定

`NetworkManagementController`の全操作は`actor_user_uuid`がnil以外で、ManagementDBの`web_admin=true`であることを毎回検証する。Webはcookieからactorを取得し、ブラウザーの任意UUIDを実行者として渡さない。

- `GET /api/network-management/settings?actor_user_uuid=...`: 設定とUUID→MCID表示情報。未初期化は404。
- `PUT /api/network-management/settings?actor_user_uuid=...`: bodyのrevision一致時だけ全体設定を保存。revision=0は初期作成。競合409、不正入力400。追加UUIDは削除されていないゲームDBユーザーに限定し、取り込み済みの旧UUIDは保持できる。Players表示情報は保存しない。
- `GET /api/network-management/players?actor_user_uuid=...&query=...`: ゲームDBのMCID前方一致で最大20件の候補を返す。

## 共通BAN

- `GET /api/network/bans/{uuid}`: shared BAN状態。未知UUIDは404。
- `PUT /api/network/bans/{uuid}?actor_user_uuid=...`: RPG `/ban`用。共通キーに加えRPG `api.networkModerationKey`とAPI `Network:ModerationKey`が一致する`X-Network-Moderation-Key`を必須とし、未設定・不一致・共通キー同値は401。actorは必須で、nilはこの専用認証を通過したサーバーConsole、その他はゲームpermission>=99または全体権限UUIDだけを許可する（不許可403）。
- `GET /api/network/bans/active`: 現在有効なManagementDB BAN一覧。Proxyが接続済みプレイヤーへ反映する。
- `GET / PUT /api/network-management/bans/{uuid}?actor_user_uuid=...`: WebAdmin専用の参照・設定・解除。RPGと同じBAN行を操作する。

更新は`expectedRevision`、`isBanned`、nullableな`expiresAtUtc`、500文字以内の`reason`を受け取る。true+期限なしは無期限、true+未来のUTC期限は期限付き、falseは解除。期限と現在時刻が等しい場合は失効済み。競合409、不正期限400。ユーザーUUID単位で全アカウントへ適用する。設定とBANの更新・監査は同一トランザクションで保存する。

全エンドポイントは共通の`X-Api-Key`認証を要求する。専用キーはWeb画面・ManagementDBへ保存しない。
