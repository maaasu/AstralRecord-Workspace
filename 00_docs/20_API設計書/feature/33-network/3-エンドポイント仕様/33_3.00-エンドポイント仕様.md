# 33_3.00-エンドポイント仕様

## Admission取得

HTTPメソッド: `GET`
パス: `/api/network/admissions/{uuid}`
コントローラ: `NetworkController`
アクション物理名: `GetAdmission`

登録済みユーザーは無期限BAN、またはAPIローカル時刻より未来のbanDateをBAN中として`admitted=false`にする。未登録UUIDはRPG側の初回登録を許可するためpermission=0、`admitted=true`を返す。

## プレイヤー所在更新・削除・一覧取得

HTTPメソッド: `PUT` / `DELETE` / `GET`
パス: `/api/network/players/{uuid}` / `/api/network/players`
コントローラ: `NetworkController`
アクション物理名: `HeartbeatPlayer` / `RemovePlayer` / `GetPlayers`

PUTはpath UUIDとbody UUIDの一致および必須文字列を検証する。一覧は30秒を超えた所在を除外する。DELETEは対象不在でも204を返す。

## サーバー状態更新・一覧取得

HTTPメソッド: `PUT` / `GET`
パス: `/api/network/servers/{serverId}` / `/api/network/servers`
コントローラ: `NetworkController`
アクション物理名: `HeartbeatServer` / `GetServers`

PUTはpathとbodyのserverId一致、非負の人数・基本定員・寄付者追加枠・管理者追加枠を検証する。一覧は30秒を超えた状態を除外し、Lobbyは一覧をサーバー選択GUIの現在人数と閲覧者別最大人数へ反映する。

## チャット登録・差分取得

HTTPメソッド: `POST` / `GET`
パス: `/api/network/chat`
コントローラ: `NetworkController`
アクション物理名: `PublishChat` / `GetChat`

POSTはmessageId、source、送信元、authorName、messageを検証し、同じmessageIdの再送には既存sequenceを返す。GETはgenerationIdと、`afterSequence`より新しい最大200件をsourceで絞り込んだmessagesを返す。API再起動後などcursorが現在sequenceより大きい場合は0として扱い、クライアントもgenerationId変更時にcursorを0へ戻して取り直す。

全エンドポイントは共通の`X-Api-Key`認証を要求する。
