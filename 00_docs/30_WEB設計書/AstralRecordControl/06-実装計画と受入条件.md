# 06 実装計画と受入条件

## 実装開始の共通条件

この設計書を入力に、通常の統合入口で段階ごとに独立した実装作業を行う。設計書があるだけで未実装のAPI/サービスを利用可能と扱わない。変更する段階の03 DTO/02経路/05画面を揃える。

各段階は「成果物が存在する」「受入条件を再現できる」「新規の説明不能な警告がない」「独立レビュー済み」を完了条件とする。Contract/状態/予約/データ保全/認証境界を重点検証し、表示コピーを写すだけのテストは作らない。実サーバーを使わないfixtureと、一時sandboxサーバーの確認を分ける。

## P0: 台帳・認証・通信基盤

### 実装単位

| ticket | 所有範囲 | 入出力/成果物 |
|---|---|---|
| C0-01 | Contracts、Solution、各サービスbootstrap | 02/03のv1 enum/DTO、厳密JSON検証、予定プロジェクト/DI境界 |
| C0-02 | Web Identity、Cli owner | 単一owner、TOTP/回復、session失効、CSRF/回数制限、専用control.db migration |
| C0-03 | Host/Server台帳、Agent接続 | token登録/失効、Hello/Reconcile、inventory適用/ACK、snapshot画面 |
| C0-04 | publish/install、ProgramData | サービス/非管理者アカウント/ACL、DB/鍵を除くbinary配布、初回設定チェック |

RunnerはGetSnapshot/ApplyInventory/hold永続化までを足場として実装するが、P0ではゲームプロセスを変更しない。台帳のServer定義はread-only/pilot登録状態にする。

### P0の実装範囲

2026-10-18実装。C0-01〜03の入口は`30_web/AstralRecordControl`、C0-04は`60_tool/control-deploy`。Web/Agent/Runnerは各schema1を持ち、初期DB作成と未知schema拒否を実装する。未登録既存DBを破棄/自動採用しない。導入ツールは自己完結publish、非管理者の専用仮想サービスアカウント登録、ACL、初回設定検査、Web/Agentの個別更新と停止中DB一式snapshotを提供する。Runner更新の自動化はP1のプロセス停止/hold確認実装後に追加し、P0ではオンライン更新を受け付けない。

再現コマンドはControl READMEとcontrol-deploy READMEを正本とする。Windowsサービス登録、証明書配置、実Minecraft/既存Craftyの停止移行は実施済みとして扱わない。

### 受入条件

- ゲーム/API/SQLを停止したfixtureでもログインし、登録済みHostの状態を取得できる。
- owner2件目作成、未登録TOTP、CookieでAgentを名乗る要求、Agent tokenで管理画面へ入る要求を拒否する。
- 旧Agent tokenと既存接続が無効化される。owner reset後の旧Cookieは次要求で拒否される。
- PCごとに異なるHostが登録され、dev-pcへdev、mc-pcへchannel1/channel2を割当可能。
- 古いconnectionEpoch/別Hostのtransfer/未知schemaを拒否する。初回失敗と長時間切断から再接続できる。
- config反映失敗では旧適用版を保持し、希望版と混同しない。Agent DB巻戻りを要復旧として止める。

## P1: Runner・基本運転・共通gate

### 実装単位

| ticket | 所有範囲 | 入出力/成果物 |
|---|---|---|
| C1-01 | Runner supervisor/ledger/log | Java直接起動、stdin/out/err、Session/stateRevision、残存プロセス照合 |
| C1-02 | Agent Inbox/Outbox、Web dispatch/UI | durable受付/完了、operationId/hash、開始期限、console、ライブ/ファイルログ |
| C1-03 | Web reservation、Agent/Runner gate、Cli | 全資源準備、fence、永続hold、ローカル緊急復旧、監査 |
| C1-04 | 既存01/02/03/16/17の入口 | 共通gate参加/継承、子処理のrun参照、停止状態確認、未対応時拒否 |

P1の変更操作有効化はC1-04完了後。共通gateを後からP4で追加する順序にはしない。未改修の旧入口が使える環境へ、変更可能なControl管理を展開しない。

### 受入条件

- 実サーバーと無関係なテストプロセスでStart/Stop/Restart/Kill、1PC複数プロセス、Session/設定版の誤対象拒否を確認する。
- Web/Agentを停止してもRunnerがログを読み続け、プロセスが継続する。再接続で操作状態とログcursorが回復する。
- Runner異常終了後の残存プロセスをUnmanagedとし、PID再利用で他プロセスをkillしない。二重起動を拒否する。
- stdin書込境界で障害を注入し、結果不明のConsoleCommandを自動再送しない。
- 同ID同hash再送は重複実行せず、同ID異なる入力を拒否する。期限切れ命令を復帰時に開始しない。
- Web操作、予約、01/02/03/16/17直接実行が同一資源で競合し、片方が副作用前に拒否される。02の公開もEnvironment予約に含める。hold取得途中の切断で開始しない。
- stop timeoutで自動Killせず、手動停止/保守hold中にcrash restartが走らない。

## P2: ファイル・バックアップ・復元

### 実装単位

| ticket | 所有範囲 | 入出力/成果物 |
|---|---|---|
| C2-01 | Agent filesystem/transfer、Web relay | root境界、etag、64KiB編集、大容量chunk/再開、ZIP検証、trash |
| C2-02 | backup profile/manifest/journal | 停止取得、SHA-256、保持/保護、NAS転送、一覧/download |
| C2-03 | restore/stage交換/復旧UI | Replace/Merge、退避、journal再開、起動抑止 |
| C2-04 | import/既存フォルダ登録 | 空root作成、EULA、ServerConfig適用、停止状態検証 |

### 受入条件

- `..`/絶対パス/ADS/link/junction/ZIP領域外/ZIP bombを拒否し、管理root外のfixtureを変更しない。
- etag競合、編集途中のファイル変更、文字コード/改行維持、大容量転送の中断/同chunk再送を確認する。
- Webを経由する20GiB相当の疎/生成stream fixtureで、全量メモリ化せず上限/空容量拒否できる。
- 不正hash・途中backup・容量不足をCompletedにしない。保持数/日数の境界と保護世代を確認する。
- Restore中の各journal境界で中断し、起動禁止とデータ退避を維持して再照合できる。
- ServerFilesしか含まないことを画面/manifestで確認し、DB/公開状態まで復元済みと表示しない。

## P3: 予約実行・監視・通知

### 実装単位

| ticket | 所有範囲 | 入出力/成果物 |
|---|---|---|
| C3-01 | Agent scheduler、適用snapshot | Once/Interval/Cron、UUIDv5 occurrence、Skip、ローカルgate、Run Now |
| C3-02 | metrics採取/集約/画面 | Host/プロセス、人数、欠測、保持期間、グラフ |
| C3-03 | event/notification outbox | 登録Webhook、eventId、限定retry、秘密mask、要復旧通知 |

### 受入条件

- Web停止中も適用済みローカル予約が動き、二重発火しない。Agent停止中の取り逃しを再開時にまとめて実行しない。
- 夏時間重複/欠落、UTC/JST、interval anchor、revision変更、保守中の競合を固定時計で検証する。
- Web未接続中のPC横断/Environment操作を開始しない。中央保守とのRunner gate競合を確認する。
- Agent未接続/ゲームAPI失敗を0人や停止へ変換せず、欠測として表示する。
- 通知送信失敗でゲーム操作を失敗へ変えない。未ACK event/未完了保守を保持期限で削除しない。

## P4: 更新・複製・PC横断保守・既存処理統合

### 実装単位

| ticket | 所有範囲 | 入出力/成果物 |
|---|---|---|
| C4-01 | provider/Artifact/update | 公式配布先の種類/版/size/hash契約、本体/Plugin更新、検証起動/退避 |
| C4-02 | clone/move/dependency Workflow | 新ID/ポート再指定、PC間転送、所有Host切替、依存起動/逆順停止 |
| C4-03 | 01/03/16/17 Adapter/Web進捗 | 既存run/journal/要求IDの再利用、起動待ち操作、世代/公開確認 |
| C4-04 | Java/Bedrock/Velocity能力表 | コマンド/起動/監視差、unsupported表示、実構成import |

### 受入条件

- 開発PCでDev更新し、MC用PCへの配布を同じ予約/Workflowで追跡する。両方Onlineになる前に副作用を開始しない。
- PC移送で同一Serverを2PC同時起動せず、複製は新ID/固有設定/autoStart=falseになる。
- Provider外URL/異種binary/更新前版不一致を拒否し、途中失敗を正常稼働へ戻さない。
- 03は同bootでrevision増加を確認できる。01/16は新Session/世代/readyを確認し、Lobby/Proxyを別Adapterで判定する。
- 公開応答喪失後も同じrun/要求IDで照合し、新パッチを重複発行しない。17はPreview/Commitを明示し通常更新へ混ぜない。
- 17中は対象プロセスを稼働維持し、Stop/Reload/seed/公開/更新を拒否する。Commit開始後のファイルだけRestoreを拒否する。

## P5: 機能完成・日常UI

- 対応AdapterのPlayers/最終接続、Kick/Ban/Pardon/Op/Deop/Whitelist、Astral正規APIへの連携。
- 過去/ローテートログ検索、操作テンプレート、画面並べ替え/表示列、スマホ/PWA。
- 管理APIの最終契約、認証付きPrometheus/OpenMetrics endpoint、通知設定/履歴。
- 不要なサーバー/退避データ/backupの確認付き削除、Control自身のbackup/移設復旧。

05の完成形全行に実装段階・対応capability・検証結果を対応付け、非対応機能は理由と対象種別を表示する。API停止でも基本運転を使えること、PWAに秘密/管理データをcacheしないこと、owner/token/DB移設復旧を最終受入に含める。他ゲームやRBACを追加して完成条件を広げない。

## 実装担当への最小引継ぎ

1. READMEと担当段階の02/03/04を読む。
2. 変更するDTO/enum/DB migration/状態遷移/画面/capabilityを列挙する。
3. 単一編集者のtask worktreeで作業し、並列化するなら独立branch/worktreeでContracts変更を先に統合する。
4. 当該段階の受入条件をfixtureで確認し、必要なら使い捨てMC sandboxで実console/停止を確認する。
5. 採用設計と実装済み範囲を同じ差分で同期し、未対応kindを有効化しない。

## 現行環境からの導入

新規Serverで一連のbackup/restore/障害復帰を検証してから既存データを停止snapshotで移す。既存Crafty側の該当サーバー自動起動/予約/直接起動経路を停止し、Control以外から二重起動しないことを確認する。Control実行時にCraftyを必要とすることはない。

最初はDevをpilotとしてP1/P2を検証し、その後チャンネルを登録する。共有API/masterを使う場合はDevでもEnvironmentを共通登録し、本番と無関係な検証と誤認しない。PC/DNS/証明書/Java実パス/既存runtimeServerId/保存先は導入時の必須検証項目とする。

本設計の追加コミットだけで実サーバーのCrafty停止・データ移動・サービス登録は行わない。
