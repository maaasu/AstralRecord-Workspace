# 06 実装計画と受入条件

## 実装開始の共通条件

この設計書を入力に、通常の統合入口で段階ごとに独立した実装作業を行う。設計書があるだけで未実装のAPI/サービスを利用可能と扱わない。変更する段階の03 DTO/02経路/05画面を揃える。

各段階は「成果物が存在する」「受入条件を再現できる」「新規の説明不能な警告がない」「独立レビュー済み」を完了条件とする。Contract/状態/予約/データ保全/認証境界を重点検証し、表示コピーを写すだけのテストは作らない。実サーバーを使わないfixtureと、一時sandboxサーバーの確認を分ける。

画面切替はWebScript.Testsで、タブGETの完了まで旧本文を保持すること、送信失敗でPOSTを自動再送しないこと、戻る・進むがGETとなること、処理中の戻るが以前の履歴を壊さないこと、認証切れでLoginへ移ることを確認する。配備をまたぐ一度限りのPOST結果を先に表示すること、旧ページのログ/metrics取得を止めて遅延応答を無視すること、P2処理中の画面移動を抑止することも検証する。実ブラウザでのちらつき・focus・狭幅表示は、この自動検証とは別に確認する。

### 受入条件

- ゲーム/API/SQLを停止したfixtureでもログインし、登録済みHostの状態を取得できる。
- owner2件目作成、誤パスワード、CookieでAgentを名乗る要求、Agent tokenで管理画面へ入る要求を拒否する。

- 旧Agent tokenと既存接続が無効化される。owner reset後の旧Cookieは次要求で拒否される。
- PCごとに異なるHostが登録され、dev-pcへdev、mc-pcへchannel1/channel2を割当可能。
- 古いconnectionEpoch/別Hostのtransfer/未知schemaを拒否する。初回失敗と長時間切断から再接続できる。
- config反映失敗では旧適用版を保持し、希望版と混同しない。Agent DB巻戻りを要復旧として止める。

### P3の実装範囲

2026-10-18実装。Web/Agent/Runnerはschema4へSQLite backup付きtransaction migrationを行う。WebはSchedule定義・適用状態・履歴/Run Now要求、metrics集約・画面、通知先/配信履歴を持つ。Agentは適用ACK済みinventoryを実行正本としてローカルscheduler/occurrenceとRuntimeChanged/ScheduleOccurrenceChangedのdurable eventを持ち、Runnerの既存hold/fenceで中央保守と競合を調停する。RunnerはSessionの終了時刻・コード・停止意図を記録する。

予約実行はWebの`Control:EnableSchedules`とAgentの`enableSchedules`を既定falseとし、P1管理運用markerとgateを維持して明示有効化する。Once、60秒以上のInterval、5フィールドCron、同一Host/Serverで最大16step・段間待機0～86400秒の連鎖を実装する。夏時間の重複/欠落、60秒超過のSkip、UUID v5の固定occurrence/子ID、Run Nowの永続要求IDと202照会先で重複発火を防ぐ。PC横断/Environment Workflow、更新Adapter、種類別運転はP4に残す。

metricsは約10秒のHost/プロセスsampleとJava localhost status pingによる人数を扱う。Webは1分粒度7日、1時間粒度90日を保持し、欠測を0へ変換しない。TPS/MSPTは取得元がなくP3では提供しない。通知はOwner CookieによるWebhook設定/API、保護されたURL全体、HTTPS/443・公開IP・DNS固定・転送制限、同一eventIdで1/5/30分の最大3回再試行とdead-letterを実装する。ゲーム操作と通知送信の成否は独立する。

終端操作・Schedule報告の本文は90日で退役させ、ID/hash等の重複照合情報を残す。未ACK Agent event、非終端操作、要復旧の保守は保持する。受入検証は一時SQLite/ローカルfixtureと送信先fake handlerで行い、実サービス登録・既存Minecraft・実NAS・外部Webhook送信は含めない。

### 受入条件

- Web停止中も適用済みローカル予約が動き、二重発火しない。Agent停止中の取り逃しを再開時にまとめて実行しない。
- 夏時間重複/欠落、UTC/JST、interval anchor、revision変更、保守中の競合を固定時計で検証する。
- Web未接続中のPC横断/Environment操作を開始しない。中央保守とのRunner gate競合を確認する。
- Agent未接続/ゲームAPI失敗を0人や停止へ変換せず、欠測として表示する。
- 通知送信失敗でゲーム操作を失敗へ変えない。未ACK event/未完了保守を保持期限で削除しない。
