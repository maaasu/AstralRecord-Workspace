# 09_player-admin-edit 概要

## 画面と認証

Web管理者がプレイヤー詳細から対象アカウントを明示して管理編集を開始する。画面は`30_web/AstralRecordWeb/AstralRecordWeb/Pages/Admin/PlayerEdit.cshtml`と対応するPageModelで構成し、既存の`WebAdminOnly`、最近のコード認証または信頼済みブラウザ、Cookie session versionの検証を再利用する。

Webサーバーは操作者UUIDを認証済みclaimsから取得し、専用管理APIキーとともにAPIへ渡す。ブラウザから渡された操作者を認可の正本にしない。変更操作はRazor PagesのPOSTとantiforgery検証を通す。

## 画面遷移

1. MCID・ユーザーUUID・アカウントUUID・現在クラス・レベルを確認し、訂正理由を入力する。
2. 編集開始で対象ユーザーの参加制限を先に永続化する。オンラインなら保存して退出させる旨を明示する。
3. 保存退避中はサーバー確認数と状態を表示する。編集フォームは全サーバーとaccount sessionの終了確認後に表示する。
4. レベル、現在クラス、inventoryの変更案を入力する。item IDと個体UUIDを区別し、既存entryを参照して数量変更・削除、マスタitem IDを指定して付与する。
5. 反映または取消の結果を確認する。完了時は参加制限が解除されるが、自動でゲームへ接続しない。

## 復旧

ブラウザ閉鎖・通信切断・認証失効だけでは参加制限を解除しない。同じ管理者が再認証して画面を開くと、所有する既存編集セッションを再開する。

結果が不明なPOSTでは操作IDと対象編集セッションを維持し、確定結果を照会する。同じ訂正を新しいIDで再実行しない。結果不明の反映を確認する前に、新しい反映や取消を行わせない。APIが明示した入力検証エラーでは内容を訂正できる。

## MVPと表示制限

| 操作 | 範囲 |
|---|---|
| レベル訂正 | 1～100。EXPはAPIが計算し、転生中は拒否 |
| クラス訂正 | 現在クラスを変更。各クラスの進行度と習得スキルは保持 |
| アイテム付与 | マスタ定義から通常アイテム・装備を生成 |
| 数量変更・削除 | 安全な通常entryのみ。装備や参照中entryはAPIの検証に従う |

通貨・装備抽選値・ルーン・loadout・習得スキルの直接編集は提供しない。表示値を派生ステータスの保存値として書き戻さない。
