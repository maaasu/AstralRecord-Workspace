# 05_0.00-概要

## サーバー設定

`/Admin/Network`はManagementDB `web_admin=true`のユーザーだけに共通メニューで表示し、画面の表示・操作には直近のコード本人確認も要求する。管理者専用領域へ配置し、各リクエストで権限をAPIへ再照会する。

ネットワーク全体のロビーID、移動クールダウン、Tab/在席通知周期、最高権限UUIDを編集し、チャンネルごとの接続先ID・表示名・ゲーム区分・基本/支援者/管理者定員・Discord通知・whitelist有効状態・debug/whitelistユーザーを設定する。API接続先や秘密値は画面へ出さない。

ユーザー追加はゲームDBのMCID前方一致候補を選ぶ。UUIDを保存し、表示にMCIDを使用する。接続先IDはVelocityとLobby/RPGの設定に一致させる必要があり、この画面からVelocity本体の定義は書き換えない。保存は期待revisionを送り、409では他の管理者の変更を上書きしない。初期状態はProxyから取り込むかWebからrevision=0で作成できる。

追加先は「チャンネル」と「デバッグ利用者／ホワイトリスト」を別々に選択する。ネットワーク全体を選ぶと全体の管理権限となる。MCID入力後250msで認可付きGETハンドラーから候補JSONを取得し、設定フォームを再送信しない。入力変更時に旧検索を中止し、遅れて返った旧結果は破棄する。空入力では検索せず、検索失敗・権限失効・候補なしを明示する。追加済み候補は重複追加を禁止し、追加先と未保存状態を表示する。UUIDリストは設定保存時にだけAPIへ送る。

## 管理者によるBAN

プレイヤー詳細の管理者操作で対象MCID・ユーザーUUID・現在の状態・理由・期限を表示する。ゲームアカウントの選択とは独立したユーザー単位の操作とし、フォームから別の対象UUIDを受け入れない。

無期限、期限付き（入力は日本時間、APIへUTCで送信）、解除を用意する。対象・期限・理由を確認ダイアログへ表示し、確認後にCSRFトークン付きPOSTで保存する。過去の期限は拒否し、revision競合では再読込を案内する。本人の公開設定や一般閲覧者へこの管理操作を提供しない。

期限はカレンダー付き日付入力と時刻入力に分け、「1日後・7日後・30日後」で日本時間の解除日時を設定できる。期限付きでは未来の日時を入力した場合だけ確認ダイアログを開き、無期限・解除では期限入力を無効にする。サーバーでも日付と時刻を厳密に検証し、入力エラー時は管理フォームと入力値を保持する。Enterによるフォーム送信も確認ダイアログを経由する。
