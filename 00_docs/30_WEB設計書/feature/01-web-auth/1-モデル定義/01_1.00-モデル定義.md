# 01_1.00-モデル定義

Webログインで使用するAPI入出力、内部結果、Cookie Claimを定義します。

## 1. API 入出力

`WebLoginChallengeConsumeRequest`: `loginCode`, `expectedUserUuid`（再認証時のみ、保護Cookieの本人UUID）

`WebLoginChallengeConsumeResponse`: `userUuid`, `mcid`, `permission`, `webAdmin`, `currentAccountId`, `accountIds`, `sessionVersion`, `codeAuthenticationProof`, `codeAuthenticatedAt`。最後の2値はコード認証成功時のみ付与し、パスワードログインではnull。

## 2. Web 内部結果

`WebLoginChallengeConsumeStatus` は `Success`、`Invalid`、`ServiceUnavailable` を持ちます。`WebLoginChallengeConsumeResult` は状態と成功時レスポンスをまとめます。

## 3. Cookie Claim

- `sessionVersion`: ManagementDBに保存された失効世代UUID。認証済み要求ごとにGET credentialsで照合する。
- `codeAuthenticatedAt`: コード認証成功日時（UTC、O形式）。コード認証成功時にAPIが返す日時をWebが保存し、パスワードログインには付与しない。
- `ClaimTypes.NameIdentifier`: user UUID
- `ClaimTypes.Name`: MCID
- `permission`: 権限値
- `currentAccountId`: 現在のアカウント ID（存在時）
- `accountId`: 所有アカウント ID（複数）

`webAdmin` はログイン応答に含まれるが、Web管理認可には利用しない。管理画面は要求ごとに `GET /api/web-auth/users/{userUuid}/authorization` を呼び、応答の `webAdmin` と5分以内の `codeAuthenticatedAt` を使用する。

`WebCredentialState`: `loginId`（未発行はnull）, `enabled`, `sessionVersion`, `codeAuthenticationProof`, `codeAuthenticatedAt`。最後の2値は有効なコード証明による設定更新応答のみ付与し、GET照会や現在パスワードだけでの更新ではnull。更新応答は新世代の証明と元の認証日時を返す。

`WebCredentialUpdateRequest`: `action`（enable/change/disable）, `currentPassword`, `newPassword`, `sessionVersion`, `codeAuthenticationProof`。UUID・世代・API発行の本人確認証明はフォームから受け取らず保護Cookieから設定する。APIが証明のUUID・世代・5分以内の期限を検証する。認証情報は公開プロフィールDTOに含めない。

- `codeAuthenticationProof`: API発行の本人確認証明。Cookieにのみ保持し、入力欄・URLへ出力しない。設定変更応答で証明の世代を更新し、元の日時は延長しない。現在パスワードだけで変更した場合はコード認証claimを削除する。
