# 01_4.00-統合フロー

```mermaid
sequenceDiagram
    actor User as ユーザー
    participant Web
    participant API
    participant ManagementDB
    User->>Web: /Login を表示
    Web-->>User: コード入力フォーム
    User->>Web: 有効な CSRF トークン付き POST
    Web->>API: POST /api/web-auth/challenges/consume（信頼登録指定可）
    API->>ManagementDB: 成功時のみplayerをupsert
    API->>ManagementDB: 信頼登録指定時はトークンハッシュを保存
    API-->>Web: プレイヤー情報、webAdmin、sessionVersion、任意のtrustedBrowserToken
    Web-->>User: HTTPS認証Cookieと任意の信頼済みブラウザCookieを発行、/MyPageへリダイレクト
    Web->>API: GET /api/web-auth/users/{uuid}/authorization（共通メニュー描画時）
    API->>ManagementDB: web_adminを取得
    API-->>Web: webAdmin
    Web-->>User: webAdmin=trueの場合だけ管理者専用メニューを表示
    User->>Web: /Admin/Items
    Web->>API: GET /api/web-auth/users/{uuid}/credentials
    API-->>Web: 現在のsessionVersion
    Note over Web: Cookie世代照合とコード認証5分以内または信頼済みブラウザを確認
    Web->>API: GET /api/web-auth/users/{uuid}/authorization
    API->>ManagementDB: web_adminを再取得
    API-->>Web: webAdmin
    Web->>API: POST /api/web-auth/users/{uuid}/trusted-browsers/validate（信頼Cookieがある場合）
    API->>ManagementDB: トークン・sessionVersion・最終利用日時を確認し利用日時を更新
    API-->>Web: trusted
    Web-->>User: trueかつコード認証済みまたは信頼済みブラウザの場合だけ管理画面を表示
```

コード消費またはWeb管理権限照会のAPI障害時は、Cookie発行または管理画面表示を行いません。

ID・パスワード方式は `POST /api/web-auth/password/login` から同じCookie発行処理へ合流する。`GET credentials` がCookie世代と一致しない場合・API障害時はサインアウトする。設定更新はCookieの本人UUID・世代・直近コード日時と入力パスワードをWebサーバーからAPIへ渡し、APIの原子的更新で得た新世代だけを操作端末へ再発行する。再認証のコード消費には本人UUIDを指定し、他人のコードを受け付けない。
