# 01_3.06-スキルツリー編集

- パス: `/skilltree/{accountId}`。
- Razor Page: `Pages/SkillTree/Index.cshtml` / `Index.cshtml.cs`。
- 本人のマイページから開く。認証必須、全応答は`no-store`。
- Webは変更要求を登録し、参加先Pluginが確定する。全置換保存APIを呼ばない。

## 表示と操作対象

対象アカウントを所有する認証済みユーザーのUUIDだけをAPIに渡す。フォーム、URL、JSONから送信された所有者UUIDや費用・条件判定を採用しない。POSTはRazor PagesのAnti-forgeryを必須とし、APIでも所有関係を再検証する。

参加先が実際にロードして公開した世代の定義と、そのプレイヤー状態に対応した評価情報を表示する。最新配置のJSONを参加先定義の代用にしない。必要な世代、評価または新鮮な稼働情報が得られない場合は編集不可とし、再取得や更新待ちを案内する。世代ハッシュや互換性の内部コードは画面文言に使わない。

接続チャンネル名・ワールド・X/Y/Z・確認時刻は本人のマイページに表示し、この編集画面には配置しない。編集画面では残高が確定済みかオフライン保存済みかを示す。オンライン中の編集は拠点またはスキルツリーワールドだけで許可する。送信前にも最新状態を取得し、Pluginが確定直前に実際の現在地を再確認する。

## 変更要求

ノードを選ぶと解放または解除の内容を表示する。CP消費元を選べるノードでは候補クラス名と使用可能CPを提示する。「選択変更」は、この未確定の解放操作で消費元クラスを選び直す操作を指す。解放済みノードの消費元だけを付け替える新たなゲーム仕様は設けない。

ノード操作はまずローカル変更案へ追加し、連続して複数ノードを選ぶ。変更内容と合計費用の確認後、操作ID、期待定義世代、期待プレイヤー状態更新番号、`action=BATCH`、順序付き`changes[{action,nodeId,sourceClassId}]`を一度に送る。変更案は1〜512件、同一ノードの重複は認めない。送信直前の再取得で世代・状態・場所が変化していれば送らず再確認を求める。Webでの表示判定を、Pluginの検証結果の代用にしない。

編集中の変更は確定残高と分離する。PP、クラス別CP、Goldを独立した固定領域に表示し、それぞれ確定残高・変更後・増減・合計解除費用を並べる。CP超過時も正確に返還するため、Pluginのearned/spent値から未丸め残高を計算し、使用可能値だけ0で下限を設ける。解除費用と返還先は取得したルールと保存済み消費元から表示する。APIの`balanceKind`が`LIVE`なら確定済み、`SAVED`ならオフライン・保存済み残高と明記する。`UNKNOWN`または再取得失敗時は残高を未確認として数値を消し、以前の残高を現在値として残さない。

| 状態 | 画面上の扱い |
|:--|:--|
| 編集中 | ノードとCP消費元を選択・確認中。まだ要求を登録していない |
| 適用待ち | APIに登録済み、またはPluginが確認中。残高を確定済みへ変更しない |
| 適用済み | APIから確定結果を受信した後だけ表示し、残高とノードを再取得 |
| 再確認が必要 | 世代・状態・条件・期限などが変化。再取得して内容を選び直す |
| 失敗 | 適用失敗の確定結果を表示 |

オフライン時は次回参加時に検証する編集案として保存する。アカウントにつき有効な要求は1件とし、新たな要求を作る前に既存要求を取り消す。取消済み・期限切れの要求は後から適用しない。確定済みの操作を取消済みに表示しない。

送信結果が不明な場合は同じ操作IDで照会する。まだAPIに届いていない場合の再送も元の操作IDと条件を保持し、新しい操作IDによる重複要求を作らない。操作IDはタブのセッション領域にも保存し、ページ再読込後の結果確認に使用する。APIの確定結果を取得するまでは次の変更を送信しない。

## 画面領域と入力

通常表示から「最大表示」で表示領域を広げる。同じ変更案・選択・表示位置・検索条件を保持し、「通常表示」で戻る。Fullscreen APIは使用しない。ヘッダーと残高領域をコンパクトにし、中央のツリー領域を残りの高さまで広げる。

パン、ズーム、全体図、開始位置リセット、選択位置へ移動、検索、ミニマップを利用できる。ノード上からもドラッグでき、一定距離以上の移動をクリックとして扱わない。タッチでは1点でパン、2点でピンチ拡大縮小する。詳細パネルは閉じられ、ツリーを引き続き操作できる。

円形の外枠、中央アイコン、装飾は従来のデザインを維持する。名前、主要ステータス効果、スキル付与、コスト、CP対象クラス、状態は円形ノードの下のラベルに常時表示する。表示名・書式・値はPluginの評価情報を正本とし、内部IDで代用しない。長い文は折り返し、効果の行数に合わせてラベルと間隔を確保する。補足条件と保存済みの実消費元は詳細に表示する。

接続線はノードとラベルの背後へ描画し、細く低い不透明度の実線・破線を使う。選択中の接続も強い発光を避け、配置の細かな歪みを強調しすぎない。縮小時も線幅を保ち、画面内に簡潔な凡例を表示する。キーボードの矢印、`+/-`、Home、Tab/Enterでも閲覧できる。

API・Plugin・DBの保存、処理権限、世代互換性、導入手順はスキルツリーAPIとPluginの設計を参照する。

## 一括変更案の検証と検索

WebではPluginが公開した同世代のnode/edge・条件判定・固定CP元/候補・確定残高から、解放順序、root接続、解除後の経路、PP/CP/Goldを変更案の順に検証する。解放予定は破線の枠、解除予定は別の枠で表示し、適用済みと区別する。「ひとつ戻す」「案を取り消す」で未送信の案を戻せる。定期取得で世代・更新番号・残高・条件が変わったら再確認を必要とし、確認後にも送信直前の再取得を行う。

`supportsBatch=false`の参加先は閲覧を継続し、一括送信には対応Pluginの更新待ちを表示する。Web事前検証の通過は確定ではない。Pluginが同じゲーム内ルールで全件を再検証し、途中に1件でも不成立があれば全件を復元する。操作IDと結果照会・取消はbatch全体に対して行う。

検索対象はノード名、主要効果、付与スキル名。空白区切りの複数語はすべてを含むnodeを探し、全角/半角を正規化する。名前のみ・効果/スキルのみの切替、効果選択、該当全ノードの強調、件数表示、前/次の一致ノードへの移動、強調解除を備える。内部node IDを名称検索の代用にしない。検索と配置の方針は[Path of Exile 2公式ツリー](https://pathofexile2.com/game/passive-skill-tree/AAAABwsAAAA=)を参考とし、画像やデザイン素材は流用しない。

パン/ズームはrequestAnimationFrame単位でまとめ、画面外のnode/edgeを描画から外す。pointer frame内で効果テキストを再分割せず、表示高はcacheする。定期取得は同じ構造のSVGを再構築せず状態差分だけ更新し、パン中は再取得を待つ。マスターのX/Z配置比率と円形ノードは維持する。
