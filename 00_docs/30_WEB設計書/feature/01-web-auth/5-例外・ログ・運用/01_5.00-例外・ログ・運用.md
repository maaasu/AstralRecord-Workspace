# 01_5.00-例外・ログ・運用

| 状態 | 画面動作 |
|---|---|
| GET | コード入力フォームを表示する |
| 有効な CSRF トークン付きPOST・有効なコード | APIで消費し、認証Cookieを発行して `/MyPage` へ遷移する |
| 無効・期限切れ・使用済みコード | ログイン画面でエラーを表示する |
| コード消費API障害 | ログイン画面で接続失敗を表示し、Cookieを発行しない |
| Web管理権限API障害、`web_admin=false`、レコードなし | 管理画面を拒否する |

`WebAuthApiClient` はログインコードをログへ出力しません。コード消費またはWeb管理権限照会の通信例外はWarningログに記録します。認証CookieはHTTPS、HttpOnly、SameSite=Lax、12時間固定で発行します。

コードログインまたは再認証時に「このブラウザを信頼する」を選ぶと、Web管理者だけに信頼済みブラウザCookieを発行します。Cookie本体はWebサーバーだけが受け取り、API・ManagementDBにはハッシュのみを保存します。管理画面へのアクセス成功ごとに最終利用日時を更新し、最後の利用から7日間アクセスがない場合は失効します。認証情報のセッション世代が更新された場合も旧Cookieを受け付けません。

## ID・パスワード認証の運用

- `/Login`、`/Reauthenticate`、`/LoginSettings` のPOSTは、接続元IPごとに合計20回/分。超過は429とRetry-After: 60。API側のID単位制限はManagementDBで永続化する。
- IP制限はWebプロセス単位。未信頼のX-Forwarded-Forを採用しない。リバースプロキシ配下では既定でプロキシIPを共有するため、公開環境の信頼済みプロキシ設定・境界側の制限を運用で整える。複数Webインスタンスでは境界側でも共通制限を設定する。
- Web認証フォームは16KiB、値1024文字、16項目を上限とする。パスワードは15〜128 Unicode文字をAPIで検証する。入力パスワード・ハッシュ・コードをログへ出力しない。
- 認証Cookieは12時間固定、自動延長なし、ブラウザセッションCookie（永続保存なし）を維持する。設定保存・コード再認証は新しいCookieを発行する。信頼済みブラウザCookieだけは、最後の管理画面利用から7日間のスライディング有効期限を持つ。
- 導入前Cookieは失効世代を持たないため再ログインが必要。通常のAPI/Web配置は`01-deploy-debug.bat`または`10-release-management-deploy.bat`を使い、ManagementDB専用migrationを配置前に成功させる。単独の手動復旧時は`14-management-db-migrate.bat`を実行する。ゲーム用`db-migrate`はManagementDBを対象にしない。旧Webを並行稼働させると世代検証を迂回できるため、Web切替は旧インスタンスを停止する。
- API障害や世代不一致時はCookieを破棄する。パスワード更新結果が不明な場合は再ログインして設定を確認する。
- Minecraftコード復旧はパスワード試行ロックとは別経路。サーバー停止中は復旧を待つ。BAN中のWeb利用可否は既存運用を変更しない。
- ManagementDBの認証情報はゲームDBリセットから独立して保持する。バックアップ・復元もManagementDBを対象にする。
