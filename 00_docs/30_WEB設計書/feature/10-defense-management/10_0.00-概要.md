# 10_0.00-概要

## 管理画面

`/Admin/Defense` はネットワーク設定上のゲームチャンネルを選択して、そのチャンネルの防衛戦だけを管理する。管理者メニューから遷移でき、`WebAdminOnly` による ManagementDB `web_admin=true` と直近のコード本人確認を画面表示・全 POST のたびに要求する。Web は認証済みユーザー UUID を actor として API に送り、API も毎回管理権限を再照会する。Razor Pages の POST は CSRF 保護を受ける。接続には通常の API Key に加え、Web と API に同じ `Defense:WebKey` を秘密設定し、`X-Defense-Web-Key` で送る。秘密値は画面へ出さない。

## 表示と操作

日次開催はチャンネルごとに ON/OFF と開始時刻 `HH:mm` を日本時間で保存する。次回予定、現在の開催、直近結果と直近20件の履歴を表示し、開始要求を受理した `PENDING` とゲームサーバーが実際に開始を報告した `RUNNING` を区別する。手動の「今すぐ開始」は受付済みの参加者を使い、日次設定を書き換えない。停止は表示中の開催 ID と理由を指定する。

受付状態と受付人数はゲームサーバーの直近報告に基づく。報告が古い場合は `UNKNOWN` / 人数なしとして「確認できません」と表示し、時刻だけから受付中と推測しない。初回の手動開始ボタンは `OPEN` かつ受付済み人数1人以上の場合だけ有効にする。開始APIの応答が不明な場合は、受付終了や `PENDING` 表示後でも同じ操作IDと元の設定版番号で再送できる。API側が既存要求の受理結果または新規開始条件を判定する。

設定フォームは専用ワールド・防衛対象と入場地点・敵出現地点・召喚量と上限・反撃・人数/最高登録Lv後の補正・受付と復帰・報酬段階を通常の入力欄で編集する。防衛Lv.1開始、30秒ごとに+1、開始時参加人数最大30人、1～3回目死亡時の15秒蘇生猶予、1・2回目の復活、3回目は蘇生不成立なら脱落、蘇生成立時の今回死亡取消は固定ルールとして表示し、画面で変更しない。未決の数値・報酬は空欄で保存できるが、API が返す `missingSettings` を日本語で表示し、ひとつでも残れば初回開始ボタンを無効にする。参加可能Mobがない場合も不足として示す。報酬段階は指定Lv以上で使う既存オーブIDと数量を表す。

設定 PUT は `expectedRevision` を送り、409では上書きせず再読込を案内する。手動開始と停止は画面で作った `operationId` を送り、通信結果が不明な場合は同じ ID で再送できる。停止は対象の `runId` で競合を検出する。API からの拒否・入力エラーと通信障害は成功扱いにせず表示する。API の要求受理をゲーム内開始成功として表示しない。
