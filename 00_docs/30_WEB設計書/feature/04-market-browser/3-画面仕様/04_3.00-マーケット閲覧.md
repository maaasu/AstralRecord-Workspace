# 04_3.00 マーケット閲覧

## 画面構成

上部に購入先アカウントの所持 Gold とアカウント切替、左側に検索条件、右側に出品一覧を置く。スマートフォンでは縦に並べる。各出品は名前、カテゴリ、レアリティ、出品者、単価、在庫数、出品日時・期限（日本時間）、個体性能の要約を常時表示する。詳細を展開すると出品時の総額、相場参照、装備情報、item master の stat を表示する。出品者のユーザー UUID を解決できる場合、名前から指定アカウントのプロフィールへ移動できる。名前を取得できない場合は「名前不明の出品者」と表示する。

所持 Gold は、ログイン本人の非削除アカウントから選んだ購入先について、既存のプロフィール詳細 API の CurrentAccount.Gold を取得する。認証ユーザーとアカウントの一致を確認し、取得失敗時は 0 ではなく未取得として扱う。残高取得が失敗しても出品一覧は表示する。ゲーム内の保存済み残高であり、購入時に再確認される旨を添える。アカウント切替時は検索条件を保持し、検索・クリア・購入結果への遷移でも購入先を保持する。

## 検索条件

- 名前、ID、lore の文字列検索
- カテゴリ、レアリティ、装備スロット
- 単価、必要レベル
- 出品 response の数値（単価、合計、数量、残数、下限価格、相場参照、価格乖離）
- item metadata の数値（売却価格、最大スタック、必要レベル、装備 stat の min/max）
- `valuationSnapshotJson` に実在する任意の数値パス

カテゴリ、レアリティ、スロット、詳細数値フィルタ候補は、取得済みの出品と item metadata から毎回生成する。Web にカテゴリ enum や翻訳表を固定しないため、新しいカテゴリや出品データ内の新しい数値属性も Web 更新なしで表示・条件指定できる。

## エラー表示

出品 API の取得、認証、JSON 形式に失敗した場合は、ダミー出品を表示せず画面内に取得失敗メッセージを表示する。item detail の 404 は未知 metadata として扱い、出品 response の情報は表示する。

## 購入フォームと結果

- 購入先は画面上部で共通選択し、出品ごとに数量を指定する。各フォームに受取先名を表示する。個体装備の数量は1に固定する。選択中のアカウント自身の出品は購入フォームを表示しない。APIはWeb認証UUIDと購入先アカウントの所有者を再検証する。
- 数量変更時に単価×数量で支払合計を計算する。Gold出品で所持金が取得できた場合だけ購入後の見込み残高または不足額を表示する。整数の丸めを避け、在庫外の数量・不正数値・long上限を超える合計は送信できない。所持金は保存済み時点の値なので、表示上の不足だけでは購入を禁止せず、APIの決済判定を正本とする。JavaScript未使用時の合計は「1個」と明記する。
- 受付後は操作ID付きでページを再表示し、`COMPLETED` はゲーム内メールからの受取を、`PENDING` はゲームサーバーでの処理待ちを表示する。`FAILED` は購入未成立と表示する。
- 応答が失われた場合も同じ操作IDの照会画面へ遷移する。再購入する際は出品状況・ゴールドを確認して新しいフォームを送る。

## 取引履歴

- `/Market` のヘッダーから `/Market/History` へ遷移し、履歴画面から出品一覧へ戻れる。
- 成立済み取引を新しい順に20件ずつ表示する。各行には出品者・購入者の現在のアカウント名と UUID、アイテム名・ID・カテゴリ・数量・単価・総額・成立日時を表示する。ユーザー UUID を解決できる名前は指定アカウントのプロフィールへリンクし、非公開プロフィールのアクセスは詳細画面と API の認可に従う。名前を取得できない場合はその旨と UUID を表示する。
- item ID とカテゴリは完全一致で絞り込める。検索条件は前後ページの導線にも保持する。
- 2ページ目以降が空になった場合も「前へ」を表示し、検索条件を保持したまま有効なページへ戻れるようにする。
- 手数料、売主受取額は公開しない。
- API／認証／JSON 形式の失敗はダミー履歴へ置き換えず、画面内に取得失敗メッセージを表示する。item detail の 404 は未知 metadata として扱う。
