# 04_0.00 概要

## 目的

`/Market` はログイン済みユーザーの出品検索と購入画面、`/Market/History` は成立済み取引の閲覧画面である。購入先には本人のアカウントだけを選択できる。

## データ取得

- `GET /api/market/listings?status=ACTIVE&page={n}&page_size=100` を終端ページ（100件未満）まで順に取得する。現行契約に総数はないため、途中ページが100件の場合は次ページも取得する。
- 出品に含まれる各 `itemId` に対し `GET /api/item/{itemId}` を取得し、名前、レアリティ、装備スロット、必要レベル、基礎 stat を補完する。
- item metadata が得られない場合も、出品レスポンスの `itemCategory` と `itemId` を表示して出品を除外しない。
- `/Market/History` は `GET /api/market/transactions?page={n}&page_size=20` を使用し、API の `hasNextPage` で次ページ有無を判定する。カテゴリと item ID の完全一致条件を API へ渡す。
- 取引履歴にも `GET /api/item/{itemId}` の名前・カテゴリ・アイコンを補完する。item metadata が得られない場合は取引 response の値を表示する。
- 出品者・購入者の名前はプロフィールへリンクする。非公開プロフィールの詳細取得はプロフィール API が拒否する。手数料、売主受取額は表示しない。

## 購入

- 各出品で購入先アカウントと数量を選び、フォームから `POST /api/market/web-purchases/{listingId}` を送る。操作IDはフォームで一意に発行し、応答を失ったときは本人の状態照会へ遷移する。
- 完了した購入品はゲーム内メールの添付から受け取る。ログイン中の購入はゲームサーバーの保存境界で決済されるまで保留と表示し、状態を再読込で確認できる。オフライン購入はAPIで直ちに決済する。
- 出品ボタンは「準備中」で無効のままとする。
- 両ページは `[Authorize]` を要求する。未ログイン利用者は既存の認証 challenge に従う。

検索候補は現在の絞り込みと独立した全ACTIVE出品から作り、カテゴリ・価格を切り替えても他候補を失わない。全条件を取得データへ適用する。出品時valuationの数値は検索だけでなくアイテム詳細にも表示する。

アイコンはスキルツリーと同じ同梱PNGを優先し、未収録のみ既存CDNへフォールバックする。共通 `minecraft-icons.mjs` でMaterial名の検証・取得・キャッシュを行う。
