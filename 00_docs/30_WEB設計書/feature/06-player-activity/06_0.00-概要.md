# プレイヤー活動履歴

管理者が同IPの関係、トレード、ダンジョン・ボス攻略、接続・パーティー操作、モブによるプレイヤー撃破を確認する読み取り専用画面。履歴は HistoryDB を正本とし、ゲーム状態の保存成否・進行条件には使用しない。

## 認可と導線

共通メニューの管理者領域に「プレイヤー活動履歴」を追加する。全画面に `WebAdminOnly` を適用し、現在の管理権限と直近のコード本人確認を要求する。API の `actor_user_uuid` は認証 Cookie の本人 UUID から作り、検索パラメーターから受け入れない。応答は `no-store` とする。IP の生値は表示しない。

## 画面

| ページ | 内容 |
|---|---|
| `/Admin/History/SameIp` | 同IPのプレイヤー関係、MCID・アカウント名、初回/最終観測、トレード回数。ペア間の取引とアカウントの攻略履歴へ移動する |
| `/Admin/History/Trades` | 成立日時、送り手→受け手、アイテム名・ID・数量・ゴールド。選択ペアの両方向を検索する |
| `/Admin/History/Dungeons` | 攻略回単位の開始/終了/所要時間、参加者全員と移動距離。表示切替でプレイヤー別の攻略回数、最速・平均時間、記録済み距離合計を表示する |
| `/Admin/History/Bosses` | 戦闘開始から討伐までの所要時間、参加者ごとの与ダメージ・死亡回数。プレイヤー別の攻略回数、最速・平均時間、与ダメージ・死亡回数合計も表示する |
| `/Admin/History/Events` | 既存 `user_history` のログイン/ログアウト、パーティー作成・招待・参加・退出等を新しい順に表示する。日時、ユーザーUUID、イベント種別、発生元、メッセージを確認し、ユーザーの攻略・取引履歴へ移動できる。`payload_json` は取得・表示しない |
| `/Admin/History/Mobs` | モブによるプレイヤー撃破回数ランキング。モブ名/ID検索から被害者別の死亡回数・被ダメージ・被命中数と、死亡イベント時系列へ移動する |

同IP一覧は異なる userUuid のペアを双方の全キャラクター間のトレード回数順に並べる。アカウント名は期間内に観測した代表名であり、現在の使用キャラクターを意味しないことを注記する。ペアリンクは両userUuid、個別履歴リンクは表示アカウントIDで絞り込む。リスクスコア・自動処罰は提供しない。同IPの一致や移動距離だけでは同一人物・不正を断定できないことを表示する。ゲームアカウント削除後も履歴時点の表示名を使用する。

## 検索と集計

既定期間は日本時間（JST）の当日を含む直近30日。画面の日付と時刻は JST とし、終了日は当日を含む。API には JST の開始日00:00以上、終了日の翌日00:00未満を UTC に変換した半開区間を送る。最大366日、1ページ50件。ページ送りで検索条件を保持する。API 側も範囲・ページサイズ・管理権限を検証する。トレード明細の表示名は履歴保存時の Minecraft Material 名ではなく、記録された `itemId` に対応する現在のアイテムマスター名を優先し、マスターを取得できない場合だけ履歴保存名へフォールバックする。Mob 名の legacy カラーコードは許可した色コードだけを固定 CSS クラスへ変換し、本文を HTML エスケープして表示する。

攻略回の棒表示は参加者の最大移動距離との比較。テレポートを除く概算であり、移動未観測は `null` または観測回数0として「観測なし」を表示し、観測された0mと区別する。攻略回数は期間内に記録された成功回を数える。

ダンジョン・ボスの攻略回表示では `sort=recent/fastest/slowest`（既定は攻略日時の新しい順）、プレイヤー別では `sort=count/fastest/slowest`（既定は攻略回数降順）を選択できる。プレイヤー別の `fastest` は最速記録の昇順、`slowest` は平均時間の降順。DBで検索結果全体をソートしてからページ分割し、画面の順位はページをまたいだ表示順とする。同値は日時・ID等で順序を固定する。経過時間は保存されたミリ秒差を秒へ変換して小数第3位まで表示する。ダンジョンID・ボスIDで完全一致検索でき、異なる対象を混在して比較している場合はその旨が分かる注記を表示する。プレイヤー別の時間は個人行動時間ではなく参加した攻略回全体の時間。

ボス参加者は入場時に確定したスナップショット（カウントダウン中に退出した人も含む）。与ダメージはHPとシールドへの実効ダメージの合計。失敗・中断は攻略集計に含まない。新規ボス履歴の導入前分は復元しない。

接続・パーティー履歴はユーザーUUID、イベント種別（完全一致）、メッセージ・種別・発生元の部分一致で絞り込む。メッセージはHTMLエスケープして表示する。記録欠落があり得るため、ログイン/ログアウトから滞在時間を推定表示しない。

モブの撃破数は死亡回数であり、ユニークな被害プレイヤー数ではない。与ダメージは死亡を伴わない攻撃も含む。プラグインのまとめ送信により反映遅延・ログ欠落があり得る。通信失敗時は取得失敗を表示し、0件成功として扱わない。導入前の未記録データは復元しない。

API DTO の正本は `20_api/AstralRecordApi/AstralRecordApi/Models/PlayerActivityModels.cs`。Web の DTO は読み取り契約のみを対応させる。
