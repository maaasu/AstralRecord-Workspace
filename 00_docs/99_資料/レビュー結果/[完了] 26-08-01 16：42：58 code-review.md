### AR-CODE-001 [高] DATETIME2 のUTC時刻をローカル時刻として epoch 化している
- 種別: `バグ/アルゴリズム`
- 対象: `20_api/AstralRecordApi/AstralRecordApi/Repositories/AccountQuestStateRepository.cs:277`
- 関連箇所: `20_api/AstralRecordApi/AstralRecordApi/Repositories/AccountQuestStateRepository.cs:289, 20_api/AstralRecordApi/AstralRecordApi/Repositories/AccountQuestStateRepository.cs:294, 00_docs/20_API設計書/feature/27-quest/1-モデル定義/27_1.00-モデル定義.md`
- 根拠: API設計は時刻を Unix epoch milliseconds、DBを `DATETIME2(3)` と規定する。一方 `FromEpoch` はUTCで保存するが、`Map` は SQL Server が `DateTimeKind.Unspecified` として返す `DATETIME2` を `new DateTimeOffset(value)` に直接渡している。`Unspecified` は実行ホストのローカルオフセットとして解釈され、Tokyo Standard Time で同一 ticks を変換すると `1785542400000` が `1785510000000` になることを確認した。
- 問題: 保存済みの accepted/completed/cooldown 時刻を GET または PUT 応答に変換すると、UTC以外のAPIホストでタイムゾーン差分だけepochがずれる。
- 影響: Pluginが読込後に保存するだけで時刻が累積的に前倒しされる。特にクールダウンが早期に終了し、受領可否・完了履歴の時刻が破損する。
- 修正方針: DBから取得した時刻を `DateTime.SpecifyKind(value, DateTimeKind.Utc)` でUTCとして扱ってからepochへ変換し、active/completion/cooldown全てのUTC round-trip回帰テストを追加する。
- 修正対象候補: `20_api/AstralRecordApi/AstralRecordApi/Repositories/AccountQuestStateRepository.cs`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-002 [高] 報酬保存中の反復クエストを再受領でき、補償が後続受領を破棄する
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/quest/service/QuestService.java:380`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/quest/service/QuestService.java:353, 10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/quest/service/QuestService.java:641, 10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/quest/service/QuestService.java:781, 00_docs/10_Plugin設計書/feature/29-quest/29_3-メソッド仕様.md`
- 根拠: `complete` は claim を保持したまま対象questをactiveから外す。`REPEATABLE`はこの間 `displayState` が `AVAILABLE` となり得るが、`accept` は同じ `accountId + questId` の `pendingRewardClaims` を検証しない。保存失敗時の補償は対象questを報酬反映前snapshotへ戻すため、後続の同一quest受領progressを上書きする。
- 問題: 報酬保存・補償が完了するまで保持すべきclaimの間に、同一反復questを受領できる。後続受領は進行stateから消え、受領時のinventory消費・非同期保存とも補償境界が重複する。
- 影響: プレイヤーの再受領操作が取り消され、item消費とquest stateの整合性を失う可能性がある。保存失敗時に再試行可能とするクエスト報酬仕様にも反する。
- 修正方針: `accept`（必要なら表示状態）で同一 `RewardClaimKey` が存在する場合は受領を拒否し、REPEATABLE questの「保存失敗→再受領試行→補償」で後続状態と受領条件itemが変化しない回帰テストを追加する。
- 修正対象候補: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/quest/service/QuestService.java`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-004 [高] 別クエストの報酬確定中に失敗補償が後続報酬を巻き戻す
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/quest/service/QuestService.java:978`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/quest/service/QuestService.java:504; 10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/quest/service/QuestService.java:793; 10_plugin/AstralRecord/src/test/java/io/github/maaasu/astralRecord/feature/quest/service/QuestServiceDesignTest.java:562; 00_docs/10_Plugin設計書/feature/29-quest/29_3-メソッド仕様.md`
- 根拠: 報酬claimは `accountId + questId` 単位のため、同一accountの異なるquestは同時に `finishPreparedRewards` へ進める。失敗したquest Aの補償は状態だけをquest Aへ限定して復元する一方、`rollbackAppliedRewards` はAの反映前inventory snapshot全体を `restoreState` し、account/classも反映前値へ全量復元する。その間にquest Bが報酬を反映・保存済みでも、Bのinventory・EXPを区別して保持しない。追加テストはBの「進行」だけを確認し、B自身の報酬反映を並行させていない。
- 問題: quest AのAPIまたはinventory保存が失敗した時点で、Aの報酬反映後に完了した別quest BのGold/item/EXP/class EXPがAの古いsnapshotへ戻される。quest stateはBの完了状態を保持するため、Bは完了済みなのに報酬だけ失った状態となる。
- 影響: 複数questを短時間に達成したプレイヤーが、保存一時失敗を契機に別questの確定報酬を失う。memoryと保存済みinventory/account進行の双方へ誤った補償状態を保存し、通常の再受領では回復できない。
- 修正方針: 報酬反映から補償完了までをaccount単位で直列化する、またはquest単位の差分だけを逆適用して後続報酬を保存する。少なくとも異なるquest A/Bで「A保存失敗、B報酬成功」の順を再現し、Bのquest state・Gold/item・account/class EXPが全て維持される恒久テストを追加する。
- 修正対象候補: `複数`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`
