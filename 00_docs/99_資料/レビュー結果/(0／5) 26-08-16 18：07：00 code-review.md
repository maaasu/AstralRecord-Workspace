### AR-CODE-001 [高] Join時に永続OFF設定がwarmup前に再生される
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/AstralRecord.java:1282`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/playersetting/event/PlayerSettingJoinEventHandler.java:45`
- 根拠: `BaseMusicEventHandler` は `PlayerSettingJoinEventHandler` より先に同じ `MONITOR` 優先度で登録され、Join 時の音楽同期が設定セッション開始・非同期 warmup より先に実行される。`BaseMusicService` の cache miss は `BASE_MUSIC=true` を返す設計である。
- 問題: BASE に参加した `BASE_MUSIC=false` のプレイヤーに対して、永続設定をロードする前に `refreshPlayer` が実行され、既定値 true として音楽再生が開始される。
- 影響: 設定 OFF のプレイヤーが warmup 完了まで音楽を聞く。ほかの eligible listener がいない場合は、この初期再生がシャッフル袋と次曲 task の開始点にもなる。
- 修正方針: Join 時の音楽開始を `PlayerSettingService.warmup` 完了後のメインスレッド同期に限定し、設定ロード前に `BaseMusicEventHandler` が再生を開始しない構成にする。ワールド移動・Quit 同期は従来どおり維持する。
- 修正対象候補: `複数`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `未修正`

### AR-CODE-002 [高] RECORDS停止が物理jukebox音源と衝突する
- 種別: `仕様不整合`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/world/service/BaseMusicService.java:171`
- 関連箇所: `00_docs/10_Plugin設計書/feature/17-world/17_5-例外・ログ・運用.md:17`
- 根拠: `Player.stopSound(Sound, SoundCategory)` は音源の発生元を識別せず、同じ Sound と `RECORDS` category のクライアント音を停止する。物理 jukebox と本実装は対象5曲について同じ音源キー・categoryを使用する。
- 問題: `stopTrack` がプラグイン管理曲だけでなく、物理 jukebox で再生中の対象5曲も停止する。`playTrack` の再生前停止、ワールド移動、設定 OFF、プラグイン停止でも発生する。
- 影響: 既存のバニラ jukebox 音が途中で切れ、設計書の「管理対象5曲だけを停止」という記述では音源の所有者分離を保証できない。
- 修正方針: 物理 jukebox との同時利用を許容するか決定する。許容する場合はクライアント側で音源を識別できる別 sound namespace 等の方式を設計し、実装・設計書・テストを同時に更新する。
- 修正対象候補: `複数`
- 修正可否: `設計判断待ち`
- 確信度: `高`
- 修正状態: `未修正`

### AR-CODE-003 [中] BASE以外へのrefreshでプレイヤー音楽を停止しない
- 種別: `仕様不整合`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/world/service/BaseMusicService.java:63`
- 関連箇所: `00_docs/10_Plugin設計書/feature/17-world/17_4-統合フロー.md:152`
- 根拠: 設計書は BASE 以外または設定 OFF の場合に管理対象曲を `stopSound` すると定義しているが、`refreshPlayer` の BASE 以外分岐は `stopPlaybackIfNoListeners` だけを呼び、対象プレイヤーの `stopTrack` を呼ばない。`handleWorldChange` が先に停止する通常経路ではこの欠落が隠れる。
- 問題: `refreshPlayer` 単体で現在ワールドが BASE 以外になった場合、プレイヤーに残っている管理対象音を停止しない。
- 影響: warmup 完了後の再同期や別の refresh 呼び出しがワールド移動通知と異なる順序で実行された場合、BASE 外で音楽が残る可能性がある。
- 修正方針: BASE 以外の分岐でも対象プレイヤーの `stopTrack(player)` を実行し、設計契約に合わせる。対応するテストの期待値も見直す。
- 修正対象候補: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/world/service/BaseMusicService.java`
- 修正可否: `自動修正可`
- 確信度: `中`
- 修正状態: `未修正`

### AR-CODE-004 [中] 音楽テストの再生禁止検証がnull引数を検証できない
- 種別: `テスト不足`
- 対象: `10_plugin/AstralRecord/src/test/java/io/github/maaasu/astralRecord/feature/world/service/BaseMusicServiceTest.java:90`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/world/service/BaseMusicService.java:168`
- 根拠: 実装は `playSound((Location) null, ...)` を呼ぶ一方、テストの `never().playSound(any(Location.class), ...)` は null に一致しない Mockito matcher である。したがって再生禁止の検証が実際の呼び出しを捕捉できない。
- 問題: `disabledBaseMusicStopsWithoutStartingPlayback` と `nonBaseWorldDoesNotStartMusic` は、実装が null Location で再生しても成功する可能性がある。また scheduler の tick 数を `anyLong()` で検証し、Join 順序、設定競合、複数 listener の cancel、物理 jukebox 影響も検証していない。
- 影響: 主要な音楽停止・曲時間・設定連携の回帰をテストが検出できず、6件のテスト成功だけでは実装契約を保証できない。
- 修正方針: `isNull(Location.class)` 等で null を明示的に検証し、曲ごとの sound と duration ticks、Join/warmup、成功・競合・stale、listener 増減、scheduler cancel のシナリオを追加する。物理 jukebox の扱いを仕様化した後に対応テストも追加する。
- 修正対象候補: `10_plugin/AstralRecord/src/test/java/io/github/maaasu/astralRecord/feature/world/service/BaseMusicServiceTest.java`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `未修正`
