### AR-CODE-001 [高] 一括移行をPlugin共通キーから分離する
- 種別: `セキュリティ`
- 対象: `20_api/AstralRecordApi/AstralRecordApi/Controllers/SkillTreeEditorController.cs:40`
- 関連箇所: `20_api/AstralRecordApi/AstralRecordApi/Repositories/SkillTreeOperationRepository.MigrationBatch.cs:18`
- 根拠: runtime GET、候補取得、一括移行がPlugin登録・heartbeatと同じX-SkillTree-Runtime-Keyだけで認証され、取得した別serverのsession IDを移行要求へ使用できる。
- 問題: 同じruntime keyを持つ別チャンネルPluginから任意serverIdの管理移行を実行できる。
- 影響: Plugin実行権限が最大100アカウントの保存状態を変更する管理権限を持ち、侵害時の影響範囲が全チャンネルへ拡大する。
- 修正方針: migration専用設定キーと専用headerを追加し、runtime GET、definition/state確認、単体・一括移行をPlugin runtime keyから分離する。
- 修正対象候補: `複数`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-003 [中] 静的に不正なbatchを適用前に全件拒否する
- 種別: `バグ/アルゴリズム`
- 対象: `20_api/AstralRecordApi/AstralRecordApi/Repositories/SkillTreeOperationRepository.MigrationBatch.cs:105`
- 関連箇所: `20_api/AstralRecordApi/AstralRecordApi/Repositories/SkillTreeOperationRepository.Migrations.cs:16`
- 根拠: batch事前検証が世代hash、移行先runtime世代、versionを確認せず、後方itemの入力不正が単体移行時に初めて判明する。
- 問題: COMMITの前方itemを適用後、後方itemの静的入力不正だけがREJECTEDとなり、全件preview済み入力をcommitする運用契約を破る。
- 影響: 操作員の入力ミスで意図しない部分適用が発生する。
- 修正方針: 全itemの純粋入力と移行先世代一致をloop前に検証し、実行中の状態競合だけを個別REJECTEDにする。
- 修正対象候補: `複数`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-004 [中] 候補ページをDB側で絞り込む
- 種別: `パフォーマンス`
- 対象: `20_api/AstralRecordApi/AstralRecordApi/Repositories/SkillTreeOperationRepository.MigrationBatch.cs:45`
- 関連箇所: `20_api/AstralRecordApi/AstralRecordApi/Repositories/PlayerActivityRepository.cs:118`
- 根拠: 各ページ要求で全候補をToListAsyncし、メモリ上でGUID文字列sortとSkip/Takeを行っている。
- 問題: page size上限がDB取得件数を制限せず、全ページ取得で全表走査と全件確保を繰り返す。
- 影響: 対象者が多い環境でAPIメモリとDB負荷がページ数に比例して増える。
- 修正方針: CountAsyncとDB側の安定順序・Skip/Takeへ分離し、取得したstate IDのnodeだけを読む。
- 修正対象候補: `複数`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

- 根拠: page、pageSize、mode、件数、重複などの入力不正とruntime/session/state競合がrepositoryのnullから一律409になる。

- 修正方針: Controllerで要求形状を検証して400を返し、repositoryのnullはruntime/state競合として409に限定する。
- 修正対象候補: `複数`
- 修正可否: `自動修正可`
