### AR-CODE-001 [中] 複数記録の累計がInt64上限を超えると一括取得が失敗する
- 種別: `バグ/アルゴリズム`
- 対象: `20_api/AstralRecordApi/AstralRecordApi/Repositories/ServerRecordsRepository.cs:30`
- 関連箇所: `20_api/AstralRecordApi/AstralRecordApi/Repositories/ServerRecordsRepository.cs:36`
- 根拠: 初回レビュー時にプレイ時間・攻略回数・討伐回数の複数アカウント合算をlongのSUMで行っていた。各行の保存可能な値を複数合算するとSQL ServerのBIGINT上限を超える。
- 問題: 個別行は有効でもSUMがoverflowして要求全体が失敗する。
- 影響: 一種類の大きな累計により全8種類のランキングを取得できない。
- 修正方針: SQL側でdecimal(38,0)へ拡張して合算し、表示契約のInt64上限へ丸める。
- 修正対象候補: `20_api/AstralRecordApi/AstralRecordApi/Repositories/ServerRecordsRepository.cs`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-002 [中] Management未移行時のProxy最高権限がランキングに入る
- 種別: `仕様不整合`
- 対象: `20_api/AstralRecordApi/AstralRecordApi/Repositories/ServerRecordsRepository.cs:14`
- 関連箇所: `20_api/AstralRecordApi/AstralRecordApi/Controllers/NetworkController.cs:145`
- 根拠: 初回RepositoryはManagement設定がnullのとき運営UUIDを空としていた。既存NetworkControllerはこの状態で旧PUT同期を受け付け、runtime.GetAuthoritiesのUUIDを最高権限として扱う。
- 問題: DB permissionが0でも旧Proxy同期で有効な最高権限UUIDが除外されない。
- 影響: 移行前の運営プレイヤーが8種類のランキングへ入る。
- 修正方針: Management設定がある場合はその一覧を正本とし、null時だけ既存runtime authorityへfallbackする。
- 修正対象候補: `20_api/AstralRecordApi/AstralRecordApi/Repositories/ServerRecordsRepository.cs`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-003 [高] 既存DBで新列とCHECKを同じbatchに追加するとmigrationが停止する
- 種別: `バグ/アルゴリズム`
- 対象: `00_docs/40_Database設計書/table-definitions/AstralRecord/migrations/20261012_account_play_time.sql:9`
- 関連箇所: `20_api/AstralRecordApi/AstralRecordApi.Tests/Repositories/ServerRecordsRepositoryTests.cs:26`
- 根拠: 初回migrationはADD列に続け同batchでCHECK(play_time_seconds>=0)をコンパイルした。旧schemaの一時SQL Server DBで未存在列参照による「列名が無効」を再現した。
- 問題: batch初期コンパイル時には追加予定列が存在しない。
- 影響: 既存本番DBへのプレイ時間列導入が停止する。
- 修正方針: CHECK追加をsp_executesqlでADD後にコンパイルし、旧列なしのschemaへ二回適用して既存行の0埋めと負値拒否を確認する。
- 修正対象候補: `00_docs/40_Database設計書/table-definitions/AstralRecord/migrations/20261012_account_play_time.sql`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-004 [中] オフライン変更の参加後反映で時間計測のモードが切り替わらない
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/account/service/AccountModeApplicationService.java:180`
- 関連箇所: `10_plugin/AstralRecord/src/test/java/io/github/maaasu/astralRecord/feature/account/service/AccountModeApplicationServiceTest.java:154`
- 根拠: applyPersistedMode(savedRemotely=true)はオフラインAPI待機中に旧モードで参加確定したユーザーへ保存済みモードを反映する。新しいchangeMode通知はオンラインpersistModeChange内だけにあり、この経路にはない。既存offlineModeSaveMergesOnlyModeWhenPlayerJoinsBeforeApplicationが当該競合経路を検証している。
- 問題: アカウントのモード変更後もPlayTimeAccumulatorのplayingが参加時のままとなる。
- 影響: PLAYERからADMINでは管理モード時間を誤加算し、ADMINからPLAYERでは通常プレイ時間が欠落する。
- 修正方針: savedRemotelyのオンライン反映でも同じinventory state lock内で確定モードをchangeModeへ通知し、両方向の積算境界を決定的に検証する。
- 修正対象候補: `複数`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`
