### AR-CODE-001 [中] 装備比較が SCALAR を加算し Plugin の上書き規則と異なる
- 種別: `バグ/アルゴリズム`
- 対象: `60_tool/skilltree-editor/src/SkillTreeEditor.Client/src/data/masterAnalytics.ts:52`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/status/service/StatusService.java:1805`
- 根拠: Plugin の addItemBonus は SCALAR を StatusRangeAccumulator.set で上書きする。基礎ステータスの処理後、calculateEnhanceStats が同一 status/type の強化値を累積し、その SCALAR を addItemBonus へ渡して基礎 SCALAR を上書きする。編集サイトは基礎と強化の全定義を同じリストにして、SCALAR も FLAT と同じ加算処理を行う。Node.js で equipmentRows を実行し、FLAT 10、基礎 SCALAR 0.5、強化 Lv1 SCALAR 2 の比較結果が 25 になることを確認した。Plugin の同条件は最後の SCALAR 2 を使用し、結果は 20 である。
- 問題: 基礎 SCALAR が複数ある場合の最後の値の採用と、累積した強化 SCALAR による基礎 SCALAR の上書きが再現されていない。
- 影響: 強化後の装備比較表・棒グラフ・CSV がゲーム内と異なる性能を示し、装備マスターのバランス調整に誤った数値を使う。
- 修正方針: 基礎 FLAT は加算、基礎 SCALAR は最後の定義で上書きする。強化値を status/type ごとに累積してから、累積強化 FLAT は基礎 FLAT に加算し、累積強化 SCALAR は基礎 SCALAR を上書きする。画面の SCALAR 合計という説明も実装に合わせて更新し、重複基礎 SCALAR と基礎 SCALAR + 強化 SCALAR の意味のある計算テストを追加する。
- 修正対象候補: `複数`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-002 [中] 新規原稿の形式が以前開いたファイルから引き継がれる
- 種別: `バグ/アルゴリズム`
- 対象: `60_tool/skilltree-editor/src/SkillTreeEditor.Client/src/components/MasterDataEditor.tsx:271`
- 関連箇所: `60_tool/skilltree-editor/src/SkillTreeEditor.Server/Services/MasterDataCodec.cs`
- 根拠: 最初の統合版では、新規作成でも source.format が json の場合に jsonFormat が true になる。JSONノードを開いてからYAMLスキルを新規作成すると、選択したYAMLテンプレートと生成した .json の保存先が不一致になる。Filebaseルートのカテゴリも ./ 接頭辞を生成するが、Resolve は . segment を拒否する。
- 問題: 選択した新規テンプレートの形式と保存先の形式が一致せず、ルート保存先も不正なパスになる。
- 影響: スキル・モブ等の新規作成がJSON解析エラーになり、ルートの新規作成も拒否される。
- 修正方針: 新規は選択テンプレート、複製は複製元、取り込みは原稿と明示した形式を採用する。ルートカテゴリは空の保存先接頭辞として扱い、作成リクエストの回帰テストを追加する。
- 修正対象候補: `60_tool/skilltree-editor/src/SkillTreeEditor.Client/src/components/MasterDataEditor.tsx`
- 修正可否: `自動修正可`
- 確信度: `高`

### AR-CODE-003 [中] 新規作成の通信中に追加入力した原稿が失われる

- 関連箇所: `60_tool/skilltree-editor/src/SkillTreeEditor.Client/src/components/MasterDataEditor.tsx:199`
- 根拠: 最初の統合版の新規ダイアログは送信・キャンセルだけをbusy中に無効化し、原稿・カテゴリ・テンプレート・slugの入力を有効にする。送信時の旧値を保存した後、成功時にsetCreateMode(null)でダイアログを閉じる。

### AR-CODE-004 [中] Windowsのパス大小文字で参照による削除保護を回避できる
- 種別: `セキュリティ`
- 対象: `60_tool/skilltree-editor/src/SkillTreeEditor.Server/Services/MasterDataService.cs:247`
- 関連箇所: `60_tool/skilltree-editor/src/SkillTreeEditor.Server/Services/MasterDataPaths.cs`
- 根拠: Windowsでは大小文字の違う入力が同じ実ファイルに解決されるが、初回統合版のKindと一部ディレクトリ認識は大文字小文字を区別する。実サーバーへの読取専用GETで、starter.jsonの通常パスはPlugin設定の参照1件、大文字パスは0件となり、共有ステータスカタログも通常108248件に対し大文字パスは0件となった。DELETEは実行していないが、DeleteAsyncは同じReferencesAsyncの件数が0なら削除へ進む。
- 問題: 同じ実ファイルに対する参照・メタデータ・保護判定が、リクエストの表記によって変わる。
- 影響: 大文字小文字を変えたAPI入力で参照中の構造や共有カタログの削除保護を回避できる。
- 修正方針: Windowsの既存パスは実エントリの表記に照合し、大小文字だけ異なる入力を境界で拒否する。パス比較をOS規則に統一し、参照・メタデータ・ノード保護と任意フォルダの回帰テストを追加する。
- 修正対象候補: `複数`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`
