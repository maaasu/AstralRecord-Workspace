### AR-CODE-001 [中] 極端な帯外価格が DB の乖離率列に保存できない
- 種別: `バグ/アルゴリズム`
- 対象: `20_api/AstralRecordApi/AstralRecordApi/Repositories/MarketRepository.cs:374`
- 関連箇所: `20_api/AstralRecordApi/AstralRecordApi/Data/AstralRecordDbContext.cs:1123`
- 根拠: 相場帯外の拒否を外した一方、出品作成は `unitPrice / referenceUnitPrice` を `PriceDeviationRate` に入れ、EF 設定に加えて `00_docs/40_Database設計書/table-definitions/AstralRecord/init.sql:1467` も実 SQL 列を `DECIMAL(18,6)` とする。例えば売値 0、参照約定単価 1、出品単価 10,000,000,000,000 の場合、見積は `ALLOW`、数量 1 の `totalPrice` も long の範囲内だが、乖離率 10,000,000,000,000 は同列の整数部 12 桁の上限を超える。
- 問題: `SaveChangesAsync` で SQL Server の精度超過が起き、売値を上回る有効価格の出品が API エラーになる。
- 影響: 相場を大きく上回る価格を許可する新仕様を一部満たせない。従来も LOW 信頼時には発生し得たが、今回 MEDIUM/HIGH の帯外価格にも範囲が広がる。SQLite の追加テストは SQL Server の列精度を再現しない。
- 修正方針: 乖離率を列の表現可能範囲で丸めるか、列と API の許容価格域を合わせる。対象の SQL Server 境界テストを追加する。
- 修正対象候補: `複数`
- 修正可否: `要確認`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-002 [中] 高額の約定履歴で相場見積が異常値または例外になる
- 種別: `バグ/アルゴリズム`
- 対象: `20_api/AstralRecordApi/AstralRecordApi/Services/MarketPriceService.cs:191`
- 関連箇所: `20_api/AstralRecordApi/AstralRecordApi/Services/MarketPriceService.cs:227`
- 根拠: `MarketTransaction.UnitPrice` は long で、中央値の偶数件計算は先に long 同士を加算する。例えば 5,000,000,000,000,000,000 が 2 件なら合計が long を超えて負の `referenceUnitPrice` になる。また MEDIUM の約定5件が [2e18, 4e18, 5e18, 6e18, 9e18] なら、中央値 5e18、p25 4e18、p75 6e18、IQR 2e18 から参考上限は 1.2e19 となり、long 上限を超えて変換時に例外になる。各価格は long の範囲内である。
- 問題: 参考価格が負値になるか `CreateQuoteAsync` が失敗し、価格判定の前に出品が失敗する。
- 影響: 個々の約定単価は long の範囲内でも、十分な履歴ができた後に相場表示と出品が壊れる。従来からある算術欠陥だが、相場帯外の出品を無制限に許可する今回の仕様では影響する履歴が増える。追加テストは通常価格のみを扱う。
- 修正方針: 中央値は加算オーバーフローを避けて計算し、参考帯は long の表現可能域に収めて変換する。境界値テストを追加する。
- 修正対象候補: `20_api/AstralRecordApi/AstralRecordApi/Services/MarketPriceService.cs`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`
