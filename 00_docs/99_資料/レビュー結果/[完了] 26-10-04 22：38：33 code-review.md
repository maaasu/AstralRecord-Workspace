### AR-CODE-001 [中] 未公開のクラスカタログでも runtime 登録が進む
- 種別: `仕様不整合`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/playeradmin/service/PlayerAdminDrainService.java:109`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/playerclass/PlayerClassService.kt:98`
- 根拠: `ClassService` は初期状態で `loadedClasses = emptyMap()` とし、`PlayerClassService.getClassCatalogHash()` は空集合にも SHA-256 の非空文字列を返す。起動時の非同期処理は `itemService.loadAll()` の後に `playerClassService.loadAll()` を行うため、アイテム公開後・クラス公開前に poll が実行され得る。API の runtime 登録は64文字の16進ハッシュを受理する。
- 問題: 今回追加した `isBlank()` 判定ではクラスカタログの未公開状態を検出できず、設計書が要求する公開済みの両カタログハッシュを登録する条件を満たさない。
- 影響: 未公開クラスの空集合ハッシュを一時的に API へ登録し、API の実カタログと不一致の間は管理編集開始が 409 で拒否される。クラスロード失敗時は不一致が継続し得る。
- 修正方針: クラススナップショットの公開済み状態を明示し、未公開なら `getClassCatalogHash()` が空文字を返すようにする。正常に公開された空カタログのハッシュは維持し、公開とクリアで状態を更新する。
- 修正対象候補: `複数`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`
