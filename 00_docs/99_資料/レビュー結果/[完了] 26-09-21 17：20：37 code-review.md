### AR-CODE-001 [高] バッチ再送時に冪等キーが変わる
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/history/service/PlayerActivityHistoryService.java:160`
- 関連箇所: `20_api/AstralRecordApi/AstralRecordApi/Repositories/PlayerActivityRepository.cs:11`
- 根拠: 初回確認時は送信失敗後にイベントだけをキューへ戻し、次回送信で新しい `batchId` を生成していた。一方APIは `batchId` をリプレイ判定に使い、各履歴イベントIDを主キーとして保存する。
- 問題: DB保存後にHTTP応答だけを失った場合、同じイベントが別の `batchId` で再送される。APIは同じバッチのリプレイとして処理できず、既存イベントIDとの一意制約競合で以降の再送が失敗する。
- 影響: 一度の通信断を契機に履歴キューが回復せず、活動履歴が欠落する。
- 修正方針: 取り出したイベント群と `batchId` を再送中バッチとして保持し、成功するまで同じ `batchId` で送信する。
- 修正対象候補: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/history/service/PlayerActivityHistoryService.java`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-004 [高] 恒久的な API 拒否を無限再送する
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/history/service/PlayerActivityHistoryService.java:170`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/history/repository/PlayerActivityHistoryRepository.java:32`
- 根拠: 初回確認時は HTTP 応答を例外へまとめ、400・413・422 のような入力またはペイロードの恒久拒否と通信障害・429・5xxを区別していなかった。
- 問題: 恒久拒否されたバッチを `retryBatch` として保持し続け、後続の正常な活動履歴が送信されない。
- 影響: 履歴キューが満杯になり、その後の正常なログも欠落する。
- 修正方針: HTTP status を送信結果として保持し、408・429・5xx・通信障害は同一 batchId で再送する。その他の4xxは恒久拒否として当該バッチだけを破棄し、次のバッチ送信を継続する。
- 修正対象候補: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/history/{repository/PlayerActivityHistoryRepository.java,service/PlayerActivityHistoryService.java}`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-009 [中] 送信タスクと障害時の即時再送が集中する
- 種別: `パフォーマンス`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/history/service/PlayerActivityHistoryService.java:150`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/history/service/PlayerActivityHistoryService.java:183`
- 根拠: 第2回確認時はキュー100件以上の各追加ごとに非同期タスクを予約し、実行側のCASだけで同時送信を抑えている。一時失敗時はretryBatchを保持するが再送待機時間がない。

- 修正方針: 予約段階から実行完了まで送信タスクを1つに制限し、一時失敗時は同じバッチIDを保ちながら少なくとも60秒再送を抑制する。停止後は新規予約しない。
