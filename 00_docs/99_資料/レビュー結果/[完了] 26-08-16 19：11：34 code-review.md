## 指摘一覧

### AR-CODE-001 [中] 耐久更新時の装備再描画が loaded metadata の表示を失わせる
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/inventory/service/InventoryService.java:4390`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/item/service/HookshotCostService.java:74, 10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/item/service/HookshotUseService.java:301`
- 根拠: `ItemStackFactory` の metadata overload（`10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/item/service/ItemStackFactory.java:310-369`）だけが `metadataJson.hookshot.loaded=true` を Lore と `hookshot_loaded` PDC marker に変換し、通常の `InventoryItemStackResolver` も `:138` でその overload を使う。一方、`InventoryService.refreshEquipmentInstanceDisplay` は `:4390` で `create(model, instance, 1)` を呼び、entry metadata を渡さない。`HookshotCostService.consumeDurabilityForFire` は耐久更新直後の `:74` でこの再描画を呼び、続く `HookshotUseService.fire` の `:301-313` は metadata 更新失敗時に rollback して終了する。設計書も loaded の正本を inventory entry metadata とし、失敗時は loaded 状態を保持すると定めている（`00_docs/10_Plugin設計書/feature/04-item/3-メソッド仕様/04_3-サービス.md:379-385`）。
- 問題: 発射前の耐久更新で現在の ItemStack が metadata なしの新しい stack に置換されるため、loaded Lore と charged-icon 用 marker が消える。通常の成功経路では後続の `refreshManagedInventoryUi` が再描画するが、metadata 更新失敗時は loaded 状態を正本に残したまま表示だけが未装填相当になる。耐久 rollback の再描画でも同じ metadata なし生成が行われる。
- 影響: 装備単位の loaded metadata とプレイヤーが見る Lore／クロスボウ状態が不一致になり、実際には左クリックで発射可能な装備が未装填に見える。再同期が起きるまで、今回要求された状態表示を誤る。
- 修正方針: `refreshEquipmentInstanceDisplay` が対象 equipment entry の現行 metadata を取得して metadata overload へ渡すか、managed inventory の表示生成を `InventoryItemStackResolver` に一元化して loaded marker と Lore を必ず保持する。metadata 更新失敗・耐久 rollback の経路で loaded 表示が残る恒久テストを追加する。
