### AR-CODE-001 [高] 進行読み込み中の初回破損が退出時に失われる
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/guide/service/GuideService.java:342`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/guide/service/GuideService.java:221`
- 根拠: 進行未ロード時の条件イベントは pendingConditionsByAccount にだけ保持され、releaseProgress はこれを削除してロード世代も無効化する。装備破損イベントは耐久値が正から0へ変化した時だけ発生する。
- 問題: 進行 API の読み込み中に初めて装備が壊れ、読み込みが完了する前に退出すると、破損条件が保存されない。
- 影響: 次回ログイン時には装備の耐久値が既に0のため同じ装備から破損イベントを再発火できず、修理ガイドへの初回案内を失う。
- 修正方針: ロード待ちの初回破損条件を退出時の保存境界へ渡すか、再ログイン後に保存済み装備状態から一度だけ補完する。ロード中破損から即退出し再ログインする順序を検証する。
- 修正対象候補: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/guide/service/GuideService.java`
- 修正可否: `要確認`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-004 [中] 破損前のシンドリ使用で初回破損時の修理案内が消える
- 種別: `仕様不整合`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/guide/service/GuideService.java:462`
- 関連箇所: `40_filebase/09.features.guide/v3.first_equipment_repair.yml`
- 根拠: GuideProgressEvaluator は手順を独立に評価する。OrbEligibility.canRepair は耐久値が最大未満なら0より大きくても使用可能とし、シンドリ使用成功で ORB_USED が記録される。修理ガイドの repair_with_sindri は ORB_USED、notice_broken_equipment は EQUIPMENT_BROKEN で達成する。
- 問題: 初回破損前に減少した装備をシンドリのオーブで修理すると repair_with_sindri が先に完了する。その後の初回破損で notice_broken_equipment が完了すると修理ガイドは全達成済みとなり、次案内選択は他の未完了ガイドへ進むか表示なしになる。
- 影響: 初めて装備が壊れた時にシンドリのオーブを使う案内が出ず、明示された初回破損時の誘導要件を満たさない。
- 修正方針: 既存の手順独立評価は維持し、修理ガイドに限定して破損時の案内を達成順にかかわらず提示するか、修理手順だけに初回破損の限定前提条件を設ける。破損前修理から初回破損までの順序を検証する。
- 修正対象候補: `複数`
- 修正可否: `要確認`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-005 [高] 退出前に予約したガイドイベントが旧セッションで再生される
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/guide/service/GuideService.java:193`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/guide/service/GuideService.java:222`
- 根拠: 進行ロード成功時に pending イベントをメインスレッド task に予約した後 Future を完了する。releaseProgress は世代とキャッシュを更新するが、予約済み task は実行時に世代・現セッションを再確認せず、記録済みの旧 AstPlayer を recordCondition に渡す。
- 問題: 保留イベントの再生が予約された直後にプレイヤーが退出すると、退出後も旧セッションのイベントが再投入される。再ログインした新セッションの進行へ先に適用される場合、達成通知先も旧 AstPlayer のままである。
- 影響: 初回破損の案内が退出済みプレイヤーへ送られる、または新ログイン側の復元が完了集合の重複判定で抑止され、現在のプレイヤーへ案内されない。ほかの保留ガイド条件にも同じ影響がある。
- 修正方針: 予約 task の実行時に取得時の世代と現セッションを再確認し、旧セッションのイベントを破棄する。保存済み装備・ペット状態からの現在セッション復元は既存 reconcileLoadedAccount に任せ、退出と task 再生の順序を検証する。
- 修正対象候補: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/guide/service/GuideService.java`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/guide/service/GuideCompletionRewardService.java`
- 関連箇所: `なし`
- 根拠: executeExclusiveAfterSave のsupplier例外は未解決の外部境界を残し、通常のGET再試行はその境界に拒否される。
- 問題: 報酬GETやPOSTの通信例外がそのままsupplierを失敗させ、復旧GETも通常操作として予約される。
- 影響: 通信結果が不明なアカウントで報酬再照会と受取再試行が進まなくなる。
- 修正方針: 通信例外を結果値へ変換して境界を閉じ、後保存失敗で残る境界のみ同じ操作IDで回復する。実Coordinatorで失敗と再試行を検証する。
- 修正対象候補: `複数`
- 修正可否: `自動修正可`
