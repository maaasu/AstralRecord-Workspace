### AR-CODE-001 [中] 踏破記録失敗時に楽観キャッシュを巻き戻していない
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/dungeon/service/DungeonService.java:995-1010`
- 関連箇所: `00_docs/10_Plugin設計書/feature/32-dungeon/32_0-概要.md:18,60 / 00_docs/10_Plugin設計書/feature/32-dungeon/32_3-処理契約.md:103-104`
- 根拠: クリア直後に `archiveByAccount` へ楽観反映している一方、非同期保存が `RuntimeException` で失敗してもログ出力だけで終了し、失敗前のキャッシュへ戻していません。さらに `openArchiveListPage` は `loadedArchiveAccounts` を見てキャッシュをそのまま再利用するため、DB 未保存のまま GUI 上は踏破済みの状態が残ります。
- 問題: API/DB 保存失敗後も archive 一覧が成功扱いのまま残り、次回の表示でも誤ったクリア回数・最終踏破日時を見せ続けます。設計上は失敗をクリア本体へ伝播しない代わりに、次回 archive GET で DB 正本へ再同期できる前提ですが、現状はキャッシュが残って再同期されません。
- 影響: 実データと GUI 表示が不一致になり、踏破回数や最終踏破日時が誤って見えます。API 障害時ほど長く残るため、運用判断を誤らせます。
- 修正方針: 非同期保存失敗時は optimistic に追加した踏破記録を戻すか、少なくとも該当アカウントの archive キャッシュを無効化して次回表示で再取得させます。
- 修正対象候補: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/dungeon/service/DungeonService.java`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-002 [低] 詳細画面の戻るが元の一覧ページを保持しない
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/dungeon/event/DungeonInteractionEventHandler.java:273-274`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/dungeon/gui/DungeonArchiveGui.java:53-110`
- 根拠: 詳細 GUI の戻る操作は常に `openArchiveListPage(..., 0)` を呼び、元の一覧ページ番号を引き継いでいません。`DetailHolder` には詳細ページ番号しか保持されておらず、2 ページ目以降の一覧から入ったときに戻り先を復元できません。
- 問題: 一覧の 2 ページ目以降から詳細へ入った利用者が戻ると、常に 0 ページ目へ飛ばされ、直前に見ていた一覧位置を失います。閲覧体験として不自然で、連続確認の導線を壊します。
- 影響: 複数ページある踏破一覧の確認がしづらくなり、ページをまたぐ連続閲覧で余計な操作が発生します。
- 修正方針: 詳細表示時に元の一覧ページを holder へ保持し、戻る操作ではそのページへ復帰させます。
- 修正対象候補: `複数`
- 修正可否: `自動修正可`
- 確信度: `中`
- 修正状態: `修正済み`
