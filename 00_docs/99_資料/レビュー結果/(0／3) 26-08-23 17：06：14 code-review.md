### AR-CODE-001 [中] NPC再表示時に古いtab list非表示タスクが新しい表示へ作用する
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/mob/service/NpcPlayerSkinPacketService.java:375`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/mob/service/NpcPlayerSkinPacketService.java:318`
- 根拠: `spawnForViewer` は表示開始時に `hideFromPlayerListNextTick` を20 tick後へ予約する。予約タスクは viewer UUID が現在 `state.viewerIds()` に存在するかだけを確認し、表示開始世代を確認していない。
- 問題: viewer が表示開始から20 tick以内に範囲外へ出て再び範囲内へ戻ると、最初の表示に紐づく予約タスクが新しい表示へ作用する。新しい表示は20 tick保持される前に tab list から非表示になる。
- 影響: NPC の出入りが短時間に発生した場合、クライアントがスキンを解決する前に profile が非表示となり、スキン表示が不安定になる可能性がある。
- 修正方針: viewer ごとの表示世代または予約タスクを保持し、同じ表示世代の予約だけが tab list 非表示を実行できるようにする。破棄時は予約を無効化する。
- 修正対象候補: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/mob/service/NpcPlayerSkinPacketService.java`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `未修正`

### AR-CODE-002 [低] 擬似 Player 破棄時に非表示にした実体 Entity を復元しない
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/mob/service/NpcPlayerSkinPacketService.java:318`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/mob/service/NpcPlayerSkinPacketService.java:353`
- 根拠: `spawnForViewer` は `viewer.hideEntity(plugin, realEntity)` を実行する一方、`destroyForViewer` は擬似 Entity と profile の削除パケットだけを送信し、`viewer.showEntity` を呼び出さない。
- 問題: 擬似 Player 表示を終了しても実体 Entity の plugin 単位の非表示状態が残る。通常の範囲外・再範囲内では擬似表示が再生成されるため表面化しにくいが、表示失敗、フォールバック、将来の表示条件変更時に実体 NPC が欠落する。
- 影響: NPC がクライアントから見えなくなり、設計上の「擬似 Player を使わない場合は実体 Entity を通常表示する」フォールバックも成立しない。
- 修正方針: viewer ごとの非表示状態を管理し、擬似表示を終了して実体を残す経路では `showEntity` を実行する。実体削除時や別の表示状態がある場合は復元しない。
- 修正対象候補: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/mob/service/NpcPlayerSkinPacketService.java`
- 修正可否: `自動修正可`
- 確信度: `中`
- 修正状態: `未修正`

### AR-CODE-003 [低] 静止中の NPC にも5 tickごとに移動パケットを送信する
- 種別: `パフォーマンス`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/mob/service/NpcPlayerSkinPacketService.java:347`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/mob/service/MobAiService.java:61`
- 根拠: viewer 更新は5 tick間隔で実行され、`syncForViewer` は位置・yaw に変化がなくても毎回 `ENTITY_TELEPORT` と `ENTITY_HEAD_ROTATION` を送信する。
- 問題: NPC 数と同時閲覧者数が増えると、表示に変化のない状態でも packet 作成・送信が増え続ける。
- 影響: サーバー側の packet 処理量とクライアント側の受信量が増え、NPC を多数配置した場合の負荷要因になる。
- 修正方針: viewer ごとに最後に送信した位置・yawを保持し、変化時または再同期時だけ送信する。再スポーン後は必ず初回同期を送る。
- 修正対象候補: `複数`
- 修正可否: `要確認`
- 確信度: `高`
- 修正状態: `未修正`
