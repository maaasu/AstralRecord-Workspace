### AR-CODE-001 [高] 再読込後のmode保存がリモート進行を古い値で上書きする
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/account/service/AccountService.java:91`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/account/service/AccountService.java:285, 10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/account/service/AccountService.java:543, 20_api/AstralRecordApi/AstralRecordApi/Repositories/PlayerStateSnapshotRepository.cs:1473`
- 根拠: `getAccounts` はAPI再読込モデルの `progressVersion` だけを `acknowledgedProgressVersions` へ反映する一方、`setMode` は再読込前の完全な `AccountModel` を `PendingModeUpdate` として保持する。snapshot はそのpendingモデルを基底に level・経験値・class進行をpayloadへ入れ、APIは `expectedProgressVersion` が一致すればそれら全列を更新する。
- 問題: 初回読込が `Lv3 / 1500 / v41`、modeを未ACK変更後の再読込が `Lv4 / 2500 / v42` の場合、追加差分は `expectedProgressVersion=42` を送るがpayloadの進行値は `Lv3 / 1500` のままである。409は回避されるが、APIで先行確定した `Lv4 / 2500` とclass進行を古い値へ戻す。
- 影響: 別チャンネルまたは先行状態で確定済みのアカウント進行が、modeだけのローカル保存によって消失する。マーケットなどの後続保存境界では、進行値が巻き戻されたまま新しい進行版として確定する。
- 修正方針: API再読込モデルをsnapshotの基底にし、未ACKの変更項目だけを再適用する。mode pendingは再読込モデルのmodeだけを置換し、experience/class progress pendingも同じ再base規則で合成する。再読込後のsnapshotが新しいlevel・経験値・class進行とmodeを同時に送る回帰テストを追加する。
