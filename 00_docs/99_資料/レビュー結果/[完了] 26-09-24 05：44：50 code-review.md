## 指摘一覧

### AR-CODE-001 [中] 範囲のドロップ率を各確率判定でロールする
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/mob/service/MobDropService.java:97`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/loot/service/LootRollService.java:73`
- 根拠: `StatusRateCalculator.resolveRatePercent` は範囲を持つ `StatusValue` を `StatusSnapshot.rollValue` で解決する。`MobDropService` はその値を直接ドロップのループ前に一度取得して全アイテムとLoot Tableへ渡し、`BundleUseService` もバンドル単位で一度取得する。`LootRollService` は受け取った率を全content・全rollで再利用する。ステータス定義は範囲値を許可し、設計では各アイテム確率判定ごとのロールを定める。
- 問題: 100〜200%など範囲値が設定された場合、同じMob／採集／バンドル内の複数の確率判定に同一の倍率が共有される。
- 影響: 各確率判定で範囲率を個別にロールする契約と異なり、複数アイテムの当選確率が一つのロール値に相関する。
- 修正方針: 範囲率の解決を各直接ドロップと各Loot Table contentの確率判定時へ移し、固定率の結果は維持する。異なる率値を連続判定へ与える決定的テストを追加する。
- 修正対象候補: `複数`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`
