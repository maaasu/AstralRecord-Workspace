## 指摘一覧

### AR-CODE-001 [低] 初期アカウント補完の失敗時に同一 IP の保留状態が残る
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/user/service/UserService.java:68`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/user/service/UserService.java:79 | 10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/user/service/UserService.java:95`
- 根拠: 既存ユーザー経路は account 解決・補完の前に `pendingSameIpUsers.put` を実行し、補完例外では `INITIALIZATION_FAILED` を返す。拒否された接続では PlayerJoinEventHandler が `consumePendingSameIpUser` を呼ばないため、キーは削除されない。
- 問題: 初期化に失敗した UUID ごとに `pendingSameIpUsers` のエントリが Plugin 稼働中残り続ける。
- 影響: API 障害中の多数の接続失敗でメモリ上の保留マップが増加し、後に同じ UUID が正常接続した時だけ除去される。
- 修正方針: 同一 IP 状態の保持をアカウント準備成功後へ移すか、`INITIALIZATION_FAILED` を返す直前に対象 UUID を削除する。失敗時に `consumePendingSameIpUser` が false となる恒久テストを追加する。
- 修正対象候補: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/user/service/UserService.java`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-002 [中] ログイン前統合フローが新しい拒否結果と補完経路を表していない
- 種別: `ドキュメント不整合`
- 対象: `00_docs/10_Plugin設計書/feature/01-user/01_4-統合フロー.md:18`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/user/service/UserService.java:56 | 10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/user/event/UserLoginEventHandler.java:41 | 00_docs/10_Plugin設計書/feature/01-user/3-メソッド仕様/01_3-サービス.md:24`
- 根拠: 差分で `onAsyncPreLogin` の戻り値を `UserPreLoginResult` へ変更し、`INITIALIZATION_FAILED` と `P_5313` の接続拒否、アカウント0件ユーザーの補完を追加した。しかし統合フローは BAN の戻り値を `false` と記載し、選択アカウントがない場合は参加情報を更新しない旧分岐のままである。図中の初期アカウント slot も実装の `0` と異なり `1` と記載している。
- 問題: 機能の統合正本が実装および同一差分で更新されたメソッド・イベント仕様と矛盾する。
- 影響: 次の修正・障害調査で、初期化失敗が許可される、または欠損 account を補完しないという誤った経路を参照する。
- 修正方針: Mermaid 図と処理要点・終了条件を `ALLOWED` / `BANNED` / `INITIALIZATION_FAILED`、slot 0、0件補完、P_5313 の拒否に同期する。
- 修正対象候補: `00_docs/10_Plugin設計書/feature/01-user/01_4-統合フロー.md`
- 修正可否: `自動修正可`
