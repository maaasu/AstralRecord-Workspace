### AR-CODE-001 [中] 強化素材とゴールドの必要量が別の文字情報へ分散している
- 種別: `可読性/保守性`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/item/service/EquipmentEnhancementService.java:559`
- 関連箇所: `EquipmentEnhancementService.java:606-671; ItemStackFactory.java:192-194; EquipmentEnhancementMenuScreenView.java:14-43`
- 根拠: createMaterialSummaryItem は CHEST 1個の lore に全素材を文字列で列挙し、createInfoItem は必要ゴールドを別の情報アイコンに表示している。素材の実アイコンは表示していない。ItemStackFactory.createDisplay と enhancement_material の filebase 定義は、素材アイコンを表示できる前提を持つ。
- 問題: プレイヤーは「何を何個」「ゴールドをいくら」消費するのかを複数の hover 情報から読み合わせる必要があり、素材が増えるほど一覧性が落ちる。素材名が解決できない場合は item ID がそのまま表示される。
- 影響: 強化実行前のコスト判断を誤りやすく、修理と強化を同じ導線へまとめても費用表示の意味が揃わない。
- 修正方針: 共通メンテナンスGUIに必要コストブロックを設け、素材は実アイテムアイコンごとに必要数/所持数を表示し、ゴールドも同じブロックへ置く。素材が枠数を超える場合は詳細ページまたはクリック詳細へ分ける。実アイコン生成は既存の ItemStackFactory.createDisplay を再利用する。
- 修正対象候補: `EquipmentMaintenanceView / EquipmentMaintenanceService のコスト表示モデル`
- 修正可否: `設計判断待ち`
- 確信度: `高`
- 修正状態: `未修正`

### AR-CODE-002 [中] 強化後のステータス・耐久値の差分が表示されない
- 種別: `可読性/保守性`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/item/service/EquipmentEnhancementService.java:606`
- 関連箇所: `ItemEquipment.kt:163-175; ItemStackFactory.java:922-1053`
- 根拠: createInfoItem は現在/次の強化値、成功率、失敗時挙動、必要ゴールドを表示するが、次レベル定義に存在する statIncrease と durabilityBonus を表示していない。ItemStackFactory の装備 lore は現在値の表示であり、強化前後の比較ではない。
- 問題: プレイヤーは成功率や費用は見られても、攻撃・防御などがいくつ増えるか、最大耐久値が変わるかをGUI内で判断できない。状態変化も名称と必要強化値が中心で、変化後の主要仕様が見えない。
- 影響: 強化の価値とリスクを比較できず、情報不足のまま素材を消費する操作になる。
- 修正方針: 強化計算結果を current/after/delta のプレビューにまとめ、通常強化は強化値、変更される status、最大耐久値を前後比較で表示する。状態変化は名称、最大強化値、エンチャント枠など変更対象を列挙し、表示値の整形は既存の status 表示規則へ委譲する。
- 修正対象候補: `EquipmentEnhancementPreview と共通差分表示 View`
- 修正可否: `設計判断待ち`
- 確信度: `高`
- 修正状態: `未修正`

### AR-CODE-003 [高] 失敗時に装備破壊となる強化を単一クリックで実行できる
- 種別: `仕様不整合`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/item/service/EquipmentEnhancementService.java:167`
- 関連箇所: `EquipmentEnhancementService.java:286-319; EquipmentEnhancementService.java:432-437; EquipmentEnhancementService.java:506-508`
- 根拠: 強化実行スロットのクリックから executeEnhancement が直ちに呼ばれ、実行前の確認段階がない。FAIL_DESTROY では selectedEquipment と selectedEntry を解除し、結果処理では deleteEquipmentInstance を呼ぶ。現在の画面には失敗時挙動の表示はあるが、破壊確認専用の操作はない。
- 問題: 破壊が起こり得る装備で、通常の実行クリックと不可逆な消滅操作の導線が同一である。
- 影響: 誤クリックや情報を読み飛ばした操作によって装備を失う危険がある。統合GUI化で操作対象が増えると、さらに誤操作の可能性が上がる。
- 修正方針: failAction が DESTROY、または少なくとも確率失敗を伴う場合は、赤字で「失敗時に装備が消滅します」を表示し、確認画面または2段階確認を必須にする。確認後も対象装備名、成功率、失敗時挙動、全コストを再表示し、実行中は再クリックを無効化する。
- 修正対象候補: `EquipmentMaintenanceConfirmationView と強化実行状態`
- 修正可否: `設計判断待ち`
- 確信度: `中`
- 修正状態: `未修正`

### AR-CODE-004 [中] 修理・強化GUIの共通導線がサービス・View・イベント処理で重複している
- 種別: `可読性/保守性`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/item/service/EquipmentRepairService.java:54`
- 関連箇所: `EquipmentEnhancementService.java:64; EquipmentRepairMenuScreenView.java:15-34; EquipmentEnhancementMenuScreenView.java:14-43; InventoryEquipmentGuiEventHandler.java:116-129,260-319; EquipmentRepairService.java:734-739; EquipmentEnhancementService.java:1001-1006; MobInteractionEventHandler.java:247-254`
- 根拠: EquipmentRepairService と EquipmentEnhancementService が、対象装備の選択、選択解除、close/save/shutdown時の返却、非同期処理中の状態保持を個別に実装している。両Viewは guide/info/target/操作枠をほぼ同じ slot（11/15/20/24）へ配置し、InventoryEquipmentGuiEventHandler も強化・修理を別メソッドで振り分けている。
- 問題: GUIの共通部分を変更するたびに複数実装を同期する必要があり、対象装備の返却やクリック制御だけが片方と異なるドリフトを起こしやすい。復元に失敗した場合のワールドへの drop fallback も別実装であり、NPC側は open 失敗後も OPEN 音を鳴らす。
- 影響: 現在の画面が似ているにもかかわらず、修理と強化の操作感、エラー表示、将来の確認処理が不一致になる。保守コストも増える。セッション境界で装備を他プレイヤーに拾われるリスクや、失敗を成功と誤認する表示が残る。
- 修正方針: EQUIPMENT_MAINTENANCE の共通GUI shell、共通 session、対象装備選択、返却、非同期境界、イベントルーティングを作り、REPAIR / ENHANCE / TRANSCENDENCE を操作モードとして切り替える。返却処理は共通化し、復元失敗時の保護された回収経路を定義する。open は成否を返して成功時だけ OPEN 音を鳴らす。修理費計算と強化計算・結果適用は既存の各ドメイン処理へ残し、巨大な単一サービスにはしない。NPCは従来どおり別役割のまま、開くタブだけ初期選択にする。
- 修正対象候補: `EquipmentMaintenanceService / EquipmentMaintenanceMenuScreenView / MenuScreen.EQUIPMENT_MAINTENANCE`
- 修正可否: `設計判断待ち`
- 確信度: `高`
- 修正状態: `未修正`
