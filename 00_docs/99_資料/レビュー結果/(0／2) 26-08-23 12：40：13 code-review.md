### AR-CODE-001 [中] YAML構造を追跡しない正規化がスカラー内容を改変する
- 種別: `バグ/アルゴリズム`
- 対象: `20_api/AstralRecordApi/AstralRecordApi/Services/MasterDataSeeder.cs:769`
- 関連箇所: `00_docs/40_Database設計書/master-data/MasterDataDB同期フロー.md:12; 00_docs/40_Database設計書/master-data/MasterDataDB設計.md:22`
- 根拠: MasterData Seeder の契約は YAML を検証し、API 配信用 JSON へ正規化することである。実装は `rawText` を改行ごとに分割し、各行の最初の `:` の後が `&` で始まると、YAML のブロックスカラー内かどうかを確認せず引用符を挿入している。またコメント切り出しも `line.IndexOf(" #")` の単純検索で、引用符内を除外していない。
- 問題: 有効な YAML の `description: |` の本文に `key: &afoo` があると、本文が `key: "&afoo"` へ変わり、保存される JSON の文字列値が入力 YAML と異なる。同様に、`"foo # key": &afoo` のような引用符付きキーではキー内の ` #` をコメント開始と誤認して値の正規化を取り逃がし、YamlDotNet が `&afoo` をアンカーとして `null` に変換する。いずれも YAML の構造を追跡せずに行を再構成していることが原因である。
- 影響: 表示文・説明文などのマスタ文字列が静かに改変されるほか、引用符付きキーを使うマスタでは意図した `&` 文字列が `null` payload になる。Seeder は失敗せず、source hash と異なる内容が MasterDataDB の JSON payload に登録されるため、後から入力とDBの差分を検出しにくい。
- 修正方針: YAML の quote/comment/block scalar/flow collection の状態を保持した正規化器にするか、YamlDotNet の構文情報を利用して対象 scalar だけを変換し、block scalar の本文と引用符内コメントを必ずそのまま通過させる。併せて block scalar、引用符内に ` #` を含むキー、flow collection の境界値を回帰テストへ追加する。
- 修正対象候補: `20_api/AstralRecordApi/AstralRecordApi/Services/MasterDataSeeder.cs; 20_api/AstralRecordApi/AstralRecordApi.Tests/Services/MasterDataSeederSkillSystemTests.cs`

- 根拠: 本番の `NormalizeAmpersandScalarLine` には `- &...` を引用符付きシーケンス要素へ変換する分岐があるが、`MasterDataTestSeed` 側は mapping value の変換だけで終了し、その分岐を持たない。新規テストは `MasterDataSeeder.ParseYamlObject` を反射で直接呼び出しており、14箇所の `MasterDataTestSeed.SeedEntryAsync` 利用経路を通らない。
- 問題: 同じ入力 `lore:\n  - &afoo` に対し、本番 parser は `"&afoo"` を返す一方、テスト helper はアンカーを `null` として `lore: [null]` にする。したがって、テストが本番と異なる payload をDBへ投入し、helper 側の変更漏れや quote-aware parser の回帰を検知できない。現在の filebase に該当する未引用シーケンス要素がないことは、処理契約の不一致を解消しない。

- 修正方針: 正規化・YAML変換を共有可能な内部 utility へ切り出して本番と `MasterDataTestSeed` で同じ実装を使うか、少なくとも sequence value の分岐を helper に同期する。production parser と helper の同一入力・同一JSON結果を検証するテストを追加し、既存の `SeedEntryAsync` 利用経路でも確認する。
