- 修正方針: 個別 GUI の見た目・slot・文言の case は戻さず、共通 holder を使って close/open/continuation/cancel/quit の token・終了一回性を検証する最小の MockBukkit テストを残す。

### AR-CODE-003 [中] 保留 GUI 遷移のプレイヤー単位取消・一回性テストを削除している
- 種別: `テスト不足`
- 対象: `10_plugin/AstralRecord/src/test/java/io/github/maaasu/astralRecord/shared/gui/GuiOpenSupportCancellationTest.java`
- 関連箇所: `00_docs/10_Plugin設計書/feature/22-trade/22_3-メソッド仕様.md:送信画面の開始・終了`
- 根拠: 削除されたテストは `GuiOpenSupport.cancelPending` に対し、対象プレイヤーの保留遷移だけを解除し、scheduler task と取消 callback を各一度だけ実行し、他プレイヤーの遷移を維持することを検証していた。設計書は同じ取消時に、当該遷移だけを中止して予約を解除し、task と callback を一度だけ終了し、他プレイヤーへ介入しないことを定める。現行 test source は `TradeService` からの `cancelPending` 呼出を確認するだけで、この共通処理の状態遷移を検証していない。
- 問題: 削除対象は個別の送信 GUI 表示ではなく、多数の GUI 呼出元が共有する `GuiOpenSupport` のプレイヤー単位の取消、冪等性、補償 callback の不変条件である。
- 影響: 後続クリックや離脱処理で取消対象が別プレイヤーへ漏れる、同じ予約の scheduler task または取消 callback が重複実行される、または取消済み画面が開く回帰を恒久テストで検知できない。
- 修正方針: 個別 GUI の表示 case は復元せず、`GuiOpenSupport.cancelPending` の対象分離、task 取消、callback 一回性、再呼出冪等性だけを検証する最小の JUnit テストを残す。
