### AR-CODE-001 [高] 満杯BAGへの同種フルスタック受取で超過分が不可視になる
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/trade/service/TradeService.java:715`
- 関連箇所: `20_api/AstralRecordApi/AstralRecordApi/Repositories/TradeRepository.cs:174 / 10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/inventory/service/InventoryItemStackResolver.java:80`
- 根拠: `22_0-概要` は、通常容量を超えた受取 entry を容量外 slot として保持・表示する契約である。一方、Trade API は受取 BAG の既存同種 stack に最大スタック数を考慮せず数量を加算し、TradeService は結果を `reconcileExternalInventoryEntries` で再同期するだけである。表示 resolver は entry 数量を item の `maxStack` 以下へ clamp する。
- 問題: 受取側の BAG が満杯で同種 stack が `maxStack` まで埋まっているときに1個以上を受け取ると、API/ローカル state は既存 entry を `maxStack` 超過の数量へ更新するが、余剰を容量外 entry へ分割しない。Bukkit 表示では `maxStack` 個までしか描画されず、受取分が見えなくなる。
- 影響: トレードは成功通知まで完了するにもかかわらず、受取 item の一部が GUI から到達不能な状態となり、容量外受取を許可する仕様を満たさない。
- 修正方針: Trade の affected BAG entry を再同期する際、通常 item の `maxStack` 超過分を別 entry へ分割し、通常容量に空きがなければ容量外 slot へ採番して保存・再描画する。満杯 BAG・既存同種フルスタック・1個以上の受取を再現する回帰テストを追加する。
- 修正対象候補: `複数`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-002 [低] Trade API設計書が容量外受取の契約へ同期されていない
- 種別: `ドキュメント不整合`
- 対象: `00_docs/20_API設計書/feature/22-trade/0-概要/22_0.00-概要（API）.md:11`
- 関連箇所: `00_docs/10_Plugin設計書/feature/22-trade/22_0-概要.md:14`
- 根拠: 今回更新された Plugin 設計書は、通常 BAG の空き容量を成立条件にせず、容量外 slot への受取・表示を現在の契約として定義している。対して API 設計書は再同期後の Plugin を「BAG 容量と予約枠に従って有効 slot を割り当てる」とだけ記載しており、容量外 slot の保持・表示を示していない。
- 問題: 同一の trade commit 後処理について Plugin 設計書と API 設計書の受取 slot 割当契約が一致していない。
- 影響: API/Plugin 境界を参照して保守する際に、満杯 BAG のトレード受取を再び通常容量不足として拒否または未配置扱いへ戻すおそれがある。
- 修正方針: API 設計書の再同期後処理を、Plugin が通常容量外の entry も slot 割当・保存・表示し、通常取得ではその slot を再利用しない契約へ同期する。
- 修正対象候補: `00_docs/20_API設計書/feature/22-trade/0-概要/22_0.00-概要（API）.md`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`
