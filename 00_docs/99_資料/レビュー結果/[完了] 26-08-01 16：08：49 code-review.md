### AR-CODE-001 [高] 既存DBへ列を導入する移行SQLがない
- 種別: `仕様不整合`
- 対象: `20_api/AstralRecordApi/AstralRecordApi/Data/AstralRecordDbContext.cs:412`
- 関連箇所: `00_docs/40_Database設計書/table-definitions/AstralRecord/init.sql:303`
- 根拠: API は常に `left_click_skill_id` を EF Core の列として選択・更新する。一方、差分内のDDLは新規作成用 `CREATE TABLE` に列を加えただけで、既存 `skill_bind_preset` 表へ列を追加する `ALTER TABLE` または同等の移行手順は存在しない。
- 問題: 既存のAstralRecord DBへこの版のAPIを配置すると、GET/PUTが存在しない `left_click_skill_id` を参照して失敗する。
- 影響: 既存プレイヤーはスキルバインドプリセットを読込・保存できず、スキル設定GUIとアクションリングが利用不能になる。
- 修正方針: 既存DBへ安全に適用できる列追加・既存行更新を含む冪等な移行SQLと、その実行手順を用意する。
- 修正対象候補: `00_docs/40_Database設計書/table-definitions/AstralRecord`
- 修正可否: `要確認`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-002 [高] 既存保存プリセットで左クリック通常攻撃の既定値が失われる
- 種別: `バグ/アルゴリズム`
- 対象: `20_api/AstralRecordApi/AstralRecordApi/Repositories/SkillBindPresetRepository.cs:99`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/skill/repository/SkillBindPresetRepository.kt:109; 10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/skill/service/SkillActionRingService.java:363`
- 根拠: 未保存presetだけは予約値を返すが、既存保存行は nullable なDB値をそのまま返す。Pluginも null をそのまま取り込み、`hasLeftClickBind` は null を未設定として扱う。設計書には既存行を予約値で初期化するとあるが、実装・移行SQLにその処理がない。
- 問題: 既存プレイヤーの保存済みプリセットは新列が null のため、要件で全プレイヤーに既定設定する武器通常攻撃を左クリックで発動できない。
- 影響: 既存ユーザーだけが武器通常攻撃を再設定するまで左クリック攻撃を失い、プリセットの別操作を保存しても null が永続化される。
- 修正方針: AR-CODE-001の移行で既存行を予約値へbackfillし、APIの読込時にも既存nullを予約値へfallbackすることで導入順序に依存しない既定値を保証する。
- 修正対象候補: `20_api/AstralRecordApi/AstralRecordApi/Repositories/SkillBindPresetRepository.cs; 00_docs/40_Database設計書/table-definitions/AstralRecord`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-004 [中] 自動保存中に「変更を破棄」が永続済みの変更を取り消せない
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/skill/event/SkillBindGuiEventHandler.java:151`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/skill/event/SkillBindGuiEventHandler.java:385; 10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/skill/service/SkillBindPresetService.java:153`
- 根拠: bind変更直後に非同期保存を開始する一方、保存中であってもclose時はdirty判定だけで「変更を破棄して閉じますか」を表示する。確定しても実行済みの非同期PUTを中止・rollbackせず、成功時にはcacheへmergeする。
- 問題: 表示文言どおりに破棄を確定しても、変更がDBへ保存される場合がある。
- 影響: ユーザーが保存しない意図で閉じた変更が次回ログイン後も残る、または保存結果と画面操作の意味が一致しない。
- 修正方針: 保存中は閉じる操作を待機・拒否して保存完了後に閉じるか、確認文言を自動保存済み/保存中に整合するものへ変更し、セッション遷移を一貫させる。
- 修正対象候補: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/skill/event/SkillBindGuiEventHandler.java`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-005 [中] 保存中クローズ後の再表示が次回の通常クローズまで抑止する
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/skill/event/SkillBindGuiEventHandler.java:165`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/skill/event/SkillBindGuiEventHandler.java:430`
- 根拠: 保存中に閉じた後は、元の `InventoryCloseEvent` が完了した状態でtaskから `openMain` を呼ぶ。`openMain` は常に `suppressCloseIfSwitchingWithinSkillGui` を実行して抑止フラグを追加するが、この再表示では置換対象のinventoryがないため消費するclose eventが発生しない。
- 問題: 再表示されたGUIを次に通常どおり閉じると、残った抑止フラグがそのclose eventを消費し、session削除とplayer inventory復元が行われない。
- 影響: 保存中に一度閉じたプレイヤーは、次回GUIを閉じてもスキル設定sessionが残留し、通常inventoryが再描画されない。
- 修正方針: close済み状態からの再表示ではsuppressCloseを追加しない専用open経路を使うか、再表示前に抑止フラグを消費して、次のユーザー起点closeを必ず通常処理する。
- 修正対象候補: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/skill/event/SkillBindGuiEventHandler.java`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`
