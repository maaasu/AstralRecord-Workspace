### AR-CODE-001 [中] 配置更新キーを送る HTTPS の証明書を検証できない場合がある
- 種別: `セキュリティ`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/worldplacement/repository/WorldPlacementRepository.java:87`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/infrastructure/util/ApiRequestUtil.kt:47`
- 根拠: 共通 HTTP クライアントは、debug または通常 API がローカル・プライベート接続先であれば、`api.ssl.verifyEnabled=false` で証明書検証を無効化できる。
- 問題: 配置 API の HTTPS URL が通常 API と別ホストでも、同じクライアントで `X-World-Placement-Key` を送信していた。
- 影響: 通信経路で配置 API を偽装できる第三者に Dev 配置全体の更新キーが漏れる。
- 修正方針: 登録トランザクションの HTTP クライアントを証明書検証が有効なものに固定する。明示的な loopback HTTP の許可は既存契約に従う。
- 修正対象候補: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/worldplacement/repository/WorldPlacementRepository.java`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/teleporter/command/TeleporterCommand.java:141`

- 修正方針: 登録前に `WorldType.TEMP` を明示的に拒否する。
- 修正対象候補: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/teleporter/command/TeleporterCommand.java`

### AR-CODE-003 [中] PUT の HTTP 200 だけで保存済みと判断する
- 種別: `仕様不整合`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/worldplacement/repository/WorldPlacementRepository.java:96`
- 関連箇所: `00_docs/20_API設計書/feature/43-world-placements/43_README.md`
- 根拠: 配置 API の単件 PUT は、更新後の revision と保存行を含む全件スナップショットを返す。
- 問題: PUT の応答本文を破棄していたため、本文が異常、revision が更新されていない、または登録した行がない HTTP 200 を保存成功として扱う。
- 影響: 保存を確認できない場合もログに成功を記録し、管理者へ保存済みとして案内する可能性がある。
- 修正方針: 応答スナップショットを検証し、revision の更新と、同一の有効な行に送信した配置 ID とウェイストーン ID があることを確認する。
- 修正対象候補: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/worldplacement/repository/WorldPlacementRepository.java`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-004 [低] エディターで正確に扱えない解除費用を登録できる
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/teleporter/command/TeleporterCommand.java:106`
- 関連箇所: `60_tool/skilltree-editor/src/SkillTreeEditor.Client/src/api/worldPlacementApi.ts:23`
- 根拠: エディターは JSON の `unlockGold` を JavaScript の `number` で読み、保存時に全配置を再シリアライズする。
- 問題: Dev のゲーム内登録で Java の `long` の上限まで費用を保存でき、エディターが正確に再送できない値が入り得る。
- 影響: 別の配置を編集した際に解除費用が丸められるか、丸め後に API の整数型の上限を超えて全件保存が失敗する。
- 修正方針: Dev でロックを有効にして新規登録する場合だけ、解除費用の上限を JavaScript の安全な整数の最大値に合わせる。
- 修正対象候補: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/teleporter/command/TeleporterCommand.java`
- 修正可否: `自動修正可`

### AR-CODE-006 [中] 配置 API の応答本文が停止すると再読込が完了しない
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/worldplacement/repository/WorldPlacementRepository.java:177`
- 関連箇所: `10_plugin/AstralRecord/src/test/java/io/github/maaasu/astralRecord/feature/worldplacement/repository/WorldPlacementRepositoryTest.java:146`
- 根拠: 配置 API は `BodyHandlers.ofString()` で本文の完了を待つ。Java HTTP クライアントのリクエスト期限だけでは、応答ヘッダー受信後に停止した本文の待機を打ち切れない。
- 問題: 共通の送信処理が本文完了まで待機するため、API がヘッダーと本文の一部を送って停止すると、GET と PUT が例外完了しない。
- 影響: ウェイストーン登録の結果通知が届かず、再読込が進行中のまま保持されると後続の再読込も同じ待機に合流する。
- 修正方針: 本文完了までの待機に設定済みの期限を適用し、期限切れと割り込みで HTTP 要求を取り消す。ヘッダーと本文の一部を送信してから停止する loopback 応答で回帰を確認する。
- 修正対象候補: `複数`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`
