- 関連箇所: `00_docs/20_API設計書/feature/34-player-state/1-モデル定義/34_1.00-モデル定義.md:28`
- 根拠: 転生中のEXPポイント変換単位は100EXPであり、Plugin、player-state API、DB制約は端数0～99へ統一されているが、Account APIモデル設計書だけが0～9を正本として記載している。

- 修正方針: Account APIモデル設計書の端数範囲を0～99へ更新する。

### AR-CODE-002 [中] migrationの制約式を統合テストが検証していない
- 種別: `テスト不足`
- 対象: `60_tool/db-migrate/tests/db-migrate.integration.ps1:72`
- 関連箇所: `00_docs/40_Database設計書/table-definitions/AstralRecord/migrations/20260915_expand_rebirth_experience_remainder.sql:20`
- 根拠: migration runnerのschema expectationはcheck制約名の存在だけを検査し、統合テストも新migrationの履歴件数と0～99の制約式を確認していない。
- 問題: 既存DBの制約が誤って0～9のままでも、manifest静的検証と配置時schema検査を通過できる。
- 影響: APIが99を受理しても既存DBだけが拒否し、保存失敗が再発する可能性がある。
- 修正方針: db-migrate統合テストで新migrationの履歴を確認し、99を受理して100を拒否することで制約式と再実行の冪等性を検証する。
- 修正対象候補: `60_tool/db-migrate/tests/db-migrate.integration.ps1`
- 修正可否: `自動修正可`
