### AR-CODE-001 [中] 統合版のダメージ数値に表示サイズが反映されない
- 種別: `仕様不整合`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/shared/display/DamageNumberScalePacketAdapter.java:71`
- 関連箇所: `00_docs/10_Plugin設計書/feature/14-combat/14_5-例外・ログ・運用.md:51`
- 根拠: [Geyser の TextDisplay 変換](https://github.com/GeyserMC/Geyser/blob/master/core/src/main/java/org/geysermc/geyser/entity/VanillaEntities.java#L440-L465) は Java の拡大率を読み飛ばし、統合版では Armor Stand の名札で表示する。AstralRecordGeyserExtension はカスタムヘッドを登録する。
- 問題: 受信者別処理は Java の TextDisplay メタデータの拡大率のみを書き換える。
- 影響: 統合版の閲覧者が小・大を保存しても、描画されるダメージ数値の文字サイズは変わらない。
- 修正方針: 統合版での表示方式を確定し、採用した方式の設定と描画を同期する。
- 修正対象候補: `複数`
- 修正可否: `設計判断待ち`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-002 [高] 新旧チャンネルの混在時に旧チャンネルで設定を保存できない
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/playersetting/service/PlayerSettingService.java:322`
- 関連箇所: `20_api/AstralRecordApi/AstralRecordApi/Repositories/PlayerStateSnapshotRepository.cs:1232`
- 根拠: 新版は設定変更時に全列挙キーを送るため DAMAGE_NUMBER_SIZE 行を新規保存する。旧版は未認識キーをロード時に除外し、旧版の列挙値だけを送る。API は既存行 ID が要求に含まれない場合に設定セクションを拒否する。
- 問題: 新版で設定を保存したユーザーの設定スナップショットを旧版が送信すると、サイズ行の欠落によって拒否される。
- 影響: 段階配備中や旧版への切り戻し後、該当ユーザーは旧チャンネルで既存設定の変更も保存できない。
- 修正方針: 新旧クライアントが同じ保存先を使う場合の互換契約を定義し、旧版が送れない設定行を保持しながら旧版の設定変更を保存できるようにする。
- 修正対象候補: `複数`
- 修正可否: `設計判断待ち`
- 確信度: `高`
- 修正状態: `未修正`
