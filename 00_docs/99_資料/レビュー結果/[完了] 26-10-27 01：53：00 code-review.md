### AR-CODE-001 [高] 原稿のコメントだけを編集するとフォームへ戻った後に保存できない
- 種別: `バグ/アルゴリズム`
- 対象: `60_tool/skilltree-editor/src/SkillTreeEditor.Client/src/components/MasterDataEditor.tsx:344`
- 関連箇所: `60_tool/skilltree-editor/src/SkillTreeEditor.Client/src/components/MasterDataEditor.tsx:238`
- 根拠: `dirty` はフォームモードでは `draft.content` と保存済み `document.content` だけを比較する。一方、原稿からフォームへ戻る処理は解析した `content` を入れるが、編集後の `draft.raw` も保持する（同ファイルの 324-334 行）。
- 問題: YAML 原稿モードでコメントまたは整形だけを変更し、フォームへ戻ると `content` は保存済みと同一なので `dirty` が false になる。追加された `!dirty` ガードで Ctrl+S と保存ボタンが書込みを拒否する。
- 影響: ユーザーの原稿変更が保存されず、未保存表示と下書き保護も消えるため、タブを閉じるとコメントや整形が失われる。原稿モードのままなら保存できるが、フォームへ戻る通常操作で発生する。
- 修正方針: 保存要否の判定に未保存の原稿変更も含める。フォームへ切り替えた後もコメントのみの変更を未保存として扱い、保存時にその原稿を維持することをテストする。
- 修正対象候補: `60_tool/skilltree-editor/src/SkillTreeEditor.Client/src/components/MasterDataEditor.tsx`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-002 [中] 必須項目の欠落時に検証結果へフォーカスしない
- 種別: `バグ/アルゴリズム`
- 対象: `60_tool/skilltree-editor/src/SkillTreeEditor.Client/src/components/MasterDataEditor.tsx:465`
- 関連箇所: `60_tool/skilltree-editor/src/SkillTreeEditor.Server/Services/MasterDataValidation.cs:230`
- 根拠: JSON Schema 検証は `result.InstanceLocation` を問題パスとして返す。`required` による子項目の欠落では、存在しない子ではなく、その親オブジェクト（ルートなら空パス）が示される。フォーム側は、パスが存在するだけで移動先の候補として採用する。
- 問題: 必須の子項目が欠けて親だけがエラーになった場合、保存失敗後のフォーカスは親セクションの見出しへ移り、問題と修正方法を示す検証結果へ移らない。空パスだけのエラーでもルート見出しへ移る。
- 影響: 欠落した必須項目をフォーム上で特定できないとき、ユーザーは検証結果へ戻って原因を探す必要がある。README の「未存在の必須項目は検証結果へフォーカス」の動作を満たさない。
- 修正方針: 親オブジェクトまたはルートだけを指すエラーで具体的な編集欄がない場合は、検証結果の見出しへフォーカスする。既存オブジェクトの必須子項目欠落とルートエラーをテストする。
- 修正対象候補: `60_tool/skilltree-editor/src/SkillTreeEditor.Client/src/components/MasterDataEditor.tsx`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`
