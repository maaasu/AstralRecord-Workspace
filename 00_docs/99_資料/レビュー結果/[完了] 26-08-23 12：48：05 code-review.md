### AR-CODE-001 [中] 定常スポーン診断ログを INFO/WARN で毎回出力している
- 種別: `パフォーマンス`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/gathering/spawner/service/GatheringSpawnerService.java:328`
- 関連箇所: `複数`
- 根拠: `GatheringSpawnerService.tick` は20 tick間隔で全配置を走査し、定義の `spawnIntervalTicks` ごとに `I_9011` と、上限判定時の `I_9014` または候補選択・生成時の `I_9015` / `I_9016` を `Logger.info` で出力する。`Logger.info(LogId, ...)` はデバッグ設定による抑制を行わず、通常ログ出力に加えて有効な監査 logger へ毎回 enqueue する。
- 問題: プレイヤーが範囲内にいる通常稼働中、配置ごとに少なくとも毎判定の INFO 行が発生し、スポーン成功時は複数行になる。候補なしの `W_9012` や生成失敗の `W_9013` も同じ周期で繰り返され得るため、診断用の詳細ログが本番コンソールと監査キューを継続的に占有する。
- 影響: 配置数に比例してコンソール出力、文字列整形、監査キューの allocation / drain が増え、定常 tick の余計な負荷とログノイズを招く。多数配置または長時間の無効地形では、必要な警告・エラーの追跡性も低下する。
- 修正方針: 判定開始・上限・候補詳細・成功詳細などの診断用途は `D_*` と `Logger.debug` に切り替え、デバッグモード時だけ出力する。設定不備や継続的な生成失敗を WARN として残す場合は、状態変化時または一定間隔へ抑制する。
- 修正対象候補: `複数`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

- 根拠: `12_5-例外・ログ・運用.md` はログを `LogId` ベースで管理し、個別 ID 採番の正本を同文書の「2. 主なログポイント」と定めている。しかし今回追加された `I_9011`～`I_9016`、`W_9011`～`W_9013` は同文書に記載されておらず、既存の `W_9010` までしか定義されていない。
- 問題: 実装と `logger.properties` だけでは、各 ID の物理名、出力レベル、運用上の意味が設計書から追跡できない。ログ仕様を正本として参照する保守・運用担当者が新規ログを把握できず、ID 採番の二重管理状態になる。

- 修正方針: `12_5-例外・ログ・運用.md` の採集スポナーのログポイント表へ、追加 ID ごとの物理名・内容・レベルを追記し、必要なら診断ログを DEBUG、異常ログを WARN とする運用方針も同時に明記する。
