### AR-CODE-001 [高] 中断した戻る遷移が履歴を不可逆に消費する
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/shared/gui/navigation/GuiNavigationService.java:94`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/shared/gui/navigation/GuiNavigationState.java:59 | 10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/shared/gui/GuiOpenSupport.java:53`
- 根拠: `beginBack()` は previous を `pollFirst()` して `expectedBackGui` に保持するが、`GuiOpenSupport.open` は後続クリックで予約を cancel し、source 不一致・offline・target open 不成立時には何も通知せず return する。設計書 `09_3-サービス.md` の「予約済み遷移が後続クリックで取り消された場合は source を閉じず、セッション終了候補も発生しない」契約では、戻る履歴も成功時以外に消費してはならない。
- 問題: 戻るクリック後、2 tick の間に別の遷移を選ぶと `openPrevious` は true を返す一方で、取り出した戻り先を復元しない。`expectedBackGui` も残るため、後から同じ inventory が開かれた場合に通常の履歴登録を誤って回避する。
- 影響: 連続クリック・open cancel・logout 前の中断で戻る履歴が消え、以後の戻るボタンが close 扱いになるか、別画面で古い back 予約が誤消費される。ユーザー要件の「cancel/失敗・連続遷移を安全に処理」に反する。
- 修正方針: GUI 遷移を成功・cancel・失敗で完了通知する token 化 API にし、`GuiNavigationState` に予約 rollback を追加する。`openPrevious` は target open 成功時だけ back を確定し、その他では同じ inventory を履歴先頭へ戻して `expectedBackGui` を消去する。
- 修正対象候補: `複数`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-002 [高] 保存中スキルマネージャーを終端扱いにしてから無条件に再表示する
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/skill/event/SkillBindGuiEventHandler.java:180`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/shared/gui/session/GuiSessionTransitionEventHandler.java:91 | 10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/shared/gui/navigation/GuiNavigationService.java:57 | 00_docs/10_Plugin設計書/feature/13-skill/4-統合フロー/13_4-スキルバインドGUI.md:69`
- 根拠: shared handler は `finishClose` 成功後に `CLOSE` と `GuiSessionEndEvent` を発行し、navigation listener は同イベントで履歴を clear する。その後に SkillBind handler は session token・現在 inventory・online state を再照合せず次 tick に `openMain` / `openSynthesis` / `openConfirm` を予約する。設計書は保存中 close の再表示で既存 session と戻る履歴を維持すると定める。
- 問題: 保存中に閉じると shared session は既に終了し、CLOSE が鳴って navigation 履歴も失われる。さらに終了確定後から予約 Runnable 実行までに別 GUI を開くと、古い Runnable がその GUI をスキルマネージャーで上書きする。
- 影響: 保存中のユーザーが戻る履歴を失い、連続操作時には意図しない GUI 強制表示や session/cleanup の取り違えが起こる。これは終端と遷移を token 単位で一元化する恒久対策の不変条件を破る。
- 修正方針: 保存中の再表示要求を close 確定前の共有 lifecycle に登録し、継続する session を終端イベント・CLOSE・navigation clear の対象外にする。やむを得ず後続 task を使う場合も、終了 generation と現在の session/inventory を token で照合して stale task を no-op にする。
- 修正対象候補: `複数`
- 修正可否: `自動修正可`

- 修正状態: `修正済み`

### AR-CODE-006 [高] 未保存変更の確認画面をセッション終了後に開き直す

- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/skill/event/SkillBindGuiEventHandler.java:216`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/shared/gui/session/GuiSessionTransitionEventHandler.java:162 | 10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/shared/gui/navigation/GuiNavigationEventHandler.java:44 | 10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/skill/gui/SkillBindGui.java:288`
- 根拠: `onGuiSessionEnd` は `GuiSessionTransitionEventHandler.completeSessionClose` が close token を終了として確定し、Hotbar Shortcut GUI の `CLOSE` 再生と終了イベント発行を行った後だけ呼ばれる。しかし未保存の MAIN 画面では SkillBind handler がここで次 tick の `openConfirm` を予約しており、close 前に `GuiSessionContinuationRequestEvent` を登録していない。設計書 `09_3-サービス.md` の共通 GUI セッション遷移は、別 GUI への成功遷移では `CLOSE`・feature cleanup・navigation clear を発生させない契約である。
- 問題: 未保存変更のあるスキルマネージャーを手動 close すると、確認 GUI は後から表示されるのに、先に元 session が終了扱いになる。`GuiNavigationEventHandler` は同じ終了イベントで履歴を clear するため、確認をキャンセルしても直前 GUI への戻り先を失う。

- 修正方針: 未保存 MAIN の close も保存中再表示と同じ共有 continuation として close event 内に登録し、次 tick に確認 inventory を生成して開く。確認画面で最終 close を選んだ場合だけ `GuiSessionEndEvent` を発行し、手動 close→確認表示、確認 cancel、最終 close の音・履歴を結合テストで固定する。

### AR-CODE-007 [高] logout が終端 cleanup を抑止してゴミ箱などの一時状態を残す
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/shared/gui/session/GuiSessionTransitionEventHandler.java:114`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/menu/event/MenuOpenEventHandler.java:242 | 10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/menu/event/MenuOpenEventHandler.java:277 | 10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/menu/service/TrashService.java:160`
- 根拠: `onPlayerQuit` は active session を即時 `clear` する。close は次 tick の `finishClose` でしか `GuiSessionEndEvent` を発行しないため、logout 中の close token は終了イベントにならない。今回 trash / sell / storage / dummy cleanup は `MenuOpenEventHandler.onGuiSessionEnd` へ移管された一方、`onPlayerQuit` は craft shortcut の cleanup だけを実行する。`TrashService.handleClose` が通常 close で内容を返却することも確認した。
- 問題: ゴミ箱を開いたまま logout すると、top inventory に退避した item を返却する `TrashService.handleClose` が呼ばれず、`trashItemsByPlayer` と player inventory の整合を回復しない。同じ経路で storage 保存、dummy 復元、hotbar shortcut mode の終了処理も飛ぶ。
- 影響: logout 時に一時 GUI 状態が残り、ゴミ箱へ移した item が正規 inventory へ戻らない。再接続までの不整合やサーバー停止時の item 消失につながり、設計書の「logout は未確定 token を破棄し、player quit の既存 cleanup へ委譲する」契約を満たさない。
- 修正方針: session lifecycle に音を鳴らさない quit 終端経路を追加するか、PlayerQuit 時に終了 inventory を使って menu の cleanup を必ず一度実行する。通常 close と logout の双方で trash item 返却・storage cleanup・session/token破棄を確認し、logout では `CLOSE` を再生しない結合テストを追加する。

- 修正可否: `自動修正可`
