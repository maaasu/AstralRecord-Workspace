### AR-CODE-001 [高] 正規化失敗後の再試行でAPI返却数量が重複する
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/inventory/service/InventoryService.java:2579`
- 関連箇所: `InventoryService.java:2778, OrbInventoryThreeWayMerger.java:120, OrbService.java:2167`
- 根拠: 三者マージ結果をstateへ反映した後に取得したsnapshotへ正規化失敗時に戻し、OrbServiceが同じbaselineで再試行する。
- 問題: 初回のAPI追加差分がstateへ残ったまま再試行され、同じ追加差分を三者マージが再適用する。
- 影響: ルーンのマスタ解決などが一度失敗すると、脱着返却ルーンが複製される。市場・Tradeの返却も同じ経路で影響を受ける。
- 修正方針: 三者マージのstate反映と共通追加正規化を同一の原子的なstate更新にし、失敗時は三者マージ反映前へ戻す。同じbaselineによる失敗後再試行で数量が増えない回帰テストを追加する。
- 修正対象候補: `InventoryService.java, InventoryServiceOrbReconciliationTest.java`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-002 [高] state lock内で未キャッシュitemのAPI I/Oへ到達する
- 種別: `パフォーマンス`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/inventory/service/InventoryService.java:2412`
- 関連箇所: `InventoryService.java:2645, ItemReferenceResolver.java, ItemService.java:230`
- 根拠: 三者マージpublish後の返却正規化をsynchronized(state)内で実行し、未キャッシュitemはresolveItemModelからItemService.loadItemへ到達する。
- 問題: account state lockを保持したままitem masterのAPI I/Oを実行し得る。
- 影響: 通信待ち中に同一accountの在庫操作を停止させ、save/account laneとの待ち合わせでdeadlockやtick停止の原因になる。
- 修正方針: authoritative affected取得後かつstate lock取得前に返却正規化用ItemModelとItemReferenceを解決し、lock内では解決済み値だけを使用する。
- 修正対象候補: `InventoryService.java, InventoryServiceOrbReconciliationTest.java`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`
