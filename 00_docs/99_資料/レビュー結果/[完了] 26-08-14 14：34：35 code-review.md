### AR-CODE-001 [高] class baseStats の加算対象と絶対値 semantics が未統一
- 種別: `仕様不整合`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/status/service/StatusService.java:814`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/playerclass/PlayerClassService.kt:89`
- 根拠: `PlayerClassService` は `baseStats + growthPerLevel × (classLevel - 1)` を返し、現在の `StatusService` はそれを `getBaseValue` に加算している。作業差分の 07-status は補正の加算を明記しているが、20-class の設計書と class YAML スキーマは `baseStats` を初期値、`growthPerLevel` を1レベルあたりの増加量と説明するだけで、グローバル基礎値との関係を定義していない。実データには `MAX_HEALTH`、`ATTACK` 等の非 Shield 値が存在する。
- 問題: 例えば `MAX_HEALTH: 105` をクラス固有の絶対的な初期値と読む場合、現在実装ではグローバル基礎値 20 に加算され 125 になる。加算仕様として正しいのか、クラス値で置換するのかを設計書間で確定しないまま実装を固定すると、全クラスの戦闘バランスが変わる。
- 影響: クラス初期値、クラスレベル成長、基本能力値からの派生値の最終 status が意図と異なる可能性がある。
- 修正方針: class status を「グローバル基礎値への加算」とするか「クラス基礎値への置換」とするかを正本で決定し、20-class、filebase schema、戦闘バランス、07-status、テストの式を統一する。
- 修正対象候補: `複数`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-002 [中] クラス master snapshot 再読込後にオンライン status を更新しない
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/playerclass/PlayerClassService.kt:49`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/AstralRecord.java:1905`
- 根拠: マスターデータ再読込は `playerClassService.replaceSnapshot(classSnapshot)` をオンライン運用中にも実行する。`replaceSnapshot` はクラスキャッシュとプレイヤーリスト名だけを更新し、`StatusService.refreshStatus` を呼ばない。`StatusService.getStatus` は有効な snapshot があれば再計算せず返す。
- 問題: 再読込で `baseStats`、`growthPerLevel`、`maxLevel` が変わっても、オンラインプレイヤーの既存 status snapshot は明示的に別の refresh が発生するまで旧値のまま残る。
- 影響: filebase のクラス定義を再読込した直後の表示・戦闘・回復計算が、プレイヤーごとに旧クラス値を参照し得る。
- 修正方針: クラス snapshot 公開後にオンラインプレイヤーの status と派生状態を一括再計算する。HP/MP/EN/Shield の現在値保持・上限 clamp 方針も併せて既存 refresh 契約へ合わせる。
- 修正対象候補: `複数`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

- 対象: `10_plugin/AstralRecord/src/test/java/io/github/maaasu/astralRecord/feature/status/service/StatusClassGrowthTest.java`

- 根拠: 追加テストは `PlayerClassService` を mock して `StatusService` の全 status 種別呼出しを検証し、別テストは `PlayerClassService.getStatusBonus` の式だけを検証する。実クラス YAML、実 `PlayerClassService`、クラスレベル変更、refresh 後の snapshot 値を同時に検証するテストは確認できない。Mob/Quest/コマンド/GUI の各呼び出し元も status refresh の実行を直接検証していない。
- 問題: 加算/置換 semantics、class level 増加、派生 status、現在値保持、各呼び出し経路の refresh 漏れを、現在のテストでは回帰として検出できない。

- 修正方針: semantics 確定後、実 `ClassModel` を使う status snapshot テストと、クラス変更・クラスレベル変更・Mob/Quest 報酬・マスター再読込後の refresh テストを追加する。

### AR-CODE-004 [低] Mob 経路で status refresh が重複する
- 種別: `パフォーマンス`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/mob/service/MobCombatService.java:427`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/skilltree/service/SkillTreeService.java:1708`
- 根拠: クラスレベルアップ時の Mob 経路は `skillTreeService.refreshProgressDerivedState` を呼び、その実装が `statusService.refreshStatus` を実行する。その後、同じ分岐で `statusService.refreshStatus` を直接呼ぶ。
- 問題: クラスレベルアップ時に同じプレイヤーの status snapshot を連続して2回再計算する。
- 影響: 直ちに値が誤るとは限らないが、装備・派生・パッシブ・バフを含む再計算コストと副作用の発生回数が増える。
- 修正方針: status refresh の責務を SkillTree 経由または呼び出し元の一方へ統一し、クラス・プレイヤーレベル双方のレベルアップで一度だけ再計算する。
- 修正対象候補: `複数`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`
