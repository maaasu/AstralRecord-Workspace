## 指摘一覧

### AR-CODE-001 [中] 相場参考上限が出品可能単価より低くなる
- 種別: `バグ/アルゴリズム`
- 対象: `20_api/AstralRecordApi/AstralRecordApi/Services/MarketPriceService.cs:191`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/market/gui/MarketGui.java:557`
- 根拠: `ResolveAllowedRange` は履歴がない LOW の場合に `(sellPrice, max(sellPrice * 50, suggestedPrice * 5))` を返す。店売り価格0・履歴なし・品質補正なしでは `suggestedPrice` も0なので参考帯は0〜0 Goldとなる。実際に `40_filebase/10.features.item/10.material/v1.10a00025.skill_gem_raw_beginner.yml` は `saleValue: 0`、`unTradeable: false` で、API設計は売値0の品も出品可能とする。さらに MEDIUM の約定101 Goldが5件あった後に店売り価格を1,000 Goldへ引き上げると、参考帯は1,000〜101 Goldになる。API設計上の出品可能最低単価は `sellPrice + 1` である。
- 問題: 参考上限が出品可能最低単価を下回り、Plugin の「相場参考上限」最大ボタンは `MarketListingDraft.quickMaxUnitPrice()` で最低単価へ補正される。そのため売値0・履歴なしでは表示上限0 Goldに対して最大ボタンは1 Gold、店売り価格引き上げ例では表示上限101 Goldに対して最大ボタンは1,001 Goldとなる。後者では参考帯自体も逆順になる。
- 影響: 取引可能な売値0の新商品や店売り価格を引き上げた商品で、ユーザーが要求した相場上限と最大ボタンの案内が矛盾する。出品可否そのものは店売り価格超で維持される。
- 修正方針: API の相場参考上限を参考下限および出品可能最低単価 `max(1, sellPrice + 1)` 以上に正規化する。`sellPrice + 1` は `long` のあふれを避けて扱い、LOW の売値0・履歴なしと、店売り価格変更後の MEDIUM/HIGH 履歴で境界値を確認する。参考帯の算出規則を記した API 設計書も同期する。

- 修正可否: `自動修正可`
