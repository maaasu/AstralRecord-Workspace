### AR-CODE-001 [低] 採集破壊パーティクルが統合フローへ反映されていない
- 種別: `ドキュメント不整合`
- 対象: `00_docs/10_Plugin設計書/feature/12-mob/12_4-統合フロー.md:226`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/gathering/service/GatheringService.java:442`
- 根拠: `12_4-統合フロー.md` の採集破壊シーケンスは HP == 0 の後に `MobDropService.roll` へ進む契約になっている。一方、実装は break sound の直後に `ParticleDisplayService.spawnForNearbyViewers` で `displayBlock` の `BlockData` を表示し、その後に報酬処理へ進む。設計書運用ルールでは、利用者から観測できる挙動と重要な処理順の変更時に関連設計書を同期することになっている。
- 問題: 今回変更された `12_2-ユースケース.md` と `12_3-サービス.md` には粒子表示が追記されているが、同じ採集完了経路を図示する `12_4-統合フロー.md` には `ParticleDisplayService` とその処理位置が記載されていない。
- 影響: 統合フローだけを参照する実装者・テスト作成者は、破壊時の表示契約と break sound／報酬処理の順序を把握できず、設計書間で現行仕様の記述が分裂する。
- 修正方針: `12_4-統合フロー.md` の採集シーケンスへ共通パーティクル表示の participant と、break sound 後かつ報酬処理前に `displayBlock` 材質の破壊パーティクルを表示する処理要点を追記する。
- 修正対象候補: `00_docs/10_Plugin設計書/feature/12-mob/12_4-統合フロー.md`
- 修正可否: `要確認`
