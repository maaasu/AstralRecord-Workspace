### AR-CODE-001 [中] 一覧再取得で完了済みclaimを消去し二重報酬を許す
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/mail/service/MailService.java:124`
- 関連箇所: `00_docs/10_Plugin設計書/feature/18-mail/18_0-概要.md:24 / 10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/mail/event/MailGuiEventHandler.java:198`
- 根拠: メール設計は同一 `(userId, mailId)` を `in-flight／completed set` で二重実行しない契約である。一方 `listAsync` 成功時に user 単位で `completedClaims` を消去し、受取成功後の GUI 再取得も `MailGuiEventHandler` から同じ経路を通る。
- 問題: 既読化成功後でも一覧取得の応答が一時的に未読を返す、または一覧が stale な場合、完了済みclaimが先に消去されて再度 `readAndReceive` が報酬準備・付与へ進む。
- 影響: 同一メールの報酬が二重付与され得る。ローカルの completed guard が一覧更新のたびに無効化され、設計書の冪等性契約を満たさない。
- 修正方針: 一覧取得成功時に `completedClaims` を消去しない。claim の保持期間・ログイン単位での初期化が必要なら、既読化結果と競合しない専用のライフサイクルで管理し、stale 一覧を含む二重受取テストを追加する。
- 修正対象候補: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/mail/service/MailService.java`
- 修正可否: `要確認`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-002 [中] rollback失敗時のcallbackが報酬残留をfalseで返す
- 種別: `仕様不整合`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/mail/service/MailService.java:267`
- 関連箇所: `00_docs/10_Plugin設計書/feature/18-mail/18_3-メソッド仕様.md:51 / 00_docs/10_Plugin設計書/feature/18-mail/18_4-統合フロー.md:63`
- 根拠: `ReadAndReceiveResult.rewardReceived` は「この呼び出しで実際に inventory mutation が発生したか」を表す契約である。既読化失敗かつ `rollbackPreparedRewards(receipt)` 失敗の分岐では、receipt に mutation があり、報酬は reconciliation 完了まで inventory に残る。
- 問題: 当該分岐は `new ReadAndReceiveResult(false, false)` を返すため、実際に報酬を付与した状態を「報酬なし」として公開する。
- 影響: 公開 callback の利用側が、報酬なし・rollback済みと、報酬残留・reconciliation待ちを区別できない。将来の GUI 音、通知、監視、再調停処理が誤った分岐を選ぶ。
- 修正方針: callback の `rewardReceived` を receipt の mutation 有無と実際の最終状態に一貫して対応させ、rollback失敗で報酬が残る分岐ではその事実を返す。rollback成功時との意味も設計書・テストで固定する。
- 修正対象候補: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/mail/service/MailService.java / 00_docs/10_Plugin設計書/feature/18-mail/18_3-メソッド仕様.md`
- 修正可否: `設計判断待ち`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-003 [中] reconciliation成功時にmailReceivedListenerが発火しない
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/mail/service/MailService.java:313`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/mail/service/MailService.java:289 / 10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/AstralRecord.java:1056 / 00_docs/10_Plugin設計書/feature/18-mail/18_5-例外・ログ・運用.md:16`
- 根拠: `mailReceivedListener` は Javadoc 上「メール報酬の受取成功時」の通知先で、実 call site は `GuideService.recordCondition(... MAIL_RECEIVED ...)` である。直接の既読化成功経路では報酬付与時に listener を呼ぶが、既読化とrollbackがともに失敗した後、reconciliation の既読化が成功する経路では completed 登録とclaim解除だけを行う。
- 問題: 報酬が inventory に残ったまま最終的に既読化された claim では、listener が一度も呼ばれない。
- 影響: 当該メールの報酬は受領済みでも `MAIL_RECEIVED` のガイド進行が欠落する。再試行で補う経路もなく、オンライン中のプレイヤーにも受取成功通知・副作用が届かない。
- 修正方針: reconciliation 用claimに通知済み状態と必要な player identity を保持し、報酬 mutation が残ったclaimの最終確定時に listener を一度だけ発火する。offline 時の扱いと通知タイミングを設計書へ明記し、rollback失敗→reconciliation成功のテストを追加する。
- 修正対象候補: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/mail/service/MailService.java / 10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/AstralRecord.java`
- 修正可否: `要確認`
- 確信度: `高`
- 修正状態: `修正済み`
