## 指摘一覧

### AR-CODE-001 [中] 定期通知の装備解決が同期 API 呼び出しへフォールバックする
- 種別: `パフォーマンス`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/item/service/EquipmentDurabilityService.java:221`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/item/service/ItemReferenceResolver.java:97`
- 根拠: `PLUGIN_GUIDE.md` および `astralrecord-code/references/plugin-code.md` は Bukkit/Paper のメインスレッド制約を要求し、装備中のプレイヤー状態は Plugin 側のロード済み状態を正本として扱う。`ItemReferenceResolver.resolveItemModel` はキャッシュ未命中時に `ItemService.loadItem` へ進み、`resolveEquipmentInstance` は `ItemService.findEquipmentInstanceById` を呼び出す。後者はキャッシュ未命中時に repository API を同期実行する。
- 問題: `EquipmentDurabilityReminderTask` の同期 timer から新規の `getDamagedArmorAndAccessoryDisplayNames` を呼ぶと、装備マスタまたは装備個体がキャッシュにない場合、プレイヤーごと・装備ごとに同期 API 通信が発生する。
- 影響: 周期通知の1回の実行がメインスレッドをブロックし、オンライン人数やキャッシュ欠落数に比例して tick 遅延、プレイヤー操作遅延、通知周期の遅延を起こし得る。
- 修正方針: この定期通知経路では `findLoadedById` と `findLoadedEquipmentInstanceById` を使用し、ロード済みでない装備はその周期の通知対象から除外する。ItemStack のカテゴリ欠落時も API 解決へフォールバックしない cache-only 解決にする。
- 修正対象候補: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/item/service/EquipmentDurabilityService.java`
- 修正可否: `自動修正可`
