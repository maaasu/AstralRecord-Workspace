### AR-CODE-001 [中] テレポーター GUI が開かなかった場合にも開く音が鳴る
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/teleporter/service/TeleporterService.java:396`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/shared/gui/GuiOpenSupport.java:42`
- 根拠: `00_docs/10_Plugin設計書/feature/25-teleporter/3-メソッド仕様/25_3-GUI・View.md` の「ウェイストーンからの GUI 表示音」は、GUI を表示した場合だけ `GuiSound.OPEN` を再生すると定めている。
- 問題: `handler.open` は `TeleporterGui.open` を通じて、既存 plugin GUI からの遷移を `GuiOpenSupport` で 2 tick 後に予約する。予約時にプレイヤーが閉じる・別 GUI へ遷移する・offline になると `openIfSourceIsCurrent` は何も開かずに戻るが、呼出元は直後に `OPEN` を再生するため、表示に失敗しても開く音だけが鳴る。
- 影響: 実際には GUI が開かない操作で成功フィードバックが発生し、今回追加した「表示時だけ」のサウンド仕様に反する。
- 修正方針: `GuiOpenSupport` の即時/遅延の両経路で実際に inventory を開くことが確定した後だけ通知できる callback または結果を用意し、テレポーターの `OPEN` をその時点へ移す。ページングは既存の `PAGE` のみを維持し、遷移中止時には再生しない。遅延遷移が中止されたケースをテストする。
- 修正対象候補: `複数`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-002 [中] InventoryOpenEvent による表示中止でも開く音と close 音抑止が残る
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/shared/gui/GuiOpenSupport.java:47`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/shared/gui/GuiOpenSupport.java:99`
- 根拠: `00_docs/10_Plugin設計書/feature/25-teleporter/3-メソッド仕様/25_3-GUI・View.md` の「ウェイストーンからの GUI 表示音」は、GUI を表示した場合だけ `GuiSound.OPEN` を再生すると定めている。`09_3-サービス.md` の共通 GUI 遷移ガードも、遷移を実行した場合だけ source の close sound を抑止すると定めている。
- 問題: `open` と `openIfSourceIsCurrent` は `Player#openInventory` の戻り後に target が実際に開かれたことを確認せず `onOpened` を実行する。別プラグイン等が `InventoryOpenEvent` を cancel すると target は表示されないが、ウェイストーンの callback は `OPEN` を鳴らす。遅延遷移ではさらに、表示前に close sound を抑止するため、cancel 後に source を閉じたときの close 音まで失われる。
- 影響: AR-CODE-001 の「表示確定後のみ OPEN」と遷移中止時の無音保証が、InventoryOpenEvent による中止経路では満たされない。
- 修正方針: `Player#openInventory` 後に target が現在の top inventory になったことを確認してから `onOpened` を実行し、遅延遷移の close sound 抑止もその確認後に行う。InventoryOpenEvent が cancel された immediate / delayed の両経路で callback と close sound 抑止が実行されないことをテストする。
- 修正対象候補: `複数`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`
