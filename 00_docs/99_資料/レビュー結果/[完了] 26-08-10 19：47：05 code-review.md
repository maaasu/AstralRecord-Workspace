### AR-CODE-001 [高] 終了転送前の索引解放により新旧セッションの転送が競合する
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/dungeon/service/DungeonService.java:1312`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/world/service/WorldService.java:525`
- 根拠: `completeSession` は `sessionsById`、party、world、participant の各索引を先に削除し、その後で参加者の帰還転送を開始する。一方 `WorldService.teleportPlayerAsync` は非同期 chunk 準備後に遅延タスクで転送し、セッション世代や取消状態を再検証しない。再参加転送も `entryTransfers` に残った実転送自体は `session.ending` で取消されない。
- 問題: 旧セッションの帰還・再参加転送が未完了でも `requestStart` の busy 判定を通過して同じ party／player の新規挑戦を受理できるため、新セッションの入場転送後に旧転送が完了してプレイヤーを受付地点へ引き戻すなど、転送の完了順で所属と実位置が食い違う。
- 影響: 新規挑戦の参加者がインスタンス外へ排出される、party が分断される、破棄中 world への遅延転送が走るなど、挑戦継続不能や一時 world 回収との競合が発生する。
- 修正方針: セッションを ENDING として保持し、保留中の入場転送を失効または完了待ちし、全帰還転送と world 退避・破棄が完了するまで party／participant の busy 索引を維持する。転送 callback には session ID／世代 token の再検証を追加し、最終 cleanup でのみ索引を解放する回帰テストを追加する。
- 修正対象候補: `複数`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-002 [中] 離脱・logout 時にダンジョン専用死亡状態が回収されない
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/dungeon/service/DungeonService.java:1277`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/player/death/PlayerDeathService.java:188`
- 根拠: Dungeon death 開始時は player ID を `dungeonDeathParticipants` に登録するが、`finalizeParticipantRemoval` と `handleQuit` は participant 索引だけを外し、当該集合からの削除や `PlayerDeathService.recoverNow` を行わない。`PlayerDeathService` は logout 後も death state と Dungeon 内の固定地点を保持し、join 時にその地点へ再配置する。
- 問題: 他の参加者が残ってセッション全体が終了しない場合、離脱済み player の死亡状態だけが存続する。復帰時 callback は既に participant でないため正規の開始地点復帰を行えず、logout／join では非参加者を稼働中 Dungeon world へ戻し得る。
- 影響: logout で再参加権を失う契約に反して旧インスタンスへ戻る、非参加者が Dungeon 内に残る、死亡中の固定・非表示・無敵状態が離脱後も継続する可能性がある。
- 修正方針: 参加者を確定離脱させる経路と logout 経路で、そのセッションが開始した death state を識別して `dungeonDeathParticipants` から除去し、`recoverNow` で callback を実行せず即時回収する。離脱・logout 中の死亡復帰を対象に回帰テストを追加する。
- 修正対象候補: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/dungeon/service/DungeonService.java`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-007 [中] 開始カウントダウン中の死亡復帰コールバックが必ず自己拒否する
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/dungeon/service/DungeonService.java:1160`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/dungeon/service/DungeonService.java:1113`
- 根拠: `handleParticipantDeath` は参加者がインスタンス world で死亡すれば `combatStarted` を確認せず Dungeon death を開始し、既定5秒後の復帰 callback を登録する。一方 `reviveParticipant` が呼ぶ `canRunDungeonRecoveryCallback` は `combatStarted` が true の場合にしか復帰を許可しないため、10秒の開始カウントダウン前半で死亡すると callback 実行時にも条件が false のままになる。`PlayerDeathService` 側は custom callback 呼出し前に死亡状態を完了済みにするため、この拒否後に別の既定復帰処理も走らない。
- 問題: 正規参加者の死亡処理を受理して死亡回数まで加算する一方、復帰地点への転送だけを抑止するため、死亡地点または void 付近にプレイヤーを残す。カウントダウン後に `combatStarted` が true になっても、消費済み callback は再実行されない。
- 影響: 開始直後の落下・void・管理操作等による死亡で参加者が START に復帰できず、再死亡や party 分断を起こして挑戦続行不能になり得る。
- 修正方針: Dungeon death を受理する期間と復帰 callback の許可条件を一致させる。開始カウントダウン中も同一の稼働 session・現参加者であれば START 復帰を許可するか、combat 開始前の死亡を別の非加算復帰として扱い、カウントダウン前半・後半および離脱／終了後の stale callback を実経路で検証する回帰テストを追加する。
- 修正対象候補: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/dungeon/service/DungeonService.java`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`
