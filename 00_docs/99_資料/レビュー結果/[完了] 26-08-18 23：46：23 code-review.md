### AR-CODE-001 [中] 非同期GUI表示の固定回数retry
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/test/java/io/github/maaasu/astralRecord/feature/item/service/OrbServiceLifecycleTest.java:1102`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/item/service/OrbService.java:273`
- 根拠: 非同期preload完了後に同期callbackを予約する処理では、MockBukkitがworker開始前に非同期task完了と判定する競合が発生し得る。
- 問題: 非同期完了と同期callbackを3回の即時retryだけで待っているため、worker開始やcallback予約が3回の間に進まない環境では一覧GUIのassertionが再度失敗する。
- 影響: テストが環境依存で間欠的に失敗し、`NO_CANDIDATE` のライフサイクス検証へ到達できない。
- 修正方針: 固定回数retryを、yieldを含む明示的なbounded timeout内でGUI表示をpollする待機へ置き換える。
- 修正対象候補: `10_plugin/AstralRecord/src/test/java/io/github/maaasu/astralRecord/feature/item/service/OrbServiceLifecycleTest.java`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-002 [中] 非同期GUI待機の期限超過
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/test/java/io/github/maaasu/astralRecord/feature/item/service/OrbServiceLifecycleTest.java:1105`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/infrastructure/util/AsyncTaskUtil.java:45`
- 根拠: `waitAsyncTasksFinished()` は非同期taskが開始済みの場合に内部待機するため、呼び出し側の2秒deadlineを超えてブロックし得る。
- 問題: 2秒のbounded timeoutを定義していても、deadline確認前にscheduler待機が長時間継続し、実際のテスト待機時間がboundedになっていない。
- 影響: 非同期taskの停滞時にテストが想定以上に長くブロックし、CIのタイムアウトや原因不明のハングにつながる。
- 修正方針: `waitAsyncTasksFinished()` をdeadline内のtick実行と短いpark待機へ置き換え、待機ループ自体を期限内に限定する。
- 修正対象候補: `10_plugin/AstralRecord/src/test/java/io/github/maaasu/astralRecord/feature/item/service/OrbServiceLifecycleTest.java`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-003 [中] 非同期GUI待機のbusy loop
- 種別: `パフォーマンス`
- 対象: `10_plugin/AstralRecord/src/test/java/io/github/maaasu/astralRecord/feature/item/service/OrbServiceLifecycleTest.java:1107`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/infrastructure/util/AsyncTaskUtil.java:45`
- 根拠: `Thread.yield()` は実行権を譲る保証がなく、worker未開始時もループを高頻度で継続させる。
- 問題: GUI表示を待つ間にtick実行を連続して行い、CPU消費とMockBukkit schedulerの過剰なtick進行を招く。
- 影響: CI負荷が上がり、実行環境によって非同期taskの実行順序が変化してテストの決定性を損なう。
- 修正方針: `Thread.yield()` を短い `LockSupport.parkNanos` 待機へ置き換え、deadline内でworkerへ実行機会を与える。
- 修正対象候補: `10_plugin/AstralRecord/src/test/java/io/github/maaasu/astralRecord/feature/item/service/OrbServiceLifecycleTest.java`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

- 対象: `10_plugin/AstralRecord/src/test/java/io/github/maaasu/astralRecord/feature/item/service/OrbServiceLifecycleTest.java:1105-1109`

- 根拠: 待機中に割り込みが発生した場合の扱いと、deadline到達時にどの非同期段階で停止したかを検証する情報がない。
- 問題: 割り込み後も待機を継続し、最後のassertionもメッセージなしのため、失敗原因をworker未完了・callback未実行・scheduler停滞から切り分けにくい。

- 修正方針: 割り込みを原因付きで即時失敗させ、timeout assertionに待機対象と経過時間を示すメッセージを付ける。
- 修正対象候補: `10_plugin/AstralRecord/src/test/java/io/github/maaasu/astralRecord/feature/item/service/OrbServiceLifecycleTest.java`
