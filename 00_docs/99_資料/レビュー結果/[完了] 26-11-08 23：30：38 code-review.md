### AR-CODE-001 [中] 一覧で再取得した道標を古い編集データで開く
- 種別: `バグ/アルゴリズム`
- 対象: `60_tool/skilltree-editor/src/SkillTreeEditor.Client/src/components/WorldPlacementEditor.tsx:390`
- 関連箇所: `60_tool/skilltree-editor/docs/SPAWNER_PLANNING.md:100`
- 根拠: 一覧は Dev 配置を再取得する。初回レビュー時の編集遷移は同一ワールドで配置 ID が編集側の作業データに見つかると、その値を選択していた。編集側の読み直しは配置 ID が見つからない場合だけ行っていた。
- 問題: 一覧を再読込したあとも、別操作で変更された同じ道標を編集で開くと、古い名前・座標・解放費用などを表示する。
- 影響: 一覧と編集画面の値が食い違い、古いリビジョンを使うため、そのまま編集して保存すると競合が発生する。
- 修正方針: 一覧の取得リビジョンを編集遷移に渡す。編集側の基準リビジョンと異なる場合は Dev 配置を読み直し、取得できた同じ配置 ID を選択する。既存 ID の外部更新と一覧からの編集遷移をテストで確認する。
