### AR-CODE-001 [高] ゴミ箱GUIの戻る・確認画面クローズで保持アイテムが返却されない
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/menu/service/TrashService.java:167`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/menu/service/TrashService.java:237 / 10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/menu/service/TrashService.java:305 / 00_docs/10_Plugin設計書/feature/09-menu/3-メソッド仕様/09_3-サービス.md:26`
- 根拠: ゴミ箱へ移動した item は `trashItemsByPlayer` に保持される。確認画面の表示時に close 抑止フラグを設定し、ゴミ箱画面の戻る操作と確認画面の戻る操作は `switchGuiWithInventoryRestore` だけを呼び出している。共有 GUI 基盤は成功した別 GUI 遷移では元画面の close cleanup を発火しない。確認画面を直接 close した場合も、抑止分岐は dummy inventory の復元だけで保持 item を返却しない。
- 問題: 破棄を確定していない通常操作で、保持 item が通常インベントリへ戻らず、feature の保持マップに残る。
- 影響: ゴミ箱の確認画面を閉じる、または戻るボタンを押すだけで、ユーザーから見て item が消失した状態になる。
- 修正方針: 破棄確定以外の戻る・close 経路で、画面遷移前に保持 item を返却する共通処理を必ず実行する。GUI セッションの close 抑止は dummy 復元だけに限定し、feature 固有の保持状態を未処理のまま残さない。
- 修正対象候補: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/menu/service/TrashService.java`
- 修正可否: `自動修正可`

### AR-CODE-002 [高] ゴミ箱の返却失敗を無視して保持アイテムを破棄している
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/menu/service/TrashService.java:446`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/inventory/service/InventoryService.java:5009 / 00_docs/10_Plugin設計書/feature/09-menu/09_4-統合フロー.md:120`
- 根拠: `returnTrashItemsToInventory` は各 item の `returnItemToOwnedInventory` の戻り値を確認せず、非空 item があれば常に `true` を返す。`InventoryService.returnItemToOwnedInventory` は容量不足や参照解決失敗時に `null` を返し、state を返却前へ戻す。呼び出し側の `handleClose` は返却結果にかかわらず直後に `discard(player)` を実行する。
- 問題: 通常のインベントリ満杯などで返却できない item があっても、保持マップから削除される。
- 影響: HOTBAR item の返却先 BAG が満杯の場合などに、返却できなかった item がインベントリにも保持状態にも残らず消失する。設計上はプレイヤー位置へ drop して消失させない契約になっている。
- 修正方針: item ごとの返却結果を収集し、返却できない item は保持して GUI を再表示するか、設計書どおりプレイヤー位置へ drop する。全 item の所在が確定するまで `discard` しない。
- 修正対象候補: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/menu/service/TrashService.java`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `未修正`

### AR-CODE-003 [高] 売却確認画面の戻る操作が保持アイテムの返却を経由しない
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/sell/service/SellService.java:308`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/sell/service/SellService.java:463 / 00_docs/10_Plugin設計書/feature/09-menu/3-メソッド仕様/09_3-サービス.md:37`
- 根拠: 売却編集画面・確認画面の直接 close は `closeSellAndReturnItems` を通るようになっているが、確認画面の戻るボタンは `switchGuiWithInventoryRestore` だけを呼び出している。成功した GUI 遷移では元画面の close cleanup が発火しないため、`sellItemsByPlayer` の保持 item が返却されない。
- 問題: 売却を確定せず確認画面の戻るボタンを押すと、保持 item が通常インベントリへ戻らない。
- 影響: 手動 close の修正後も、確認画面の戻る操作だけで item が見えない保持状態になり、ユーザーからは消失に見える。
- 修正方針: 確認画面の戻る操作でも `closeSellAndReturnItems` 相当の返却処理を画面遷移前に実行し、返却失敗分は既存の売却 GUI 再表示処理で保持する。
- 修正対象候補: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/sell/service/SellService.java`

### AR-CODE-004 [高] bundle 報酬の収容不足分が通常操作で破棄される
- 種別: `仕様不整合`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/item/service/BundleUseService.java:238`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/item/service/BundleUseService.java:265 / 00_docs/10_Plugin設計書/feature/04-item/04_9-未決事項.md:5`
- 根拠: bundle 本体を先に 1 個消費した後、各報酬を `addItemToNormalInventory` へ要求し、戻り値の付与数だけを表示している。要求数と付与数の差分を保持・drop・補償する処理がない。設計書にも、容量不足分は現状破棄される未決事項として記載されている。
- 問題: インベントリ容量が足りないという通常状態で、bundle 報酬の一部または全部が付与されず、そのまま失われる。
- 影響: bundle 本体を消費したにもかかわらず、ユーザーが受け取れる報酬量が減少する。equipment / rune 報酬では instance の扱いも必要になる。
- 修正方針: 開封前の全量収容チェック、受取箱、instance を含む ground item、または安全な消費 rollback のいずれかを仕様決定し、要求数と付与数の差分を必ず補償する。
- 修正対象候補: `複数`
- 修正可否: `設計判断待ち`
- 確信度: `高`
- 修正状態: `未修正`
