## 指摘一覧

### AR-CODE-001 [中] 統合版HUDの送信失敗で消去の再試行状態を失う
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecordProxy/src/main/java/io/github/maaasu/astralrecordproxy/AstralRecordProxyPlugin.java:1134`
- 関連箇所: `10_plugin/AstralRecordProxy/src/main/java/io/github/maaasu/astralrecordproxy/AstralRecordProxyPlugin.java:1143; 10_plugin/AstralRecordProxy/src/main/java/io/github/maaasu/astralrecordproxy/AstralRecordProxyPlugin.java:1162; 10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/hud/service/PlayerHudService.java:102; 10_plugin/AstralRecordGeyserExtension/src/main/java/io/github/maaasu/astralrecordgeyser/AstralRecordGeyserExtension.java:246`
- 根拠: 依頼は追跡欄の解除漏れ防止とバックエンド切替時の消去を要求する。GeyserPackCapabilities.sendQuestHudは送信口不在や反射呼出失敗でfalseを返し、Extensionの送信も設定確認失敗や反射例外でfalseを返す。JSON UIは専用TIPを保持するため、消去値の正常送信まで旧表示が残る。
- 問題: forwardQuestHudはsendQuestHudがfalseの場合にもcomputeからnullを返し、以前の表示成功を記録したtimestampを削除する。clearQuestHudとexpireQuestHudも送信結果を無視してtimestampを削除する。RPG側はProxyへのhide要求送信開始でhide値を送信済みとし、表示中のheartbeatと異なり同じhide値を継続再送しない。
- 影響: クエスト欄を表示した後、追跡解除・ボス/ダンジョン移行・バックエンド切替・タイムアウトの消去TIPが一時的に失敗すると、Proxyの期限監視対象から外れる。送信経路が復旧しても専用ラッチへ消去値が届かず、古いクエスト欄が残り続ける。表示後にforce-resource-packs設定をfalseへ変更した場合は、Extensionが既知のラッチへのhideまで拒否する。
- 修正方針: 送信失敗時は以前の表示成功または消去待ちの状態を保持する。明示消去と期限消去も成功するまで再試行対象へ残し、正常な新表示更新とのUUID単位の直列化を維持する。表示成功済みの同一GeyserConnectionへの消去は設定変更後も許可し、新規未確認接続へ専用値を送らない境界を維持する。

- 修正状態: `修正済み`
