### AR-CODE-001 [中] 実際の装備経路と状態遷移を検証するテストが不足している
- 種別: `テスト不足`
- 対象: `10_plugin/AstralRecord/src/test/java/io/github/maaasu/astralRecord/feature/item/service/ItemStackFactorySetEffectLoreTest.java:73`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/status/service/StatusService.java:177`
- 根拠: 追加テストは `ItemStackFactory.create(..., equippedSetCounts)` の Lore 文字列と、`HotbarRenderer` が保持中 slot だけ `resolveForEquippedDisplay` を呼ぶことを確認している。一方、設計書は実際の有効装備を active loadout の防具・オフハンド・アクセサリと現在選択中 HOTBAR 主手から集計し、`StatusService.refreshStatus` 後に装備表示を再描画する契約を定めている。
- 問題: active loadout の防具・アクセサリ・オフハンド、現在保持中主手の実データを使った `InventoryService.getEquippedItemReferences` → `collectEquippedSetCounts` → 表示更新の結合経路がテストされていない。また、耐久値が0になったときの有効セット数減少と灰色化、持ち替え時に旧主手が静的表示へ戻ること、BAG・非選択 HOTBAR・マスター表示が静的なままであることも実スタックで検証されていない。現在のテストが通っても、resolver の呼出し先や status 更新の接続を壊す回帰を検出できない。
- 影響: 要求の中心である「装備中だけ動的表示」が実際のゲーム経路で適用されない、または耐久・持ち替え後に表示が古いままになる不具合を、CI で検出できない。
- 修正方針: 既存の MockBukkit / DesignTestFixtures を使い、active loadout に防具・オフハンド・アクセサリ、HOTBAR に主手候補と非選択候補、BAG に同一セット装備を構成する。`StatusService.refreshStatus` を通した実 ItemStack の Lore を確認し、セット数の増減・耐久値0遷移・主手持ち替え・静的表示経路を分けて検証する。少なくともオフハンドと耐久値0遷移を個別の回帰シナリオとして追加する。
