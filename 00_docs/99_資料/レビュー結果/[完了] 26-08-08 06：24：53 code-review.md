## 指摘一覧

### AR-CODE-001 [高] メディテーション解除状態の UUID キーがイベント経路と一致しない
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/skill/service/MeditationSkillRuntimeService.java:47`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/skill/event/MeditationSkillEventHandler.java:41、10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/AstralRecord.java:1068`
- 根拠: `PassiveSkillService` の内部状態は account UUID で管理される一方、Bukkit の Player イベントは Minecraft の Player UUID を提供する。`AstPlayer` は account UUID と Bukkit Player UUID を別々に保持できる既存モデルである。
- 問題: runtime の登録・照会・SkillService/DamageService listener は account UUID を使うが、スニーク解除・被弾・通常攻撃イベントは Player UUID を渡しているため、両UUIDが異なるプレイヤーでは状態が解除されない。
- 影響: スニーク解除後も3倍回復が残る、被弾・通常攻撃・他スキル使用後も準備カウントが残るなど、固定条件に反する。
- 修正方針: 短命な表示・入力状態のキーを Bukkit Player UUID に統一し、runtime tick、executor、SkillService/DamageService listener、イベント解除で同じキーを使う。account UUIDを正本とするPassiveSkillServiceの管理キーは変更しない。
- 修正対象候補: `複数`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`
