### AR-CODE-001 [高] インベントリ内のスロット交換が一意制約へ衝突する
- 種別: `バグ/アルゴリズム`
- 対象: `20_api/AstralRecordApi/AstralRecordApi/Repositories/InventoryRepository.cs:205`
- 関連箇所: `00_docs/40_Database設計書/table-definitions/AstralRecord/init.sql:790`
- 根拠: 一括保存が既存行を有効なまま最終スロットへ直接更新し、最後に一度だけ保存するため、2行のスロット交換では部分一意インデックスへ途中状態が衝突する。
- 問題: stable UUIDを保った通常の並べ替えが保存できない。
- 影響: インベントリ保存が500エラーとなり、クライアントの並べ替え操作が失敗する。
- 修正方針: 直列化トランザクション内で対象行を一度論理削除して保存し、その後に最終値で再有効化する。スロット交換テストを追加する。
- 修正対象候補: `20_api/AstralRecordApi/AstralRecordApi/Repositories/InventoryRepository.cs`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`
