## 指摘一覧

### AR-CODE-001 [高] TEXT系からNVARCHAR(100)への直接ALTERはSQL Serverで失敗する
- 種別: `バグ/アルゴリズム`
- 対象: `00_docs/40_Database設計書/table-definitions/AstralRecord/migrations/20260906_player_state_snapshot.sql:39-41`
- 関連箇所: `00_docs/40_Database設計書/table-definitions/AstralRecord/migrations/20260906_player_state_snapshot.sql:18-28`
- 根拠: `sys.types` で `text`、`ntext`、`image` を検出した後、同じ分岐で `ALTER COLUMN [item_id] NVARCHAR(100) NULL` を実行している。SQL ServerのALTER TABLE仕様では、textはvarchar(max)/nvarchar(max)/xml、ntextはvarchar(max)/nvarchar(max)/xml、imageはvarbinary(max)への型変更だけが許可され、これらからNVARCHAR(100)への直接変更は許可されない。
- 問題: `item_id` がTEXT系の既存DBでは、長さ検証を通過する値しかなくてもALTER COLUMNでmigrationが失敗し、後続の索引再作成とmigration履歴記録まで到達しない。`DATALENGTH(CONVERT(NVARCHAR(MAX), ...))` による事前検証は、ALTER COLUMNの許可される変換先制限を解決しない。
- 影響: TEXT/NTEXT（および検出対象に含めたIMAGE）のlegacy DBを、このmigrationでNVARCHAR(100)へ正規化できない。XACT_ABORTとトランザクションにより変更はロールバックされるが、対象DBのmigration適用は終了コード1で停止する。
- 修正方針: TEXT/NTEXT/IMAGEを検出した場合は、SQL Serverで許可される中間型への変換または新列への明示的なデータ移送を行い、200バイト超を事前に拒否した上でNVARCHAR(100)へ正規化する。IMAGEをitem_idの対象に含める必要性と変換規則も明確化する。
- 修正対象候補: `00_docs/40_Database設計書/table-definitions/AstralRecord/migrations/20260906_player_state_snapshot.sql`
- 修正可否: `設計判断待ち`
