## 指摘一覧

### AR-CODE-001 [高] インスタンス対応の通常ワールドにある受付が拒否される
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/world/service/InstanceTeleportService.java:220`
- 関連箇所: `40_filebase/60.features.world/v1.wild_overworld.yml:11`
- 根拠: 第1回レビュー時の entryWorld は BOSS_FIELD/DUNGEON を除外する条件に加えて !data.instanceEnabled() を要求している。現行の midgard_greenfields は worldType: OVERWORLD かつ instanceEnabled: true である。17-world/17_1-モデル定義は instanceEnabled を instance 対応フラグと定義し、内部戦場の区分とはしていない。陽冠のサンバード、ミドルアースの遺跡、万象聖域の遺跡、アルダ始まりの遺跡はこのワールド上に受付を定義している。
- 問題: 通常ワールドの instance 対応フラグを内部戦場の判定へ使用しているため、有効な受付ワールドを null として返す。
- 影響: 上記4件の候補は利用不可として表示され、クリックしても P_5791 となり受付へ移動できない。
- 修正方針: BOSS_FIELD/DUNGEON の種別除外を維持し、通常ワールドに対する instanceEnabled の拒否条件を除去する。受付座標と world ID の検証は維持する。
- 修正対象候補: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/world/service/InstanceTeleportService.java`
- 修正可否: `自動修正可`
