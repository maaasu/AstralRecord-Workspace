### AR-CODE-001 [高] 未指定slotが通常アイテム消費順の先頭になる
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/inventory/service/InventoryService.java:90`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/inventory/service/InventoryService.java:6394`
- 根拠: `00_docs/10_Plugin設計書/feature/08-inventory/3-メソッド仕様/08_3-サービス.md:44-46` は BAG 優先、各 inventory 内は slotIndex 降順、未指定 slot は指定済み slot の後、同順位は inventoryEntryId 昇順と定義している。実装は null slot を `Integer.MIN_VALUE` に変換した後で comparator 全体を `reversed()` しているため、null は指定済み slot より大きい値として先頭に並ぶ。
- 問題: `orderNormalItemConsumptionEntries` は `consumeItemAmountFromInventory` と `findOwnedNormalItemEntryForConsumption` の共通経路で使われる。たとえば BAG に同じ itemId の slotIndex `null` と `5` の entry がある場合、itemId 消費およびオーブ一覧クリック時の暗黙 resolver は slotIndex `null` の entry を先に選ぶ。
- 影響: 未指定 slot の stack が前方 stack より先に減算・予約され、通常アイテム消費、オーブ素材支払い予約、インベントリ内オーブの起点選択が仕様と異なる。今回追加されたテストは指定済み slot の配列順を検証するが、null slot を含まないためこの誤りを検出できない。
- 修正方針: null slot が指定済み slot より後になる comparator に修正し、slotIndex の同順位について inventoryEntryId 昇順を維持する。null slot と指定済み slot、同一 slot の entry ID 順を入力配列順を変えて検証するテストを追加する。
- 修正対象候補: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/inventory/service/InventoryService.java`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-002 [高] 明示されたオーブentryを別entryへ再配分する
- 種別: `仕様不整合`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/item/service/OrbService.java:952`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/item/service/OrbService.java:267 | 00_docs/10_Plugin設計書/feature/08-inventory/08_2-ユースケース.md:150,160 | 00_docs/10_Plugin設計書/feature/08-inventory/3-メソッド仕様/08_3-サービス.md:46`
- 根拠: 通常インベントリのクリックは `handleInventoryOrbClick` からクリックした `inventoryEntryId` を session に保存する明示 entry 起点であり、設計書は移動・消費済みの起点オーブを別 entry に振り替えず、明示された entry を直接操作すると定義している。一方 `resolveCurrentOrb` は `findOwnedEntry` で起点が無効になった後、session の起点種別を確認せず `findOwnedNormalItemEntryForConsumption` を呼び、結果の ID を `session.orbEntryId` へ上書きする。
- 問題: 通常インベントリで entry A をクリックした後、非同期 preload 中または操作中に A が消費・移動され、同じ itemId の entry B が残っていると、resolveCurrentOrb は B を採用する。その後 `reserveOrbOperationPayment` へ渡す起点 ID（`OrbService.java:1833`）と API 操作へ渡す起点 ID（`OrbService.java:1903`）が B になり、明示操作が別 stack の消費へ変わる。インベントリ内オーブ一覧起点は itemId による暗黙選択なのでフォールバック対象だが、通常インベントリ起点まで同じ処理にしている。
- 影響: プレイヤーがクリックした stack と異なる entry がオーブ消費・支払い対象になり、起点 entry が stale になった場合に「操作せず再描画する」という実行不能時の契約に反する。既存テストは一覧起点の後方 entry 選択を検証しているが、通常インベントリ起点で A が消え B が残るケースを検証していない。
- 修正方針: `returnToInventoryOrbListOnFailure` などの起点種別で分岐し、itemId による再解決はインベントリ内オーブ一覧起点に限定する。通常インベントリ起点で明示 entry が無効になった場合は session を継続せず、既存の失敗再描画・終了経路へ進めるテストを追加する。
- 修正対象候補: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/item/service/OrbService.java`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`
