### AR-CODE-001 [中] 再検証した SHA と最終統合 SHA の一致が保証されない
- 種別: `バグ/アルゴリズム`
- 対象: `.codex/skills/astralrecord-code-version-commit-develop/references/cloud-workflow.md:30`
- 関連箇所: `.codex/skills/astralrecord-code-version-commit-develop/references/quality-gate.md:29`
- 根拠: Cloud への重い再検証委譲の後に Filebase 再検証とプラグイン版番号コミットを行い、最終的な統合 HEAD を作る手順になっている。品質ゲートは検査後に差分が変わった場合の対象確認を要求する。
- 問題: Cloud が再検証した統合 SHA と、ローカル `develop` に取り込む最終 SHA またはツリーが一致することを確認する条件がない。
- 影響: 再検証後の版番号更新や追加コミットを含む最終成果を、検証済みとして誤って統合できる。
- 修正方針: 再検証対象の SHA と最終統合対象を照合し、後続変更があれば影響する検査を最終ツリーで再実行する手順を明記する。
- 修正対象候補: `.codex/skills/astralrecord-code-version-commit-develop/references/cloud-workflow.md`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-002 [中] 実クライアント確認まで一律に任意化している

- 対象: `.codex/skills/astralrecord-code-version-commit-develop/references/quality-gate.md:27`
- 関連箇所: `PLUGIN_GUIDE.md:124`
- 根拠: プラグインガイドは見た目・操作感・演出を実サーバーまたは実クライアントで確認すると定める。Cloud 品質ゲートの追記は Minecraft クライアント確認を依頼で指定された場合だけに限定している。

- 修正方針: Paper/Purpur 実行の通常省略は維持し、プロジェクトやモデル制作スキルが要求する実クライアント確認は可能なら実施し、実施不能な状態は未確認として報告する。

### AR-CODE-003 [中] リモートの既存作業ブランチを誤って更新できる
- 種別: `バグ/アルゴリズム`
- 対象: `.codex/skills/astralrecord-code-version-commit-develop/references/cloud-workflow.md:22`
- 関連箇所: `.codex/skills/astralrecord-code-version-commit-develop/references/cloud-workflow.md:24`
- 根拠: Cloud 側は同名のローカルブランチだけを確認し、通常の `git push HEAD:refs/heads/<task-branch>` で成果を送る。
- 問題: リモートに同名ブランチが存在し、その先端が Cloud の成果 HEAD の祖先なら、通常 push は拒否されずに他作業のブランチを早送りできる。
- 影響: 別タスクのリモートブランチに今回のコミットが混入し、成果の所有範囲と引き継ぎ SHA が曖昧になる。
- 修正方針: 作業開始時と push 直前にリモートの同名ブランチ不存在を確認し、作成時の競合も拒否する条件で新規参照を作る。
- 修正対象候補: `.codex/skills/astralrecord-code-version-commit-develop/references/cloud-workflow.md`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-004 [低] リモートのみ先行時の開始 SHA が曖昧になる
- 種別: `可読性/保守性`
- 対象: `.codex/skills/astralrecord-code-version-commit-develop/references/cloud-workflow.md:9`
- 関連箇所: `.codex/skills/astralrecord-code-version-commit-develop/references/cloud-workflow.md:16`
- 根拠: リモートのみ先行する場合はリモート先端を使用しつつ、手元の開始ブランチはそのまま残す。引き継ぎ文には「同期済み開始ブランチと SHA」を記す。
- 問題: 手元の開始 HEAD と Cloud に渡す実効的なリモート先端が異なる場合、どちらを開始 SHA とするか明確でない。
- 影響: 依存コミットの確認や成果の説明で異なるベースを参照するおそれがある。
- 修正方針: ローカル開始 HEAD と Cloud に渡すリモート先端 SHA を別々に記録し、依存確認で使用する SHA を指定する。
- 修正対象候補: `.codex/skills/astralrecord-code-version-commit-develop/references/cloud-workflow.md`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`
