## 指摘一覧

### AR-CODE-001 [低] STORAGE の BAG→HOTBAR 横断消費を回帰テストしていない
- 種別: `テスト不足`
- 対象: `10_plugin/AstralRecord/src/test/java/io/github/maaasu/astralRecord/feature/inventory/service/ItemInventoryStatusDesignTest.java:846`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/inventory/service/InventoryService.java:6867`
- 根拠: 設計書 `08_2-ユースケース.md` の「6. ストレージ収納・取り出し」および `08_3-サービス.md` の「14. ストレージ操作」は、通常アイテムを BAG、HOTBAR の順で各 `slotIndex` 降順に消費すると規定する。追加テストは BAG の2 entryだけを作成しており、HOTBAR entry を作成・検証していない。
- 問題: `collectOwnedItemBatch` の inventory 横断順、BAG 不足時の HOTBAR への継続、HOTBAR の固定 slot を前詰めしないことが、この STORAGE 操作経路では保護されない。
- 影響: 将来この経路の inventory 順序または削除処理が変わっても、BAG を残して HOTBAR を先に減らす、または HOTBAR slot を詰める退行を検出できない。
- 修正方針: BAG の同一 item を要求数未満にし、HOTBAR に同一 item を置いた収納テストを追加する。BAG の後方から先に全量を減らした後に HOTBAR の後方 slot を減らすこと、HOTBAR の残存 entry の `slotIndex` が変わらないことを検証する。
- 修正対象候補: `10_plugin/AstralRecord/src/test/java/io/github/maaasu/astralRecord/feature/inventory/service/ItemInventoryStatusDesignTest.java`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`
