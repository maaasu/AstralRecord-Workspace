## 指摘一覧

### AR-CODE-001 [中] 疑似サーバー残存検知が現行 MockBukkit 名に限定されている
- 種別: `テスト不足`
- 対象: `.codex/skills/astralrecord-plugin-test/scripts/validate_test_traceability.py:258`
- 関連箇所: `.codex/skills/astralrecord-plugin-test/scripts/validate_test_traceability.py:1276`
- 根拠: テスト運用ルールは MockBukkit に限らず疑似サーバーを恒久テストへ残さないと定めているが、source 検査は `org.mockbukkit` と `MockBukkit`、POM 検査は `mockbukkit` 文字列だけを照合している。
- 問題: 旧 MockBukkit パッケージを個別 mock 型だけで利用する source や、別名の疑似サーバー依存を追加しても validator が成功する。
- 影響: 一時診断専用の疑似サーバー source・依存が将来のコミットに残り、今回追加するルールを自動ゲートで保証できない。
- 修正方針: 既知の疑似サーバー package、型名、依存名の marker を明示的な一覧として定義し、source と POM の両方で照合する。旧 package と別名依存の validator 単体テストを追加する。
- 修正対象候補: `複数`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-002 [中] 裸の Mock 型名検知が自作テストダブルを誤検知する
- 種別: `バグ/アルゴリズム`
- 対象: `.codex/skills/astralrecord-plugin-test/scripts/validate_test_traceability.py:261`
- 関連箇所: `.codex/skills/astralrecord-plugin-test/scripts/tests/test_validate_test_traceability.py:244`
- 根拠: `ServerMock`、`WorldMock`、`PlayerMock`、`PluginMock` は package 条件なしで拒否されるが、同名の自作テストダブルは疑似サーバーとは限らない。現行・旧 MockBukkit package は別の pattern ですでに検出できる。
- 問題: MockBukkit を使用しない純粋な自作テストダブルまで `MOCK_SERVER_SOURCE_REMAINS` になる。
- 影響: 許可される通常 JUnit テストが validator の誤検知でコミット不能になる。
- 修正方針: 裸の個別 mock 型名を pattern から外し、現行・旧 MockBukkit package と `MockBukkit` / `MockBukkitTestBase` の明示識別子だけを拒否する。自作 `PlayerMock` を許可する単体テストを追加する。
- 修正対象候補: `複数`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`
