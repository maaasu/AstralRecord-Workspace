### AR-CODE-001 [中] 静止中にも毎 tick 全表示範囲を ray trace している
- 種別: `パフォーマンス`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/skill/service/SkillActionRingService.java:1174`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/skill/service/SkillActionRingService.java:1275, 10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/skill/service/SkillActionRingService.java:1333, 10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/skill/service/SkillActionRingService.java:428`
- 根拠: `UPDATE_INTERVAL_TICKS` は 1 であり、`tick` は各 session ごとに毎 tick `updateLayout` を呼ぶ。8枠では `resolveLayoutScale` が中心と円周で13回、各アイコンとラベルの箱で144回、timer と instruction の箱で18回、計175回 `World#rayTraceBlocks` を実行する。視点位置・視線・周囲ブロックが変わらない場合も同じ計算を繰り返す。Paper API の `World#rayTraceBlocks` は chunk を読み込む可能性があると明記している。
- 問題: リング表示は最大100 tickで、1 sessionだけでも静止中に約17,500回の block ray trace がメインスレッドで発生する。複数プレイヤーが同時に開くと session 数に比例して増え、表示を開くだけで server tick の負荷が増加する。
- 影響: 人数や周辺チャンク状態によって tick 遅延を起こし得る。短時間表示であっても、アクションリングを同時利用する場面でメインスレッドの余力を不必要に消費する。
- 修正方針: 前回の視点位置・視線・リング姿勢を保持し、位置または姿勢が変わった tick は直ちに再計算する。静止中は数 tick ごとの再確認へ間引き、ブロック設置・破壊などの動的な遮蔽物も遅延を限定して反映する。再計算しない tick は前回の `layoutScale` を使用する。
