### AR-CODE-001 [中] 売却 GUI の通常クローズ時に返却失敗を無視して保持状態を破棄している
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/sell/service/SellService.java:192`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/sell/service/SellService.java:193` / `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/sell/service/SellService.java:496` / `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/inventory/service/InventoryService.java:2431`
- 根拠: `00_docs/10_プラグイン設計書/feature/09-menu/3-メソッド仕様/09_3.01-イベント.md:299` は、売却 GUI の戻るまたは通常クローズ時に売却枠内アイテムを返却すると定義している。
- 問題: `handleClose` は `returnSellItemsToInventory(player, allItems)` の戻り値にかかわらず直後に `discard(player)` を実行する。さらに `returnSellItemsToInventory` は各 `InventoryService.returnItemToOwnedInventory(...)` の戻り値を確認せず、返却不能なアイテムがあっても true を返し得る。
- 影響: 返却先 inventory が満杯、対象 item reference / model 解決失敗、または `InventoryService` 側で null が返るケースで、売却されていないアイテムを保持状態ごと破棄し、GUI close により実体も失う可能性がある。クリック返却側は `returnItemToOwnedInventory(...) == null` を検出して GUI から除去しないため、close 経路だけ安全性が落ちている。
- 修正方針: `returnSellItemsToInventory` で返却結果を item ごとに確認し、失敗した item を保持して次 tick で売却 GUI を再表示する、または返却前に容量を検証して失敗時は `discard` しない。少なくとも失敗を通知し、未返却分を保持する。
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-002 [低] 売却確定のゴールド加算が設計書指定の InventoryService.addGold を経由していない
- 種別: `仕様不整合`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/sell/service/SellService.java:316`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/sell/service/SellService.java:705` / `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/inventory/service/InventoryService.java:983`
- 根拠: `00_docs/10_プラグイン設計書/feature/09-menu/3-メソッド仕様/09_3.01-イベント.md:310` は、売却額の合計を `InventoryService.addGold` で通貨インベントリへ加算すると定義している。
- 問題: 実装は `creditGold(...)` という sell 独自ロジックで `ItemService.DEFAULT_CURRENCY_ITEM_ID` を読み、`ItemStackFactory#create` と `returnItemToOwnedInventory` を直接組み合わせている。通貨加算の正規 API である `InventoryService.addGold` と別経路になっている。
- 影響: 現時点では似た処理に見えるが、通貨表示用 resolver、maxStack 分割、通貨 inventory の正規化、将来の金額加算ルール変更が `InventoryService.addGold` 側に入った場合、売却だけ挙動が乖離する。設計書と違う API 境界のため、テストや監査でも見落とされやすい。
- 修正方針: `handleSellConfirmClick` から `inventoryService.addGold(astPlayer, totalSaleValue)` を呼ぶようにし、不要になる `creditGold` を削除する。必要であれば `InventoryService.addGold` の失敗時挙動を既存利用箇所と合わせて検証する。
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`
