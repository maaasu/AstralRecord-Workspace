### AR-CODE-001 [低] ログイン Attribute の失敗・再ログイン復元経路を恒久テストしていない
- 種別: `テスト不足`
- 対象: `10_plugin/AstralRecord/src/test/java/io/github/maaasu/astralRecord/feature/player/event/PlayerJoinEventHandlerTest.java:334`
- 関連箇所: `00_docs/10_Plugin設計書/feature/03-player/3-メソッド仕様/03_3-イベント.md:23`
- 根拠: 設計書は、参加反映成功時に `StatusService.refreshStatus` が設定した `Attribute.MOVEMENT_SPEED` を保持し、失敗時に `MOVEMENT_SPEED` と `JUMP_STRENGTH` をログイン前へ戻す契約を定めている。実装変更は `finishJoinLoading(attempt, notifyComplete)` の `!notifyComplete` 分岐と、再ログイン開始時の旧 `LoadingControl` 復元にも関係する。
- 問題: 追加テスト `successfulJoinKeepsStatusManagedMovementSpeedAfterLoadingLockIsRemoved` は成功経路だけを検証し、失敗経路で Attribute を stub/assert していない。既存の main-thread handoff 失敗・公開後例外テストと旧/新 join テストも Attribute を観測しないため、`restoreLoadingControl(..., !notifyComplete)` が失敗時に元の移動速度・ジャンプ力を復元しない退行、または旧世代の復元が新しいログインの値へ作用する退行が全テスト成功のまま残る。
- 影響: データ取得・メインスレッド反映・後続 feature の失敗後に移動速度が `0` または旧世代の値で残り、再ログイン時の一時ロック解除後もプレイヤーの移動速度/ジャンプ力が不正になる回帰を検知できない。
- 修正方針: 失敗 fixture に `MOVEMENT_SPEED` / `JUMP_STRENGTH` の AttributeInstance と元値を設定し、ロック時の `0` 設定および失敗終了後の両属性復元を検証する。さらに旧 Player の退出後に新 Player で再ログインするケースで、旧 attempt の後処理が新世代の Attribute を変更しないことを検証する。
- 修正対象候補: `10_plugin/AstralRecord/src/test/java/io/github/maaasu/astralRecord/feature/player/event/PlayerJoinEventHandlerTest.java`
