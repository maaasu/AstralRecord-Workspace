### AR-CODE-001 [高] 歩ける半ブロック床が安全な足場から除外される
- 種別: `バグ/アルゴリズム`
- 対象: `60_tool/spawner-planner/scanner/src/main/java/com/astralrecord/tools/terrain/RegionTerrainScannerPlugin.java:230`
- 関連箇所: `60_tool/spawner-planner/planner.py:152`
- 根拠: `scanCell` は最初の固体床で探索を止め、`type.isOccluding()` が真の列だけを `safe` に加える。実ワールドの開始地点周辺にも `dirt_path`、階段、スラブがあり、これらの非完全立方体は遮光床判定から外れる。
- 問題: 実際に歩ける橋や道の列が `safeCount` に入らず、床のある区画が危険または接続不能と判定される。
- 影響: 開始地点からの連結解析とスポナー候補選定が地形を過小評価する。実スキャンの初期計算では 36,864 区画中 14,492 区画が `disconnected` となっており、通路の誤除外はこの値と被覆結果に影響し得る。
- 修正方針: 床の遮光性ではなく上面で安全に立てる衝突形状を判定し、危険床と足・頭の空間検査は維持する。道・階段・スラブを含む橋の区画を確認する。
- 修正対象候補: `60_tool/spawner-planner/scanner/src/main/java/com/astralrecord/tools/terrain/RegionTerrainScannerPlugin.java`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-002 [中] 接続判定に配置用の足場数閾値を流用している
- 種別: `バグ/アルゴリズム`
- 対象: `60_tool/spawner-planner/planner.py:152`
- 関連箇所: `60_tool/spawner-planner/planner.py:172`
- 根拠: `walkable` に入る条件は `safeCount >= minSafeColumns` で、現行ポリシーの `minSafeColumns` は8。開始地点からの BFS もこの `walkable` だけを通る。
- 問題: 4m区画中に歩ける列が1〜7列ある細い通路や橋を、通過不能として扱う。配置中心として必要な広い足場と、接続を確認するための通路が同一条件になる。
- 影響: 通路の先に安全な広場があっても `disconnected` に変わり、提案対象から外れる。
- 修正方針: 接続用の通過条件と配置用の足場数条件を分け、接続は少数の安全列を持つ区画も通れるようにする。配置候補の8列条件は維持する。
- 修正対象候補: `60_tool/spawner-planner/planner.py`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-003 [高] 既存の解析先を許容して他プラグインを起動し得る
- 種別: `セキュリティ`
- 対象: `60_tool/spawner-planner/prepare-server.ps1:16`
- 関連箇所: `60_tool/spawner-planner/prepare-server.ps1:26`
- 根拠: 拒否する既存パスは `$target/$WorldName` だけであり、既存の `$target/plugins`、`server.jar`、`server.properties` などは検査しない。その後 `server.jar` と設定ファイルを上書きし、既存 `plugins` ディレクトリを残して起動手順へ進む。
- 問題: 既存サーバーを解析先に指定すると、その設定・JARを破壊し、残留する AstralRecord 等のプラグインをコピーしたワールドで実行できる。独立した解析専用サーバーという前提を保証していない。
- 影響: 想定外のサーバー変更と、解析コピーへの実スポナー配置や外部接続が起こり得る。
- 修正方針: 解析先を新規または明示的に許可した無害な補助ファイルのみのディレクトリに限定し、祖先のリンクも検査してから最初の書き込みを行う。
- 修正対象候補: `60_tool/spawner-planner/prepare-server.ps1`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-004 [中] 森林バイオームの人工床を森林候補として扱う
- 種別: `仕様不整合`
- 対象: `60_tool/spawner-planner/planner.py:56`
- 関連箇所: `60_tool/spawner-planner/README.md`
- 根拠: `habitat()` は床材の種類を確認する前に、バイオーム名が `forest` 等を含むだけで `forest` を返す。scanner は木以外で最初に見つけた固体を `ground` とするため、森林内の石レンガ屋根なども十分な `safeCount` と接続があれば配置候補になる。
- 問題: README とポリシーが示す人工建築の安全地帯を自動認定しない条件が実装されていない。
- 影響: 建築物の床や屋根上に森林用スポナーを提案し得る。接続判定を改善すると対象が増える。
- 修正方針: 森林判定より先に人工床材を除外または `other` に分類し、意図した自然床だけを配置対象にする。
- 修正対象候補: `60_tool/spawner-planner/planner.py`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-006 [高] 地表上面だけの起点選択で実開始地点からの接続が消える
- 種別: `バグ/アルゴリズム`
- 対象: `60_tool/spawner-planner/planner.py:181`
- 関連箇所: `60_tool/spawner-planner/scanner/src/main/java/com/astralrecord/tools/terrain/RegionTerrainScannerPlugin.java:230`
- 根拠: 第2回の実ワールド再解析は36,864区画すべて `ok` だったが、上面の `safeColumnY` だけから開始地点3m・高さ差2以内の最近傍1列を選ぶ計算では到達3列、対象0区画、提案0件になった。worldマスタの開始Yは107で、同柱の最上面は石英スラブ上Y112。近傍の地表Y107の4列は小さく孤立し、候補を含む大連結成分の最近接は水平5m・Y106だった。
- 問題: 屋根下などにある実開始地点の歩行床を測らず、地表上面だけで最近傍起点を決めるため、地形内の有効な歩行接続を誤って失う。
- 影響: 正常に解析できた実ワールドでも全候補が `disconnected` となり、配置プレビューが0件になる。
- 修正方針: 上面から一定深さ内の追加の歩行床を別測定し、実開始座標と同柱・近い高度の測定床を起点にする。追加床と地表候補を3次元で隣接探索し、出現適性の判定は地表候補に限定する。
- 修正対象候補: `複数`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`
