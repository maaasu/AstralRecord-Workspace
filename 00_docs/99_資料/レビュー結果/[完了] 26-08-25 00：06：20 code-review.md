### AR-CODE-001 [高] ルーン個体・乱数の生成経路が残存している
- 種別: `仕様不整合`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/mob/service/MobDropPresentationService.java:527`
- 関連箇所: `20_api/AstralRecordApi/AstralRecordApi/Services/RuneService.cs:10`
- 根拠: 通常インベントリへの付与だけをスタック化している一方、モブドロップ、クエスト、メール、Rune API が `RuneInstance` とランダム stat roll を生成している。
- 問題: 入手経路により itemId スタックと個体ルーンが混在する。
- 影響: 要求された固定値・スタック可能なルーン管理を満たさず、装着・取引・表示が経路依存になる。
- 修正方針: 新規ルーンの個体生成を廃止し、全付与経路を通常 inventory entry の itemId と数量へ統一する。旧個体はログイン時に通常 item へ移行する。
- 修正対象候補: `複数`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-002 [高] ルーン装脱着と在庫更新が原子的でない
- 種別: `バグ/アルゴリズム`
- 対象: `20_api/AstralRecordApi/AstralRecordApi/Services/EquipmentService.cs:97`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/item/service/OrbService.java:1019`
- 根拠: API は runeItemId のマスタ検証のみで装備を更新し、プラグインが後続で別処理として消費・返却を行う。
- 問題: API失敗再試行、インベントリ満杯、クラッシュ時にルーンの複製・消失・誤補償が起こり得る。
- 影響: プレイヤー資産の不整合と、API直接呼び出しによる無所持装着を許す。
- 修正方針: API の単一トランザクションで対象 inventory entry の数量と装備 rune slot を更新し、プラグインはその確定結果だけを反映する。
- 修正対象候補: `複数`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-003 [高] ルーン操作オーブが成功時に消費されない

- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/item/service/OrbService.java:1019`

- 根拠: ルーン装着・脱着成功経路に、選択したオーブの `consumeNormalItem` がない。

- 修正方針: 成功時の在庫トランザクションにオーブ1個の消費を含める。
- 修正対象候補: `複数`
- 修正可否: `自動修正可`
