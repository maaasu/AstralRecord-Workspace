### AR-CODE-001 [高] 個体品を HOTBAR から共通返却できず API 確定後にマーケット操作が失敗する
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/inventory/service/InventoryService.java:2367`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/inventory/service/InventoryService.java:6100`
- 根拠: `InventoryService` の外部取引正規化は、設計書 `00_docs/10_Plugin設計書/feature/08-inventory/3-メソッド仕様/08_3-サービス.md` の 12.2 に従い BAG 以外の entry を `returnItemToOwnedInventory` と同じ個体返却処理へ渡している。API の inventory entry payload は itemId と instanceType / instanceId の併記を許容し、マーケットの装備・ルーン entry もこの形で返る。
- 問題: `resolveItemReference(InventoryEntryModel)` は `itemId` が存在すると `new ItemReference(..., null, null)` を返し、entry の `instanceType` / `instanceId` を捨てる。したがって HOTBAR に復元された EQUIPMENT / RUNE を `relocateReturnedEntryThroughOwnedInventory` が共通返却へ渡すと、`addExistingInstanceEntry` の instance ID 検証に失敗し、正規化全体が例外になる。BAG に復元された個体品はこの分岐に入らないため、経路依存で発生する。
- 影響: 取り下げ API が成功して source entry が復元済みなのに Plugin は操作失敗として扱う。`executeExclusiveAfterSave` は operation 開始後の例外で未解決外部操作境界を解除しないため、装備・ルーンの HOTBAR 取り下げで所持品保存と UI 完了が止まり、再ログイン前の state と API 正本が不整合になり得る。
- 修正方針: itemId が併記された個体 entry でも instanceType / instanceId を保持した `ItemReference` を生成する（または instance resolver を経由して生成する）。EQUIPMENT / RUNE の HOTBAR 返却を、metadata と個体 ID を保持した BAG 追加として完了できる回帰テストを追加する。
- 修正対象候補: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/inventory/service/InventoryService.java`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-002 [高] マーケット取り下げの容量事前判定が容量外 stack を空き容量として数える
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/inventory/service/InventoryService.java:3033`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/market/event/MarketGuiEventHandler.java:685, 10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/inventory/service/InventoryService.java:1344`
- 根拠: インベントリ設計 `00_docs/10_Plugin設計書/feature/08-inventory/3-メソッド仕様/08_3-サービス.md` は容量外の既存 entry を新規追加先として再利用しない契約である。実際の `addStackedItems` は slotIndex が null または実効容量外の entry をスキップする。一方 `canAddItemToNormalInventory` の stack 容量集計は managed slot 判定なしで `maxStack - quantity` を合算している。
- 問題: 実効容量内の slot が満杯でも、同じ item の容量外 entry に残量があると事前判定が true になる。例えば BAG 容量1で slot1 の同種 stack が満杯、容量外 entry に同種 item が1個ある場合、取り下げ前の `canReturnListingToInventory` は返却可能と判定するが、正規化時の共通 `addStackedItems` は容量外 entry を使わず、空き slotもなく全量追加に失敗して例外になる。
- 影響: 取り下げ API はすでに escrow を返却した後に Plugin 側だけが失敗する。購入・取り下げの保存 lane はこの例外で確定完了せず、ユーザーには誤った容量失敗／通信失敗が表示される。容量不足なら API を呼ばないというマーケット設計を満たさず、外部取引後の未解決境界を残す。
- 修正方針: 容量事前判定と `addStackedItems` が同じ managed slot predicate を共有し、容量外・slot未指定 entry の残量を空き容量に算入しないようにする。容量外 stack を含む取り下げの「API 呼出前に拒否される」テストと、共通返却の全量 rollback テストを追加する。
- 修正対象候補: `複数`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-003 [高] 購入時の共通 stack 正規化が API 確定後の容量不足で失敗する
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/inventory/service/InventoryService.java:2417`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/market/event/MarketGuiEventHandler.java:640-651, 10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/inventory/service/InventoryService.java:3002-3051`
- 根拠: 購入経路は `purchaseListing` から API を呼び出した後に `reconcileExternalInventoryEntriesToOwnedInventory` を実行するが、購入前の `canAddItemToNormalInventory` 判定はない。API は同一 item の既存 BAG entry を数量更新してから `affectedInventoryEntryIds` を返し、共通 `addStackedItems` は容量外 entry を追加先として使わない。
- 問題: BAG 容量が 1、同一 item の有効 slot が maxStack で満杯、購入数量が 1 の場合、API 確定後の三者マージは affected entry と数量差分 entry を作る。正規化は差分を `addStackedItems` へ渡すが空き slot がなく `null` を投げるため、購入 API 成功後に Plugin 操作だけが例外完了する。
- 影響: 購入者の Gold 減算・出品残数更新が確定済みなのに、購入失敗表示と UI 未更新になり、`executeExclusiveAfterSave` の未解決外部操作境界も残る。購入者 BAG の容量不足を拒否するのか容量外 entry を許容するのかが実装と設計で未確定のまま、いずれの契約にも安全に完了しない。
- 修正方針: 購入前に指定数量の容量を保存 lane 内で検証して API を呼ばず拒否する、または容量外受取を正式な共通経路として保持する。少なくとも API 確定後の正規化失敗を通常の購入失敗として返さない回帰テストを追加する。
- 修正対象候補: `複数`
- 修正可否: `設計判断待ち`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-004 [中] 出品作成が残存 source を受取アイテムとして正規化する
- 種別: `仕様不整合`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/market/event/MarketGuiEventHandler.java:600-603`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/inventory/service/InventoryService.java:2313-2345, 00_docs/10_Plugin設計書/feature/23-market/23_4-統合フロー.md:150`
- 根拠: `MarketListingDraft.selectedSources()` はクリックした stack の数量より少ない出品数量も許容する。その場合 API は source entry を削除せず数量だけ減らす。一方 `submitListing` は source ID を `reconcileExternalInventoryEntriesToOwnedInventory` へ渡し、正規化は API の残存 source を受取アイテムとして扱う。
- 問題: HOTBAR の stack から一部数量だけ出品すると、残った source entry が `normalizeExternallyReturnedOwnedEntries` の BAG 以外分岐へ入り、共通返却処理で BAG へ移動する。同じ item の BAG stack がある場合は残存数量まで統合される。出品作成はアイテムを受け取る操作ではなく、設計書が記載する「entry 削除だけの出品作成では item 正規化は no-op」とも一致しない。
- 影響: 部分出品後に HOTBAR の残数が消えて BAG へ移動し、プレイヤーの配置と GUI 表示が予期せず変化する。出品前後の inventory の差分を source 数量の減算だけに保てない。
- 修正方針: 出品作成は `reconcileExternalInventoryEntries` の三者マージだけを使うか、mutation 種別／API delta が負であることを渡して受取正規化をスキップする。HOTBAR の部分出品で残数と slot が維持される回帰テストを追加する。
- 修正対象候補: `複数`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-005 [中] 容量内へ統合可能な affected stack が容量外に残る
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/inventory/service/InventoryService.java:2391-2424`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/inventory/service/InventoryService.java:2504-2533, 3002-3051`
- 根拠: 取り下げ容量判定は有効 slot の同一 stack 残量を数えて true を返す。三者マージの BAG 圧縮は既存契約どおり容量外 entry を保持する。正規化は API affected ID を常に retained の canonical entry として残し、`addStackedItems` は容量外 entry を追加先に使わない。
- 問題: BAG 容量 1 の有効 slot に同一 item が 63 個あり、容量外 slot に該当 affected entry 1 個が返る場合、事前判定は 1 個の stack 空きを数えて成功する。しかし三者マージ後の affected entry は容量外 slot 2 になり、正規化は有効 slot の 63 個を除去してから容量外 canonical entry を使えない `addStackedItems` へ 63 個を渡す。結果は有効 slot 63 個と容量外 slot 1 個の二重 stack となり、合計 64 個を一枠へ統合できない。
- 影響: 取り下げ成功後も重複 stack と容量外表示が残り、今回の共通インベントリ操作統合の契約を満たさない。容量外 entry の存在を考慮した回帰ケースがないため、AR-CODE-002 の容量 predicate を直しても返却結果が正規化されない。
- 修正方針: affected entry が容量外の場合は同一 item の有効 slotを canonical entry の slot に引き継いでから共通 stack 処理を行う、または全同一 item を一度集約して canonical ID を保ったまま有効 slotへ再配置する。容量 1・有効 stack 63・容量外 affected 1 の取り下げテストを追加する。
- 修正対象候補: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/inventory/service/InventoryService.java`
- 修正可否: `自動修正可`
- 確信度: `高`
