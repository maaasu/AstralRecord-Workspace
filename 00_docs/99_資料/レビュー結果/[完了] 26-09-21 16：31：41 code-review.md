### AR-CODE-001 [高] 複製後のスキルバインドが元の習得個体 UUID を参照する
- 種別: `バグ/アルゴリズム`
- 対象: `20_api/AstralRecordApi/AstralRecordApi/Repositories/AccountRepository.cs:311`
- 関連箇所: `00_docs/20_API設計書/feature/11-skill/3-エンドポイント仕様/11_3.02-バインドプリセット.md:3`
- 根拠: Skill bind preset の action、left-click、passive は対象アカウント所有の `learnedSkillId` を正本として保存する。
- 問題: 複製は `AccountLearnedSkillEntity.LearnedSkillId` を新規発番する一方、プリセット JSON と left-click の値をそのままコピーしている。
- 影響: 複製先の保存済みバインドが他アカウントの UUID を参照し、読み出し時に無効化される。
- 修正方針: UUID として解釈でき、複製元の習得個体に対応する値だけを新しい `learnedSkillId` へ置換して保存する。
- 修正対象候補: `20_api/AstralRecordApi/AstralRecordApi/Repositories/AccountRepository.cs`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-002 [中] 初回複製後にユーザーの選択アカウント UUID が設定されない
- 種別: `バグ/アルゴリズム`
- 対象: `20_api/AstralRecordApi/AstralRecordApi/Repositories/AccountRepository.cs:267`
- 関連箇所: `20_api/AstralRecordApi/AstralRecordApi/Repositories/AccountRepository.cs:51`
- 根拠: 複製先ユーザーに既存アカウントがない場合、作成アカウントは active になる。
- 問題: `dbo.user.account_id` は上書き先が既存かつ選択中の場合だけ更新されるため、最初の複製では active な新アカウントを UUID で解決できない。
- 影響: `GET /api/account/resolve?user_mcid=...` が選択アカウントを返せない。
- 修正方針: 複製先に既存アカウントがなかった場合も、新 UUID を `user.account_id` に設定する。
- 修正対象候補: `20_api/AstralRecordApi/AstralRecordApi/Repositories/AccountRepository.cs`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-003 [中] Commit 結果不明時の実行戦略再試行が複製成功を 409 に変換する
- 種別: `バグ/アルゴリズム`
- 対象: `20_api/AstralRecordApi/AstralRecordApi/Repositories/AccountRepository.cs:187`
- 関連箇所: `20_api/AstralRecordApi/AstralRecordApi.Tests/Repositories/AccountRepositoryTests.cs:887`
- 根拠: 複製は `CreateExecutionStrategy().ExecuteAsync` と `CommitAsync` を使用し、既存テスト基盤は commit 結果不明後の delegate 再実行を再現する。
- 問題: 初回 commit が成功した後の再実行は、作成済み先を `TARGET_ACCOUNT_EXISTS` または `TARGET_CHANGED` として扱う。
- 影響: API 呼出し側へ 409 を返す一方でデータベースには複製済みデータが残る。
- 修正方針: 同一 `CloneAsync` 呼出しの全実行戦略再試行で生成する clone UUID を共有し、その UUID の確定済みアカウントが存在する場合は確定結果を復元する。
- 修正対象候補: `20_api/AstralRecordApi/AstralRecordApi/Repositories/AccountRepository.cs`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

- 根拠: バインドに保存する UUID は対象アカウント所有の `learnedSkillId` を正本とする。

- 修正方針: 再マップ表にない UUID を action、left-click、passive のすべてで null に置換する。
- 修正対象候補: `20_api/AstralRecordApi/AstralRecordApi/Repositories/AccountRepository.cs`
- 修正可否: `自動修正可`
- 確信度: `高`

### AR-CODE-005 [中] 同一ユーザーへの同時作成ガードを検証する恒久テストがない
- 種別: `テスト不足`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/account/command/AccountCreateCommand.java`
- 関連箇所: `00_docs/10_Plugin設計書/feature/02-account/3-メソッド仕様/02_3-コマンド.md`
- 根拠: pendingUserIds は同じユーザーへの同時作成を拒否し、APIは個々の作成要求を別の最小空きスロットへ割り当てる。
- 問題: 同一ユーザーへの先行要求が未完了の間、後続要求がAPI作成に到達しないことを検証するテストがない。
- 影響: ガードの回帰で、同時管理操作から意図せず複数のアカウントが作成され得る。
- 修正方針: Mockitoのschedulerと未完了futureで先行要求を保持し、後続要求が作成APIを呼ばないこと、完了後に再作成できることを検証する。
- 修正対象候補: `10_plugin/AstralRecord/src/test/java/io/github/maaasu/astralRecord/feature/account/command/AccountCreateCommandTest.java`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`
