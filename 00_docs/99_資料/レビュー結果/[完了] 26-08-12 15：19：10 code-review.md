### AR-CODE-001 [高] block-local の collision shape と world 座標 AABB を直接比較している
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/mob/service/MobEntityController.java:1127`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/mob/service/MobEntityController.java:1101`
- 根拠: `00_docs/10_Plugin設計書/feature/12-mob/3-メソッド仕様/12_3-実体Mob制御.md` は Vex の実 AABB と block collision shape の重なりで候補位置と毎 tick の移動線分を拒否すると定めている。Paper の `CraftBlock#getCollisionShape()` はブロック状態の shape を座標移動せず `CraftVoxelShape` に渡し、`CraftVoxelShape#overlaps` はその block-local bounding box と引数を直接比較する。
- 問題: `isVexPositionClear` は world 座標へ移した Vex の `bounds` を、各ブロックの 0..1 を基準とする collision shape へそのまま渡している。原点付近以外では座標空間が一致せず、通常のワールド座標にある壁・床・天井を非衝突と誤判定する。
- 影響: A* の通過可否と毎 tick の sweep guard が同じ誤判定を共有するため、生成経路が壁を直進し、Vex のブロック貫通を防ぐという今回の中心要件を満たさない。
- 修正方針: collision shape の各 bounding box を対象 block の X/Y/Z だけ world 座標へ平行移動して Vex AABB と比較するか、比較用 Vex AABB を対象 block のローカル座標へ変換する。部分ブロックを保つため full-block 判定への置換は避ける。
- 修正対象候補: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/mob/service/MobEntityController.java`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-002 [中] Y ドリフト追加に対して地上 Mob の navTargetY が更新されない
- 種別: `パフォーマンス`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/mob/service/MobEntityController.java:979`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/mob/service/MobEntityController.java:605`
- 根拠: `00_docs/10_Plugin設計書/feature/12-mob/12_0-概要.md` と `12_3-実体Mob制御.md` は、100体規模で毎 tick 全 Mob が再計算しないよう経路再設定を一定間隔と目標移動量で制限すると定めている。
- 問題: 共通 `hasTargetDrifted` は今回 `navTargetY` を含む三次元判定へ変わったが、地上 Mob の `moveTo` 成功後は `navTargetX` と `navTargetZ` だけを保存する。通常高度が 0 以外なら未更新の `navTargetY = 0` との差が常に閾値を超え、経路保持中かつ 10 tick 未満でも AGGRO/LEASHED の 5 tick 意思決定ごとに Paper Pathfinder へ `moveTo` を再要求する。
- 影響: Vex 対応が地上 Mob の既存レート制限を退行させ、Mob 数が多い場面で不要な経路再計算とメインスレッド負荷を増やす。
- 修正方針: 地上 Mob 側でも経路要求時に `navTargetY` を保存するか、地上用 X/Z ドリフト判定と Vex 用 X/Y/Z ドリフト判定を分離する。設計上の地上挙動を維持するなら後者が明確。
- 修正対象候補: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/mob/service/MobEntityController.java`

### AR-CODE-003 [中] 毎 tick の Vex 経路追従が戦闘用の直接移動を同一 tick で打ち消す
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/mob/service/MobEntityController.java:645`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/mob/service/MobAiService.java:221`
- 根拠: `00_docs/10_Plugin設計書/feature/12-mob/3-メソッド仕様/12_3-戦闘.md` は Mob への移動ベクトルを `MobEntityController.addVelocity` で実体へ反映すると定め、既存 AI は RANGED / MAGIC の preferred range 周辺で `stopPathfinding` 後に `addVelocity` して横移動させる。現行 filebase の Vex 2種もいずれも `combat.style: MAGIC` である。
- 問題: `MobAiService.tick` は state 処理の後に全 Mob へ `tickVexNavigation` を呼ぶ。Vex の `strafeOrStop` は同じ tick 内で経路を消去して `addVelocity` するが、その直後の `tickVexNavigation` は `navPath == null` を理由に速度をゼロへ戻す。経路がある場合も `setVelocity(velocity)` で既存速度を置換するため、`MobKnockbackService` が加算したノックバックも次の AI tick で経路速度へ上書きされる。
- 影響: 現在の MAGIC 型 Vex は preferred range 周辺で設計済みの横移動を実行できず静止する。また、被弾時のノックバックが地上 Mob より著しく短くなり、既存の戦闘挙動を退行させる。
- 修正方針: Vex の経路速度と戦闘用直接移動・ノックバックを区別し、同一 tick の意図的な直接速度を経路追従が消さない状態を持たせるか、Vex の strafe / retreat を衝突検査付き経路要求へ統合する。併せて Vex の strafe と加算速度が経路 tick 後にも残るテストを追加する。
- 修正対象候補: `複数`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-004 [中] Vex の経路破棄が WANDER NPC の詰まり観測まで消去する
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/mob/model/MobInstance.java:647`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/mob/service/MobEntityController.java:664`
- 根拠: `00_docs/10_Plugin設計書/feature/12-mob/3-メソッド仕様/12_3-サービス.md` は、NPC が同じ WANDER 目的地に対して 30 tick 連続で水平移動しなければ配置アンカーへ戻すと定める。一方、`12_3-実体Mob制御.md` は Vex の保持経路を使い切った場合または sweep 衝突時に経路を破棄して再計算すると定める。
- 問題: `MobInstance.clearNavPath()` は Vex の `navPath` / `navFlightSpeed` だけでなく、WANDER 詰まり検知の `navBlockedSinceTick` / `navLastObservedLocation` も同時に初期化する。`tickVexNavigation()` は WANDER 目的地が変わっていなくても、部分経路の使い切りまたは sweep 衝突でこのメソッドを呼ぶため、経路を破棄するたびに 30 tick の詰まり観測まで中断される。
- 影響: WANDER の Vex NPC が同一目的地へ水平進捗できないまま部分経路の消化や経路衝突を繰り返すと、詰まりタイマーが成立せず、3 秒後の `resetPosition` が実行されない。回復が最長 60 秒の周期リセットまで遅れ、rebase で取り込んだ NPC 詰まり回復を Vex 経路制御が退行させる。
- 修正方針: Vex の飛行経路だけを破棄する操作と、WANDER 詰まり観測を含む全ナビゲーション状態のクリアを分離する。経路完了・sweep 衝突・直接速度への切替では詰まり観測を保持し、明示停止・WANDER 目的地変更・`resetPosition` では従来どおり両方を消す。Vex WANDER NPC が経路破棄を挟んでも 30 tick 後にリセットされる恒久テストを追加する。
- 修正対象候補: `複数`
- 修正可否: `自動修正可`

- 修正状態: `修正済み`
