### AR-CODE-001 [高] 進行条件なしで草原スポナーから高防御敵が出現する
- 種別: `仕様不整合`
- 対象: `40_filebase/41.features.mob.spawner/v1.midgard_grassland_spawner.yml:10`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/spawner/service/MobSpawnerService.java:516`
- 根拠: `00_docs/60_戦闘バランス設計書/04-レベル帯コンテンツ設計.md:42-54` は草原・サバンナ帯を Mob Lv.1〜4 の順序として定義し、`midgard_shield_guard` は `450 / 43 / 65`、`midgard_savanna_sunback` は `600 / 58 / 88`、`midgard_savanna_acacia_watcher` は `400 / 73 / 70` としています。一方、草原スポナーは `grassboar` 以外も同時に抽選し、スポーン処理は時間帯・近傍プレイヤー数・上限だけを確認して `mobService.spawn` を呼びます。プレイヤー Lv・装備更新・地域解放によるスポーン制限は確認できません。
- 問題: 初期状態や装備更新前のプレイヤーが、設計上は後続の戦闘強度を持つ敵へ同じスポナーから遭遇できます。プレイヤーの解決攻撃力が簡素な初期武器込みでも概算 `R=26.4` の場合、`D=70` 以上は戦闘計算の `D / R >= 2.5` によりダメージが0となり、`D=65` も完全防御直前になります。
- 影響: グラスボアだけ倒せて他の敵が強すぎる、という体感が再現されます。敵の役割倍率や個別 HP / R / D が誤っているというより、想定プレイヤー強度に到達する前の遭遇が進行を飛び越えています。
- 修正方針: 草原スポナーを導入敵の解放条件に対応させる、または Player Lv.5 相当の装備を確実に取得するまで後続スポナーを利用できない導線にします。Player Lv.1 から全種を抽選する仕様を維持する場合は、Lv.2〜4 の敵の D / R を初期プレイヤー基準へ再調整し、TTK・耐久時間を再計測します。
- 修正対象候補: `複数`
- 修正可否: `設計判断待ち`
- 確信度: `高`
- 修正状態: `未修正`

### AR-CODE-002 [高] プレイヤーの実効成長値が戦闘バランス設計アンカーと一致していない
- 種別: `仕様不整合`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/status/service/StatusService.java:921`
- 関連箇所: `00_docs/60_戦闘バランス設計書/02-成長曲線.md:56-99、40_filebase/20.features.class/v1.adventurer.yml:12-60`
- 根拠: 設計アンカーは Player Lv.1 を `HP 50 / R 17 / D 18`、Lv.5 を `HP 250 / R 87 / D 91` とし、増加分を class・レベル成長、equipment、skill tree へ配分します。しかし `StatusService#getLevelBonus` は `INVENTORY_SLOTS` 以外の Player Lv.へ `0` を返します。初期アカウントは Player Lv.1・class Lv.1 で、スキルツリー状態も未解放集合から始まります。さらに現行 `adventurer` の `MAX_HEALTH +105` は共通基礎 `20` と VITALITY 派生を加算するため、装備なしでも HP は概算 `145` となり、Lv.1 の設計値 `50` と一致しません。
- 問題: 現在のプレイヤー側は Player Lv.だけでは戦闘力が上がらず、class・装備購入／更新・スキルツリー解放が揃って初めて敵の設計曲線へ近づきます。装備導線や解放状態が未整備のテストでは、敵側の D だけが先に増えたように見えます。
- 影響: 敵の個別調整前に、プレイヤーの初期値・成長源・更新時期が設計アンカーから外れているため、TTK・プレイヤー耐久時間の評価結果を敵の妥当性判定へ直接使えません。ユーザーが感じている「グラスボア以外が強い」は、プレイヤーのステータス上昇コンテンツが存在しないというより、必要な成長が遭遇前に保証されていないことが主因です。
- 修正方針: 設計アンカーと現行の class / status 実装のどちらを正とするか決定し、Player Lv.到達時の成長、初期装備、Player Lv.5 更新装備、スキルツリー解放を一連の標準進行として実装・検証します。その後、標準装備済みの各レベル帯で敵の TTK・耐久時間を再計測します。
- 修正対象候補: `複数`
- 修正可否: `設計判断待ち`
- 確信度: `高`
- 修正状態: `未修正`
