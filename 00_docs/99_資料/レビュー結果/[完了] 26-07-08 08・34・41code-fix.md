### AR-CODE-001 [高] 戦闘中の耐久値減少が同期 HTTP で永続化され、メインスレッドを止める可能性がある

- 修正可否: 修正済み（方針確認済み）
- 関連箇所:
  - `E:\AstralRecord-Workspace\10_plugin\AstralRecord\src\main\java\io\github\maaasu\astralRecord\feature\combat\service\DamageService.java:334`
  - `E:\AstralRecord-Workspace\10_plugin\AstralRecord\src\main\java\io\github\maaasu\astralRecord\feature\item\service\EquipmentDurabilityService.java:169`
  - `E:\AstralRecord-Workspace\10_plugin\AstralRecord\src\main\java\io\github\maaasu\astralRecord\feature\item\repository\ItemRepository.kt:247`
- 内容: `DamageService` の攻撃・被ダメージ処理から `EquipmentDurabilityService` が呼ばれ、装備ごとに `ItemRepository.updateEquipmentDurability` を実行します。この repository は `HttpClient.send(...)` による同期 HTTP 送信です。戦闘イベントのホットパスで API レイテンシがそのままサーバ tick に乗り、武器・防具・アクセサリー分だけ複数回発生します。
- 影響: API 遅延や一時的な応答低下が、戦闘中のラグや TPS 低下として表面化します。被ダメージ側の防具・アクセサリーが多いほど悪化します。
- 根拠: Paper/Spigot のゲーム処理中にブロッキング I/O を置く設計は避けるべきです。`$astralrecord-code` の plugin-code チェックリストでも、リアルタイム処理の性能・副作用確認が求められています。
- 修正案: 耐久値の減少はメモリ上で即時反映し、永続化は非同期キューまたはバッチ更新に寄せてください。Bukkit API に触れる inventory/status 更新だけをメインスレッドへ戻し、HTTP はメインスレッド外で実行する構成が必要です。
