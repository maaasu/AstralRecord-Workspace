### AR-CODE-001 [中] ショップ購入後の保存完了前にマーケットキャッシュを破棄する
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/shop/service/ShopService.java:237`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/AstralRecord.java:1080`
- 根拠: `InventoryService.saveNow` は API I/O を非同期 executor で実行し、完了を返却 future で通知する契約である。現状は future を待たずに購入成功通知とマーケットキャッシュ破棄を行っている。
- 問題: アストラルドショップでトークンを購入した直後にマーケットGUIを開くと、API側のCURRENCY inventory保存前に概要取得が走り、旧トークン数・旧最大出品枠をキャッシュする可能性がある。
- 影響: 購入直後のプレイヤーに最大15秒程度、実際より少ない出品枠が表示される。実効枠の正本はAPIでも、表示更新のタイミングが不正確になる。
- 修正方針: `saveNow` の完了成功時にマーケットキャッシュを破棄する後続処理を登録し、保存失敗時は新しい概要取得を誘発しない。既存の購入成功通知は維持し、保存完了後のキャッシュ無効化だけを追加する。
- 修正対象候補: `複数`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-002 [低] マーケット拡張トークンの不正なinventory条件を検証するテストが不足する

- 対象: `20_api/AstralRecordApi/AstralRecordApi.Tests/Repositories/MarketRepositoryEquipmentListingTests.cs`
- 関連箇所: `20_api/AstralRecordApi/AstralRecordApi/Repositories/MarketRepository.cs:1118`
- 根拠: 実装は `GAME` プロファイル、`CURRENCY` inventory、`currency` category、論理削除・有効状態・正の数量を集計条件に含めているが、現行のリポジトリテストは正しい条件のトークンだけを検証している。
- 問題: `GAME` 以外、`CURRENCY` 以外、item category が `currency` 以外、無効／論理削除済みのentryが誤って枠へ加算されない契約が、テストで固定されていない。

- 修正方針: SQLiteリポジトリテストに不正条件のトークンentryを追加し、概要・出品作成の実効枠へ加算されないことを検証する。
- 修正対象候補: `20_api/AstralRecordApi/AstralRecordApi.Tests/Repositories/MarketRepositoryEquipmentListingTests.cs`

### AR-CODE-003 [中] SQL Server専用のトークン枠ロック経路が恒久テストで検証されていない
- 種別: `テスト不足`
- 対象: `20_api/AstralRecordApi/AstralRecordApi/Repositories/MarketRepository.cs:1150`
- 関連箇所: `20_api/AstralRecordApi/AstralRecordApi.Tests/Repositories/MarketRepositoryEquipmentListingTests.cs:607`
- 根拠: `CountExpansionListingSlotsAsync` は SQL Server かつ `forUpdate` の場合だけ `FindExpansionEntriesForUpdateAsync` を選び、`UPDLOCK, HOLDLOCK` を付与した生 SQL を実行する。現在の MarketHarness は SQLite 接続を固定しているため、拡張トークン関連のリポジトリテストはこの分岐を一度も実行しない。
- 問題: SQL Server 固有のテーブル名・列名・パラメータ化された `IN` 条件、ロックヒントの適用対象に回帰が入っても、SQLite テストと `IsolationLevel.Serializable` の確認だけでは検出できない。
- 影響: 本番 SQL Server で新規出品時のトークン枠再集計が失敗または競合保護を失い、上限判定と実際の出品枠が不整合になる可能性がある。
- 修正方針: SQL Server integration テストで `CreateListingAsync` の拡張トークン枠判定を実行し、SQL Server 分岐の成功と並行登録時のロック動作を検証する。実 DB を常時使えない場合は、SQL 生成・条件を検証できる分離可能なテスト境界を追加する。
- 修正対象候補: `20_api/AstralRecordApi/AstralRecordApi.Tests/Repositories/MarketRepositoryEquipmentListingTests.cs`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `未修正`
