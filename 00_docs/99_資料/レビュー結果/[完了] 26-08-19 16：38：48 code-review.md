### AR-CODE-001 [中] Boss 準備中キャンセル時に作成枠を破棄完了前に解放する
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/boss/service/BossChallengeService.java:1098`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/boss/service/BossChallengeService.java:1192、10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/boss/service/BossFieldInstanceService.java:121`
- 根拠: `beginChallengeCompletion` は `cancelPendingCreation` でキャンセルフラグを立てた後、`challenge.field()` が未設定なら `finishChallengeRemoval` へ進み、作成チケットを `release` します。一方 `cancelPendingCreation` はフラグ設定だけで、コピー・ロード・削除の完了を待ちません。作成 Future が後から field を返した場合も、終了状態のため `finishFieldPreparation` は field の破棄を要求するだけです。
- 問題: フィールド作成中のキャンセルで、作成途中のフォルダ／ワールドの回収完了前にキュー枠を解放しています。
- 影響: 次の要求が先行して開始され、作成・ロード・削除処理が設定上限を超えて並行します。有限の通常枠・予約枠による同時実行制限を実際には守れません。
- 修正方針: キャンセル時のコピー・ロード・フォルダ削除を表す完了 Future を追跡し、field の破棄または作成途中資産の回収完了後にだけ `creationQueue.release` するよう、Boss の終了経路と `BossFieldInstanceService` の契約を接続してください。
- 修正対象候補: `複数`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-002 [中] キュー開始 callback の例外で作成枠が永久占有される
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/shared/challenge/InstanceCreationQueue.java:215`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/boss/service/BossChallengeService.java:727-735、10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/dungeon/service/DungeonService.java:598-607`
- 根拠: `grant` は `active.put` の直後に `onGranted().accept` を呼びますが、callback 例外時の rollback がありません。さらに Boss／Dungeon は `enqueue` が返った後に challenge／session へチケット IDを保存するため、callback が同期例外を投げると呼出元にもチケット IDが残りません。
- 問題: 開始処理の同期例外で active からチケットが除去されず、後続要求へ枠を渡す処理も実行されません。
- 影響: 予約枠1件または通常枠の1件がプラグイン停止まで占有され、同じ枠の待機要求が進まなくなります。
- 修正方針: 開始 callback の失敗を捕捉して active から確実に rollback し、必要なら後続待機列を drain する失敗契約を `InstanceCreationQueue` と呼出元に定義してください。
- 修正対象候補: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/shared/challenge/InstanceCreationQueue.java および呼出元`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-004 [中] DONOR 権限 migration の台帳と適用順が未整備
- 種別: `ドキュメント不整合`
- 対象: `00_docs/40_Database設計書/table-definitions/README.md:21-30`
- 関連箇所: `00_docs/40_Database設計書/table-definitions/AstralRecord/migrations/20260819_add_donor_permission.sql:2-24、00_docs/40_Database設計書/table-definitions/AstralRecord/migrations/20260801_remove_builder.sql:25-33、20_api/AstralRecordApi/AstralRecordApi/Models/AccessControlContract.cs:17-18`
- 根拠: API は `0/5/99` を受理し、新 migration は DB 制約を `0,5,99` に変更しますが、`20260819_add_donor_permission.sql` は本番 migration 一覧に登録されていません。旧 `20260801_remove_builder.sql` は非 `99` の permission を `0` に戻し、制約を `0,99` に再作成します。
