### AR-CODE-001 [中] 元被弾より先に反撃を確定している
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/skill/executor/active/swordsman/SwordsmanBladeCounterRuntimeService.java:162-168`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/combat/service/DamageService.java:573-602 / 00_docs/10_Plugin設計書/feature/13-skill/13_6-発動スキル追加ガイド.md:153`
- 根拠: 設計は「元damageを50%へ減らす。その後、発動時点の攻撃snapshotで反撃」と定めています。一方、`DamageService` は被ダメージ倍率を解決するために `DirectDamageModifier` を元hit反映前に呼び、modifier実装はそのcallback内から同じ `DamageService.attack` へ同期再入して反撃を最後まで適用しています。元hitの `applyDamageResult` はcallbackから戻った後です。
- 問題: 処理順が「敵の攻撃を受ける → 反撃」ではなく「反撃を適用する → 敵の攻撃を適用する」になっています。反撃のライフスティールは元hit前に回復し、反撃で攻撃元Mobを倒しても、その死亡済みMobの元hitが後からPlayerへ適用されます。
- 影響: 反撃前なら致死となる被弾をライフスティールの先行回復で生存できるほか、死亡処理、ダメージログ、リスナー、演出の因果順が逆転し、戦闘結果と設計上のプレイ判断が一致しません。
- 修正方針: direct modifierは受付判定と50%倍率の決定だけを行い、元hitのshield/HP/death反映後に呼ぶpost-hit処理で反撃を1回実行します。元hit後にPlayerが死亡した場合にも反撃を成立させるかは、設計文の「その後」に合わせて明示し、少なくとも現行の先行ライフスティールを排除する統合テストを追加します。
- 修正対象候補: `複数`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-002 [中] 回避された攻撃でもカウンター成功演出と反撃が発生する
- 種別: `仕様不整合`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/skill/executor/active/swordsman/SwordsmanBladeCounterRuntimeService.java:147-168`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/combat/service/DamageService.java:564-582 / 00_docs/10_Plugin設計書/feature/13-skill/13_6-発動スキル追加ガイド.md:152-154`
- 根拠: ブレードカウンターの設計対象は管理対象Mobから「受ける有効な直接hit」であり、回数を先に消費した後に元damageを軽減して反撃すると定めています。`DamageService` は回避結果でもmodifierへ通知しますが、runtime側は `calculated.evaded()` を確認せず、回数消費、guard/critical演出、反撃をすべて実行します。
- 問題: Mob攻撃が命中判定で回避されて元damageが0でも、カウンター成功として反撃damageと成功演出が発生します。反撃側が回避・無効化されても試行回数を戻さない確定仕様と、そもそも元攻撃を受けていない回避結果から反撃を開始するかどうかが混同されています。
- 影響: EVASIONが高い構成ほど被弾せずに追加damageだけを得られ、想定した「攻撃を受けて50%軽減し反撃する」リスク・リターンと耐久/DPS試算が崩れます。MISS表示とshield成功演出が同時に出る表示不整合も発生します。
- 修正方針: modifier通知は受付試行の確定に利用しても、`calculated.evaded()` では成功演出・反撃・50%軽減処理を行わないよう分離します。回数を消費する契約は状態遷移に合わせて維持し、Mob→Playerの命中、回避、0damage、`OTHER`、PvPを通すruntime/DamageService統合テストを追加します。
- 修正対象候補: `複数`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-003 [低] 初期反撃回数3固定の契約を検証していない
- 種別: `仕様不整合`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/skill/executor/active/swordsman/SwordsmanBladeCounterExecutor.java:45-47`
- 関連箇所: `00_docs/10_Plugin設計書/feature/13-skill/13_6-発動スキル追加ガイド.md:154 / 10_plugin/AstralRecord/src/test/java/io/github/maaasu/astralRecord/feature/skill/active/ActiveSkillExecutorDesignTest.java:190-220 / 40_filebase/30.features.skill/v1.swordsman_blade_counter.yml`
- 根拠: 設計は最大反撃回数をSkill Lv.1～5で `3 / 3 / 4 / 4 / 5` と定め、filebaseも基礎値3へLv.3・5で1ずつ加算しています。テストの検証契約にも「初期3回を要求する」とありますが、executorは `maximumCounters >= 1` なら受理し、テストは3の成功と別parameterの失敗しか確認していません。
- 問題: 基礎値1、2、4など設計外の定義でもマスタ読込時のparameter検証を通過し、レベルごとの最大反撃回数が契約値から外れます。
- 影響: filebaseの誤設定を起動・再読込時に検出できず、スキルのDPSと軽減可能hit数が設計値と異なる状態で公開される可能性があります。
- 修正方針: `maximumCounters` の基礎値を3固定で検証し、3以外を指定した定義が `maximumCounters` の `SkillParameterException` になるテストを追加します。
- 修正対象候補: `複数`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`
