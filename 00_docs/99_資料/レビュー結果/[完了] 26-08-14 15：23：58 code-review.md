### AR-CODE-001 [高] スタック出品の取り下げが残数を上書きする
- 種別: `バグ/アルゴリズム`
- 対象: `20_api/AstralRecordApi/AstralRecordApi/Repositories/MarketRepository.cs:607`
- 関連箇所: `20_api/AstralRecordApi/AstralRecordApi/Repositories/MarketRepository.cs:378`
- 根拠: `23_4.00-統合フロー.md` の escrow 方針は、スタック品をキャンセル時に seller inventory へ返却すると定義している。
- 問題: 出品時は source entry から数量を減算する一方、取り下げ時は `listing.Quantity` を代入している。たとえば 10 個から 3 個を出品すると source は 7 個になるが、取り下げ後は 3 個となり、残っていた 7 個を失う。
- 影響: スタック品を取り下げたプレイヤーのアイテムが恒久的に消失する。
- 修正方針: 個体品は復元量を 1 に固定し、スタック品は現在の source 数量へ出品数量を加算する。加算時の overflow を失敗として扱い、正常な取り下げ・部分出品の回帰テストを追加する。
- 修正対象候補: `20_api/AstralRecordApi/AstralRecordApi/Repositories/MarketRepository.cs`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-002 [高] 購入と取り下げが同時に成立し得る
- 種別: `バグ/アルゴリズム`
- 対象: `20_api/AstralRecordApi/AstralRecordApi/Repositories/MarketRepository.cs:237`
- 関連箇所: `20_api/AstralRecordApi/AstralRecordApi/Repositories/MarketRepository.cs:312`
- 根拠: `23_4.00-統合フロー.md` は出品作成・購入・キャンセルを更新ロック付きの DB トランザクションで二重消費を防ぐ方針としている。
- 問題: 購入とキャンセルはどちらも `market_listing` を通常の読み取りで取得してから状態を更新している。双方が `ACTIVE` を読んだ後に購入が `SOLD` を確定しても、キャンセル側が escrow を復元して `CANCELED` を保存でき、スタック品では購入者と出品者の双方へ同じ数量が存在する。
- 影響: 同時操作でアイテム複製、約定状態の上書き、支払いと出品状態の不整合が発生する。
- 修正方針: 購入・キャンセルともに Serializable transaction 内で `market_listing` を `UPDLOCK, HOLDLOCK` 相当で先に取得し、片方だけが状態遷移できるようにする。競合時はもう片方が最新 status を確認して 409 を返す。
- 修正対象候補: `20_api/AstralRecordApi/AstralRecordApi/Repositories/MarketRepository.cs`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-003 [中] 削除済み装備個体を escrow として受け入れる
- 種別: `バグ/アルゴリズム`
- 対象: `20_api/AstralRecordApi/AstralRecordApi/Repositories/MarketRepository.cs:437`
- 関連箇所: `20_api/AstralRecordApi/AstralRecordApi/Repositories/MarketRepository.cs:423`
- 根拠: 同じ個体品である Rune は `!IsDeleted` を条件にしており、market の source entry も削除済みを拒否している。
- 問題: 装備取得用の更新ロック query は `equipment_instance.is_deleted` を除外しないため、壊れた entry 参照が残った場合に削除済み装備を出品・購入できる。
- 影響: 削除済み装備を復活させたり、購入者に無効な個体を渡したりする可能性がある。
- 修正方針: SQL Server と fallback query の双方で `IsDeleted == false` を条件にし、削除済み装備の出品を拒否するテストを追加する。
- 修正対象候補: `20_api/AstralRecordApi/AstralRecordApi/Repositories/MarketRepository.cs`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`
