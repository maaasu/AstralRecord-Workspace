### AR-CODE-002 [中] 期限到来済みリチャージを攻撃後に確定している
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/combat/service/DamageService.java:526`
- 関連箇所: `00_docs/10_Plugin設計書/feature/07-status/3-メソッド仕様/07_3-サービス.md:168`
- 根拠: 攻撃経路は `hasActiveShield`、shield 適用、固定 HP damage 加算、リチャージ延長抽選を実行した後、536 行目で初めて `completeShieldRechargeIfReady` を呼ぶ。設計は完了時刻を過ぎた状態を一度だけ完了し、進行中のリチャージだけを延長対象とする。
- 問題: 完了予定時刻を過ぎているが定期 task 未実行の短い区間では、満タンへ戻るべき shield がないものとして通常・固定 HP damage が通る。さらに延長抽選が成功すると、期限切れ state を先に延長して完了自体を取り消せる。
- 影響: shield の防御結果が tick 順序や一時的な lag に依存し、攻撃者が期限切れリチャージを再延長できる。
- 修正方針: 同一の `nowMs` で既存リチャージを `hasActiveShield` より前に settle する。破壊 hit で新規開始した 0 秒リチャージ用に後段完了が必要なら、その場合だけ残し、期限到来直後の hit が回復済み shield へ入るテストを追加する。
- 修正対象候補: `複数`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-003 [中] Player リチャージ完了量が現在の MAX_SHIELD と一致しない
- 種別: `仕様不整合`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/status/service/StatusService.java:356`
- 関連箇所: `00_docs/10_Plugin設計書/feature/07-status/3-メソッド仕様/07_3-サービス.md:168`
- 根拠: 設計は破壊時に固定する対象を基礎時間と短縮率とし、Player の完了時は `MAX_SHIELD` を一括設定すると定める。実装は破壊時の maxShield を `ShieldRechargeState.rechargeAmount` に保存し、完了時の現在 `MAX_SHIELD` ではなくその旧値を current shield と `shieldDisplayCapacities` に設定する。
- 問題: リチャージ中の装備・buff 変更で `MAX_SHIELD` が 100 から 200 へ増えた場合は 100 までしか回復せず、50 へ減った場合は current が 50 に clamp されても表示 capacity は 100 のままになる。0 化時も state だけを除去して旧 capacity を残すため、再装備後へ stale 値を持ち越す。
- 影響: 実 shield、ActionBar・armor bar の現在 `MAX_SHIELD` 基準、頭上表示の保存 capacity が分裂し、満タン表示と実際の吸収量が一致しなくなる。
- 修正方針: Player 完了時の current shield と表示 capacity は完了時点の `snapshot.getMaxValue(MAX_SHIELD)` で揃え、max が 0 の場合も state と capacity を整合する値へ破棄・再設定する。リチャージ中の max 増加・減少・0 化を恒久テストへ追加する。
- 修正対象候補: `複数`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-004 [中] 実 HP damage が 0 の nonLethal Mob でもリチャージを延長する

- 関連箇所: `00_docs/10_Plugin設計書/feature/14-combat/3-メソッド仕様/14_3-サービス.md:131`
- 根拠: 設計はリチャージ中に「実 HP damage」が発生した直接攻撃だけを延長対象とし、nonLethal Mob は HP 1 を下限に実効 damage を clamp する。実装は HP 反映前に `result.finalDamage() > 0` だけを eligibility としている。
- 問題: HP 1 の nonLethal Mob は正の計算結果でも実際の HP 減少が 0 だが、延長率の抽選と時間追加が行われる。
- 影響: 訓練・検証用の nonLethal 対象へ実害のない hit を繰り返し、リチャージを無制限に延長できる。
- 修正方針: victim 種別と nonLethal 下限を反映した実効 HP 減少量を先に算出するか HP 反映処理から返し、その値が正の場合だけ延長する。shield break は別条件のまま維持し、HP 1 境界テストを追加する。
- 修正対象候補: `複数`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-006 [中] MAX_SHIELD の後付け取得後に Shield を開始できない
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/status/service/StatusService.java:154`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/status/service/StatusRegenTask.java:87`
- 根拠: `refreshStatus` は既存 snapshot の `currentShield` を維持して新しい最大値へ clamp するため、装備・職業・buff・skilltree などで `MAX_SHIELD` が 0 から正数へ変わっても現在値は 0 のままとなる。新方式の `StatusRegenTask` は既存リチャージ state の完了だけを行い、state 開始は `DamageService` が有効 Shield を破壊した場合だけである。現在値 0 は有効 Shield にならず破壊 result も作れないため、state を開始する経路がない。実到達 call site として `InventoryEquipmentGuiEventHandler.java:636`、`ClassCommand.java:88` / `:148` などを確認した。
- 問題: セッション中に初めて Shield 能力を得た場合、または最大 Shield を 0 にした後で再取得した場合、管理全回復・死亡復帰・再ログインまで Shield が 0 のまま利用不能になる。
- 影響: Shield 装備・職業・buff 等を途中取得しても防御効果が発生せず、プレイヤーの選択と表示上の最大値が実戦挙動へ反映されない。
- 修正方針: `MAX_SHIELD` の 0 から正数への遷移を検出し、即時満タン化または Player 基礎30秒のリチャージ開始のどちらかを仕様として確定した上で、`currentShield`、`shieldDisplayCapacity`、`ShieldRechargeState` を一貫して初期化し、state なしの 0→正遷移を恒久テストへ追加する。
- 修正対象候補: `複数`
- 修正可否: `設計判断待ち`
- 確信度: `高`
