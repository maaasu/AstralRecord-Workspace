### AR-CODE-001 [中] アクション枠へ通常攻撃を保存できる API 契約が未更新
- 種別: `ドキュメント不整合`
- 対象: `20_api/AstralRecordApi/AstralRecordApi/Repositories/SkillBindPresetRepository.cs:188`
- 関連箇所: `00_docs/20_API設計書/feature/11-skill/1-モデル定義/11_1.00-モデル定義.md:39、00_docs/20_API設計書/feature/11-skill/3-エンドポイント仕様/11_3.02-バインドプリセット.md:22`
- 根拠: 実装は `HasValidOwnedBindingsAsync` で通常攻撃予約値を passive 枠だけ拒否し、active / left-click では所有済み習得個体の検証から除外する。一方 API 設計書は通常攻撃予約値を left-click だけに許可すると定義している。
- 問題: 実装と公開 API 契約が逆の状態で残るため、アクション枠へ通常攻撃を設定する正規リクエストを API 利用者・将来の保守者が 400 対象と誤認する。
- 影響: 今回修正した HTTP 400 の再発調査・クライアント実装・回帰テストの前提が不一致になり、後続変更で active 枠の許可を再び外すリスクがある。
- 修正方針: `SkillBindPresetResponse` の予約値説明と PUT 仕様を、通常攻撃予約値は active / left-click に許可し passive には不許可、と実装およびプラグイン設計書へ合わせて更新する。
- 修正対象候補: `00_docs/20_API設計書/feature/11-skill/1-モデル定義/11_1.00-モデル定義.md、00_docs/20_API設計書/feature/11-skill/3-エンドポイント仕様/11_3.02-バインドプリセット.md`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`
