### AR-CODE-001 [中] イベント一覧の代表アカウント検索に対応する索引がない
- 種別: `パフォーマンス`
- 対象: `20_api/AstralRecordApi/AstralRecordApi/Repositories/PlayerActivityRepository.cs:150`
- 関連箇所: `20_api/AstralRecordApi/AstralRecordApi/Data/HistoryDbContext.cs:46`
- 根拠: `GetEventsAsync` はページ内の `user_uuid` を使い、期間を限定せず `player_ip_observation` をユーザーごとに並べて最新行を取る。HistoryDB の `init.sql` と `20260921_player_activity.sql` にある同表の索引は `(global_ip, observed_at)` だけで、`user_uuid` を先頭とする索引はない。HistoryDB はゲームDBリセット後も保持する設計である。
- 問題: 管理画面のイベント一覧を開くたび、蓄積した全接続観測行の走査とユーザー別の並べ替えが必要になる。
- 影響: 観測履歴の増加につれてイベント一覧の応答時間と HistoryDB の負荷が増える。
- 修正方針: `user_uuid, observed_at DESC, event_id DESC` をキーとする索引を HistoryDB の既存DB向け migration、新規DB用 `init.sql`、EF モデルへ揃えて追加する。
- 修正対象候補: `複数`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-002 [低] マーケット取得手順にユーザー UUID の追加が反映されていない
- 種別: `ドキュメント不整合`
- 対象: `00_docs/20_API設計書/feature/23-market/3-エンドポイント仕様/23_3.01-取得系.md:69`
- 関連箇所: `00_docs/20_API設計書/feature/23-market/1-モデル定義/23_1.00-モデル定義.md:198`
- 根拠: 今回のモデル定義と API 応答には `sellerUserUuid` / `buyerUserUuid` が追加されたが、公開取引履歴の処理内容は売主・買主のアカウント UUID と現在名だけを返すと記述している。出品一覧と出品詳細の処理内容も、出品者へ付加する項目に `sellerUserUuid` を記載していない。
- 問題: エンドポイント仕様の処理内容から、追加されたユーザー UUID の取得元と公開動作を確認できない。
- 影響: API 契約を確認する実装者がモデル定義とエンドポイント仕様で異なる内容を読む。
- 修正方針: 各取得手順に、未削除の出品者・売主・買主アカウントから `user_id` を読み、解決できない場合は null とすることを追記する。
- 修正対象候補: `00_docs/20_API設計書/feature/23-market/3-エンドポイント仕様/23_3.01-取得系.md`
