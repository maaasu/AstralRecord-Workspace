## 指摘一覧

### AR-CODE-001 [低] 終端状態のトレード申請が requests に残り続ける
- 種別: `パフォーマンス`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/trade/service/TradeService.java:58`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/trade/service/TradeService.java:138`
- 根拠: `requests` は request 作成時に追加される一方、accept 失敗時の `CANCELLED`、accept 成功時の `ACCEPTED`、期限切れ時の `EXPIRED` は status を更新するだけで map から除去されない。全参照箇所を照合しても削除経路は存在しない。
- 問題: 過去の申請がサーバー稼働中ずっとメモリに残り、`expireRequests` と pending request 検索が全履歴を走査する。
- 影響: トレード申請を継続的に行うサーバーでは使用メモリと request ごとの走査コストが単調増加し、長期稼働時の遅延要因になる。
- 修正方針: `ACCEPTED`、`CANCELLED`、`EXPIRED` へ遷移した request を、状態遷移後に `requests` から確実に除去する。期限処理では iterator 等を使い、走査中の安全な削除を行う。
- 修正対象候補: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/trade/service/TradeService.java`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`
