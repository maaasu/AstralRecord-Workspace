### AR-CODE-001 [中] 破損した購入 receipt の再送が 500 になる
- 種別: `バグ/アルゴリズム`
- 対象: `20_api/AstralRecordApi/AstralRecordApi/Repositories/MarketRepository.cs:293`
- 関連箇所: `20_api/AstralRecordApi/AstralRecordApi/Repositories/MarketRepository.cs:1321`
- 根拠: `affected_inventory_entry_ids_json` は nullable で既存取引では NULL になり得る一方、再送時の復元失敗は `InvalidOperationException` のままコントローラー外へ送出される。
- 問題: 復旧可能な保存済み receipt 不正が API 内部エラーとして処理される。
- 影響: 同一冪等キーの再送が 500 となり、クライアントが購入結果を正しく判別できない。
- 修正方針: 復元失敗を rollback し、409 `market.purchase_receipt_invalid` の失敗結果へ変換する。
- 修正対象候補: `複数`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-003 [低] 購入再送が決定的な HTTP エラーにも実行される
- 種別: `仕様不整合`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/market/event/MarketGuiEventHandler.java:1036`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/market/repository/MarketRepository.java:280`
- 根拠: `purchaseWithReplay` は全 `RuntimeException` を再送するが、設計書は応答を受信できなかった場合だけ一度再送すると定める。HTTP 400/404/409 も `IllegalStateException` になるため再送対象になる。
- 問題: 通信失敗と API が返した決定的エラーを区別していない。
- 影響: 不正要求や競合時に不要な購入 API 呼び出しが重複する。
- 修正方針: 通信・応答喪失専用例外を導入し、その例外だけ同じ要求で再送する。
- 修正対象候補: `複数`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-007 [低] 売上受取再送が決定的な HTTP エラーにも実行される
- 種別: `仕様不整合`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/market/event/MarketGuiEventHandler.java:1011`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/market/repository/MarketRepository.java:280`
- 根拠: `claimProceedsWithReplay` は全 `RuntimeException` を再送し、HTTP 400/403/404/409 の確定応答も `IllegalStateException` として再送対象になる。購入再送は通信失敗専用の `MarketTransportException` に限定済みである。

- 修正方針: 売上受取も `MarketTransportException` だけ同じ要求で再送し、HTTP エラーを再送しないテストを追加する。
- 修正対象候補: `複数`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`
