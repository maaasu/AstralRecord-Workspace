### AR-CODE-001 [高] 余分な取得件数がページ境界の欠落を生む
- 種別: `バグ/アルゴリズム`
- 対象: `30_web/AstralRecordWeb/AstralRecordWeb/Services/MarketApiClient.cs`
- 関連箇所: `20_api/AstralRecordApi/AstralRecordApi/Repositories/MarketRepository.cs`
- 根拠: Web は20件表示のため `page_size=21` を指定して21件目を捨てる一方、API は同じ21件をページ幅として `Skip((page - 1) * pageSize)` を計算している。
- 問題: 1ページ目の21件目を表示せず、2ページ目は22件目から始まるため、各ページ境界で1件ずつ履歴が欠落する。
- 影響: 利用者が成立済み取引を漏れなく確認できず、設計書の取引履歴表示を満たさない。
- 修正方針: API が表示件数をページ幅として内部で1件余分に取得し、`items` と `hasNextPage` を返すページ応答へ変更する。連続41件以上のページング回帰テストを追加する。
- 修正対象候補: `複数`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-002 [中] 公開履歴の時系列取得を支える索引がない
- 種別: `パフォーマンス`
- 対象: `20_api/AstralRecordApi/AstralRecordApi/Repositories/MarketRepository.cs`
- 関連箇所: `00_docs/40_Database設計書/table-definitions/AstralRecord/dbo.market_transaction.md`
- 根拠: 公開履歴は `completed_at DESC, transaction_id DESC` で全件またはカテゴリ条件を並べるが、既存索引は item、signature、seller、buyer を先頭キーとしている。
- 問題: 無条件の履歴表示で全件ソートが必要になり、OFFSET が深くなるほど読み取りコストも増える。
- 影響: 約定数の増加に伴い履歴画面とDBの応答性能が劣化する。
- 修正方針: `(completed_at DESC, transaction_id DESC)` の索引をDB設計、初期化SQL、EF構成へ同期追加する。item索引にも安定順の `transaction_id` を加える。
- 修正対象候補: `複数`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-003 [中] 空の後続ページから前ページへ戻れない
- 種別: `バグ/アルゴリズム`
- 対象: `30_web/AstralRecordWeb/AstralRecordWeb/Pages/Market/History.cshtml`
- 関連箇所: `00_docs/30_WEB設計書/feature/04-market-browser/3-画面仕様/04_3.00-マーケット閲覧.md`
- 根拠: ページナビゲーションが取引一覧を表示する `else` 節の内側にあり、取引0件では描画されない。
- 問題: 末尾越えや同時更新により2ページ目以降が空になると「前へ」が消え、検索条件を保持したまま戻れない。
- 影響: 利用者が検索をやり直さない限り有効な履歴ページへ復帰できず、設計された前後ページ導線を満たさない。
- 修正方針: 空表示と独立して `PageNumber > 1 || HasNextPage` の場合にナビゲーションを描画し、空の2ページ目を検証するテストを追加する。
- 修正対象候補: `複数`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-004 [中] 同一成立日時の安定順を回帰テストできない
- 種別: `テスト不足`
- 対象: `20_api/AstralRecordApi/AstralRecordApi.Tests/Repositories/MarketRepositoryEquipmentListingTests.cs`
- 関連箇所: `20_api/AstralRecordApi/AstralRecordApi/Repositories/MarketRepository.cs`
- 根拠: 41件のページングテストは全取引の `CompletedAt` を1分ずつ変えており、`transaction_id DESC` のタイブレークが使われるデータを含まない。
- 問題: `ThenByDescending(TransactionId)` が削除または変更されても、既存テストはページの重複・欠落なしで通過し得る。
- 影響: 同一ミリ秒に複数約定した実データでページ境界の順序が不安定になっても回帰検知できない。
- 修正方針: 同一 `CompletedAt` の複数取引を20件目と21件目を含む位置に配置し、transaction ID 降順とページ間の重複・欠落なしを明示検証する。
- 修正対象候補: `20_api/AstralRecordApi/AstralRecordApi.Tests/Repositories/MarketRepositoryEquipmentListingTests.cs`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`
