### AR-CODE-001 [中] 出品取消と出品作成でseller/statusとinventoryのロック順が逆転する
- 種別: `バグ/アルゴリズム`
- 対象: `20_api/AstralRecordApi/AstralRecordApi/Repositories/MarketRepository.cs:485`
- 関連箇所: `20_api/AstralRecordApi/AstralRecordApi/Repositories/MarketRepository.cs:1470`
- 根拠: 出品作成はseller/status範囲ロック後にescrow元inventory_entryを更新ロックする一方、取消はescrow元inventory_entryを更新ロックしてからACTIVE出品をCANCELEDへ更新する。同一sellerで並行すると、出品作成がseller/status範囲を保持してentryを待ち、取消がentryを保持してstatus索引更新を待つ循環を構成できる。
- 問題: 今回追加した出品作成のaccount先頭ロックを取消側が取得しないため、同一accountの2操作が直列化されない。
- 影響: SQL Serverがいずれかを1205犠牲にし、出品作成または取消が失敗する可能性が残る。
- 修正方針: `CancelListingAsync` のtransaction先頭でもseller accountを`UPDLOCK, HOLDLOCK`で取得し、出品作成と取消を同一account単位で直列化する。両操作の並行SQL Serverテストを追加する。
- 修正対象候補: `20_api/AstralRecordApi/AstralRecordApi/Repositories/MarketRepository.cs`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`
