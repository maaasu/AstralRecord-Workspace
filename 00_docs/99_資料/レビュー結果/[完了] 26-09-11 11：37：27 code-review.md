### AR-CODE-001 [低] ロック待機の検証が処理開始遅延でも成功する
- 種別: `テスト不足`
- 対象: `20_api/AstralRecordApi/AstralRecordApi.Tests/Repositories/PlayerStateUpdateLocksSqlServerTests.cs:31`
- 関連箇所: `20_api/AstralRecordApi/AstralRecordApi.Tests/Repositories/PlayerStateUpdateLocksSqlServerTests.cs:62`
- 根拠: second readerの開始後に固定150ms待ち、Task未完了だけでロック待機を判定している。
- 問題: SQLクエリ発行前の遅延を実際のSQLロック待機と区別できない。
- 影響: 更新ロックを除去しても、実行環境の遅延によって排他テストが偶発的に成功し得る。
- 修正方針: SQL Server DMVでsecond sessionがfirst sessionのロックを待っていることを観測してからcommitする。
- 修正対象候補: `20_api/AstralRecordApi/AstralRecordApi.Tests/Repositories/PlayerStateUpdateLocksSqlServerTests.cs`
