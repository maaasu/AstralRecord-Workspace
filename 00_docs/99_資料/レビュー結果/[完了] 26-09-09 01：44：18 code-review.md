### AR-CODE-001 [中] 停止中に借用済み共有 HttpClient を close できる
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/infrastructure/util/ApiRequestUtil.kt:67`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/AstralRecord.java:833`
- 根拠: `sharedClient()` は client をそのまま呼出側へ返すが、借用中の数を追跡しない。`closeSharedClient()` は pooled reference を null にした直後、借用済み client を close する。`onDisable` は scheduler task を cancel するだけで、既に `AsyncTaskUtil.supplyAsync` から実行中の HTTP 呼出の終了を待たない。そのため、停止と同時に開始済み repository 呼出が shared client を取得した後に close され、`send` が `java.io.IOException: closed` で失敗し得る。null 化後に残存 task が `sharedClient()` を呼べば新 client を生成でき、停止処理はその新 client を閉じない。
- 問題: close と借用中 HTTP I/O の排他・drain がなく、停止時に共有 client の再生成と close 済み client 利用が競合する。
- 影響: Plugin 停止または reload 中の保存・読取が closed で失敗し、停止後に生成された HttpClient が未closeのまま残る。
- 修正方針: 停止開始後の新規借用を拒否し、既存借用または Plugin 管理下の非同期 HTTP task を drain してから client を close する。再起動時だけ再生成できる状態へ遷移させ、この競合を制御したテストを追加する。
- 修正対象候補: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/infrastructure/util/ApiRequestUtil.kt, 10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/AstralRecord.java`
