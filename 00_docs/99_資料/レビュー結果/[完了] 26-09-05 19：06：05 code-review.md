### AR-CODE-001 [低] 実運用のPAPER起点を検証していない
- 種別: `テスト不足`
- 対象: `10_plugin/AstralRecord/src/test/java/io/github/maaasu/astralRecord/feature/item/view/ItemStackPacketAdapterTest.java:278`
- 関連箇所: `00_docs/10_Plugin設計書/feature/04-item/3-メソッド仕様/04_3-アダプタ・リスナー.md:90`
- 根拠: `ItemStackFactory` はサーバー側カスタムアイテムの基底 Material を `PAPER` に固定し、filebase のポーション定義も `icon: POTION` を PDC に保持している。実装はアイコン解決結果が `POTION` のとき Bedrock 送信表示を `PAPER` に変換する。
- 問題: 追加テストは `itemWithPotionIcon(Material.POTION)` で元 ItemStack を作成しており、実運用の `PAPER` 起点を検証していない。
- 影響: 実運用経路では Bedrock 側の変換が不要な `PAPER` のまま維持され、Java 側だけ `POTION` へ変換されることを確認できないため、回帰検知が不十分になる。
- 修正方針: 同じテストに `PAPER` 起点のポーションアイコンを追加し、Bedrock は元の `PAPER` を維持し、Java は送信コピーだけ `POTION` になり、元 ItemStack が変化しないことを検証する。
- 修正対象候補: `10_plugin/AstralRecord/src/test/java/io/github/maaasu/astralRecord/feature/item/view/ItemStackPacketAdapterTest.java`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-002 [低] Bedrock判定確定後に装備表示を再同期しない
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/item/view/ItemStackPacketAdapter.java:292`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/playersetting/event/PlayerSettingJoinEventHandler.java:45`
- 根拠: Bedrock 判定スナップショットの初回作成・変更時は `Player#updateInventory()` のみが呼ばれる。ログイン時の `refreshEquipmentView()` は `AstPlayer` キャッシュ登録前に実行され得るため、その時点では Java 版扱いで装備パケットが送信される。
- 問題: Bedrock 判定が後から `true` になっても、既に送信した受信者本人および追跡中プレイヤーの手持ち・装備表示を、確定後の Bedrock 向け表示へ再送しない。
- 影響: ログイン直後などに、対象プレイヤーの inventory は `PAPER` へ更新されても、他プレイヤーの手持ち・装備にある `POTION` icon は次の装備更新まで Java 向け表示のまま残る可能性がある。
- 修正方針: Bedrock 判定スナップショットが変化した場合は inventory の再同期に加えて、受信者本人と追跡中プレイヤーの装備を確定した受信者判定で再送する。既存の設定変更時の再同期範囲は変更しない。
- 修正対象候補: `複数`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`
