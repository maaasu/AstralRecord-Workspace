## 指摘一覧

### AR-CODE-001 [中] 大きな基準値で離散候補が同じ保存値に丸まる
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/item/model/EquipmentStatRandom.java:67`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/item/service/ItemService.java:565`
- 根拠: `base=10000000000000000, offsetMin=-1, offsetMax=1, step=1` は有限・小数4桁以内・3候補という設計条件を満たし、`validateBase` も通る。しかし `sample` が BigDecimal 候補を `doubleValue()` に変換すると、`9999999999999999`・`10000000000000000`・`10000000000000001` のいずれも同じ double 値になる。
- 問題: 有効な定義でも離散候補の抽選結果が保存前に潰れ、仕様の一様な離散抽選と `min=max` の確定値が一致しない。
- 影響: 大きな基準値と小さい刻みを組み合わせた装備では、個体ごとの差が消える。マスター表示の範囲と実際の確定値も食い違う。
- 修正方針: 候補を BigDecimal のまま文字列化して個体へ保存する。既存の double 戻り値が必要な呼び出しがある場合は、表現可能性の検証と契約上の扱いを明示する。

- 修正可否: `自動修正可`
