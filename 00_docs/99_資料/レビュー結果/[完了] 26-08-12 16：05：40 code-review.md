### AR-CODE-001 [中] BOSS 部屋の状態遷移に旧契約が残っている

- 根拠: `32_3-処理契約.md` は BOSS 接続だけ START/NORMAL 全室 `CLEARED` 後に解放すると定め、実装も `DungeonBossGatePolicy.connectionsToUnlockAfterClear` で同条件を判定している。一方、対象箇所は親部屋の `CLEARED` だけで全子部屋を `AVAILABLE` にし、全ゲートを除去する契約として読める。

- 関連箇所: `00_docs/10_Plugin設計書/feature/28-player-interaction/28_0-概要.md:112`
- 根拠: `28_0-概要.md` の変更影響は feature 候補追加時に `28_3-サービス.md` を更新するよう定める。実装は `DungeonInteractionEventHandler` から RIGHT_CLICK の `WORLD_INTERACTION`、`stableOrder=DUNGEON_CONTROLLER`、`CLAIM_AND_CANCEL`、視線距離と実行直前 guard を持つ `dungeon-reward-chest` 候補を追加したが、interaction 正本の RIGHT_CLICK 候補責務・family 別候補契約・executor 境界に Dungeon 報酬がない。

### AR-CODE-003 [中] 報酬アクセスの実 eligibility と stale guard を回帰テストが固定していない
- 種別: `テスト不足`
- 対象: `10_plugin/AstralRecord/src/test/java/io/github/maaasu/astralRecord/feature/dungeon/event/DungeonInteractionEventHandlerTest.java:53`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/dungeon/service/DungeonService.java:966`
- 根拠: `32_3-処理契約.md` は ownership、現在参加者、クリア待機、同一 World、`rewardsByPlayer` の eligible 登録、CHEST Material、main hand、距離、遮蔽、実行直前の同一対象・視線再検証を契約にしている。追加テストは `findRewardChestTarget` の戻り値を mock し、eligible 負系も単に `null` を返させるため、`DungeonService.rewardSession` と CHEST 材質判定を通らない。正系 guard も同じ target が返り続ける場合だけである。
- 問題: 非参加者、別 World、未クリア・ending、非 CHEST、eligible key 不在を拒否する条件と、空報酬リストでも key があれば eligible とする条件、target・CHEST・視線が実行直前に失効した場合の executor 見送りが直接検証されていない。
- 影響: 報酬所有権の漏れ、空報酬プレイヤーのアクセス不能、CHEST 消失後や視線変更後の GUI 誤表示が将来混入しても既存テストが成功する。
- 修正方針: 必要なら eligibility 判定を副作用のない package-private policy へ分離し、ownership・参加状態・空報酬 key・World・Material・session 状態の境界を直接テストする。ハンドラには off hand 拒否と、target 変更・CHEST 消失・遮蔽変化で `executeIfValid()` が executor を呼ばない負系を追加する。
- 修正対象候補: `複数`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`
