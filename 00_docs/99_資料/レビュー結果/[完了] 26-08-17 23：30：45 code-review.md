### AR-CODE-001 [中] instanceType単独のentryを通常stackとして解決する
- 種別: `仕様不整合`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/inventory/service/InventoryItemStackResolver.java:55`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/inventory/service/InventoryService.java:5605`
- 根拠: `00_docs/20_API設計書/feature/13-inventory/1-モデル定義/13_1.00-モデル定義.md:80` は `instanceType` と `instanceId` を必ず対で指定し、通常 stack は個体情報を持たない契約です。Plugin の `isNormalItemEntry` と API の `IsNormalStackEntry` も、個体情報が残る entry を通常 stack から除外しています。
- 問題: `resolve` は `InventoryInstanceType.fromCode(entry.getInstanceType())` が成功しても `instanceId` が null の場合、個体経路を使わず `itemId` の通常 stack 経路へフォールバックします。そのため `itemId` 併記かつ `instanceType=EQUIPMENT`・`instanceId=null` の entry は Plugin では通常 ItemStack として表示・移動対象になり得ますが、Plugin/API の通常数量・支払い判定では通常 stack として扱われません。未知の `instanceType` と `instanceId` 併記でも同様に、`itemId` があれば通常 stack へフォールバックします。
- 影響: 不正または中間状態の entry で、表示される ItemStack と消費・移動・個体判定の意味が分岐し、個体情報を失った通常アイテムとして操作される可能性があります。正常な `instanceType + instanceId` の個体 entry と、両方空の通常 stack の既存経路には影響しません。
- 修正方針: `instanceType` または `instanceId` の片方だけが指定された場合、または未知の `instanceType` が指定された場合は通常 stack 経路へフォールバックせず null/不正 entry として扱い、正常な通常 stack は `instanceType` 空かつ `instanceId` null の場合だけ解決する。対応する境界テストを追加する。
- 修正対象候補: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/inventory/service/InventoryItemStackResolver.java, 10_plugin/AstralRecord/src/test/java/io/github/maaasu/astralRecord/feature/inventory/service/InventoryItemStackResolverTest.java`
