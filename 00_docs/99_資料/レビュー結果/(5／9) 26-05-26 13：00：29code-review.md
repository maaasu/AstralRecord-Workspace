### AR-CODE-002 [高] ショートカット設定 API 取得失敗時に例外で落ちる

- 確信度: 高
- 修正状態: 修正済み（fetchByAccountId の例外キャッチ → LogId.W_5601 警告ログ + defaults 返却）

- 根拠: 09_3.04 §3 手順 6「API 失敗時はローカル cache を `MenuShortcutSettings.defaults()` で上書きし、再リトライは行わない」、09_5.00 §3 にも同方針が記述され「次回 API 取得 / 再ログイン時に再同期させる」意図が明記されている。

- 確信度: 高
- 修正状態: 修正済み（Q-CODE-003 回答: 通知必要。putToApi 失敗時 → LogId.W_5602 + cache.put(defaults) + false 返却。handleShortcutActionSelectorClick 失敗時 → GuiSound.DENY + PlayerMsgId.P_5600 送信。設計書 09_5.00 へのユーザ通知仕様追記が必要 → $astralrecord-docs-fix へ引き継ぎ）

- 修正方針: 取得は非同期化（`runTaskAsynchronously` 内で実行し、結果反映だけ `runTask` で main へ戻す）するか、`AstPlayerCache` 拡張等で参加時に事前ロードして event 中は cache 取得のみに限定する。
- 修正可否: `要確認`
- 確信度: 高
- 修正状態: 修正済み（Q-CODE-002 回答: 非同期化。scheduleCraftShortcutRender を runTaskAsynchronously に変更し、findByAccountId を非同期スレッドで呼び出した後 runTask でメインに戻す。updateSlot は CompletableFuture.supplyAsync で非同期化済み）
