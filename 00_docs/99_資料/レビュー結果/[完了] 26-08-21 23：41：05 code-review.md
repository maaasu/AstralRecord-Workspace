### AR-CODE-001 [中] ログイン停止状態が表示・設計・実装で食い違う
- 種別: `ドキュメント不整合`
- 対象: `30_web/AstralRecordWeb/AstralRecordWeb/Pages/Login.cshtml.cs:16`
- 関連箇所: `00_docs/30_WEB設計書/feature/01-web-auth/3-画面仕様/01_3.01-ログイン画面.md:7`
- 根拠: ユーザー要件では公開サイトのログイン画面を操作不能にして未実装と案内することが確定しており、ルート `README.md` の Web ドキュメント運用は大きな導線・運用変更時に関連資料の更新を求めている。一方、Plugin は `/web` コマンドを登録してログインコード発行機能を保持している。
- 問題: Razor Page はフォームと POST の両方を常時無効化しているが、Web 認証設計書はコード受付、API 消費、Cookie 発行、`/MyPage` 遷移を現行動作として記載したままである。さらに画面は「ログインコードの発行」自体も利用できないと案内しており、現在も登録されている Plugin 側の発行機能と区別できていない。
- 影響: プレイヤーはゲーム内コード発行と Web ログインのどちらが停止中か判断できず、実装・運用担当もログインを利用可能と誤認してリリース判断や後続変更を誤る可能性がある。
- 修正方針: 画面文言を Web ログイン停止の案内へ限定し、Web 認証の概要・画面仕様・統合フロー・運用記載を「現在はフォームと POST を停止し、API 消費と Cookie 発行を行わない」という現行状態へ同期する。再開時に実装・画面・設計を同時更新する条件も関連資料へ明記する。

### AR-CODE-002 [中] ホームの初期画像転送量が約17.8 MiBある
- 種別: `パフォーマンス`
- 対象: `30_web/AstralRecordWeb/AstralRecordWeb/wwwroot/css/site.css:1166`
- 関連箇所: `30_web/AstralRecordWeb/AstralRecordWeb/wwwroot/css/site.css:1692`
- 根拠: 公開ページでは初期表示に必要な画像を表示寸法に合わせて圧縮し、モバイル回線での転送量とデコード負荷を抑えるのが一般的な Web パフォーマンス要件である。実測したファイルは `bg-town.png` が 2560x1440 / 8,668,519 bytes、`bg-sky.png` が 2560x1440 / 8,082,820 bytes、`icon.png` が 1254x1254 / 1,915,541 bytes だった。
- 問題: 新しいホームは CSS 背景として 2 枚のフル解像度 PNG を同じページから参照し、レイアウトとホーム内で大きな PNG アイコンも参照するため、キャッシュ前の画像転送量だけで約 17.8 MiB になる。表示幅 320px の確認でも同じ画像 URL が使用され、画面幅に応じた軽量版がない。
- 影響: モバイル回線でホームの初期表示と背景描画が大幅に遅れ、通信量・メモリ使用量・画像デコード負荷が増える。実際のユーザーへ公開するホームとして離脱や操作開始の遅延につながる。
- 修正方針: 表示品質を確認しながら背景とアイコンへ適切な寸法の WebP または AVIF を用意し、`image-set` やレスポンシブな画像指定で端末密度・画面幅に合う軽量版を配信する。PNG は必要なフォールバックに限定する。
- 修正対象候補: `複数`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-003 [中] ログイン停止のサーバ側防御に回帰テストがない
- 種別: `テスト不足`
- 対象: `30_web/AstralRecordWeb/AstralRecordWeb/Pages/Login.cshtml.cs:27`
- 関連箇所: `30_web/AstralRecordWeb/AstralRecordWeb/Pages/Login.cshtml:20`
- 根拠: ログイン停止は見た目だけでなく POST 経路でも API 消費と認証 Cookie 発行を防ぐ必要がある認証境界であり、ユーザー要件で明示された重要挙動である。一般的なセキュリティ回帰防止としてサーバ側の拒否を自動検証する必要がある。
- 問題: `LoginEnabled` と `OnPostAsync` 冒頭のガードは実装されているが、Web 配下にテストプロジェクトがなく、有効な CSRF トークン付き POST でも API を呼ばず、認証 Cookie を発行せず、未実装ページを返すことが恒久テストされていない。
- 影響: 将来フォーム表示やフラグ周辺を変更した際、UI だけが無効な状態またはサーバ側認証だけが意図せず復活する回帰をビルドで検知できない。
- 修正方針: `WebApplicationFactory` 等を用いた統合テストを追加し、有効な CSRF トークン付き `/Login` POST に対して認証 API 未呼出し、認証 Cookie 未発行、未実装案内を含む 200 応答を検証する。
- 修正対象候補: `30_web/AstralRecordWeb`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-004 [中] 公開規約ページがモバイルでも約8MiBのPNG背景を配信する
- 種別: `パフォーマンス`
- 対象: `30_web/AstralRecordWeb/AstralRecordWeb/Pages/Terms.cshtml:7`
- 関連箇所: `30_web/AstralRecordWeb/AstralRecordWeb/Pages/Privacy.cshtml:7`
- 根拠: 公開ページでは表示寸法に合う圧縮画像を配信して転送量とデコード負荷を抑えるのが一般的な Web パフォーマンス要件である。追加済みの `bg-sky-640.webp` は 32,110 bytes だが、`bg-sky.png` は 8,082,820 bytes あり、390px 幅の `/Terms` と `/Privacy` でも computed background は後者を固定参照することを実測した。
- 問題: ホームとログインにはデスクトップ・モバイル別の WebP 指定が追加された一方、利用規約とプライバシーポリシーは inline style で元のフル解像度 PNG を直接指定したままであり、追加した軽量画像へ切り替わらない。管理用の `Pages/Admin/Items.cshtml` も同じ固定指定を持つ。
- 影響: 公開ナビゲーションから規約またはプライバシーポリシーを初めて開いた利用者は、モバイルでもページ背景だけで約 8 MiB を転送・デコードする。ホームで解消した初期表示遅延と通信量の問題が公開サイト内の主要ページで再発する。
- 修正方針: 本文は変更せず、背景種別を表す CSS class へ inline 指定を置き換え、既存 PNG を fallback としつつ desktop/mobile 用 `image-set` で追加済み WebP を選択する。管理ページの town 背景にも同じ仕組みを適用する。
- 修正対象候補: `複数`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

- 関連箇所: `30_web/AstralRecordWeb/AstralRecordWeb/Pages/Index.cshtml:183`

- 問題: ヒーロー上部のボタンのアクセシブル名は表示テキスト由来の「コピー」だけであり、`aria-describedby` が参照する status も操作前は空である。同じページ下部にはサーバーアドレスを名前に含む別のコピーボタンがあるため、上部ボタンだけは何をコピーする操作か名前から判断できない。

- 修正方針: 上部ボタンへ `aria-label="Java版サーバーアドレスをコピー"` など対象を含む名前を付け、既存の live region による成功・失敗通知は維持する。
