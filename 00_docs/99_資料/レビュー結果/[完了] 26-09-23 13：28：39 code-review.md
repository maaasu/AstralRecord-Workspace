## 指摘一覧

### AR-CODE-001 [中] 復旧クリックがワールド操作に負けて hold session を残す
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/skill/event/SkillActionRingEventHandler.java:70`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/shared/interaction/InteractionTier.java:14, 10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/shared/interaction/PlayerInteractionGatewayEventHandler.java:452`
- 根拠: hold guard は helper により `InteractionTier.FALLBACK`（優先度100）で候補化されます。NPC・採集物・装置などの候補は `WORLD_INTERACTION`（優先度300）であり、dispatcher は高い tier を勝者にします。リング session が100 tickの選択期限で先に消えた場合、`closeActionRingForHigherPriorityWinner` も `actionRingOpen` が false のため hold session を取消しません。
- 問題: `RELEASE_USE_ITEM` 欠落後にリング表示だけが期限切れとなったプレイヤーが、ワールド上の対象へ右・左クリックすると、ワールド操作が実行され、`cancelAndClose` は実行されません。残留した hold session は次の解除パケット待ちのままとなり、同じ経路での復旧を繰り返し失敗します。
- 影響: 設計書が定める「新たな右・左クリックで待機とリングを閉じる」復旧契約を満たさず、復旧操作の対象位置によっては長押し選択を再び開けない状態が残ります。
- 修正方針: hold session がある右・左クリックの guard を、入力を占有できる `EXCLUSIVE_CONTEXT` tier で候補化する。既存の hotbar と同じく当該入力を消費し、hold session とリングを必ず取消す。
- 修正対象候補: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/skill/event/SkillActionRingEventHandler.java`
