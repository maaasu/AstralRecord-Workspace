## 指摘一覧

### AR-CODE-001 [中] 候補画面の表示とクリック時のフィルター値が再読込でずれる
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/item/event/ItemAdminGuiEventHandler.java:307`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/item/gui/ItemAdminGuiView.java:97; 10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/item/service/ItemService.java:167`
- 根拠: 候補 GUI は `openFilterSelection` に渡した `values` で slot を描画する一方、クリック時の `handleFilterOptionClick` は同じ slot を `availableCategories` / `availableRarities` の再評価結果で解決します。`ItemService#replaceMasterDataSnapshot` はロード済み item のスナップショットを置換するため、候補画面を開いてから item マスタの再読込または単体ロードで候補集合・ソート順が変わり得ます。
- 問題: 表示後に候補が追加・削除されると、クリックしたアイコンの値ではなく新しい候補リストの同じ index をフィルターへ設定します。たとえばカテゴリ `currency`, `material` を表示中に `bundle` が追加されると、画面上の slot 2 の `material` をクリックしても、再評価後 slot 2 の `currency` が適用されます。
- 影響: 管理者が選んだ表示上のカテゴリ・レア度と異なる一覧が開かれ、設計書が定める「候補をクリックして適用」と一致しません。
- 修正方針: 候補画面を開いた時点の不変な slot-to-value 対応を holder または画面単位 state に保持し、クリック時はその対応だけで選択値を解決する。合わせて、描画済みの上限を超える slot を選択対象にしない境界判定を対応表に集約する。
- 修正対象候補: `複数`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`
