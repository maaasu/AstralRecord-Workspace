### AR-CODE-001 [低] SQL Server専用の選択排他分岐を実DBで検証できない
- 種別: `テスト不足`
- 対象: `20_api/AstralRecordApi/AstralRecordApi/Repositories/SkillBindPresetRepository.cs:177`
- 関連箇所: `20_api/AstralRecordApi/AstralRecordApi.Tests/Repositories/SkillBindPresetRepositoryTests.cs:66`
- 根拠: SQLite単体テストは既存選択の解除と新しい選択の保存が2回に分かれることは検証するが、`Database.IsSqlServer()` 以下の `UPDLOCK, HOLDLOCK` とSQL Serverのフィルタ付き一意インデックスは実行しない。
- 問題: 今回追加したSQL Server専用分岐のSQL構文、ロック動作、並行選択後の一意性を自動検証できない。
- 影響: SQL Server固有のクエリまたはトランザクション制御が将来壊れても、SQLiteテストだけでは検出できない。
- 修正方針: 既存の任意実行型SQL Server統合テス基盤に合わせ、複数DbContextから同一アカウントの異なるプリセットを並行選択し、両リクエストが完了した後も選択中が1件であることを検証する。
- 修正対象候補: `20_api/AstralRecordApi/AstralRecordApi.Tests/Repositories/SkillBindPresetSqlServerIntegrationTests.cs`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-002 [低] 並行テストがアカウント単位の直列化を回帰検証できない
- 種別: `テスト不足`
- 対象: `20_api/AstralRecordApi/AstralRecordApi.Tests/Repositories/SkillBindPresetSqlServerIntegrationTests.cs:23`
- 関連箇所: `20_api/AstralRecordApi/AstralRecordApi/Repositories/SkillBindPresetRepository.cs:119`
- 根拠: 初期選択がプリセット1で、並行要求も1と2のため、片方は選択済み行の再保存になる。
- 問題: アカウントロックを除去しても、現在の条件では両方成功・最終選択1件になり得るため、テスト名の `SerializePerAccount` を保護できない。
- 影響: 将来アカウント排他が削除または無効化されても、SQL Server統合テストが偶然成功する可能性がある。
- 修正方針: プリセット1を初期選択とし、未選択のプリセット2と3を事前作成して、2と3を並行選択する。
- 修正対象候補: `20_api/AstralRecordApi/AstralRecordApi.Tests/Repositories/SkillBindPresetSqlServerIntegrationTests.cs`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`
