### AR-CODE-001 [低] BAN関連の通信・JSON例外が機能別ログに記録されない
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/user/repository/UserRepository.kt:123`
- 関連箇所: `00_docs/10_Plugin設計書/feature/01-user/3-メソッド仕様/01_3-リポジトリ.md:250`
- 根拠: 設計書は `findMcids` の非 `2xx` または JSON 変換失敗を `LogId.E_5061`、`updateBan` の非 `2xx` または通信・JSON変換失敗を `LogId.E_5062` で記録すると定義している。実装は非 `2xx` と `InterruptedException` だけを記録し、`HttpClient#send` の `IOException` と JSON 変換例外はログ記録なしで上位へ伝播する。
- 問題: API接続失敗や応答JSON不正時に、BAN機能固有の失敗ログが残らない。
- 影響: BAN更新・MCID補完の障害原因を `E_5061` / `E_5062` から追跡できず、運用時の切り分けが不完全になる。
- 修正方針: `findMcids` と `updateBan` で通信・JSON変換例外を対応する `LogId` と例外付きで記録してから再送出する。
- 修正対象候補: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/user/repository/UserRepository.kt`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

- 根拠: 現行の `BanCommandTest` は `CommandSender` モックで実行しており、`AstCommand` のコンソール許可経路しか検証していない。非ADMINプレイヤー拒否、ADMINプレイヤー許可、debugユーザーを管理者例外にしない仕様、`BanTabCompleter`、未来の `banDate` による接続拒否のテストがない。

### AR-CODE-003 [低] BAN実装後も旧仕様の記述が設計書に残っている
- 種別: `ドキュメント不整合`
- 対象: `00_docs/20_API設計書/feature/01-user/5-例外・ログ・運用/01_5.00-例外・ログ・運用.md:66`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/user/event/UserLoginEventHandler.java:34`
- 根拠: API設計書は `banDate` の運用を未確定として `01_9.00-未決事項` を参照しているが、同未決事項からBAN項目は削除され、更新系仕様で無期限時の `banDate=null` と期限付き更新が確定している。またPluginイベント設計書は、実装が `try/catch` に変更された後も例外処理を `runSafely` と記載している。APIユースケースにも呼び出し元を将来の `UserCommand` 系とする記述が残っている。
- 問題: 実装済みの `/ban` と確定済みの期限仕様に対して、未確定・将来実装を示す古い説明が残る。
- 影響: 運用担当や後続実装者が、BAN仕様が未実装・未確定だと誤認する。
- 修正方針: API例外・ユースケース、Pluginイベント設計書を現行の `BanCommand`、確定済み `banDate` 仕様、イベントハンドラの例外処理へ最小限同期する。
- 修正対象候補: `複数`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`
