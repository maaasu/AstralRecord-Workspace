### AR-CODE-001 [高] 移行を再実行すると新仕様の未受取売上まで削除される
- 種別: `バグ/アルゴリズム`
- 対象: `00_docs/40_Database設計書/table-definitions/AstralRecord/migrations/20260816_market_listing_settlement.sql:35`
- 関連箇所: `00_docs/40_Database設計書/table-definitions/AstralRecord/migrations/20260816_market_listing_settlement.sql:6、20_api/AstralRecordApi/AstralRecordApi/Repositories/MarketRepository.cs:492`
- 根拠: `remaining_quantity` の追加・旧値の初期化は `COL_LENGTH(...) IS NULL` の初回ブロック内ですが、`SOLD` と `CANCELED` の旧データ整理はその外側で毎回実行されます。新仕様では `SOLD` を売上受取まで残す一方、受取処理は Gold 加算と同時に `is_deleted = true` にします。
- 問題: この移行を二度目以降に実行すると、初回移行後に発生した未受取 `SOLD` も旧データとして論理削除されます。以後の受取 API は当該出品を取得できず、売上を払い出せません。
- 影響: 出品者の売上が失われ、未受取 `SOLD` が使用すべき出品枠も不正に解放されます。
- 修正方針: 旧 `SOLD` / `CANCELED` の変換を初回スキーマ変更時だけに限定するか、旧データだけを恒久的に識別できる移行履歴・条件を用いる。新しい `SOLD` を作成した後に同じ移行を再実行しても行が変化しない検証を追加する。
- 修正対象候補: `00_docs/40_Database設計書/table-definitions/AstralRecord/migrations/20260816_market_listing_settlement.sql`
- 修正可否: `自動修正可`

### AR-CODE-002 [高] 売上受取が確定結果不明後に再送できない
- 種別: `バグ/アルゴリズム`
- 対象: `20_api/AstralRecordApi/AstralRecordApi/Models/MarketModels.cs:113`
- 関連箇所: `20_api/AstralRecordApi/AstralRecordApi/Repositories/MarketRepository.cs:468、20_api/AstralRecordApi/AstralRecordApi/Repositories/MarketRepository.cs:497、10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/market/event/MarketGuiEventHandler.java:793、10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/inventory/service/InventorySaveCoordinator.java:311`
- 根拠: 新設の `MarketProceedsClaimRequest` に冪等キーがなく、受取成功時は売上を加算して同じ transaction 内で出品を論理削除します。再取得は `is_deleted = 0` に限定されるため、commit 後に HTTP 応答が失われた場合、同じ操作を再送しても 404 となります。保存 coordinator は外部 transaction の確定有無が不明な例外で、同一 operation ID の replay と再同期を前提にしています。
- 問題: Gold が既に加算済みでも Plugin は受取失敗として扱い、同じ受取結果・影響 inventory entry を取得して同期を完了できません。
- 影響: 売上は DB 上で加算済みにもかかわらず GUI とローカル所持金の同期が未完了になり、外部操作の未解決境界が残り得ます。再試行しても安全に復旧できません。
- 修正方針: claim request に安定した idempotency key を持たせ、出品削除後も売主とキーで受取結果（額・affected entry ID）を返せる永続的な receipt / replay 経路を追加する。Plugin は同じキーを保持して確定結果不明時に再送し、commit 後応答喪失の回帰テストを追加する。
- 修正対象候補: `20_api/AstralRecordApi/AstralRecordApi/Models/MarketModels.cs、20_api/AstralRecordApi/AstralRecordApi/Repositories/MarketRepository.cs、20_api/AstralRecordApi/AstralRecordApi/Data、00_docs/40_Database設計書/table-definitions/AstralRecord、10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/market`
- 修正可否: `要確認`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-003 [中] 取り下げ時の容量確認が保存 lane と原子的でない
