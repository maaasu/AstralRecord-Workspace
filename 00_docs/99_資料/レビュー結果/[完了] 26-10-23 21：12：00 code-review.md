### AR-CODE-001 [中] LF属性の追加だけでは既存checkoutのハッシュ不一致が残る
- 種別: `ドキュメント不整合`
- 対象: `60_tool/db-migrate/README.md`
- 関連箇所: `.gitattributes`
- 根拠: git check-attrはLFを返すが、既存SQLのgit ls-files --eolはi/lf w/crlfを示す。
- 問題: 属性の追加だけでは既存ファイルをLFへ書き戻さないため、現在の配布で同じハッシュ不一致が再発する。
- 影響: SQL内容と適用履歴が正しくても再実行が停止し、属性追加だけで解消したとの誤認につながる。
- 修正方針: 既存checkoutもGit原本と改行以外が一致し、ステージ済みSQL変更がないことを確認した上で原本バイトへ揃える手順を記載し、DEV-01で実施して履歴hash一致を再確認する。
