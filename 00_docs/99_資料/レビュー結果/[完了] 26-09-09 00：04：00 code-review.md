### AR-CODE-001 [中] 削除済み migration を manifest が参照して検証が停止する
- 種別: `バグ/アルゴリズム`
- 対象: `00_docs/40_Database設計書/table-definitions/AstralRecord/migrations/20260906_player_state_snapshot.sql`
- 関連箇所: `60_tool/db-migrate/db-migrate.config.json:57`
- 根拠: 差分で migration 本体が削除されている一方、manifest は同名ファイルを managed migration として保持する。`60_tool/db-migrate/Program.cs:157-187` は全 manifest entry の実ファイルを必須とし、`dotnet run --project 60_tool/db-migrate/DbMigrateTool.csproj -- --config 60_tool/db-migrate/db-migrate.config.json --validate-only` は `Migration file was not found` で失敗した。
- 問題: snapshot table は `init.sql` または `11-db-reset-except-release-notes.bat` で作成する完全移行方針なのに、migration manifest と一覧だけが削除前の経路を参照する。そのため migration tool の検証が停止する。
- 影響: `db-migrate` を使う配置前検証が FileNotFound で失敗し、運用者が削除済み migration 経路を選んでしまう。
- 修正方針: `db-migrate.config.json` から当該 managed migration entry を削除し、table-definitions の一覧も `init.sql` または `11-db-reset-except-release-notes.bat` を使う完全移行方針へ更新する。
- 修正対象候補: `60_tool/db-migrate/db-migrate.config.json, 00_docs/40_Database設計書/table-definitions/README.md`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-002 [中] チャンネル移動の ACK 待機中に account 切替が旧セッションを解放する
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/account/command/AccountSwitchCommand.java:140`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/network/NetworkBridgeService.java:168`
- 根拠: 移動中の guard は移動・inventory・drop・pickup・interact・hotbar event だけを取消すが、`AccountSwitchCommand` は transfer 状態を確認せず `prepareAccountSwitch` を実行する。同メソッドは `PlayerService.onPlayerQuit` へ進み、実行中の移動保存と並行して旧 session/cache を解放する。`00_docs/10_Plugin設計書/feature/03-player/3-メソッド仕様/03_3-保存.md:43` は移動成功まで runtime/cache を解放しないと規定する。
- 問題: `transferToLobby` の snapshot ACK 待機中に管理者が対象プレイヤーを `/account switch` すると、移動失敗後も旧セッションが維持される保証が崩れる。
- 影響: channel transfer と account switch が競合し、保存 lane の状態世代不一致、移動失敗、または不整合な session lifecycle を起こす。
- 修正方針: transfer 中の account switch を拒否するか、PlayerService/InventorySaveCoordinator に session transition の共通排他 gate を置き、ACK または接続失敗まで session 終了・切替を直列化する。
- 修正対象候補: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/account/command/AccountSwitchCommand.java`
- 修正可否: `要確認`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-003 [低] player setting の保存経路を仕様書が独立 API と誤記している
- 種別: `ドキュメント不整合`
- 対象: `00_docs/10_Plugin設計書/feature/03-player/3-メソッド仕様/03_3-保存.md:47`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/playersetting/service/PlayerSettingService.java:178`
- 根拠: 設計書は player setting が user 単位の独立 API を使うと記載するが、実装は `snapshotPlayerState` で `playerSettings` section を作成して保存 lane に渡す。API仕様も `00_docs/20_API設計書/feature/34-player-state/34_README.md:3` と `0-概要/34_0.00-概要.md:13-16` で snapshot 経由かつ個別 POST/PUT 非使用を正本としている。
- 問題: 同じ feature の設計書内で保存契約が矛盾し、将来の実装が旧個別 API 経路を再導入する判断材料になる。
- 影響: player setting と inventory などの原子保存境界を誤解した変更が入り得る。
- 修正方針: 独立 API とする記述を、user 所有を維持しつつ player-state snapshot の optional section として account lane から保存する現行契約へ更新する。
- 修正対象候補: `00_docs/10_Plugin設計書/feature/03-player/3-メソッド仕様/03_3-保存.md`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`
