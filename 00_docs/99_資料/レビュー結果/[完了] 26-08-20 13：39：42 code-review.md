### AR-CODE-001 [中] unmanaged Player 被弾時の最終イベント結果が combat 設計書と一致しない
- 種別: `ドキュメント不整合`
- 対象: `00_docs/10_Plugin設計書/feature/14-combat/14_2-ユースケース.md:33`
- 関連箇所: `00_docs/10_Plugin設計書/feature/14-combat/14_4-統合フロー.md:22、10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/player/event/PlayerVanillaDamageBlockEventHandler.java:49`
- 根拠: `DamageService` は attacker / victim とも unmanaged の `EntityDamageByEntityEvent` を変更せず返すが、被弾側が Player なら既存の `PlayerVanillaDamageBlockEventHandler` が `HIGHEST`・`ignoreCancelled = false` で `EntityDamageEvent` を受け、damage を `0` にしてキャンセルする。`EntityDamageByEntityEvent` は `EntityDamageEvent` の一種であり、キャッシュ外 Player にも同 handler が適用されることを `PlayerVanillaDamageBlockEventHandlerTest.cancelsVanillaDamageForPlayerOutsidePlayerCache` が検証している。
- 問題: 両文書は「両者 unmanaged なら event を変更しない」と最終結果のように記載しており、被弾側が Player の場合に後続の player handler でキャンセルされる経路を表していない。
- 影響: unmanaged Player への Bukkit ダメージが通ると保守者が誤認し、combat と player のイベント優先度や外部プラグインとの連携を誤って変更・判断するおそれがある。
- 修正方針: `CombatDamageEventHandler` / `DamageService` が局所的に event を変更しないことを明記し、被弾側が Player の場合は `PlayerVanillaDamageBlockEventHandler` が別途 damage `0`・cancel にする旨を `14_2-ユースケース.md` と `14_4-統合フロー.md` へ同期する。
- 修正対象候補: `複数`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`
