### AR-CODE-001 [中] unmanaged ダメージの統合フローが実装後の結果と矛盾する
- 種別: `ドキュメント不整合`
- 対象: `00_docs/10_Plugin設計書/feature/14-combat/14_4-統合フロー.md:22`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/combat/event/BukkitDamageBlockEventHandler.java:21`
- 根拠: `EntityDamageByEntityEvent` は `EntityDamageEvent` の一種であり、`CombatDamageEventHandler` が NORMAL で両者 unmanaged の event を変更せず返した後でも、追加 handler が HIGHEST で無条件に damage を 0 にしてキャンセルする。
- 問題: 統合フローは「両者 unmanaged」時に event を変更しないと記載したままで、追加された Bukkit ダメージ抑止を表現していない。
- 影響: 実際にはバニラ・外部プラグイン由来の unmanaged 同士のダメージもキャンセルされるのに、設計書を参照する保守者が未変更と誤認し、後続のイベント処理または仕様変更を誤って判断する。
- 修正方針: `BukkitDamageBlockEventHandler` を統合フローへ追加し、unmanaged 分岐を含む全 Bukkit `EntityDamageEvent` が最終的にキャンセルされることを明記する。
- 修正対象候補: `00_docs/10_Plugin設計書/feature/14-combat/14_4-統合フロー.md`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-002 [低] 事前キャンセル済み event を扱う登録契約がテストされていない
- 種別: `テスト不足`
- 対象: `10_plugin/AstralRecord/src/test/java/io/github/maaasu/astralRecord/feature/combat/event/BukkitDamageBlockEventHandlerTest.java:19`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/combat/event/BukkitDamageBlockEventHandler.java:21`
- 根拠: 設計書は事前キャンセル状態を問わず処理するため `priority = HIGHEST` と `ignoreCancelled = false` を契約として定めているが、追加テストは handler メソッドを直接呼ぶだけで annotation の値を検証していない。
- 問題: annotation の priority または `ignoreCancelled` が将来変更・欠落しても、既存テストは通過する。
- 影響: 事前キャンセル済み Bukkit event では handler 自体が呼ばれなくなり、設計上の「事前キャンセル状態を問わず無効化する」契約を回帰で失う。
- 修正方針: `onEntityDamage` の `EventHandler` annotation が `HIGHEST` および `ignoreCancelled = false` であることを反射で検証するテストを追加する。
- 修正対象候補: `10_plugin/AstralRecord/src/test/java/io/github/maaasu/astralRecord/feature/combat/event/BukkitDamageBlockEventHandlerTest.java`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-003 [中] management 外 Bukkit damage のユースケースが最終的なキャンセル結果と矛盾する
- 種別: `ドキュメント不整合`
- 対象: `00_docs/10_Plugin設計書/feature/14-combat/14_2-ユースケース.md:33`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/combat/event/BukkitDamageBlockEventHandler.java:21`
- 根拠: `BukkitDamageBlockEventHandler` は `EntityDamageEvent` 全体を `HIGHEST`・`ignoreCancelled = false` で damage 0・cancel にする。更新済みの `14_0-概要.md:42` と `14_4-統合フロー.md:30-38` も、その最終処理を明記している。
- 問題: ユースケースは「両者とも unmanaged なら event を変更しない」と記載したままで、`CombatDamageEventHandler` / `DamageService` の局所的な未変更と、続く全 Bukkit event の最終キャンセルを区別していない。
- 影響: 外部プラグインまたはバニラ由来の unmanaged 同士のダメージが通ると設計書読者が誤認し、互換性判断や後続の event 処理を誤る。
- 修正方針: `CombatDamageEventHandler` が両者 unmanaged の event をその場では変更しないことは維持したうえで、後続の `BukkitDamageBlockEventHandler` により最終的に cancel / damage 0 となる契約へユースケースを更新する。
- 修正対象候補: `00_docs/10_Plugin設計書/feature/14-combat/14_2-ユースケース.md`
- 修正可否: `自動修正可`
