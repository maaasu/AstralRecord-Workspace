### AR-CODE-001 [中] RECORDSカテゴリ共有により物理ジュークボックスを停止する
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/world/service/BaseMusicService.java:179`
- 関連箇所: `00_docs/10_Plugin設計書/feature/17-world/17_5-例外・ログ・運用.md:17`
- 根拠: `Player.stopSound(Sound, SoundCategory)` は指定した sound event を指定 category で停止する API であり、category だけを対象にする API ではない。実装は `BaseMusicTrack.values()` の5つのバニラ音楽ディスク sound event に対して `RECORDS` category で停止を送る。これらは物理ジュークボックスが再生する音源イベントと同じである。設計書も同じ音源の物理ジュークボックスへ影響し得ることを記載しているが、許容条件または回避方法は定義していない。
- 問題: `stopTrack` は `activeTracksByPlayer` に登録されたプラグイン再生だけを識別して停止するのではなく、プレイヤーの client 上で同じ sound event と `RECORDS` category で再生中の音をすべて停止する。次曲切替、BASE退出、設定 OFF、warmup 前、plugin 停止のいずれでも呼ばれるため、拠点音楽と無関係な物理ジュークボックスの再生まで停止する。
- 影響: `MUSIC` から `RECORDS` への変更で音量カテゴリは意図どおり共有される一方、対象プレイヤーが物理ジュークボックスの近くにいる場合、同じ5曲のいずれかを再生中のジュークボックスが途中で無音になる。プレイヤー単位の `BASE_MUSIC` OFF やワールド移動などの通常操作でも発生し、現行の Mockito テストでは client 上の外部音源との衝突を検証できない。
- 修正方針: 物理ジュークボックスの中断を許容するかを先に設計判断する。許容しない場合は、vanilla 音源イベントを `RECORDS` category で共有したまま source を区別できない制約を踏まえ、プラグイン再生と物理再生を識別できる音源・停止方式へ変更し、関連設計書と統合検証を更新する。許容する場合も、影響範囲を明示した受入条件と実サーバー確認を設計書へ追加する。
