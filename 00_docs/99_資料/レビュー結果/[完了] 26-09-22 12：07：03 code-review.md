### AR-CODE-001 [高] 同時Tab同期で新規entryを再び削除する
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecordProxy/src/main/java/io/github/maaasu/astralrecordproxy/AstralRecordProxyPlugin.java:919`
- 関連箇所: `10_plugin/AstralRecordProxy/src/main/java/io/github/maaasu/astralrecordproxy/AstralRecordProxyPlugin.java:278, 355, 937`
- 根拠: `refreshTabEntries` は接続完了時の即時呼出し、同イベントが登録する1秒後task、RPGメタデータ受信時、`tabRefreshSeconds` の定期taskから排他なしに実行される。各実行は独自に `proxy.getAllPlayers()` のスナップショットを取得してから `removeStaleTabEntries` を実行するため、古い実行Aが新規接続者を含まない集合を保持したまま、新しい実行Bがそのentryを追加した後にAが削除処理へ進むと、AはBが追加したentryを stale として削除する。
- 問題: 接続直後の欠落を復元するために増やした即時・遅延更新が互いに競合し、全体Tabのentryを再度欠落させる。これは修正対象の「総参加人数は多いがTabには自分だけ」の現象を周期更新まで再発させる。
- 影響: プレイヤー接続・backend切替・メタデータ到着が近接した場合、Tabの人数ヘッダーと一覧が不一致になり、一覧が最大で次の定期更新まで古い状態になる。
- 修正方針: TabListへの反映を単一の直列実行経路へ集約し、実行中の更新要求はフラグで1回だけ追走するなど、スナップショット取得からentry追加・削除までが同時実行されないようにする。接続時・メタデータ時はその直列化された更新要求だけを発行し、新規接続直後に古いスナップショットがentryを削除できないことを検証する回帰テストを追加する。
- 修正対象候補: `10_plugin/AstralRecordProxy/src/main/java/io/github/maaasu/astralrecordproxy/AstralRecordProxyPlugin.java`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

### AR-CODE-002 [中] 切断処理が進行中Tab同期と競合する
- 種別: `バグ/アルゴリズム`
- 対象: `10_plugin/AstralRecordProxy/src/main/java/io/github/maaasu/astralrecordproxy/AstralRecordProxyPlugin.java:318`
- 関連箇所: `10_plugin/AstralRecordProxy/src/main/java/io/github/maaasu/astralrecordproxy/AstralRecordProxyPlugin.java:919, 947`
- 根拠: `refreshTabEntries` は今回 `synchronized` 化されたが、`onDisconnect` は同じモニタを取得せずに `removeTabEntryFromAllViewers` を実行する。同期taskが切断直前の `connectedPlayers` スナップショットを取得した後、切断handlerがentryを削除し、その同期taskがsnapshot内の対象を `tabList.addEntry` へ進めば、削除済みentryを再追加できる。
- 問題: 接続・メタデータ・定期更新同士の競合は直列化された一方、切断時の即時削除はその直列化の外に残っている。切断済みプレイヤーがTabへ残留し、人数表示と一覧の最新性を損なう。
- 影響: 接続・切断が集中する状況では、切断したプレイヤーのentryが次の定期同期まで残り得る。今回の「常に最新の情報を表示」の要件を満たさない。
- 修正方針: entry削除もTab同期と同じ直列実行境界に入れ、スナップショットからのentry反映と並行しないようにする。切断削除と同期反映を意図的に交差させても切断済みentryが再追加されない回帰テストを追加する。
- 修正対象候補: `10_plugin/AstralRecordProxy/src/main/java/io/github/maaasu/astralrecordproxy/AstralRecordProxyPlugin.java`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`
