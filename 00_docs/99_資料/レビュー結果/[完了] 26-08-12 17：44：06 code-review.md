### AR-CODE-001 [中] 実詠唱 lifecycle を通る移動速度回帰テストがない
- 種別: `テスト不足`
- 対象: `10_plugin/AstralRecord/src/test/java/io/github/maaasu/astralRecord/feature/skill/service/SkillServiceDesignTest.java:334`
- 関連箇所: `10_plugin/AstralRecord/src/main/java/io/github/maaasu/astralRecord/feature/skill/service/SkillService.java:739`
- 根拠: 設計書は詠唱開始時の移動制限と、完了・中断、quit / death / world 変更時の cast と一時 modifier の破棄を active skill lifecycle の契約としている（`00_docs/10_Plugin設計書/feature/13-skill/3-メソッド仕様/13_3-サービス.md:5`、`00_docs/10_Plugin設計書/feature/13-skill/4-統合フロー/13_4-統合フロー.md:68,76`、`00_docs/10_Plugin設計書/feature/13-skill/13_5-例外・ログ・運用.md:48`）。実装は `beginCast` で modifier を適用し、`CastingSession.cleanup` を `finishCast` / `cancelCasting` から呼び出す構成になっている。
- 問題: 追加テスト `castMovementSpeedCleanupKeepsMovementSpeedChangedDuringCasting` は `SkillService.applyCastMovementSpeedModifier` と返却された `Runnable` を直接呼ぶだけで、実際の `beginCast`、`CastingSession` 登録、詠唱完了・条件中断・world / death / quit / plugin stop の cleanup 経路を通っていない。そのため、modifier の適用呼び出し忘れ、セッションへの cleanup 登録漏れ、実 lifecycle からの cleanup 呼び出し漏れがあってもテストが成功し、今回の「詠唱後に移動速度がリセットされる」回帰を実行経路として検出できない。
- 影響: 将来の詠唱 lifecycle 変更で移動速度 modifier が残留または未適用になっても検知できず、詠唱完了後の速度復元不具合や、world 移動・死亡・退出後の速度異常を再発させる可能性がある。既存の属性 modifier や status / condition による再計算との相互作用も保護されていない。
- 修正方針: MockBukkit の scheduler と実際の `castSkill` / `castLearnedSkill` 経路を使い、正の `castTimeTicks` で詠唱を開始している間に移動速度の base/status を変更し、正常完了後に cast modifier だけが除去され更新後の速度が残ることを検証する。併せて condition 中断または `ActiveSkillLifecycleService.clearTransient` / `clearAll` の代表経路で modifier が必ず除去されること、既存の別 modifier を保持することを確認する。
- 修正対象候補: `10_plugin/AstralRecord/src/test/java/io/github/maaasu/astralRecord/feature/skill/service/SkillServiceDesignTest.java`
