### AR-CODE-001 [中] メール到着通知の数量が配信先アカウントで変わる
- 種別: `バグ/アルゴリズム`
- 対象: `20_api/AstralRecordApi/AstralRecordApi/Repositories/DonationRepository.cs:181`
- 関連箇所: `20_api/AstralRecordApi/AstralRecordApi/Repositories/DonationRepository.cs:198`
- 根拠: 新規アカウントには過去の承認累計をまとめ、既存アカウントには承認ごとの差分をメール配信する。
- 問題: 本人共通のMailDelivered通知本文に、最初に配信されたアカウント別grant.Amountを入れている。
- 影響: 同じ累計到達額でも先に配信されたアカウントによって通知数量が変わり、別アカウントのメール数量と一致しない。
- 修正方針: 本人共通の配信通知本文からアカウント別数量を除き、数量は各メール本文に保持する。
- 修正対象候補: `20_api/AstralRecordApi/AstralRecordApi/Repositories/DonationRepository.cs`
- 修正可否: `自動修正可`
- 確信度: `高`
- 修正状態: `修正済み`

- 種別: `バグ/アルゴリズム`
- 対象: `20_api/AstralRecordApi/AstralRecordApi/Repositories/DonationRepository.cs:135`
- 関連箇所: `20_api/AstralRecordApi/AstralRecordApi/Data/Entities/DonationEntities.cs:53`
- 根拠: 今回の重複抑止は新規MailDelivered作成時に適用する。既存通知には申請ID・grant ID・累計到達額の相関キーがない。
- 問題: 更新前に保存された未ACKの重複通知は、APIがそのまま返す。
- 影響: 既存未ACK通知が残っている利用者は更新後の次回ログインでも重複表示され得る。
- 修正方針: 実DBで対象通知と承認・配布記録を監査し、別申請の通知を巻き込まない対象だけ整理する。相関キーのない一律の文字列一致削除は行わない。
