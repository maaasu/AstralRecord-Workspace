## 検証と受入範囲

`validate_lapis.py <worktree>` は全YAMLの重複キー・namespace ID、19予約ID、3セット、対応攻撃タグ、共有status/tag、乱数の精度/刻み/確率、強化段階、進化・素材・採集/モブdrop参照、shop配置案、胸の素材量、所有範囲を確認する。実行結果は `VALIDATION.txt`。数値根拠は `BALANCE_REPORT.md`。

重いMaven/dotnet/npm build、実サーバー操作、DB/ポート操作、push、develop統合、deployは実施しない。実機未確認は外見の持ち替え/攻撃表示、生成個体の保存復元、enchant/rune/進化画面、セット効果、採集と新モブの実配置・交換導線、職別スキルを含む実戦。共有ショップとrecipeが未登録のため、今回の装備YAMLだけでは新商品として購入できない。統合担当はmanifestから登録して導線を受け入れる。

武器7品 `20a00400〜20a00406` は装備featureの方針に従い、Mobドロップ時に武器専用Bundleへ梱包する。後続の共有統合担当は、最早入手がこの装備の進行段階に合う対象Mob・ドロップ確率を決め、ラピス武器専用Bundleとloot pool/tableの採番・登録・Mob接続を行う。既存エリヴァの `50a00003` 武器Bundleと `eriva_weapon_pool` は参考にするが、既存品を自動で置換しない。対象Mob・確率・新Bundle/loot IDは未決・未予約で、今回の編集範囲には含めない。ショップ/recipe登録と、この武器ドロップ導線の登録・実配置確認を別々の受入項目とする。防具12品は通常Enemyのドロップへ追加せず、基本の素材交換導線を使う。
