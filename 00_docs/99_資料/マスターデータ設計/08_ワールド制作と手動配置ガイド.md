# ワールド制作と手動配置ガイド

この文書は、AstralRecord の地域コンテンツについて、ユーザーが担当する実ワールド制作と稼働サーバー上の手動配置をまとめた作業手順です。

`40_filebase` のマスタ定義だけでは、実ワールドの地形、スポーン地点、Mob スポナー、採集スポナー、NPC、スキルツリーの座標は作成されません。Codex が担当する定義・実装作業と、ユーザーが Minecraft 上で確認して決める配置作業を、この文書の境界に従って接続します。

## 1. この文書で扱う範囲

### Codex が担当する作業

- world / mob / mob spawner / gathering / gathering spawner / NPC / shop / quest の filebase 定義を作成・修正する。
- アイテムの取得元と用途、ショップ、クエスト、報酬の参照を接続する。
- ワールド ID、`baseWorldPath`、推奨レベル帯、必要な配置 ID と配置条件を提示する。
- ユーザーから受け取った確定スポーン座標を world 定義へ反映する。
- 配置完了まで非公開にしていたクエストや地域導線を、確認後に再掲載する。
- filebase だけでは成立しない処理を Plugin に実装し、テストする。

### ユーザーが担当する作業

- Paper/Bukkit が読み込める実ワールドフォルダを作成し、建築する。
- 安全なスポーン地点と帰還リング周辺を用意し、座標と向きを確定する。
- 稼働サーバー上で Mob スポナー、採集スポナー、必要な NPC を手動配置する。
- 必要な場合だけ、専用ワールド上でスキルツリーのノード位置と接続を配置する。
- PLAYER モードで実際に移動、戦闘、採集、購入、受注、報告まで確認する。
- 配置座標と確認結果を Codex に返す。

### 現時点の制約

- 座標データは、稼働サーバーの `plugins/AstralRecord/*.yml` に保存され、リポジトリの `40_filebase` には含まれない。
- Plugin には、存在しない実ワールドを建築済みマップとして生成するコマンドはない。
- Mob / 採集スポナーには ID 単位の一括削除コマンドがない。不要座標の整理には現地操作またはサーバー停止中の配置 YAML 編集が必要になる。
- 不明な座標を仮置きしたまま quest board や本番導線を公開しない。

## 3. 今回すぐ必要な作業

### 3.1 配備前の確認

1. Codex 側の filebase / Plugin 修正が `develop` に取り込まれていることを確認する。
2. 通常の配備手順で、稼働サーバーへ Plugin と filebase を反映する。
3. quest / quest board を変更した配備では、Plugin またはサーバーを再起動し、起動時の一括ロードを完了させる。`/quest reload` コマンドは存在しない。
4. `mob_spawners.yml`、`gathering_spawners.yml`、`npc_locations.yml` をバックアップする。
5. 配置作業を行う自分のアカウントが管理操作可能であることを確認する。

管理配置を始めるときは、ゲーム内で次を実行します。

```text
/am ADMIN
```

`/am ADMIN` は管理権限を持つアカウントだけが実行できます。Mob / 採集スポナーは ADMIN モード中にはプレイヤー接近数へ算入されないため、出現確認時は後述のとおり PLAYER モードへ戻します。

### 3.2 旧 `goblin_training_spawner` 配置の清掃

旧配置先 `worlds/world_arcanum_city` は現在の稼働サーバーに存在しないため、現地でスポナーを狙って削除できません。次の手順で配置ファイルから清掃します。

1. サーバーを停止する。
2. `<server-root>\plugins\AstralRecord\mob_spawners.yml` を別名でバックアップする。
3. `spawners:` 配下から、`id: goblin_training_spawner` の4エントリだけを削除する。
4. `windwait_field_spawner` 21件と `windwait_patrol_spawner` 19件を削除していないことを確認する。
5. サーバーを起動する。
6. ゲーム内で次を実行し、定義と配置を再読込する。

```text
/mob load
/mob spawner reload
/mob spawner list
```

`/mob spawner list` の配置総数は、外縁スポナーを置く前なら40件です。外縁スポナー配置後は `40 + 今回置いた外縁スポナー数` になります。

サーバー起動中に `mob_spawners.yml` を直接編集すると、Plugin の保存処理で上書きされる可能性があります。停止中だけ編集してください。

### 3.3 `windwait_outer_spawner` の配置

このスポナーは `skyway_guard` と `glowlamp_watcher` を world time `12000-23999` の間だけ出現させます。半径は22mで、現行クエストは `skyway_guard` 2体と `glowlamp_watcher` 1体の討伐を要求します。

1. ADMIN モードで `greenfall_fields` へ移動する。
2. 定義と既存配置を再読込する。
3. 配置アイテムを受け取る。

```text
/am ADMIN
/world tp greenfall_fields
/mob load
/mob spawner reload
/mob spawner item windwait_outer_spawner 1
```

4. 草原外縁の、半径22m程度に歩ける地面が広がる場所を選ぶ。
5. 配置アイテムを手に持ち、登録したい足元ブロックへ通常のブロック設置操作を行う。
6. 成功メッセージを確認する。実ブロックの設置はキャンセルされ、その操作でブロックが置かれるはずだった座標だけが `mob_spawners.yml` に保存される。
7. 保存後の `mob_spawners.yml` で world / x / y / z を確認し、作業記録へ控える。

Mob の出現候補には、固体ブロックの上と、足元・頭上の2ブロック分が通過可能かつ非液体である空間が必要です。複層構造では、スポナー原点より下3ブロックから上方へも空間を探索するため、意図しない床や建物内に出現しないか確認してください。

最初は1か所で導線確認できます。追加数はマップの広さと実測した密度を見て決め、不明な座標をこの文書で固定しません。

### 3.4 外縁スポナーの動作確認

スポナーは近くに PLAYER モードのプレイヤーがいる場合だけ動作します。

```text
/am PLAYER
```

次を確認します。

- world time `12000-23999` の間に、配置地点の半径22m以内で待機する。
- `skyway_guard` と `glowlamp_watcher` の両方が出現する。
- 地中、屋根上、壁内、帰還リング内など、意図しない位置に出現しない。
- 敵が地形へ引っ掛からず、プレイヤーへ接近できる。
- 2体と1体を討伐できる程度の供給が継続する。

配置をやり直す場合は再度 ADMIN モードにし、表示される Mob スポナーを6m以内から左クリックします。Mob スポナーには ID 一括削除コマンドがないため、削除対象を目視してから操作してください。

```text
/am ADMIN
```

### 3.5 ショップとクエストの確認

`weapon_shopkeeper` と `village_elder` は拠点へ配置済みなので、新規配置は不要です。PLAYER モードで次を確認します。

- `weapon_shopkeeper` を右クリックし、`starter_pickaxe` と `starter_herb_hoe` を購入できる。
- 購入した `starter_herb_hoe` で `greenfall_fields` の採集物を取得できる。
- `village_elder` を右クリックし、現在公開中のクエストだけが quest board に表示される。
- `windwait_field_patrol` を受注し、配置済み `windwait_field_spawner` から出現する `windwait_stray` を3体倒して、`village_elder` へ報告できる。
- `windleaf_gathering` を受注し、`windleaf_patch` を2回採集して自動完了できる。

`windwait_outer_patrol` は、外縁スポナーの配置確認が終わるまで quest board から外しておく場合があります。配置と討伐確認が完了したら、ユーザーは結果と配置座標を Codex へ返してください。quest board への再掲載は Codex が filebase 側で行います。再掲載版を配備した後は Plugin またはサーバーを再起動し、PLAYER モードで外縁クエストの表示・受注・討伐・報告を再確認します。

## 4. 新しい地域ワールドを用意する手順

### 4.1 IDと制作ブリーフを先に確定する

建築を始める前に、Codex 側で少なくとも次を決めます。

- `world.id`
- 表示名と地域モチーフ
- レベル帯と想定人数
- `worldType`
- `baseWorldPath`
- `instanceRootPath`
- Mob / 採集スポナーの ID、半径、時間帯、足元ブロック条件
- 必要な NPC と機能
- プレイヤーが「到着、戦闘、採集、報酬、帰還」できる最低限の導線

先に ID を確定しないまま仮フォルダ名で建築すると、WorldMasterData と Bukkit ワールド名、保存済み配置の `world` が食い違います。

### 4.2 実ワールドフォルダを作る

Plugin は `baseWorldPath` に既存の `level.dat` がある場合だけワールドをロードします。新しいフィールドがオーバーワールドで、Codex が次の形のパスを指定した場合、サーバールートから見た同じ場所へ完全なワールドフォルダを用意します。

```text
plugins/AstralRecord/worlds/overworld/<world-id>
```

作業条件:

- Paper/Bukkit で一度正常に保存されたワールド一式である。
- `level.dat`、`region` など、利用するディメンションに必要なファイルを含む。
- 稼働サーバーへフォルダをコピー・置換するときは、原則としてサーバーを停止する。
- 既存ワールドを複製する場合は、Paper/Bukkit の複製手順に従い、ワールド UID の競合がない状態にする。
- `baseWorldPath` のフォルダ名を配置後に独断で変更しない。
- 元ワールドと配置ファイルを別の場所へバックアップする。

Plugin は、フォルダが存在しない場合に空の代替ワールドを自動生成しません。`/world tp <world-id>` が失敗した場合は、まず `baseWorldPath` と `level.dat` を確認します。

### 4.3 建築上の最低要件

#### スポーンと帰還地点

- スポーン座標の直下を固体ブロックにし、プレイヤーの足元と頭上を塞がない。
- 水、溶岩、焚き火、サボテン、奈落、落下直前の縁を避ける。
- スポーン中心から水平2m以内を、安全に立ってスニークできる場所にする。この範囲がオーバーワールドから拠点へ戻る帰還トリガーになる。
- 帰還判定は Y 座標を使わないため、リングと同じ X/Z 範囲の直上・直下に通路、建物の階、滞在エリアを作らない。上下階でスニークしても帰還が発動する。
- `showSpawnParticle: true` の場合に、リングと高さ2.25mの案内表示を視認できる空間を確保する。
- 帰還リングから戦闘・採集エリアへ迷わず出られる道を1本以上用意する。
- Mob スポナーの有効半径を帰還リングへ重ねない。
- スポーン地点から安全に離れられるまで、落下必須・跳躍必須・一方通行の地形にしない。

#### Mob エリア

- 各 Mob スポナー定義の `radiusMeters` 内に、固体地面と2ブロック分の非液体空間を十分に用意する。
- 遠距離敵には射線、近接敵には接近経路を用意する。
- 崖や奈落を使う場合も、出現直後に敵が落下し続ける配置にしない。
- 複層建築、洞窟、屋根がある場合は、各高さで意図しないスポーンが起きないか実測する。
- スポナー同士の半径を重ねる場合は、`maxNearbyMobs` により一方が止まらないか確認する。

#### 採集エリア

- 採集スポナーの `radiusMeters` 内で、最上面ブロックを定義の `requiredBaseBlocks` に合わせる。
- 採集物の出現位置は、その X/Z の最上面に決まるため、木の葉・屋根・人工物が上にある場所を避ける。
- 出現先の1ブロックを通過可能かつ非液体にする。
- 道具を購入または取得してから到達できる導線にする。
- 地形が条件を満たしていても、24回の候補探索で見つけられるだけの面積があるか実測する。

#### NPC エリア

- NPC の足元を平坦で安全にし、プレイヤーが正面から右クリックできる空間を用意する。
- NPC の向きは配置者の yaw / pitch を引き継ぐため、配置時に立ち位置と視線を合わせる。
- ショップ、quest board、帰還など、NPC の機能が見た目から判別できる建物または目印を用意する。
- 戦闘スポナーの範囲内へ、通常の町NPCを置かない。

### 4.4 スポーン座標をCodexへ返す

建築が終わったら、次を記録して Codex へ渡します。

```text
worldId:
baseWorldPath:
spawnLocation:
  x:
  y:
  z:
  yaw:
  pitch:
スポーン円の安全確認: OK / NG
拠点へのスニーク帰還確認: OK / NG
```

Codex がこの値を WorldMasterData へ反映するまで、仮座標の world 定義を本番導線へ公開しません。

### 4.5 ワールドを読込・検証する

WorldMasterData と実ワールドの両方がサーバーへ反映された後、ADMIN モードで次を実行します。

```text
/am ADMIN
/world reload
/world list
/world info <world-id>
/world tp <world-id>
/world loaded
```

確認内容:

- `/world info` の `baseWorldPath` と実フォルダが一致する。
- `/world tp` が失敗せず、確定したスポーン地点へ着く。
- 地面への埋まり、落下、窒息がない。
- スポーンリングと案内が正しい位置へ表示される。
- PLAYER モードでスポーン円内に立ってスニークすると拠点へ帰還できる。
- 拠点側のオーバーワールド選択 GUI に表示名、説明、推奨レベルが表示される。

`autoLoad: false` のワールドは、`/world reload` だけでは新規ロードされず、`/world tp <world-id>` の時点でオンデマンドロードされます。

## 5. 新地域へ手動配置する手順

### 5.1 マスタを再読込する

配備後に、変更したカテゴリだけを再読込します。

```text
/am ADMIN
/world reload
/mob load
/mob spawner reload
/mob npc reload
/gathering load
```

スキルツリーを変更した場合だけ、次も実行します。

```text
/skilltree reload
```

quest / quest board にはライブ再読込コマンドがありません。これらを変更した場合は、上記コマンドで代替せず、配備後に Plugin またはサーバーを再起動します。再起動後は PLAYER モードで対象 quest board を開き、掲載内容が新しい定義と一致することを確認します。

### 5.2 Mob スポナー

```text
/mob spawner item <mob-spawner-id> [amount]
```

ADMIN モードで配置対象ワールドへ移動し、Codex が提示したゾーン内で配置アイテムを使用します。配置ごとに world / x / y / z を記録してください。

配置後の確認:

```text
/mob spawner list
/am PLAYER
```

PLAYER モードで半径内へ入り、定義された時間帯、出現種、密度、地形適合を確認します。調整のためスポナーを消すときは、ADMIN モードで表示を6m以内から左クリックします。

### 5.3 採集スポナー

```text
/gathering spawner item <gathering-spawner-id> [amount]
```

配置アイテムを対象ブロックへ設置操作すると、その操作でブロックが置かれるはずだった座標が登録され、実ブロックの設置自体はキャンセルされます。採集スポナーは Mob スポナーと異なり、左クリック対象を探す管理表示による削除には対応していません。配置後に `gathering_spawners.yml` で正確な world / x / y / z を確認し、必ず記録してください。不要になった場合の確実な整理方法は、サーバー停止中に `gathering_spawners.yml` の該当エントリだけを削除する方法です。

確認:

```text
/gathering spawner list
/am PLAYER
```

PLAYER モードで半径内へ入り、要求された足元ブロック上に採集物が現れ、必要道具で採集でき、報酬アイテムが得られることを確認します。

### 5.4 NPC

配置地点に立ち、NPC を向かせたい方向を見てから実行します。

```text
/mob npc place <npc-id>
```

座標を明示する既存形式もありますが、向きはコマンド実行者の現在の yaw / pitch が使われます。現地で立って配置する方法を標準とします。

確認:

```text
/mob npc list
```

NPC を右クリックし、定義された SHOP / QUEST などの画面が開くことを確認します。

NPC を ID で削除する既存コマンドは次のとおりです。

```text
/mob npc remove <npc-id>
```

このコマンドは同じ ID の配置をすべて削除します。複数地点にいる NPC へは、バックアップと件数確認なしで使用しないでください。

### 5.5 スキルツリーは通常地域へ置かない

現在のスキルツリーは、専用ワールド `skill_tree` の `skilltree_structure.yml` に13位置・12接続が配置済みです。通常の新地域パッケージごとに複製する必要はありません。

専用ワールドやツリー構造を変更するよう Codex から明示された場合だけ、`skilltree_structure.yml` をバックアップして次を使います。

```text
/skilltree reload
/skilltree position-item <position-id> [amount]
/skilltree connector-item [amount]
```

- position item: 対象ブロック面を右クリックすると隣接座標へ位置を登録し、対象位置を左クリックすると削除する。
- connector item: 最初の位置を左クリックし、次の位置を右クリックすると接続を切り替える。
- 構造変更後は PLAYER モードで `/skilltree` に入り、全ノードの表示、接続、解放操作、`/skilltree back` を確認する。

## 6. Codexへ返す配置記録

新地域ごとに次の形式で返してください。座標が未確定の行は空欄にし、推測値を入れません。

```text
地域名 / worldId:
実ワールド配置日:
実ワールドフォルダ:
spawn: x=, y=, z=, yaw=, pitch=

Mob spawner:
- id=, world=, x=, y=, z=, 動作確認=OK/NG

Gathering spawner:
- id=, world=, x=, y=, z=, 必要道具=, 動作確認=OK/NG

NPC:
- id=, world=, x=, y=, z=, yaw=, pitch=, 右クリック確認=OK/NG

プレイ確認:
- 拠点から移動:
- スポーン安全性:
- スニーク帰還:
- Mob討伐とドロップ:
- 採集と報酬:
- ショップ購入:
- クエスト受注・進行・報告:

残っている問題:
```

Codex はこの報告を受けて、world の確定座標、quest board の掲載、説明文、配置依存の残事項を更新します。
