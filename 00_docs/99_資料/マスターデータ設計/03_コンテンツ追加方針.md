# コンテンツ追加方針

## 1. 基本方針

マスタは単品で増やすのではなく、小さなプレイ循環として増やす。

最小単位は次のいずれかにする。

- 敵を倒す、素材を拾う、消耗品や装備に使う。
- フィールドへ行く、敵に遭遇する、報酬を得る。
- クラスや装備の特徴を試す。

## 2. 初期オーバーワールドの追加単位

最初に作るべき単位は次の通り。

| Group | Count | Purpose |
|:--|--:|:--|
| Material | 3-5 | 敵ドロップ、後続レシピ、売却用 |
| Consumable | 1-2 | HP/MP 回復の基礎 |
| Equipment | 6-10 | 剣、弓、杖、基本防具 |
| Enemy | 3 | 近接、遠距離、少し硬い敵 |
| Loot pool/table | 2-4 | 共通素材と敵別報酬 |
| Spawner | 1-2 | フィールド配置用 |
| Shop | 任意 | 初期販売が必要な場合だけ |
| World | 任意 | 既存ワールドに追記が必要な場合だけ |

## 3. 作成順

1. 既存スキーマと既存 YAML を読む。
2. 追加する level band とエリアモチーフを決める。
3. 素材と消耗品を作る。
4. 装備を作る。
5. 敵を作る。
6. loot pool/table を作る。
7. spawner を作る。
8. 必要なら shop/world を更新する。
9. 参照と ID 重複を確認する。

## 4. ファイル命名

- 既存ディレクトリが `v1.<id>.yml` 形式なら同じ形式にする。
- ID は lowercase snake_case にする。
- デバッグ由来の `test`, `sample`, `lab` は本番向け追加では使わない。
- `starter` は初心者配布や初期販売の意味がある場合だけ使う。

## 5. 参照の考え方

- 敵が落とすものは、先に item を定義する。
- loot table が参照する pool は、先に pool を定義する。
- equipment が skill や set effect を参照する場合、参照先が存在するか確認する。
- Resource Pack の custom model が未整備なら、Bukkit Material の既存アイコンで成立させる。

## 6. 既存マスタとの関係

既存にはデバッグ用や検証用の定義が含まれる。新規本番向けマスタでは、既存をそのまま拡張するより、明確な production ID で追加する。

ただし、数値感、YAML 形式、ref の書き方、カテゴリ名、Material 名は既存に合わせる。
