# 命名規則と世界観メモ

## 1. 役割

この資料は、マスタ名と説明文の統一感を出すためのメモです。

プレイヤーに強制的に見せるストーリーや、厳密な世界史ではありません。

## 2. 採用する軽いモチーフ

| Motif | Usage |
|:--|:--|
| 星界 | ワールド全体、上位素材、UI 表現 |
| 記録 | AstralRecord の名前と相性がよい。古文書、記録片、航路図など |
| 空島 | 初期ワールド、フィールド、移動、風の表現 |
| 町と工房 | 初期装備、鍛冶、店、生活感 |
| 発光鉱石 | 素材、魔力、夜の視認性 |
| 古い航路 | フィールド名、探索導線、飛空艇モチーフ |

## 4. 名前のルール

- 表示名は短くする。
- 日本語名は 4-10 文字程度を基本にする。
- プレイヤーに表示される `name`、`displayName`、`title`、`label` は日本語で書く。
- 英語 ID は意味が推測できる lowercase snake_case にする。
- 過度に固有名詞化しない。
- 序盤装備は強そうすぎる名前にしない。

## 5. Lore のルール

- 1-2 行を基本にする。
- `description`、`lore`、メール本文、NPC のクリック時メッセージなど、プレイヤーに表示・送信される文章は日本語で書く。
- 性能と雰囲気を少しだけ伝える。
- シナリオ前提の固有事件は書かない。
- `&7` など既存の色コード表現に合わせる。

例:

```yaml
lore:
  - "&7浮島の外縁で採れる軽い繊維。"
  - "&7初歩的な装備の補修に使われる。"
```

## 6. 避けること

- 神話固有名を大量に使う。
- プレイヤーが知らない人物名を序盤アイテムへ付ける。
- 物語の結末や大事件を item lore に書く。
- デバッグ感のある `試作`, `テスト`, `検証用` を本番マスタへ入れる。
