# コンテンツ拡張手順書

この文書は、`40_filebase` の本番向けマスタデータを継続的に増やすための作業手順です。

目的は、単発の item や mob を思いつきで足すのではなく、ゲーム進行時間を伸ばす playable loop を小さく確実に積み上げることです。

## 1. 着手判断

迷った場合は、次の順に着手する。

| Priority | 着手対象 | 理由 |
|:--|:--|:--|
| 1 | 次のレベル帯のエリアパッケージ | プレイヤーの滞在時間と進行先を直接増やす |
| 2 | 既存エリアの報酬ループ補強 | 敵や採取があっても使い道が薄い状態を解消する |
| 3 | 装備更新と recipe / shop 導線 | 素材を集める意味と短期目標を作る |
| 4 | quest / quest board 導線 | 既存ループをプレイヤーに見つけやすくする |
| 5 | class / skill / buff 拡張 | 進行先と報酬が足りてからビルド幅を広げる |
| 6 | boss / dungeon 拡張 | 準備帯と報酬帯が揃ってから追加する |

原則として、最初に増やすべきものは単品のスキル、単品の高レア装備、単品のボスではない。まず、プレイヤーが「行く、戦う、拾う、作る、更新する、次へ向かう」流れを成立させる。

## 2. 1回の追加単位

1回の作業では、1つのレベル帯と1つのエリアモチーフに絞る。

推奨単位は次のどちらかにする。

| Unit | 目的 | 標準構成 |
|:--|:--|:--|
| Area package | 進行先を増やす | world 更新または既存 world 利用、enemy 3-5、material 4-8、equipment 4-8、consumable 1-2、loot pool/table 2-4、spawner 1-2、recipe/shop/quest は必要分 |
| Reward package | 既存エリアを厚くする | material 3-6、equipment 3-6、recipe 3-6、loot pool/table 更新、shop または quest 追加 |

作業量が大きい場合でも、1回で複数エリアや複数レベル帯を混ぜない。後続作業で同じ手順を繰り返す。

## 3. レベル帯ロードマップ

現状の filebase は初期帯が中心なので、まず level 1-8 を完成させ、その後は次の帯へ伸ばす。

| Phase | Level Band | 主な目的 | 完了条件 |
|:--|:--|:--|:--|
| 0 | 1-8 | 初期オーバーワールドの穴埋め | 通常敵、素材、初期装備、回復、loot、spawner、最低限の recipe / shop / quest が揃う |
| 1 | 9-15 | 2つ目のフィールド | 初期装備からの更新先、少し役割差のある敵、次エリア素材が揃う |
| 2 | 16-25 | 初級ダンジョン準備 | フィールド産素材、専用 recipe、ダンジョン前装備、強敵前の消耗品が揃う |
| 3 | 26-35 | 初級ダンジョン / 小ボス | 道中敵、ボス、専用 loot、周回報酬、交換または制作導線が揃う |
| 4 | 36-50 | 中盤入口 | クラス差が出る装備、複数エリア素材、反復できる金策と強化素材が揃う |

Phase 0 が未完了なら Phase 1 以降を優先しない。序盤が短い問題は、まず Phase 0 の可処分コンテンツを厚くしてから次帯へ進む。

## 4. 作業前の棚卸し

追加前に、対象レベル帯について次を確認する。

1. 既存の対象 YAML を読む。
   - `40_filebase/config.yml`
   - 対象カテゴリの `YAMLスキーマ定義.md`
   - 近い用途の既存 YAML 2-3 件
2. 既存 ID を検索する。
   - `rg "id: <candidate_id>" 40_filebase`
   - `rg "<candidate_id>" 40_filebase`
3. 参照先を確認する。
   - item を参照する mob / recipe / shop / loot
   - loot pool を参照する loot table
   - mob を参照する spawner
   - world / quest / shop からの導線
4. 不足カテゴリを判定する。

不足カテゴリの判定は次の表で行う。

| 状態 | 次に足すもの |
|:--|:--|
| world や spawner が薄い | enemy と spawner を先に作る |
| 敵はいるが報酬が薄い | material、loot pool/table、低確率装備を作る |
| 素材はあるが使い道が薄い | equipment、consumable、recipe、shop を作る |
| 報酬はあるがプレイヤーが気づきにくい | quest、quest_board、shop 表示を作る |
| 装備更新が止まる | 次レベル帯の weapon / armor / accessory を作る |
| 戦闘が単調 | enemy role、skill、buff を最小限だけ足す |

## 5. 作成順

新しいエリアパッケージは、必ず次の順に作る。

### 5.1 エリア定義

- level band を決める。
- エリアモチーフを1つに絞る。
- 既存 world を使うか、新規 world を作るか決める。
- `world` は配置や導線が決まっていない場合、無理に増やさない。

### 5.2 素材と消耗品

- material を 4-8 件作る。
- consumable は 1-2 件に留める。
- 通常素材、やや低確率素材、後続強化用素材を分ける。
- 先に item が存在しないと、mob / loot / recipe が参照できない。

### 5.3 装備

- weapon 2-3 件、防具 3-5 件、必要なら accessory 1 件程度を作る。
- 序盤から特殊効果を増やしすぎない。
- 既存 `StatusType.md` にない status は使わない。
- 新規 set effect は、装備単体の役割が固まってから追加する。

### 5.4 敵

- 通常敵は 3-5 体にする。
- 最低限、近接、遠距離、硬め、軽い特殊行動の役割を分ける。
- 1体ごとに drop 目的を持たせる。
- 敵の HP、防御、攻撃を同時に上げすぎない。

### 5.5 Loot

- pool を先に作り、table は pool を束ねる。
- 通常素材は高め、装備直ドロップは低め、後続素材は低確率にする。
- loot table が存在するだけでなく、敵や報酬導線から参照されていることを確認する。

### 5.6 Spawner

- enemy が揃ってから spawner を作る。
- 同時出現数、半径、再出現間隔は既存 spawner の値に寄せる。
- level band 内の敵だけを混ぜる。

### 5.7 Recipe / Shop / Quest

- recipe は素材の使い道を作るために追加する。
- shop は初期販売、交換、救済導線が必要な場合だけ追加する。
- quest は既存ループへ誘導する目的で追加する。
- quest を先に作って、未定義の item / mob / gathering を参照しない。

## 6. 完了条件

Area package は、次を満たしたら完了とする。

- プレイヤーが対象 world または既存 world 内の対象エリアへ行く理由がある。
- 3体以上の通常敵、または採取を含む代替行動がある。
- 敵や採取から得た素材に使い道がある。
- level band に合う装備更新先がある。
- loot pool/table と spawner の参照が解決している。
- 必要な recipe / shop / quest が最低限存在する。
- `test`, `sample`, `lab` を本番 ID に使っていない。
- lore は短く、強制ストーリーを前提にしていない。
- Plugin/API/Web/Resource Pack の追加実装が必要な箇所は残事項として明記している。

## 7. 追加作業の標準手順

実作業では次の順で進める。

1. 対象 phase と level band を決める。
2. `00_docs/99_資料/マスターデータ設計` の関連資料を読む。
3. 対象カテゴリの schema を読む。
4. 既存 YAML を読み、数値感と書式を合わせる。
5. 作る ID 一覧を先に決める。
6. item 系を作る。
7. mob / gathering 系を作る。
8. loot pool/table を作る。
9. spawner を作る。
10. recipe / shop / quest を必要分だけ作る。
11. 全参照を検索で確認する。
12. 追加 YAML をすべて読み返す。
13. 作った playable loop、参照関係、残事項を報告する。

## 8. 次回依頼テンプレート

新規エリアパッケージを作る場合:

```text
$astralrecord-code-version-commit-develop を使って、E:\AstralRecord-Workspace\40_filebase に level <min>-<max> の <area-name> 向け Area package を追加してください。enemy 3-5、material 4-8、equipment 4-8、loot pool/table、spawner、必要な recipe / shop / quest を含め、結果を報告してください。
```

既存エリアの報酬を厚くする場合:

```text
$astralrecord-code-version-commit-develop を使って、E:\AstralRecord-Workspace\40_filebase の <existing-area-id> 向け Reward package を追加してください。素材の使い道、装備更新、recipe、loot 参照を補強し、結果を報告してください。
```

手順だけを確認したい場合:

```text
E:\AstralRecord-Workspace\00_docs\99_資料\マスターデータ設計\07_コンテンツ拡張手順書.md に従って、次に追加すべき filebase マスタの候補を提案してください。まだ YAML は変更しないでください。
```

## 9. 次に着手すべき候補

現時点の優先候補は次の順にする。

1. Phase 0 の初期オーバーワールドを完成させる。
   - 既存の `windwait` / `greenfall_fields` 系の敵、素材、装備、loot、spawner、recipe、quest の参照を点検し、穴を埋める。
2. Phase 1 の level 9-15 フィールドを追加する。
   - 初期装備からの更新先、次素材、少し強い通常敵、spawner、loot をまとめて作る。
3. Phase 1 の recipe / shop / quest 導線を補強する。
   - 追加素材の使い道とプレイヤーへの提示を作る。
4. Phase 2 の初級ダンジョン準備帯を作る。
   - ダンジョン前装備、回復、対強敵用素材、導線 quest を作る。

この順番なら、単品マスタだけが増えてゲーム進行が伸びない状態を避けやすい。
