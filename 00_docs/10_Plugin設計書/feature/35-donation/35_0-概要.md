# 35_0-概要

## 目的

Web の寄付申請と審査結果を、ログイン中の本人へゲーム内で通知する。承認報酬は API が作成した期限なしメールから本人が手動で受け取る。

## 責務

- ログイン完了時とオンライン中2秒間隔で `GET /api/donations/notifications?user_uuid={userUuid}` を非同期取得する。
- API が返す `id`、`kind`、`amount`、`message` のうち `message` を装飾コードと制御文字を除去して `PlayerMessageService` で表示する。対応する `kind` は `Submitted`、`Approved` / `MailDelivered`、`Rejected` である。
- 表示後に `POST /api/donations/notifications/{id}/ack?user_uuid={userUuid}` を非同期実行する。API 障害時は次回監視で再試行し、ACK に失敗した通知を同一 Plugin 稼働中に重複表示しない。
- 有償アストラルドの item master `99a00021` は `CURRENCY`、`unTradeable=true`、`unSellable=true` とし、通常の Gold／既存アストラルドと別の item ID で扱う。トレード・マーケットの既存 `unTradeable` 判定を使う。

## 境界・不変条件

- 寄付申請、審査、通知本文、メール作成、メールの公開期限、受取可否の正本は API にある。Plugin は寄付金額や審査結果を確定しない。
- 通知 API の通信は Bukkit メインスレッドを待たせず、表示だけをメインスレッドへ戻す。停止後は新しい取得・表示を開始しない。
- 通知の ACK とメール報酬の受取は別操作である。メールの受取は既存の `mailClaim`、inventory、equipment の同一 player-state snapshot 契約を使う。
- 通貨保管庫と通常ストレージは account 単位の状態として管理する。有償通貨を他 account へ移す操作は許さない。アカウント複製時の有償通貨除外は API の責務とする。

## 依存・連携
