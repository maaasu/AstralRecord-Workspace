# 11_3-サービス

## 1. 設定一覧読込

クラス名: `PlayerSettingService`
物理名: `loadPlayerSettings`

全 key の既定 entry を生成し、`PlayerSettingRepository.findByUserId` の有効 row を key ごとに型変換して上書きする。不明 key は無視し、不正 JSON は `W_5311` を出して既定値を維持する。取得失敗時は `W_5310` を出し、既定値 snapshot を返す。

## 2. session 管理と warmup

クラス名: `PlayerSettingService`
物理名: `beginSession`, `captureSessionToken`, `warmup`, `clear`

- `beginSession` は user の token を更新する。
- `captureSessionToken` は現在 token を返す。
- `warmup` は設定を読み、token が一致する場合だけ cache へ登録する。
- `clear` は token を破棄する。未送信 key がない場合だけ cache も破棄し、未送信値がある場合は次の session warmup へ overlay できるよう保持する。

## 3. snapshot・設定参照

クラス名: `PlayerSettingService`
物理名: `getSnapshot`, `getPlayerSetting`

cache miss 時は既定値 snapshot を cache へ登録して返す。個別 key は entry がない場合も `PlayerSettingDefaults.resolveDefault` を返す。

## 4. 型別参照

クラス名: `PlayerSettingService`
物理名: `getParticleDensityScale`, `isDamageLogDisplayEnabled`, `isDropLogDisplayEnabled`, `isDamageLogMessageEnabled`, `isPerformanceInfoDisplayEnabled`, `isAutoSaveMessageEnabled`, `isArmorDisplayEnabled`, `isActionRingHoldSelectEnabled`

各 key を業務側が必要とする primitive 値へ変換する。型不整合時は key の既定値へ fallback する。`isArmorDisplayEnabled`、`isActionRingHoldSelectEnabled` はパケット・入力処理から使用するため cache のみを参照し、cache miss 時は API を呼ばない。

## 5. 設定更新

同一 user の設定更新は key が異なる場合も直列化し、cache は API 通信を待たず当該 key の新値へ置き換える。同一 user/key の連続更新は最後の値へ coalesce し、通信完了時は値を置き戻さず API ID/version metadata だけを merge する。更新後に session token が clear されても未送信値は破棄しない。

クラス名: `PlayerSettingService`
物理名: `updatePlayerSetting`

1. session token が現在値と異なれば `staleSession` を返す。
2. cache を直ちに新値へ更新し、user/key ごとの pending を最後の値で置換して非同期 delivery を予約する。
3. delivery は API ID がない key に `repository.create`、ある key に保持 version の `expectedVersion` を指定した `repository.update` を送る。
4. 成功時は ID/version metadata だけを更新し、captured delivery より新しい値がある場合もその値を維持する。
5. `409` は API の最新 model から ID/version metadata を取り込み、同じ最後の希望値を再送する。
6. 通信失敗は `W_5312` を出して dirty のまま user単位 `1`、`2`、`4`、…、最大`30`秒の指数backoffで自動再送する。更新操作の即時delivery要求はこの待機を短縮しない。成功ACKで失敗回数を解除し、`409` も最新ID/version metadata取得後に最低250ms待って再送する。logout 時は dirty を保持し、plugin disable 時は `flushPendingWrites` の async drain 完了を待ってから writer を停止する。
7. `PlayerSettingRepository` は `409` 以外のHTTP失敗を `IOException` 由来の例外へ統一するため、現契約では `400` / `401` / `403` の恒久失敗を区別できない。これらもdirtyを保持してbackoff再送する。恒久停止が必要になった時点で status を持つ共通例外へ置き換える。
8. shutdown drain は API送信前と失敗後に dirty 全量を `player-settings` の `PendingStateStore` へ atomic 保存する。通信失敗・競合反復上限では値を捨てず、次回login overlay用に残す。
9. delivery開始前に `<plugin-data>/player-settings/<userId>.bin` へ userごとの固定送信payloadを保存する。captureからatomic write/deleteまでを userごとの file-write lock で直列化し、ACK後も独立deleteせず最新pendingを再判定する同じ保存処理へ渡す。次回起動時はファイルを復元し、login warmupで取得したID/version metadataへ最後の希望値をoverlayして再送する。

## 6. 既定値解決

クラス名: `PlayerSettingDefaults`
物理名: `resolveDefault`

指定 key の `getDefaultValue()` を返す。
