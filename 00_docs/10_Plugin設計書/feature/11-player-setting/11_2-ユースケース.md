# 11_2-ユースケース

## 1. login 時に設定を warmup する

1. join した user の新しい session token を採番する。
2. API から user の設定行を非同期取得する。
3. 全 key の既定値へ取得済み row を重ねた snapshot を作る。
4. token が現在 session と一致する場合だけ cache へ登録する。
5. 同一 session の online player へ、`NIGHT_VISION` の設定値に応じた効果をメインスレッドで同期する。

## 2. コマンドから参照・変更する

1. `/setting` は secret key を除く全設定を cache から表示する。
2. `/setting gui` は設定 GUI を開く。
3. `/setting <key> <value>` は key と value を検証し、cache と dirty state を同期更新する。
4. プレイヤーへ直ちに反映結果を通知し、account の200ms集約保存を予約する。
5. `NIGHT_VISION` の更新成功時は、設定値に応じて無期限・粒子なしの暗視効果を付与または除去する。

## 3. GUI から変更する

1. クリック時は API を更新せず、player 単位の draft map だけを変更して再描画する。
2. GUI close 時に変更された key を cache と dirty state へ順次反映し、同一 account の保存要求を200ms内で集約する。
3. online かつ同一 session のローカル反映結果だけを通知する。
4. 管理者が secret slot 53 を連続 5 回押した場合だけ super mode を draft へ追加する。
5. `ARMOR_DISPLAY` のローカル反映後は本人の inventory と追跡中プレイヤーの防具を再送し、次の装備変更を待たず表示へ反映する。
6. `ACTION_RING_HOLD_SELECT` のローカル反映後は本人の inventory を再送し、選択中 hotbar 主武器だけをクライアント専用トライデント表示へ即時に切り替える。以後はホットバースロット切り替え時にも選択中 slot だけを更新する。
7. `NIGHT_VISION` のローカル反映成功時は、設定値に応じて無期限・粒子なしの暗視効果を付与または除去する。

## 4. 他 feature から参照する

各 feature は `getPlayerSetting` または型別 helper を同期呼び出しする。パケット送信スレッドから参照する `ARMOR_DISPLAY`、`ACTION_RING_HOLD_SELECT` は cache miss 時にそれぞれ既定値 `true` / `false` を直ちに返し、API I/O を発生させない。

## 5. logout する

quit 時に session token を除去する。SQL ACK 済みなら cache と account 対応も破棄し、dirty state が残る場合は logout 保存の section 作成と同一 Plugin プロセス内の再 login に備えて保持する。
