# 11_0-概要

## 1. 目的

player-setting feature は、user 単位の表示・通知設定をローカル cache へ即時反映し、player-state 完成スナップショットで SQL に永続化する。コマンドと GUI の双方から待機なしで変更でき、channel 移動時は SQL ACK 後にだけ状態を引き継ぐ。

## 2. 構成

| 層 | 実装 | 責務 |
|---|---|---|
| event | `PlayerSettingJoinEventHandler`, `PlayerSettingGuiEventHandler` | session warmup、cache 解放、GUI draft |
| command | `PlayerSettingCommand`, `PlayerSettingTabCompleter` | 一覧、GUI、key 更新 |
| gui | `PlayerSettingGui` | 設定表示と slot / user ID の識別 |
| service | `PlayerSettingService`, `PlayerSettingDefaults`, `PlayerSettingEffectService` | cache 参照、dirty state、`playerSettings` section、session token、設定由来の効果同期 |
| cache | `PlayerSettingCache` | user UUID ごとの不変 snapshot |
| repository | `PlayerSettingRepository` | login 時の API 一覧取得 |

## 3. 整合性方針

- cache miss や API 取得失敗時も全 key の既定値 snapshot を返す。
- 更新操作は cache の値を直ちに変更し、user/key ごとに最後の dirty revision を保持して account の200ms集約保存を予約する。
- `playerSettings` section は全 key の ID、値、保存済み `expectedVersion` を含む完成状態として、inventory 等と同じ SQL transaction で保存する。
- ACK は捕捉 revision と全 key を照合し、`userSettingId` と `version` の metadata だけを cache へ反映する。捕捉後の新しい値は維持する。
- join ごとに session token を更新し、前 session の読込 callback で再ログイン後の cache を上書きしない。未 ACK 値と account 対応は logout 後も保持する。
- channel 移動は通常 save lane の境界保存で `playerSettings` を含む全 dirty state の SQL ACK を待ち、失敗時は現在の channel に残す。

## 4. 依存・連携

- `user` / `player`: user UUID、online session、join / quit lifecycle、管理者権限、`NIGHT_VISION` 効果の同期を利用する。
- `menu`: 設定 GUI の入口、共通 navigation、hotbar shortcut click support を利用する。
- `hud`: `PERFORMANCE_INFO_DISPLAY` を sidebar / tab list、`BUFF_SIDEBAR_DISPLAY` を有効バフ欄へ反映する。
- `combat`: damage log の表示可否を参照する。
- `loot` / `particle` / `temp-block`: drop log、particle 密度、temporary display の表示可否を参照する。
- `inventory`: `AUTO_SAVE_MESSAGE` を autosave 通知へ反映する。
- `item`: `ARMOR_DISPLAY` を受信者本人と受信者が追跡中の他プレイヤーの防具レイヤー表示へ反映する。
- `skill`: `ACTION_RING_HOLD_SELECT` を action ring の入力方式と、本人の選択中主武器だけをクライアント専用トライデントとして送る表示方式へ反映する。右クリック開始前から使用種別を同期するため、リング開閉中に限定しない。
- `skilltree`: `SKILL_TREE_COMPACT_DISPLAY` をワールド上のノードラベル情報量へ反映する。
- AstralRecordApi `/api/player-setting`: login 時に user 単位の設定を取得する。
- AstralRecordApi `/api/player-state/snapshots`: `playerSettings` 完成状態を version 検証付きで永続化する。
