# 11_2.00-ユースケース

## 1. login 時に設定を warmup する

1. join した user の新しい session token を採番する。
2. API から user の設定行を非同期取得する。
3. 全 key の既定値へ取得済み row を重ねた snapshot を作る。
4. token が現在 session と一致する場合だけ cache へ登録する。

## 2. コマンドから参照・変更する

1. `/setting` は secret key を除く全設定を cache から表示する。
2. `/setting gui` は設定 GUI を開く。
3. `/setting <key> <value>` は key と value を検証し、非同期で API を作成または更新する。
4. 完了時はメインスレッドへ戻り、成功・競合・失敗を通知する。

## 3. GUI から変更する

1. クリック時は API を更新せず、player 単位の draft map だけを変更して再描画する。
2. GUI close 時に変更された key を非同期で順次永続化する。
3. online かつ同一 session の完了結果だけを通知する。
4. 管理者が secret slot 53 を連続 5 回押した場合だけ super mode を draft へ追加する。

## 4. 他 feature から参照する

各 feature は `getPlayerSetting` または型別 helper を同期呼び出しする。cache miss の場合は既定値 snapshot が使用され、表示処理から API I/O を発生させない。

## 5. logout する

quit 時に cache と session token を除去し、旧 session の非同期完了を stale として無視できる状態にする。
