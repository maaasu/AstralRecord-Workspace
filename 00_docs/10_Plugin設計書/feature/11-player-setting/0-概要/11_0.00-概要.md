# 11_0.00-概要

## 1. 目的

player-setting feature は、user 単位の表示・通知設定を API に永続化し、online 中は snapshot cache から同期参照できるようにする。コマンドと GUI の双方から変更でき、API version を使った楽観ロック競合を解決する。

## 2. 構成

| 層 | 実装 | 責務 |
|---|---|---|
| event | `PlayerSettingJoinEventHandler`, `PlayerSettingGuiEventHandler` | session warmup、cache 解放、GUI draft |
| command | `PlayerSettingCommand`, `PlayerSettingTabCompleter` | 一覧、GUI、key 更新 |
| gui | `PlayerSettingGui` | 設定表示と slot / user ID の識別 |
| service | `PlayerSettingService`, `PlayerSettingDefaults` | snapshot 構築、参照、更新、session token |
| cache | `PlayerSettingCache` | user UUID ごとの不変 snapshot |
| repository | `PlayerSettingRepository` | API の一覧取得・作成・更新 |

## 3. 整合性方針

- cache miss や API 取得失敗時も全 key の既定値 snapshot を返す。
- 更新は entry の version を `expectedVersion` として送る。
- `409 Conflict` は API の最新 model を cache へ反映し、player に同期結果を通知する。
- join ごとに session token を更新し、前 session の非同期完了で再ログイン後の cache を上書きしない。
