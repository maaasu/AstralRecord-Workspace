## 3. 例外方針

- load / parse 失敗は既定値へ fallback し、参照側を停止しない。
- repository の `InterruptedException` は interrupt flag を復元して失敗として伝播する。
- GUI / command は local cache の反映だけを同期実行し、stale session では変更しない。
- snapshot の version conflict、不完全 ACK、恒久的なHTTP失敗は共通 player-state 保存失敗として扱う。
- 通常保存の一時障害では dirty state と捕捉 snapshot を保持する。channel 移動時に ACK を確認できなければ移動を中止し、共通の失敗メッセージを表示する。

## 4. 運用方針

- key 追加時は enum、default、API 許容値、command 補完、必要な GUI slot、利用 feature を同時に更新する。
- API row が存在しないことと設定値 `false` / `OFF` を区別する。
- online 中の表示値は cache を参照し、永続化の確定は `playerSettings` section の SQL ACK で判定する。
- pending 設定をローカルファイルへ保存しない。logout 後も未 ACK state と account 対応を同一 Plugin プロセス内で保持する。
