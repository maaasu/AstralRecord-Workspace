# 11_1-モデル定義

## 1. プレイヤー設定モデル

物理名: `PlayerSettingModel`

`userSettingId`、`userId`、`settingKey`、JSON 文字列 `settingValueJson`、optimistic lock 用 `version`、作成・更新日時、作成者・更新者、論理削除 flag を保持する API model。

## 2. snapshot と entry

物理名: `PlayerSettingSnapshot`、`PlayerSettingEntry`

snapshot は user UUID と `Map<PlayerSettingKey, PlayerSettingEntry>` の不変な時点値を保持する。entry は API ID、型変換済み value、version を保持する。API に行がない key は ID / version を持たない既定値 entry とする。

## 3. 設定 key

物理名: `PlayerSettingKey`

| key | 型 | 既定値 | GUI slot |
|---|---|---|---:|
| `DAMAGE_LOG_DISPLAY` | boolean | `true` | 20 |
| `DAMAGE_LOG_MESSAGE` | boolean | `false` | 21 |
| `PARTICLE_DENSITY` | `ParticleDensity` | `NORMAL` | 22 |
| `PERFORMANCE_INFO_DISPLAY` | boolean | `false` | 23 |
| `COMBAT_DPS_DISPLAY` | boolean | `true` | 40 |
| `DROP_LOG_DISPLAY` | boolean | `true` | 24 |
| `AUTO_SAVE_MESSAGE` | boolean | `false` | 29 |
| `GUIDE_REMINDER` | boolean | `true` | 41 |
| `BUFF_SIDEBAR_DISPLAY` | boolean | `false` | 30 |
| `ARMOR_DISPLAY` | boolean | `true` | 31 |
| `ACTION_RING_HOLD_SELECT` | boolean | `false` | 32 |
| `SKILL_TREE_COMPACT_DISPLAY` | boolean | `false` | 33 |
| `NIGHT_VISION` | boolean | `false` | 38 |
| `RANDOM_STATUS_RANGE_DISPLAY` | boolean | `false` | 39 |
| `TEMP_DROP_DISPLAY` | boolean | `true` | GUI なし |
| `TEMP_BLOCK_DISPLAY` | boolean | `true` | GUI なし |
| `ADVENTURE_RECORD_SUPER_MODE` | boolean | `false` | 管理者用 secret slot 53 |
| `SPAWNER_VISUAL_MODE` | `MobSpawnerVisualMode` | `NORMAL` | GUI なし（管理者モード本人のコマンド） |

boolean の入力は `on` / `true`、`off` / `false` を受理する。key 入力は `-` を `_` へ正規化して大文字比較する。

`SPAWNER_VISUAL_MODE` は `NORMAL`（通常）、`LIGHT`（軽量）、`OFF`（非表示）を受理する。Mob・採集スポナー共通の管理表示設定であり、`dbo.user_setting` の user UUID に紐づき全チャンネル・全アカウントで共有する。JSON は `{"value":"NORMAL"}` 形式で保存し、未登録・不正値の既定は `NORMAL`。表示処理は cache のみを参照し、初期読込前は `OFF` とする。Player PDC の旧設定は参照・移行しない。

`DROP_LOG_DISPLAY` は Mob の通常・レアドロップと採集アイテムの全体通知を受け取るかを制御する。既定値は `true`。

`GUIDE_REMINDER`（定期ガイド通知）は、10分ごとのガイド画面への導線と次の未完了手順の通知をまとめて切り替える。達成直後の次手順案内・全達成報酬通知には適用しない。既定値と未読込・型不正時の値は `true`。ユーザー単位の既存 `playerSettings` 保存経路で永続化し、API・DBスキーマは変更しない。

`COMBAT_DPS_DISPLAY` は戦闘アクションバーのDPS表示だけを切り替える。既定値と未読込・型不正時の値は `true` とし、従来のDPS表示を維持する。HUDはロード済みcacheだけを参照する。既存の任意設定キー・JSON値を保存するAPIと `dbo.user_setting` を利用し、API・DBスキーマは変更しない。

`RANDOM_STATUS_RANGE_DISPLAY`（ランダムステータス範囲表示）は、装備ステータス直下の灰色の乱数範囲行だけを受信者ごとに表示・非表示にする。インベントリ、アイテム共有チャットとドロップ通知のホバーへ適用し、確定済みのステータス値・強化値・通常の説明文は維持する。ロード済み cache だけを参照し、未読込時は `false` を返す。API・DB は任意の設定キーと JSON 値を保存する既存経路を使用し、スキーマ変更は不要。

## 4. particle 密度

物理名: `ParticleDensity`

| 値 | 表示名 | scale |
|---|---|---:|
| `OFF` | 非表示 | 0.0 |
| `VERY_LOW` | とても少ない | 0.25 |
| `LOW` | 少ない | 0.5 |
| `NORMAL` | 標準 | 1.0 |
| `HIGH` | 多い | 1.5 |
| `VERY_HIGH` | とても多い | 2.0 |

粒子表示は `ParticleDisplayService` を共通入口とし、表示を受け取るプレイヤーの密度を使う。

- 線・円・円弧・魔法陣などの点群は、最大密度用の候補点から `scale / 2` の割合で均等に地点を選ぶ。標準は候補の約半数、とても多いは全候補とし、密度を上げるほど点間隔を狭める。形状生成側は標準時の点数の2倍を目安に候補を用意する。
- 任意の点群を補間して異なる部品同士をつなげない。複数パーツは各パーツの点を連続して並べ、同じ座標は向きに関係なく一回だけ描画する。
- 点群の非表示以外の採用数は最低1点、上限4096点とする。拡散・移動速度がともに0の定義は、密度によらず各地点へ1粒だけ表示する。
- 複数の敵中心・独立した火花など、意味を持つ発生源の集合は `spawnBurstsForNearbyViewers` で一括送信する。地点数は間引かず、各発生源へ単発演出の密度を適用する。
- 単発の散布・着弾演出は散布個数へ倍率を適用し、端数は確率的に表示する。固定された単一点は重複を増やさず、低密度では表示頻度を抑える。
- `OFF` はすべてのプラグイン粒子を表示しない。近傍表示は各閲覧者から64m以内の候補を先に抽出してから密度を適用し、異なるworldの地点は送信しない。


## 5. 変更要求と更新結果

物理名: `PlayerSettingChangeRequest`、`PlayerSettingService.UpdateResult`

変更要求は `userId`、key、型変換済み value、更新者 UUID を保持する。更新結果は成功、optimistic lock conflict、stale session を区別し、conflict 時は最新 model と通知メッセージを保持する。

## 6. 既定値と cache

物理名: `PlayerSettingDefaults`、`PlayerSettingCache`

既定値は `PlayerSettingKey.getDefaultValue()` を正本とする。cache は user UUID ごとの `PlayerSettingSnapshot` を保持し、mutable model を外部へ公開しない。
