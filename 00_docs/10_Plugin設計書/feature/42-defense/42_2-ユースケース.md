# 42_2-ユースケース

## 受付と開始

プレイヤーは `/defense join` で接続中チャンネルの受付に登録し、`/defense leave` で退出、`/defense status` で現在の防衛レベル・登録人数・確定人数を確認する。`/defense help` は使い方を表示し、引数なしはstatusとする。死亡中、通常プレイ以外のアカウント、既存挑戦との予約競合、設定不足、満員、受付締切後は参加させない。受付の上限は30人。

Web管理者はチャンネルごとのJST日次時刻と必要な調整値を設定し、即時開始・停止を操作する。APIは同一チャンネルの開催を一つに制限し、手動開始は直近30秒以内のPlugin受付報告がOPENかつ1人以上の場合だけ受け付ける。日次は設定された開始時刻の `registrationLeadSeconds` 前に `PENDING` を発行する。Pluginは既存ワールド、中央・入場・召喚地点、適格Mob、参加者の入場成立を確認する。手動開催は準備完了後、日次開催は定刻以降に `STARTED` を報告して戦闘に移る。転送に失敗した参加者は確定人数に含めず、誰も入場できなければ中断する。

## 戦闘と個人状態

中央の防衛対象が破壊されるまで時間と防衛レベルを進める。敵は防衛対象へ進軍し、挑発者を優先する。参加者に攻撃された敵は設定時間・距離内で反撃し、条件が切れれば中央へ戻る。敵の召喚は設定間隔と波・tick・同時生存上限を守り、上限超過分を次波へ繰り越さない。

1・2回目の死亡は15秒後に入場地点へ自動復活する。HP・MP・ENGは全快、経験値ペナルティは適用しない。シールドは設定の `EMPTY` / `FULL` に従い、設定秒数だけ復活保護を付ける。3回目も15秒の蘇生可能時間を設け、その間に既存蘇生スキルが成功すれば今回の死亡1回を取り消す。蘇生しなければ15秒後に脱落・帰還する。切断しても死亡回数は維持する。

本人が復帰猶予内に同じアカウントで戻る場合だけ、元の参加状態を保って入場地点へ再転送する。自己退出、脱落、猶予超過後は戦闘へ戻さない。全員脱落・切断しても戦闘は続き、防衛対象の破壊か管理停止・障害を終了条件とする。

## 到達段階と帰還

`N = rewardEveryLevels` として、Lv.`N, 2N, 3N, ...` の到達時だけ、その瞬間に戦闘中・非AFK・非脱落・必要活動秒数以上の参加者について報酬を要求する。切断、蘇生待ち、脱落、AFK中の段階は後から付与しない。APIは固定参加者、到達レベル、活動秒数、AFK状態を検証し、その段階以下で最も高い `rewardTiers.requiredDefenseLevel` のオーブを確定する。確定済み段階は敗北・切断・所持品満杯で失われない。別チャンネルの後続開催にも参加でき、全チャンネル共通の日次受取制限はない。

終了・中断時は敵、防衛対象、BossBar、チャンク保持を回収し、参加者を保存した帰還元へ戻す。APIへの報告・報酬保存が失敗した場合はローカルoutboxに残し、通信復旧後に再送する。
