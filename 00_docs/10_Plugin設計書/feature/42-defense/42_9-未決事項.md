# 42_9-未決事項

## 運営設定で決める調整値

以下の値は設計書で固定しない。Webでチャンネル別に設定し、APIとPluginの検証を通過して初めて開始可能になる。値が空欄・不正なら不足項目を表示し、開催を拒否する。Lv.1開始・30秒ごと+1、死亡3回上限と15秒の蘇生猶予、最大30人、1～10人の人数倍率1は確定済み仕様であり、本書の判断待ちには含めない。

| 領域 | 必須設定 |
|:--|:--|
| ワールド・位置 | 既存`worldName`、`coreX/Y/Z`、`entryX/Y/Z`、1点以上の`spawnPoints` |
| 防衛対象 | `coreMaxHealth`、`coreDefense` |
| 増援と上限 | `baseSpawnCount`、`spawnIntervalSeconds`、`maxSpawnsPerWave`、`maxSpawnsPerTick`、`maxAliveEnemies` |
| 戦闘と難化 | `retaliationSeconds`、`retaliationRange`、`playerSpawnCoefficient`、`playerHealthCoefficient`、`playerDamageCoefficient`、`postMaxLevelHealthCoefficient`、`postMaxLevelDamageCoefficient` |
| 受付・復帰・復活 | `registrationLeadSeconds`、`reconnectGraceSeconds`、`reviveProtectionSeconds`、`reviveShieldMode`（`EMPTY` / `FULL`） |
| 報酬 | `rewardEveryLevels`、`minimumActiveSeconds`、1段階以上の`rewardTiers`（各`requiredDefenseLevel`、既存orbの`orbItemId`、`orbQuantity`） |

数値を設定する際は、Mobの登録レベル分布、30人時の同時生存数とtick負荷、進軍経路、オーブ供給量を確認する。設定値は開催開始時にスナップショット化し、進行中の開催へ遡及しない。

## 実機で確かめる事項

- ワールドの実在、入場・中央・各召喚地点の安全性と進軍経路、256チャンク以内の読み込み範囲。
- 最大30人、設定した増援量・生存上限でのサーバー負荷、遠隔/飛行Mobと既存スキルの攻撃・挑発挙動。
- 実SQL Server、API、Web、実サーバーとクライアントを接続した開催・中断・メール配送と再起動後の帰還。ローカルの静的検証や単体テストを実機確認の代わりにしない。
