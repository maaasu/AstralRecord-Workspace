# 42_3-サービス

## 受付・開始判定

Pluginは `api.serverId` と `defense.runtimeKey` が揃うと監視を開始する。約5秒ごとにruntimeをpollし、受付状態 `OPEN` / `PREPARING` / `CLOSED` と登録人数0～30を報告する。`PENDING` のrunを受けてもWeb/API側の受理を開始成功と扱わない。run添付の設定を再検証し、既存ワールドを解決し、安全な入場・中央・全召喚地点と適格Mob候補を確認する。該当するチャンクの矩形範囲が256を超えれば拒否する。ワールドを新規生成しない。

会場の既存チャンクを生成なしの非同期読込で一つずつ準備し、ticketの付与と次の準備をmain threadで分割する。未生成・障害・部外者滞在・安全地点の不備は開始を中断する。受付時に本人・アカウントと他挑戦の予約を照合し、帰還元を保存して非同期転送する。開始前の退出は受付枠を空け、開始後は固定母集団に脱落履歴を残す。開始直前に到着とワールド所在を再確認し、入場失敗者を確定対象から外す。確定人数が0なら `NO_PARTICIPANTS` でABORTED。成功時に防衛対象を作り、確定人数を固定して `STARTED` をoutboxへ保存する。日次開始時刻より前には戦闘へ移さない。

受付から帰還完了までは共通遷移ゲートでアカウント切替・チャンネル移動を拒否する。保存不能stateの復旧は妨げず、異なるアカウントを旧アカウントの帰還元へ転送しない。帰還待ちの本人アカウントに切り替わった場合にだけ帰還を再試行する。帰還が完了した本人だけ挑戦予約を解放し、他人の切断中の帰還待ちで次回開催を塞がない。

## 進行・標的・損害

防衛レベルは戦闘開始後の単調な経過時間から算出し、5秒ごとに `HEARTBEAT` でレベルと各参加者の活動秒数・AFK・脱落を報告する。増援の一波の数は人数補正後に切り上げ、波の上限と空き生存枠で抑える。各tickの生成数は `maxSpawnsPerTick` に制限する。候補は開催時に固定し、同じ開催中のマスタ再読込を既存候補へ反映しない。

防衛戦の敵は中央を基本標的とし、既存の有効な挑発を優先する。挑発がなければ、攻撃者が生存・参加中かつ `retaliationRange` 内で `retaliationSeconds` の間だけ反撃する。プレイヤー・ペットの攻撃は参加中本人に属する場合だけ防衛戦の敵へ通し、敵からの攻撃も参加者へ限定する。防衛対象への攻撃は所属する防衛戦の敵だけが行う。防衛戦個体の通常Mob報酬は抑止する。

## 報酬・永続化

`N = rewardEveryLevels` として、Lv.`N, 2N, 3N, ...` の到達時に先に最新 `HEARTBEAT` をキューへ積む。その節目時点で非AFK・非脱落・必要活動秒数などの資格を固定し、条件を満たす参加者だけの `rewards` を積む。outboxの本文と `operationId` は送信前に `defense_runtime.json` へ保存し、送信成功まで削除しない。同じ操作の再送は本文も同一とし、未到達の未来段階を再算定・再抽選しない。API側は開催・アカウント・段階で重複確定を防ぐ。メール配送の永続化と受取はAPI/既存メールの責務とする。

API送信は非同期でruntime指示を取得してから最大16件のoutboxを順番に処理し、受付状態を送信する。処理結果だけをメインスレッドへ戻してゲーム状態を更新する。通信障害時は次回pollで再送し、メインスレッドをHTTP待機させない。所有開催の消失または通信途絶が `max(60秒,reconnectGraceSeconds)` を超えた場合は中断・帰還する。同一所有者の保存済み進捗と報酬は終端後も再送し、戦闘は再開しない。ローカルjournalが破損または保存不能なら上書きせず、開始・進行を止め、保存成功に依存せず会場・Mob・ticketを回収して運営へログで示す。

設定済みの会場名もjournalへ保持し、開催間とAPI未接続時も地形・通常スポーン・外部転送を保護する。敵の死亡・反撃期限切れに合わせて反撃記録を除去する。

### 状態ファイルの読込・置換保存

`DefenseStateStore` はPluginデータディレクトリの `defense_runtime.json` をUTF-8 JSONとして読む。ファイル未作成時だけ空のJSON objectを返す。不正なJSONは `IOException` として通知し、既存ファイルを上書きしない。

保存時は同じディレクトリの一時ファイルへUTF-8 JSONを書き、`ATOMIC_MOVE` と `REPLACE_EXISTING` で置換する。ファイルシステムがatomic moveに対応しない場合は `REPLACE_EXISTING` で置換する。保存失敗は呼出側へ通知し、メインスレッドの進行を止める。
