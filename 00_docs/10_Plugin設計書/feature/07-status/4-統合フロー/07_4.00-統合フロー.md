# 07_4.00-統合フロー

## 1. ステータス再計算

### シーケンス

```mermaid
sequenceDiagram
    participant P as AstPlayer
    participant S as StatusService
    participant B as BuffService
    participant I as InventoryService

    P->>S: refreshStatus
    S->>B: purgeExpired
    S->>S: account mode・level・class・装備・set effect補正
    loop StatusType ごと
        S->>B: getTotalBonus(preBuffTotal)
        S->>S: base / bonus / final を確定
    end
    S->>P: StatusSnapshot 更新
    S->>I: applyBagSlotCapacity(INVENTORY_SLOTS)
    S-->>P: 更新後 StatusSnapshot
```

### 処理要点

- `MAX_HEALTH` / `MAX_MANA` / `MAX_ENERGY` / `MAX_SHIELD` の最大値を再計算する。
- 既存スナップショットがある場合は現在 HP / MP / EN / Shield を各新最大値へ clamp して引き継ぐ。
- 初回スナップショットは HP / MP / EN を最大値、Shield を最大値として生成する。
- `INVENTORY_SLOTS` の最終値は BAG の実効容量へ反映する。

### 例外・終了条件

- status 未初期化時の `getStatus` は `refreshStatus` を呼び、必ずスナップショットを返す。

## 2. `/status` 表示

### シーケンス

```mermaid
sequenceDiagram
    participant P as プレイヤー
    participant C as StatusCommand
    participant S as StatusService
    participant M as PlayerMessageService

    P->>C: /status [detail]
    C->>S: getStatus(astPlayer)
    S-->>C: StatusSnapshot
    alt detail
        C->>M: P_5100..P_5108 と全 StatusValue
    else 通常表示
        C->>M: 基本リソース・主要値
    end
```

### 処理要点

- `/status` と `/status detail` を提供し、`StatusType` の表示名、カテゴリ色、単位、小数桁を使って整形する。
- Shield の最大値は `MAX_SHIELD` として status 値一覧に含まれる。

## 3. 定期自然回復

### シーケンス

```mermaid
sequenceDiagram
    participant T as StatusRegenTask
    participant C as AstPlayerCache
    participant S as StatusService

    loop 20 tick ごと
        T->>C: getAll
        loop online かつ生存中の AstPlayer
            T->>S: getStatus
            T->>S: recoverHp(HP_REGEN / 5)
            T->>S: recoverMp(MP_REGEN / 5)
            T->>S: recoverEnergy(ENERGY_REGEN / 5)
            opt Shield 変更から再充填待機時間経過
                T->>S: recoverShield(1 + SHIELD_RECHARGE_RATE)
            end
        end
    end
```

### 処理要点

- HP / MP / EN の regen 値は「5秒あたり」のため、1秒 task では `1/5` を回復する。
- Shield の基準再充填待機は 10,000 ms とし、`SHIELD_RECHARGE_REDUCTION` を `0..95%` に clamp して短縮する。最短待機は 500 ms とする。
- Shield 回復量は eligible tick ごとに `1 + SHIELD_RECHARGE_RATE` とする。

### 例外・終了条件

- オフライン、Bukkit の死亡状態、回復量 0 以下、または最大値到達済みのリソースは処理しない。

## 4. インベントリ変更時の装備反映

### シーケンス

```mermaid
sequenceDiagram
    participant EVT as inventory 操作 event
    participant I as InventoryService
    participant S as StatusService
    participant P as プレイヤー

    EVT->>I: 装備スナップショット更新
    alt 更新成功
        I->>S: refreshStatus
        I-->>P: PlayerMsgId.P_5601 / GuiSound.EQUIP
    else 更新失敗
        I-->>P: GuiSound.DENY
    end
```

### 処理要点

- 通常 hotbar の slot `0..7` を装備割当、slot `8` を inventory 切替に使用する。
- 切替対象は所持数 1 以上の `NORMAL` / `EQUIPMENT` / `RUNE` とする。
- hotbar、offhand、防具、装備可能 item の変更後に装備スナップショットを更新し、成功時だけ status を再計算する。

## 5. HOTBAR_SLOT 変更後の status observer

### シーケンス

```mermaid
sequenceDiagram
    participant EVT as PlayerItemHeldEvent
    participant G as PlayerInteractionGatewayEventHandler
    participant D as PlayerInputDispatcher
    participant O as PlayerHeldItemStatusEventHandler
    participant S as StatusService

    EVT->>G: onPlayerItemHeld
    G->>D: HOTBAR_SLOT を仲裁
    alt event が未キャンセル
        EVT->>O: onPlayerItemHeld（MONITOR observer）
        O->>O: 次 tick へ遅延
        O->>S: refreshStatus
    else input lock 等が勝者
        O-->>EVT: observer は実行されない
    end
```

### 処理要点

- observer は入力候補を返さず、入力所有権や勝者選択に影響しない。
- 次 tick に遅延し、選択後の main hand item を含めて status を再計算する。
