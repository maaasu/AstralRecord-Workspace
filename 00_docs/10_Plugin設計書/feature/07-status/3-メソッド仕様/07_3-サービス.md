# 07_3-サービス

## 1. StatusService メソッド仕様

### ステータス取得

クラス名: `StatusService`
物理名: `getStatus`

処理内容:

1. [[03_1-モデル定義]].プレイヤーセッション から [[07_1-モデル定義]].ステータススナップショット を取得する。
2. [[05_3-サービス]].期限切れバフ削除 を実行する。
3. ステータス値一覧が空、または期限切れバフを1件以上削除した場合、[[07_3-サービス]].ステータス再計算 を実行して結果を返す。
4. それ以外の場合、保持済みのステータススナップショットを返す。

### ステータス再計算

クラス名: `StatusService`
物理名: `refreshStatus`

処理内容:

1. [[05_3-サービス]].期限切れバフ削除 を実行する。
2. 現在の [[07_1-モデル定義]].ステータススナップショット を退避する。
3. 全 [[07_1-モデル定義]].ステータス種別 について、基礎値・アカウントモード補正・レベル由来の `INVENTORY_SLOTS` 補正・職業 Shield 補正・装備補正・スキルツリー補正・パッシブスキル補正・バフ補正を計算する。
   - 装備補正は、現在装備中の防具、オフハンド、拡張アクセサリ、メインハンド選択アイテムの equipment instance から取得する。`requiredLevel` または現在クラスの `requiredClasses[].level` を満たさない装備は、個別補正・セット効果数の双方から除外する。
   - equipment の `FLAT` は加算する。`SCALAR` は同一装備内に同じステータスの `FLAT` がある場合だけ、その装備のフラット値へ適用する。複数の `SCALAR` は装備単位で最後に定義された値を採用し、対応する `FLAT` がない `SCALAR` は無効とする。
   - 装備に `setId` が設定されている場合は装備数を集計し、`/api/seteffect/{setId}` の `pieces[].count` 条件を満たすステータス補正を累積適用する。
4. 基本能力値の最終値から派生ステータス補正を計算して加算する。派生先と係数は [[07_1-モデル定義]].基本能力値 を正本とする。
5. 退避したステータス値一覧が空の場合、[[07_3-サービス]].全リソース最大値回復（内部） で HP / MP / EN / Shield を最大値まで回復した状態に初期化する。
6. 退避したステータス値一覧が存在する場合、現在 HP / MP / EN / Shield を維持しながら新しい最大値の範囲内へ丸める。`MAX_SHIELD` が 0 から正数へ変化した場合は現在 Shield を 0 のまま維持し、その時点の `SHIELD_RECHARGE_REDUCTION` で Player 基礎30秒を一度だけ短縮したリチャージを開始する。正数から 0 へ変化した場合は進行中のリチャージ状態と表示capacityを破棄する。
7. [[03_1-モデル定義]].プレイヤーセッション に再計算後のステータススナップショットを設定する。`MAX_SHIELD` の付け外しでは即時満タンへ戻さない。`MOVEMENT_SPEED = 100` をバニラプレイヤーの標準速度 `0.1` とし、Bukkit プレイヤーの `Attribute.MOVEMENT_SPEED` には `0.1 × MOVEMENT_SPEED / 100` として反映する。`INVENTORY_SLOTS` は小数点以下を切り捨て、最小0として BAG の実効容量へ反映する。
8. 再計算後のステータススナップショットを返す。

### バフ適用

クラス名: `StatusService`
物理名: `applyBuff`

処理内容:

1. [[05_3-サービス]].バフ付与 を実行する。
2. 適用結果が失敗の場合、[[07_3-サービス]].ステータス取得 を実行して現在状態を返す。
3. 適用結果が成功の場合、[[07_3-サービス]].ステータス再計算 を実行して結果を返す。

### バフ解除

クラス名: `StatusService`
物理名: `removeBuff`

処理内容:

1. [[05_3-サービス]].バフ解除 を実行する。
2. [[07_3-サービス]].ステータス再計算 を実行して結果を返す。

### 一時固定値バフ適用

クラス名: `StatusService`
物理名: `applyTemporaryFlatBuff`

処理内容:

1. 指定ステータス、正の上昇値、持続秒数からセッション内限定の `FLAT` バフを生成する。
2. 同一プレイヤー・同一ステータスの管理コマンド用一時バフがある場合は削除し、新しい値と失効時刻で置き換える。
3. [[07_3-サービス]].ステータス再計算 を実行する。
4. 付与した [[05_1-モデル定義]].アクティブバフを返す。

入力:

- `player`: 対象プレイヤー
- `statusType`: 上昇させる [[07_1-モデル定義]].ステータス種別
- `value`: 正の有限値
- `durationSeconds`: `1`〜`107374182` 秒

例外時挙動:

- 上昇値または持続秒数が有効範囲外の場合は `IllegalArgumentException` を送出する。

### Shield リチャージ

クラス名: `StatusService`

- `startShieldRecharge` は Player の Shield 破壊時、またはセッション中の `MAX_SHIELD` 0 から正数への遷移時に呼び、基礎30秒へ開始時点の `SHIELD_RECHARGE_REDUCTION` を適用して完了時刻を固定する。
- `extendShieldRecharge` は進行中だけ受理し、攻撃者の基礎追加秒数へ呼出時点の被ダメ側 `SHIELD_RECHARGE_REDUCTION` を適用して完了時刻へ加算する。
- `completeShieldRechargeIfReady` は完了時刻を過ぎた状態を一度だけ取り除き、回復阻害とは独立して `MAX_SHIELD` を一括設定する。
- `restoreAll`、ログアウト、死亡開始ではリチャージ状態を破棄し、通常初期シールドへ戻す。
- リチャージ状態と表示capacityはセッション内だけで保持し、保存しない。

### スナップショット生成

クラス名: `StatusService`
物理名: `createSnapshot`

処理内容:

1. 全 [[07_1-モデル定義]].ステータス種別 を走査する。
2. [[07_3-サービス]].基礎値取得 でステータス種別ごとの基礎値を取得する。
3. [[07_3-サービス]].補正値取得 でアカウントモード・レベル・装備・スキル・バフを合算した補正値を取得する。
4. 基礎値と補正値から [[07_1-モデル定義]].ステータス値 を生成する。
5. 基本能力値から派生する補正を全ステータス値へ加算する。
6. 全ステータス値、現在 HP / MP / EN / Shield `0.0`、Shield 変更時刻として現在 epoch milliseconds、計算日時で [[07_1-モデル定義]].ステータススナップショット を生成する。

### 補正値取得

クラス名: `StatusService`
物理名: `getBonusValue`

処理内容:

1. [[07_3-サービス]].アカウントモード補正取得 で [[02_1-モデル定義]].アカウントモード 補正を取得する。
2. [[07_3-サービス]].レベル補正取得 で、`INVENTORY_SLOTS` にだけ [[02_1-モデル定義]].プレイヤーレベル進行 の `level` 補正を取得する。
3. Shield 系ステータスの場合、現在職業の補正を取得する。
4. 装備補正を加算する。`FLAT` を先に加算し、`SCALAR` はその時点の基礎値と非バフ補正へ乗算する。
5. スキルツリー補正とパッシブスキル補正を順に加算する。
6. 基礎値と非バフ補正の合計を [[05_3-サービス]].バフ補正合計取得 へ渡し、バフ補正を取得する。
7. 非バフ補正とバフ補正を合算して返す。

### レベル補正取得

クラス名: `StatusService`
物理名: `getLevelBonus`

処理内容:

1. `INVENTORY_SLOTS` 以外は補正値 `0.0` を返す。
2. `INVENTORY_SLOTS` はレベル5ごとに1増加するため、`floor(max(0, level) / 5)` を返す。

	| ステータス種別 | 補正値 |
	|---|---:|
	| インベントリスロット数（`INVENTORY_SLOTS`） | `floor(max(0, level) / 5)` |

### 連携サービス設定

クラス名: `StatusService`

- 各連携サービス。`null` を許容する。

処理内容:

1. 指定された連携サービス参照を保持する。
2. 未設定の `SkillTreeService` / `PassiveSkillService` / `PlayerClassService` は対応補正を `0.0` として扱う。
3. `ConditionService` が未設定の場合、回復阻害なし・移動速度倍率 `1.0` として扱う。

## 状態異常との統合

`recoverHp`、`recoverMp`、`recoverEnergy`、`recoverShield` は回復阻害中なら現在値を変更しない。自然回復とポーションもこれらのメソッドを経由する。`restoreAll` は死亡後リスポーンと管理コマンド用の例外として回復阻害を無視する。

`applyMovementSpeed` は通常の移動速度へ `ConditionService.movementSpeedMultiplier` を掛け、冷気を0.5、凍結または感電の拘束中を0として反映する。
