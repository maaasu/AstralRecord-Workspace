# 07_1-モデル定義

## 1. ドメインモデル

`status` 機能の中心はステータススナップショット。
ステータス種別ごとの基礎値・補正値・合計値の最小値／最大値と、現在 HP / MP / EN / Shield を同時に保持する。

## 2. ステータススナップショット

物理名: `StatusSnapshot`

### 2.1 項目

| 項目              | 説明                                                     |
| --------------- | ------------------------------------------------------ |
| `values`        | [[07_1-モデル定義]].ステータス種別 ごとの [[07_1-モデル定義]].ステータス値 |
| `currentHp`     | 現在 HP                                                  |
| `currentMp`     | 現在 MP                                                  |
| `currentEnergy` | 現在 EN                                                  |
| `currentShield` | 現在 Shield                                              |
| `shieldChangedAtMs` | 旧互換の Shield 変更時刻。リチャージ判定には使用しない |
| `calculatedAt`  | 計算日時                                                   |

### 2.2 保持先

- [[03_1-モデル定義]].プレイヤーセッション.statusSnapshot に保持する。
- 空状態の場合は、[[07_3-サービス]].ステータス再計算 により初期化する。

## 3. ステータス値

物理名: `StatusValue`

| 項目 | 説明 |
|---|---|
| `baseMinValue` / `baseMaxValue` | 基礎値の下限／上限 |
| `bonusMinValue` / `bonusMaxValue` | アカウントモード・現在クラス・プレイヤーレベル・装備・スキルツリー・パッシブスキル・バフ・基本能力値からの派生による補正値の下限／上限 |
| `minValue` / `maxValue` | 基礎値と補正値を合算した下限／上限 |
| `rollValue` | 下限と上限が異なる場合は範囲内からランダム取得し、同値ならその値を返す |

`MAX_HEALTH`、`MAX_MANA`、`MAX_ENERGY`、`MAX_SHIELD`、`INVENTORY_SLOTS`、`QUEST_LIMIT` は状態管理上の上限値として参照ごとに変動させないため、単一値で保持する。それ以外は装備等が範囲を持つ場合に最小値／最大値を維持する。

表示時は下限と上限が同値なら単一値へ畳み込み、異なる場合だけ range として表示する。percentage 種別の保存値は 0..1 の比率へ再変換せず percentage point として `%` 表示する。

## 4. ステータス種別

物理名: `StatusType`

ID・論理名・カテゴリ・表示単位・小数桁・範囲可否の正本は`40_filebase/75.shared.status/v1.status_types.yml`とし、`StatusType.kt`は`60_tool/generate-status-types.ps1`で生成する。Plugin固有のステータス計算と利用箇所は本設計書およびPluginソースを正本とする。

### 4.1 リソース系

| 物理名 | 論理名 | 用途 |
|---|---|---|
| `MAX_HEALTH` | 最大HP | HP 上限 |
| `MAX_MANA` | 最大MP | MP 上限 |
| `MAX_ENERGY` | 最大EN | EN 上限 |
| `MAX_SHIELD` | 最大シールド | Shield 上限 |

### 4.2 基本能力値

| 物理名 | 論理名 | 用途 |
|---|---|---|
| `STRENGTH` | 筋力 | 近接攻撃系の基礎能力 |
| `DEXTERITY` | 器用さ | 間接攻撃系の基礎能力 |
| `INTELLIGENCE` | 知力 | 魔法攻撃・MP 系の基礎能力 |
| `VITALITY` | 体力 | HP・防御・自然回復系の基礎能力 |
| `AGILITY` | 敏捷性 | 攻撃速度・移動速度・回避系の基礎能力 |
| `LUCK` | 幸運 | クリティカルやドロップ系の基礎能力 |

基本能力値は、現在クラス・装備・スキルツリー・パッシブスキル・バフ・アカウントモードを反映した最終値から、以下の派生補正を加算する。HP・防御・回復・速度・回避率・会心率などの派生ステータスでは、直接指定された補正とも加算し、基本能力値による補正を派生先でさらに乗算しない。攻撃力だけは別扱いで、本書の「4.2.2 攻撃力への基本能力値倍率」の式を使う。基本能力値が範囲値の場合、範囲を許可する派生ステータスは対応する下限／上限を維持し、最大HP・最大MPは基本能力値の範囲平均を用いる。

### 4.2.1 派生ステータスの計算

基本能力値の最終値を `P`、基本能力値からの係数を `k` とすると、派生補正は次で求める。

```text
範囲を持つ派生先:
  派生補正の下限 = P_min × k
  派生補正の上限 = P_max × k

範囲を持たない派生先（MAX_HEALTH / MAX_MANA）:
  派生補正 = ((P_min + P_max) / 2) × k

派生先の最終値 = 基礎値 + 基本能力値以外の直接補正 + 派生補正
```

したがって、基本能力値が整数で1増えた場合の増加量は、下表の「1あたりの補正」または攻撃力の「1ポイントあたりの倍率変化」になる。`EVASION` と `CRITICAL_RATE` の `point` は、倍率そのものではなく**パーセントポイント**を表す。ドロップ確率への `LUCK` 補正は、設定率に対する相対倍率として扱う。

| 基本能力値 | 派生先 | 基本能力値1あたりの補正 |
|---|---|---:|
| `INTELLIGENCE` | `MAX_MANA` | `+1` |
| `INTELLIGENCE` | `MP_REGEN` | `+0.1` |
| `VITALITY` | `MAX_HEALTH` | `+2` |
| `VITALITY` | `DEFENSE`, `MAGIC_DEFENSE` | 各 `+1` |
| `VITALITY` | `HP_REGEN` | `+0.1` |
| `AGILITY` | `ATTACK_SPEED`, `MOVEMENT_SPEED` | 各 `+1` |
| `AGILITY` | `EVASION` | `+0.1%` |
| `LUCK` | `CRITICAL_RATE` | `+0.1%` |

`LUCK` は加えて、`luckAffected = true` の直接ドロップ確率へ `1 + LUCK / 100` 倍を適用する。例えば `LUCK=20` は設定率の120%、`LUCK=100` は設定率の200%となり、設定率0.1%は実効率0.2%になる。補正後の確率はドロップ抽選時に0〜100%へクランプする。

### 4.2.2 攻撃力への基本能力値倍率

筋力・器用さ・知力は、対応する攻撃力へ固定値を加算せず、`ATTACK` と攻撃種別攻撃力の合計へ倍率として適用する。`P` は装備・職業・スキル・バフなどを反映した基本能力値の最終値である。

| 攻撃種別 | 使用する基本能力値 | 解決攻撃力 | 基本能力値が1増えたとき |
|---|---|---|---|
| `MELEE` | `STRENGTH` | `(ATTACK + MELEE_ATTACK) × (1 + STRENGTH / 100)` | 攻撃倍率が `+1` ポイント（`×0.01`）。実攻撃力の増加量は `(ATTACK + MELEE_ATTACK) × 0.01` |
| `RANGED` | `DEXTERITY` | `(ATTACK + RANGED_ATTACK) × (1 + DEXTERITY / 100)` | 攻撃倍率が `+1` ポイント（`×0.01`）。実攻撃力の増加量は `(ATTACK + RANGED_ATTACK) × 0.01` |
| `MAGIC` | `INTELLIGENCE` | `(ATTACK + MAGIC_ATTACK) × (1 + INTELLIGENCE / 100)` | 攻撃倍率が `+1` ポイント（`×0.01`）。実攻撃力の増加量は `(ATTACK + MAGIC_ATTACK) × 0.01` |

例えば `ATTACK + MELEE_ATTACK = 100` の場合、筋力が `20` なら近接攻撃力は `100 × 1.20 = 120`、筋力が `21` なら `100 × 1.21 = 121` になる。この場合だけ、筋力1あたり近接攻撃力が1増える。`ATTACK + MELEE_ATTACK = 8` なら、筋力1あたりの増加量は `0.08` であり、固定で1増えるわけではない。

### 4.2.3 初期値だけで計算した例

直接補正がなく、6つの基本能力値がすべて基礎値 `5` の場合、主なステータスは次のようになる。`HP_REGEN` / `MP_REGEN` は5秒あたりの回復量であり、定期回復ではこの値を `5` で割った量を毎秒適用する。

| ステータス | 計算 | 結果 |
|---|---|---:|
| 最大HP | `20 + 5 × 2` | `30` |
| 最大MP | `10 + 5 × 1` | `15` |
| 防御力 | `5 + 5 × 1` | `10` |
| 魔法防御力 | `3 + 5 × 1` | `8` |
| HP回復力 | `1 + 5 × 0.1` | `1.5` |
| MP回復力 | `0.5 + 5 × 0.1` | `1.0` |
| 攻撃速度 | `100 + 5 × 1` | `105` |
| 移動速度 | `100 + 5 × 1` | `105`（Bukkit速度 `0.105`） |
| 回避率 | `3 + 5 × 0.1` | `3.5%` |
| 会心率 | `5 + 5 × 0.1` | `5.5%` |
| 各攻撃種別の解決攻撃力 | `(8 + 0) × (1 + 5 / 100)` | `8.4` |

### 4.3 攻撃系

| 物理名 | 論理名 |
|---|---|
| `ATTACK` | 攻撃力 |
| `MELEE_ATTACK` | 近接攻撃力 |
| `RANGED_ATTACK` | 間接攻撃力 |
| `MAGIC_ATTACK` | 魔法攻撃力 |
| `CRITICAL_RATE` | 会心率 |
| `CRITICAL_DAMAGE` | 会心ダメージ |
| `SUPER_CRITICAL_RATE` | 超星会心率 |
| `SUPER_CRITICAL_DAMAGE` | 超星会心倍率 |
| `SKILL_DAMAGE_INCREASE` | スキルダメージ増加 |
| `NORMAL_ATTACK_DAMAGE_INCREASE` | 通常攻撃ダメージ増加 |
| `FINAL_DAMAGE_MULTIPLIER` | 最終ダメージ倍率（常時適用） |
| `ACCURACY` | 命中率 |
| `ATTACK_SPEED` | 攻撃速度（基準値100。通常攻撃・攻撃行動の間隔を `ceil(基本間隔 × 100 / 攻撃速度)` にする） |
| `SHIELD_BREAK` | シールド破壊力 |
| `FIXED_HEALTH_DAMAGE` | HP固定ダメージ（直接攻撃の命中時だけ加算し、シールド有効中は無効） |
| `SHIELD_RECHARGE_DELAY_CHANCE` | シールドリチャージ加算率（直接攻撃ごとの延長抽選確率） |
| `SHIELD_RECHARGE_DELAY_SECONDS` | シールドリチャージ加算値（抽選成功時の基礎追加秒数） |
| `DEFENSE_PENETRATION_RATE` | 防御力貫通率 |
| `MELEE_DEFENSE_PENETRATION_RATE` | 近接防御貫通率 |
| `RANGED_DEFENSE_PENETRATION_RATE` | 間接防御貫通率 |
| `MAGIC_DEFENSE_PENETRATION_RATE` | 魔法防御貫通率 |
| `LIFE_STEAL` | ライフスティール |

`ATTACK` は全攻撃種別に共通する基礎攻撃力、`MELEE_ATTACK` / `RANGED_ATTACK` / `MAGIC_ATTACK` は攻撃種別ごとの追加攻撃力として扱う。`WEAPON` 装備の主攻撃力は、SWORD/HAMMER/SPEAR なら `MELEE_ATTACK`、BOW/SHORTBOW/LONGBOW なら `RANGED_ATTACK`、WAND/STAFF なら `MAGIC_ATTACK` のように、武器の攻撃種別に対応するステータスで指定する。`ATTACK` を含む最終値と対応する種別攻撃力、基本能力値から、戦闘時の攻撃力を次式で解決する。

```text
種別攻撃力 = (ATTACK + 対応する種別攻撃力)
            × (1 + 対応する基本能力値 / 100)
```

### 4.5 属性系

属性は `FIRE` / `ICE` / `LIGHTNING` ごとに以下のステータスを持つ。すべて単位は `%`。毒は属性ではなく状態異常として扱う。

| 接尾辞 | 用途 |
|---|---|
| `_DAMAGE_INCREASE` | 対応属性ダメージ増加 |
| `_RESISTANCE` | 対応属性耐性 |
| `_RESISTANCE_CAP` | 対応属性耐性として計算できる上限値（初期値 75%） |
| `_PENETRATION` | 対応属性耐性の相殺 |

### 4.6 状態異常系

燃焼、凍結、冷気、感電、毒状態、盲目、衰弱、回復阻害はそれぞれ付与確率増加と付与耐性を持つ。燃焼・感電・毒状態は追加でDoTダメージ増加、DoT耐性、DoT貫通を持つ。毒状態の物理名は `POISONED_` を使う。

| `ENERGY_REGEN` | EN回復力 |

| `ENERGY_COST_REDUCTION` | エネルギー消費軽減率 |
| `HEALING_INCREASE` | 回復量増加（自身のHP回復） |

## 6. Shield リチャージ状態

物理名: `ShieldRechargeState`

| 項目 | 説明 |
|---|---|
| `startedAtMs` | シールド破壊後またはShield残存時の被ダメージ後にリチャージを開始した epoch milliseconds |
| `completesAtMs` | 基礎時間と攻撃による延長を反映した完了予定時刻 |
| `rechargeAmount` | 1回のリチャージ処理で適用する回復量。Player は1秒あたりの加算量、Mob は完了時の設定値として扱う |
| `incrementalRecovery` | PlayerのShield残存時パッシブによる段階回復なら`true`。Shield破壊後の通常全回復なら`false` |

Player の状態は `StatusService`、Mob の状態は `MobInstance` がセッション内だけで保持する。Player は`incrementalRecovery=true`なら待機時間経過後の定期処理ごとに `rechargeAmount` を加算し、最大Shield到達まで state を保持する。`incrementalRecovery=false`なら待機完了時に最大Shieldへ一括回復する。Mob は完了時に `rechargeAmount` を現在値へ設定する。進捗は `(now - startedAtMs) / (completesAtMs - startedAtMs)` を `0..1` へ丸め、延長時は `completesAtMs` だけを後ろへ移す。ログアウト・死亡・復帰では状態を破棄し、永続化しない。

通常シールドバーは現在周期の `shieldDisplayCapacity` を分母とする。Player は `MAX_SHIELD`、Mob はスポーン時の `shield.max`、リチャージ完了後の Mob は実際の `rechargeAmount` を満タン値とする。
