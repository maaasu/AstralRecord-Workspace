# 18_0-概要

## 目的

ログイン中アカウントに対して、公開期間とアカウント状態をAPIが判定したメール一覧を表示する。未読メールの報酬、装備個体、既読状態を単一player-state snapshotで確定する。

## 責務

- `ALL`、`UNREAD`、`READ` filter で利用可能メールを取得する。
- GUI request ごとに account ID、ログインセッション、開いている inventory を再検証し、古い非同期応答を破棄する。
- 未読メールのreward modelを非同期で解決し、重要操作lane内でequipment instanceと報酬entryをローカル生成する。
- 報酬、equipment、`mailClaim`を同じSQL transactionで確定し、失敗時はローカル状態を操作前へ戻す。
- DROP 操作では `mailDelete` section を完成スナップショットへ含め、アカウント別削除状態を SQL ACK で確定する。

## 責務外

- メール本文・配信対象・公開期間の作成。
- welcome mail の作成や重複防止。プラグインには `createWelcomeMailIfAbsent` 相当の処理はなく、API／master data 側の責務である。
- 添付報酬以外の arbitrary command 実行。

## 整合性原則

- account ID はメール可視性・既読・削除・inventory 付与の主体として扱い、user ID は現在のログインセッションと監査上の更新者として扱う。
- 同一 `(accountId, mailId)` の受取を in-flight／completed set で二重実行しない。一覧再取得では completed set を消去せず、API の stale 応答で排他を解除しない。
- API応答が不明な場合はsnapshot IDで結果照会し、未完了なら同じpayloadを再送する。
- 受取成功の通知はSQL ACK時点でオンラインのプレイヤーへ一度だけ行い、切断中は次回ログイン完了後へ保留する。

## 依存・連携

| feature | 依存内容 |
|:--|:--|
| infrastructure / API | `/api/mail`の一覧取得、`/api/player-state/snapshots`の受取・削除確定 |
| item | 報酬item定義の解決、equipment instanceのローカル生成。ルーンは通常スタックitemとして扱う |
| inventory | NORMAL inventoryへのstate-only一括付与、重要保存、失敗時補償 |
| player / menu | user・account identity、通知、GUI navigation |

## 変更影響

- API の mail response／action を変更した場合は [[18_1-モデル定義]]、[[18_3-メソッド仕様]] と API 設計書を更新する。
- 受取・snapshot・rollbackを変更した場合は[[18_4-統合フロー]]と[[18_5-例外・ログ・運用]]を更新する。
- GUI の click、filter、page を変更した場合は [[18_2-ユースケース]] と [[18_4-統合フロー]]を更新する。
- welcome mail 等の発行規則は API／master data 側に記載し、プラグインだけの仕様として追加しない。
