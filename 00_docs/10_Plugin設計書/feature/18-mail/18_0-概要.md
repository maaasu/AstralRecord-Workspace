# 18_0-概要

## 目的

ログイン中アカウントに対して、公開期間とアカウント状態を API が判定したメール一覧を表示する。未読メールを開いたときだけ任意の報酬を NORMAL inventory へ付与し、API の既読状態とローカル付与結果を補償可能な順序で整合させる。

## 責務

- `ALL`、`UNREAD`、`READ` filter で利用可能メールを取得する。
- GUI request ごとに account ID、ログインセッション、開いている inventory を再検証し、古い非同期応答を破棄する。
- 未読メールの reward model／instance を非同期で準備し、main thread で一括付与する。
- 付与後に API を既読化し、失敗時は inventory rollback または reconciliation を行う。
- DROP 操作で API 上のアカウント別削除状態へ更新する。

## 責務外

- メール本文・配信対象・公開期間の作成。
- welcome mail の作成や重複防止。プラグインには `createWelcomeMailIfAbsent` 相当の処理はなく、API／master data 側の責務である。
- 添付報酬以外の arbitrary command 実行。

## 整合性原則

- account ID はメール可視性・既読・削除・inventory 付与の主体として扱い、user ID は現在のログインセッションと監査上の更新者として扱う。
- 同一 `(accountId, mailId)` の受取を in-flight／completed set で二重実行しない。一覧再取得では completed set を消去せず、API の stale 応答で排他を解除しない。
- API 既読化が失敗したまま報酬だけ残る状態を許容せず、rollback できない場合は 100 tick 後に再調停する。
- 受取成功の通知は、既読化が最終確定した時点でオンラインのプレイヤーへ一度だけ行い、切断中は次回ログイン完了後へ保留する。

## 依存・連携

| feature | 依存内容 |
|:--|:--|
| infrastructure / API | `/api/mail` の一覧、既読化、削除 |
| item | 報酬 item 定義の解決、equipment instance の事前生成。ルーンは通常スタック item として扱う |
| inventory | NORMAL inventory への一括付与と rollback receipt |
| player / menu | user・account identity、通知、GUI navigation |

## 変更影響

- API の mail response／action を変更した場合は [[18_1-モデル定義]]、[[18_3-メソッド仕様]] と API 設計書を更新する。
- 受取・rollback・reconciliation を変更した場合は [[18_4-統合フロー]] と [[18_5-例外・ログ・運用]]を更新する。
- GUI の click、filter、page を変更した場合は [[18_2-ユースケース]] と [[18_4-統合フロー]]を更新する。
- welcome mail 等の発行規則は API／master data 側に記載し、プラグインだけの仕様として追加しない。
