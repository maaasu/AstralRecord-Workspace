# 18_5-例外・ログ・運用

## 例外方針

- repository は 404 を業務上の未存在として返し、その他の非期待 status／通信失敗を runtime exception とする。
- service は非同期境界で例外を捕捉し、main thread callback の `false`／failure に変換する。
- 報酬の一部付与を許さず、`InventoryGrantReceipt` 単位で rollback する。
- API 既読化と rollback が両方失敗した場合は無限放置せず 100 tick 間隔で再調停する。
- rollback 失敗で報酬が inventory に残った場合、受取 callback は `success=false`／`rewardReceived=true` とし、reconciliation 成功時に受取成功 listener を一度だけ確定する。

## ログ・メッセージ

| ID | 用途 |
|:--|:--|
| `LogId.E_5190` | mail API operation、path、failure reason |
| `LogId.E_5601` | mail GUI click／drag／close の安全実行失敗。player と `mail_gui_click`／`mail_gui_drag`／`mail_gui_close` を記録 |
| `P_5620` | 報酬受取成功 |
| `P_5621` | 削除結果 |
| `P_5622` | メール未存在／既読化失敗 |
| `P_5623` | 報酬準備・付与失敗 |
| `P_5624` | 未読件数通知 |

## 運用

- mail ID は URL encode 後も一意となる安定 ID を使う。
- `publishFrom`／`publishTo` とアカウント別可視性は API の正本とし、plugin で再実装しない。
- reconciliation が長時間継続する場合は `E_5190` と API 稼働状況、inventory rollback 条件を確認する。
- 既読化の最終確定時に player が offline の場合、受取成功 listener はログイン完了後へ保留し、`notifyPendingMailReceived` で一度だけ再送する。
- welcome mail の有無は API／master data を監査し、plugin の起動・ログイン処理へ暗黙に追加しない。
