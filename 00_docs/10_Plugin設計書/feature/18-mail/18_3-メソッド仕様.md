# 18_3-メソッド仕様

## 利用可能メール取得

クラス名: `MailRepository`
物理名: `findAvailable`

- 引数: `UUID accountId`, `MailFilter filter`
- 戻り値: `List<MailEntry>`
- 例外: 200 以外、通信・JSON 変換失敗は `RuntimeException`。割込は interrupt flag を復元する。

`GET /api/mail?account_id={accountId}&filter={apiValue}` を同期実行する。

`MailRepository` は一覧取得専用であり、既読化と削除の更新 API を持たない。

## 一覧非同期取得

クラス名: `MailService`
物理名: `listAsync`

- 引数: account ID、filter、`Consumer<List<MailEntry>> completion`、`Runnable failure`
- 戻り値: なし
- 例外: worker thread の runtime exception を main thread の `failure` へ変換する。

一覧取得と reward model preload を async、callback を main thread で実行する。

## メニューの未読状態cache

クラス名: `MailService`
物理名: `getCachedUnreadStatus`, `refreshUnreadCountAsync`, `invalidateUnreadCount`, `discardMenuState`

ログイン時の既存 `countUnread` と、ALL / UNREAD一覧取得成功時の件数をaccount単位で保持する。READ一覧だけでは未読件数を推定しない。表示の有効期限は60秒とし、未取得・期限切れはnull、0件は確認済みの0として区別する。`getCachedUnreadStatus` はAPI通信を行わない。

メインメニューの表示完了時だけ、未取得・期限切れの件数を非同期取得する。accountごとのinflight要求を共有し、API失敗後は15秒間再取得を抑止する。更新中の表示と完了時のcallbackは主スレッドで行い、呼出側は画面・ログインセッション・accountを再検証する。

受取・削除の開始と完了、Web受取によるメール画面無効化、全ガイド報酬メール発行時は件数を無効化する。無効化前の要求は世代を照合して応答を採用しない。無効化後に開いたメニューの要求が旧世代の取得中に合流した場合は、旧応答完了後に現世代を一度取得し、開き直しを要求しない。終了したaccountの取り外し済みstateからは再取得しない。新しい配信や公開期限の変更は次回メニューを開いた時の期限付き再取得で確認する。ログアウト・account終了時は表示cacheとcallbackを破棄する。取得要求のない10分間非活動のcacheも後続取得の開始時に除去する。未読表示cacheは受取可否・保存・報酬付与の判定に使用しない。

## 既読・報酬受取

クラス名: `MailService`
物理名: `readAndReceive`

- 引数: `AstPlayer astPlayer`, `MailEntry mail`, `Consumer<ReadAndReceiveResult> completion`
- 戻り値: なし
- 例外: 内部失敗を `ReadAndReceiveResult.success=false` と player message へ変換する。

1. `(accountId, mailId)` を排他する。
2. 既読なら付与なしで成功する。
3. reward modelをasyncで解決する。ルーンは通常スタック item として準備し、equipment個体はまだ生成しない。個体ID付きペット・卵は所有者限定APIで所有者・アイテムID・卵種別を照合し、表示cacheへ補完する。ペット・卵の添付は数量1と既存個体IDを必須とし、IDなし報酬を通常stackへ変換しない。
4. main threadでplayer identityを再検証し、account別重要操作laneへ登録する。
5. 重要操作内でinventoryとequipment cacheの補償点を取得し、equipment個体をローカル生成して報酬entryをstateへ反映する。既存ペット・卵は `PET` / `PET_EGG` の数量1個体entryとして同じ一括付与へ含める。
6. `mailClaim`、inventory、equipmentを単一player-state snapshotへ含める。APIはメールの公開条件・未読状態を検証し、同じSQL transactionで既読化と報酬を確定する。
7. SQL ACK後だけGUI・成功通知・listenerを反映する。保存失敗時は全ローカル状態を操作前へ戻して`P_5625`を表示する。

callback の `ReadAndReceiveResult.success` はSQL ACKまで完了したか、`rewardReceived` はこの呼び出しで確定したinventory mutationがあるかを表す。既読済み、`receiveOnRead=false`、報酬なし、または完了済みclaimの再実行では`rewardReceived=false`とする。失敗時は補償後に`success=false`、`rewardReceived=false`を返す。

## 受取成功通知の再送

クラス名: `MailService`
物理名: `notifyPendingMailReceived`

- 引数: `AstPlayer astPlayer`
- 戻り値: なし
- 事前条件: プレイヤーの user／account データと `AstPlayerCache` がログイン処理で公開済みであること。

SQL ACK時にプレイヤーがofflineだったメール報酬について、元のaccountとログインセッションに一致するプレイヤーの保留通知をmain threadで一度だけlistenerへ渡す。オンライン状態またはuser／accountの一致を確認できない場合は通知せず、次回呼び出しへ保留する。

## メール削除

クラス名: `MailService`
物理名: `delete`

- 引数: `AstPlayer astPlayer`, `MailEntry mail`, `Consumer<Boolean> completion`
- 戻り値: なし
- 例外: 完成スナップショットの保存失敗を `false` と player message に変換する。

未読かつ `receiveOnRead=true` の報酬付きメールは `P_7301` を表示して拒否する。それ以外は main thread で現在の user／account を再検証し、account別重要操作laneへ登録する。`mailDelete:{accountId}:{mailId}` の保留 section を作成し、`mailDelete`を含む完成スナップショットのSQL ACK後だけ`P_5621`と成功callbackを返す。確定失敗時は保留sectionを破棄してメールを表示上も削除せず、`P_5622`と`false`を返す。

## GUI open・event

クラス名: `MailGuiEventHandler`
物理名: `open` / `onInventoryClick` / `onInventoryDrag` / `onInventoryClose`

- open 引数: player、任意の filter と page
- event 引数: Bukkit inventory event
- 戻り値: なし
- 例外: event は `runSafely` が捕捉し、`LogId.E_5601` へ player と `mail_gui_click`／`mail_gui_drag`／`mail_gui_close` を渡す。

対象 GUI の標準 click／drag は cancel する。LEFT 系は受取、DROP 系は削除、filter／page／back／hotbar shortcut は専用分岐で処理する。
