# 18_3.00-メソッド仕様

## 利用可能メール取得

クラス名: `MailRepository`
物理名: `findAvailable`

- 引数: `UUID userId`, `MailFilter filter`
- 戻り値: `List<MailEntry>`
- 例外: 200 以外、通信・JSON 変換失敗は `RuntimeException`。割込は interrupt flag を復元する。

`GET /api/mail?user_id={userId}&filter={apiValue}` を同期実行する。

## 既読化・削除

クラス名: `MailRepository`
物理名: `markRead` / `delete`

- 引数: `UUID userId`, `String mailId`
- 戻り値: 更新後 `MailEntry?`、または削除成否
- 例外: 404 は `null`／`false`、その他の非期待 status と通信失敗は `RuntimeException`。

どちらも body に `userId` と `updatedBy` を入れ、`PUT /api/mail/{encodedId}/read|delete` を呼ぶ。

## 一覧非同期取得

クラス名: `MailService`
物理名: `listAsync`

- 引数: user ID、filter、`Consumer<List<MailEntry>> completion`、`Runnable failure`
- 戻り値: なし
- 例外: worker thread の runtime exception を main thread の `failure` へ変換する。

一覧取得と reward model preload を async、callback を main thread で実行する。

## 既読・報酬受取

クラス名: `MailService`
物理名: `readAndReceive`

- 引数: `AstPlayer astPlayer`, `MailEntry mail`, `Consumer<Boolean> completion`
- 戻り値: なし
- 例外: 内部失敗を `false` と player message へ変換する。

1. `(userId, mailId)` を排他する。
2. 既読なら付与なしで成功する。
3. reward model と equipment／rune instance を async で準備する。
4. main thread で player identity を再検証し、NORMAL inventory へ一括付与する。
5. async で API を既読化する。失敗時は receipt rollback、できなければ reconciliation を予約する。

## メール削除

クラス名: `MailService`
物理名: `delete`

- 引数: `AstPlayer astPlayer`, `String mailId`, `Consumer<Boolean> completion`
- 戻り値: なし
- 例外: repository 例外を `false` に変換する。

API は async で呼び、main thread で現在の user／account を再検証して `P_5621` または失敗通知を送る。

## GUI open・event

クラス名: `MailGuiEventHandler`
物理名: `open` / `onInventoryClick` / `onInventoryDrag` / `onInventoryClose`

- open 引数: player、任意の filter と page
- event 引数: Bukkit inventory event
- 戻り値: なし
- 例外: event は `runSafely` が捕捉し、`LogId.E_5601` へ player と `mail_gui_click`／`mail_gui_drag`／`mail_gui_close` を渡す。

対象 GUI の標準 click／drag は cancel する。LEFT 系は受取、DROP 系は削除、filter／page／back／hotbar shortcut は専用分岐で処理する。
