# 18_3.00-メソッド仕様

## メール一覧取得

クラス名: `MailService`
物理名: `listAsync`

1. userId とフィルターを受け取り、scheduler の async task で対象ユーザーのメールを取得する。
2. 一覧に含まれる正の報酬 item model を同じ async task で先読みする。
3. 取得完了または失敗通知だけを main thread へ戻す。GUI と Bukkit API は main thread で操作する。

## メール既読化

クラス名: `MailService`
物理名: `readAndReceive`

1. `(userId, mailId)` を in-flight 集合へ登録し、同じメールの重複操作を拒否する。
2. 既読済みの場合は報酬を再付与せず成功扱いとする。
3. 未読の場合は全報酬の item model を async task で解決する。1 件でも解決できなければ既読化しない。
4. main thread で現在の user・選択 account を再検証し、inventory state の補償用スナップショットを取得する。
5. 全報酬を通常インベントリへ仮予約し、各付与数が要求数と完全一致することを確認する。
6. 部分付与、容量不足、例外時はスナップショットへ復元し、メールを未読のまま保つ。
7. 全量予約後だけ async task で API の既読化を実行する。API 失敗時もスナップショットへ復元する。
8. API 既読化成功後に予約を確定し、in-flight 登録を解除する。

## 報酬受け取り

クラス名: `MailService`
物理名: `readAndReceive`

1. 報酬は item model と個数の組として全件解決する。
2. inventory feature の通常インベントリ付与へ委譲し、全件の exact amount 成功を既読化の前提とする。
3. メール API の `readAt` を報酬受け取り確定点として扱い、部分成功状態は作らない。

## 初回メール作成

クラス名: `MailService`
物理名: `createWelcomeMailIfAbsent`

1. 対象 account に `welcome_mail` が存在するか確認する。
2. 存在する場合は作成せず終了する。
3. mail filebase マスタから `welcome_mail` を解決し、対象 account 宛に作成する。

## メール GUI クリック

クラス名: `MailGuiEventHandler`
物理名: `onInventoryClick`

1. メール項目の左クリックまたは Shift+左クリックは、既読化と未受け取り報酬の受け取りを実行する。
2. メール項目上でドロップキーを押した `ClickType.DROP`、または Ctrl+ドロップキーの `ClickType.CONTROL_DROP` は、`MailService.delete` を呼び出して一覧から削除する。
3. 右クリックや Shift+右クリックでは削除しない。
4. 一覧取得、削除、受け取りは async で実行し、完了時だけ main thread で同じフィルターとページ位置を再描画する。
5. GUI を閉じた、account を切り替えた、または後続の一覧要求が発生した場合、古い一覧応答は表示しない。
