# 27_5-例外・ログ・運用

## 1. 付与拒否

| 条件 | 結果 | ログ |
| --- | --- | --- |
| 管理外 Bukkit entity | `UNMANAGED_TARGET` | なし |
| 死亡中 player / `MobState.DEAD` | `DEAD_TARGET` | なし |
| `MobCategory.NPC` | `NPC_TARGET` | なし |
| Boss 制御時間補正後が 1 tick 未満 | `RESISTED` | なし |
| 実効 chance の乱数判定失敗 | `CHANCE_FAILED` | なし |

拒否は通常の業務結果です。呼び出し元は `ConditionApplyResult.success` と `rejectReason` を使って分岐し、例外として扱いません。

## 2. 実装済みログ

| ID | テンプレート | 出力元 | 継続方針 |
| --- | --- | --- | --- |
| `E_5901` | `状態異常 tick 処理に失敗しました: condition=%s target=%s` | `ConditionTickTask.run` | 対象 condition だけ失敗扱いとして後続を継続 |
| `E_5902` | `状態異常プレイヤーイベント処理に失敗: player=%s, operation=%s` | `ConditionPlayerEventHandler` の 9 event | 例外を Bukkit へ再送出せず event handler を終了 |

`LogId.java` と `logger.properties` は同じ ID と引数順を保持します。`E_5900` は戦闘ダメージ処理のログであり、condition player event では使用しません。

`E_5902` の operation は次の固定値です。

- `player_move`
- `player_interact`
- `player_interact_entity`
- `inventory_click`
- `inventory_drag`
- `player_drop_item`
- `player_swap_hand`
- `player_quit`
- `player_death`

通常の付与、更新、拒否、解除、期限切れ sweep、表示更新成功は高頻度のためログを出しません。現行実装に condition 専用の WARN ログや表示 task 専用 ERROR ログはありません。

## 3. プレイヤー向け表示

- 付与・解除ごとの chat message は送らない。
- condition feature 専用の `PlayerMsgId` / `player.properties` 定義は持たない。
- 有効状態は hud feature が HP / MP / ENG と同じ ActionBar に最大 3 件を装飾表示し、解除後は次回 HUD 更新で通常表示へ戻す。
- 攻撃・スキル・操作が制限された場合も、condition feature 自身は追加 chat message を送らない。

5900 番台の player message を condition 用には割り当てず、実在しない想定 ID を設計契約にしません。

## 4. パフォーマンス契約

- DoT / 間欠制御は 5 tick 間隔で、1 run 最大 300 condition を循環処理する。
- 表示は 10 tick 間隔、期限切れ sweep は 100 tick 間隔とする。
- プレイヤー ActionBar の状態異常欄は対象ごとに最大 3 件へ制限する。
- 凍結 BlockDisplay は対象ごとに最大 1 個とし、condition ごとに増殖させない。
- recurring particle は `ParticleDisplayService` の近傍 viewer 解決を使う。
- active condition と凍結 display の参照は UUID を key とする runtime map にだけ保持し、永続化しない。

## 5. バニラ視覚効果との境界

- `BURNING` の fire ticks は見た目だけに使う。Mob は `MobVanillaEffectProtectionService.applyPluginFireTicks` を経由し、バニラ炎上抑止と区別する。
- Poison / Blindness PotionEffect はクライアント表示だけに使い、効果値の正本にしない。
- `FIRE_TICK` などバニラ由来ダメージは condition DoT の正本にしない。
- Slowness、Weakness などのバニラ PotionEffect で冷気・衰弱を実装しない。

## 6. cleanup と障害境界

- `getActiveConditions` は対象単位、`purgeExpiredConditions` は全体 sweep として期限切れを解除する。
- player quit / death と Mob 破棄は対象単位の `clearAll` を呼ぶ。
- plugin disable は task cancel 後に `clearAllRuntimeState` を呼ぶ。
- cleanup は active map が把握している状態だけを対象とし、全 world の孤立 display 検索は行わない。
- `ConditionDisplayTask` は現行、対象単位の例外隔離を持たない。必要なログ・継続方針は [[27_9-未決事項]] とする。
