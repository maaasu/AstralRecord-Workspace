# 27_2.00-ユースケース

## 1. スキル命中で状態異常を付与する

1. `skill` executor は攻撃命中後、`ConditionApplyRequest` を作成する。
2. `ConditionService.applyCondition` は対象可否、死亡状態、NPC 除外、ボス耐性、付与確率を判定する。
3. 付与成功時、既存状態の重複規則に従って `ActiveCondition` を追加または更新する。
4. 付与時点の攻撃者ステータスから `snapshotPower` を確定する。
5. `ConditionDisplayService.showApplied` が本人・周囲向けに短い獲得表示を出す。

## 2. 炎上中に火属性 DoT を与える

1. `ConditionTickTask` が `BURNING` の `nextTickAtMs` 到達を検出する。
2. `ConditionTickService.tickCondition` が tick damage を算出する。
3. `DamageService.applyConditionDamage` へ `DamageType.MAGIC`, `DamageElement.FIRE`, `snapshotPower` を渡す。
4. `DamageService` は通常の shield / HP / death / threat / boss damage statistics 経路を使って反映する。
5. `ConditionDisplayService` は対象の fire ticks と炎パーティクルを維持する。

## 3. 毒中に毒属性 DoT と回復阻害を適用する

1. 毒付与時に `ActiveCondition.type = POISON` を保持する。
2. DoT は `DamageElement.POISON` として `DamageService.applyConditionDamage` に渡す。
3. 回復処理側は `ConditionService.healingReceivedMultiplier(target)` を参照し、`POISON` の倍率を乗算する。
4. 複数スタック時は倍率を下限値まで強化する。初期下限は 50% とする。

## 4. 冷気スタックから凍結へ移行する

1. `CHILLED` 付与時、既存スタックを最大 5 まで増やす。
2. スタックが 5 に達した場合、`FROZEN` を付与する。
3. `FROZEN` 付与後、`CHILLED` を解除する。
4. `FROZEN` 中は移動不可、攻撃不可、スキル不可、Mob AI 停止を適用する。
5. `FROZEN` 解除時、BlockDisplay の氷表示を破棄する。

## 5. スタン・沈黙・攻撃不可で行動を制限する

1. 通常攻撃処理は実行前に `ConditionService.canAttack(entity)` を確認する。
2. スキル発動処理は実行前に `ConditionService.canCastSkill(entity)` を確認する。
3. プレイヤー移動イベントと Mob AI tick は `ConditionService.canMove(entity)` を確認する。
4. 不可の場合、実処理を中断し、必要に応じて本人へ短い通知を出す。

## 6. 無敵でダメージを無効化する

1. `INVULNERABLE` 付与中の対象に `DamageService` がダメージ適用しようとする。
2. `DamageService` は計算前または計算後反映前に `ConditionService.isDamageImmune(victim)` を確認する。
3. true の場合、`DamageResult(0)` として HP/Shield 反映、threat 加算、ノックバックを行わない。
4. `ConditionDisplayService` はバリア粒子と BlockDisplay を表示する。

## 7. Mob / Boss 死亡・despawn で状態異常を解除する

1. `MobCombatService.handleDeath` または `MobService.destroy` が対象 Mob を破棄する前に `ConditionService.clearAll(mob)` を呼ぶ。
2. `ConditionService` は active condition を削除する。
3. `ConditionDisplayService.clearAll` が TextDisplay / BlockDisplay / fire ticks を破棄する。

## 8. プレイヤー退出・死亡で状態異常を解除する

1. プレイヤー退出時、`ConditionService.clearAll(player)` を呼ぶ。
2. プレイヤー死亡開始時、死亡処理前に `ConditionService.clearAll(player)` を呼ぶ。
3. 死亡中プレイヤーには新規 condition を付与しない。
4. 再ログイン時に過去の condition は復元しない。
