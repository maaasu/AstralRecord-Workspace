# 27_0.00-概要

## 1. 目的

`condition` 機能は、プレイヤーと戦闘 Mob に対して状態異常・行動制限・保護状態を一定時間付与し、効果処理と視覚表示を一元化する。

主目的は以下。

- 炎上、毒、出血、冷気、凍結、スタン、沈黙、攻撃不可、無敵、脆弱などの状態管理
- 状態異常中の DoT、行動制限、被ダメージ補正、回復阻害の適用
- 本人と周囲プレイヤーの双方に分かるパーティクル、TextDisplay、BlockDisplay、バニラ可視状態の表示
- 属性ダメージ（火 / 氷 / 毒 / 雷 / 聖 / 闇 / 無属性）の計算入力提供
- プレイヤーと Mob を `AstEntity` として同じ入口で扱う

## 2. コンテキスト

- 状態異常はオンライン中・スポーン中だけ有効な揮発状態として扱う。初期実装では DB 永続化しない。
- プレイヤー状態は `AstPlayer` または `ConditionService` の UUID 別メモリストアに保持する。
- Mob 状態は `MobInstance` または `ConditionService` の Mob instance UUID 別メモリストアに保持する。
- NPC は構造上 `AstEntity` として付与可能にしてよいが、`MobCategory.NPC` は初期ポリシーで付与不可にする。
- DoT はバニラ `EntityDamageEvent` / `Entity#damage(...)` を使わず、[[14_3.02-サービス]].`DamageService.applyConditionDamage` 経由で custom combat に流す。
- バニラ炎上、凍結、毒 PotionEffect のダメージや制御効果は正本にしない。必要な見た目だけをプラグイン管理で使う。

## 3. buff との境界

`buff` は `StatusType` に対する一時的な数値補正を扱う。
`condition` は、数値補正だけでは表せない戦闘状態を扱う。

| 区分 | 正本 feature | 例 |
|---|---|---|
| 攻撃力 +10、移動速度 +10%、防御力 -10 | `buff` | `attack_up_small`, `armor_break` |
| 炎上 DoT、毒 DoT、凍結、スタン、攻撃不可、無敵 | `condition` | `BURNING`, `POISON`, `FROZEN`, `INVULNERABLE` |
| 状態異常に伴う補助的な速度低下・被ダメージ増加 | `condition` | `CHILLED` の移動速度低下、`VULNERABLE` の被ダメージ増加 |

状態異常による一時的な能力低下を `buff` に変換して二重管理しない。
表示、残り時間、解除、重複規則、耐性判定を `condition` で完結させる。

## 4. 属性ダメージの位置づけ

属性は防御種別とは別軸で扱う。

- `DamageType`
  - 物理防御、魔法防御、防御無視のどれで軽減するかを表す。
- `DamageElement`
  - 火、氷、毒、雷、聖、闇、無属性のどの属性として補正・表示・耐性判定するかを表す。

例:

| 攻撃 | `AttackType` | `DamageType` | `DamageElement` |
|---|---|---|---|
| 剣の通常攻撃 | `MELEE` | `PHYSICAL` | `NEUTRAL` |
| 火球 | `MAGIC` | `MAGIC` | `FIRE` |
| 毒 DoT | `MAGIC` | `TRUE` または `MAGIC` | `POISON` |
| 凍結解除時の破砕ダメージ | `MAGIC` | `MAGIC` | `ICE` |

既存 skill / filebase の `damageType` はそのまま維持し、未指定の `damageElement` は `NEUTRAL` とする。

## 5. 構成要素（実装単位）

- `model/ConditionType`
  - 状態異常種別の列挙。
- `model/ConditionCategory`
  - DoT / 行動制限 / 防御状態 / 被ダメージ補正などの分類。
- `model/ActiveCondition`
  - 付与中状態、付与元、残り時間、スタック、次回 tick 時刻を保持する。
- `model/ConditionEffect`
  - DoT、移動不可、攻撃不可、スキル不可、無敵、被ダメージ倍率などの効果を表す。
- `model/ConditionApplyRequest`
  - スキル・Mob AI・コマンドなどからの付与要求。
- `service/ConditionService`
  - 付与、解除、照会、期限切れ整理、状態制約判定を制御する。
- `service/ConditionTickService`
  - DoT と periodic effect を処理する。
- `display/ConditionDisplayService`
  - パーティクル、TextDisplay、BlockDisplay、fire ticks などを表示する。
- `task/ConditionTickTask`
  - 一定間隔で全 active condition を処理する。
- `task/ConditionDisplayTask`
  - 一定間隔で周囲表示を更新する。
