# 27_3.05-タスク・スケジューラ

3 task は Bukkit main thread の `runTaskTimer` で実行し、初回遅延と周期に同じ tick 数を指定します。`start` は二重起動を無視し、`stop` は保持した `BukkitTask` を cancel します。

## 1. `ConditionTickTask`

| 項目 | 値 |
| --- | --- |
| 物理メソッド | `start(JavaPlugin)` / `stop()` / `run()` |
| 初回遅延・周期 | 5 tick |
| 1 run 上限 | 300 condition |
| 依存 | `ConditionService`, `ConditionTickService` |

`run` は `snapshotAllActiveConditions` を取得し、前回の `nextConditionIndex` から最大 300 件を循環処理します。件数が 300 を超える場合は次回 run が最初の未処理 index から再開します。snapshot が空なら index を 0 へ戻し、`stop` 時にも index を初期化します。

各 condition は個別の `try/catch` で隔離し、`RuntimeException` を `E_5901(conditionId, targetId)` へ記録して後続処理を継続します。

## 2. `ConditionDisplayTask`

| 項目 | 値 |
| --- | --- |
| 物理メソッド | `start(JavaPlugin)` / `stop()` / `run()` |
| 初回遅延・周期 | 10 tick |
| 依存 | `ConditionService`, `ConditionDisplayService` |

`run` は `snapshotVisibleTargets` で有効 condition を持つ対象を一意化し、対象ごとに `getActiveConditions` と `refreshTargetDisplay` を呼びます。表示ごとの viewer 解決は `ParticleDisplayService` に委譲します。

現行 task には対象単位の例外隔離や専用ログはありません。表示更新失敗時の隔離方針は [[27_9.00-未決事項]] とします。

## 3. `ConditionCleanupTask`

| 項目 | 値 |
| --- | --- |
| 物理メソッド | `start(JavaPlugin)` / `stop()` / `run()` |
| 初回遅延・周期 | 100 tick |
| 依存 | `ConditionService` |

`run` は `ConditionService.purgeExpiredConditions` を 1 回呼びます。サービスが内部 map を直接走査し、期限切れ condition の削除、表示解除、player status 再計算を行います。

対象 entity 消失の検出、孤立 BlockDisplay の全 world 検索、`MobVanillaEffectProtectionService` の fire tracking 掃除は現行 task の責務ではありません。

## 4. plugin lifecycle

- enable 時は `ConditionTickTask`、`ConditionDisplayTask`、`ConditionCleanupTask` の順に開始する。
- disable 時は同じ 3 task を停止してから `ConditionService.clearAllRuntimeState` を呼ぶ。
- `clearAllRuntimeState` は active map が把握する対象だけを掃除する。全 world の scoreboard tag 検索は行わない。
