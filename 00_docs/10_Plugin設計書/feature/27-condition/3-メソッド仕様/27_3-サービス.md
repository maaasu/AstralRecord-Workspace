# 27_3-サービス

## 1. `ConditionService.applyCondition`

### 1.1 付与前検証

次の対象は active map を変更せず、対応する `ConditionRejectReason` を返します。

| 条件 | 拒否理由 |
| --- | --- |
| AstralRecord 管理外 entity | `UNMANAGED_TARGET` |
| `PlayerDeathService` 上で死亡中の player | `DEAD_TARGET` |
| `MobCategory.NPC` | `NPC_TARGET` |
| `MobState.DEAD` | `DEAD_TARGET` |
| 実効確率の乱数判定に失敗 | `CHANCE_FAILED` |
| Boss 制御時間補正後が 1 tick 未満 | `RESISTED` |

### 1.2 付与確率

```text
effectiveChance = clamp(
  baseChance
  * (1 + sourceApplyChanceIncrease / 100)
  * (1 - targetApplyResistance / 100),
  0,
  100
)
```

- `source=null` の付与確率増加は 0 とする。
- 付与確率増加と付与耐性は `ConditionType` が指定する種別専用 `StatusType` を参照する。
- DoT 貫通は付与確率へ影響しない。
- source がある場合、基礎持続時間へ `状態異常持続時間増加 / 100` を加算倍率として適用する。
- Boss かつ `ConditionCategory.CONTROL` の持続時間は、上記補正後に 25% へ丸める。

### 1.3 新規付与と同種更新

新規付与では、固定値と `source ATTACK * powerCoefficient` を `snapshotPower` へ保存し、最初の DoT / 間欠制御時刻を設定します。

同種が有効な場合は次の順で更新します。

1. 要求 `strength` が既存値より高い場合は強い要求とする。
2. 同値なら `(snapshotPower + HP基準値 * healthRate) / tickIntervalTicks` を比較する。間隔 0 は分子をそのまま比較する。
3. 強い要求だけが source、strength、power、healthRate、interval、次回 DoT 時刻を置き換える。
4. 弱い要求でも終了時刻は `max(existingExpiresAt, requestedExpiresAt)` へ延長する。
5. player 対象なら `StatusService.refreshStatus` を呼び、`ConditionDisplayService.showApplied` で表示する。

## 2. 解除・照会・全体掃除

| 物理メソッド | 契約 |
| --- | --- |
| `removeCondition(target, type)` | 指定 type を 1 件解除し、表示と player status を更新する。未保持は 0、解除成功は 1 |
| `clearAll(target)` | 対象 map を削除し、全表示と player status を更新する。解除件数を返す |
| `getActiveConditions(target)` | 対象の期限切れを除去してから immutable list を返す |
| `snapshotAllActiveConditions()` | 全対象から呼出時点で有効な condition だけを snapshot する。期限切れ自体はこのメソッドで削除しない |
| `snapshotVisibleTargets()` | 有効な condition を持つ `AstEntity` の集合を返す |
| `purgeExpiredConditions()` | 内部 map 全体を直接走査し、期限切れ condition を表示解除・status 更新付きで削除する |
| `clearAllRuntimeState()` | 登録済み対象の表示を解除して active map を空にし、player status を更新する |

`ConditionCleanupTask` は、有効状態だけを返す snapshot ではなく `purgeExpiredConditions` を呼ぶことで、通常照会が発生しない対象の期限切れも掃除します。

## 3. 行動可否と倍率

| 物理メソッド | 現行契約 |
| --- | --- |
| `canMove` | `movementBlocked` または間欠制御中が 1 件でもあれば false |
| `canAttack` | `attackBlocked` が 1 件でもあれば false |
| `canCastSkill` | `skillBlocked` が 1 件でもあれば false |
| `canInteract` | 同じ condition が movement / attack / skill をすべて block する場合に false |
| `canRunAi` | `aiBlocked` が 1 件でもあれば false |
| `movementSpeedMultiplier` | 移動不可なら 0。その他は active condition の最小倍率 |
| `castTimeMultiplier` | active condition の最大倍率。下限 1 |
| `damageDealtMultiplier` | active condition の倍率を乗算する。source `null` は 1 |
| `isHealingBlocked` | `healingBlocked` が 1 件でもあれば true |
| `healingReceivedMultiplier` | 回復阻害中は 0、それ以外は 1 の互換 API |
| `isDamageImmune` | 無敵 condition がないため常に false の互換 API |
| `damageTakenMultiplier` | 被ダメージ倍率 condition がないため常に 1 の互換 API |

## 4. `conditionDamageMultiplier`

燃焼・感電・毒だけが種別専用 DoT ステータスを使います。

```text
effectiveResistance = max(0, dotResistance - dotPenetration)
multiplier = max(0, 1 + dotDamageIncrease / 100)
           * max(0, 1 - effectiveResistance / 100)
```

- source `null` の増加・貫通は 0 とする。
- 貫通は DoT 耐性だけを相殺し、付与耐性へ影響しない。
- 属性増加・属性耐性・属性貫通は参照しない。

## 5. `ConditionTickService.tickCondition`

1 件の `ActiveCondition` を次の順で処理します。

1. 期限切れなら `removeCondition` して終了する。
2. 感電の次回制御時刻に到達していれば 6 tick の移動禁止を設定し、次回を 16～32 tick 後へ更新して pulse 表示する。
3. DoT なし、または次回 pulse 前なら終了する。
4. `snapshotPower + HP基準値 * healthRate` を 0 以上へ clamp する。
5. 正の値なら `DamageService.applyConditionDamage` と表示 pulse を呼ぶ。
6. `lastTickAtMs` と `nextTickAtMs` を現在時刻基準で更新する。

燃焼・感電は pulse 時点の最大 HP、毒は pulse 時点の現在 HP を割合基準にします。DoT 専用倍率、衰弱、毒の非致死 clamp、シールド・HP・死亡は `DamageService` が処理します。
