# 27_3.02-サービス

## 状態異常付与

クラス名: `ConditionService`
物理名: `applyCondition`

1. `ConditionApplyRequest.target` が managed entity であることを検証する。
   - `AstEntityType.BUKKIT` は付与不可として `ConditionApplyResult.rejected(UNMANAGED_TARGET)` を返す。
2. 対象がプレイヤーの場合、死亡中でないことを検証する。
   - `PlayerDeathService.isDead(target.id()) = true` なら `DEAD_TARGET` として拒否する。
3. 対象が Mob の場合、`MobCategory.NPC` でないことを検証する。
   - NPC は `NPC_TARGET` として拒否する。
4. `chance` を 0-100 にクランプし、100 未満ならサーバー乱数で付与可否を判定する。
5. `ConditionResistanceProfile` を解決し、duration と効果量へ耐性倍率を適用する。
   - duration が 1 tick 未満になる場合は `RESISTED` として拒否する。
6. 付与時点の `snapshotPower` を算出する。
   - `basePower + sourceAttack * sourceAttackCoefficient + sourceTypedAttack * sourceTypedAttackCoefficient + targetMaxHealth * targetMaxHealthCoefficient`
   - source が `null` の場合、source 由来係数は 0 とする。
7. 同種 condition が有効な場合、`ConditionStackPolicy` に従って既存 condition を更新する。
8. 新規または更新された `ActiveCondition` をメモリストアへ保存する。
9. `ConditionDisplayService.showApplied` を呼び、本人・周囲表示を開始する。
10. `ConditionApplyResult.applied(activeCondition)` または `updated(activeCondition)` を返す。

## 状態異常解除

クラス名: `ConditionService`
物理名: `removeCondition`

1. 対象 ID と `ConditionType` に一致する active condition を検索する。
2. 見つからない場合は 0 件解除として終了する。
3. 見つかった condition をメモリストアから削除する。
4. `ConditionDisplayService.clearCondition` を呼び、TextDisplay / BlockDisplay / fire ticks を解除する。
5. 解除件数を返す。

## 全状態異常解除

クラス名: `ConditionService`
物理名: `clearAll`

1. 対象 ID に紐づく active condition をすべて取得する。
2. 取得した condition をメモリストアから削除する。
3. `ConditionDisplayService.clearAll` を呼び、対象に紐づく表示生成物をすべて破棄する。
4. 解除件数を返す。

## 状態異常照会

クラス名: `ConditionService`
物理名: `getActiveConditions`

1. 対象 ID に紐づく active condition を取得する。
2. 現在時刻が `expiresAtMs` を超えた condition は除外し、内部的に期限切れ解除へ回す。
3. 残り condition を `List.copyOf` 相当の変更不可リストで返す。

## 移動可否判定

クラス名: `ConditionService`
物理名: `canMove`

1. 対象の active condition を取得する。
2. `ConditionEffect.movementBlocked = true` の condition が 1 件でもあれば false を返す。
3. それ以外は true を返す。

対象 condition:

| 種別 | 判定 |
|---|---|
| `FROZEN` | 移動不可 |
| `STUNNED` | 移動不可 |

## ダメージ無効判定

クラス名: `ConditionService`
物理名: `isDamageImmune`

1. 対象の active condition を取得する。
2. `ConditionEffect.damageImmune = true` の condition があれば true を返す。
3. それ以外は false を返す。

`DamageService` は shield 計算前にこの判定を呼び、true の場合は HP/Shield ダメージ、threat、ノックバック、ダメージ表示を発生させない。

## 被ダメージ倍率取得

クラス名: `ConditionService`
物理名: `damageTakenMultiplier`

1. 対象の active condition を取得する。
2. 各 condition の `damageTakenMultiplier` を乗算する。
3. 下限 0.1、上限 5.0 にクランプして返す。

初期状態で `VULNERABLE` は 1 スタックにつき 1.10、最大 3 スタックで 1.30 相当とする。

## 回復受取倍率取得

クラス名: `ConditionService`
物理名: `healingReceivedMultiplier`

1. 対象の active condition を取得する。
2. 各 condition の `healingReceivedMultiplier` を乗算する。
3. 下限 0.5、上限 2.0 にクランプして返す。

初期状態で `POISON` は 1 スタックにつき 0.85、最大 3 スタックで下限 0.5 とする。

## 状態異常 tick 処理

クラス名: `ConditionTickService`
物理名: `tickCondition`

1. 対象 entity を `ConditionTargetResolver` で `AstEntity` に復元する。
2. 対象が存在しない、死亡中、Mob 死亡済み、NPC になっている場合は condition を解除する。
3. 現在時刻が `expiresAtMs` 以上なら condition を解除する。
4. `tickIntervalTicks <= 0` の condition は DoT 処理を行わず、次の condition へ進む。
5. `nextTickAtMs` 未満なら処理しない。
6. `snapshotPower`、stack、対象最大 HP 係数から tick damage を算出する。
7. `DamageService.applyConditionDamage(source, target, tickDamage, damageType, damageElement, type)` を呼ぶ。
8. `lastTickAtMs` と `nextTickAtMs` を更新する。
9. `ConditionDisplayService.pulse` を呼び、DoT 発生時の短い粒子/ダメージ色表示を出す。
