# 27_2-ユースケース

## 1. スキルから状態異常を付与する

1. スキル実行側が命中処理とは別に `conditions` 定義を読み、対象ごとの `ConditionApplyRequest` を作る。
2. `ConditionService` が管理対象・生存状態・NPC 対象を検証する。
3. 付与元の種別別付与確率増加と、対象の種別別付与耐性から実効確率を求める。
4. Boss かつ `CONTROL` category の場合は持続時間を 25% へ短縮する。
5. 新規付与または同種更新後、プレイヤーの status を再計算し、即時表示と particle pulse を行う。

属性ダメージの `Element` は状態異常付与条件に使いません。火属性攻撃でも、`ConditionApplyRequest` がなければ `BURNING` は発生しません。

## 2. 同種状態異常を更新する

1. 同じ対象・同じ `ConditionType` の既存状態を取得する。
2. 要求 `strength` が高ければ、付与元、固定値、HP割合、間隔を新要求へ置き換える。
3. `strength` が同じ場合、`(固定値 + HP割合値) / tick間隔` で正規化した強度が高い要求だけを採用する。
4. 弱い要求では効果値を保持する。
5. どの場合も終了時刻は `max(既存, 新要求)` とし、短縮しない。

冷気と凍結は別の `ConditionType` なので同時保持します。凍結中は完全移動禁止が優先され、凍結解除後も冷気が残っていれば移動 0.5 倍へ戻ります。

## 3. DoT を反映する

1. `ConditionTickTask` が有効な active condition を最大 300 件取得する。
2. `ConditionTickService` が pulse 時刻に達した燃焼・感電・毒の基礎値を求める。
3. `DamageService.applyConditionDamage` が種別別 DoT 増加・耐性・貫通と、付与元の衰弱倍率を適用する。
4. シールドの有無と残量にかかわらず HP、死亡処理を反映する。シールド残量は変更しない。
5. 成功した DoT pulse の particle を表示し、次回時刻を更新する。

DoT は会心せず、すべてシールドを貫通します。毒を含む DoT は対象 HP を参照せず、最終ダメージで HP 0 に到達できます。

## 4. 凍結・感電中の行動を制限する

1. `ConditionPlayerEventHandler` が player move と各種 interaction を受け取る。
2. 凍結中は移動を元座標へ戻し、interaction、inventory 操作、drop、swap を cancel する。
3. 感電の間欠制御中は `canMove` が false となり、移動だけを元座標へ戻す。
4. 通常攻撃、スキル、Mob AI は各 feature が `canAttack`、`canCastSkill`、`canRunAi` を照会して止める。

## 5. 回復阻害を反映する

1. `StatusService` の HP / MP / ENG / Shield 回復 API が `ConditionService.isHealingBlocked` を確認する。
2. 回復阻害中は通常回復要求を現在値のまま返す。
3. 死亡復帰などの `StatusService.restoreAll` は全回復用の別経路であり、回復阻害判定を通さない。

## 6. 期限切れ・終了時に解除する

1. 通常照会では `getActiveConditions` が対象単位で期限切れを除去する。
2. `ConditionCleanupTask` は 100 tick ごとに `purgeExpiredConditions` を呼び、照会されない対象も全体 sweep する。
3. player quit / death と Mob 破棄では対象単位の `clearAll` を呼ぶ。
4. plugin disable では 3 task を停止し、`clearAllRuntimeState` で active map と登録済み表示を破棄する。
