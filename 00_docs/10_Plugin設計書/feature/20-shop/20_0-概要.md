# 20_0-概要

## 目的

master data で定義した商品と複数種類の対価を GUI で提示し、player inventory の整合性を維持したまま一括購入させる。

## 責務

- shop と shop recipe を独立に読み込み、一つの `CacheSnapshot` として公開する。
- shop ID または色コードを除いた表示名で定義を検索する。
- command は `PUBLIC`、NPC は `PUBLIC`／`NPC_ONLY` を開く。
- direct cost と recipe cost を合算し、購入 preview を生成する。
- `AccountMode.PLAYER`、所持量、格納可能量を検証して購入する。
- 支払い・付与途中の失敗時に inventory snapshot を復元する。

## 責務外

- 市場相場、player 間販売、shop stock、販売回数、期間限定在庫。
- NPC の spawn／interaction 解決。
- 商品 item master／recipe master の編集。

## 現在の契約

- `/shop <shopId または表示名>` で開く。`/shop open ...` ではない。
- `ShopService` は購入 domain service であり GUI を開かない。open は `ShopGuiEventHandler` が担う。
- `amount` は 1 口あたりの商品数量、GUI の quantity は購入口数である。
- 価格は `priceGold + recipe.requiredCurrency` と、`requiredItems + recipe.ingredients` の合計。
- stock model は存在しないため、購入可能性は残高と inventory capacity だけで決まる。
- マーケット拡張トークンは `astrald_shop`（NPC 専用）で販売し、購入数に応じた枠の有効化は market API が `CURRENCY` inventory の所持数量を正本として判定する。
- `astrald_shop` のトークン購入対価は組み込み通貨 item `astrald` のみで、Gold は使用しない。α／β／γ／δの価格はそれぞれ50／100／150／200アストラルドとする。
- `astrald_shop` に stock または購入回数制限はなく、種類ごとの枠反映上限を超えて購入したトークンも CURRENCY inventory に保持する。

## 依存・連携

| feature | 依存内容 |
|:--|:--|
| infrastructure / filebase | shop master の一覧取得と cache |
| filebase / shop repository | `recipeId` の追加 gold・ingredient cost |
| item | 商品・必要 item の model 解決と表示名 |
| inventory / currency | 所持数、支払い、商品付与、snapshot／保存 |
| mob / npc / menu | NPC 導線と GUI navigation |

## 変更影響

- shop／entry／recipe schema を変更した場合は [[20_1-モデル定義]]、filebase 設計書、parser を更新する。
- 購入 validation・補償順序を変更した場合は [[20_3-メソッド仕様]]、[[20_4-統合フロー]]、[[20_5-例外・ログ・運用]]を更新する。
- command／NPC access を変更した場合は [[20_2-ユースケース]] と [[20_3-メソッド仕様]]を更新する。
- 在庫・販売回数制限を導入する場合は model と永続化を設計してから仕様へ追加する。
