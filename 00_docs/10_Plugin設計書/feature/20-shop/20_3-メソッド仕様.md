# 20_3-メソッド仕様

## Cache 読み込み・置換

クラス名: `ShopService`
物理名: `loadCacheSnapshot` / `replaceCacheSnapshot` / `warmCaches`

- 引数: replace は `CacheSnapshot snapshot`
- 戻り値: snapshot、なし、または shop 件数
- 例外: repository／recipe 取得失敗を呼び出し元へ伝播する。

shop と recipe を先に読み、構築済み snapshot を両 repository へ置換する。

## Shop 検索

クラス名: `ShopService`
物理名: `findById` / `findByIdOrName` / `findCommandAccessibleByIdOrName`

- 引数: shop ID または検索文字列
- 戻り値: `ShopDefinition?`
- 例外: なし

表示名検索は色コードを除去し、trim、空白圧縮、小文字化する。command 用は `access.isCommandAccessible()` を追加検証する。

## 購入 preview

クラス名: `ShopService`
物理名: `preview`

- 引数: `AstPlayer player`, `ShopEntry entry`, `int quantity`
- 戻り値: `ShopPurchasePreview`
- 例外: なし

`AccountMode.PLAYER` でない場合は購入不可 preview。Gold と currency／item の不足分を `missingItems` に集める。category が `CURRENCY` かつ ID が `gold` の cost は組み込み全額面の Gold 換算残高で判定し、その他の `CURRENCY` cost（`astrald` を含む）は同一 currency ID の残高だけで判定する。`NORMAL` item の数量とは混同しない。Gold が 0 で currency cost のみの場合、GUI は必要 Gold 行を表示せず、通貨名と必要数を表示する。スキルジェムは `ShopSpecialPurchaseHandler` から習得・レベルアップ・最大レベル・処理中・未解決を取得し、数量を1へ固定する。最大レベル、処理中、未解決は `canPurchase=false` とする。

## 購入

クラス名: `ShopService`
物理名: `purchase`

- 引数: `AstPlayer player`, `ShopEntry entry`, `int quantity`
- 戻り値: 全支払いと exact 商品付与を完了した場合 `true`
- 例外: 途中失敗は `false` と snapshot restore へ変換する。

1. gameplay mode、商品 model、preview、NORMAL inventory capacity を検証する。
2. account inventory state を snapshot する。
3. Gold、required currency／item を category 別の残高から消費する。通常の所持先で不足する required currency／item は、`storage_cloud_access_token` を CURRENCY inventory に1個以上所持している場合だけ STORAGE から補う。`astrald_shop` では `astrald` を消費する。
4. `max(1, entry.amount) * quantity` を商品 category に対応する inventory へ付与する。`CURRENCY` 商品は `CURRENCY` へ付与し、通常 BAG へ混在させない。
5. cost 消費と商品付与は同じ snapshot 境界で扱う。exact amount でなければ restoreする。通常商品は必要な GUI 反映と `saveNow` を行い、購入成功通知は保存完了を待たず、保存成功後の通知は `saveNow` の成功 future に接続する。currency 間だけで完結する購入では BAG GUI を不要に更新しない。
6. スキルジェムは購入操作をaccount単位で予約し、購入により新規作成されたentry UUIDを特定する。ローカル支払い・付与の直後に `SkillGemPurchaseService` へ渡し、外部 mutation 専用 lane で事前保存、未習得なら `learnFromPurchaseAsync`、習得済みなら `levelUpFromPurchaseAsync`、対象entry正本照合、操作後再保存を直列実行する。API mutation完了までは同じaccountの追加ジェム購入を拒否し、完了後にオンラインの同一accountが開いている一覧・確認画面だけを再評価する。

## スキルジェム購入効果

クラス名: `SkillGemPurchaseService`、`ShopSpecialPurchaseHandler`
物理名: `preview` / `reserve` / `completePurchase` / `cancel`

- 引数: `AstPlayer player`、購入 `ItemModel`、購入entry UUID、失敗補償、保存成功・表示更新callback
- 戻り値: `ShopSpecialPurchaseState` または予約成否
- 例外: 習得状態のロード前、skill定義不在、同一accountの処理中は購入不可stateへ変換する。

未習得は `SKILL_LEARN`、APIロード順の先頭個体が最大レベル未満なら `SKILL_LEVEL_UP`、最大レベルなら `SKILL_MAX_LEVEL` を返す。成功時はロード済み習得キャッシュとオンライン時のインベントリGUIを更新し、新規習得は `SKILL_LEARNED`、レベルアップは `SKILL_ENHANCED` をオンライン状態に依存せず通知する。APIが明示的に拒否した場合、または正本照合で mutation 未成立を確認した場合は、購入entryだけを除去して支払額・素材を全返却してから失敗通知する。最大レベルではreserveせず、支払い以降の購入処理へ進めない。

## Cost 解決

クラス名: `ShopService`
物理名: `resolveGoldCost` / `resolveRequiredItems`

- 引数: `ShopEntry entry`
- 戻り値: 1 口の gold、または merged `List<ShopCostItem>`
- 例外: なし

direct cost と `recipeId` の cost を合算し、負の gold は 0 として扱う。

## GUI open・event

クラス名: `ShopGuiEventHandler`、`ShopGui`
物理名: `openFromCommand` / `openFromNpc` / `onInventoryClick` / `onInventoryDrag`

- 引数: player、shop ID、または inventory event
- 戻り値: なし
- 例外: event は `runSafely` で捕捉し `E_5601` に operation を渡す。

スキルジェムは一覧・確認画面の両方に `購入時の効果` を表示する。未習得は習得、習得済みは現在レベルから次レベルへの変化、最大レベルは `※ すでにレベルMAXのため購入できません。` を表示する。数量変更操作は受理せず、`canPurchase=false` の確定クリックはcancelして拒否音だけを再生する。非同期の習得・強化完了時は、現在開いている同じshopの一覧または確認画面を再描画する。

command open は `PUBLIC` のみ、NPC open は access 制限をかけず既知 ID を開く。click／drag は対象 GUI の標準操作を cancel する。

## `/shop` command

クラス名: `ShopCommand`
物理名: `executePlayerCommand`

- 構文: `/shop <shopId または表示名>`
- 実行者: gameplay player
- 戻り値: なし
- 例外: 未解決を `P_5930` へ変換する。
