# 20_3-メソッド仕様

## Cache 読み込み・置換

クラス名: `ShopService`
物理名: `loadCacheSnapshot` / `replaceCacheSnapshot` / `warmCaches`

- 引数: replace は `CacheSnapshot snapshot`
- 戻り値: snapshot、なし、または shop 件数
- 例外: repository／recipe 取得失敗を呼び出し元へ伝播する。

shop と recipe を先に読み、構築済み snapshot を両 repository へ置換する。公開後に指定レシピの未解決商品を検査し、管理者向け警告を出す。

## Shop 検索

クラス名: `ShopService`
物理名: `findById` / `findByIdOrName` / `findCommandAccessibleByIdOrName`

- 引数: shop ID または検索文字列
- 戻り値: `ShopDefinition?`
- 例外: なし

表示名検索は色コードを除去し、trim、空白圧縮、小文字化する。command 用は `access.isCommandAccessible()` を追加検証する。

## 購入 preview

クラス名: `ShopService`
物理名: `preview`

- 引数: `AstPlayer player`, `ShopEntry entry`, `int quantity`
- 戻り値: `ShopPurchasePreview`
- 例外: なし

`AccountMode.PLAYER` でない場合は購入不可 preview。Gold と currency／item の不足分を `missingItems` に集める。category が `CURRENCY` かつ ID が `gold` の cost は組み込み全額面の Gold 換算残高で判定し、その他の `CURRENCY` cost（`99a00008`、旧ID `astrald` を含む）は同一 currency ID の残高だけで判定する。`NORMAL` item の数量とは混同しない。Gold が 0 で currency cost のみの場合、GUI は必要 Gold 行を表示せず、通貨名と必要数を表示する。スキルの習得・レベルアップはショップ preview の対象ではなく、スキルマネージャーが skill master の必要素材定義に従って実行する。

preview は商品 model を解決し、`max(1, entry.amount) * quantity` の全量を `InventoryService.canAddItemToNormalInventory` で判定する。支払いによる空きの増加は先取りせず、購入時と同じスタック余裕・カテゴリ別収納先・オーブ自動収納の条件を用いる。容量不足は `inventoryFull` で対価不足とは独立して保持し、`canPurchase=false` とする。GUI 初回表示・数量変更・購入後の再表示で再計算し、表示後も確定時と重要操作 lane 内で再検証する。

指定された `recipeId` が SHOP レシピとして解決できない場合は、費用・不足情報を空にし `canPurchase=false` を返す。direct cost だけの価格を有効な購入費用として提示しない。未指定・空白の場合は従来どおり direct cost のみを使用する。

preview 内ではレシピを一度だけ解決し、存在判定と Gold・素材計算に同じ値を使う。途中でマスタが再公開されても、検証済みレシピの費用を省略しない。

## 購入

クラス名: `ShopService`
物理名: `purchase`

- 引数: `AstPlayer player`, `ShopEntry entry`, `int quantity`
- 戻り値: SQL ACK 後に購入結果を返す `CompletableFuture<Boolean>`
- 例外: 業務条件の再検証失敗は `false`、保存失敗は exceptional completion とし、どちらも必要な rollback を完了してから返す。

1. gameplay mode、商品 model、指定レシピの解決を含む preview、NORMAL inventory capacity を検証する。
2. `executeCriticalPlayerMutation` へ登録し、lane 内でも preview と容量を再検証する。重要操作より前の dirty state は先に SQL ACK まで保存する。
3. account inventory state と装備 cache の rollback 点を取得する。
4. Gold、required currency／item を category 別の残高から消費する。通常の所持先で不足する required currency／item は、`99a00010` を CURRENCY inventory に1個以上所持している場合だけ STORAGE から補う。`astrald_shop` では `99a00008`（旧ID `astrald` も互換受付）を消費する。
5. `max(1, entry.amount) * quantity` を商品 category に対応する inventory へ exact amount 付与する。`CURRENCY` 商品は `CURRENCY` へ付与し、通常 BAG へ混在させない。
6. cost 消費と商品付与を含む完成 player-state snapshot を即時保存する。保存失敗または途中失敗では inventory と装備 cache を操作前へ戻す。
7. SQL ACK 後にだけ `applyCommittedPurchase` が GUI、`SHOP_PURCHASED` 通知、保存済み購入 listener を反映する。currency 間だけで完結する購入では BAG GUI を不要に更新しない。

## Cost 解決

クラス名: `ShopService`
物理名: `resolveGoldCost` / `resolveRequiredItems`

- 引数: `ShopEntry entry`
- 戻り値: 1 口の gold、または merged `List<ShopCostItem>`
- 例外: なし

direct cost と `recipeId` の cost を合算し、負の gold は 0 として扱う。費用の提示前に `isRecipeAvailable(entry)` で指定レシピの存在を検証し、未解決なら費用を表示しない。

`isRecipeAvailable(entry)` はレシピ未指定・空白または解決可能な場合だけ `true` を返す。未解決時は商品ごとに `W_6301` を一度記録し、cache 公開時に警告の抑制状態をリセットする。

## GUI open・event

クラス名: `ShopGuiEventHandler`、`ShopGui`
物理名: `openFromCommand` / `openFromNpc` / `onInventoryClick` / `onInventoryDrag`

- 引数: player、shop ID、または inventory event
- 戻り値: なし
- 例外: event は `runSafely` で捕捉し `E_5601` に operation を渡す。

command open は `PUBLIC` のみ、NPC open は access 制限をかけず既知 ID を開く。click／drag は対象 GUI の標準操作を cancel する。

## `/shop` command

クラス名: `ShopCommand`
物理名: `executePlayerCommand`

- 構文: `/shop <shopId または表示名>`
- 実行者: gameplay player
- 戻り値: なし
- 例外: 未解決を `P_5930` へ変換する。
