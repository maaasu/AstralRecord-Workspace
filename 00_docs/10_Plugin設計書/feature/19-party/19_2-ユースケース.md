# 19_2-ユースケース

## UC-19-01 party を作成する

- `AccountMode.PLAYER` かつ未所属の player が実行する。
- UUID を採番し、実行者を leader／最初の member として登録する。
- 作成履歴を非同期記録する。

## UC-19-02 招待する／承認・辞退する

- inviter が未所属なら party を自動作成する。
- leader のみ online target を招待でき、自己招待、所属済み、満員を拒否する。招待者または target が Dungeon／Boss の作成開始後の参加者なら拒否する。
- target が open 送信 session 中でなければ承諾 command 付きのクリック式通知、参加中なら招待を保持して非クリック式通知を送る。
- target は leader 名を指定して承認または辞退する。
- 承認時は leader online、party 存在、leader 維持、空き枠を再検証する。作成開始後の Dungeon／Boss 参加者は招待を承認できない。

## UC-19-03 脱退・切断する

- member を party と逆引きから除外する。
- leader が抜けて member が残る場合、加入順先頭へ leader を移す。
- logout も同じ内部処理で即時脱退する。

## UC-19-04 解散・追放・leader 移譲

- 解散、追放、移譲は現在 leader のみ実行できる。
- 解散は全 member の逆引きと関連 invite を削除する。
- 追放は自己を対象にできず、同じ party の member だけを除外する。
- 移譲先は同じ party の別 member とする。

## UC-19-05 party chat

- `/party chat <message>` で現在partyのonline memberへ送り、発言者・party識別名・本文をProxyへ監視通知として送る。
- `/party chat` は現在 party に所属している実行者の通常チャット送信先を party chat へ切り替える。再実行で全体 chat へ戻す。
- モード有効中の通常チャットは現在partyのonline memberへ送る。party未所属、空messageは拒否する。Proxyは監視通知を`serverAuthorityUsers`へ全チャンネル横断で配信し、DBのpermissionだけでは監視対象にしない。

## UC-19-06 管理者が party 一覧を確認する

- `user.permission` が Admin の player が `/party list` を実行すると、現在保持している全 party を作成順で表示する。
- 各 party の一覧行には party ID、人数、leader を表示し、カーソルを合わせると hover text で参加者一覧と leader 表示を確認できる。
- Admin 以外の `/party list` は従来どおり自身の party member 一覧を表示する。

## UC-19-07 Mob 報酬を共有する

- `MobCombatService` は正の threat を持つ参加者を先に recipient 候補へ入れ、討伐者の `Party` を `findParty` で取得する。
- party member UUID を列挙し、online、討伐者と同一 world、討伐者から 60 block 以内の player を追加する。
- party feature 自身に `findNearbyMembers` は存在しない。

## UC-19-08 パーティーを掲示板へ公開する

- 現在のleaderだけがパーティーGUIから募集設定GUIを開ける。
- 紙を置いた金床GUIの名前変更欄で募集内容を入力する。制御文字を除去して前後空白を取り除き、空文字列と50文字超を拒否する。
- 参加方式は「承認が必要」と「承認不要で参加可能」を切り替えられる。
- 募集内容が未設定、またはpartyが満員の場合は公開できない。
- 掲載中も募集内容と参加方式を変更でき、leaderは同じGUIから掲載を停止できる。

## UC-19-09 掲示板から参加する

- `PARTY_BOARD` GUI actionを持つNPCから、現在のサーバー内で公開中のpartyだけをページング表示する。
- 各項目はleaderのプレイヤーヘッドとし、leader名に基づくparty名、承認要否、現在member、募集内容を表示する。
- 承認不要の場合、クリック時に所属・挑戦中状態・掲載状態・空き枠を再検証して即時参加する。
- 承認制の場合、クリック時に同じ条件を検証して参加申請を保持し、leaderへ`/party approve <player>`を実行するクリック可能メッセージを送る。leaderが送信session中の場合はcommandを含む非クリック式通知にする。
- leaderは通知クリックまたはcommand入力で申請者を参加させる。承認時もonline、未所属、挑戦中状態、掲載状態、空き枠を再検証する。
- 参加により上限6人へ到達した場合は掲載を自動停止し、残りの参加申請を破棄する。
