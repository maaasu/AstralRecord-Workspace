# 19_5-例外・ログ・運用

## 例外方針

- 業務上の拒否は `PartyActionResult.failure` で返し、例外を投げない。
- party state 更新は synchronized method 内で一貫して行う。
- ユーザー履歴は async の best effort とし、失敗しても party 操作を取り消さない。
- GUI event 例外は基盤の `runSafely` で捕捉する。

## ログ・メッセージ

- `PlayerMsgId.P_5900`〜`P_5925` と party chat 用 message を操作結果・通知に使う。
- `LogId.E_6100` は party GUI／quit event の player と operation を記録する。
- `LogId.W_6100` は user history の `userId`、event type、reason を記録する。

## 運用

- party はメモリ限定で、plugin disable／再起動時に全件消える。
- logout は自動脱退となるため、一時切断からの自動復帰はない。
- member 上限を変更する場合は GUI 表示、service validation、message を同時に更新する。
- party 状態を server 間共有する要件が生じた場合は、現在の同期 map をそのまま永続 model とみなさず別設計を行う。
