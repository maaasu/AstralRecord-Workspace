# 19_0-概要

## 目的

同一サーバープロセスでオンライン中のプレイヤーが一時的なグループを作り、招待、リーダー操作、party chat、Mob 報酬共有を利用できるようにする。

## 責務

- `Party`、member 逆引き、target 別招待をメモリ保持する。
- 作成、招待、承認、辞退、脱退、解散、追放、リーダー移譲を同期化して更新する。
- 参加・権限変更を online member へ通知し、ユーザー履歴を非同期記録する。
- GUI と `/party` / `/pt` の両導線へ同じ `PartyService` 契約を提供する。
- パーティーチャットの送信モードと管理者向けパーティー一覧を提供する。
- logout 時に対象 member を即時脱退させる。

## 責務外

- DB への party 永続化、server 間 party、offline member 維持。
- 報酬量の計算。party feature は membership を提供し、Mob 側が同一 world・60 block 内を選ぶ。
- 自動 match making。

## 現在の制約

- party 上限は leader を含め 6 人。
- party 操作は `AccountMode.PLAYER` のみ。Dungeon／Boss の作成開始後は招待・承認を行わない。
- invite は `createdAt` を保持するが、有効期限判定は実装していない。
- leader が脱退・切断した場合、`LinkedHashSet` の先頭に残る member を次 leader とする。
- plugin disable 時は `clearAll()` で全 party／invite を破棄する。

## 依存・連携

| feature | 依存内容 |
|:--|:--|
| player / user | `AccountMode.PLAYER` guard、通知、ユーザー履歴 |
| menu / gui | パーティー一覧・メンバー操作 GUI |
| chat | `/party chat` の party member と Admin 宛配信、通常チャットのトグル |
| mob | 討伐報酬の party member 展開と距離判定 |
| trade | target が open trade session 中の招待通知を非クリック式へ切り替える |

## 変更影響

- party／invite の保持構造、上限、lifecycle を変更した場合は [[19_1-モデル定義]] と [[19_5-例外・ログ・運用]]を更新する。
- 招待、脱退、権限操作を変更した場合は [[19_2-ユースケース]]、[[19_3-メソッド仕様]]、[[19_4-統合フロー]]を更新する。
- コマンド alias、パーティーチャットモード、管理者一覧表示を変更した場合は [[19_2-ユースケース]]、[[19_3-メソッド仕様]]、[[19_4-統合フロー]]を更新する。
- 報酬共有距離・対象条件を変更した場合は mob feature と [[19_4-統合フロー]]を更新する。
- 未実装の招待有効期限を決定した場合は [[19_9-未決事項]]を解消し、実装・運用章へ反映する。
