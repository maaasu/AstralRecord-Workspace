# 29_2-ユースケース

## 1. NPCからボードを開く

1. playerがクエストGUI actionを持つNPCを右または左クリックする。
2. 共通入力gatewayがNPC候補を一件に確定する。
3. `MobInteractionEventHandler`が`type=QUEST`または`QUEST_BOARD`と`boardId`を解決する。
4. gameplay accountかつboard定義が存在する場合、NPC template IDを保持したボードGUIを開く。
5. pageごとのquestを表示状態、目標、受領条件、報酬とともに描画する。

## 2. クエストを受領する

1. ボード上の`AVAILABLE` questをクリックする。
2. gameplay account mode、現在の表示状態、受領上限を再検証する。
3. 同じitem IDの受領条件を集約し、全必要数を所持しているか確認する。
4. `consume=true`の合計数をitem IDごとに一回消費する。
5. `QuestProgress.start`で進行を作り、受領元NPC template IDを保存する。
6. クエスト状態を最新保存世代へ登録し、受領通知と`UI_TOAST_IN`を再生する。

## 3. 進行度を確認する

1. メインメニューのクエスト項目、または`/quest`で受領中・報告可能questの一覧GUIを開く。
2. loreへ各目標の`現在数 / 必要数`、受領条件、報酬を表示する。
3. active questは最大28件まで一覧へ描画する。通常は`QUEST_LIMIT`によりこれより少なく制限される。
4. active questがない論理スロットには、現在の受領枠数と`QUEST_LIMIT`を増やすと受領可能数が増えることを示す案内itemを表示する。

## 4. クエストを破棄する

1. 一覧GUIのquest itemへ通常ドロップまたはCtrl+ドロップを行う。左クリックを含む通常クリックでは破棄しない。
2. 対象を`activeQuests`から削除し、進行度と`readyToTurnIn`を破棄する。
3. 完了履歴やcooldownは追加せず、状態保存を予約する。
4. 破棄通知とbutton soundを再生し、一覧GUIを再描画する。

## 5. 目標を進行する

1. Mob報酬対象playerには`recordMobKill`、gathering報酬対象playerには`recordGathering`を呼ぶ。
2. active questから、目標typeとprefix除去後target IDが一致する目標を探す。
3. 一致した各目標を1増やし、必要数で上限を固定する。
4. 全目標達成時、`NPC`は`readyToTurnIn=true`として達成通知を出す。
5. `AUTO`は重複受取guardを取得し、報酬準備・反映・保存を開始する。

## 6. AUTOクエストを完了する

1. 目標達成時に、報酬itemを非同期で解決し、equipment instanceを準備する。ルーンは通常stack itemとして準備する。
2. メインスレッドでinventory snapshotを取得し、Gold、item、account/class EXPを反映する。
3. questをactiveから削除し、完了時刻と必要なcooldownを記録する。
4. quest状態をAPI保存した後、inventory状態を保存する。
5. 両方成功した場合だけ完了通知、sound、particleを出して受取guardを解除する。
6. いずれかが失敗した場合はquest状態と報酬を受取前へ戻し、補償保存後に再試行を許可する。

## 7. NPCクエストを報告する

1. `READY_TO_TURN_IN` questをボードでクリックする。
2. `turnInNpcId`があればそのNPC、なければ`acceptedNpcId`と現在のNPCを比較する。
3. NPCが一致すればAUTOと同じ報酬commit処理へ進む。
4. NPCが一致しなければ状態を変更せず、報告先不一致を通知する。

## 8. 繰り返し状態を判定する

- `ONCE`: 完了後は`COMPLETED`となり再受領できない。
- `REPEATABLE`: 完了履歴は保存するが、受領条件を満たせば再び`AVAILABLE`になる。
- `COOLDOWN`: 完了時刻から`cooldownSeconds`までは`COOLDOWN`、経過後は受領条件に応じて`AVAILABLE`または`LOCKED`になる。

## 9. ログイン・ログアウトする

1. ログインロードの非同期区間でAPI状態を読み、必要なら旧YAMLを移行する。
2. メインスレッド適用時に`loadToken`を検証し、最新要求だけをsessionへ公開する。
3. ログアウト時はsession stateをreleaseし、最新snapshotを直ちにaccount別保存queueへ連結する。
4. 保存完了前に再ログインした場合は、古いAPI結果ではなく保持中の最新snapshotを適用する。
