# 29_9-未決事項

## 1. 報酬のdurable transaction

現行の重複受取guardはplugin process内の`accountId + questId`だけを排他し、quest state API、inventory API、account/class進行を補償処理で整合させる。server crash、process kill、通信結果不明、複数serverからの同時受取に対するatomicityとidempotencyは保証しない。

本番で複数serverを許可する前に、受取claim IDを永続化し、DB transactionまたはoutbox/sagaで再実行可能なcommit境界を定義する。

## 2. 受領条件itemとquest stateの一括保存

受領時は条件itemをmemoryから消費してinventory保存を即時要求し、quest stateは1秒debounceで保存する。両store間にcrash windowがあり、inventory保存失敗futureも受領結果へ接続していない。

条件itemを消費するquestでは、inventoryとquest stateの一括transaction、または失敗時のitem返却・受領取消を実装する必要がある。

## 3. 将来の目標種別

現行は`KILL_MOB`と`GATHERING`だけを公開する。次の候補はsource event、target ID、party共有、重複通知、永続化schemaを決めてから追加する。

- item納品
- NPC会話
- 特定地点到達
- craft
- dungeon / boss討伐
- AND / ORを含む複合条件

## 4. クエスト破棄確認

一覧GUIはクエスト項目への通常ドロップまたはCtrl+ドロップで即時破棄する。左クリックを含む通常クリックでは破棄しない。確認GUI、一定進行以上だけの確認、再受領不可questの警告など、追加の誤操作対策は未実装である。

## 5. 報酬失敗メッセージの分割

`P_6606`はinventory空き不足の文言だが、item master不明、equipment instance準備失敗、inventory state未ロードでも使う。playerが取れる行動を正しく案内するため、空き不足と運用/API失敗を別IDへ分ける。

## 6. マスタ重複・参照整合の起動時検証

repositoryは各YAMLの基本形式を検証するが、重複quest/board ID、boardから不存在questへの参照、objective targetや報告NPCの不存在を一括検証しない。現在は同じIDを後からmapへ入れた定義が上書きし、不明quest entryはGUI描画時に無視する。

起動時またはfilebase validatorで参照graphを検証し、公開を中止する条件と警告だけにする条件を定義する。
