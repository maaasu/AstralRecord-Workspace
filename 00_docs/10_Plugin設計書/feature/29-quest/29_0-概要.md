# 29_0-概要

## 1. 目的

クエスト機能は、NPCクエストボードから受領した任務をaccount UUID単位で管理し、Mob討伐またはgathering採取の進行を記録して、完了時に経験値、Gold、itemを付与する。

## 2. 実装範囲

- NPCボードGUIと`/quest`一覧GUIを提供する。
- 受領上限は`max(3, floor(StatusType.QUEST_LIMITの最大値))`とする。
- 目標種別は`KILL_MOB`と`GATHERING`である。
- 完了方式は条件達成時に受取処理を開始する`AUTO`と、指定NPCで報告する`NPC`である。
- 繰り返し方式は`ONCE`、`REPEATABLE`、`COOLDOWN`である。
- 受領中または報告可能なクエストは、一覧GUIから確認なしで破棄できる。破棄時は進行度を削除し、完了履歴やcooldownを追加しない。

## 3. マスターデータ

- クエスト定義は`40_filebase/47.features.quest`から読む。
- クエストボード定義は`40_filebase/48.features.quest_board`から読む。
- NPC interactionは`id: gui`と`type: QUEST`または`QUEST_BOARD`を使い、`boardId`を指定する。互換入力として`questBoardId`も受け付ける。
- item、Mob、gathering、NPCへの参照値は、`type:id`形式なら最初の`:`より後ろを実行時IDとして扱う。

## 4. プレイヤー状態

`QuestPlayerState`はaccount UUID単位でメモリに保持し、`/api/account-quest/{accountId}`へGET/PUTする。APIが未保存状態を返した場合だけ、plugin data folderの`quest-states/<accountId>.yml`を読み、API保存成功後に旧YAMLを削除する。

通常の状態変更は最新snapshotを世代管理し、1秒debounce後にaccount単位の直列キューへ保存する。ログアウト時は最新世代を即時flushし、即時再ログインでは未保存snapshotを優先する。plugin停止時は全保存を待機し、残った世代を同期再試行する。

## 5. 進行・報酬境界

- Mob討伐は`MobCombatService`が各報酬対象playerへ`recordMobKill`を通知する。
- 採取完了は`GatheringService`が各報酬対象playerへ`recordGathering`を通知する。
- 進行数は目標必要数を上限として1件ずつ加算する。
- 報酬itemの解決とequipment / rune instance作成は非同期、inventory・account・class・クエスト状態の反映はメインスレッドで行う。
- クエスト状態保存とinventory保存の両方が成功した後だけ完了通知を出す。失敗時はクエスト状態と反映済み報酬を受取前へ戻し、補償保存後に再試行を許可する。

API/DBをまたぐdurable transaction、複数server間の受取排他、rune未確定instanceの永続削除は未実装であり、[[29_9-未決事項]]を正本とする。

## 6. 関連データ

- `40_filebase/47.features.quest/*`: クエスト定義
- `40_filebase/48.features.quest_board/*`: NPCクエストボード定義

## 7. 依存・連携

- `mob`: NPC interaction、Mob討伐進行
- `gathering`: 採取進行
- `inventory`: 受領条件アイテム、報酬アイテム、Gold
- `item`: stack報酬の解決、equipment / rune instanceの準備・補償削除
- `account` / `class`: EXP報酬
- `status`: `QUEST_LIMIT` による最大受領数
- `skilltree`: EXP報酬によるレベル変化後の派生状態再計算
- `player`: ログイン時ロード、ログアウト時release、account mode guard
