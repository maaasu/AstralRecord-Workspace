# 29_1-モデル定義

## 1. クエスト定義

物理名: `QuestDefinition`

| 項目 | 型・既定 | 説明 |
|:--|:--|:--|
| `id` | `String` | クエストID。空定義はrepositoryが除外する |
| `name` | `String` / `id` | GUI表示名 |
| `description` | `List<String>` / 空 | GUI lore。`&` legacy色指定を変換する |
| `icon` | `Material` / `PAPER` | GUI icon。`MaterialNameResolver`で互換名を含めて解決し、不正値は`PAPER`へfallbackする |
| `repeatMode` | `QuestRepeatMode` / `ONCE` | `ONCE` / `REPEATABLE` / `COOLDOWN` |
| `cooldownSeconds` | 0以上 | `COOLDOWN`完了後の再受領待機秒 |
| `completionMode` | `QuestCompletionMode` / `NPC` | `AUTO` / `NPC` |
| `turnInNpcId` | nullable | 明示報告先NPC ID。prefixを除去して保持する |
| `objectives` | 1件以上 | [[29_1-モデル定義]].クエスト目標 |
| `requirements` | 0件以上 | [[29_1-モデル定義]].受領条件 |
| `rewards` | non-null | [[29_1-モデル定義]].クエスト報酬 |

## 2. クエスト目標

物理名: `QuestObjectiveDefinition`

| 項目 | 説明 |
|:--|:--|
| `id` | クエスト内の進行map key。未指定時はtypeとtargetから生成する |
| `type` | `KILL_MOB`または`GATHERING` |
| `targetId` | Mob template IDまたはgathering definition ID |
| `targetLevel` | `KILL_MOB` に限定した Mob レベル。nullなら全レベルに一致する |
| `label` | GUI表示名。未指定時は`targetId` |
| `amount` | 必要数。最小1 |

filebase YAML の `objectives[].level` を `targetLevel` として読み込む。未指定の既存クエストは全レベルの Mob 討伐に一致する。

不明な目標type、空のtarget、または全目標が無効な定義は読込対象外とする。

## 3. item定義・受領条件

物理名: `QuestItemStackDefinition` / `QuestRequirementDefinition`

| 項目 | 説明 |
|:--|:--|
| `itemId` | Astral item ID。参照prefixを除去する |
| `category` | item読込category。既定`material` |
| `amount` | 必要数。最小1 |
| `consume` | `true`なら受領時に消費、`false`なら受領時の所持確認だけを行う |

同じ`itemId`が複数行ある場合、所持確認は全行の`amount`合計、消費は`consume=true`行の合計を使う。消費APIはitemIdごとに一回だけ呼ぶ。

## 4. クエスト報酬

物理名: `QuestRewardDefinition`

| 項目 | 説明 |
|:--|:--|
| `exp` | account EXPと選択class EXPの両方へ付与する。最小0 |
| `gold` | inventory currencyのGoldへ付与する。最小0 |
| `items` | stack item（ルーンを含む）またはequipment instanceの報酬一覧 |

stack itemは通常inventoryへ数量付与する。equipmentだけは報酬反映前にinstanceを非同期生成し、失敗時はequipment instanceを削除する。ルーンは通常stack itemのため削除対象の個体を持たない。

## 5. プレイヤークエスト状態

物理名: `QuestPlayerState`

| 項目 | 説明 |
|:--|:--|
| `accountId` | account UUID |
| `activeQuests` | quest IDから`QuestProgress`へのmap。受領中と報告可能を保持する |
| `completedAt` | quest IDから完了epoch millisへのmap |
| `cooldownUntil` | quest IDから再受領可能epoch millisへのmap |

`snapshot()`はactive progressを含むdeep copyを作る。保存queue、ロード世代比較、報酬補償はこのsnapshotを使用する。

## 6. クエスト進行

物理名: `QuestProgress`

| 項目 | 説明 |
|:--|:--|
| `questId` | クエストID |
| `acceptedAtEpochMillis` | 受領時刻 |
| `acceptedNpcId` | 受領元NPC template ID。明示報告先がないNPC完了で使う |
| `objectiveProgress` | objective IDごとの0以上の進行数 |
| `readyToTurnIn` | 報告可能またはAUTO報酬処理待ちを表す |

`QuestProgress.start`は全目標を0で初期化する。目標が空のprogrammatic定義では`readyToTurnIn=true`になるが、filebase repositoryは目標0件の定義を公開しない。

## 7. クエストボード

物理名: `QuestBoardDefinition` / `QuestBoardEntry`

| 項目 | 説明 |
|:--|:--|
| `id` | ボードID |
| `name` | GUI title。未指定時は`id` |
| `entries` | 表示するquestと配置の一覧 |
| `questId` | 参照prefixを除去したquest ID |
| `page` | 1始まり。最小1 |
| `slot` | 0〜27のlogical slot |
| `row` / `column` | `slot`未指定時の1始まり配置 |

GUIは54slotで、logical slotを中央7列×4行へ写像する。前pageはslot 45、次pageはslot 53を使う。

## 8. 表示状態

物理名: `QuestDisplayState`

| 状態 | 判定 |
|:--|:--|
| `IN_PROGRESS` | activeに存在し、`readyToTurnIn=false` |
| `READY_TO_TURN_IN` | activeに存在し、`readyToTurnIn=true` |
| `COOLDOWN` | `cooldownUntil`が現在時刻より後 |
| `COMPLETED` | `ONCE`かつ`completedAt`に存在 |
| `AVAILABLE` | 上記以外で受領条件itemを所持 |
| `LOCKED` | 上記以外で受領条件itemが不足 |

受領上限は表示状態へ含めず、`accept`時に別途判定する。

## 9. 永続化世代

物理名: `QuestService.InitialState` / `QuestStatePersistenceCoordinator.LoadedState`

| 項目 | 説明 |
|:--|:--|
| `accountId` | account UUID |
| `loadToken` | 最新ロード要求だけをsessionへ適用する単調増加token |
| `generation` | account内の最新snapshot世代 |
| `state` | 読込またはメモリ優先で選ばれたsnapshot |

保存channelは`latestGeneration`、`scheduledGeneration`、`persistedGeneration`と直列`tail`を持つ。ロード中に保存世代が進んだ場合はAPI結果より最新メモリsnapshotを優先する。
