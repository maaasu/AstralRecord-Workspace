# 29_5.00-例外・ログ・運用

## 1. プレイヤー通知

通知は`PlayerMessageService`を介し、`PlayerMsgId`と`player.properties`を正本とする。

| ID | 場面 | 現行メッセージ要旨 |
|:--|:--|:--|
| `P_6600` | 表示状態が`AVAILABLE`でない | 現在受領不可 |
| `P_6601` | active件数が上限以上 | 受領上限到達 |
| `P_6602` | 受領条件item不足または消費失敗 | 必要item不足 |
| `P_6603` | 受領成功 | quest名付き受領通知 |
| `P_6604` | 破棄成功 | quest名付き破棄通知 |
| `P_6605` | 報告NPC不一致 | このNPCには報告不可 |
| `P_6606` | 報酬準備またはinventory反映失敗 | 報酬用inventory空き不足 |
| `P_6607` | NPC完了条件達成 | quest名付き達成通知 |
| `P_6608` | 報酬と状態の保存完了 | quest名付き完了通知 |
| `P_6609` | 報酬保存失敗後の補償完了・再試行案内 | 時間を置いた再試行 |

`P_6606`はitem解決・instance準備失敗にも共用されるため、文言分割は [[29_9.00-未決事項]] とする。

## 2. GUI sound・完了effect

- board/listを開く: `GuiSound.OPEN`
- page移動・受領・報告・破棄成功: `GuiSound.SELECT`
- 無効操作: `GuiSound.DENY`
- 受領成功: `Sound.UI_TOAST_IN`
- 破棄成功: `Sound.UI_BUTTON_CLICK`
- 条件達成・完了: `UI_TOAST_CHALLENGE_COMPLETE`、`ENTITY_PLAYER_LEVELUP`
- 条件達成・完了particle: `PLAYER_LEVEL_UP_TOTEM`、`PLAYER_LEVEL_UP_END_ROD`

NPC完了条件達成時と、全永続化成功後の完了時は同じeffectを使用する。AUTOでは条件達成直後の独立通知を出さず、報酬commit成功後に完了effectを出す。

## 3. 実行時ログ

| Log ID | 記録条件 | 運用 |
|:--|:--|:--|
| `W_6600` | 通常/停止時のquest state API保存失敗 | account IDと例外種別を記録。通常時はdirtyを維持して再試行 |
| `W_6601` | 報酬item解決、instance準備、非同期handoff失敗 | questをactiveに残し、未確定instanceをcleanup |
| `W_6604` | 報酬反映またはquest/inventory保存失敗 | 受取前状態へ補償を開始 |
| `W_6605` | commit成功後の完了演出失敗 | 報酬commitは戻さず、演出だけ失敗として記録 |
| `W_6606` | 報酬補償または補償保存失敗 | durable stateを手動監査対象とする |
| `E_5601` | quest GUI click handlerの未処理例外 | player名と`quest_gui_click`を記録 |

`W_6602`と`W_6603`は旧YAML保存実装向け定義として残っているが、現行のAPI repositoryは使用しない。

## 4. 通常状態保存失敗

account channelの保存失敗は例外完了し、`scheduledGeneration`を`persistedGeneration`へ戻す。dirty markerと保存期限を残すため、20tick taskの次回走査で最新snapshotを再試行する。

ログアウト済みstateも保存完了までchannelに保持する。即時再ログインではAPIの古い値より保持snapshotを優先し、保存成功後かつロード参照なしになってからevictする。

## 5. 報酬失敗・補償

- 準備失敗: questはactiveかつ`readyToTurnIn`のまま、準備済みequipmentを削除し、runeはcacheからevictする。
- 反映失敗: inventory snapshotとaccount/class progressを戻し、questをactiveのまま残す。
- quest/inventory保存失敗: active/completed/cooldown、inventory、account/class progressを全て受取前へ戻す。
- 補償状態を再保存し終えるまでprocess-local reward claimを解除しない。
- 補償自体が失敗した場合は`W_6606`を記録し、API/DBとmemoryの手動照合を要する。

## 6. 停止処理

`QuestService.stop`は新しい報酬開始を拒否し、定期taskを止め、全session stateを保存queueへ連結する。queue完了後に残る未保存世代を同期再試行してからmemoryをclearする。

停止中の非同期保存失敗は中間`W_6600`を抑止し、最終同期再試行も失敗した場合に記録する。停止処理は失敗をログへ残すが、無期限retryやshutdown中断は行わない。

## 7. 運用監視

- `W_6600`の連続発生: account-quest API疎通と対象accountの更新可否を確認する。
- `W_6604` / `W_6606`: quest state、inventory、account/class進行、equipment/rune instanceを同時に照合する。
- 旧YAML削除失敗: APIへ移行済みかを確認してから、対象`quest-states/<accountId>.yml`を手動整理する。
- 長時間残る`readyToTurnIn`: 報告NPC ID、報酬item定義、inventory空き、API保存ログを確認する。
