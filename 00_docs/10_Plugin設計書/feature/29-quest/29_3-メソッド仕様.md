# 29_3-メソッド仕様

## 1. クエスト定義読込

クラス名: `QuestDefinitionRepository`

物理名: `findAll` / `parse`

1. `FileDatabaseManager`のroot配下にある`47.features.quest`の`.yml`を走査する。
2. 空ID、目標0件、未知type、空targetの定義・目標は公開しない。
3. reference値は scalar の `type:id` と `{ ref: "type:id" }` の nested YAML 形式を受け付け、いずれも prefix を除去する。`turnInNpcId` と objective の `targetId` へ同じ規則を適用する。
4. icon、repeat、completion、item category、amountへ既定値と下限制約を適用する。
5. 有効な`QuestDefinition`一覧を返す。

## 2. クエストボード読込

クラス名: `QuestBoardRepository`

物理名: `findAll`

1. root配下の`48.features.quest_board`から`.yml`を走査する。
2. 空IDのboardと空quest参照のentryを除外する。
3. `quests`の`questId`、`page`、`slot`、`row`、`column`を`QuestBoardEntry`へ変換する。
4. `questId`のreference prefixを除去し、pageを最小1へ正規化する。

## 3. マスタ公開

クラス名: `QuestService`

物理名: `loadMasterDataSnapshot` / `replaceMasterDataSnapshot` / `loadAll`

1. questとboardを一旦immutable `MasterDataSnapshot`へ読み込む。
2. 公開時に既存mapをclearし、IDをkeyとして一括置換する。
3. `findQuest` / `findBoard`は呼出値のreference prefixを除去して検索する。

## 4. プレイヤー状態API

クラス名: `QuestPlayerStateRepository`

物理名: `load` / `save`

1. `load`は`GET /api/account-quest/{accountId}`を実行し、active quest、objective進行、完了時刻、cooldownを復元する。
2. APIの`isSaved=false`かつ旧`quest-states/<accountId>.yml`が存在する場合、旧状態を読み込む。
3. 旧状態をPUT保存し、成功後にYAMLを削除して移行状態を返す。保存または削除失敗は例外とする。
4. `save`は状態全体をJSONへ変換し、同endpointへPUTして置換する。
5. HTTP 200以外、通信中断、JSON解析失敗は`RuntimeException`として上位へ伝播する。

## 5. ロード・保存世代管理

クラス名: `QuestService` / `QuestStatePersistenceCoordinator`

物理名: `loadInitialState` / `applyInitialState` / `discardInitialState` / `save` / `releaseState` / `start` / `stop`

1. `loadInitialState`はaccount channelへ`loadToken`を発行する。未保存の最新snapshotがあればAPI読込より優先する。
2. `applyInitialState`は最新tokenだけを適用し、古いロード結果は拒否する。
3. 通常変更は世代を進め、1秒後を保存期限としてdirty登録する。保存失敗後はアカウントごとに1秒から最大60秒までの指数バックオフを適用する。
4. 20tick間隔のtaskが期限到来accountを検出し、account別`CompletableFuture` tailへ最新世代のPUTを直列連結する。
5. 保存失敗時はscheduled世代をpersisted世代へ戻すため、dirty状態のbackoff終了後のtickで同じ最新snapshotを再試行できる。
6. `releaseState`はsession mapからstateを外し、最新snapshotを保持したまま即時flushする。保存済みかつロード参照がなければchannelをevictする。
7. `stop`は全session stateを最新世代へ登録し、非同期queue完了を待って未保存世代を同期再試行してからmemoryをclearする。

## 6. 表示状態・受領上限

クラス名: `QuestService`

物理名: `displayState` / `cooldownRemainingSeconds` / `maxActiveQuests`

1. active progress、cooldown、ONCE完了履歴、受領条件の順で表示状態を判定する。
2. cooldown残秒はmillisecond差を秒単位で切り上げ、0未満を0とする。
3. 最大受領数は`max(3, floor(StatusType.QUEST_LIMITの最大値))`とする。
4. 受領上限到達は表示状態へ含めず、受領処理で再検証する。

## 7. クエスト受領

クラス名: `QuestService`

物理名: `accept` / `canMeetRequirements` / `consumeRequirements`

1. gameplay account、同一account UUIDとquest IDの`RewardClaimKey`が報酬保存または補償中でないこと、`AVAILABLE`、active件数上限を順に検証する。claimが残る間は、繰り返しクエストも受領条件itemを消費せず拒否する。
2. 同じitem IDの全受領条件を合計し、normal BAGとHOTBARの合計所持数を確認する。
3. `consume=true`のamountをitem ID単位で合計し、item IDごとに一回消費する。
4. `QuestProgress.start`へprefix除去済みNPC IDを渡し、active mapへ追加する。
5. quest状態の保存をdebounce予約し、inventory保存を非同期要求する。
6. 成功時に`P_6603`と`UI_TOAST_IN`を通知する。

## 8. 目標進行

クラス名: `QuestService`

物理名: `recordMobKill` / `recordGathering` / `recordObjective`

1. active progressのsnapshotを走査し、不明questと報告可能済みquestを除外する。
2. typeとprefix除去後target IDが一致する各objectiveを1増やし、必要数でcapする。
3. 全objective達成時、`AUTO`は`complete`を開始する。
4. `NPC`は`readyToTurnIn=true`にして`P_6607`と完了effectを通知する。
5. 進行が変化したstateを保存世代へ登録する。

## 9. NPC報告・重複受取guard

クラス名: `QuestService`

物理名: `turnIn` / `complete`

1. activeかつ`readyToTurnIn=true`だけを報告対象とする。
2. NPC完了では`turnInNpcId`、未指定なら`acceptedNpcId`を現在NPCと比較する。必要NPCがnullの場合は任意boardから報告できる。
3. account UUIDとquest IDの`RewardClaimKey`へ一意なclaim IDを登録し、同一process内の重複受取を拒否する。
4. AUTO達成時は、報酬処理開始前に`readyToTurnIn=true`を保存対象へ登録する。
5. plugin停止中、新しい報酬処理は開始しない。

## 10. 報酬準備・反映

クラス名: `QuestService`

物理名: `prepareRewards` / `finishPreparedRewards` / `applyPreparedRewards`

1. 非同期executorでitem masterを解決する。
2. stack itemはmodelとamountを保持し、equipment / runeはamount件のinstanceをAPI作成する。
3. メインexecutorへ戻った時点でclaim、session state、`readyToTurnIn`を再検証する。
4. inventory報酬があればaccount inventory全体の補償snapshotを取得する。
5. Gold、stack item、prepared instanceを全件反映する。一件でも不足・失敗ならinventory snapshotを復元する。
6. EXPをaccountと選択classへ同量付与する。level変化時は`SkillTreeService.refreshProgressDerivedState`、未設定時は`StatusService.refreshStatus`を実行する。
7. activeからquestを削除し、`completedAt`を記録する。`COOLDOWN`かつ秒数が正なら`cooldownUntil`も記録する。

## 11. 報酬commit・補償

クラス名: `QuestService`

物理名: `saveImmediately` / `continueRewardPersistence` / `finishRewardPersistence` / `compensateRewardPersistence`

1. 完了後quest stateをdebounce待ちせずAPI保存する。
2. quest保存成功後、inventory報酬がある場合だけ`InventoryService.saveNow`を連結する。
3. 両方成功した場合だけ`P_6608`、sound、particleを通知してclaimを解除する。
4. 同一accountでは報酬反映から保存成功または補償完了までを直列化する。失敗時は対象questのactive/completed/cooldownだけを受取前snapshotへ戻し、inventory、account/class進行を復元するため、補償後に後続questの報酬反映を開始する。
5. 作成済み未確定equipment instanceを削除する。rune instanceは削除APIがないためplugin cacheからevictする。
6. 復元したquest stateとinventoryを再保存し、補償完了後にclaimを解除して`P_6609`を通知する。

## 12. クエスト破棄

クラス名: `QuestService`

物理名: `abandon`

1. prefix除去後quest IDをactive mapから削除する。
2. 対象がなければ`false`を返す。
3. 保存を予約し、`P_6604`とbutton soundを通知する。
4. 完了履歴とcooldownは変更しない。

## 13. NPC interaction・GUI

クラス名: `MobInteractionEventHandler` / `QuestGuiEventHandler` / `QuestGui`

物理名: `openQuestBoard` / `openBoard` / `openList` / `onInventoryClick` / `onInventoryDrag`

1. NPC resolverの勝者executorが`id=gui` actionを順に処理し、`type=QUEST`または`QUEST_BOARD`をquest GUIへ委譲する。
2. `boardId`、互換値`questBoardId`、NPC template IDを`openBoard`へ渡す。
3. gameplay accountとboard存在を検証し、`BoardHolder`にboard ID、NPC ID、page indexを保持する。
4. board clickはpage移動、`AVAILABLE`受領、`READY_TO_TURN_IN`報告だけを処理し、同pageを再描画する。
5. list clickは対象active questを即時破棄し、一覧を再描画する。
6. board/list内のclickとdragはcancelする。click例外は共通GUIログ`E_5601`で記録する。
7. メインメニューのクエスト項目は`QuestGuiEventHandler.openList`へ委譲する。

## 14. クエスト一覧command

クラス名: `QuestCommand`

物理名: `executePlayerCommand`

1. player専用`/quest`を受け付ける。
2. `QuestGuiEventHandler`が初期化済みなら`openList`へ委譲する。
3. 非gameplay accountまたは未ロードplayerはdeny soundで終了する。
