# 29_3-メソッド仕様

## 1. クエスト定義読込

クラス名: `QuestDefinitionRepository`

物理名: `findAll` / `parse`

1. `FileDatabaseManager`のroot配下にある`47.features.quest`の`.yml`を走査する。
2. 空ID、目標0件、未知type、空targetの定義・目標は公開しない。
3. reference値は scalar の `type:id` と `{ ref: "type:id" }` の nested YAML 形式を受け付け、いずれも prefix を除去する。`turnInNpcId` と objective の `targetId` へ同じ規則を適用する。
4. icon、repeat、completion、item category、amountへ既定値と下限制約を適用する。
5. 有効な`QuestDefinition`一覧を返す。

## 2. クエストボード読込

クラス名: `QuestBoardRepository`

物理名: `findAll`

1. root配下の`48.features.quest_board`から`.yml`を走査する。
2. 空IDのboardと空quest参照のentryを除外する。
3. `quests`の`questId`、`page`、`slot`、`row`、`column`を`QuestBoardEntry`へ変換する。
4. `questId`のreference prefixを除去し、pageを最小1へ正規化する。

## 3. マスタ公開

クラス名: `QuestService`

物理名: `loadMasterDataSnapshot` / `replaceMasterDataSnapshot` / `loadAll`

1. questとboardを一旦immutable `MasterDataSnapshot`へ読み込む。
2. 公開時に既存mapをclearし、IDをkeyとして一括置換する。
3. `findQuest` / `findBoard`は呼出値のreference prefixを除去して検索する。

## 4. プレイヤー状態API

クラス名: `QuestPlayerStateRepository`

物理名: `load` / `createSnapshotSection`

1. `load`は`GET /api/account-quest/{accountId}`を実行し、active quest、objective進行、完了時刻、cooldownを復元する。
2. `createSnapshotSection`は状態全体、`clientRevision`、DBから読んだ`expectedVersion`を`questState` JSONへ変換する。通信は行わない。
3. 読込は`ApiRequestUtil.sharedClient()`の共有HTTP clientを使用する。
4. GETのHTTP 200以外、通信中断、JSON解析失敗は`RuntimeException`として上位へ伝播する。

## 5. ロード・保存世代管理

クラス名: `QuestService` / `QuestStatePersistenceCoordinator`

物理名: `loadInitialState` / `applyInitialState` / `discardInitialState` / `snapshotPlayerState` / `releaseState` / `start` / `stop`

1. `loadInitialState`はaccount channelへ`loadToken`を発行する。同じPluginプロセスにSQL ACK待ちの最新snapshotがあればAPI読込より優先する。
2. `applyInitialState`は最新tokenだけを適用し、古いロード結果は拒否する。
3. 通常変更は世代を進め、`InventoryService.queueLocalPlayerSave`で共通account laneへ保存を登録する。1秒周期のtaskはACK待ちの最新世代を再び共通laneへ通知する。
4. `snapshotPlayerState`はpending revisionがある場合だけ完全状態をcaptureし、共通`POST /api/player-state/snapshots`へ`questState` sectionとして渡す。
5. ACKの`clientRevision`と`version`を照合し、capture世代が最新ならpendingを解除して`persistedVersion`を更新する。
6. `releaseState`は最新snapshotを保持し、共通境界保存のACK後にsession mapと保持channelを破棄する。ACK前の即時再ログインは保持状態を利用する。
7. `stop`は全session stateをpendingにし、保存・drainは共通プレイヤー保存ライフサイクルへ委譲する。

## 6. 表示状態・受領上限

クラス名: `QuestService`

物理名: `displayState` / `cooldownRemainingSeconds` / `maxActiveQuests`

1. active progress、cooldown、ONCE完了履歴、受領条件の順で表示状態を判定する。
2. cooldown残秒はmillisecond差を秒単位で切り上げ、0未満を0とする。
3. 最大受領数は`max(3, floor(StatusType.QUEST_LIMITの最大値))`とする。
4. 受領上限到達は表示状態へ含めず、受領処理で再検証する。

## 7. クエスト受領

クラス名: `QuestService`

物理名: `accept` / `canMeetRequirements` / `consumeRequirements`

1. gameplay account、同一account UUIDとquest IDの`RewardClaimKey`が報酬処理中でないこと、`AVAILABLE`、active件数上限を順に検証する。
2. 同じitem IDの全受領条件を合計し、normal BAGとHOTBARの合計所持数を確認する。
3. `consume=true`のamountをitem ID単位で合計し、item IDごとに一回消費する。
4. `QuestProgress.start`へprefix除去済みNPC IDを渡し、active mapへ追加する。
5. 条件item消費とquest追加を同じ重要操作として`questState`とinventoryを単一snapshotへ含める。
6. SQL ACK後にだけ`P_6603`と`UI_TOAST_IN`を通知する。保存失敗時はitemとquest stateを操作前へ戻して`P_6606`を送る。
7. SQL ACK後、受領listenerへplayerとquest IDを一度通知する。受領失敗時は通知しない。

## 8. 目標進行

クラス名: `QuestService`

物理名: `recordMobKill` / `recordGathering` / `recordObjective`

1. active progressのsnapshotを走査し、不明questと報告可能済みquestを除外する。
2. typeとprefix除去後target IDが一致し、`KILL_MOB` で `targetLevel` が未指定または討伐 Mob の実効レベルと一致する各objectiveを1増やし、必要数でcapする。
3. 全objective達成時、`AUTO`は`complete`を開始する。
4. `NPC`は`readyToTurnIn=true`にして`P_6607`と完了effectを通知する。
5. 進行が変化したstateを保存世代へ登録する。

## 9. NPC報告・重複受取guard

クラス名: `QuestService`

物理名: `turnIn` / `complete`

1. activeかつ`readyToTurnIn=true`だけを報告対象とする。
2. NPC完了では`turnInNpcId`、未指定なら`acceptedNpcId`を現在NPCと比較する。必要NPCがnullの場合は任意boardから報告できる。
3. account UUIDとquest IDの`RewardClaimKey`へ一意なclaim IDを登録し、同一process内の重複受取を拒否する。
4. AUTO達成時は、報酬処理開始前に`readyToTurnIn=true`を保存対象へ登録する。
5. plugin停止中、新しい報酬処理は開始しない。
6. NPC報告の開始だけでは完了listenerを通知せず、報酬と関連状態の保存成功後にだけ完了listenerへplayerとquest IDを一度通知する。

## 10. 報酬準備・反映

クラス名: `QuestService`

物理名: `prepareRewards` / `finishPreparedRewards` / `applyPreparedRewards`

1. 非同期executorでitem masterを解決する。
2. stack item（ルーンを含む）はmodelとamountを保持し、equipmentは必要個数とmodelだけを準備する。
3. メインexecutorへ戻った時点でclaim、session state、`readyToTurnIn`を再検証する。
4. 重要操作laneでinventory、equipment cache、account/class進行、quest stateの補償点を取得する。
5. equipment instanceをローカル生成し、Gold、stack item、equipment entryを全件反映する。一件でも不足・失敗なら全状態を補償点へ戻す。
6. EXPをaccountと選択classへ同量反映する。派生状態の再計算と画面更新はSQL ACK後に行う。
7. activeからquestを削除し、`completedAt`を記録する。`COOLDOWN`かつ秒数が正なら`cooldownUntil`も記録する。

## 11. 報酬commit・補償

クラス名: `QuestService`

物理名: `finishPreparedRewards` / `finishRewardPersistence` / `rollbackAppliedRewards`

1. `executeCriticalPlayerMutation`が先行する通常変更を保存した後、完成状態を一度だけcaptureして`POST /api/player-state/snapshots`へ送る。
2. APIはsnapshot IDを冪等キーとして処理する。POST応答が不明な場合は結果照会し、未完了なら同じsnapshotを再送する。
3. inventory、equipment、account/class進行、quest stateは同じSQL transactionで確定する。
4. SQL ACK後だけ`P_6608`、`GuiSound.CONFIRM`、particle、完了listener、NPC報告GUIのcallbackを実行してclaimを解除する。
5. SQL失敗、version競合、結果照会後も確定できない通信失敗では、`rollbackAppliedRewards`、equipment rollback、quest checkpoint復元を同じaccount lane内で実行する。成功演出は出さず`P_6606`を送ってclaimを解除する。
6. 同一accountの報酬処理は直列化し、後続報酬が先行操作の補償に巻き込まれないようにする。

## 12. クエスト破棄

クラス名: `QuestService`

物理名: `abandon`

1. prefix除去後quest IDをactive mapから削除する。
2. 対象がなければ`false`を返す。
3. 保存を予約し、`P_6604`とbutton soundを通知する。
4. 完了履歴とcooldownは変更しない。

## 13. NPC interaction・GUI

クラス名: `MobInteractionEventHandler` / `QuestGuiEventHandler` / `QuestGui`

物理名: `openQuestBoard` / `openBoard` / `openList` / `refreshBoard` / `refreshList` / `onInventoryClick` / `onInventoryDrag`

1. NPC resolverの勝者executorが`id=gui` actionを順に処理し、`type=QUEST`または`QUEST_BOARD`をquest GUIへ委譲する。
2. `boardId`、互換値`questBoardId`、NPC template IDを`openBoard`へ渡す。
3. gameplay accountとboard存在を検証し、`BoardHolder`にboard ID、NPC ID、page indexを保持する。
4. board clickはpage移動、`AVAILABLE`受領、`READY_TO_TURN_IN`報告だけを処理し、同pageを現在のinventoryへ再描画する。NPC報告は報酬と関連永続化の成功後にも、報告開始時と同じboardを表示中の場合だけ完了callbackで再描画する。
5. list clickは共通hotbar shortcutを先に処理する。クエスト項目への通常ドロップまたはCtrl+ドロップだけで対象active questを即時破棄して一覧を再描画し、それ以外のクリックでは破棄しない。
6. board/list内のclickとdragはcancelする。click例外は共通GUIログ`E_5601`で記録する。
7. メインメニューのクエスト項目は`QuestGuiEventHandler.openList`へ委譲する。
8. 一覧の7列×4行の論理スロットでは、active quest直後から`maxActiveQuests - 1`までを空欄の受領可能枠として維持し、`maxActiveQuests`以降だけに`BOOK`の受領枠案内itemを置く。案内loreは現在の`maxActiveQuests`と、受領枠を増やすステータス効果で受領可能数が増えることを表示する。slot `49`には受領枠専用itemを置かない。
9. 一覧のslot `49`は共通GUIナビゲーションに使用し、戻り先がある場合は`戻る`、ない場合は`閉じる`を表示する。クリック処理は共通ナビゲーションへ委譲する。
10. quest itemのloreは状態、説明、完了方法、再受領ルール、目標、受領条件、報酬、操作の順に表示する。目標の進行数は達成済みを緑、未達成を黄色で表示し、受領中一覧では達成状態の文言も併記する。クエスト受注・報告画面では進行数と色だけを表示する。`COOLDOWN`中は残り時間を日・時間・分・秒の日本語単位で表示する。

## 14. クエスト一覧command

クラス名: `QuestCommand`

物理名: `executePlayerCommand`

1. player専用`/quest`を受け付ける。
2. `QuestGuiEventHandler`が初期化済みなら`openList`へ委譲する。
3. 非gameplay accountまたは未ロードplayerはdeny soundで終了する。
