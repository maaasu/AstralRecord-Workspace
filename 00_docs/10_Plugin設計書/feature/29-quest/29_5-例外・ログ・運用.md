# 29_5-例外・ログ・運用

## 1. プレイヤー通知

通知は`PlayerMessageService`を介し、`PlayerMsgId`と`player.properties`を正本とする。

| ID | 場面 | 現行メッセージ要旨 |
|:--|:--|:--|
| `P_6600` | 表示状態が`AVAILABLE`でない | 現在受領不可 |
| `P_6601` | active件数が上限以上 | 受領上限到達 |
| `P_6602` | 受領条件item不足または消費失敗 | 必要item不足 |
| `P_6603` | 受領成功 | quest名付き受領通知 |
| `P_6604` | 破棄成功 | quest名付き破棄通知 |
| `P_6605` | 報告NPC不一致 | このNPCには報告不可 |
| `P_6606` | 報酬準備またはinventory反映失敗 | 報酬用inventory空き不足 |
| `P_6607` | NPC完了条件達成 | quest名付き達成通知 |
| `P_6608` | 報酬と状態の保存完了 | quest名付き完了通知 |
| `P_6609` | 受領または報酬の重要保存失敗 | 時間をおいて再試行 |

`P_6606`は報酬定義・容量・ローカル反映の失敗、`P_6609`はSQL保存の失敗に使用する。

## 2. GUI sound・完了effect

- board/listを開く: `GuiSound.OPEN`
- page移動・受領・報告・破棄成功: `GuiSound.SELECT`
- 無効操作: `GuiSound.DENY`
- 受領成功: `Sound.UI_TOAST_IN`
- 破棄成功: `Sound.UI_BUTTON_CLICK`
- 条件達成・完了: `GuiSound.CONFIRM`
- 条件達成・完了particle: `PLAYER_LEVEL_UP_TOTEM`、`PLAYER_LEVEL_UP_END_ROD`

NPC完了条件達成時と、全永続化成功後の完了時は同じ`GuiSound.CONFIRM`とparticle effectを使用する。AUTOでは条件達成直後の独立通知を出さず、報酬commit成功後に完了effectを出す。

## 3. 実行時ログ

| Log ID | 記録条件 | 運用 |
|:--|:--|:--|
| `W_6601` | 報酬item解決、非同期handoff失敗 | questをactiveに残してclaimを解除 |
| `W_6604` | 同期報酬反映失敗 | 同じmutation lock内で受取前状態を補償 |
| `W_6605` | commit成功後の完了演出失敗 | 報酬commitは戻さず、演出だけ失敗として記録 |
| `W_6606` | 同期報酬反映の補償失敗 | durable stateを手動監査対象とする |
| `W_5252` | 共通player-state保存失敗 | snapshot ID、account ID、HTTP/例外理由を確認する |
| `E_5601` | quest GUI click handlerの未処理例外 | player名と`quest_gui_click`を記録 |

## 4. 通常状態保存失敗

通常進行・破棄の保存失敗は共通account laneがdirtyを維持し、最新の全section snapshotを再試行する。quest固有のPUT queueやbackoffは持たない。

ログアウト済みstateもSQL ACKまで同じPluginプロセスのchannelに保持する。即時再ログインではAPIの古い値より保持snapshotを優先し、ACK後かつロード参照なしになってからevictする。

## 5. 報酬失敗・補償

- 準備失敗: questはactiveかつ`readyToTurnIn`のまま残し、ローカルequipmentはまだ生成しない。
- 同期反映失敗: 同じaccount lane内でinventory、equipment cache、account/class進行、quest stateを戻す。
- POST応答不明: snapshot IDで結果照会し、未完了なら同一payloadを再送する。この照会中は成功・失敗を確定しない。
- SQL失敗、version競合、結果照会後も確定できない通信失敗: 全ローカル状態を操作前へ戻し、`P_6609`を表示してclaimを解除する。
- 補償自体が失敗した場合は`W_6606`を記録し、API/DBとmemoryの手動照合を要する。

## 6. 停止処理

`QuestService.stop`は新しい報酬開始を拒否し、定期taskを止め、全session stateを共通保存対象へ登録する。Plugin全体の停止処理がaccount laneをdrainする。

停止時もPlugin data folderへplayer stateや未送信payloadを書き出さない。drain結果は共通プレイヤー保存ログで確認する。

## 7. 運用監視

- `W_5252`の連続発生: player-state API疎通、snapshot結果照会、対象accountのversion競合を確認する。
- `W_6604` / `W_6606`: quest state、inventory、account/class進行、equipment instanceを同時に照合する。ルーンはinventory数量を照合する。
- 長時間残る`readyToTurnIn`: 報告NPC ID、報酬item定義、inventory空き、API保存ログを確認する。
