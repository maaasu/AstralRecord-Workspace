# 40_player-admin-edit 概要

Web管理者によるプレイヤー情報の訂正中は、対象ユーザーの全アカウントへの参加を制限する。ゲーム内の保存状態とWeb編集を同時に正本にしない。

## 編集開始と保存境界

1. APIは編集開始要求をユーザー単位で直列化し、対象アカウント・操作者・編集セッションを固定して参加制限を永続化する。
2. Proxy・Lobby・RPGは同じ編集セッションと現在のサーバー起動IDを確認する。RPGは新規操作・ロード・アカウント移動を止め、実行中の重要操作と先行保存を完了させる。
3. RPGは最終snapshotと関連保存の結果が確定してから退出処理を完了する。ペット保存も同じ待機境界に含め、本体とペットの両方が成功した後にaccount sessionを閉じる。保存に失敗した場合、成功扱いの退出確認を送らない。退出中の非同期保存が完了する前にキャッシュや参加権限を解放しない。
4. 各サーバーは対象ユーザーの接続・ロード・移動・未完了保存が残っていないことを確認して応答する。APIが全応答とaccount sessionの終了を確認するまでは、Web編集を許可しない。

TTL切れ、接続人数の減少、API再起動後の所在一覧の空状態を、最終保存またはオフライン確認の代わりにしない。起動IDが変わったサーバーの古い確認応答を新しい起動へ付け替えない。

## 編集中の参加と保存

参加制限はユーザーUUID単位とする。Proxyの入場判定だけでなく、RPGのロード開始およびAPIのaccount session取得でも確認する。確認中の参加要求と編集開始が競合した場合、編集開始後に新しい保存権限を取得させない。

最終保存待ちの既存sessionによる保存は退避段階だけ許可する。編集可能になった後は、通常snapshot・旧session・遅延した保存要求でWeb訂正結果を更新できない。確定済みsnapshot IDの照会または同一payload再送は過去のACKを返すだけであり、新しい更新権限を与えない。

ペットprogressと開始前に受理済みの有償購入・Webメール受取の処理も、未退避DRAINING/RECOVERY_REQUIREDでcaptureされたRPG保存権限を検証して完了させる。新規のペット操作・購入・受取を編集中に開始しない。READY/APPLYINGでは最終保存の例外を許可せず、確定済み操作の同一再送は読み取り専用のreceipt照会とする。

## オフライン訂正と計算

オフラインになった後の訂正はAPIが管理トランザクションで実行する。Bukkitの仮プレイヤーを作成しない。プレイヤーレベルと累計EXPは同時に更新し、最高到達レベルを保持する。EXP閾値はアカウントUUIDを含む既存Plugin規則と一致させる。転生中のレベル訂正は拒否する。

現在クラスを切り替える場合は、クラス別の保存済み進行度を保持し、未経験クラスだけLv.1・EXP 0で開始する。習得個体・バインド・スキルツリー解放記録は削除しない。派生ステータス・使用可能スキル・有効ノードは次回参加時に通常のロード経路で再計算する。レベル低下だけでは最高到達レベル由来のPPを減らさない。

装備付与は個体ID・関連行・ルーン枠・抽選値とinventory entryを同じトランザクションで作成する。stackはマスタ上限・収納容量・既存entry規則を守る。APIに必要なマスタがない、または参加先Pluginと必要な定義の版が一致しない場合は適用を拒否する。

## 冪等性と復旧

反映は編集セッション・操作者・期待版・確認した状態・操作IDを検証する。訂正結果、操作receipt、参加制限の解除を同じトランザクションで確定する。同じ操作ID・同じ内容の再送は元の結果を返し、同じIDで異なる内容は拒否する。

通信結果不明では新しい操作IDで再実行せず、確定結果を照会する。ブラウザ閉鎖・Cookie失効・編集期限切れで参加制限を自動解除しない。管理者は同じ編集セッションを再開し、最終保存とオフライン状態を再確認して反映または取消する。取消も保存待ちのまま参加を許可しない。

API開始と最初のRPG確認取得の間に退出した場合も、実アカウントとプレイヤー・inventory・petを含む退出保存futureを保持する。未完了futureは期限で捨てない。完了済み失敗からの回復は、同じ実アカウントの後続の完全退出保存が成功した場合だけ許可し、関連保存laneと正確なaccount sessionの終了確認も継続する。

runtime登録・退避取得・ACKは既存の共通APIキーで認証する。runtime専用キーは不要とし、サーバー起動ID・編集対象・最終保存・退出・account session終了の確認は維持する。
