# 02_2-ユースケース

## 1. 初期アカウント作成

- 契機: [[01_3-サービス]].新規ユーザ登録
- 入力: ユーザUUID、アカウント名、slot `0`、作成者
- 結果: [[02_1-モデル定義]].アカウントモデル を作成し、user 側の選択アカウントIDへ反映する

## 2. 選択アカウント解決

- 契機: ログイン処理、オンライン状態構築、user の最終参加情報更新
- 優先: [[01_1-モデル定義]].ユーザモデル.accountId
- フォールバック: `isActive = true` のアカウント

## 3. アカウントモード変更

- 契機: `/account mode <mode> [<player|accountUuid>]` または `/am <mode> [<player|accountUuid>]`
- 実行条件: コンソール、または permission `99` 以上のプレイヤー
- 結果: アカウントモードを更新し、オンライン中なら [[03_1-モデル定義]].プレイヤーセッション へ反映する

## 4. 管理者のゲームモードによるアカウントモード変更

- 契機: permission `99` 以上のオンラインプレイヤーがゲームモードを変更する
- ADVENTURE: アカウントモードを `PLAYER` に更新する
- CREATIVE: アカウントモードを `ADMIN` に更新する
- SURVIVAL / SPECTATOR: アカウントモードは変更しない。`PLAYER` モードでは従来どおり変更を抑止する
- 結果: `ADMIN + ADVENTURE` の組み合わせは維持せず、ADVENTURE 選択時は `PLAYER` として反映する

## 5. 経験値加算・レベルアップ

- 契機: 戦闘、クエスト、探索、クラフト等の gameplay 報酬
- 入力: 対象アカウントUUID、加算経験値
- 処理: [[02_3-サービス]].経験値加算 で累計経験値を更新し、必要に応じて複数レベル分のレベルアップ判定を行う
- 補足: Mob 撃破時はドロップ受取対象ごとに mob 定義の `exp` をそのまま加算する
- 結果: [[02_1-モデル定義]].アカウントモデル の `level` / `totalExperience` が更新され、レベルアップ数と同数のパッシブポイント（PP）を獲得したものとして扱う。PPは永続化せず、現在レベルと解放済みノードから算出する
