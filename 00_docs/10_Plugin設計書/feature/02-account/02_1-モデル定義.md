# 02_1-モデル定義

## 1. ドメインモデル

`account` 機能の中心はアカウントモデル。
[[01_1-モデル定義]].ユーザモデル に紐づくゲーム内アカウントを表し、選択状態、モード、メニューショートカット設定、プレイヤーレベル進行を保持する。

## 2. アカウントモデル

物理名: `AccountModel`

### 2.1 項目

#### 2.1.1 識別情報

- `uuid`
- `userId`
- `accountName`
- `slotIndex`

#### 2.1.2 選択・モード

- `isActive`
- `mode`
- `menuShortcutsJson`

#### 2.1.3 プレイヤーレベル進行

- `level`
- `totalExperience`

#### 2.1.4 クラス進行

- `classId`: 現在選択中クラス ID
- `classLevel` / `classExperience`: 現在クラスの互換ミラー
- `classProgresses`: クラス ID ごとの `ClassProgressModel` 一覧

クラス別レベル・累計経験値は `classProgresses` を正本とし、転職しても他クラスの進行度を保持する。

物理名: `ClassProgressModel`

| 項目 | 型 | 既定値 | 説明 |
|---|---|---|---|
| `classId` | `String` | なし | クラス ID |
| `level` | `int` | `1` | クラスレベル |
| `experience` | `long` | `0` | 累積クラス経験値 |

#### 2.1.5 監査情報

- `createdAt`
- `updatedAt`
- `createdBy`
- `updatedBy`
- `isDeleted`

## 3. アカウントモード

物理名: `AccountMode`

| 値 | 論理名 | 説明 |
|---|---|---|
| `0` | 通常プレイヤー | 通常プレイ用。GUIインベントリへ反映する |
| `1` | ビルダー | ビルド権限向け。GUIインベントリ反映は行わない |
| `2` | 管理者 | 管理権限向け。GUIインベントリ反映は行わない |

- `AccountMode.PLAYER` のみ、ドッジや ActionBar / Sidebar などのゲーム中 HUD 更新対象とする。
- `AccountMode.PLAYER` のみ、通常プレイ導線（NPC interaction、通常 GUI / command、ショップ、ストレージ、売却、装備強化、パーティー、トレード）を処理対象とする。
- `user.permission` が管理者権限であっても、account mode が `ADMIN` / `BUILDER` の場合は通常プレイ導線を実行しない。管理者向けデバッグは、管理者 permission を持つ `AccountMode.PLAYER` で実行する。

## 4. プレイヤーレベル進行

### 4.1 項目定義

| 項目 | 説明 |
|---|---|
| `level` | 現在のプレイヤーレベル。初期値は `1`、最小値は `1`、最大値は `100` |
| `totalExperience` | そのアカウントが累計で獲得した経験値。消費では減少しない |

### 4.2 次レベル必要経験値

次の 1 レベルに必要な経験値は、現在レベル `L` と account UUID から以下で算出する。

| 要素 | 算出式 |
|---|---|
| 基本増加量 | `500 + (L * L * 120)` |
| tier加算 | `floor(L / 10) * 850` |
| wave加算 | `[0, 90, 35, 140, 60, 185, 95, 230][(L - 1) mod 8]` |
| milestone加算 | `L mod 5 = 0` の場合 `600 + (L * 80)`、それ以外は `0` |
| hash加算 | `Hash(accountUuid + ":" + L) mod (90 + (L * 4))` |

- `Hash(...)` はサーバ実装で固定のハッシュ関数を使い、同一 account / 同一 level で常に同値を返す。
- 必要経験値は `基本増加量 + tier加算 + wave加算 + milestone加算 + hash加算` とする。
- 累積必要経験値はレベル `1` から対象レベル直前までの必要経験値総和とする。
- この式は内部仕様であり、プレイヤーへは exact 値を常時表示しない。
- プレイヤーレベルアップ時は上昇レベル数と同数のパッシブポイント（PP）を獲得したものとして扱う。未使用PPは永続化せず、現在レベルと解放済みノードから算出する。

### 4.3 表示方針

- 通常 UI では `level` と経験値進捗バーのみ表示する。
- 次レベル必要経験値の exact 値はデバッグ・管理用途を除きプレイヤーへ開示しない。
- プレイヤー向けには `LOW` / `MID` / `HIGH` / `NEAR` の 4 段階進捗表現を優先する。

### 4.4 経験値加算結果

物理名: `AccountExperienceResult`

| 項目 | 型 | 説明 |
|---|---|---|
| `previousAccount` | `AccountModel` | pending 進行を重ねた更新前状態 |
| `updatedAccount` | `AccountModel` | 今回の加算後状態 |
| `grantedExperience` | `int` | 実際に受理した加算値。0 以下の入力は `0` |
| `levelUps` | `int` | 今回上昇したレベル数 |

- `leveledUp()` は `levelUps > 0` を返す。

## 5. 関連 feature とのモデル関係

- `user`
  - [[01_1-モデル定義]].ユーザモデル.accountId は選択中アカウントを指す。
- `player`
  - [[03_1-モデル定義]].プレイヤーセッション は現在のアカウントモデルを保持する。
- `status`
  - [[07_3-サービス]].レベル補正取得 が `level` を参照してステータス補正を算出する。
- `inventory`
  - アカウントモードが通常プレイヤーの場合、GUIインベントリへ反映する。
