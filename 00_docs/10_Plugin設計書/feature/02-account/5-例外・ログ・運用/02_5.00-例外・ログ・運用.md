# 02_5.00-例外・ログ・運用

## 1. 方針

`account` 機能は、API 異常をリポジトリでログ記録して例外化し、サービス・コマンド側で呼び出し元へ伝播する。

## 2. 主なログポイント

- `AccountService`
  - アカウント作成成功: `LogId.I_5100`
  - アカウント切替成功: `LogId.I_5101`
  - アカウントモード更新成功: `LogId.I_5102`
  - レベルアップ成功: `LogId.I_5103`
  - 経験値 flush 失敗: `LogId.E_5156`
  - クラス進行 flush 失敗: `LogId.E_5157`
  - 停止時の残存 pending: `LogId.W_5156`
- `AccountModeCommand`
  - 非同期対象解決・永続化失敗: `LogId.E_5154`
- `AccountRepository`
  - 一覧取得: `LogId.W_5150`, `LogId.E_5150`（`200` 成功時はログなし）
  - 単体取得: `LogId.D_5151`, `LogId.W_5151`, `LogId.E_5151`
  - 登録: `LogId.D_5152`, `LogId.E_5152`
  - アクティブアカウント切替: `LogId.D_5153`, `LogId.E_5153`
  - アカウントモード更新: `LogId.D_5154`, `LogId.E_5154`
  - アカウント進行更新: `LogId.D_5155`, `LogId.E_5155`

## 3. プレイヤーメッセージ

| ID | テンプレート | 出力箇所 |
|---|---|---|
| `PlayerMsgId.P_5330` | `アカウントモード変更サービスが初期化されていません。` | `AccountModeCommand` 初期化検証 |
| `PlayerMsgId.P_5331` | `mode は名称（PLAYER/BUILDER/ADMIN）または 0, 1, 2 のいずれかで指定してください。` | `AccountModeCommand` mode 入力検証 |
| `PlayerMsgId.P_5332` | `アカウントモードを更新しました: {0} = {1}` | `AccountModeCommand` 更新成功 |
| `PlayerMsgId.P_5333` | `対象アカウントが見つかりません: {0}` | `AccountModeCommand` 対象解決失敗 |
| `PlayerMsgId.P_5334` | `対象アカウントのモードを更新中です。完了までお待ちください。` | 同一対象の並行更新拒否 |
| `PlayerMsgId.P_5062` | `コマンドの実行中にエラーが発生しました。詳細はサーバーログを確認してください。` | mode の非同期処理失敗 |

プレイヤーおよびコンソールへのコマンド結果は `PlayerMsgId` / `player.properties` を経由し、コマンドクラスへ文言を直書きしない。

## 4. スレッドと再試行

- `AccountModeCommand` は対象解決と API 永続化を非同期、オンライン `AstPlayer` と inventory GUI の反映をメインスレッドで行う。
- 同一 account の永続化は `AccountModeApplicationService` が直列化し、最新世代だけをオンラインへ反映する。
- 経験値・クラス進行 flush が失敗した場合は pending を削除せず、次回定期 flush または停止時 flush で再試行する。
