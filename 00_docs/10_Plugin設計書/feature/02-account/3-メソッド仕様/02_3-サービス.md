### アカウント作成

クラス名: `AccountService`
物理名: `createAccount`

処理内容:

1. [[02_3-リポジトリ]].ユーザ別アカウント一覧取得で既存スロットを確認する

	| 項目 | 内容 |
	|---|---|
	| 検証対象 | `slotIndex` |
	| 使用済み | `IllegalArgumentException` を送出する |

2. [[02_1-モデル定義]].アカウントモデル を組み立てる

	| 項目 | 内容 |
	|---|---|
	| `uuid` | 新規UUID |
	| `userId` | ユーザUUID |
	| `accountName` | アカウント名 |
	| `slotIndex` | 入力スロット |
	| `isActive` | 既存アカウントが空なら `true` |
	| `mode` | [[02_1-モデル定義]].アカウントモード の通常プレイヤー |
	| `level` | `1` |
	| `totalExperience` | `0` |
	| `createdBy` / `updatedBy` | 入力された作成者UUID |

3. [[02_3-リポジトリ]].アカウント登録を実行する
4. 正常終了時は `LogId.I_5100` を記録する

	| 項目 | 内容 |
	|---|---|
	| ID | `LogId.I_5100` |
	| レベル | `INFO` |
	| テンプレート | `アカウントを作成しました: %s (slot=%d, user=%s)` |
	| 出力条件 | アカウント作成成功時 |
	| 引数 | `accountName`, `slotIndex`, `userId` |

### アカウントモード変更・オンライン反映

クラス名: `AccountModeApplicationService`
物理名: `changeMode`

入力:

- `accountUuid`: 更新対象アカウント UUID
- `mode`: 更新後 `AccountMode`
- `updatedBy`: 更新者 UUID

処理内容:

1. [[02_3-サービス]].アカウントモード直列永続化 を実行する
2. [[02_3-サービス]].永続化済みモードオンライン反映 を実行する
3. 永続化後の `AccountModel` を返す

### アカウントモード直列永続化

クラス名: `AccountModeApplicationService`
物理名: `persistModeChange`

処理内容:

1. アカウント UUID 単位の `ModeChangeState.persistenceMonitor` で API 更新を直列化する
2. `AccountService.setMode` を実行する
3. 当該アカウントの `persistedGeneration` を加算する
4. 更新後アカウントと世代を `PersistedModeChange` として返す

スレッド条件:

- Bukkit API を使用しないため非同期タスクから呼び出せる

### 永続化済みモードオンライン反映

クラス名: `AccountModeApplicationService`
物理名: `applyPersistedMode`

処理内容:

1. `PersistedModeChange.generation` が当該アカウントの最新世代か確認し、古い場合は `false` を返す
2. 同一アカウント UUID のオンライン `AstPlayer` を走査する
3. ADMIN から別モードへ移る場合は tool inventory snapshot を保存する
4. `AstPlayer.applyAccountMode` で更新後アカウントを反映する
5. 新旧 mode に応じて通常 inventory、tool inventory、または空 GUI を反映する
6. 最新世代を反映した場合は `true` を返す

スレッド条件:

- Bukkit / inventory GUI を操作するためメインスレッドから呼び出す

### 経験値加算

クラス名: `AccountService`
物理名: `grantExperienceCached`

処理内容:

1. 加算経験値が `0` 以下の場合、現在の [[02_1-モデル定義]].アカウントモデル を変更せず返す
2. 引数のアカウントモデルに、未 flush の経験値キャッシュがあればそれを優先して基準状態とする
3. `totalExperience` へ加算経験値を加える
4. [[02_1-モデル定義]].プレイヤーレベル進行 の式で次レベル必要経験値と累積必要経験値を算出し、到達済みの間は `level` を繰り上げる

	| 項目 | 内容 |
	|---|---|
	| 判定単位 | 1レベルずつ順に判定する |
	| 複数上昇 | 大量経験値で複数レベル到達した場合も同一処理内で反映する |
	| 表示方針 | exact な次レベル必要経験値はプレイヤーへ返さない |

5. 更新後の `level` / `totalExperience` を account 単位の経験値キャッシュへ保持する
6. 定期 flush タスクが一定間隔で [[02_3-リポジトリ]].アカウント進行更新を実行する
7. プラグイン停止時は `stop` で残存キャッシュを同期 flush する
8. Mob 撃破契機でレベルが変化した場合は、上昇レベル数と同数のパッシブポイント（PP）を獲得したものとして、skilltree の派生状態を再計算できるよう結果へ含める。PPは account-skilltree 永続状態へ保存しない
9. レベルが変化した場合は `LogId.I_5103` を記録する

	| 項目 | 内容 |
	|---|---|
	| ID | `LogId.I_5103` |
	| レベル | `INFO` |
	| テンプレート | `アカウントレベルが上がりました: %s (level=%d, totalExp=%d)` |
	| 出力条件 | 経験値加算でレベルが 1 以上上昇した場合 |
	| 引数 | `accountUuid`, 更新後 `level`, 更新後 `totalExperience` |

出力:

- [[02_1-モデル定義]].経験値加算結果

### pending 進行復元

クラス名: `AccountService`
物理名: `restoreCachedProgress`

処理内容:

1. 補償対象の `AccountModel` を経験値 pending とクラス進行 pending の双方へ登録する
2. 次回 flush では指定スナップショットを正本として保存する

出力:

- なし

### レベル内経験値進捗率取得

クラス名: `AccountService`
物理名: `experienceProgress`

処理内容:

1. レベルを `1` 以上へ正規化する
2. 最大レベルなら `1.0` を返す
3. 現在レベル開始時と次レベル開始時の累積必要経験値から進捗率を算出する
4. 結果を `0.0..1.0` に clamp して返す

### 現在レベル経験値割合喪失

クラス名: `AccountService`
物理名: `loseCurrentLevelExperiencePercentCached`

処理内容:

1. pending 進行を重ねた状態を基準にし、割合を `0..100` に clamp する
2. 現在レベル開始後に獲得した経験値だけから指定割合を減算する
3. レベル開始時の累積必要経験値を下限とし、レベルダウンさせない
4. 変更後状態を pending へ登録し、`Optional<AccountModel>` を返す

終了条件:

- 割合 0、レベル内経験値 0、または値が変わらない場合は `Optional.empty()`

### クラス進行キャッシュ更新

クラス名: `AccountService`
物理名: `updateClassProgressCached`

処理内容:

1. pending 進行を重ねたアカウントを基準にする
2. 選択クラスの `classId` / `classLevel` / `classExperience` と `classProgresses` を更新する
3. account UUID 単位のクラス進行 pending へ登録し、更新後 `AccountModel` を返す

### クラス進行即時保存

クラス名: `AccountService`
物理名: `saveClassProgressNow`

処理内容:

1. `AstPlayer` の現在クラス進行を [[02_3-サービス]].クラス進行キャッシュ更新 へ登録する
2. 当該 pending を直ちに `AccountRepository.updateClassProgress` で flush する

### サービス停止

クラス名: `AccountService`
物理名: `stop`

処理内容:

1. 定期 flush task を停止する
2. 経験値・クラス進行 pending が空になるまで最大 `MAX_STOP_FLUSH_ATTEMPTS` 回同期 flush する
3. 残存 pending がある場合は `LogId.W_5156` を記録する

例外時挙動:

- 個別経験値 flush 失敗は `LogId.E_5156`、個別クラス進行 flush 失敗は `LogId.E_5157` を記録し、pending を保持する
