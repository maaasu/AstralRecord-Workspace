### アカウント切替

クラス名: `AccountService`
物理名: `switchAccount`

処理内容:

1. [[02_3-リポジトリ]].アクティブアカウント切替を実行する
2. 切替後の [[02_1-モデル定義]].アカウントモデル を返す
3. 正常終了時は `LogId.I_5101` を記録する

	| 項目 | 内容 |
	|---|---|
	| ID | `LogId.I_5101` |
	| レベル | `INFO` |
	| テンプレート | `アカウントを切り替えました: %s (user=%s)` |
| 出力条件 | アカウント切替成功時 |
| 引数 | `accountUuid`, `userId` |

管理者コマンドから呼び出す場合は、対象ユーザーと実行者を分離する次の形式を使用する。

```text
switchAccount(userId, accountUuid, updatedBy)
```

- `userId`: 切替対象ユーザー UUID
- `accountUuid`: 選択するアカウント UUID
- `updatedBy`: API の `updatedBy` に保存するコマンド実行者 UUID
- 2 引数形式は `updatedBy = userId` として扱う既存呼び出し互換用である

補足:

- API 側で対象ユーザーの他アカウントを非アクティブ化し、`user.accountId` と対象アカウントを同一更新として反映する。

### アカウントモード更新

クラス名: `AccountService`
物理名: `setMode`

処理内容:

1. account UUID 単位の進行ガード内で、未ACKの進行を重ねた `AccountModel` の `mode` を即時変更する
2. mode だけの pending と `clientRevision` を更新する。API通信・保存要求は開始しない
3. 更新後のローカル `AccountModel` を返し、`LogId.I_5102` を記録する

	| 項目 | 内容 |
	|---|---|
	| ID | `LogId.I_5102` |
	| レベル | `INFO` |
	| テンプレート | `アカウントモードを更新しました: %s (mode=%s, updatedBy=%s)` |
	| 出力条件 | アカウントモード更新成功時 |
	| 引数 | `accountUuid`, `mode.value`, `updatedBy` |

### offlineモードAPI保存

クラス名: `AccountService`
物理名: `saveOfflineMode`

処理内容:

1. [[02_3-サービス]].アカウント取得 と同じ account UUID 単位の進行ガードを取得する
2. 未ACK進行がある場合は `IllegalStateException` で拒否し、API更新を開始しない
3. [[02_3-リポジトリ]].アカウントモード更新 を実行する
4. API応答の `progressVersion` をACK済み進行版へ最大値で反映し、古い取得応答へ重ねる保存済みmodeとして保持する
5. API保存済み `AccountModel` を返し、`LogId.I_5102` を記録する

スレッド条件:

- offline管理コマンドの非同期タスクからだけ呼び出し、BukkitメインスレッドでAPI応答を待たない

### offlineモードオンライン反映

クラス名: `AccountService`
物理名: `mergeSavedOfflineMode`

処理内容:

1. offline API保存待機中に対象がログインした場合、現在のオンライン `AccountModel` を基準にする
2. API保存済み結果から `mode` と `updatedBy` だけを重ねる
3. ログイン後に発生した未ACK進行をさらに重ね、レベル・経験値・クラス進行をAPI応答で上書きしない

### アカウント名変更

クラス名: `AccountService`
物理名: `renameAccount`

処理内容:

1. 選択中アカウント UUID を対象として、`AccountRepository.updateName` を実行する
2. API が 409 を返した場合はアカウント名重複としてプレイヤーへ通知し、キャッシュを変更しない
3. 成功時は更新後の `AccountModel` をキャッシュへ反映する
4. 表示名は `{accountName}#{slotIndex}` とし、`#slotIndex` だけを灰色で描画する

### アカウントモード変更・オンライン反映

クラス名: `AccountModeApplicationService`
物理名: `changeMode`

入力:

- `accountUuid`: 更新対象アカウント UUID
- `mode`: 更新後 `AccountMode`
- `updatedBy`: 更新者 UUID

処理内容:

1. オンラインaccountを対象に [[02_3-サービス]].モードローカル確定 を実行する
2. [[02_3-サービス]].ローカルモードオンライン反映 を実行する
3. 共通 player-state 保存を予約し、API応答を待たず更新後 `AccountModel` を返す

### モードローカル確定

クラス名: `AccountModeApplicationService`
物理名: `persistModeChange`

処理内容:

1. アカウント UUID 単位の `ModeChangeState.persistenceMonitor` で local mutation を直列化する
2. オンラインなら `InventoryService.executeLocalPlayerMutation` の state lock 内で `AccountService.setMode` を実行する
3. offlineなら `IllegalStateException` で拒否し、offline管理コマンド専用のAPI保存経路へ委譲させる
4. 当該アカウントの `persistedGeneration` を加算する
5. 更新後アカウントと世代を `PersistedModeChange` として返す。保存要求は inventory/UI 反映後に行う

スレッド条件:

- オンラインaccountは Bukkit/inventory state を含むためメインスレッドから呼び出す

### ローカルモードオンライン反映

クラス名: `AccountModeApplicationService`
物理名: `applyPersistedMode`

処理内容:

1. `PersistedModeChange.generation` が当該アカウントの最新世代か確認し、古い場合は `false` を返す
2. 同一アカウント UUID のオンライン `AstPlayer` を走査する
3. `InventoryService.executeLocalPlayerMutation` の state lock 内で、ADMIN から別モードへ移る場合は tool inventory snapshot を保存する
4. offline API保存後に対象がログイン済みなら、現在のオンライン進行を保持して保存済みmodeだけを合成する
5. 同じ state lock 内で `AstPlayer.applyAccountMode` と、新旧 mode に応じた通常 inventory、tool inventory、または空 GUI の反映を行う
6. ローカル確定結果だけ、state lock 解放後に `AccountService.requestLocalPlayerSave` で共通 player-state 保存を予約する。offline API保存済み結果は再保存しない
7. 最新世代を反映した場合は `true` を返す

スレッド条件:

- Bukkit / inventory GUI を操作するためメインスレッドから呼び出す

### 経験値加算

クラス名: `AccountService`
物理名: `grantExperienceCached`

処理内容:

1. 加算経験値が `0` 以下の場合、現在の [[02_1-モデル定義]].アカウントモデル を変更せず返す
2. 引数のアカウントモデルに、未 flush の経験値キャッシュがあればそれを優先して基準状態とする
3. `totalExperience` へ加算経験値を加える
4. [[02_1-モデル定義]].プレイヤーレベル進行 の式で次レベル必要経験値と累積必要経験値を算出し、到達済みの間は `level` を繰り上げる

	| 項目 | 内容 |
	|---|---|
	| 判定単位 | 1レベルずつ順に判定する |
	| 複数上昇 | 大量経験値で複数レベル到達した場合も同一処理内で反映する |
	| 表示方針 | exact な次レベル必要経験値はプレイヤーへ返さない |

5. 更新後の `level` / `totalExperience` を account 単位の経験値キャッシュへ保持する
6. 定期 flush タスクは一定間隔で account ID を共通プレイヤー保存キューへ登録する。API 通信はこのタスクから直接行わない
7. プラグイン停止時は `stop` で残存進行を共通プレイヤー保存キューへ登録する
8. Mob 撃破契機でレベルが変化した場合は、上昇レベル数と同数のパッシブポイント（PP）を獲得したものとして、skilltree の派生状態を再計算できるよう結果へ含める。PPは account-skilltree 永続状態へ保存しない
9. レベルが変化した場合は `LogId.I_5103` を記録する

	| 項目 | 内容 |
	|---|---|
	| ID | `LogId.I_5103` |
	| レベル | `INFO` |
	| テンプレート | `アカウントレベルが上がりました: %s (level=%d, totalExp=%d)` |
	| 出力条件 | 経験値加算でレベルが 1 以上上昇した場合 |
	| 引数 | `accountUuid`, 更新後 `level`, 更新後 `totalExperience` |

出力:

- [[02_1-モデル定義]].経験値加算結果

### pending 進行復元

クラス名: `AccountService`
物理名: `restoreCachedProgress`

処理内容:

1. 補償対象の `AccountModel` を経験値 pending とクラス進行 pending の双方へ登録する
2. 次回 flush では指定スナップショットを正本として保存する

出力:

- なし

### レベル内経験値進捗率取得

クラス名: `AccountService`
物理名: `experienceProgress`

処理内容:

1. レベルを `1` 以上へ正規化する
2. 最大レベルなら `1.0` を返す
3. 現在レベル開始時と次レベル開始時の累積必要経験値から進捗率を算出する
4. 結果を `0.0..1.0` に clamp して返す

### 現在レベル経験値割合喪失

クラス名: `AccountService`
物理名: `loseCurrentLevelExperiencePercentCached`

処理内容:

1. pending 進行を重ねた状態を基準にし、割合を `0..100` に clamp する
2. 現在レベル開始後に獲得した経験値だけから指定割合を減算する
3. レベル開始時の累積必要経験値を下限とし、レベルダウンさせない
4. 変更後状態を pending へ登録し、`Optional<AccountModel>` を返す

終了条件:

- 割合 0、レベル内経験値 0、または値が変わらない場合は `Optional.empty()`

クラス名: `AccountService`

3. account UUID 単位のクラス進行 pending へ登録し、更新後 `AccountModel` を返す

### accountProgress state section

クラス名: `AccountService`
物理名: `snapshotPlayerState`

dirty な経験値、クラス進行、またはmodeがある account だけ、共通 player-state snapshot の `accountProgress` section を返す。payload は `accountId`、`clientRevision`、`expectedProgressVersion`、`updatedBy`、`level`、`totalExperience`、`classId`、`classLevel`、`classExperience`、`classProgresses` に限定し、mode変更がdirtyの場合だけ `mode` を加える。アカウント名・権限・ban・プロフィール系の値は含めない。

- section ACK は `clientRevision` と `int` 型 `progressVersion` が必須である。不正値・欠落・捕捉revision不一致は例外としてsnapshot送信失敗へ返し、dirtyを保持する。
- ACK の `progressVersion` は snapshot世代が古く当該dirtyを解除できない場合も進める。dirty解除だけは同名 section の `clientRevision` が捕捉した revision と一致する場合に限る。
- snapshot取得後に進行が変化して revision が進んだ場合、古い ACK は新しいdirtyを解除しない。
- API応答はローカル進行値を上書き・rollbackしない。ACK の `int` 型 `progressVersion` だけを取り込み、`int` 型 `expectedProgressVersion` で検証する。進行と無関係な account row 更新とは別の進行専用version契約を使用する。
- account UUID ごとの進行ガードで、pending 合成、dirty revision の採番、snapshot捕捉、ACK解除を直列化する。inventory を伴う変更は `InventoryService.executeLocalPlayerMutation` の state lock を先に取得し、その内側でこのガードを取る。
- state lock / account進行ガードの内側では API 通信も保存要求も開始しない。mode の保存要求は state lock 解放後に `requestLocalPlayerSave` を呼ぶ。

### アカウント削除

クラス名: `AccountService`
物理名: `deleteAccount`

1. 対象 account UUID の未保存経験値・クラス進行を破棄する。
2. [[02_3-リポジトリ]].アカウント削除 を実行し、削除結果を返す。
3. API 削除成功時は `LogId.I_5104` を記録する。

### サービス停止

クラス名: `AccountService`
物理名: `stop`

処理内容:

1. 定期 flush task を停止する
2. 残存経験値・クラス進行の account ID を共通プレイヤー保存キューへ登録する
3. 共通snapshotの永続化・再試行・停止drainへ委譲し、pending値はACKまで保持する
