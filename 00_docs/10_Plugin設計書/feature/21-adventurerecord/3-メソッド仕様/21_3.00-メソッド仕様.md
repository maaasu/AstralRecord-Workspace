# 21_3.00-メソッド仕様

## 冒険記録一覧構築

クラス名: `AdventureRecordService`
物理名: `buildEntriesAsync`

1. 入力 `AstPlayer`、`AdventureRecordListType`、検索対象 item ID 集合を受け取る。
2. scheduler の async task でスーパーモード設定を解決し、`AdventureRecordRepository.findMobRecords(accountId, category)` を 1 回だけ呼んで討伐済み Mob 記録を取得する。
3. 取得元 feature は `adventurerecord` repository、`mob` feature の `MobService`、`playersetting` feature のスーパーモード設定とする。
4. 取得項目は `mobId`、討伐数、初回討伐日時、最終討伐日時、`MobTemplate` の表示名、カテゴリ、drop 設定とする。
5. 記録済み `mobId` ごとに `MobService.findTemplate` を呼び、テンプレート未解決、一覧種別不一致、検索条件不一致の entry は除外する。
6. `isSuperMode(player)` が `true` の場合のみ、`MobService.getLoadedMobIds()` から未討伐 Mob も補完し、討伐済み entry の後ろに `mobId` 昇順で追加する。
7. main thread へ `EntryResult` を返し、`entries` の `defeated` で討伐済み / 未討伐を、`superMode` で表示モードを区別する。
8. repository 取得失敗時は main thread の失敗 callback へ返し、GUI を開かない。

失敗時出力:

| 種別 | ID | レベル | テンプレート | 出力条件 | 引数 |
|---|---|---|---|---|---|
| ログ | `LogId.E_5600` | ERROR | `メニューイベント処理に失敗しました: %s` | GUI click / drag / close から一覧構築を呼んだ処理で例外が発生した場合 | `playerName`, `action` |

## 冒険記録 GUI 表示

クラス名: `AdventureRecordGui`
物理名: `open`

1. 呼び出し元導線と表示対象 `AdventureRecordListType` を受け取る。
2. [[21_3.00-メソッド仕様]].冒険記録一覧構築 を非同期で呼び出し、プレイヤー単位の request ID を保持する。
3. 最新 request ID と user・account が一致する応答だけを main thread で `AdventureRecordGui.openMobList` へ渡す。GUI close、後続要求、account 切替後の古い応答は破棄する。
4. ページ切替は GUI holder に保持した同一 entry snapshot を使用し、repository を再取得しない。
5. 戻る操作は呼び出し元導線へ返す。メイン画面からの戻りは menu feature のメインメニューへ返す。
6. 検索画面では選択中 item ID 集合を保持し、検索ボタン押下時に `AdventureRecordListType.SEARCH` として再表示する。

失敗時出力:

| 種別 | ID | レベル | テンプレート | 出力条件 | 引数 |
|---|---|---|---|---|---|
| ログ | `LogId.E_5600` | ERROR | `メニューイベント処理に失敗しました: %s` | AdventureRecord GUI の click / drag / close 処理で例外が発生した場合 | `playerName`, `action` |

## 記録イベント反映

クラス名: `AdventureRecordService`
物理名: `recordDefeatAsync`

1. 入力 `AstPlayer recipient` と討伐された `MobTemplate template` を受け取る。
2. `template.category` が `ENEMY` または `BOSS` でなければ記録対象外として何もせず終了する。
3. 保存先は AstralRecord API の `/api/adventure-record/mob/defeat` とし、`AdventureRecordRepository.recordMobDefeat(accountId, mobId, category, userId)` へ非同期で委譲する。
4. 必須入力は `accountId`、`userId`、`mobId`、`MobCategory` とする。
5. 戻り値は持たない。失敗時はログを残し、呼び出し元 feature の主処理は継続する。
6. 重複防止や冪等性キーは現行仕様では repository / API 側の責務とし、plugin 側では同一討伐イベントを追加抑止しない。

失敗時出力:

| 種別 | ID | レベル | テンプレート | 出力条件 | 引数 |
|---|---|---|---|---|---|
| ログ | `LogId.E_5703` | ERROR | `Mob ドロップ抽選で例外が発生しました: mobId=%s` | 討伐記録の非同期保存で例外が発生した場合 | `mobId` |
