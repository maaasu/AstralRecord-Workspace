# 21_5-例外・ログ・運用

## 例外方針

- API 一覧取得失敗は非同期 failure callback へ変換し、既存 GUI を上書きしない。
- 討伐・踏破はローカル差分へ即時反映し、通常の snapshot 保存失敗時は差分を破棄せず共通 save lane の結果照会・再送へ渡す。
- チャンネル移動境界で保存失敗が確定した場合は移動を中止し、現在チャンネルに残して失敗メッセージを表示する。
- API record と MobTemplate の不整合は該当 entry を表示対象外にする。
- 非同期応答は player online、account、request ID を再検証し、GUI close で request ID を無効化する。
- Mob 詳細は一覧の `Entry` snapshot が保持する `MobTemplate` を使う。status ID が `StatusType` に存在しない値は表示せず、ワールド上の MobInstance が存在しないことをエラーにはしない。

## ログ

- GUI click／drag／close は `LogId.E_5601` と `adventure_record_gui_click`／`drag`／`close` を使う。
- player-state 保存・結果照会・失敗確定は共通 save lane のログを使う。

## 運用

- account ID と mob ID／dungeon ID の一意制約、および `snapshotId` 単位の差分冪等加算契約を維持する。
- Mob master ID 変更時は既存記録の migration または alias 方針を同時に決める。
- super mode は player setting の管理用機能であり、通常 player の未討伐情報を開示しない。
- 冒険記録一覧の初期表示は ENEMY／BOSS 横断とし、カテゴリフィルターは一覧の検索導線とは独立して扱う。
- Mob 情報画面とステータス詳細画面は通常 player に Mob master ID や MobInstance の内部状態を開示せず、表示名・基礎ステータス・討伐情報だけを表示する。
