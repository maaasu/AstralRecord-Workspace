# 15_0.00-概要

## 1. 位置づけ

ホットバーアクションは移行済みの旧 feature であり、現行実装に独立パッケージはない。責務は次のとおり分割されている。

| 責務 | 現行の正本 |
|:--|:--|
| Bukkit / Paper 入力の正規化と候補選択 | player-interaction |
| 武器の左クリック候補と実行 | item |
| メインハンド item とホットバー状態 | inventory |
| skill 発動、クールダウン、アクションリング | skill |

## 2. 左クリック武器アクション

- `PlayerInteractionGatewayEventHandler` が `LEFT_CLICK` を正規化し、`ItemWeaponAttackEventHandler.resolve` を候補 resolver として呼び出す。
- メインハンド入力、`AccountMode.PLAYER`、skilltree 非編集中、アクションリング非表示・攻撃抑止なしを候補条件とする。
- 攻撃不能状態では `weapon-attack-condition-guard`、実行可能時は `weapon-left-click-action` を返す。いずれも `FALLBACK` tier の `CLAIM_AND_CANCEL` 候補である。
- 実行時はメインハンドの `ItemEquipment.slot == WEAPON`、装備要件、耐久値、`onUse.leftClickSkillId`、クールダウンを再検証する。
- `SkillService.castSkill` へ `SkillCastTrigger.AUTO_ATTACK` を渡し、発動成功時だけ item マスタの `leftClickCooldownTicks` を開始する。

## 3. 右クリックとホットバー操作

- 右クリックのアクションリング候補と skill 実行は skill feature が管理する。
- `HOTBAR_SLOT` の入力調停は player-interaction、保存・描画は inventory feature が管理する。
- 候補探索中には ring 開閉、skill 発動、skilltree 状態変更を行わず、選択された executor だけが状態を変更する。

## 4. メッセージ・ログ

本 feature 固有の現行メッセージ・ログはない。未参照の `LogId.E_6000` / `logger.properties` 定義は実行経路の仕様として扱わない。入力 gateway の例外は player-interaction feature の `LogId.E_5999` で記録する。
