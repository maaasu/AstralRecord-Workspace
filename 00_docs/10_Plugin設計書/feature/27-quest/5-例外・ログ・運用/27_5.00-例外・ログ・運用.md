# 27_5.00-例外・ログ・運用

## 1. プレイヤー通知

クエスト機能は `PlayerMsgId` と `player.properties` を通じて共通システムタグ付きで通知する。

| 場面 | 通知 |
|---|---|
| 受領成功 | `クエストを受領しました: <クエスト名>` |
| 受領不可 | `このクエストは現在受領できません。` |
| 上限到達 | `受領中のクエストが上限に達しています。` |
| アイテム不足 | `クエスト受領に必要なアイテムが不足しています。` |
| 条件達成 | `クエスト条件を達成しました: <クエスト名>` |
| 完了 | `クエストを完了しました: <クエスト名>` |
| 破棄 | `クエストを破棄しました: <クエスト名>` |

## 2. サウンド・パーティクル

- 受領成功時は `UI_TOAST_IN` を鳴らす。
- 条件達成/完了時は `UI_TOAST_CHALLENGE_COMPLETE` と `ENTITY_PLAYER_LEVELUP` を鳴らす。
- 条件達成/完了時は `SharedParticleDefinitions.PLAYER_LEVEL_UP_TOTEM` と `PLAYER_LEVEL_UP_END_ROD` を表示する。

## 3. 保存失敗

現在の `QuestPlayerStateRepository` はYAML保存失敗時に例外を外へ投げない。  
本番API永続化へ移行する際は保存失敗をログID付きで記録し、報酬二重付与を避けるためのトランザクション境界を定義する。
