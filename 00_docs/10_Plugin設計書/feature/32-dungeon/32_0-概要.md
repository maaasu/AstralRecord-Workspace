# 32_0-概要

## 1. 目的

ダンジョン機能は、専用の手作りワールドを要求せず、開始要求ごとに独立した void ワールドへ攻略空間を自動生成する。部屋数・形・テーマ・出現 Mob は filebase から調整でき、同じ定義と seed から同じ配置を再現できる。

## 2. 責務

- マスタ定義された受付ゲート内のスニークで、ソロまたはオンラインパーティーの参加者を確定し、待機ハブへ退避してインスタンスを非同期準備する。`/dungeon start <dungeonId>` は受付範囲内での開始 fallback として残す。
- 有限の通常作成枠・寄付者予約作成枠を使い、枠が空くまで待機ハブで待つ。待機中は title／subtitle でダンジョン名、順番、待機人数を表示する。
- 受付地点へ青緑色の門型フレーム、ポータル粒子、ダンジョン名とスニーク案内の TextDisplay を表示し、Boss の円環演出と区別する。
- BSP で指定範囲内に部屋を分散配置し、接続木、開始部屋、唯一のボス部屋を決定する。
- 部屋、直交折れ線通路、ゲート、任意の中央柱をマスタの重み付き Material から生成し、部屋ごとの weighted room type とテーマ装飾を決定的に適用する。
- 各部屋内へ区画番号、START／NORMAL／BOSSの役割、未開放／進入可能／攻略中／攻略済みを示す TextDisplay を生成し、カルトグラフを使わなくても現地で進行状態を判別可能にする。START は常に安全地帯と表示する。
- 部屋内 Mob の全滅で通常子部屋へのゲートを開く。BOSS 部屋へのゲートだけは別分岐を含む BOSS 以外の全部屋がクリアされるまで閉鎖し、解放済み部屋への進入時に次の戦闘を開始する。
- 初回の START 部屋転送後に10秒の開始カウントダウンを行い、STARTを戦闘なしで完了して最初のNORMAL部屋へのゲートを解放する。
- パーティー共有死亡回数、帰還ゲートからの自主離脱／再参加、リーダー中止、Dungeon Sidebar を管理する。
- ボス部屋クリア時に対象者ごとの報酬を確定し、共通 interaction gateway が視線先の実チェストを解決してページング GUI を開き、30秒後に強制帰還・破棄する。
- メインハンドの `CARTOGRAPH` tool 右クリックで、現地の部屋状態表示を補助する現在セッションの相対マップ、または踏破済みダンジョンと設定報酬の archive を表示する。
- 現在セッションの相対マップでは部屋間の通路接続を描画し、本人の現在地と向いている8方向の矢印を表示する。パーティー参加者の位置は表示せず、攻略済み部屋のクリックで本人だけをその部屋へ移動する。
- ボス部屋クリア時に Adventure Record をメモリへ楽観反映して API へ非同期保存し、再起動後もアカウント単位の踏破履歴を利用できるようにする。
- 退出、全参加者不在、生成失敗、死亡許容回数超過、踏破後30秒、Plugin 停止時に Mob・表示・task・ワールド・フォルダを回収する。

## 3. 責務外

- 複数階、鍵アイテム、制限時間は扱わない。
- 部屋や通路を Schematic として手作業管理しない。
- 受付時点に含まれなかった真の途中参加、進行中マップ・カルトグラフ binding・未受取報酬の永続化、サーバー再起動後のセッション復帰は扱わない。踏破 archive だけは Adventure Record として永続化する。
- 個別ダンジョンのテーマ、攻略段階、Mob 構成そのものは本 feature のコードへ埋め込まない。

## 4. 主要境界と不変条件

- 1 開始要求につき一意な一時 `DUNGEON` ワールドを作り、他セッションと共有しない。
- 部屋数は固定値ではなく `roomCount.min` から `roomCount.max` の範囲で seed により決定する。
- 接続は全室を結ぶ閉路なしの木とし、開始部屋からグラフ距離が最大の葉を唯一のボス部屋とする。
- START 部屋は安全地帯として Mob を一切出現させない。START から距離1の最初のNORMAL戦闘部屋では `firstCombatRoomMaxMobLevel` を超える Mob を抽選候補から除外し、候補が一体もない定義は公開しない。
- ボス部屋には `bossMobId` の BOSS Mob を一体だけ出現させる。
- 通路は初期生成済みとし、未クリア側を表示ゲート Material とその奥の不可視 BARRIER で遮断する。通常子部屋への接続は親部屋全滅時、BOSS 部屋への接続は BOSS 以外の全部屋クリア時に、対応する両方を AIR に置換する。
- 受付後は参加者を Boss と同じ待機ハブへ移し、生成完了時にオンライン・通常プレイモード・待機ハブ滞在を再判定する。最少人数未満なら元地点へ戻して終了する。
- 作成枠は `config.yml` の `instanceLimits.dungeon` から読み込み、通常枠と有限の寄付者予約枠を別カウントする。寄付者判定は受付リーダーの `AstPlayer.user.permission >= UserPermission.DONOR(5)` とし、`ADMIN(99)` も対象とする。枠は作成開始から一時 Dungeon world の破棄完了まで保持する。
- 待機中に参加者の一人でも Hub を離れた場合は要求を取り消して終了し、再受付は同じ枠の列末尾から行う。
- START 部屋へ初回転送した後は10秒カウントし、終了時にSTARTを `CLEARED` として次室を解放する。STARTではカウント終了後も Mob を生成しない。参加者が一人以上残る限り受付時の最少人数は再判定せず、再参加者にはカウントダウンを繰り返さない。
- `deathLimit` は0を許容し、共有死亡回数が設定値以下の間は復帰可能、設定値を超えた死亡で終了する。
- 帰還ゲートから自主離脱した受付時参加者だけが同一インスタンスへ再参加できる。ログアウトで権利を失い、挑戦開始後に現パーティーへ加入したメンバーは参加できない。
- Dungeon Mob の死亡報酬受取人は死亡確定時、クリア報酬受取人はボス部屋クリア確定時に、当該 Dungeon world 内にいる現在参加者へ固定する。後補償しない。
- クリア報酬は受取人ごとに独立抽選し、未受取分はクリアから30秒後のセッション破棄と同時に破棄する。
- 実報酬 GUI は抽選後の item と数量だけを示し、設定確率を表示しない。直接報酬および loot table を平坦化した設定確率はカルトグラフ archive だけに表示する。
- カルトグラフの現在マップ binding は装備 instance ID、player ID、dungeon session ID の組でメモリだけに保持する。同じ dungeon master でも session ID が異なれば別登録であり、離脱・終了・失敗・logout・Plugin 停止で削除する。
- カルトグラフの新規 session 登録には現在耐久75以上を要求して固定75を一度だけ消費する。同じ session の再表示は残耐久0でも許可し、既存の修理オーブで回復できる。
- shared interaction gateway では、視認可能な eligible 報酬 CHEST の `WORLD_INTERACTION` 候補をカルトグラフの `ITEM_USE` 候補より優先し、チェスト操作を奪わない。
- reload は新規開始へだけ反映し、進行中セッションは受付時の Dungeon、受付 World、Mob スナップショットを保持する。

## 5. データと依存

- Dungeon マスタ: `40_filebase/65.features.dungeon/*.yml`
- 受付 World 参照: `entry.worldRef` が示す既存 World マスタ
- 生成 World: DungeonService が安全な共通既定値から一時 `DUNGEON` World 定義を組み立てるため、ダンジョンごとの World マスタは不要
- Mob 参照: [[12_0-概要]] の ENEMY/BOSS Mob マスタ
- パーティー: [[19_0-概要]] の受付時オンラインメンバー一覧
- ワールド登録・転送: [[17_0-概要]] の実行時 World 登録とチャンク準備済み転送
- 死亡確定・報酬後通知: [[14_0-概要]] の Mob 死亡処理
- 死亡・復帰: PlayerDeathService
- クリア報酬抽選・付与: MobDropService、InventoryService、item feature
- カルトグラフ装備・耐久・修理: item／inventory feature、共有 `CARTOGRAPH` equipment tag
- 踏破 archive: Adventure Record API の `account_dungeon_record`。Plugin はメインスレッド外で GET／POST し、保存失敗をクリア本体へ伝播しない
- 表示: DisplayTextService、共通 interaction gateway、hud feature
