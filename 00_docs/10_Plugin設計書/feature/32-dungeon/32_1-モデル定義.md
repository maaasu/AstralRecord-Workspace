# 32_1-モデル定義

## 1. DungeonDefinition

`DungeonDefinition` は一つの YAML に一つのダンジョンを保持する。BSP の分割木、生成済み座標、個別部屋 ID は実行時情報であり、マスタへ保存しない。

| 区分 | 主な項目 | 契約 |
|:--|:--|:--|
| 識別 | `id`, `displayName`, `worldRef` | `worldRef` は DUNGEON 用 World マスタ参照 |
| 参加 | `party.min`, `party.max` | 受付時オンライン参加者数の許容範囲 |
| 生成 | `area`, `roomCount`, `roomSize`, 高さ、通路寸法、`splitRatio` | roomCount と寸法は範囲で指定する |
| 形状 | `roomShapes[]` | `RECTANGLE` または `CYLINDER` と正の相対 weight |
| 外観 | `floor`, `wall`, `ceiling`, `corridor`, `gateMaterial`, `pillar` | Material weight の合計を 100 に揃える必要はない |
| 戦闘 | `normalMobPool`, `mobsPerRoom`, `firstCombatRoomMaxMobLevel`, `bossMobId` | 通常 ENEMY と唯一の BOSS を分けて参照する |

完全な物理キー、型、境界値は `40_filebase/65.features.dungeon/docs.dungeon.YAMLスキーマ定義.md` を正本とする。

## 2. DungeonLayout

`DungeonLayout` は DungeonDefinition と seed から生成する immutable な配置計画であり、Bukkit World や Material を持たない。

- `rooms`: 両端を含む X/Z 矩形、形状、START/NORMAL/BOSS 役割、開始部屋からの距離を持つ。
- `connections`: 親部屋、子部屋、直交折れ線通路の中心線を持つ。件数は `rooms.size - 1` とする。
- `startRoomId`: 部屋矩形の `minX`、`minZ`、ID の昇順で一意に決定する。
- `bossRoomId`: 開始部屋以外の葉のうち開始部屋から最遠の一室とし、同距離は座標と ID で決定する。

## 3. DungeonBlockPlan

`DungeonBlockPlan` は DungeonLayout にテーマを適用した最終ブロック配置である。

- `placements`: 重複座標を解決済みの Material と、任意の階段向き・上下半分。
- `gateBlocksByConnection`: 親部屋の出口を塞ぐブロック座標。部屋クリア時に AIR へ置換する。
- `spawnPointsByRoom`: 壁と中央柱を避けた Mob 候補座標。
- `playerSpawn`: 開始部屋内の安全な転送座標。

## 4. セッション状態

セッションは受付時の Dungeon、World、Mob 定義、seed、参加者 UUID、帰還 Location、配置計画、一時 World、部屋状態、部屋別生存 Mob UUID をメモリに保持する。

部屋状態は次の順で遷移する。

```text
LOCKED -> AVAILABLE -> ACTIVE -> CLEARED
```

親部屋が `CLEARED` になると子部屋を `AVAILABLE` にし、参加者がその部屋へ入った時点で `ACTIVE` として Mob を生成する。
