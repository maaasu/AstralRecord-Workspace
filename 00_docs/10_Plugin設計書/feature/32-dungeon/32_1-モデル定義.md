# 32_1-モデル定義

## 1. DungeonDefinition

`DungeonDefinition` は一つの YAML に一つのダンジョンを保持する。BSP の分割木、生成済み座標、個別部屋 ID は実行時情報であり、マスタへ保存しない。

| 区分 | 主な項目 | 契約 |
|:--|:--|:--|
| 識別 | `id`, `displayName` | ファイル間で一意な ID と表示名 |
| 案内 | `recommendedLevel` | 受付地点の TextDisplay に表示するプレイヤー向け推奨レベル。1以上の整数 |
| 受付 | `entry.worldRef`, 座標, `radius` | Boss と同様に既存 World 上の受付範囲を定義する |
| 参加 | `party.min`, `party.max` | 受付時点の現在パーティー参加者数の許容範囲。省略時 `1..4` |
| 挑戦 | `challenge.deathLimit`, `challenge.reviveDelaySeconds`, `challenge.timeLimitSeconds` | 共有死亡許容回数、復帰待機秒、開始後制限時間。省略時 `5`, `5`, `600`。timeLimitSeconds の明示 `null` は無制限 |
| 生成 | `area`, `roomCount`, `roomSize`, 高さ、通路寸法、`splitRatio` | すべて省略可能。roomCount と寸法は範囲で指定する |
| 形状 | `roomShapes[]` | `RECTANGLE` または `CYLINDER` と正の相対 weight |
| 部屋タイプ | `roomTypes[]` | `STANDARD` / `SUPPORT_HALL` / `COLLAPSED` / `ORE_CHAMBER` と正の相対 weight。省略時は `STANDARD:1` |
| 外観 | `floor`, `wall`, `ceiling`, `corridor`, `gateMaterial`, `lightMaterial`, `pillar`, `decorations` | 照明、支柱・梁、瓦礫、鉱石等の accent を汎用 Material として定義する。weight 合計を 100 に揃える必要はない |
| 戦闘 | `normalMobPool`, `mobsPerRoom`, `firstCombatRoomMaxMobLevel`, `bossMobId` | Mob 参照だけ必須。Mobレベル、weight と数値調整値は既定値を持つ。BOSS 部屋の BOSS Mob には共通の HP／シールド人数補正を適用する |
| クリア報酬 | `clearRewards.items[]`, `clearRewards.lootTable` | Mob drops と同じ直接 item／loot table 抽選。クリア対象者ごとに独立抽選する |

`recommendedLevel` はプレイヤーへ提示する攻略目安であり、Mob の実レベル、最初の戦闘部屋の Mob レベル上限、設計メタデータの `progression` とは別の値です。

完全な物理キー、型、境界値は `40_filebase/65.features.dungeon/docs.dungeon.YAMLスキーマ定義.md` を正本とする。
省略時だけ既定値を補い、明示された値は constructor で補正しない。型違いは repository、境界外の `deathLimit`／`reviveDelaySeconds`／`timeLimitSeconds`／報酬 `rate`／`amount` は公開前 validator で拒否する。`timeLimitSeconds` は `null` または30秒以上とする。

`normalMobPool[].level` と `bossMobLevel` は任意の Mob レベルプロファイル指定であり、未指定または未登録時は対象Mobの最小レベルを使用する。

## 2. DungeonLayout

`DungeonLayout` は DungeonDefinition と seed から生成する immutable な配置計画であり、Bukkit World や Material を持たない。

- `rooms`: 両端を含む X/Z 矩形、形状、`DungeonRoomType`、START/NORMAL/BOSS 役割、開始部屋からの距離を持つ。
- `connections`: 親部屋、子部屋、直交折れ線通路の中心線を持つ。件数は `rooms.size - 1` とする。
- `startRoomId`: 部屋矩形の `minX`、`minZ`、ID の昇順で一意に決定する。
- `bossRoomId`: 開始部屋以外の葉のうち開始部屋から最遠の一室とし、同距離は座標と ID で決定する。

## 3. DungeonBlockPlan

`DungeonBlockPlan` は DungeonLayout にテーマを適用した最終ブロック配置である。

- `placements`: 重複座標を解決済みの Material と、任意の階段向き・上下半分。
- `gateBlocksByConnection`: 親部屋を出た後の対象通路上で、他 connection の通路 footprint と重ならない最初の完全な表示ゲート面。通常接続は親部屋クリア時、BOSS への接続は BOSS 以外の全部屋クリア時に AIR へ置換する。
- `gateBarrierBlocksByConnection`: 各表示ゲートの通路奥側に配置し、未クリア側への通行を遮断する不可視 BARRIER 面。表示面と同様に対象 connection の footprint 内かつ他 connection の footprint 外へ配置し、対応する `gateBlocksByConnection` と同じ解放条件で AIR へ置換する。
- `roomEntrancesByRoom`: START 以外の子部屋 ID ごとに、全接続が実配置した通路 footprint のうち、歩行可能な子部屋内セルへ隣接する全部屋外セルを閉鎖面として持つ。算出時は対象部屋の incoming connection 自身の進行ゲート／バリアだけを解放後の AIR とみなし、outgoing／他 connection の閉鎖ゲートは歩行不可のまま除外する。incoming ゲート解放後は親側から子部屋へ到達可能で、閉鎖面は必ず1セル以上とする。さらに閉鎖面へ隣接する歩行可能な通路側接近セルと、子部屋 spawn から到達可能な部屋側転送着地点を持つ。閉鎖面は初期配置へ含めず、対象部屋の `ACTIVE` 中だけ GLASS にする。通路幅、子部屋直前の屈曲、別接続の重なりにより閉鎖セル数は変動する。
- `spawnPointsByRoom`: 壁と中央柱を避けた Mob 候補座標。
- `playerSpawn`: 開始部屋内の安全な転送座標。

部屋タイプは次の装飾意味を持つ。START／NORMAL／BOSS の進行役割とは独立しており、同じ seed では同じ type になる。

| type | 装飾契約 |
|:--|:--|
| `STANDARD` | 部屋タイプ固有装飾なし |
| `SUPPORT_HALL` | 外周支柱と天井梁。中央導線を塞がない |
| `COLLAPSED` | 中央の縦横導線を空けた床上瓦礫 |
| `ORE_CHAMBER` | 外周壁面の ore／accent 差し替え |

## 4. セッション状態

セッションは受付時の Dungeon、受付 World、実行時生成した DUNGEON World 定義、Mob 定義、seed、配置計画、一時 World、部屋状態、部屋別生存 Mob UUID に加え、次をメモリに保持する。

- `originalParticipants`: 受付時点の固定参加者。late join 判定と BOSS Mob 人数補正の正本。
- `participants`: 現在インスタンスへ参加中の UUID。
- `waitingAbsentParticipants`: ハブ初期スポーンで待機離脱した現在 party member。再到着まで作成待機列へ入れない。
- `gateReturnEligible`: 帰還ゲートで自主離脱し、同じ受付ゲートから再参加できる UUID。logout で失効する。
- `partyKey`, `initiatorId`: 現在パーティーからセッションを引くキーと、ソロ中止権限の正本。
- `deathCount`, `deathsByPlayer`: パーティー共有／個人の死亡回数。終了条件は `deathCount > deathLimit`。
- `returnLocations`, `entryTransfers`, `returnTransfers`, `transferGeneration`: 強制帰還先、保留転送、active／ENDING 世代を追跡する。ENDING 世代の全転送と World 破棄が完了するまで busy index を保持する。
- `dungeonDeathParticipants` と player→session ownership: 当該セッションが開始した死亡状態だけを離脱・終了時に回収する。
- `startCountdownTask`, `clearReturnTask`: 初回10秒カウントダウンとクリア後30秒回収。
- `startedAtMs`, `challengeTimeLimitTask`: カウントダウン完了後に開始する挑戦時間と、`timeLimitSeconds` が非nullの時だけ動作する終了監視。時間超過時は通常の失敗終了・帰還を行う。
- `reservedCreationSlot`, `creationQueueTicketId`: 現在 party のいずれかの `AstPlayer.user.permission >= UserPermission.DONOR(5)` に基づく寄付者予約枠要求と、作成枠キューのチケットを保持する。`ADMIN(99)` も対象。枠は一時 Dungeon world の破棄完了まで解放しない。
- 帰還 gate、中止 controller、全室の状態 TextDisplay、報酬 CHEST／TextDisplay と、それぞれの reverse index。全室の状態 TextDisplay は room ID ごとに保持し、部屋状態遷移時に表示を更新する。報酬 CHEST は player→session ownership と `rewardsByPlayer` の eligible 登録を共通 interaction gateway の候補判定に使用する。
- `rewardsByPlayer`: クリア時に固定した対象者ごとの未受取 `DungeonRewardEntry`。
- `currentRoomByParticipant`: カルトグラフの現在地表示に使う participant ごとの部屋 ID。
- `closedActiveRoomEntrances`, `pendingRoomEntryByParticipant`: 現在ガラス閉鎖中の子部屋と、通路側から部屋側への非同期転送を開始済みの participant を保持する。pending は成功・失敗の完了時とセッション終了時に回収する。
- `cartographTransfers`: participant ごとに保留中のカルトグラフ非同期転送 Future を保持する。同じ participant の多重開始を拒否し、離脱とセッション終了の転送待機対象へ含める。
- `emergencyCooldownEndsAtMs`, `emergencyTargetRoomId`: 緊急未踏査区画転送をダンジョン単位で抑止する終了時刻と、通知クリック用に固定した転送先。クールダウンは `timeLimitSeconds / rooms.size` 秒で、時間制限なしでは既定600秒を使う。

NORMAL／BOSS 部屋状態は次の順で遷移する。

```text
LOCKED -> AVAILABLE -> ACTIVE -> CLEARED
```

START 部屋だけは初期 `AVAILABLE` から、開始カウントダウン完了時に戦闘を行わず直接 `CLEARED` へ遷移する。通常子部屋は親部屋が `CLEARED` になった時点で `AVAILABLE` にする。BOSS 子部屋は接続元だけでなく START/NORMAL の全部屋が `CLEARED` になった時点で `AVAILABLE` にし、対応するゲートを解放する。参加者が `AVAILABLE` のNORMAL／BOSS部屋へ入った時点で `ACTIVE` として Mob を生成する。

各部屋の状態 TextDisplay は「`DungeonLayout.rooms` の確定順に1から割り当てるプレイヤー向け区画番号と役割」「現在状態」の2行とし、内部 room ID は表示しない。NORMAL／BOSSは `LOCKED` を未開放、`AVAILABLE` を進入可能、`ACTIVE` を攻略中、`CLEARED` を攻略済みと表示し、STARTは内部状態にかかわらず安全地帯と表示する。`ACTIVE` 部屋内からカルトグラフで別部屋へ転送することはできない。

## 5. Dungeon Sidebar表示モデル

`DungeonSidebarInfo` はダンジョン表示名、共有死亡回数／許容回数、クリア済み部屋数／全室数、参加者表示名、待機状態、Hub 未到着で灰色表示する参加者名を保持する。メンバー待機／作成待機列中は Hub 待機前でも生成し、`P_6713`／`P_6714` に対応する状態を表示する。ボス部屋クリア後は強制帰還までの残秒を追加し、攻略中は現在 Dungeon world 内にいる参加者だけを表示する。

## 6. クリア報酬モデル

`DungeonRewardEntry` は GUI 表示後も同じ当選を識別する `claimId`、`itemId`、未受取 `amount`、抽選元の `configuredRate` を保持する。報酬一覧は `configuredRate` 昇順、同率は抽選結果順とし、GUI holder はページ描画時の slot と claimId の対応を immutable に固定する。

`configuredRate` は抽選・sort とカルトグラフ archive のため内部に保持するが、実報酬 GUI の lore へは出力しない。

## 7. カルトグラフ表示モデル

- `CartographSessionRegistry.Binding`: equipment instance ID をキーに player ID と dungeon session ID を保持する一時 binding。PDC、filebase、API、DB へ保存しない。
- `MapSnapshot`: `sessionId`、`dungeonId`、表示名、immutable `DungeonLayout`、room ID ごとの `DungeonMapRoomState`、本人の現在 room ID、本人の yaw、緊急転送クールダウン残秒を GUI へ公開する。GUI は `dungeonId` と room ID を文言へ表示しない。パーティー参加者の位置は含めない。
- `DungeonMapRoomState`: `LOCKED` / `AVAILABLE` / `ACTIVE` / `CLEARED`。`LOCKED` は `?`、現在地は専用表示とする。
- `DungeonMapLayoutPlanner.Placement`: room ID ごとの page と slot。部屋中心の相対 X/Z を 5行×9列へ射影し、衝突時はマンハッタン距離、slot番号の順で最寄り空きへ決定的に退避する。45室を超えた分は次ページへ送る。接続ごとの `CorridorPlacement` は同一ページの部屋 slot を避けた最短経路として描画する。
- `AdventureDungeonRecord`: APIから取得した account単位の `dungeonId`、`clearCount`、初回／最終踏破日時。Plugin cache はクリア時に楽観更新し、archiveの一覧に使う。
- `ArchiveDungeon` / `ArchiveReward`: dungeon masterの表示名と、直接 `clearRewards.items` および起動時cache済み `LootModel.flattenedEntries` を表示用に平坦化した数量・設定確率。未解決itemは BARRIER とし、GUI描画中にAPI I/Oしない。
