# 32_3-処理契約

## 1. BSP 配置生成

1. `roomCount.min..max` から seed で目標部屋数を一つ選ぶ。
2. `area.width x area.depth` の根区画を、各子区画が最小部屋と余白を収容できる位置で再帰分割する。縦横比が大きい場合は長辺を優先し、それ以外は seed で分割方向を選ぶ。
3. 葉区画ごとに余白を確保した非重複部屋を一室生成し、`roomShapes` の相対 weight で形状、`roomTypes` の相対 weight で部屋タイプを選ぶ。
4. 分割木の左右部分木ごとに中心間距離が最小の部屋を接続する。経路探索では接続元・接続先以外の部屋と、既に確定した通路の部屋外区間を障害物として避け、物理的な交差によるゲート迂回を作らない。全室を結ぶ接続数 `部屋数 - 1` の木にならない生成結果は採用しない。
5. 開始部屋から幅優先探索し、開始部屋以外で距離が最大の葉を唯一の BOSS 部屋にする。同じマスタと seed は部屋、接続、形状、部屋タイプ、役割を含め同じ DungeonLayout を返す。

## 2. ブロック生成

- RECTANGLE は矩形外周、CYLINDER は楕円近似の境界を壁とし、床から天井までを生成する。
- 床、壁、天井、通路はそれぞれの Material リストを相対 weight でブロック単位に抽選する。
- 部屋・通路の床の直下（`baseY - 1`）へ、対応する床 Material の支持層を1段追加し、void ワールドの空洞を防ぐ。
- 経路探索済みの直交中心線を指定幅へ拡張し、床・側壁・天井を持つ折れ線通路として生成する。部屋内部は再充填せず、外周との交点だけを開口する。
- 各通路では親部屋境界を出た後から、通路幅分の表示面とその通路奥側の同面積 `BARRIER` 面が「対象 connection の footprint 内」かつ「他の全 connection の footprint 外」に収まる最初の位置を進行ゲートにする。これにより別 connection の入室経路を塞がず、未クリア部屋への通行は表示面と不可視バリアで確実に遮断する。部屋クリアによる解放時は両方を同時に除去する。
- 全接続の進行ゲート／バリアを配置し終えた後、全接続が実際に開削した通路 footprint と各子部屋の実形状を照合する。対象部屋の incoming connection 自身の進行ゲート／バリア座標だけは解放後の AIR とみなし、outgoing／他 connection の閉鎖ゲートは歩行不可のまま扱う。incoming ゲート解放後に親側から子部屋内へ到達できることを前提とし、歩行可能な子部屋内セルへ隣接する全部屋外セルを1セル以上の入口閉鎖面とする。幅3/5/7、子部屋直前の屈曲、別 connection の footprint が作る開口も漏れなく含める一方、別 connection の閉鎖ゲートを GLASS へ置換しない。閉鎖面自体は初期配置せず、閉鎖面へ隣接する歩行可能な通路側接近セルと、子部屋 spawn から到達可能な部屋側転送着地点を併せて `roomEntrancesByRoom` に保持する。
- `pillar.enabled` かつ部屋ごとの seed 抽選が `chance` 未満なら、部屋中央へ床上から天井下まで柱を置く。床側と天井側の東西南北には向きを設定した階段を置く。
- 部屋の中央を基準とした一定間隔と各通路の中心線へ、床と上方の空間を確認したうえで `lightMaterial` を配置する。当たり判定のある照明は床ブロックを置き換えて床と同じ高さへ、当たり判定のない照明は床上へ配置する。照明は親部屋側の閉鎖ゲート、ACTIVE中に閉鎖する子部屋入口、Mob 出現候補に重ねない。照明や装飾を避けた安全な Mob 出現候補を確保できない生成結果は採用しない。
- `SUPPORT_HALL` は `supportMaterial` を外周へ、`beamMaterial` を天井面へ置く。`COLLAPSED` は `rubble` を中央縦横導線と通路幅の余白から外れた空気座標だけへ置く。`ORE_CHAMBER` は外周壁だけを `accent` へ差し替える。
- 部屋タイプ装飾は seed と room ID から決定し、player spawn、Mob spawn候補、部屋中央の通路、ゲート表示面と不可視バリアを塞がない。装飾後に空気である座標だけをspawn候補とする。

## 3. 遭遇 Mob と部屋進行

- START 部屋は安全地帯とし、通常 Mob、BOSS Mobのいずれも生成しない。
- STARTからグラフ距離1のNORMAL部屋は、通常 Mob 抽選前に `level <= firstCombatRoomMaxMobLevel` の候補だけへ絞り込み、`mobsPerRoom.min..max` 体を相対 weight で抽選する。分岐により距離1のNORMAL部屋が複数ある場合は、いずれにも同じ上限を適用する。
- 距離2以降のNORMAL部屋は通常 Mob pool 全体から `mobsPerRoom.min..max` 体を相対 weight で抽選する。
- 通常 Mob は `normalMobPool[].level`、BOSS Mob は `bossMobLevel` を `MobTemplate.resolveLevel` へ渡して実効テンプレートをロードする。未指定または未登録レベルは同一 Mob の最小レベルプロファイルを使用する。
- BOSS 部屋は解決済み `bossMobId` の MobTemplate を一体生成する。
- DungeonService は生成した Dungeon Mob の `keepWhenUnobserved` を `true` に設定し、プレイヤーが視認距離外へ移動しても MobService の自動破棄対象から除外する。セッション終了時は生存 Mob UUID を明示的に破棄する。
- DungeonService は生成した Mob instance UUID を session/room に関連付ける。DamageService は死亡確定時に当該 Dungeon world 内へいる現在参加者を固定し、既存のプレイヤー別 drop 抽選・item／exp／money 付与・quest・演出をその受取人だけへ実行してから死亡 UUID を通知する。外部パーティーメンバーや後補償は対象外とする。
- 部屋の生存 UUID が空になった時だけクリアする。通常部屋ではその部屋から通常子部屋へ出るゲートと通行遮断バリアを除去して子部屋を AVAILABLE にし、表示ゲートの各ブロックに共有の破壊パーティクルを表示して `BLOCK_IRON_BREAK` を再生する。
- AVAILABLE の NORMAL／BOSS 部屋へ最初の参加者が進入して `ACTIVE` へ遷移した時点で、子部屋境界の入口閉鎖面を GLASS にして部屋内からの退出を物理的に防ぐ。CLEARED 遷移時はこの GLASS 面をすべて AIR に戻し、以後の通常移動を復元する。
- `DamageService` は Dungeon Mob が関与する通常攻撃、スキル、投射物、状態異常のダメージを、同一セッションの当該 `ACTIVE` 部屋内にいる参加者との間だけに限定する。判定はプレイヤーの現在座標を部屋形状へ照合して行い、部屋外、別セッション、非参加者とのダメージは適用しない。
- GLASS 閉鎖中の入口で、通路側接近面へ移動した同セッションの現在参加者は部屋側着地点へ yaw／pitch を保持して非同期転送し、戦闘への後続参加を許可する。入口転送は participant ごとに一件だけ保留でき、開始直前と完了時に session index、participant、同一 Dungeon world、対象部屋の ACTIVE 状態、閉鎖状態を再検証する。失敗を含む完了時は pending を解除する。
- BOSS 部屋へ入るゲートは、接続元の部屋を先にクリアしても解放しない。START/NORMAL の全室が CLEARED になった時点で配置全体から BOSS への接続を解放し、BOSS 部屋を AVAILABLE にする。開始部屋、分岐数、各分岐の攻略順にかかわらず BOSS 戦を最後の部屋戦闘とする。
- ボス部屋では生存 UUID が空になった時点でクリア報酬待機へ進む。
- 全ブロック生成後、各部屋内の安全な Mob spawn候補付近へ、区画番号・役割と現在状態を2行で示す非永続 TextDisplay を生成する。カルトグラフの所持・使用有無に依存しない。
- NORMAL／BOSSの表示は部屋状態の変更直後に未開放、進入可能、攻略中、攻略済みへ更新する。STARTは進行用にCLEAREDとなった後も安全地帯と表示し、セッション終了時に全室分を破棄する。

## 4. 開始・生成・転送

- 受付地点の TextDisplay は Dungeon master の `displayName`、`recommendedLevel` を `推奨レベル: Lv.N` 形式で表示し、その下へスニークによる挑戦開始案内を表示する。
- 受付 gate 内の SNEAK を共通 interaction gateway で解決する。新規開始は party 所属の全 member から受理し、参加者は現在の party member、未所属時は実行者一名とする。`/dungeon start <id>` も同じ受付範囲・新規開始検証を使う fallback とするが、再参加には使わない。
- 実行者が `entry.worldRef` と同一 World かつ受付半径内にいること、参加者数、通常プレイモード、他ダンジョン利用中を同期検証してから全員を予約状態にする。
- 受付後は実行者だけを Boss と同じ待機ハブへ転送し、他の party member は各自の受付 gate で移動する。実行者の転送成功後、まだ Hub へ到着していない current member へ実行者名・ダンジョン名と「あなたを待っています」を含む待機通知を一度送る。全 current member がオンライン・通常プレイモード・Hub 滞在になるまで作成枠キューへ登録せずメンバー待機とする。全員が揃った場合だけ FIFO 登録する。通常枠と寄付者予約枠は別の有限上限を持ち、寄付者判定は現在 party のいずれかの `AstPlayer.user.permission >= UserPermission.DONOR(5)`（`ADMIN(99)` も対象）で行う。待機中の Sidebar はメンバー待機／順番待機を表示し、Hub 未到着名を灰色にする。順番待機の title は空、subtitle だけへ同一枠内の順番と待機人数を表示する。
- ハブ初期スポーンの SNEAK は受付開始位置への帰還として扱う。party が列中の場合だけ確認 GUI を表示し、確定後にチケットを取り消してメンバー待機へ戻し、全員が揃い直した時点で最後尾へ登録する。solo は確認なしで離脱する。party leave／kick／logout は構成変更通知で同期し、残りが全員 Hub にいれば列位置を維持し、揃わなければメンバー待機へ戻す。待機中の current member が一人も Hub にいなくなった場合はチケットを取り消して挑戦を終了する。disband は Hub 待機者を受付開始位置へ戻して終了する。一人以上が Hub に残る間は待機タイムアウトを設けない。作成開始後は参加者を固定する。
- BSP とブロック計画は Bukkit API を呼ばない非同期処理とする。void World の作成、実行時登録、Block 変更はメインスレッドで行い、一 tick あたりの上限件数に分割する。
- 必要チャンクを先読みして Plugin chunk ticket を保持し、全ブロック生成完了後にだけ適格な参加者を START 部屋へ転送する。
- 初回転送成功後、開始地点へ帰還 gate と中止 controller、全室の状態 TextDisplay を生成して10秒カウントダウンを開始する。毎秒 title `開始まで N秒`、subtitle にダンジョン表示名、カウント音を送り、カウント中の部屋移動では Mob を生成しない。
- 10秒経過後に title `{ダンジョン名} 挑戦開始`、subtitle `ダンジョン`、開始音を送り、START部屋を戦闘なしで `CLEARED` にして次のNORMAL部屋を `AVAILABLE` とし、対応ゲートを解放する。START部屋を `ACTIVE` にせずMobも生成しない。カウント中に Dungeon world 内の現在参加者が0人なら終了するが、`party.min` は再判定しない。
- 開始カウントダウン中の現在参加者の死亡も共有死亡数へ加算し、許容回数内なら同じ稼働セッションの現在参加者であることを復帰時に再検証して START 地点へ戻す。離脱または ENDING 移行後の遅延復帰は拒否する。
- reload は検証済み定義を参照交換する。準備中・進行中セッションは受付時スナップショットを使用する。

## 5. 離脱・再参加・中止

- START 部屋の帰還 gate 内で現在参加者が SNEAK すると受付地点へ転送し、転送成功後に現在参加者から外す。ソロ、または残存現在参加者が0人ならセッションを終了する。
- 現在参加者が残る場合、帰還 gate で自主離脱した `originalParticipants` だけを `gateReturnEligible` とする。同じパーティーキー・同じ受付 gate の SNEAKで同一インスタンスの START 地点へ転送し、再カウントダウンなしで再参加させる。
- logout は現在参加者と gateReturnEligible のどちらからも外す。PartyService により実パーティーからも離脱するため、その後は個人パーティーとして新規挑戦できるが、旧インスタンスへは戻せない。
- 挑戦開始後に対象パーティーへ加入したメンバー、帰還 gate 以外で離脱したメンバー、logout で権利を失ったメンバーが受付 gate で SNEAK した場合は `現在挑戦中です。` を表示して拒否する。
- 帰還 gate 隣の中止 controller は、同一 world の3.5 block以内での DROP_ITEM を視線判定なしで claim/cancel する。現在 party leader、または solo initiator だけが確認 GUI を開け、確定時は現在参加者全員を強制帰還してセッションを終了する。中止確認 GUI の右下には緊急未踏査区画転送ボタンを表示する。
- `/dungeon leave` は既存 fallback として自主退出を行うが、gateReturnEligible は付与しない。

## 6. クリア報酬と30秒回収

- ボス部屋クリア時点で当該 Dungeon world 内にいる現在参加者だけを eligible snapshot とする。外にいる参加者、後から再参加した参加者には報酬を生成しない。AFK中の参加者は踏破記録の対象に含めるが、クリア報酬の抽選は行わず空の報酬一覧だけを保持する。
- `clearRewards` はAFK中でない eligible player ごとに独立抽選し、当選 item を設定確率の昇順（低確率順）で `DungeonRewardEntry` にする。確率は抽選と内部sortのため保持する。AFK中に報酬GUIを操作してもアイテムは付与しない。
- 実報酬 GUI は item表示、当選数量、受取案内だけを lore に追加し、`configuredRate` や設定確率を表示しない。
- ボス部屋中心付近かつ部屋 bounds 内で、床があり上2 blockを使える安全な座標を探索する。中心柱などで塞がれている場合は近傍へずらし、通常 CHEST block と `{ダンジョン名}`／`ダンジョン報酬`／`右クリックで開く` の3行 TextDisplayを生成する。
- eligible player の main hand 右クリックでは、共通 interaction gateway が player→session ownership、現在参加者、ボス部屋クリア済みかつ終了処理前、同一 World、`rewardsByPlayer.containsKey(playerId)` の eligible 登録、報酬座標の CHEST Material を確認し、共有視線 ray の AABB 命中距離と遮蔽判定を満たす報酬 CHEST を WORLD_INTERACTION 候補にする。eligible key があれば報酬一覧が空でも操作対象とする。
- 候補が勝者になった時点でバニラの CHEST 操作を cancel する。勝者実行直前にも session eligibility、同一の session／World／block 座標、CHEST Material、更新後の視線 ray と遮蔽を再検証し、session・対象・Material・視線のいずれかが失効した場合は GUI を開かず、別候補へ fallback しない。成立時だけ個人別54 slotページング GUI を開く。対象外プレイヤーや視線外の CHEST は候補にしない。
- InventoryClick／InventoryDrag は標準移動を cancel し、描画時の slot→claimId を再検証して二重 click や古い page から別報酬を取得させない。
- item click は通常インベントリへ収容できた数量だけ移し、全量収容時に claim を削除する。全く収容できない場合は報酬を残して通知する。
- item click で1個以上の収容に成功した場合は、連続受取向けの `GuiSound.ITEM_RECEIVE` を再生する。収容できなかった場合は再生しない。
- クリア待機中の死亡は共有死亡数へ加算せず、経験値 penalty なしで START 地点へ復帰させる。
- クリア確定から30秒後、報酬 GUI を無効化し、未受取報酬を破棄し、現在参加者を強制帰還してセッションを破棄する。30秒前に現在参加者が0人になった場合は早期終了できる。

## 7. 終了と回収

- 自主離脱は保留中の入場転送があれば完了を待つ。インスタンス外への転送成功を確認してから参加者を外し、失敗時は追跡を維持して再試行可能にする。
- セッション終了時は transfer generation を ENDING 世代へ進めて旧入場・復帰・カルトグラフ callback を失効させる。保留中の初回入場・復帰・ACTIVE入口入室・カルトグラフ／個別帰還転送を待ってから現在参加者を帰還させ、一時 World のアンロードとフォルダ削除が完了した後にだけ party／participant／world の busy index を解放する。ACTIVE入口の閉鎖・pending状態とカルトグラフ転送追跡も終了時に回収する。
- 参加者不在、死亡許容回数超過、中止、準備・転送・Mob／controller／CHEST／task生成失敗、クリア後30秒では、開始 countdown／clear task、残存 Mob、帰還 gate、中止 controller、全室の状態 TextDisplay、報酬 CHEST／TextDisplay、reverse index、未受取報酬を確実に破棄する。視認距離外維持指定で自動破棄を抑止した Mob も、このセッション終了処理で明示的に破棄する。部分生成で例外が起きた場合も生成済み要素を rollback する。
- 参加者離脱・logoutでは本人のカルトグラフ binding、sessionの成功・失敗・中止・全終了経路ではそのsessionの全bindingと開いている現在マップGUIを破棄する。
- player→session ownership を照合し、このセッションが開始した Dungeon 専用 death session だけを `recoverNow` で復帰 callback を実行せず即時回収する。離脱・logout 後に遅延 callback が到着しても、現在参加者と active 世代の再検証に失敗するため Dungeon へ戻さない。オンライン参加者を受付前 Location または非 DUNGEON ワールドへ退避してから一時 World をアンロードする。
- アンロード成功後だけ実行時 World 登録を解除し、インスタンスフォルダを非同期削除する。
- Plugin 停止時はスケジューラに依存せず同期回収する。次回起動時は共通インスタンスルート直下で本機能の `dungeon-` 接頭辞を持つ残存フォルダだけを削除する。

## 8. カルトグラフ

### 8.1 入力候補

- 対象は main hand にある、起動時cacheから解決済みの `EQUIPMENT`、`slot=TOOL`、共有tag `CARTOGRAPH`、equipment instance ID付きitemとする。
- main hand右クリック時、視認可能な eligible報酬CHESTがあれば既存の `WORLD_INTERACTION` 候補だけを返す。報酬CHESTがなければカルトグラフを `ITEM_USE`、claim/cancel候補として返し、勝者実行直前に同じequipment instance IDがmain handにあることを再検証する。

### 8.2 現在ダンジョンマップ

1. playerがactive dungeon session内にいて、そのカルトグラフが同じplayer／sessionへbinding済みで残耐久が1以上なら、耐久を消費せず現在mapを開く。残耐久0では開けない。
2. 未登録または別sessionのbindingなら、cache済みequipment instanceの現在耐久が75以上であることを要求する。不足時は登録も消費も行わない。
3. 成立時は既存のequipment耐久cacheを現在値から固定75減らしてdirty化し、inventory内の同instance表示を更新してからbindingする。ちょうど75は0になる。同じdungeon masterでもsession IDが違えば新規登録とする。
4. GUIは54 slotとし、上5行へ部屋中心の相対X/Zを5×9で射影する。衝突は決定的な最寄り空きへ退避し、45室超はページングする。各部屋 icon の lore に `区間 1` のような確定順の区画番号を表示し、START（最初の部屋）は現在地表示中も `EMERALD_BLOCK` とする。
5. `LOCKED` は `?`、`AVAILABLE`、`ACTIVE`、`CLEARED`、現在地を別素材・表示名で区別する。内部dungeon IDとroom IDは表示しない。room状態または現在roomが変わった時、開いている同session mapを最新snapshotで再描画する。
6. 部屋間の `DungeonLayout.connections` は、配置済み部屋 slot を避けた同一ページ内の最短経路へ射影し、閉鎖通路と解放済み通路を別素材で描画する。通路自体は操作対象にしない。
7. GUI下段には snapshot の本人 yaw を8方向へ丸めた矢印を表示する。地図を開いたまま向きを変えた場合も、yaw 変更時に本人の矢印だけを再描画する。パーティー参加中も現在地・矢印とも操作本人のものだけを表示し、他の参加者の位置や名前は表示しない。
8. `CLEARED` 部屋の slot はクリック時に session、participant、binding、現在地と部屋状態を再検証し、操作本人が `ACTIVE` 部屋内にいない場合だけ、同じ Dungeon world の安全な spawn point へ現在の yaw / pitch のまま非同期転送する。転送 Future は session と participant に関連付けて多重開始を拒否する。チャンク準備後の実転送直前にも transfer generation、session index、participant ownership、オンライン、同じ Dungeon world、同じ装備個体 binding、現在地が `ACTIVE` 部屋外であること、移動先が `CLEARED` のままであることをメインスレッドで再検証する。操作本人が `ACTIVE` 部屋内にいる場合、セッションが ENDING へ移行した場合、および移動先が `LOCKED`／`AVAILABLE`／`ACTIVE` の場合は実転送しない。
9. 中止確認 GUI の右下には `ENDER_PEARL` の緊急未踏査区画転送ボタンを表示する。注意書きとして緊急以外は押さず、管理者が監視する場合があることを表示する。`AVAILABLE`／`ACTIVE` の未踏査区画が一つなら操作本人を直ちに安全地点へ転送し、複数なら45区画ごとのページングを持つ区間選択 GUI を表示する。転送先選択時、他のオンライン参加者には操作プレイヤー名を含むクリック可能な通知を送り、同じ部屋への任意転送を許可する。操作・通知クリックの双方で session、参加者、部屋状態を再検証する。
10. 緊急転送は成功後、ダンジョン単位でクールダウンする。秒数は `challenge.timeLimitSeconds / layout.rooms.size` とし、時間制限なしでは既定600秒を用いる。緊急転送実行はログに記録する。
11. mapのInventoryClick／InventoryDragは標準移動をcancelする。

bindingはメモリのみで、item PDC・API・DBへ保存しない。参加者離脱、session終了／失敗／中止、logout、Plugin停止で削除する。最大耐久と通常の修理可否はequipment instanceの既存機構へ従い、修理オーブはslot非依存のdamage済みrepairable equipmentとして扱う。

### 8.3 ダンジョン外archive

- active dungeon session外で右クリックした場合、accountの踏破記録をメインスレッド外で `GET /api/adventure-record/dungeon` からlazy loadし、最新踏破順で一覧表示する。cache済みなら再利用できる。
- 一覧には一度以上踏破した、現在ロード済みdungeon masterで表示名を解決できる記録だけを出す。内部dungeon IDをプレイヤーへ表示しない。
- 詳細は `clearRewards.items` と、参照先が起動時cache済みの場合の `LootModel.flattenedEntries` を平坦化し、item表示名、設定数量、設定確率を示す。itemは `ItemService.findLoadedById` だけで解決し、未解決時はBARRIERにする。GUI click中を含むメインスレッドからitem／loot／Adventure Record APIを呼ばない。
- archive一覧／詳細のInventoryClick／InventoryDragは標準移動をcancelし、ページ・戻る操作だけを受け付ける。

### 8.4 踏破永続化

- ボス部屋クリア確定時のeligible playerごとに、Plugin cacheの `clearCount` と最終踏破時刻を楽観更新し、`POST /api/adventure-record/dungeon/clear` を非同期実行する。
- API／DBの失敗はログへ記録するが、部屋クリア、報酬抽選、30秒待機、session cleanupを失敗させない。次回archive GETでDB正本と再同期できる。

## 9. ワールド保護

DUNGEON ワールドではプレイヤーのブロック破壊・設置を常にキャンセルする。実行時 World 定義は自然 Mob スポーンを禁止し、AstralRecord の MobService による CUSTOM spawn だけを許可する。
