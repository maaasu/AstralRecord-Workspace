# 13_0.00-概要

## 1. 位置づけ

`skill` 機能は、filebase 由来のスキル定義を API 経由で取得し、Plugin 内の実行ロジックへバインドして使用する機能である。
スキルの見た目・消費リソース・共通挙動はマスタデータで定義し、個別ロジックは `implementationId` に対応する Plugin 実装へ委譲する。

## 2. 設計方針

- スキル定義の正本は `40_filebase/30.features.skill/` とする。
- API は `skill` 定義を読み取り専用で返し、Plugin は `/api/skill` から取得したレスポンスを実行用モデルへ変換する。
- `implementationId` は Plugin 側実装クラスの解決キーとする。新規のコード定義発動スキルは `id = implementationId` とし、1 スキル 1 executor を既定とする。
- `params` は共有 executor をデータ駆動にする場合の自由形式パラメータとし、新規のコード定義発動スキルでは省略を既定とする。
- API/Plugin 共通で `params` の詳細型までは固定しない。共通スキーマで保証するのは「Map であること」までとする。
- リソース種別と消費量は top-level `resourceType` / `resourceCost` を正本とし、旧 `params` / `manaCost` は互換入力としてのみ扱う。

## 3. コンテキスト

- スキル発動主体はプレイヤーまたは Mob とする。
- `resourceType` / `resourceCost` / `cooldownTicks` / `castTimeTicks` / `requiredLevel` は Plugin 側で共通制御する。
- `onCast.sound` は共通演出として Plugin 側サービスが処理する。
- 個別演出・当たり判定・倍率計算は `implementationId` に紐づく実行クラスで処理する。
- プレイヤー発動スキルは `feature/skill/active` の対象選択、custom combat、particle、projectile、移動、task、一時効果サービスを再利用する。

## 4. 想定実装

- `service/SkillService`
  - スキル一覧同期、発動前検証、実行クラス委譲を担う。
- `repository/SkillRepository`
  - AstralRecord API `/api/skill` との HTTP 通信を担う。
- `registry/SkillRegistry`
  - `implementationId` と実行クラスの対応表を保持する。
- `model/SkillDefinition`, `model/SkillCastContext`
  - API レスポンスと実行時情報を Plugin 用モデルへ正規化する。
- `executor/SkillExecutor`
  - 個別スキルロジックの共通インターフェースとする。
- `executor/active/*`
  - 1 スキル 1 executor と職業別 catalog を配置する。
- `active/service/*`
  - 当たり判定・戦闘適用・演出・移動・時間処理を個別 executor から分離する。
