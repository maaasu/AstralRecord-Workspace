# 13_2-ユースケース

## 1. 起動時にスキル定義を同期する

- Plugin 起動時に API からスキル定義を全件取得する。
- `implementationId` ごとに実行クラスの登録有無を検査する。
- 取得成功分のみレジストリへ反映し、失敗内容はログへ残す。

## 2. プレイヤーがスキルを発動する

- プレイヤー入力からプリセットに保存された習得個体 UUID を解決する。
- 個体の所持と「現在クラスの `usableSkills` または現在有効なスキルツリーノード」の使用許可を別々に検証する。
- 習得レベル差分と有効シジルを合成し、個体専用の定義を作る。
- `requiredLevel` / MP / cooldown / cast time を共通検証する。
- 詠唱時間がある場合は、ActionBar にスキル名、残り秒数、ライム色の完了部分と灰色の未完了部分からなる太い進捗バーを表示する。完了部分は難読化装飾で周期的に揺らし、0.5 秒ごとに進捗に応じて音程が上がる詠唱音を本人へ再生する。
- `implementationId` に対応する実行クラスへ処理を委譲する。

## 3. ジェムでスキル個体を習得する

- インベントリのスキルジェムを左クリックし、消費確認後にLv.1の新規個体を習得する。
- 同じskill IDを所持済みでも、上書きやレベルアップはせず別UUIDの個体を作る。
- スキルマネージャーは合成画面を開かず、習得済み個体のバインドだけを扱う。
- シジル装着オーブは習得済みスキル一覧から対象個体と対応シジルを選び、空き枠へ1個消費装着する。
- シジル脱着オーブは習得済みスキル一覧から対象個体と装着行を選び、シジルを所持品へ1個返却する。

## 4. スキルマネージャーで設定する

- 6プリセットそれぞれにaction 6枠、left-click 1枠、passive 9枠を設定する。
- 使用不可個体もバインドできるが、許可が戻るまで機能しない。
- 忘却した個体UUIDの既存バインドは保持し、「未習得スキル」と表示して発動を拒否する。バインドを解除した時点で設定から消える。
- パッシブ有効枠は基本5、statusで最大9まで増加する。超過バインドは保持する。

## 5. Mob がスキルを発動する

- Mob AI が `ai.combat.skills` からスキル ID を順番に選択する。
- Mob は `MobSkillCaster` として共通制御層へ渡され、レベル / MP / EN の制約は原則スキップする。
- 個別ロジックはプレイヤー発動と同じ `SkillExecutor` を再利用する。`normal_attack` はプレイヤー起点なら Mob、Mob 起点ならプレイヤーを攻撃対象にする。
- `normal_attack` のprojectileは `impactRadius > 0` の場合だけ着弾地点から追加対象を距離順に選び、最初の命中対象を含めて `maxTargets` 体まで同じdamage・conditionを適用する。
- `castTimeTicks > 0` の場合、Mob の頭上 TextDisplay に詠唱バーを表示し、詠唱完了後に executor へ委譲する。

## 6. 同一ロジックを複数定義で使い分ける

- `fireball_a` / `fireball_b` のように同一 `implementationId` を共有する。
- 差分は `params` で与え、色・威力・速度・範囲などを切り替える。
