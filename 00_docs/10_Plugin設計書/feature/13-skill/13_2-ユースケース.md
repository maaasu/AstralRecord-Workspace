# 13_2-ユースケース

## 1. 起動時にスキル定義を同期する

- Plugin 起動時に API からスキル定義を全件取得する。
- `implementationId` ごとに実行クラスの登録有無を検査する。
- 取得成功分のみレジストリへ反映し、失敗内容はログへ残す。

## 2. プレイヤーがスキルを発動する

- プレイヤー入力またはクラス習得情報から対象スキル ID を解決する。
- `requiredLevel` / MP / cooldown / cast time を共通検証する。
- 詠唱時間がある場合は、ActionBar にスキル名、残り秒数、ライム色の完了部分と灰色の未完了部分からなる太い進捗バーを表示する。完了部分は難読化装飾で周期的に揺らし、0.5 秒ごとに進捗に応じて音程が上がる詠唱音を本人へ再生する。
- `implementationId` に対応する実行クラスへ処理を委譲する。

## 3. Mob がスキルを発動する

- Mob AI が `ai.combat.skills` からスキル ID を順番に選択する。
- Mob は `MobSkillCaster` として共通制御層へ渡され、レベル / MP / EN の制約は原則スキップする。
- 個別ロジックはプレイヤー発動と同じ `SkillExecutor` を再利用する。`normal_attack` はプレイヤー起点なら Mob、Mob 起点ならプレイヤーを攻撃対象にする。
- `castTimeTicks > 0` の場合、Mob の頭上 TextDisplay に詠唱バーを表示し、詠唱完了後に executor へ委譲する。

## 4. 同一ロジックを複数定義で使い分ける

- `fireball_a` / `fireball_b` のように同一 `implementationId` を共有する。
- 差分は `params` で与え、色・威力・速度・範囲などを切り替える。
