# 13_0-概要

## 1. 位置づけ

`skill` 機能は、filebase 由来のスキル定義を API 経由で取得し、Plugin 内の実行ロジックへバインドして使用する機能である。
スキルの見た目・消費リソース・共通挙動はマスタデータで定義し、個別ロジックは `implementationId` に対応する Plugin 実装へ委譲する。

## 2. 設計方針

- スキル定義の正本は `40_filebase/30.features.skill/` とする。
- API は `skill` 定義を読み取り専用で返すほか、習得済みスキル個体・装着シジル・共有プリセットを永続化する。
- 所持と使用許可を分離する。所持はジェムから作るUUID付き個体、使用許可は現在クラスまたは有効なスキルツリーノードから得る。
- API は各skill masterから `00_skill_gem_<skillId>` の仮想アイテムを生成する。ジェムはレベルを持たず、新規習得または選択個体のレベルアップで消費する。
- 装備・ルーン・セット効果からのスキル付与は行わない。通常攻撃は武器の `SWORD` / `HAMMER` / `SPEAR` / `BOW` / `SHORTBOW` / `LONGBOW` / `WAND` / `STAFF` タグから自動解決する。
- `implementationId` は Plugin 側実装クラスの解決キーとする。新規のコード定義発動スキルは `id = implementationId` とし、1 スキル 1 executor を既定とする。
- `params` は共有 executor をデータ駆動にする場合の自由形式パラメータとし、新規のコード定義発動スキルでは省略を既定とする。
- API/Plugin 共通で `params` の詳細型までは固定しない。共通スキーマで保証するのは「Map であること」までとする。
- リソース種別と消費量は top-level `resourceType` / `resourceCost` を正本とする。旧 `params` は互換入力、`manaCost` は通常は旧MP定義との互換入力とし、`resourceType: ENERGY` と正の `manaCost` を併記した場合だけ副MP消費として扱う。

## 3. コンテキスト

- スキル発動主体はプレイヤーまたは Mob とする。
- `resourceType` / `resourceCost` / `manaCost` による複合消費 / `cooldownTicks` / `castTimeTicks` / `requiredLevel` は Plugin 側で共通制御する。
- `onCast.sound` は共通演出として Plugin 側サービスが処理する。
- 個別演出・当たり判定・倍率計算は `implementationId` に紐づく実行クラスで処理する。
- プレイヤー発動スキルは `feature/skill/active` の対象選択、custom combat、particle、projectile、移動、task、一時効果サービスを再利用する。
- ドッジ連動パッシブは、成功したドッジ通知を起点に短命な runtime 状態を作り、custom combat の直接攻撃経路へだけ効果を適用する。

## 4. 想定実装

- `service/SkillService`
  - スキル一覧同期、習得個体の解決、所持・許可検証、実行クラス委譲を担う。
- `service/LearnedSkillService`, `service/SkillPermissionService`, `service/LearnedSkillResolver`
  - 習得個体のAPI同期、クラス／ツリー許可の和集合、レベル／シジル合成を担う。
- `repository/SkillRepository`
  - AstralRecord API `/api/skill` との HTTP 通信を担う。
- `registry/SkillRegistry`
  - `implementationId` と実行クラスの対応表を保持する。
- `model/SkillDefinition`, `model/SkillCastContext`
  - API レスポンスと実行時情報を Plugin 用モデルへ正規化する。
- `executor/SkillExecutor`
  - 個別スキルロジックの共通インターフェースとする。
- `executor/active/*`
  - 1 スキル 1 executor と職業別 catalog を配置する。
- `active/service/*`
  - 当たり判定・戦闘適用・演出・移動・時間処理を個別 executor から分離する。

## 6. 依存・連携

- `player` / `account` / `status`: player caster、session lifecycle、MP / EN、status modifier を扱う。
- `mob`: `MobSkillCaster`、AI の skill 選択、頭上 cast bar を扱う。
- `combat`: active skill の damage、condition、threat、knockback を共通経路へ委譲する。
- `inventory` / `menu` / `player-interaction`: スキルマネージャー、ジェム左クリック、action ring入力調停を扱う。
- `class`: `usableSkills` を現在クラスの使用許可へ供給する。
- `skilltree`: 現在有効な解放済みノードを追加の使用許可へ供給する。
- AstralRecordApi `/api/skill`、`/api/account-skills`、`/api/skill-bind-presets`: 定義、習得個体、プリセットの正本。
- `40_filebase/30.features.skill/*` / `40_filebase/35.features.skilltree/*`: API が配信する定義とtree構造の正本。
