# 13_1.00-モデル定義

## 1. スキル定義モデル

物理名: `SkillDefinition`

API `SkillResponse` を Plugin 側で利用しやすい形へ正規化した実行用モデル。

| 項目 | 説明 |
|---|---|
| `id` | スキル ID |
| `implementationId` | 実行クラスの解決キー |
| `name` | 表示名 |
| `description` | 説明文 |
| `icon` | 表示アイコン |
| `lore` | 説明行配列 |
| `cooldownTicks` | 共通クールダウン |
| `manaCost` | 旧定義との互換用 MP 消費量。新規定義は `resourceCost` を使用する |
| `resourceType` | 共通消費リソース種別。`MANA` / `ENERGY` |
| `resourceCost` | 共通消費量 |
| `castTimeTicks` | 共通詠唱時間 |
| `requiredLevel` | 共通要求レベル |
| `onCastSound` | 共通発動サウンド。未指定時は `null` |
| `params` | `Map<String, Object>`。個別ロジックが解釈する自由形式パラメータ |
| `tags` | 検索・分類用タグ |

`resourceType` / `resourceCost` は top-level 項目を優先する。未指定の場合だけ、旧定義との互換のため
`params.resourceType` / `params.resourceCost`、さらに消費量は `manaCost` の順で補完する。
補完後の値は定義ロード時に top-level 項目へ正規化し、executor が共通消費設定を `params` から読むことは禁止する。

## 2. スキル一覧項目モデル

物理名: `SkillSummary`

一覧 UI や参照解決で最低限使用する軽量モデル。

| 項目 | 説明 |
|---|---|
| `id` | スキル ID |
| `name` | 表示名 |
| `implementationId` | 実行クラス解決キー |
| `icon` | 一覧表示用アイコン |
| `tags` | 分類タグ |

## 3. スキル実行コンテキスト

物理名: `SkillCastContext`

個別スキルロジックへ引き渡す発動時コンテキスト。

| 項目 | 説明 |
|---|---|
| `skill` | [[13_1.00-モデル定義]].スキル定義モデル |
| `caster` | [[13_1.00-モデル定義]].スキル発動者 |
| `primaryTarget` | 主対象。単体対象スキルで使用 |
| `targets` | 範囲・複数対象の解決結果 |
| `castLocation` | 発動位置 |
| `statusSnapshot` | 発動者のステータススナップショット |
| `trigger` | 発動理由。コマンド / 通常攻撃派生 / AI など |
| `now` | 判定基準時刻 |

## 4. スキル発動者

物理名: `SkillCaster`

プレイヤー / Mob いずれの発動経路でも共通制御層が同一契約で参照できるよう、発動主体をラップする共通インターフェース。`SkillExecutor` 側で `instanceof` 分岐を持たない前提とする。現実装は `PlayerSkillCaster` のみで、Mob 用実装は [[13_9.00-未決事項]] に従い未提供。

| 項目 | 説明 |
|---|---|
| `casterId()` | 発動者を一意に識別する UUID。クールダウン管理キーにも使用する |
| `level()` | `requiredLevel` 比較に用いる発動者レベル。レベル概念を持たない発動者は `null` を返し、共通制御層が既定値を適用して検証する |
| `currentMana()` | `resourceType = MANA` の比較に用いる現在 MP |
| `currentEnergy()` | `resourceType = ENERGY` の比較に用いる現在 EN |
| `consumeMana(amount)` | 共通制御からの MP 消費反映。上下限のクランプは実装側の責務 |
| `consumeEnergy(amount)` | 共通制御からの EN 消費反映。上下限のクランプは実装側の責務 |
| `statusSnapshot()` | ステータススナップショット取得経路 |
| `notify(messageId, args...)` | 発動者向け通知メッセージの送信。通知概念を持たない発動者（Mob 等）は no-op で構わない |

クールダウン状態は発動者ごとに `SkillService` 側で集中保持する（[[13_3.02-サービス]].クールダウン管理 を参照）。発動位置は `castSkill` の引数 `castLocation` として共通制御層へ渡すため、本契約では `location()` を持たない。

## 5. スキル実行インターフェース

物理名: `SkillExecutor`

`implementationId` に紐づく個別ロジックの共通契約。

| 項目 | 説明 |
|---|---|
| `implementationId()` | 担当する `implementationId` を返す |
| `cast(context)` | `params` を解釈して個別ロジックを実行し、効果適用の成功／失敗だけを `SkillCastResult` で返す。リソース消費量とクールダウンは定義を正本として `SkillService` が適用する |
| `onActivate(context)` | パッシブスキルの有効化直後に呼び出される。不要な実装は no-op とする |
| `onDeactivate(context)` | パッシブスキルの無効化直前に呼び出される。不要な実装は no-op とする |
| `requiresPassiveTick()` | パッシブスキルが定期 tick 呼び出しを必要とするかを返す。ステータス補正のみの実装は `false` |
| `passiveTickIntervalTicks()` | 定期 tick 呼び出しが必要な場合の呼び出し間隔を返す。`requiresPassiveTick()` が `false` の場合は使用しない |
| `onTick(context)` | `requiresPassiveTick()` が `true` のパッシブスキルだけ、指定間隔で呼び出される |
| `passiveStatusModifiers(context)` | パッシブスキルが付与するステータス補正を返す |
| `validateParams(skill)` | 任意。起動時または reload 時に `params` 妥当性を検証する |

パッシブスキルの有効状態は `PassiveSkillService` が管理し、呼び出しが必要な契機は executor 側の契約で宣言する。ステータス補正のみのパッシブは毎 tick 呼び出さず、ステータス再計算時だけ `passiveStatusModifiers(context)` を参照する。

## 6. スキルレジストリ

物理名: `SkillRegistry`

`implementationId` と `SkillExecutor` の対応、`skillId` と定義の対応を管理する。

| 項目 | 説明 |
|---|---|
| `executors` | `Map<String, SkillExecutor>` |
| `definitionsById` | `Map<String, SkillDefinition>` |

## 7. スキル実行結果

物理名: `SkillCastResult`

共通制御と個別ロジックの境界で返す結果。

| 項目 | 説明 |
|---|---|
| `success` | 発動成功フラグ |
| `messageId` | プレイヤー向け通知 ID。不要なら `null` |

## 8. `params` 読み取り規約

物理名: `SkillParamReader`

`params` は自由形式だが、各実装で生の Map を散在させないため、型変換補助を介して参照する。

| 項目 | 説明 |
|---|---|
| `requireString(key)` | 必須文字列取得。未定義時は例外 |
| `getDouble(key, defaultValue)` | 数値取得 |
| `getBoolean(key, defaultValue)` | 真偽値取得 |
| `getRefId(key, prefix)` | `skill:` / `buff:` 等の参照値取得 |

## 9. 識別子規約

- `skillId` は API / filebase / Plugin 全層で同一文字列を保持し、case-sensitive で照合する。
- Plugin 内部の比較・キャッシュキー化でも `trim()` や `toLowerCase(Locale.ROOT)` による正規化は行わず、受け取った値をそのまま使用する。
- 空白混入や全角混入を含む不正な `skillId` は API 側で受理しない前提とする。
