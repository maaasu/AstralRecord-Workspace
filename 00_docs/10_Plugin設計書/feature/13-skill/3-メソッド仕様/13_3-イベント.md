# 13_3-イベント

## 1. スキルマネージャー表示・操作

クラス名: `SkillBindGuiEventHandler`

`open` は習得個体と6プリセットのロード完了を確認してセッションを作る。未完了なら画面を開かず `false` と `GuiSound.DENY` を返し、完了してメイン画面を開いた場合だけ `true` を返す。メイン画面では一覧、passive 9枠、left-click、action 6枠、slot 0 の通常攻撃、プリセット、前後ページ、slot 49 の戻る／直開きcloseを処理する。

GUI 操作では、ページ移動に `GuiSound.PAGE`、通常攻撃設定・戻るに `GuiSound.SELECT`、シジル操作成功に `GuiSound.UPGRADE`、確認画面の表示と確定に `GuiSound.CONFIRM` を再生する。拒否操作は `GuiSound.DENY` を再生する。`GuiSessionTransitionService` が session token を次 tick に照合し、成功した画面遷移では source の `CLOSE` と feature 固有 cleanup を実行しない。未保存変更のある MAIN 画面を手動 close した場合も、`InventoryCloseEvent` 内で破棄確認画面への shared continuation を登録するため、確認画面表示まで `CLOSE`、navigation 履歴消去、SkillBind cleanup を実行しない。確認の cancel は MAIN へ戻り、確認画面の最終 close だけが `GuiSessionEndEvent` を一度発火して session とシジル操作の選択状態を後片付けする。Hotbar Shortcut GUI の `CLOSE` は共有基盤が再生し、SkillForget GUI も終了理由が無音の logout では `CLOSE` を再生しない。

未習得スキルの一覧左クリックは、詳細画面を開かず `learnRequiredItems` を消費して習得する。習得済みスキルは最大レベルならクリックでバインドし、最大レベル未満なら27 slotの詳細画面を開く。詳細画面では「このスキルをバインド」と「レベルアップ」を個別に操作でき、一覧で選択済みだったバインド枠をセッションに保持してその枠へ設定する。詳細画面の戻る操作は遷移前の一覧ページへ戻る。最大レベル未満のレベルアップを受け付けた後は処理中表示にして二重操作を拒否し、成功時は更新後の詳細画面を保持する。最大レベル到達時は更新後個体を表示するスキルマネージャーへ戻る。選択済みで有効な種別適合バインド枠があればその枠へ、未選択なら種別に合う最初の空き枠へ対象個体UUIDを設定し、即時保存する。activeはaction ringの空き枠を優先して空のleft-click枠を最後に使い、passiveは現在有効なpassive枠だけを対象にする。空き枠がない場合は `P_5865` を表示する。シジル装着・脱着はシジル用オーブから専用GUIを開いて行う。許可のない所持個体も設定できるが、発動時には未所持 (`P_5809`) と使用許可なし (`P_5863`) を分けて拒否する。パッシブ枠は一覧クリック直前と保存直前にも現在の有効枠数を再検証し、超過枠では既存バインドの維持・解除だけを許可する。

シジル用オーブから開いた専用GUIでは、対象習得済み個体を選び、装着時はプレイヤーインベントリのシジルitem IDを、脱着時は装着行UUIDを選択してAPI mutationを開始する。結果クリック直前に起点オーブと装着用シジルitem IDを通常アイテム共通消費順でentryへ解決し、解決したentry IDまたは装着行をAPIへ送り、APIが必要なオーブ・シジルを同一mutationで検証・消費（脱着はシジルを返却）するため、先行同期の失敗だけでmutationを中断せず、終了後に対象entryをAPI正本へ再同期する。成功後は習得個体・インベントリ・パッシブ状態を更新し、通常収納と同じ前詰め規則で後続entryを移動する。ログアウト時は選択時に保持したaccountIdで操作を無効化し、先行するキャッシュ削除の有無にかかわらず再接続後へ持ち越さない。非許可シジル、空き枠なし、同一 `equipGroupId` はそれぞれ固有の player message を表示し、選択・消費・mutationを行わず結果枠にも理由を表示する。それ以外のシジル操作失敗は `P_5864` を表示する。

API成功応答が `inventorySnapshot` を含む場合は、消費・返却entryをそのsnapshotで反映する。snapshotがない旧API応答だけは個別entry取得で再同期する。

dragは常にcancelし、保存中の二重操作を拒否する。非同期callbackはplayer online、session、account generationを再確認する。

active スキルを action ring へ設定した場合は、プリセット保存成功後に設定したスキル定義 ID を `SKILL_BOUND` としてガイドへ通知する。left-click 枠や passive 枠への設定、保存失敗、保存中断では通知しない。

## 2. スキルマネージャーの習得・レベルアップ

クラス名: `LearnedSkillService`、`SkillBindGuiEventHandler`

現在使用許可を持つ未習得スキルは「未習得」として表示し、左クリックで詳細画面を開かず習得する。習得済みスキルは使用許可がなくても灰色アイコンで表示し、最大レベル未満では一覧クリックで詳細画面へ遷移する。最大レベルの習得済みスキルは詳細画面を開かず、一覧クリックでバインドする。既存データに同じ skill ID の個体が複数ある場合は、API ロード順の先頭個体だけをレベルアップ対象とする。

クリック時に `LearnedSkillService` が `learnFromManagerAsync` または `levelUpFromManagerAsync` を実行する。詳細画面のレベルアップ成功後は、更新後のレベルが最大未満なら詳細画面を再表示し、最大到達ならスキルマネージャーを再表示する。いずれの復帰でも更新後の習得個体を再取得してGUIを生成し、旧レベルを表示しない。必要素材は skill master の `learnRequiredItems` / `levelUpRequiredItems` を正本とし、未指定なら無条件で実行する。API は account の有効な GAME inventory の BAG・HOTBAR にある通常アイテムだけを対象に、共通消費順（BAG→HOTBAR、slot降順、slot未指定は後）で必要数量を原子的に検証・消費する。STORAGE と instance item は消費対象外とする。Plugin は有効な GAME プロファイルの BAG・HOTBAR・STORAGE にある一致 entry UUID 全件をローカルの正本再同期候補として保持し、API requestには送信しない。STORAGE は再同期候補にだけ含める。APIは成功応答で更新後個体と実消費entry・数量を返す。Pluginは候補entry全件と応答の実消費entryを正本再同期し、個別再同期が失敗した場合だけ実消費entryへ応答数量をローカル反映する。STORAGE候補など応答にないentryは推測消費しない。同期済みstateから表示中のインベントリとHOTBARを再描画して、消費後の個数を同じ成功処理でクライアントへ反映する。新規習得は `SKILL_LEARNED`、レベルアップは `SKILL_ENHANCED` として、現在のplayer sessionで成功callbackが有効な場合だけ通知なしでガイドへ記録する。

API が業務エラーを返した場合は state を変更しない。通信結果が不明な場合も、候補 entry 全件と習得個体一覧を API 正本から再同期して、消費済みの可能性を回復する。正本取得に失敗した場合は mutation lock を解放し、次回操作とログアウト保存を再試行可能にする。スキル忘却も同じ `operationId` 付き非同期 mutation とし、応答が遅い場合は `P_5874` を一度だけ表示して GUI を閉じる。結果確定後に対象個体をキャッシュから除去し、代償付き忘却で先に消費した通貨は失敗時に返却する。

最大レベルでは習得・レベルアップ API を呼ばない。

## 3. action ring入力解決

クラス名: `SkillActionRingEventHandler`、`SkillActionRingHoldService`、`SkillActionRingService`

プリセットのバインド値を `learnedSkillId` として解決し、該当個体のレベル・シジル・使用許可・共有cooldownを表示と発動の両方へ使う。発動候補の取得時と実行直前に main-hand weapon の装備条件（プレイヤーレベル・クラス・クラスレベル）と耐久値を再確認し、条件不足の武器では発動しない。バインドが残っていても許可を失った個体は発動せず、`P_5863` でスキル名を通知する。

`ACTION_RING_HOLD_SELECT=false` は従来操作であり、右クリックでリングを開き、左クリックで選択、次の左クリックで発動する。`true` は選択中 hotbar slot の主武器だけを事前にクライアントへ仮想 `TRIDENT` として送り、空中右クリックで長押しを開始する。`RELEASE_USE_ITEM` を受けた時点で現在のリング選択を確定し、解除時に選択項目がなければ選択確定を行わずリングを閉じる。確定後は従来どおり次の左クリックで発動する。サーバー側の主武器は常に `PAPER` のまま保持し、解除時には開始時と同じ hotbar slot、item ID、equipment instance ID、および武器 PDC をメインスレッドで再確認する。

長押し中は hotbar 変更、offhand swap、drop、inventory open、world change、death、quit、リングの明示closeで待機を破棄する。解除パケットは有効な待機 session にだけ cancel して選択確定へ振り替える。長押し開始中は右・左クリックと hotbar 入力を action ring の guard が占有する。

## 4. active skill lifecycle

world changeは詠唱・移動task・temporary effect・当該プレイヤーが発生させた一時挑発を破棄しcooldownを維持する。death / quitはcooldownを含む全一時skill stateと当該プレイヤーの一時挑発を破棄する。

## 5. メディテーション中断

クラス名: `MeditationSkillEventHandler`、`MeditationSkillRuntimeService`

- バインド済みパッシブの tick 中、プレイヤーがスニークしていない場合は準備・発動状態を破棄する。
- `EntityDamageEvent` と custom `DamageService` のプレイヤー実ダメージ通知、`PrePlayerAttackEntityEvent`、`SkillService` の検証済みskill-use通知を受けた場合は即時破棄する。
- runtime の短命状態は Bukkit Player UUID をキーにする。`PlayerToggleSneakEvent` の解除、`PlayerDeathEvent`、`PlayerQuitEvent`、`PlayerChangedWorldEvent`、クラス変更後のパッシブ再調停でも状態が残らないようにする。
- 3秒は60 tickとして管理し、開始後7秒に当たる140 tickの間、発動中のスニーク継続だけを条件に自然回復倍率を有効化する。開始時の倍率は2.0、以降20 tickごとに0.5ずつ加算し、最後は5.0とする。効果開始時に `buff:adventurer_meditation` を付与し、移動速度+120%を7秒適用する。中断時はこのバフを強制解除し、完了時はMP / ENGだけを最大値へ戻して全効果を終了する。HP自然回復とShield回復は倍率・全回復の対象外とする。発動時に円形 particle と控えめな音を一度だけ出し、維持中は低密度の周回 particle と環境音を間隔表示する。全回復時には `TOTEM_OF_UNDYING` / `END_ROD` の完了パーティクルを一度ずつ表示し、`ENTITY_PLAYER_LEVELUP` を一度再生する。環境音は `activeSoundIntervalTicks`（現行値40 tick）に従って再生し、`World#playSound` と `SoundCategory.PLAYERS` により音源位置の周囲にいるプレイヤーにも聞こえる。自然回復倍率の効果対象は自身のみとする。

## 6. 例外処理

GUI click / drag / close の例外は `E_5601`、action ringとactive lifecycleは `E_3002` へ操作context付きで記録し、Bukkit event loopへ再送出しない。
