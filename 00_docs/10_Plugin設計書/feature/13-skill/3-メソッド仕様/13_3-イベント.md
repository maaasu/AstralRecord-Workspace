# 13_3-イベント

## 1. スキルマネージャー表示・操作

クラス名: `SkillBindGuiEventHandler`

`open` は習得個体と6プリセットのロード完了を確認してセッションを作る。未完了なら画面を開かず `false` と `GuiSound.DENY` を返し、完了してメイン画面を開いた場合だけ `true` を返す。メイン画面では一覧、passive 9枠、left-click、action 6枠、slot 0 の通常攻撃、プリセット、前後ページ、slot 49 の戻る／直開きcloseを処理する。

GUI 操作では、ページ移動に `GuiSound.PAGE`、通常攻撃設定・戻るに `GuiSound.SELECT`、確認画面の表示と確定に `GuiSound.CONFIRM` を再生する。拒否操作は `GuiSound.DENY` を再生する。`GuiSessionTransitionService` が session token を次 tick に照合し、成功した画面遷移では source の `CLOSE` と feature 固有 cleanup を実行しない。未保存変更のある MAIN 画面を手動 close した場合も、`InventoryCloseEvent` 内で破棄確認画面への shared continuation を登録するため、確認画面表示まで `CLOSE`、navigation 履歴消去、SkillBind cleanup を実行しない。確認の cancel は MAIN へ戻り、確認画面の最終 close だけが `GuiSessionEndEvent` を一度発火して session とプレイヤー inventory を後片付けする。Hotbar Shortcut GUI の `CLOSE` は共有基盤が再生し、SkillForget GUI も終了理由が無音の logout では `CLOSE` を再生しない。

一覧の左クリックは、選択済みで有効な種別適合バインド枠があればその枠へ、未選択なら種別に合う最初の空き枠へ対象個体UUIDを設定し、即時保存する。activeはaction ringの空き枠を優先して空のleft-click枠を最後に使い、passiveは現在有効なpassive枠だけを対象にする。空き枠がない場合は `P_5865` を表示する。右クリックは合成画面を開かず拒否する。許可のない所持個体も設定できるが、発動時には未所持 (`P_5809`) と使用許可なし (`P_5863`) を分けて拒否する。パッシブ枠は一覧クリック直前と保存直前にも現在の有効枠数を再検証し、超過枠では既存バインドの維持・解除だけを許可する。

dragは常にcancelし、保存中の二重操作を拒否する。非同期callbackはplayer online、session、account generationを再確認する。

## 1.1 シジルオーブ操作

クラス名: `SkillSigilOrbService`

`OrbService` は `SIGIL_ATTACH` / `SIGIL_DETACH` を装備候補収集へ渡さず、シジルオーブ専用セッションへ委譲する。専用GUIは起点オーブentry UUID、習得済み個体UUID、選択したシジルentry UUIDまたは装着行UUIDを保持し、確定直前に同じ起点entryの所有・数量・item ID・effect type、対象個体、空き枠、許可ID、group重複を再検証する。装着成功時は素材entry、脱着成功時はAPIが返したentryを正本へ同期し、習得個体cache更新後に有効パッシブを再調停する。オーブ自体は予約・消費しない。API待機中はGUI click、drag、hotbar持ち替えを拒否し、close時は同じsession tokenのGUIを再表示する。

## 2. スキルジェム習得

クラス名: `SkillGemLearnEventHandler`

通常インベントリのスキルジェム左クリックをcancelして確認GUIを開く。右クリックはcancelだけ行い、それ以外の動作をしない。確認GUIは上部だけをcancelし、下部のプレイヤーインベントリは共通ホットバー操作へ委譲する。確定時はentry UUIDを指定してAPIでジェムを1個消費し、Lv.1の新規習得個体を作る。既存個体へのレベルアップは行わない。先行インベントリ同期が失敗しても、素材entryをAPI正本で検証・再同期するmutationを続行する。習得・プリセット保存・シジル操作の操作トークンはプレイヤー世代ごとに管理し、ログアウト時にGUIセッションとともに破棄する。古いcallbackは再ログイン後の新しい操作状態を解除しない。

対象スキルをすでに習得済みの場合は、確認GUIのタイトルを赤文字の「このスキルの習得は非推奨です。」へ変更し、確認内容に「このスキルはすでに習得済みです。」、確定ボタンの説明に「同じスキルを別個体として習得します。」と表示する。初回習得時は従来どおり「スキル習得確認」を表示する。

成功時は習得キャッシュとインベントリGUIを即時更新し、習得した skill ID を外部 listener へ通知する。失敗時は永続状態を再ロードし、確認GUI下部の所持品表示にも再適用した上で消費されていない旨を通知する。キャンセル・closeではmutationを呼ばない。

## 3. action ring入力解決

クラス名: `SkillActionRingEventHandler`、`SkillActionRingHoldService`、`SkillActionRingService`

プリセットのバインド値を `learnedSkillId` として解決し、該当個体のレベル・シジル・使用許可・共有cooldownを表示と発動の両方へ使う。発動候補の取得時と実行直前に main-hand weapon の装備条件（プレイヤーレベル・クラス・クラスレベル）と耐久値を再確認し、条件不足の武器では発動しない。バインドが残っていても許可を失った個体は発動せず、`P_5863` でスキル名を通知する。

`ACTION_RING_HOLD_SELECT=false` は従来操作であり、右クリックでリングを開き、左クリックで選択、次の左クリックで発動する。`true` は選択中 hotbar slot の主武器だけを事前にクライアントへ仮想 `TRIDENT` として送り、空中右クリックで長押しを開始する。`RELEASE_USE_ITEM` を受けた時点で現在のリング選択を確定し、解除時に選択項目がなければ選択確定を行わずリングを閉じる。確定後は従来どおり次の左クリックで発動する。サーバー側の主武器は常に `PAPER` のまま保持し、解除時には開始時と同じ hotbar slot、item ID、equipment instance ID、および武器 PDC をメインスレッドで再確認する。

長押し中は hotbar 変更、offhand swap、drop、inventory open、world change、death、quit、リングの明示closeで待機を破棄する。解除パケットは有効な待機 session にだけ cancel して選択確定へ振り替える。長押し開始中は右・左クリックと hotbar 入力を action ring の guard が占有する。

## 4. active skill lifecycle

world changeは詠唱・移動task・temporary effect・当該プレイヤーが発生させた一時挑発を破棄しcooldownを維持する。death / quitはcooldownを含む全一時skill stateと当該プレイヤーの一時挑発を破棄する。

## 5. メディテーション中断

クラス名: `MeditationSkillEventHandler`、`MeditationSkillRuntimeService`

- バインド済みパッシブの tick 中、プレイヤーがスニークしていない場合は準備・発動状態を破棄する。
- `EntityDamageEvent` と custom `DamageService` のプレイヤー実ダメージ通知、`PrePlayerAttackEntityEvent`、`SkillService` の検証済みskill-use通知を受けた場合は即時破棄する。
- runtime の短命状態は Bukkit Player UUID をキーにする。`PlayerToggleSneakEvent` の解除、`PlayerDeathEvent`、`PlayerQuitEvent`、`PlayerChangedWorldEvent`、クラス変更後のパッシブ再調停でも状態が残らないようにする。
- 5秒は100 tickとして管理し、発動中のスニーク継続だけを条件に自然回復倍率を有効化する。発動時に円形 particle と控えめな音を一度だけ出し、維持中は低密度の周回 particle と環境音を間隔表示する。環境音は `activeSoundIntervalTicks`（現行値40 tick）に従って再生し、`World#playSound` と `SoundCategory.PLAYERS` により音源位置の周囲にいるプレイヤーにも聞こえる。自然回復倍率の効果対象は自身のみとする。

## 6. 例外処理

GUI click / drag / close の例外は `E_5601`、action ringとactive lifecycleは `E_3002` へ操作context付きで記録し、Bukkit event loopへ再送出しない。
