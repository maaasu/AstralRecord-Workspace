# 13_3-サービス

## 1. definition load / reload

クラス名: `SkillService`
物理名: `loadDefinitions`, `reloadDefinitions`, `replaceDefinitions`

1. `SkillRepository.findAll` の summary ID ごとに詳細を取得する。
2. API definition と built-in definition を統合する。
3. ID / implementation ID 空、負の resource / cooldown / cast time / required level、executor 不在、params 不正を除外する。
4. 検証済み map を `SkillRegistry.replaceDefinitions` へ反映し、件数を返す。

## 2. executor・built-in definition 登録

クラス名: `SkillService`
物理名: `registerExecutor`, `registerBuiltInDefinition`, `registerBuiltInDefinitions`

`registerExecutor` は executor を registry へ登録する。同一 implementation ID の二重登録は後勝ちにせず、既存を維持する。`registerBuiltInDefinition(s)` は API definition と統合する組み込み definition を保持する。

## 3. cast 可否

クラス名: `SkillService`
物理名: `canCast`

required level、現在 MP / EN、caster ごとの cooldown、進行中 cast を検証して `SkillCastResult` を返す。resource は `resourceType` / `resourceCost` を優先し、legacy definition は `manaCost` へ fallback する。MP / EN の実消費量にはそれぞれ `MP消費軽減率` / `エネルギー消費軽減率` を適用する。

`PlayerSkillCaster.level()` と `MobSkillCaster.level()` は現状 `Integer.MAX_VALUE` のため、required level は両者で実質通過する。

## 4. skill 発動

クラス名: `SkillService`
物理名: `castSkill`

1. definition と executor を解決し、`canCast` を実行する。
2. 基本 cast time に `詠唱時間短縮率` と状態異常の詠唱倍率を乗算する。`ceil(基本詠唱時間 × max(0, 1 - 短縮率 / 100) × 状態異常倍率)` が 0 tick なら即時発動し、正なら caster ごとの session / Bukkit task を作る。player は movement を制限し、HUD の primary ActionBar にスキル名・残り秒数・太い進捗バーを表示する。バーは完了部分をライム色かつ難読化装飾、未完了部分を灰色とし、0.5 秒間隔の詠唱音は進捗に応じて音程を上げる。Mob は `MobInstance` の cast 表示状態を更新する。
3. 完了時に resource を消費し、executor を実行する。
4. 成功時は `ceil(基本CD × max(0, 1 - CD短縮率 / 100))` の cooldown と sound を反映する。短縮率が 100% 以上なら cooldown は 0 tick となる。失敗時は `E_5802` と player message を返す。

## 5. cooldown・cast lifecycle

クラス名: `SkillService`
物理名: `getRemainingCooldownTicks`, `startCooldown`, `cancelCasting`, `clearCasterState`, `stop`

caster / skill 単位の cooldown と cast task を管理する。装備の左クリック攻撃は `startAttackCooldown` を使い、CD短縮後の間隔へさらに `ceil(間隔 × 100 / 攻撃速度)` を適用する（基準速度 100、最短 1 tick）。`cancelCasting` は詠唱だけ、`clearCasterState` は caster の全一時状態、`stop` は全 caster と task を破棄する。player の詠唱完了・中断時は primary ActionBar renderer を解除し、通常 HUD を即時再描画する。

## 6. passive skill 同期

クラス名: `PassiveSkillService`
物理名: `reconcileNow`, `getStatusBonus`, `stop`

所持 skill と選択 preset の passive slots から有効 passive を決定する。`passiveBindRequired=false` は所持だけ、`true` は選択 preset の passive slot への bind を必要とする。status modifier は status 再計算へ提供し、tick 要求 executor だけ scheduler 対象にする。

## 7. bind preset cache / 保存

クラス名: `SkillBindPresetService`
物理名: `getPresets`, `hasLoadedPresets`, `invalidate`, `loadInitialPresets`, `applyInitialPresets`, `selectedPresetIndex`, `selectPreset`, `saveAsync`

- API 結果を 6 preset へ正規化する。不足分は 1..3 unlocked、4..6 locked の fallback で補う。
- selected index は 1..6 へ clamp する。
- account ごとの同時 save は 1 件だけ許可し、generation が変わった旧 callback は無視する。
- API I/O は async、cache merge と callback は main thread で行う。

## 8. 所持 skill 解決

クラス名: `SkillOwnershipService`
物理名: `ownedSkillIds`

player の skilltree 解放状態などから現在所持する skill ID set を返す。bind GUI と passive 調停はこの set を共通利用する。

## 9. active skill 共通支援

| クラス | 主な物理名・責務 |
|---|---|
| `SkillCombatService` | `hit`, `provoke`, `knockback`: combat / condition / threat へ委譲 |
| `SkillTargetingService` | `inCone`, `inLine`, `inRadius`, `nearestFrom`, `groundTarget`: 有効 Mob target 解決 |
| `SkillMovementService` | `dash`, `backstep`, `blink`: collision を検査した player 移動 |
| `SkillProjectileService` | `launch`: tick projectile と hit callback |
| `SkillEffectService` | `point`, `line`, `ring`, `arc`, `sound`: 共通 effect |
| `SkillTaskService` | `later`, `repeat`, `cancel`, `clearCaster`, `stop`: caster scope task |
| `TemporarySkillEffectService` | outgoing / incoming / knockback multiplier の期限付き modifier |
