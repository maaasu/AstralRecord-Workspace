# 13_3-サービス

## 1. definition load / reload

クラス名: `SkillService`

`SkillRepository` から取得した API 定義と built-in 通常攻撃定義を検証して `SkillRegistry` へ一括反映する。ID、implementation、基礎値、`cooldownId`、`maxLevel`、レベル差分、シジル枠、許可シジルを検証し、不正な定義だけを隔離する。

## 2. executor・built-in definition 登録

同一 implementation ID の executor 二重登録は拒否する。built-in は通常攻撃などジェム・所持・使用許可の対象外であるシステムスキルに用いる。

## 3. cast 可否

active 発動前に required level、MP / EN、共有 cooldown、詠唱中状態を検証する。プレイヤーの習得個体発動では、実行直前にも `learnedSkillId` の所持と skill ID の使用許可を再検証する。passive は active cast 経路で拒否する。

## 4. skill 発動

クラス名: `SkillService`
物理名: `castLearnedSkill`, `castSkill`

プレイヤーの通常バインドは `castLearnedSkill` へ `learnedSkillId` を渡す。所持個体を取得し、`LearnedSkillResolver` でレベル差分と有効シジルを合成してから cost・cast time・cooldown・executor context へ使用する。

詠唱完了時にも所持・使用許可を再検証する。executor 成功時だけリソースを消費し、発動スキル自身の解決済み cooldown 時間で共有キーを開始する。

`castSkill` は Mob・システムスキル・管理用経路に用いる。通常攻撃は武器タグから選んだ built-in definition をこの経路で発動する。

## 5. cooldown・cast lifecycle

`cooldownId` が同じスキルはプレイヤー単位で同じ終了時刻を参照する。未指定時は skill ID をキーとする。スキルAが5秒、スキルBが8秒でも、A発動時は共有グループを5秒、B発動時は8秒にする。共有状態には終了時刻と発動時の総tickを保持し、アクションリングの残量と分母にも同じ値を使う。

武器通常攻撃はbuilt-in skill IDにかかわらず `weapon_normal_attack` をcooldown keyとして共有する。開始時間は実行した武器の基本tickへcooldown短縮率と攻撃速度を適用して決定し、表示用skill IDには実行したbuilt-in IDを保持する。クールダウンボスバーは近接・間接・魔法で分けずプレイヤーごとに1本とし、通常攻撃時のタイトルを「通常攻撃」、色をBukkit APIで灰色に最も近い `BarColor.WHITE`、styleを `BarStyle.SEGMENTED_10` とする。

world change は詠唱・関連タスクを破棄して cooldown を維持し、death / quit は cooldown を含む一時状態を破棄する。パッシブへ cooldown は適用しない。

## 6. passive skill 同期

クラス名: `PassiveSkillService`

所持個体、使用許可、選択プリセットを基に有効パッシブを個体 UUID 単位で決定する。`passiveBindRequired=false` は所持と許可だけ、`true` は有効範囲内のパッシブ枠へのバインドも必要とする。

## 6.1 自然回復倍率

クラス名: `PassiveSkillService`、`StatusService`

`PassiveSkillService.getResourceRegenMultiplier` は有効パッシブ executor の倍率を resource 単位で評価し、同一スキル個体の重複や複数パッシブの過剰な乗算を避けるため最大値を返す。`StatusService.getNaturalRegenMultiplier` は `MP_REGEN` / `ENERGY_REGEN` をそれぞれ `MANA` / `ENERGY` へ対応付け、`StatusRegenTask` の既存 `regen / 5` に倍率を適用する。HP自然回復と最大値・固定回復処理はこの経路の対象外とする。

`adventurer_meditation` は runtime が発動中のときだけ両resourceへ `3.0` を返す。5秒準備中、スニーク解除、被弾、通常攻撃、他スキル使用、ログアウト、死亡、ワールド移動、クラス変更、バインド解除後は倍率を返さない。

## 6.2 スキル使用通知

クラス名: `SkillService`

`castSkill` / `castLearnedSkill` は発動可否の検証に成功し、cast開始または即時実行へ進む直前にプレイヤー向け skill-use listener を一度呼び出す。メディテーションはこの通知を受けて準備・発動状態を破棄する。拒否されたスキル使用は休息状態を変更しない。

## 7. bind preset cache / 保存

クラス名: `SkillBindPresetService`

API 結果をプリセット6個、action 6枠、left-click 1枠、passive 9枠へ正規化する。保存は非同期で行い、account ごとの世代とセッションを確認して古い callback を破棄する。API は習得済み UUID の所有を検証する。

## 習得済みスキル個体

クラス名: `LearnedSkillService`、`SkillOwnershipService`

ログイン時に account の習得個体を API からロードし、UUIDを保持したままキャッシュする。同じ skill ID の個体を複数保持する。ジェム左クリックは常にLv.1の新規個体を作り、既存個体を上書き・レベルアップしない。

レベルアップとシジル装着は、スキルマネージャーで選択した個体 UUID とインベントリ entry UUID を API へ送る。API成功後は習得個体キャッシュを更新し、素材entry UUIDだけをAPIから再取得して消費後数量と正本 `updatedAt` を反映する。通信結果が不明な失敗時も習得個体一覧と対象entryだけを再取得し、API待機中に発生した無関係なアイテム移動・取得を全体置換しない。ログアウトでaccount世代が変わった応答はローカル状態へ適用しない。

## 使用許可

クラス名: `SkillPermissionService`

現在クラスの `usableSkills` と `SkillTreeService.getUnlockedSkillIds` の和集合を返す。後者は現在クラス条件を満たして表示・効果が有効な解放済みノードだけを含む。所持判定とは混在させない。

## 習得済みスキル個体の解決

クラス名: `LearnedSkillResolver`

Lv.2から現在レベルまでの前レベル差分を累積する。装着済みシジルは許可 ID、現在レベルのslot範囲、item master、`equipGroupId`、同group重複を再検証し、有効なものだけを適用する。status modifier は加算し、ロジック変更型は有効シジル ID を context へ渡す。

## パッシブスロット

`activePassiveSlotCount` は基本5へ、パッシブ効果自身を除いた `PASSIVE_SKILL_SLOTS` を1値1枠で加え、最大9とする。保存済み9枠は維持し、現在枠数を超える位置だけを発動対象から除外する。

## 8. スキルマネージャー

クラス名: `SkillBindGuiEventHandler`

選択中バインド枠がなければ一覧クリックで個体の合成画面を開く。active / left-click 枠選択中はactiveだけ、passive枠選択中はbind-required passiveだけを一覧へ出す。常時発動パッシブは設定候補から除外する。使用許可の有無は表示するが、許可がなくても所持個体のバインドは許可する。

## 9. active skill 共通支援

`SkillCombatService`、`SkillTargetingService`、`SkillMovementService`、`SkillProjectileService`、`SkillEffectService`、`SkillTaskService`、`TemporarySkillEffectService` を再利用する。個別 executor は Bukkit damage や独自 scheduler を重複実装しない。

## 10. skill tree 設定・master snapshot

クラス名: `SkillTreePluginConfig`、`SkillTreeService`

- `SkillTreePluginConfig.loadFile` は呼出時点の disk 上 `config.yml` からworld、structure ID、centerを読む。
- structure IDは小文字英数字で開始し、小文字英数字・`_`・`-`だけを許可する。
- master snapshot置換時、player state未読込のonline playerには派生効果を適用しない。読込済みplayerでは有効なスキル使用許可とパッシブを調停してからstatusを再計算する。
- node definitionの同一性はIDだけでなく、表示・icon・lore（任意。未定義時は説明表示なし）・tag・point・condition・effectの内容を比較する。
- ワールドのnodeラベルとスキルツリーGUIのnode表示では、loreが未定義または空の場合に説明行を追加しない。PP nodeに条件がある場合は条件行を表示し、条件成立時は白、未成立時は赤で表示する。classId条件付きnodeのコストは`CP[クラス名] コスト`形式で表示し、コスト値を黄色にする。クラスを解決できない場合は`未登録のクラス`と表示し、内部IDは表示しない。コスト0でもclassId条件があるnodeはCost行を表示する。

## 11. skill tree unlock・relock・派生効果

クラス名: `SkillTreeService`

- skill effectは所有権ではなく使用許可を追加する。unlock / relock、クラス条件、player level条件、master reloadのたびに有効許可集合を再評価する。
- root unlock / relockとpoint集計では、永続stateに残る未知node IDを現在masterのnodeとして数えない。
- class条件のないclass point nodeは消費元classの明示選択を要求する。class条件があるnodeは、その条件に対応するancestor classを消費元として記録する。
- current classとplayer levelの条件を満たさないCP nodeは非表示とする。PP nodeは条件行を表示するため表示を維持する。いずれも解放済みの場合は条件未達中のskill使用許可とstatus effectを無効化する。
- 条件未達のPP nodeは表示するが、解放・解除のplayer-control入力候補には含めない。
- 許可集合またはstatus effectが変化した場合は、パッシブ調停後に`StatusService.refreshStatus`を実行する。

## 12. skill tree 入力候補・node 実行

クラス名: `SkillTreeEventHandler`、`SkillTreeService`

- 視線上にnodeがない場合は候補を返さず、nodeがある場合はnode IDとray入口距離を持つplayer-control候補を一件返す。
- winner選択後は解決済みnode / positionを実行し、ray targetを再選択しない。left clickはunlock、right clickは確認GUIを経由してrelockする。
- left clickでは、`pointCost > 0`のnodeだけを解放ポイントの事前残高判定の対象とする。`pointCost == 0`のnodeは残高0でも事前に拒否せず、いずれのnodeも最終的な解放可否は`SkillTreeService.canUnlockNode`へ委譲する。
- nodeの解放に成功した場合は、解放したnode名と解放後の残りポイントを通知する。class pointは実際の消費元クラスを `CP[クラス表示名]` として表示し、passive pointは `PP` として表示する。
- 「確認GUIを表示しない」はプレイヤー単位の一時状態とし、スキルツリーワールドから離れた時点またはquit時に破棄する。
- node用`Interaction` entityがsnapshotに含まれる場合はPDCのnode IDから配置を直接解決する。
- packet nodeは意図的にbarrier blockと重なるため、block遮蔽距離より奥でもnode hitboxとの交差を候補として扱う。
