# 13_3-サービス

## 1. definition load / reload

クラス名: `SkillService`

`SkillRepository` から取得した API 定義と built-in 通常攻撃定義を検証して `SkillRegistry` へ一括反映する。ID、implementation、基礎値、`cooldownId`、`maxLevel`、レベル差分、シジル枠、許可シジルを検証し、不正な定義だけを隔離する。executor種別やresourceを解決した定義へ再構築するときも、`learnRequiredItems` / `levelUpRequiredItems` を欠落させず保持する。

## 2. executor・built-in definition 登録

同一 implementation ID の executor 二重登録は拒否する。built-in は通常攻撃など所持・使用許可の対象外であるシステムスキルに用いる。

## 3. cast 可否

active 発動前に required level、必要な全MP / ENG、共有 cooldown、詠唱中状態を検証する。プレイヤーの習得個体発動では、実行直前にも `learnedSkillId` の所持と skill ID の使用許可を再検証する。passive は active cast 経路で拒否する。

## 4. skill 発動

クラス名: `SkillService`
物理名: `castLearnedSkill`, `castSkill`

プレイヤーの通常バインドは `castLearnedSkill` へ `learnedSkillId` を渡す。所持個体を取得し、`LearnedSkillResolver` でレベル差分と有効シジルを合成してから cost・cast time・cooldown・executor context へ使用する。

詠唱完了時にも所持・使用許可を再検証する。executor 成功時だけ `onCast.sound` を再生してリソースを消費し、発動スキル自身の解決済み cooldown 時間で共有キーを開始する。

### 4.2 複合リソース消費

通常は `resourceType` / `resourceCost` の1種類を消費する。`resourceType: ENERGY` かつ `manaCost > 0` の定義だけは、`resourceCost` を主ENG消費、`manaCost` を副MP消費として扱う。発動前と詠唱完了時に両方の残量を先に検証し、片方でも不足すればどちらも消費しない。executor成功後だけ両方を消費するため、片方だけ消費される状態を作らない。`ENERGY_COST_REDUCTION` と `MANA_COST_REDUCTION` は対応する消費へ個別に適用する。

`castSkill` は Mob・システムスキル・管理用経路に用いる。通常攻撃は武器タグから選んだ built-in definition をこの経路で発動する。

### 4.1 スキルキャストディスク

`SkillActionRingService.castActionSlotWithHotbarWeapon` は、指定されたアクションスロット番号を選択プリセットから再解決し、指定ホットバーの使用可能なWEAPONを一時的な主手として扱う。主手切替後に `StatusService.refreshStatus` を実行し、その武器を含む `StatusSnapshot` を `castLearnedSkill` または武器通常攻撃へ渡す。呼び出し後は選択中ホットバー枠を必ずディスクへ戻し、元の主手でステータスを再計算する。一時武器の最大値クランプで失われた現在HP/MP/ENG/Shieldは復元し、実際に確定したスキル消費だけを保持する。スキルキャストディスク自身はスキルIDを永続化せず、スロット番号だけをitem metadataへ保存する。

## 5. cooldown・cast lifecycle

`cooldownId` が同じスキルはプレイヤー単位で同じ終了時刻を参照する。未指定時は skill ID をキーとする。スキルAが5秒、スキルBが8秒でも、A発動時は共有グループを5秒、B発動時は8秒にする。共有状態には終了時刻と発動時の総tickを保持し、アクションリングの残量と分母にも同じ値を使う。

武器通常攻撃はbuilt-in skill IDにかかわらず `weapon_normal_attack` をcooldown keyとして共有する。開始時間は実行した武器の基本tickへcooldown短縮率と攻撃速度を適用して決定し、表示用skill IDには実行したbuilt-in IDを保持する。クールダウンボスバーは近接・間接・魔法で分けずプレイヤーごとに1本とし、通常攻撃時のタイトルを「通常攻撃」、色をBukkit APIで灰色に最も近い `BarColor.WHITE`、styleを `BarStyle.SEGMENTED_10` とする。

world change は詠唱・関連タスクを破棄して cooldown を維持し、death / quit は cooldown を含む一時状態を破棄する。通常のパッシブへ cooldown は適用しないが、バスティオンストライクの反撃成立時は `SkillService` のスキル cooldown として登録し、`SkillCooldownBossBarService` のプレイヤー共通ボスバーへ表示する。

## 6. passive skill 同期

クラス名: `PassiveSkillService`

所持個体、使用許可、選択プリセットを基に有効パッシブを個体 UUID 単位で決定する。`passiveBindRequired=false` は所持と許可だけ、`true` は有効範囲内のパッシブ枠へのバインドも必要とする。

## 6.1 自然回復倍率

クラス名: `PassiveSkillService`、`StatusService`

`PassiveSkillService.getResourceRegenMultiplier` は有効パッシブ executor の倍率を resource 単位で評価し、同一スキル個体の重複や複数パッシブの過剰な乗算を避けるため最大値を返す。`StatusService.getNaturalRegenMultiplier` は `MP_REGEN` / `ENERGY_REGEN` をそれぞれ `MANA` / `ENERGY` へ対応付け、`StatusRegenTask` の既存 `regen / 5` に倍率を適用する。HP自然回復と最大値・固定回復処理はこの経路の対象外とする。

`adventurer_meditation` は `chargeTicks: 60` tick（3秒）の連続スニーク後に回復効果を開始する。開始時から `activeDurationTicks: 140` tick（7秒）の間、MP / ENGだけへ自然回復倍率を適用し、開始直後は `initialRegenMultiplier: 2.0`、以降20 tick（1秒）ごとに `regenMultiplierIncrement: 0.5` を加算する。したがって開始から1秒ごとの倍率は2.0、2.5、3.0、3.5、4.0、4.5、5.0となる。HP自然回復とShield回復は対象外とする。

回復効果の開始時に `buff:adventurer_meditation` を付与し、移動速度へ `SCALAR: 1.20`（+120%）を適用する。スニーク解除、被弾、通常攻撃、他スキル使用、ログアウト、死亡、ワールド移動、クラス変更、バインド解除でruntimeを中断すると、このバフも同時に解除する。開始から140 tick経過時はバフと自然回復倍率を終了し、`restoreMpAndEnergy` でMP / ENGだけを最大値へ戻す。その直後、プレイヤーの高さ1m付近へ `TOTEM_OF_UNDYING` と `END_ROD` の完了パーティクルを近傍 viewer 向けに一度ずつ表示し、`SoundCategory.PLAYERS` の `ENTITY_PLAYER_LEVELUP` を一度再生する。完了後、スニークを継続していても再発動せず、いったん中断してから再度60 tickの準備が必要となる。

## 6.2 ドッジ連動パッシブ

`administrator_just_dodge` は `PassiveSkillService` が有効化した個体の `params` を `JustDodgeSkillRuntimeService` へ登録する。`DodgeService.executeDodge` が成功通知を送ると、`invulnerabilityTicks` の間だけ対象プレイヤーの直接攻撃受付状態を開始する。`DamageService` は `DamageSource.NORMAL_ATTACK` / `SKILL` の計算済みダメージだけをこの runtime へ渡し、無効化された場合はShield・HP・耐久・被弾listener・ダメージ表示を適用せず終了する。`DamageService.applyConditionDamage` はこの判定を呼び出さない。

有効時間内の直接hitは回数制限なしで無効化する。最初の無効化時だけ `energyRecoveryAmount` を回復し、同じドッジ中の後続hitでは回復しない。各無効化時には `DODGE_CLOUD` と `ITEM_SHIELD_BLOCK` を表示し、最初の無効化時だけ追加で `JUST_DODGE_ENERGY_ABSORB_END_ROD` と `ENTITY_EXPERIENCE_ORB_PICKUP` を表示してENG回復を示す。パッシブ解除時は登録設定とドッジ中の一時状態を破棄し、死亡・退出・ワールド移動・Plugin停止時も同じruntime状態を破棄する。

## 6.3 スペルステップ

クラス名: `SpellStepSkillRuntimeService`、`DodgeService`

`hunter_spell_step` は `PassiveSkillService` が有効化した個体の設定を `SpellStepSkillRuntimeService` へ登録する。`SkillService` のプレイヤーcast成功通知で、成功した定義のタグに `ranged` が含まれる場合だけ、現在tickから20tick（1秒）以内の次回ドッジを1回分だけ待機する。同じ待機中に別の遠隔スキルが成功した場合は、1回分の権利を重ねず有効期限を20tickへ更新する。

`DodgeService` は地上・生存・受付時間などの通常条件を確認した後に消費量を一度だけ解決する。スペルステップの待機権を消費できた場合はENG消費量を0とし、`params.triggerSound`（定義値は `block.beacon.power_select`）を `SoundCategory.PLAYERS` で再生する。待機権がない場合は既存どおりENGを15消費する。待機権はドッジ成功時だけ消費され、通常のドッジ演出・成功通知はそのまま適用する。

パッシブ解除時は個体設定と待機権を破棄する。死亡・ワールド移動では待機権だけ、退出・Plugin停止では設定を含む全状態を破棄する。DPS、攻撃対象、状態異常、PvP対象の追加はない。

## 6.4 アーケインフロー

クラス名: `ArcaneFlowSkillRuntimeService`、`SkillService`

`mage_arcane_flow` は `PassiveSkillService` が有効化したバインド必須パッシブであり、習得済み個体ごとに `params.castTimeReductionPercent` を runtime へ登録する。Lv.1は5%、`levels` の各 `paramDeltas` は1.25%として、Lv.5で10%になる。`MageArcaneFlowSkillExecutor` はこの固定進行を読込時に検証する。

`SkillService` はプレイヤーのスキル実行が成功した後に、成功したスキル ID を追加 listener へ通知する。アーケインフローは最後に成功したスキル IDをプレイヤー単位で保持し、現在のスキル定義が共有タグ `magic` を持ち、直前の成功スキル IDと異なる場合だけ追加詠唱短縮率を返す。初回、同じスキル、現在のスキルが `magic` でない場合、またはパッシブが無効な場合は短縮しない。失敗・キャンセルしたスキルは履歴へ記録しない。直前のスキルが非魔法であっても履歴として扱い、次の異なる魔法スキルは条件を満たす。

追加短縮率は既存の `CAST_TIME_REDUCTION` と状態異常による詠唱倍率へ乗算し、最終的な詠唱 tick を切り上げて解決する。resolver は詠唱開始前と開始処理内から複数回呼ばれるため、詠唱時間の解決中に履歴を変更しない。

条件成立時は `SharedParticleDefinitions.SKILL_MAGE_ARCANE_DUST` を使った半径約0.72m・16点の紫色リングを、`ParticleDisplayService` の近傍 viewer 表示経路でプレイヤーの高さ1m付近へ表示する。死亡・ワールド移動では直前スキル履歴を破棄し、退出・パッシブ解除・Plugin停止では設定と履歴を破棄する。ダメージ、状態異常、リソース消費、クールダウン、DPSは追加しない。

## 6.5 スキル使用通知

クラス名: `SkillService`

`castSkill` / `castLearnedSkill` は発動可否の検証に成功し、cast開始または即時実行へ進む直前にプレイヤー向け skill-use listener を一度呼び出す。メディテーションはこの通知を受けて準備・発動状態を破棄する。拒否されたスキル使用は休息状態を変更しない。

## 7. bind preset cache / 保存

クラス名: `SkillBindPresetService`

API 結果をプリセット6個、action 6枠、left-click 1枠、passive 9枠へ正規化する。`isSelected`を読み取り、選択中プリセット番号をキャッシュへ復元する。プリセット切替とバインド内容保存は `InventoryService.executeLocalPlayerMutation` 内で即時にキャッシュへ確定し、`queueLocalPlayerSave` で account 単位の player-state snapshot を後送する。個別の bind API 保存は行わない。section `skillBindPresets` は `clientRevision`、選択番号、全プリセット、各行の `expectedVersion` と `targetVersion` を送る。ACK はバインド内容をキャッシュへ戻さず、captured revision と一致する場合だけ dirty を解除する。ACK metadata の version は後続snapshotの expectedVersion とruntimeのversion基準へ取り込む。API は習得済み UUID の所有を検証する。

退出・アカウント切替時のプリセットinvalidateはセッションだけを失効させる。未保存または送信中のsectionは、保存laneがsnapshotを捕捉する前でも、内容・選択番号・dirty・保存version基準を完全ACKまで保持する。再参加のinitial load / applyは保持状態を旧API値より優先する。loadとapplyの間にACKが完了しても保持内容を優先し、ACK後は退出済み状態だけを破棄する。ACK の preset ID 集合は送信集合と完全一致しなければならない。ACK versionに送信後の変更差分を加えた値をruntimeと次回targetVersionへ反映し、重複・旧保存世代のACKは無視する。不完全または解釈不能な ACK は dirty を残した成功として扱わず、保存失敗として上位へ通知する。

## 習得済みスキル個体

クラス名: `LearnedSkillService`、`SkillOwnershipService`

ログイン時は API から account の習得個体を UUID を保持したままキャッシュする。同じ Plugin プロセス内の再参加時に未保存状態を保持している場合は、下記の保持規則を優先する。習得状態や未送信操作を Plugin data folder へ保存しない。

習得、レベルアップ、シジル装着・脱着、忘却は `executeCriticalPlayerMutation` で処理する。素材を伴う操作は `reserveLocalMutationPayment` と `commitLocalOrbOperationPayment` を同じ account state lock 内で使い、素材消費と習得個体更新を原子的に反映する。脱着時のシジル返却、代償付き忘却の Astrald 消費と補填付与も同じ境界へ含める。section `learnedSkills` は全現存個体（各 `expectedVersion` / `targetVersion`、sigil UUID・group・slot）と、削除競合検出用 `deletedSkills[{learnedSkillId,expectedVersion}]` を完成 snapshot として送る。SQL ACK 後だけ成功 callback を呼ぶ。保存失敗時は inventory と習得個体を checkpoint へ戻し、失敗した snapshot を後送しない。ACK は習得内容を置換せず、同一 revision だけ dirty を解除する。ACK metadata の version / updatedAt / deletedIds は保存基準へ反映し、versionは後続変更を維持した runtime の version 基準にも取り込む。

習得個体も退出・アカウント切替ではsession tokenを失効させ、未保存・送信中の個体、シジル、削除予定、dirty、保存version基準は完全ACKまで保持する。再参加時のload / applyは保持状態を優先し、旧API値による上書きや忘却個体の復活を許可しない。loadとapplyの間のACK完了でも保持内容を維持する。完全ACK後の破棄は退出済み状態だけを対象とする。ACK の現存個体と削除 ID は送信集合と完全一致し、`updatedAt` は UTC の `Z` または offset を含む ISO-8601 日時として解釈し、offset 付き値は UTC へ正規化する。ACK versionと送信後の変更差分からruntimeおよび次回targetVersionを進め、重複ACKや破棄済み保存世代のACKでは後続状態を変更しない。不完全または解釈不能な ACK は dirty を残した成功として扱わず、保存失敗として上位へ通知する。

忘却時に保存済みversionがある個体だけを削除予定へ追加する。先行snapshotで新規learnを送信後に忘却した場合は、先行ACKで現在個体が不在であることを確認し、返された作成済みversionを後続削除のexpectedVersionへ追加する。dirty照会やcheckpointによる捕捉だけでは送信済みと判定しない。新規learnを実送信前に忘却した場合はAPI上の個体が存在しないため削除予定は不要とする。

## 使用許可

クラス名: `SkillPermissionService`

現在クラスの `usableSkills` と `SkillTreeService.getUnlockedSkillIds` の和集合を返す。後者は現在クラス条件を満たして表示・効果が有効な解放済みノードだけを含む。所持判定とは混在させない。

## 習得済みスキル個体の解決

クラス名: `LearnedSkillResolver`

Lv.2から現在レベルまでの前レベル差分を累積する。装着済みシジルは許可 ID、現在レベルのslot範囲、item master、`equipGroupId`、同group重複を再検証し、有効なものだけを適用する。status modifier は加算し、ロジック変更型は有効シジル ID を context へ渡す。

## パッシブスロット

`activePassiveSlotCount` は基本5へ、パッシブ効果自身を除いた `PASSIVE_SKILL_SLOTS` を1値1枠で加え、最大9とする。保存済み9枠は維持し、現在枠数を超える位置だけを発動対象から除外する。

## 8. スキルマネージャー

クラス名: `SkillBindGuiEventHandler`

選択中バインド枠がなければ一覧クリックで個体を表示する。シジル操作はシジル用オーブから専用GUIを開き、一覧から対象個体を選ぶ。active / left-click 枠選択中はactiveだけ、passive枠選択中はbind-required passiveだけを一覧へ出す。常時発動パッシブは設定候補から除外する。使用許可の有無は表示するが、許可がなくても所持個体のバインドは許可する。

## 9. active skill 共通支援

`SkillCombatService`、`SkillTargetingService`、`SkillMovementService`、`SkillProjectileService`、`SkillEffectService`、`SkillTaskService`、`TemporarySkillEffectService` を再利用する。個別 executor は Bukkit damage や独自 scheduler を重複実装しない。`SkillTargetingService.inSphere` は、中心からMobの実body boundsまでの最短3次元距離で球形半径へ交差するMobを選び、上下方向を独立した許容差へ分離しない。`SkillMovementService` は安全確認付きの瞬間移動に加え、移動禁止状態を確認した水平velocity移動も提供する。`SkillProjectileService` の重力飛翔体群は、同一tick内の全線分で `SkillTargetingService` が取得したMob候補とbody boundsのsnapshotを共有する。命中ごとに登録・死亡・NPC・world条件を再検証し、線分交差順とBlock優先規則は単発判定と同じにする。高さ上限付きBlock判定では、線分のうち排他的上限Yより低い区間だけを通常のBlock ray traceへ渡す。`TemporarySkillEffectService` は対象単位の全効果解除に加え、`effectId` を指定した個別解除を提供し、異なる一時効果を誤って消去しない。

## 10. skill tree 設定・master snapshot

クラス名: `SkillTreePluginConfig`、`SkillTreeService`

- `SkillTreePluginConfig.loadFile` は呼出時点の disk 上 `config.yml` からworld、structure ID、centerを読む。
- structure IDは小文字英数字で開始し、小文字英数字・`_`・`-`だけを許可する。
- master snapshot置換時、player state未読込のonline playerには派生効果を適用しない。読込済みplayerでは有効なスキル使用許可とパッシブを調停してからstatusを再計算する。
- node definitionの同一性はIDだけでなく、表示・icon・lore（任意。未定義時は説明表示なし）・tag・point・condition・effectの内容を比較する。
- ワールドのnodeラベルとスキルツリーGUIのnode表示では、loreが未定義または空の場合に説明行を追加しない。PP nodeに条件がある場合は条件行を表示し、条件成立時は白、未成立時は赤で表示する。classId条件付きnodeのコストは`CP[クラス名] コスト`形式で表示し、コスト値を黄色にする。クラスを解決できない場合は`未登録のクラス`と表示し、内部IDは表示しない。コスト0でもclassId条件があるnodeはCost行を表示する。

## 11. skill tree unlock・relock・派生効果

ノード unlock・relock は `InventoryService.executeLocalPlayerMutation` 内で検証・状態変更し、relock の gold 消費も同一 lock 内で行う。`skillTree` section は `clientRevision`、`expectedVersion`、`targetVersion`、全 `unlockedNodes[{nodeId,consumedClassId}]` を後送する。個別 API 保存は停止し、ACK は内容を cache へ戻さず、captured revision 一致時だけ dirty を解除する。

クラス名: `SkillTreeService`

- skill effectは所有権ではなく使用許可を追加する。unlock / relock、クラス条件、player level条件、master reloadのたびに有効許可集合を再評価する。
- root unlock / relockとpoint集計では、永続stateに残る未知node IDを現在masterのnodeとして数えない。
- プレイヤーデータロード時は、解放済みnodeが現在のnode定義・配置へ存在し、rootから解放済みnodeだけを通る経路で全解放済みnodeへ到達できることを検証する。不成立ならローカルで全nodeを解除し、ロードしたversionを期待値とする完成スナップショットで後送する。初期ロード中に補修APIを呼ばない。条件未達・現在ポイント不足は既存どおり効果無効化だけであり、状態を解除しない。
- class条件のないclass point nodeは消費元classの明示選択を要求する。class条件があるnodeは、その条件に対応するancestor classを消費元として記録する。
- current classとplayer levelの条件を満たさないCP nodeは非表示とする。PP nodeは条件行を表示するため表示を維持する。いずれも解放済みの場合は条件未達中のskill使用許可とstatus effectを無効化する。
- 条件未達のPP nodeは表示するが、解放・解除のplayer-control入力候補には含めない。
- 許可集合またはstatus effectが変化した場合は、パッシブ調停後に`StatusService.refreshStatus`を実行する。

再参加時のスキルツリーinitial load / applyは未保存・送信中のローカル状態を優先し、旧API値による置換や補修を行わない。load後からapplyまでにACKが完了しても保持状態を優先する。初期反映の取消も未保存状態は完全ACKまで保持し、ACK後に取消済みcacheだけを解放する。ACK versionに未送信変更差分を加えた次回targetVersionを使い、旧保存世代または重複ACKは無視する。

## 12. skill tree 入力候補・node 実行

クラス名: `SkillTreeEventHandler`、`SkillTreeService`

- 視線上にnodeがない場合は候補を返さず、nodeがある場合はnode IDとray入口距離を持つplayer-control候補を一件返す。
- winner選択後は解決済みnode / positionを実行し、ray targetを再選択しない。left clickはunlock、right clickは確認GUIを経由してrelockする。
- left clickでは、`pointCost > 0`のnodeだけを解放ポイントの事前残高判定の対象とする。`pointCost == 0`のnodeは残高0でも事前に拒否せず、いずれのnodeも最終的な解放可否は`SkillTreeService.canUnlockNode`へ委譲する。
- nodeの解放に成功した場合は、解放したnode名と解放後の残りポイントを通知する。class pointは実際の消費元クラスを `CP[クラス表示名]` として表示し、passive pointは `PP` として表示する。
- 「確認GUIを表示しない」はプレイヤー単位の一時状態とし、スキルツリーワールドから離れた時点またはquit時に破棄する。
- node用`Interaction` entityがsnapshotに含まれる場合はPDCのnode IDから配置を直接解決する。
- packet nodeは意図的にbarrier blockと重なるため、block遮蔽距離より奥でもnode hitboxとの交差を候補として扱う。
