# 13_3-リポジトリ

## 1. スキル定義

クラス名: `SkillRepository`

`GET /api/skill` と `GET /api/skill/{skillId}` を使用する。表示項目、発動制御、`cooldownId`、`maxLevel`、レベル差分、レベル別シジル枠、許可シジルを `SkillDefinition` へ変換する。

## 2. 習得済みスキル個体

クラス名: `LearnedSkillRepository`

| 操作 | API |
|---|---|
| 一覧ロード | `GET /api/account-skills/{accountId}` |
| 必要素材を消費して新規習得 | `POST /api/account-skills/{accountId}/learn` |
| 指定個体レベルアップ | `POST /api/account-skills/{accountId}/{learnedSkillId}/level-up` |
| 指定個体へシジル装着 | `POST /api/account-skills/{accountId}/{learnedSkillId}/sigils` |
| 指定個体からシジル脱着 | `POST /api/account-skills/{accountId}/{learnedSkillId}/sigils/{learnedSkillSigilId}/detach` |

習得・レベルアップ・シジル操作の成功応答にある任意 `inventorySnapshot` は共通Parserで読む。snapshotがnullの旧API応答は既存の個別entry再取得へフォールバックする。

装着mutationは、操作確定時に通常アイテム共通消費順で解決した `SIGIL_ATTACH` オーブとシジルの inventory entry UUID、および更新者を送る。脱着mutationは同じ順で解決した `SIGIL_DETACH` オーブ、装着行UUID、更新者を送り、レスポンスの習得個体と`returnedInventoryEntryId`を受け取る。APIは受信したentryをtransaction内で検証し、操作成立時に指定オーブを1個消費する。成功後はオーブentryとシジルentry（脱着時は返却entry）を正本へ再同期する。レスポンスのUUID、level、version、装着シジルをそのままキャッシュへ反映する。

## 3. バインドプリセット

クラス名: `SkillBindPresetRepository`

`GET /api/skill-bind-presets?account_id={accountId}` と `PUT /api/skill-bind-presets/{accountId}/{presetIndex}` を使用する。action 6枠、left-click、passive 9枠には習得個体UUIDまたはleft-click用通常攻撃予約値を保存する。

## 4. インベントリentry UUID

習得・レベルアップ・シジルmutationで素材を一意に指定できるよう、PluginからAPIへ保存するinventory draftは既存 `inventoryEntryId` を維持する。slot移動やGUI保存で別UUIDへ採番し直さない。既存entryには取得時の `updatedAt` を `expectedUpdatedAt` として送り、mutation後の古い一括保存を拒否する。保存成功応答は、送信後も内容が変化していないentryだけへ反映してAPI採番の新しい更新時刻を取り込み、待機中のローカル変更は上書きしない。

## 6. skill tree node 定義読込

`SkillTreeNodeRepository` はskill effectを使用許可IDとして読み込む。`lore` は任意項目であり、省略時は空の説明として読み込む。ノード全体のロード時、同じ `unlockCondition.classId`（条件なし同士を含む）に同じskill IDが複数定義されていた場合はマスタ不整合としてロードを失敗させる。`classId` が異なる場合だけ重複を許可し、`playerLevel` の違いは許可条件の区別に使わない。

`SkillTreePlayerStateRepository` はアカウント単位の解放ノードとclass point消費元を永続化する。現在クラス条件を満たさないノードは派生許可集合へ含めない。

## 7. skill tree structure 読込

クラス名: `SkillTreeStructureRepository`
物理名: `load`

- plugin configが選択したstructure JSONを毎回読み、相対node座標を設定centerへ加算して絶対座標にする。
- edgeは無向として両端IDの正規順へ揃える。
- node ID / 座標の重複、自己edge、同じ無向edgeの重複、未配置node参照、rootから到達不能なnode、座標加算overflowを拒否する。

## 8. skill tree player state

クラス名: `SkillTreePlayerStateRepository`

accountごとの解放nodeとclass point消費元を永続化する。読込結果はjoin generationに対応するstateとしてserviceへ渡し、古いjoin callbackが新しいsession stateを破棄しないよう、破棄時はstate instanceの一致を要求する。
