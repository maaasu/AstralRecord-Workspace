# 13_6-発動スキル追加ガイド

## 1. 目的

本章は、新しいプレイヤー発動スキルを追加する際の実装境界と確認項目を定める。
個別スキルはゲームデザインを読み取れる小さなクラスとし、Bukkit scheduler、ダメージ経路、Mob 検索、particle 表示を個別実装で作り直さない。

## 2. 責務の分離

| 層 | 責務 | 配置 |
|---|---|---|
| マスタデータ | 表示、共通コスト、詠唱、要求レベル | `40_filebase/30.features.skill/` |
| 個別 executor | 形状、射程、倍率、命中後の効果 | `feature/skill/executor/active/<profession>/` |
| 共通実行基盤 | 当たり判定、custom combat、演出、移動、projectile、遅延処理、一時効果 | `feature/skill/active/` |
| 登録 | executor 一覧の組み立て | `ActiveSkillExecutorCatalog` と職業別 catalog |
| 共通発動制御 | 個体所持、使用許可、コスト、クールダウン、詠唱 | `SkillService` |

## 3. 追加手順

1. `v1.<skill-id>.yml` を作成する。
2. コード定義の発動スキルでは `id` と `implementationId` を同じ値にする。
3. `resourceType` / `resourceCost` / `cooldownTicks` / `castTimeTicks` / `requiredLevel` は top-level に記載する。
4. 個別 executor を 1 スキル 1 クラスで作成し、対応する職業別 catalog へ追加する。
5. 試作中のスキルは `administrator.usableSkills` へ使用許可を追加し、対応する自動生成ジェムを取得して別途習得して確認する。
6. Plugin テスト、API テスト、filebase 検証を実行する。

### 最小 YAML 例

```yaml
schemaVersion: 1
id: swordsman_example
type: SKILL
implementationId: swordsman_example
name: "&f例示技"
description: "&7前方を攻撃する。"
icon: IRON_SWORD
lore:
  - "&7前方3mへ近接攻撃力100%のダメージ。"
cooldownTicks: 40
resourceType: ENERGY
resourceCost: 10
castTimeTicks: 0
requiredLevel: 1
maxLevel: 1
sigilSlotsByLevel: []
allowedSigilIds: []
gem:
  rarity: COMMON
  tradeable: false
  sellable: false
tags:
  - active
  - swordsman
```

`params` は省略を既定とする。射程や倍率だけを変えた多数の定義を一つの executor で共有するなど、振る舞いをデータ駆動にする明確な理由がある場合だけ使用する。

## 4. 個別 executor の規約

- `PlayerActiveSkillExecutor` を継承し、コンストラクタで skill ID と `ActiveSkillServices` を渡す。
- `castPlayer` には「対象形状を決める → 効果を適用する → 演出を出す」というスキル固有の流れだけを記述する。
- 消費リソースとクールダウン値を executor から返さない。成功時は `context.success()` を返し、`SkillService` がマスタ定義を一元適用する。
- ダメージは `SkillCombatService` から custom combat へ流す。Bukkit の `LivingEntity#damage` を直接呼び出さない。
- Mob 検索は `SkillTargetingService` を使い、NPC、別 world、死亡済み Mob を個別クラスで再判定しない。
- particle は `SharedParticleDefinitions` と `SkillEffectService` を使う。プレイヤーの particle 密度設定を無視する `World#spawnParticle` の直接使用を行わない。
- 数 tick 後の攻撃や連続攻撃は `SkillTaskService` で発動者 UUID と紐付ける。退出、死亡、world 変更後に効果を残さず、攻撃ステータスは `SkillCastContext.statusSnapshot` の発動時点値を使う。
- 短距離移動は `SkillMovementService` を使い、移動不能状態、全身幅を含む経路遮蔽、足場、頭上空間を確認する。

## 5. 共通サービス選択

| したいこと | 使用するサービス |
|---|---|
| 扇形・直線・円柱の当たり判定 | `SkillTargetingService` |
| 属性ダメージ・状態異常・ヘイト・ノックバック | `SkillCombatService` |
| 線・円・弧の particle、効果音 | `SkillEffectService` |
| 貫通と swept capsule 命中を持つ飛翔体 | `SkillProjectileService` |
| ダッシュ・バックステップ・ブリンク | `SkillMovementService` |
| 遅延攻撃・複数 wave・罠 | `SkillTaskService` |
| 一定時間の被ダメージ・与ダメージ・ノックバック補正 | `TemporarySkillEffectService` |

## 6. レビュー・テストチェック

- skill ID、`implementationId`、executor の登録キーが完全に一致している。
- コストと cooldown は YAML の top-level 定義だけが決定している。
- ブロック遮蔽、複数命中順、最大命中数、同一対象への重複命中を確認する。
- 衝突に応じて発動する projectile は、最初のMob衝突・地形Block衝突・最大射程への無衝突到達を区別する。Mob の swept capsule 交差距離と Block 面の距離を比較し、Mob が厳密に手前なら ENTITY、同距離または Block が手前なら BLOCK とする。Block 着弾では表示用の正確な衝突地点と遮蔽判定・範囲効果用の手前側中心を分け、着弾 Block 自身で手前側の Mob を遮蔽しないことを確認する。最大射程へ無衝突で到達したときの効果発生は個別skill仕様に従い、着弾時だけ起爆するskillはそこで効果を発生させない。
- 命中しない場合にダメージ、状態異常、ヘイトが発生しない。
- 退出、死亡、world 変更、Plugin 停止時にタスクと一時効果が破棄される。
- `params` を使わない executor は、マスタデータに `params` が追加された場合を読込時エラーとして検出する。
- API から取得した定義と仮想ジェムが登録され、ジェムで習得した個体を Administrator の使用許可でバインド・発動できる。

`ActiveSkillExecutorCatalog` が返す built-in player executor は次の 17 ID とし、各 ID を重複なく一度だけ登録する。全要素は `PlayerActiveSkillExecutor` として共通 player 発動契約へ接続する。

| 職業 | built-in skill ID |
|:--|:--|
| adventurer | `adventurer_astral_edge`, `adventurer_blast_arrow`, `adventurer_mana_burst`, `adventurer_smash`, `adventurer_quick_shot`, `adventurer_lightning_bolt` |
| swordsman | `swordsman_shield_drain`, `swordsman_flame_rush`, `swordsman_challenging_roar`, `swordsman_bastion_strike` |
| hunter | `hunter_fade_shot`, `hunter_arrow_rain`, `hunter_crash_arrow`, `hunter_heal_arrow` |
| mage | `mage_fireball`, `mage_heal_aura`, `mage_sparking` |

## 7. 冒険者クイックショットの実装契約

`adventurer_quick_shot` は、通常クラスでは冒険者だけが `usableSkills` で使用許可を得る、旅人の射撃を置き換える基礎的な単体・間接攻撃である。マスタは `v1.adventurer_quick_shot.yml`、executor は `AdventurerQuickShotExecutor`、登録先は `AdventurerSkillExecutorCatalog` とする。

- 発動時に照準方向へ、Mob だけを対象とする仮想飛翔体を1本発射する。`SkillProjectileService` の swept capsule 判定を使用し、PvP対象は選択しない。
- 飛翔体は射程12m、速度2.2m/tick、当たり半径0.45m、非貫通・最大1体とする。ブロック遮蔽で停止し、水は遮蔽として扱わない。
- 最初に命中したMob 1体だけへ `RANGED` / `NONE` の間接攻撃力150%を適用する。Lv.2～5の `SKILL_DAMAGE_INCREASE +5%` により、Lv.5の実効倍率は180%となる。
- 消費はEN 6、cooldownは40 tick（2.0秒）、詠唱は0 tickとする。通常攻撃との追加GCD・キャンセル処理は設けない。
- 演出は `SKILL_HUNTER_ARROW` と `SKILL_HUNTER_IMPACT` を流用し、`ENTITY_ARROW_SHOOT` を高めのpitchで鳴らす。新しい共有particle定義は追加しない。
- アクションリングと左クリックバインドは既存の有効な主手 `WEAPON` 判定をそのまま使用し、弓限定の追加条件は設けない。

## 8. 冒険者ライトニングボルトの実装契約

`adventurer_lightning_bolt` は、冒険者が扱う雷属性の基礎魔法である。マスタは `v1.adventurer_lightning_bolt.yml`、executor は `AdventurerLightningBoltExecutor`、登録先は `AdventurerSkillExecutorCatalog` とする。`id`、`implementationId`、executor の登録キーは同一値にそろえる。

- MP 10、cooldown 60 tick（3.0秒）、詠唱4 tick（0.2秒）、射程14m、飛翔体速度2.8m/tick、当たり半径0.45mとする。発動時に青白い収束粒子を出した後、視線方向へ非貫通の仮想飛翔体を1本だけ発射する。
- 最初に命中したMob 1体へ `MAGIC` / `LIGHTNING` の基礎倍率145%を1回適用する。Lv.2～5の `SKILL_DAMAGE_INCREASE +5%` は主攻撃と連鎖攻撃の双方へ共通 combat 経路で適用する。主対象が `SHOCKED` である必要はない。
- 主対象から水平半径5m・上下5m以内で、`SkillTargetingService.inRadius` が返す視線遮蔽のないMobを距離順・UUID順に確認する。そのうち `SkillCombatService.hasCondition(target, ConditionType.SHOCKED)` が真の別対象だけを最大2体まで選び、各対象へ基礎倍率40%の `MAGIC` / `LIGHTNING` を1回ずつ適用する。候補を先に最大数へ切らず、感電対象を抽出してから最大2体へ切るため、近い非感電Mobがいても後続の感電Mobを選べる。
- 連鎖は主対象の命中処理で1段だけ発生し、連鎖先を新しい中心として探索しない。主対象は連鎖対象から除外し、候補リストは共通サービスの一意なMobを使うため、同一発動内の再命中・元対象への戻り・循環は発生しない。本スキルは `SHOCKED` を付与せず、感電していない敵へ連鎖しない。
- 対象選択は既存 active skill と同じMob専用規約に従うため、PvEの管理対象Mobのみを対象とし、PvP、NPC、別world、死亡Mobは対象外とする。Blockまたは最大射程で終端した場合はダメージも連鎖も発生しない。
- 現行リポジトリには `mage_chain_lightning` の定義・executor は存在しないが、比較上の無条件複数対象連鎖とは異なり、ライトニングボルトは通常時に単体で完結し、`SHOCKED` の配置がある場合だけ追加火力を得る。
- 通常命中は `SKILL_MAGE_LIGHTNING` の青白い雷光と `ENTITY_LIGHTNING_BOLT_IMPACT` で示す。連鎖時は主対象から各感電対象へ `CONDITION_SHOCKED_SPARK` の線分を描き、主命中と連鎖を視覚的に判別できるようにする。
- Lv.5 の基礎倍率は主対象174%、連鎖48%。Lv.30の `R=151.4`、命中100%、属性耐性・会心・防御・操作時間を除いた主対象DPSは `151.4 × 1.74 ÷ 3.0 = 87.81`。感電対象を2体満たす理想条件では `151.4 × (1.74 + 0.48 × 2) ÷ 3.0 = 136.26` となり、通常時の単体性能をクイックショットより低く、条件成立時の合計を同程度へ抑える。
- 冒険者の `usableSkills` と Administrator の検証用 `usableSkills` を許可し、ジェムは `skill_gem_exchange` の1ページ目で無印原石1個から1個を交換する。初級以上の原石から個別ジェムへは直接交換しない。専用skilltree nodeは追加しない。

## 9. 冒険者マナバーストの実装契約

`adventurer_mana_burst` は、冒険者が接近した複数の敵を正面へまとめて攻撃する、無属性・魔法属性なしの基礎範囲魔法である。マスタは `v1.adventurer_mana_burst.yml`、executor は `AdventurerManaBurstExecutor`、登録先は `AdventurerSkillExecutorCatalog` とする。冒険者と Administrator が `usableSkills` で使用でき、`skill_gem_exchange` の1ページ目で無印原石1個から個別ジェム1個を交換して習得する。

### 9.1 数値と対象形状

- 発動者の目線方向を中心に、射程7m・全角60度の前方扇形へ判定する。全角は180度以下の値だけを許可し、360度の周囲攻撃へ変化できないよう executor でも検証する。
- `SkillTargetingService.inCone(player, range, angle, maxTargets, true)` を使用し、最大6体、ブロック遮蔽ありで選択する。既存の Mob 選択規則により、NPC・別world・死亡済みMob・PvP対象を除外し、Bossを含める。
- 対象は `inCone` の既存ソートで発動者の現在位置から近い順に選び、同一対象へ遅延・反復・副対象処理を行わない。したがって1回の発動で同一対象へ1回だけ命中する。
- 選択した各対象へ `MAGIC` / `NONE` の `damageRatio` 1.10（Lv.1）を1回適用する。Lv.2～5は `SKILL_DAMAGE_INCREASE +5%` を1回ずつ加え、Lv.5は132%となる。状態異常、属性効果、ノックバック、ヘイト追加処理は持たない。
- 消費MPは13、cooldownは60 tick（3.0秒）、詠唱は2 tick（0.1秒）とする。射程12m・MP10・3.5秒の単体魔法比較基準より短射程・高コストとし、単体では明確に高効率にならないようにする。

### 9.2 演出

発動者の目線から前方0.35m・下方0.25mの手元／武器先端近傍へ `MAGIC_PROJECTILE_CORE_DUST` の紫色の魔力波を複数の円弧として表示し、射程と全角を視認できるようにする。最終円弧へ `MAGIC_IMPACT_ENCHANT` を重ね、星光を含む半透明の波として表現する。選択対象ごとに `MAGIC_IMPACT_ENCHANT` と `MAGIC_IMPACT_DUST` を対象位置へ表示し、魔力粒子が弾ける命中表現とする。既存の `SkillEffectService` / `ParticleDisplayService` を経由し、直接 `World#spawnParticle` は呼び出さない。

### 9.3 テスト契約

`ActiveSkillExecutorDesignTest` は17個の built-in ID の一意性とマスタ params の必須値を検証する。`AdventurerManaBurstExecutorTest` は、射程7m・全角60度・最大6体・遮蔽判定ありの扇形選択、`MAGIC` / `NONE` の1回命中、複数対象への命中粒子、360度攻撃や状態異常処理がないことを検証する。`HunterHealArrowExecutorTest` は、強い重力、敵Mobへの固定30%ダメージ、Mob命中後の継続、Block着弾時の回復エリア、プレイヤーごとの1回回復を検証する。

## 10. シールドドレインの実装契約

`swordsman_shield_drain` は、敵のシールド破壊を主目的とする単体近接スキルである。マスタは `v1.swordsman_shield_drain.yml`、executor は `SwordsmanShieldDrainExecutor`、登録先は `SwordsmanSkillExecutorCatalog` とする。使用許可はソードマンの `usableSkills` から初期配布し、Administrator の `usableSkills` には検証用許可を残す。skilltreeには配置しない。

### 10.1 数値・対象・演出

- 発動者の前方6m・全角40度から、遮蔽のない最寄りMob 1体だけを選ぶ。既存の `SkillTargetingService.inCone` によりNPC・別world・死亡Mob・PvP対象を除外する。EN 10、cooldown 60 tick、詠唱0 tickとする。
- `MELEE` / `NONE` の基礎倍率は65%。Lv.2～5は `SKILL_DAMAGE_INCREASE +5%` を各レベルで加え、Lv.5は78%。自身の現在Shield量による追加倍率は適用しない。
- シールドダメージは通常式 `(最低1の換算値 + SHIELD_BREAK) × 3.0` とし、この一撃だけ3倍にする。HPダメージ、命中、会心、防御、属性、無敵、脅威、リチャージは既存経路を変更しない。
- `DamageResult.shieldDamage` が返す、当該hitで実際に減少した対象Shieldの50%を `StatusService.recoverShield` で自身へ加算する。対象Shieldがない、回避・無効・0ダメージ、または回復阻害中なら吸収0とし、自身の `MAX_SHIELD` を超えない。
- 青白い斬撃と対象Shield周囲の破片を表示する。実際に自身のShieldが回復した場合だけ、対象から発動者へ流れる粒子と到達4 tick後の円形Shieldを表示する。すべて `SkillEffectService` / `ParticleDisplayService` と `SharedParticleDefinitions` を経由する。

### 10.2 入手・テスト契約

API が自動生成する `00_skill_gem_swordsman_shield_drain` を、`skill_gem_exchange` の1ページ目にある個別ジェム商品として無印原石1個で販売する。`skill_gem_raw_exchange` は上位原石1個から直下位原石3個への一方向交換だけを表示する。

恒久テストは、現在Shield量にかかわらず基礎65%を維持すること、実Shield減少量50%回復、シールドが削れない場合の吸収0、実回復量0での吸収演出不使用、3倍シールドブレイク指定、catalog ID一意性を検証する。

## 11. フレイムラッシュの実装契約

`swordsman_flame_rush` は、前方の敵を炎で横薙ぎし、短い間隔の後に同じ対象へ縦斬りを重ねるソードマンの範囲近接スキルである。マスタは `v1.swordsman_flame_rush.yml`、executor は `SwordsmanFlameRushExecutor`、登録先は `SwordsmanSkillExecutorCatalog` とする。使用許可はソードマンのskilltree node `1204` とAdministratorの検証用 `usableSkills` から与える。ソードマンの `usableSkills` には追加しない。

### 11.1 数値・対象・演出

- EN 14、cooldown 80 tick、詠唱0 tick。前方6m・全角60度の遮蔽なし範囲から、距離順のMobを最大5体選ぶ。既存の `SkillTargetingService.inCone` により、PvP対象、NPC、別world、死亡Mobは選ばない。
- 初撃は火属性 `MELEE` 65%の横薙ぎ、4 tick後の二撃目は火属性 `MELEE` 75%の縦斬りとする。`SKILL_DAMAGE_INCREASE` は両方へ共通 combat 経路で適用し、Lv.10の実効倍率はそれぞれ94.25%・108.75%、合計203%となる。
- 初撃ではノックバックを適用しない。二撃目も対象を再選択せず、初撃で選択した各Mobへ1回だけ処理する。
- 二撃目の炎上付与率は、Lv.1〜7が0%、Lv.8が35%、Lv.9が40%、Lv.10が45%である。炎上DoTは既存状態異常規則に従い、20 tickごとに付与元の解決攻撃力20%を与える。
- 横薙ぎは使用者に近い半径1.6m・2.7m・3.8mのオレンジ `DUST` と `FLAME` を重ね、右から左へ6 tickで流す。縦斬りは赤 `DUST` と `FLAME` を増量して表示し、命中点へ既存の炎粒子も重ねる。表示は `SkillEffectService` / `ParticleDisplayService` 経由に限定する。

### 11.2 DPS・入手・テスト契約

- 単体のCD基準DPSは、命中100%、会心・防御・属性補正・操作時間なし、詠唱0秒で確認する。Lv.10では `R × (0.9425 + 1.0875) ÷ 4.0 = R × 0.5075`。炎上は付与20 tick後から100 tickの期限前までに4回DoTが発生するため、Lv.10の45%付与では `R × 0.20 × 4 × 0.45 ÷ 4.0 = R × 0.09` を追加する。したがって理想条件の合計は `R × 0.5975` であり、炎上を外した通常単体ではアストラルエッジLv.5の `R × 0.72` を超えない。
- APIが自動生成する `00_skill_gem_swordsman_flame_rush` は存在するが、依頼範囲では交換ショップへ追加しない。
- 恒久テストは、catalog ID一意性、前方5体上限、初撃のノックバック不使用、右から左へ6 frameの横薙ぎ演出、4 tick後の二撃目、Lv.1〜7では炎上なし・Lv.8/9/10では二撃目へ35%/40%/45%の炎上判定が付くことを検証する。

## 12. チャレンジングロアの実装契約

### 17.1 数値・対象・消費

- Lv.1は詠唱40 tick（2秒）、cooldown 240 tick（12秒）、主ENG 16、副MP 8とする。共通サービスが両残量を事前検証し、成功時だけ両方を消費する。

### 17.2 弾道

雨矢の始点は雨開始時点のプレイヤー目線位置から5m上空を基準に、水平方向1.25m・高さ0.45mの乱数を加える。終点は半径内へ面積一様となる `radius × sqrt(random)` で選び、着弾地点付近から上下にsolid floorと通過可能な足元を探索する。飛翔時間は10〜14 tickから選び、毎tick移動後に0.14m/tick²の重力を加えて指定終点へ届く離散初速を計算する。各矢の最大移動距離はこの離散弾道の全step長に0.25mの許容値を加えて決め、深い地表でも固定上限で途中終了させない。雨矢のBlock判定は初弾の正確な着弾Yを排他的上限とし、そのY以上の線分区間ではBlockを貫通する。着弾Yより低い区間では従来どおり最初のBlockで終了する。全雨矢を1つの反復taskで管理し、同tickの軌跡粒子はviewer探索をまとめて表示する。

### 17.3 バランス・テスト契約

終点面積だけでなく、プレイヤー頭上から着弾円へ収束する途中の全線分を実衝突と同じ拡張AABBで評価する。通常幅0.6mの中心静止Mob、遮蔽なし、距離3〜18mの決定的シミュレーションでは、単体への雨矢期待命中はLv.1で約12.0〜15.3本、Lv.5で約7.5〜13.8本となる。Lv.5のCD＋詠唱周期DPSは `R × (0.84 + 0.36 × 7.5〜13.8) ÷ 14 = R × 0.253〜0.415` とする。全81本が別対象へ有効命中する理想分散上限は `R × 2.143` であり、対象密度と地形の影響を受ける範囲攻撃として扱う。

## 19. ヒールアローの実装契約

`hunter_heal_arrow` は、強い重力で落下する矢を敵または地形へ着弾させ、各命中地点へ味方を回復するエリアを作るハンターの支援射撃である。マスタは `v1.hunter_heal_arrow.yml`、executor は `HunterHealArrowExecutor`、登録先は `HunterSkillExecutorCatalog` とする。使用許可はハンターの skilltree node `1213` と Administrator の検証用 `usableSkills` から与え、ハンターの class `usableSkills` には追加しない。

### 19.1 数値・対象・終端

- 基礎クールダウンは200 tick（10秒）、Lv.2～5で各10 tick短縮し、Lv.5は160 tick（8秒）とする。消費は ENERGY 14、詠唱は0 tick、最大Lv.5とする。回復量はLv.1～5で12 / 16 / 20 / 24 / 28、レベル差分は `params.healAmount` へ加算する。
- 発動時の視線方向へ初速 `params.projectileSpeed: 1.25` の仮想矢を1本発射し、`gravityPerTick: 0.14` の下向き加速度を毎tick適用する。矢はMob命中後も消えずに貫通し、Blockへヒットするまで飛翔を継続する。無衝突時はサーバー保護のため80 tickまたは飛翔距離48mでRANGE終端とし、RANGEでは回復エリアを作らない。
- 各敵Mobへの命中は同じ矢から1回だけとし、`RANGED` / `NONE` の `damageRatio: 0.30` を適用して、そのMob命中地点へ回復エリアを作る。Block衝突時も正確なBlock衝突地点へ回復エリアを作る。プレイヤー、NPC、別worldのMobはMob projectile対象に含めない既存Mob判定へ従う。
- 回復エリアは水平半径2m、上下許容差2m、持続60 tick（3秒）とする。登録済みでゲームプレイ中のプレイヤーを毎tick検索し、そのエリアで最初に検出した1回だけ `SkillCombatService` 経由で `StatusService.recoverHp` を呼ぶ。発動者も回復対象に含み、回復阻害・最大HP上限・`HEALING_INCREASE` は既存のStatusService規則を適用する。Mobへの回復、PvPダメージ、同一エリア内の再入場による再回復は行わない。

### 19.2 演出・入手・テスト契約

矢の軌跡、着弾、エリア輪郭、実回復時の表示は `SharedParticleDefinitions` の緑系定義と `SkillEffectService` を経由して表示する。エリア輪郭は5 tick間隔で更新し、常時大量の粒子を生成しない。発動と着弾には既存の矢／Beacon系サウンドを使用する。APIが自動生成する `00_skill_gem_hunter_heal_arrow` は、`skill_gem_exchange` の1ページ目・slot15で無印原石1個から1個を交換する。

恒久テストは、catalog ID一意性、必須paramsと敵Mob倍率30%の固定、初速と重力値、Mob命中後の継続、Block終端、RANGE終端でのエリア非生成、半径内プレイヤーへの即時回復、同一エリアでのプレイヤー単位の1回制限、回復阻害・上限を反映した実回復量、task lifecycleでの破棄を検証する。
## 20. スペルステップの実装契約

`hunter_spell_step` は、遠隔スキルの成功後に次のドッジを1回だけ無償化するハンター用バインド必須パッシブである。マスタは `v1.hunter_spell_step.yml`、executor は `HunterSpellStepSkillExecutor`、runtime は `SpellStepSkillRuntimeService` とする。使用許可はハンターの skilltree node `1207` から与え、ハンターの class `usableSkills` には追加しない。自動生成ジェム `00_skill_gem_hunter_spell_step` は `skill_gem_exchange` の1ページ目で無印原石1個から交換する。

### 20.1 発動条件・消費・演出

- `SkillService` の成功通知で、成功したスキル定義に共有タグ `ranged` が含まれる場合だけ、20tick（1秒）の待機権を作る。失敗したスキル、`ranged` タグのないスキル、パッシブ自身の有効化は待機権を作らない。同じプレイヤーに複数の遠隔スキル成功が続いた場合も待機権は1回分だけとし、期限を最新成功から20tickへ更新する。
- `DodgeService` は通常の受付条件を満たした後に待機権を一度だけ消費し、該当ドッジのEN消費を0にする。待機権がない場合は既存のEN15消費を使い、エネルギー不足時は従来どおりドッジを実行しない。無料化はドッジの移動、無敵判定、通常ドッジ音、成功通知を変更しない。
- 無料化成立時は `params.triggerSound` の音（`block.beacon.power_select`、volume 0.8、pitch 1.3）を `SoundCategory.PLAYERS` で再生する。追加パーティクル、ダメージ、状態異常、PvP効果は持たない。死亡・ワールド移動では待機権を破棄し、退出・パッシブ解除・Plugin停止では設定も破棄する。

### 20.2 テスト契約

恒久テストは、`ranged` タグ付き成功後だけ20tick以内の次回ドッジを無料化すること、権利を同じドッジへ二重適用しないこと、20tick経過後・非遠隔スキル・パッシブ解除後は無料化しないこと、無料化成立時の発動音設定検証、死亡・ワールド移動・退出の状態破棄、executorの固定20tick・sound key・音量・音程パラメータ検証を確認する。

## 21. メイジファイアーボールの実装契約

`mage_fireball` は、火球を最初の敵または地形へ着弾させ、小範囲を攻撃するメイジの初期範囲魔法である。マスタは `v1.mage_fireball.yml`、executor は `MageFireballExecutor`、登録先は `MageSkillExecutorCatalog` とする。メイジとAdministratorの `usableSkills` から使用許可を与え、APIが自動生成する `00_skill_gem_mage_fireball` は `skill_gem_exchange` の1ページ目・slot17で無印原石1個から交換する。専用skilltree nodeは追加しない。

### 21.1 数値・対象・終端

- MP 12、cooldown 80 tick（4秒）、詠唱4 tick（0.2秒）、最大Lv.5とする。Lv.2〜5は各 `SKILL_DAMAGE_INCREASE +5%` を加え、Lv.5の実効倍率は132%となる。
- 発動時の照準方向へ、射程16m・速度1.45m/tick・当たり半径0.45mの重力なし・非貫通仮想火球を1本だけ発射する。最初のMobまたはBlockに着弾したときだけ起爆し、最大射程への無衝突到達ではダメージ、爆発、状態異常を発生させない。
- 着弾地点を中心に、水平半径2.25m・上下2.25m・ブロック遮蔽ありのMobを距離順で最大4体まで選び、各対象へ `MAGIC` / `FIRE` の基礎倍率110%を1回だけ適用する。NPC、PvP対象、別world、死亡Mobは既存の対象選択規則により除外し、Bossは対象に含める。持続エリア、炎上、ノックバック、同一発動内の再命中は発生させない。
- Block着弾では表示用の正確な衝突地点と、遮蔽判定・範囲効果用の手前側中心を `SkillProjectileTermination` から分けて使用する。起爆はentity/blockのどちらから通知されても1回だけとする。

### 21.2 演出・DPS・テスト契約

- 飛翔中はフレイムラッシュの橙色・赤色の `DUST` 表現を基にした `MAGE_FIREBALL_TRAIL` を使い、ランダムな粉塵の広がりで火球の球体を表示する。着弾時は `MAGE_FIREBALL_IMPACT` と既存の `SKILL_MAGE_FIRE` を重ね、`ENTITY_GENERIC_EXPLODE` を小さめの音量で1回鳴らす。すべて `SkillProjectileService`、`SkillEffectService`、`SharedParticleDefinitions` を経由し、直接のparticle生成は行わない。
- 単体のCD基準DPSは、命中100%、会心・防御・属性補正・操作時間なしで、Lv.5の `R × 1.32 ÷ (4.0 + 0.2) = R × 0.314` とする。ライトニングボルトLv.5の `R × 0.544` より単体を低く保ち、半径内の複数Mobへ有効命中した場合だけ総ダメージが増える範囲魔法として扱う。
- 恒久テストは、catalogの17 ID一意性、Lv.5・射程16m・半径2.25m・最大4体のfilebase値、橙色球体の飛翔体定義、敵／Block着弾での `MAGIC` / `FIRE` 範囲hit、Range終端での非起爆を検証する。

## 22. メイジ ヒールオーラの実装契約

`mage_heal_aura` は、発動者の周囲へ即時回復を行うメイジの短周期支援魔法である。マスタは `v1.mage_heal_aura.yml`、executor は `MageHealAuraExecutor`、登録先は `MageSkillExecutorCatalog` とする。メイジのclass `usableSkills` とAdministratorの検証用 `usableSkills` から使用許可を与える。

### 22.1 数値・対象・回復

- 基礎クールダウンは40 tick（2.0秒）で、Lv.2〜5は各2 tick短縮し、Lv.5は32 tick（1.6秒）とする。消費はMP 6、詠唱は0 tick、最大Lv.5とする。回復量はLv.1〜5で5 / 6 / 7 / 8 / 9とし、レベル差分は `params.healAmount` へ加算する。
- 発動者の現在位置を中心に、水平半径4m・上下3m内のゲームプレイ中プレイヤー全員を `SkillTargetingService.playersInRadius` で取得する。発動者自身も含め、Party所属、PvP、視線、Mobは対象条件にしない。別world、死亡、観戦などゲームプレイ対象外のプレイヤーは共通サービスで除外する。
- 各対象へ1回だけ `SkillCombatService.recoverHp` を呼び、最大HP、回復阻害、回復量増加を既存の `StatusService` 規則へ委ねる。ダメージ、状態異常、ヘイト、継続タスクは発生させない。

### 22.2 演出・入手・テスト契約

発動位置へ半径4mの紫色particleリングと中心pulseを即時表示し、効果半径を確認できるようにする。実際にHPが増えたプレイヤーには `HAPPY_VILLAGER` の回復particleを重ねる。すべて `SharedParticleDefinitions` と `SkillEffectService` を経由し、直接particle送信は行わない。発動音はBeacon系を使う。APIが自動生成する `00_skill_gem_mage_heal_aura` は、`skill_gem_exchange` の1ページ目・slot18で無印原石1個から1個を交換する。

恒久テストは、catalog ID一意性、正の半径・高さ・回復量の必須検証、本番マスタの最大Lv・コスト・params、範囲内の全プレイヤーへの即時回復、範囲輪郭・実回復particle表示を確認する。
## 23. メイジ スパーキングの実装契約

`mage_sparking` は、Path of Exile 2のSparkをモチーフに、発動者の周囲へ壁面反射する雷弾を放つメイジ用の範囲制圧魔法である。マスタは `v1.mage_sparking.yml`、executorは `MageSparkingExecutor`、登録先は `MageSkillExecutorCatalog` とする。使用許可はメイジskilltree node `1208` とAdministratorの検証用 `usableSkills` から与え、メイジclassの `usableSkills` には追加しない。

### 23.1 数値・弾道・対象

- MP14、cooldown160tick（8秒）、詠唱4tick（0.2秒）、最大Lv.5とする。雷弾数はLv.1の5個からレベルごとに2個増え、Lv.5は13個となる。ダメージ倍率、感電率、寿命はレベルで増加させない。
- 足元から0.75mの位置を共通始点とし、発動時yawを基準に水平360度へ雷弾を等間隔で放つ。各弾は速度0.65m/tick、命中半径0.45m、寿命50tick（2.5秒）とし、重力・追尾・上下方向の初速を持たない。
- `SkillTargetingService.blockHit` が返す正確なBlock面と外向き面法線を使い、`v' = v - 2(v・n)n` で鏡面反射する。衝突面の前後へ最大0.05m離して表示終端と反射後始点を置き、同じ面への即時再衝突を避ける。反射後はそのtickの残り移動距離を同tick内で進み、異常な狭所に対する安全上限を1tick最大4反射とする。水は既存Block判定と同様に遮蔽扱いしない。
- 各雷弾は最初に触れた管理対象Mobへ `MAGIC` / `LIGHTNING` 100%を1回与えて消滅する。同じ発動の別雷弾が命中済み対象へ触れた場合も、その場で消滅して奥の対象へ貫通させない。再ダメージは与えず、単体倍率は最大100%とする。命中対象には25%で `SHOCKED` を100tick付与する。PvP、NPC、別world、死亡Mobは既存Mob判定で除外する。
- 全雷弾を発動単位の1つの反復taskで進め、同tickのMob候補snapshotとviewer探索を共有する。退出・死亡・world変更・Plugin停止では既存task lifecycleにより破棄する。

### 23.2 バランス・入手・演出・テスト契約

- 単体CD基準はSkill Lv.5、命中100%、会心・防御・属性補正・操作時間なしで `R × 1.00 ÷ (8.0 + 0.2) = R × 0.1220` とする。感電は100tick期限前の4回DoTを期待値で分け、25%付与時は1発動あたり `R × 0.10 × 4 × 0.25 = R × 0.10` を追加評価する。雷弾数増加は複数対象への命中機会に配分し、単体倍率へ加算しない。
- 軌跡は既存 `SKILL_MAGE_LIGHTNING`、命中点は `CONDITION_SHOCKED_SPARK` を使い、発動時に低音量の雷鳴、命中時に雷撃音を再生する。粒子は `SkillEffectService.lines` で同tickの全線分を一括表示し、`ParticleDisplayService` のviewer探索を共有する。
- APIが自動生成する `00_skill_gem_mage_sparking` は、`skill_gem_exchange` の1ページ目・slot19で無印原石1個から交換する。node解放は使用許可だけを与え、習得済み個体はジェム消費で作成する既存規則を維持する。
- 恒久テストは、catalogの17 ID一意性、5 / 7 / 9 / 11 / 13個のレベル成長、360度等間隔の初速、面法線による反射、50tick寿命、Block手前のMob優先、同一発動内の対象重複抑止、100%雷魔法ダメージ、25%・100tickの感電、node `1208` と仮想ジェム参照を検証する。
