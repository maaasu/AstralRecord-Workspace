# 13_1-モデル定義

## 1. スキル定義

物理名: `SkillDefinition`

| 項目 | 内容 |
|---|---|
| `id` | スキルマスタ ID |
| `implementationId` | `SkillExecutor` の解決キー |
| `name`, `description`, `icon`, `lore`, `tags` | 表示・分類情報 |
| `cooldownTicks`, `castTimeTicks`, `requiredLevel` | Lv.1 の共通発動制御値 |
| `resourceType`, `resourceCost` | 主消費リソース。`MANA` / `ENERGY` / パラディン専用`GUARD`。旧定義では `manaCost` を主MP消費へ正規化する |
| `manaCost` | 通常は旧MP定義との互換入力。`resourceType: ENERGY` と併記した正数だけは副MP消費 |
| `cooldownId` | プレイヤー内の cooldown 共有キー。未指定時は `id` |
| `maxLevel` | スキル個体の最大レベル。スキルごとに定義 |
| `levels` | 各レベルで前レベルから加える cooldown・cost・cast time・params・status の差分 |
| `sigilSlotsByLevel` | 到達レベル以下で有効なシジル装着可能数 |
| `allowedSigilIds` | 装着を許可するシジル ID |
| `kind` | `ACTIVE` / `PASSIVE` |
| `passiveBindRequired` | パッシブスロットへの設定を発動条件にするか |
| `params` | Executorと説明文で共有する実効パラメータ。レベル差分を適用後、発動と表示の両方で使用する |

レベル差分は Lv.2 から `maxLevel` まで定義し、対象レベルまでを累積する。

## 2. 習得済みスキル個体

物理名: `LearnedSkillInstance`、`LearnedSkillSigil`

`LearnedSkillInstance` は `learnedSkillId`（UUID）、account ID、skill ID、level、version、装着済みシジルを保持する。同じ skill ID・level・シジル構成の個体を個数制限なく所持でき、バインドは skill ID ではなく `learnedSkillId` を保存する。

`LearnedSkillSigil` は装着行 UUID、sigil ID、`equipGroupId`、slot index を保持する。シジル装着では対応する SIGIL_ATTACH オーブとシジルを各1個消費し、シジル脱着では対応する SIGIL_DETACH オーブを1個消費して、指定した装着行のシジルを所持品へ1個返却する。同一個体へ同じ `equipGroupId` を複数装着しない。

## 3. 解決済みスキル

物理名: `ResolvedLearnedSkill`

習得レベルまでの差分と、有効な装着済みシジルの補正を基礎定義へ合成した発動時スナップショットを保持する。シジル ID 集合も executor へ渡し、ロジック変更型シジルは executor が ID を判定する。ステータス型シジルは同じ status への値を加算する。

`description` / `lore` に `{skill.<param>}` 形式のプレースホルダーを指定した場合、GUIはこの解決済みスナップショットの `params` を使って展開する。`cooldownTicks` など top-level 共通値のプレースホルダーは、同じ解決済みスキル定義の値を使う。展開されたプレースホルダー値は黄色で表示し、数値は小数第2位を四捨五入して小数第1位まで（末尾の0は除去）に整形する。`percent` 書式、配列の index 指定、配列全体の列挙に対応し、`SKILL_DAMAGE_INCREASE` は `effectiveDamageRatio` / `effectiveDamageRatios` の計算値へ反映する。Executorも同じ解決済み `params` を参照し、表示値と発動値を分離しない。

## 4. 所持と使用許可

所持の正本は API からロードした `LearnedSkillInstance` だけである。使用許可は、現在クラスの `usableSkills`、現在表示・効果有効な解放済みスキルツリーノードの skill effect、装備中の `SKILLBOOK` マスタの `usableSkills` の和集合である。スキルブックを外すと、その装備由来の許可は失われる。

所持個体は許可がなくてもバインドできる。発動には所持個体と使用許可の両方が必要で、許可だけではバインドも発動もできない。クラス変更やノード再ロックで許可を失ってもバインド値は維持する。

## 5. バインドプリセット

物理名: `SkillBindPreset`

1アカウントにつきプリセット9個を持ち、各プリセットは発動12枠、左クリック1枠、パッシブ12枠を共有して保持する。発動枠の先頭8枠だけをaction ringへ表示し、9番以降はスキルキャストディスクで指定できる。初期状態で設定可能な発動枠は先頭9枠で、CURRENCY inventoryのアクティブ枠解放トークン1個につき1枠を追加し、最大12枠まで実効解放する。空値は `null`。初期解放は1..3とし、API由来の`isUnlocked`に加えて、CURRENCY inventoryのプリセット解放トークン1個につき未解放プリセットを1つ実効解放する（最大6個）。この所持数による解放はAPIへ永続化しない。選択中のプリセットは`isSelected`で永続化し、ログイン時に復元する。

`__weapon_normal_attack__` は左クリック用の予約値であり、現在主手武器の `SWORD` / `HAMMER` / `SPEAR` / `BOW` / `SHORTBOW` / `LONGBOW` / `WAND` / `STAFF` タグからシステム通常攻撃を都度解決する。通常攻撃に所持・使用許可は不要である。

## 6. スキルマネージャーセッション

物理名: `SkillBindSession`、`SkillBindInventoryHolder`、`SkillBindScreen`、`SkillBindType`

セッションは9プリセット、選択プリセット、active・left-click・passive の下書き、下段設定枠の横スクロール位置、選択中バインド枠、dirty・保存中状態、習得処理中のスキル IDを保持する。プレイヤーが操作する画面は `MAIN` / `CONFIRM`、バインド種別は `LEFT_CLICK` / `ACTIVE` / `PASSIVE` とする。旧 `SYNTHESIS` 画面への操作導線は提供しない。

## 7. パッシブスロット数

基本値は5枠。`PASSIVE_SKILL_SLOTS` の値1と、CURRENCY inventoryのパッシブスロット解放トークン1個につき1枠を加え、最大12枠とする。トークンは所持中に反映し、枠数が減っても超過位置の保存済みバインドは削除しないが、その枠は発動対象にしない。超過枠は解除だけ可能で、新規設定はできない。

## 8. 習得素材とシジルのアイテムモデル

物理名: `ItemSigil`、`ItemSigilModifier`

スキルの習得・レベルアップ素材は skill master の `learnRequiredItems` / `levelUpRequiredItems` に item ID と数量で定義する。未指定の段階は素材なしで実行でき、指定時はスキルマネージャーが必要なインベントリentryを消費する。プレイヤーへ送信する表示コピーには、現在のクラスで使用可能なスキルと有効なスキルツリーノードを基に `現在使用可能: はい` または `現在使用可能: いいえ` を表示する。

シジルは `sigil` カテゴリの filebase アイテムで、`equipGroupId` と任意の status modifier を持つ。装着可否とスロット数はスキル定義側を正本とし、装着・脱着は対応するシジル用オーブから行う。

## 9. caster / context / executor

`SkillCaster` は caster UUID、level、status、MP・ENG、通知を抽象化する。`SkillCastContext` と `PassiveSkillContext` は解決済み定義、習得個体、有効シジル ID を executor へ渡す。パッシブに cooldown は適用しない。

## 10. スキルツリー

### node definition

`SkillTreeSkillEffect` はスキルを習得させず、現在有効な間だけ使用許可を追加する。CPノードはクラス・プレイヤーレベル条件を満たさない場合に非表示とし、PPノードは条件を表示するため表示を維持する。いずれも条件未達時は許可を含む効果を無効化する。解放状態はアカウント単位で保持し、再ロックで許可を失う。

同じクラス条件では同じskill IDの使用許可を複数nodeへ定義しない。クラス条件が異なる場合だけ同じskill IDを許可できる。

### structure snapshot

配置node、root、無向edge、絶対座標を不変snapshotとして保持する。

### player state

account単位の解放node ID、class point消費元、ロード世代を保持する。
