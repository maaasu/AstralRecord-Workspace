# 12_1-モデル定義

## 1. ドメインモデル

`mob` 機能は、API から取得する **テンプレート系** モデル群と、ワールド上の **実体系** モデル群、AI 駆動のための **状態系** モデル群で構成される。

| 区分 | モデル | 役割 |
|---|---|---|
| テンプレート系 | [[12_1-モデル定義]].Mob テンプレート 等 | API から取得する静的定義 |
| 実体系 | [[12_1-モデル定義]].Mob インスタンス | ワールド上に生成された実体 |
| 状態系 | [[12_1-モデル定義]].Mob 戦闘状態 / [[12_1-モデル定義]].脅威値テーブル | tick 単位で変動する AI 状態 |

## 2. Mob テンプレート

物理名: `MobTemplate`

API `GET /api/mob/{mobId}` から取得する Mob 定義の表現。

### 2.1 項目

- `schemaVersion`
- `id`
- `category`: [[12_1-モデル定義]].Mob カテゴリ
- `displayName`（API では `name`）
- `title`（任意）
- `level`: Mob の既定実効レベル。`levels` 未指定時、または指定レベルが見つからない時は `levels` の最小レベルを使用する。撃破経験値補正と頭上表示に使用し、プレイヤー側はアカウントレベルのみを参照する。
- `levelProfiles`: 同一マスタ内のレベル別実効プロファイル一覧。共通定義から部分上書きした値を保持する。
- `entityType`: Bukkit `org.bukkit.entity.EntityType`。通常は Bukkit `Mob` を生成し、固定表示用 `ARMOR_STAND` は Bukkit `ArmorStand` を生成する。NPC の場合は Bukkit block `Material` 名も許容する。通常 block は配置座標を中心にした `BlockDisplay` fakeblock として扱う。`CHEST` / `TRAPPED_CHEST` / `ENDER_CHEST` は元 Material の `ItemStack` を使う `ItemDisplay` とし、`BARREL` へ正規化しない
- `nameVisible`
- `icon`（任意）
- `lore`
- `tags`
- `skin`: [[12_1-モデル定義]].Mob スキン設定（任意。`entityType = PLAYER` の場合に主に使用）
- `variant`: `MobVariantConfig`。同一マスタから生まれる実体 Mob の見た目差分を固定する設定。未指定時は `age: ADULT`。
- `equipment`: [[12_1-モデル定義]].Mob 装備設定
- `baseStats`: [[12_1-モデル定義]].Mob ベースステータス のリスト
- `shield`: [[12_1-モデル定義]].Mob Shield 設定。未指定時は Shield なし
- `idle`: [[12_1-モデル定義]].Mob 待機設定
- `interactions`: [[12_1-モデル定義]].Mob インタラクション設定（NPC クリック定義。未指定時は空設定）
- `targeting`: [[12_1-モデル定義]].Mob ターゲット設定（`NPC` の場合は `null`）
- `combat`: [[12_1-モデル定義]].Mob 戦闘設定（`NPC` の場合は `null`）
- `drops`: [[12_1-モデル定義]].Mob ドロップ設定（`NPC` の場合は `null`）

## 3. Mob カテゴリ

物理名: `MobCategory`

| 値 | 意味 |
|---|---|
| `ENEMY` | 通常エネミー。`targeting` / `combat` / `drops` を持つ |
| `BOSS`  | ボスエネミー。`ENEMY` と同一構造だが、固有ギミックはプラグイン側で個別実装 |
| `NPC`   | 非戦闘 NPC。`targeting` / `combat` / `drops` は持たない（`null`） |

NPC は `interactions` により左クリック・右クリック時のアクションを宣言できる。実行系は `id` と `params` を見て、メッセージ送信や GUI 起動などの処理へ接続する。

文字列からのカテゴリ解決（物理名: `from`）は、大小区別なし・前後空白除去で判定し、未知値は `ENEMY` にフォールバックする。

## 4. Mob ベースステータス

物理名: `MobBaseStat`

| 項目 | 型 | 説明 |
|---|---|---|
| `status` | `String` | `StatusType` 名（例: `MAX_HEALTH`） |
| `value` | `double` | ステータス値。各 `StatusType` の単位定義に従う |

正本: [[07_1-モデル定義]].StatusType。`StatusType` に存在しない名前は読み込み時にスキップしてログ記録する。

### 4.1 Mob Shield 設定

物理名: `MobShieldConfig`

| 項目 | 型 | 説明 |
|---|---|---|
| `enabled` | `boolean` | Shield の有効可否 |
| `max` | `double` | 初回 spawn 時の Shield 値 |
| `rechargeTimeSeconds` | `double?` | Shield 破壊から一括回復までの秒数。未設定の Mob は自動回復しない |
| `rechargeAmount` | `double?` | リチャージ完了時の Shield 値。未設定時は `max` |

`rechargeAmount` は初期値 `max` の上限には制限されない。たとえば `max=100`、`rechargeAmount=50` なら完了後の現在値と表示容量は 50、`rechargeAmount=500` なら完了後は 500 とする。各リチャージ周期では、回復量をその周期の満タン表示容量として扱う。

## 5. Mob スキン設定

物理名: `MobSkin`

| 項目 | 型 | 説明 |
|---|---|---|
| `texture` | `String?` | Base64 エンコード済みスキンテクスチャ値 |
| `signature` | `String?` | テクスチャ署名値 |

`entityType = PLAYER` の NPC だけが参照する。`texture` と `signature` の両方が設定された場合、実体の当たり判定用 Entity をクライアントから隠し、ProtocolLib の擬似 Player として表示する。擬似 Player の GameProfile はスキン解決のため 20 tick tab list に保持した後、一覧から非表示にする。

`PLAYER` は Bukkit Entity として直接 spawn しない。実体は NPC 用の Entity として保持し、クリック判定・配置・移動の基準に使用する。片方でも未設定の場合は擬似 Player 表示を行わず、実体 Entity の通常表示を使用する。

実体 Mob の現在 yaw / pitch と `lookAt` から算出した頭部 yaw / pitch は `MobInstance` に保持し、viewer ごとの擬似 Player へ `ENTITY_LOOK` と `ENTITY_HEAD_ROTATION` で反映する。頭上の Mob TextDisplay は隠された実体 Entity の passenger ではなく、擬似 Player の足元から固定高さで追従させる。擬似 Player の内部 GameProfile 名は viewer の名前タグへ表示しない。

### MobVariantConfig

同一マスタの Mob がランダムな見た目差分を持たないようにするための設定。未指定時は `age: ADULT` として扱う。

| 項目 | 型 | 説明 |
|---|---|---|
| `age` | `ADULT` / `BABY` | Ageable Mob の大人 / 子供表現。spawn 時に設定し、age lock で固定する。 |
| `kind` | `String?` | Cat / Rabbit / Fox / Frog / Axolotl / Parrot / Mooshroom などの種類。対応する Bukkit setter の値名を指定する。 |
| `color` | `String?` | Sheep / Horse / Llama などの色。対応する Bukkit setter の値名を指定する。 |
| `style` | `String?` | Horse などの模様。対応する Bukkit setter の値名を指定する。 |
| `profession` | `String?` | Villager / ZombieVillager の職業。Paper `Villager.Profession` の値名を指定する。 |
| `villagerType` | `String?` | Villager のバイオーム種別。Paper `Villager.Type` の値名を指定する。 |
| `villagerLevel` | `Integer?` | Villager の取引レベル。1 から 5 の範囲へ補正して適用する。 |
| `pattern` / `bodyColor` / `patternColor` | `String?` | TropicalFish などの模様・体色・模様色。対応する Bukkit setter の値名を指定する。 |
| `mainGene` / `hiddenGene` | `String?` | Panda の主遺伝子・隠し遺伝子。対応する Bukkit setter の値名を指定する。 |

名前付きの差分は大小文字を区別せず解決する。Java enum に加え、Paper 1.21.11 で `OldEnum` interface として提供される `Villager.Profession` / `Villager.Type` も解決対象とする。対象 Entity に対応 setter がない場合、または値名を解決できない場合は、その差分だけを反映せず既定外見を維持する。

## 6. Mob 装備設定

物理名: `MobEquipmentConfig`

| 項目 | 型 | 説明 |
|---|---|---|
| `mainHand` | `String?` | Minecraft 標準の Material 名（例: `IRON_SWORD`） |
| `offHand` | `String?` | Minecraft 標準の Material 名 |
| `helmet` | `String?` | Minecraft 標準の Material 名 |
| `chestplate` | `String?` | Minecraft 標準の Material 名 |
| `leggings` | `String?` | Minecraft 標準の Material 名 |
| `boots` | `String?` | Minecraft 標準の Material 名 |

API レスポンスの各値は Minecraft 標準の Material 名として解決し、対応する `ItemStack` を Bukkit の実体 Mob の該当スロットへ設定する。`item:...` のようなアイテムマスター参照や解決できない値は装備へ反映しない。
装備は表示のみに使用し、ダメージや防御値には影響しない（独自ステータス計算のため）。

## 7. Mob 待機設定

物理名: `MobIdleConfig`

| 項目 | 型 | 説明 |
|---|---|---|
| `behavior` | [[12_1-モデル定義]].待機行動 | 待機時の行動パターン |
| `wanderRadius` | `double` | `WANDER` 時の徘徊半径 |
| `speed` | `double` | 待機時の移動速度倍率（1.0 = Paper Pathfinder に渡す標準倍率） |

## 8. 待機行動

物理名: `IdleBehavior`

| 値 | 意味 |
|---|---|
| `STATIONARY` | スポーン地点から動かない |
| `WANDER` | スポーン地点を中心にランダム徘徊。NPC は定期リセットと詰まり検知の対象 |
| `PATROL` | 予約値。現行は経路定義と巡回処理を持たず、IDLE 時に pathfinding を停止する |

## 9. Mob ターゲット設定

物理名: `MobTargetingConfig`

| 項目 | 型 | 説明 |
|---|---|---|
| `strategy` | [[12_1-モデル定義]].ターゲット戦略 | ターゲット選定方式 |
| `aggroRange` | `double` | 敵対検知範囲（ブロック単位） |
| `deaggroRange` | `double` | 敵対解除距離。`aggroRange * 2` がデフォルト |
| `leashRange` | `double` | スポーン地点からの最大追跡距離。超えるとリセット |
| `retaliateOnly` | `boolean` | 攻撃を受けるまで自動索敵せず、待機行動（`WANDER` ならスポーン地点周辺の徘徊）を継続する。攻撃を受けた後のみターゲット選定を行うか |

## 10. ターゲット戦略

物理名: `TargetStrategy`

| 値 | 意味 |
|---|---|
| `NEAREST` | 最も近いプレイヤー |
| `HIGHEST_THREAT` | [[12_1-モデル定義]].脅威値テーブル の値が最大のプレイヤー |
| `RANDOM` | 範囲内のプレイヤーからランダム |
| `LOWEST_HP` | プレイヤー側 `AstPlayer` の現在 HP が最低のプレイヤー |

## 11. Mob 戦闘設定

物理名: `MobCombatConfig`

| 項目 | 型 | 説明 |
|---|---|---|
| `style` | [[12_1-モデル定義]].戦闘スタイル | 戦闘スタイル |
| `preferredRange` | `double` | 戦闘時に維持したい理想距離。スキル発動距離ではない |
| `normalAttack` | `MobNormalAttackConfig?` | 通常攻撃の距離と間隔。`null` なら直接通常攻撃をしない |
| `skills` | `List<MobSkillBinding>` | Mob master が参照する Mob 専用スキル ID と少数の数値パラメーター |

Mob スキルのロジック、許可パラメーター、既定 timing、演出は、ID ごとの `MobSkillExecutor` を正本とする。Mob master は ID と timing 上書き、少数の数値パラメーターだけを持つ。player の skill master / gem とは混在させない。`preferredRange` は遠距離 / 魔法 Mob の後退・左右移動など、間合い維持の基準として扱う。

## 12. 戦闘スタイル

物理名: `CombatStyle`

| 値 | 意味 |
|---|---|
| `MELEE` | 近接戦闘。スキル発動距離まで接近して攻撃し、`preferredRange` は理想距離として扱う |
| `RANGED` | 遠距離戦闘。距離を保ちつつ攻撃。スケーリングは `DEXTERITY` |
| `MAGIC`  | 魔法戦闘。距離を保ちつつ攻撃。スケーリングは `INTELLIGENCE` |

## 13. Mob インタラクション設定

物理名: `MobInteractionsConfig`

| 項目 | 型 | 説明 |
|---|---|---|
| `leftClick` | `List<MobInteractionActionConfig>` | 左クリック時に実行するアクション一覧 |
| `rightClick` | `List<MobInteractionActionConfig>` | 右クリック時に実行するアクション一覧 |

未指定時は `MobInteractionsConfig.EMPTY` として空配列を保持する。NPC 以外のカテゴリでは現行実装上は空設定として扱う。

## 14. Mob インタラクションアクション

物理名: `MobInteractionActionConfig`

| 項目 | 型 | 説明 |
|---|---|---|
| `id` | `String` | アクション ID。初期定義は `message` / `gui` / `command` / `restore_status` |
| `params` | `Map<String, String>` | アクションごとのパラメータ |

`MobRepository.parseTemplate` は API から返る `interactions.leftClick[]` / `interactions.rightClick[]` を読み取り、`params` のプリミティブ値を文字列として保持する。

初期定義:

| `id` | `params` | 説明 |
|---|---|---|
| `message` | `message` | プレイヤーに送るメッセージ本文 |
| `gui` | `type` | 開く GUI の種類（例: `SHOP`, `SELL`, `CLASS`, `STORAGE`）。装備加工系 GUI は使用不可 |
| `command` | `command` | プレイヤーとして実行するコマンド文字列。先頭の `/` は任意 |
| `restore_status` | （なし） | 現在の HP / MP / EN / Shield を最大値まで回復する。回復阻害中も実行する |

`gui.type=SHOP` は NPC interaction 専用の開き方として shop feature へ通知する。この導線では `access=NPC_ONLY` のショップを開けるが、同じショップは `/shop` やメニュー導線からは開けない。

## 15. Mob ドロップ設定

物理名: `MobDropConfig`

| 項目 | 型 | 説明 |
|---|---|---|
| `exp` | `int` | 撃破時の基礎経験値。受取人のプレイヤーレベルと Mob レベルの差に応じて補正する |
| `money` | [[12_1-モデル定義]].Mob 金銭ドロップ | 金銭ドロップ。`null` 許容 |
| `items` | `List<MobDropItem>` | ドロップアイテム一覧 |
| `lootTable` | `String?` | 既存 LootTable の ID。`MobRepository.parseTemplate` で prefix `loot_table:` を除去した素の ID を保持 |

`items` と `lootTable` は併用可能。両方指定時はそれぞれ独立に抽選する。

## 16. Mob 金銭ドロップ

物理名: `MobMoneyDrop`

| 項目 | 型 | 説明 |
|---|---|---|
| `min` | `int` | 最小値（両端含む） |
| `max` | `int` | 最大値（両端含む） |

撃破時に `[min, max]` の一様分布で 1 回抽選する。

## 17. Mob ドロップアイテム

物理名: `MobDropItem`

| 項目 | 型 | 説明 |
|---|---|---|
| `itemId` | `String` | item ID。`MobRepository.parseTemplate` で prefix `item:` を除去した素の ID を保持 |
| `rate` | `double` | ドロップ確率（0.00 〜 100.00） |
| `amount` | `String` | 数量。固定値（`1`）または範囲（`1~3`） |
| `luckAffected` | `boolean` | `true` の場合、幸運補正の影響を受ける |
| `hidden` | `boolean` | `true` の場合、図鑑表示しない |

### 17.1 Mob ドロップ結果アイテム

物理名: `MobDropResultItem`

| 項目 | 型 | 説明 |
|---|---|---|
| `itemId` | `String` | 当選した item ID |
| `amount` | `int` | 確定した数量 |
| `dropRate` | `double` | 当選元の `MobDropItem.rate`（%）。リザルト表示とレア判定に使用する |

通常 Mob（`ENEMY`）は `dropRate <= 0.1`、ボス（`BOSS`）は `dropRate <= 5.0` の当選アイテムをレアドロップとして扱う。

## 18. Mob インスタンス

物理名: `MobInstance`

ワールド上に生成された AstralRecord Mob の実行時状態。通常は Bukkit/Paper の実体 `Mob`、固定表示用カカシは実体 `ArmorStand` と紐付き、クライアントへの本体表示・当たり判定は実体 Entity が担当する。経路探索は `Mob` 実体だけが担当する。

### 18.1 項目

- `instanceId`: `UUID`
- `bukkitEntityId`: `UUID?`（紐付く Bukkit Entity UUID。生成前または破棄後は `null`）
- `entityId`: `int`（紐付く Bukkit Entity ID。未紐付け時は `-1`）
- `template`: [[12_1-モデル定義]].Mob テンプレート
- `spawnLocation`: スポーン位置（leash 判定の基準）
- `currentLocation`: 現在位置
- `currentHealth`: `double`。`recoverHealth` は正の有限量を最大 HP まで加算し、実回復量を返す
- `currentShield`: `double`（初回は `shield.max`。リチャージ中は 0）
- `shieldDisplayCapacity`: `double`（現在の Shield 周期で満タンとして表示する容量）
- `shieldRechargeState`: `ShieldRechargeState?`（開始時刻、完了時刻、回復量。非リチャージ時は `null`）
- `nonLethal`: `boolean`（`true` の場合は combat 側の HP 反映で残 HP 1 を下限とする）
- `keepWhenUnobserved`: `boolean`（`true` の場合は視認距離外 enemy の自動破棄対象から除外する）
- `state`: [[12_1-モデル定義]].Mob 戦闘状態
- `target`: 現ターゲット `AstPlayer`（`null` 許容）
- `lastAttackTick`: `long`（最終攻撃 tick）
- `lastAttackerUuid`: `UUID?`（最後にダメージを与えたプレイヤー UUID。致死処理のキラー特定フォールバックに使用）
- `threatTable`: [[12_1-モデル定義]].脅威値テーブル
- `navTargetX` / `navTargetY` / `navTargetZ`: 最後に経路探索へ渡したターゲット座標。`navTargetY` は Vex の高度変化判定にも使用する
- `navRecomputeTick`: 最後に経路を再計算した内部 tick
- `navPath` / `navPathIndex`: Vex の三次元飛行ウェイポイントと次に追従する位置。地上 Mob の経路本体は Paper Pathfinder が保持する
- `navFlightSpeed`: Vex が現在の経路を追従するときの 1 tick あたり速度
- `navDirectVelocityOverride`: Vex の戦闘用直接移動またはノックバック速度を次の経路追従 tick まで優先するフラグ
- `navBlockedSinceTick`: WANDER 目的地への移動が詰まり始めた内部 tick。詰まりなしは `-1`
- `navLastObservedLocation`: WANDER 移動の進捗判定に使う直近観測位置
- `wanderAnchor`: `WANDER` 時の中心座標（通常は `spawnLocation`）
- `wanderTarget`: `WANDER` 時の現在の目的地（未設定時は `null`）
- `wanderPauseUntilTick`: `WANDER` 時に次の目的地を選ぶ前の停止解除 tick
- `lastWanderTeleportTick`: WANDER の詰まり時に配置アンカーへ緊急テレポートした最後の内部 tick。未実行は `-1`
- `viewers`: `MobService` 側の内部キャッシュで保持する。Mob 本体ではなく頭上 packet display の表示対象プレイヤー UUID 集合として使用する

### 18.2 ライフサイクル

- 生成時: `currentHealth = MAX_HEALTH の baseStat 値`、`currentShield = shield.max`、`shieldDisplayCapacity = shield.max`、`shieldRechargeState = null`、`state = IDLE`、`threatTable` は空、`nonLethal=false`、`keepWhenUnobserved=false`、`lastWanderTeleportTick=-1`。`MobEntityController` が実体 Mob を生成した後、`bindEntity` で `bukkitEntityId` / `entityId` / `currentLocation` を同期する。
- 死亡時: 通常個体は `currentHealth <= 0` で `state = DEAD` に遷移し、ドロップ確定または AI tick の破棄処理で実体 Mob を remove する。`nonLethal=true` の個体は combat 側で HP 1 を維持するため、この遷移へ進まない。

## 19. Mob 戦闘状態

物理名: `MobState`

| 値 | 意味 |
|---|---|
| `IDLE` | 非接敵。`idle.behavior` に従って動く |
| `AGGRO` | 接敵。`targeting` の選定に基づきターゲットを追跡 |
| `COMBAT` | 戦闘中。Mob スキルを試行し、使用できなければ `normalAttack` の間隔で攻撃する。`preferredRange` を理想距離として維持 |
| `LEASHED` | `leashRange` を超えたためスポーン地点へ帰還中 |
| `DEAD` | 撃破済み。次 tick で完全消滅する |

状態遷移は [[12_4-統合フロー]] を参照。

## 20. 脅威値テーブル

物理名: `MobThreatTable`

`Map<UUID, Double>` をキャプセル化した内部構造。プレイヤー UUID をキーとし、脅威値を蓄積する。

| メソッド | 役割 |
|---|---|
| `add(playerId, amount)` | 既存値に加算 |
| `set(playerId, amount)` | 値を上書き |
| `remove(playerId)` | エントリ除去 |
| `top()` | 最大脅威値のプレイヤー UUID を返す（空なら `null`） |
| `decay(factor)` | 全エントリに `factor`（0.0〜1.0）を乗算（時間経過の減衰） |

脅威値の初期付与・加算量は [[12_3-戦闘]] で定義する。

## 21. Mob スポナー定義

物理名: `MobSpawnerDefinition`

filebase の `40.features.mob/spawner/*.yml` から読み込む静的定義。スポーン座標は含めず、プラグインデータフォルダ配下 `mob_spawners.yml` の `MobSpawnerLocation` で保持する。

| 項目 | 型 | 説明 |
|---|---|---|
| `id` | `String` | スポナー ID |
| `region` | `String?` | スポナー範囲の地域表示名。未設定時はプレイヤー地域判定に使用しない |
| `radiusMeters` | `double` | 登録座標を中心とした水平スポーン範囲。上方向の高さ上限にも使う |
| `spawnMobs` | `List<MobSpawnerEntry>` | スポーン対象 Mob と抽選重み |
| `timeWindows` | `List<MobSpawnerTimeWindow>` | スポーン可能なワールド時間帯 |
| `itemMaterial` | `Material` | `user.permission = 99` 向けスポナーアイテムの見た目。ブロック Material のみ |
| `spawnIntervalTicks` | `long` | スポーン判定間隔 |
| `maxAlivePerSpawner` | `int` | 当該スポナー由来の同時存在上限 |
| `maxNearbyMobs` | `int` | 他スポナー由来を含む周辺 Mob 上限 |
| `spawnPerPlayer` | `int` | 範囲内プレイヤー 1 人あたりの目標スポーン数。最大 6 人分まで加算 |

`MobSpawnerEntry` は `mobId`、任意の `level`、`weight` を持つ。`level` 未指定または未登録時は対象 Mob の最小レベルプロファイルを使用する。地域レベルの加重平均と実際のスポーンは、同じ実効レベルを参照する。

## 22. Mob スポナー座標

物理名: `MobSpawnerLocation`

| 項目 | 型 | 説明 |
|---|---|---|
| `spawnerId` | `String` | `MobSpawnerDefinition.id` |
| `worldName` | `String` | Bukkit ワールド名 |
| `x` / `y` / `z` | `int` | ブロック座標 |

座標キーは `worldName:x:y:z` とし、スポナー ID に関係なく同一座標の重複登録を拒否する。

### Mob spawner 表示・削除認可

- packet 表示は `AccountMode.ADMIN` の場合に `user.permission` を問わず許可する。
- 左クリック削除候補は `user.permission = 99` かつ `AccountMode.ADMIN` の場合だけ生成し、同条件を winner 実行直前にも再検証する。
- `AccountMode.PLAYER` では候補を claim/cancel しないため、近傍 Mob への通常攻撃を妨げない。
- 登録済み Mob spawner ブロックの破壊削除も同じ条件で判定し、条件不足時は block break event を cancel する。
- 設置と Mob/NPC command の既存 `user.permission` 判定はこの削除認可から独立して維持する。

## 24. 関連 feature とのモデル関係

- `status`:
  - `StatusType` を `baseStats[].status` キーとして直接参照する。
  - `STRENGTH` / `DEXTERITY` / `INTELLIGENCE` / `ATTACK` / `DEFENSE` / `MAGIC_DEFENSE` などはダメージ計算に使用する。
- `player`:
  - `AstPlayer` がターゲット・ダメージ送付先・ドロップ受取先となる。
  - 永続化対象は Mob 側にはなく、`AstPlayer` のインベントリ・経験値・所持金更新は各 feature の API 経由で行う。
- `loot`:
  - `drops.lootTable` の参照解決で `LootTableResponse` を読み出す。
- `item`:
  - `drops.items[].itemId` の参照解決で `ItemResponse` を読み出す。
- `skill`:
  - player 用 `SkillService`、skill master、skill gem は Mob 専用スキルを扱わない。
- `mob`:
  - `MobSkillRegistry` が `ai.combat.skills[].id` を Mob 専用 executor へ解決する。
## 25. NPC interaction 制約

- `NPC` で `damageImmune = true` の場合は、Bukkit 側の無敵化だけでなく custom combat / built-in 通常攻撃 / 特殊攻撃からも HP を減算しない。
- NPC interaction を受け付けた入力では、hotbar-action feature の武器通常攻撃・特殊攻撃は同時発火させない。
- NPC interaction の受付距離は 3 ブロック、視線 ray size は 0.75 とし、近距離で対象を正面に捉えた場合のみ発火させる。

- NPC interaction は通常プレイ導線として扱い、`AccountMode.PLAYER` の場合のみアクションを実行する。
- `AccountMode.ADMIN` のプレイヤーが NPC をクリックした場合、対象 NPC の interaction event は cancel し、GUI 表示や通常プレイ処理は実行しない。
- `user.permission = ADMIN` は管理者権限の判定であり、account mode の通常プレイ許可とは別に扱う。

## 26. 採集定義

採集 damage は現在の `MINING_SPEED` を一度だけ使用する。固定値は四捨五入し、range は上下限内で roll する。tool 由来の値を別途重複加算せず、未設定または 0 以下でも最低 1 damage とする。

物理名: `GatheringDefinition`

`40_filebase/42.features.gathering/` から読み込む採集 object の静的定義。

| 項目 | 型 | 説明 |
|---|---|---|
| `schemaVersion` | `int` | schema version |
| `id` / `category` / `name` | `String` | 定義 ID、採集カテゴリ、表示名 |
| `maxHealth` | `int` | 採集 object の耐久値。1 未満は 1 |
| `displayBlock` | `Material` | packet-only BlockDisplay。block でない値は `STONE` |
| `displayScale` | `Vector3f` | 表示 scale。描画時に 0.75 倍する |
| `requiredToolTags` | `List<String>` | 使用可能 tool tag。大文字へ正規化し、空なら制限なし。複数指定時はいずれか 1 つの一致で許可 |
| `drops` | `MobDropConfig` | Mob と共有する item / loot table / exp / money 定義 |
| `sounds.hit` / `sounds.break` | `GatheringSound?` | hit 時・破壊時の sound key、volume、pitch |

## 27. 採集インスタンス

物理名: `GatheringInstance`

| 項目 | 型 | 説明 |
|---|---|---|
| `instanceId` | `UUID` | server session 内の識別子 |
| `definition` | `GatheringDefinition` | 生成元定義 |
| `location` | `Location` | block 中央へ正規化した位置。getter は clone を返す |
| `currentHealth` | `int` | 生成時は `maxHealth`。damage は最低 1、下限 0 |
| `activePlayerId` | `UUID?` | 現在 session を所有する player。別 player が開始すると旧 session を終了する |

tool 変更、視線逸脱、要件不一致で session を終了する場合は `resetHealth()` で HP と所有者を初期化する。破壊完了時は instance 自体を破棄するため HP を復元しない。

## 28. 採集スポナー定義・配置

物理名: `GatheringSpawnerDefinition`、`GatheringSpawnerEntry`、`GatheringSpawnerTimeWindow`、`GatheringSpawnerLocation`

| 項目 | 説明 |
|---|---|
| `radiusMeters` | player / 採集 object の周辺判定と水平 spawn 半径。最低 1.0 |
| `spawnGatherings` | 採集 ID と 1 以上へ補正した抽選 weight |
| `timeWindows` | world time の許可範囲。空なら `0..23999`。日跨ぎ範囲を許可 |
| `itemMaterial` | 管理者向け設置 item と表示 block |
| `spawnIntervalTicks` | スポナー別の判定間隔。最低 1 tick |
| `maxAlivePerSpawner` | 当該配置由来の alive 上限 |
| `maxNearbyGatherings` | 他配置由来も含む半径内の採集 object 上限 |
| `spawnPerPlayer` | 周辺 gameplay player 1 人あたりの目標数。player 数は最大 6 人分まで評価 |
| `requiredBaseBlocks` | random spawn 候補の足元 material 条件。空なら制限なし |

配置は `GatheringSpawnerLocation(spawnerId, worldName, x, y, z)` とし、`worldName:x:y:z` を一意キーに plugin data folder の `gathering_spawners.yml` へ保存する。

## 29. 採集と関連 feature の境界

- `item`: メインハンドの Astral item ID から equipment tag を解決し、`requiredToolTags` と照合する。
- `status`: `MINING_SPEED` の確定値を四捨五入し、最低 1 の採集 damage とする。
- `mob` / `loot` / `inventory` / `currency`: `MobDropService` と `MobDropPresentationService` を共有して報酬を抽選・付与する。
- `quest`: 採集 object の破壊・報酬付与後に gathering ID を通知するだけとし、定義・instance・session・spawner は `feature/gathering` が所有する。
- `player-interaction`: 採集・採集 spawner の候補収集、可視性検証、勝者選択を所有する。候補収集中は採集 damage や配置変更を行わない。
