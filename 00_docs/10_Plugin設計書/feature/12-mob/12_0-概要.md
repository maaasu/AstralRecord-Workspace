# 12_0-概要

## 1. 目的

`mob` 機能は、AstralRecord における NPC・敵・ボスを表すカスタムエンティティを管理する。
Mob 本体は Bukkit/Paper の実体 `Mob` として生成するが、バニラの goal・攻撃・ダメージ処理には依存しない。実体 Entity はクライアント同期・当たり判定・Paper Pathfinder の土台として利用し、AI の意思決定・HP・ヘイト・攻撃処理はプラグイン側で独自実装する。

主目的は以下。

- Mob テンプレートの API 経由ロード・メモリキャッシュ管理
- ワールド上の Mob インスタンス（実体 Mob）の生成・更新・破棄
- 独自の AI（待機・徘徊・ターゲティング・戦闘）の駆動
- 独自のダメージ計算・ノックバック処理・ヘイト管理
- 撃破時のドロップ・経験値・金銭の抽選と払い出し
- filebase のスポナーマスタとプラグインデータフォルダ配下の座標キャッシュによる定常スポーン管理
- filebase の採集定義・採集スポナー定義、採集 instance、packet-only 表示、採集 session と完了報酬の管理

## 2. コンテキスト

- Mob テンプレートは AstralRecord API（`/api/mob`, `/api/mob/{mobId}`）から取得し、`MobService` の内部キャッシュに保持する。
- ワールド上に存在する Mob インスタンス（`MobInstance`）はサーバセッション内のメモリでのみ管理する（永続化なし）。
- 表示と当たり判定は Bukkit/Paper の実体 `Mob` を使う。スポーン直後に `Bukkit.getMobGoals().removeAllGoals(mob)` を実行し、バニラ AI の goal は全削除する。
- 地上 Mob の移動は Paper Pathfinder に目標地点を渡す。`VEX` は有界三次元 A* で飛行経路を計算する。いずれも目標再設定は一定間隔・目標地点の移動量でレート制限し、100体規模で毎 tick 全 Mob が経路再計算しない設計とする。
- Mob 実体は `setInvulnerable(true)` とし、バニラダメージでは HP を減らさない。ダメージ授受は本機能または combat/skill 側から `MobInstance.currentHealth` へ反映する。
- ボス（`category = BOSS`）の **フェーズ遷移・スキルローテーション・専用ギミック** は本機能のスコープ外で、別途 plugin 側で個別実装する想定。
- スポナーの静的条件は `40_filebase/40.features.mob/spawner/` の `mob.spawner` マスタで管理し、座標はプラグインデータフォルダ配下 `mob_spawners.yml` に保存する。座標はマスタへ含めない。
- 採集 object は `40_filebase/42.features.gathering/`、採集 spawner は `40_filebase/43.features.gathering.spawner/` を定義正本とし、設置座標だけを plugin data folder の `gathering_spawners.yml` に保存する。
- 採集完了後の item / exp / money は Mob の drop 抽選・付与経路を共有する。quest feature へは `QuestService.recordGathering(player, gatheringId)` で進捗だけを通知する。

## 3. 構成要素（実装単位）

- `command/MobCommand`, `command/MobTabCompleter`
  - `/mob load|list|spawn|delete` を提供。`spawn` はテンプレート ID と実行者の現在地から `MobInstance` を生成し、`delete` はインスタンス UUID またはテンプレート ID に一致する `MobInstance` を破棄する。
  - `/mob npc place|remove|list|reload` を提供。`place` は NPC テンプレートを座標付きで永続配置し、`remove` は指定テンプレートに紐づく保存済み NPC 配置と出現中 NPC をまとめて削除する。
  - `/mob spawner item <spawnerId> [amount]` は `user.permission = 99` のプレイヤーにスポナー設置アイテムを付与する。`/mob spawner list|reload` はスポナー定義と登録座標の確認・再読込を行う。
- `service/MobService`
  - テンプレートのロード・キャッシュ、インスタンスの生成・破棄、参照取得 API を提供する。
- `service/MobEntityController`
  - 実体 Mob の生成、vanilla goal 全削除、PDC 紐付け、Paper Pathfinder の移動要求、実体削除を担当する。
- `service/NpcPlayerSkinPacketService`
  - `category = NPC` かつ `entityType = PLAYER`、署名付き `skin` を持つ NPC だけを ProtocolLib の疑似 Player として表示する。実体 Entity は AI・移動・当たり判定・クリック解決の基準として保持し、viewer ごとに隠す。
  - 疑似 Player の表示開始時に GameProfile を tab list へ一時登録し、スキン解決後に非表示にする。表示解除時は世代を無効化し、隠していた実体 NPC を復元する。
- `service/MobAiService`
  - tick 駆動の AI ルーパー。Idle / Targeting / Leash の状態遷移を管理する。100体想定のため、IDLE 探索・追跡判断・viewer 更新は間隔を空けて分散実行する。
- `service/MobCombatService`
  - 攻撃判定・独自ダメージ計算・致死判定・ドロップ確定までの責務を持つ。
- `service/MobKnockbackService`
  - 攻撃を受けた Mob、または Mob から受けたプレイヤーへのノックバックベクトル算出と送出を行う。
- `model/MobThreatTable`
  - Mob 単位のヘイト（プレイヤー -> 脅威値）を保持し、`HIGHEST_THREAT` 戦略の入力を提供する。
- `service/MobDropService`
  - `drops.items` の確率抽選、`drops.lootTable` の参照解決、経験値・金銭の払い出しを行う。
- `repository/MobRepository`
  - `/api/mob` と `/api/mob/{mobId}` への HTTP リクエストを実行する。
  - `feature/spawner/service/MobSpawnerService`
    - スポナー定義・座標キャッシュ・スポーン判定・座標ライトビハインド保存を管理する。オーバーワールドのプレイヤーは、範囲内で最も近い `region` 設定済みスポナーの地域へ更新し、対象がなければ「オーバーワールド」へ戻す。地域レベルは、同じ `region` を定義する全スポナーの出現 Mob レベルを `spawnMobs.weight` で加重平均し、四捨五入した整数とする。解決できない Mob は除外し、有効な Mob がない地域は 0 とする。同一地域の別スポナーへ切り替わっても地域タイトルは再表示しない。範囲内プレイヤー数は最大 6 人まで加算し、スポナー単位上限と周辺 Mob 上限で湧き過ぎを抑止する。スポーン地点は登録座標から `radiusMeters` 以内の水平範囲で抽選し、上方向は登録 Y 座標 + `radiusMeters` を上限とする。登録 Y 座標 - 3 以上では最上面以外でも足元と頭上に空間があれば候補に含め、登録 Y 座標 - 3 未満ではその X/Z 列の最上面だけを候補にする。足元が葉っぱ block の地点は候補から除外し、有効地点を見つけられない場合は登録座標へフォールバックしない。
- `feature/spawner/event/MobSpawnerBlockEventHandler`
  - スポナーアイテム設置、登録block破壊、packet-only表示への左クリックから副作用なし候補を提供する。[[28_3-サービス]].勝者選択 後のexecutorだけが、実blockを置かず専用itemも消費せずに座標登録・削除を行う。同一block座標の重複登録を拒否し、削除は`user.permission = 99`のプレイヤーだけに許可する。通常プレイヤーはスポナー表示を見えない前提とし、左クリック時も候補を返さず通常操作として通す。
  - `feature/spawner/service/MobSpawnerVisualizer`
    - `AccountMode.ADMIN` のプレイヤーにのみ、登録済みスポナーを ProtocolLib の packet-only BlockDisplay / TextDisplay と少量パーティクルで表示する。設置・削除権限とは独立した可視条件とし、`AccountMode.PLAYER` では表示しない。実ブロックやサーバー管理 Entity は置かないためスポナー表示自体は当たり判定を持たない。
- `feature/gathering/service/GatheringService`
  - 採集定義 cache、採集 instance、プレイヤー単位の採集 session、視線判定、tool tag 検証、破壊時の drop 付与と quest 進捗通知を所有する。初回入力で 1 回採集し、以降は 8 tick 間隔で同じ対象・同じ tool の間だけ継続する。
- `feature/gathering/service/GatheringVisualizer` / `GatheringPacketDisplay`
  - 採集 block を 48 block、名称または採集中 HP gauge を 8 block の範囲へ packet-only 表示する。表示 entity は server entity として生成しない。
- `feature/gathering/spawner/service/GatheringSpawnerService`
  - 採集 spawner 定義・配置 cache、20 tick 間隔の出現判定、60 秒間隔の dirty 保存、周辺 gameplay player 数に応じた出現数、重み付き採集 object 選択を所有する。
- `feature/gathering/spawner/service/GatheringSpawnerVisualizer`
  - `AccountMode.ADMIN` の viewer に限り、採集 spawner の block / label と particle を表示する。配置・削除の実行権限は `hasAdminPermission()` で別途検証する。
- `feature/gathering/event/*` / `feature/gathering/spawner/event/*`
  - 採集対象・採集 spawner の左クリックと block mutation を副作用なしの `PlayerInputCandidate` として提供し、勝者 executor だけが採集開始または配置変更を行う。
- `shared/display/OverheadDisplayService`
  - Mob の頭上 HP 表示は実体 TextDisplay として扱う。通常 Mob は Mob Entity の passenger として接続し、`entityType = PLAYER` の疑似 Player NPC は隠された実体 Entity に依存せず、疑似 Player の足元から固定高さで追従させる。Mob 本体の表示は実体 Entity または ProtocolLib の疑似 Player に任せる。
- `shared/interaction`とmob/spawner resolver
  - NPC・fakeblock NPC・spawner表示・block mutationを`PlayerInputCandidate`へ正規化する。候補収集時にinteraction action、GUI表示、command実行、座標変更を行わない。
- [[12_1-モデル定義]]
  - Mob テンプレート、インスタンス、AI 設定、ドロップ設定など。

## 4. 依存関係

- 内部依存
  - `MobService` -> `MobRepository`, `MobEntityController`, `NpcPlayerSkinPacketService`, `MobAiService`
  - `MobAiService` -> `MobService`, `MobThreatTable`
  - `MobCombatService` -> `MobKnockbackService`, `MobDropService`, `MobThreatTable`
  - `MobSpawnerService` -> `MobService`, filebase, plugin data folder
  - `GatheringService` -> `GatheringDefinitionRepository`, `MobDropService`, `MobDropPresentationService`, `ItemService`, `QuestService`
  - `GatheringSpawnerService` -> `GatheringService`, gathering filebase, plugin data folder
- 外部依存
  - AstralRecord API（`/api/mob`, `/api/mob/{mobId}`）
  - `feature/status` の `StatusType`
  - `feature/player` の `AstPlayer`（ターゲット・ダメージ授受の対象）
  - `feature/currency` の通貨加算経路（Mob 撃破時の金銭払い出し）
  - `feature/quest` の採集 objective 進捗通知
  - Paper API（MobGoals / Pathfinder / 実体 Entity）
  - Paper API（TextDisplay passenger 追従などの共有表示）
  - `CommandRegister`（`MobCommand` / `MobTabCompleter` / `TextDisplayCommand` の明示登録）

- `status` / `combat`: Mob と player の status、独自 damage、HP / shield 減算を扱う。
- `skill`: Mob skill caster と `combat.skills` の発動を扱う。
- `loot` / `item` / `currency` / `account`: 討伐報酬を解決・付与する。
- `player` / `player-setting`: target、viewer、地域状態、drop log 表示設定を参照する。
- `quest`: 採集完了時に `QuestService.recordGathering` へ進捗通知する。採集定義・採集 session・スポーンの所有者ではない。
- `boss`: boss challenge、scaling、死亡処理を連携する。
- `player-interaction`: NPC / fakeblock / spawner / block mutation の候補収集と勝者選択を正本とする。
- AstralRecordApi `/api/mob` と `40_filebase/40.features.mob/{boss,enemy,npc,spawner}/*`: Mob template の永続正本。
- `40_filebase/42.features.gathering/*` / `40_filebase/43.features.gathering.spawner/*`: 採集 object と採集 spawner の定義正本。
- plugin data folder の `mob_spawners.yml`、`gathering_spawners.yml`、`npc_placements.yml`、`text_displays.yml`: 実行環境ごとの配置状態を保持する。
- Paper API / ProtocolLib: 実体 Mob、Pathfinder、packet-only spawner display を提供する。

## 5. ライフサイクル登録点

- 起動時:
  - `MobService` をプラグイン初期化で生成する。
  - `MobSpawnerService` をプラグイン初期化で生成し、起動時にスポナーマスタと座標ファイルを一括ロードする。
  - `GatheringService` / `GatheringSpawnerService` を生成し、採集定義・spawner 定義・配置をロード後、visualizer と spawn task を開始する。
  - `MobAiService` の tick タスクを `BukkitScheduler.runTaskTimer`（メインスレッド）で起動する。tick 周期は 1 tick。
  - `MobSpawnerService` のスポーン判定タスク、座標オートセーブタスク、PLAYER 以外向け表示タスクを起動する。
  - `MobCommand` / `MobTabCompleter` を `core` 側で登録する。
- 終了時:
  - `core` 側で `MobAiService.stop` を呼び、tick タスクを停止する。
  - `core` 側で `MobSpawnerService.stop` を呼び、未保存の座標キャッシュを保存する。
  - `core` 側で `GatheringSpawnerService.stop`、続いて `GatheringService.stop` を呼び、配置保存・task / packet 表示・採集 session を終了する。
  - 続けて `core` 側で `MobService.destroyAll` を呼び、全実体 Mob の削除とキャッシュ破棄を行う。
  - tick 停止 → 全 Mob 破棄の順を守ること。`MobService.destroyAll` 自体は tick 停止を呼ばない。

起動時に `MobService.loadAll` で全件プリロードする。テンプレートは `/mob load` で再ロードでき、`spawn` の初回呼び出し時にも未キャッシュ ID を都度ロードする。

## 7. 飛行 Mob の移動

- `VEX` は地上 Mob 用の Paper Pathfinder では経路を生成できないため、`MobEntityController` が Vex の実当たり判定を通過可否に使う有界三次元 A* で経路を計算する。探索は水平 20 block、上下 10 block、最大 768 展開ノードに制限し、範囲外・到達不能時は目標へ最も近い安全な部分経路を採用する。
- 探索は 26 近傍を使用し、複数軸の斜め移動では直交中間位置も通過可能な場合だけ採用して角抜けを防ぐ。未ロードチャンクは閉塞として扱い、探索によるチャンクロードを行わない。
- 経路再計算は追跡目標の X/Y/Z 変化が 1.5 block を超えた場合、保持経路を使い切った場合、または衝突で経路を破棄した場合に行う。再計算は 10 tick 以上、経路を得られない場合の再試行は 20 tick 以上の間隔を空ける。
- 経路追従と次 tick の移動線分に対する AABB 衝突検査は毎 tick 行い、衝突を検出した場合は速度をゼロにして経路を破棄する。
- 追跡中の目標地点は選択中プレイヤーの位置とし、プレイヤーの高度を含めて接近する。
- Vex の移動停止時は速度をゼロにし、以前の移動ベクトルで漂流し続けないようにする。

## 9. 管理コマンドのカテゴリ境界

- 管理コマンドはカテゴリ別に扱う。`/mob spawn` は `ENEMY` / `BOSS` 専用、`/mob npc place|remove|list|reload` は `NPC` 専用とする。
- 補完候補も同じカテゴリ境界を守り、`spawn` に `NPC` を混在させない。
- `NPC` を引数に取るコマンドは、テンプレート ID に加えてカラーコード除去後の表示名、および `id（表示名）` 形式の補完候補を受け付ける。表示名解決はロード済みテンプレートに対して行い、ID 完全一致は未ロードテンプレートでも遅延ロードで解決する。

## 10. スポナーアイテム表示

`/mob spawner item <spawnerId> [amount]` で付与される Mob スポナー設置アイテムは、日本語の表示名と lore を持つ。lore には、設置前に確認できるスポナー情報として、ID、種別、表示ブロック、スポーン半径、判定間隔、時間帯、出現対象と重み、スポナー単位上限、周辺 Mob 上限、プレイヤーあたり出現数を表示する。
