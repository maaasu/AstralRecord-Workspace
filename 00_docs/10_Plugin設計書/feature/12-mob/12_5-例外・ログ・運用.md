# 12_5-例外・ログ・運用

## 1. 方針

`mob` / `gathering` 機能はワールド上の実体・packet-only object を継続管理するため、障害時もサーバを止めずに以下を維持する。

- 不正なテンプレートが 1 件あっても他テンプレートのロード・利用は継続する
- AI tick 中の例外は該当インスタンスのみ DEAD 扱いで除去し、他インスタンスへ波及させない
- API 通信失敗時はリポジトリ層が `IOException` を `RuntimeException` で伝播し、`MobService` 側で握りつぶさない

ログ出力は `LogId` ベースで行う。Mob 固有ログは `5700-5799`、採集配置保存と packet 送信・スポーン診断は infrastructure の shared `6400-6401` / `9010-9019` を使用する。
個別 ID 採番は本ファイル「2. 主なログポイント」を正本とし、各メソッド仕様（[[12_3-サービス]] / [[12_3-戦闘]] / [[12_3-リポジトリ]] / [[12_3-実体Mob制御]]）の処理番号直下にインライン表として記載する。
ID 命名は `LogId.<I|W|E|D>_<番号>` 形式に統一する（既存 feature と同じ命名規約）。

## 3. 例外処理の境界

- **Repository**
  - HTTP 異常時は `IOException` を `RuntimeException` で伝播
  - `InterruptedException` は割り込みフラグを立て直し `RuntimeException` でラップ
  - `findById` の `404` は `W_5700` を記録して `null` を返す
- **Service (`MobService`)**
  - リポジトリ例外を握りつぶさず呼び出し元へ伝播
  - `spawn` でテンプレート未発見時は `null` を返す
  - `spawn` の template 未解決は `W_5701` を記録して `null` を返す
- **AiService (`MobAiService`)**
  - `tick` 全体は try/catch で個別インスタンスの例外を捕捉し、該当インスタンスを `DEAD` 扱いにする
  - tick タスク全体の例外は ERROR ログ後、tick を継続させる
- **CombatService**
  - 命中判定・ダメージ計算・会心判定は例外捕捉なし（呼び出し元 `MobAiService` で捕捉される）
  - 致死処理のドロップ抽選例外は ERROR ログのうえ、Mob 破棄は実行する（致死自体は確定）
- **EntityController (`MobEntityController`)**
  - 実体 Mob 生成に失敗した場合は `MobService.spawn` が WARN ログを記録し、インスタンスを登録しない
- **Gathering**
  - filebase root 未設定・対象 directory 不在は空定義として扱う
  - 不明定義 ID / world 不在時の `GatheringService.spawn` は `null` を返す
  - 採集 spawner 配置保存失敗時は service の dirty を維持し、次回周期または stop で再試行する
  - packet 送信失敗は対象 viewer の表示だけを諦め、他 viewer と採集 session を継続する

## 4. スレッド上の注意

- `MobRepository.findById` / `findAll` は同期 HTTP。メインスレッドでの呼び出しはブロックする可能性がある。
- 初回テンプレートロードは `/mob load` などの管理者操作で行うこと。Spawn 時の遅延ロードはイベントブロック量を増やす可能性があるため監視対象。
- `MobAiService.tick` と `MobEntityController` の Bukkit/Paper API 操作はメインスレッドで実行する。頭上 TextDisplay の spawn / passenger attach / destroy も同様。
- `GatheringService` の session task、visualizer、`GatheringSpawnerService` の spawn / save task と Bukkit / ProtocolLib 操作はメインスレッドで実行する。

| MsgId | 内容 | 出力タイミング |

## 6. 運用上の注意

### Mob インスタンスの採用済み運用契約

- Mob インスタンスは永続化せず、サーバ再起動で消滅する。
- 実体 Mob は永続化しない。サーバ終了時は `MobService.destroyAll` で remove する。
- Paper API の Pathfinder / MobGoals の挙動はサーババージョン更新時に確認する。

### 固定 TextDisplay の採用済み運用契約

- 固定 TextDisplay 配置は `text_displays.yml` を正本として永続化する。表示エンティティ自体は停止時に破棄し、起動時またはワールドロード後に YAML から再生成する。
- 固定 TextDisplay のテキストでは `&` カラーコードを許容する。表示適用は plugin 共通の `ColorCodeUtil` 経由で行い、`ChatColor` は使用しない。

### 採集の採用済み運用契約

- 採集定義は `40_filebase/42.features.gathering`、採集 spawner 定義は `40_filebase/43.features.gathering.spawner`、配置は plugin data folder の `gathering_spawners.yml` を正本とする。
- 採集 instance・HP・player session は永続化しない。定義 reload または停止時に破棄する。
