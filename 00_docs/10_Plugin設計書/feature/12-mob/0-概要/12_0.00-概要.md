# 12_0.00-概要

## 1. 目的

`mob` 機能は、AstralRecord における NPC・敵・ボスを表すカスタムエンティティを管理する。
Mob 本体は Bukkit/Paper の実体 `Mob` として生成するが、バニラの goal・攻撃・ダメージ処理には依存しない。実体 Entity はクライアント同期・当たり判定・Paper Pathfinder の土台として利用し、AI の意思決定・HP・ヘイト・攻撃処理はプラグイン側で独自実装する。

主目的は以下。

- Mob テンプレートの API 経由ロード・メモリキャッシュ管理
- ワールド上の Mob インスタンス（実体 Mob）の生成・更新・破棄
- 独自の AI（待機・徘徊・ターゲティング・戦闘）の駆動
- 独自のダメージ計算・ノックバック処理・ヘイト管理
- 撃破時のドロップ・経験値・金銭の抽選と払い出し
- filebase のスポナーマスタとプラグインデータフォルダ配下の座標キャッシュによる定常スポーン管理

## 2. コンテキスト

- Mob テンプレートは AstralRecord API（`/api/mob`, `/api/mob/{mobId}`）から取得し、`MobService` の内部キャッシュに保持する。
- ワールド上に存在する Mob インスタンス（`MobInstance`）はサーバセッション内のメモリでのみ管理する（永続化なし）。
- 表示と当たり判定は Bukkit/Paper の実体 `Mob` を使う。スポーン直後に `Bukkit.getMobGoals().removeAllGoals(mob)` を実行し、バニラ AI の goal は全削除する。
- 移動は Paper Pathfinder に目標地点を渡す。目標再設定は一定間隔・目標地点の移動量でレート制限し、100体規模で毎 tick 全 Mob が経路再計算しない設計とする。
- Mob 実体は `setInvulnerable(true)` とし、バニラダメージでは HP を減らさない。ダメージ授受は本機能または combat/skill 側から `MobInstance.currentHealth` へ反映する。
- ボス（`category = BOSS`）の **フェーズ遷移・スキルローテーション・専用ギミック** は本機能のスコープ外で、別途 plugin 側で個別実装する想定。
- スポナーの静的条件は `40_filebase/40.features.mob/spawner/` の `mob.spawner` マスタで管理し、座標はプラグインデータフォルダ配下 `mob_spawners.yml` に保存する。座標はマスタへ含めない。

## 3. 構成要素（実装単位）

- `command/MobCommand`, `command/MobTabCompleter`
  - `/mob load|list|spawn|delete` を提供。`spawn` はテンプレート ID と実行者の現在地から `MobInstance` を生成し、`delete` はインスタンス UUID またはテンプレート ID に一致する `MobInstance` を破棄する。
  - `/mob npc place|remove|list|reload` を提供。`place` は NPC テンプレートを座標付きで永続配置し、`remove` は指定テンプレートに紐づく保存済み NPC 配置と出現中 NPC をまとめて削除する。
  - `/mob spawner item <spawnerId> [amount]` は `user.permission = 99` のプレイヤーにスポナー設置アイテムを付与する。`/mob spawner list|reload` はスポナー定義と登録座標の確認・再読込を行う。
- `service/MobService`
  - テンプレートのロード・キャッシュ、インスタンスの生成・破棄、参照取得 API を提供する。
- `service/MobEntityController`
  - 実体 Mob の生成、vanilla goal 全削除、PDC 紐付け、Paper Pathfinder の移動要求、実体削除を担当する。
- `service/MobAiService`
  - tick 駆動の AI ルーパー。Idle / Targeting / Leash の状態遷移を管理する。100体想定のため、IDLE 探索・追跡判断・viewer 更新は間隔を空けて分散実行する。
- `service/MobCombatService`
  - 攻撃判定・独自ダメージ計算・致死判定・ドロップ確定までの責務を持つ。
- `service/MobKnockbackService`
  - 攻撃を受けた Mob、または Mob から受けたプレイヤーへのノックバックベクトル算出と送出を行う。
- `service/MobThreatTable`
  - Mob 単位のヘイト（プレイヤー -> 脅威値）を保持し、`HIGHEST_THREAT` 戦略の入力を提供する。
- `service/MobDropService`
  - `drops.items` の確率抽選、`drops.lootTable` の参照解決、経験値・金銭の払い出しを行う。
- `repository/MobRepository`
  - `/api/mob` と `/api/mob/{mobId}` への HTTP リクエストを実行する。
- `feature/spawner/service/MobSpawnerService`
  - スポナー定義・座標キャッシュ・スポーン判定・座標ライトビハインド保存を管理する。オーバーワールドのプレイヤーは、範囲内で最も近い `region` 設定済みスポナーの地域へ更新し、対象がなければ「オーバーワールド」へ戻す。地域レベルは、同じ `region` を定義する全スポナーの出現 Mob レベルを `spawnMobs.weight` で加重平均し、四捨五入した整数とする。解決できない Mob は除外し、有効な Mob がない地域は 0 とする。同一地域の別スポナーへ切り替わっても地域タイトルは再表示しない。範囲内プレイヤー数は最大 6 人まで加算し、スポナー単位上限と周辺 Mob 上限で湧き過ぎを抑止する。スポーン地点は登録座標から `radiusMeters` 以内の水平範囲で抽選し、上方向は登録 Y 座標 + `radiusMeters` を上限とする。登録 Y 座標 - 3 以上では最上面以外でも足元と頭上に空間があれば候補に含め、登録 Y 座標 - 3 未満ではその X/Z 列の最上面だけを候補にする。
- `feature/spawner/event/MobSpawnerBlockEventHandler`
  - スポナーアイテム設置時は実ブロックを置かずに座標を登録し、同一ブロック座標の重複登録を拒否する。登録済みスポナーの左クリック削除は、対象ブロック自体が登録済みスポナーである場合、またはスポナー表示を空振り左クリックで直接狙った場合に限り `user.permission = 99` のプレイヤーのみに許可する。通常プレイヤーはスポナー表示を見えない前提とし、左クリック時も警告メッセージを出さずに通常操作として通す。
- `feature/spawner/service/MobSpawnerVisualizer`
  - `AccountMode.ADMIN` のプレイヤーにのみ、登録済みスポナーを ProtocolLib の packet-only BlockDisplay / TextDisplay と少量パーティクルで表示する。実ブロックやサーバー管理 Entity は置かないためスポナー表示自体は当たり判定を持たない。
- `shared/display/OverheadDisplayService`
  - Mob の頭上 HP 表示は実体 TextDisplay を Mob Entity の passenger として接続して扱う。Mob 本体の表示は実体 Entity に任せる。
- [[12_1.00-モデル定義]]
  - Mob テンプレート、インスタンス、AI 設定、ドロップ設定など。

## 4. 依存関係

- 内部依存
  - `MobService` -> `MobRepository`, `MobEntityController`, `MobAiService`
  - `MobAiService` -> `MobService`, `MobThreatTable`
  - `MobCombatService` -> `MobKnockbackService`, `MobDropService`, `MobThreatTable`
  - `MobSpawnerService` -> `MobService`, filebase, plugin data folder
- 外部依存
  - AstralRecord API（`/api/mob`, `/api/mob/{mobId}`）
  - `feature/status` の `StatusType`
  - `feature/player` の `AstPlayer`（ターゲット・ダメージ授受の対象）
  - `feature/currency` の通貨加算経路（Mob 撃破時の金銭払い出し）
  - Paper API（MobGoals / Pathfinder / 実体 Entity）
  - Paper API（TextDisplay passenger 追従などの共有表示）
  - Reflections（任意。コマンド自動登録に使用）

## 5. ライフサイクル登録点

- 起動時:
  - `MobService` をプラグイン初期化で生成する。
  - `MobSpawnerService` をプラグイン初期化で生成し、起動時にスポナーマスタと座標ファイルを一括ロードする。
  - `MobAiService` の tick タスクを `BukkitScheduler.runTaskTimer`（メインスレッド）で起動する。tick 周期は 1 tick。
  - `MobSpawnerService` のスポーン判定タスク、座標オートセーブタスク、PLAYER 以外向け表示タスクを起動する。
  - `MobCommand` / `MobTabCompleter` を `core` 側で登録する。
- 終了時:
  - `core` 側で `MobAiService.stop` を呼び、tick タスクを停止する。
  - `core` 側で `MobSpawnerService.stop` を呼び、未保存の座標キャッシュを保存する。
  - 続けて `core` 側で `MobService.destroyAll` を呼び、全実体 Mob の削除とキャッシュ破棄を行う。
  - tick 停止 → 全 Mob 破棄の順を守ること。`MobService.destroyAll` 自体は tick 停止を呼ばない。

起動時に `MobService.loadAll` で全件プリロードする。テンプレートは `/mob load` で再ロードでき、`spawn` の初回呼び出し時にも未キャッシュ ID を都度ロードする。

| ライブラリ | 用途 | 状態 |
|---|---|---|
| `io.papermc.paper:paper-api` | 実体 Mob、MobGoals、Pathfinder、TextDisplay passenger 追従 | 既存 `pom.xml` に provided 登録済み |
| `net.dmulloy2:ProtocolLib:5.4.0` | 既存互換用 | 既存 `pom.xml` に provided 登録済み |
| `com.google.code.gson:gson` | API レスポンスの JSON パース | 既存 `pom.xml` に provided 登録済み |
| `org.reflections:reflections` | コマンド・イベント自動登録 | 既存 `pom.xml` に登録済み |
| Bukkit Scheduler | tick 駆動 | Paper API 標準 |

追加で新規ライブラリは導入しない方針。経路探索は Paper Pathfinder を使用し、独自 A\* 実装は持たない。

## 追加補足

- 管理コマンドはカテゴリ別に扱う。`/mob spawn` は `ENEMY` / `BOSS` 専用、`/mob npc place|remove|list|reload` は `NPC` 専用とする。
- 補完候補も同じカテゴリ境界を守り、`spawn` に `NPC` を混在させない。
- `NPC` を引数に取るコマンドは、テンプレート ID に加えてカラーコード除去後の表示名、および `id（表示名）` 形式の補完候補を受け付ける。表示名解決はロード済みテンプレートに対して行い、ID 完全一致は未ロードテンプレートでも遅延ロードで解決する。

## スポナーアイテム表示

`/mob spawner item <spawnerId> [amount]` で付与される Mob スポナー設置アイテムは、日本語の表示名と lore を持つ。lore には、設置前に確認できるスポナー情報として、ID、種別、表示ブロック、スポーン半径、判定間隔、時間帯、出現対象と重み、スポナー単位上限、周辺 Mob 上限、プレイヤーあたり出現数を表示する。
