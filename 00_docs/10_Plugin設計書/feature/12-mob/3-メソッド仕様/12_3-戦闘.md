# 12_3-戦闘

戦闘・ダメージ・ノックバック・ヘイト・ドロップを管理するレイヤー。バニラ Bukkit のダメージイベント（`EntityDamageEvent`）と属性（`AttributeInstance`）には依存せず、すべて本機能内で計算する。

## 1. MobCombatService メソッド仕様

### ターゲット選定

クラス名: `MobCombatService`
物理名: `selectTarget`

責務:

`targeting.strategy` に従って Mob のターゲットを選定する。

処理内容:

1. `aggroRange` 内のオンラインかつ生存しているプレイヤーを抽出する（同一ワールド・距離判定）
2. 候補が空なら `null` を返す
3. `strategy` 別に選定
   | 値 | 選定方法 |
   |---|---|
   | `NEAREST` | 距離が最小のプレイヤー |
   | `HIGHEST_THREAT` | [[12_1-モデル定義]].脅威値テーブル の `top()` をまず採用。`null` の場合は `NEAREST` にフォールバック |
   | `RANDOM` | 候補から `ThreadLocalRandom` で選出 |
   | `LOWEST_HP` | `AstPlayer.currentHealth` が最小のプレイヤー（同値時は最近接） |
4. 選定結果を `MobInstance.target` に設定する

入力:

- `instance`: 対象 Mob インスタンス

出力:

- `AstPlayer`（選定失敗時は `null`）

### 攻撃 tick

クラス名: `MobCombatService`
物理名: `tickCombat`

責務:

`ai.combat.skills` 未設定の `COMBAT` 状態 Mob による従来の直接通常攻撃を 1 tick 分処理する。`ai.combat.skills` が設定されている Mob は `MobAiService` から skill feature の `SkillService.castSkill(..., SkillCastTrigger.MOB_AI, ...)` を呼び出して攻撃する。

処理内容:

1. `instance.target` が `null` または範囲外なら `AGGRO` 復帰
2. `attackIntervalTicks` へ `ceil(基本間隔 × 100 / ATTACK_SPEED)` を適用し、`serverTick - instance.lastAttackTick` が短ければ何もしない。Mob テンプレートに `ATTACK_SPEED` がなければ基準値 100 を使う
3. `combat.style` を `MELEE` / `RANGED` / `MAGIC` の attack type へ変換する
4. `DamageService.attack(AstEntity.mob(instance), AstEntity.player(target), attackType, ..., NORMAL_ATTACK, outgoingDamageMultiplier)` を呼ぶ
5. 命中、会心、防御、属性、シールド、HP、ノックバック、表示、死亡処理は `DamageService` に委譲する
6. `instance.lastAttackTick = serverTick`

### AI スキル攻撃

クラス名: `MobAiService`
物理名: `castCombatSkill`

責務:

`COMBAT` 状態の Mob が `ai.combat.skills` に設定されたスキルを使ってプレイヤーへ攻撃する。

処理内容:

1. `combat.skills` が空の場合は [[12_3-戦闘]].攻撃 tick へフォールバックする。
2. Mob が詠唱中なら新しいスキル発動は行わない。
3. `internalTick - instance.lastAttackTick < attackIntervalTicks` なら何もしない。
4. `MobInstance.nextCombatSkillIndex` に基づいて `combat.skills` からスキル ID を選び、発動後に次インデックスへ進める。
5. 次に使用するスキルの発動距離は `SkillDefinition.params.activationRange` を優先し、未指定時は `params.hitRange`、それも未指定または定義未ロード時は `combat.preferredRange` にフォールバックする。発動距離内であれば、`RANGED` / `MAGIC` が近すぎて後退中でも発動を試みる。
6. `SkillService.castSkill(new MobSkillCaster(instance), skillId, SkillCastTrigger.MOB_AI, castOrigin(instance, target), target, List.of(target))` を呼ぶ。`castOrigin` は詠唱開始時の位置と向きを固定する。
7. 成功した場合だけ `lastAttackTick` を更新する。

### ダメージ委譲

クラス名: `DamageService`
物理名: `attack`, `applyDamage`

Mob の自律攻撃と player から Mob への攻撃は、どちらも `DamageService` を唯一のダメージ計算・HP反映経路とする。`MobCombatService` は独自の `computeDamage`、会心計算、`Player#damage`、Mob HP 直接減算を行わない。

`DamageService` は attack type に応じた基本能力値・種別攻撃力、防御・貫通、命中、会心、属性、最終補正、シールド、HP、threat、ノックバック、死亡処理を担当する。Mob レベルは直接のダメージ補正に使用せず、成長差はテンプレートのステータス値で表現する。`MobInstance.outgoingDamageMultiplier` は Mob 自律攻撃だけが追加で渡す攻撃者固有倍率であり、攻撃力解決後かつ会心・防御より前に適用する。

### 致死処理

クラス名: `MobCombatService`
物理名: `handleDeath`

責務:

死亡が確定した Mob のドロップ・破棄を処理する。

処理内容:

1. キラーを決定する
   - `instance.lastAttackerUuid` を使用
   - 取得失敗時は [[12_1-モデル定義]].脅威値テーブル の `top()` をフォールバックとして使用
   - それでも `null` の場合は以下ログを記録してキラーなしで進める

    | 項目 | 内容 |
    |---|---|
    | ID | `LogId.W_5703` |
    | レベル | `WARN` |
    | テンプレート | `Mob のキラーを特定できませんでした instanceId={0}` |
    | 出力条件 | 脅威値テーブル `top()` と `lastAttackerUuid` の両方が `null` の時 |
    | 引数 | インスタンス ID |

2. [[12_3-戦闘]].ドロップ確定 を呼ぶ。例外が発生した場合は捕捉のうえ以下ログを記録し、ドロップは空として進める

    | 項目 | 内容 |
    |---|---|
    | ID | `LogId.E_5703` |
    | レベル | `ERROR` |
    | テンプレート | `Mob のドロップ抽選で例外が発生しました instanceId={0}: {1}` |
    | 出力条件 | ドロップ確定中の例外捕捉時 |
    | 引数 | インスタンス ID, 例外メッセージ |

3. キラーが見つかれば、ドロップ・経験値・金銭を払い出す
   - アイテム: `feature/inventory` の API 経由で追加
   - 経験値: `AccountService.grantExperienceCached` で即時にメモリ反映し、定期 flush で account API へまとめて保存する
   - 金銭: `feature/currency` の通貨加算経路で追加する
4. [[12_3-サービス]].個別 Mob 破棄 を呼ぶ

### ドロップ配布対象と演出

Mob 撃破時のドロップは、対象プレイヤーごとに個別抽選・個別表示・個別付与する。

配布対象:

1. 対象 Mob に 1 ダメージ以上の有効ダメージを与え、脅威テーブルに残っているオンラインプレイヤー
2. とどめを刺したプレイヤーのパーティーメンバーのうち、とどめを刺したプレイヤーと同一ワールドかつ 60m 以内のオンラインプレイヤー

処理:

1. `MobInstance.lastAttackerUuid` を優先してとどめを刺したプレイヤーを特定し、未設定時のみ `MobThreatTable.top()` にフォールバックする。
2. 配布対象を重複排除したうえで、各 `AstPlayer` を `MobDropService.roll` に渡して個別に抽選する。
3. 抽選結果は対象プレイヤーだけに見える TextDisplay のリザルトとして表示し、ドロップアイテム名、数量、設定上のドロップ確率（%）を含める。
4. 解決できたドロップアイテムのうち演出上限内のものだけ ItemDisplay を生成し、PDC を維持したまま icon Material を反映した表示用 ItemStack を `ItemDisplay.ItemDisplayTransform.GROUND` で描画する。
5. 装備 / ルーンはアニメーション開始と同時に非同期で instance API を呼び出し、通常アイテムは即時準備済み扱いにする。
6. ItemDisplay は上方から約 12 tick で着地する落下演出を行い、短い着地待機後に対象プレイヤーの位置へ自動回収される。回収終端では API 完了まで待機できる。
7. 回収到達時に、通常アイテムは `InventoryService.addItemToNormalInventory(..., "mob_drop")`、装備 / ルーンは事前生成済み instance を `InventoryService.addPreparedInstanceToNormalInventory(...)` で追加する。
8. 演出上限を超えたドロップは ItemDisplay を生成せず、同じ付与経路でインベントリへ追加する。
9. item ID を `ItemService` で解決できないドロップは表示・付与対象から除外する。
10. 解決できた当選アイテムのうち、通常 Mob は `rate <= 0.1%`、`BOSS` は `rate <= 5%` をレアドロップと判定する。
11. レアドロップは獲得プレイヤー名、アイテム名、数量、確率をオンラインプレイヤーへ全体通知する。ただし受信者の `DROP_LOG_DISPLAY` が `false` の場合はその受信者に表示しない。

補足:

- 致死処理のうち Bukkit Entity の破棄、表示生成、アニメーション開始はメインスレッドで行う。
- 外部 API / 永続化 I/O を伴う経験値更新はメインスレッドを直接ブロックせず、account 単位の逐次非同期キューへ委譲する。

ダメージ成立時のノックバックは `DamageService` のダメージ結果処理から `MobKnockbackService.apply` を呼ぶ共通経路で適用する。シールド吸収だけで HP ダメージが成立しない場合はノックバックを発生させない。攻撃種別ごとの倍率は `MELEE = 1.0`、`RANGED = 0.55`、`MAGIC = 0.4` とし、近接武器を最大、弓・杖など遠距離系を弱めに扱う。

## 2. MobKnockbackService メソッド仕様

### ノックバック適用

クラス名: `MobKnockbackService`
物理名: `apply`

責務:

攻撃方向にノックバックベクトルを算出し、対象へ送出する。

処理内容:

1. 攻撃元と対象の水平ベクトルを正規化する
2. 基本ノックバック量 `baseKnockback = 0.4`
3. `StatusType.KNOCKBACK_RESISTANCE` を 0-100% として読み、`multiplier * (1 - resistance / 100)` で軽減する。
4. 垂直成分 `verticalKick = 0.4`
5. 対象がプレイヤーなら `Player.setVelocity` で送出
6. 対象が Mob なら `MobEntityController.addVelocity` 経由で実体 Mob の速度へ反映する

入力:

- `source`: 攻撃元（Mob / Player）
- `target`: 被攻撃側（Mob / Player）
- `multiplier`: ノックバック倍率（既定 1.0）

出力:

- なし

## 3. MobThreatTable メソッド仕様

### 脅威値加算

クラス名: `MobThreatTable`
物理名: `add`

責務:

指定プレイヤー UUID の脅威値に値を加算する。

処理内容:

1. `Map.merge(playerId, amount, Double::sum)` で加算
2. 値が 0 以下になった場合はエントリ削除

入力:

- `playerId`: プレイヤー UUID
- `amount`: 加算量

### 脅威値最大プレイヤー取得

クラス名: `MobThreatTable`
物理名: `top`

責務:

最大脅威値を持つプレイヤー UUID を返す。

処理内容:

1. エントリが空なら `null`
2. `Map.Entry.comparingByValue` で最大値を取り、UUID を返す

### 脅威値減衰

クラス名: `MobThreatTable`
物理名: `decay`

責務:

すべてのエントリに減衰係数を乗算する。

処理内容:

1. `factor` を `0.0 <= factor <= 1.0` にクランプ
2. 各エントリに `value * factor` を適用
3. 1.0 未満となったエントリは削除

呼び出し元: `MobAiService.tick` から定期的（例: 100 tick = 5 秒ごと）に呼ぶ。減衰係数の既定は 0.99。

## 4. MobDropService メソッド仕様

### ドロップ確定

クラス名: `MobDropService`
物理名: `roll`

責務:

`drops` 設定に基づいてドロップ結果を抽選し、配布可能な形式に確定する。

処理内容:

1. `drops` が `null` なら空結果を返す
2. `drops.items[]` を順に評価
   | 項目 | 処理 |
   |---|---|
   | `rate` | 0-100 の乱数と比較。`rate >= 100` の場合は確定ヒット |
   | `luckAffected = true` | キラーの最新 `StatusSnapshot` の `LUCK` 値で `rate` に加算補正（`LUCK * 0.05`）。補正後は 0〜100 にクランプ |
   | `amount` | `n` 形式は固定値、`a~b` 形式は `[a, b]` の一様分布 |
   | `hidden` | ドロップ結果には影響しない（図鑑表示用フラグ） |
3. `drops.lootTable` が指定されていれば、`LootService.getLoaded` で起動時ロード済みキャッシュを参照する。ヒット時は `LootRollService.roll` の content ごとの独立確率抽選結果を結合し、キャッシュ未命中時は直接ドロップだけを維持する。loot content の設定 `rate` はそのまま表示・レア判定へ渡す
4. `drops.exp`, `drops.money.min~max` を結果に含める。`drops.exp` は受取人ごとに、プレイヤーと Mob の絶対レベル差 1 につき 5% 減衰し、最低 10% まで補正する。同レベルは 100% とする。

入力:

- `template`: 撃破された Mob テンプレート
- `killer`: キラー（`AstPlayer`、`null` 許容）

出力:

- [[12_3-戦闘]].ドロップ結果（アイテム ID + 数量 + 設定上のドロップ確率のリスト、合計 exp、合計 money）

### ドロップ結果

物理名（型）: `MobDropResult`

| 項目 | 型 | 説明 |
|---|---|---|
| `items` | `List<MobDropResultItem>` | item ID、数量、設定上のドロップ確率の組 |
| `exp` | `int` | レベル差補正後の経験値合計 |
| `money` | `int` | 金銭合計 |

## 5. 設計上の制約

- ダメージ計算式は本ドキュメントが正本。改訂時は本ファイルと [[12_4-統合フロー]] を必ず更新する。
- 命中判定・会心判定・ドロップ抽選はすべてサーバーサイドで完結する（クライアント乱数を信用しない）。
- 致死処理はメインスレッドで実行する。ドロップ抽選で I/O が必要になった場合は非同期化を検討（[[12_9-未決事項]] 参照）。

## 6. バニラダメージとバニラ可視状態の抑止

`MobVanillaDamageBlockEventHandler` は `MobService.getInstanceByEntity(...)` で AstralRecord 管理 Mob を解決し、`category = ENEMY` / `BOSS` の Bukkit `EntityDamageEvent` を常にキャンセルする。炎上、窒息、奈落、溶岩、落下、凍結など、Bukkit が発火するバニラダメージは HP 計算へ入れない。

damage / combust handler 自体の例外は `E_5706(operation, target)` を使用し、operation は `vanilla_damage` / `vanilla_combust`、target は entity name とする。

同ハンドラは `EntityCombustEvent` もキャンセルし、バニラ由来の fire ticks を 0 に戻す。これにより、日光で燃える EntityType をモデルとして使った enemy / boss でも、炎上表示と炎ダメージは発生しない。

火傷などの独自状態異常で炎上表示を追加する場合は、`MobVanillaEffectProtectionService.applyPluginFireTicks(entity, ticks)` を経由して付与する。この経路で付与された fire ticks はプラグイン由来として扱い、バニラ燃焼抑止の解除対象から外す。ただし、fire ticks によるバニラ `FIRE_TICK` ダメージ自体は引き続き `EntityDamageEvent` 側でキャンセルし、独自状態異常のダメージ計算は AstralRecord の combat / status 経路で行う。

## プレイヤー死亡中の戦闘除外

- `MobAiService.selectTarget(...)` は `Player#isDead()` が true のプレイヤー、および `PlayerDeathService.isDead(playerUuid)` が true の custom 死亡中プレイヤーをターゲット候補に含めない。
- `MobAiService.resolveChaseTarget(...)` は現在 target が Bukkit 死亡中または custom 死亡中の場合、target を失効扱いにして再選定する。再選定できない場合は target を解除して `IDLE` へ戻す。
- `MobCombatService.applyDamage(...)` は攻撃者プレイヤーが死亡中の場合、Mob へダメージ、ノックバック、threat 加算を行わず `0.0` を返す。
- `MobCombatService.resolveDropRecipients(...)` / `addRecipient(...)` は死亡中プレイヤーをドロップ、経験値、討伐記録、演出付与の対象に含めない。
