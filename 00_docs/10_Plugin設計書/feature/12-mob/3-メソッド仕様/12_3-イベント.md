# 12_3-イベント

## 1. 採集対象の左クリック候補

クラス名: `GatheringInteractionEventHandler`
物理名: `resolve`

`InputFamily.LEFT_CLICK` かつメインハンド入力だけを対象とし、`GatheringService.findTargetedHit` で視線上の採集 object と hitbox 入口距離を解決する。snapshot の blocking distance より手前に見える場合、次の候補を 1 件返す。

| 項目 | 値 |
|---|---|
| candidate ID | `gathering-interaction` |
| tier | `WORLD_INTERACTION` |
| order | `GATHERING` |
| stable key | gathering instance UUID |
| claim | `CLAIM_AND_CANCEL` |
| executor | `GatheringService.startMining(player)` |

勝者実行前に snapshot を refresh し、同じ instance が引き続き可視であることを再検証する。候補収集時は HP、採集 session、drop を変更しない。

## 2. 採集スポナーの左クリック候補

クラス名: `GatheringSpawnerBlockEventHandler`
物理名: `resolve`

メインハンド左クリックでは `AccountMode.ADMIN` の viewer だけを対象とする。clicked block または視線 6 block 以内・radius 0.9 の登録座標から最短候補を選び、次を返す。

| 項目 | 値 |
|---|---|
| candidate ID | `gathering-spawner-left-interaction` |
| tier | `WORLD_INTERACTION` |
| order | `GATHERING_SPAWNER` |
| stable key | world UUID と block 座標 |
| claim | `CLAIM_AND_CANCEL` |
| executor | 管理権限を再検証して `removeLocation` |

勝者実行前に視線と同一座標を再検証する。viewer 条件と削除権限は同一ではなく、削除時は `GatheringSpawnerService.isAdminMode` の `hasAdminPermission()` 判定を必ず行う。

## 3. 採集スポナーの block mutation 候補

クラス名: `GatheringSpawnerBlockEventHandler`
物理名: `resolve`

- `BLOCK_PLACE`: item の PDC `gathering_spawner_id` を読めた場合、`gathering-spawner-place` を `CLAIM_AND_CANCEL` で返す。executor は権限・定義・座標重複を検証して配置を登録する。
- `BLOCK_BREAK`: 登録座標の場合、`gathering-spawner-break` を `CLAIM` で返す。executor は権限を検証し、登録を削除する。権限不足時は event を cancel する。
- 通知は成功時 `P_5709` / `P_5710`、登録失敗 `P_5711`、権限不足 `P_5719` を使う。

block event 自体の cancel と winner 選択は `player-interaction` を正本とし、この resolver は候補収集時に配置 cache を変更しない。

## 4. Mob spawner の左クリック・block mutation 候補

クラス名: `MobSpawnerBlockEventHandler`
物理名: `resolve`

- packet 表示の可否は `MobSpawnerService.canViewSpawnerVisual` が `user.permission = 99` だけで判定し、account mode は参照しない。
- `mob-spawner-left-interaction` は `MobSpawnerService.canRemoveSpawner` が `user.permission = 99` かつ `AccountMode.ADMIN` を返す場合だけ `CLAIM_AND_CANCEL` で候補化する。同条件・同座標・可視性を winner 実行直前にも再検証する。
- 条件を満たさない場合は候補を返さず、左クリックを claim/cancel しない。
- 登録済み座標の `mob-spawner-break` は `CLAIM` 候補とし、executor が同じ削除認可を再検証する。拒否時は block break event を cancel する。
- `mob-spawner-place` の設置認可は従来どおり `isAdminMode` の user permission 判定を使う。

## 5. Mob・採集 world input の共通境界

- `MobInteractionEventHandler`、`MobSpawnerBlockEventHandler`、`GatheringInteractionEventHandler`、`GatheringSpawnerBlockEventHandler` はいずれも `PlayerInputResolver<PlayerInteractionSnapshot>` として gateway へ登録する。
- tier、距離、candidate order、stable key による勝者選択は [[28_3-サービス]] を正本とする。
- winner executor が失敗・拒否しても、同じ入力で次順位候補へ fallback しない。
- managed Mob の Bukkit damage / combust 抑止は [[12_3-戦闘]] の `MobVanillaDamageBlockEventHandler` を正本とする。

## 6. NPC 配置の world load retry

クラス名: `NpcPlacementWorldEventHandler`
物理名: `onWorldLoad`

`WorldLoadEvent` を `MONITOR` で受け、20 tick 後に `NpcPlacementService.spawnLoadedWorlds` を実行する。未 spawn 配置が残る間は最大 5 回まで再試行する。

- event 受付例外: `E_5706(operation=npc_world_load, target=<worldName>)`
- retry 例外: `E_5706(operation=npc_world_retry, target=<worldName>:remaining=<count>)`

## 7. managed Mob の vanilla damage・combust 抑止

クラス名: `MobVanillaDamageBlockEventHandler`
物理名: `onEntityDamage`, `onEntityCombust`

`ENEMY` / `BOSS` category の managed entity に対する Bukkit damage と combust を `HIGHEST` で cancel し、vanilla visual を解除する。例外は `E_5706` へ `vanilla_damage` / `vanilla_combust` と entity name を渡し、AI tick 用 `E_5702` を流用しない。独自 HP・condition damage の契約は [[12_3-戦闘]] を正本とする。
