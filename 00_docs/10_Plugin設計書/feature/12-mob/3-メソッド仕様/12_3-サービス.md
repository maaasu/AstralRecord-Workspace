# 12_3-サービス

## 1. MobService メソッド仕様

`MobService` はテンプレートキャッシュ、`MobInstance` キャッシュ、Bukkit 実体 Mob との対応、頭上 packet display 用 viewer キャッシュを管理する。

### テンプレート全件ロード

クラス名: `MobService`
物理名: `loadAll`

1. [[12_3-リポジトリ]].Mob 一覧取得 を呼ぶ。
2. 取得した `MobTemplate` を id キーの `LinkedHashMap` に保持する。
3. `LogId.I_5700` を記録し、ロード件数を返す。

### テンプレート取得

クラス名: `MobService`
物理名: `findTemplate`

1. `templates` キャッシュから `mobId` を取得する。
2. 未ヒット時は [[12_3-リポジトリ]].Mob 取得 を呼び、取得できた場合のみキャッシュへ登録する。
3. 取得できない場合は `null` を返す。

### テンプレート入力解決

クラス名: `MobService`
物理名: `resolveTemplateId`

1. 入力がロード済みテンプレート ID と完全一致する場合は、その ID を返す。
2. 入力がテンプレート ID らしい ASCII 形式（英数字、`_`、`-`）のときだけ、未ロードテンプレートに対して `findTemplate` による遅延ロード解決を試みる。
3. ロード済みテンプレートに対して、カラーコード除去後の表示名、および `id（表示名）` / `id(displayName)` 形式を正規化比較する。
4. 指定カテゴリに一致するテンプレートだけを候補とし、一致しない場合は `null` を返す。

### Mob スポーン

クラス名: `MobService`
物理名: `spawn`

1. テンプレート ID を受け取った場合はキャッシュまたは API から解決する。未取得なら `LogId.W_5701` を記録して `null` を返す。`MobTemplate` を直接受け取った場合は API・キャッシュを介さず、その実行時テンプレートを使用する。
2. レベル指定付きの ID 呼び出しは `MobTemplate.resolveLevel(level)` を通し、未指定または未登録レベルでは同一 Mob の最小レベルプロファイルを使用する。レベル指定なしの既存呼び出しも同じ既定解決を通る。
3. `UUID.randomUUID()` で `instanceId` を採番し、`MobInstance` を生成する。
4. `MobEntityController.spawn` を呼び、Bukkit/Paper の実体 `Mob` を生成する。
5. 実体生成時、`MobEntityController` は以下を行う。
   - `Bukkit.getMobGoals().removeAllGoals(mob)` で vanilla goal を全削除する。
   - `setAI(true)` / `setAware(true)` を維持し、Paper Pathfinder を利用可能にする。
   - `setInvulnerable(true)` によりバニラダメージでは HP を減らさない。
   - `setPersistent(false)` / `setRemoveWhenFarAway(false)` / `setCanPickupItems(false)` / `setCollidable(false)` / `setSilent(true)` を設定する。
   - PDC に `mob_instance_id` と `mob_template_id` を保持する。
   - `MobInstance.bindEntity` で `bukkitEntityId` / `entityId` / `currentLocation` を同期する。
6. 実体生成に失敗した場合は `LogId.W_5705` を記録して `null` を返す。
7. `instances`、`instanceByEntity`、`viewers` に登録し、`LogId.D_5701` を記録して `MobInstance` を返す。

### Mob HP回復

クラス名: `MobService`
物理名: `recoverHealth`

1. `MobInstance.recoverHealth` で正の有限回復量だけを受け付け、現在 HP を最大 HP までクランプする。`DEAD` 状態または最大 HP 到達済みなら増加量は `0` とする。
2. 実際に増加した量が正の場合だけ、回復対象 Mob と実回復量を HP 回復通知へ渡す。定期回復など表示しない呼び出しでは通知フラグを `false` にする。
3. 実回復量を返す。

### 実体から Mob インスタンス取得

クラス名: `MobService`
物理名: `getInstanceByEntity`

Bukkit Entity UUID から管理中の `MobInstance` を取得する。`ComplexEntityPart` の場合は親 Entity の UUID を使い、Ender Dragon の各部位を同じボスへ解決する。

### Mob 破棄

クラス名: `MobService`
物理名: `destroy`

1. `instances` から `instanceId` を削除する。
2. 対応する状態異常、`viewers`、`instanceByEntity`、Bukkit 実体 Mob を破棄する。
3. 破棄 listener へ `instanceId` を通知し、`SkillService.clearCasterState` で詠唱とクールダウンを解放する。
4. 成功時は `LogId.D_5702` を記録し、破棄できたかどうかを返す。

### 全 Mob 破棄

クラス名: `MobService`
物理名: `destroyAll`

1. 全 `MobInstance` の状態異常、実体 Mob、詠唱、クールダウンを破棄する。
2. `instances`、`instanceByEntity`、`viewers` をクリアする。
3. `LogId.I_5701` を記録し、破棄件数を返す。

### 表示対象 viewer 更新

クラス名: `MobService`
物理名: `updateViewers`

Mob 本体は Bukkit/Paper の entity tracking に任せる。本メソッドは頭上 packet display の viewer キャッシュだけを更新する。

1. 実体 Mob の現在位置を `MobEntityController.syncLocation` で `MobInstance.currentLocation` へ反映する。
2. 64 ブロック以内かつ同一ワールドのオンラインプレイヤー UUID を `viewers` へ登録する。
3. 範囲外またはオフラインのプレイヤー UUID を `viewers` から削除する。

### viewer キャッシュによる近接プレイヤー判定

クラス名: `MobService`
物理名: `hasPlayerWithinDistanceUsingCachedViewers`

直前の `updateViewers` で得た 64 ブロック以内の viewer 集合を再利用し、指定距離内のプレイヤー有無を判定する。オンラインプレイヤー全体の追加走査は行わず、集合内のプレイヤーについてだけ同一ワールドと距離を再確認する。`MobAiService` の近接プレイヤー不在判定はこの経路を使用する。

### Mob 発光状態更新

クラス名: `MobService`
物理名: `setGlowing`

1. `MobInstance.glowing` を更新し、管理対象の実体 Entity へ `setGlowing` を反映する。
2. `category = NPC`、要求された `entityType = PLAYER`、署名付き `skin` がそろう場合は、`NpcPlayerSkinPacketService.setGlowing` へ委譲して表示中の疑似 Player へも反映する。
3. player-skin NPC の疑似 Player がまだ表示 state を持たない場合は、次回の表示開始時に `MobInstance.glowing` を Entity Metadata へ反映する。

### NPC プレイヤースキン表示同期

クラス名: `NpcPlayerSkinPacketService`
物理名: `sync`, `setGlowing`, `remove`, `removeAll`

`category = NPC`、要求された `entityType = PLAYER`、署名付き `skin` がそろうテンプレートだけを対象とする。`MobRepository` は `PLAYER` を実体生成用の `VILLAGER` へ解決するが、`requestedEntityType` は `PLAYER` のまま保持する。

1. 表示対象 viewer ごとに実体 NPC を `hideEntity` で隠し、同じ位置へ GameProfile 付きの疑似 Player を ProtocolLib で送信する。初回の PlayerInfo から `listed=false` とし、スキン付き GameProfile は登録するが tab list には一度も掲載しない。GameProfile の内部名は viewer ごとの hidden name team へ登録し、名前タグとして表示しない。
2. 疑似 Player の `USE_ENTITY` は、viewer と fake entity ID を検証したうえで実体 NPC の Entity ID へ書き換える。AI、移動、当たり判定、NPC interaction は実体 NPC の経路を継続利用する。
3. viewer 集合の探索は 5 tick 周期、表示中 viewer への transform 同期は 1 tick 周期で行う。位置・体の向き・実体 Mob の現在角度または `lookAt` から算出した頭部 yaw/pitch のいずれかが変化したときだけ疑似 Player の移動・look packet を送信する。
4. `setGlowing` は Entity Metadata の Entity flags（index `0`）へ glowing bit `0x40` を設定または解除し、表示中の全 viewer へ送信する。表示 state がない場合は `MobInstance.glowing` を次回の表示開始へ引き継ぐ。
5. 表示解除、範囲外、NPC 破棄、ProtocolLib 無効化時は疑似 Player と profile を削除し、表示開始時に隠した実体 NPC を viewer ごとに再表示する。スキン値が不完全な NPC は疑似 Player 化せず、実体 Entity の通常表示を使う。疑似 Player NPC の頭上 Mob TextDisplay は実体 Entity の passenger ではなく、疑似 Player の足元から固定高さで追従する。

### 視認距離外 enemy 破棄

クラス名: `MobService`
物理名: `destroyEnemiesOutsideViewDistance`

1. `category == ENEMY` かつ `keepWhenUnobserved=false` の `MobInstance` を対象にする。`BOSS` / `NPC` と維持指定された enemy は自動破棄対象外とする。
2. 実体位置を同期し、同一ワールドかつ 64 ブロック以内のオンラインプレイヤーが 1 人もいない enemy を抽出する。
3. 抽出した enemy は `MobService.destroy` で破棄する。プラグイン都合の削除のため、`MobCombatService.handleDeath` は呼ばず、ドロップ、討伐記録、リザルト TextDisplay は発生させない。

### 近接プレイヤー不在 Mob 破棄

クラス名: `MobAiService`
物理名: `destroyMobsAfterIdleTimeout`

1. `category = ENEMY` または `BOSS`、`keepWhenUnobserved=false`、`state != DEAD` の `MobInstance` を対象にする。`NPC` と維持指定個体は対象外とする。
2. `targetId = null` かつ、直前の viewer 更新後に 20 ブロック以内の有効なプレイヤーがいない場合、`noNearbyPlayerSinceTick` を開始または継続する。ターゲットまたは近接プレイヤーが戻った場合は `-1` に戻す。
3. 近接プレイヤー不在状態が 1,200 サーバー tick（60 秒）継続し、その区間の開始後に Mob が実ダメージまたはシールドダメージを与えた、または受けていない場合、`MobService.destroy` でリザルトなしに破棄する。ダメージ成立時刻は `lastCombatActivityTick` で記録し、区間内に成立した場合はその時刻から再度 1,200 tick を待つ。
4. 判定は viewer 更新後の 20 tick 周期で行い、`Bukkit.getOnlinePlayers()` の Mob ごとの追加走査を行わない。

### Paper Pathfinder 移動要求

クラス名: `MobService`
物理名: `moveToward`

1. `MobEntityController.moveTo` へ `MobInstance`、目標 `Location`、AI 速度倍率、内部 tick を渡す。
2. `MobEntityController` は目標地点の移動量と `PATH_RECOMPUTE_INTERVAL_TICKS` により、毎 tick の経路再計算を避ける。
3. 目標付近に到達した場合は `stopPathfinding` で経路探索を停止する。
4. `NPC` かつ `idle.behavior = WANDER` の個体は、分散した 600 tick（30 秒）周期で `wanderAnchor` へ戻る経路を設定する。通常の周期処理ではテレポートせず、現在の徘徊目的地を配置アンカーへ切り替える。
5. 同じ WANDER 目的地に対して 200 tick（10 秒）連続で水平移動がない場合は詰まりと判定する。前回の緊急テレポートから 3,600 tick（3 分）以上経過している場合だけ `wanderAnchor` へテレポートして位置・経路・徘徊目的地をリセットし、クールダウン中は配置アンカーへの経路を再設定する。判定は IDLE の 10 tick 間隔で行う。

## 1.5. NpcPlacementService メソッド仕様

### NPC 配置ロード

クラス名: `NpcPlacementService`
物理名: `loadAll`

1. `npc_placements.yml` から NPC 配置一覧を読み込む。
2. 既存の管理対象 NPC 実体と location-key キャッシュを破棄し、最新配置へ入れ替える。
3. その時点で `Bukkit.getWorld(worldName)` が解決できる配置は即時スポーンする。
4. ワールドがまだ解決できない配置もメモリ上には保持し、後続の `spawnLoadedWorlds` / `spawnForWorld` で再試行できる状態を維持する。
5. スポーン前に対象チャンクを明示的にロードし、起動直後やワールドロード直後でも `World.spawnEntity(...)` が失敗しにくい状態にしてから生成を試みる。

### ロード済みワールド再スポーン

クラス名: `NpcPlacementService`
物理名: `spawnLoadedWorlds`

1. 現在ロード済みの全ワールドに対して、未スポーンの NPC 配置だけを再評価する。
2. `AstralRecord` の onEnable 完了後 1 tick 遅延起動、および `WorldLoadEvent` 後の 1 tick 遅延再試行経路から呼び出し、起動順差で取りこぼした NPC を補完する。
3. すでに管理中の location-key は重複スポーンしない。

### NPC 配置削除

クラス名: `NpcPlacementService`
物理名: `removeByNpcId`

1. `placements` から `npcId` 一致する location-key 一覧を抽出する。
2. 抽出した location-key ごとに、保存済み配置・出現中 NPC・チャンクチケットをまとめて破棄する。
3. 1 件以上削除した場合だけ `npc_placements.yml` を更新する。
4. 戻り値は削除した配置件数とする。

## 2. MobEntityController メソッド仕様

### 実体 Mob 生成

クラス名: `MobEntityController`
物理名: `spawn`

通常 Mob は `template.entityType()` に対応する Bukkit `Mob` を生成する。固定表示用の `ARMOR_STAND` は例外として可視の Bukkit `ArmorStand` を生成し、重力・衝突・装備操作を無効化する。spawn 直後で Paper の `isValid` がまだ反映されていなくても、dead でない生成済み ArmorStand は管理対象として取得できる。NPC `entityType` が通常 block Material として解決された場合は `Interaction` と `BlockDisplay` の二層構造を生成し、配置座標を fakeblock の水平中心として扱う。BlockDisplay は transformation で水平中央へ寄せ、下端を配置 Y 座標に接地させ、通常ブロックの `0.75` 倍で描画する。`CHEST` / `TRAPPED_CHEST` / `ENDER_CHEST` は例外として元 Material の `ItemStack` を持つ `ItemDisplay` を使い、transform は `NONE`、`Transformation.translation.y` は `+0.375`、scale は `0.75` とする。world の spawn 座標自体へ Y offset は加えない。block NPC の描画はプレイヤー方向へ回転させず、配置時の向きのまま固定する。PDC に `mob_instance_id` / `mob_template_id` を付与して fakeblock NPC として扱う。

block NPC は通常 NPC と同じ頭上 display text を持ち、AI tick で ambient particle を表示する。Entity ray trace で対象を拾えない場合も、視線と 1 block AABB の交差判定で左クリック/右クリック interaction を発火させる。

### 実体 Mob 設定

クラス名: `MobEntityController`
物理名: `configure`

vanilla goal 全削除、PDC 設定、独自名表示、不要挙動の抑止、Pathfinder のドア・浮遊設定を行う。Piglin 系（`Piglin` / `PiglinBrute`）には `setImmuneToZombification(true)` を設定し、ワールド環境による Zombified Piglin への変換を抑止する。

### 実体 Mob 取得

クラス名: `MobEntityController`
物理名: `getMob`

`MobInstance.bukkitEntityId` から `Bukkit.getEntity` で実体を解決する。`getMob` は無効・死亡済み・Mob 以外なら `null` を返し、汎用 `getEntity` と位置同期は有効な `ArmorStand` も返す。

### 実体位置同期

クラス名: `MobEntityController`
物理名: `syncLocation`

有効な実体 Mob の `getLocation()` を `MobInstance.currentLocation` に反映し、同じ位置の yaw / pitch を疑似 Player 表示用の頭部角度へ同期する。

### 移動要求

クラス名: `MobEntityController`
物理名: `moveTo`

Paper Pathfinder の `moveTo(target, speed)` を呼び出す。以下の軽量化ルールを持つ。

- 目標まで 0.6 ブロック以内なら `stopPathfinding` する。
- 既存 path があり、目標地点の X/Z 変化が 1.5 ブロック未満で、再計算間隔未満なら再要求しない。
- `MOVEMENT_SPEED` と `idle.speed` から Pathfinder speed を算出し、`0.05` から `2.5` に丸める。

## 3. MobAiService メソッド仕様

### tick タスク開始 / 停止

クラス名: `MobAiService`
物理名: `start` / `stop`

`BukkitScheduler.runTaskTimer` で 1 tick 周期の AI ループを起動・停止する。開始時は `LogId.I_5702`、停止時は `LogId.I_5703` を記録する。

### AI tick 本体

クラス名: `MobAiService`
物理名: `tick`

1. 内部 tick を進め、`MobService.getInstances` のスナップショットを取得する。
2. 各インスタンスで実体位置を同期する。実体が存在しない場合はインスタンスを破棄する。
3. 100 tick ごとに脅威値を減衰する。
4. leashRange 超過、またはスポーン地点との上下差が8ブロックを超えた場合は `LEASHED` へ遷移する。
5. 状態別処理を行う。
   - `IDLE`: 10 tick 間隔でターゲット探索・徘徊目的地選定を行う。`NPC` かつ `idle.behavior = WANDER` は 600 tick（30 秒）ごとに `wanderAnchor` へ戻る経路を設定し、通常の周期ではテレポートしない。現在位置を観測し、同一目的地へ 200 tick（10 秒）水平移動しなければ詰まりと判定する。前回の緊急テレポートから 3,600 tick（3 分）以上経過している場合だけ詰まり時にテレポートし、クールダウン中は配置アンカーへの経路を再設定する。`NPC` かつ `idle.behavior = STATIONARY` の場合は path を停止し、水平速度も 0 に補正したまま 64 ブロック以内の最寄りプレイヤーへ視線だけ向ける。ただし block NPC は視線追従の回転対象外とし、描画を固定する。
   - `AGGRO`: 5 tick 間隔で追跡対象の再評価と Pathfinder 目標設定を行う。
- `COMBAT`: 次スキルの共通発動距離判定が不成立なら `AGGRO` へ戻す。`allowsVerticalTargeting=true` のスキルが三次元射程内にあり、高低差だけが 1.25 block を超える場合は、Pathfinder を停止して現在地から詠唱・発動する。この場合は後退・左右移動を行わない。同じ高さ、および上下照準を許可しないスキルでは従来どおり高低差 1.25 block を上限とし、`RANGED` / `MAGIC` で理想距離より近すぎる場合は、その場停止せず後退して距離を取り直す。
   - `LEASHED`: 5 tick 間隔でスポーン地点へ戻す。上下差が8ブロックを超えた場合は `resetPosition` で直接リセットし、それ以外は Pathfinder 目標設定を行う。到達で `IDLE` へ戻す。
   - `DEAD`: `MobService.destroy` で破棄する。
6. 5 tick ごとに `MobService.updateViewers` を呼び、頭上 packet display の viewer キャッシュを更新する。
7. 同じ 5 tick 周期で `MobService.destroyEnemiesOutsideViewDistance` を呼び、どのプレイヤーの描画距離にも入っていない `ENEMY` をリザルトなしで破棄する。`keepWhenUnobserved=true` の個体は維持する。
8. viewer 更新後の 20 tick 周期で [[12_3-サービス]].近接プレイヤー不在 Mob 破棄を呼び、`targetId` がなく、20 ブロック以内にプレイヤーがいない状態が 1,200 tick 続き、同区間にダメージ活動がない `ENEMY` / `BOSS` をリザルトなしで破棄する。
9. 毎 tick `MobService.syncPlayerSkinPacketViews` を呼び、表示中の疑似 Player NPC の位置・体の向き・頭部回転を差分同期する。

バインドサークル拘束中は経路探索を止め、`COMBAT` 状態かつ攻撃可能な場合だけ通常攻撃を続ける。ただし `scriptedAction=true` の専用行動中は、拘束中でも通常攻撃を実行しない。

### 一時挑発と追跡対象解決

クラス名: `MobTauntService` / `MobAiService`
物理名: `apply` / `activeTaunter` / `resolveChaseTarget`

1. 一時挑発はMobインスタンスIDごとに、対象Mob、挑発者プレイヤーUUID、有効期限tickを保持する。脅威テーブルへ値を加算しない。
2. 同じMobへ新しい挑発を適用した場合は、既存の挑発者と期限を後発の値で置換し、Mobを `AGGRO` にして現在対象を挑発者へ更新する。NPC、ターゲット設定なし、`DEAD`、`LEASHED` は適用しない。
3. `resolveChaseTarget` は有効な挑発者を、現在対象のdeaggroRange内維持と通常のtargeting strategyより先に解決する。挑発者がonline・生存・同一worldなら追跡対象として返す。
4. 期限切れ、挑発者が無効、退出、死亡、world変更では、その挑発が設定した現在対象だけを解除する。その後は既存の `HIGHEST_THREAT` 等のstrategyから通常選定する。
5. Mob破棄時は当該Mobの状態を、Plugin停止時は全状態を破棄する。

### 軽量化ルール

- バニラ goal は spawn 直後に全削除し、不要な vanilla 行動 tick を発生させない。
- `setAI(false)` は使わない。Paper Pathfinder を利用するため `AI=true` を維持する。
- IDLE の探索は全 Mob 同時ではなく、`instanceId.hashCode + internalTick` で分散する。
- AGGRO / LEASHED の追跡判断は 5 tick 間隔に抑える。
- Pathfinder の `moveTo` は目標ドリフトと再計算間隔で制限する。
- Mob 本体の viewer 管理は Bukkit/Paper に任せ、プラグイン側 viewer は頭上表示用に限定する。
- 疑似 Player NPC は viewer 集合を 5 tick ごとに探索し、既存 viewer への transform だけを毎 tick 差分同期する。

## 4. 設計上の制約

- すべての Bukkit/Paper API 操作はメインスレッドから呼び出す。
- 実体 Mob は永続化しない。サーバ停止時は `destroyAll` で remove する。
- バニラダメージイベントを Mob HP の正本にはしない。独自攻撃・combat/skill 側から `MobInstance.currentHealth` を更新する。

## 6. プレイヤー入力候補解決

クラス名: `PlayerInputResolver`
物理名: `resolve`

mob / spawner側のresolverは[[28_1-モデル定義]].プレイヤー入力コンテキスト を読み、次の`PlayerInputCandidate`を副作用なしで返す。

| family | 候補 | tier・距離 |
|:--|:--|:--|
| 右クリック | NPC、fakeblock NPC | world interaction。拡張entity AABBまたはblock AABBへのray入口距離 |
| 左クリック | NPC、fakeblock NPC、packet-only Mob / gathering spawner 表示、採集 object | world interaction。拡張entity AABB、block AABBまたは各 hitbox への ray 入口距離 |
| block mutation | Mob / gathering spawner item 設置、登録 block 破壊 | world interaction。event 対象 block までの距離 |

1. NPC候補は一つの選択済みユースケースとして、勝者executor内で定義順の`message` / `gui` / `command` actionを実行してよい。`gui` の `type: LOGIN_BONUS` は `LoginBonusService.openAfterDataLoaded`、`type: PARTY_BOARD`は`PartyBoardGui.open`を呼び出す。
2. Mob entity NPCはPaperの単発ray結果だけを採用せず、rayの太さで拡張した全entity AABBと全block NPC AABBを入口距離で比較する。同一種別で距離が同じNPC / fakeblock NPCはMob instance UUID、Mob spawnerはworld UUIDとblock座標のlocation keyで決定する。
3. 遮蔽blockより遠いpacket-only表示は候補にしない。
4. 権限不足、無効なaction、重複座標などは勝者の拒否として終了し、武器・action ring・別spawnerへfallbackしない。
5. 入力相関、tier比較、winner一件実行は[[28_3-サービス]]を正本とする。

## 7. GatheringService メソッド仕様

### 採集定義の読込・公開

クラス名: `GatheringService`
物理名: `loadAll`, `loadDefinitionSnapshot`, `replaceDefinitionSnapshot`, `findDefinition`, `activateDefinitionSnapshot`

- `loadDefinitionSnapshot` は repository の全定義を immutable list にする。
- `replaceDefinitionSnapshot` は ID key の cache を全置換する。
- `activateDefinitionSnapshot` は旧定義に属する instance・採集 session・packet 表示を全破棄する。Bukkit API を操作するためメインスレッドで実行する。
 - `loadAll` は 3 段階を順に実行し、公開後の定義件数を返す。
- `findDefinition` は namespace prefix を除いた採集 ID から定義を参照し、未登録時は `null` を返す。スポナーの管理表示名解決にも使用する。

### 採集 service の開始・停止

クラス名: `GatheringService`
物理名: `start`, `stop`

`start` は `GatheringVisualizer` の 5 tick task を冪等に開始する。`stop` は全 player session、visualizer、instance cache を破棄する。drop 表示と quest は `setDropPresentationService` / `setQuestService` で plugin 初期化後に注入する。

### 採集 instance の生成・破棄

クラス名: `GatheringService`
物理名: `spawn`, `destroy`, `clearInstances`

- `spawn` は namespace prefix を除いた ID を cache から解決し、world が存在する場合だけ block 中央へ `GatheringInstance` を生成する。同一ワールドの同一ブロック座標に既存 instance がある場合は重複生成せず `null` を返す。
- `destroy` は対象 instance の全採集 session、instance cache、packet 表示を除去する。
- `clearInstances` は全 session を cancel し、全表示と instance を除去する。定義・spawner reload 前の追跡整合に使用する。

### 採集対象の参照

クラス名: `GatheringService`
物理名: `findTargeted`, `findTargetedHit`

player の視点から 5.5 block の ray を作成し、同一 world の instance を radius 0.85 の sphere として評価する。入口距離が最短の instance を返し、同距離時は instance UUID の昇順を採用する。候補解決だけを行い、session や HP は変更しない。

### 採集開始・継続

クラス名: `GatheringService`
物理名: `startMining`

1. `AstPlayer` と gameplay mode、視線対象、メインハンドの equipment tag、耐久値切れでないこと、装備由来 `GATHERING_LEVEL` が対象 `level` 以上であることを検証する。レベル不足時は `PlayerMsgId.P_5734` を通知する。
2. 同じ instance・同じ tool signature の session が既にあれば追加 damage を与えず `true` を返す。
3. 同じ player の別 session があれば終了する。同じ instance にいる他 player の session は維持し、対象へ参加者として追加する。
4. `MINING_SPEED` を四捨五入した最低 1 damage を即時適用する。
5. 未破壊なら player ごとに 8 tick task を開始する。tool、視線、tag、level、online、instance 参加状態のいずれかが変わればその session を停止する。他の参加者が残る場合は共有HPを維持し、最後の参加者が停止した場合だけHPを初期化する。継続判定は block / entity の割り込みではなく、対象への視線 ray と5.5 blockの到達範囲で判定する。
6. 破壊時は break sound と `displayBlock` 材質のブロック破壊パーティクルを表示する。その後、オンラインかつgameplay modeの全貢献者へ `MobDropService.roll` を個別実行し、`drops.exp` のアカウント・クラス経験値反映、各貢献者が最後にdamageを与えたTOOL装備個体の `durability.consume` 1回消費、`MobDropPresentationService.presentAndGrant`、`QuestService.recordGathering` の順に処理してから全sessionとinstanceを破棄する。採集の当選アイテムは通常ドロップとして `PlayerMsgId.P_5732` で獲得対象プレイヤー本人へ通知する。

quest 通知は報酬 recipient と drop presentation が解決できた完了経路だけで行う。quest feature は進捗更新のみを担当する。

## 7.5. MobSpawnerService メソッド仕様

### Mob スポナーの定常出現

クラス名: `MobSpawnerService`

各配置について interval、time window、周辺 gameplay player、配置別 alive、周辺 Mob 上限を検証する。条件を満たす場合、定義 entry を weight 抽選し、登録座標から半径内の水平位置を抽選する。登録 Y 座標 - 3 以上では足元と頭上の空間を、登録 Y 座標 - 3 未満では X/Z 列の最上面を候補として評価する。

- 20 tick ごとの周期判定で、時間帯と周辺 gameplay player 条件を満たす配置を待機列へ入れる。同じ配置の待機は1件だけ保持する。
- 同期タスクは毎 tick、待機列の先頭1配置を処理する。1 tick の探索予算は最大32候補判定、Mob生成は全スポナーを通して最大1体とし、探索途中の配置を末尾へ戻す。負荷集中時は出現を遅延させ、未処理周期を蓄積しない。
- 最大24個の水平候補列と最後の登録 X/Z の地表候補について、ロード済みチャンクだけを探索する。未ロードならブロックや高さを取得せず当該列を棄却し、スポーンのためにチャンクを同期ロード・生成しない。
- 各継続処理で時間帯、周辺 gameplay player、配置別 alive、周辺 Mob 上限を再確認する。削除・マスタ再読込・停止時は該当する待機状態を破棄し、World実体が変わった場合は探索を作り直す。
- 足元 block が葉っぱ tag に該当する候補は受理しない。
- 最後の登録 X/Z の地表候補にも同じ高さ・床・空間条件を適用する。有効候補がない場合は Mob を生成せず、登録座標へ無条件にフォールバックしない。

### Mob スポナー表示名

クラス名: `MobSpawnerService`
物理名: `getSpawnerDisplayName`, `createSpawnerItem`

`getSpawnerDisplayName` はスポナーの `spawnMobs` を走査し、対象 Mob の指定レベルに対応する日本語表示名を重複なく連結する。対象定義または表示名を解決できない場合は ID を表示せず「未登録のモブ」とし、対象が空の場合は「出現対象なし」とする。設置 item の表示名・lore、配置成功通知、ADMIN viewer の packet label はこの表示名を使用する。

### Mob スポナー管理表示モード

クラス名: `MobSpawnerService`, `MobSpawnerVisualizer`, `SpawnerVisualizer`, `GatheringSpawnerVisualizer`
物理名: `getVisualMode`, `setVisualMode`, `tick`（内部）

`/mobspawnerdisplay <normal|light|off>` は `AccountMode.ADMIN` の本人に適用し、`user.permission` に依存しない。既存のプレイヤー PDC キーを Mob・採集スポナーで共有し、未設定・未知値では `normal` とする。コマンド変更は両方の管理表示へ即時反映する。

- 40 tick ごとに、同じワールドの送信済みチャンク内かつ32 block 以内の配置を距離・表示キー順で選択する。BlockDisplay は viewer ごと・スポナー種別ごとに最大64件とし、範囲外・上限外になった表示を先に破棄する。表示のためにチャンクをロードしない。
- `normal` では選択された配置のうち8 block 以内の最寄り8件まで出現対象名の TextDisplay を表示する。周期粒子は同じ近距離配置の最寄り4地点までとし、設定変更の即時同期では粒子を追加送信しない。
- `light` は同じ距離・件数上限で BlockDisplay だけを表示する。`off` は Mob・採集スポナーの管理表示をすべて破棄する。
- 無変更の表示を周期的に破棄・再生成しない。新規選択、材質・座標・ラベルの変更、近距離ラベルの表示切替だけを送信する。entity / metadata の送信失敗時は部分表示の破棄を試み、同じ entity ID を保持して次周期で再試行する。稼働中に表示の破棄送信に失敗した場合も、成功または viewer 切断まで追跡を保持する。破棄待ちのブロック・ラベルを表示上限に含め、新しい表示の追加を抑止する。
- 切断、テレポート、ワールド変更、リスポーンで viewer の表示状態を破棄する。チャンク解除時はそのチャンクの表示だけを破棄する。必要な表示は次の周期で再送する。停止時は全表示の破棄送信を試み、周期 task とイベント監視を解除する。オンライン viewer を残すプラグイン単独無効化と破棄送信失敗が重なった場合の停止後再送は未対応で、旧表示がチャンク解除または切断まで残り得る。

表示設定はモブ・採集物のスポーン判定、スポナー設置・削除の権限や独自の視線操作判定を変更しない。出現した採集物本体の表示は管理表示とは別に維持する。

## 8. GatheringSpawnerService メソッド仕様

### 採集スポナーマスタの読込・公開

クラス名: `GatheringSpawnerService`
物理名: `loadAll`, `loadMasterDataSnapshot`, `replaceMasterDataSnapshot`

定義と配置を `MasterDataSnapshot` として読み、定義 cache、location-key cache、配置別 instance 追跡集合を全置換する。旧配置の待機列と未完了の探索も破棄し、公開後は dirty を解除する。

### task と dirty 保存

クラス名: `GatheringSpawnerService`
物理名: `start`, `stop`

- `start` は毎 tick の spawn 探索 task、60 秒の dirty 保存 task、particle service 注入済みなら ADMIN viewer 用 visualizer を開始する。生成時期の判定と待機列への追加は従来どおり20 tick単位で行う。
- `stop` は task と visualizer を停止し、待機列と未完了の探索を破棄して、dirty 配置を `gathering_spawners.yml` へ保存する。

### 設置 item・配置管理

クラス名: `GatheringSpawnerService`
物理名: `createSpawnerItem`, `getSpawnerDisplayName`, `readSpawnerId`, `registerLocation`, `removeLocation`, `hasLocation`

- 設置 item は定義の `itemMaterial` と PDC `gathering_spawner_id` を持ち、種別・時間帯・出現対象の日本語表示名・上限を lore に表示する。`getSpawnerDisplayName` は namespace prefix を許容し、解決できない対象は ID ではなく「未登録の採集物」として表示する。
- 配置 key は `worldName:x:y:z`。未ロード ID と重複座標は登録せず、登録・削除成功時だけ dirty にする。
- `isAdminMode` は `AstPlayer.hasAdminPermission()`、`canViewSpawnerVisual` は `AccountMode.ADMIN` を判定するため、用途を混同しない。

### 採集 object の定常出現

クラス名: `GatheringSpawnerService`
物理名: `tick`（内部）

20 tick単位で各配置のintervalを判定し、未処理の配置を重複なく待機列へ追加する。毎tick、待機列から最大1件を開始し、time window、周辺gameplay player、配置別alive、周辺採集object上限を検証して定義entryをweight抽選する。

探索はメインスレッド上で1件ずつ進め、1tickあたり列準備・候補判定の合計1,024ステップ、または1msの期限に達した時点で次tickへ持ち越す。期限は各ステップの前に確認するため、単一のBukkit呼出しの所要時間まで保証するものではない。未ロードchunkは除外し、探索による同期ロード・生成を行わない。

登録座標を中心とする球形半径内で、各X/Z列のsolidな足元materialとpassable / non-liquid条件を満たす最上位候補を求める。**各列の候補を高さによらず一様抽選**し、範囲全体の最高Yには限定しない。したがって同じ範囲にY=64以上の候補があっても、条件を満たすY=63以下や負のYの列を選択できる。Yの制限は登録Y±半径とworldの最小・最大高度だけで、固定の海面高度下限は設けない。

生成直前に配置・定義・worldの有効性、time window、周辺gameplay player、出現数上限、候補chunkのロード状態と足元・空間を再検証する。全スポナーを通じて生成は最低5tick間隔で1個ずつ行い、表示更新時の集中も抑える。`GatheringService.spawn` は同一ブロック座標の既存objectを引き続き拒否する。採集objectの表示距離・サイズ・label・採集演出は変更しない。

## 9. 採集 packet 表示

### 採集 object 表示

クラス名: `GatheringVisualizer`, `GatheringPacketDisplay`
物理名: `start`, `stop`, `remove`, `tick`（内部）

- 5 tick 間隔で instance と viewer の差分を同期する。
- BlockDisplay は 48 block、label は 8 block 以内へ表示する。
- 採集中 player には 10 segment の HP gauge、それ以外には採集名を表示する。
- ProtocolLib packet 送信失敗は shared `W_9010` に packet type と world name を渡す。

### 採集スポナー表示

クラス名: `GatheringSpawnerVisualizer`
物理名: `start`, `stop`, `tick`（内部）

`SpawnerVisualizer` の共通管理表示を使い、Mob スポナーと同じモード・距離・件数上限・差分同期・viewer ライフサイクルを適用する。上限は採集スポナーと Mob スポナーで各々数える。`/mobspawnerdisplay light|off` は採集スポナーにも即時反映する。出現対象の日本語表示名は `GatheringSpawnerService.getSpawnerDisplayName` から取得する。
