# 12_3-サービス

## 1. MobService メソッド仕様

`MobService` はテンプレートキャッシュ、`MobInstance` キャッシュ、Bukkit 実体 Mob との対応、頭上 packet display 用 viewer キャッシュを管理する。

### テンプレート全件ロード

クラス名: `MobService`
物理名: `loadAll`

1. [[12_3-リポジトリ]].Mob 一覧取得 を呼ぶ。
2. 取得した `MobTemplate` を id キーの `LinkedHashMap` に保持する。
3. `LogId.I_5700` を記録し、ロード件数を返す。

### テンプレート取得

クラス名: `MobService`
物理名: `findTemplate`

1. `templates` キャッシュから `mobId` を取得する。
2. 未ヒット時は [[12_3-リポジトリ]].Mob 取得 を呼び、取得できた場合のみキャッシュへ登録する。
3. 取得できない場合は `null` を返す。

### テンプレート入力解決

クラス名: `MobService`
物理名: `resolveTemplateId`

1. 入力がロード済みテンプレート ID と完全一致する場合は、その ID を返す。
2. 入力がテンプレート ID らしい ASCII 形式（英数字、`_`、`-`）のときだけ、未ロードテンプレートに対して `findTemplate` による遅延ロード解決を試みる。
3. ロード済みテンプレートに対して、カラーコード除去後の表示名、および `id（表示名）` / `id(displayName)` 形式を正規化比較する。
4. 指定カテゴリに一致するテンプレートだけを候補とし、一致しない場合は `null` を返す。

### Mob スポーン

クラス名: `MobService`
物理名: `spawn`

1. テンプレート ID を受け取った場合はキャッシュまたは API から解決する。未取得なら `LogId.W_5701` を記録して `null` を返す。`MobTemplate` を直接受け取った場合は API・キャッシュを介さず、その実行時テンプレートを使用する。
2. `UUID.randomUUID()` で `instanceId` を採番し、`MobInstance` を生成する。
3. `MobEntityController.spawn` を呼び、Bukkit/Paper の実体 `Mob` を生成する。
4. 実体生成時、`MobEntityController` は以下を行う。
   - `Bukkit.getMobGoals().removeAllGoals(mob)` で vanilla goal を全削除する。
   - `setAI(true)` / `setAware(true)` を維持し、Paper Pathfinder を利用可能にする。
   - `setInvulnerable(true)` によりバニラダメージでは HP を減らさない。
   - `setPersistent(false)` / `setRemoveWhenFarAway(false)` / `setCanPickupItems(false)` / `setCollidable(false)` / `setSilent(true)` を設定する。
   - PDC に `mob_instance_id` と `mob_template_id` を保持する。
   - `MobInstance.bindEntity` で `bukkitEntityId` / `entityId` / `currentLocation` を同期する。
5. 実体生成に失敗した場合は `LogId.W_5705` を記録して `null` を返す。
6. `instances`、`instanceByEntity`、`viewers` に登録し、`LogId.D_5701` を記録して `MobInstance` を返す。

### Mob 破棄

クラス名: `MobService`
物理名: `destroy`

1. `instances` から `instanceId` を削除する。
2. 対応する `viewers` と `instanceByEntity` を削除する。
3. `MobEntityController.remove` で Bukkit 実体 Mob を remove する。
4. 成功時は `LogId.D_5702` を記録し、破棄できたかどうかを返す。

### 全 Mob 破棄

クラス名: `MobService`
物理名: `destroyAll`

1. 全 `MobInstance` の実体 Mob を `MobEntityController.remove` で削除する。
2. `instances`、`instanceByEntity`、`viewers` をクリアする。
3. `LogId.I_5701` を記録し、破棄件数を返す。

### 表示対象 viewer 更新

クラス名: `MobService`
物理名: `updateViewers`

Mob 本体は Bukkit/Paper の entity tracking に任せる。本メソッドは頭上 packet display の viewer キャッシュだけを更新する。

1. 実体 Mob の現在位置を `MobEntityController.syncLocation` で `MobInstance.currentLocation` へ反映する。
2. 64 ブロック以内かつ同一ワールドのオンラインプレイヤー UUID を `viewers` へ登録する。
3. 範囲外またはオフラインのプレイヤー UUID を `viewers` から削除する。

### 視認距離外 enemy 破棄

クラス名: `MobService`
物理名: `destroyEnemiesOutsideViewDistance`

1. `category == ENEMY` かつ `keepWhenUnobserved=false` の `MobInstance` を対象にする。`BOSS` / `NPC` と維持指定された enemy は自動破棄対象外とする。
2. 実体位置を同期し、同一ワールドかつ 64 ブロック以内のオンラインプレイヤーが 1 人もいない enemy を抽出する。
3. 抽出した enemy は `MobService.destroy` で破棄する。プラグイン都合の削除のため、`MobCombatService.handleDeath` は呼ばず、ドロップ、討伐記録、リザルト TextDisplay は発生させない。

### Paper Pathfinder 移動要求

クラス名: `MobService`
物理名: `moveToward`

1. `MobEntityController.moveTo` へ `MobInstance`、目標 `Location`、AI 速度倍率、内部 tick を渡す。
2. `MobEntityController` は目標地点の移動量と `PATH_RECOMPUTE_INTERVAL_TICKS` により、毎 tick の経路再計算を避ける。
3. 目標付近に到達した場合は `stopPathfinding` で経路探索を停止する。

## 1.5. NpcPlacementService メソッド仕様

### NPC 配置ロード

クラス名: `NpcPlacementService`
物理名: `loadAll`

1. `npc_placements.yml` から NPC 配置一覧を読み込む。
2. 既存の管理対象 NPC 実体と location-key キャッシュを破棄し、最新配置へ入れ替える。
3. その時点で `Bukkit.getWorld(worldName)` が解決できる配置は即時スポーンする。
4. ワールドがまだ解決できない配置もメモリ上には保持し、後続の `spawnLoadedWorlds` / `spawnForWorld` で再試行できる状態を維持する。
5. スポーン前に対象チャンクを明示的にロードし、起動直後やワールドロード直後でも `World.spawnEntity(...)` が失敗しにくい状態にしてから生成を試みる。

### ロード済みワールド再スポーン

クラス名: `NpcPlacementService`
物理名: `spawnLoadedWorlds`

1. 現在ロード済みの全ワールドに対して、未スポーンの NPC 配置だけを再評価する。
2. `AstralRecord` の onEnable 完了後 1 tick 遅延起動、および `WorldLoadEvent` 後の 1 tick 遅延再試行経路から呼び出し、起動順差で取りこぼした NPC を補完する。
3. すでに管理中の location-key は重複スポーンしない。

### NPC 配置削除

クラス名: `NpcPlacementService`
物理名: `removeByNpcId`

1. `placements` から `npcId` 一致する location-key 一覧を抽出する。
2. 抽出した location-key ごとに、保存済み配置・出現中 NPC・チャンクチケットをまとめて破棄する。
3. 1 件以上削除した場合だけ `npc_placements.yml` を更新する。
4. 戻り値は削除した配置件数とする。

## 2. MobEntityController メソッド仕様

### 実体 Mob 生成

クラス名: `MobEntityController`
物理名: `spawn`

通常 Mob は `template.entityType()` に対応する Bukkit `Mob` を生成する。固定表示用の `ARMOR_STAND` は例外として可視の Bukkit `ArmorStand` を生成し、重力・衝突・装備操作を無効化する。NPC `entityType` が block Material として解決された場合は `Interaction` と `BlockDisplay` の二層構造を生成し、配置座標を fakeblock の水平中心として扱う。BlockDisplay は transformation で水平中央へ寄せ、下端を配置 Y 座標に接地させ、通常ブロックの `0.75` 倍で描画する。block NPC の描画はプレイヤー方向へ回転させず、配置時の向きのまま固定する。PDC に `mob_instance_id` / `mob_template_id` を付与して fakeblock NPC として扱う。`CHEST` / `TRAPPED_CHEST` / `ENDER_CHEST` は BlockDisplay で描画されないため、表示用 Material は `BARREL` に正規化する。

block NPC は通常 NPC と同じ頭上 display text を持ち、AI tick で ambient particle を表示する。Entity ray trace で対象を拾えない場合も、視線と 1 block AABB の交差判定で左クリック/右クリック interaction を発火させる。

### 実体 Mob 設定

クラス名: `MobEntityController`
物理名: `configure`

vanilla goal 全削除、PDC 設定、独自名表示、不要挙動の抑止、Pathfinder のドア・浮遊設定を行う。

### 実体 Mob 取得

クラス名: `MobEntityController`
物理名: `getMob`

`MobInstance.bukkitEntityId` から `Bukkit.getEntity` で実体を解決する。`getMob` は無効・死亡済み・Mob 以外なら `null` を返し、汎用 `getEntity` と位置同期は有効な `ArmorStand` も返す。

### 実体位置同期

クラス名: `MobEntityController`
物理名: `syncLocation`

有効な実体 Mob の `getLocation()` を `MobInstance.currentLocation` に反映する。

### 移動要求

クラス名: `MobEntityController`
物理名: `moveTo`

Paper Pathfinder の `moveTo(target, speed)` を呼び出す。以下の軽量化ルールを持つ。

- 目標まで 0.6 ブロック以内なら `stopPathfinding` する。
- 既存 path があり、目標地点の X/Z 変化が 1.5 ブロック未満で、再計算間隔未満なら再要求しない。
- `MOVEMENT_SPEED` と `idle.speed` から Pathfinder speed を算出し、`0.05` から `2.5` に丸める。

## 3. MobAiService メソッド仕様

### tick タスク開始 / 停止

クラス名: `MobAiService`
物理名: `start` / `stop`

`BukkitScheduler.runTaskTimer` で 1 tick 周期の AI ループを起動・停止する。開始時は `LogId.I_5702`、停止時は `LogId.I_5703` を記録する。

### AI tick 本体

クラス名: `MobAiService`
物理名: `tick`

1. 内部 tick を進め、`MobService.getInstances` のスナップショットを取得する。
2. 各インスタンスで実体位置を同期する。実体が存在しない場合はインスタンスを破棄する。
3. 100 tick ごとに脅威値を減衰する。
4. leashRange 超過なら `LEASHED` へ遷移する。
5. 状態別処理を行う。
   - `IDLE`: 10 tick 間隔でターゲット探索・徘徊目的地選定を行う。`NPC` かつ `idle.behavior = STATIONARY` の場合は path を停止し、水平速度も 0 に補正したまま 64 ブロック以内の最寄りプレイヤーへ視線だけ向ける。ただし block NPC は視線追従の回転対象外とし、描画を固定する。
   - `AGGRO`: 5 tick 間隔で追跡対象の再評価と Pathfinder 目標設定を行う。
- `COMBAT`: 射程外または高低差超過なら `AGGRO` へ戻す。`RANGED` / `MAGIC` で理想距離より近すぎる場合は、その場停止せず後退して距離を取り直す。
   - `LEASHED`: 5 tick 間隔でスポーン地点へ Pathfinder 目標設定を行い、到達で `IDLE` へ戻す。
   - `DEAD`: `MobService.destroy` で破棄する。
6. 5 tick ごとに `MobService.updateViewers` を呼び、頭上 packet display の viewer キャッシュを更新する。
7. 同じ 5 tick 周期で `MobService.destroyEnemiesOutsideViewDistance` を呼び、どのプレイヤーの描画距離にも入っていない `ENEMY` をリザルトなしで破棄する。`keepWhenUnobserved=true` の個体は維持する。

### 軽量化ルール

- バニラ goal は spawn 直後に全削除し、不要な vanilla 行動 tick を発生させない。
- `setAI(false)` は使わない。Paper Pathfinder を利用するため `AI=true` を維持する。
- IDLE の探索は全 Mob 同時ではなく、`instanceId.hashCode + internalTick` で分散する。
- AGGRO / LEASHED の追跡判断は 5 tick 間隔に抑える。
- Pathfinder の `moveTo` は目標ドリフトと再計算間隔で制限する。
- Mob 本体の viewer 管理は Bukkit/Paper に任せ、プラグイン側 viewer は頭上表示用に限定する。

## 4. 設計上の制約

- すべての Bukkit/Paper API 操作はメインスレッドから呼び出す。
- 実体 Mob は永続化しない。サーバ停止時は `destroyAll` で remove する。
- バニラダメージイベントを Mob HP の正本にはしない。独自攻撃・combat/skill 側から `MobInstance.currentHealth` を更新する。

## 5. TextDisplayPlacementService メソッド仕様

固定 TextDisplay は実体 Mob ではないが、NPC 配置と同じくワールド上へ滞在する運用オブジェクトとして扱う。

### 固定 TextDisplay 配置ロード

クラス名: `TextDisplayPlacementService`
物理名: `loadAll`

1. [[12_3-リポジトリ]].固定 TextDisplay 配置一覧取得 を呼ぶ。
2. 既存の管理対象 TextDisplay とチャンク保持を破棄し、読み込んだ配置へ入れ替える。
3. その時点で `Bukkit.getWorld(worldName)` が解決できる配置は `DisplayTextService` で即時表示する。
4. ワールドがまだ解決できない配置もメモリ上には保持し、後続の `spawnLoadedWorlds` / `spawnForWorld` で再試行できる状態を維持する。
5. 表示前に対象チャンクを明示的にロードし、プラグインチャンクチケットで保持する。

### 固定 TextDisplay 配置

クラス名: `TextDisplayPlacementService`
物理名: `place`

1. `TextDisplayPlacement.from(id, text, location)` で配置情報を作成する。
2. 同一 ID の表示が存在する場合は破棄する。
3. `placements` を更新し、`text_displays.yml` へ保存する。
4. 表示基盤 `DisplayTextService` に `DisplayAnchor.fixed(location)` と `DisplayTextOptions.defaults(text)` ベースの固定表示を登録する。

### 固定 TextDisplay 削除

クラス名: `TextDisplayPlacementService`
物理名: `remove`

1. 指定 ID の配置を `placements` から削除する。
2. 表示中の TextDisplay があれば破棄する。
3. 対象チャンクのチケットを解放する。
4. `text_displays.yml` を更新する。

### ワールドロード後の再表示

クラス名: `TextDisplayPlacementWorldEventHandler`
物理名: `onWorldLoad`

1. `WorldLoadEvent` 後に 20 tick 遅延して `spawnForWorld` を実行する。
2. 未表示配置が残る場合は最大 5 回まで再試行する。

## 6. プレイヤー入力候補解決

クラス名: `PlayerInputResolver`
物理名: `resolve`

mob / spawner側のresolverは[[28_1-モデル定義]].プレイヤー入力コンテキスト を読み、次の`PlayerInputCandidate`を副作用なしで返す。

| family | 候補 | tier・距離 |
|:--|:--|:--|
| 右クリック | NPC、fakeblock NPC | world interaction。拡張entity AABBまたはblock AABBへのray入口距離 |
| 左クリック | NPC、fakeblock NPC、packet-only Mob / gathering spawner 表示、採集 object | world interaction。拡張entity AABB、block AABBまたは各 hitbox への ray 入口距離 |
| block mutation | Mob / gathering spawner item 設置、登録 block 破壊 | world interaction。event 対象 block までの距離 |

1. NPC候補は一つの選択済みユースケースとして、勝者executor内で定義順の`message` / `gui` / `command` actionを実行してよい。`gui` の `type: LOGIN_BONUS` は `LoginBonusService.openAfterDataLoaded` を呼び出す。
2. Mob entity NPCはPaperの単発ray結果だけを採用せず、rayの太さで拡張した全entity AABBと全block NPC AABBを入口距離で比較する。同一種別で距離が同じNPC / fakeblock NPCはMob instance UUID、Mob spawnerはworld UUIDとblock座標のlocation keyで決定する。
3. 遮蔽blockより遠いpacket-only表示は候補にしない。
4. 権限不足、無効なaction、重複座標などは勝者の拒否として終了し、武器・action ring・別spawnerへfallbackしない。
5. 入力相関、tier比較、winner一件実行は[[28_3-サービス]]を正本とする。

## 7. GatheringService メソッド仕様

### 採集定義の読込・公開

クラス名: `GatheringService`
物理名: `loadAll`, `loadDefinitionSnapshot`, `replaceDefinitionSnapshot`, `activateDefinitionSnapshot`

- `loadDefinitionSnapshot` は repository の全定義を immutable list にする。
- `replaceDefinitionSnapshot` は ID key の cache を全置換する。
- `activateDefinitionSnapshot` は旧定義に属する instance・採集 session・packet 表示を全破棄する。Bukkit API を操作するためメインスレッドで実行する。
- `loadAll` は 3 段階を順に実行し、公開後の定義件数を返す。

### 採集 service の開始・停止

クラス名: `GatheringService`
物理名: `start`, `stop`

`start` は `GatheringVisualizer` の 5 tick task を冪等に開始する。`stop` は全 player session、visualizer、instance cache を破棄する。drop 表示と quest は `setDropPresentationService` / `setQuestService` で plugin 初期化後に注入する。

### 採集 instance の生成・破棄

クラス名: `GatheringService`
物理名: `spawn`, `destroy`, `clearInstances`

- `spawn` は namespace prefix を除いた ID を cache から解決し、world が存在する場合だけ block 中央へ `GatheringInstance` を生成する。
- `destroy` は instance cache と packet 表示を除去する。
- `clearInstances` は全 session を cancel し、全表示と instance を除去する。定義・spawner reload 前の追跡整合に使用する。

### 採集対象の参照

クラス名: `GatheringService`
物理名: `findTargeted`, `findTargetedHit`

player の視点から 5.5 block の ray を作成し、同一 world の instance を radius 0.85 の sphere として評価する。入口距離が最短の instance を返し、同距離時は instance UUID の昇順を採用する。候補解決だけを行い、session や HP は変更しない。

### 採集開始・継続

クラス名: `GatheringService`
物理名: `startMining`

1. `AstPlayer` と gameplay mode、視線対象、メインハンドの equipment tag を検証する。
2. 同じ instance・同じ tool signature の session が既にあれば追加 damage を与えず `true` を返す。
3. 既存 session または別 player の所有 session を終了し、対象 HP を初期化する。
4. `MINING_SPEED` を四捨五入した最低 1 damage を即時適用する。
5. 未破壊なら 8 tick task を開始する。tool、視線、tag、online、instance 所有者のいずれかが変われば停止して HP を初期化する。
6. 破壊時は sound、`MobDropService.roll`、`MobDropPresentationService.presentAndGrant`、`QuestService.recordGathering` の順に処理し、session と instance を破棄する。

quest 通知は報酬 recipient と drop presentation が解決できた完了経路だけで行う。quest feature は進捗更新のみを担当する。

## 8. GatheringSpawnerService メソッド仕様

### 採集スポナーマスタの読込・公開

クラス名: `GatheringSpawnerService`
物理名: `loadAll`, `loadMasterDataSnapshot`, `replaceMasterDataSnapshot`

定義と配置を `MasterDataSnapshot` として読み、定義 cache、location-key cache、配置別 instance 追跡集合を全置換する。公開後は dirty を解除する。

### task と dirty 保存

クラス名: `GatheringSpawnerService`
物理名: `start`, `stop`

- `start` は 20 tick の spawn 判定 task、60 秒の dirty 保存 task、particle service 注入済みなら ADMIN viewer 用 visualizer を開始する。
- `stop` は task と visualizer を停止し、dirty 配置を `gathering_spawners.yml` へ保存する。

### 設置 item・配置管理

クラス名: `GatheringSpawnerService`
物理名: `createSpawnerItem`, `readSpawnerId`, `registerLocation`, `removeLocation`, `hasLocation`

- 設置 item は定義の `itemMaterial` と PDC `gathering_spawner_id` を持ち、定義・時間帯・出現対象・上限を lore に表示する。
- 配置 key は `worldName:x:y:z`。未ロード ID と重複座標は登録せず、登録・削除成功時だけ dirty にする。
- `isAdminMode` は `AstPlayer.hasAdminPermission()`、`canViewSpawnerVisual` は `AccountMode.ADMIN` を判定するため、用途を混同しない。

### 採集 object の定常出現

クラス名: `GatheringSpawnerService`
物理名: `tick`（内部）

各配置について interval、time window、周辺 gameplay player、配置別 alive、周辺採集 object 上限を検証する。条件を満たす場合、定義 entry を weight 抽選し、半径内で最大 24 回、足元 material と passable / non-liquid 条件を満たす最高地点を探索して `GatheringService.spawn` する。

## 9. 採集 packet 表示

### 採集 object 表示

クラス名: `GatheringVisualizer`, `GatheringPacketDisplay`
物理名: `start`, `stop`, `remove`, `tick`（内部）

- 5 tick 間隔で instance と viewer の差分を同期する。
- BlockDisplay は 48 block、label は 8 block 以内へ表示する。
- 採集中 player には 10 segment の HP gauge、それ以外には採集名を表示する。

### 採集スポナー表示

クラス名: `GatheringSpawnerVisualizer`
物理名: `start`, `stop`, `tick`（内部）

40 tick 間隔で 64 block 内の `AccountMode.ADMIN` viewer に packet-only block / label と shared spawner particle を表示する。packet entity は 5 cycle ごとに再生成し、viewer・配置・mode の変化で破棄する。
