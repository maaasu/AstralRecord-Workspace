# 12_3-リポジトリ

## 1. Mob template 全件取得

クラス名: `MobRepository`
物理名: `findAll`

`GET /api/mob` の `200` summary 配列から ID を取り出し、各 ID を `findById` で詳細取得して `List<MobTemplate>` を返す。summary に ID がない行と詳細が `null` の行は除外する。非 `200` は `E_5701` を記録し、`IOException` を `RuntimeException` で伝播する。

service へは summary ではなく、各 ID の詳細取得まで完了した template 一覧を返す。

## 2. Mob template 単体取得

クラス名: `MobRepository`
物理名: `findById`

URL encode した ID で `GET /api/mob/{mobId}` を呼ぶ。

| status | 挙動 |
|---:|---|
| 200 | `parseTemplate` で `MobTemplate` を返す |
| 404 | `W_5700` を記録して `null` |
| その他 | `E_5700` を記録し、`IOException` を `RuntimeException` で伝播 |

`InterruptedException` は interrupt flag を復元する。

## 3. template parse（内部）

クラス名: `MobRepository`
物理名: `parseTemplate`

- category、entity / block type、skin、equipment、base stats、Shield、AI、interaction、combat、drop、boss config を JSON から構築する。
- `shield.rechargeTimeSeconds` と `shield.rechargeAmount` は nullable として読み取る。時間未設定は Mob の自動回復なし、回復量未設定は `shield.max` として解決する。
- `PLAYER` は NPC なら `VILLAGER`、その他は `ZOMBIE` へ正規化する。
- Bukkit block material は `BLOCK_DISPLAY` と `blockMaterial` へ正規化する。entity / block のどちらにも解決できない template は `W_5705` を記録して除外する。
- 不明 `StatusType` の base stat は `W_5704` を記録してその row だけ除外する。
- `item:*`、`skill:*`、`loot_table:*` の参照は suffix ID を保持する。

## 4. NPC 配置 repository

クラス名: `NpcPlacementRepository`
物理名: `loadAll`, `saveAll`

plugin data folder の `npc_placements.yml` へ NPC ID、world、座標・向きを保存する。欠損・不正な行は除外し、有効な配置だけを返す。

## 5. 固定 TextDisplay 配置 repository

クラス名: `TextDisplayPlacementRepository`
物理名: `loadAll`, `saveAll`

plugin data folder の `text_displays.yml` の `textDisplays` 配列へ ID、text、world、座標・向きを読み書きする。ファイル未作成時は空一覧を返す。text は `&` color code と改行を保持する。

## 6. 採集定義 repository

クラス名: `GatheringDefinitionRepository`
物理名: `findAll`

`FileDatabaseManager` の root 配下 `42.features.gathering` を再帰走査し、拡張子 `.yml` かつ名前に `YAML` を含まないファイルを読み込む。

- `id` 欠損・空白は定義ごと除外する。
- `displayBlock` は Bukkit block material だけを許可し、不正・非 block は `STONE`。
- `maxHealth`、display scale、required tool tags、Mob と共有する drop config、hit / break sound を `GatheringDefinition` へ変換する。
- item / loot table ID は最初の `:` より後ろの suffix を保持する。
- filebase root 未設定または directory 不在時は空一覧を返す。

## 7. 採集スポナー定義 repository

クラス名: `GatheringSpawnerDefinitionRepository`
物理名: `findAll`

`FileDatabaseManager` の root 配下 `43.features.gathering.spawner` 直下にある対象 YAML を読み、採集 ID / weight、time window、item material、interval、各上限、required base blocks を `GatheringSpawnerDefinition` へ変換する。`id` 欠損は除外し、不正 material は item が `SPAWNER`、base block は除外へ fallback する。

## 8. 採集スポナー配置 repository

クラス名: `GatheringSpawnerLocationRepository`
物理名: `loadAll`, `saveAll`

plugin data folder の `gathering_spawners.yml` にある `spawners` 配列へ `id`、`world`、block 座標を読み書きする。

- 未作成時は空一覧、`id` / `world` 欠損 row は除外する。
- parent directory 作成失敗は `E_6401`、YAML 保存失敗は `E_6400` を `type=gathering_spawner` で記録し `false` を返す。
- 保存成功時だけ `true` を返し、service が dirty を解除する。
