# 09_4.00-統合フロー

## 1. `/menu` 表示フロー（command -> view）

1. [[09_3.03-コマンド]].メニュー表示実行 が `AstPlayer` を `PlayerGuiRenderContextFactory` へ渡し、同一時点の描画コンテキストを生成する
2. `MenuView.open(AstPlayer, PlayerGuiRenderContext)` が [[09_1.00-モデル定義]].メニュー画面種別 `MAIN` の inventory を生成する
3. メインメニュー画面ビューが `MenuIconDefinition` と `MenuIconFactory` から項目を生成し、コンテキストの動的 lore を追加して配置する
4. Bukkit API 境界で `AstPlayer.bukkit` へ GUI を開く

## 1.1 統合プレイヤー情報表示フロー（main menu / command -> player detail）

1. メインメニューのプレイヤー情報項目クリック、または [[09_3.03-コマンド]].プレイヤー情報サブコマンド実行 が起点になる
2. `AstPlayerCache` から `AstPlayer` を取得し、未取得時は拒否音で終了する
3. status feature の `StatusService.refreshStatus` でスナップショットを再計算する
4. [[09_3.07-GUI・View]].統合プレイヤー情報表示 が `PlayerDetailGui` をタイトル `プレイヤー情報: <playerName>` で生成して開く
5. プレイヤーヘッドへ基本情報、アカウント、クラス、資産と活動を統合し、現在地は world master の表示名だけを表示する
6. カテゴリ別ステータスは左上へ整列し、合計値・基礎値・補正値を数値だけで色分け表示する
7. `slot 16` の「現在のバフ」をクリックすると、対象プレイヤー ID を保持したバフ詳細 GUI を開く
8. メインメニューから開いた場合は back slot でメインメニューへ戻る。コマンドから直接開き、直前の GUI がない場合は back slot を表示しない

## 1.2 共通 GUI 戻るフロー

1. `GuiNavigationEventHandler` が管理 GUI の open を監視し、`AstPlayer.guiNavigationState` に現在画面と履歴を記録する
2. 同一画面のページ送り・フィルター変更・再描画は現在画面を置換し、履歴を追加しない
3. 戻るボタンは履歴先頭の GUI を開く。固定したメニューや一覧には戻さない
4. 戻り先が存在しない場合は、戻るボタンと同じスロットに閉じるボタンを表示する。メインメニューは履歴の有無にかかわらず `slot 49` を常に閉じるボタンとする
5. GUI を閉じ、次 tick に別の管理 GUI が開かれていなければ履歴を破棄する。その後にコマンドで GUI を開いても、閉じる前の画面は戻り先にならない
6. プラグイン管理 GUI から別の GUI へ切り替える場合は、クリック時のクライアント同期ずれを避けるため共通 open 処理で 2 tick 遅延して開く

## 2. クラフト欄ショートカットフロー（event -> fixed settings -> view）

1. join / open / craft prepare / close で [[09_3.01-イベント]].クラフトショートカット再描画予約 が呼ばれる
2. 次 tick に [[09_3.01-イベント]].クラフトショートカット描画 が実行される
3. `AstPlayer` から `PlayerGuiRenderContext` を 1 回生成し、ステータス、CP / PP、Gold、帰還費用、現在装備を同一スナップショットに固定する
4. [[09_1.00-モデル定義]].固定メニューショートカット設定 の `defaults()` が固定 4 スロットを返す
5. [[09_3.07-GUI・View]].クラフトショートカット描画 が `MenuShortcutAction.iconDefinition` と `MenuIconFactory` を使い、成果物スロットと 2x2 スロットへ独立したアイコンを描画する
6. `CraftShortcutView` が各アイコンにクラフト欄固有の PDC 識別子を付与する

## 3. BAG スクロール・GUI下部操作フロー（menu -> inventory）

1. BAG 右端上・下のスクロールアイコンをクリックする
2. inventory feature が先頭表示行を1行増減して BAG を再描画する
3. カスタムGUI中も右端中央はインベントリ情報を表示する
4. ホットバー9枠は通常表示を維持し、GUI固有の取り込み対象外クリックは通常操作へ委譲する

## 4. 装備 GUI フロー（menu -> inventory）

1. メインメニューの装備 slot をクリックする
2. inventory feature からオフハンドと種類別アクセサリ9枠のスナップショットを取得する
3. [[09_3.07-GUI・View]].装備 GUI 表示 が54スロットの装備 GUI を開き、Bukkit 防具、オフハンド、選択中ホットバーアイテムを反映する
4. GUI表示中の選択ホットバー変更はメイン装備表示へ即時反映する
5. アクセサリ配置時は item master の `equipment.tag` と種類別スロットを照合し、保存時は `ACCESSORY_SLOT.slotIndex 2..10` と loadout の `ACCESSORY.slotIndex 1..9` へ変換する
6. プレイヤーヘッドは統合プレイヤー情報画面、共通位置 `slot 49` の戻るボタンは GUI 履歴の直前画面へ遷移し、遷移前に装備スナップショットを保存する。`slot 16` の鞍は将来用ペットスロットとして操作を受け付けない

## 4.1 装備強化 GUI フロー（npc interaction -> inventory / item）

1. NPC interaction の `gui.type = EQUIPMENT_ENHANCE` を実行する
2. item feature が統合 BAG と通常ホットバーを維持する
3. `EquipmentEnhancementService.open` が `MenuScreen.EQUIPMENT_ENHANCE` の GUI を開く
4. プレイヤーが BAG またはホットバーの装備をクリックすると強化スロットへセットする。対象外アイテムは通常の BAG／ホットバー操作へ委譲する
5. item feature が次強化段階の master 定義を参照し、必要素材は消費アイテム表示用アイテムの lore に一覧表示し、必要ゴールド・成功率・失敗時挙動は強化情報として GUI に表示する。強化不可の場合は理由を実行アイコンへ表示する
6. プレイヤーが実行アイコンをクリックすると、inventory feature が補償用 state を取得して素材 / Gold を消費し、その後に item feature が強化 API を呼ぶ
7. 支払いまたは API 更新失敗時は支払い前 state へ復元する。成功時は強化済み装備へ差し替え、抽選失敗時は failAction に従って据え置き / 降格 / 破壊を反映する
8. インベントリを閉じる操作または戻る時は、未実行の対象装備を BAG へ戻す

## 4.1.1 装備修理 GUI フロー（npc interaction -> inventory / item）

1. NPC interaction の `gui.type = EQUIPMENT_REPAIR` を実行する
2. item feature が統合 BAG と通常ホットバーを維持する
3. `EquipmentRepairService.open` が `MenuScreen.EQUIPMENT_REPAIR` の GUI を開く
4. プレイヤーが BAG またはホットバーの装備をクリックすると修理スロットへセットする。対象外アイテムは通常の BAG／ホットバー操作へ委譲する
5. item feature が装備インスタンスの現在耐久と最大耐久から回復耐久・必要 Gold を計算し、修理情報として GUI に表示する
6. プレイヤーが実行アイコンをクリックすると、inventory feature が補償用 state を取得して Gold を消費し、item feature が装備耐久更新 API を呼ぶ
7. API 失敗時は Gold 消費前 state へ復元する。更新と支払いの両方が成功した場合だけ修理済み装備へ差し替え、破損状態から復帰した場合は status feature がステータスを再計算する
8. インベントリを閉じる時は、未実行の対象装備を所持へ戻し、下部表示インベントリを元の表示種別へ復元する

## 4.2 スキルバインド GUI フロー（menu -> skill）

1. メインメニューのスキル設定 slot をクリックする
2. `MenuOpenEventHandler.handleMainMenuClick` が `SkillBindGuiEventHandler.open` を呼び出す
3. skill feature が所持スキルとプリセットを読み込み、ページング付きのスキルバインド GUI を開く
4. スキルバインド GUI 表示中はプレイヤーインベントリ 3 行を管理 UI で占有し、上から 2 行目の左から 8 枠を発動系スキルバインド、同じ行の右端を発動系クリア、ホットバー 9 を保存ボタンとして表示する
5. 空きバインドスロットをクリックすると選択中の割当先になり、所持スキルをクリックすると選択先、または次の空きスロットへ割り当てる

## 4.2 通貨 GUI ページングフロー（event -> view）

1. 通貨 GUI で通貨をクリックすると通常 BAG へ取り出し、下段プレイヤーインベントリの通貨をクリックすると CURRENCY へ収納する。数量は左クリック1個、右クリック半分、Shift+左クリック1スタック、Shift+右クリック全量とし、収納側の Shift+右は BAG・ホットバー全体の同一通貨を対象にする。前後ページ・戻るをクリックする。閉じる場合はプレイヤーインベントリ側の BAG 制御列中央 `slot 26` をクリックする
2. [[09_3.01-イベント]].通貨 GUI クリック がクリック種別を判定する
3. ページ送りの場合、`MenuInventoryHolder.pageIndex` を元に `±1` した番号で [[09_3.07-GUI・View]].通貨 GUI 表示 を再呼び出しする
4. 戻るは GUI 履歴の直前画面へ戻り、インベントリを閉じた場合は GUI を終了して履歴を破棄する

## 4.3 拠点帰還フロー（menu -> world）

1. メインメニューの `帰還` アイコンをクリックする
2. `MenuOpenEventHandler.handleMainMenuClick` が GUI を閉じ、`ReturnToBaseService.beginReturn` を呼び出す
3. `ReturnToBaseService` が `joinSpawn.world` に対応する `WorldMasterData` を解決し、`100 x Lv` の必要ゴールド量を算出する
4. 所持ゴールドが足りない場合はエラーメッセージを表示して終了する
5. 帰還可能な場合はタイトル・サブタイトル・ボスバーを表示し、3 秒の待機を開始する
6. 待機中はプレイヤーの現在位置を監視し、パーティクルとサウンドで帰還演出を継続する
7. プレイヤーが移動した場合は帰還をキャンセルし、キャンセルメッセージを表示する
8. 3 秒経過後に `InventoryService.consumeGold` でゴールドを消費し、`WorldService.teleportToSpawnAsync` で、帰還直前のプレイヤーの `yaw` / `pitch` を保持して参加時スポーン地点へ帰還する
9. テレポート失敗時は消費したゴールドを戻し、失敗メッセージを表示する

## 5. ショートカット設定フロー（廃止済み）

1. 現行仕様ではメインメニューにショートカット設定 slot を配置しない
2. account API へ `menuShortcutsJson` を保存しない
3. クラフト欄は固定 4 スロットを常に描画する

## 追記（ゴミ箱GUIフロー）
1. メインメニューのゴミ箱アイコンでゴミ箱GUIを開く。
2. プレイヤーインベントリ側の BAG／ホットバーアイテムを左クリックで1個、右クリックで半分、Shift+左クリックで1スタック、Shift+右クリックで対象表示スタック全量をゴミ箱GUIへ移動する。通常の装備・割り当て操作よりGUI固有移動を優先し、プレイヤー側のアイテムはその分だけ減る。
3. ゴミ箱GUI側のアイテムも同じ数量規則でプレイヤーインベントリへ戻す。
4. ゴミ箱GUIで戻るを押した場合は廃棄せず GUI 履歴の直前画面へ戻り、ゴミ箱の内容は保持する（再度開いた際に復元される）。
5. ゴミ箱GUI下でも通常ホットバー操作と BAG スクロールを利用でき、GUI は標準のインベントリ閉じる操作で終了する。
6. ゴミ箱GUIを閉じた場合（ESC/X など）はゴミ箱内のアイテムをすべてプレイヤーインベントリへ戻し、保持データを破棄する。返却対象がある場合は、インベントリへ戻した旨のメッセージをプレイヤーへ表示する。
7. ゴミ箱GUIで廃棄ボタン（旧 閉じる slot）を押下した場合はゴミ箱確認GUIを表示する。
8. ゴミ箱確認GUIで廃棄アイコン押下、またはGUIを閉じた場合は廃棄確定。廃棄対象がある場合は、削除件数メッセージをプレイヤーへ表示する。
9. ゴミ箱確認GUIで「ゴミ箱GUIに戻る」押下時は廃棄せずゴミ箱GUIへ戻る。

## 追記（2026-05-27）trash起点フロー

1. TrashCommand.executePlayerCommand が TrashService.open を呼び出す。
2. MenuOpenEventHandler.handleMainMenuClick でメインメニューのゴミ箱アイコン押下時に TrashService.open を呼び出す。
3. ゴミ箱GUIの戻る操作は `TrashService.handleClick` で受け、`trashItemsByPlayer` を保持したまま GUI 履歴の直前画面へ戻す。

## 追記（2026-05-30）通常メニュー下部ダミーとパーティー GUI フロー

1. menu 系 GUI、プレイヤー設定 GUI、パーティー GUI、ログインボーナス GUI を開くと、装備・ゴミ箱など実アイテム操作対象を除き、プレイヤー下部インベントリをダミーで埋める。
2. 対象 GUI を閉じると、inventory feature の GUI 表示状態を再反映して下部インベントリを復元する。
3. メインメニューのパーティーアイコンからパーティー GUI を開く。
4. パーティー GUI の slot 49 は GUI 履歴の直前画面へ戻る。slot 51 は所属中のみ離脱または解散を実行する。
5. 未所属時は slot 22 でパーティー作成、招待一覧のプレイヤーヘッドクリックで招待承諾を行う。
## 追記（2026-06-01 プレイヤー一覧・パーティーGUI）

### 1. メインメニューからプレイヤー一覧を開く
1. メインメニューのプレイヤー一覧アイコンをクリックする。
2. `MenuOpenEventHandler` が `PlayerListGui` を `PLAYER_INFO` 用途で開く。
3. 一覧には現在オンラインのプレイヤーをページング付きで表示する。
4. プレイヤー頭をクリックすると `PlayerDetailGui` を開く。
5. `PlayerDetailGui` は対象プレイヤーヘッドへ基本情報、アカウント、クラス、所持 Gold、プレイ時間を統合し、現在地は world master の表示名だけを表示する。左上のカテゴリ別ステータスは現在値を太字で先頭に置き、その成立内訳を `現在値 (基礎値 +補正値)` の記号形式で表示する。内訳に「基礎」「補正」の文字ラベルは付けない。
6. 詳細画面のトレード申請アイコンは `TradeService.requestTrade`、パーティー招待アイコンは `PartyService.invite` を呼び出す。
7. 戻るでプレイヤー一覧、さらに戻るでメインメニューへ戻る。

### 2. `/player info <playerName>` からプレイヤー詳細を開く
1. コマンド実行者が対象プレイヤー名を指定して `/player info <playerName>` を実行する。
2. `PlayerInfoCommand` がオンラインプレイヤーを検索する。
3. 対象が存在する場合 `PlayerDetailGui` を直接開く。
4. 詳細画面からトレード申請またはパーティー招待を実行できる。自分自身を対象にした場合は操作を拒否する。
5. コマンドから直接開いた時点で GUI 履歴がない場合は、`slot 49` に閉じるボタンを表示する。
6. 対象が存在しない場合はプレイヤー向けメッセージを返す。

### 3. パーティー GUI の表示とメンバー操作
1. パーティー GUI を開くとリーダー頭を上段中央 `slot 13` に表示する。
2. 一般メンバーは下段中央から左右へ `31 -> 30 -> 32 -> 29 -> 33` の順に表示する。
3. リーダーはメンバー頭クリックで `PartyMemberActionGui` を開く。
4. `PartyMemberActionGui` からリーダー昇格またはキックを実行する。
5. 実行後はパーティー GUI を再描画して最新状態を反映する。

### 4. パーティー招待 GUI
1. パーティー GUI の招待アイコンをクリックする。
2. `PlayerListGui` を `PARTY_INVITE` 用途で開く。
3. 一覧にはオンラインかつパーティー未所属のプレイヤーのみ表示する。
4. 対象プレイヤー頭クリックで招待を送信し、パーティー GUI へ戻る。

### 5. バフ表示補正
1. `PlayerDetailGui` は対象プレイヤーの現在有効なバフ名を表示し、表示前にカラーコードを除去する。
2. 「現在のバフ」クリック時は対象プレイヤー ID と有効バフ一覧を `MenuView.openBuff` へ渡す。
3. バフ詳細 GUI は対象プレイヤー ID を保持し、20 tick ごとの再描画でも同じ対象の有効バフ一覧を取得する。
4. バフ詳細 GUI でもカラーコードを除去した表示名を使う。
