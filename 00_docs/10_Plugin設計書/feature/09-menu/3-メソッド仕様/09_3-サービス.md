# 09_3-サービス

## 1. 描画コンテキスト生成

クラス名: `PlayerGuiRenderContextFactory`
物理名: `create`

`AstPlayer` からアカウント、現在 status、CP、gold、帰還費用、装備表示名、通貨残高を取得し、不変な `PlayerGuiRenderContext` を返す。

## 2. GUI 遷移

クラス名: `MenuGuiTransitionService`
物理名: `applyPlayerInventoryDummy`, `fillPlayerInventoryDummy`, `consumePlayerInventoryDummyApplied`, `consumeSuppressedPlayerInventoryRestore`, `restorePlayerInventory`, `switchGuiWithoutInventoryReload`, `switchGuiWithInventoryRestore`

- menu 表示中の下部 inventory を dummy で保護する。
- `AstPlayer.isBedrock=true` のプレイヤーには下部 inventory の dummy として `GLOW_LICHEN` を使用し、それ以外では `GRAY_STAINED_GLASS_PANE` を使用する。
- GUI 間遷移では dummy の不要な復元だけを抑止する。close 音と GUI 固有の終了処理は共有 GUI セッション基盤が判定する。
- 通常画面へ戻る遷移では inventory feature に実データの再描画を委譲する。

## 3. ゴミ箱

クラス名: `TrashService`
物理名: `open`, `handleClick`, `handleDrag`, `handleClose`

- `open` は保持中 item と page を引き継いで編集画面を開く。
- `handleClick` / `handleDrag` は内容枠、ページ、確認、戻る操作だけを許可する。
- 確認時は item を破棄して `P_5601`、戻る・close 時は item を返却して `P_5602` を通知する。
- 有効なページ移動は `GuiSound.PAGE`、非空の確認画面表示は `GuiSound.CONFIRM`、破棄成功は `GuiSound.TRASH_DISPOSE` を再生する。空の確認操作では close 音を重ねない。
- private な確認処理を独立した public メソッドとしては扱わない。

## 売却

クラス名: `SellService`
物理名: `open`, `handleClick`, `handleDrag`, `handleClose`

- 有効なページ移動は `GuiSound.PAGE`、非空の確認画面表示は `GuiSound.CONFIRM`、売却成功は `GuiSound.SELL` を再生する。
- 空の確認操作では close 音を重ねず、売却成功時も `SELL` 以外の close 音を重ねない。
- 売却確定せずに売却編集画面または売却確認画面を閉じた場合、保持中のアイテムを通常インベントリへ返却し、売却状態を破棄する。返却できないアイテムは売却 GUI を再表示して保持する。

## 4. 共通 GUI navigation session

クラス名: `GuiNavigationState`、`GuiNavigationService`

- player ごとに現在画面と履歴 stack を保持し、back は直前画面から順に一件ずつ戻る。
- 同一画面の page 再描画は現在画面を置換し、履歴を増やさない。
- 履歴がない画面と `isAlwaysCloseNavigation=true` の holder は back slot を共通の `BARRIER` close button へ置換する。通常の履歴付き画面では、画面が用意した既存 back item を変更しない。
- `isAlwaysCloseNavigation=true` は操作と表示だけを close にし、保持済み履歴自体は削除しない。
- 共有 GUI セッション基盤が終了を確定した場合だけ、現在画面、全履歴、予約中の back 遷移を破棄する。
- back 遷移で記録済み画面を開いたときは、その画面を新しい履歴として積み直さない。
- back は inventory を先に履歴から除く代わりに一意の予約 token を持つ。`GuiOpenSupport` の open が cancel・失敗した場合は同じ token の予約だけを rollback し、古い callback は後続 back 操作の予約や履歴を変更しない。

## 5. 共通 GUI セッション遷移

クラス名: `GuiOpenSupport`、`GuiSessionTransitionService`、`GuiSessionTransitionEventHandler`、`GuiSessionContinuationRequestEvent`、`GuiSessionEndEvent`

- `GuiOpenSupport` は source inventory が現在開かれており player が online の場合だけ target inventory を開く。予約済み遷移が後続クリックで取り消された場合は source を閉じず、セッション終了候補も発生しない。
- `InventoryOpenEvent` が cancel されずにプラグイン管理 GUI を開いた時点で、共有基盤は player ごとに新しい session token を発行する。
- `InventoryCloseEvent` は終了を即決せず、同じ session token と inventory を含む close token を作り、次 tick に評価する。成功した別 GUI open が同 tick 中に session token を置き換えた場合、古い close token は無効になり、`GuiSessionEndEvent`、`CLOSE` 音、feature 固有 cleanup を発火しない。
- feature は個別の close 音抑止 API を呼び出さない。close 音の可否は `GuiSessionTransitionEventHandler` が session の終了確定時だけ判断する。
- target の open が cancel・失敗した場合は新しい session token が登録されないため、次 tick に source の終了を一度だけ確定する。`GuiSessionEndEvent` を発火し、`GuiCloseSoundHolder` を実装した GUI には `GuiSound.CLOSE` を一度だけ再生する。
- 連続遷移では close token ごとに session token を照合するため、古い失敗 callback や古い close 判定が後続 GUI セッションを終了しない。logout は active session と未確定 token を `endSilently` で消費し、`GuiSessionEndEvent` を一度だけ発火して feature cleanup と navigation 履歴破棄へ委譲する。この経路では `CLOSE` 音を再生しない。
- 保存中や未保存変更の確認など、close 後も同一 GUI セッション内で別画面を表示する feature は、`InventoryCloseEvent` 内で `GuiSessionContinuationRequestEvent` を発行する。共有基盤は source session と一致する継続 token を登録して次 tick に target supplier を評価し、成功した open は通常の GUI 遷移として扱う。この間は `GuiSessionEndEvent`、`CLOSE` 音、navigation 履歴消去を発生させない。target open 成功後の feature 固有処理は、実際に target を開けた場合だけ実行する。
- 継続 target の生成・open が cancel・失敗した場合、または別 GUI の open・logout で継続 token が無効になった場合は、古い Runnable を実行せず、source の終了だけを中央判定で一度確定する。

## 6. 共通 gold 金額入力

クラス名: `GoldAmountSettingGui`

- 27 slot GUI に桁移動、加減算、半減、倍増の control を固定配置する。
- step は 1 gold から 10 進桁で上下でき、加減算結果は `0..maxAmount` に clamp する。
- 大きな step と回数の積で `long` overflow を起こさず、上限または 0 へ安全に丸める。

## 7. 共通 page GUI

クラス名: `PagedGuiView`

hotbar shortcut で close と inventory 切替を扱う chest GUI では、旧 chest close slot に別の close button を描画せず背景 pane のまま維持する。

## 8. ガイド進捗評価

クラス名: `GuideProgressEvaluator`

- ガイドの step は master の順序で表示するが、達成判定は全未達成 step を個別に評価する。先行 step の未達成を理由に、条件を満たした後続 step を未達成のままにしない。
- 同一イベントで複数 step の条件が一致する場合は、該当する全 step を達成済みとして記録する。
- step に `targetId` が指定されている場合は進捗対象 ID の一致を必須とし、`targetIds` が指定されている場合はいずれかの候補 ID に一致したときに達成する。両方が指定された場合も、いずれかに一致すればよい。どちらも未指定の場合は同じ種別の進捗を対象 ID で限定しない。
- `ORB_USED` は消費したオーブ item ID、`DUNGEON_CLEARED` はクリアした dungeon ID を対象 ID として評価する。
- `PLAYER_LOGGED_IN`、ログインボーナス・メール・バンドル・ショップ購入・スキル習得・スキルツリー解放・スキル強化・スキル発動・Mob 討伐・採集完了・ウェイストーンテレポート・クエスト受領・クエスト完了を条件にできる。各条件は対象処理が成功した時だけ記録する。
- 採集の `GATHERING_COMPLETED` はスポナー生成物では生成元スポナー ID、手動生成物では採集定義 ID を対象 ID とする。
- `WAYSTONE_TELEPORTED` は `WorldService.teleportPlayerAsync` の成功 callback 後に対象ウェイストーン ID を記録する。事前検証失敗やテレポート失敗では記録しない。
- `QUEST_ACCEPTED` と `QUEST_COMPLETED` はクエスト ID を対象 ID とする。`QUEST_COMPLETED` は報酬と関連状態の保存成功後に記録し、NPC 完了では報告操作の成功時にだけ記録する。

## 9. ガイド案内アクション

クラス名: `GuideActionService`

- `NAVIGATE_NPC` はプレイヤーと同じワールドにいる指定 NPC の最寄り個体を選び、座標をプレイヤーへ通知する。スポーン中の個体は 200 tick 発光させ、未スポーン時は登録済み配置座標を利用する。player-skin NPC は表示中の疑似 Player を発光させ、通常 NPC は実体 Entity を発光させる。
- `OPEN_MENU` は許可済みの通常 GUI を開く。現状は `mail` を `MailGuiEventHandler` へ委譲する。
- 未登録 ID や未対応 menu は内部 ID を表示せず、汎用エラーを通知する。

## 10. GUI サウンド意味付け

クラス名: `GuiSound`

- `OPEN` / `CLOSE` は画面の開閉、`SELECT` は通常の選択・項目移動、`PAGE` はページ移動、`TOGGLE` は設定切替、`CONFIRM` は確認操作に使う。
- 無効なクリック・不足・権限不成立は `DENY` を使い、処理結果が確定した場合は操作内容に応じた結果音を使う。
- 購入・売却・報酬受取・強化・修理・プレイヤー間取引・テレポート・スキル習得は、それぞれ `PURCHASE` / `SELL` / `REWARD` / `UPGRADE` / `REPAIR` / `TRADE` / `TELEPORT` / `SKILL_LEARN` を使う。
- ただし、ダンジョンの個別アイテム受取は連続操作を前提とするため、`ITEM_RECEIVE`（`ENTITY_ITEM_PICKUP`）を使う。
- `GuiSessionTransitionEventHandler` は session token により終了が確定した `GuiCloseSoundHolder` 対象 GUI にだけ `CLOSE` を一度だけ再生する。成功した別 GUI 遷移の source close では再生しない。通常 GUI の共通ホットバー操作を使う `HotbarShortcutGuiHolder` はこの marker を継承し、オーブ画面の `OrbGuiHolder` も手動終了音の対象として実装する。
