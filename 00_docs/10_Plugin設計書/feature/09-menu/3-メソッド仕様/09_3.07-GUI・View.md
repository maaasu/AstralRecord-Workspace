# 09_3.07-GUI・View

## 共通 GUI ナビゲーション・閉じる表示規則

- `HotbarShortcutGuiHolder` を実装する GUI は、プレイヤーインベントリの BAG 制御列中央 `slot 26` に表示する共通閉じるアイコンを使用する。ホットバー9枠は通常表示を維持する。
- 上記 GUI のチェスト側には閉じるアイコンを置かず、背景アイテムをクリックしても閉じる処理を発火させない。
- 共通ページング GUI はチェスト側に閉じるアイコンを持たず、閉じる操作はプレイヤーインベントリ側の共通ホットバーへ統一する。
- 表示した操作アイコンとイベントの発火対象を一致させ、不可視の操作スロットを作らない。ただし、明示的に設計された管理者向け隠し操作は除く。
- `GuiNavigationHolder` の戻る操作は、固定した画面ではなく、GUI を閉じずに直前に開いていた GUI を開く。同一画面のページ送り・フィルター変更・再描画は履歴を増やさない。
- 直前の GUI が存在しない場合は、戻るボタンと同じスロットを `BARRIER` の閉じるボタンへ置き換える。メインメニューの `slot 49` は履歴の有無にかかわらず常に閉じるボタンとする。
- ESC、インベントリキー、共通閉じる操作などで GUI セッションが終了した場合は履歴を破棄する。以後コマンドなどで開く GUI から、終了前の GUI へ戻してはならない。

## 共通メニューアイコン生成

クラス名: `MenuIconFactory`
物理名: `create`

責務:

`MenuIconDefinition` を正本として、メインメニューとクラフト欄ショートカットの GUI 用 `ItemStack` を生成する。

処理内容:

1. `MenuIconDefinition` から素材、表示名、表示色、基本説明を取得する
2. `PlayerGuiRenderContext` からゴールドを先頭にした所持通貨一覧、現在装備、帰還費用などの画面固有 lore を追加する。通貨一覧は最大10種類を表示し、11種類目以降がある場合は末尾に `…` を表示する。ゴールドの数量は末尾に `G` を付ける
3. `GuiItems.create` を使用し、呼び出しごとに独立した `ItemStack` を生成する
4. クラフト欄の PDC 識別子は、生成後に `CraftShortcutView` が表示先固有値として付与する

## 3.1 装備強化 GUI 表示

クラス: `EquipmentEnhancementService`
対象: `open`

概要

NPC interaction など明示導線から開く装備強化用 GUI を表示する。装備 GUI からの遷移アイコンと装備強化 GUI の戻るボタンは持たず、強化時の自動オープンは行わない。

処理の要点:

1. `MenuScreen.EQUIPMENT_ENHANCE` の 54 スロット inventory を作成する。
2. GUI 表示中も統合 `BAG` と通常ホットバーを維持し、BAG／ホットバー内の装備クリックを強化対象選択として優先する。対象外アイテムは通常のインベントリ操作へ委譲する。
3. 装備をセットした時点で item master の `equipment.enhance.levels[*].requiredMaterials` / `requiredCurrency` / `successRate` / `failAction` を参照し、次強化段階が存在する場合のみ必要素材・必要ゴールド・成功率・失敗時挙動を日本語で表示する。現在状態の有効な強化上限へ到達している場合は、次 rank の `equipment.transcendence[]` を検索し、`requiredEnhanceLevel` を満たす状態変化を次操作として表示する。強化・状態変化不可の場合は理由を実行アイコンへ表示する。
4. 必要素材は inventory feature の所持数を参照し、GUI 上の消費アイテム表示用アイテム 1 個の lore に「必要数 / 所持数」の一覧として表示する。実行ボタン押下時にのみ消費する。
5. 実行時は補償用 inventory state を取得してから必要素材と Gold を消費し、その後に装備強化 API を呼ぶ。支払いまたは API 更新失敗時は支払い前 state へ復元する。
6. 通常強化は装備強化 API、状態変化は状態変化 API を呼ぶ。結果に応じて成功 / 状態変化 / 失敗 / 降格 / 破壊を反映し、プレイヤーメッセージとサウンド・パーティクルを再生する。
7. 戻る / ホットバー閉じる時はセット中の装備をプレイヤー所持へ戻し、下部表示インベントリも元の表示種別へ復元する。GUI 内に専用の閉じるボタンは配置しない。

## 3.2 装備修理 GUI 表示

クラス: `EquipmentRepairService`
対象: `open`

概要

NPC interaction から開く装備修理用 GUI を表示する。メインメニューには修理導線を置かず、拠点などに配置された修理 NPC からのみ開く。

処理の要点:

1. `MenuScreen.EQUIPMENT_REPAIR` の 54 スロット inventory を作成する。
2. GUI 表示中も統合 `BAG` と通常ホットバーを維持し、BAG／ホットバー内の装備クリックを修理対象選択として優先する。対象外アイテムは通常のインベントリ操作へ委譲する。
3. 対象装備の `durabilityValue` / `durabilityMax` から回復耐久と必要 Gold を表示し、耐久値なし・最大耐久済み・所持 Gold 不足は実行不可として表示する。
4. 実行時は補償用 inventory state を取得して Gold を消費し、装備耐久更新 API を呼ぶ。API 失敗時は支払い前 state へ復元し、更新と支払いの両方が成功した場合だけ GUI と保存処理へ反映する。
5. 閉じる時はセット中の装備をプレイヤー所持へ戻し、下部表示インベントリも元の表示種別へ復元する。

## 8. クラフトショートカット描画

クラス名: `MenuView`
物理名: `renderCraftShortcuts`

責務:

プレイヤーの 2x2 クラフト欄へショートカットアイコンを描画する。

処理内容:

1. `MenuOpenEventHandler` が `AstPlayer` から `PlayerGuiRenderContext` を 1 回生成する
2. `CraftShortcutView.createCraftResultIcon` は `MenuIconDefinition.MAIN_MENU` から成果物スロットのメニューアイコンを生成する
3. `MenuShortcutSettings.defaults()` の固定 4 action を 2x2 スロットへ配置する
4. 各 action は `MenuShortcutAction.iconDefinition` が参照する共通定義から生成し、Gold、現在装備、帰還費用、ステータスは同一コンテキストから lore へ追加する
5. `CraftShortcutView` がクラフト欄固有の PDC スロット番号と action code を付与する
6. 描画抑止フラグが立っているプレイヤーは描画しない
7. `STATUS` は互換識別値を維持したまま `MenuIconDefinition.ACCOUNT_INFO` を使い、クリック時は統合プレイヤー情報画面を開く

備考:

- クラフト欄ショートカットは「アイコン表示のみ」であり、実クラフト処理は menu feature では行わない。クラフト欄からのアイテム生成・素材消費は発生しない前提とする。
- 描画抑止フラグはメインメニュー／通貨 GUI の遷移中に一時的に有効化し、遷移完了後に解除する（[[09_3.01-イベント]] 参照）。

## 追記（2026-06-02）ストレージGUI/View

### ストレージGUI表示
クラス名: MenuView
物理名: openStorage
- `MenuScreen.STORAGE` の 54 スロット GUI を作成する。
- 0-44 スロットをストレージ内容領域とし、空枠は `GRAY_STAINED_GLASS_PANE` のプレースホルダーで表示する。
- 初期表示は収納順の昇順とし、収納時に採番した `slotIndex` を使う。
- 下段には前ページ、カテゴリフィルタ、レア度フィルタ、並び順、昇順/降順、ガイド、次ページを配置する。戻るボタンは配置しない。
- 並び順は収納順、獲得順、レア度順、売値順を循環し、昇順/降順ボタンで方向を切り替える。
- ストレージ内アイテムの lore には `スタック: <amount>` と `獲得: <datetime>` のみを追加する。カテゴリ、レア度、売値は通常アイテムの lore に含まれるため重複表示しない。数量は通常スタック上限で分割せず 1 entry の数量として表示する。`獲得` は収納時刻ではなく、収納元アイテムの作成日時（初回取得日時）を使用する。通常アイテムは同一 itemId / itemCategory の entry へ統合され、装備・ルーンなど instanceId と紐づくアイテムは統合されない。
- 下部プレイヤーインベントリの BAG／ホットバーアイテムをクリックすると、通常の装備・割り当て操作よりストレージ収納を優先する。ストレージ内容領域のアイテムをクリックすると所持インベントリへ取り出す。
- 収納・取り出し後は保存を即時実行せず、開いている間のストレージ表示情報をメモリ上で更新してから開いているページを再描画する。変更がある場合、保存はストレージ GUI を閉じる時にまとめて即時実行する。
- クリック数量は左クリック1個、右クリック半分、Shift+左クリック1スタック、Shift+右クリック全量とする。下部プレイヤーインベントリからの Shift+右収納は BAG・ホットバー全体の同一通常アイテムを対象にし、ストレージ側からの Shift+右取り出しは BAG の空き容量まで複数スタックへ分割する。
