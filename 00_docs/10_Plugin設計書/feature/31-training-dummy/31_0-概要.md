# 31_0-概要

## 1. 目的

検証用カカシ機能は、管理者がワールドへ再利用可能な攻撃対象を配置し、同じカカシに対する物理・魔法・シールドの挙動を複数プレイヤーで確認できるようにする。

## 2. 責務

- 管理者プレイヤー向け `/dummy` コマンドでカカシを配置、削除、再読み込みし、設定 GUI を開く。
- 配置と共有検証ステータスを Plugin data folder の `training-dummies.yml` に永続化する。
- 通常の Mob 基盤へ実行時テンプレートを渡し、固定位置に維持される攻撃可能な実体として生成する。
- HP が 1 未満にならない非致死個体とし、視認者がいない場合も自動破棄しない。
- 最大 HP、防御力、魔法防御、シールド有無・最大値を GUI から変更し、定期的に HP と有効なシールドを全回復する。
- 視線先のカカシに対する Drop キー入力を、共有設定 GUI を開く操作へ変換する。

## 3. 責務外

- 通常 Mob、ボス、NPC のマスタデータ、AI、ドロップ、討伐報酬を定義しない。
- カカシの HP、シールド、設定をプレイヤー別には保持しない。
- 戦闘計算式や入力候補間の優先順位そのものは変更しない。
- 配置を API、DB、filebase へ同期しない。

## 4. 主要境界と不変条件

- 永続定義の正本は `training-dummies.yml`、出現中の `MobInstance` はサーバセッション内だけの一時状態とする。
- カカシは filebase の Mob マスタへ登録せず、`training_dummy:<配置ID>` の実行時テンプレートとして生成する。
- 配置 ID ごとに定義と出現中インスタンスを一件ずつ対応付ける。同じ ID を再配置した場合は既存定義を初期値で上書きし、実体を再生成する。
- 設定変更は共有定義を保存してから実体を再生成するため、出現中の HP・シールドは新しい最大値へ戻る。
- 非致死個体への HP damage は残 HP 1 を下限とし、通常の死亡・ドロップ処理へ進めない。
- Drop キーによる GUI 表示には管理者権限を要求しない。配置済みカカシを視認できるプレイヤーが共有設定を変更できる現行契約とする。

## 5. データ・設定の正本

| データ | 正本 | ライフサイクル |
|:--|:--|:--|
| 配置 ID、ワールド、座標、向き | `training-dummies.yml` | 起動・reload 時に読み込み、配置・削除時に全件保存 |
| 最大 HP、防御力、魔法防御、シールド、回復間隔 | `training-dummies.yml` | GUI 更新または手編集後の reload で反映 |
| 出現中インスタンス ID、現在 HP・シールド | メモリ | 起動中だけ保持し、停止・reload・設定変更時に破棄 |

詳細な項目と制約は [[31_1-モデル定義]] を正本とする。

## 6. 依存・連携

- `mob`: 実行時テンプレートの生成、実体 Mob、固定位置制御、インスタンス管理は [[12_0-概要]] を利用する。
- `combat`: damage 計算、shield / HP 反映と非致死上限は [[14_0-概要]] を利用する。
- `player-interaction`: Drop キーの候補収集、優先順位、claim と event cancel は [[28_0-概要]] を正本とする。
- `user` / `player`: `/dummy` の管理者権限と player-only 実行を提供する。
