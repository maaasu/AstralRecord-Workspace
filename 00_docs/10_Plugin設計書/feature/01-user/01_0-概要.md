# 01_0-概要

## 1. 目的

`user` 機能は、プレイヤーのユーザー実体（`dbo.user` 相当）を管理する。
主目的は以下。

- 初回ログイン時のユーザー登録
- ログイン時の最終参加情報更新
- 権限値（`permission`）の運用変更

## 2. コンテキスト

- 本機能は `AsyncPlayerPreLoginEvent` を入口に動作する。
- データアクセスは直接 DB ではなく AstralRecord API (`/api/user/*`) 経由。
- `account` 機能と密結合で、初回登録時に `account` も生成する。

## 3. 構成要素（実装単位）

- `event/UserLoginEventHandler`
  - 非同期ログインイベントを受け、`UserService` に委譲する。
- `service/UserService`
  - 初回登録判定、登録フロー、ログイン更新フローの業務制御を行う。
- `repository/UserRepository`
  - `/api/user` への HTTP リクエストを実行する。
- `command/UserCommand`, `UserPermissionCommand`
  - 管理者向けに `permission` 変更を提供する。
- [[01_1-モデル定義]].ユーザモデル, [[01_1-モデル定義]].システムユーザ
  - ユーザー表現とシステム更新主体を定義する（詳細は [[01_1-モデル定義]]）。

## 4. 依存関係

- 内部依存
  - `UserService` -> `UserRepository`
  - `UserService` -> `AccountService`
  - `UserPermissionCommand` -> `UserService`, [[03_1-モデル定義]].プレイヤーキャッシュ
- 外部依存
  - Bukkit/Paper イベント (`AsyncPlayerPreLoginEvent`)
  - AstralRecord API (`/api/user`)

- `account`
  - 新規ユーザー登録時に初期アカウント作成を委譲する。
- `player`
  - [[03_1-モデル定義]].プレイヤーキャッシュ 経由でオンラインプレイヤーの権限反映を行う。

## 5. ライフサイクル登録点

- `AstralRecord#setupFeature` で `UserRepository`, `UserService` を初期化
- `AstralRecord#registerPluginFeatures` で `UserLoginEventHandler` を登録
- `core/CommandRegister` で `/user` コマンドを登録
