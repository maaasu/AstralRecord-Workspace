# 01_5-例外・ログ・運用

## 1. 方針

`user` 機能は「ログ記録して処理継続」を基本とする。
特にログイン前処理では、取得失敗時にサーバー全体を止めないことを優先している。

## 2. 主なログポイント

- `UserLoginEventHandler`
  - 予期しない例外: `LogId.E_5000`
- `UserService`
  - ログイン前処理失敗: `LogId.W_5051`
  - `getUser` 失敗: `LogId.W_5052`
  - 同一IPの別ユーザー確認をスキップ: `LogId.W_5053`（IPはログへ出力しない）
  - 新規登録成功: `LogId.I_5050`
- `UserPermissionCommand`
  - permission 変更監査: `LogId.I_5053`（実行者 UUID、対象 UUID、変更前 permission、変更後 permission、実行経路 `PLAYER` / `CONSOLE`）
  - permission 非同期更新失敗: `LogId.E_5059`（対象 UUID）
- `BanCommand`
  - BAN変更監査: `LogId.I_5054`（実行者 UUID、対象 UUID、変更前後の無期限フラグ・期限、実行経路）
  - BAN非同期更新失敗: `LogId.E_5063`（対象 MCID）
- `UserRepository`
  - 取得成功: `LogId.D_5055`
  - 取得失敗/異常: `LogId.W_5055`, `LogId.E_5055`
  - 登録成功/異常: `LogId.D_5056`, `LogId.E_5056`
  - アカウントID更新成功/異常: `LogId.D_5057`, `LogId.E_5057`
  - ログイン情報更新成功/異常: `LogId.D_5058`, `LogId.E_5058`
  - permission 更新成功/異常: `LogId.D_5059`, `LogId.E_5059`
  - ユーザー履歴登録成功/異常: `LogId.D_5060`, `LogId.E_5060`
  - MCID一覧取得成功/異常: `LogId.D_5061`, `LogId.E_5061`
  - BAN情報更新成功/異常: `LogId.D_5062`, `LogId.E_5062`
  - 同一IPの別ユーザー有無確認成功/異常: `LogId.D_5064`, `LogId.E_5064`（IPはログへ出力しない）

## 3. 例外処理の境界

- `Repository`
  - HTTP 異常や `InterruptedException` を捕捉し、ログ記録後に例外化する。
- `Service`
  - ログイン前処理では repository 例外を捕捉し、警告ログで吸収する箇所がある。
- `EventHandler`
  - イベントハンドラの `try/catch` で `LogId.E_5000` を記録し、最終的なイベント境界で例外漏れを防ぐ。

## 4. スレッド上の注意

- `AsyncPlayerPreLoginEvent` で DB/API 呼び出しを実施するため、メインスレッドブロックは回避できる。
- `/user permission` の API 取得・更新は `AsyncTaskUtil.supplyAsync` で実行し、`AstPlayer`、スキルツリー表示条件、Bukkit コマンド可視性の反映はメインスレッドへ戻して行う。
- 同一対象の権限更新は `pendingTargets` で直列化し、完了時に必ず解除する。
- `/ban` の MCID検索・BAN更新は `AsyncTaskUtil.supplyAsync` で実行し、DB更新成功後の `Player.kick` はメインスレッドで行う。
- 同一MCIDのBAN更新は `pendingMcids` で直列化し、完了時に必ず解除する。
- `InterruptedException` 捕捉時は `Thread.currentThread().interrupt()` を再設定している。
