# 01_3-コマンド

## 1. command メソッド仕様

### ユーザルート振分

クラス名: `UserCommand`
物理名: `executeCommand`

責務:

`/user` の第一引数を判定し、サブコマンドへ委譲する。

処理内容:

1. 引数なしの場合は usage を返す
2. 第一引数が `permission` の場合、権限変更実行へ委譲する
3. 対応外サブコマンドは usage を返す

入力:

- `args[0]`: サブコマンド名

出力:

- なし

例外時挙動:

- 基底 `AstCommand` 側で例外を捕捉しエラーメッセージを返す

### 権限変更実行

クラス名: `UserPermissionCommand`
物理名: `executeCommand`

責務:

入力検証、実行権限検証、permission 更新、オンライン反映を行う。

処理内容:

1. 実行者がプレイヤーの場合 `permission >= 99`、または `config.yml` の `plugin.debugUsers` に実行者 UUID が含まれることを検証する

	| 項目 | 内容 |
	|---|---|
	| 検証対象 | コマンド送信者 |
	| コンソール | 許可 |
	| プレイヤー | [[03_1-モデル定義]].プレイヤーキャッシュ から取得したユーザ権限が `99` 以上、または `plugin.debugUsers` の UUID 完全一致なら許可 |
	| デバッグユーザー | `plugin.debugUsers` に設定された UUID と実行者 UUID が一致する場合、`/user permission` のみ許可する |
	| 拒否条件 | [[03_1-モデル定義]].プレイヤーキャッシュ 取得不可かつ `plugin.debugUsers` 不一致、または `permission < 99` かつ `plugin.debugUsers` 不一致 |

	| 項目 | 内容 |
	|---|---|
	| メッセージID | `PlayerMsgId.P_5061` |
	| レベル | `ERROR` |
	| テンプレート | `このコマンドを実行する権限がありません。` |
	| 出力条件 | 実行者がプレイヤー かつ `permission < 99` かつ `plugin.debugUsers` 不一致 |
	| 引数 | なし |

2. permission 値を [[01_1-モデル定義]].ユーザ権限 へ解決する

	| 項目 | 内容 |
	|---|---|
	| 入力 | `args[0]` |
| 名称指定 | 英語ID（`PLAYER` / `DONOR` / `ADMIN`）と大小無視で一致した場合に採用する |
	| 数値指定 | 整数として解析でき、列挙値（`0`/`5`/`99`）と一致する場合に採用する |
	| 拒否条件 | 名称・数値いずれにも一致しない |

	| 項目 | 内容 |
	|---|---|
	| メッセージID | `PlayerMsgId.P_5301` |
	| レベル | `ERROR` |
| テンプレート | `permission は名称（PLAYER/DONOR/ADMIN）または 0 / 5 / 99 のいずれかで指定してください。` |
	| 出力条件 | 名称・数値いずれにも解決できない場合 |
	| 引数 | なし |

3. 対象（プレイヤー名/UUID）を UUID へ解決する

	| 項目 | 内容 |
	|---|---|
	| 入力 | `args[1]`（省略可） |
	| 省略時（プレイヤー実行） | 実行者自身の UUID を対象とする |
	| 省略時（コンソール実行） | エラーメッセージを返して終了する |
	| プレイヤー名指定 | オンラインプレイヤー名と完全一致した場合、その UUID を使用する |
	| UUID指定 | UUID文字列として解析できた場合、その UUID を使用する |
	| 解決失敗 | エラーメッセージを返して終了する |

	| 項目 | 内容 |
	|---|---|
	| メッセージID | `PlayerMsgId.P_5300` |
	| レベル | `ERROR` |
	| テンプレート | `対象プレイヤーまたはUUIDが見つかりません: {0}` |
	| 出力条件 | UUID解決失敗時 |
	| 引数 | `args[1]` |

	| 項目 | 内容 |
	|---|---|
	| メッセージID | `PlayerMsgId.P_5305` |
	| レベル | `ERROR` |
	| テンプレート | `コンソールから実行する場合は対象プレイヤーを指定してください。` |
	| 出力条件 | コンソール実行かつ対象指定省略時 |
	| 引数 | なし |

4. 同一対象の更新中でないことを確認し、対象 UUID を `pendingTargets` へ登録する

	| 項目 | 内容 |
	|---|---|
	| メッセージID | `PlayerMsgId.P_5306` |
	| 出力条件 | 同一対象 UUID が既に更新中 |
	| 終了時処理 | 非同期処理の成否にかかわらず対象 UUID を解除する |

5. 非同期タスクで監査用の変更前 permission を取得する

	| 項目 | 内容 |
	|---|---|
	| 取得方法 | [[01_3-サービス]].ユーザ取得 を呼び、対象ユーザの permission を保持する |
	| 取得失敗 | `null` の場合は変更前 permission を `null` として後続の監査ログに記録する |

6. 同じ非同期タスクで [[01_3-サービス]].権限更新を呼び更新する

	| 項目 | 内容 |
	|---|---|
	| 対象ユーザ | 手順3で解決した UUID |
	| 設定値 | 手順2で検証した permission |
	| 更新者 | プレイヤー実行時は実行者UUID、コンソール実行時は [[01_1-モデル定義]].システムユーザ |
	| サービス未初期化 | エラーメッセージを返して終了する |
	| 更新後取得失敗 | エラーメッセージを返して終了する |

	| 項目 | 内容 |
	|---|---|
	| メッセージID | `PlayerMsgId.P_5302` |
	| レベル | `ERROR` |
	| テンプレート | `UserService が初期化されていません。` |
	| 出力条件 | `AstralRecord.getInstance().getUserService() == null` |
	| 引数 | なし |

	| 項目 | 内容 |
	|---|---|
	| メッセージID | `PlayerMsgId.P_5303` |
	| レベル | `ERROR` |
	| テンプレート | `ユーザー更新後の取得に失敗しました: {0}` |
	| 出力条件 | 権限更新の戻り値が `null` |
	| 引数 | `targetUuid` |

7. メインスレッドへ戻り、監査ログを記録する

	| 項目 | 内容 |
	|---|---|
	| ID | `LogId.I_5053` |
	| レベル | `INFO` |
	| テンプレート | `permission を変更しました: 実行者=%s, 対象=%s, 変更前=%s, 変更後=%s, 経路=%s` |
	| 出力条件 | 権限更新成功時 |
	| 引数 | 実行者 UUID、対象 UUID、変更前 permission（取得失敗時は `null`）、変更後 permission、実行経路（`PLAYER` / `CONSOLE`） |

8. 対象がオンラインなら [[03_1-モデル定義]].プレイヤーキャッシュ へ反映する

	| 項目 | 内容 |
	|---|---|
	| 判定条件 | `Bukkit.getPlayer(targetUuid)` が `null` ではない |
	| 反映先 | オンライン中の [[03_1-モデル定義]].プレイヤーセッション |
	| 反映内容 | `AstPlayer.applyPermission(updated)` |
	| 後続更新 | `SkillTreeService.markViewerContextDirty(online)`（サービス初期化済みの場合）、`Player.updateCommands()` |

9. 結果メッセージを返す

	| 項目 | 内容 |
	|---|---|
	| メッセージID | `PlayerMsgId.P_5304` |
	| レベル | `INFO` |
	| テンプレート | `permission を更新しました: {0} = {1}` |
	| 出力条件 | 権限更新成功時 |
	| 引数 | `updated.getMcid()`, `updated.getPermission()` |

入力:

- `args[0]`: 設定する permission（名称 `PLAYER`/`DONOR`/`ADMIN`、または数値 `0`/`5`/`99`）
- `args[1]`: 対象プレイヤー名または UUID（省略時はプレイヤー実行者自身、コンソール実行ではエラー）

出力:

- なし

例外時挙動:

- 入力不正・対象不明・サービス未初期化時はエラーメッセージを返して終了する
- 非同期処理失敗時は `LogId.E_5059` を記録し、`PlayerMsgId.P_5062` を送信する
- 全完了経路で `pendingTargets` から対象 UUID を削除する

### ユーザ補完候補取得

クラス名: `UserTabCompleter`
物理名: `getCompletions`

責務:

`/user` の入力位置に応じた補完候補を返す。

処理内容:

1. 第1引数位置では `permission` を返す
2. `permission` サブコマンド時は `UserPermissionTabCompleter` へ委譲する
3. それ以外は空リストを返す

### 権限変更補完候補取得

クラス名: `UserPermissionTabCompleter`
物理名: `getCompletions`

責務:

`/user permission` の候補（対象・permission値）を返す。

処理内容:

1. 第1引数位置では権限名称（`PLAYER`, `DONOR`, `ADMIN`）だけを返す。数値入力は実行時に受理するが補完候補には含めない
2. 第2引数位置ではオンラインプレイヤー名を返す
3. それ以外は空リストを返す

### BAN実行

クラス名: `BanCommand`
物理名: `executeCommand`

責務:

DBに登録された MCID を対象に、無期限または日数指定の有期限 BAN を非同期で更新し、オンライン対象をキックする。

処理内容:

1. 引数を `/ban <mcid> <indefinite|temporary> [days]` として検証する
2. `indefinite` は第3引数を受け付けず、`temporary` は正の整数の日数を必須とする
3. `UserService.getUserByMcid` で対象ユーザーを解決する。対象はオンライン状態ではなく API の参加履歴を正とする
4. 同一 MCID の更新中は `pendingMcids` で拒否する
5. `AsyncTaskUtil.supplyAsync` 内で `UserService.setBan` を呼び、`temporary` は現在日時（秒切捨て）に日数を加えた `banDate` を保存する
6. メインスレッドへ戻り、`LogId.I_5054` を記録する
7. 対象がオンラインなら `Player.kick(PlayerMsgResource.getComponent(PlayerMsgId.P_5307))` を実行する
8. 成否にかかわらず `pendingMcids` から対象を解除する

| 項目 | 内容 |
|---|---|
| 実行権限 | コンソール、または `UserPermission.ADMIN` のプレイヤー |
| デバッグユーザー | 許可しない。`plugin.debugUsers` による例外許可は使用しない |
| 対象未検出 | `PlayerMsgId.P_7115` を返し、更新しない |
| 引数不正 | `PlayerMsgId.P_5310` または `P_5311` と usage を返し、更新しない |
| 更新中 | `PlayerMsgId.P_5309` を返し、二重更新しない |
| 非同期失敗 | `LogId.E_5063` を記録し `PlayerMsgId.P_5062` を返す |
| 無期限完了 | `PlayerMsgId.P_5308` を返す |
| 有期限完了 | `PlayerMsgId.P_5312` を返す |

### BAN補完候補取得

クラス名: `BanTabCompleter`
物理名: `getCompletionsAsync`

処理内容:

1. 第1引数位置で API の `GET /api/user/mcids?prefix={prefix}` を非同期呼び出しし、論理削除されていない参加履歴ユーザーの MCID を返す
2. 第2引数位置で `indefinite` / `temporary` を返す
3. `temporary` の第3引数位置で日数入力例 `1` / `7` / `30` を返す
4. 管理者プレイヤー以外は候補を返さない。コンソールは許可する

## 2. コマンド仕様

- ルート: `/user`
- サブコマンド: `/user permission <permission> [<player|uuid>]`
- 短縮ルート: `/uperm <permission> [<player|uuid>]`
  - `/user permission` と同じ権限・入力・補完・処理を使用する。
- ルート: `/ban <mcid> <indefinite|temporary> [days]`
  - `indefinite` は無期限、`temporary` は第3引数の日数で有期限 BAN を設定する。

## 3. 実行権限仕様

- 送信者がコンソール: 実行可
- 送信者がプレイヤー:
  - `config.yml` の `plugin.debugUsers` に実行者 UUID が含まれる: `/user permission` のみ実行可
  - [[03_1-モデル定義]].プレイヤーキャッシュ 取得不可 かつ `plugin.debugUsers` 不一致: 拒否
  - [[03_1-モデル定義]].プレイヤーセッション.user.permission < `99` かつ `plugin.debugUsers` 不一致: 拒否
  - それ以外: 実行可
- `/ban` のプレイヤー実行は `UserPermission.ADMIN` のみ。デバッグユーザー例外は適用しない。
