# 01_4-統合フロー

## 1. ログイン前処理

### シーケンス

```mermaid
sequenceDiagram
    participant EVT as AsyncPlayerPreLoginEvent
    participant H as UserLoginEventHandler
    participant S as UserService
    participant UR as UserRepository
    participant AS as AccountService

    EVT->>H: onAsyncPreLogin
    H->>S: onAsyncPreLogin(uuid, name, address)
    S->>UR: findByUuidSilent(uuid)
    alt ユーザー未登録
        S->>UR: insert(user)
        S->>AS: createAccount(userId, 1)
        AS-->>S: 初期アカウント
        S->>UR: updateAccountId(userId, accountId)
    else ユーザー登録済み
        S->>AS: getSelectedAccount(user)
        alt 選択アカウントあり
            S->>UR: updateJoinInfo(userId, name, address)
        end
    end
```

### 処理要点

- `AsyncPlayerPreLoginEvent` の非同期イベント内で API 呼び出しまで完結する。
- 未登録時はユーザー、初期アカウント、選択アカウント ID の順に作成・更新する。
- 登録済みでも選択アカウントが取得できない場合は参加情報を更新しない。

### 例外・終了条件

- API 処理の例外は `UserService.onAsyncPreLogin` が捕捉して `LogId.W_5051` を記録する。

## 2. 権限変更

### シーケンス

```mermaid
sequenceDiagram
    participant C as UserPermissionCommand
    participant A as AsyncTaskUtil
    participant S as UserService
    participant R as UserRepository
    participant PC as AstPlayerCache
    participant ST as SkillTreeService
    participant P as Bukkit Player

    C->>C: executePlayerCommand / 入力・権限検証
    C->>C: pendingTargets へ対象UUIDを登録
    C->>A: supplyAsync
    A->>S: setPermission(targetUuid, permission)
    S->>R: updatePermission
    S->>R: findByUuid
    R-->>S: 更新後 UserModel
    A-->>C: メインスレッドで完了処理
    opt 対象がオンラインかつキャッシュ済み
        C->>PC: get(targetUuid)
        C->>PC: AstPlayer.applyPermission
        C->>ST: markViewerContextDirty
        C->>P: updateCommands
    end
    C->>C: pendingTargets から対象UUIDを削除
```

### 処理要点

- 同一対象への並行更新は `pendingTargets` で拒否し、二重送信を防ぐ。
- API 更新と再取得は非同期、Bukkit オブジェクトとキャッシュの更新はメインスレッドで行う。
- オンライン反映後はスキルツリー表示条件とコマンド可視性も更新する。

### 例外・終了条件

- 更新中の対象には `PlayerMsgId.P_5306` を返す。
- 非同期処理失敗時は `LogId.E_5059` を記録して `PlayerMsgId.P_5062` を送信する。
- 成否にかかわらず `pendingTargets` の登録を解除する。
