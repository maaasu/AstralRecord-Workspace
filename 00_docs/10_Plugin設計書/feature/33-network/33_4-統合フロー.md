# 33_4-統合フロー

## RPGからロビーへの保存付き転送

1. `/lobby`はプレイヤー単位の共通セッション遷移ゲートを取得する。同一プレイヤーの二重実行またはアカウント切替中は開始せず、取得後はプレイヤーを一時的に無敵化して移動・インベントリ・ドロップ・拾得・操作・持ち替えを凍結する。
2. 現在の player session を維持したまま Bukkit 状態を capture し、player-state の debounce を即時 flush して Quest state とともに保存 ACK を待つ。この時点では feature runtime と cache を解放しない。
3. いずれかの保存が失敗または例外終了した場合は接続要求を送らず、無敵化と操作凍結を解除して現在のチャンネルに残す。プレイヤーへ保存失敗メッセージを表示する。
4. 全保存の ACK 成功時だけ`astralrecord:network`の`connect`メッセージをProxyへ送る。
5. Proxyは許可接続先、接続中予約を含む定員、RPG接続クールタイムを検証してVelocity接続要求を実行する。クールタイムはRPG接続時に加えてRPG離脱・Proxy切断時にも開始する。
6. Proxy 接続要求後に退出イベントが発生した時点で、通常の logout 処理が feature runtime と cache を解放してセッション遷移ゲートを解除する。要求後5秒を超えて元RPGに残った場合はゲートと凍結を解除し、移動失敗として現在チャンネルでの操作を再開する。

## サーバー選択

- Lobbyの`/server`または設定NPCへの視線クリックでGUIを開く。
- GUIのslot、material、表示名、lore、Proxy接続先名はLobby `config.yml`を正本とする。
- GUIはNetwork APIのサーバー状態を非同期取得し、各アイコンへ現在人数と閲覧者が利用できる最大人数を表示する。寄付者は基本上限と寄付者追加枠、管理者はさらに管理者追加枠を`基本人数 +追加人数`として表示する。
- 閲覧者の利用可能枠が満員の場合はアイコンへ「満員のため接続できません」と表示し、クリックによる接続要求を送らない。API状態が未取得またはオフラインの場合も接続要求を送らない。
- GUIの判定後も、Proxyは同じ権限別上限と接続中予約を使って最終判定する。クールタイムはProxyだけが確定する。
- Proxyは所在heartbeat周期ごとに各backendを非同期pingし、成功時だけ`online`、失敗時は人数0の`offline`としてNetwork APIへ送る。

## 全体チャット

1. LobbyまたはRPGの通常の全体チャットはローカル配信を止め、発言者UUID、チャンネル、アカウント表示、レベル、クラス名、変換前本文、変換後本文をProxyへ送る。Proxyは変換済み本文を `原文[変換後]` として、原文は白、括弧は灰色、変換後は金色・斜体で表示する。アイテム共有チャットはホバー・クリック操作を維持するためRPG内配信とする。
2. Proxyは送信元接続と発言者UUIDの一致を確認して全Proxyプレイヤーへ一度だけ配信する。送信元backendがProxy設定の`discord.excludedSourceServers`に含まれない場合だけ、Minecraft発言をNetwork APIへ登録する。
3. LobbyはNetwork APIのMinecraft発言を読み、DiscordSRVの`global`対応チャンネルへ送る。独自中継が有効な間は`triggeringBukkitEvent`の状態に依存せずDiscordSRV標準のMinecraft→Discord処理をキャンセルし、独自中継との二重送信を防ぐ。
4. DiscordSRVの`global`対応チャンネルに投稿されたbot以外の発言をLobbyで通常broadcastをキャンセルしてNetwork APIへ登録する。アカウント連携の要否、ロール・ID・本文フィルターはDiscordSRV設定を正本とする。
5. ProxyはNetwork APIのDiscord発言を読み、全Proxyプレイヤーへ一度だけ配信する。

APIチャットはメッセージUUIDで冪等化し、generationIdとsequence cursorで差分取得する。API再起動でgenerationIdが変わった場合はcursorを0へ戻して先頭から再取得する。

## Discordサーバー接続通知

1. Lobby上のDiscordSRV標準参加・初回参加・退出通知はランタイム設定で常時停止し、backend単位のJoin/QuitをDiscordへ送らない。
2. Proxyの初回`ServerPostConnectEvent`はネットワーク参加として「プレイヤー名がサーバーに参加した」通知をNetwork APIへ登録する。Proxyの`DisconnectEvent`だけをネットワーク退出として扱う。
3. 前backendを持つ`ServerPostConnectEvent`はチャンネル切替として、Proxy `channelNames`の表示名を用いた「切替元から切替先へ接続した」通知を登録する。
4. 切替元または切替先、実切断元が`discord.excludedSourceServers`に含まれる場合は通知を登録しない。これにより除外backendとLobby間の往復も通知しない。
5. Lobbyは`kind=lifecycle`のMinecraftメッセージを通常チャットの`[server] author:`形式にせず、通知本文だけDiscordSRVへ送る。
6. LobbyのDiscord中継開始時はNetwork API応答の`latestSequence`をカーソルとして設定し、それ以前の短期中継履歴を送らない。`latestSequence`を返さない旧API応答では中継を停止してAPI更新を待つ。

## 最高権限とプライベートチャット監視

1. Proxyは`serverAuthorityUsers`を起動時と所在heartbeat周期にNetwork APIへ全置換送信する。APIは単一プロセスのメモリに保持し、Lobby admissionではBAN判定を維持したまま該当UUIDの実効permissionを`99`にする。
2. 各RPG backendはNetwork APIの最高権限一覧を非同期に定期取得する。該当UUIDは保存済み`user.permission`を書き換えず、実効permission `99`としてOP、管理機能、管理者接続枠、whitelist、debugUsers例外へ反映する。
3. DMは同一backendなら従来形式で送受信者へ配信する。別backendのオンライン受信者は送信元RPGからProxyへ配送要求を送り、Proxyが送受信者へ同じ形式で一度だけ配信する。どちらの場合も、送信者・受信者・変換前本文・変換後本文をProxyへ監視メッセージとして送る。パーティーチャットのローカル受信者は現在パーティーのonline memberだけとし、発言者・パーティー識別名・変換前本文・変換後本文をProxyへ送る。
4. Proxyは監視メッセージを`serverAuthorityUsers`に一致するオンラインプレイヤーへだけ全backend横断で配信する。DMは「送信者 → 受信者」、パーティーチャットは「パーティー識別名」と発言者を表示する。DBのpermission `99`だけのプレイヤーは受信対象に含めない。

## 全体Tabと所在

- Lobby表示は`[ロビー] MCID`とする。
- RPG表示は`[channel] [classShortName Lv.classLevel] [AFK] accountName#slotIndex`とし、RPG側Tabと同じクラス・レベルの順序、shortNameに定義した色・装飾、AFK時だけ付く赤いAFK接頭辞を使用する。アカウント名は通常白色、`#slotIndex`は灰色とし、所有ユーザーのpermissionが寄付者の`5`と一致する場合はアカウント名だけ水色・太字とする。
- RPGはロード完了時と5秒周期でメタデータをProxyへ送る。
- RPGはshortNameのlegacy色・装飾コードと所有ユーザーのpermissionをTabメタデータへ保持し、ProxyはそれをAdventure Componentへ変換して表示する。permission未送信の旧メタデータはプレイヤー権限の`0`として扱う。
- ProxyはTabメタデータを、送信元backendがプレイヤーの現在接続先backendと一致する場合だけ採用し、backend切替中の旧接続からの通知を破棄する。
- LobbyとRPGはオンラインプレイヤー1人を経由し、5秒周期で各サーバーの平均MSPTをProxyへ送る。
- Proxyは2秒周期で各viewerのTabListを確認し、表示内容が変化したentryだけを反映する。
- ProxyはTabヘッダーへ`ASTRAL RECORD`と閲覧者の現在接続先backendのMSPT、フッターへ閲覧者のpingとProxy全体の参加人数を表示する。MSPT未受信時と最終受信から15秒を超えた場合は計測中表示とする。
- network機能が有効なRPGでは、ヘッダー/フッターとプレイヤーリスト名の競合を避けるためRPG側の旧Tab更新を停止し、Proxy表示を正本とする。
- API所在heartbeatは10秒周期、API側TTLは30秒とし、切断時は即時削除を試みる。
