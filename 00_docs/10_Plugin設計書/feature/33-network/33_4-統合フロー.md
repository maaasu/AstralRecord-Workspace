# 33_4-統合フロー

## RPGからの保存付き転送

1. `/lobby`はプレイヤー単位の共通セッション遷移ゲートを取得する。同一プレイヤーの二重実行またはアカウント切替中は開始せず、取得後はプレイヤーを一時的に無敵化して移動・インベントリ・ドロップ・拾得・操作・持ち替えを凍結する。
2. 現在の player session を維持したまま Bukkit 状態を capture し、player-state の debounce を即時 flush して Quest state とともに保存 ACK を待つ。この時点では feature runtime と cache を解放しない。
3. いずれかの保存が失敗または例外終了した場合は接続要求を送らず、無敵化と操作凍結を解除して現在のチャンネルに残す。プレイヤーへ保存失敗メッセージを表示する。
4. 全保存の ACK 成功時だけ`astralrecord:network`の`connect`メッセージをProxyへ送る。通常の`/lobby`はロビーを、Proxy最高権限の`/server <gameServer>`は指定RPG backendを接続先とする。
5. ProxyはAPI admissionでユーザーBAN・接続先チャンネルの入場ロールを確認し、許可接続先、接続中予約を含む定員、RPG接続クールタイムを検証してVelocity接続要求を実行する。API照会失敗時は接続しない。クールタイムはRPG接続時に加えてRPG離脱・Proxy切断時にも開始する。
6. Proxy 接続要求後に退出イベントが発生した時点で、通常の logout 処理が feature runtime と cache を解放してセッション遷移ゲートを解除する。`InvulnerabilityVisualService` も退出イベントで無敵と発光を解除し、player data に転送中の状態を残さない。要求後5秒を超えて元RPGに残った場合はゲートと凍結を解除し、移動失敗として現在チャンネルでの操作を再開する。

## サーバー選択

- Lobbyの`/server`または設定NPCへの視線クリックでGUIを開く。
- Proxy `serverAuthorityUsers`に登録されたプレイヤーは、LobbyまたはRPGで`/server <gameServer>`を実行してRPGチャンネルを直接指定できる。候補補完はProxy `gameServers`のうち現在接続中でないbackendだけを返し、通常プレイヤーへは候補を公開しない。
- RPG上で最高権限が`/server <gameServer>`を実行した場合、Proxyはクールタイムを先に検証し、移動元RPGへ`prepare_connect`を送る。このときプレイヤー、移動元、移動先、有効期限10秒を結び付けた一回限りの転送準備を保持する。移動元は通常の`/lobby`と同じ保存・凍結処理を行い、保存ACK後にだけ指定先への`connect`を返す。Proxyは返された要求でも現在の接続元、転送準備、最高権限、接続先、クールタイム、定員を再検証し、転送準備を一度だけ消費する。
- GUIのslot、material、表示名、lore、Proxy接続先名はLobby `config.yml`を正本とする。
- GUIはNetwork APIのサーバー状態を非同期取得し、各アイコンへ現在人数と閲覧者が利用できる最大人数を表示する。寄付者は基本上限と寄付者追加枠、管理者はさらに管理者追加枠を`基本人数 +追加人数`として表示する。
- 各アイコンはRPGアイテムと同様に、`◆`付き表示名、`◈───────────◈`区切り、`❖`セクション見出し、設定説明、接続状態の詳細行で構成する。バニラ由来の属性などの追加ツールチップは非表示にし、独自の表示名とLoreは保持する。
- 閲覧者の利用可能枠が満員の場合はアイコンへ「満員のため接続できません」と表示し、クリックによる接続要求を送らない。API状態が未取得またはオフラインの場合も接続要求を送らない。
- GUIの判定後も、Proxyは同じ権限別上限と接続中予約を使って最終判定する。クールタイムはProxyだけが確定する。
- network有効時はRPGのローカル人数判定・予約・Bukkit最大人数の書換えを行わない。チャンネルAPIで入場許可を確認済みの場合だけnativeのKICK_FULLを解除し、その他の拒否には触れない。ローカルwhitelist操作も拒否してWeb管理設定を案内する。
- Proxyは所在heartbeat周期ごとに各backendを非同期pingし、成功時だけ`online`、失敗時は人数0の`offline`としてNetwork APIへ送る。

## 全体チャット

1. LobbyまたはRPGの通常の全体チャットはローカル配信を止め、発言者UUID、チャンネル、アカウント表示、レベル、クラス名、変換前本文、変換後本文をProxyへ送る。Proxyは変換済み本文を `原文[変換後]` として、原文は白、括弧は灰色、変換後は金色・斜体で表示する。アイテム共有チャットはホバー・クリック操作を維持するためRPG内配信とする。
2. Proxyは送信元接続と発言者UUIDの一致を確認して全Proxyプレイヤーへ一度だけ配信する。送信元backendがProxy設定の`discord.excludedSourceServers`に含まれない場合だけ、Minecraft発言をNetwork APIへ登録する。
3. LobbyはNetwork APIのMinecraft発言を読み、DiscordSRVの`global`対応チャンネルへ送る。通常発言はDiscordSRV管理Webhookを使い、アカウント表示と送信元backendを投稿者名、Minecraftスキンを投稿者アイコンとして表示する。Webhook管理権限またはプレイヤー識別情報がない場合は、送信元と発言者を太字見出しにしたBot投稿へ退避する。独自中継が有効な間は`triggeringBukkitEvent`の状態に依存せずDiscordSRV標準のMinecraft→Discord処理をキャンセルし、独自中継との二重送信を防ぐ。
4. DiscordSRVの`global`対応チャンネルに投稿されたbot以外の発言をLobbyで通常broadcastをキャンセルしてNetwork APIへ登録する。アカウント連携の要否、ロール・ID・本文フィルターはDiscordSRV設定を正本とする。
5. ProxyはNetwork APIのDiscord発言を読み、全Proxyプレイヤーへ一度だけ配信する。

APIチャットはメッセージUUIDで冪等化し、generationIdとsequence cursorで差分取得する。API再起動でgenerationIdが変わった場合はcursorを0へ戻して先頭から再取得する。

## Discordサーバー接続通知

1. Lobby上のDiscordSRV標準参加・初回参加・退出通知はランタイム設定で常時停止し、backend単位のJoin/QuitをDiscordへ送らない。
2. Proxyの初回`ServerPostConnectEvent`はネットワーク参加として「プレイヤー名がサーバーに参加した」通知を、プレイヤーUUID・Minecraft名と`action=join`とともにNetwork APIへ登録する。Proxyの`DisconnectEvent`だけをネットワーク退出として扱い、プレイヤー識別情報と`action=leave`を付けて登録する。
3. 前backendを持つ`ServerPostConnectEvent`はチャンネル切替として、Proxy `channelNames`の表示名を用いた「切替元から切替先へ接続した」通知を、プレイヤー識別情報と`action=channel_connect`とともに登録する。
4. 切替元または切替先、実切断元が`discord.excludedSourceServers`に含まれる場合は通知を登録しない。これにより除外backendとLobby間の往復も通知しない。
5. Lobbyは`kind=lifecycle`のMinecraftメッセージを通常チャットWebhookにせず、actionに応じて参加は緑、チャンネル接続は青、退出は赤のEmbedとしてDiscordへ送る。プレイヤー識別情報がある場合は、`DiscordSRV.getAvatarUrl`で解決したMinecraftスキンURLをEmbed author iconへ設定し、プレイヤー名をauthorへ表示する。actionまたは識別情報がない旧通知は従来どおり`AstralRecord システム`名義の青色Embedとし、BotにEmbed Links権限がない場合はシステム通知用プレーンテキストへ退避する。
6. LobbyのDiscord中継開始時はNetwork API応答の`latestSequence`をカーソルとして設定し、それ以前の短期中継履歴を送らない。`latestSequence`を返さない旧API応答では中継を停止してAPI更新を待つ。

## 最高権限とプライベートチャット監視

1. ProxyはManagementDBの設定を起動時と既定5秒周期に取得し、`authorityUsers`を最高権限として扱う。未初期化時だけ旧YAMLをbootstrapへ送り、定期的な全置換PUTはしない。Lobby admissionはBAN判定を維持したまま全体権限UUIDの実効permissionを99以上にする。Proxyは同一覧を`/server <gameServer>`の許可判定にも使用する。
2. RPGは接続前に`network.channelName`を用いたchannel-accessを必須照会する。全体権限は保存済み`user.permission`を書き換えずOP・管理機能・例外へ反映し、チャンネルdebug/whitelistは対応する例外だけへ反映する。オンライン中も非同期に更新し、チャンネルアクセスcacheは5秒で失効する。ローカルdebug/whitelistへfallbackしない。
3. DMは同一backendなら従来形式で送受信者へ配信する。別backendのオンライン受信者は送信元RPGからProxyへ配送要求を送り、Proxyが送受信者へ同じ形式で一度だけ配信する。どちらの場合も、送信者・受信者のUUID、表示名、変換前本文、変換後本文をProxyへ監視メッセージとして送る。パーティーチャットのローカル受信者は現在パーティーのonline memberだけとし、発言者・パーティー識別名・参加者UUID・変換前本文・変換後本文をProxyへ送る。
4. Proxyは監視メッセージを`serverAuthorityUsers`に一致するオンラインプレイヤーへだけ全backend横断で配信する。ただし送信者・DM受信者・パーティー参加者本人は通常配信との重複を避けるため監視対象から除外する。DMは「送信者 → 受信者」、パーティーチャットは「パーティー識別名」と発言者を表示する。DBのpermission `99`だけのプレイヤーは受信対象に含めない。

オンラインロール更新はメインスレッドで対象UUIDのスナップショットを作り、そのUUIDだけを非同期API通信へ渡す。Bukkit Playerの参照とOP反映はメインスレッドで行い、更新が実行中なら次の周期の重複起動を抑止する。

## 共通BAN

Webの確認ダイアログとRPG `/ban`は同じManagementDBのBAN revisionを読み、期待版が一致した場合だけ更新する。WebはWebAdmin、RPGは専用ModerationKeyと実行者権限を必須とする。network有効時のRPGは旧ゲームDBのBANを再判定しない。Proxy admissionは管理BAN行がある場合にそれを優先し、管理行がない旧ユーザーだけ旧BANを参照する。解除・期限切れの管理行を削除して旧BANへ戻してはならない。

Proxyは新規ログイン・転送前のadmissionと、周期的な有効BAN一覧で拒否・切断を行う。無期限は無期限と表示し、期限付きは残日数を切り上げ、UTC期限を日本時間へ変換して解除日時と理由を表示する。期限≦API現在UTCは解除済みとする。

## 全体Tabと所在

- Lobby表示は`[ロビー] MCID`とする。
- RPG表示は通常`[channel] [classShortName Lv.classLevel] [AFK] accountName#slotIndex`とし、最大クラスレベル到達時は `Lv.` を維持して数値部分を赤太字の`max`に置き換えた`Lv.max`を表示する。`AccountMode.ADMIN` の場合は`[channel] accountName#slotIndex`を表示し、クラス・レベル・AFKを省略する。通常表示はRPG側Tabと同じクラス・レベルの順序、shortNameに定義した色・装飾、AFK時だけ付く赤いAFK接頭辞を使用する。アカウント名は通常白色、`#slotIndex`は灰色とし、所有ユーザーのpermissionが寄付者の`5`と一致する場合はアカウント名だけ水色・太字とする。
- RPGはロード完了時と5秒周期でメタデータをProxyへ送る。
- RPGはshortNameのlegacy色・装飾コード、最大クラスレベル到達状態、ADMIN用のクラス・レベル・AFK省略状態、所有ユーザーのpermissionをTabメタデータへ保持し、ProxyはそれをAdventure Componentへ変換して表示する。permission、最大到達状態、またはADMIN用省略状態を未送信の旧メタデータは、それぞれプレイヤー権限の`0`、最大未到達、通常表示として扱う。アカウントモード変更時は周期送信を待たず最新メタデータを即時送信する。
- ProxyはTabメタデータを、送信元backendがプレイヤーの現在接続先backendと一致する場合だけ採用し、backend切替中の旧接続からの通知を破棄する。
- LobbyとRPGはオンラインプレイヤー1人を経由し、5秒周期で各サーバーの平均MSPTをProxyへ送る。
- Proxyは管理設定のtabRefreshSeconds（既定2秒）で各viewerのTabListを確認し、1回の更新で固定した同一オンラインプレイヤースナップショットから人数・viewer・entry対象を決定する。接続完了時は即時と1秒後、RPGメタデータ受信時は即時にも再同期し、backendの接続初期packetや切替と競合して欠落したentryを周期更新まで待たず復元する。全体同期と切断時entry削除は同じ排他境界で直列実行し、古いスナップショットから切断済みentryを再追加しない。
- ProxyはTabヘッダーへ`ASTRAL RECORD`と公開サーバーアドレス、フッターへ閲覧者の現在接続先backendのMSPT、ping、Proxy全体の参加人数を区切り線付きで表示する。公開サーバーアドレスはProxy `config.yml` の `tab.serverAddress` を正本とし、空文字なら省略する。MSPT未受信時と最終受信から15秒を超えた場合は計測中表示とする。
- network機能が有効なRPGでは、ヘッダー/フッターとプレイヤーリスト名の競合を避けるためRPG側の旧Tab更新を停止し、Proxy表示を正本とする。
- API所在heartbeatは管理設定presenceHeartbeatSeconds（既定10秒）、API側TTLは30秒とし、切断時は即時削除を試みる。設定変更でTab/heartbeat taskを再作成し、次の実行から反映する。
