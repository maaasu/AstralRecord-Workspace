# 33_4-統合フロー

## RPGからロビーへの保存付き転送

1. `/lobby`は二重実行をUUID単位で拒否し、プレイヤーを一時的に無敵化して移動・インベントリ・ドロップ・拾得・操作・持ち替えを凍結する。
2. `PlayerJoinEventHandler.prepareAccountSwitch`と同じセッション終了処理で、Bukkit状態のsnapshot取得、feature runtime解放、インベントリを含む全保存を開始する。
3. 保存が失敗または例外終了した場合は接続要求を送らず、破棄済みruntimeでプレイを継続させないため切断する。次回接続はProxyによりLobbyとなる。
4. 保存成功時だけ`astralrecord:network`の`connect`メッセージをProxyへ送る。
5. Proxyは許可接続先、接続中予約を含む定員、RPG接続クールタイムを検証してVelocity接続要求を実行する。クールタイムはRPG接続時に加えてRPG離脱・Proxy切断時にも開始する。
6. 接続要求後5秒を超えて元RPGに残った場合は、キャッシュ破棄済み状態での操作を防ぐため切断する。

## サーバー選択

- Lobbyの`/server`または設定NPCへの視線クリックでGUIを開く。
- GUIのslot、material、表示名、lore、Proxy接続先名はLobby `config.yml`を正本とする。
- GUIクリックはProxyへ接続要求を渡すだけとし、Lobbyは接続先の存在、定員、クールタイムを確定しない。

## 全体チャット

1. LobbyまたはRPGの通常の全体チャットはローカル配信を止め、発言者UUID、チャンネル、アカウント表示、レベル、クラス名、本文をProxyへ送る。アイテム共有チャットはホバー・クリック操作を維持するためRPG内配信とする。
2. Proxyは送信元接続と発言者UUIDの一致を確認して全Proxyプレイヤーへ一度だけ配信し、Minecraft発言をNetwork APIへ登録する。
3. LobbyはNetwork APIのMinecraft発言を読み、DiscordSRVの`global`対応チャンネルへ送る。
4. DiscordSRVの`global`対応チャンネルに投稿された、Minecraftアカウント連携済みユーザーの発言だけをLobbyで通常broadcastをキャンセルしてNetwork APIへ登録する。
5. ProxyはNetwork APIのDiscord発言を読み、全Proxyプレイヤーへ一度だけ配信する。

APIチャットはメッセージUUIDで冪等化し、generationIdとsequence cursorで差分取得する。API再起動でgenerationIdが変わった場合はcursorを0へ戻して先頭から再取得する。

## 全体Tabと所在

- Lobby表示は`[ロビー] MCID`とする。
- RPG表示は`[channel] [Lv.classLevel classShortName] [AFK] accountName#slotIndex`とし、AFK部分はAFK時だけ付ける。
- RPGはロード完了時と5秒周期でメタデータをProxyへ送る。
- Proxyは2秒周期で各viewerのTabListを確認し、表示内容が変化したentryだけを反映する。
- API所在heartbeatは10秒周期、API側TTLは30秒とし、切断時は即時削除を試みる。
