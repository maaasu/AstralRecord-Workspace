# 33_0-概要

## 目的

同一PC上の複数PaperサーバーをVelocityで束ね、プレイヤーがロビーGUIからRPGチャンネルを手動選択できる構成を提供する。初回接続、再接続はいずれもロビーを入口とし、RPG間の自動振り分けは行わない。

## コンポーネント責務

| コンポーネント | 責務 |
|:--|:--|
| `AstralRecordProxy` | 初期接続先のロビー固定、接続先検証、RPG接続30秒クールタイム、定員判定、全体チャット配信、全体Tab、API heartbeat |
| `AstralRecordLobby` | API admission、permission=99のOP同期、一般プレイヤー保護、NPCレイキャスト、サーバー選択GUI、DiscordSRVとAPIチャットの中継 |
| `AstralRecord.feature.network` | `/lobby`実行時の全保存、Proxyへの接続要求、RPGチャットとTabメタデータの送信 |
| Network API | BAN・permissionのadmission、TTL付きオンライン所在、サーバー状態、Discord/Minecraftチャットの短期中継 |

## 不変条件

- Proxyへの新規接続先は常に`lobbyServer`であり、最終接続チャンネルへ直接復帰しない。
- Lobby接続前のfallback接続は拒否する。Lobbyからkickされた場合は理由を保持してProxyから切断し、RPGからkickされた場合だけLobbyへ戻す。
- RPGサーバーからロビーへ戻る操作は`/lobby`だけを使用し、保存成功前に接続要求を送らない。
- RPGサーバー上の`/server`は接続を行わず、`/lobby`の使用を案内する。
- RPGチャンネルへの接続は前回のRPG接続から30秒経過後だけ許可する。ロビーへの帰還にはクールタイムを適用しない。
- 接続先はProxy設定の`gameServers`または`lobbyServer`に存在する名前だけを許可し、設定定員以上のRPG接続を拒否する。
- Lobby管理者はAPIのpermissionが正確に`99`のUUIDだけとする。Bukkit OPだけでは保護を迂回できない。
- Lobby一般プレイヤーはAdventure固定、ブロック・エンティティ操作リーチ0、PvPと破壊的操作禁止とする。管理者は対象外とする。
- サーバー選択NPCは通常リーチとは別に視線レイキャストで最大6mまで検出し、ブロック越しには検出しない。
- DiscordSRVはLobbyだけへ配置し、RPG側の`discord.enabled`はfalseとする。

## 設定正本

- Proxy: `plugins/astralrecordproxy/config.yml`
- Lobby: `plugins/AstralRecordLobby/config.yml`
- RPG: `plugins/AstralRecord/config.yml`の`network.channelName`を`ch1`、`ch2`、`dev`ごとに変更する。
- Velocity本体には`lobby`、`ch1`、`ch2`、`dev`の各backendを登録し、backendへの直接公開を行わない。

詳細な転送・チャット・Tabフローは[[33_4-統合フロー]]、配置条件は[[33_5-例外・ログ・運用]]を参照する。
