# 22_3.00-メソッド仕様

## 1. トレードコマンド

クラス名: `TradeCommand`
物理名: `onCommand`

責務:

`/trade` 系コマンドを解析し、申請送信または承諾へ委譲する。

処理内容:

1. `/trade <playerName>` をトレード申請として受け付ける。
2. `/trade accept` を最新の有効な受信申請の承諾として受け付ける。
3. 実行者が Player でない場合はエラーメッセージを送信して終了する。
4. 対象プレイヤー指定、自己申請、オンライン状態を検証する。
5. 申請時は [[22_3.00-メソッド仕様]].トレード申請送信 を呼び出す。
6. 承諾時は [[22_3.00-メソッド仕様]].トレード申請承諾 を呼び出す。

メッセージ:

| ID | レベル | テンプレート | 出力条件 | 引数 |
|---|---|---|---|---|
| `PlayerMsgId.P_6203` | - | `対象プレイヤーは現在トレードできません。` | TradeService 未初期化、対象プレイヤー未解決、自己申請、対象がオフライン、または対象が取引不可の場合 | なし |

## 2. トレード申請送信

クラス名: `TradeService`
物理名: `requestTrade`

責務:

申請者から相手プレイヤーへトレード申請を作成し、クリック可能メッセージを送信する。

処理内容:

1. 申請者と相手プレイヤーの AstPlayer を取得する。
2. 申請者と相手が同一プレイヤーの場合はエラーメッセージを送信して終了する。
3. 相手プレイヤーがオンラインでない場合はエラーメッセージを送信して終了する。
4. どちらかが既に取引中の場合はエラーメッセージを送信して終了する。
5. 同一相手への有効な申請が存在する場合は既存申請を更新せず、申請済みメッセージを送信して終了する。
6. [[22_1.00-モデル定義]].トレード申請 を `PENDING` で作成する。
7. 相手プレイヤーへ、申請が届いている旨と `/trade accept` で開始できる旨のメッセージを送信する。
8. メッセージにはクリック実行コマンド `/trade accept` を設定する。
9. 申請者へ申請送信済みメッセージを送信する。

メッセージ:

| ID | レベル | テンプレート | 出力条件 | 引数 |
|---|---|---|---|---|
| `PlayerMsgId.P_6203` | - | `対象プレイヤーは現在トレードできません。` | AstPlayer 未取得、自己申請、相手がオフライン、いずれかが取引中、または同一相手への有効申請が既にある場合 | なし |
| `PlayerMsgId.P_6200` | - | `{0} にトレード申請を送信しました。` | 申請作成に成功した場合 | `targetName` |
| `PlayerMsgId.P_6201` | - | `{0} からトレード申請が届いています。/trade accept で開始できます。` | 相手プレイヤーへ申請通知を送信する場合 | `senderName` |

## 3. トレード申請承諾

クラス名: `TradeService`
物理名: `acceptTrade`

責務:

有効な受信申請を承諾し、2 人のトレードセッションと取引 GUI を開始する。

処理内容:

1. 承諾者宛ての最新の `PENDING` 申請を取得する。
2. 有効な申請が存在しない、または期限切れの場合はエラーメッセージを送信して終了する。
3. 申請者と承諾者がどちらもオンラインであることを検証する。
4. どちらかが既に取引中の場合はエラーメッセージを送信して終了する。
5. 申請状態を `ACCEPTED` に更新する。
6. [[22_1.00-モデル定義]].トレードセッション を `OPEN` で作成する。
7. [[22_3.00-メソッド仕様]].トレード GUI 表示 を双方に対して呼び出す。

メッセージ:

| ID | レベル | テンプレート | 出力条件 | 引数 |
|---|---|---|---|---|
| `PlayerMsgId.P_6202` | - | `トレード申請が見つかりません。` | 有効な受信申請が存在しない、または期限切れの場合 | なし |
| `PlayerMsgId.P_6203` | - | `対象プレイヤーは現在トレードできません。` | 申請者または承諾者がオンラインでない、またはいずれかが取引中の場合 | なし |

## 4. トレード GUI 表示

クラス名: `TradeGui`
物理名: `open`

責務:

閲覧者から見た取引 GUI を生成し、現在のセッション状態を表示する。

処理内容:

1. GUI タイトルを `{相手プレイヤー名}とのトレード` とする。
2. [[22_1.00-モデル定義]].トレード GUI レイアウト に従って 54 スロット GUI を生成する。
3. 自分側アイテム設置スロットへ閲覧者の提示アイテムを配置する。
4. 相手側アイテム表示スロットへ相手の提示アイテムを表示専用として配置する。
5. 左から 5 列目の slot `4, 13, 31, 40` にしきりのダミーアイテムを配置する。
6. slot `22` に閲覧者と相手の提示 Gold 金額を表示し、クリックで共通 Gold 金額設定 GUI を開くボタンを配置する。
7. slot `49` に閲覧者の準備状態と相手の準備状態に応じた取引準備完了ボタンを配置する。
8. 閲覧者が準備中の場合、再クリックで準備キャンセルできる表示にする。
9. 相手が準備中で閲覧者が未準備の場合、クリックで即時取引開始になる表示にする。

## 5. トレード GUI クリック処理

イベント物理名: `InventoryClickEvent`
クラス名: `TradeGuiEventHandler`
物理名: `onInventoryClick`

責務:

取引 GUI 内のクリックを制御し、提示アイテム変更、準備状態変更、取引成立へ振り分ける。

処理内容:

1. クリック者が Player でなければ終了する。
2. 対象 inventory がトレード GUI でなければ終了する。
3. トレード GUI 上のクリックとドラッグは最初にすべてキャンセルし、Bukkit 標準のアイテム移動を発生させない。
4. slot `22` の場合は共通 Gold 金額設定 GUI を開く。GUI の ItemStack は表示専用 projection とし、セッション正本へ取り込まない。
5. slot `49` の場合は [[22_3.00-メソッド仕様]].取引準備切替 を呼び出す。
6. プレイヤーインベントリ側のアイテム提示は InventoryService の正本 entry を再解決し、取引可否判定後に `takeOwnedItemAmount` で取り出して escrow へ追加する。
7. モデル未解決または取引不可の場合は fail-closed とし、取引不可メッセージを送信する。
8. 自分側提示スロットのクリックは escrow から取り出し、InventoryService の通常インベントリへ返却できた場合だけセッションから減算する。
9. 提示・引き戻しの途中失敗時は inventory snapshot とセッション提示一覧を操作前へ戻す。
10. 提示内容が変わった場合、双方の準備状態を未準備へ戻す。
11. 双方の GUI を再描画する。
12. 例外時は runSafely で以下ログを記録する。

    | 項目 | 内容 |
    |---|---|
    | ID | LogId.E_6200 |
    | レベル | ERROR |
    | テンプレート | トレードGUIクリック処理に失敗しました: %s |
    | 出力条件 | runSafely で例外発生時 |
    | 引数 | プレイヤー名 |

メッセージ:

| ID | レベル | テンプレート | 出力条件 | 引数 |
|---|---|---|---|---|
| `PlayerMsgId.P_6204` | - | `このアイテムはトレードできません。` | 自分側提示スロットへ取引不可アイテムを移動しようとした場合 | なし |

## 6. 取引準備切替

クラス名: `TradeService`
物理名: `toggleReady`

責務:

取引準備完了ボタンの押下に応じて準備状態を切り替え、必要に応じて取引を成立させる。

処理内容:

1. セッションが `OPEN` であることを検証する。
2. 押下者が準備中の場合、押下者の準備状態を未準備へ戻し、双方の GUI を再描画して終了する。
3. 相手が未準備の場合、押下者の準備状態を準備中へ更新し、双方の GUI を再描画して終了する。
4. 相手が準備中の場合、押下者の準備状態を準備中へ更新する。
5. [[22_3.00-メソッド仕様]].取引成立実行 を呼び出す。

メッセージ:

| ID | レベル | テンプレート | 出力条件 | 引数 |
|---|---|---|---|---|
| `PlayerMsgId.P_6205` | - | `相手の準備完了を待っています。もう一度押すと準備をキャンセルします。` | 押下者のみ準備中へ更新した場合 | なし |
| `PlayerMsgId.P_6206` | - | `トレード準備をキャンセルしました。` | 準備中の押下者が再クリックして準備を解除した場合 | なし |

## 7. 取引成立実行

クラス名: `TradeService`
物理名: `completeTrade`

責務:

双方の提示アイテムを検証し、互いのインベントリへ交換付与する。

処理内容:

1. セッションが `OPEN` であり、双方が準備中であることを検証する。
2. 双方の提示アイテムと提示 Gold 金額を再取得し、取引不可アイテムが含まれないことを item feature で再検証する。
3. 双方の提示アイテムと提示 Gold がいずれも空の場合、取引成立メッセージを送信せず [[22_3.00-メソッド仕様]].取引中止実行 と同様に取引を中止する。
4. 双方の受け取り先インベントリに必要な空き容量があることを inventory feature で検証する。
5. 双方の所持 Gold が提示 Gold 以上であることを currency / inventory feature で検証する。
6. 検証に失敗した場合、取引を成立させず、双方の準備状態を未準備へ戻す。
7. 検証成功時、双方の InventoryService state の補償用スナップショットを取得し、セッション状態を `COMMITTING` へ更新する。
8. プレイヤー A の提示アイテムと提示 Gold をプレイヤー B へ、プレイヤー B の提示アイテムと提示 Gold をプレイヤー A へ付与する。
9. 途中の付与、Gold 減算・加算、または例外で失敗した場合は双方をスナップショットへ復元してから `OPEN` へ戻し、提示内容を再表示する。補償未完了の状態で提示アイテムを再付与しない。
10. 全交換成功後にセッション状態を `COMPLETED` へ更新する。
11. 双方の取引 GUI を閉じる。
12. 双方へ取引成立メッセージを送信する。

メッセージ・ログ:

| 種別 | ID | レベル | テンプレート | 出力条件 | 引数 |
|---|---|---|---|---|---|
| プレイヤー通知 | `PlayerMsgId.P_6209` | - | `相手のインベントリに空きがないため、トレードを開始できません。` | 双方の受け取り先インベントリの空き検証に失敗した場合 | なし |
| プレイヤー通知 | `PlayerMsgId.P_6207` | - | `トレードが成立しました。` | 取引成立完了時 | なし |
| ログ | `LogId.E_6201` | ERROR | `トレード成立処理に失敗しました: %s` | 空き検証、付与、GUI close など成立処理で例外が発生した場合 | `sessionId` または失敗箇所 |

## 8. 取引中止確認表示

クラス名: `TradeCancelConfirmGui`
物理名: `open`

責務:

取引 GUI を閉じた時に、取引中止確認 GUI を表示する。

処理内容:

1. 対象プレイヤーの `OPEN` セッションを取得する。
2. セッションが存在しない場合は終了する。
3. 取引中止実行ボタンと取引 GUI へ戻るボタンを持つ確認 GUI を生成する。
4. 確認 GUI 上のアイテム移動はすべて禁止する。
5. 中止実行ボタン押下時は [[22_3.00-メソッド仕様]].取引中止実行 を呼び出す。
6. 戻るボタン押下時は [[22_3.00-メソッド仕様]].トレード GUI 表示 を呼び出す。

## 9. 取引中止実行

クラス名: `TradeService`
物理名: `cancelTrade`

責務:

取引を中止し、提示アイテムを元の所有者へ返却する。

処理内容:

1. セッションが `OPEN` でなければ終了する。
2. 双方の InventoryService state の補償用スナップショットを取得し、セッションを `COMMITTING` へ更新する。
3. プレイヤー A、B の escrow アイテムをそれぞれ元の InventoryService 正本へ返却する。
4. 片方でも返却できない場合は双方の snapshot を復元してセッションを `OPEN` へ戻し、提示内容を維持する。
5. 全返却成功後だけセッション状態を `CANCELLED` へ更新する。
6. 双方の取引 GUI または取引中止確認 GUI を閉じる。
7. 双方へ取引中止メッセージを送信する。

メッセージ・ログ:

| 種別 | ID | レベル | テンプレート | 出力条件 | 引数 |
|---|---|---|---|---|---|
| プレイヤー通知 | `PlayerMsgId.P_6208` | - | `トレードを中止しました。` | 取引中止完了時 | なし |
| ログ | `LogId.W_6202` | WARN | `トレードアイテム返却に失敗しました: %s` | 中止時または例外補償時に提示アイテムを所有者へ返却できない場合 | `playerName` |

## 10. トレード GUI クローズ処理

イベント物理名: `InventoryCloseEvent`
クラス名: `TradeGuiEventHandler`
物理名: `onInventoryClose`

責務:

取引 GUI の予期しないクローズを検知し、必要に応じて取引中止へ委譲する。

処理内容:

1. 閉じた inventory がトレード GUI、取引中止確認 GUI、または Gold 金額設定 GUI でなければ終了する。
2. システム操作による再描画・成立・中止処理中のクローズであれば終了する。
3. トレード GUI の通常クローズの場合は、表示 ItemStack を読み取らず [[22_3.00-メソッド仕様]].取引中止確認表示 へ委譲する。
4. Gold 金額設定 GUI の通常クローズの場合は、取引 GUI を再表示する。
5. 取引中止確認 GUI の通常クローズの場合は [[22_3.00-メソッド仕様]].取引中止実行 を呼び出す。
