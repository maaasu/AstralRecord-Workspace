# 22_3-メソッド仕様

## 招待・承認

クラス名: `TradeService`
物理名: `requestTrade` / `acceptTrade`

- 引数: sender／target Bukkit `Player`、承認は accepter
- 戻り値: なし
- 例外: 業務不成立を player message へ変換する。

request は 60 秒期限で作成する。request／accept は両者が拠点ワールドまたはスキルツリー専用ワールドにいることを検証し、accept は期限と両者の identity／mode／world／session を再検証して `TradeSession` を開始する。

## Ready・確定

クラス名: `TradeService`
物理名: `toggleReady`

- 引数: `Player player`
- 戻り値: なし
- 例外: commit failure を rollback と `E_6201` へ変換する。

本人の ready を反転し、双方 ready なら内部 `completeTrade` を実行する。提示 item／gold の変更後も ready は維持し、本人が ready 操作を再度行ったときだけ準備を解除する。commit 前に提示 item、gold、account identity、両者の許可対象ワールドを再検証する。受取 BAG の通常容量は判定せず、API 再同期で `slot_index` 未指定の受取 entry を容量外 slot まで割り当てる。A/B の save lane は各 account の baseline 取得、API transaction、再同期・保存を future で連結し、lane worker が相手 lane の完了を同期待機しない。`COMPLETED` と session close は Trade API 成功後にだけ実行する。API 成功後は affected entry ID を A/B の local state へ再同期してから Bukkit inventory を更新する。API が明示する 4xx 業務拒否だけ `OPEN` と ready 解除へ戻し予約表示を維持する。送信後の通信喪失・応答解析失敗・5xx、および成功後の再同期・保存失敗は `COMMITTING` と未解決保存境界を維持し、同じ session ID の API replay で確定応答または再同期完了を得るまで cancel しない。

## Item 提示・取り下げ

クラス名: `TradeService`
物理名: `offerOwnedItem` / `withdrawOfferedItem`

- 引数: player、session ID、slot／item 情報
- 戻り値: mutation 完了時 `true`
- 例外: runtime failure は `E_6201` に記録して `false`。

NORMAL inventory state は提示時に変更せず、source `inventory_entry_id` と数量を session に記録して GUI 上だけを予約非表示にする。withdraw／cancel は同じ数量の予約を解除する。item／gold の提示変更後も ready 状態は変更しない。`isTradeable` は ItemModel の `unTradeable` を解決する。

## Gold 設定

クラス名: `TradeService`
物理名: `openGoldAmountSetting` / `applyGoldAmount`

- 引数: player、apply は session ID と amount
- 戻り値: なし
- 例外: invalid session／mode を message 化する。

open 時の上限は `max(ownedGold, currentOffer)`、apply 時は最新 ownedGold 以内へ clamp する。

`GoldAmountSettingGui` は調整単位 `step` を 1 から 10^18 の10進桁で保持する。桁切替は通常クリックで1桁、Shiftクリックで3桁移動する。増減は通常1倍、右クリック5倍、Shiftクリック10倍とし、半分・2倍・0・最大の補助操作も提供する。すべての加算・乗算は `long` 範囲で飽和させた後、0 から上限へ clamp する。

## Cancel・終了

クラス名: `TradeService`
物理名: `cancelTrade` / `cancelAll`

- 引数: player または session、全件はなし
- 戻り値: なし
- 例外: restore failure を `E_6201` へ記録する。

DB commit 前の cancel は、両 owner の予約表示を解除して session を削除する。API が明示する 4xx 業務拒否では session を削除せず `OPEN` に戻す。送信後の通信喪失・応答解析失敗・5xx、または API 成功後の再同期中は `COMMITTING` のため cancel できない。commit 後の所有権・inventory membership は API 正本なので、Plugin 側の rollback は行わない。

## `/trade` command

クラス名: `TradeCommand`
物理名: `executePlayerCommand`

- 構文: `/trade <playerName|accept>`
- 実行者: player
- 戻り値: なし
- 例外: usage／target 未存在を player message へ変換する。

## GUI event

クラス名: `TradeGuiEventHandler`
物理名: `onInventoryClick` / `onInventoryDrag` / `onInventoryClose` / `onPlayerQuit`

holder の session ID と viewer UUID を検証し、standard movement を cancel する。click／drag 例外は `E_6200`、commit／cancel failure は service の `E_6201`。許可対象外ワールドへの移動時は open session を中止する。

提示内容の更新時は、同一 session を表示中の Trade GUI だけをその場で再描画する。相手が Gold 金額設定 GUI または中止確認 GUI を操作中の場合、その画面を強制的に閉じない。
