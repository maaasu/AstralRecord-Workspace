# 22_3-メソッド仕様

## 送信画面の開始・終了

TradeService.openSend(sender, target, returnAction) は Bukkit main thread で両者の online・PLAYER mode・許可 world・account を検証する。自己送信と送信者の既存 OPEN/COMMITTING を拒否する。受信者を activeSessionByPlayer へ登録せず、送信者の GUI だけ開く。遅延 GUI 遷移の取消では同じ遷移だけを中止し、予約を解除する。初回表示後に close 抑止は残さない。

leave(player, back) は OPEN の予約を解除し、back かつ returnAction がある場合だけ起点へ戻る。cancelTrade(player) は自分の送信、cancelRelatedSessions(player) は quit・account 切替・world 離脱時の関連送信、cancelAll() は全 OPEN を中止する。受信者の別 GUI を閉じない。確定中の取消は行わない。

送信画面が開く前に相手が離脱した場合も、当該sessionの保留遷移を GuiOpenSupport.cancelPending で取り消す。スケジュール済みタスクと取消コールバックを一度だけ終了し、取消後に孤立した送信画面を開かない。遷移がない場合や他プレイヤーの保留遷移には介入しない。

## アイテム予約

offerOwnedItem(player, sourceBukkitSlot, clickType, displayedItem) は authoritative owned entry と ItemModel を照合し、送信可能品の clone と source entry ID を session へ追加する。NORMAL inventory の正本は移動せず、hideOwnedEntryQuantityFromGui で同数量を予約する。表示 item の直接移動・ドラッグは常にキャンセルする。45表示枠が埋まる場合は新規予約しない。

withdrawOfferedItem(player, offerIndex, clickType) は指定数量の予約を解除する。失敗時に元の clone と source entry ID を維持し、描画失敗だけで確定済み予約を巻き戻さない。数量は ItemTransferSupport に従い、同じ source entry の複数表示は commit 時に合算する。

## Gold 設定

openGoldAmountSetting は max(ownedGold, currentAmount) を入力上限に使用する。applyGoldAmount は session ID を照合し、最新の所持金以内へ金額を clamp して送信画面へ戻る。GoldAmountSettingGui は桁変更・加減・半分・2倍・0・最大を提供し、long 範囲で飽和したあと0〜上限へ clamp する。受信者の画面は変更しない。

## 送信確定

send(player) は送信者の OPEN だけを completeTrade へ渡す。受信者の承認は不要。両者の開始時 account identity、PLAYER mode、許可 world、送信可能品と有効 source entry ID、最新の Gold 残高を再検証する。品もGoldも空なら OPEN を保ちエラー表示する。B 側に品またはGoldがある要求は拒否する。

COMMITTING へ遷移してから両 account の prepareExternalOperationAfterSave を非同期に連結し、A の品/Gold、B の空明細/0、session ID を operation ID として TradeRepository.commit へ渡す。通常 BAG の空き容量は確定条件にしない。同じ account を使う別確定と重なる場合は保存境界で拒否され、未確定なら再操作できる。

## 再同期・回復

commitTradeWithInventoryLocks は両 account の保存済み baseline を準備し、lane worker が相手の future を同期待機しない。API 応答の affected entry を reconcileTradeInventoryEntries で各 account に再同期・保存してから main thread で完了する。maxStack 超過の分割、slotless 品の容量外 slot 配置、装備/ルーン owner の強制再読込を維持する。

API が明示する 4xx 業務拒否・確定前の準備失敗は、両者の identity と送信者の GUI が有効なら OPEN へ戻す。離脱済みなら予約を解除する。通信喪失・5xx・応答解析失敗・確定後再同期失敗は COMMITTING と未解決保存境界を維持し、同じ operation ID と要求内容を replay して未完了 account だけを再同期する。確定結果が不明なまま予約を返却しない。

## 受信通知

確定・再同期の完了後、同じ account を利用中の送信者へ P_6207（実消費Gold、受信者名）、受信者へ P_6201（送信者名、受取Gold）と品ごとの P_6211（表示名、数量）を PlayerMessageService 経由で送る。表示名が解決不能なら内部IDを出さず P_6212 の汎用名を使う。送信者の同じsession画面だけ閉じ、受信者の GUI は維持する。

## `/send` command

SendCommand は `/send <playerName>` を player から受け、オンラインプレイヤーを最後の引数で指定する。SendTabCompleter は自分以外のオンライン名を補完する。returnAction は null。`/trade` と accept 操作は登録しない。

## GUI event

TradeGuiEventHandler は holder の session ID・viewer UUID を検証する。click と drag は Bukkit の標準移動をキャンセルし、内容移動は予約サービスへ委譲する。共有 HotbarShortcutClickSupport.handleControls がスクロール・hotbar 操作を担当する。手動 close は予約を解除し、内部金額遷移だけ close を抑止する。受信者側に操作 GUI はない。
