# 22_0-概要

## 目的

両 player が提示内容を確認して ready にした場合だけ、item と gold の所有を交換する。offer 中の item は通常 inventory state を変更せず GUI から予約非表示にし、起点 entry ID と数量を session に保持して二重利用を防ぐ。

## 責務

- sender／target の招待を 60 秒保持し、`/trade accept` で session を開始する。
- player と account の対応を session 開始時に固定する。
- tradeable item の起点 entry と数量を GUI から予約非表示にし、withdraw／cancel 時は表示を戻す。
- gold offer を残高以内へ clamp する。item／gold の提示変更後も、各 player が明示的に切り替えた ready 状態は維持する。
- 双方 ready 時に tradeability、gold、identity を再検証し、API の単一 transaction で commit する。通常 BAG の空き容量はトレード成立条件にしない。
- API 成功時に affected entry ID を両 account の local state へ再同期し、受取 BAG entry に `slot_index` がなければ Plugin 側の BAG 配置規則で slot を割り当てて保存・Bukkit 表示へ反映する。受取通常 item の既存同種 stack が `maxStack` を超える場合は超過分を別 entry へ分割し、通常容量に空きがなければ容量外 slot として保持・表示する。通常の取得ではその slot を再利用しない。
- cancel／quit／GUI close confirm では予約表示だけを各所有者へ戻す。

## 責務外

- offline trade、server 間 trade、market listing。
- trade history の永続化、手数料、価格査定。
- 許可対象外ワールドへ移動後の session 継続。

## 現在の契約

- request TTL は 60 秒。
- session は `OPEN -> COMMITTING -> COMPLETED|CANCELLED`。API が明示する 4xx 業務拒否だけ `OPEN` へ戻し予約を保持する。送信後の通信喪失・応答解析失敗・5xx、および API 成功後の再同期・保存失敗は確定不明として `COMMITTING` を維持し、同じ session ID の replay で回復するまで cancel／再提示しない。
- `ItemModel.getUnTradeable()` が true の item は提示不可。
- request／accept と GUI 操作は `WorldType.BASE` またはスキルツリー専用ワールドでのみ許可する。参加中に許可対象外ワールドへ移動した場合は session を中止する。
- offer item list は clone と source inventory entry ID を保持し、外部 mutation を共有しない。
- plugin disable 時は `cancelAll()` で全 open session の予約表示を解除する。

## 依存・連携

| feature | 依存内容 |
|:--|:--|
| player | `AccountMode.PLAYER`、online identity、通知 |
| item | `unTradeable` 判定と item identity |
| inventory / currency | offer reservation、Gold 残高、API 正本からの再同期／保存 |
| trade API | item membership、装備／ルーン owner、Gold を原子的に確定 |
| menu / shared GUI | 取引 GUI、cancel confirm、gold amount setting |

## 変更影響

- request TTL／status を変更した場合は [[22_1-モデル定義]]、[[22_2-ユースケース]]を更新する。
- escrow、commit、rollback を変更した場合は [[22_3-メソッド仕様]]、[[22_4-統合フロー]]、[[22_5-例外・ログ・運用]]を更新する。
- GUI layout／close 遷移を変更した場合は [[22_1-モデル定義]] と [[22_4-統合フロー]]を更新する。
- durable recovery を実装した場合は [[22_9-未決事項]]を解消する。
