# 22_0-概要

## 目的

同一サーバーのオンラインプレイヤーへ、アイテムとゴールドを一方向に送信する。相互トレード、申請、相手の承認、ready 操作は提供しない。既存の原子的な移管 API を使うため、内部の feature/trade と TradeService・TradeSession・TradeRepository 名を維持する。

## 責務

- プレイヤー情報画面の「アイテム・送金」、または `/send <playerName>` から送信者だけに GUI を開く。
- 両 player と account の対応を開始時に固定する。受信者は送信者の session の操作対象にならず、自分の送信画面も開ける。
- item は通常 inventory state を変更せず GUI から予約非表示にし、起点 entry ID と数量を保持する。取り下げ・中止時は予約を解除する。
- 送信ボタンで identity、world、tradeability、Gold 残高を再検証し、A=送信者の item/Gold、B=受信者の空明細/0 Gold として API の単一 transaction へ渡す。
- 通常 BAG の空き容量は成立条件にしない。API 成功後に affected entry を両 account の local state へ再同期し、slot_index 未指定品へ BAG slot を割り当てる。通常 item の maxStack 超過は分割し、通常容量に空きがなければ容量外 slot へ保持・表示する。通常取得で容量外 slot は再利用しない。
- 受信者へ送信者名・アイテム表示名と数量・受取 Gold を通知する。金額のみ、アイテムのみ、両方の送信を許可する。

## 現在の契約

- 両者の AccountMode は PLAYER、world は WorldType.BASE またはスキルツリー専用ワールドであること。自己送信、オフライン、異なるサーバーへの送信は不可。
- 送信者の session は一つ。受信者の GUI は開かず、閉じず、送信完了で強制遷移させない。
- OPEN -> COMMITTING -> COMPLETED。確定前の中止は CANCELLED。確定前の準備失敗・API の明示的な業務拒否は同じ identity と送信画面があれば OPEN へ戻す。
- 送信後の通信喪失・5xx・応答解析失敗・再同期失敗は COMMITTING を維持し、同じ operation ID で回復するまで再送信・中止しない。
- `ItemModel.getUnTradeable()` が true の品は送信不可。ドラッグと Bukkit の直接移動を禁止する。
- quit・account 切替・許可対象外 world への移動で当人に関係する未確定 session を中止する。plugin disable は `cancelAll()` を使う。

## 依存・連携

player は identity と通知、item は表示名・移管可否、inventory/currency は予約と保存・再同期、trade API は原子的な所有移転、menu/shared GUI は情報画面・hotbar・金額入力を担う。API と DB の契約変更はない。
