# 22_4.00-統合フロー

## 1. 申請から GUI 開始まで

1. 申請者が `/trade <playerName>` を実行する。
2. [[22_3.00-メソッド仕様]].トレード申請送信 が [[22_1.00-モデル定義]].トレード申請 を作成する。
3. 相手プレイヤーへクリック可能な申請メッセージを送信する。
4. 相手プレイヤーが `/trade accept` またはメッセージクリックで承諾する。
5. [[22_3.00-メソッド仕様]].トレード申請承諾 が [[22_1.00-モデル定義]].トレードセッション を作成する。
6. 双方へ [[22_3.00-メソッド仕様]].トレード GUI 表示 を実行する。

## 2. アイテム提示同期

1. プレイヤーが自分側アイテム設置スロットへアイテムを置く。
2. [[22_3.00-メソッド仕様]].トレード GUI クリック処理 が全操作を cancel し、InventoryService 正本 entry に対して item feature の取引可否判定を呼び出す。
3. 取引可能な場合、`takeOwnedItemAmount` で正本から取り出した ItemStack だけを escrow とセッション提示一覧へ追加する。
4. 提示内容変更により双方の準備状態を未準備へ戻す。
5. 双方の GUI を再描画し、相手側には表示専用スロットとして反映する。

## 3. 取引成立

1. プレイヤー A が取引準備完了ボタンを押す。
2. プレイヤー B が未準備の場合、プレイヤー A を準備中にして再描画する。
3. プレイヤー B が取引準備完了ボタンを押す。
4. プレイヤー A が準備中のため、[[22_3.00-メソッド仕様]].取引成立実行 を即時実行する。
5. item feature と inventory feature の検証に成功した場合、補償用スナップショットを取得してセッションを `COMMITTING` にする。
6. 双方の提示アイテムと Gold を交換し、途中失敗時は双方の state を復元して `OPEN` へ戻す。
7. 全交換成功時だけセッションを `COMPLETED` にし、GUI を閉じ、成立メッセージを送信する。

## 4. 準備キャンセル

1. 準備中のプレイヤーが取引準備完了ボタンを再度押す。
2. [[22_3.00-メソッド仕様]].取引準備切替 がそのプレイヤーの準備状態を未準備へ戻す。
3. 双方の GUI を再描画する。

## 5. 取引中止

1. プレイヤーが取引 GUI を閉じる。
2. [[22_3.00-メソッド仕様]].取引中止確認表示 が確認 GUI を表示する。
3. 中止実行ボタンを押すと [[22_3.00-メソッド仕様]].取引中止実行 がセッションを `CANCELLED` にする。
4. 提示アイテムを元の所有者へ返却する。
5. 双方の GUI を閉じ、中止メッセージを送信する。

## 6. 例外的な中止

1. 片方のプレイヤーがログアウト、または予期しない GUI クローズを発生させる。
2. [[22_3.00-メソッド仕様]].取引中止実行 が取引を中止する。
3. オンラインの相手プレイヤーへ中止メッセージを送信する。
4. 返却に失敗したアイテムは inventory feature の返却失敗時ルールに従う。
