# 22_4-統合フロー

## 1. 招待から session 開始

### シーケンス

```mermaid
sequenceDiagram
    actor Sender as 申請者
    actor Target as 対象者
    participant Command as TradeCommand
    participant Trade as TradeService
    Sender->>Command: /trade target
    Command->>Trade: requestTrade(sender, target)
    Trade-->>Target: clickable accept通知
    Target->>Command: /trade accept
    Command->>Trade: acceptTrade(target)
    Trade->>Trade: TTL・online・mode・session再検証
    Trade-->>Sender: TradeGui
    Trade-->>Target: TradeGui
```

### 処理要点

- request status は `PENDING -> ACCEPTED`、期限到達時は `EXPIRED`。
- session へ両 player UUID と account ID を固定する。

### 例外・終了条件

- 60 秒超過、sender offline、mode 不正、既存 session では開始しない。
- 既存sessionには `COMMITTING` を含む。確定・復旧完了までは別のトレードを開始しない。

## 2. Item／gold 提示

### シーケンス

```mermaid
sequenceDiagram
    actor Player as プレイヤー
    participant GUI as TradeGuiEventHandler
    participant Trade as TradeService
    participant Inventory as InventoryService
    Player->>GUI: owned itemをoffer
    GUI->>Trade: offerOwnedItem(...)
    Trade->>Inventory: source entryをGUIから予約非表示
    Trade->>Trade: source entry ID・session items更新・ready維持
    opt gold slot
        GUI->>Trade: openGoldAmountSetting
        Player->>GUI: 調整桁と増減／半分／2倍／0／最大を操作
        Player->>Trade: applyGoldAmount
        Trade->>Trade: 最新残高以内へclamp・ready維持
    end
    Trade-->>Player: 両GUI再描画
```

### 処理要点

- unTradeable item は escrow に入れない。
- 予約は local inventory state を変更しないため、autosave が API commit 前の ownership を送信しない。
- Gold 金額設定は 1 から 10^18 の調整単位を切り替え、飽和演算と残高上限 clamp で1桁から大額まで扱う。
- 相手側 slot は表示専用。
- item／gold の提示変更は、同一 session の Trade GUI を開いている参加者だけを再描画する。相手が Gold 金額設定または中止確認 GUI を開いている場合、その操作画面は維持する。

### 例外・終了条件

- holder session／viewer 不一致、session 非 OPEN、inventory mutation 失敗では更新しない。
- 表示予約の更新に失敗した場合は、提示元entry ID・数量と予約数量を元へ戻す。提示確定後のTrade GUI再描画失敗はログへ記録し、確定した提示情報だけを巻き戻さない。

## 3. Commit

### シーケンス

```mermaid
sequenceDiagram
    actor A as Player A
    actor B as Player B
    participant Trade as TradeService
    participant Inventory as InventoryService
    participant API as Trade API
    A->>Trade: toggleReady
    B->>Trade: toggleReady
    Trade->>Trade: mode・world・item・gold再検証
    Trade->>Trade: status=COMMITTING
    Trade->>Inventory: A/B save laneの基準stateを確定
    Trade->>API: item・Gold・operation IDをcommit
    API->>API: membership・個体owner・Goldを単一transactionで更新
    alt API成功
        API-->>Trade: A/B affected entry IDs
        Trade->>Inventory: 両account stateをAPI正本から再同期
        alt 再同期・保存成功
            Trade->>Trade: status=COMPLETED・session削除
        else 再同期・保存失敗
            Trade->>Trade: status=COMMITTINGを維持
            Trade->>API: 同じoperation IDでreplayして未完了accountを再同期
        end
    else API明示4xx業務拒否
        Trade->>Trade: status=OPEN・ready解除・予約維持
    else 送信後の通信/応答解析/5xx失敗
        Trade->>Trade: status=COMMITTINGを維持
        Trade->>API: 同じoperation IDでreplayして確定応答を取得
    end
```

### 処理要点

- GUI で見た内容ではなく commit 時点の source entry ID・数量 snapshot を使う。
- API は装備個体の `account_id` と inventory entry membership を同一 transaction で移管する。ルーンは通常 stack entry の数量を移管する。Plugin は state を公開する前に affected entry の装備個体 cache を API 正本で強制再取得・置換するため、受取側の resolver が owner 不一致で空表示／再ログイン時削除となる経路を防ぐ。再取得中に cache または未保存耐久値の世代が競合した場合は再同期を未解決として recovery へ戻し、推測による上書きを行わない。
- A/B の save lane は相互待機せず、各 account の baseline を先に保存して未解決境界を保持した後、API transaction と各 account の再同期・保存を future で連結する。single-thread executor でも lane worker は相手 lane を `join` しない。
- 通常 BAG の空き容量は commit 前判定に使わない。API 再同期で受取 entry の `slot_index` が未指定なら、既存 entry の末尾へ容量外 slot を含めて配置する。通常の取得処理は容量外 slot を空き枠として扱わない。
- item／gold 変更後も ready は維持し、各 player は ready slot の再操作でいつでも自身の準備を解除できる。

### 例外・終了条件

- API が明示する 4xx 業務拒否だけは DB 未変更として `OPEN` へ戻し再操作可能。送信後の通信喪失・応答解析失敗・5xx は API transaction 未確定を証明しないため、`COMMITTING` と account の未解決保存境界を維持し、同じ session ID の冪等 replay で確定応答を取得する。API 成功後の再同期・保存失敗も同じ replay で未完了 account だけを再同期する。
- 未確定の失敗後に参加者が退出・account変更・mode変更・許可外ワールド移動していた場合は、再操作へ戻さず中止する。確定前も開始時account identityとの一致を検証する。

## 4. Close・cancel

### シーケンス

```mermaid
sequenceDiagram
    actor Player as プレイヤー
    participant Event as TradeGuiEventHandler
    participant Confirm as TradeCancelConfirmGui
    participant Trade as TradeService
    participant Inventory as InventoryService
    Player->>Event: trade GUIを閉じる
    Event->>Confirm: 次tickにopen
    alt cancel確定 または confirm close / quit
        Event->>Trade: cancelTrade
        Trade->>Inventory: 予約表示を各ownerへ復元
        Trade->>Trade: status=CANCELLED・session削除
    else back
        Event->>Trade: reopenTrade
    end
```

### 処理要点

- internal reopen では suppressed close set を使い、意図しない confirm 再表示を防ぐ。
- close抑止は現在の取引関連GUIを閉じる場合だけ設定し、通常inventoryからの初回openには残さない。2 tick遅延遷移の取消・表示失敗は取引中止へ接続し、画面のないOPEN sessionを残さない。遷移差し替え時の古い取消通知は新しい遷移へ作用しない。
- amount GUI close は trade GUI へ戻す。
- 終了時は開始時accountの予約だけを解除する。GUI再描画・closeは現在accountが開始時と一致する場合だけ行い、切替後のaccount画面を閉じない。
- 許可対象外ワールドへの移動は session を中止する。

### 例外・終了条件

- plugin disable は `cancelAll()` で同じ予約解除を全 session に適用する。
