# 22_4-統合フロー

## 1. 開始

プレイヤー情報画面または SendCommand → TradeService.openSend → identity/world 検証 → 送信者だけの TradeGui。戻り先は情報画面の場合だけ保持する。

## 2. 提示

送信者の owned item click → source entry 解決 → clone と ID を session へ記録 → 同数量を予約非表示 → 送信者 GUI 再描画。上側clickで予約解除。金額設定画面への遅延遷移中だけ close を抑止する。手動終了は予約を解除する。

## 3. Commit

送信ボタン → identity/world/残高/移管可否再検証 → COMMITTING → 両account事前保存 → API単一transaction（A送信、B空/0）→ affected entry再同期・保存 → COMPLETED → 送信者画面終了・両者へ結果通知。

再同期では装備個体の owner を API 正本で強制再読込し、送信側 cache を残さない。同一個体の強制再読込同士は直列化し、後発処理が先行した受取側の確定 owner を古い cache で上書きしない。受取通常品は maxStack 超過を分割し、slotless 品へ通常容量外まで slot を割り当てる。

未確定拒否は保存境界を解除して OPEN（離脱済みなら CANCELLED）へ戻る。確定不明または再同期失敗は COMMITTING のまま同じ operation ID で replay し、未完了 account だけ再同期する。lane worker は他laneの完了を同期待機しない。
