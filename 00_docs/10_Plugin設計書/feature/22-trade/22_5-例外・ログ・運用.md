# 22_5-例外・ログ・運用

## 例外方針

- request／session の業務不成立は `P_6200`〜`P_6209` 系で通知する。
- offer／withdraw／cancel は GUI reservation の復元で補償する。commit は API transaction が成功した場合だけ完了にする。
- `COMMITTING` 中の再操作を拒否する。
- GUI holder の session ID と viewer UUID を必ず照合する。

## ログ

| ID | 用途 |
|:--|:--|
| `E_6200` | trade GUI click／drag の event failure |
| `E_6201` | offer、withdraw、commit、cancel、rollback failure |
| `W_6202` | player inventory へ item を戻す際の overflow 等の warning |

## 運用

- request は 60 秒で期限切れとなり、期限確認時に `EXPIRED` へ更新する。
- session／reservation はメモリ状態であり、正常 disable では `cancelAll` する。commit 正本は API の `trade_commit` 台帳である。
- world transition は現在 cancel 条件ではない。運用上自動 cancel と説明しない。
- `unTradeable` master field が tradeability の正本である。
- API commit の送信後に通信喪失・応答解析失敗・5xx を検知した場合は `E_6201` を基に request／operation ID を確認し、同じ ID を再送して確定応答を取得する。API が明示する 4xx 業務拒否だけを未確定として `OPEN` へ戻す。異なる要求での ID 再利用は 409 とする。
