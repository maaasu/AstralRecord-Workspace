# 23_5.00-例外・ログ・運用

## 例外方針

- HTTP 通信失敗は `RuntimeException`、非期待 status は response body を含む `IllegalStateException` とする。
- interrupt 時は thread の interrupt flag を復元して `RuntimeException` を投げる。
- detail／summary／quote の 404 だけを正常な `Optional.empty()` とする。
- JSON field の UUID／日時形式が不正な場合は parse exception を caller へ伝播する。
- `MarketService` は repository 例外を捕捉しない。UI／scheduler 境界を持つ将来の caller が thread と通知を管理する。

## ログ

現在の market feature は専用 `LogId` を使用しない。例外を握り潰さないため、呼び出し側は operation、listing／account ID、例外を適切な境界で記録する。

## Cache 運用

| cache | TTL | invalidation |
|:--|--:|:--|
| listing list | 15 秒 | create／purchase／cancel、`clearCache` |
| listing detail | 30 秒 | purchase 対象、404、`clearCache`。create／cancel 成功後は更新値で上書き |
| account summary | 15 秒 | seller mutation、purchase buyer、404、`clearCache` |
| price quote | 5 秒 | seller mutation、404、`clearCache` |

- cache は process local で、他 server の mutation は TTL 満了まで反映されない。
- status code／request field は `00_docs/20_API設計書/feature/23-market/` と同期する。
- repository は同期 HTTP である。main thread から直接連続呼出ししない。
- `clearCache` は lifecycle reload や障害復旧時に全 cache を明示破棄する用途に限定する。
