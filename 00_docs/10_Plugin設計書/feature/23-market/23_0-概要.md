# 23_0-概要

## 目的

Market API の業務処理を plugin 内から一貫した Java model で呼び出し、サーバー内で完結するマーケット GUI を提供する。閲覧、出品、購入、取り下げはすべて API を正本として確定する。

## 責務

- query を URL encode して出品一覧を取得する。
- 出品詳細、account summary、価格見積の未存在を `Optional.empty()` で表す。
- 出品作成、数量指定購入、cancel、売上受取 request を JSON 化して API へ送る。売上受取は出品 ID から安定して導出した冪等キーを使い、応答喪失時も同じ結果を再送取得する。
- response を `MarketListing`、`MarketTransaction` 等へ変換する。出品レスポンスの `sellerAccountName` を公開出品の表示へ利用する。
- 一覧 15 秒、詳細 30 秒、summary 15 秒、見積 5 秒で cache する。
- mutation 成功時に関連 seller／buyer／listing cache を無効化する。
- `MarketGuiEventHandler` が出品一覧、自分の出品、出品アイテム選択、価格設定、購入数量／取り下げ確認を描画する。自分の出品の `SOLD` をクリックすると売上を受け取り、その枠を削除する。マーケット画面は共通ホットバー操作へ参加し、一覧画面の上段ヘッダー、共通ページング、出品枠の開放状態を表示する。マーケット一覧・出品選択画面には閉じるボタンを表示せず、画面内の戻る操作を用いる。
- `/market` は `UserPermission.ADMIN` のプレイヤーだけが実行できる。通常プレイヤーは NPC の `gui.type: MARKET` から開く。
- API が直接更新する inventory entry は `InventorySaveCoordinator.executeExclusiveAfterSave` と `reconcileExternalInventoryEntries` で三者マージする。取り下げの返却容量は確認クリック時と保存 lane 内の API 呼出直前の両方で確認する。
- 購入額は Plugin 設定済みの Gold 額面を使い、購入者の Gold と取得アイテムを API transaction 後に再同期する。出品者の売上 Gold は受取操作成功時だけ再同期する。

## 責務外

- 出品可能性、価格 guard、手数料、残高・在庫移転、idempotency の業務判定。これらは API が正本。
- API の価格ガード、Gold 残高・inventory 正本、出品枠・状態遷移の業務判定。
- plugin 側の market 状態永続化。

## 現在の境界

`MarketService` は validation を追加しない薄い facade で、全公開 method を `MarketRepository` へ委譲する。同期 HTTP は Bukkit main thread で実行せず、読み取りは Bukkit 非同期 task、inventory を変える mutation は account ごとの保存 lane 上で実行する。

## 依存・連携

| feature | 依存内容 |
|:--|:--|
| infrastructure / API | HTTP request builder、Market API の業務判定・transaction |
| Gson / Java time | JSON model 変換、期限・cache TTL |
| inventory | 出品／購入／返却／売上受取後 entry の保存直後 API 操作と正本再同期、取り下げ前の容量確認 |
| currency | Gold 残高表示、売上受取後の API 正本通貨再同期 |
| mob | `MARKET` GUI action を持つ NPC からの通常プレイヤー導線 |

## 変更影響

- Market API request／response field を変更した場合は [[23_1-モデル定義]]、[[23_3-メソッド仕様]] と API 設計書を同時更新する。
- endpoint／status code を変更した場合は [[23_3-メソッド仕様]] と [[23_5-例外・ログ・運用]]を更新する。
- cache TTL／invalidation を変更した場合は [[23_4-統合フロー]] と [[23_5-例外・ログ・運用]]を更新する。
- GUI／inventory 統合を変更した場合は [[23_4-統合フロー]]、NPC schema、PlayerMsgId を同時更新する。
