# 23_5-例外・ログ・運用

## 例外方針

- HTTP 通信失敗、interrupt、408／425／429／5xx は mutation の結果不明を表す `MarketTransportException` とする。interrupt 時は thread の interrupt flag を復元する。
- mutation のその他の非期待 status は API が要求を確定しなかったことを表す `MarketRequestRejectedException` とする。
- detail／summary／quote の 404 と、cancel-result の 404 だけを正常な `Optional.empty()` とする。
- キャンセルの 200 receipt で listing ID、seller、status、日時、`affectedInventoryEntryIds` が欠損・不正な場合は成功とせず `MarketTransportException` とする。
- `MarketService` は repository 例外を捕捉しない。caller が thread 境界と通知を管理する。

## ログ

`MarketGuiEventHandler` は GUI click / drag 境界を `LogId.E_6320` で記録する。API HTTP 例外は player message `P_6305` を基本とし、Gold 不足は `P_6307`、出品枠上限は `P_6306`、自己出品購入は `P_6309` を優先する。取り下げの確認時または保存 lane 内の再確認で容量不足になった場合は API を呼ばず `P_6308` を表示する。取り下げ結果が不明な間は `P_6310` を一度表示し、同一出品について復旧中の例外を `E_6320` へ一度記録する。購入成功 `P_6302` は確定消費 Gold を表示する。

## Cache 運用

| cache | TTL | invalidation |
|:--|--:|:--|
| listing list | 15 秒 | create／purchase／cancel／claim、`clearCache` |
| listing detail | 30 秒 | purchase／claim 対象、404、`clearCache`。create／部分売却後 cancel 成功後は更新値で上書き |
| account summary | 15 秒 | seller mutation、purchase buyer、claim、404、`clearCache` |
| price quote | 5 秒 | seller mutation、claim、404、`clearCache` |

- cache は process local で、他 server の mutation は TTL 満了まで反映されない。
- status code／request field は `00_docs/20_API設計書/feature/23-market/` と同期する。
- repository は同期 HTTP である。main thread から直接連続呼出ししない。
- GUI mutation は必ず `InventorySaveCoordinator` の account lane で実行する。API 成功後に entry 再同期へ失敗した場合は lane を失敗として閉じ、次の保存で API 正本を上書きしない。
- キャンセルは事前保存後に prepared handle を保持する。API が 4xx で拒否した場合だけ破棄し、応答喪失や 5xx では同じ `idempotencyKey` の結果照会・冪等再送を続ける。receipt の再同期と保存が完了するまで、新規 mutation、autosave、logout save に操作前 state を書かせない。
- キャンセル再照会の Bukkit scheduler 登録が通常稼働中に失敗した場合は、player-state と共用する非同期 executor へ同じ遅延再試行を退避する。Plugin 停止時は process-local の再試行を終了して prepared 境界を維持し、操作前 state の停止保存を抑止する。ローカル復旧ファイルは作らず、次回ログインで API／SQL の inventory 正本を読み直す。
- 購入後にオンライン出品者通貨を再同期しない。出品者は `SOLD` item をクリックして売上を受け取り、その成功 response の通貨 entry だけを保存 lane 上で再同期する。
- `clearCache` は lifecycle reload、障害復旧、またはショップでマーケット拡張トークンの inventory 保存が成功した直後に全 cache を明示破棄する用途に使用する。
