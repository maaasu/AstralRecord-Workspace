# ボス機能 理想ユースケース

## UC-01 挑戦受付

1. プレイヤーが `challenge.entryLocation` の `entryRadius` 内でスニークする。
2. `BossChallengeService` は入口範囲に該当する `BOSS` マスタを検索する。
3. プレイヤーが gameplay 対象でない場合は受付しない。
4. パーティー所属時はリーダーだけが受付できる。
5. 受付時点でオンラインのパーティーメンバーを参加者として固定する。ソロ時は受付者 1 人を参加者にする。
6. 参加者数が `partyMin` 以上 `partyMax` 以下でなければ受付しない。
7. 同じ `partyKey` の挑戦が既に存在する場合は受付しない。
8. ハブ WorldMasterData とフィールド WorldMasterData を検証する。
9. 検証成功時は挑戦インスタンスを作成し、参加者をハブへ転送してフィールド準備に進む。

## UC-02 フィールド準備

1. `fieldWorldId` の WorldMasterData は `worldType=BOSS_FIELD` かつ `instanceEnabled=true` でなければならない。
2. `baseWorldPath` に `level.dat` を持つテンプレートワールドが存在しなければ準備失敗にする。
3. `instanceRootPath` 配下へ挑戦 ID を含む一意な world フォルダを作成する。
4. テンプレートから runtime ファイルを除いてコピーする。
5. Bukkit world をロードし、RPG 用ゲームルールを適用する。
6. 失敗時は `FIELD_PREPARE_FAILED` として終了し、作成途中のフォルダは削除を試みる。

## UC-03 フィールド入場と戦闘開始

1. 参加者のオンライン状態を再確認する。
2. 必須参加者が 0 人なら `NO_PARTICIPANTS` で終了する。
3. 全オンライン参加者を `playerSpawnLocation` へ非同期転送する。
4. 全員分の転送 Future が成功した場合だけ、ボスを `bossSpawnLocation` に spawn する。
5. 1 人でも転送失敗またはログアウトがあれば `TRANSFER_FAILED` で終了し、成功済み参加者も `entryLocation` へ戻す。
6. ボス spawn 成功後、参加者数補正を適用して `IN_PROGRESS` にする。

## UC-04 戦闘中

1. 1 秒周期で挑戦状態を監視する。
2. 制限時間超過時は `TIME_LIMIT` で終了する。
3. ボスフィールド内にオンライン参加者が 0 人になった場合は `NO_PARTICIPANTS` で終了する。
4. 参加者がボスへ与えた有効ダメージだけを `damageByPlayerId` に加算する。
5. 非参加者または別 world のプレイヤーによるダメージは報酬/結果集計に含めない。

## UC-05 死亡と復帰

理想仕様では、ボス挑戦中の参加者死亡は通常死亡とは別の挑戦内死亡として扱う。

1. 参加者が死亡した場合、即時で `deathCountByPlayerId` と `currentDeathCount` を加算する。
2. `deathLimit > 0` かつ `currentDeathCount >= deathLimit` の場合は `DEATH_LIMIT` で終了する。
3. 死亡上限未満の場合、対象プレイヤーを復帰待機状態にする。
4. `reviveDelaySeconds` 経過後、プレイヤーがオンラインで挑戦継続中なら `playerSpawnLocation` へ復帰させる。
5. 復帰時は HP/MP/EN/Shield の回復量を `challenge` 設定で制御する。未定義時は HP 50%、MP/EN/Shield は現状維持とする。
6. 復帰待機中のプレイヤーは報酬対象候補には残るが、討伐時にフィールド world にいない場合は報酬対象外になる。

## UC-06 討伐成功

1. ボス Mob の HP が 0 になった場合、死亡地点を保持して `RESULT_WAITING` に遷移する。
2. 通常 Mob の死亡演出とドロップ抽選は再利用してよいが、報酬対象はボス挑戦側で確定する。
3. 報酬対象は `participantIds` と討伐時の同一 world 条件で固定する。
4. 経験値、通貨、アイテム、図鑑、クエスト進行は対象者ごとに付与する。
5. アイテム演出が失敗またはキャンセルされた場合でも、対象者への確定付与を失わせない。
6. TextDisplay でダメージランキングを表示し、15 秒後に `entryLocation` へ戻す。
7. フィールド world を unload し、フォルダを削除する。

## UC-07 失敗終了

失敗終了では報酬を付与しない。結果表示には失敗理由、経過時間、総ダメージ、個人別ダメージ、死亡回数を出す。

失敗理由:

- `TIME_LIMIT`
- `NO_PARTICIPANTS`
- `FIELD_PREPARE_FAILED`
- `TRANSFER_FAILED`
- `BOSS_SPAWN_FAILED`
- `DEATH_LIMIT`
- `ADMIN_STOP`
- `PLUGIN_SHUTDOWN`

## UC-08 管理操作

| コマンド | 用途 |
|---|---|
| `/boss list` | 進行中の挑戦 ID、ボス ID、状態、参加者数、経過秒を表示 |
| `/boss stop <challengeId|partyKey>` | 指定挑戦を `ADMIN_STOP` で終了 |
| `/boss cleanup` | 将来: 残存インスタンス world を監査/削除 |

管理コマンドは `UserPermission.ADMIN` を要求する。
