# 26_4.00-統合フロー

## 1. 挑戦受付から戦闘開始

1. `BossEntryParticleTask` がボス挑戦地点を表示する。
2. プレイヤーが円内でスニークする。
3. `PlayerInteractionGatewayEventHandler`が入力を`SNEAK`へ正規化し、`BossEntryEventHandler.resolve`が入口までの実距離、`WORLD_INTERACTION`、`stableOrder = 10`、`CLAIM`の候補を返す。
4. dispatcherがinput lock、boss / world、player-control候補を比較する。同tierのboss / worldは実距離が近い方を優先し、同距離だけstable orderで決定する。
5. boss entry候補が勝った場合だけ`BossChallengeService.acceptChallenge`を呼ぶ。元eventはcancelせず、world spawn actionとwall-cling / dodgeは実行しない。
6. `BossChallengeService` がボスマスター、挑戦設定、パーティー状態、リーダー権限、進行中重複を検証する。
7. 受付時点の参加予定者を固定し、`BossChallengeInstance` と `BossWaitingFlag` を作成する。
8. 対象プレイヤーを `boss.hubWorldId` のハブワールドへ転送する。
9. `BossFieldInstanceService.createFieldAsync` が `challenge.fieldWorldId` の `WorldMasterData` を使い、パス検証・ディレクトリ作成・ボスフィールドコピーを非同期で行う。
10. コピー完了後、サービス全体で直列化したロード枠を取得し、一時ワールド名を予約登録してからメインスレッドで Bukkit ワールドをロードする。次のロードとは最低 1 tick 空け、UUID と `WorldMasterData` を関連付ける。
11. プレイヤー地点とボス地点の一意なチャンクを非緊急 Future で準備し、各 Future 完了直後から開始完了まで chunk ticket を保持する。
12. 全チャンク準備完了時に、オンライン、同一パーティー所属、ハブ滞在を満たすメンバーを最終参加者として確定する。
13. 待機中に離脱したメンバーを除外し、残り人数が `partyMin` 未満なら挑戦を終了する。
14. 最終参加者全員を `challenge.playerSpawnLocation` へ転送する。
15. 全員の転送成功後、`BossChallengeService` が実参加人数でボスを補正し、`challenge.bossSpawnLocation` へスポーンして状態を `IN_PROGRESS` にする。
16. ボス生成後に開始準備用 chunk ticket を解除する。

## 1.1 中止controllerのDROP_ITEM調停

1. `PlayerInteractionGatewayEventHandler.onPlayerDropItem`がitem dropを`DROP_ITEM`へ正規化する。
2. 近傍にボス挑戦中止controllerがあれば、`BossChallengeCancelEventHandler.resolve`が`WORLD_INTERACTION`、`stableOrder = 10`、`CLAIM_AND_CANCEL`の候補を返す。
3. input lockがなければboss候補がmenu craft shortcutとplayer-mode normal drop guardより先に勝つ。
4. boss候補が勝った場合だけ元eventをcancelし、リーダーなら中止GUIを開く。下位のmenu / player候補は実行しない。
5. controllerがなければboss候補を返さず、他候補もなければ通常ドロップを変更しない。

## 2. 戦闘中

1. `BossChallengeTickTask` が `IN_PROGRESS` の挑戦を定期確認する。
2. 残り時間、デスカウント、ボス HP、現在フェーズを表示する。
3. `DamageService` が対象ボスへダメージを反映する。
4. `BossDamageStatisticsService.recordDamage` が参加者別の有効与ダメージを加算する。
5. 参加者死亡時、`BossPlayerDeathEventHandler` がデスカウントを加算する。
6. `currentDeathCount >= challenge.deathLimit` の場合、終了理由 `DEATH_LIMIT` で挑戦を終了する。
7. 残り時間が `0` 以下の場合、終了理由 `TIME_LIMIT` で挑戦を終了する。
8. ボス HP が 0 以下の場合、終了理由 `DEFEATED` で挑戦を終了する。
9. ボスフィールド内の参加者が 0 人になった場合、終了理由 `NO_PARTICIPANTS` で挑戦を終了する。

## 3. 討伐成功終了

1. `BossChallengeService.endChallenge(DEFEATED)` が状態を `ENDING` にする。
2. `BossRewardService.grantRewards` が報酬対象者を確定する。
3. 通常 Mob と同じ報酬処理で `drops.items`、`drops.lootTable`、`drops.exp`、`drops.money` を付与する。
4. ボス討伐演出を再生する。
5. `BossChallengeService` が状態を `RESULT_WAITING` にし、15 秒間ボスフィールドを保持する。
6. TextDisplay でパーティーメンバーのダメージ統計と退場までの残り秒数を表示する。
7. 待機時間経過後、参加者を退場先へ転送する。
8. `BossFieldInstanceService.destroyField` が Mob 破棄、ワールドアンロード、フォルダ削除を行う。
9. キャッシュと待機フラグを削除し、状態を `ENDED` にする。

## 4. 失敗終了

1. `BossChallengeService.endChallenge(<失敗理由>)` が状態を `ENDING` にする。
2. 報酬処理は実行しない。
3. `BossResultViewService.showResult` が失敗理由、経過時間、合計与ダメージ、プレイヤー別与ダメージ、死亡回数を表示する。
4. 参加者を退場先へ転送する。
5. 参加者全員の退場成功を確認する。失敗時はフィールドを保持して再試行する。
6. `BossFieldInstanceService.destroyFieldAsync` が Mob 破棄、ワールドアンロード、フォルダ非同期削除を行う。
7. 破棄に失敗した場合は、遅れて完了したフィールド入場転送を考慮して手順 4 の退場処理から再試行する。
8. 破棄成功後にキャッシュと待機フラグを削除し、状態を `ENDED` にする。

## 5. ログアウトとパーティー制御

1. 挑戦中に参加者がログアウトした場合、対象参加者を非アクティブ化する。
2. 残り参加者がいる限り挑戦状態は変更しない。
3. 最後の参加者がログアウトした場合、終了理由 `NO_PARTICIPANTS` で失敗終了する。
4. パーティーリーダーがログアウトしても、party feature 側のリーダー切替に従い、ボス挑戦は継続する。
5. ボス挑戦中の自発的なパーティー解散・離脱は、party feature の要求イベントをキャンセルして抑制する。

## 6. 起動時掃除

1. プラグインロード時に `WorldMasterData` をロードする。
2. `BossFieldStartupCleanupTask` が `BOSS_FIELD` かつ `instanceEnabled = true` の `instanceRootPath` 配下を確認する。
3. 残存インスタンスワールドがあれば、ロード済みワールドをアンロードしたうえでフォルダ削除する。
4. 削除失敗時はログを残し、次回起動時の掃除対象に残す。
