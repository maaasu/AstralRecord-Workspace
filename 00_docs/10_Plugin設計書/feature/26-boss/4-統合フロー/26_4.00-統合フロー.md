# 26_4.00-統合フロー

## 1. 入口入力からフィールド準備開始

### シーケンス

```mermaid
sequenceDiagram
    participant P as Player
    participant G as Interaction Gateway
    participant E as BossEntryEventHandler
    participant B as BossChallengeService
    participant W as WorldService
    participant F as BossFieldInstanceService

    P->>G: PlayerToggleSneakEvent
    G->>E: resolve(SNEAK)
    E->>B: findNearestChallengeEntry
    B-->>E: BossEntryHit
    E-->>G: boss-entry / CLAIM
    G->>B: acceptChallenge（勝者時だけ）
    B->>B: gameplay・boss・party・人数・重複検証
    B->>W: hub / field WorldMasterData 検証
    B->>B: challenge / party key 登録
    B->>W: 参加予定者を hub spawn へ転送
    W-->>B: 全転送 Future 完了
    B->>B: hub・party 条件と partyMin を再確認
    B->>F: createFieldAsync
```

### 処理要点

- `SNEAK` 候補は入口までの実距離で他の world interaction 候補と比較し、勝者になった場合だけ受付する。
- 受付時のオンライン party member を `expectedParticipantIds` に固定する。
- 専用待機 flag は使わず、hub world、現在 party、online 状態で入場可能者を判定する。
- hub 転送の一部失敗は即 `TRANSFER_FAILED` にせず、完了時の eligible 人数が `partyMin` 未満なら `PARTICIPANT_REQUIREMENT_NOT_MET` とする。

### 例外・終了条件

- gameplay 対象外、master／入口／leader／人数／重複／world 設定不備は challenge を登録しない。

## 2. フィールド作成と戦闘開始

### シーケンス

```mermaid
sequenceDiagram
    participant B as BossChallengeService
    participant F as BossFieldInstanceService
    participant FS as File System
    participant WS as WorldService
    participant BW as Bukkit World
    participant M as MobService

    B->>F: createFieldAsync(challenge, worldData)
    F->>FS: path 検証・template copy（async）
    F->>WS: prepareWorldLoad（一時名予約）
    F->>BW: createWorld（main / 直列）
    F->>WS: registerRuntimeWorld / gamerule
    F->>BW: spawn地点 chunk Future + ticket
    F-->>B: BossFieldInstance
    B->>B: 40 tick 後に実参加者を確定
    B->>WS: 全実参加者を field へ転送
    WS-->>B: 全転送 Future 完了
    B->>M: spawn(bossId, bossSpawn)
    B->>B: HP・攻撃倍率補正 / controller生成 / markStarted
    B->>F: releaseStartupChunkTickets
```

### 処理要点

- file 操作は非同期、world load／登録／unload は world tick 外のメインスレッドで行う。
- world load は全 challenge で直列化し、各 load 間を最低1 tick空ける。
- player／boss spawn が同一 chunk の場合は1件だけ準備する。
- field 転送は確定した実参加者全員が成功した場合だけ boss を生成する。
- scaling は実参加人数を用い、最大 HP・現在 HP・`outgoingDamageMultiplier` を更新する。

### 例外・終了条件

- copy／load／chunk 準備失敗は `FIELD_PREPARE_FAILED`。
- field 転送失敗は `TRANSFER_FAILED`、boss spawn 失敗は `BOSS_SPAWN_FAILED`。
- 失敗時も chunk ticket、runtime world、copy folder を回収する。

## 3. 戦闘・ダメージ・死亡復帰

### シーケンス

```mermaid
sequenceDiagram
    participant D as DamageService
    participant B as BossChallengeService
    participant C as BossChallengeInstance
    participant PDS as PlayerDeathService
    participant W as WorldService
    participant T as Challenge tick

    D->>B: isBossMob / recordBossDamage
    B->>C: addDamage(HP実損 + Shield実損)
    alt 参加者 HP が 0 以下
        D->>B: handleParticipantDeath
        B->>C: recordDeath
        B->>PDS: startDeath(penalty=false, delay, callback)
        alt deathLimit 到達
            B->>B: endChallenge(DEATH_LIMIT)
        else 復帰可能
            PDS->>W: 全回復後 playerSpawn へ転送
        end
    end
    loop 20 tick ごと
        T->>B: tick
        B->>B: time limit / field内参加者有無
    end
```

### 処理要点

- damage 集計は `IN_PROGRESS` の実参加者だけを対象とする。
- 死亡は通常 death session を再利用するが、経験値 penalty を無効にし、復帰先を field に差し替える。
- 復帰時は HP / MP / EN / Shield を全回復する。
- Sidebar は準備中／戦闘中の表示参加者へ boss 名、死亡数、時間、参加者を表示する。

### 例外・終了条件

- 制限時間到達は `TIME_LIMIT`、field 内参加者0人は `NO_PARTICIPANTS`。
- 復帰転送失敗は `TRANSFER_FAILED`。

## 4. 討伐成功・報酬・結果待機

### シーケンス

```mermaid
sequenceDiagram
    participant D as DamageService
    participant B as BossChallengeService
    participant MC as MobCombatService
    participant DP as Drop Presentation
    participant TD as TextDisplay

    D->>B: resolveRewardRecipients(bossMobId)
    B-->>D: 同一fieldの固定参加者
    D->>MC: handleDeath(mob, recipients)
    MC->>MC: drops・quest・exp・record
    MC->>DP: presentAndGrant
    MC->>MC: destroy Mob
    D->>B: handleBossDefeated
    B->>B: state = RESULT_WAITING / I_6502
    B->>TD: damage順位・死亡回数・残秒表示
    Note over B,TD: 15秒待機
    B->>B: beginChallengeCompletion(DEFEATED)
```

### 処理要点

- reward recipient は実参加者、online、field world 同一、`AstPlayer` 解決可能を満たす対象へ固定する。
- 通常 Mob の固定受取人 overload を再利用し、現在 party／threat table では受取人を決めない。
- 討伐報酬処理が先に実行され、その後 challenge を15秒の結果待機へ移す。
- TextDisplay は damage 合計、順位、比率、個人死亡回数、退場までの残り秒数を動的表示する。

## 5. 失敗・中止・退場・フィールド破棄

### シーケンス

```mermaid
sequenceDiagram
    participant C as Command / GUI / Watchdog
    participant B as BossChallengeService
    participant PDS as PlayerDeathService
    participant W as WorldService
    participant F as BossFieldInstanceService

    C->>B: endChallenge(reason)
    B->>B: state = ENDING / controller・task・display破棄
    B->>B: 失敗なら boss Mob 破棄・理由通知
    B->>PDS: recoverNow(参加者)
    B->>W: entryLocation へ非同期退場
    alt 退場失敗
        W->>W: 別world spawn fallback
    end
    alt 全員退場成功
        B->>F: destroyFieldAsync
        F->>F: ticket解除・unload・非同期delete
        F-->>B: success
        B->>B: state = ENDED / cache解除
    else 退場または破棄失敗
        B->>B: 5秒後に退場から再試行
    end
```

### 処理要点

- `/boss stop`、`/boss cancel`、中止 GUI は `ADMIN_STOP` を使う。
- 失敗終了では Mob 報酬処理を呼ばない。
- field は参加者の退場成功を確認するまで保持する。
- unload または delete 失敗でも challenge index を残し、再試行可能にする。

## 6. 起動・停止と残存フィールド

### シーケンス

```mermaid
sequenceDiagram
    participant P as AstralRecord
    participant B as BossChallengeService
    participant F as BossFieldInstanceService
    participant FS as File System

    P->>B: start
    B->>B: challenge tick / entry visual task開始
    B->>F: cleanupStaleFieldsAsync（初回だけ）
    F->>FS: 有効instance root直下を非同期delete
    P->>B: stop
    B->>F: cancelPendingCreations
    B->>B: challengeをshutdown回収
```

### 処理要点

- startup cleanup は `BOSS_FIELD` かつ instance 有効な root だけを対象とする。
- load 済み field に player がいる、または unload に失敗した場合は削除しない。
- plugin disable 中に async delete を予約できない folder は次回起動時の cleanup に残す。
