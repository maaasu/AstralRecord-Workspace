# 26_2-ユースケース

## 1. 挑戦受付

- 契機: プレイヤーがボス入口円内でスニークし、boss entry 候補が入力調停に勝つ。
- 事前条件: gameplay player、`BOSS` template と challenge が存在、入口円内、現在パーティーメンバー数が `partyMin..partyMax`、同じ party key が未挑戦。リーダー限定ではない。
- 処理: [[26_3-サービス]].ボス挑戦受付
- 結果: 受付を実行した本人だけをハブへ非同期転送し、現在パーティーメンバー全員がハブへ集まるまでメンバー待機にする。

ハブ／フィールドの `WorldMasterData` は受付時に確認する。フィールドは `BOSS_FIELD` かつ `instanceEnabled = true` を必須とする。

## 2. ハブ転送と最終参加者確定

1. 受付を実行した本人だけへハブ spawn 転送を開始する。
2. 他の現在パーティーメンバーは自動転送せず、各自が受付地点でスニークしてハブへ移動する。
3. 現在パーティーメンバー全員がオンライン・通常プレイモード・ハブ滞在を満たすまで、作成枠キューへ登録せずメンバー待機を継続する。待機タイムアウトは設けない。
4. 全員が揃った場合だけ、Boss／Dungeon 共通の作成枠キューへ登録する。空きがなければ Hub で待機し、空きがあれば作成枠を占有してフィールド準備へ進む。
5. 作成開始後は参加者を固定し、フィールド準備完了から40 tick後に同じ条件を再評価して実参加者を確定する。

待機中は `InstanceCreationQueue` が枠ごとの FIFO とチケットを管理する。既定の通常枠は2件、寄付者予約枠は1件で、実値は `config.yml` の `instanceLimits.boss` から読み込む。待機中の Hub title は空とし、subtitle だけへ同一枠内の順番、待機人数を表示する。Sidebar には順番待機中の状態を表示する。ハブ初期スポーンでスニークすると受付開始位置へ戻る。パーティーが列にいる場合は確認 GUI を表示し、確定後はチケットを取り消してメンバー待機へ戻す。全員が揃い直した場合は列の最後尾へ登録する。ソロは確認なしで離脱する。

待機中の party leave、leader kick、disband、logout は PartyService の構成変更通知で同期する。全員が揃って列にいる状態からメンバーが脱退し、残りの現在メンバー全員がハブにいる場合はチケット位置を維持する。ハブにいないメンバーの脱退で残りが全員揃った場合は列の最後尾へ登録し、ハブに残るメンバーの脱退や新規加入で揃わない場合はメンバー待機へ戻す。解散時はハブにいる待機者を受付開始位置へ戻して終了する。

## 3. フィールド準備と戦闘開始

1. 作成枠を占有した要求について、instance root、コピー元、`level.dat`、コピー先逸脱・重複を検証する。
2. runtime file を除外してテンプレートを非同期コピーする。
3. 一時 world 名を予約し、world tick 外かつ直列ロード枠取得後に Bukkit world をロードする。
4. runtime world 登録と RPG gamerule 適用後、参加者地点・ボス地点の重複しない chunk を非緊急 Future で準備し ticket を保持する。
5. 実参加者全員のフィールド転送が成功した場合、10秒の開始カウントダウンを行う。毎秒 title `開始まで N秒`、subtitle にボス表示名、カウント音を送信し、この間はボスを生成しない。フィールド内参加者が開始条件を満たさなくなれば終了する。
6. 10秒後に title `{ボス名} 挑戦開始`、subtitle `ボス戦`、開始音を送り、その後にだけボスを生成する。失敗は `TRANSFER_FAILED` または `BOSS_SPAWN_FAILED` とする。
7. 実参加人数で最大 HP・現在 HP・シールドを共通補正し、`scaling` が有効な場合だけ既存の challenge 固有与ダメージ倍率も補正して、中止 controller を生成して `IN_PROGRESS` にする。作成枠は挑戦終了後のフィールドワールド破棄完了まで保持する。
8. ボス生成後または開始失敗時に開始用 chunk ticket を解除する。

## 4. 戦闘進行と表示

- 1秒ごとに制限時間とフィールド内参加者有無を確認する。
- 制限時間到達は `TIME_LIMIT`、オンラインかつ同一フィールドにいる参加者が0人なら `NO_PARTICIPANTS` とする。
- `DamageService` が HP／Shield へ実際に反映した有効ダメージを参加者別に加算する。
- hud feature は `BossChallengeSidebarInfo` を使い、ボス名、共有死亡回数、経過／制限時間、参加者名を表示する。
- ボス地点には BlockDisplay＋Interaction と中止案内 TextDisplay を置く。

## 5. 死亡と復帰

1. `DamageService` がボスフィールド内の実参加者の HP 0 を検出する。
2. 既に死亡中でなければ共有死亡回数と個人死亡回数を加算する。
3. `PlayerDeathService.startDeath` を、経験値ペナルティなし、`reviveDelaySeconds`、専用復帰 callback で開始する。
4. 共有死亡回数が `deathLimit` を超えた場合だけ `DEATH_LIMIT` で挑戦を終了する。`deathLimit = 0` は1回目の死亡で終了する。
5. 許容回数内なら復帰時に HP / MP / ENG / Shield を全回復し、フィールドの `playerSpawnLocation` へ非同期転送する。
6. 復帰転送失敗は `TRANSFER_FAILED` とする。挑戦終了時は死亡状態を即時回収する。

## 6. 討伐成功と報酬

1. ボス HP が0以下になると `DamageService` が報酬対象を問い合わせる。
2. 対象は確定済み実参加者のうち、オンライン、`AstPlayer` cache 登録済み、討伐時に同一フィールド world にいるプレイヤーとする。
3. `MobCombatService.handleDeath(mob, recipients)` が対象者ごとに drops 抽選、quest、経験値／skill point、冒険記録、drop 表示・付与を行い、Mob を破棄する。
4. 挑戦を `RESULT_WAITING` にし、戦闘開始から討伐までの経過秒数を含む討伐メッセージと、討伐時間・ダメージ順位・死亡回数・退場までの残り秒数を TextDisplay へ表示する。
5. 15秒後に終了処理へ進む。

与ダメージ量、参加時間、職業、順位による報酬差は付けない。

## 7. 失敗・中止・退場

- 失敗時は報酬処理を呼ばず、理由別メッセージを送る。
- `/boss stop`、`/boss cancel`、中止 GUI は `ADMIN_STOP` とする。
- 死亡状態を即時回収後、入口へ転送する。入口転送失敗時はハブ以外・フィールド以外の最初の world spawn を fallback とする。
- 全員の退場に失敗した場合は5秒後に再試行し、フィールドを保持する。
- 退場成功後に world をアンロードしてフォルダーを非同期削除する。破棄失敗時も5秒後に退場から再試行する。
- 破棄成功後に party key と challenge cache を削除する。

## 8. 管理・起動停止

- `/boss instances` と `/boss list`: 稼働中挑戦を表示する。
- `/boss stop <partyId|partyKey|challengeIdPrefix>`: 対象挑戦を停止する。
- `/boss cancel`: 実行プレイヤーが現在のリーダーである挑戦を停止する。
- 起動時は有効な全 `BOSS_FIELD.instanceRootPath` 直下を残存候補として掃除する。
- plugin 停止時は定期 task、入口表示、準備中コピー、結果 task／display、controller を回収し、可能な範囲で退場・field 破棄を要求する。
