# 26_5-例外・ログ・運用

## 1. 受付・準備・終了の扱い

| 条件 | 挑戦状態／応答 |
|---|---|
| gameplay player でない | 登録せず `P_5065` |
| boss master／category／challenge 不正 | 登録せず `P_6501` |
| 入口円外 | 登録せず `P_6502` |
| party leader でない | 拒否条件にしない。party の現在 member なら受付可能 |
| 受付時または入場時の人数不正 | 登録前は拒否、登録後は `PARTICIPANT_REQUIREMENT_NOT_MET` |
| 同じ party key が登録済み | 登録せず `P_6505` |
| hub master 不在／実 world load 不可 | 登録せず `P_6506` / `P_6523` |
| field master 不在／type・instance 不正 | 登録せず `P_6507` / `P_6522` |
| 通常枠または寄付者予約枠が満杯 | Hub で作成待機し、title は空、`P_6534` の順番・待機人数だけを subtitle で定期更新。Sidebar は `P_6714` |
| 受付実行者だけが Hub 到着 | Hub 未到着の現在 member へ `P_6535` を一度送信し、待機実行者名と「あなたを待っています」を通知 |
| メンバー待機中 | Sidebar に `P_6713` を表示し、Hub 未到着メンバー名を灰色表示 |
| メンバー待機中に Hub 未到着、または列中に Hub を離脱 | 終了せずメンバー待機へ戻す。全員が揃い直したら該当列の末尾へ登録 |
| party leave／kick／logout | PartyService 通知で現在 member を再同期。残りが全員 Hub なら列位置を維持し、揃わなければメンバー待機 |
| party disband | Hub にいる待機者をボス受付開始位置へ戻し、挑戦待機を終了 |
| base folder または `level.dat` 不在 | `FIELD_PREPARE_FAILED`、`W_6501`、`E_6500` |
| copy／world load／chunk 準備失敗 | `FIELD_PREPARE_FAILED`、`E_6500`、途中 field を回収 |
| field 転送失敗 | `TRANSFER_FAILED`、`P_6521` |
| boss spawn 失敗 | `BOSS_SPAWN_FAILED`、`E_6500` |
| 制限時間／参加者不在／死亡上限 | 対応する終了理由で報酬なし |
| 退場失敗 | field と challenge index を保持し5秒後に再試行 |
| unload／folder delete 失敗 | `E_6503` / `E_6502`、退場から5秒後に再試行 |

メインスレッドで file copy、再帰 delete、chunk Future 待機を行わない。world load／unload は world tick 外へ延期する。

## 4. コマンド権限

- console は `/boss instances|list|stop` を実行できる。
- player の管理操作は cache 登録済み `AstPlayer` かつ permission 値が `UserPermission.ADMIN` 以上であることを要求する。
- `/boss cancel` と controller／GUI 中止は管理者権限ではなく、現在の solo initiator または party leader 条件を要求する。

## 5. 設定

- ハブ ID は `config.yml` の `boss.hubWorldId` を正規キーとする。
- 作成枠は `config.yml` の `instanceLimits.boss.normalLimit`／`reservedLimit` を正規キーとし、通常枠は1件以上、予約枠は0件以上へ補正する。
- 寄付者予約枠は現在 party のいずれかの `AstPlayer.user.permission >= UserPermission.DONOR(5)` で判定し、`ADMIN(99)` も対象とする。予約枠は有限とする。
- 未指定時は legacy `plugin.boss.hubWorldId`、さらに未指定なら `skyhaven_isle` を使う。
- field は `WorldMasterData.worldType = BOSS_FIELD` かつ `instanceEnabled = true` が必須。
- startup cleanup の削除対象は有効 field master の `instanceRootPath` 直下の directory に限定する。

## 6. 運用確認

- `/boss instances` で `ENDING` が長時間残る場合、参加者の退場先、world unload、folder permission、`E_6502` を確認する。
- 起動時に残存 field へ player がいる場合は自動削除しない。player を退避して次回起動または手動運用で回収する。
- field prepare の時間上限は設けない。コピー量と chunk load を監視し、Watchdog 延長で対処しない。
