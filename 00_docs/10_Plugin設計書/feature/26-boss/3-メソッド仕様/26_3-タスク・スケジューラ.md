# 26_3-タスク・スケジューラ

## 1. 定期処理開始

クラス名: `BossChallengeService`
物理名: `start`

処理内容:

1. challenge tick task がなければ、初回20 tick後・以降20 tick周期の同期 task を登録する。
2. entry visual task がなければ frame を0へ戻し、初回0 tick・以降10 tick周期の同期 task を登録する。
3. startup cleanup を未開始の場合だけ flag を立て、`BossFieldInstanceService.cleanupStaleFieldsAsync` を fire-and-forget で呼ぶ。
4. 複数回呼ばれても task と startup cleanup を重複開始しない。

## 2. 定期処理停止

クラス名: `BossChallengeService`
物理名: `stop`

処理内容:

1. challenge／entry visual task を cancel して参照を `null` にする。
2. 全入口 prompt display を破棄する。
3. 全 pending field creation の cancel flag を立てる。
4. 全 challenge を shutdown 回収し、challenge／party key／boss Mob／controller index を空にする。

shutdown 回収は死亡状態解除、退場転送、field 破棄を要求するが、plugin disable と非同期処理が競合した folder は次回 startup cleanup に残り得る。

## 3. 挑戦監視 tick

クラス名: `BossChallengeService`
物理名: `tick`

周期: 20 tick

処理内容:

1. `IN_PROGRESS` challenge の snapshot を走査する。
2. challenge に紐付く `MobInstance` の現在 HP／最大 HP から BossBar のタイトルと進捗率を更新し、field world 内の実参加者だけへ表示する。
3. `(now - startedAtMs) / 1000 >= timeLimitSeconds` なら `TIME_LIMIT` で終了する。
4. timeout でなければ、実参加者のうちオンラインかつ field world にいる player が1人以上いるか確認する。
5. 0人なら `NO_PARTICIPANTS` で終了する。

BossBar はボス生成後に作成し、討伐成功時の結果待機、失敗終了、挑戦停止のいずれでも参加者から除去して非表示にする。タイトルはボス表示名と `現在 HP/最大 HP` を表示し、進捗率は `currentHealth / maxHealth` を `0.0` から `1.0` に丸める。

`handleQuit` もこの tick を即時実行する。

## 4. 入口演出 tick

クラス名: `BossChallengeService`
物理名: `tickEntryVisuals`

周期: 10 tick

処理内容:

1. challenge 付きのロード済み BOSS template を走査する。
2. entry world がロード済みで、入口中心から64 block以内に viewer がいる場合だけ描画する。
3. `max(0.75, entryRadius)` の10点 ring dust と中心上の soul fire を表示する。
4. 入口上2.35 blockへ、ボス名とスニーク案内の TextDisplay を作成または更新する。
5. 今回 active でなかった template の prompt display を破棄し、frame を進める。

## 5. フィールド作成スケジューリング

クラス名: `BossFieldInstanceService`
物理名: `createFieldAsync`

- path 検証、directory 作成、template copy、folder delete は Bukkit async task で行う。
- `Bukkit.createWorld`、runtime world 登録、gamerule、unload は main thread で行う。
- world tick 中は次の scheduler task へ延期する。
- world load は service 全体で1件だけ許可し、slot を最低1 tick後に解放する。
- player／boss spawn chunk は non-urgent Future を使い、同期 `join` / `get` で待機しない。

## 6. 結果待機と終了再試行

- 討伐成功時は15秒後に終了処理を呼ぶ同期 delayed task を challenge に保持する。
- 参加者退場または field 破棄が失敗した場合は5秒後に `exitParticipantsAndCleanup` を再実行する。
- field 準備失敗後のロード済み world は、破棄成功または plugin disable まで20 tick周期で回収を再試行する。
