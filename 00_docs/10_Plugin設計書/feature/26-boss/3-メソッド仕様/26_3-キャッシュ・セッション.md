# 26_3-キャッシュ・セッション

## 1. 挑戦 service 内 index

クラス名: `BossChallengeService`

専用 cache class は持たず、次の Map でプロセス内状態を保持する。

| 物理名 | 型 | 役割 |
|---|---|---|
| `challengesById` | `ConcurrentHashMap<UUID, BossChallengeInstance>` | challenge ID から本体を取得する |
| `challengeIdByPartyKey` | `ConcurrentHashMap<String, UUID>` | solo／party key の同時挑戦を一意化する |
| `challengeIdByBossMob` | `ConcurrentHashMap<UUID, UUID>` | boss Mob ID から challenge を解決する |
| `cancelControllersByChallengeId` | `ConcurrentHashMap<UUID, BossChallengeCancelController>` | challenge の中止装置を保持する |
| `challengeIdByCancelInteraction` | `ConcurrentHashMap<UUID, UUID>` | Interaction entity から challenge を解決する |
| `entryPromptDisplays` | `HashMap<String, EntryPromptDisplay>` | boss template ID ごとの入口案内表示を保持する |

Dungeon と Boss の共通 `ChallengeParticipationRegistry` は、party key と参加者UUIDを挑戦受付から終了処理完了まで同期予約する。競合時は予約を登録せず、保持中の挑戦表示名を受付メッセージへ渡す。

`entryPromptDisplays` は同期 entry visual task と stop からだけ操作する。

## 2. フィールド service 内状態

クラス名: `BossFieldInstanceService`

| 物理名 | 型 | 役割 |
|---|---|---|
| `pendingCreations` | `ConcurrentHashMap<UUID, PendingFieldCreation>` | challenge ごとの copy／load cancel flag |
| `startupChunkTicketsByChallengeId` | `ConcurrentHashMap<UUID, List<Chunk>>` | 戦闘開始まで保持する chunk ticket |
| `worldLoadSlotInUse` | `AtomicBoolean` | Bukkit world load の全体直列化 |

## 3. 登録・解除契機

| 状態 | 登録 | 解除 |
|---|---|---|
| 挑戦受付 | challenge、party key | field 破棄まで成功した終了時 |
| フィールド転送完了 | challenge が保持する開始 countdown task | ボス生成直前、終了開始、stop 時 |
| ボス生成 | boss Mob index、controller 2種 | 討伐確定または終了開始時 |
| field 準備開始 | pending creation | 作成 Future 完了時 |
| chunk 準備完了 | startup tickets | ボス生成完了、準備失敗、field 破棄時 |
| 討伐結果待機 | result task、result display | 終了開始または stop 時 |

## 4. 永続化

挑戦、集計、field、controller、pending creation は DB／file へ永続化しない。plugin 再起動後に session を復元せず、残存 instance directory だけ startup cleanup で回収する。
