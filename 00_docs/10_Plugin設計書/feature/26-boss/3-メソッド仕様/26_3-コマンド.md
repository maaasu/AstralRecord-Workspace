# 26_3-コマンド

## 1. ボスコマンド実行

クラス名: `BossCommand`
物理名: `executeCommand`

コマンド: `/boss <horologium|cancel|instances|list|stop|teleport> [partyId|partyKey|challengeIdPrefix|type instanceId]`。登録usageは`P_8068`、説明は`P_8069`から取得する。

処理内容:

1. plugin または `BossChallengeService` が未初期化の場合、`P_6520` を error 表示する。
2. 引数なしは `P_8060` の一般向け受付・中止案内を表示し、管理者には既存 usage も表示する。
3. 第1引数 `horologium` は管理者判定より先に専用受付へ進む。player かつ引数1件だけを受け付け、console には `P_5060`、余分な引数には一般向け案内を返す。
4. 第1引数 `cancel` は管理者判定より先にプレイヤー向け中止処理へ進む。
5. `instances` / `list` / `stop` / `teleport` は console または `UserPermission.ADMIN` 以上のオンライン `AstPlayer` だけ許可する。権限不足は `P_5061` を表示する。
6. `instances` / `list` は [[26_3-コマンド]].稼働中挑戦一覧、`stop` は管理者停止、`teleport` は管理者挑戦リーダー位置への転送を実行する。
7. 不明な第1引数は一般プレイヤーに `P_8060`、管理者に既存 usage を表示する。

## 1.1 ホロロギウム専用受付

クラス名: `BossCommand`, `BossChallengeService`
物理名: `executeCommand`, `acceptHorologiumFromBase`

コマンド: `/boss horologium`

処理内容:

1. 固定 boss ID `horologium_clockwork_sovereign` だけを既存 `acceptChallenge` に渡す。
2. 実行者の world が WorldService に登録済みの `BASE` または `HUB` であることを要求し、違う場合は `P_8061` を表示する。ダンジョン・他ボス会場・野外からの移動に使えない。
3. 位置条件以外のアカウント、人数、パーティー待機、共通予約、ハブ・フィールド処理は既存受付と同じ。待機中のメンバーも各自コマンドで参加できる。
4. 受付成立時に全参加予定者へ `P_8062` を送り、同会場の報酬資格、非AFK、BAG容量を案内する。待機への後参加にも送る。
5. 終了・中断・失敗時の帰還地点は `starlit_nox` のマスタ spawn `(-75,-42,-576)` とする。

## 2. 稼働中挑戦一覧

クラス名: `BossCommand`
物理名: `handleList`

コマンド: `/boss instances`, `/boss list`

処理内容:

1. `BossChallengeService.describeActiveForAdmin` と `DungeonService.describeActiveForAdmin` を取得し、ボス／ダンジョンの稼働中セッションを一つの一覧へまとめる。
2. 空の場合は `P_6538` を表示する。
3. 1件以上の場合は `P_6536` に件数を渡す。
4. プレイヤー実行時は各行を `P_6537` で表示し、`/boss teleport <boss|dungeon> <instanceId>` のクリックイベントを付ける。コンソール実行時は同じ内容をクリックなしで表示する。

## 3. 管理者挑戦リーダー位置への転送

クラス名: `BossCommand`
物理名: `handleTeleport`

コマンド: `/boss teleport <boss|dungeon> <instanceId>`

処理内容:

1. プレイヤー実行かつ `UserPermission.ADMIN` 以上であることを確認する。
2. 種別と UUID を検証し、Boss の場合は `BossChallengeService.teleportAdminToLeader`、Dungeon の場合は `DungeonService.teleportAdminToLeader` を呼び出す。
3. クリック時点で対象セッションが存在し、終了処理中でなく、現在のパーティーリーダーが対象参加者としてオンラインであることを再検証する。
4. リーダーの現在 `Location` を `PlayerTeleportService` へ渡し、管理者を転送する。対象が見つからない、リーダーがオフライン、または転送失敗の場合は `P_6539` を表示する。

## 4. 管理者停止

クラス名: `BossCommand`
物理名: `handleStop`

コマンド: `/boss stop <partyId|partyKey|challengeIdPrefix>`

処理内容:

1. 引数が2件でなければ usage を表示する。
2. `BossChallengeService.stopChallenge(args[1])` を呼ぶ。
3. 対象なしは `P_6519`、停止開始は `P_6518` を引数文字列付きで表示する。

`stopChallenge` は challenge UUID prefix の複数一致を検出せず、iteration 上で最初の一致を停止する。運用上の扱いは [[26_9-未決事項]] とする。

## 5. リーダー中止・討伐後の終了

クラス名: `BossCommand`
物理名: `handlePlayerCancel`

コマンド: `/boss cancel`

処理内容:

1. console からの実行は `P_5060` を error 表示する。
2. player の中止・終了可能 challenge を検索し、現在の party leader 条件を確認する。討伐後の `RESULT_WAITING` も対象にする。
3. `STOPPED` は `P_6528`、討伐後の `FINISHED` は `P_7727`、`NOT_LEADER` は `P_6526`、`NO_CHALLENGE` は `P_6527` を表示する。

## 6. 補完

`BossTabCompleter` は第1引数に一般プレイヤーへ `horologium` / `cancel` を提示する。管理者には既存管理操作も加え、console には管理操作だけを提示する。
