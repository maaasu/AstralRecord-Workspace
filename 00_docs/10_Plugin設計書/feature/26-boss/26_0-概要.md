# 26_0-概要

## 1. 目的

`boss` feature は `MobCategory.BOSS` の Mob を通常の戦闘・報酬基盤へ載せながら、挑戦単位の受付、参加者固定、一時ワールド、制限時間、死亡・復帰、結果表示、運用停止を管理する。

## 2. 対象範囲

- ボス入口円と案内 TextDisplay の表示
- `SNEAK` 入力によるソロ／パーティー挑戦受付
- 受付を実行した本人だけのハブ転送と、現在のパーティーメンバー全員がハブへ集まるまでのメンバー待機
- ハブ初期スポーンのスニークによる挑戦受付開始位置への復帰
- 有限の通常作成枠・寄付者予約作成枠によるインスタンス作成待機列
- 作成待機中の Hub 滞在と、title を空にして subtitle だけへ出す順番・待機人数表示
- メンバー待機／順番待機の Sidebar 状態表示と、Hub 未到着メンバー名の灰色表示。ハブ初期スポーンから待機離脱した本人は Sidebar 対象外とする
- パーティーが列から離脱するときの再度最後尾へ並び直す確認 GUI
- `BOSS_FIELD` テンプレートの非同期コピー、直列ロード、必要チャンク準備
- フィールド転送後10秒の title／sound 開始カウントダウンと、完了後のボス生成
- BossChallenge／Dungeon の BOSS Mob へ実参加人数に応じた HP・シールド倍率補正
- 挑戦参加者へのボス HP BossBar 表示と戦闘中の HP 同期
- 制限時間、参加者不在、共有死亡許容回数超過、管理操作による終了
- 固定参加者の有効ダメージ・死亡回数集計
- 討伐時の固定受取人向け通常 Mob 報酬処理
- Sidebar、討伐後 TextDisplay、中止 controller／GUI
- 退場、ワールド破棄、起動時の残存フィールド掃除
- Boss ID ごとの3段階ローテーション、予兆攻撃、限定召喚
- Dungeon 外での上限制御付き自然地形破壊と、Dungeon world での強制無効化

## 3. 対象外

- DB へ永続化する討伐履歴・ランキング
- 挑戦開始後の自動途中参加・自動再入場
- `/boss cleanup` による手動掃除

方針未確定の要件は [[26_9-未決事項]] に集約する。採用済みだが未実装の仕様が生じた場合は、カテゴリ `8` へ分離する。

## 4. 実装構成

| 構成 | 主な責務 |
|---|---|
| `BossChallengeService` | 受付、参加者確定、戦闘開始、死亡、集計、報酬対象、終了、中止、表示情報 |
| `BossFieldInstanceService` | コピー、world ロード、chunk ticket、アンロード、非同期削除、起動時掃除 |
| `BossEntryEventHandler` | `SNEAK` の入口候補提供 |
| `ChallengeWaitingHubEventHandler` | ハブ初期スポーンの待機離脱候補と確認 GUI |
| `BossChallengeCancelEventHandler` | controller の右クリック／ドロップ候補と中止 GUI click |
| `BossPlayerEventHandler` | logout 後の参加者不在確認 |
| `BossCommand` | `/boss instances|list|stop|cancel` |
| `BossChallengeCancelGui` | リーダー用の挑戦中止確認 GUI |
| `BossChallengeCancelController` | ボス地点の BlockDisplay、Interaction、案内 TextDisplay |
| `BossMechanicService` | HP段階、予兆、範囲攻撃、召喚、地形破壊、終了回収 |
| `BossMechanicProfile` / `BossTerrainPolicy` | Boss ID別ローテーションと破壊可能ブロックの固定契約 |
| `shared/challenge/InstanceCreationQueue` | 通常枠・寄付者予約枠の有限上限、FIFO待機、作成中枠の解放 |
| `PartyMembershipChangeListener` | パーティー加入・脱退・解散時の待機構成同期 |

作成待機の状態本体は `shared/challenge/InstanceCreationQueue` が保持し、Boss 側は挑戦 ID と作成枠チケット IDだけを保持する。待機順と Hub の滞在確認・title／subtitle 更新は既存の `BossChallengeService` tick で行う。

### インスタンス作成枠（Boss／Dungeon共通）

- Boss と Dungeon はそれぞれ独立した `InstanceCreationQueue` を持ち、他 feature の枠数を共有しない。
- 通常プレイヤーは `normalLimit` の通常枠へ FIFO で入る。設定値は1件以上とする。
- パーティーに `AstPlayer.user.permission >= UserPermission.DONOR(5)` のメンバーが1人でもいれば、`reservedLimit` の有限な予約枠を要求する。`ADMIN(99)` もこの条件を満たす。予約枠は通常枠と別カウントだが、無制限 bypass にはしない。`reservedLimit=0` の場合は通常枠を使用する。
- 枠は Hub 転送後の作成要求へ割り当て、フィールドの作成開始からインスタンスのワールド破棄完了まで占有する。破棄完了後に次の待機要求へ解放する。
- パーティーは現在の全メンバーが Hub にいる場合だけ作成待機列へ入る。加入が発生した場合は列から外してメンバー待機へ戻し、新メンバーを含む全員が Hub に集まった時点で列の末尾へ登録する。
- Hub 初期スポーンのスニークは対象プレイヤーを対応するボス受付開始位置へ戻す。列にいる場合は確認 GUI を表示し、確定後はチケットを取り消してパーティーをメンバー待機へ戻す。
- パーティー脱退・追放・解散・logout は挑戦待機の離脱として同期する。残りの現在メンバーが全員 Hub にいる脱退ではチケット位置を維持し、そうでなければメンバー待機へ戻す。解散時は Hub 待機者を受付開始位置へ戻して待機を終了する。
- 待機中のパーティー構成変更に待機タイムアウトは設けない。作成開始後またはボス挑戦中の固定参加者は、パーティー構成変更によって再列入場させず、Party の招待・承認も拒否する。待機ハブから離脱した `waitingAbsent` は current member／expected participant に残すが、本人の Sidebar と拠点帰還制限からは除外し、再到着時に待機へ復帰できる。

## 5. 正本と境界

| データ／処理 | 正本 |
|---|---|
| ボス戦闘定義、`challenge`、drops | ボス Mob master と `MobTemplate` |
| ハブ ID | `config.yml` の `boss.hubWorldId` |
| Boss／Dungeon 作成枠上限 | `config.yml` の `instanceLimits.boss` / `instanceLimits.dungeon` |
| 寄付者予約枠判定 | 現在パーティーのいずれかの `AstPlayer.user.permission >= UserPermission.DONOR(5)` |
| 作成待機順・作成中枠 | 各 feature が所有する `InstanceCreationQueue` |
| フィールド種別、コピー元／先 | `WorldMasterData` |
| 有効ダメージ、死亡検出 | `DamageService` |
| Mob 報酬抽選・付与 | `MobCombatService` と関連する drop service |
| ボスの現在 HP / 最大 HP | `MobInstance` |
| ボス固有ローテーション、地形破壊上限 | boss feature の profile / policy |
| HP / MP / ENG / Shield 全回復 | `PlayerDeathService` 経由の `StatusService` |
| 挑戦中 Sidebar | hud feature |

## 8. 依存・連携

- `mob`: `MobCategory.BOSS`、`MobTemplate.challenge`、Mob 生成・破棄、固定受取人向け報酬処理を利用する。
- `world`: `WorldMasterData` 検証、ハブ解決、runtime world 登録、非同期転送を利用する。
- `party`: 現在のメンバー構成、加入・脱退・解散通知、フィールド入場直前の所属再確認に利用する。待機受付にリーダー限定条件は設けない。
- `player`: gameplay mode 判定、死亡・復帰、プレイヤーメッセージを利用する。
- `combat`: ボスへの有効ダメージ、ボス討伐、参加者死亡の通知元とする。
- `status`: 復帰時の HP / MP / ENG / Shield 全回復を担当する。
- `hud`: 準備中・戦闘中の挑戦情報を Sidebar に表示する。
- `shared/challenge`: 作成枠キューと開始 countdown／死亡許容判定を提供する。
- `player-interaction`: `SNEAK`、`RIGHT_CLICK`、`DROP_ITEM` の候補調停を担当する。
