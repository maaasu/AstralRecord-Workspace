# 06_3-リポジトリ

## 1. LootRepository メソッド仕様

### ルートテーブル一覧取得

クラス名: `LootRepository`  
物理名: `findAll`

責務:

API から全ルートテーブル一覧を取得する。

処理内容:

1. `GET /api/loot/table` と `GET /api/loot/pool` を呼ぶ
2. 両方が `200` なら pool を ID Map にし、table の pool 参照を解決した [[06_1-モデル定義]].ルートテーブル のリストへ変換して返す
3. その他ステータスは `LogId.E_5300` を記録し例外化する

	| 項目 | 内容 |
	|---|---|
	| ID | `LogId.E_5300` |
	| レベル | `ERROR` |
	| テンプレート | `ルートテーブル取得に失敗しました (API): %s` |
	| 出力条件 | `GET /api/loot/table` が `200` 以外 または 例外 |
	| 引数 | APIエラーメッセージ or 例外メッセージ |

4. `InterruptedException` は `Thread.currentThread().interrupt()` を実行のうえ `LogId.E_5300` を記録し `RuntimeException` でラップして送出する

入力:

- なし

出力:

- `List<LootModel>`: ルートテーブル一覧

### ルートテーブル取得

クラス名: `LootRepository`  
物理名: `findById`

責務:

指定 ID のルートテーブルを API から取得する。

処理内容:

1. ルートテーブル ID を URL エンコードする
2. `GET /api/loot/table/{tableId}` を呼ぶ
3. `200` の table が参照する pool ごとに `GET /api/loot/pool/{poolId}` を呼び、解決できた pool を結合して [[06_1-モデル定義]].ルートテーブル へ変換し、`LogId.D_5300` を記録する

	| 項目 | 内容 |
	|---|---|
	| ID | `LogId.D_5300` |
	| レベル | `DEBUG` |
	| テンプレート | `ルートテーブルを取得しました (API): id=%s` |
	| 出力条件 | `GET /api/loot/table/{tableId}` が `200` |
	| 引数 | `lootId` |

4. `404` は `LogId.W_5300` を記録して `null` を返す

	| 項目 | 内容 |
	|---|---|
	| ID | `LogId.W_5300` |
	| レベル | `WARN` |
	| テンプレート | `ルートテーブルが見つかりませんでした (API): id=%s` |
	| 出力条件 | `GET /api/loot/table/{tableId}` が `404` |
	| 引数 | `lootId` |

5. その他ステータスは `LogId.E_5300` を記録し例外化する（ログ詳細テーブルは [[06_3-リポジトリ]].ルートテーブル一覧取得 step 3 を参照）
6. `InterruptedException` / `IOException` は `LogId.E_5300` を記録し例外として再送出する（ログ詳細テーブルは [[06_3-リポジトリ]].ルートテーブル一覧取得 step 3 を参照）

入力:

- `lootId`: ルートテーブル ID

出力:

- [[06_1-モデル定義]].ルートテーブル（存在しない場合は `null`）

## 2. JSON パース

### ルートテーブルオブジェクトパース（内部補助）

クラス名: `LootRepository`
物理名: `parseTableObject`

外部公開しない内部補助メソッド。

処理内容:

1. JSON から `schemaVersion`, `id`, `pools` を取得する。
2. `rolls` の固定値または範囲文字列を min/max に分解する。未指定・null・不正値は `1~1`、降順範囲は昇順へ正規化する。
3. table DTO と参照 pool Map を `resolveTable` で結合し、`minRolls` / `maxRolls` と参照解決済み pool を持つ [[06_1-モデル定義]].ルートテーブル を生成する。

### ルートプールオブジェクトパース（内部補助）

クラス名: `LootRepository`
物理名: `parsePoolObject`

処理内容:

1. `contents[]` の `itemId`、`rate`、`amount` を読み取る。`itemId` は prefix を除去し、`amount` の固定値・範囲は min/max へ正規化する。
2. `pick` の固定値または範囲文字列を min/max に分解する。未指定または null は `contents.size`、空 contents は `0~0` とする。
3. 降順範囲は昇順へ正規化し、min/max を `0〜contents.size` にクランプして [[06_1-モデル定義]].ルートプール を生成する。

## 3. API エンドポイント一覧

- `GET /api/loot/table`
- `GET /api/loot/table/{tableId}`
- `GET /api/loot/pool`
- `GET /api/loot/pool/{poolId}`

## 4. ステータスコード方針

- `GET`:
  - `200`: 正常
  - `404`: `null` 返却（警告ログあり）
  - その他: 例外化

## 5. DTO/永続化対応

- DTO: [[06_1-モデル定義]].ルートテーブル
- 永続化相当: `file/loot/table/*`（API 経由で取得）
- 更新主体: なし（読み取り専用）
