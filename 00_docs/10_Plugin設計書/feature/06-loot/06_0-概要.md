# 06_0-概要

## 1. 目的

`loot` 機能は、AstralRecord で扱うルートテーブル（ドロップ抽選定義）のマスタを管理する。
主目的は以下。

- ルートテーブル定義（`LootModel`）の API 取得と起動時一括ロード
- メモリキャッシュ管理と即時参照の提供
- 解決済みルートテーブルの共通独立確率抽選
- `item` の bundle、`mob`、`gathering` からのルート内容参照

## 2. コンテキスト

- 本機能は起動時に `LootService.loadAll` で全ルートテーブルを API から一括取得する。
- `LootRollService` が各 content を `rate`% で独立判定し、bundle・Mob・採集で共通利用する。
- `item` 機能の `ItemStackFactory` はバンドル lore 構築時に [[06_3-サービス]].ロード済み優先ルート取得 を呼び、cache miss 時に単体 API 取得を試みる。
- `MobDropService` は起動時ロード済みキャッシュだけを参照し、抽選中に API I/O を行わない。
- API 経由のみで取得し、キャッシュは正規化済みキー（trim + `:` 接頭辞除去 + 小文字）の不変 `LinkedHashMap` スナップショットとして保持する。`loadAll` はローカル Map の構築完了後に `volatile` 参照へ一括公開する。

## 3. 構成要素（実装単位）

- `service/LootService`
  - 起動時一括ロード、キャッシュ保持、参照・クリア処理を提供する。
- `service/LootRollService`
  - `rolls`、各 pool の `pick` 上限、`contents[].rate`、`amount` に基づく独立確率抽選を提供する。
- `repository/LootRepository`
  - `/api/loot/table`, `/api/loot/table/{tableId}` への HTTP リクエストを実行する。
- [[06_1-モデル定義]].ルートテーブル, ルートエントリ
  - ドロップテーブルとエントリの表現を定義する（詳細は [[06_1-モデル定義]]）。

## 4. 依存関係

- 内部依存
  - `LootService` -> `LootRepository`
- 外部依存
  - AstralRecord API (`/api/loot/table`, `/api/loot/table/{tableId}`)
- 利用側
  - `ItemStackFactory`（[[04_3-サービス]].プロトタイプテンプレート構築 内のバンドルルートロア追加。物理名: `appendBundleLootLore`）
  - `BundleUseService`
  - `MobDropService`（Mob と採集の共通ドロップ確定）

- `item`
  - `ItemStackFactory` のバンドルルートロア追加（[[04_3-サービス]].プロトタイプテンプレート構築 内の内部処理、物理名: `appendBundleLootLore`）で [[06_3-サービス]].ロード済み優先ルート取得 を参照する。
  - `ItemBundle.lootTableId` が本 feature のキャッシュキーとなる。
- `mob` / `gathering`
  - `MobDropService` が `drops.lootTable` をキャッシュから解決し、[[06_3-サービス]].ルートテーブル抽選 の結果を直接ドロップへ結合する。
  - `drops.items[].luckAffected` はキラーの最新 `LUCK` を使って直接ドロップの確率を補正する。

## 5. ライフサイクル登録点

- `AstralRecord#onLoad` で `LootService` を生成
- `AstralRecord#setupFeature` の非同期タスクで `lootService.loadAll()` を実行（`itemService.loadAll()` より先に実行される）
- コマンド・イベントの登録は行わない
