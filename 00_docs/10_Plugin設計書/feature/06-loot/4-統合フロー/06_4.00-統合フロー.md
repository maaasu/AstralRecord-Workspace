# 06_4.00-統合フロー

## 1. 起動時の一括ロード

### シーケンス

```mermaid
sequenceDiagram
    participant P as AstralRecord
    participant S as LootService
    participant R as LootRepository

    P->>S: loadAll（非同期セットアップ）
    S->>S: loadSnapshot
    S->>R: findAll
    R-->>S: table / pool 結合済み LootModel 一覧
    S->>S: 正規化 ID の不変 Map を構築
    S->>S: replaceSnapshot
    S-->>P: ロード件数
```

### 処理要点

- 全件取得が完了するまで公開中キャッシュを変更せず、構築済み不変 Map を一回で `volatile` 参照へ公開する。
- `loadSnapshot` と `replaceSnapshot` を分離し、master reload の prepare / commit に利用できる。
- ID は trim、接頭辞除去、小文字化してキャッシュキーにする。

### 例外・終了条件

- `loadAll` は例外を `LogId.E_5301` で記録し、既存スナップショットを維持して `0` を返す。

## 2. バンドル Lore 表示時の参照

### シーケンス

```mermaid
sequenceDiagram
    participant F as ItemStackFactory
    participant S as LootService
    participant R as LootRepository

    F->>S: getLoadedOrFetch(lootTableId)
    alt キャッシュヒット
        S-->>F: LootModel
    else キャッシュミス
        S->>R: findById(lootTableId)
        R-->>S: LootModel / null
        opt 取得成功
            S->>S: 不変スナップショットへ追加
        end
        S-->>F: LootModel / null
    end
    F->>F: 候補名・個数・確率を Lore 化
```

### 処理要点

- `appendBundleLootLore` はキャッシュ優先で参照し、未ロード時には同期的な単件 API 取得を試みる。
- 解決済みの場合は候補 item の表示名と個数を中心に表示し、loot table 名や item ID を通常表示しない。

### 例外・終了条件

- 未検出または API 例外時は `◆ ルート情報: <lootTableId> (未取得)` を表示する。
- API 例外は `LogId.E_5301` に記録し、`getLoadedOrFetch` は `null` を返す。

## 3. キャッシュクリアと再ロード

### シーケンス

```mermaid
sequenceDiagram
    participant C as 管理経路
    participant S as LootService

    C->>S: clearCache
    S->>S: 空の不変 Map へ原子的に置換
    C->>S: getLoaded / getLoadedLoots
    S-->>C: null / 空リスト
    opt 再ロード
        C->>S: loadAll
    end
```

### 処理要点

- 参照中 Map を変更せず、空 Map への参照置換でクリアする。
- 再ロード完了まではキャッシュ参照結果が空になる。

## 4. bundle 開封抽選

### シーケンス

```mermaid
sequenceDiagram
    participant B as BundleUseService
    participant S as LootService
    participant R as LootRollService
    participant I as InventoryService

    B->>S: getLoadedOrFetch(lootTableId)
    S-->>B: 解決済み LootModel / null
    B->>R: roll(lootModel)
    loop rolls 回 × pool
        R->>R: content を rate% で独立判定
        R->>R: pick 上限超過時だけ無作為に絞込
        R->>R: amount 閉区間抽選
    end
    R-->>B: LootRollResult 一覧
    B->>I: bundle 消費・報酬格納
```

### 処理要点

- `rolls`、`pick`、`amount` は min / max を並べ替えた閉区間から実行ごとに選ぶ。
- rate は `0..100` に clamp し、全候補失敗による報酬なしを許容する。
- inventory に入らない報酬の現行処理と改善方針は item feature の [[04_2.00-ユースケース]] / [[04_9.00-未決事項]] を正本とする。

## 5. Mob・採集ドロップ

### シーケンス

```mermaid
sequenceDiagram
    participant D as MobDropService
    participant S as LootService
    participant R as LootRollService
    participant P as MobDropPresentationService

    D->>D: drops.items を独立確率抽選
    opt luckAffected
        D->>D: 最新 LUCK × 0.05 point を加算
    end
    opt drops.lootTable 指定あり
        D->>S: getLoaded(lootTableId)
        S-->>D: 起動時ロード済み LootModel / null
        D->>R: roll(lootModel)
        R-->>D: table 抽選結果
    end
    D->>D: 直接結果と table 結果を結合
    D->>P: 表示・付与
```

### 処理要点

- Mob・採集のドロップ確定中は `getLoaded` だけを使い、API I/O を行わない。
- Mob は撃破地点、採集は採集オブジェクト地点を表示・付与起点とする。
