# 配置スナップショット

## API 応答の検証

`GET /api/world-placements/{environment}` の応答は `schemaVersion = 1`、空でない `revision`、`placements` 配列を必須とする。行ごとに一意な `placementId`、既知の `kind`、`worldId`、物理 `worldName`、有限の座標・向き、真偽値の `enabled` を検証する。スポナー・NPC では有効な `templateId` と null の `waystone`、ウェイストーンでは null の `templateId` と有効な `waystone` を必須とする。スポナー座標はブロック整数、ウェイストーンの `unlockGold` は非負とする。無効化された行も検証し、実行時には含めない。

重複する `placementId`、有効な同種同座標のスポナー・NPC、同じウェイストーン ID、未知の種別、不正なフィールドが一件でもあれば全件を拒否する。`worldName` のスラッシュを含む既存の Bukkit ワールド名はそのまま保持する。ウェイストーンの `createdAt` または `createdBy` が null の場合は実行時にそれぞれ epoch と `system` を使用する。

## 非同期取得と公開

起動時と `/worldplacements reload` 実行時だけ、Bukkit メインスレッド外で API を一回呼ぶ。通信失敗、非 200 応答、JSON・契約エラーの場合は公開中の全種別を維持する。取得・検証済みの３種類を同じメインスレッド処理で公開し、NPC の再配置とウェイストーン表示更新を行う。公開中のマスターデータ自動再読込では API 配置を取り直さず、配置の現在値を維持する。

起動時の初回 API 取得が成功するまでマスター準備完了状態へ進めない。API モードでは３種類の旧 YAML を正本として読み書きしない。ゲーム内の設置・削除は API モードで先に拒否し、ブロック設置イベントではブロックとアイテムの消費を取り消す。
