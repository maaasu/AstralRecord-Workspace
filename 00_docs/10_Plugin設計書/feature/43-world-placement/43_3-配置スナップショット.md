# 配置スナップショット

## API 応答の検証

`GET /api/world-placements/{environment}` の応答は `schemaVersion = 1`、空でない `revision`、`placements` 配列を必須とする。行ごとに一意な `placementId`、既知の `kind`、`worldId`、物理 `worldName`、有限の座標・向き、真偽値の `enabled` を検証する。スポナー・NPC では有効な `templateId` と null の `waystone`、ウェイストーンでは null の `templateId` と有効な `waystone` を必須とする。スポナー座標はブロック整数、ウェイストーンの `unlockGold` は非負とする。無効化された行も検証し、実行時には含めない。

重複する `placementId`、有効な同種同座標のスポナー・NPC、同じウェイストーン ID、未知の種別、不正なフィールドが一件でもあれば全件を拒否する。`worldName` のスラッシュを含む既存の Bukkit ワールド名はそのまま保持する。ウェイストーンの `createdAt` または `createdBy` が null または空白の場合は実行時にそれぞれ epoch と `system` を使用する。空白、未知、アイテムでない `icon` は従来の YAML 読込と同じく未設定として扱い、表示側で BEACON へフォールバックする。

## 非同期取得と公開

起動時、`/worldplacements reload` 実行時、Dev でのウェイストーン登録後に、Bukkit メインスレッド外で配置を一括取得する。通信失敗、非 200 応答、JSON・契約エラーの場合は公開中の全種別を維持する。取得・検証済みの３種類を同じメインスレッド処理で公開し、NPC の再配置とウェイストーン表示更新を行う。スポナーの同じ座標には追跡中の生存 Mob を引き継ぎ、未変更の定義と配置では探索待機状態も維持する。削除した座標の Mob は通常の Mob ライフサイクルに残し、当該スポナーの追跡から外す。公開中のマスターデータ自動再読込では API 配置を取り直さず、配置の現在値をメインスレッドで維持する。非同期のマスター準備は公開中の配置マップを直接読まない。

起動時の初回 API 取得が成功するまでマスター準備完了状態へ進めない。API モードでは３種類の旧 YAML を正本として読み書きしない。Dev のウェイストーン登録を除くゲーム内の設置・削除は API モードで先に拒否し、ブロック設置イベントではブロックとアイテムの消費を取り消す。

## Dev のウェイストーン登録

`/teleporter set` は、メインスレッドで固定ワールドの論理 ID、Bukkit の物理名、実行時のブロック座標と向きを確定する。非同期で Dev のスナップショットを取得し、その revision を `expectedRevision` にして `PUT /api/world-placements/dev/{placementId}` を送る。作成時の配置 ID とウェイストーン ID は別々に生成する。更新キーは `X-World-Placement-Key` で PUT にだけ送る。409 の場合は競合を通知し、自動再送せずに終了する。200 の場合はスナップショットを検証し、新しい revision の同一行に両方の ID がある場合に保存を確認済みとする。

保存成功後、進行中の再読込があれば完了を待ち、保存後に開始した GET で最新配置を取得・公開する。保存済みのウェイストーンを公開できなければ、保存確認済みの ID と `/worldplacements reload` を案内する。保存結果が不明な場合は再実行前に World Placement Editor で ID を確認するよう案内する。

登録に使う GET と PUT は HTTPS の証明書を検証する。平文 HTTP は loopback の接続先に限る。配置 API への各要求は本文の受信完了までをタイムアウトの対象とする。
