# 14_5-例外・ログ・運用

## 1. ログ

| ID | レベル | テンプレート | 出力箇所 |
|---|---|---|---|
| `LogId.E_5900` | ERROR | `戦闘ダメージ処理に失敗しました: %s` | [[14_3-イベント]].Entity 間 damage 受信 の `runSafely` 例外時 |

## 2. player message

| ID | 用途 |
|---|---|
| `P_5350` | player の与 damage 詳細 |
| `P_5351` | player attack が evade された詳細 |
| `P_5352` | player の被 damage 詳細 |
| `P_5353` | player が evade した詳細 |
| `P_5354` | player が行った HP 回復の詳細（回復対象・回復手段付き） |
| `P_5355` | player が受けた HP 回復の詳細（回復元・回復手段付き） |
| `P_5356` | 自身の HP 回復の詳細（回復手段付き） |

`DAMAGE_LOG_MESSAGE=true` の player だけへ `PlayerMessageService` で送る。上限・回復量増加適用後の実回復量を黄緑色の `+` 付きで表示する。別 player への回復では、回復者へ `P_5354`（`→+実回復量 対象 player | 回復手段`）、回復対象へ `P_5355`（`←+実回復量 回復元 player | 回復手段`）を送る。自身への回復では `P_5356`（`+実回復量 | 回復手段`）だけを送る。回復手段はスキル名、ポーション名、ライフスティール、死亡復帰、NPC 名などの表示名を使う。プレイヤー名・回復手段はカラーコードと改行を除去し、各 12 code point までに短縮するため、メッセージはチャットの2行目へ送らない長さに収める。

HP 自然回復と検証用カカシの定期 HP リセットは常時回復として扱い、回復数値の TextDisplay と HP 回復チャット通知の対象外とする。damage number と player の recovery number は `DAMAGE_LOG_DISPLAY` を別途参照する（Mob の明示的な recovery number は常に表示対象）。

damage message は相手名を表示せず、`→` / `←` で与 damage / 被 damage を区別する。命中時はダメージ値、attack type / element、解決攻撃力、貫通前後の defense、属性がある場合は上限・貫通適用前後の resistance、hit / accuracy / evasion、critical、被弾者の HP スナップショットを英語短縮形式で表示する。ダメージ値は HP / shield を示す接頭辞を付けず、shield break は値の末尾へ `!` を付ける。HP スナップショットは `(現在HP/最大HP->反映後HP)` 形式で表示する。通常会心は `CRIT`、超星会心は `S-CRIT`、回避は `MISS` とする。具体的な読み方は `00_docs/60_戦闘バランス設計書/01-戦闘計算.md` の「ダメージログの読み方」を参照する。

表示値は `DamageResult.breakdown` の計算時 snapshot を使う。整数は `.0` を省略し、それ以外は小数第1位まで表示する。無属性では resistance を省略し、複数属性では属性ごとの resistance を `F` / `I` / `L` で区別する。

## 3. thread / I/O

- Bukkit event、damage 計算、status / Mob state、effect、display はメインスレッドで処理する。
- combat feature 内で SQL / HTTP / YAML I/O を行わず、事前 load 済み snapshot / cache を参照する。
- damage calculator は Bukkit world を変更しない純粋計算とし、乱数 supplier を除く副作用を持たない。

## 4. vanilla damage との整合

- managed entity を含む `EntityDamageByEntityEvent` は combat handler が `NORMAL` で custom damage へ変換し、damage 0 / cancel にする。
- player の全般的な vanilla damage 抑止は player feature の handler を正本とする。
- player HP は `DamageService` から `StatusService.consumeHp` へ実際に反映し、HP 0 で custom death flow を開始する。
- Mob 実体は invulnerable とし、`MobInstance.currentHealth` を正本とする。

## 5. 表示負荷

damage number と recovery number は共有 `DisplayTextService` の TextDisplay を利用し、client interpolation と自動破棄を使う。combat 側で ArmorStand や独自追従 task を追加しない。
