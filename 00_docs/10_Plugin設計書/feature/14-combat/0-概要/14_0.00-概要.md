# 14_0.00-概要

## 1. 目的

combat feature は player と custom Mob の damage 計算、shield / HP 反映、threat・death・表示への副作用を一元管理する。Bukkit の damage 値は custom combat への入口に限定し、managed entity の状態正本にはしない。

## 2. 分類

- attack type は `MELEE`、`RANGED`、`MAGIC`。
- element は `NONE`、`FIRE`、`ICE`、`LIGHTNING`、`POISON`、`LIGHT`、`DARK`。
- scaling は attacker status から基礎値を作る `ATTACKER_STATUS` と、外部の基礎値を使う `FIXED`。
- attack type と element は独立し、1 attack に複数 element ratio を指定できる。

## 3. 計算順序

1. `ATTACKER_STATUS` だけ accuracy - evasion で hit 判定する。
2. scaling に応じて基礎 damage を解決し、element ratio 合計を掛ける。
3. managed attacker は scaling に関係なく critical / super critical を判定する。
4. managed victim の defense を 1 回だけ差し引く。
5. attacker / victim がともに managed の場合は level difference multiplier を掛ける。
6. damage を element ratio で配分し、element increase / resistance / penetration を成分ごとに適用する。
7. condition / temporary skill の最終 multiplier、shield、HP の順に反映する。
8. threat、durability、hurt / death effect、damage number、詳細 message を反映する。

## 4. condition damage

condition damage は専用 multiplier と temporary modifier を適用し、hit、critical、defense、element status を参照しない。`POISON` は victim HP を 1 未満にしない。shield は通常 damage と同じ順で消費する。

## 5. 入力境界

player の左クリック通常攻撃は [[28_4.00-統合フロー]] の winner executor から `DamageService.attack` へ到達する。`CombatDamageEventHandler` は発生済み `EntityDamageByEntityEvent` の変換だけを担当し、入力候補を選び直さない。Mob AI は skill / built-in attack から直接 `DamageService` を呼ぶ。
