# 14_2-ユースケース

## 1. player が Mob を通常攻撃する

1. player-interaction の winner executor が player / Mob を `AstEntity` へ解決する。
2. `DamageService.attack` が attack status、hit、critical、defense、element を計算する。
3. shield または Mob HP を減算し、threat、aggro、knockback、equipment durability を更新する。
4. 通常 Mob が HP 0 なら Mob death / drop、boss なら boss challenge 完了処理へ接続する。`nonLethal=true` の Mob は HP 1 で止め、死亡処理へ進めない。

## 2. skill が複数 element damage を与える

1. skill が attack type と element component list を渡す。
2. defense 適用後の damage を component ratio で配分する。
3. element ごとの damage increase、resistance - penetration を適用して合算する。
4. condition / temporary modifier、shield / HP の順に反映する。

## 3. Mob が player を攻撃する

1. Mob AI の skill または built-in attack が `DamageService.attack` を直接呼ぶ。
2. player shield があれば shield だけ、なければ `StatusService.consumeHp` で独自 HP を減算する。
3. knockback、hurt effect、damage number、詳細 message を反映する。
4. HP 0 の場合は boss participant death または通常 player death flow を開始する。

## 4. condition DoT を適用する

1. condition tick が base damage と condition type を渡す。
2. condition damage / dealt multiplier と temporary modifier を適用する。
3. condition damage は HP 0 まで適用し、死亡条件を満たした場合は通常の death flow へ接続する。
4. shield を参照・減算せず、HP、死亡処理、表示を反映する。hit、critical、defense、element 補正は行わない。

## 5. management 外 Bukkit damage を変換する

attacker / victim のいずれかが managed の `EntityDamageByEntityEvent` は vanilla damage を cancel する。victim が managed、attacker が unmanaged の場合は event の元 damage を `FIXED` として処理する。両者とも unmanaged の場合、combat handler は event を変更しない。ただし victim が Player なら、後続の `PlayerVanillaDamageBlockEventHandler` が Bukkit damage を damage `0`・cancel にする。
