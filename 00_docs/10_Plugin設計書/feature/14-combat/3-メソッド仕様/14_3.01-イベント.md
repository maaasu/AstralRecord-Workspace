# 14_3.01-イベント

## プレイヤー起点攻撃受付

イベント物理名: `PrePlayerAttackEntityEvent`
クラス名: `PlayerInteractionGatewayEventHandler`
物理名: `onPrePlayerAttackEntity`

1. 左クリックsemantic inputを`PlayerInputContext`へ正規化する。
2. NPC等のworld interaction、open action ring、weapon / combat候補を副作用なしで収集する。
3. `PlayerInputDispatcher`でweapon / combat候補が勝った場合だけ通常攻撃executorへ委譲する。
4. world interactionまたはopen action ringが勝った場合はvanilla attackを抑止し、combat処理を開始しない。
5. `PlayerArmSwingEvent`は直接combatを開始せず、semantic eventがない場合だけ次tick fallbackとして扱う。

同一入力の相関、距離・tier比較、event抑止は[[28_3.01-イベント]]と[[28_3.02-サービス]]を正本とする。

## エンティティ間ダメージ受信
イベント物理名: `EntityDamageByEntityEvent`
クラス名: `CombatDamageEventHandler`
物理名: `onEntityDamageByEntity`

優先度 `NORMAL`、`ignoreCancelled = true` で登録する。

本eventは発生済みダメージをcustom combatへ変換する境界であり、トップレベルのプレイヤー入力候補を選び直さない。プレイヤー通常攻撃は上記gatewayの勝者executorから`DamageService.attack(...)`へ直接到達させ、同じ入力を二重実行しない。

1. `runSafely` で [[14_3.02-サービス]].エンティティ間ダメージ確定 を呼び出す
2. 計算式や HP 更新ロジックはここに記述しない
3. 例外発生時は以下ログを記録する

    | 項目 | 内容 |
    |---|---|
    | ID | LogId.E_5900 |
    | レベル | Error |
    | テンプレート | 戦闘ダメージ処理に失敗しました: %s |
    | 出力条件 | `runSafely` で例外発生時 |
    | 引数 | 被弾者エンティティ名（`event.getEntity().getName()`） |
