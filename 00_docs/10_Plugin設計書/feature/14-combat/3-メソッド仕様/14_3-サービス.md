# 14_3-サービス

## 1. damage 計算

SKILL と NORMAL_ATTACK の damage increase は各 source にだけ適用する。`FINAL_DAMAGE_MULTIPLIER` は最終反映前に乗算し、明示値 `0` は damage なしとして扱う。Mob はさらに実行時の `outgoingDamageMultiplier` を乗算し、ボスの参加人数補正を通常攻撃とskillへ共通適用する。現行 enum にない削除済み element は `NONE` へ正規化する。

クラス名: `DamageCalculator`
物理名: `calculate`

`ATTACKER_STATUS` の基礎 attack は次式とする。

```text
statusAttack = (ATTACK + typedAttack) * (1 + primary / 100)
resolvedAttack = max(baseDamage, statusAttack)  // ATTACKER_STATUS
resolvedAttack = baseDamage                     // FIXED
R = max(0, resolvedAttack)
preDefense = R * sum(positive component ratios)
           * sourceDamageMultiplier * attackerDamageMultiplier

normalCriticalMultiplier = critical
    ? (CRITICAL_DAMAGE > 0 ? CRITICAL_DAMAGE : 150) / 100
    : 1
superStarCriticalRate = superStarCriticalRateOverride != null
    ? max(0, superStarCriticalRateOverride)
    : max(0, SUPER_CRITICAL_RATE)
superCriticalPercent = (SUPER_CRITICAL_DAMAGE > 0 ? SUPER_CRITICAL_DAMAGE : 30) / 100
superCriticalMultiplier = !superStarCritical ? 1
    : superStarCriticalMode == ROLL ? 1 + superCriticalPercent
    : superCriticalPercent  // FORCE
criticalApplied = preDefense
                * normalCriticalMultiplier
                * superCriticalMultiplier

D = effectiveGeneralDefense + effectiveTypedDefense
B = 2.5
G = log(0.5) / log(1 - 1 / B)

defenseMultiplier = 0                         // R <= 0。この場合 Q は計算しない
Q = D / R                                     // R > 0 の場合だけ計算
defenseMultiplier = 0                         // R > 0 かつ Q >= B
defenseMultiplier = (1 - Q / B) ^ G           // R > 0 かつ Q < B
postDefense = criticalApplied * defenseMultiplier  // managed victim
```

`R` は component ratio、発生元倍率、攻撃者固有倍率、会心より前の解決攻撃力である。通常会心と超星会心が両方成立した場合は両倍率を乗算し、各倍率が0以下なら通常会心150%、超星会心30%を使う。`ROLL` の超星会心率は `superStarCriticalRateOverride` が指定されていればその一撃だけその値を使い、攻撃者の `SUPER_CRITICAL_RATE` へ加算しない。未指定時は `SUPER_CRITICAL_RATE` を使う。超星会心の主攻撃 `ROLL` は100%へこの30%を加算し、追尾弾 `FORCE` は30%だけを乗算する。`D` は共通防御と攻撃種別防御へ各貫通率を適用した後の合計である。`R <= 0` では `Q` を計算せずダメージを0にする。攻防が同値なら50%軽減し、防御が攻撃の2.5倍以上ならダメージを0にする。防御倍率を会心後ダメージ全体へ掛けるため、skill 倍率や会心倍率が上がっても同じ攻防比率の軽減率は変わらない。

element component ごとは次式とする。

```text
share = postDefense * component.ratio / ratioTotal
effectiveResistance = min(resistance, resistanceCap) - penetration
elementMultiplier = max(0, 1 + increase / 100)
                  * max(0, 1 - effectiveResistance / 100)
finalDamage = sum(share * elementMultiplier)
```

`ATTACKER_STATUS` の managed attacker だけ hit 判定を行う。通常会心は scaling を問わず managed attacker に適用する。超星会心はプレイヤーから攻撃可能 Mob への攻撃だけを対象に通常会心とは独立して判定し、`ROLL` で成立した主攻撃へ `1 + SUPER_CRITICAL_DAMAGE / 100`（未設定時130%）を乗算する。スキル固有の一撃限定率を使う場合も、成立後の主撃倍率と追尾弾生成は共通の超星会心経路を使う。

命中時の `DamageResult.breakdown` には、解決攻撃力、貫通前後の defense、非 `NONE` 属性ごとの上限・貫通適用前後の resistance を同じ計算内で保存する。damage log はこの snapshot を使用し、表示時に status を再取得しない。

`NORMAL_ATTACK` / `SKILL` では、回避・無効化されず有効shieldがない場合だけ、攻撃者の `FIXED_HEALTH_DAMAGE` を計算済み通常damageへ別成分として加算する。この成分には本節の会心・防御・属性・各種倍率を再適用せず、ライフスティールの算出元にも含めない。`DamageScaling.FIXED`、effect damage、condition damageには加算しない。

## 2. 超星会心追尾弾

クラス名: `SuperStarCriticalProjectileService`
物理名: `spawn`

超星会心が成立した主攻撃ごとに、被弾 Mob の身体中央からネザースターの `ItemDisplay` を7個生成する。各追尾弾は水平面のランダムな方位、上向き25～65度の仰角、毎秒3.2～4.8 block の速度を個別に抽選する。初速に直交する単位長のランダムな曲率軸へ、速度長を保ったまま毎 tick 3度旋回しながら10～20 tick 飛行した後、半径24 block 内の最寄りの攻撃可能 Mob を毎 tick 再選択し、毎秒7 block で追尾する。追尾中は現在方向から目標側の曲線方向へ毎 tick 最大15度ずつ旋回し、星ごとにランダムな横方向・位相の揺らぎを合成する。対象までの残距離が1 tickの追尾速度未満なら移動長を残距離へ短縮し、15度の旋回上限を維持したまま、対象直前の揺らぎを減衰して接触へ収束させる。索敵半径24 blockの境界で現在方向と正反対にいる静止対象にも、生成から100 tickの生存期間内に接触へ収束する。対象不在時はその場で再索敵し、生成から100 tick（5秒）で消滅する。

初期飛行・追尾を問わず、1 tick の移動線分で最初に接触した攻撃可能 Mob へ命中して追尾弾は消滅する。生成時に被弾 Mob の当たり判定内から外へ出る区間は接触と数えない。この除外は生成元の UUID だけに適用し、同じ位置に重なる別の攻撃可能 Mob は接触対象とする。生成元除外の終了後は、移動開始点が攻撃可能 Mob の当たり判定内なら即時接触として扱う。命中時は元攻撃と同じ attack type、element component、scaling、source でダメージを再計算する。命中、通常会心、対象防御、属性補正、最終補正を再評価し、超星会心は発生率を再抽選せず `SUPER_CRITICAL_DAMAGE / 100` を `FORCE` で強制適用する。主攻撃 `ROLL` のような100%加算は行わない。追尾弾から追加の追尾弾は生成せず、装備耐久消費とノックバックも発生させない。

## 3. hit chance 計算

クラス名: `DamageCalculator`
物理名: `calculateHitChance`

`clamp(accuracy - evasion, 1, 100)` を返す。100 のときは乱数判定を行わず必ず命中するため、命中率は100%に到達できる。下限を1とするため、回避率だけで完全回避にはならない。Mob の configured accuracy が 0 以下の場合は 100 を既定値にする。通常の `DamageCalculator.calculate(context)` は一撃補正0として扱い、補正付き計算では `accuracy + max(0, attackerAccuracyBonus)` を命中率へ加算してから同じclampを適用する。補正値が有限値でない場合は0として扱う。

## 4. Bukkit damage 変換

unmanaged attacker の Bukkit event damage は event の cancel / zero 化より前に取得し、FIXED damage 入力へ渡す。

クラス名: `DamageService`
物理名: `handleEntityDamage`

projectile shooter を含め attacker / victim を解決する。両者 unmanaged は event を維持する。一方でも managed なら event を cancel / 0 damage とし、victim unmanaged、damage-immune Mob、Mob -> player の event 経路は終了する。managed attacker は `attack`、unmanaged attacker は event damage の `applyDamage` へ接続する。Mob -> player は AI の直接呼び出しを正本とし、event から二重適用しない。

## 5. status scaling attack

クラス名: `DamageService`
物理名: `attack`

attacker / victim、attack type、任意の component list を `DamageScaling.ATTACKER_STATUS` で共通処理へ渡す。component 省略時は無属性 1.0。`attackWithAccuracyBonus` はこの一撃だけ命中率へ加算する補正を指定でき、命中判定以外のダメージ倍率、会心、防御、属性、shield処理は通常の `attack` と同じ経路で処理する。`attackWithSuperStarCriticalChance` はこの一撃だけ超星会心率を指定し、攻撃者の `SUPER_CRITICAL_RATE` へ加算せず `ROLL` の判定へ渡す。

## 6. fixed / effect damage

クラス名: `DamageService`
物理名: `applyDamage`, `applyEffectDamage`

外部 base を `DamageScaling.FIXED` で処理する。`applyDamage` は指定 attack type、`applyEffectDamage` は `MAGIC` / 無属性を使用する。hit は省略するが managed attacker の critical、victim defense、最終 modifier は適用する。

## 7. condition damage

クラス名: `DamageService`
物理名: `applyConditionDamage`

 dead player、damage-immune Mob を除外し、condition 固有 multiplier、dealt multiplier、temporary effect を base に掛ける。condition の基礎値は付与時に付与元の能力値から解決済みであり、対象 HP を参照しない。すべての condition damage は shield の有無と残量を参照せず、shield を減算しないまま HP へ直接反映する。HP 0 に到達した場合は通常の death flow へ接続する。通常 calculator と damage log は通さない。

## 8. Bukkit entity 解決

クラス名: `DamageService`
物理名: `resolveEntity`

projectile shooter、alive `AstPlayer`、`MobService` の entity index の順に解決し、該当しなければ `AstEntity.bukkit` を返す。death flow 中 player は managed player として再解決しない。

## 9. result 反映（内部）

life steal は shield 吸収前の計算値ではなく、固定HPダメージ成分を除いて実際に減少した通常HP damageだけから算出する。正の微小 damage が shield へ入る場合は最低 1 shield を消費し、同じ hit の shield particle は batch 表示する。通常のshield damageは`最低1の換算値 + SHIELD_BREAK`であり、個別skillが正の`shieldBreakMultiplier`を明示したhitだけ、その合計へ倍率を乗算する。個別skillが`SHIELD_BREAK`への比率を明示したhitは、通常の換算値・加算・倍率を使わず、`max(1, SHIELD_BREAK × 比率)`を適用する。現在Shieldで上限を適用した実消費量を`DamageResult.shieldDamage`へ格納する。

クラス名: `DamageService`
物理名: `applyDamageResult`

- `finalDamage <= 0` は shield damage へ変換せず、HP・shield と命中時副作用を変更しない。
- shield damage は shield threat と break / hit effect を反映し、破壊時の余剰と固定HPダメージを含め同hitのHP damageは0とする。
- evade と 0 damage を除き、通常会心は `CRITICAL_HIT_CRIT` と `ENTITY_PLAYER_ATTACK_CRIT`、超星会心は `SUPER_STAR_CRITICAL_BURST_END_ROD` / `SUPER_STAR_CRITICAL_IMPACT` と `ENTITY_FIREWORK_ROCKET_TWINKLE` を被弾対象の身体中央へ反映する。Mob への有効な HP damage では、対象 `LivingEntity#getHurtSound()` が返す被ダメージ音（null の場合は再生しない）と既存の `ENTITY_PLAYER_HURT` を同じ被弾位置で再生する。例えば PIG は `ENTITY_PIG_HURT`、SKELETON は `ENTITY_SKELETON_HURT` となる。shield damage でも会心情報を維持して表示し、両会心が成立した場合は両演出を重ねる。パーティクル表示は `ParticleDisplayService` を経由する。
- player HP は `StatusService.consumeHp` で減算し、HP 0 なら boss participant death または `PlayerDeathService.startDeath` を呼ぶ。
- Mob HP は `MobInstance.currentHealth` へ反映し、player threat / aggro / boss damage を更新する。通常個体は HP 0 なら Mob / boss death を呼ぶ。`nonLethal=true` の個体は実効 HP damage を `min(max(0, currentHealth - 1), finalDamage)` とし、更新後 HP を 1 以上に保って死亡処理を呼ばない。
- HP damage 時だけ attack type に応じた knockback を適用する。倍率は `MELEE=0.55`、`RANGED=0.55`、`MAGIC=0.4` とする。`MobKnockbackService` は対象 UUID ごとに最後の適用から4 tickの受付クールダウンを持ち、クールダウン中は速度を加算しない。

## 10. Shield リチャージ開始・延長

- shield break resultを作った直後に被ダメ側の通常リチャージを開始する。Playerは管理者向けパッシブの有無にかかわらず30秒後に最大Shieldへ一括回復し、Mobは`shield.rechargeTimeSeconds`未設定なら開始しない。
- Playerの設定済み再充填パッシブは、shield breakではなく、ShieldまたはHPへの実ダメージ後も現在Shieldが正数として残る場合だけ、設定待機後の段階回復を開始する。Shield 0、回避、無効、0 damageでは開始しない。
- 基礎時間には開始時点の被ダメ側`SHIELD_RECHARGE_REDUCTION`を適用し、進行中の装備・buff変更では再計算しない。
- 破壊hit自身、またはリチャージ中に実HP damageが発生した`NORMAL_ATTACK` / `SKILL`ごとに、攻撃者の`SHIELD_RECHARGE_DELAY_CHANCE`を抽選する。0以下は失敗、100以上は必ず成功する。
- 成功時は`max(0, SHIELD_RECHARGE_DELAY_SECONDS) × (1 - clamp(被ダメ側短縮率, 0, 100) / 100)`秒を、その時点の残り時間へ上限なく追加する。
- evade、immune、0 damage、condition DoTは抽選しない。順序は「break→開始→同hit抽選・延長」とする。

## 11. level difference

正の基礎 EXP は level difference 補正後も最低 1 を返す。

クラス名: `LevelDifferenceCalculator`
物理名: `damageMultiplier`, `experienceMultiplier`, `scaleExperience`

レベル差を Mob 撃破経験値の倍率へ変換する。ダメージ計算には使用しない。

## 12. 通常攻撃劣化

クラス名: `NormalAttackDegradationService`、`ItemWeaponAttackService`、`WeaponAttackSkillExecutor`
物理名: `beginNormalAttack`、`rollbackNormalAttack`、`currentDamageMultiplier`、`currentAttackSpeedMultiplier`

プレイヤーモードで成功した通常攻撃 cast を1回として、連続回数をプレイヤー単位で保持する。ただし、現在クラスが `adventurer` のプレイヤーは通常攻撃劣化の対象外とし、連続回数・BossBarを保持せず、通常攻撃倍率と攻撃速度倍率を常に等倍とする。Mob がいない空振りも通常攻撃 cast の成功として数えるが、劣化ダメージの適用先は既存のPvE標的選別を通った Mob だけとする。通常攻撃の cast が失敗した場合は連続回数を更新前へ戻し、プレイヤー同士の攻撃には適用しない。

`NORMAL_ATTACK_DEGRADATION_DELAY` の現在値を `d = floor(max(0, totalValue))` として求める。`totalValue` は `StatusService` が計算した現在値であり、1ポイントにつき劣化が発生しない通常攻撃回数を1回追加する。最初の `4 + d` 回は段階0として補正を付与せず、`5 + d` 回目から `通常攻撃劣化[1]` を付与し、段階ごとに次の補正を通常攻撃へ適用する。段階11までの連続回数上限も `d` 回分延長する。ダメージ倍率は既存の通常攻撃 status 補正とは別の一時攻撃者倍率として、通常の命中・会心・防御・属性・shield 計算へ渡す。

| 段階 | 連続回数（`d` を加味） | 通常攻撃倍率 | 攻撃速度補正 |
|:--:|--:|--:|--:|
| 0 | 1〜`4 + d`回 | 100% | なし |
| 1 | `5 + d`回目 | 90% | なし |
| 2 | `6 + d`回目 | 85% | なし |
| 3 | `7 + d`回目 | 85% | なし |
| 4 | `8 + d`回目 | 70% | -10% |
| 5 | `9 + d`回目 | 60% | -20% |
| 6 | `10 + d`回目 | 50% | -30% |
| 7 | `11 + d`回目 | 40% | -40% |
| 8 | `12 + d`回目 | 30% | -50% |
| 9 | `13 + d`回目 | 20% | -50% |
| 10 | `14 + d`回目 | 10% | -50% |
| 11 | `15 + d`回目以降 | 0% | -50% |

段階11を最大段階とする。通常攻撃倍率はダメージ計算の下限である0%へ到達し、段階12以降も実効値が変化しないためである。攻撃速度補正は攻撃停止を避けるため50%減を上限とし、段階8以降は変化させない。

最後の通常攻撃から10秒間、次の通常攻撃がなければ連続回数と劣化段階を0へ戻す。通常攻撃が成功するたびに10秒へ更新する。段階1へ遷移する通常攻撃が成功した時点で `P_5357` を1回送信する。プレイヤーのスキルが成功した場合も通常攻撃劣化を即時解除するが、通常攻撃自身の成功通知は解除対象から除外する。

状態は `BuffService` を使用せず、`NormalAttackDegradationService` の一時 runtime state として管理する。段階が0の場合はBossBarを表示しない。段階が1以上の場合だけ `BarColor.RED` / `BarStyle.SEGMENTED_6` の専用BossBarを表示し、タイトルを `通常攻撃劣化[段階]`、進捗を最後の通常攻撃から10秒までの残り時間として更新する。プレイヤー退出・アカウントモード変更・プラグイン停止時は状態とBossBarを破棄する。
