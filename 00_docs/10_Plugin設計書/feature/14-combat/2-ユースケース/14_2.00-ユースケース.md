# 14_2.00-ユースケース

## 1. バニラ接触ダメージを custom combat に変換する
1. Bukkit が `EntityDamageByEntityEvent` を発火する
2. `CombatDamageEventHandler` が `DamageService.handleEntityDamage(...)` へ委譲する
3. 攻撃者または被弾者が managed entity の場合、イベントをキャンセルする
4. 被弾者が managed entity の場合のみ `DamageService` が custom damage として再適用する
5. 被弾者が custom player なら `StatusService.consumeHp(...)`、custom mob なら `MobInstance.currentHealth` を更新する

## 2. 通常攻撃を custom hit 判定から直接適用する
1. `PlayerInteractionGatewayEventHandler`が`PrePlayerAttackEntityEvent`または左クリックsemantic inputを受ける
2. combat resolverが`FALLBACK`のweapon / combat候補を副作用なしで返し、`stableOrder`で表示中action ringより後、新規action ringより前に順序付ける
3. [[28_3.02-サービス]].勝者選択 でcombat候補が勝った場合だけ`ItemWeaponAttackService`へ委譲する
4. `ItemWeaponAttackService`が`normal_attack`実装のskillを起動する
5. `WeaponAttackSkillExecutor`がparticle / soundを出しつつ、skill paramsに基づいて前方の当たり判定を走査する
6. 走査範囲内のmanaged entityを`DamageService.resolveEntity(...)`で集約する
7. 重複除外後、各targetへ`DamageService.attack(...)`を直接適用する
8. `DamageCalculator`が攻撃者の`ACCURACY`と対象の`EVASION`から命中率を算出する
9. 回避時はHP・Shield・耐久・ノックバックを変更せず、回避TextDisplay / 詳細メッセージだけを設定に従って出力する

NPC、skilltree、gathering、spawner、open action ringなど上位候補が勝った場合は通常攻撃を開始しない。選択済みcombat executorが失敗しても別候補へfallbackしない。

## 3. DoT・デバフダメージを固定値で適用する
1. バフ / デバフや将来の effect tick がダメージ発生を決定する
2. 呼び出し元は被弾者を `AstEntity` へ解決する
3. 固定値ダメージを `DamageService.applyEffectDamage(...)` へ渡す
4. `DamageCalculator` は `DamageScaling.FIXED` として扱い、攻撃者ステータスを上乗せせず最終ダメージを確定する
5. custom player / custom mob の HP を直接更新する
6. `DamageScaling.FIXED` は命中・回避判定を行わず、DoT が tick ごとに回避されないようにする
