# 28_3-イベント

## 1. 右・左クリック受付

イベント物理名: `PlayerInteractEvent`

クラス名: `PlayerInteractionGatewayEventHandler`

物理名: `onPlayerInteract`

1. `PlayerInteractEvent`の初期状態は`Cancellable.isCancelled()`だけで判断しない。AIR interactではvanillaの事前予測により`useInteractedBlock = DENY`、`useItemInHand = DEFAULT`となり得るため、この組み合わせは処理対象とする。`useInteractedBlock`と`useItemInHand`がともに`DENY`の場合だけ、先行handlerによる入力全体の明示cancelとして追加処理せず維持する。
2. `RIGHT_CLICK_AIR` / `RIGHT_CLICK_BLOCK`を`RIGHT_CLICK`、`LEFT_CLICK_AIR` / `LEFT_CLICK_BLOCK`を`LEFT_CLICK`へ正規化する。
3. player、server tick、familyから入力tokenを解決し、main/offhand重複を相関する。
4. [[28_3-サービス]].プレイヤー入力調停を呼び出す。
5. `PlayerInputDispatchResult`の`InputClaimPolicy`に従い、必要な場合だけitem使用・block使用をdenyしてeventをcancelする。
6. 未装填の`HOOKSHOT` tool main hand右クリックは、同一instance・装備条件・非skill詠唱・非牽引を確認できる場合に装填のみの`WORLD_INTERACTION`、`stableOrder = 80`、`CLAIM_AND_CANCEL`候補として収集する。右クリック装填は完了後に自動発射せず、loaded状態を保持する。未装填の左クリックは従来どおり装填候補とし、loaded `HOOKSHOT` toolのmain hand左クリックは同一instanceと24 block以内の固体アンカーを確認できる場合に発射候補として収集する。`RIGHT_CLICK_BLOCK` / `LEFT_CLICK_BLOCK`で`clickedBlock`のAABB入口距離を解決できる場合はその`hitDistance`を使い、generic vanilla block候補と同じ距離で比較する。それ以外はsnapshotの最初の遮蔽blockまでの`hitDistance`を使う。同距離では既存の独自world操作を優先し、generic vanilla block候補（`90`）より先にフックショットを実行する。loadedまたは装填中の右クリック、無効な左クリック照準、loaded・装填中の左クリックは候補を返さず、素材・耐久の業務判定は勝者executorだけが行う。左クリック装填完了時に有効アンカーがあれば`HookshotUseService`が自動発射する。

## 2. entity右クリック受付

イベント物理名: `PlayerInteractEntityEvent`

クラス名: `PlayerInteractionGatewayEventHandler`

物理名: `onPlayerInteractEntity`

1. `PlayerInteractEntityEvent`が初期cancel済みでも、直接対象がserver-side `Interaction` entityの場合はcustom interaction候補を評価する。それ以外のcancel済みentity右クリックは、先行handlerによる外部cancelとして追加処理しない。
2. `RIGHT_CLICK`の入力tokenへ、直接対象entityとsource handを追加する。
3. 同tickの`PlayerInteractAtEntityEvent`または`PlayerInteractEvent`と相関し、同じ論理入力を二重実行しない。
4. plugin候補がない通常entityはworld interactionの`CLAIM`候補として扱い、同一tokenの重複dispatchだけを抑止する。元eventはcancelしない。
5. [[28_3-サービス]].プレイヤー入力調停を呼び出す。

## 3. entity位置指定右クリック受付

イベント物理名: `PlayerInteractAtEntityEvent`

クラス名: `PlayerInteractionGatewayEventHandler`

物理名: `onPlayerInteractAtEntity`

1. [[28_3-イベント]].entity右クリック受付と同じ`RIGHT_CLICK`へ正規化する。
2. 直接対象entity、hand、共通rayをsnapshotへ保持する。entity内クリック位置は現行snapshotへ保持せず、候補比較はAABB入口距離を使う。
3. 同tickのentity右クリック受付が処理済みならexecutorを再実行しない。

## 4. entity左クリック受付

イベント物理名: `PrePlayerAttackEntityEvent`

クラス名: `PlayerInteractionGatewayEventHandler`

物理名: `onPrePlayerAttackEntity`

1. `willAttack=true`かつeventが既にcancel済みの場合は、先行handlerによる外部cancelとして追加処理しない。`willAttack=false`によるPaperの初期cancelは独自interaction候補の評価対象とする。
2. `LEFT_CLICK`のsemantic eventとして入力tokenを確定する。
3. NPC、ウェイストーン、skilltree、gathering、spawner、表示中action ring、攻撃条件guard、weapon、Astral item guard、vanilla combat候補を同じcontextから収集する。
4. `CLAIM_AND_CANCEL`の勝者はvanilla attackを抑止する。`willAttack=true`のvanilla combat候補は`CLAIM`し、元eventをcancelしない。
5. 非action-ring候補が勝った場合、候補guardより前の共通実行直前処理で表示中action ringを閉じる。これは候補executorとは別の入力所有権反映である。

## 5. 腕振りfallback受付

イベント物理名: `PlayerArmSwingEvent`

クラス名: `PlayerInteractionGatewayEventHandler`

物理名: `onPlayerArmSwing`

1. 受信tickではexecutorを呼ばず、`LEFT_CLICK`のpending fallbackとして記録する。
2. 同tickに`PlayerInteractEvent`または`PrePlayerAttackEntityEvent`を観測した場合はfallbackを破棄する。
3. semantic eventがなかった場合だけ、次tickに選択済み勝者の`executeIfValid()`を一回呼び出す。
4. `executionGuard`は`PlayerInteractionSnapshot.refresh()`で現在のray・遮蔽状態を再生成し、現在も同一target・手持ちitem・player状態であるかを再検証する。`false`ならexecutorを見送り、候補を再収集せず敗者へfallbackしない。
5. fallback解決後はpendingを破棄する。ledger entryは前tick参照期間を過ぎた後続相関時、またはquit時に破棄する。

## 6. block設置受付

イベント物理名: `BlockPlaceEvent`

クラス名: `PlayerInteractionGatewayEventHandler`

物理名: `onBlockPlace`

1. eventが既にcancel済みの場合は追加処理しない。
2. `BLOCK_MUTATION`としてMob spawner item、Gathering spawner itemの候補を副作用なしで収集する。
3. [[28_3-サービス]].プレイヤー入力調停で勝者を一件に確定する。
4. Mob spawner itemまたはGathering spawner itemの勝者は`CLAIM_AND_CANCEL`で実blockの設置とvanillaのitem消費を抑止し、座標登録・通知だけを行う。

## 7. block破壊受付

イベント物理名: `BlockBreakEvent`

クラス名: `PlayerInteractionGatewayEventHandler`

物理名: `onBlockBreak`

1. eventが既にcancel済みの場合は追加処理しない。
2. `BLOCK_MUTATION`としてMob spawner座標、Gathering spawner座標の候補を収集する。
3. 同一座標が複数featureの候補になっても、[[28_3-サービス]].プレイヤー入力調停の勝者だけを削除する。
4. 勝者executorが拒否されても別feature候補を実行しない。

## 8. itemドロップ受付

イベント物理名: `PlayerDropItemEvent`

クラス名: `PlayerInteractionGatewayEventHandler`

物理名: `onPlayerDropItem`

1. eventが既にcancel済みの場合は追加処理しない。
2. player、server tick、ドロップ対象item entityとitem stackを`DROP_ITEM` contextへ正規化する。
3. 次の候補を副作用なしで収集する。
   1. 入力ロック: `INPUT_LOCK`、`stableOrder = 0`、`CLAIM_AND_CANCEL`
   2. boss cancel controller: `WORLD_INTERACTION`、`stableOrder = 10`、`CLAIM_AND_CANCEL`
   3. training dummy: `WORLD_INTERACTION`、実体までの命中距離、`stableOrder = 20`、`CLAIM_AND_CANCEL`
   4. menu craft shortcut: `ITEM_USE`、`stableOrder = 90`、`CLAIM_AND_CANCEL`
   5. player-mode normal drop guard: `FALLBACK`、`stableOrder = 500`、`CLAIM_AND_CANCEL`
4. dispatcherは勝者を最大一件だけ実行する。training dummy が勝った場合は共有設定 GUI を開き、menu craft shortcutが勝った場合だけ生成済みitem entityをremoveする。
5. 勝者のpolicyが`CLAIM_AND_CANCEL`なら元eventをcancelする。
6. 候補がなければ未処理とし、通常ドロップとitem entityを変更しない。

## 9. ホットバースロット変更受付

イベント物理名: `PlayerItemHeldEvent`

クラス名: `PlayerInteractionGatewayEventHandler`

物理名: `onPlayerItemHeld`

1. eventが既にcancel済みの場合は追加処理しない。
2. 変更前slotと変更要求先slotを`HOTBAR_SLOT` contextへ正規化する。
3. 次の候補を副作用なしで収集する。
   1. 入力ロック: `INPUT_LOCK`、`stableOrder = 0`、`CLAIM_AND_CANCEL`
   2. displayed action ring guard: `FALLBACK`、`stableOrder = 100`、`CLAIM_AND_CANCEL`
4. displayed action ring guardが勝った場合はslot変更を抑止して現在のring sessionを維持する。ringを新規表示したりsessionを変更したりしない。
5. 候補がなければ未処理とし、通常のslot変更を変更しない。
6. status・equipment・item表示更新などの後続observerは競合候補へ登録しない。eventがcancel済みなら実処理せず、未cancelの通常slot変更だけを反映する。

## 10. スニーク変更受付

イベント物理名: `PlayerToggleSneakEvent`

クラス名: `PlayerInteractionGatewayEventHandler`

物理名: `onPlayerToggleSneak`

1. eventが既にcancel済みの場合は追加処理しない。
2. 変更後のsneaking状態を`SNEAK` contextへ正規化する。
3. 次の候補を副作用なしで収集する。
   1. 入力ロック: `INPUT_LOCK`、`stableOrder = 0`、`CLAIM_AND_CANCEL`
   2. boss entry: `WORLD_INTERACTION`、`stableOrder = 10`、処理成立時`CLAIM`
   3. base / overworld spawn action: `WORLD_INTERACTION`、`stableOrder = 15`、処理成立時`CLAIM`
   4. wall-cling / dodge player control: `FALLBACK`、`stableOrder = 500`、処理成立時`CLAIM`
4. boss entryとworld spawn actionはスニーク開始時だけ候補を返す。world spawn actionは対象地点から水平2メートル以内を成立条件とし、成立後は高低差を含む3D実距離を`hitDistance`へ設定する。同じtierでは近い候補を先に選び、同距離の場合だけ`stableOrder`を比較する。
5. player controlは開始・解除の状態に応じて候補を返す。worldまたはbossが勝った場合は実行しない。
6. `CLAIM`の業務勝者は元eventをcancelせず、vanillaのスニーク姿勢変更を維持する。入力ロックが勝った場合だけ`CLAIM_AND_CANCEL`で姿勢変更を抑止する。
7. 候補がなければ未処理とし、vanillaのスニーク姿勢変更を変更しない。

## 11. プレイヤー退出時入力破棄

イベント物理名: `PlayerQuitEvent`

クラス名: `PlayerInteractionGatewayEventHandler`

物理名: `onPlayerQuit`

1. [[28_3-サービス]].プレイヤー入力状態破棄を呼び出す。
2. 未実行のarm swing fallbackを破棄する。
