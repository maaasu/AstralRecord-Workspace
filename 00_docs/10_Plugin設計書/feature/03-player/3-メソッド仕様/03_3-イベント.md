# 03_3-イベント

## 1. event メソッド仕様

### プレイヤー参加イベント受付

イベント物理名: `PlayerJoinEvent`
クラス名: `PlayerJoinEventHandler`
物理名: `onPlayerJoin`

処理内容:

1. プレイヤーUUIDとプレイヤー名を取得する
2. ロード中プレイヤーとして登録し、現在座標を移動ロック位置として保持する
3. `PlayerMsgId.P_5071` を送信し、ロード中であることを通知する
4. サーバー全体で参加ロード開始間隔を予約し、非同期タスクで [[03_3-サービス]].プレイヤー参加ユーザ読込 を実行する
5. 一定 tick 後に [[03_3-サービス]].プレイヤー参加アカウント読込 を実行する
6. さらに一定 tick 後に [[03_3-サービス]].プレイヤー参加インベントリstate読込 を実行する
7. 参加データが取得できた場合、非同期で [[03_3-サービス]].参加時メニュー導線付与 の準備を行う
8. メインスレッドで quest、skill tree、skill bind preset、[[03_3-サービス]].プレイヤー参加反映 の順に状態を公開し、準備済みならメニューアイテム、通行証の順にローカル反映する
9. プレイヤー参加反映後、[[03_3-サービス]].ログインボーナス表示 を開始する。API取得は非同期、GUI描画だけをメインスレッドで行う
10. 後続 feature の反映まで成功した場合、inventory retained-state lease の現在世代を確定する
11. ロード中登録と移動ロックを解除し、開始からの経過時間をミリ秒で渡して `PlayerMsgId.P_5072`（末尾に灰色の `({0}ms)`）を送信する
12. 非同期で未読メール件数を取得し、1件以上ならクリックでメールGUIを開く件数通知を送信する
13. 一定 tick 後の非同期タスクで [[03_3-サービス]].ログイン履歴登録 を実行する
14. 途中でデータ取得またはメインスレッド反映に失敗した場合は、公開済み状態を player、skill bind preset、skill tree、quest の逆順で破棄し、未公開 inventory state の lease と準備済み装備インスタンスを返却・削除する
15. ロールバック後にロード中登録と移動ロックを解除する
16. 例外時は `LogId.E_5070` を記録する

	| 項目 | 内容 |
	|---|---|
	| ID | `LogId.E_5070` |
	| レベル | `ERROR` |
	| テンプレート | `プレイヤーイベント処理に失敗しました: event=%s, player=%s, reason=%s` |
	| 出力条件 | 参加イベント処理で例外発生時 |
	| 引数 | `PlayerJoinEvent`, プレイヤー名, 例外メッセージ |

### プレイヤー参加ロード中移動抑止

イベント物理名: `PlayerMoveEvent`
クラス名: `PlayerJoinEventHandler`
物理名: `onPlayerMove`

処理内容:

1. 対象プレイヤーがロード中プレイヤーとして登録されているか判定する
2. ロード中でない場合は何もしない
3. `PlayerTeleportEvent` の場合はテレポートを許可し、移動先を新しいロック位置として保持する
4. 通常移動で移動先座標のワールドまたは X/Y/Z がロック位置と異なる場合、移動先をロック位置へ差し戻す
5. yaw/pitch は移動先の値を引き継ぎ、ロード中でも視点変更は許可する

### プレイヤー退出イベント受付

イベント物理名: `PlayerQuitEvent`
クラス名: `PlayerJoinEventHandler`

1. [[03_3-サービス]].プレイヤー退出処理を実行する

3. 非同期タスクで [[03_3-サービス]].ログアウト履歴登録 を実行する
4. 例外時は `LogId.E_5070` を記録する

### プレイヤーモード操作制限

イベント物理名: `InventoryClickEvent` / `InventoryDragEvent` / `PlayerGameModeChangeEvent`

クラス名: `PlayerModeEventHandler`
物理名: `onInventoryClick` / `onInventoryDrag` / `onGameModeChange`

処理内容:

1. AstralRecord 内部で実行したゲームモード変更は連動対象から除外する
2. プレイヤーキャッシュから対象アカウントモードと permission を取得する
3. permission `99` 以上のプレイヤーが ADVENTURE を選択した場合は account mode を `PLAYER`、CREATIVE を選択した場合は `ADMIN` へ更新し、オンライン反映を行う
4. SURVIVAL / SPECTATOR は account mode を変更しない
5. 通常プレイヤーモードの場合、ADVENTURE 以外へのゲームモード変更と通常インベントリ操作をキャンセルする
6. 例外時は `LogId.E_5072` を記録する

	| 項目 | 内容 |
	|---|---|
	| ID | `LogId.E_5072` |
	| レベル | `ERROR` |
	| テンプレート | `プレイヤーモード操作制限処理に失敗しました: %s` |
	| 出力条件 | プレイヤーモード操作制限で例外発生時 |
	| 引数 | プレイヤー名 |

通常プレイヤーモードのitemドロップ抑止は、同クラスの`PlayerInputResolver.resolve`が`DROP_ITEM`候補として提供する。

- account modeが`PLAYER`でなければ候補を返さない。
- `FALLBACK`、`stableOrder = 500`、`CLAIM_AND_CANCEL`の`player-mode-drop-guard`候補を返す。
- 候補収集時はeventをcancelせず、勝者executorにも追加副作用を持たせない。
- input lock、boss cancel、menu craft shortcutのいずれかが勝った場合、本候補は実行しない。候補がなければ通常ドロップを変更しない。

### バニラDMコマンド遮断

イベント物理名: `PlayerCommandPreprocessEvent`
クラス名: `ManagedChatEventHandler`
物理名: `onPlayerCommandPreprocess`

処理内容:

1. 入力コマンドの先頭 token を小文字化し、先頭 `/` と `minecraft:` などの namespace を除去して解決後 command 名を正規化する
2. command 名が `msg` / `tell` / `w` / `whisper` の場合は event をキャンセルする
3. `PlayerMsgId.P_5945` を送信し、管理対象の `/message <player> <text>` 利用を案内する

### 全体チャット受付

イベント物理名: `AsyncChatEvent`
クラス名: `ManagedChatEventHandler`
物理名: `onAsyncChat`

処理内容:

1. vanilla chat event をキャンセルする
2. Adventure Component を plain text 化して trim し、空なら終了する
3. Bukkit メインスレッドへ切り替える
4. `PlayerMessageService.broadcastGlobalChat` でオンラインプレイヤーへ再配信する

例外時挙動:

- `AbstractEventHandler.runSafely` で共通 event 実行失敗 `LogId.E_3002` を記録する

### しゃがみplayer-control候補

入力family: `SNEAK`

クラス名: `PlayerSneakEventHandler`
物理名: `resolve`

処理内容:

1. gatewayが生成した`SNEAK` context以外では候補を返さない
2. [[03_1-モデル定義]].プレイヤーキャッシュ から gameplay処理対象の [[03_1-モデル定義]].プレイヤーセッション を取得する
3. `FALLBACK`、`stableOrder = 500`、`CLAIM`の`player-sneak-control`候補を副作用なしで返す
4. 候補が勝った後のexecutorで、しゃがみ開始時は壁張り付き開始を試行し、成立しなければ地上ドッジ受付開始を実行する
5. しゃがみ解除時は壁張り付き中なら壁張り付き解除を実行し、そうでなければしゃがみ解除ドッジ判定を実行する
6. boss entryまたはworld spawn actionが勝った場合、本executorは実行しない
7. `CLAIM`は元`PlayerToggleSneakEvent`をcancelせず、vanillaのスニーク姿勢変更を維持する
8. executor例外時は`LogId.E_5170`を記録し、他候補へfallbackしない

### 入力イベント受付

イベント物理名: `PlayerInputEvent`
クラス名: `PlayerInputEventHandler`
物理名: `onPlayerInput`

処理内容:

1. [[03_1-モデル定義]].プレイヤーキャッシュ から [[03_1-モデル定義]].プレイヤーセッション を取得する
2. `event.input.jump` の押下状態を [[03_3-サービス]].jump入力処理 へ渡す
3. 例外時は `LogId.E_5171` を記録する

`PlayerInputEvent`はjump状態など連続入力の受付であり、共通入力仲裁の`PlayerInputContext`とは別契約である。候補へ登録せず、[[28_0-概要]].対象外 のままとする。

### プレイヤー入力共通受付

イベント物理名: `PlayerInteractEvent` / `PlayerInteractEntityEvent` / `PlayerInteractAtEntityEvent` / `PrePlayerAttackEntityEvent` / `PlayerArmSwingEvent` / `BlockPlaceEvent` / `BlockBreakEvent` / `PlayerDropItemEvent` / `PlayerItemHeldEvent` / `PlayerToggleSneakEvent`
クラス名: `PlayerInteractionGatewayEventHandler`
物理名: `onPlayerInteract` / `onPlayerInteractEntity` / `onPlayerInteractAtEntity` / `onPrePlayerAttackEntity` / `onPlayerArmSwing` / `onBlockPlace` / `onBlockBreak` / `onPlayerDropItem` / `onPlayerItemHeld` / `onPlayerToggleSneak`

1. Bukkit/Paper eventを`RIGHT_CLICK` / `LEFT_CLICK` / `BLOCK_MUTATION` / `DROP_ITEM` / `HOTBAR_SLOT` / `SNEAK`の`InputFamily`と`InputSource`へ正規化する。
2. 同一物理入力をtick tokenへ相関し、[[28_3-サービス]].プレイヤー入力調停 を呼び出す。
3. `PlayerInputDispatchResult`の`InputClaimPolicy`に従い、勝者確定後にだけeventを抑止する。
4. 詳細なingress別処理順は[[28_3-イベント]]を正本とする。

### プレイヤー退出時入力状態破棄

イベント物理名: `PlayerQuitEvent`
クラス名: `PlayerInteractionGatewayEventHandler`
物理名: `onPlayerQuit`

1. player UUIDに紐づく入力tokenと未実行のarm swing fallbackを破棄する。
2. `PlayerJoinEventHandler.onPlayerQuit`が担当する保存・キャッシュ破棄とは独立に実行する。

### バニラプレイヤーダメージ抑止

イベント物理名: `EntityDamageEvent`
クラス名: `PlayerVanillaDamageBlockEventHandler`
物理名: `onEntityDamage`

処理内容:

1. 対象がプレイヤーか確認する
2. 原因が `VOID` の場合は damage を `0` にして event をキャンセルし、現在 Bukkit ワールドを `WorldService.findByBukkitWorld` で `WorldMasterData` へ逆引きする
3. `WorldMasterData` を解決できた場合は、その `spawnLocation` を奈落ダメージ発生ワールドへ適用し、`WorldService.teleportToSpawnInWorld` で転送する。解決できない場合は Bukkit のワールド既定スポーンへ fallback しない
4. `VOID` 以外では、damage が正で、原因が FALL / FIRE / FIRE_TICK / POISON 以外なら hurt animation と hurt sound を再生する
5. damage を `0` にし、event をキャンセルする

例外時挙動:

- 共通 event 実行失敗 `LogId.E_3002` を対象プレイヤー名付きで記録する

### vanilla死亡受付

イベント物理名: `PlayerDeathEvent`
クラス名: `PlayerDeathEventHandler`
物理名: `onPlayerDeath`

処理内容:

1. inventory と level を保持し、drop と dropped experience を空にする
2. キャッシュ済み `AstPlayer` があれば `PlayerDeathService.startDeath` へ委譲する

### 死亡状態の参加・退出受付

イベント物理名: `PlayerJoinEvent` / `PlayerQuitEvent`
クラス名: `PlayerDeathEventHandler`
物理名: `onPlayerJoin` / `onPlayerQuit`

処理内容:

1. 参加時は `PlayerDeathService.handleJoin` で死亡者の可視性と自身の死亡状態を復元する
2. 退出時は `PlayerDeathService.handleQuit` で title を解除する

### 死亡中移動抑止

イベント物理名: `PlayerMoveEvent`
クラス名: `PlayerDeathEventHandler`
物理名: `onPlayerMove`

処理内容:

1. `PlayerDeathService.lockLocation` が `null` なら何もしない
2. `PlayerTeleportEvent` は許可する
3. world または X/Y/Z が固定地点から変わる場合、移動先を固定地点へ差し戻す
4. yaw / pitch は要求された値を維持する

例外時挙動:

- 死亡関連 event の例外は共通 event 実行失敗 `LogId.E_3002` を対象プレイヤー名付きで記録する
