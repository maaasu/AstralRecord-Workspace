# 03_3.02-サービス

## 1. service メソッド仕様

### プレイヤー参加データ読込

クラス名: `PlayerService`
物理名: `loadPlayerJoinData`

処理内容:

1. [[03_3.02-サービス]].プレイヤー参加ユーザ読込 を実行する
2. ユーザ取得結果が `null` の場合は `null` を返す
3. [[03_3.02-サービス]].プレイヤー参加アカウント読込 を実行する
4. 選択アカウント取得結果が `null` の場合は `null` を返す
5. [[03_3.02-サービス]].プレイヤー参加インベントリstate読込 を実行する
6. [[03_1.00-モデル定義]].プレイヤー参加データ を返す

### プレイヤー参加ユーザ読込

クラス名: `PlayerService`
物理名: `loadPlayerJoinUser`

処理内容:

1. [[01_3.02-サービス]].ユーザ取得 で [[01_1.00-モデル定義]].ユーザモデル を取得する
2. ユーザ取得結果が `null` の場合は `LogId.W_5070` を記録して `null` を返す

	| 項目 | 内容 |
	|---|---|
	| ID | `LogId.W_5070` |
	| レベル | `WARN` |
	| テンプレート | `プレイヤー参加データの取得をスキップしました: player=%s, reason=%s` |
	| 出力条件 | ユーザ取得結果が `null` |
	| 引数 | プレイヤー名, `user not found` |

3. ユーザ取得結果を返す

### プレイヤー参加アカウント読込

クラス名: `PlayerService`
物理名: `loadPlayerJoinAccount`

処理内容:

1. [[02_3.01-サービス]].選択アカウント取得 で [[02_1.00-モデル定義]].アカウントモデル を取得する
2. 選択アカウント取得結果が `null` の場合は `LogId.W_5070` を記録して `null` を返す

	| 項目 | 内容 |
	|---|---|
	| ID | `LogId.W_5070` |
	| レベル | `WARN` |
	| テンプレート | `プレイヤー参加データの取得をスキップしました: player=%s, reason=%s` |
	| 出力条件 | 選択アカウント取得結果が `null` |
	| 引数 | プレイヤー名, `account not found` |

3. アカウント取得結果を返す

### プレイヤー参加インベントリstate読込

クラス名: `PlayerService`
物理名: `loadPlayerJoinInventoryState`

処理内容:

1. 同一アカウントの保存キュー完了を待機する
2. ログアウト保存失敗により保持中の state があれば世代付き lease として取得し、なければ `InventoryPersistence.load(accountId)` を実行する
3. retained state は lease 取得時にも保持一覧から外さない。同一アカウントの後続ログイン試行には同じ state と新しい世代を渡し、旧試行の解放を無効化する
4. state はこの時点では新規公開せず、retained-state lease と組にして返す

### プレイヤー参加トランザクション反映

クラス名: `PlayerService`
物理名: `applyPlayerJoinTransactional`

処理内容:

1. プレイヤーがオンラインかつ未キャッシュであることを確認する
2. Bukkit プレイヤー状態の復元用スナップショットを取得し、[[03_1.00-モデル定義]].プレイヤーセッション を生成する
3. inventory state registry、[[03_3.04-キャッシュ]].プレイヤーキャッシュ、地域状態の順に公開する
4. アカウントモードが通常プレイヤーの場合、inventory feature へ GUI インベントリ反映を依頼する
5. アカウントモードがビルダーまたは管理者の場合、inventory feature へ対応するツールモードスナップショット復元を依頼する
6. [[07_3.02-サービス]].ステータス再計算 を実行する
7. 反映途中の例外時は GUI・地域・プレイヤーキャッシュ・inventory state・Bukkit プレイヤー状態を逆順で復元し、例外を再送出する
8. 後続処理向けに、一回の参加反映だけを識別するロールバック対象を返す

終了条件:

- プレイヤーがオフライン、または同一 UUID が既にキャッシュ済みの場合は `null` を返す

### プレイヤー参加反映ラッパー

クラス名: `PlayerService`
物理名: `applyPlayerJoin`

処理内容:

1. [[03_3.02-サービス]].プレイヤー参加トランザクション反映 を実行する
2. `null` の場合は `false` を返す
3. [[03_3.02-サービス]].プレイヤー参加反映確定 を実行して `true` を返す
4. 確定までに例外が発生した場合は [[03_3.02-サービス]].プレイヤー参加反映ロールバック 後に再送出する

### プレイヤー参加インベントリstate破棄

クラス名: `PlayerService`
物理名: `discardPlayerJoinInventoryState`

処理内容:

1. retained-state lease がある場合は `InventorySaveCoordinator.releaseRetainedStateLease` で後続ログイン試行へ返す
2. lease がない場合は、期待する state インスタンスだけを `InventoryStateRegistry` から削除する

### プレイヤー参加反映確定

クラス名: `PlayerService`
物理名: `commitPlayerJoin`

処理内容:

1. 確定済みまたはロールバック済みなら何もしない
2. retained-state lease がある場合は現在世代を CAS で確定する
3. 確定成功後、参加反映を committed として記録する

例外時挙動:

- lease の所有世代が失効している場合は `IllegalStateException` を送出し、呼び出し元にロールバックさせる

### プレイヤー参加反映ロールバック

クラス名: `PlayerService`
物理名: `rollbackPlayerJoin`

処理内容:

1. 対象参加反映が未ロールバックであることを確認する
2. GUI、inventory state 内部変更、地域状態、当該プレイヤーキャッシュ、クリックガード、inventory state lease、Bukkit プレイヤー状態の順に復元する
3. キャッシュと registry は期待するインスタンスが現在も登録されている場合だけ削除し、後続セッションの状態は変更しない
4. retained-state lease は所有世代が現在世代と一致する場合だけ解放し、後続ログイン試行が取得済みなら何もしない
5. 各復元処理の例外は `LogId.E_5070` で記録し、残りの復元処理を継続する

### ログインボーナス表示

クラス名: `LoginBonusService`
物理名: `openAfterDataLoaded`

処理内容:

1. [[03_3.04-キャッシュ]].プレイヤーキャッシュ取得で [[03_1.00-モデル定義]].プレイヤーセッション を取得する
2. セッション未ロードまたはプレイヤーがオフラインの場合は何もせず終了する
3. 当月（Asia/Tokyo）の `YearMonth` を算出する
4. Plugin 管理の非同期タスクで `LoginBonusClaimRepository` を呼び、AstralRecord API `/api/login-bonus/claims` からアカウントIDごとの当月受け取り済み日付と表示用アイテム定義を取得する
5. 最新の表示 request ID と一致し、プレイヤーが同じアカウントでオンラインの場合だけ、メインスレッドへ戻して `YYYY年M月 ログイン報酬` の月間カレンダー GUI を開く
6. GUI は日曜始まり・土曜終わりの 7 列表示とし、左右端の列はダミーまたは月移動操作に使用する
7. 過去日かつ未受け取りはグレーのテラコッタ、未来の平日は紙、未来の土日または祝日は地図、当日未受け取りは時計、受け取り済み日は受け取り済み表示として描画する

### ログインボーナス受け取り

クラス名: `LoginBonusService`
物理名: `claim`

処理内容:

1. [[03_3.04-キャッシュ]].プレイヤーキャッシュ取得で [[03_1.00-モデル定義]].プレイヤーセッション を取得する
2. セッション未ロード、プレイヤーがオフライン、またはクリック日付が当日（Asia/Tokyo）ではない場合は失敗として終了する
3. プレイヤー単位の in-flight guard を取得し、同時受取操作を拒否する
4. 非同期タスクで報酬 item 定義を取得し、メインスレッドで Gold と休日追加報酬の全量付与可否を事前検証する
5. 非同期タスクで AstralRecord API `/api/login-bonus/accounts/{accountId}/claims` へ当日の受取登録を依頼する
6. DB 側の `dbo.login_bonus_claim` に同一 `account_id + claim_date` が既に存在し、API レスポンスの `wasCreated=false` が返った場合は受け取り済みとして終了する
7. メインスレッドで補償用 inventory state を取得し、`gold` を毎日 `1000`、土日または祝日は追加で `astrald` を `10` 全量付与する
8. 途中付与時は inventory state の復元完了を確認してから、非同期で `DELETE /api/login-bonus/accounts/{accountId}/claims/{claimDate}` を呼んで同日再試行を可能にする。復元失敗時は重複付与防止のため受取登録を取消せず、監査ログを残す
9. 全経路で in-flight guard を解除する。API の `wasCreated=false` は受け取り済みとして `PlayerMsgId.P_5075` を送信し、それ以外の API 通信、事前検証、報酬付与、または取消処理の失敗時は `PlayerMsgId.P_5074` を送信する

    | 項目 | 内容 |
    |---|---|
    | ID | `PlayerMsgId.P_5074` |
    | レベル | - |
    | テンプレート | `ログインボーナス処理に失敗しました。時間をおいて再試行してください。` |
    | 出力条件 | API通信、事前検証、報酬付与、または取消処理が完了しなかった場合。受取済みは除く |
    | 引数 | なし |

受け取り済みの場合は次のメッセージを送信する。

| 項目 | 内容 |
|---|---|
| ID | `PlayerMsgId.P_5075` |
| レベル | - |
| テンプレート | `本日のログインボーナスは受け取り済みです。明日また受け取れます。` |
| 出力条件 | API が `wasCreated=false` を返した場合 |
| 引数 | なし |

### 地上ドッジ受付開始

クラス名: `DodgeService`
物理名: `beginSneakWindow`

処理内容:

1. 既存のドッジ受付状態をクリアする
2. 通常プレイヤー、オンライン、生存、地上であることを確認する
3. しゃがみ開始時刻・しゃがみ開始座標・ドッジ受付終了時刻を [[03_1.00-モデル定義]].プレイヤーセッション へ記録する
4. `hud` feature へドッジ受付バー表示を依頼する

### しゃがみ解除ドッジ判定

クラス名: `DodgeService`
物理名: `tryTriggerOnSneakRelease`

処理内容:

1. ドッジ受付バーを解除し、HUD の ActionBar を通常のリソース表示へ戻す
2. しゃがみ開始時刻・しゃがみ開始座標を取り出し、[[03_1.00-モデル定義]].プレイヤーセッション 側はクリアする
3. ドッジ受付終了時刻をクリアする
4. しゃがみ開始時刻が記録されているか確認する
5. しゃがみ時間が `250ms` 未満か確認する
6. プレイヤーがオンラインかつ生存しており、現在も地上であることを確認する
7. エネルギー不足の場合は失敗音を再生して終了する
8. 条件を満たす場合はドッジを実行する

### ドッジ実行

クラス名: `DodgeService`
物理名: `executeDodge`

処理内容:

1. [[07_3.02-サービス]].EN消費 でエネルギーを `15` 消費する
2. しゃがみ開始座標から現在座標への XZ ベクトルでドッジ方向を計算する（移動量が極小の場合は視線方向にフォールバックする）
3. Bukkit プレイヤーへ速度を設定する
4. [[03_1.00-モデル定義]].プレイヤーセッション のドッジ中フラグを `true` に更新する
5. 効果音・パーティクルを再生する
6. `8tick` 後にドッジ中フラグを解除する

### jump入力処理

クラス名: `AirActionService`
物理名: `handleJumpInput`

処理内容:

1. `PlayerInputEvent` の jump 押下状態を [[03_1.00-モデル定義]].プレイヤーセッション.isJumpInputPressed へ反映する
2. 地上なら [[03_1.00-モデル定義]].プレイヤーセッション.isAirJumpConsumed を解除して終了する
3. 空中で jump 押下が立ち上がった場合のみ、通常プレイヤー・生存・未消費・壁張り付き中でないことを確認する
4. 条件を満たす場合は二段ジャンプを実行する

### 壁張り付き開始

クラス名: `AirActionService`
物理名: `tryStartWallCling`

処理内容:

1. 通常プレイヤー、オンライン、生存、空中であることを確認する
2. 正面近距離のレイ判定で固体ブロックを検出し、壁方向ベクトルを得る
3. [[03_1.00-モデル定義]].プレイヤーセッション へ壁方向・壁張り付き終了時刻・壁張り付き中フラグを記録する
4. 重力を停止し、速度を `0` にしてその場で静止させる
5. `hud` feature へ壁張り付きバー表示を依頼する
6. `1 tick` 間隔タスクで、時間切れまたはスニーク解除まで静止状態を維持する

### 壁張り付き解除

クラス名: `AirActionService`
物理名: `releaseWallCling`

処理内容:

1. 壁張り付き中でなければ何もしない
2. 現在の視線方向と壁方向ベクトルの角度が `120度` 以上離れているか判定する
3. 壁張り付き維持タスクを停止し、重力停止・壁張り付き状態・壁張り付きバー表示を解除する
4. 条件を満たした場合のみ、現在の視線方向へ壁キックを実行する

## 2. メッセージサービス

### メッセージサービス取得

処理内容:

1. plugin の保持インスタンスが初期化済みなら返す

### システムメッセージ送信

クラス名: `PlayerMessageService`
物理名: `send`

入力:

- 宛先: `AstPlayer` / `Player` / `CommandSender` の overload

### 整形済みメッセージ送信

物理名: `sendRaw`

処理内容:

1. `Player` 宛では対話引数を Component 化して共通 prefix を付ける

### Componentメッセージ送信

クラス名: `PlayerMessageService`
物理名: `sendComponent`

処理内容:

### クリック可能メッセージ送信

### ダイレクトメッセージ配信

## 3. 地域サービス

### ログイン時地域初期化

クラス名: `PlayerRegionService`
物理名: `initializeRegion`

処理内容:

1. 保留中の地域 title task をキャンセルする
2. 現在 world の `WorldType.regionDisplayName`、管理外 world では world 名を地域に設定する
3. 地域 level を `0` にし、title は表示しない

### ワールド変更時地域更新

クラス名: `PlayerRegionService`
物理名: `handleWorldChange`

処理内容:

1. world 種別の既定地域と level `0` へ更新する
2. 地域が変わった場合は `45 tick` 後に最新セッション・地域を確認して title を表示する
3. 遅延中にスポナー地域へ変わった場合は最終地域だけを表示する

### スポナー地域更新

クラス名: `PlayerRegionService`
物理名: `updateRegionFromSpawner`

処理内容:

1. OVERWORLD、非空地域名であることを確認する
2. trim 済み地域と `max(0, regionLevel)` をセッションへ反映する
3. 地域が変わり world 変更 title の保留中でなければ即時 title を表示する
4. 地域が実際に変わった場合だけ `true` を返す

### オーバーワールド地域リセット

クラス名: `PlayerRegionService`
物理名: `resetOverworldRegion`

処理内容:

1. OVERWORLD の既定表示名と level `0` で `updateRegionFromSpawner` を呼ぶ

### 地域状態破棄

クラス名: `PlayerRegionService`
物理名: `clearPlayer`

処理内容:

1. 対象 UUID の保留 title task があればキャンセルして削除する

### スポナー地域対象ワールド判定

クラス名: `PlayerRegionService`
物理名: `isSpawnerRegionWorld`

処理内容:

1. `WorldService.resolveWorldType(world) == WorldType.OVERWORLD` を返す

## 4. 死亡サービス

### 死亡開始listener設定

クラス名: `PlayerDeathService`
物理名: `setDeathStartedListener`

処理内容:

1. custom combat 側へ死亡 UUID を通知する listener を置換する

### 死亡更新開始・停止

クラス名: `PlayerDeathService`
物理名: `start` / `stop`

処理内容:

1. `start` は多重起動を無視し、`20 tick` 間隔の死亡状態更新 task を開始する
2. `stop` は task、死亡表示、全死亡状態を破棄する

### 死亡状態開始

クラス名: `PlayerDeathService`
物理名: `startDeath`

入力:

- 基本 overload: `AstPlayer`, 死亡地点
- 拡張 overload: 維持時間、経験値ペナルティ有無、復帰 action

処理内容:

1. 既に死亡中なら `false` を返す
2. 維持時間を最低 `1,000 ms` として死亡状態を登録し、listener を通知する
3. 指定時は現在レベル内経験値の `10%` を減算する
4. HP を全消費し、全 Mob の threat / attacker / target から除外する
5. プレイヤーを死亡地点へ固定・無敵化・非表示化し、頭部と死亡 text、countdown を表示する

### 死亡状態照会・即時復帰・固定位置取得

クラス名: `PlayerDeathService`
物理名: `isDead` / `recoverNow` / `lockLocation`

処理内容:

1. `isDead` は UUID が死亡 map に存在するか返す
2. `recoverNow` はオンラインなら全回復して死亡状態だけを解除し、通常 teleport / recovery action は実行しない
3. `recoverNow` の対象がオフラインなら、次回ログイン時の既定復帰へ切り替える
4. `lockLocation` は死亡地点の clone、非死亡中は `null` を返す

### 死亡中の参加・退出反映

クラス名: `PlayerDeathService`
物理名: `handleJoin` / `handleQuit`

処理内容:

1. `handleJoin` は参加者から他の死亡中プレイヤーを隠し、自身も死亡中なら 2 tick 後に位置・表示・無敵状態を復元する
2. 期限経過済みなら復帰処理を実行する
3. `handleQuit` は title を解除し、死亡 state 自体は保持する
