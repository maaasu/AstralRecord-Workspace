# 03_4-統合フロー

## 1. ログイン反映

### シーケンス

```mermaid
sequenceDiagram
    participant EVT as PlayerJoinEvent
    participant H as PlayerJoinEventHandler
    participant PS as PlayerService
    participant US as UserService
    participant AS as AccountService
    participant IR as InventoryStateRegistry
    participant C as AstPlayerCache
    participant LB as LoginBonusService

    EVT->>H: onPlayerJoin
    H->>H: ロード中登録・移動ロック
    H->>PS: loadPlayerJoinUser（非同期）
    PS->>US: getUser
    H->>PS: loadPlayerJoinAccount（遅延非同期）
    PS->>AS: getSelectedAccount
    H->>PS: loadPlayerJoinInventoryState（遅延非同期）
    H->>PS: applyPlayerJoinTransactional（メインスレッド）
    PS->>IR: inventory state 公開
    PS->>C: AstPlayer 公開
    H->>PS: commitPlayerJoin
    H->>LB: openAfterDataLoaded
    H->>H: ロード中登録・移動ロック解除
    H->>PS: recordLoginHistory（遅延非同期）
```

### 接続前の人数制限

```mermaid
sequenceDiagram
    participant EVT as AsyncPlayerPreLoginEvent
    participant W as WhitelistConnectionEventHandler
    participant U as UserLoginEventHandler
    participant C as PlayerCapacityEventHandler
    participant US as UserService
    participant CS as PlayerCapacityService

    EVT->>W: onAsyncPreLogin
    W-->>EVT: whitelist外ならKICK_OTHER
    EVT->>U: onAsyncPreLogin
    U->>US: 接続前のBAN・ユーザー処理
    U-->>EVT: BANならKICK_OTHER
    EVT->>C: onAsyncPreLogin（HIGHEST）
    C->>US: getUser(uuid)
    C->>CS: tryReserve(uuid, permission)
    alt 枠あり
        CS-->>C: true
    else 枠なし
        CS-->>C: false
        C-->>EVT: KICK_FULL / P_7140
    end
```

- `PlayerCapacityService` はオンライン人数と接続前予約数を同一ロック内で確認し、並行ログインによる枠超過を防ぐ。
- `PlayerCapacityService` のオンライン人数は起動時にメインスレッドで初期化し、`PlayerJoinEvent` / `PlayerQuitEvent` で予約解放と同じロック内から更新する。
- 接続が `PlayerJoinEvent` まで進んだ場合、`PlayerLoginEvent` 以降で拒否された場合、またはワールド参加前に `PlayerConnectionCloseEvent` が発火した場合は UUID の予約を解放する。

### 処理要点

- user、account、inventory state を段階的に非同期取得し、Bukkit 状態と feature 状態の公開だけをメインスレッドで行う。
- player 公開後に quest、skill tree、skill bind preset 等の参加状態を反映し、すべて成功してから retained-state lease を確定する。
- ロード中の通常移動は固定位置へ戻すが、yaw / pitch と `PlayerTeleportEvent` は許可する。
- ログインボーナスは参加データ公開後に非同期取得し、最新 request ID と同一アカウントを確認して GUI を開く。

### 例外・終了条件

- 途中失敗時は公開済み feature を逆順に破棄し、`PlayerService.rollbackPlayerJoin` で Bukkit 状態と retained-state lease を復元する。
- 失敗時もロード中登録と移動ロックを解除し、`LogId.E_5070` を記録する。

## 2. ログアウト保存

### シーケンス

```mermaid
sequenceDiagram
    participant EVT as PlayerQuitEvent
    participant H as PlayerJoinEventHandler
    participant PS as PlayerService
    participant SC as PlayerSaveCoordinator
    participant C as AstPlayerCache
    participant IG as PlayerInteractionGatewayEventHandler
    participant L as PlayerInputSequenceLedger
    participant US as UserService

    EVT->>H: onPlayerQuit
    H->>PS: onPlayerQuit
    PS->>SC: save(LOGOUT)
    PS->>C: remove
    EVT->>IG: onPlayerQuit
    IG->>L: clear(playerUuid)
    IG->>IG: pendingArmSwings を削除
    H->>PS: recordLogoutHistory（非同期）
    PS->>US: recordHistory(PLAYER_LOGOUT)
```

### 処理要点

- 保存要求を発行してから `AstPlayerCache` からセッションを削除する。
- 共通入力 gateway は同じ退出イベントで tick token と pending arm swing を破棄する。保存処理との順序依存はない。

### 例外・終了条件

- 保存失敗時の inventory state 保持・再試行は [[03_3-保存]] を正本とする。
- 退出イベント処理の例外は `LogId.E_5070` で記録する。

## 3. プレイヤー入力共通入口

### シーケンス

```mermaid
sequenceDiagram

    participant G as PlayerInteractionGatewayEventHandler
    participant L as PlayerInputSequenceLedger
    participant D as PlayerInputDispatcher
    participant R as PlayerInputResolver群
    participant X as 勝者executor

    EVT->>G: onPlayerInteract 等
    G->>L: tick token 相関
    G->>D: dispatch(context)
    D->>R: resolve(context)
    R-->>D: 副作用なし候補
```

### 処理要点

- 右・左クリック、block mutation、item drop、hotbar slot、sneak を `InputFamily` / `InputSource` へ正規化する。
- player feature は `DROP_ITEM` の player-mode guard と `SNEAK` の wall-cling / dodge fallback を提供する。
- 候補の優先順位、距離比較、arm swing の次 tick fallback は [[28_4-統合フロー]] を正本とする。

## 5. プレイヤー死亡と復帰

### シーケンス

```mermaid
sequenceDiagram
    participant EVT as PlayerDeathEvent / custom combat
    participant H as PlayerDeathEventHandler
    participant DS as PlayerDeathService
    participant AS as AccountService
    participant SS as StatusService
    participant MS as MobService
    participant WS as WorldService

    EVT->>H: onPlayerDeath または startDeath 呼び出し
    H->>DS: startDeath(astPlayer, location)
    DS->>AS: loseCurrentLevelExperiencePercentCached(10%)
    DS->>SS: consumeHp(currentHp)
    DS->>MS: threat / attacker / target を解除
    DS->>DS: 10秒の固定・非表示・死亡演出
    loop 20 tick ごと
        DS->>DS: countdown / 期限判定
    end
    DS->>SS: restoreAll
    DS->>WS: teleportToSpawnAsync
```

### 処理要点

- vanilla 死亡では inventory、level、drop を保持し、AstralRecord の死亡状態へ統合する。
- 死亡中は無敵化して他プレイヤーから隠し、死亡地点へ固定する。テレポートイベントは移動固定の対象外とする。
- 期限終了時は全リソースを回復し、指定 recovery action または参加スポーンへ復帰する。

### 例外・終了条件

- 既に死亡中の場合、`startDeath` は `false` を返して二重開始しない。
- イベント処理失敗は共通 event 実行失敗 `LogId.E_3002` を記録する。

## 6. vanilla damage 抑止と奈落復帰

### シーケンス

```mermaid
sequenceDiagram
    participant Bukkit as EntityDamageEvent
    participant Handler as PlayerVanillaDamageBlockEventHandler
    participant World as WorldService
    participant Teleport as PlayerTeleportService
    Bukkit->>Handler: onEntityDamage
    alt player-vs-player and both PvP flags enabled
        Handler-->>Bukkit: custom combatへ委譲（抑止しない）
    else other player damage
        Handler->>Bukkit: damage=0 / cancel
        alt cause == VOID
            Handler->>World: findByBukkitWorld(player.getWorld())
            World-->>Handler: WorldMasterData
            Handler->>World: teleportToSpawnInWorld(player, data, player.getWorld())
            World->>Teleport: current world + master spawn coordinates
        else other vanilla cause
            Handler-->>Bukkit: cancel only
        end
    end
```

### 処理要点

- プレイヤー間の `EntityDamageByEntityEvent` は、攻撃者・被弾者の `AstPlayer.isPvpEnabled` が両方 `true` の場合だけ抑止せず、`CombatDamageEventHandler` のcustom combat変換へ渡す。フラグの既定値は `false` とする。
- 上記以外のプレイヤーへの Bukkit `EntityDamageEvent` は damage を 0 にしてキャンセルする。
- `VOID` では、奈落ダメージを受けた Bukkit ワールドを維持し、そのワールドに WorldMasterData の `spawnLocation` を適用して転送する。
- WorldMasterData を逆引きできない場合は Bukkit の既定スポーンへ fallback せず、damage のキャンセルだけを行う。
- 転送は `PlayerTeleportService` 経由で行い、転送前のプレイヤーの yaw / pitch を維持する。

## 7. 拠点石ボタンのブロックリーチ

- `setupFeature` で `WorldService` のワールド定義をロードした後、`StoneButtonReachService` を生成する。
- プラグインの機能登録完了時にサービスを開始し、メインスレッドの `20 tick（1 秒）` 周期で `AstPlayerCache` の `AccountMode.PLAYER` を確認する。
- 現在ワールドが拠点で、初期スポーンから三次元距離 `15` メートル以内にいる場合だけ、目線の先を最大 `4.5` ブロック ray trace する。
- 最初のヒットが石ボタンならブロックリーチを `4.5`、それ以外なら `0` にする。拠点以外、範囲外、対象外アカウントではリーチを拡張しない。
- `AccountMode.PLAYER` の `PlayerInteractEvent` によるブロッククリックは、拠点初期スポーンから `15` メートル以内の `Material.STONE_BUTTON` だけを許可し、それ以外を入力 gateway の `CLAIM_AND_CANCEL` でキャンセルする。
- プラグイン停止時は更新タスクを停止し、プレイヤーモードのブロックリーチを `0` に戻してからオンラインプレイヤーの停止保存へ進む。
