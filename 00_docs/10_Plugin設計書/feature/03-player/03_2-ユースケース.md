# 03_2-ユースケース

## 1. ログイン反映

- 契機: `PlayerJoinEvent`
- 非同期処理: [[03_3-サービス]].プレイヤー参加データ読込
- メインスレッド処理: [[03_3-サービス]].プレイヤー参加トランザクション反映、後続 feature 成功後の [[03_3-サービス]].プレイヤー参加反映確定
- 結果: [[03_1-モデル定義]].プレイヤーセッション を構築して [[03_1-モデル定義]].プレイヤーキャッシュ へ登録し、参加反映後に `PassiveSkillService` が有効パッシブを再同期する

## 2. ログアウト保存

- 契機: `PlayerQuitEvent`
- 処理: キャッシュ削除前に有効パッシブの実行状態を破棄し、[[03_3-サービス]].プレイヤー退出処理を実行する
- 結果: 保存タスクを実行し、プレイヤーキャッシュから削除する

## 3. プレイヤーモード操作制限

- 契機: インベントリクリック、インベントリドラッグ、アイテムドロップ、ゲームモード変更
- 条件: [[03_1-モデル定義]].プレイヤーセッション.account.mode が通常プレイヤー
- 結果: 対象操作をキャンセルする

## 4. ドッジ発動

- 契機: 地上でしゃがみ開始後、短時間で地上しゃがみ解除
- 条件: オンライン、生存、地上、エネルギー十分
- 結果: エネルギーを消費し、しゃがみ開始時座標から解除時座標へのベクトル（移動なしの場合は視線方向）を方向とした移動ベクトル・演出・ドッジ中フラグを反映し、成功したドッジをドッジ連動パッシブへ通知する

## 5. 二段ジャンプ

- 契機: 滞空中に `PlayerInputEvent` で jump 押下が立ち上がる
- 条件: オンライン、生存、通常プレイヤー、現在の滞空中で未使用
- 結果: スタミナ消費なしで上方向 + 視線前方へ速度を加え、同じ滞空中では再発動しない

## 6. 壁張り付き / 壁キック

- 契機: 滞空中にスニーク開始、または壁張り付き中にスニーク解除
- 条件: 壁張り付き開始時は空中で正面近距離に固体ブロックがあること。壁キック時は壁張り付き中に壁方向から `120度` 以上背を向けて解除すること
- 結果: スタミナ消費なしで一定時間その場に停止し、時間切れまたはスニーク解除で落下へ戻す。条件を満たしたスニーク解除時のみ向いている方向へ壁キックする

## 7. 全体 chat と direct message

- 全体 chat 契機: `AsyncChatEvent`
- 全体 chat 結果: vanilla 配信をキャンセルし、plain text 化した本文を `PlayerMessageService` の形式でオンライン全員へ再配信する
- 全体 chat 本文: `Component.text` として追加するため、プレイヤー入力の `&c` などはカラーコードへ変換せず、そのまま表示・中継する
- DiscordSRV連携: `discord.globalChannelId` とDiscordSRVの `global` channelが一致する場合だけ、Minecraft全体 chat とDiscord雑談を相互中継する。Discord側はDiscordSRVのアカウントリンク済みユーザーだけを受け付ける
- direct message 契機: `/message <player> <message>`
- direct message 条件: 宛先が完全一致するオンラインの別プレイヤーで、本文が空でないこと
- direct message 結果: 送信者用・受信者用の別メッセージを送る。vanilla の `/msg` / `/tell` / `/w` / `/whisper` は同じ引数を保持して `/message` へ変換する
- vanilla の `/say <message>` は管理全体チャットとして配信し、引数なしの場合は空本文メッセージを返す

## 8. 地域更新

- 契機: ログイン、world 変更、オーバーワールドのスポナー地域出入り
- 処理: world 種別の既定地域、またはスポナー定義の地域名と平均 Mob level をセッションへ反映する
- 結果: 地域変更時に title を表示する。world 変更直後は既存 world title と競合しないよう `45 tick` 遅延する

## 9. 死亡と復帰

- 契機: custom combat の HP 枯渇、または `PlayerDeathEvent`
- 処理: inventory / level / drop を保持し、現在レベル内経験値の `10%` を減算して HP を 0 にする
- 死亡中: 死亡地点へ固定、無敵、他プレイヤーから非表示とし、頭部・死亡 text・countdown を表示する
- 結果: 10 秒後に全リソースを回復し、指定 recovery action または参加スポーンへ戻す

## 10. vanilla damage 抑止

- 契機: プレイヤーへの Bukkit `EntityDamageEvent`
- 結果: 原因にかかわらず damage を 0 にしてキャンセルし、バニラ由来の hurt animation / sound は再生しない。`VOID` では現在ワールドの `WorldMasterData.spawnLocation` へ戻す

## 11. whitelist メンテナンス

- 契機: 管理者またはコンソールによる `/whitelist [enable <true|false>|user <add|remove> <playerName>]` / `/wl [enable <true|false>|user <add|remove> <playerName>]`
- 状態変更: 引数なしは現在値を反転し、`enable` の第2引数は `true` / `false` を受け付けて `plugin.whitelistEnabled` へ保存する
- ユーザー設定: `user add|remove <playerName>` はAPIに登録されたMinecraftユーザー名をUUIDへ解決し、`plugin.whitelistUsers` を更新して `config.yml` へ保存する。未登録ユーザー名では設定を変更しない
- 補完: `WhitelistTabCompleter` はサブコマンド、真偽値、操作種別、第3引数のオンラインプレイヤー名を提示する。DB登録有無は実行時に確認する
- 接続条件: 有効時は `plugin.debugUsers` または `plugin.whitelistUsers` に UUID が含まれるプレイヤーを `AsyncPlayerPreLoginEvent` で許可する。両方が空集合の場合は全員拒否する
- 設定値: `debugUsers` / `whitelistUsers` の各要素は前後空白を除去して UUID として解析し、不正な UUID と空値は無視する。`ConfigProperties.reload()` 実行後は再読み込みした設定を接続判定へ反映する
- 権限: `plugin.debugUsers` のプレイヤーは既存どおりデバッグユーザーとして扱い、`plugin.whitelistUsers` のみに含まれるプレイヤーは接続だけを許可し、デバッグユーザー向けの権限例外は与えない。両方に含まれる場合はデバッグユーザーとして扱う
- 有効化時: debugUsers / whitelistUsers のいずれにも含まれない接続中プレイヤーをキックし、メンテナンス開始による遮断理由を表示する
- DiscordSRV: 有効時は Minecraft→Discord の全体 chat と起動・停止・プレイヤー参加・初回参加・退出通知を止め、Discord→Minecraft の受信を継続する

## 12. 権限別接続人数制限

- 契機: `AsyncPlayerPreLoginEvent`
- 設定: `config.yml` の `playerCapacity.maxPlayers`、`playerCapacity.donorExtraPlayers`、`playerCapacity.adminExtraPlayers`
- 接続枠: `maxPlayers` は `PLAYER` 用の基本枠、`donorExtraPlayers` は `DONOR` 以上（`ADMIN` を含む）の追加枠、`adminExtraPlayers` は `ADMIN` だけの追加枠とする
- 判定: `user.permission < UserPermission.DONOR(5)` は基本枠まで、`DONOR(5)` 以上は基本枠 + 寄付者追加枠まで、`ADMIN(99)` 以上はさらに管理者追加枠まで許可する
- 占有数: 接続中プレイヤー数と接続前予約数を合算して判定する。同一 UUID の予約は二重計上しない
- 例: `30 / 5 / 1` の場合、通常プレイヤーは30人まで、寄付者以上は35人まで、管理者は36人まで参加できる
- 接続枠を使い切った場合は `AsyncPlayerPreLoginEvent.Result.KICK_FULL` と `PlayerMsgId.P_7140` で拒否する。参加・退出、後続ログイン段階での拒否、またはワールド参加前の `PlayerConnectionCloseEvent` で接続前予約を解放する
