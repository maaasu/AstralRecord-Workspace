# 03_0-概要

## 1. 目的

`player` 機能は、オンライン中のプレイヤー状態を [[03_1-モデル定義]].プレイヤーセッション として保持し、ログイン反映・ログアウト保存・プレイヤーモード制御・AFK判定・移動 action・地域・メッセージ・死亡状態を管理する。

## 2. コンテキスト

- ログイン時は user/account/inventory state のAPI取得を非同期かつ段階的に行い、Bukkit API 操作のみメインスレッドに戻す。
- ログインデータロード中はプレイヤーの座標移動をロックし、ロード完了後に解除する。
- オンライン中の他 feature は [[03_1-モデル定義]].プレイヤーキャッシュ 経由で状態を参照する。
- プレイヤーモードではインベントリ操作・ドロップ・ゲームモード変更を制限する。

## 3. 構成要素（実装単位）

- `event/PlayerJoinEventHandler`
  - ログイン・ログアウトイベントを受け、PlayerService に委譲する。
  - 参加時データロードの開始間隔と段階実行を制御し、ロード中の移動を抑止する。
- `feature/whitelist/service/WhitelistService`, `feature/whitelist/command/WhitelistCommand`
  - `plugin.whitelistEnabled` を永続化し、`plugin.debugUsers` または `plugin.whitelistUsers` に含まれる UUID でメンテナンス接続を制御する。
- `feature/whitelist/event/WhitelistConnectionEventHandler`
  - `AsyncPlayerPreLoginEvent` で whitelist 外の接続を拒否する。
- `feature/player/service/PlayerCapacityService`, `feature/player/event/PlayerCapacityEventHandler`
  - `playerCapacity.maxPlayers` を通常プレイヤーの基本枠とし、`donorExtraPlayers` を寄付者以上、`adminExtraPlayers` を管理者だけの追加枠として接続前に適用する。
  - 接続前予約をオンライン人数と合わせて数え、並行したログイン試行で枠を二重消費しないようにする。
- `event/PlayerModeEventHandler`
  - 通常プレイヤーモード中のインベントリクリック・ドラッグ・アイテムドロップ・ゲームモード変更の操作制限を行う。
- `event/PlayerSneakEventHandler`
  - しゃがみ操作からドッジ発動候補または壁張り付きを検出する。
- `event/PlayerInputEventHandler`
  - jump 入力の立ち上がりを検出し、二段ジャンプを委譲する。
- `afk/event/AfkPlayerEventHandler`, `afk/service/AfkService`
  - 前後左右入力と位置差を用いてAFK状態をセッション内で判定する。
  - AFK中は title、Tab表示名、頭上TextDisplayへ状態を反映し、Mob・採集のEXPと自動ドロップ付与を抑止する。
- `event/ManagedChatEventHandler`, `command/DirectMessageCommand`
  - vanilla chat を管理形式へ置換し、`/message` のオンライン direct message を提供する。
- `feature/discord/service/DiscordSrvChatBridge`
  - DiscordSRVの`global` channelとMinecraft全体 chatを相互中継し、Discord受信側はアカウントリンク済みユーザーだけを受け付ける。
- `event/PlayerVanillaDamageBlockEventHandler`
  - プレイヤーの vanilla damage を抑止し、custom combat 側へ被ダメージ責務を限定する。奈落時は現在ワールドのマスタースポーンへ戻す。
- `death/PlayerDeathEventHandler`, `death/PlayerDeathService`
  - vanilla/custom combat の死亡を一時死亡状態へ統合し、固定・表示・経験値ペナルティ・復帰を管理する。
- `service/PlayerService`, `DodgeService`, `AirActionService`, `PlayerMessageService`, `PlayerRegionService`, `StoneButtonReachService`
  - プレイヤーセッション構築、保存、移動 action、メッセージ配信、地域更新を制御する。
  - 拠点初期スポーン付近の石ボタン注視時だけ、プレイヤーモードのブロックリーチを一時的に 4.5 へ変更する。
- [[03_1-モデル定義]].プレイヤーキャッシュ
  - オンライン中のプレイヤーセッションを保持する。
  - 実装単位は `AstPlayerCache`。
- `save/*`
  - ログアウト・プラグイン停止時などの保存タスクを調整する。
- `shared/interaction/*`
  - Bukkit/Paper 入力を共通 token へ相関し、全 feature の候補から勝者一件だけを実行する。

## 5. 依存・連携

- `user`
  - [[01_3-サービス]].ユーザ取得 で [[01_1-モデル定義]].ユーザモデル を取得する。
  - [[01_1-モデル定義]].ユーザモデル を [[03_1-モデル定義]].プレイヤーセッション に保持する。
- `account`
  - [[02_3-サービス]].選択アカウント取得 で [[02_1-モデル定義]].アカウントモデル を取得する。
  - [[02_1-モデル定義]].アカウントモデル を [[03_1-モデル定義]].プレイヤーセッション に保持する。
- `inventory`
  - 通常プレイヤーのインベントリGUI反映と保存タスクで連携する。
- `status`
  - ログイン時は [[07_3-サービス]].ステータス再計算、ドッジ時は [[07_3-サービス]].ENG消費 で連携する。
- `class` / `playerclass`
  - [[03_1-モデル定義]].プレイヤーセッション の `classId` とクラス ID ごとの独立した `classLevel` / `classExperience` を保持する。職業マスタ、職業 GUI、職業コマンドの正本は本 feature ではなく class / playerclass 側とする。
- `player-interaction`
  - 右クリック、左クリック、block mutation、item drop、hotbar slot変更、sneak変更の共通入口と候補仲裁は[[28_0-概要]]を正本とする。共通gatewayは`shared/interaction`へ配置し、player featureは入力ロック、player-mode drop guard、wall-cling / dodge fallback、プレイヤー状態、退出ライフサイクルを提供する。

- `hud` / `mob` / `gathering`
  - AFK状態は `PlayerClassService` のTab表示、`OverheadDisplayService` の頭上TextDisplay、Mob・採集報酬のEXPと自動ドロップ付与で参照する。

- `DiscordSRV`
  - `global` channelのDiscord雑談とMinecraft全体 chatを中継する。Discord受信はDiscordSRVのアカウントリンク状態を確認し、通常のDiscordSRV配信をAstralRecord形式へ置き換える。
- whitelist 有効時は DiscordSRV の `DiscordChatChannelMinecraftToDiscord` を一時的に無効化し、Minecraft→Discord の全体 chat と起動・停止・プレイヤー参加・初回参加・退出通知を抑制する。`DiscordChatChannelDiscordToMinecraft` は変更せず、Discord→Minecraft の受信は維持する。

- `loginbonus`
  - 実装は独立パッケージだが、設計書では player join 導線として本 feature に含める。
  - ログイン時の自動表示と NPC の `LOGIN_BONUS` action から `LoginBonusService` を呼び出す。
