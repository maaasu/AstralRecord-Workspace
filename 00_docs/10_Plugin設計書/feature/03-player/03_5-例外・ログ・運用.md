# 03_5-例外・ログ・運用

## 1. 方針

`player` 機能はオンライン中状態の境界であり、イベント境界では `runSafely` により例外漏れを防ぐ。保存処理は個別タスクで失敗しても後続タスクを継続する。

## 2. 主なログポイント

- `PlayerJoinEventHandler`
  - ログイン・退出イベント異常: `LogId.E_5070`
  - 参加データ読み込みの再試行待機中断: `LogId.E_5073`
- `PlayerModeEventHandler`
  - プレイヤーモード操作制限イベント異常: `LogId.E_5072`
- `PlayerService`
  - user/account 取得失敗: `LogId.W_5070`
- `PlayerSaveCoordinator`
  - 保存タスク失敗: `LogId.W_5071`
- `PlayerSneakEventHandler`
  - しゃがみイベント異常: `LogId.E_5170`
- `PlayerInputEventHandler`
  - 入力イベント異常: `LogId.E_5171`
- `ManagedChatEventHandler`
  - chat / vanilla message command イベント異常: `LogId.E_3002`
- `DiscordSrvChatBridge`
  - DiscordSRV未導入、設定不備、初期化失敗: `LogId.W_7100` / `LogId.W_7101` / `LogId.W_7102`
  - MinecraftからDiscordへの送信失敗: `LogId.E_7100`
- `WhitelistService` / `DiscordSrvChatBridge`
  - DiscordSRV messages.yml の起動・停止通知をランタイム値だけで抑制できない場合: `LogId.W_7110`
- `PlayerDeathEventHandler` / `PlayerVanillaDamageBlockEventHandler`
  - 死亡状態・vanilla damage イベント異常: `LogId.E_3002`
- `PlayerVanillaDamageBlockEventHandler`
  - `VOID` の発生ワールドを WorldMasterData へ解決できない場合は Bukkit の既定スポーンへ fallback せず、damage のキャンセルだけを行う。
  - WorldMasterData のスポーン地点転送が失敗した場合は `LogId.W_5753` を記録する。
- [[03_1-モデル定義]].プレイヤーセッション
  - OP権限付与: `LogId.I_5070`
  - OP権限付与メッセージ: `PlayerMsgId.P_5070`

## 3. スレッド上の注意

- user/account 取得は非同期タスクで実行する。
- Bukkit API を触るプレイヤー参加反映はメインスレッドで実行する。
- メインスレッドの参加反映は feature ごとの公開順を記録し、例外時は公開済み状態だけを逆順でロールバックする。
- ロールバック中の個別例外は `LogId.E_5070` に記録し、後続の解放処理を継続する。
- `AsyncChatEvent` は非同期で受け、全体 chat の Bukkit 配信だけをメインスレッドへ切り替える。
- 地域 title、死亡 countdown、死亡表示、`AstPlayer` / Bukkit 状態の変更はメインスレッドで行う。
- `StoneButtonReachService` のワールド解決、ray trace、ブロックリーチ属性変更はメインスレッドの `20 tick` 周期で行う。拠点初期スポーンから `15` メートルを超えた場合や石ボタン以外を見た場合は、プレイヤーモードのブロックリーチを `0` に戻す。

## 4. chat・ダイレクトメッセージ

| ID | 用途 |
|---|---|
| `P_5940` | system message 共通 prefix |
| `P_5941` | 全体 chat |
| `P_5942` | party chat |
| `P_5943` | direct message 送信者表示 |
| `P_5944` | direct message 受信者表示 |
| `P_5945` | 旧 vanilla DM command 遮断案内（現行の変換処理では未使用） |
| `P_5946` | direct message 空本文 |
| `P_5947` | direct message 自分宛拒否 |
| `P_6990` | Discord受信の全体 chat 識別タグ |

- chat 本文は Component から plain text へ変換するため、入力側の装飾 Component は引き継がない。
- 全体 chat 本文は `Component.text` として追加し、`&` / `§` をカラーコードとして解釈しない。
- DiscordSRVの `Channels` は `global` を `discord.globalChannelId` へ割り当て、`DiscordChatChannelRequireLinkedAccount` は `true` にする。
- Discord受信メッセージは `PlayerMsgId.P_6990` で配信し、通常のDiscordSRV Minecraft配信はAPIイベントでキャンセルする。
- `plugin.whitelistEnabled` が有効な間は、Minecraft→Discord の全体 chat を中継せず、DiscordSRVの `DiscordChatChannelServerStartupMessage` / `DiscordChatChannelServerShutdownMessage` を空のランタイム値へ差し替える。実サーバーの DiscordSRV 設定ファイルは変更しない。
- `/message` の宛先はオンライン名の完全一致だけを許可し、オフライン配送・履歴保存は行わない。

## 5. 死亡状態運用

- 通常死亡状態は 10 秒、定期更新は 20 tick 間隔とする。
- 死亡 state は切断時にも保持し、再参加時に位置・可視性・演出を復元する。
- plugin 停止時は task、頭部 ItemDisplay、死亡 TextDisplay、全 state を破棄する。
