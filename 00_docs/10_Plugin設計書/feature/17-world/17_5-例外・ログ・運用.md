# 17_5-例外・ログ・運用

## 例外方針

- API 取得・変換失敗は snapshot 構築を失敗させ、旧定義を残す。
- 転送 API は `CompletableFuture<Boolean>` で成否を返し、呼び出し元が main thread へ戻して通知・補償する。
- BASE 帰還では、消費後の転送失敗時に同額ゴールドを再付与して即時保存する。
- world、spawn、player のいずれかが無効なら Bukkit teleport を実行しない。

## ログ・メッセージ

- world 定義取得、load、unload、GUI slot 検証には `I_5750`〜`I_5754`、`D_5750`〜`D_5751`、`W_5750`〜`W_5755`、`E_5750`〜`E_5756` を使う。
- ゲートウェイ／GUI event の安全実行ログには実際の event operation を渡す。
- OVERWORLD 転送先の必要 Currency 不足は `PlayerMsgId.P_5777`、必要条件を満たした転送失敗は `P_5766`、BASE 帰還は `P_5607`〜`P_5619` 系で通知する。
- 定義にないログ ID を設計上だけで追加しない。

## 運用

- world master の seed 元と API 定義を同時に更新する。
- `baseWorldPath` はサーバーが読める実在フォルダにし、world ID と Bukkit world 名の衝突を避ける。
- `overworldTeleportGui.slot` は GUI の有効範囲で一意にする。重複時は world ID 順で先に処理した定義が残る。
- `requiredItemId` は `item:<id>` 形式の Currency 参照として定義し、未指定なら入場条件なしとする。API Seeder が参照先の存在と `currency` カテゴリを検証する。
- `showSpawnParticle=false` の world では ring／TextDisplay を生成しない。
- reload は管理コマンドであり、API seed を含む同期処理である。高負荷時の連打を避ける。
