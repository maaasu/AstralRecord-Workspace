# 17_0.00-概要

## 目的

API が返す `WorldMasterData` をプラグイン内の正本として保持し、論理 world ID と Bukkit `World` を結び付ける。管理対象ワールドのロード、スポーン地点解決、RPG 向け gamerule、移動演出を一つの feature に集約する。

## 責務

- filebase の world master を API へ seed し、`/api/world` と `/api/world/{id}` から完全な定義を読み込む。
- world ID、Bukkit UUID、Bukkit 名、フォルダ名の対応をキャッシュする。
- `baseWorldPath` から未ロードワールドを必要時に生成・ロードし、`spawnLocation` へ転送する。
- BASE のゲートウェイまたはスポーン地点から OVERWORLD 選択 GUI を開く。
- OVERWORLD のスポーン地点から、通常帰還または即時帰還で BASE へ戻す。
- 管理ワールドへ RPG gamerule を適用し、AstralRecord 管理外の Mob を抑止する。
- `showSpawnParticle` が有効なスポーン地点だけ演出を表示する。

## 責務外

- instance world の複製・破棄そのもの。`instanceEnabled`、`instanceRootPath` は定義として保持するが、本 feature 単独ではインスタンスを生成しない。
- Mob の生成・戦闘ロジック。
- world master の編集 UI。

## 現在の主要契約

- `autoLoad` は起動時ロードの意図を表す。`false` でもコマンドや転送要求により `resolveOrLoadWorld` がロードし得る。
- `/api/world` が概要行だけを返す場合、repository は各 ID の詳細 API で完全な定義へ展開する。詳細が 404 の行があれば snapshot 全体の構築を失敗させる。
- イベントの hot path は UUID／名前キャッシュを優先し、API へアクセスしない。
- プレイヤー転送は `PlayerTeleportService` を通し、オーバーヘッド表示と TextDisplay passenger を転送前後で整合させる。
- Bukkit コマンドは lifecycle の動的登録を使うため `plugin.yml` に command 定義を持たない。
