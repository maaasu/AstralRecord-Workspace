# 17_3-サービス

## 定義一覧取得

クラス名: `WorldRepository`
物理名: `findAll`

- 引数: なし
- 戻り値: 完全な `List<WorldMasterData>`
- 例外: API 通信・JSON 変換失敗を runtime exception として通知する。

1. `/api/world` を取得する。
2. 一覧要素が完全定義ならそのまま変換し、概要行なら `/api/world/{id}` で詳細化する。
3. 概要行の詳細が 404 の場合は `IllegalStateException` とし、不完全な一覧を返さない。

## 定義 snapshot 読み込み・反映

クラス名: `WorldService`
物理名: `loadDefinitionSnapshot` / `replaceDefinitionSnapshot` / `activateDefinitionSnapshot`

- 引数: 反映系は `DefinitionSnapshot snapshot`
- 戻り値: 読み込みは snapshot、反映系はなし
- 例外: repository の取得失敗を呼び出し元へ伝播する。

`activateDefinitionSnapshot` は cache を置換した後、`autoLoad` 定義をロードし runtime 索引へ登録する。個別 world の有効化に失敗した場合は `E_5753` を記録して他の world を継続し、すでに公開した定義 snapshot を破棄せず例外を外へ送出しない。`autoLoad=false` の定義はロード済み Bukkit world と索引を結び付けても RPG gamerule を変更しない。RPG gamerule は `SPAWN_MOBS=false`、`MOB_GRIEFING=false`、`KEEP_INVENTORY=true`、`IMMEDIATE_RESPAWN=true`、`NATURAL_HEALTH_REGENERATION=false` とする。`reloadFromYaml` は master seed と再読込を同期的に実行する管理操作である。

## Bukkit world 解決

クラス名: `WorldService`
物理名: `resolveLoadedWorld` / `resolveOrLoadWorld` / `findByBukkitWorld`

- 引数: `WorldMasterData data`、または Bukkit `World world`
- 戻り値: 解決結果。未解決時は `null`
- 例外: world 生成失敗を独自には捕捉しない。

ロード済み解決は UUID、名前、フォルダ対応を使う。`resolveOrLoadWorld` は未ロード時に `baseWorldPath` を Bukkit world としてロードし、成功後に runtime cache と RPG gamerule を更新する。

runtime world はロード前に名前と master ID の対応を予約でき、UUID 登録前でも管理対象・表示名を解決する。同じ runtime 名の重複予約は拒否し、cancel で予約を解除する。同一 master から生成した複数 runtime world は UUID ごとに独立登録し、master が reload 中に一時的に消えても種別・表示 metadata を保持する。master 再公開時は各 runtime 登録を同じ master へ再結合し、一つを unregister しても他の runtime 登録は維持する。

## スポーン地点解決・転送

クラス名: `WorldService`
物理名: `resolveSpawnLocation` / `resolveOrLoadSpawnLocation` / `teleportToSpawn` / `teleportToSpawnAsync`

- 引数: `WorldMasterData data`、転送は `Player player` と必要に応じて teleport cause
- 戻り値: `Location?`、または `CompletableFuture<Boolean>`
- 例外: 非同期転送の失敗は future を exceptional completion にし得る。

`resolveSpawnLocation` はロード済み world のみ、`resolveOrLoadSpawnLocation` は必要時ロードを許可し、返す `Location` には master の world / x / y / z / yaw / pitch を設定する。ただし `teleportToSpawn` と `teleportToSpawnAsync` の実転送は `PlayerTeleportService` を経由する。`withCurrentLookDirection` は target `Location` を clone した上で world / x / y / z を維持し、yaw / pitch を転送直前のプレイヤー視線へ置き換えるため、入力された target `Location` 自体は変更しない。

同一マスターから複数の runtime world が存在する場合に特定ワールドへマスターのスポーン座標を適用するときは、`teleportToSpawnInWorld` を使う。転送先 Bukkit world は呼び出し側が解決済みの対象ワールドを渡し、座標・向きは `WorldMasterData.spawnLocation` から作成する。

## OVERWORLD 転送先一覧・転送

クラス名: `OverworldTeleportService`
物理名: `listDestinations` / `teleportToDestination`

- 引数: 転送は `Player player`, `AstPlayer astPlayer`, `String worldId`
- 戻り値: 一覧、またはなし
- 例外: 転送結果の throwable を main thread で失敗メッセージへ変換する。

一覧は `OVERWORLD` かつ有効 GUI slot の定義だけを slot 順に返す。同一 slot は world ID 順の先頭だけを採用する。`isBaseWorld` は Bukkit world を `WorldService` の定義へ解決し、種別が `BASE` の場合だけ `true` とする。転送先 ID が不正、種別違い、転送失敗の場合は `PlayerMsgId.P_5766` を通知する。

## 拠点帰還

クラス名: `ReturnToBaseService`
物理名: `calculateGoldCost` / `beginReturn` / `beginImmediateReturn` / `cancelAll`

- 引数: level、または `AstPlayer`
- 戻り値: 費用、または開始可否
- 例外: 非同期転送失敗は callback 内で補償・通知する。

通常帰還費用は `100 * max(1, level)`。通常帰還は 60 tick 静止後に消費・保存・転送し、転送失敗時は同額を戻して保存する。即時帰還は待機と費用を使わない。ダンジョンセッションの参加中、またはボス挑戦の準備中・進行中・結果待ち・終了処理中は、通常帰還と即時帰還を開始しない。

## 管理外 Mob 抑止

クラス名: `WorldNaturalSpawnBlockEventHandler`
物理名: `onCreatureSpawn` / `onWorldLoad` / `onChunkLoad`

管理 world 内で instance ID を持たない Mob を cancel・削除する。`CUSTOM` spawn は他 plugin が識別子を付与する猶予として次 tick に再検証する。
