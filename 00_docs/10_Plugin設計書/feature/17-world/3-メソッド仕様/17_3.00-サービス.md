# World サービス仕様

## WorldRepository

API の `GET /api/world` と `GET /api/world/{worldId}` を呼び出し、`WorldMasterData` に変換する。`findAll()` は `GET /api/world` の各 JSON object をその場で parse し、一覧要素ごとの `findById()` は呼び出さない。

## WorldService

`WorldMasterData` のプラグイン内キャッシュと Bukkit ワールド解決を担当する。

| Method | Description |
|---|---|
| `loadAll()` | API から全 `WorldMasterData` を再読込し、ID 単位でキャッシュ更新する。既にロード済みのワールドは `autoLoad` にかかわらず UUID キャッシュへ登録し、`autoLoad = true` の未ロードワールドだけロードする。 |
| `reloadFromYaml()` | MasterData Seeder API で filebase YAML を MasterDataDB に反映したあと、`loadAll()` を再実行してキャッシュと Bukkit ワールド解決を更新する。 |
| `getAll()` | キャッシュ済み `WorldMasterData` 一覧を返す。 |
| `showWorldChangeTitle(player)` | `PlayerChangedWorldEvent` 後に現在ワールドの表示名をタイトル表示する。 |
| `getById(worldId)` | 指定 ID の `WorldMasterData` を返す。 |
| `resolveLoadedWorld(data)` | `baseWorldPath` や既存ロード状況から対応する Bukkit ワールドを解決する。 |
| `findByBukkitWorld(world)` | 通常・一時ワールドの UUID キャッシュ、または生成中の一時ワールド名キャッシュから `WorldMasterData` を O(1) で逆引きする。イベント中に `resolveLoadedWorld` やファイル探索は行わない。 |
| `resolveWorldType(world)` | `WorldMasterData` または一時ワールドの実行時登録から `WorldType` を返し、地域既定値の解決に使う。 |
| `resolveDisplayName(world)` | `WorldMasterData` または一時ワールドの登録情報からプレイヤー向けワールド表示名を返し、解決できない場合は Bukkit ワールド名へフォールバックする。 |
| `prepareWorldLoad(worldName, worldData)` | `Bukkit.createWorld` より前にワールド名、マスタ ID、表示名、ワールド種別を登録し、生成途中の World / ChunkLoad イベントから解決可能にする。 |
| `registerRuntimeWorld(world, worldData)` | ロードに成功した一時ワールドを UUID で登録する。同一マスタ由来の複数インスタンスを個別に保持し、登録時の表示名をフォールバック用に保存する。 |
| `cancelWorldLoad(worldName, worldData)` | ワールドのロード成功・失敗時に生成予定名を解除する。 |
| `unregisterRuntimeWorld(world)` | 一時ワールドのアンロード成功後に UUID 登録を解除する。 |
| `resolveSpawnLocation(data)` | `resolveLoadedWorld(data)` と `data.spawnLocation` から Bukkit `Location` を生成する。 |
| `teleportPlayerAsync(player, targetLocation, onSuccess)` | `TextDisplay` passenger を一時解除して chunk を先読みし、`teleportAsync` 完了後に `onSuccess` を呼ぶ。 |
| `teleportToSpawnAsync(player, data)` | `resolveSpawnLocation(data)` を使って既定スポーンへ非同期テレポートする。参加時スポーンと `/world tp` で利用する。 |
| `applyRpgGameRules(world)` | RPG 用 gamerule を設定する。 |

`WorldSpawnParticleTask` は `WorldMasterData.showSpawnParticle` が `true` のワールドだけにスポーン地点リングパーティクルを表示する。`WorldType = BASE` の場合は「スニークでオーバーワールドへ移動」、`WorldType = OVERWORLD` の場合は「スニークで拠点に帰還」の TextDisplay も同じ条件で表示する。`false` のワールドでも `spawnLocation` は参加時スポーンと `/world tp` に引き続き利用する。

## PlayerRegionService

`AstPlayer.currentRegion` / `currentRegionLevel` の初期化・切り替えと地域タイトル表示を担当する。ログイン時は現在ワールド種別の地域既定値をタイトルなしで設定し、地域レベルを 0 とする。ワールド移動時は `HUB=ハブ`、`BASE=拠点`、`OVERWORLD=オーバーワールド`、`DUNGEON=ダンジョン`、`BOSS_FIELD=ボスフィールド` へ更新して地域レベルを 0 に戻し、既存のワールド移動タイトル完了後に地域タイトルを表示する。オーバーワールドではスポナー地域とその地域レベルを受け取り、待機中に地域が確定した場合は最終地域だけを表示する。同一地域への再設定では地域レベルだけを更新し、タイトルを表示しない。

`WorldService.loadAll` は `WorldMasterData.autoLoad = true` のワールドだけを Bukkit ワールドとして起動時ロードする。`autoLoad = false` のワールドは MasterData として保持するが常時ロードせず、ボスフィールドなどのインスタンス生成や明示的なロード経路でのみ Bukkit ワールド化する。

ボスフィールドなどの一時生成ワールドは、ロード前に Bukkit ワールド名を予約登録し、ロード成功後に UUID と元の `WorldMasterData` を関連付ける。これにより生成途中の ChunkLoad イベントもファイル I/O なしで管理対象と判定する。`PlayerChangedWorldEvent` のタイトルには最新の `WorldMasterData.displayName` を使い、マスタ再読込で一時欠落した場合は登録時の表示名を使う。ボスフィールドの両方が空の場合も日本語の「ボスフィールド」とし、Bukkit 内部名やワールドパスは表示しない。ワールドアンロード成功時は UUID 登録を解除する。

`findByBukkitWorld` はイベント用の hot path とし、キャッシュ未登録なら即座に `null` を返す。パス候補探索を伴う `resolveLoadedWorld` はワールドロード、明示テレポート、マスタ再読込などの cold path だけで使用し、パス比較はファイルシステムへアクセスしない絶対正規化パス比較とする。junction / symlink の実体同一性は解決せず、マスタと Bukkit ワールドでは同じ字句パスを使用する。

`teleportPlayerAsync` / `teleportToSpawnAsync` / `teleportToSpawn` はプレイヤー向け共通テレポート経路として扱う。テレポート先 `Location` の `yaw` / `pitch` をそのまま使わず、移動直前のプレイヤーの `yaw` / `pitch` を反映してから Bukkit の teleport API を呼び出す。

## OverworldTeleportService

拠点ワールドからオーバーワールドへ移動する GUI の候補抽出と転送を担当する。

| Method | Description |
|---|---|
| `listDestinations()` | `WorldType = OVERWORLD` かつ `overworldTeleportGui.slot` が 0 以上 44 以下の `WorldMasterData` だけを抽出し、スロット順で返す。重複スロットはワールド ID の昇順で先の1件だけを採用する。 |
| `isBaseWorld(world)` | Bukkit ワールドに対応する `WorldMasterData` が `BASE` か判定する。 |
| `teleportToDestination(player, astPlayer, worldId)` | 指定 `worldId` の `spawnLocation` へ非同期テレポートする。失敗時のみプレイヤーメッセージを返す。 |

## OverworldSpawnReturnEventHandler

オーバーワールドの初期スポーン地点でのスニーク帰還候補を提供する`PlayerInputResolver`。

1. `resolve`は`SNEAK` contextかつ`PlayerToggleSneakEvent.isSneaking() == true`の瞬間だけ判定する。
2. `WorldMasterData` が解決できる場合は `WorldType = OVERWORLD` のワールドだけを対象とし、トリガー中心には `spawnLocation` を使う。
3. `WorldMasterData` がない `Environment.NORMAL` ワールドでは Bukkit 既定スポーンをトリガー中心に使う。
4. プレイヤーの現在位置とトリガー中心の水平距離が2メートル以内なら、高低差を含む3D実距離を`hitDistance`に設定した`overworld-spawn-return`候補を返す。水平距離は成立判定だけに使用する。
5. 候補は`WORLD_INTERACTION`、`stableOrder = 15`、`CLAIM`とし、候補収集時は帰還を開始しない。
6. 本候補が勝った場合だけexecutorが`ReturnToBaseService.beginImmediateReturn(astPlayer)`を呼ぶ。
7. 同tierのboss / world候補とは実距離を先に比較し、同距離の場合だけ`stableOrder`を比較する。敗者になった場合は帰還しない。
8. `CLAIM`は元eventをcancelせず、スニーク姿勢を維持する。判定は押下瞬間のみで、押しっぱなし中の継続判定は行わない。

## BaseWorldGatewayEventHandler

拠点ワールド内のゲートウェイ接触で GUI を開く。

1. `PlayerMoveEvent` で `END_GATEWAY` / `END_PORTAL` / `NETHER_PORTAL` ブロックへ入った瞬間を検出する。
2. すでに同じゲートウェイ帯から抜けていないプレイヤーは再オープンしない。
3. GUI を開く前に、プレイヤーを現在ワールドの Bukkit 既定スポーンへ `PLUGIN` cause で退避させる。
4. 退避後の次 tick に `OverworldTeleportGuiEventHandler.open(player)` を呼び、候補がなければエラーメッセージのみ返す。
5. `PlayerTeleportEvent` の `END_GATEWAY` / `END_PORTAL` / `NETHER_PORTAL` は拠点ワールドでは常に `cancel` する。

## BaseWorldSpawnTeleportEventHandler

拠点ワールド内のスポーン地点付近でのスニークによるGUI表示候補を提供する`PlayerInputResolver`。

1. `resolve`は`SNEAK` contextかつ`PlayerToggleSneakEvent.isSneaking() == true`の瞬間だけ判定する。
2. `OverworldTeleportService.isBaseWorld(world)` が `true` の Bukkit ワールドだけを対象にする。
3. `WorldMasterData` が `WorldType = BASE` の場合に `WorldService.resolveSpawnLocation(data)` をトリガー中心として使う。
4. プレイヤーの現在位置とトリガー中心の水平距離が2メートル以内なら、高低差を含む3D実距離を`hitDistance`に設定した`base-world-spawn-teleport`候補を返す。水平距離は成立判定だけに使用する。
5. 候補は`WORLD_INTERACTION`、`stableOrder = 15`、`CLAIM`とし、候補収集時はGUIを開かない。
6. 本候補が勝った場合だけexecutorが`OverworldTeleportGuiEventHandler.open(player)`を呼ぶ。
7. すでに同じGUIを開いているプレイヤーには候補を返さない。
8. boss entry等の近い`WORLD_INTERACTION`候補が勝った場合やinput lock中は本executorを実行しない。world候補が勝った場合はplayer-control fallbackも実行しない。
9. `CLAIM`は元eventをcancelせず、スニーク姿勢を維持する。

## OverworldTeleportGuiEventHandler

オーバーワールド転送 GUI の表示とクリック遷移を担当する。

1. GUI を開く前に `OverworldTeleportService.listDestinations()` を取得する。
2. 候補が 0 件ならメッセージ `P_5769` を返して開かない。`overworldTeleportGui` または `slot` が未指定のワールドは候補に含めない。
3. GUI を開いたプレイヤーには `DARKNESS` を付与する。
4. クリックされた `worldId` を `OverworldTeleportService.teleportToDestination(...)` へ渡す。
5. `guiIconMaterial` は item icon、`displayName` / `description` / `adventureGuide` は lore/表示文に使う。
6. GUI を閉じた次 tick に、まだ同じ GUI を開いていなければ `DARKNESS` を解除する。
7. 候補アイテムは `overworldTeleportGui.slot` の 0 以上 44 以下へ直接配置し、空きスロットを詰めない。下段 45 から 53 はスペーサーとして予約する。

`WorldService.loadAll()` は world マスタを ID 昇順で読み込んだ後、オーバーワールド転送 GUI のスロットを検証する。0 から 44 の範囲外は `W_5755`、重複は `W_5754` を警告し、重複時は ID 昇順で先に読み込まれたワールドを表示対象として扱う。

## ReturnToBaseService

`joinSpawn.world` を拠点として扱い、menu feature からの帰還導線を担当する。

| Method | Description |
|---|---|
| `calculateGoldCost(playerLevel)` | 帰還コストを `100 x max(1, playerLevel)` で計算する。 |
| `beginReturn(astPlayer)` | 拠点スポーン `WorldMasterData` とスポーン座標を解決し、帰還確認と演出を開始する。 |
| `beginImmediateReturn(astPlayer)` | 拠点スポーン `WorldMasterData` を解決し、ゴールド消費なし・待機なしで即時帰還を開始する。 |
| `cancelAll()` | 実行中の帰還処理をすべて解除する。 |
