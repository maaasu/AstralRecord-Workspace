# 37_0-概要

## 目的と境界

犬・猫・ニワトリの個体、卵、成長、配合、召喚、戦闘支援を扱う。静的ルールの正本は `40_filebase/55.features.pet/v1.pets.yml` 一つで、個体生成・遺伝・スキル抽選・レベル確定はAPIが担当する。Pluginは個体の公開応答をキャッシュし、戦闘中のHP比率・死亡・クールダウン・活動経験値だけを更新する。実装所有パスは [FEATURE_CATALOG](../../FEATURE_CATALOG.md) に定義する。

## 個体と卵の不変条件

個体IDと所有アカウントIDを保持する。卵は種類・出自・譲渡可否だけを公開し、名前・性別・サイズ・基礎個体値・潜在能力・スキルを返さない。Pluginの変換境界でも卵の `details` を除去するため、上流応答に詳細が混入しても表示側へ公開しない。孵化済みの詳細は入力JSONと返却JSONから独立したコピーとして保持し、表示処理から遺伝値を変更できない。

野生由来は譲渡可能、配合由来は卵の段階からアカウント拘束。最終判定はAPIの個体出自・所有者・装備選択で行う。卵とペットは数量1の個体entryであり、通常stackの生成経路では作らない。

## 管理者の卵取得とメール受領

管理者item一覧と `/item get` から卵を取得できる。マスターの `eggItemId` に対応する種類を解決し、BAG枠を予約してから既存 `/eggs` 原子APIで個体を作成する。予約は通信結果不明の復旧中も保持し、三者マージのstate lock内で取り込みと解除を確定する。通常stackを生成せず、容量不足、確定拒否、結果確認中を区別する。孵化済みペットを直接生成しようとした場合は、卵を取得して施設で孵化する案内を返す。

Webマーケット購入のメール添付は、所有者限定の個体APIで `accountId`・`instanceId`・`itemId`・卵種別を照合し、既存進行を置換せず表示cacheへ補完する。受取snapshotには `PET` / `PET_EGG` の数量1個体entryを含める。個体IDのないペット添付は受領前に拒否し、通常stackへ変換しない。

## 装備と施設

装備画面slot16または `/pet` からペット管理を開く。`/pet name <名前>` は装備中の孵化済み個体をAPIで改名する。所有個体を選択し、保存で装備選択を確定して1体だけ後方へ召喚する。Shift保存で解除する。選択は通常装備個体スロットとは別の `account_pet_state` に保存する。

`pet_center` の右クリックから施設画面を開く。卵を選択して孵化ボタン、オスとメスを右クリックで親に設定して配合ボタン、戦闘不能個体を選択して復活ボタンを実行する。施設操作時に対話したNPCの個体ID・種類・同一ワールド・距離6ブロック以内を検証する。復活オーブはBAGから専用選択画面を開き、消費元entryをAPIへ指定する。

素材の正本と採集オブジェクトからアイテムまでの根拠は [ペット導入運用](../../../../40_filebase/55.features.pet/docs.pet.導入運用.md) を参照する。初期孵化は大地の心花びら256、大地の命玉16、種類別採集Lv2素材128を消費する。

## 成長と遺伝

成長度はLv1〜100、スキル解放は1・20・50、配合条件は両親Lv20以上の同種異性かつ生存。各種8スキル、T0〜T3に各2種類。野生の初期スキルはT0、後続はT0〜T1・T0〜T2。配合子の初期スキルは親の習得済みから継承し、初期T2/T3なら後続にT3を含める。

討伐・採集で実際に獲得する活動経験値を召喚中の生存個体へ配分する。必要XPはプレイヤーの基礎曲線と同形で、アカウント固有の微小hash加算だけを除く。時間経過・放置だけのXP付与はない。

ステータス別のティア、基礎値、潜在フラグを保存する。野生T4上限、配合T10上限。親の高い基礎値を項目ごとに継承し、育成後の値を基礎値へコピーしない。潜在能力は成長増分だけを2倍にし、その能力を金色で表示する。

## 戦闘とライフサイクル

ペットは主人の味方の管理戦闘エンティティで、敵の標的・通常攻撃・スキル・範囲攻撃・飛び道具の被弾対象となる。主人の攻撃系統とHP等を種族の係数で参照する。ペット由来の主人バフを除外した能力を参照し、自己増幅を防ぐ。犬・猫は主人の直接命中を起点とする基本追撃をスキル枠外で持ち、追加の習得スキルも自動発動する。追撃由来の攻撃から追撃を再発動しない。

ペットの討伐は主人に報酬を帰属させる。卵抽選は討伐1回に1回で、報酬対象者の誰か1人へ付与する。種類抽選にはマスターの `dropWeight`、活動XPには `experience.activityRate` を適用する。ペット自身やNPCは卵を落とさない。召喚ペットのバニラ産卵等のアイテム生成も `EntityDropItemEvent` で取り消す。

死亡はHP比率0と死亡フラグで保存し、装備していても召喚しない。施設または専用オーブだけで復活する。装備解除・ログアウト・主人の死亡による退場はペット死亡と区別し、HP・クールダウンを保持する。ログイン読込、退出、チャンネル移動、プラグイン停止でも保存境界へ接続する。

## 非同期保存と原子操作

原子操作の開始時に召喚個体を退場させて最終状態を確定し、未確定中は再召喚しない。確定成功・拒否後に保存済み選択へ戻す。オンラインの不足個体再読込も同accountの進行laneへ直列化する。

戦闘中に同期APIを呼ばない。活動XP・HP・死亡・クールダウンをキャッシュし、2秒ごとの非同期保存で同じアカウントの進行を直列化する。未確定の進行要求は同じoperationIdと内容で再送する。APIがレベルと追加スキルを確定する。

素材を消費する孵化・配合・復活と装備保存は、支払い予約→安定した事前保存→API原子操作→保存済みbaseline・現在ローカル・応答正本の三者マージ→事後保存で確定する。通信結果が不明な場合は境界とoperationIdを保持し、再試行する。確定拒否の場合は予約を解除する。Bukkitの表示・召喚更新はメインスレッドへ戻す。

インベントリ取り込みと個体cache再取得は別の完了段階として保持する。三者マージ成功後に個体APIの再取得が失敗しても、復旧ではcache再取得から再開し、確定済みの同じentry差分を再加算しない。

## 運用と確認範囲

DB migration `20261001_pet.sql` → API → Filebase配置・MasterDataDB同期 → Pluginの順で更新する。施設NPCの実座標はリポジトリに含まれないため、管理者が `/mob npc place pet_center` で配置する。実サーバー上の追従・GUI・敵スキル演出と施設配置は、ビルド・契約テストとは別の確認が必要。

パンダ・ウーパールーパー・イルカ、異種配合は対象に含めない。
