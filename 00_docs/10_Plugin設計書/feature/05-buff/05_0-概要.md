# 05_0-概要

## 1. 目的

`buff` 機能は、プレイヤーへ一時的に付与される能力補正（バフ / デバフ）を管理する。
主目的は以下。

- バフ定義（`BuffType`）の API 取得・メモリキャッシュ管理
- プレイヤーへのバフ付与・解除・期限切れ整理
- ステータス再計算時に必要となるバフ補正合計値（FLAT / SCALAR）の提供
- バフ獲得時の短時間 TextDisplay 通知
- プレイヤー設定が有効な場合に HUD サイドバーへ提供する獲得順の有効バフ一覧

## 2. コンテキスト

- バフ定義は AstralRecord API (`/api/buff/{buffId}`) から取得し、`BuffService` の内部キャッシュに保持する。
- プレイヤーごとの「現在掛かっているバフ」は [[03_1-モデル定義]].プレイヤーキャッシュ 内の `AstPlayer.activeBuffs` に直接保持される（永続化なし、セッション中の状態）。
- バフ補正は [[05_3-サービス]].バフ補正合計取得 で `StatusType` 別に合算し、`StatusService` がステータス再計算時に呼び出す。
- 失効時刻は `durationTicks / 20` 秒として `LocalDateTime` で計算する。

## 3. 構成要素（実装単位）

- `service/BuffService`
  - バフ定義のキャッシュ管理、付与・解除・期限切れ整理、補正合計算出の業務制御を行う。
- `service/BuffAcquisitionDisplayService`
  - バフ獲得時に残時間と代表補正をプレイヤー視界右下へ短時間表示する。
- `repository/BuffRepository`
  - `/api/buff/{buffId}` への HTTP リクエストを実行する。
- [[05_1-モデル定義]].バフタイプ, アクティブバフ, バフ補正, バフ補正タイプ
  - バフマスタ・付与中状態・補正単位を定義する（詳細は [[05_1-モデル定義]]）。

## 4. 依存関係

- 内部依存
  - `BuffService` -> `BuffRepository`
  - `BuffAcquisitionDisplayService` -> `DisplayTextService`
- 外部依存
  - AstralRecord API (`/api/buff/{buffId}`)
  - [[03_1-モデル定義]].プレイヤーキャッシュ.AstPlayer.activeBuffs を直接更新する

- `player`
  - [[03_1-モデル定義]].プレイヤーキャッシュ に保持される `AstPlayer.activeBuffs` を直接操作対象とする。
- `status`
  - `StatusService` が `BuffService` を内部生成・所有し、ステータス再計算時に [[05_3-サービス]].バフ補正合計取得 を呼ぶ。
- `item`
  - `PotionUseService` が `ItemConsumable.effects` の `BUFF` タイプから `StatusService.applyBuff` を呼び、付与成功時にバフ獲得通知を表示する。
- `skill`
  - `SkillCombatService` が発動スキルの `buffId` を `StatusService.applyBuff` へ渡し、スキル由来のバフを付与する。
- `hud` / `player-setting`
  - `BUFF_SIDEBAR_DISPLAY` が有効なプレイヤーに限り、`StatusService.getActiveBuffs` が返す獲得順の一覧を HUD が最大5件表示する。

## 5. ライフサイクル登録点

- `StatusService` のコンストラクタ内で `new BuffService()` が生成される（`buff` 機能専用の `AstralRecord#setupFeature` 登録は行わない）。独立したライフサイクル登録は導入しない。
- 起動時の一括ロードは行わず、`BuffService.apply` の初回呼び出し時に該当バフを遅延ロードしてキャッシュへ登録する。

## 7. condition との境界

`buff` は `StatusType` への一時的な数値補正を扱う。
炎上、毒、凍結、スタン、沈黙、攻撃不可、無敵など、DoT・行動制限・専用表示を伴う戦闘状態は [[27_0-概要]] の `condition` を正本とする。

状態異常による速度低下や被ダメージ増加は `buff` へ変換して管理せず、付与・解除・表示・重複規則を `condition` 内で完結させる。
