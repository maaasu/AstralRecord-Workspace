# テレポーター統合フロー

## 1. 起動時ロード

1. Plugin 初期化で `WaystoneDefinitionRepository.loadAll` を呼ぶ。
2. `TeleporterService.loadDefinitions` が制約を検証してキャッシュを構築する。
3. イベントハンドラ、コマンド、GUI ハンドラ、packet view を登録する。
4. オンラインプレイヤーが存在する場合、解除状態取得後に packet 表示を同期する。

## 2. 管理者配置フロー

1. `/teleporter set <name> <lockEnabled> <unlockGold>` を受ける。
2. `TeleporterCommand.executeSet` が実行者と引数を検証する。
3. `TeleporterService.createWaystone` が ID を生成し、現在地から `WaystoneDefinition` を作る。
4. `WaystoneDefinitionRepository.save` が `waystones.yml` へ保存する。
5. `WaystonePacketView.syncForPlayer` を全オンラインプレイヤーへ実行する。
6. 管理者へ登録完了メッセージを送信する。

## 3. ロック解除フロー

1. プレイヤーがウェイストーンを右クリックする。
2. `TeleporterInteractEventHandler` が hitbox から対象ウェイストーンを解決する。
3. 対象がロック中であれば `TeleporterService.unlockWaystone` へ委譲する。
4. `TeleporterService` が最新解除状態を API から取得する。
5. `CurrencyService` がゴールド残高を確認する。
6. ゴールド不足ならメッセージを送信して終了する。
7. ゴールドが足りる場合は消費する。
8. `AccountWaystoneRepository.unlock` が API へ解除登録する。
9. 成功時、解除状態キャッシュへ対象 ID を追加する。
10. `WaystonePacketView.syncForPlayer` が対象プレイヤーの表示をロック中から解除済みへ更新する。
11. ウェイストーン中心に解除成功サウンドと共通パーティクル演出を再生する。

## 4. GUI 表示フロー

1. プレイヤーが解除済みウェイストーンを左クリックまたは右クリックする。
2. `TeleporterInteractEventHandler` が対象ウェイストーンを解決する。
3. `TeleporterGui.open` が `TeleporterService.buildGuiEntries` を呼び出す。
4. `TeleporterService` は起点と同じ `worldName` のウェイストーンだけを抽出する。
5. 起点自身を除外する。
6. 解除済みを先頭、未解除を後続に並べる。
7. `TeleporterGui.render` が 54 slot GUI を描画する。
8. GUI 表示中の hotbar は通常表示を維持し、専用の閉じるボタンは表示しない。

## 5. GUI テレポートフロー

1. プレイヤーが GUI 内の解除済みウェイストーンをクリックする。
2. `TeleporterGuiEventHandler` が `TeleporterGui.resolveEntry` で対象項目を解決する。
3. `TeleporterService.teleportToWaystone` が同一ワールド、解除済み、ロード済みワールドを検証する。
4. GUI を閉じ、GUI 用 hotbar の表示状態を復元する。
5. `WorldService.teleportPlayerAsync` で、テレポート直前のプレイヤーの `yaw` / `pitch` を保持してテレポートする。
6. テレポート完了後、数 tick 遅延して `WaystonePacketView.syncForPlayer` を実行する。

## 6. 表示同期フロー

1. プレイヤー参加、ワールド移動、解除成功、reload、定義追加、定義削除を契機に同期を開始する。
2. `WaystonePacketView` は対象プレイヤーの現ワールドと解除状態を取得する。
3. 表示対象、非表示対象、metadata 更新対象を差分計算する。
4. packet spawn / metadata / destroy を送信する。
5. packet-only entity ID は `WaystoneViewState` として保持する。

## 7. 削除フロー

1. `/teleporter remove <waystoneId>` を受ける。
2. `TeleporterCommand.executeRemove` が権限と引数を検証する。
3. `TeleporterService.removeWaystone` が定義存在を確認する。
4. `WaystoneDefinitionRepository.remove` が `waystones.yml` から削除する。
5. 全オンラインプレイヤーに destroy packet を送信する。
6. 削除完了メッセージを送信する。

## 8. API / DB 境界

Plugin は SQL Server へ直接接続しない。
解除状態の読み書きは `AccountWaystoneRepository` から AstralRecord API を経由する。

| 操作 | API | DB |
|:--|:--|:--|
| 解除状態取得 | `GET /api/account-waystone/{accountId}` | `dbo.account_waystone_unlock` |
| 解除登録 | `POST /api/account-waystone/{accountId}/unlock` | `dbo.account_waystone_unlock` |

`waystones.yml` に存在しない `waystoneId` が DB に残っていても、Plugin は表示と GUI の対象にしない。
