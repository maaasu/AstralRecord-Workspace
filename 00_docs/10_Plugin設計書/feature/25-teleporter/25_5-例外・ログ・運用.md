## 2. ログ

| ID | レベル | テンプレート | 用途 |
|:--|:--|:--|:--|
| `LogId.I_5950` | INFO | `ウェイストーンを作成しました: id=%s, name=%s, world=%s` | 定義の作成・保存成功 |
| `LogId.E_5951` | ERROR | `テレポーターGUI処理に失敗しました: player=%s` | GUI の開閉・クリック処理例外 |
| `LogId.E_5952` | ERROR | `ウェイストーン解除失敗後の返金に失敗しました: player=%s, waystoneId=%s, gold=%d` | API 登録失敗後のゴールド補償失敗 |
| `LogId.E_5953` | ERROR | `waystones.yml の保存に失敗しました: %s` | YAML 保存失敗 |
| `LogId.E_5954` | ERROR | `account-waystone API の呼び出しに失敗しました: %s` | 解除状態 API の取得・登録失敗 |
| `LogId.E_5955` | ERROR | `ウェイストーン表示同期処理に失敗しました: player=%s, trigger=%s` | join、world change、quit 時の packet 表示同期例外 |

`LogId` と `logger.properties` は同時に更新する。プレイヤーライフサイクル同期とワールド内クリックでは、クリック処理用の ID を流用しない。

## 3. エラー時の挙動

### 3.1 `waystones.yml` 読み込み失敗・不正行

- ファイルが存在しない場合は空定義として扱う。
- YAML 内で `id`、`name`、`worldName`（旧 `world` も許容）が欠ける行は読み飛ばす。
- 数値・日時の不正値は `0` または `Instant.EPOCH` へフォールバックする。
- `icon` の省略または無効値は未設定として扱い、GUI と ItemDisplay では `BEACON` へフォールバックする。
- reload は読み込んだスナップショットでキャッシュを置換し、packet 表示を全再同期する。

### 3.2 `waystones.yml` 保存失敗

- repository は `E_5953` を記録して `IllegalStateException` を送出する。
- 作成時は追加した定義をキャッシュから取り除き、削除時は変更前スナップショットを順序も含めて復元する。
- 表示同期と成功メッセージは保存成功後だけ実行する。
- 例外はコマンド基盤へ伝播し、共通のコマンド失敗処理へ集約する。

### 3.3 `account-waystone` API 取得失敗

- ロック有効ウェイストーンの初回操作時に非同期取得する。
- 取得失敗時は解除状態キャッシュを更新せず、`P_5964` を通知して操作を終了する。
- ロック無効ウェイストーンは解除状態 API を必要としない。

### 3.4 解除登録失敗

- ゴールド消費・即時保存後に API 登録を非同期実行する。
- API 登録失敗時は同額の返金と再保存を試み、`P_5957` を通知する。
- 返金に失敗した場合は `E_5952` に player、waystoneId、gold を残す。分散トランザクションではないため、このログを補填判断に使用する。
- 同一アカウント・同一ウェイストーンの並行解除は `unlocksInProgress` で抑止する。

### 3.5 テレポート失敗

- 同一ワールドでない、未解除、実行時依存未設定、対象 Location を解決できない場合は `P_5954` を通知する。
- `WorldService.teleportPlayerAsync` 開始後の成否通知・チャンク準備は World feature の契約に従う。
- GUI を閉じた後の位置巻き戻しは行わない。

## 4. 運用

- `waystones.yml` は管理コマンドで更新する。手編集した場合は `/teleporter reload` を実行する。
- 現行実装は同一座標の重複登録を拒否しない。重複を避けることは運用上の責務とし、自動検証の追加は未決事項で扱う。
- 削除したウェイストーンの API 側解除行は削除しない。削除済み ID を再利用しない。
- `waystoneId` は API / DB のキーであるため、手編集で変更しない。
- `icon` は Bukkit Material 名を指定する。変更後は `/teleporter reload` で GUI とワールド上表示へ反映する。
- `E_5952` が出た場合はゴールド補填の要否、`E_5953` が出た場合は data folder の権限・空き容量を確認する。

## 5. 権限

- `/teleporter` は `AstCommand` の `playerOnly=true`、必要権限 `UserPermission.ADMIN` として登録される。コンソールからは実行できない。
- `set`、`remove`、`list`、`reload` はすべて管理者プレイヤー専用である。
- 通常プレイヤーはワールド内のウェイストーン操作、解除、GUI 内テレポートを利用する。
