# 08_0-概要

## 1. 目的

`inventory` feature は、アカウント単位の統合所持品（BAG）、装備スロット、アクセサリスロット、ホットバー表示、ストレージを管理する。

主な責務は次の通り。

- API から inventory / entry / equipment loadout を取得してプレイヤー状態を構築する
- プレイ中の変更を account 単位の in-memory state へ集約する
- BAG のうち8列×3行を Bukkit PlayerInventory へ反映し、1行単位のスクロールを扱う
- アイテム取得、装備変更、ホットバー操作、アクセサリ操作、ストレージ収納・取り出しを扱う
- player save と 60 秒オートセーブで dirty state を API へ反映する

## 2. コンテキスト

- 永続化データは AstralRecord API の inventory / equipment loadout エンドポイントを利用する
- join 時に `InventoryPersistence.load(accountId)` が inventory / entry / loadout を取得し、`PlayerInventoryState` を構築する
- プレイ中の inventory feature は API を直接呼ばず、`PlayerInventoryStateRegistry` 上の state を更新する
- dirty state のみ `InventoryPersistence.save(...)` で API へ反映する
- 表示対象管理は [[02_1-モデル定義]].アカウントモード が通常プレイモードの場合のみ GUI に反映する
- 表示アイテム生成は item feature の ItemStack 生成・復元仕様へ依存する
- menu feature から装備 GUI とカスタムGUI中の BAG／ホットバー操作を起動される

## 3. 実装責務

- `command/InventoryCommand`, `InventoryTabCompleter`
  - `/inventory` による BAG 再描画
- `event/InventoryEquipmentGuiEventHandler`
  - 装備 GUI のクリック、BAG スクロール・クローズ、通常ホットバー操作
- `service/InventoryService`
  - state 更新、GUI 反映、保存前スナップショット反映、装備・ホットバー操作
- `service/InventorySaveTask`, `InventoryAutoSaveTask`
  - logout / plugin disable / manual save と 60 秒オートセーブ
- `repository/InventoryRepository`, `EquipmentLoadoutRepository`
  - API エンドポイントとの通信と JSON 変換
- `state/PlayerInventoryState`, `PlayerInventoryStateRegistry`, `InventoryPersistence`
  - account 単位 state、registry、load/save と dirty 制御
- `feature/storage/service/StorageService`, `feature/storage/command/StorageCommand`
  - `/storage`、ストレージ表示、収納・取り出しの操作を扱う。ストレージ GUI への導線だけを menu feature が持つ。

## 5. 依存・連携

- `player`: join / quit / 保存トリガと `AstPlayer` セッションを利用する。
- `account`: アカウントモードに応じて通常・ツール用インベントリを切り替える。
- `item`: entry と Bukkit `ItemStack` の相互変換、装備・ルーン instance を利用する。
- `item`: オーブ操作の候補抽出と実行前再検証へ、BAG / HOTBAR / 装備中の entry・instance 参照を提供する。
- `menu`: 装備・ストレージ画面を共有する。旧装備加工画面は持たない。
- `status`: `INVENTORY_SLOTS` を BAG の実効容量へ反映する。
- `player-interaction`: `HOTBAR_SLOT` の競合調停を担当する。inventory の装備表示更新は非競合 observer として参加する。

`feature/storage` は独立した実装パッケージだが、所持品 state と永続化を共有するため本 feature の設計範囲に含める。ホットバー保存・ショートカット表示・Bukkit スロット操作も本 feature を正本とする。
