# 08_3-リポジトリ

## 1. インベントリ一覧取得

クラス名: `InventoryRepository`
物理名: `findByAccountId`

説明

accountId に紐づく inventory 一覧を API から取得する。

処理手順:

1. `GET /api/inventory?account_id={accountId}` を送信する
2. `200` は JSON 配列を [[08_1-モデル定義]].インベントリモデル 一覧へ変換する
3. `404` / `500` はエラーとして扱う
4. ステータス異常は `IOException` を送出する

## 2. インベントリ初期作成

クラス名: `InventoryService`, `PlayerStateRepository`

指定 accountId / inventoryType / profile から決定的な UUID をローカル生成し、メモリ上の inventory として直ちに利用可能にする。初回保存では完成スナップショットの inventory 行へ `isNew=true` と作成属性を含め、entry・loadout・equipment・各 player section と同じ SQL transaction で作成する。個別の `POST /api/inventory` は呼ばない。

単体取得 `findById`、entry 単体取得 `findEntryById` も同じ 404 / API 異常方針に従う。

## 3. インベントリエントリ一覧取得

クラス名: `InventoryRepository`
物理名: `findEntries`

説明

inventoryId 配下の entry 一覧を API から取得する。

処理手順:

1. `GET /api/inventory/{inventoryId}/entries` を送信する
2. `200` は JSON 配列を [[08_1-モデル定義]].インベントリエントリモデル 一覧へ変換する
3. `404` は対象 inventory 未存在または削除済みとして扱う
4. ステータス異常は `IOException` を送出する

## 4. 通常保存の完成状態 API

クラス名: `PlayerStateRepository`
物理名: `saveSnapshot`

通常プレイ中の変更は account 単位の完成状態として一回だけ送る。`InventoryRepository` の entry 単位 GET は join/load と外部取引後の正本照合に残るが、通常保存は `replaceEntries`、slot 別 `PUT`、`createEntry` / `updateEntry` / `deleteEntry` を呼ばない。

1. `InventoryPersistence` が state lock 下で inventory、entry、loadout、dirty equipment、登録 section を捕捉する。
2. `POST /api/player-state/snapshots` へ一つの payload を送る。
3. API は同一 transaction で全行を反映し、request の全行・section を含む ACK を返す。
4. Plugin は ACK を検証してから baseline と `updatedAt` を更新する。不完全 ACK、409 を含む確定的な 4xx は保存契約不整合として account の経済操作を止める。
5. 一時通信障害は state を dirty のまま保持し、同じ捕捉 payload を backoff 後に再送する。

## 5. インベントリ metadata 更新

クラス名: `InventoryRepository`
物理名: `updateMetadata`

metadata は完成状態 snapshot の inventory 行に含める。単独 `PUT /api/inventory/{inventoryId}` は通常保存経路では使用しない。

## 6. 装備ロードアウト操作

クラス名: `EquipmentLoadoutRepository`, `InventoryService`, `PlayerStateRepository`
物理名: `findByAccountId`, `findById`

説明

装備ロードアウト本体と slot を初期ロードし、プレイ中の変更は完成スナップショットで反映する。

処理手順:

1. 一覧取得は `GET /api/equipment/loadouts?account_id={accountId}&loadout_profile={profile}` を送信する。
2. 単体照会が必要な外部取引後だけ `GET /api/equipment/loadouts/{loadoutId}` を使用する。
3. 未作成時は決定的な UUID のロードアウトをローカル生成し、初回 snapshot 行へ `isNew=true` と作成属性を含める。
4. アクティブ化と slot 更新・削除はメモリ状態へ即時反映し、loadout と全 slot を完成スナップショットで保存する。個別の作成・activate・slot PUT/DELETE API は呼ばない。
