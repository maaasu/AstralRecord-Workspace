# 08_3-リポジトリ

## 1. インベントリ一覧取得

クラス名: `InventoryRepository`
物理名: `findByAccountId`

説明

accountId に紐づく inventory 一覧を API から取得する。

処理手順:

1. `GET /api/inventory?account_id={accountId}` を送信する
2. `200` は JSON 配列を [[08_1-モデル定義]].インベントリモデル 一覧へ変換する
3. `404` / `500` はエラーとして扱う
4. ステータス異常は `IOException` を送出する

## 2. インベントリ作成

クラス名: `InventoryRepository`
物理名: `create`

説明

指定 accountId / inventoryType / profile の inventory 本体を API に作成する。

処理手順:

1. `POST /api/inventory` に JSON body を送る
2. body には `accountId`, `inventoryType`, `inventoryProfile`, `slotCapacity`, `isEnabled`, `metadataJson`, `createdBy` を含める
3. 成功レスポンスは [[08_1-モデル定義]].インベントリモデル へ変換する

単体取得 `findById`、entry 単体取得 `findEntryById` も同じ 404 / API 異常方針に従う。

## 3. インベントリエントリ一覧取得

クラス名: `InventoryRepository`
物理名: `findEntries`

説明

inventoryId 配下の entry 一覧を API から取得する。

処理手順:

1. `GET /api/inventory/{inventoryId}/entries` を送信する
2. `200` は JSON 配列を [[08_1-モデル定義]].インベントリエントリモデル 一覧へ変換する
3. `404` は対象 inventory 未存在または削除済みとして扱う
4. ステータス異常は `IOException` を送出する

## 4. インベントリエントリ一括置換

クラス名: `InventoryRepository`
物理名: `replaceEntries`

説明

指定 inventoryId の entry 一覧を API へ全置換で反映する。
現行実装では通常プレイ中の変更は `PlayerInventoryState` に蓄積し、save 時に本メソッドで inventoryId 単位に反映する。

処理手順:

1. `PUT /api/inventory/{inventoryId}/entries` に JSON body を送信する
2. body は [[08_1-モデル定義]].インベントリエントリ下書き の配列で構成する
3. 成功レスポンスは [[08_1-モデル定義]].インベントリエントリモデル 一覧へ変換して返す
4. `404` は対象 inventory 未存在または削除済みとして扱う
5. ステータス異常は `IOException` を送出する

個別操作が必要な呼び出し元には `createEntry`、`updateEntry`、`deleteEntry` を提供する。通常プレイ中の dirty state 保存は、個別操作ではなく `replaceEntries` を使用する。

## 5. インベントリ metadata 更新

クラス名: `InventoryRepository`
物理名: `updateMetadata`

`PUT /api/inventory/{inventoryId}` へ metadata と更新者を送信し、ツール用インベントリ snapshot など state 上の metadata 差分を反映する。

## 6. 装備ロードアウト操作

クラス名: `EquipmentLoadoutRepository`
物理名: `findByAccountId`, `findById`, `create`, `activate`, `upsertSlot`, `deleteSlot`

説明

装備ロードアウト本体と slot 差分を API へ反映する。

処理手順:

1. 一覧取得は `GET /api/equipment/loadouts?account_id={accountId}&loadout_profile={profile}` を送信する
2. 作成は `POST /api/equipment/loadouts` を送信する
3. アクティブ化は `POST /api/equipment/loadouts/{loadoutId}/activate` を送信する
4. slot upsert は `PUT /api/equipment/loadouts/{loadoutId}/slots` を送信する
5. slot delete は `DELETE /api/equipment/loadouts/{loadoutId}/slots/{slotType}/{slotIndex}?updated_by={updatedBy}` を送信する

`InventoryPersistence.save(...)` は前回保存スナップショットとの差分比較で changed slot のみ `upsertSlot` / `deleteSlot` を呼ぶ。
