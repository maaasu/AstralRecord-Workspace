# 08_3-サービス

## 1. state 参照

クラス名: `InventoryService`
物理名: `getInventories`, `getInventory`, `getEntries`, `getPersistence`, `getStateRegistry`

説明

inventory feature の読み取り系は API を直接呼ばず、`PlayerInventoryStateRegistry` 上の state を参照する。

処理手順:

1. `accountId` から `PlayerInventoryState` を取得する
2. inventory 一覧、inventory 単体、entry 一覧を state から返す
3. state 未登録時は空一覧または `null` を返す

## 2. 通常インベントリアイテム追加

クラス名: `InventoryService`
物理名: `addItemToNormalInventory`, `addItemToNormalInventoryWithCapacityResult`, `reserveBagSlotForPreparedInstance`, `completePreparedInstanceReservation`, `releasePreparedInstanceReservation`

説明

取得アイテムを統合 `BAG` へ追加し、state を更新する。通貨だけは `CURRENCY` を使用する。BAG の `INVENTORY_SLOTS` による実効容量に空きがなければ追加数0を返す。容量外の既存 entry は新規追加先として再利用しない。

`addItemToNormalInventoryWithCapacityResult` は、実付与数、新規に占有した BAG slot 数、付与後の BAG 空き slot 数を同じ state lock 内で返す。`addItemToNormalInventory` は互換用にこの結果の実付与数だけを返す。通貨または state 未登録時の BAG 空き slot 数は `-1` とする。

Mob / gathering など、装備・ルーン個体を非同期 API で事前生成する経路は `reserveBagSlotForPreparedInstance` で BAG slot を先に予約する。予約済み slot は全ての通常 slot 解決と BAG の削除後前詰め処理で使用済みとして扱い、生成成功時だけ `completePreparedInstanceReservation` で同じ slot の entry に確定する。同メソッドは確定追加後の BAG 空き slot 数を state lock 内で返す。予約後に実効容量が下がっても、その確定 entry は容量外 entry として保持する。生成失敗・演出取消時は `releasePreparedInstanceReservation` で予約を解除する。

処理手順:

1. item category から格納先 `InventoryType` を解決する
2. 対象 inventory が未存在なら `ensureInventory` で API に同期作成する
3. 装備・ルーンは必要に応じて instanceId を生成して新規 entry を追加する
4. 通常スタック可能アイテムは実効容量内の既存 entry へ加算するか、実効容量内の空き slot へ追加する。容量外 entry には加算しない
5. 非同期個体生成の予約中 slot は空き slot として再利用せず、予約確定時は予約 slot へだけ entry を追加する
6. 追加成功時は `state.replaceEntries(...)` により dirty を立てる
7. 対象 inventory が表示中なら GUI を再描画する
8. 容量通知が必要な呼び出し元は付与結果を使い、メッセージ送信は `InventoryService` に重複実装しない

## 3. 管理者インベントリ保存・反映

説明

`InventoryProfile.ADMIN` 用 `BAG` inventory の `metadataJson` に `admin` キーの Bukkit 実インベントリスナップショットと `GameMode` を保持し、`AccountMode.ADMIN` の場合だけ保存・反映する。

## 4. 表示インベントリ GUI 反映

クラス名: `InventoryService`
物理名: `applyInventoriesToGui`, `applyInventoryToGui`, `getDisplayedInventoryType`, `clearGuiInventory`

説明

表示対象 inventory を Bukkit `PlayerInventory` の管理スロットへ反映する。

処理手順:

1. state 上の `displayedType` と対象 inventory を解決する
2. `InventoryItemStackResolver` で entry を `ItemStack` へ変換する
3. BAG の表示範囲は、実効容量と保持中 entry の最大 `slotIndex` の大きい方までとする
4. 容量外 entry に「容量外: 移動・破棄のみ」を付け、空の容量外枠は新規配置不可の黒色枠として表示する
5. 管理対象スロットだけを書き換え、不要な再配置を避ける
6. GUI 反映対象 mode でない場合は何もしない

## 6. 現在装備同期

クラス名: `InventoryService`
物理名: `syncCurrentEquipmentState`

説明

Bukkit の現在装備状態を active loadout に同期する。

処理手順:

1. 頭 / 胴 / 脚 / 足 / オフハンド / 種類別アクセサリ9枠の `ItemStack` から装備インスタンス ID を読む
2. `PlayerInventoryState.upsertActiveLoadoutSlot(...)` で loadout slot を更新する
3. loadout 更新により dirty を立てる

## 7. 装備 GUI 保存

クラス名: `InventoryService`
物理名: `saveEquipmentGui`

説明

装備 GUI 上の ItemStack を `EQUIP_SLOT` / `ACCESSORY_SLOT` inventory と active loadout へ反映する。

処理手順:

1. GUI スロットの ItemStack を inventory entry へ変換する。アクセサリは `equipment.tag` と対象の種類別スロットが一致することを検証する
2. 防具・オフハンド・種類別アクセサリ9枠を `EQUIP_SLOT` / `ACCESSORY_SLOT` inventory へ `state.replaceEntries(...)` で置き換える
3. active loadout slot も同時に更新する
4. Bukkit 現在装備状態は防具とオフハンドのみ更新する。種類別アクセサリは仮想装備として state と loadout に保持する

## 10. ホットバー操作

クラス名: `InventoryService`
物理名: `handleHotbarSlotClick`, `moveToHotbar`, `setHotbarShortcutMode`, `isHotbarShortcutMode`, `hasHotbarEntry`

クラス名: `HotbarShortcutClickSupport`
物理名: `handle`

説明

`InventoryService` はホットバー entry の選択と Bukkit スロット操作を扱い、`HotbarShortcutClickSupport.handle` は各 GUI の共通ショートカットクリックを処理する。
- ホットバーは Bukkit slot `0..8` の9枠すべてをアイテム割当へ使用する。
- カスタムGUI表示中もホットバー割当アイテムを維持し、BAG 制御列中央の Bukkit slot `26` はインベントリ情報を表示する。
- `HotbarShortcutGuiHolder` 対象 GUI に専用の閉じるアイコンは配置せず、ホットバー9枠は通常表示を維持する。GUI の終了は標準のインベントリ閉じる操作と `InventoryCloseEvent` で扱う。
- lore は `→ 通常[所持アイテム数]` / `→ 装備[所持アイテム数]` / `→ ルーン[所持アイテム数]` を表示し、選択中の行のみ太字にして末尾へ黄色の ` (選択中)` を付ける。
- 空スロット選択は「割当先選択」とみなし、呼び出し元ではクリック音を再生する。
- 表示中インベントリからホットバーへ割り当てる操作は移動扱いとし、HOTBAR entry を更新したあと元インベントリ entry を削除する。
- ホットバーへ割り当てた直後も BAG の `bagScrollRow` を維持する。
- ホットバーからアイテムを外した場合は BAG へ entry を返却する。

## 11. 装備移動とアクセサリ移動

クラス名: `InventoryService`
物理名: `equipToSlot`, `moveOwnedItemToEquipmentGui`, `moveToAccessorySlot`, `returnItemToOwnedInventory`, `compactInventoryEntries`

説明

表示中 inventory と装備 GUI / 防具スロット / アクセサリスロット間の移動を行う。

処理手順:

1. 移動元 entry または Bukkit `ItemStack` を解決する
2. 防具・サブ武器・アクセサリを装備スロットへ移動する場合は `requiredLevel` と、現在クラスに一致する `requiredClasses[].classId / level` を検証する。条件未達時は移動せず、理由を player message で通知する
3. 必要に応じて instanceId を保持したまま戻し先 inventory へ追加する
4. entry を全量移動して削除した場合、BAG は容量外 entry を失わないよう全 entry を表示順のまま連続する `slotIndex` へ詰め直す。部分移動では元の `slotIndex` を維持し、HOTBAR は固定スロットのため詰め直さない
5. 変更結果を state に反映し、dirty を立てる
6. BAG の現在スクロール位置を維持して GUI を再描画する

## 12. 即時保存

クラス名: `InventoryService`
物理名: `saveNow`

説明

マーケットやストレージ終了など即時整合性が必要な操作を、`InventorySaveCoordinator` のアカウント別保存キューへ登録する。state 未登録時は完了値 `false` を返す。

## 13. 旧 flush API の互換フック

クラス名: `InventoryService`
物理名: `flushPendingCoalescedWrites`, `awaitPendingWrites`

説明

旧 coalescer 実装との互換のために残しているフック。
現行実装では `flushPendingCoalescedWrites` は no-op、`awaitPendingWrites` は `InventoryPersistence.awaitShutdown(...)` を呼ぶだけである。

即時整合性が必要な処理は `InventoryPersistence.saveNow(PlayerInventoryState)` を使う。

## 14. ストレージ操作

クラス名: `InventoryService`
物理名: `getStorageViewEntries`, `moveOwnedItemToStorage`, `moveAllOwnedMatchingItemsToStorage`, `withdrawStorageEntry`

説明

ストレージ GUI 用に `STORAGE` inventory の表示一覧取得、表示中インベントリからの収納、ストレージから所持インベントリへの取り出しを行う。

処理手順:

1. `getStorageViewEntries` は state 上の `STORAGE` entry を `StorageViewEntry` に変換する
2. カテゴリフィルタとレア度フィルタが指定されている場合は、`ItemModel.category` / `ItemModel.rarity` で絞り込む
3. 並び順は収納順（`slotIndex`）、獲得順（`metadataJson.acquiredAt`）、レア度順、売値順から選択し、昇順・降順を適用する
4. `moveOwnedItemToStorage` は表示中 inventory の Bukkit slot から entry を解決し、`instanceType` / `instanceId` を持たない通常アイテムは同一 itemId / itemCategory の既存 storage entry へ数量加算する。装備・ルーンなど instanceId と紐づくアイテムは統合せず新しい `STORAGE` entry を追加する
5. `moveAllOwnedMatchingItemsToStorage` は基準 slot と同一 itemId / itemCategory の通常アイテムを BAG・ホットバー全体から収集して一括収納する。個体 ID を持つアイテムは基準 slot の1個だけを収納する
6. 収納時は `slotIndex` に次の収納順を採番し、収納元 entry の `createdAt` を `metadataJson.acquiredAt` に保存する
7. `withdrawStorageEntry` は対象 storage entry を通常の所持インベントリへ戻す。Shift+左相当は1スタック上限、Shift+右相当は空き容量まで全量を複数スタックへ分割する
8. 収納・取り出し後は対象 entry の数量を減算または削除し、state の dirty を立てる
9. ストレージ GUI を閉じる時、変更がある場合だけ `saveNow` を呼ぶ
10. BAG から全量収納して entry が消えた場合は、後続 entry を表示順のまま前詰めする

## 15.1. オーブ操作の保存laneとAPI正本照合

クラス名: `InventorySaveCoordinator`, `InventoryService`
物理名: `executeExclusiveAfterSave`, `findOwnedEntry`, `reconcileOrbOperationEntries`

処理内容:

1. `findOwnedEntry` は account ID と inventory entry ID を使い、BAG / HOTBAR の現在 state から所有 entry を再解決する。GUI 上の ItemStack は正本にしない。
2. baseline-aware `executeExclusiveAfterSave` は非coalesce jobとして同一account laneへ入り、現在stateとdurability dirtyをAPIへ保存する。保存中変更が無くなった最後の成功応答entryを `PersistedInventoryBaseline` として固定してからオーブ原子操作を開始する。
3. Pluginはオーブ・素材・goldを先行消費しない。クリック時はAPI支払い量を予約し、報酬加算・新規entry・entry移動を止めず、予約量との二重消費だけを防ぐ。stable pre-save中は対象通常itemの消費を保留し、baseline取得後にそのpersisted rowsへentry別予約を再配分してから予約外残量の消費を許可する。goldは額面にかかわらず予約総価値を利用可能残高から除外する。
4. API transactionを唯一の支払い正本とする。API開始前の事前保存・state世代失敗では予約を解除し、POST開始後の応答不明・割り込みでは同じ予約と未解決境界を維持する。
5. APIは業務失敗時の起点オーブを含む `affectedInventoryEntryIds` を返す。`reconcileOrbOperationEntries` は全正本取得に成功してから、通常entryを `authoritative + (current - baseline)` で一度だけ三者マージする。API tombstoneへ正のローカル差分がある場合は新UUIDへ載せ替え、削除済みIDを復活させない。数量だけの部分減少は既存slotを保持し、entry全削除時だけBAGを表示順で前詰めする。HOTBARの固定slotは全削除時も前詰めしない。
6. goldはaffected IDだけでなくCURRENCY inventoryの全正規額面とlegacy IDを取得し、baseline・current・authoritativeの総価値差分を正規額面へ再構成する。baseline後の新規entry、同時加算・予約外消費、slot・metadata変更は保持する。
7. 応答不明時は同じoperationIdのPOST再送・GET台帳照会をbackoff付きで続ける。正本取得失敗中はstateを変更せず、三者マージ完了後の保存再試行ではAPI差分を再適用しない。マージ済みstateのdirtyが安定して消えたことをstate monitor内で確認してから未解決境界を解除し、後続auto-save/logout-saveへ進む。負数量・桁あふれは丸めず未解決境界を保持する。
8. `targetAvailable=false` は装備cacheとstate内inventory/loadout参照を破棄し、同lane内でcleanupを含むマージ済みstateの保存が成功するまでoperationを確定扱いにしない。ローカル推測によるrollbackを行わず、未解決操作を持つstateはauto-save・logout-save・停止保存の対象にしない。
9. プラグイン停止時はproducer停止・オーブsession detach後、accepted済みaccount laneを最大5秒先にdrainする。未解決操作がないaccountだけをmain threadでcache正本表示へ再描画・snapshot準備し、`PLUGIN_DISABLE` 非coalesce jobを登録してから新規lane受付を閉じる。保存成功時だけinventory state・equipment cache・該当 `AstPlayer` cacheを解放し、timeout・未解決・競合accountは古いstateを直接保存・clearせず、事前保存済みstateとAPI/DB正本を次回起動時に再読込する。

## 16. 表示スロット補足

- 表示インベントリを Bukkit `PlayerInventory` へ反映する際、管理対象スロット `9`〜`35` の利用可能な空き枠は `GRAY_STAINED_GLASS_PANE`、容量外の空き枠は `BLACK_STAINED_GLASS_PANE` で敷き詰める。
- `ADMIN` の Bukkit inventory と `GameMode` は、`InventoryProfile.ADMIN` の `BAG.metadataJson` に `admin` キーで保持する。
- `saveToolInventorySnapshot` は metadata 変更を state の dirty tracking へ載せ、`InventoryPersistence.save` が未保存 metadata を `InventoryRepository.updateMetadata` で反映する。
- autosave は Bukkit API をメインスレッドで snapshot 化してから、API 永続化だけを非同期保存キューへ渡す。

## 17. feature 境界

- オーブ操作は装備を一時退避せず、Pluginの現在stateとAPI transaction内の所有・配置条件を再検証する。支払いと装備更新はoperation台帳と同時に確定する。
- storage への明示 transfer は同じ item の hotbar 割当より優先する。旧 BAG に残る currency entry の一括移動は `CURRENCY` inventory へ戻す。
- status refresh は永続 DTO の装備値ではなく、現在 inventory / loadout が保持する装備 instance 参照を bonus 計算へ渡す。
