# 08_3-タスク・補助

## 1. インベントリ保存

クラス名: `InventorySaveTask`
物理名: `prepare`, `save`

説明

player feature の保存トリガから Bukkit 側の最新状態を `PlayerInventoryState` に取り込み、その state を API へ反映する。

処理手順:

1. `prepare` はメインスレッドで、ツール用または通常プレイ用の Bukkit inventory snapshot を state へ取り込む。
2. `save` は `PlayerInventoryStateRegistry` から accountId の state を取得し、未登録なら終了する。
3. player 保存トリガを永続化用トリガへ変換し、`InventoryPersistence.save(state, trigger)` を呼ぶ。

## 2. インベントリオートセーブ

クラス名: `InventoryAutoSaveTask`
物理名: `start`, `runSaveAll`, `stop`

説明

online プレイヤーの dirty state を 60 秒間隔で保存する。

処理手順:

1. plugin 起動時に 60 秒間隔の timer を開始する
2. `AUTO_SAVE_MESSAGE=true` の online プレイヤーへ、灰色の `PlayerMsgId.P_5280` で開始を通知する
3. メインスレッドで tool inventory snapshot を取得した後、非同期処理へ渡す
4. `PlayerInventoryStateRegistry.all()` で online 全 state を走査する
5. 各 state を `InventorySaveCoordinator.saveAuto(state)` のアカウント別保存キューへ登録する
6. 全 state が例外なく終了し、保存試行後に dirty が復元された state もない場合だけ、保存開始からの経過時間をミリ秒で渡して、開始通知対象かつ online のプレイヤーへ灰色の `PlayerMsgId.P_5281`（`({0}ms)` 付き）で完了を通知する
7. 保存失敗時は `LogId.W_5252` を WARN 出力し、他プレイヤーの保存を継続する。失敗した周期では完了通知を送らない
8. plugin disable 時は timer を停止する

ログ:

| ID | レベル | テンプレート | 出力条件 | 引数 |
|---|---|---|---|---|
| `LogId.W_5252` | WARN | `インベントリ同期に失敗しました: target=%s, reason=%s` | autosave または永続化処理が例外・失敗を返した場合 | `target=accountId`, `reason=例外メッセージまたは失敗理由` |

## 3. ItemStack 変換

クラス名: `InventoryItemStackResolver`
物理名: `resolve`

説明

[[08_1-モデル定義]].インベントリエントリモデル から Bukkit `ItemStack` を復元する。

処理手順:

1. entry の `itemId` から item feature の `ItemModel` を取得する
2. `instanceType=EQUIPMENT` の場合は装備インスタンス付き `ItemStack` を生成する
3. `instanceType=RUNE` の場合はルーンインスタンス付き `ItemStack` を生成する
4. 通常アイテムは数量を `maxStack` に収めて生成する
5. モデル解決不能時は `null` を返す

## 4. スナップショットエンコード・デコード

クラス名: `InventorySnapshotCodec`
物理名: `encode`, `decode`

説明

Bukkit `ItemStack[]` と `metadataJson` の相互変換を行う。

処理手順:

1. `encode` は `ItemStack[]` を `BukkitObjectOutputStream` で Base64 化し JSON へ格納する
2. `decode` は JSON から contents 配列を取り出し、Base64 + `BukkitObjectInputStream` で `ItemStack[]` を復元する
3. 新形式に失敗した場合は legacy contents の復元を試みる
4. 復元不能時は `null` を返す

## 5. 永続化制御

クラス名: `InventoryPersistence`
物理名: `load`, `save`, `hasPendingChanges`, `saveNow`, `clearAccount`, `awaitShutdown`

説明

join 時ロードと dirty state 永続化を担う。

処理手順:

1. `load(accountId)` は inventory 一覧、各 inventory entry、equipment loadout を API から取得して `PlayerInventoryState` を構築する
2. `save(state, trigger)` は `dirty` が立っている場合だけ保存する
3. inventory は inventoryId 単位で `replaceEntries` を呼ぶ
4. loadout は前回保存スナップショットとの差分比較で changed slot だけ `upsertSlot` / `deleteSlot` を呼ぶ
5. 保存失敗時は WARN を出し、`state.restoreDirty()` で次回 save 対象へ戻す
6. `saveNow(state)` は即時整合性が必要な処理向けで、`dirty` を立てたうえで通常 save を流用する

## 6. アカウント別保存調停

クラス名: `InventorySaveCoordinator`
物理名: `saveNow`, `saveAuto`, `enqueueLogoutReconciliation`, `saveOnLogout`, `beginClosing`, `awaitPendingWrites`

処理内容:

1. 同一 accountId の保存を直列化し、autosave の重複要求はまとめる。
2. logout ではメインスレッドで取得済み snapshot を保存し、失敗した state を retained state として保持する。
3. retained state があるアカウントの再ログイン時は、前回 state の未保存差分を先に reconciliation する。
4. plugin disable 開始後は新規要求を拒否し、既存の保存完了を指定時間まで待つ。
