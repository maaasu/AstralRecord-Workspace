# 08_3-タスク・補助

## 1. インベントリ保存

クラス名: `InventorySaveCoordinator`, `InventoryPersistence`
物理名: `saveAuto`, `saveNow`, `saveCriticalNow`, `saveForBoundary`

説明

保存トリガを account 別 lane へ登録し、状態を完成スナップショットとして API へ反映する。Bukkit inventory の取り込みは表示・退出処理の既存メインスレッド境界で行い、保存 task が slot 別の API 更新を組み立てない。

処理手順:

1. 通常変更は `saveAuto` へ登録し、200ms の debounce 範囲で同一 account の autosave を集約する。
2. `saveNow` と `saveForBoundary` は先行 autosave を先に確定する。チャンネル移動などの境界は ACK 成功時だけ続行する。
3. 重要操作は `executeCriticalMutation` 内でローカル変更と rollback を登録する。pre-save の capture 中に通常変更が増えた場合は既存の安定化処理で次便まで保存し、未保存差分がなくなってから変更を実行する。`saveCriticalNow` の ACK 後だけ成功を返し、保存失敗が確定した場合は pending snapshot を後送せず rollback を実行する。HTTP 200 後の ACK 契約不一致は SQL 保存済みの可能性があるため、完成ローカル状態と blocked snapshot を保持して rollback しない。

## 2. インベントリオートセーブ

クラス名: `InventoryAutoSaveTask`
物理名: `start`, `runSaveAll`, `stop`

説明

online プレイヤーの dirty state を 60 秒間隔で保存する。

処理手順:

1. plugin 起動時に 60 秒間隔の timer を開始する
2. `AUTO_SAVE_MESSAGE=true` の online プレイヤーへ、灰色の `PlayerMsgId.P_5280` で開始を通知する
3. メインスレッドで tool inventory snapshot を取得した後、非同期処理へ渡す
4. `PlayerInventoryStateRegistry.all()` で online 全 state を走査する
5. 各 state を `InventorySaveCoordinator.saveAuto(state)` のアカウント別保存キューへ登録する
6. 全 state が例外なく終了し、保存試行後に dirty が復元された state もない場合だけ、保存開始からの経過時間をミリ秒で渡して、開始通知対象かつ online のプレイヤーへ灰色の `PlayerMsgId.P_5281`（`({0}ms)` 付き）で完了を通知する
7. 保存失敗時は `LogId.W_5252` を WARN 出力し、他プレイヤーの保存を継続する。失敗した周期では完了通知を送らない
8. plugin disable 時は timer を停止する

ログ:

| ID | レベル | テンプレート | 出力条件 | 引数 |
|---|---|---|---|---|
| `LogId.W_5252` | WARN | `インベントリ同期に失敗しました: target=%s, reason=%s` | autosave または永続化処理が例外・失敗を返した場合 | `target=accountId`, `reason=例外メッセージまたは失敗理由` |

## 3. ItemStack 変換

クラス名: `InventoryItemStackResolver`
物理名: `resolve`, `resolveForBag`

説明

[[08_1-モデル定義]].インベントリエントリモデル から Bukkit `ItemStack` を復元する。

処理手順:

1. entry の `itemId` から item feature の `ItemModel` を取得する
2. `instanceType=EQUIPMENT` の場合は装備インスタンス付き `ItemStack` を生成する
3. 通常アイテム（ルーンを含む）は数量を `maxStack` に収めて生成する
4. モデル解決不能時は `null` を返す
5. 通常 BAG 表示用の `resolveForBag` は、武器・道具・バンドル・消耗品へ「クリックでホットバースロットに設定」、有効なオーブへ「クリックで使用」の lore を追加する。`resolve` はこの案内を追加せず、HOTBAR・装備スロット・STORAGE・ごみ箱など別の表示経路で再利用する

## 4. スナップショットエンコード・デコード

クラス名: `InventorySnapshotCodec`
物理名: `encode`, `decode`

説明

Bukkit `ItemStack[]` と `metadataJson` の相互変換を行う。

処理手順:

1. `encode` は `ItemStack[]` を `BukkitObjectOutputStream` で Base64 化し JSON へ格納する
2. `decode` は JSON から contents 配列を取り出し、Base64 + `BukkitObjectInputStream` で `ItemStack[]` を復元する
3. 新形式に失敗した場合は legacy contents の復元を試みる
4. 復元不能時は `null` を返す

## 5. 永続化制御

クラス名: `InventoryPersistence`
物理名: `load`, `save`, `hasPendingChanges`, `saveNow`, `clearAccount`, `awaitShutdown`

説明

join 時ロードと dirty state 永続化を担う。

処理手順:

1. `load(accountId)` は inventory 一覧、各 inventory entry、equipment loadout を API から取得して `PlayerInventoryState` を構築する。アイテムマスタの完全スナップショットが公開済みの場合は、存在しない通常 item master を参照する entry と、存在しない item master を参照する装備 instance の inventory / loadout 参照を破棄し、即時保存で API 正本からも論理削除する。撤廃済みスキルジェムは master 未解決の通常 entry として次回ロード時に補償なしでこの処理の対象とする。マスタ未ロード時は誤削除を避けるため cleanup しない
2. `save(state, trigger)` は dirty state、dirty equipment、登録 section のいずれかがある場合に完成状態を捕捉する
3. `PlayerStateRepository.saveSnapshot` は inventory / entry / loadout / equipment / section を同一 transaction で保存する
4. ACK 検証成功時だけ baseline と各 `updatedAt` を反映する。捕捉後の変更は dirty のまま維持する
5. 一時通信障害は同じ pending snapshot を指数 backoff（上限30秒）で再送する。確定的な 4xx または ACK 不正は snapshot を blocked とし、自動再送しない
6. `saveNow` は pending snapshot を含めて ACK 完了を確認する。`saveCriticalNow` は通信失敗 snapshot を破棄して呼出元の rollback へ失敗を返す。ACK 契約不一致では pending / blocked snapshot を保持し、呼出元へ補償禁止の失敗を通知する

## 6. アカウント別保存調停

- 同一 account の autosave は200msで集約し、通常保存、重要操作、logout、境界 flush は同じ account lane で直列化する。
- logout 保存が失敗した state は in-memory retained state として registry 上に保持する。再ログインは同じ state lease を引き継ぎ、古い永続データを再読込しない。これはローカル保留ファイルではない。
- 通常の再ログイン待機は先行保存の失敗を既存仕様どおり非伝播とするが、アカウント切替は `awaitQueuedSavesOrThrow` で旧セッションの全保存結果を確認し、`false` または例外があれば切替を中止する。
- closing drain 後の late save / 外部操作は dirty flag を消さず拒否する。外部操作がまだ開始されていない場合は未解決境界を解除して例外完了し、支払い予約を呼び出し側で解放できるようにする。pending write の待機処理自身は保存 lane を作成・追従せず、自己待機を発生させない。
- inventory 本体、equipment durability、登録 section のいずれかが pending なら `saveNow` は成功を返さない。
- market、trade、既存の外部 API 原子操作は API 正本の entry を返すため、保存前 baseline と外部操作後の正本を三者マージして state の期待集合を更新する。これは通常保存の reconciliation ではなく、外部取引結果を local state へ反映するための専用 lane である。

クラス名: `InventorySaveCoordinator`
物理名: `saveNow`, `saveAuto`, `saveForBoundary`, `executeCriticalMutation`, `saveOnLogout`, `saveOnLogoutWithResult`, `awaitQueuedSavesOrThrow`, `beginClosing`, `awaitPendingWrites`

処理内容:

1. 同一 accountId の保存を直列化し、autosave の重複要求はまとめる。
2. logout ではメインスレッドで取得済み snapshot を保存し、失敗した state を retained state として保持する。
3. retained state があるアカウントの再ログイン時は、同じ in-memory state を lease として取得し、保存 lane の完了後に引き継ぐ。
4. plugin disable 開始後は新規要求を拒否し、既存の保存完了を指定時間まで待つ。
