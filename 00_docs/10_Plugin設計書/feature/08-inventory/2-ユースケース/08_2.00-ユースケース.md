# 08_2.00-ユースケース

## 1. 統合所持品表示・スクロール

対象: プレイヤー

契機: `/inventory`、インベントリ表示、上スクロール・下スクロールクリック

事前条件:

- プレイヤーが [[03_1.00-モデル定義]].プレイヤーセッション としてキャッシュ済みである
- アカウントモードが GUI インベントリ反映対象である
- `BAG` inventory がロード済みである

正常系:

1. BAG の `slotCapacity` を8スロット単位の行へ分割する
2. `bagScrollRow` から連続3行を解決し、Bukkit slot 9〜16 / 18〜25 / 27〜34へ反映する
3. slot 17 / 26 / 35へ上スクロール／情報／下スクロールを反映する
4. スクロールクリック時は `bagScrollRow` を1だけ増減し、同じ3行表示を再描画する
5. カスタムGUI表示中も slot 26 はインベントリ情報を表示し、専用の閉じるアイコンは配置しない

## 2. アイテム付与

対象: コマンド・ルート報酬等の呼び出し元

正常系:

1. 通貨は `CURRENCY`、それ以外はカテゴリを問わず `BAG` を格納先にする
2. 必要なインベントリが存在しなければ作成する
3. スタック可能アイテムは既存エントリへ数量加算する
4. 装備・ルーン等は個体 ID を作成してエントリを追加する
5. BAG の `slotCapacity` に空きがなければ追加数0として取得を拒否する
6. 追加後は現在のスクロール位置を維持して GUI を再描画する

## 3. 装備 GUI 操作

対象: プレイヤー

正常系:

1. 装備可能スロットと ItemStack の装備種別を照合する
2. 既存装備があれば所有インベントリへ戻す
3. 新しい装備を Bukkit 装備スロットまたは装備 GUI スロットへ配置する
4. EQUIP_SLOT / ACCESSORY_SLOT のスナップショットを保存する
5. 有効装備プリセットへ装備状態を同期する

## 4. ホットバー割当とショートカット表示

対象: プレイヤー

補足:

- ホットバー9枠はカスタムGUI表示中も通常の割当アイテムを表示する
- カスタムGUIに対象アイテムを移動するクリック処理がある場合は、その処理を通常ホットバー操作より優先する

正常系:

1. 表示中インベントリの該当エントリを取得する
2. ホットバー空きスロットまたは選択スロットを解決する
3. HOTBAR インベントリのエントリを更新する
4. 元インベントリの該当エントリを削除し、表示中インベントリを再描画する
5. ホットバーへ割り当てた後も BAG のスクロール位置を維持する
6. Bukkit ホットバーへ表示アイテムまたはショートカットアイコンを描画する

補足:

- ホットバーからアイテムを外した場合は BAG へ返却する

## 5. スナップショット保存・読み込みメソッド提供

対象: player feature 等、保存・復元の契機を制御する呼び出し元

責務範囲:

inventory feature は指定 account のインベントリ本体・エントリの提供と、自機能が管理する 4 種スナップショット（`BAG` / `EQUIP_SLOT` / `ACCESSORY_SLOT` / `HOTBAR`）の保存・読み込みメソッドの提供までを担当する。
保存・復元の契機、実行順序、リトライ、失敗時の業務挙動は呼び出し元の責務とし、inventory feature は判断しない。

提供する保存メソッド:

- [[08_3.02-サービス]].統合所持品スナップショット保存 — BAG 表示領域を扱う
- [[08_3.02-サービス]].装備スロットスナップショット保存 — 防具スロット・オフハンドを `EQUIP_SLOT` エントリへ保存する
- [[08_3.02-サービス]].アクセサリスロットスナップショット保存 — アクセサリ装備状態を `ACCESSORY_SLOT` エントリへ保存する
- [[08_3.02-サービス]].ホットバースナップショット保存 — ホットバーを `HOTBAR` エントリへ保存する

提供する読み込みメソッド:

- [[08_3.02-サービス]].通常インベントリスナップショット読み込み
- [[08_3.02-サービス]].装備スロットスナップショット読み込み
- [[08_3.02-サービス]].アクセサリスロットスナップショット読み込み
- [[08_3.02-サービス]].ホットバースナップショット読み込み

呼び出し元との契約:

1. 呼び出し元が必要な保存・読み込みメソッドを必要なタイミングで呼ぶ
2. inventory feature 側は呼び出しごとに単独で完結し、他のスナップショットの状態には依存しない
3. 保留中の非同期書き込み待機は呼び出し元から要求された場合のみ実施する

## 6. ストレージ収納・取り出し

対象: プレイヤー

契機: `/storage`、または別途用意されるストレージオープンイベント

正常系:

1. ストレージ GUI を開き、`STORAGE` inventory の entry 一覧を表示する
2. 初期表示はアイテムを収納した順とし、`slotIndex` の昇順を収納順として扱う
3. 下部プレイヤーインベントリの表示中アイテムをクリックすると `STORAGE` entry として追加し、収納元 entry から該当数量を減算または削除する。Shift+右クリックの場合は BAG・ホットバー全体の同一 itemId / itemCategory の通常アイテムを一括収納する
4. 収納時は `instanceType` / `instanceId` を持たない通常アイテムだけ、同一 itemId / itemCategory の既存 storage entry へ数量統合する。装備・ルーンなど instanceId と紐づくアイテムは既存 entry へ統合せず、別 entry / 別スロットとして表示する
5. ストレージ内アイテムをクリックすると通常の所持インベントリへ戻し、`STORAGE` entry から該当数量を減算または削除する。Shift+右クリックでは BAG の空き容量まで対象 entry の全量を複数スタックへ分割して取り出す
6. 収納・取り出し操作ではストレージ表示情報をメモリ上で更新して開いている GUI ページを再描画し、変更がある場合は GUI を閉じる時にまとめて即時 save する
7. GUI ではカテゴリとレア度でフィルタできる
8. 並び順は収納順、獲得順、レア度順、売値順を選択でき、各並び順で昇順・降順を切り替えられる
9. 数量規則は左クリック1個、右クリック半分（切り上げ）、Shift+左クリック1スタック、Shift+右クリック全量とする

補足:

- 収納順は収納時に採番した `slotIndex` を使う。
- 獲得順は収納元 entry の `createdAt` を `metadataJson.acquiredAt` に保存して使う。古いデータで値が無い場合はストレージ entry の `createdAt` を使う。
