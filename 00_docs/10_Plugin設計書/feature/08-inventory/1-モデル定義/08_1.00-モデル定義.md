## 3. インベントリ種別

対象実装: `InventoryType`

| 値 | コード | 用途 | スロット管理 | インスタンス対応 | コマンド表示 |
|---|---|---|---|---|---|
| `BAG` | `BAG` | 未装着の通常アイテム・装備・ルーンを統合した所持品 | あり | あり | 可 |
| `CURRENCY` | `CURRENCY` | 通貨 | あり | なし | 不可 |
| `STORAGE` | `STORAGE` | ストレージ | なし | なし | 不可 |
| `EQUIP_SLOT` | `EQUIP_SLOT` | 装備スロット保存 | あり | あり | 不可 |
| `HOTBAR` | `HOTBAR` | ホットバー保存 | あり | なし | 不可 |
| `ACCESSORY_SLOT` | `ACCESSORY_SLOT` | アクセサリスロット保存 | あり | あり | 不可 |

`/inventory` の表示対象は `BAG` のみ。アイテムカテゴリによる表示切替は行わない。

`BAG.slotCapacity` は所持可能な論理スロット数で、既定値は32。1行を8スロットとして扱い、Bukkit PlayerInventory の3行には24スロットを表示する。右端列の slot 17 / 26 / 35 はそれぞれ上スクロール、インベントリ情報、下スクロールの制御領域とし、BAG entry は配置しない。既定状態では4行目を1行スクロールして表示できる。

`STORAGE` は `/storage` と別途用意されるストレージオープンイベントから操作する。メインメニューにはストレージアイコンを配置しない。`slotIndex` は GUI の物理スロットではなく収納順を表す連番として使い、`metadataJson.acquiredAt` に収納元 entry の作成日時を保持して獲得順ソートに利用する。`instanceType` / `instanceId` を持たない通常アイテムは同一 itemId / itemCategory の既存 entry へ数量統合し、装備・ルーンなど instanceId と紐づくアイテムは統合せず別 entry として保持する。

## 5. アクセサリスロット種別

対象実装: `AccessorySlotType`

`ACCESSORY_SLOT` inventory の `slotIndex 1..10` を表す列挙。`slotIndex 1` はオフハンド、`slotIndex 2..10` は種類別アクセサリとして扱う。アクセサリ装備は item master の `equipment.slot = ACCESSORY` に加え、`equipment.tag` がスロット種別と一致する場合のみ配置できる。

| 値 | slotIndex | 用途 |
|---|---:|---|
| `OFF_HAND` | 1 | オフハンド |
| `AMULET` | 2 | アミュレット x1。`equipment.tag = AMULET` |
| `TALISMAN_1` | 3 | タリスマン x2 の1枠目。`equipment.tag = TALISMAN` |
| `TALISMAN_2` | 4 | タリスマン x2 の2枠目。`equipment.tag = TALISMAN` |
| `CHARM_1` | 5 | チャーム x3 の1枠目。`equipment.tag = CHARM` |
| `CHARM_2` | 6 | チャーム x3 の2枠目。`equipment.tag = CHARM` |
| `CHARM_3` | 7 | チャーム x3 の3枠目。`equipment.tag = CHARM` |
| `CORE` | 8 | コア x1。`equipment.tag = CORE` |
| `RELIC_1` | 9 | レリック x2 の1枠目。`equipment.tag = RELIC` |
| `RELIC_2` | 10 | レリック x2 の2枠目。`equipment.tag = RELIC` |

## 6. インベントリインスタンスタイプ

対象実装: `InventoryInstanceType`

| 値 | コード | 意味 |
|---|---|---|
| `EQUIPMENT` | `EQUIPMENT` | 装備インスタンス。`instanceId` に equipment instance UUID を持つ |

| 項目 | 説明 |
|---|---|
| `equipmentLoadoutSlotId` | ロードアウトスロット UUID |

## 12. プレイヤー状態モデル

対象実装: `PlayerInventoryState`

1 アカウント分の inventory / entry / loadout / GUI 表示状態を保持する in-memory 集約モデル。join 時に API から構築し、プレイ中は本モデルのみを更新する。

| 項目 | 説明 |
|---|---|
| `accountId` | 対象アカウント UUID |
| `inventories` | 所有 `InventoryModel` 一覧 |
| `entriesByInventoryId` | inventoryId ごとの `InventoryEntryModel` 一覧 |
| `loadouts` | 所有 `EquipmentLoadoutModel` 一覧 |
| `displayedType` | GUI 表示中の `InventoryType`。統合後は `BAG` 固定 |
| `bagScrollRow` | BAG 表示の先頭行（0始まり、非永続） |
| `selectedHotbarSlot` | 選択中ホットバー。未選択時は `null` |
| `hotbarShortcutMode` | カスタムGUI表示フラグ。true の間は GUI 側のプレイヤーインベントリ操作を許可する |
| `dirty` | 次回 save 対象フラグ |

主な操作:

- `putInventory`, `replaceEntries`, `putLoadout`, `upsertActiveLoadoutSlot`
- `replaceEntriesFromLoad`
- `updateInventoryMetadata`
- `takeAndClearDirty`, `restoreDirty`

## 13. state レジストリ

対象実装: `PlayerInventoryStateRegistry`

join 中プレイヤーの `PlayerInventoryState` を accountId 単位で保持するレジストリ。

| 操作 | 説明 |
|---|---|
| `put(state)` | join 時に state を登録する |
| `get(accountId)` | inventory feature / save task が state を参照する |
| `remove(accountId)` | quit / plugin disable 時に state を破棄する |
| `all()` | オートセーブが全 state を走査する |

## 14. 永続化トリガ

対象実装: `InventoryPersistence.SaveTrigger`

| 値 | 用途 |
|---|---|
| `AUTO` | 60 秒オートセーブ |
| `LOGOUT` | player quit 時 |
| `PLUGIN_DISABLE` | plugin disable 時 |
| `IMMEDIATE` | 即時整合性が必要な `saveNow` |

## 15. 関連 feature とのモデル関係

- `item`: `itemId`、`itemCategory`、装備・ルーンインスタンス ID を参照し、ItemStack 生成に利用する
- `account`: accountId とアカウントモードを表示反映判定と同期する
- `menu`: inventory 種別選択、装備 GUI、ショートカット表示の状態を参照する
