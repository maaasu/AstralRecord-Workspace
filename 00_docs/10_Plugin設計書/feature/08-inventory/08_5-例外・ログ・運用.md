## 3. 例外・運用方針

- `InventoryEquipmentGuiEventHandler` の `runSafely` で包んだ GUI 更新処理は、`E_5601` へ `player` と `operation` を渡して記録し、Bukkit event loop へ例外を送出しない
- API 通信中の `InterruptedException` は interrupt flag を復元して RuntimeException とする
- API の 404 は、一覧取得では空レスポンス、単体取得では `null` として扱う
- join 時ロード失敗は WARN のみ残して処理継続する。state は空のまま生成され、必要な inventory は後続処理で補完する
- プレイ中の変更は `PlayerInventoryState` に集約し、`dirty` で保存要否を管理する
- autosave / logout save 失敗時は `PlayerInventoryState.restoreDirty()` により次回 save 対象へ戻す
- inventory entry 永続化は inventoryId 単位の `replaceEntries` で行い、loadout は前回保存との差分 slot のみ `upsertSlot` / `deleteSlot` する
- `replaceEntries` の 409 Conflict は、送信後に同じ inventory entry がローカルで変更されていない場合だけ API 正本 snapshot で復旧する。並行するローカル変更がある場合は上書きせず保存失敗として dirty を保持する
- `InventoryAutoSaveTask` は 60 秒間隔で dirty state を保存する。1 人の失敗で他プレイヤー保存は止めない
- ログアウト保存は `InventorySaveCoordinator` のアカウント別キューで直列化する。失敗した state は reconciliation 用に保持する
- `InventoryService.flushPendingCoalescedWrites` は旧呼び出し元との互換用 no-op、`InventoryService.awaitPendingWrites` は persistence の停止待機へ委譲する
- inventory クリックは [[08_3-サービス]].クリッククールタイム で抑止し、100ms のクールタイム中の重複操作は無視する

## 4. 運用メモ

- `/inventory` は統合所持品 BAG の再描画のみを行い、カテゴリ切替引数を持たない
- BAG が満杯の場合は追加数0として取得を拒否する。受取箱・一時保管は現在の契約に含めない
- ストレージは基礎5ページを上限とし、`storage_expansion_token` の所持数1個につき1ページを加算する。新規 storage entry が上限に達した場合は収納数0として状態を変更せず、既存の同一通常アイテムへの数量統合だけを許可する
- API payload 変更が発生した場合は [[08_3-リポジトリ]] と `20_API設計書` 側も合わせて更新する
- 装備 GUI スロットやアクセサリ slotIndex を変更した場合は menu feature 側の表示仕様とも同期する
