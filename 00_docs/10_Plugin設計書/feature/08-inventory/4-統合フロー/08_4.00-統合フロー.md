# 08_4.00-統合フロー

## 1. `/inventory` 表示開始フロー

1. [[08_3.03-コマンド]].インベントリ再描画 がアカウントモードを検証する
2. 統合所持品 `BAG` を表示対象として解決する
3. `PlayerService.onPlayerJoin` が `InventoryPersistence.load(accountId)` を実行済みで、state が registry に登録されている前提で進む
4. [[08_3.02-サービス]].インベントリ GUI 反映 が state 上の BAG と `bagScrollRow` を参照する
5. [[08_3.05-タスク・補助]].ItemStack 変換 で entry から `ItemStack` を生成する
6. `INVENTORY_SLOTS` の実効容量と保持中 entry の最大 `slotIndex` から現在の3行24アイテム枠を解決し、右端3制御枠へ反映する。BAG の永続 `slotCapacity` は参照しない
7. 容量外 entry は同じ `slotIndex` のまま表示し、移動・破棄だけを許可する。空いた容量外スロットは実効容量が回復するまで再利用しない

## 2. アイテム取得フロー

1. item feature が [[08_3.02-サービス]].通常インベントリアイテム追加 を呼ぶ
2. 通貨は `CURRENCY`、それ以外は `BAG` を格納先として解決する
3. 装備・ルーンの場合は必要に応じて instanceId を生成して entry を追加する
4. 通常アイテムの場合は state 上の実効容量内にある既存 entry へ加算するか、実効容量内の空きスロットへ追加する
5. entry 変更後は `PlayerInventoryState.dirty` が立ち、次回 autosave / logout save の対象になる
6. 一部または全部が入りきらない場合は `PlayerMsgId.P_5241` を返す
7. BAG 追加後は現在の `bagScrollRow` を維持して GUI を再描画する

## 3. 装備 GUI フロー

1. menu feature が装備 GUI を開く
2. [[08_3.01-イベント]].装備 GUI クリック が防具・オフハンド・種類別アクセサリ9枠のクリックを受け付ける
3. inventory service が防具種別、またはアクセサリの `equipment.tag` と `AMULET` / `TALISMAN` / `CHARM` / `CORE` / `RELIC` 枠の一致を検証し、state 上の entry / loadout を更新する
4. 装備解除時は BAG へ戻し、現在のスクロール位置を維持して再描画する
5. GUI クローズまたは保存契機に [[08_3.02-サービス]].装備 GUI 保存 を呼ぶ
6. `EQUIP_SLOT` / `ACCESSORY_SLOT` entry と active loadout slot が dirty state に保持される。`ACCESSORY_SLOT.slotIndex 1..10` は loadout の `ACCESSORY.slotIndex 0..9` へ1引いて対応付ける
7. autosave / logout save 時に loadout 差分だけ API へ同期する
8. Bukkit 現在装備状態は防具とオフハンドを更新し、種類別アクセサリは仮想装備として保持する

## 4. join / autosave / logout フロー

1. `PlayerService.onPlayerJoin` が `InventoryPersistence.load(accountId)` を呼び、inventory / entry / loadout を state 化する
2. 構築した state を `PlayerInventoryStateRegistry.put(state)` で登録する
3. プレイ中の inventory 操作は state のみを更新し、dirty を立てる
4. `InventoryAutoSaveTask` が 60 秒ごとに全 state を走査し、dirty state のみ保存する
5. `InventorySaveTask` は logout / plugin disable / manual save 時に Bukkit 側最新スナップショットを state に取り込み、そのまま保存する
6. quit / plugin disable 後は registry と persistence 内キャッシュを破棄する

## 5. menu 連携フロー

1. menu feature がクラフトショートカット GUI からショートカットボタンを開く
2. inventory 表示アクションは [[08_3.02-サービス]].インベントリ GUI 反映 へ移譲する
3. GUI 表示中はホットバー割当を維持し、BAG 右端中央にはインベントリ情報を表示する
4. GUI を閉じても中央制御はインベントリ情報のまま維持する
5. GUI が下部アイテムの取り込みを提供する場合はその処理を優先し、対象外クリックは通常の BAG／ホットバー操作へ委譲する

## 6. HOTBAR_SLOT表示observerフロー

1. `PlayerInteractionGatewayEventHandler`が`PlayerItemHeldEvent`を`HOTBAR_SLOT`として調停する。
2. input lock、action ringの候補が勝った場合は元eventをcancelする。
3. [[08_3.01-イベント]].装備 GUI の補助操作 は非競合observerとしてeventを監視し、cancel済みなら処理しない。
4. 候補なしで通常slot変更が許可された場合だけ、変更要求先slotのitemを装備GUIのメイン表示`slot 19`へ反映する。
5. observerは候補を返さず、他featureの入力所有権や勝者選択へ影響しない。
