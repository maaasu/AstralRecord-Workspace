# 08_2-ユースケース

## 1. 統合所持品表示・スクロール

対象: プレイヤー

契機: `/inventory`、インベントリ表示、上スクロール・下スクロールクリック

事前条件:

- プレイヤーが [[03_1-モデル定義]].プレイヤーセッション としてキャッシュ済みである
- アカウントモードが GUI インベントリ反映対象である
- `BAG` inventory がロード済みである

正常系:

1. `INVENTORY_SLOTS` の実効容量と、容量外を含む保持中 entry の最大 `slotIndex` の大きい方を8スロット単位の行へ分割する
2. `bagScrollRow` から連続3行を解決し、Bukkit slot 9〜16 / 18〜25 / 27〜34へ反映する
3. slot 17 / 26 / 35へ上スクロール／情報／下スクロールを反映する
4. スクロールクリック時は `bagScrollRow` を1だけ増減し、同じ3行表示を再描画する
5. カスタムGUI表示中も slot 26 はインベントリ情報を表示し、専用の閉じるアイコンは配置しない
6. 実効容量を超える entry には容量外表示を付け、空の容量外枠は新規配置不可として表示する
7. 通常 BAG 表示用の ItemStack には、武器・道具・バンドル・消耗品へ「クリックでホットバースロットに設定」、有効なオーブへ「クリックで使用」の案内を追加する
8. この操作案内は通常 BAG 表示だけに追加し、HOTBAR・装備スロット・STORAGE・ごみ箱など別の表示経路には追加しない

## 1.5. インベントリ内オーブ一覧

対象: プレイヤー

契機: 通常プレイヤーインベントリの slot `26` に表示するインベントリ情報アイコンをクリック

正常系:

1. 9x6 の `INVENTORY_ORB_LIST` GUI を開き、最外周を操作不能なダミーアイテムで埋める。内側4行7列へオーブを表示する
2. BAG と HOTBAR の `orb` entry だけを抽出し、同じ item ID の entry は1項目へ集約する。表示順は既存の BAG / HOTBAR と slot 順を維持する
3. ItemStack の表示個数は通常のスタック上限内に丸めるが、lore には集約後の実数量を表示する。たとえば64個と32個の同種オーブは `所持数: 96` と表示する
4. 下段のページボタンで28種類単位にページを切り替える。オーブ項目をクリックすると、クリック時点で同じ item ID を持つ正本 entry を再解決し、既存のオーブ装備操作 GUI を開く
5. オーブ装備操作 GUI の下段中央に表示する起点オーブをクリックした場合も、この一覧 GUI を開き直す。一覧から別のオーブを選択できる

実行不能時:

- クリック時点で選択したオーブが消費・移動済み、またはマスタ未登録になっていた場合は操作を開始せず一覧を再描画する
- ページ移動不可のページボタン、枠、一覧中央の情報アイコンは操作せず拒否音だけを鳴らす

## 2. アイテム付与

対象: コマンド・ルート報酬等の呼び出し元

正常系:

1. 通貨は `CURRENCY`、それ以外はカテゴリを問わず `BAG` を格納先にする
2. 必要なインベントリが存在しなければ作成する
3. スタック可能アイテムは実効容量内の既存エントリへ数量加算する
4. 既存スタックだけでは入りきらない通常アイテム、装備・ルーン等は実効容量内の空き slot へ entry を追加する
5. `INVENTORY_SLOTS` の実効容量内に空きがなければ追加数0として取得を拒否する。非同期で個体 ID を生成する装備・ルーンは、生成前に BAG slot を予約し、予約済み slot を他の取得・移動・削除後の前詰め処理へ渡さない。予約後に実効容量が下がった場合も、その予約は容量外 entry として確定できるため永続化済み個体を孤立させない
6. 通常アイテムの付与結果は、実付与数・今回新規に使用した BAG slot 数・付与後の BAG 空き slot 数を同じ state lock 内で確定する
7. 追加後は現在のスクロール位置を維持して GUI を再描画する

## 3. 装備 GUI 操作

対象: プレイヤー

正常系:

1. 装備可能スロットと ItemStack の装備種別を照合する
2. 既存装備があれば所有インベントリへ戻す
3. 新しい装備を Bukkit 装備スロットまたは装備 GUI スロットへ配置する
4. EQUIP_SLOT / ACCESSORY_SLOT のスナップショットを保存する
5. 有効装備プリセットへ装備状態を同期する

## 4. ホットバー割当とショートカット表示

対象: プレイヤー

補足:

- ホットバー9枠はカスタムGUI表示中も通常の割当アイテムを表示する
- カスタムGUIに対象アイテムを移動するクリック処理がある場合は、その処理を通常ホットバー操作より優先する

正常系:

1. 表示中インベントリの該当エントリを取得する
2. 選択スロットがない場合は、同一 `itemCategory` / `itemId` の最初の HOTBAR stack を DB slot 順で検索する
3. 同一 stack の数量が `maxStack` 未満なら、クリック元の数量を加算する。加算しきれない場合は超過分をクリック元の BAG entry に残す
4. 同一 stack が満杯、または存在しない場合は、ホットバー空きスロットまたは選択スロットを解決する。空きスロットは `1`〜`9`、オフハンドの順で検索する
5. HOTBAR インベントリのエントリを更新する
6. 全量を移動した元インベントリの該当エントリを削除し、部分移動なら元の `slotIndex` を維持して数量だけ減らす
7. ホットバーへ割り当てた後も BAG のスクロール位置を維持する
8. Bukkit ホットバーへ表示アイテムまたはショートカットアイコンを描画する

補足:

- 空きスロットがない場合は、元インベントリを含めて state を変更しない
- ホットバーからアイテムを外した場合は BAG へ返却する

## 5. スナップショット保存・読み込みメソッド提供

対象: player feature 等、保存・復元の契機を制御する呼び出し元

責務範囲:

inventory feature は指定 account のインベントリ本体・エントリの提供と、自機能が管理する 4 種スナップショット（`BAG` / `EQUIP_SLOT` / `ACCESSORY_SLOT` / `HOTBAR`）の保存・読み込みメソッドの提供までを担当する。
保存・復元の契機、実行順序、リトライ、失敗時の業務挙動は呼び出し元の責務とし、inventory feature は判断しない。

提供する保存メソッド:

- [[08_3-サービス]].統合所持品スナップショット保存 — BAG 表示領域を扱う
- [[08_3-サービス]].装備スロットスナップショット保存 — 防具スロット・オフハンドを `EQUIP_SLOT` エントリへ保存する
- [[08_3-サービス]].アクセサリスロットスナップショット保存 — アクセサリ装備状態を `ACCESSORY_SLOT` エントリへ保存する
- [[08_3-サービス]].ホットバースナップショット保存 — ホットバーを `HOTBAR` エントリへ保存する

提供する読み込みメソッド:

- [[08_3-サービス]].通常インベントリスナップショット読み込み
- [[08_3-サービス]].装備スロットスナップショット読み込み
- [[08_3-サービス]].アクセサリスロットスナップショット読み込み
- [[08_3-サービス]].ホットバースナップショット読み込み

呼び出し元との契約:

1. 呼び出し元が必要な保存・読み込みメソッドを必要なタイミングで呼ぶ
2. inventory feature 側は呼び出しごとに単独で完結し、他のスナップショットの状態には依存しない
3. 保留中の非同期書き込み待機は呼び出し元から要求された場合のみ実施する

## 6. ストレージ収納・取り出し

対象: プレイヤー

契機: `/storage`、または別途用意されるストレージオープンイベント

正常系:

1. ストレージ GUI を開き、`STORAGE` inventory の entry 一覧を表示する
2. 初期表示はアイテムを収納した順とし、`slotIndex` の昇順を収納順として扱う
3. 下部プレイヤーインベントリの表示中アイテムをクリックすると `STORAGE` entry として追加し、収納元 entry から該当数量を減算または削除する。Shift+右クリックの場合は BAG・ホットバー全体の同一 itemId / itemCategory の通常アイテムを一括収納する
4. 収納時は `instanceType` / `instanceId` を持たない通常アイテムだけ、同一 itemId / itemCategory の既存 storage entry へ数量統合する。装備・ルーンなど instanceId と紐づくアイテムは既存 entry へ統合せず、別 entry / 別スロットとして表示する
5. ストレージ内アイテムをクリックすると通常の所持インベントリへ戻し、`STORAGE` entry から該当数量を減算または削除する。Shift+右クリックでは BAG の空き容量まで対象 entry の全量を複数スタックへ分割して取り出す
6. 収納・取り出し操作ではストレージ表示情報をメモリ上で更新して開いている GUI ページを再描画し、変更がある場合は GUI を閉じる時にまとめて即時 save する
7. GUI のカテゴリ、レアリティ、並び順、並び方向の各フィルターアイコンをクリックすると候補アイコン一覧を開き、候補を1つ選択して適用する。カテゴリでは「すべて」に加えて `orb`（オーブ）を選択できる

## 7. プレイヤーがオーブから装備操作を開始する

対象: プレイヤー

契機: 通常プレイヤーインベントリに表示された `orb` カテゴリのアイテムをクリック

正常系:

1. クリックした inventory entry ID とオーブ item ID を session に保持し、元のクリックをキャンセルする。
2. オーブ効果に適合する装備だけを BAG / HOTBAR と装備中から収集する。同一装備は重複させず、装備中を先頭に並べる。
3. 強化は装備種別、現在の状態変化ランク、次の強化レベルの有無、修理は耐久値不足、状態変化は即時次ランクとオーブの目標ランク、エンチャントは枠と共通マスタ候補で絞り込む。
4. 候補クリック時は、オーブ entry と対象装備 instance が現在も同じアカウントに属し、数量・効果・対象条件を満たすことを state 正本から再検証する。
5. 成立した操作はオーブを必ず1個だけ消費する。強化・修理・エンチャントは素材・通貨を消費せず、状態変化だけは装備マスタ定義の素材・通貨を確認画面で表示して同時消費する。
6. クリック時にオーブ1個・状態変化素材・goldをローカル残高から減らさず予約する。stable事前保存の完了までは予約対象の通常item消費だけを保留し、報酬加算・新規entry・移動は許可する。保存応答をbaselineとしてentry別予約を再確定した後は予約外残量を消費できる。API確定までの差分は `API確定数量 + (現在数量 - baseline数量)` で一度だけ合成し、APIが削除したentryに正の残量があれば新しいentry IDで保持する。新規entryと無関係な変更も維持する。
7. goldは個々の額面entryを上書きせず、全額面と互換IDをgold価値へ換算して同じ三者マージを行い、正規額面へ再構成する。合成後のstateを同じaccount lane内で保存し、保存中に追加変更が入った場合は安定するまで再保存してから後続logout・停止保存へ進む。

実行不能時:

- 候補から外れた装備、移動・消費済みのオーブ、別アカウントの装備は変更・消費せず再描画する。
- エンチャント候補がない場合は「付与できるエンチャントがありません」と通知し、装備もオーブも変更しない。
8. 並び順は収納順、獲得順、レア度順、売値順を候補一覧から選択でき、並び方向も昇順・降順を候補一覧から選択できる
9. 数量規則は左クリック1個、右クリック半分（切り上げ）、Shift+左クリック1スタック、Shift+右クリック全量とする
10. BAG の entry を全数収納して削除した場合は、容量外 entry を含む後続 entry の表示順を保ったまま `slotIndex` を前詰めする。部分収納では元のスロットを維持する

補足:

- 収納順は収納時に採番した `slotIndex` を使う。
- 獲得順は収納元 entry の `createdAt` を `metadataJson.acquiredAt` に保存して使う。古いデータで値が無い場合はストレージ entry の `createdAt` を使う。
