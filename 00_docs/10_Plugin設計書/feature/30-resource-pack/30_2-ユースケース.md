# 30_2-ユースケース

## 1. Java Edition プレイヤーへ要求する

前提: 機能が有効で、プレイヤーが Bedrock 除外条件に一致しない。

1. プレイヤーがサーバーへ参加する。
2. URL、任意の SHA-1 と prompt、force を使ってリソースパック要求を送る。
3. 送信内容を INFO ログへ残す。
4. クライアントが status を通知したら、管理対象 pack ID だけを状態別に処理する。

## 2. Bedrock 接続を除外する

前提: `skipBedrock=true` で、プレイヤー名が設定 prefix のいずれかに一致する。

1. Java 用リソースパック要求を送らない。
2. 除外したプレイヤー名を INFO ログへ残す。

## 3. 不正な SHA-1 でも URL 要求を継続する

前提: SHA-1 が空ではないが、40 桁の 16 進文字列ではない。

1. URL と不正値を WARN ログへ残す。
2. SHA-1 を `null` として要求を送る。
3. URL 自体が空の場合は機能を無効として送信しない。

## 4. クライアント失敗を通知する

1. 本機能の pack ID と一致する status event を受ける。
2. download、URL、reload の失敗は対応するプレイヤーメッセージを送る。
3. 拒否時は表示欠落の可能性を通知し、WARN ログを残す。
