# 30_2-ユースケース

## 1. Java Edition プレイヤーへ要求する

前提: 機能が有効で、プレイヤーが Bedrock 除外条件に一致しない。

1. プレイヤーがサーバーへ参加する。
2. 配布中のSHA-1を非同期に取得し、公開WebのURLとともに送る。取得できず固定URL方式が有効なら、設定済みURLと任意のSHA-1を送る。
3. 送信内容を INFO ログへ残す。
4. クライアントが status を通知したら、管理対象 pack ID だけを状態別に処理する。管理配布に成功した接続では専用フォントを使う。

## 2. Bedrock 接続を除外する

前提: プレイヤー名が設定 prefix のいずれかに一致する。

1. 管理配布のJava用パックは送信しない。固定URL方式では `skipBedrock=true` の場合に送信を省略する。
2. Geyser Extension がプロキシの接続時にBedrockパックを配布する。

## 3. 不正な SHA-1 でも URL 要求を継続する

前提: 固定URL方式のSHA-1が空ではなく、40桁の16進文字列ではない。

1. URL と不正値を WARN ログへ残す。
2. SHA-1 を `null` として要求を送る。
3. URL 自体が空の場合は機能を無効として送信しない。

## 4. クライアント失敗を通知する

1. 本機能の pack ID と一致する status event を受ける。
2. download、URL、reload の失敗は対応するプレイヤーメッセージを送る。
3. 拒否時は表示欠落の可能性を通知し、WARN ログを残す。
