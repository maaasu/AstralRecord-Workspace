# 30_0-概要

## 1. 目的

Web API に配置した Java Edition / Bedrock Edition のリソースパックを参加時に配布する。最初の配布対象はダメージ数値の専用フォントと描画モデル。

## 2. 責務

- Paper は Java 接続ごとに最新の配布情報を内部APIから非同期取得し、公開WebのZIPのURLとSHA-1を案内する。管理配布を無効化した場合や配布情報を取得できない場合は設定済み固定URL方式を利用する。
- Paper はパックIDを照合し、管理配布の適用成功を通知した接続で専用フォントを使う。
- Bedrock パックは Geyser Extension が内部APIから検証して取得し、統合版の接続時に配布する。適用対象の接続だけがダメージ数値の専用モデルを描画する。
- クライアント結果をログへ記録し、利用者が対処できる失敗はメッセージで通知する。

## 3. 責務外

- パックのビルドとAPIへの配置はデプロイツールが担当する。Paper はZIPを直接取得しない。
- クライアントの適用状態は接続の間だけ保持する。

## 4. 実装境界

`ResourcePackJoinEventHandler` と `ResourcePackStatusEventHandler` が Bukkit event を受け、判断と通知を `ResourcePackService` へ委譲する。内部APIの取得は `ResourcePackRepository` が行う。ダメージ数値の受信者別表示は [[14_5-例外・ログ・運用]] を参照。

## 5. 依存・連携

- [[03_0-概要]]: プレイヤー参加ライフサイクルとプレイヤー向けメッセージ

## 6. 変更影響

- 設定キー、既定値、pack ID の導出規則を変更した場合は、モデル定義と運用を更新する。
- 送信条件、Bedrock 判定、status 分岐を変更した場合は、メソッド仕様と統合フローを更新する。
- メッセージ ID またはログ ID を変更した場合は、例外・ログ・運用を更新する。
