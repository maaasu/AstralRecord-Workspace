# 30_1-モデル定義

## 1. リソースパック設定

物理名: `ConfigProperties` の `resourcePack.*`

| キー | 型 | 既定値 | 用途 |
|:--|:--|:--|:--|
| `resourcePack.managed.enabled` | boolean | `true` | APIに配置した最新のJava用パックを要求する |
| `resourcePack.managed.publicBaseUrl` | string | `https://astralrecord.com` | クライアントがZIPを取得するWebのorigin |
| `resourcePack.enabled` | boolean | `false` | 固定URL方式の有効化 |
| `resourcePack.url` | string | サンプル URL | Java 用 ZIP の配布 URL |
| `resourcePack.sha1` | string | 空 | 任意の 40 桁 SHA-1。形式不正時は送信値から除外する |
| `resourcePack.force` | boolean | `false` | Paper の required フラグ |
| `resourcePack.prompt` | string | 適用依頼文 | クライアント表示。空なら `null` |
| `resourcePack.skipBedrock` | boolean | `true` | 固定URL方式でBedrockと判定した接続を除外するか |
| `resourcePack.bedrockNamePrefixes` | string list | `.`, `*` | プレイヤー名の先頭一致に使う。空リスト時も `ConfigProperties` がこの既定値を設定する |

## 2. 管理対象 pack ID

管理配布のパックIDは固定UUID。URLにSHA-1を含め、ファイルが変わるとクライアントの取得先も変わる。固定URL方式のIDは trim 済みURLから `UUID.nameUUIDFromBytes` で生成する。status は有効な方式のIDが一致したときだけ処理する。

## 3. クライアント状態

物理名: `PlayerResourcePackStatusEvent.Status`

| 分類 | 状態 | 処理 |
|:--|:--|:--|
| 正常進行 | `ACCEPTED`, `DOWNLOADED`, `SUCCESSFULLY_LOADED` | INFO ログ |
| 利用者判断 | `DECLINED` | 警告メッセージと WARN ログ |
| 利用者が対処可能な失敗 | `FAILED_DOWNLOAD`, `INVALID_URL`, `FAILED_RELOAD` | 状態別メッセージ |
| 破棄 | `DISCARDED` | WARN ログ |
| その他 | 上記以外 | DEBUG ログ |

## 4. Bedrock 判定

物理名: `BedrockPlayerDetector#isBedrock(String, List<String>)`

リソースパック送信前の判定では、設定した prefix のうち、`null` と空白文字列を除いたいずれかでプレイヤー名が始まる場合に Bedrock 接続として扱う。大文字・小文字の変換は行わない。この設定判定と、プレイヤーモデルの `user.mcid` に `.` を含むかによる `AstPlayer.isBedrock` 判定は用途を分ける。
