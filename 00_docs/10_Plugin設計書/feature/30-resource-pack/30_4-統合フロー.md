# 30_4-統合フロー

## 1. 参加時のリソースパック要求

### シーケンス

```mermaid
sequenceDiagram
    participant Bukkit
    participant Join as ResourcePackJoinEventHandler
    participant Service as ResourcePackService
    participant Player
    Bukkit->>Join: PlayerJoinEvent
    Join->>Service: applyTo(player)
    alt 機能無効
        Service-->>Join: 終了
    else Bedrock 除外対象
        Service->>Service: I_5551
    else Java Edition 対象
        Service->>Service: URLからpack UUID生成
        opt SHA-1形式不正
            Service->>Service: W_5550 / SHA-1をnull化
        end
        Service->>Player: setResourcePack(...)
        Service->>Service: I_5550
    end
```

### 処理要点

1. ハンドラの登録自体が `isEnabled` により制御される。
2. `applyTo` でも有効性を再確認し、設定変更・直接呼び出しに対して安全に終了する。
3. SHA-1 不正は送信中止ではなく、SHA-1 なしの要求へ縮退する。

## 2. クライアント status の処理

### シーケンス

```mermaid
sequenceDiagram
    participant Bukkit
    participant Handler as ResourcePackStatusEventHandler
    participant Service as ResourcePackService
    participant Message as PlayerMessageService
    Bukkit->>Handler: PlayerResourcePackStatusEvent
    Handler->>Service: isManagedPack(event.id)
    alt 管理対象外
        Handler-->>Bukkit: 無処理
    else 管理対象
        Handler->>Service: handleStatus(player, status)
        alt 正常進行
            Service->>Service: I_5552〜I_5554
        else 拒否・破棄
            Service->>Message: P_5553（拒否時のみ）
            Service->>Service: W_5551 / W_5552
        else download・URL・reload失敗
            Service->>Message: P_5550〜P_5552
        else その他
            Service->>Service: D_5550
        end
    end
```

### 処理要点

1. URL が変わると導出 UUID も変わり、旧要求の遅延 status は管理対象外になる。
2. status は永続化せず、通知とログだけを行う。

### 例外・終了条件

ハンドラ内例外は `runSafely` が捕捉し、`E_5550` へ集約する。
