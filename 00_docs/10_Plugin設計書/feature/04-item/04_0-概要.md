# 04_0-概要

## 1. 目的

`item` 機能は、AstralRecord 上で扱う独自アイテムのマスタ定義（`ItemModel`）と、プレイヤーが所有する装備/ルーンの個別インスタンス（`EquipmentInstance` / `RuneInstance`）を統一的に管理する。
主目的は以下。

- アイテムマスタの起動時一括取得・正規化 ID キャッシュ管理と個別再ロード
- カテゴリ別アイテム（bundle / currency / equipment / material / consumable / rune）の構造化保持
- 装備/ルーンインスタンスの生成・取得
- マスタ + インスタンスからの Bukkit `ItemStack` 生成と、icon・カスタムモデルデータのパケット書き換え
- 共通入力仲裁への item use / weapon / vanilla guard 候補提供と、バニラ消費の抑止

## 2. コンテキスト

- 本機能は起動時の非同期セットアップで全アイテム summary と詳細を API から取得し、正規化 ID キャッシュへ登録する。
- `/item load <itemId>` と bundle 報酬解決では単体 API 取得を行い、取得結果を同じマスタキャッシュへ反映する。`/item get` はロード済みキャッシュだけを参照する。
- 通常のサーバ側 ItemStack はベース Material を `PAPER` に固定し、パケット送信時に icon Material へ差し替える方式を採る。
- ItemDisplay や地面に出るドロップ実体など、インベントリ送信パケットを通らない表示では `ItemStackFactory#createDisplay` / `asDisplayStack` で PDC を維持したまま Material を icon に差し替える。
- 装備/ルーンインスタンスは AstralRecord API（`/api/equipment/instances`, `/api/rune/instances`）で生成され、確定済みのステータスロール値を含む。
- `bundle` カテゴリの Lore 表示には [[06_3-サービス]].ロード済み優先ルート取得 を使い、キャッシュ未命中時は単体 API 取得を試みる。

## 3. 構成要素（実装単位）

- `service/ItemService`
  - アイテムマスタの一括・単体 API 取得、正規化 ID キャッシュ、装備/ルーンインスタンス生成の業務制御を行う。
- `service/ItemStackFactory`
  - `ItemModel` および各種インスタンスから `ItemStack` を生成し、Lore・PDC・customModelData を構築する。
- `service/ItemDropAnimationService`
  - 報酬 ItemDisplay の icon Material 表示、落下、回収演出を Mob ドロップと bundle 開封で共通利用する。
  - ItemDisplay は `ItemDisplay.ItemDisplayTransform.GROUND` で描画し、ブロック系 icon もドロップ実体に近い姿勢で表示する。
- `repository/ItemRepository`
  - `/api/item`, `/api/equipment/instances`, `/api/rune/instances` への HTTP リクエストを実行する。
- `repository/SetEffectRepository`
  - `/api/seteffect` への HTTP リクエストでセット効果定義を取得する。
- `command/ItemCommand`, `ItemTabCompleter`
  - `/item` で管理 GUI、`/item load` で単体再ロード、`/item get` でロード済みアイテムの付与を提供する。
- `gui/ItemAdminGuiEventHandler`, `gui/ItemAdminGuiView`
  - ロード済みアイテムのフィルタ・ページ表示とクリック付与を提供する。
- `service/BundleUseService`, `service/PotionUseService`
  - 右クリック item use 勝者の約3秒待機、キャンセル、効果・報酬適用を管理する。
- `event/ItemInteractionBlockEventHandler`
  - 共通入力仲裁へ item use / vanilla guard 候補を返し、バニラ消費、持ち替え・退出時の pending use 解放を処理する。
- `view/ItemStackPacketAdapter`
  - ProtocolLib を介して送信パケットの ItemStack を icon Material / customModelData に書き換える。
- [[04_1-モデル定義]].アイテムモデル, 装備インスタンス, ルーンインスタンス, セット効果
  - アイテムマスタ・プレイヤー固有インスタンス・セット効果の表現を定義する（詳細は [[04_1-モデル定義]]）。

## 4. 依存関係

- 内部依存
  - `ItemService` -> `ItemRepository`
  - `ItemStackFactory` -> `LootService`
  - `ItemCommand` -> `ItemService`, `InventoryService`, `CurrencyService`, `MenuView`
  - `ItemInteractionBlockEventHandler` -> `ItemStackFactory`（静的 PDC 読み取り）, [[03_1-モデル定義]].プレイヤーキャッシュ
  - `ItemStackPacketAdapter` -> `ItemStackFactory`（静的 PDC 読み取り）
- 外部依存
  - AstralRecord API (`/api/item`, `/api/equipment/instances`, `/api/rune/instances`, `/api/seteffect`)
  - Bukkit/Paper（`ItemStack`, `PersistentDataContainer`, `ItemMeta`）
  - ProtocolLib（`PacketAdapter`, `PacketContainer`）

- `loot`
  - [[04_3-サービス]].ItemStackFactory のバンドル lore 構築は [[06_3-サービス]].ロード済み優先ルート取得 を呼び、未ロード時は API 取得を試みる。
  - bundle 開封は `loot_table:` 接頭辞を正規化し、解決済み table / pool 構造を `LootRollService` で抽選する。
- `inventory`
  - `/item get` でアイテムをインベントリへ付与する際に `InventoryService.addItemToNormalInventory` を呼び出す。
- `account`
  - 装備/ルーンインスタンスの所有者識別に [[02_1-モデル定義]].アカウントモデル.uuid を使用する。
- `player`
  - [[04_3-イベント]].アイテム操作ブロック で [[03_1-モデル定義]].プレイヤーキャッシュ からアカウントモードを参照する。
- `status`
  - 装備/ルーンの Lore 表示で `StatusType` を解決し、表示名・カラー分類に使用する。
  - ステータス表示名は `StatusType` のカテゴリ色を使用し、ステータス値はカテゴリにかかわらず共通色で表示する。
  - ステータス範囲値は半角 `~` ではなく全角 `～` で表示し、値自体は太字の共通色で表示する。
  - アイテムカテゴリの保存・API 値は英語 ID のままとし、プレイヤー向け表示では `ItemCategory.displayNameJa` の日本語名を使用する。
- `currency`
  - `currency` カテゴリの item 表現は本 feature が保持するが、所持通貨の取得・加算・表示用 ItemStack 一覧の正本は currency feature とする。
- `player-interaction`
  - クリック入力の候補収集、優先順位、勝者一件実行は[[28_0-概要]]を正本とし、本featureはitem useとweapon / combat候補を提供する。`HOTBAR_SLOT`後の使用待機解除は非競合observerとして扱う。
  - item use は `ITEM_USE`、weapon / combat は `FALLBACK` 候補として登録し、tick token と勝者結果で二重実行を防ぐ。

## 5. ライフサイクル登録点

- `AstralRecord#onLoad` で `ItemService`, `LootService`, `ItemStackFactory` を生成
- `AstralRecord#setupFeature` の非同期タスクで `lootService.loadAll()` → `itemService.loadAll()` を実行
- `AstralRecord#setupFeature` で `ItemStackPacketAdapter#register` を呼び出してパケットリスナー登録
- `AstralRecord#registerPluginFeatures` で `ItemInteractionBlockEventHandler` を登録
- `core/CommandRegister` で `/item` コマンドを登録
