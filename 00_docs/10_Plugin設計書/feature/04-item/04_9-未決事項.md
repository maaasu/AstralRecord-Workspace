# 04_9-未決事項

## 1. bundle 報酬の収容不能時処理

- `BundleUseService.completePendingUse` は bundle を先に 1 個消費し、各報酬の `InventoryService.addItemToNormalInventory` が返した付与数だけを結果表示へ含める。
- 要求数と付与数の差分は受取箱・ground item・補償 state のいずれにも保存されず、現状は破棄される。
- equipment / rune は所有 instance の生成も伴うため、単純な master ItemStack drop では正しい補償にならない。
- 開封前の全量収容検証、受取箱、instance 付き ground item、または消費 rollback のどれを採用するか決定する必要がある。

## 2. 同期 API 呼び出しの実行 thread

- `/item load` は player command のメインスレッドで `ItemService.loadItem` を直接呼ぶ。
- bundle 開始時の `LootService.getLoadedOrFetch` と、bundle 報酬未ロード時の `ItemService.loadItem` も待機完了 callback 内で同期 API を呼ぶ。
- `ItemStackFactory.appendBundleLootLore` も cache miss 時に同期 API を試みる。
- 非同期 prepare とメインスレッド commit へ分離するか、起動時 cache miss をエラーとして同期 fallback を廃止するかは未決定。

## 3. クリック family 外の vanilla 経路

- drop、所持品交換、dispenser 等、クリック family 外で AstralRecord item が vanilla 判定に入る経路の許可・抑止方針は未整理である。

## 4. customModelData 未対応クライアント

- `ItemStackPacketAdapter` は `customModelData` を送信 ItemStack へ反映する。
- resource pack 未適用・不一致クライアントでの fallback 表示、検出、プレイヤー案内は未検証である。
