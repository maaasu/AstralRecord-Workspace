# 04_3-サービス

## 1. アイテムマスタロード

### 全アイテムロード

クラス名: `ItemService`
物理名: `loadAll`

処理内容:

1. [[04_3-サービス]].アイテムマスタスナップショット構築 を実行する
2. [[04_3-サービス]].アイテムマスタスナップショット置換 を実行する
3. snapshot 件数を返す

### アイテムマスタスナップショット構築

クラス名: `ItemService`
物理名: `loadMasterDataSnapshot`

処理内容:

1. `ItemRepository.findAll` で全 summary を取得する
2. summary ごとに `ItemRepository.findById(id, category)` で詳細を取得する
3. 未検出詳細は `LogId.W_5200` を記録してスキップする
4. 取得 item を正規化 ID key の一時 map へ登録する
5. Gold 7 額面と `astrald` の組み込み通貨を追加する
6. カテゴリ件数を `LogId.I_5202`、合計を `LogId.I_5203` で記録し、不変 list を返す

例外時挙動:

- API 例外は `LogId.E_5202` を記録し、それまでの取得分と組み込み通貨を snapshot として返す

### アイテムマスタスナップショット置換

クラス名: `ItemService`
物理名: `replaceMasterDataSnapshot`

入力:

- 準備済み `List<ItemModel>`

処理内容:

1. master item cache と set-effect cache をクリアする
2. snapshot 全 item を正規化 ID key で登録する
3. equipment / rune instance cache と dirty durability は保持する

### アイテムマスタキャッシュクリア

クラス名: `ItemService`
物理名: `clearMasterDataCache`

処理内容:

1. master item cache と set-effect cache だけをクリアする
2. runtime equipment / rune state は保持する

### カテゴリ単位ロード

クラス名: `ItemService`
物理名: `loadAllByCategory`

処理内容:

1. category を trim・小文字化し、空なら `0` を返す
2. `ItemRepository.findAllByCategory` の結果を共有 cache へ追加する
3. currency category の場合は組み込み通貨も追加する
4. 成功件数を返す

例外時挙動:

- `LogId.E_5202` を記録して `0` を返す

### 個別アイテムロード

クラス名: `ItemService`
物理名: `loadItem`

入力:

- overload 1: item ID
- overload 2: item ID と category

処理内容:

1. ID を正規化し、空なら `null` を返す
2. 組み込み通貨 ID なら組み立てて cache へ登録する
3. category 未指定時は一覧 API で一致 summary を検索する
4. `ItemRepository.findById` で詳細を取得し、成功時は共有 cache へ登録する

例外時挙動:

- category 未指定経路の例外は `LogId.E_5202` を記録して `null` を返す
- category 指定経路の repository 例外は呼び出し元へ伝播する

## 2. マスタキャッシュ参照

### ロード済みアイテム参照

クラス名: `ItemService`
物理名: `getLoadedItems` / `getLoadedItemsByCategory` / `findLoadedById`

処理内容:

1. `getLoadedItems` は category、ID 順の snapshot list を返す
2. `getLoadedItemsByCategory` は大小無視で category を絞り込む
3. `findLoadedById` は正規化 ID key の item、未登録なら `null` を返す

### ロード済みキー参照

クラス名: `ItemService`
物理名: `getLoadedCategories` / `getLoadedItemIds`

処理内容:

1. ロード済み item から重複なしの category / item ID list を返す

### 対応カテゴリ判定

クラス名: `ItemService`
物理名: `isSupportedCategory` / `getSupportedCategories`

処理内容:

1. `ItemCategory.supportedApiValues()` を正本に判定・一覧返却する

### セット効果取得

クラス名: `ItemService`
物理名: `findSetEffectById`

処理内容:

1. 正規化 ID で cache を確認する
2. 未登録なら `SetEffectRepository.findById` を呼び、取得成功時に cache する
3. 未検出・例外時は `null` を返し、例外は `LogId.E_5202` へ記録する

## 3. 所有インスタンス

### 装備インスタンス作成・取得

クラス名: `ItemService`
物理名: `createEquipmentInstance` / `findEquipmentInstanceById`

入力:

- 作成: equipment ID、account ID、source、createdBy
- 取得: instance ID

処理内容:

1. 作成は `POST /api/equipment/instances`、取得は cache 優先で詳細 API を呼ぶ
2. 成功結果を正規化 instance ID key で cache する

例外時挙動:

- `LogId.E_5202` を記録して `null` を返す

### 装備強化・状態変化

クラス名: `ItemService`
物理名: `enhanceEquipmentInstance` / `transcendEquipmentInstance`

処理内容:

1. instance ID、target level / rank、updatedBy を repository へ渡す
2. 成功結果で equipment instance cache を更新する
3. 例外時は `LogId.E_5202` を記録して `null` を返す

### 装備インスタンス削除

クラス名: `ItemService`
物理名: `deleteEquipmentInstance`

処理内容:

1. repository 削除成功時だけ instance cache から削除して `true` を返す
2. 空 ID・未削除・例外時は `false` を返し、例外は `LogId.E_5202` へ記録する

### ルーンインスタンス作成・取得・破棄

クラス名: `ItemService`
物理名: `createRuneInstance` / `findRuneInstanceById` / `evictRuneInstanceFromCache`

処理内容:

1. 作成・取得は repository を呼び、成功結果を instance cache へ登録する
2. `evictRuneInstanceFromCache` は永続 API を呼ばず、準備済み rune を runtime cache からだけ除去する
3. 作成・取得例外は `LogId.E_5202` を記録して `null` を返す

## 4. 装備耐久値

### 耐久値キャッシュ更新

クラス名: `ItemService`
物理名: `updateEquipmentDurability`

処理内容:

1. equipment instance を cache 優先で解決する
2. durability を `0..durabilityMax` に clamp した新 instance を cache へ反映する
3. account ID・updatedBy と共に dirty update を登録する
4. 戦闘中の同期 HTTP は行わない

### dirty耐久値照会・保存・破棄

クラス名: `ItemService`
物理名: `hasDirtyEquipmentDurability` / `flushDirtyEquipmentDurability` / `clearDirtyEquipmentDurability`

処理内容:

1. account ID 単位で未保存 update を照会する
2. flush は最新 cache 値を repository へ保存し、成功した同一 pending だけを削除する
3. 失敗 update は次回保存用に残し、`LogId.W_5252` を記録する
4. clear はログアウト後 state 破棄境界で当該 account の dirty update を削除する

### 戦闘耐久値消費

クラス名: `EquipmentDurabilityService`
物理名: `canUseMainHandWeapon` / `consumeOnAttackHit` / `consumeOnDamageTaken` / `isBroken`

処理内容:

1. 最大耐久値が正で現在値 0 以下の instance を破損と判定する
2. 破損した main-hand weapon は攻撃へ使用できない
3. 実 HP damage または shield damage が発生した命中だけを消費抽選対象にする
4. 攻撃側は weapon と攻撃寄与 accessory、被ダメージ側は armor と反応 accessory を対象にする
5. 同一 instance を 1 hit 内で二重消費しない

## 5. ItemStack生成

### マスタItemStack生成

クラス名: `ItemStackFactory`
物理名: `create`

入力:

- `ItemModel`、任意の amount

処理内容:

1. model 内容から template を構築または cache から clone する
2. amount を `1..maxStack` に clamp する
3. 表示名、Lore、icon、customModelData、item ID、category 等を PDC へ格納する
4. bundle Lore は `LootService.getLoadedOrFetch` で候補を解決する

### 所有インスタンスItemStack生成

クラス名: `ItemStackFactory`
物理名: `create`

入力:

- equipment overload: `ItemModel`, `EquipmentInstance`, amount
- rune overload: `ItemModel`, `RuneInstance`, amount

処理内容:

1. instance ID と確定 roll、強化、状態変化、enchant、rune、耐久値を Lore / PDC へ反映する
2. instance 固有のため template cache は使用しない

### display・shop ItemStack生成

クラス名: `ItemStackFactory`
物理名: `createDisplay` / `createShopDisplay` / `asDisplayStack`

処理内容:

1. `createDisplay` / `asDisplayStack` は PDC を保った clone の Material を icon へ置換する
2. `createShopDisplay` は未確定 equipment 等を `min～max` の範囲で表示する

### 耐久表示反映

クラス名: `ItemStackFactory`
物理名: `applyDurabilityVisual`

処理内容:

1. PDC の最大・現在耐久値を読み、vanilla damage bar へ比率を反映する
2. 装備 Lore の耐久バーは、耐久率 `75%以上` を濃い緑、`50%以上75%未満` を緑（ライムではない緑）、`25%以上50%未満` を黄色、`25%未満` を赤で表示し、未充填部分は灰色とする
3. 対象 PDC または `Damageable` meta がない場合は `false` を返す

### ItemStack PDC参照・外観反映

クラス名: `ItemStackFactory`
物理名: `getAstralItemId` / `getIconName` / `getCustomModelData` / `getAppearanceColor` / `getPotionType` / `getCategory` / `getEquipmentInstanceId` / `getRuneInstanceId` / `applyAppearance`

処理内容:

1. 各 getter は対応 PDC、未設定なら `null` を返す
2. `applyAppearance` は color / potion PDC を Bukkit meta へ適用できた場合に `true` を返す

### ItemStack template cache管理

クラス名: `ItemStackFactory`
物理名: `clearCache` / `cacheSize`

処理内容:

1. clear 時は全 prototype を破棄し `LogId.D_5210` を記録する
2. `cacheSize` は現在の template 件数を返す

## 6. 使用待機

### bundle開封開始・取消

クラス名: `BundleUseService`
物理名: `beginBundleUse` / `cancelPendingOpen`

処理内容:

1. bundle 拡張と loot table ID を検証し、`LootService.getLoadedOrFetch` で開封前に解決する
2. 同一プレイヤーの既存待機を通知なしで取消し、`60 tick` の移動キャンセル可能待機を開始する
3. subtitle / BossBar を表示し、完了時に同一手の同一 item を再確認する
4. `LootRollService.roll`、bundle 消費、報酬 item 解決、inventory 付与、演出・結果表示を行う
5. `AstPlayer` overload の cancel は必要に応じて取消通知し、UUID overload は退出用に通知なしで破棄する

戻り値:

- 開始・取消対象が成立した場合 `true`

### potion使用開始・取消

クラス名: `PotionUseService`
物理名: `use` / `cancelPendingUse`

処理内容:

1. consumable 拡張を検証し、`onUse.useTimeTicks` の移動キャンセル可能待機を開始する
2. 完了時に RECOVER / BUFF effect の rate 判定を行う
3. RECOVER は HP / MP / EN の固定値または最大値比率、BUFF は `StatusService.applyBuff` へ委譲する
4. 1 件以上適用した場合だけ元 item を 1 個消費する
5. 取消 overload の通知方針は bundle と同じとする

## 7. 補助サービス

### 装備条件判定

クラス名: `EquipmentRequirementService`
物理名: `check` / `checkAndNotify`

処理内容:

1. equipment の level / class 条件を `AstPlayer` と照合する
2. `check` は失敗種別と必要値を `Result` で返す
3. `checkAndNotify` は失敗時に対応メッセージを送り、利用可否を boolean で返す

### 武器左クリック処理

クラス名: `ItemWeaponAttackService`
物理名: `handleLeftClick` / `hasLeftClickAction` / `hasUsableMainHandWeapon`

処理内容:

1. main-hand weapon の `SWORD` / `BOW` / `STAFF` tagから組み込み通常攻撃を解決する
2. 装備条件・耐久値を確認して system skill 実行へ委譲する
3. `hasLeftClickAction` は副作用なしで候補成立可否を返す
4. `hasUsableMainHandWeapon` は主手が weapon であり、プレイヤーレベル・クラス・クラスレベルの装備条件を満たし、耐久値切れでない場合だけ true を返し、action ring と左クリック bind の発動前判定に共通利用する

### 報酬落下回収演出

クラス名: `ItemDropAnimationService`
物理名: `playCollectingDrop`

処理内容:

1. icon Material の `ItemDisplay` を起点から落下させ、対象プレイヤーへ回収する演出を再生する
2. 表示量は model の最大 stack 以内とし、実付与の正本には使用しない

### 装備修理

クラス名: `EquipmentRepairService`
物理名: `open` / `repairHeldEquipment` / `createProcessingInfoItem` / `createProcessingExecuteItem` / `calculateRepairCost`

処理内容:

1. 装備加工 GUI から一時退避された装備を `repairHeldEquipment` で検証し、成功時だけ更新済み ItemStack を返す
2. 所持 gold を消費し、キャッシュの耐久値を最大へ更新する。対象 entry への返却は対象枠クリックまたは GUI 終了時に加工 GUI 側が行い、実行直後は対象枠へ保持する
3. 同一 instance の連打を抑止し、更新失敗時は支払い前 state へ補償する
4. 修理実行アイテムへ回復耐久、必要ゴールド、所持ゴールド、実行可否をまとめて表示する
5. 費用は `ceil(missingDurability * (1 + max(0, durabilityMax - 300) / 1400))`、修理不要時 `0` とする

### 装備強化

クラス名: `EquipmentEnhancementService`
物理名: `open` / `handleTopClick` / `handlePlayerInventoryClick` / `handleClose` / `prepareForPlayerSave` / `prepareAllForShutdown`

処理内容:

1. `MenuScreen.EQUIPMENT_PROCESSING` の修理・強化モードで共通の対象装備一時退避、返却、close・save・shutdown 回収を管理する
2. 強化では実アイテムアイコン、必要数 / 所持数、次のステータス・耐久値差分を表示し、実行枠へ必要ゴールドと全消費素材をまとめる
3. プレイヤー向けの素材名・装備名・ステータス名には内部 ID を使わず、表示名または汎用 fallback を使用する
4. 失敗時に装備破壊となる場合は二段階確認を行う
5. close・save・shutdown 時に session item を回収し、失われないよう player inventory または地面へ返却する
