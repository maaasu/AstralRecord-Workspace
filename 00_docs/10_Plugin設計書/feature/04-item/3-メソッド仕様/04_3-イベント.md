# 04_3-イベント

## 1. クリック入力受付

イベント物理名: `PlayerInteractEvent` / `PlayerInteractEntityEvent` / `PlayerInteractAtEntityEvent` / `PrePlayerAttackEntityEvent` / `PlayerArmSwingEvent`
クラス名: `PlayerInteractionGatewayEventHandler`
物理名: `onPlayerInteract` / `onPlayerInteractEntity` / `onPlayerInteractAtEntity` / `onPrePlayerAttackEntity` / `onPlayerArmSwing`

1. gatewayが右クリックまたは左クリックを`PlayerInputContext`へ正規化する。
2. item resolverはAstralRecord item、account mode、入力種別を読み、item useまたはweapon / combatの`PlayerInputCandidate`を副作用なしで返す。
3. item use候補は`ITEM_USE`としてworld interactionより下位・action ringより上位にする。weapon / combat候補は`FALLBACK`とし、`stableOrder`で表示中action ringより後、新規action ringより前にする。
4. 勝者executorだけがbundle・potion・フックショット・武器通常攻撃へ委譲する。
5. 候補収集時はeventをcancelせず、勝者の`InputClaimPolicy`をgatewayが反映する。

ingressの重複相関、全feature間の優先順位、次tick arm swing fallbackは[[28_3-イベント]]と[[28_3-サービス]]を正本とする。

### item入力候補解決

クラス名: `ItemInteractionBlockEventHandler`
物理名: `resolve`

入力:

- `PlayerInputContext<PlayerInteractionSnapshot>`

処理内容:

1. family が `RIGHT_CLICK` / `LEFT_CLICK` 以外なら空リストを返す
2. PLAYER mode、hand あり、`InventoryService.getItemModelInHand` で AstralRecord item を解決できることを確認する
3. 右クリックの BUNDLE / CONSUMABLE は `ITEM_USE`、`CLAIM_AND_CANCEL` の `astral-item-use` 候補を返す
4. それ以外は `FALLBACK`、`CLAIM_AND_CANCEL` の `astral-item-vanilla-guard` 候補を返す
5. equipment guard の勝者 executor では `EquipmentRequirementService.checkAndNotify` を実行する

出力:

- 0 件または 1 件の `PlayerInputCandidate`

### フックショット入力候補解決

クラス名: `HookshotInteractionEventHandler`
物理名: `resolve`

処理内容:

1. `RIGHT_CLICK`は常に空リストを返し、フックショットの処理を発動しない。`LEFT_CLICK`かつmain hand、PLAYER mode、主手が未装填の同一 `HOOKSHOT` tool instanceで、非skill詠唱・非牽引なら装填候補を返す。左クリック装填はアンカー照準を必要としない。主手instanceがloadedであり、現在視線の24 block以内に固体アンカーがある場合は発射候補を返す。候補化前の照準確認は読み取り専用であり、無効照準では通常world操作をclaimしない。
2. 両候補は `WORLD_INTERACTION`、`stableOrder = 80`、`CLAIM_AND_CANCEL`とする。`LEFT_CLICK_BLOCK`で`clickedBlock`のAABB入口距離を解決できる場合はその`hitDistance`を使い、generic vanilla block候補と同じ距離で比較する。それ以外はsnapshotの最初の遮蔽blockまでの`hitDistance`を使う。同距離では既存の独自world操作（`10`〜`70`）を優先し、generic vanilla block操作（`90`）より先にフックショットを実行する。
3. executor直前には、装填開始は同じ主手instance・未装填・開始条件、発射は同じ主手instance・loaded状態・有効アンカーを再検証する。再検証に失敗した場合は別候補へfallbackしない。
4. quit、death、world変更、成功した外部teleportはobserverとして短期牽引と未完了装填を終了する。完成済みのloaded metadataは削除しない。

## 2. アイテム使用executor境界

- bundle候補の勝者は`BundleUseService`へ委譲する。
- potion候補の勝者は`PotionUseService.use`へ委譲する。
- hookshot左クリックの未装填候補の勝者は`HookshotUseService.startLoading`、loaded候補の勝者は`HookshotUseService.fire`へ委譲する。装填完了時の有効アンカーへの発射は`HookshotUseService`内で自動実行する。
- weapon / combat候補の勝者は`ItemWeaponAttackService`へ委譲する。
- executor開始時にitemやplayer状態が失効していた場合は拒否または失敗として終了し、別候補へfallbackしない。
- executor の例外は `runSafely` が共通 event 実行失敗 `LogId.E_3002` を記録し、イベント境界へ漏らさない。

## 3. バニラ消費受付

イベント物理名: `PlayerItemConsumeEvent`
クラス名: `ItemInteractionBlockEventHandler`
物理名: `onPlayerItemConsume`

AstralRecord itemのバニラ消費を抑止する。本eventはクリック候補の勝者選択を行わず、item useの業務効果は勝者executorから開始する。

## 4. ホットバー変更後の使用待機解除observer

イベント物理名: `PlayerItemHeldEvent`

クラス名: `ItemInteractionBlockEventHandler`

物理名: `onPlayerItemHeld`

1. `MONITOR`かつ`ignoreCancelled = true`で監視し、cancel済みeventでは実処理しない。
2. 未cancelの通常slot変更が成立した場合だけ、進行中のbundle開封とpotion使用待機をcancelする。
3. 本処理は`HOTBAR_SLOT`の候補を返さない非競合observerであり、input lock、表示中action ring guardとの勝者選択へ参加しない。
4. `HOTBAR_SLOT`候補がslot変更をcancelした場合、持ち替えは成立していないため使用待機を解除しない。
5. 入力所有権とcancel方針は[[28_3-イベント]].ホットバースロット変更受付 を正本とする。

## 5. 退出時の使用待機解除

イベント物理名: `PlayerQuitEvent`
クラス名: `ItemInteractionBlockEventHandler`
物理名: `onPlayerQuit`

処理内容:

1. `BundleUseService.cancelPendingOpen(playerUuid)` を通知なしで実行する
2. `PotionUseService.cancelPendingUse(playerUuid)` を通知なしで実行する
3. 例外は共通 event 実行失敗 `LogId.E_3002` を対象プレイヤー名付きで記録する
