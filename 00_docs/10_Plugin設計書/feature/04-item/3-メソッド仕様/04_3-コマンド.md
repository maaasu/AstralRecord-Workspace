# 04_3-コマンド

## 1. item コマンド振分

クラス名: `ItemCommand`
物理名: `executeCommand`

入力:

- 引数なし
- `load <itemId>`
- `get <itemId|itemName> [amount] [player]`

処理内容:

1. 引数なしの場合は、実行者がプレイヤーなら [[04_3-コマンド]].管理者item GUI委譲 を実行する。コンソールからはプレイヤー専用メッセージを返す
2. 第1引数 `load` は [[04_3-コマンド]].アイテム単体再ロード へ委譲する
3. 第1引数 `get` は [[04_3-コマンド]].ロード済みアイテム付与 へ委譲する
4. その他は usage を返す

権限:

- `AstCommand` の `UserPermission.ADMIN(99)` ガードを使用する。`load` はコンソールからも実行できる

## 2. 管理者item GUI委譲

クラス名: `ItemCommand`
物理名: `openAdminGui`

処理内容:

1. plugin から `ItemAdminGuiEventHandler` を取得する
2. 未初期化なら `PlayerMsgId.P_5063` を送信する
3. 初期化済みなら `ItemAdminGuiEventHandler.open(player)` を呼ぶ

## 3. アイテム単体再ロード

クラス名: `ItemCommand`
物理名: `handleLoad`

入力:

- `args[1]`: item ID

処理内容:

1. 引数不足なら usage を返す
2. `ItemService.loadItem(args[1])` で詳細 API から単体取得し、共有キャッシュへ反映する
3. 未検出なら `PlayerMsgId.P_5201` へ item ID 1 引数を渡して終了する
4. 成功時は実行者へ `PlayerMsgId.P_5209` を送り、日本語カテゴリ名、ID、表示名を渡す

出力:

- なし

## 4. ロード済みアイテム付与

クラス名: `ItemCommand`
物理名: `handleGet`

入力:

- `args[1]`: item ID またはロード済みアイテム名。カテゴリータグ付き候補はカテゴリーと表示名の組で解決する
- `args[2]`: 数量または対象プレイヤー名。省略時は `1`、正の整数として解釈できない場合は対象プレイヤー名
- `args[3]`: 対象プレイヤー名。`args[2]` に数量を指定した場合のみ指定可能

処理内容:

1. 引数不足または不正な引数数・数量なら usage を返す
2. 対象プレイヤーを解決する。対象省略時は実行者自身、コンソールで対象省略時は `PlayerMsgId.P_5305` を返す。明示対象はオンラインかつ `AstPlayerCache` 済みだけを受け付け、解決できない場合は `PlayerMsgId.P_5814` を返す
3. `args[1]` が `[カテゴリー表示名]アイテム名` の形式ならカテゴリーと表示名の組で `ItemService.findLoadedByCategoryAndName` を呼び出し、それ以外は `ItemService.findLoadedByIdOrName(args[1])` で共有キャッシュだけを参照する。タグなし入力はID一致を優先してから表示名を検索する
4. 未ロードなら実行者へ `PlayerMsgId.P_5213` を送信し、API 取得せず終了する
5. `InventoryService` 未初期化なら実行者へ `PlayerMsgId.P_5063` を送信する
6. 卵は `PetService.grantEggItems` でマスターの `eggItemId` から種類を解決し、既存の卵作成API・事前保存・三者マージを使って非同期付与する。1個ずつ空き枠を確認し、確定数だけ成功通知する。空き不足は `P_5241`、未確定操作は `P_9603`、マスター不整合や確定拒否は `P_9605` と区別する。孵化済みペットの直接生成は行わず `P_9604` で卵と施設孵化を案内する。他カテゴリは対象 `AstPlayer` へ `InventoryService.addItemToNormalInventory` で付与する
7. 付与数が 0 以下なら実行者へ `PlayerMsgId.P_5241` を送信する
8. 通貨以外は対象の解決した `InventoryType` の GUI を反映する
9. 成功時は実行者へ `PlayerMsgId.P_5240` を送り、対象が別プレイヤーなら対象にも同じメッセージを送る

出力:

- なし

## 5. item コマンド補完

クラス名: `ItemTabCompleter`
物理名: `getCompletions`

処理内容:

1. 管理者プレイヤーまたはコンソールにだけ候補を返す
2. 第1引数位置では `load`, `get` を返す
3. `load` の第2引数位置では `ItemService.getLoadedItemIds()` を返す
4. `get` の第2引数位置では、IDを表示せず、`[カテゴリー表示名]アイテム名` 形式のロード済みアイテム候補を返す
5. `get` の第3引数位置では `1`, `8`, `16`, `32`, `64` とオンラインプレイヤー名を返す
6. `get` の第4引数位置ではオンラインプレイヤー名を返す。`load` の対象引数は補完しない
7. その他は空リストを返す

## 6. 管理者item GUI表示

クラス名: `ItemAdminGuiEventHandler`
物理名: `open`

処理内容:

1. `ADMIN(99)` 権限を防御的に再確認する
2. プレイヤー単位のカテゴリ・レア度・ページ状態を初期化する
3. `ItemService.getLoadedItems()` をフィルタし、`ItemAdminGuiView.open` へ渡す

終了条件:

- 権限不足は `PlayerMsgId.P_5707` を送信して終了する

## 7. 管理者item GUI描画

クラス名: `ItemAdminGuiView`
物理名: `open` / `render`

処理内容:

1. 54 slot inventory を作成し、slot `0..44` の内容領域へ最大 45 item を表示する
2. slot `45..53` に前後ページ、カテゴリ・レア度 filter、guide を描画する。移動先のない前後ページ slot は空にせず、「これ以上操作できません」と表示する操作不可のブランクアイコンを配置する。移動不可時は前後ページ名や範囲外のページ番号を表示しない
3. item 表示は `ItemStackFactory.createShopDisplay` を使い、未確定 roll を範囲で表示する
4. 管理者配布 Lore は `ItemStackFactory` の共通ヘッダーにある `カテゴリ | <item ID>` 表示を使用し、管理者配布用の内部ID行を重複追加しない

## 8. 管理者item GUI操作

イベント物理名: `InventoryClickEvent` / `InventoryDragEvent` / `GuiSessionEndEvent`
クラス名: `ItemAdminGuiEventHandler`
物理名: `onInventoryClick` / `onInventoryDrag` / `onGuiSessionEnd`

処理内容:

1. 対象 GUI の top inventory と drag は vanilla 操作をキャンセルする。player inventory 側は `HotbarShortcutClickSupport` へ委譲し、BAG スクロール、hotbar 割当、表示 item 操作を共通処理する
2. カテゴリまたはレア度 filter をクリックすると、ロード済み item に存在する候補と「すべて」の一覧 GUI を開く。候補をクリックして適用し、ページを 0 に戻した一覧 GUI へ戻る
3. 前後ページ操作は filter 結果内でページを正規化する
4. 内容 item の左 click は 1、右 click は半 stack 切り上げ、Shift+左 click は 1 stack を要求する
5. `InventoryService.addItemToNormalInventory(..., "admin_gui")` で付与し、失敗時は `P_5241` と拒否音を返す
6. フィルター候補画面への内部遷移中は GUI state を維持し、共有 GUI セッションの終了確定時だけプレイヤー単位の GUI state を削除する

## 9. showitem コマンド

クラス名: `ItemChatShareCommand`

物理名: `executePlayerCommand`

入力:

- `/showitem <itemName>`
- `/si <itemName>`

処理内容:

1. `itemName` を空白結合し、`[<slotNumber>] <itemName>` 形式なら表示中 BAG の論理スロット番号（左上を `1` とする）と表示名の両方で AstralRecord item を 1 件解決する。旧形式の表示名だけを指定した場合は後方互換として先頭出現順で 1 件解決する。
2. 解決できない場合は `PlayerMsgId.P_5949` を送信して終了する。
3. 解決できた item はインベントリ表示専用のクリック操作案内を除いた clone を hover tooltip に使い、先頭の `◆` 装飾を除いた表示名を全体チャットの本文として送信する。
4. 本文へカーソルを合わせると item の表示名・lore を含む通常のアイテム tooltip を表示する。本文をクリックすると、`◆` と装飾コードを含まない表示名をクライアントのクリップボードへコピーする。

権限:

- `AstCommand` の player-only ガードを使用する。追加の権限は要求しない。

## 10. showitem 補完

クラス名: `ItemChatShareTabCompleter`

物理名: `getPlayerCompletions`

1. 実行プレイヤーの表示中 BAG から、表示名を持つ AstralRecord item ごとに `[<slotNumber>] <itemName>` 形式の候補を先頭出現順で返す。`slotNumber` は BAG の論理スロット番号（左上を `1` とする）であり、同名 stack も個別に候補へ含める。
2. 表示名に空白が含まれる場合は、すでに入力済みの語を再挿入しない残り部分だけを候補にする。

## 11. enhance コマンド

クラス名: `EnhanceCommand`

物理名: `executeCommand` / `parseArguments`

入力:

- `/enhance <itemName> <level|+delta|-delta> [player]`
- `itemName` は `/si` と同じ `[<BAGスロット番号>] <表示名>`。表示名だけの指定も受け付ける。

処理内容:

1. `AstCommand` の `UserPermission.ADMIN(99)` ガードを使用する。
2. 末尾とその直前が整数で、末尾がオンラインプレイヤー名に一致する場合は対象名として優先し、その直前を強化値指定とする。それ以外では末尾の十進整数を強化値指定として取り出す。末尾が整数でない場合はプレイヤー名、その直前を強化値指定として解釈する。残りを空白結合して装備指定とする。空白を含む装備名を保持し、引数不足・小数・符号だけの入力・不正な整数では usage を返す。オンライン名と一致する数値を自分の設定値として明確に指定する場合は、実行者名を末尾に明示する。
3. プレイヤー省略時は実行者自身。コンソールで省略した場合は `P_5305`、オンラインかつ読み込み済みの対象が見つからない場合は `P_5814` を返す。対象の account mode が通常プレイを処理しない場合は `P_5065` を返す。
4. `ItemEnhanceService.setLevel` で表示中 BAG の所持装備を解決し、所有 entry と個体を更新直前に再検証する。対象がない場合は `P_5231`、別の所持品操作の確定待ちでは `P_5232` を返す。
5. 符号なしの整数はその値へ設定する。`+N` は現在値に N を加算し、`-N` は現在値から N を減算する。`+0` / `-0` は現在値を維持する。入力桁数による整数オーバーフローを起こさず、計算結果を `0` から現在状態の到達可能な強化上限へ補正する。
6. 管理者による値変更は抽選・オーブ・素材・ゴールドの消費を行わない。強化値と耐久値を一体変更し、装備表示・BAG / HOTBAR 表示・ステータスを更新する。実行者と、別プレイヤーを指定した場合は対象にも `P_5230` で変更前後の強化値と上限を通知する。

## 12. enhance 補完

クラス名: `EnhanceTabCompleter`

物理名: `getCompletions`

1. 管理者プレイヤーにだけ、自分の表示中 BAG で強化可能な装備を `[<BAGスロット番号>] <表示名>` の形式で返す。同名装備はスロット別に候補へ含め、入力済みの語を再挿入しない残り部分だけを返す。
2. 装備マスタの強化定義・現在状態の到達可能上限・所持 entry・所有個体が有効なものに限定する。現在値が上限に達していても減算・設定できるため候補へ含める。
3. 装備指定完了後は `0`, `1`, 到達可能上限, `+1`, `-1` を補完する。重複値は一度だけ返す。
4. 強化値指定完了後は、管理者またはコンソールにオンラインプレイヤー名を補完する。
