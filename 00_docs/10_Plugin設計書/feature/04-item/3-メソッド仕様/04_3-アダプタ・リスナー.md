# 04_3-アダプタ・リスナー

## 1. ItemStackPacketAdapter メソッド仕様

### パケットアダプタ登録

クラス名: `ItemStackPacketAdapter`
物理名: `register`

責務:

ProtocolLib に `SET_SLOT` / `WINDOW_ITEMS` / `ENTITY_EQUIPMENT` の送信リスナーを登録する。`ENTITY_EQUIPMENT` は slot-stack pair list を直接書き換えず、必要時だけ Paper API の受信者専用装備更新へ置き換える。

処理内容:

1. 既に登録済みであれば何もせず終了する
2. `ProtocolLibrary.getProtocolManager` を取得する
3. `PacketAdapter` を `ListenerPriority.NORMAL` で生成し、`PacketType.Play.Server.SET_SLOT`、`WINDOW_ITEMS`、`ENTITY_EQUIPMENT` を購読する
4. リスナーは `onPacketSending` で `event.isCancelled()` を確認し、受信者の `ARMOR_DISPLAY` と `ACTION_RING_HOLD_SELECT` を cache から取得し、アクションリング表示状態と表示開始時に保存した選択中 hotbar slot を `SkillActionRingService` から取得して、パケット種別ごとの書き換えへ委譲する。長押し設定が有効かつアクションリング表示中の場合だけ、選択中 hotbar slot の主武器を仮想トライデント候補にする
5. 登録完了を `LogId.I_5210` で記録する

	| 項目 | 内容 |
	|---|---|
	| ID | `LogId.I_5210` |
	| レベル | `INFO` |
	| テンプレート | `ItemStackPacketAdapter を登録しました` |
	| 出力条件 | パケットリスナー登録完了時 |
	| 引数 | なし |

### SET_SLOT書き換え

クラス名: `ItemStackPacketAdapter`
物理名: `handleSetSlot`

責務:

単一スロット送信パケットの `ItemStack` を icon Material / customModelData に書き換える。`ACTION_RING_HOLD_SELECT=true` かつアクションリング表示中で、送信対象が本人の選択中 hotbar slot の主武器である場合だけ、icon ではなく `TRIDENT` として送る。

処理内容:

1. パケットの index `0` の `ItemStack` を読み取る
2. `null` または `AIR` なら何もせず終了する
3. [[04_3-アダプタ・リスナー]].アイコン書き換え判定 で書き換え後の ItemStack を取得する
4. 書き換えが発生した場合のみ、パケットの index `0` を上書きする

### WINDOW_ITEMS書き換え

クラス名: `ItemStackPacketAdapter`
物理名: `handleWindowItems`

責務:

インベントリ一括送信パケットの ItemStack 配列を icon Material / customModelData に書き換える。`ACTION_RING_HOLD_SELECT=true` かつアクションリング表示中の場合だけ、player inventory window の選択中 hotbar index の主武器を仮想トライデント候補にする。

処理内容:

1. パケットの ItemList を読み取る
2. リストが `null` または空なら何もせず終了する
3. 各要素ごとに [[04_3-アダプタ・リスナー]].アイコン書き換え判定 を呼び出す
4. 書き換えが発生した要素のみ差し替え、最後にパケットへ書き戻す

### ENTITY_EQUIPMENT書き換え

クラス名: `ItemStackPacketAdapter`
物理名: `handleEntityEquipment`

責務:

他エンティティのメインハンド・オフハンド・防具 ItemStack を受信者向け icon と防具表示設定へ置き換える。

処理内容:

1. `getSlotStackPairLists()` から装備 slot と ItemStack の pair 一覧を取得する
2. 各 AstralRecord ItemStack に [[04_3-アダプタ・リスナー]].アイコン書き換え判定 を適用し、変更が必要か判定する。置換時に元更新を欠落させないよう、再送用には全 slot と元 ItemStack を退避する
3. 変更が不要なら元パケットをそのまま送信する
4. 変更が必要なら元パケットを cancel し、Bukkit メインスレッドで対象 `LivingEntity` を解決する
5. 対象 `LivingEntity` を解決できた場合は、退避した slot を Paper API の `Player#sendEquipmentChange` で受信者へ送信し、Paper に packet 符号化を委譲する
6. 対象を解決できない場合は、pair-list を書き換えていない元 `PacketContainer` のコピーを ProtocolLib listener filter を通さず受信者へ再送し、cancel 済みの更新を欠落させない
7. Paper API 再送前に、受信者・entityId・slot・変換済み ItemStack ごとの共有再送識別を登録する。同一内容の連続再送は件数を保持し、各一致パケットで一回だけ消費する
8. listener は別スレッドで到達した Paper API 再送パケットでも識別を消費してそのまま送信する。未消費の識別は5秒で期限切れにし、受信者の logout 時にも破棄する

### アイコン書き換え判定

クラス名: `ItemStackPacketAdapter`
物理名: `replaceIcon`

責務:

AstralRecord アイテムであれば icon Material と customModelData を解決して書き換え済み ItemStack を返す。主武器に限り、呼出側が仮想トライデントを指定した場合は icon Material の代わりに `TRIDENT` を使う。

処理内容:

1. `ItemStackFactory` から icon、customModelData、appearance 情報を取得する
2. icon・customModelData・appearance がすべて未設定で、仮想トライデント対象でもない場合は `null` を返し、書き換えをスキップする
3. 仮想トライデント指定かつ PDC の装備 slot が `WEAPON` なら、`original.withType(Material.TRIDENT)` で送信コピーだけを差し替える。それ以外で icon が指定されていれば [[04_3-アダプタ・リスナー]].Material解決 でキャッシュ越しに Material を取得し、元の Material と異なる場合のみ `original.withType(iconMaterial)` で差し替える
4. customModelData が指定されていれば `CustomModelDataComponentUtil.readAsInt(meta)` で現在値を取得し、`needsCustomModelDataUpdate` で差分判定の上、必要なら `CustomModelDataComponentUtil.writeFromInt(meta, customModelData)` を実行する
5. appearance と耐久表示を送信コピーへ適用する
6. 受信者の `ARMOR_DISPLAY` が `false` かつ送信コピーが `EQUIPPABLE` component を持つ場合、同 component を `unsetData` する
7. 書き換えが発生した場合のみ書き換え後の ItemStack、発生しなかった場合は `null` を返す

### 装備表示再同期

クラス名: `ItemStackPacketAdapter`
物理名: `refreshEquipmentView`

責務:

設定変更または login warmup 後、受信者本人の inventory と受信者が追跡中のプレイヤー防具をメインスレッドから再送する。

処理内容:

1. 受信者の `updateInventory()` を呼び、本人の armor slot を含む inventory 表示を再同期する
2. online player のうち受信者本人または受信者が追跡中の target を列挙する
3. target の HEAD / CHEST / LEGS / FEET を受信者の表示設定に応じて変換する
4. 変換済み ItemStack を再送識別へ登録してから `sendEquipmentChange` で受信者へ送信し、`ENTITY_EQUIPMENT` の slot-stack pair list を再書換しない

### Material解決

クラス名: `ItemStackPacketAdapter`（static メソッド）  
物理名: `resolveMaterial`

責務:

icon Material 名を解決し、`ConcurrentHashMap` でキャッシュする。

処理内容:

1. 入力名を大文字化する
2. キャッシュに無ければ `Material.matchMaterial` で解決する
3. 解決失敗時は `LogId.W_5210` を記録し、キャッシュに `null` を保持する

	| 項目 | 内容 |
	|---|---|
	| ID | `LogId.W_5210` |
	| レベル | `WARN` |
	| テンプレート | `不明な icon Material 名です: %s` |
	| 出力条件 | `Material.matchMaterial` 失敗時 |
	| 引数 | 解決対象 Material 名（大文字） |

### customModelData 更新判定

クラス名: `ItemStackPacketAdapter`（static メソッド）  
物理名: `needsCustomModelDataUpdate`

責務:

期待値と現在値を比較し、書き換えが必要かどうかを返す。

処理内容:

1. `currentCustomModelData == null` の場合は更新必要として `true` を返す
2. 現在値と期待値が異なる場合は `true` を返す
3. それ以外は `false` を返す

## 2. 対象パケット

- `PacketType.Play.Server.SET_SLOT`
- `PacketType.Play.Server.WINDOW_ITEMS`
- `PacketType.Play.Server.ENTITY_EQUIPMENT`

## 3. 性能上の考慮

- Material 名 → `Material` の変換結果は `ConcurrentHashMap` でキャッシュし、毎パケット呼び出しを回避する
- AstralRecord アイテムでない ItemStack は PDC 読み取りのみで即スキップする
- 防具表示設定は cache のみを参照し、パケット送信処理から API I/O を発生させない
- 長押し選択設定の cache、アクションリング表示状態と表示開始時に保存した選択中 hotbar slot、ItemStack PDC だけを参照し、パケット送信処理から Bukkit 状態変更や API I/O を発生させない
- ItemStack の書き換えは `withType` と `ItemMeta` 直接更新で行い、不要なオブジェクト生成を抑える
