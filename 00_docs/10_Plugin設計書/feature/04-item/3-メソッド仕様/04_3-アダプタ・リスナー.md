# 04_3-アダプタ・リスナー

## 1. ItemStackPacketAdapter メソッド仕様

### パケットアダプタ登録

クラス名: `ItemStackPacketAdapter`
物理名: `register`

責務:

ProtocolLib に `SET_SLOT` / `WINDOW_ITEMS` / `ENTITY_EQUIPMENT` の送信リスナーを登録する。

処理内容:

1. 既に登録済みであれば何もせず終了する
2. `ProtocolLibrary.getProtocolManager` を取得する
3. `PacketAdapter` を `ListenerPriority.NORMAL` で生成し、`PacketType.Play.Server.SET_SLOT`、`WINDOW_ITEMS`、`ENTITY_EQUIPMENT` を購読する
4. リスナーは `onPacketSending` で `event.isCancelled()` を確認し、受信者の `ARMOR_DISPLAY` を cache から取得して、パケット種別ごとの書き換えへ委譲する
5. 登録完了を `LogId.I_5210` で記録する

	| 項目 | 内容 |
	|---|---|
	| ID | `LogId.I_5210` |
	| レベル | `INFO` |
	| テンプレート | `ItemStackPacketAdapter を登録しました` |
	| 出力条件 | パケットリスナー登録完了時 |
	| 引数 | なし |

### SET_SLOT書き換え

クラス名: `ItemStackPacketAdapter`
物理名: `handleSetSlot`

責務:

単一スロット送信パケットの `ItemStack` を icon Material / customModelData に書き換える。

処理内容:

1. パケットの index `0` の `ItemStack` を読み取る
2. `null` または `AIR` なら何もせず終了する
3. [[04_3-アダプタ・リスナー]].アイコン書き換え判定 で書き換え後の ItemStack を取得する
4. 書き換えが発生した場合のみ、パケットの index `0` を上書きする

### WINDOW_ITEMS書き換え

クラス名: `ItemStackPacketAdapter`
物理名: `handleWindowItems`

責務:

インベントリ一括送信パケットの ItemStack 配列を icon Material / customModelData に書き換える。

処理内容:

1. パケットの ItemList を読み取る
2. リストが `null` または空なら何もせず終了する
3. 各要素ごとに [[04_3-アダプタ・リスナー]].アイコン書き換え判定 を呼び出す
4. 書き換えが発生した要素のみ差し替え、最後にパケットへ書き戻す

### ENTITY_EQUIPMENT書き換え

クラス名: `ItemStackPacketAdapter`
物理名: `handleEntityEquipment`

責務:

他エンティティのメインハンド・オフハンド・防具 ItemStack を受信者向け icon と防具表示設定へ書き換える。

処理内容:

1. `getSlotStackPairLists()` から装備 slot と ItemStack の pair 一覧を取得する
2. 各 AstralRecord ItemStack に [[04_3-アダプタ・リスナー]].アイコン書き換え判定 を適用する
3. 元の pair / ItemStack を直接変更せず、変更後の pair 一覧を構築する
4. 変更がある場合だけパケットへ一覧を書き戻す

### アイコン書き換え判定

クラス名: `ItemStackPacketAdapter`
物理名: `replaceIcon`

責務:

AstralRecord アイテムであれば icon Material と customModelData を解決して書き換え済み ItemStack を返す。

処理内容:

1. `ItemStackFactory` から icon、customModelData、appearance 情報を取得する
2. すべて `null` の場合は `null` を返し、書き換えをスキップする
3. icon が指定されていれば [[04_3-アダプタ・リスナー]].Material解決 でキャッシュ越しに Material を取得し、元の Material と異なる場合のみ `original.withType(iconMaterial)` で差し替える
4. customModelData が指定されていれば `CustomModelDataComponentUtil.readAsInt(meta)` で現在値を取得し、`needsCustomModelDataUpdate` で差分判定の上、必要なら `CustomModelDataComponentUtil.writeFromInt(meta, customModelData)` を実行する
5. appearance と耐久表示を送信コピーへ適用する
6. 受信者の `ARMOR_DISPLAY` が `false` かつ送信コピーが `EQUIPPABLE` component を持つ場合、同 component を `unsetData` する
7. 書き換えが発生した場合のみ書き換え後の ItemStack、発生しなかった場合は `null` を返す

### 装備表示再同期

クラス名: `ItemStackPacketAdapter`
物理名: `refreshEquipmentView`

責務:

設定変更または login warmup 後、受信者本人の inventory と受信者が追跡中のプレイヤー防具をメインスレッドから再送する。

処理内容:

1. 受信者の `updateInventory()` を呼び、本人の armor slot を含む inventory 表示を再同期する
2. online player のうち受信者本人または受信者が追跡中の target を列挙する
3. target の HEAD / CHEST / LEGS / FEET を `sendEquipmentChange` で受信者へ再送する
4. 再送パケットは通常の `ENTITY_EQUIPMENT` 書き換えを通し、受信者の最新設定を反映する

### Material解決

クラス名: `ItemStackPacketAdapter`（static メソッド）  
物理名: `resolveMaterial`

責務:

icon Material 名を解決し、`ConcurrentHashMap` でキャッシュする。

処理内容:

1. 入力名を大文字化する
2. キャッシュに無ければ `Material.matchMaterial` で解決する
3. 解決失敗時は `LogId.W_5210` を記録し、キャッシュに `null` を保持する

	| 項目 | 内容 |
	|---|---|
	| ID | `LogId.W_5210` |
	| レベル | `WARN` |
	| テンプレート | `不明な icon Material 名です: %s` |
	| 出力条件 | `Material.matchMaterial` 失敗時 |
	| 引数 | 解決対象 Material 名（大文字） |

### customModelData 更新判定

クラス名: `ItemStackPacketAdapter`（static メソッド）  
物理名: `needsCustomModelDataUpdate`

責務:

期待値と現在値を比較し、書き換えが必要かどうかを返す。

処理内容:

1. `currentCustomModelData == null` の場合は更新必要として `true` を返す
2. 現在値と期待値が異なる場合は `true` を返す
3. それ以外は `false` を返す

## 2. 対象パケット

- `PacketType.Play.Server.SET_SLOT`
- `PacketType.Play.Server.WINDOW_ITEMS`
- `PacketType.Play.Server.ENTITY_EQUIPMENT`

## 3. 性能上の考慮

- Material 名 → `Material` の変換結果は `ConcurrentHashMap` でキャッシュし、毎パケット呼び出しを回避する
- AstralRecord アイテムでない ItemStack は PDC 読み取りのみで即スキップする
- 防具表示設定は cache のみを参照し、パケット送信処理から API I/O を発生させない
- ItemStack の書き換えは `withType` と `ItemMeta` 直接更新で行い、不要なオブジェクト生成を抑える
