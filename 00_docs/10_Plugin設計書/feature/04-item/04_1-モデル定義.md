# 04_1-モデル定義

## 1. ドメイン構成

`item` 機能は `ItemModel` を中心に、カテゴリ別定義とプレイヤー所有インスタンスを分離します。

- カテゴリ別定義: `ItemBundle`, `ItemCurrency`, `ItemEquipment`, `ItemConsumable`, `ItemRune`, `ItemSkillGem`, `ItemSigil`, `ItemOrb`
- 所有インスタンス: `EquipmentInstance`, `RuneInstance`
- セット効果: `SetEffect`

## 2. `ItemCategory`

`bundle`, `currency`, `equipment`, `material`, `consumable`, `rune`, `skill_gem`, `sigil`, `orb`, `unknown` を扱います。API 値とコマンド入力は `fromApiValue` / `fromInput` で解決し、対応値は `supportedApiValues` を正とします。

## 3. `ItemModel`

共通項目は `schemaVersion`, `id`, `category`, `name`, `icon`, `rarity`, `maxStack`, `saleValue`, `customModelData`, `lore`, `unTradeable`, `unSellable` です。カテゴリ固有定義は対応する `bundle`, `currency`, `equipment`, `consumable`, `rune`, `skillGem`, `sigil`, `orb` に保持します。

## 4. カテゴリ固有定義

### 4.1 `ItemBundle`

`lootTableId` と `onUse`（`sound`, `effect`, `particle`）を持ちます。

### 4.2 `ItemCurrency`

`type`, `group`, `expiresAt` を持ちます。

ゴールド系の組み込み通貨は `type=gold`, `group=denomination` とし、`gold`（1）、`gold_coin`（10）、`gold_ingot`（100）、`gold_block`（1,000）、`gold_diamond`（10,000）、`gold_diamond_block`（100,000）、`yggdrasil_star_core`（1,000,000）の7額面を持ちます。

### 4.3 `ItemEquipment`

`slot`, `handType`, `tag`, `requiredLevel`, `requiredClasses`, `setId`, `stats`, `durability`, `enhance`, `enchant`, `rune`, `transcendence` を持ちます。skill 付与フィールドは持ちません。

- `ItemEquipmentStat`: `status`, `type`, `min`, `max`, `rollValue`, `displayValue`
- `ItemEquipmentDurability`: 最大耐久値と消費設定
- `ItemEquipmentEnhance`: `maxLevel` とレベル別ステータス・耐久補正
- `ItemEquipmentEnchantDef`: `maxSlots`
- `ItemEquipmentRuneDef`: `maxSlotsRaw`, `allowedRuneIds`
- `ItemEquipmentClassRequirement`: 装備可能な現在クラス ID と必要クラスレベル
- `ItemEquipmentTranscendence`: `rank`, `requiredEnhanceLevel`, 必要素材・通貨と名称・強化上限・スロット上限の上書き

`requiredLevel` はアカウントのプレイヤーレベル、`requiredClasses[].level` は現在選択中クラスのクラスレベルとして共通判定する。防具・サブ武器・アクセサリは条件未達時に装着不可とし、ホットバーへ割り当て可能な武器は条件未達時にクリック操作と装備由来ステータスを無効化する。

武器の通常攻撃は `tag=SWORD` / `BOW` / `STAFF` から自動解決し、implementation ID は順に `normal_attack_melee`, `normal_attack_bow`, `normal_attack_magic` を使用します。通常攻撃はジェム、習得、使用許可を必要としないシステムスキルです。

### 4.4 `ItemConsumable`

`onUse` と `effects` を持ちます。効果は `type`, `value`, `isPercent`, `buffId` 等で表現します。

### 4.5 `ItemRune`

`targetSlots`, `requiredEnhanceLevel`, `stats` を持ちます。skill は付与しません。

### 4.6 `ItemSkillGem`

`skillId` を持ちます。ID は `00_skill_gem_<skillId>` で、API が skill master から仮想生成します。ジェム自身はレベルを持たず、左クリックによる別個体の新規習得、またはスキルマネージャーで指定個体を1レベル上げる素材として消費します。

### 4.7 `ItemSigil`

`equipGroupId`, `modifiers` を持ちます。ステータス補正は `modifiers` を計算時に加算し、ロジック変更系は装着済みシジルのアイテム ID を各スキルロジックが判定します。スキルマネージャーで習得済み個体へ合成すると消費され、取り外しできません。同じ個体には同じ `equipGroupId` を複数装着できません。

### 4.8 `ItemOrb`

`effect` に1種類の装備操作を保持します。`type` は `ENHANCE` / `REPAIR` / `TRANSCENDENCE` / `ENCHANT`、ランク条件は `rank` と `rankMode`（`EXACT` / `AT_MOST`）で表現します。強化は `targetSlots`、修理は `repairAmount` または `repairFull`、エンチャントは `enchantMasterId` と `enchantOperation` を使用します。

エンチャント操作は `OVERWRITE_RANDOM` / `FILL_ONE_EMPTY` / `FILL_ALL_EMPTY` とし、いずれも1回の成立した実行につきオーブを必ず1個だけ消費します。`FILL_ALL_EMPTY` も消費数は1個です。

## 5. 所有インスタンス

### 5.1 `EquipmentInstance`

`equipmentInstanceId`, `accountId`, `itemId`, `enhanceLevel`, `runeMaxSlots`, `transcendenceRank`, `durabilityMax`, `durabilityValue`, `createdAt`, `updatedAt`, `statRolls`, `enchants`, `runes` を保持します。`enchants` の各要素は `slotIndex`, `enchantMasterId`, `effectId`, `status`, `type`, `value` を持ちます。

API 応答の `durabilityMax` / `durabilityValue` が `null` の場合は `0`、`createdAt` / `updatedAt` が `null` の場合は空文字列へ正規化する。`statRolls` / `enchants` / `runes` が `null` の場合は変更可能な空 collection として扱う。同一装備に同じ `effectId` は重複しません。

### 5.2 `RuneInstance`

`runeInstanceId`, `accountId`, `itemId`, `createdAt`, `updatedAt` と確定済みの `RuneStatRoll` を保持します。

## 6. セット効果

`SetEffect` は必要装備数別の `SetEffectPiece` を持ち、各 piece が `SetEffectStat` を保持します。

## 7. ItemStack 永続キー

`ItemStackFactory` は `PersistentDataContainer` に次のキーを保存します。

- `astralrecord:item_id`
- `astralrecord:icon`
- `astralrecord:custom_model_data`
- `astralrecord:category`
- `astralrecord:rarity`
- `astralrecord:equipment_instance_id`
- `astralrecord:equipment_slot`
- `astralrecord:rune_instance_id`

## 8. API 契約

- `GET /api/item`, `GET /api/item/{itemId}`
- `GET /api/enchant/{enchantMasterId}`
- `POST/GET /api/equipment/instances`
- `POST /api/equipment/orb-operations`, `GET /api/equipment/orb-operations/{operationId}`, `POST /api/equipment/durability`
- `POST/GET /api/rune/instances`
- `GET /api/seteffect`, `GET /api/seteffect/{setId}`

ステータス種別は `StatusType` と一致させ、item / equipment / rune / set effect 間で文字列を独自定義しません。
