# 04_4-統合フロー

## 1. 起動時のアイテム一括ロード

### シーケンス

```mermaid
sequenceDiagram
    participant P as AstralRecord
    participant IS as ItemService
    participant IR as ItemRepository
    participant C as categoryCaches

    P->>IS: loadAll（非同期セットアップ）
    IS->>IR: findAll
    IR-->>IS: ItemSummary 一覧
    loop summary ごと
        IS->>IR: findById(id, category)
        IR-->>IS: ItemModel / null
        IS->>C: ID 単位で snapshot へ追加
    end
    IS->>C: 組み込み通貨を追加・master cacheを置換
    IS-->>P: ロード件数
```

### 処理要点

- plugin 起動時に一覧 API と各 summary の詳細 API を呼び、`ConcurrentHashMap` の ID key キャッシュへ登録する。
- `ItemStackFactory` のテンプレートは item キャッシュと別管理し、必要時に生成する。

### 例外・終了条件

- カテゴリ単位の取得結果と失敗は `LogId.I_5202` / `I_5203` / `E_5202` 等で記録する。

## 2. `/item get` による付与

### シーケンス

```mermaid
sequenceDiagram
    participant P as 管理者
    participant C as ItemCommand
    participant IS as ItemService
    participant IV as InventoryService

    P->>C: /item get itemId amount
    C->>IS: findLoadedById(itemId)
    alt ロード済みアイテムあり
        C->>IV: addItemToNormalInventory(player, model, amount)
        IV-->>C: 付与数
        opt 通貨以外
            C->>IV: applyInventoryToGui
        end
        C-->>P: PlayerMsgId.P_5240
    else 未ロード
        C-->>P: PlayerMsgId.P_5213
    end
```

### 処理要点

- `/item get` は起動時または `/item load` でロード済みのキャッシュだけを参照し、API 取得を行わない。
- 数量は省略時 `1`、整数化失敗時 `1`、下限 `1` とする。
- 付与数が 0 以下なら `PlayerMsgId.P_5241` を返す。

## 3. 送信 ItemStack のアイコン置換

### シーケンス

```mermaid
sequenceDiagram
    participant S as Server
    participant A as ItemStackPacketAdapter
    participant F as ItemStackFactory
    participant C as Client

    S->>A: SET_SLOT / WINDOW_ITEMS
    A->>F: getIconName / getCustomModelData
    alt 長押し選択設定有効の本人hotbar主武器
        A->>A: 送信コピーだけをTRIDENTへ変換
        A-->>S: 書換後 ItemStack
    else AstralRecord item
        A->>A: Material 解決・customModelData 更新
        A-->>S: 書換後 ItemStack
    else 対象 PDC なし
        A-->>S: 元の ItemStack
    end
    S->>C: パケット送信

    S->>A: ENTITY_EQUIPMENT
    A->>F: getIconName / getCustomModelData
    alt 変更不要
        A-->>S: 元パケットを通過
        S->>C: パケット送信
    else 変更必要
        A->>A: 元パケットを cancel・全装備 slot を退避
        A->>S: Bukkit メインスレッドで再送を予約
        alt LivingEntity を解決
            S->>C: sendEquipmentChange(変換済み全 slot)
            Note over A,C: 再送識別により再送パケットはそのまま通過
        else 解決失敗
            S->>C: 元PacketContainerをfilterなしで再送
        end
    end
```

### 処理要点

- サーバー側の保存 ItemStack は変更せず、送信時の表示だけを差し替える。
- `ACTION_RING_HOLD_SELECT` が有効なら、本人 hotbar 内の主武器全枠を `SET_SLOT` / `WINDOW_ITEMS` の送信コピーで `TRIDENT` にする。持ち替え直後でもクライアントがトライデント使用を開始できるよう、選択中一枠には限定しない。これはクライアントの使用継続・解除入力を得るための仮想化であり、`ENTITY_EQUIPMENT` とサーバー保存状態には適用しない。
- `SET_SLOT` と `WINDOW_ITEMS` は ProtocolLib の元パケットを送信コピーへ書き換える。
- `ENTITY_EQUIPMENT` は pair-list を直接書き戻さない。変更が必要な場合だけ元パケットを cancel し、Paper API の `Player#sendEquipmentChange` で全 slot を再送して、他プレイヤーのメインハンド・オフハンド・防具にもマスター icon を反映する。
- `LivingEntity` の解決に失敗した場合は、pair-list を書き換えていない元 `PacketContainer` を ProtocolLib listener filter なしで再送する。
- 防具表示設定はパケット受信者を基準とし、本人と受信者が追跡中の他プレイヤーへ同じ表示方針を適用する。
- 再送した `ENTITY_EQUIPMENT` は再送識別により listener の変換対象外とする。
- `resolveMaterial` は Material 解決結果をキャッシュする。

### 例外・終了条件

- 不明な icon Material は `LogId.W_5210` を記録し、元の Material を維持する。

## 6. `/item` 管理者 GUI

### シーケンス

```mermaid
sequenceDiagram
    participant P as 管理者
    participant C as ItemCommand
    participant H as ItemAdminGuiEventHandler
    participant V as ItemAdminGuiView
    participant IS as ItemService
    participant IV as InventoryService

    P->>C: /item
    C->>H: open(player)
    H->>IS: getLoadedItems
    H->>V: open(player, state, items)
    V-->>P: 54 slot GUI（内容領域 45 slot）
    P->>H: InventoryClickEvent
    alt フィルタまたはページ操作
        H->>V: 再描画
    else 内容アイテムをクリック
        H->>IV: addItemToNormalInventory(..., "admin_gui")
        IV-->>H: 付与数
    end
```

### 処理要点

- `/item` 無引数は usage ではなく ADMIN(99) 専用 GUI を開く。
- カテゴリ・レア度フィルタとページ状態はプレイヤー単位で保持する。
- 左クリックは 1、右クリックは半スタック切り上げ、Shift+左クリックは 1 スタックを付与する。最大スタック 1 の item は常に 1 となる。
- 表示 ItemStack は shop 表示と同じ未確定範囲 Lore を使い、付与成功後も GUI を閉じない。

### 例外・終了条件

- 権限不足、対象不明、付与不能のクリックは拒否し、付与不能時は `PlayerMsgId.P_5241` と拒否音を返す。

## 7. クリック item 使用

### シーケンス

```mermaid
sequenceDiagram
    participant EVT as PlayerInteractEvent
    participant G as PlayerInteractionGatewayEventHandler
    participant R as ItemInteractionBlockEventHandler
    participant H as HookshotInteractionEventHandler
    participant D as PlayerInputDispatcher
    participant B as BundleUseService
    participant P as PotionUseService
    participant HS as HookshotUseService
    participant L as LootService
    participant LR as LootRollService
    participant IV as InventoryService

    EVT->>G: onPlayerInteract
    G->>R: resolve(context)
    G->>H: resolve(context)
    R-->>D: ITEM_USE / weapon候補
    H-->>D: 左クリック: 未装填なら装填候補 / loadedなら発射候補（order 80）、右クリックは候補なし
    D->>D: 全 feature 候補を仲裁
    alt bundle の ITEM_USE が勝者
        D->>B: beginBundleUse
        B->>L: getLoadedOrFetch(lootTableId)
        B->>LR: roll(loot)
        B->>IV: bundle消費・報酬格納
    else consumable の ITEM_USE が勝者
        D->>P: usePotion
    else 未装填hookshot左クリックが勝者
        D->>HS: startLoading
        HS->>HS: 30 tick・移動速度50%低下・ActionBar進捗
        HS->>IV: hook 1個消費とloaded metadataを同時確定
        alt 現在照準に有効アンカーあり
            HS->>HS: 自動発射
            HS->>IV: instance耐久消費とloaded metadata解除
            HS->>HS: BlockDisplay / particleとvelocity牽引
        else 無効照準
            HS-->>D: loaded metadataを保持
        end
    else loaded hookshot左クリックが勝者
        D->>HS: fire
        HS->>IV: instance耐久消費とloaded metadata解除
        HS->>HS: BlockDisplay / particleとvelocity牽引
    end
    D-->>G: claim結果
    G-->>EVT: vanilla 操作を抑止
```

### 処理要点

- resolver は副作用なしで候補を返し、dispatcher が選んだ一件だけを実行する。
- hookshot は右クリックでは候補を返さず、未装填の左クリックで装填候補、loaded状態の左クリックで発射候補を返す。両候補を `stableOrder=80` で既存独自world操作の `10`～`70` の後、generic vanilla block の `90` の前に位置付ける。
- bundle は `loot_table:` 接頭辞を正規化して loot を解決し、各 content の確率と pool の `pick` 上限を `LootRollService` で処理する。
- 報酬は AstralRecord inventory へ格納する。現実装では収容できなかった残数を生成せず破棄するため、改善方針は [[04_9-未決事項]] で管理する。
- 成功時はサマリー、各報酬名と個数、表示・音・パーティクルを提示する。
- hookshotは左クリックで装填を開始し、装填完了時だけhookを1個消費する。装填完了後に有効アンカーがあれば自動発射し、発射時だけ耐久を消費してloaded状態を外す。照準が無効、または耐久不足ならloaded状態を保持する。牽引は`Player#setVelocity`の速度補正だけで行い、座標teleportは使わない。右クリックは何も発動しない。

### フックショット状態

```mermaid
stateDiagram-v2
    [*] --> UNLOADED
    UNLOADED --> LOADING: 左クリック / 30 tick開始
    LOADING --> UNLOADED: 中断・素材不足
    LOADING --> LOADED: hook 1個消費 + metadata保存
    LOADED --> PULLING: 装填完了 + 固体アンカー + 耐久消費（自動発射）
    LOADED --> PULLING: 左クリック + 固体アンカー + 耐久消費
    PULLING --> UNLOADED: 到達・時間切れ・終了
    LOADED --> LOADED: 無効照準・耐久不足・持ち替え・再ログイン
```

### 例外・終了条件

- loot または報酬 item を解決できない場合は bundle を消費せず失敗する。
- 勝者 executor の拒否・失敗・例外後に、別候補へ fallback しない。

## 8. HOTBAR_SLOT 後の使用待機解除

### シーケンス

```mermaid
sequenceDiagram
    participant EVT as PlayerItemHeldEvent
    participant G as PlayerInteractionGatewayEventHandler
    participant D as PlayerInputDispatcher
    participant O as ItemInteractionBlockEventHandler
    participant B as BundleUseService
    participant P as PotionUseService

    EVT->>G: onPlayerItemHeld
    G->>D: HOTBAR_SLOT を仲裁
    alt event が未キャンセル
        EVT->>O: onPlayerItemHeld（MONITOR observer）
        O->>B: cancelPendingOpen
        O->>P: cancelPendingUse
    else input lock 等が勝者
        O-->>EVT: observer は実行されない
    end
```

### 処理要点

- `ItemInteractionBlockEventHandler.onPlayerItemHeld` は候補を返さない非競合 observer とする。
- 実際に hotbar 変更が成立した場合だけ bundle / potion の使用待機を解除する。
