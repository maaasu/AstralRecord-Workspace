# AstralRecord コード修正

現在のタスクで返された指摘、指定された指摘 ID、または依頼者が提供したレビュー本文を入力とする。[レビューの共通書式](../_shared/review-record-format.md) を参考に、対象箇所、成立条件、期待、実際、影響を確認する。新規実装は `$astralrecord-code`、ワークスペーススキル自体の編集方法は `$skill-creator` を使う。

## 手順

1. 作業ルートの `AGENTS.md` に従い、依頼の対象と現在の専用作業ツリーを確認する。対象プロジェクトのガイドと、今回の判断に関係するパーソナライズの要望・機能判断を読む。プラグインや API の実装規約は [plugin-code.md](../astralrecord-code/references/plugin-code.md) と [api-code.md](../astralrecord-code/references/api-code.md) を参照する。
2. 依頼者が指定した指摘を対象とする。指定がない場合は自動修正可の指摘を候補とする。指摘の根拠を、依頼と確定条件、現行コードと呼び出し元、既存テスト、スキーマや設定に照らす。成立条件と期待する挙動を確定し、解消済みの指摘や根拠が現状と合わない指摘は確認結果を返す。判断が未確定の場合は必要な確認を残す。
3. 確定した範囲で最小限の修正を行う。既存の規約に従い、影響する呼び出し元の契約を保つ。公開契約、スキーマ、利用手順や運用資料の記載に影響する場合は該当箇所を更新する。
4. 指摘の成立条件を使って修正を検証する。プラグインのソース・リソースを修正した場合は `python .codex/skills/astralrecord-code/scripts/check_plugin_resources.py --repo-root <task-worktree>` を実行し、再利用した ID のプロパティ文言と操作の意味が一致することも確認する。[プラグインテストの構成検証](../astralrecord-code/references/plugin-code.md#プラグインテストの構成検証) の実行条件に該当する場合は、構成検証を実行する。統合作業では該当する品質ゲートに従い、ビルド・テスト・静的検査の出力と警告を確認する。
5. 対応状況を各指摘に対応付け、変更箇所、検証結果、残る質問を会話または担当の返答で渡す。同じタスク内の再レビューにこの結果を使う。継続的に効く判断が根拠付きで確定した場合は、[AIパーソナライズ](../../../00_docs/10_AIパーソナライズ/README.md) の規則に従い、該当するメモを更新する。
