# AstralRecord モブモデル制作

差分を作るときは `$astralrecord-code-version-commit-develop` の準備済み作業ツリーを使う。[リソースパック指示](../../../50_resourcepack/AGENTS.md) で対象バージョン、両版対応、描画確認の条件を確認する。アイテムモデル、マスターデータだけの変更、攻撃範囲などギミックだけの変更は、それぞれの担当へ渡す。

## 制作前に確認する

- 対象のマスター、既存の編集元と配布アセット、通常の表示経路を確認する。モチーフ、前方軸、足元原点、実寸、部位のピボット、アニメーション名を控える。改修では同じ視点・画角の旧モデルを残し、残す輪郭と作り直す部位を決める。
- Java 版では ItemDisplay など表示エンティティの固定変換まで確認する。統合版では Geyser の置換条件とクライアントエンティティのスケール、ボーン、表示境界を確認する。両版で使える形状と動作を先に決める。表示倍率と戦闘上の当たり判定を別々に扱う。
- ゲーム内で使う外観を新規追加する場合は、両版のアセットを `50_resourcepack/scripts/build-resourcepack.ps1` の収録一覧に入れ、Java 側のモデル選択と統合版側のエンティティ登録を確認する。対応パックを読み込んだ接続に表示を切り替え、未対応の接続には既存の代替表示を使う。

## 形とテクスチャを作る

- まず胴体・頭・付属肢の大きさと位置関係でモチーフを読めるようにする。主役の意匠を一つ決め、紋章の段差や角の形をほかの部位に小さく繰り返す。背面と下側も視線が届く姿勢から確認する。
- 模様を立体化するときは、紋章の台座、外周、芯、放射部などを厚みの異なるパーツに分ける。羽根や装甲の境界は、段差、重なり、稜線、切り欠きとして作る。元の描き込みは除き、無地に近い素材で見ても、斜めから形と影で模様を識別できるようにする。
- マイクラらしさは、大きな直方体、段状の輪郭、離散的な明暗のピクセル群で作る。材質を示す色のかたまりを面に置き、面の向きと段差が読める明暗差を付ける。細かい装飾を増やす前に、戦闘時の縮尺で主役の意匠が見えるか確認する。
- 動く部位の装飾は、その部位のボーンと一緒に動かす。関節をまたぐパーツは分割し、曲げたときに胸や翼を貫通しないことを確認する。浮いた装飾は斜め視点で確認する。異なる色の羽根などが外から見える同じ平面で重なるとちらつくため、重なる部分を切るか、厚さ方向の段をずらす。

## 戦闘での動きをつなぐ

- 待機・移動・予兆・発動・復帰で、翼・頭・手足などの姿勢を変え、戦闘距離でも状態を見分けられるようにする。予兆の開始、発動、中断に表示を結び付ける。空中判定やモデル全体の揺れだけで、攻撃モーションの確認を終えない。
- 攻撃の見せ方は、予兆境界と時間変化する部分を分ける。予兆の円や帯は実際の命中寸法で固定し、内部の光や立体形状を動かす。発動は軌道・形状・高さなどを時間で変化させ、着弾から消えるまで連続したフレームで確認する。
- 表示を代替する場合は、実体の可視性と発光を接続ごとに扱う。専用モデルへ発光を反映し、隠している実体の発光ビットも落とす。追跡開始・途中参加・無敵解除・表示の回収と、パック非対応接続の復帰を確認する。
- 使い回せる姿勢やアイテムをキャッシュする。通常時の送信頻度、発動中のフレーム更新回数、一時表示の上限と回収条件を決め、同じ状態を繰り返し送らない。統合版のクライアントで補間できる動きは状態の変更を起点に再生する。

## 書き出しと合格条件

1. Blockbench の Java Block/Item と Bedrock Entity の編集元を `50_resourcepack/blockbench/entities/` に保存し、配布用のモデルとテクスチャを書き出す。リグを改修したときは統合版のアニメーションも同期する。MCP が接続できない場合は、独立したヘッドレス Chromium で Blockbench Web の編集元保存と各形式の書き出し機能を使う。
2. 前・斜め・横または背面を両版で見比べる。模様の立体化では、輪郭と厚みが見える斜めの寄りと、実際の表示寸法を意識した引きの両方を確認する。アニメーションは通常姿勢に加えて、付属肢が最も開く姿勢と閉じる姿勢など、貫通が起きやすい代表フレームを確認する。
3. 次のどれかがあれば修正して確認し直す。前後・足元のずれ、意匠が見失われる平坦さ、面のちらつき、部位の欠落、可動部の貫通、装飾が別の部位に残る動き、どちらかの版だけで失われる形や材質。
4. JSON、参照と UV、Java 版のキューブの回転・座標範囲、統合版のボーン階層と表示境界、配布アーカイブへの収録を検査する。リソースパックのビルドを同じ入力で繰り返し、両版の出力が再現できることを確認する。
5. 確認結果は、Blockbench 等の描画、静的検査・通信、Minecraft 実クライアントの描画に分けて記録する。実クライアントで確認できなかった状態は、何を確認できたかとあわせて報告する。
