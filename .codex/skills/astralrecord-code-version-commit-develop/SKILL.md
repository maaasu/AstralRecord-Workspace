# AstralRecord 実装・版番号・コミット・develop 反映

## 目的

差分を作る作業を、並列編集可能な専用作業ツリーからdevelop反映まで一貫して扱う。差分作成中の作業ツリー分離は常に維持し、成功した完了処理後の後片付けはGit スキルに任せる。対象外の資料・ツール・検証工程だけを作業種別に応じて読み飛ばす。

## 最初の分類

1. `質問・説明・診断・読み取り専用レビュー`で差分が不要なら、このスキルを起動せず回答する。
2. ルート `AGENTS.md` の単一ライターによるファイルベース直接更新の例外は、分類・準備の前に `$astralrecord-master-data-create-direct` へ渡す。そのスキルの適用条件に合わない場合は、この統合入口を使う。
3. 差分が必要なら、先に [task-routing.md](references/task-routing.md) を読み、`対象`、`変更種別`、`軽量品質ゲート/標準品質ゲート`、`必要な参照`を決める。
4. ルート `AGENTS.md` に従い、対象プロジェクトの `Read Next` と対象の担当スキルだけを読む。作業ツリー管理参照は準備/完了処理でGit スキルから読む。既読資料や無関係なスキル・ガイドを読み直さない。
5. `標準品質ゲート` またはワークスペーススキルの処理の変更では [quality-gate.md](references/quality-gate.md) を読む。軽量品質ゲートでは読まない。
6. `40_filebase` の並列作業だけ [parallel-filebase.md](references/parallel-filebase.md) を読む。

## 担当スキルの選択

- 既存 `AR-CODE-*` 指摘の修正 → `$astralrecord-code-fix`
- 既存 `AR-DOC-*` 指摘の修正 → `$astralrecord-docs-fix`
- Minecraft内の職業・戦闘スキル → `$astralrecord-skill-author`
- 本番向け `40_filebase` マスタ作成 → `$astralrecord-master-data-author`
- `.codex/skills` の定義・参照・スクリプト・`agents/openai.yaml` → `$skill-creator`
- その他のプラグイン/API/Web/設計書に関連する実装 → `$astralrecord-code`

## 必須の作業手順

1. `$astralrecord-git-worktree-develop` の準備で、ローカル `develop`から作業ブランチ / 作業ツリーを作る。
2. 対象の担当スキルをその作業ツリー内で一度に一人の編集担当が実行し、最小の対象資料だけを読んで検証する。
3. 変更種別に対応するレビュー/修正を実行する。
   - 設計書だけ（`00_docs/40_Database設計書`以外） → `$astralrecord-docs-review` / `$astralrecord-docs-fix`
   - コード、設定、ワークスペーススキル/ツール、ファイルベース、リソースパック、混在 → `$astralrecord-code-review` / `$astralrecord-code-fix`
4. 並列または遅延マージなら、品質ゲート後に対象ファイルだけをコミットし、作業ツリーを保持して完了処理待ちにする。開始から完了までを単独で行う依頼なら完了処理する。
5. 完了処理は `$astralrecord-git-worktree-develop` に任せる。リベース後、プラグイン成果物を変更した場合だけ `$astralrecord-plugin-version` を実行する。
6. 準備、品質ゲート、完了処理が停止した場合は作業ツリーを保持し、管理ファイルを更新して停止理由を報告する。

## 条件付きで省略できる工程

- 差分なし: 作業ツリー、担当、ビルド、レビュー、コミット、マージをすべて省略。
- 誤字、コメント、表示メタデータなどの軽量品質ゲート: 全体ビルド、第2回レビュー、専門担当を省略可。詳細は [quality-gate.md](references/quality-gate.md)。
- API/Web/設計書/filebase/resourcepack/スキルのみ: プラグイン版番号を省略。
- プラグインのテストソース、POM、許可された設計入力、テスト方針のパスに変更がない: テストのトレーサビリティ検証を省略。
- 対象外プロジェクトのガイド、参照、テスト方針、生成物確認は省略。

## 省略してはいけないもの

- 差分を作る作業の専用作業ツリーと、一人の編集担当による編集分離。
- 範囲を限定した差分確認、コミット前確認、必要なレビュー、リベース後の競合・影響確認。
- `40_filebase` のリベース後YAML、ID重複、変更参照の検証。
- プラグイン成果物を変更した完了処理での版番号更新。
- 処理終了時の `E:\AstralRecord-Worktrees\WORKTREE_MANAGEMENT.md` 更新。

## サブエージェント方針

- 利用可能なら実装者と第1回のレビュー担当を分ける。
- 標準品質ゲートの第2回のレビュー担当は修正担当と分ける。
- 単純な一ファイル変更は独立レビュー担当一人でよい。
- 専門家は複数ファイル、複数プロジェクト、セキュリティ、並行性、データ整合性のときだけ追加する。

## 最終報告

日本語で、`実装結果`、`品質ゲート`、`ブランチ / 作業ツリー`、`Git結果`、`作業ツリー管理`、`未対応事項`を簡潔に報告する。プラグイン版番号は実施した場合だけ記載し、未実施なら理由を明記する。
