# 品質ゲート

標準品質ゲートまたはワークスペーススキルのロジック変更でだけ読む。軽量品質ゲートの一ファイル非動作変更では、担当スキルの検証と独立レビュアー一人に留める。

軽量レビュー担当に指摘があれば、対応する修正スキルで自動修正可能な指摘だけを直し、対象検査と一度の対象を絞った確認を実行する。`要確認`や設計判断は勝手に確定しない。

## 標準品質ゲート

- 担当検証後に第1回レビューを行う。
- 指摘があり、自動修正可能なら修正スキルを一度だけ実行し、対象確認を再実行する。
- 第2回は修正担当と独立したレビュー担当で行う。新規の自動修正可能な回帰だけ、第2回修正と対象IDの確認を一度だけ許可する。
- 指摘がないレビュー記録は作成しない。指摘がある場合だけ作業ツリー内に正規記録を一つ作り、検証ツールを通す。
- `[高]`、`[中]`、未解決の自動修正可能指摘を残したまま完了処理しない。
- `[低]`、`[情報]`、または設計判断を要する未解決事項は、非ブロッキング理由を記録して最終報告に明記する。

## ビルド警告ゲート

意味のあるビルド、コンパイル、テスト、静的解析コマンドがある標準品質ゲートでは、標準エラーを含む完全な出力を保存して警告も確認する。

1. 警告を作業起因、既存、外部/ツールチェーン起因に分類する。
2. 作業起因で修正可能な警告は修正し、同じ確認を再実行する。
3. 既存警告は可能なら同じ実行環境の比較対象 `develop` でも同じ確認を行う。
4. 未説明の新規警告、確認不能な警告、未承認の作業起因警告があれば完了処理しない。

軽量品質ゲートでは、この規則だけを理由に全体ビルドを実行しない。ただし対象プロジェクトの既存規則がビルドを要求する場合は従い、出力した警告は確認する。

## Cloud-first の実行確認

- 通常の変更では、対象の担当スキルとプロジェクト規則に従うビルド、単体テスト、静的検査など、クラウドで実行可能な確認をクラウド作業ツリーで行う。実行できない検査と理由を最終報告に明記する。
- Paper/Purpur のサーバー起動や Minecraft クライアントによる実機確認は、依頼で指定された場合に実行する。通常の品質ゲートには追加しない。
- Blockbench の 3D 制作・検証は従来どおり対象のモデル制作スキルに従う。クラウドでヘッドレス実行できる工程はクラウドで行い、ローカル環境が必要な工程はクラウドで検証したものと同じコミットをローカルで確認する。
- ローカル `develop` への引き渡し時には、実際に検査したコミットの完全な SHA と検査結果を伝える。検査後に差分が変わった場合は、変更後のコミットに必要な対象確認を再実行する。

## プラグインテストのトレーサビリティ

次のいずれかが変更された場合だけ、作業ルートから次の検証を実行する。

- プラグインのテストソース
- `10_plugin/AstralRecord/pom.xml`
- 許可された設計入力
- テスト方針のパス

```powershell
python <task-root>/.codex/skills/astralrecord-plugin-test/scripts/validate_test_traceability.py
```

テストのトレーサビリティ検証は、差分に上記のパスがない作業では起動しない。
