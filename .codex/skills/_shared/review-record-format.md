# レビューの共通書式

指摘は `[高]`、`[中]`、`[低]`、`[情報]` の重要度順に記載する。同じタスクの修正・再レビューで各指摘を参照する場合は、`AR-CODE-001` のような ID を引き継ぐ。

```markdown
### [高] <指摘の要点>
- 対象: <パスと行、または対象の契約>
- 根拠と成立条件: <確認した根拠、問題が起きる入力・状態・操作>
- 期待: <根拠に基づく結果>
- 実際: <現行差分の結果>
- 影響: <利用者、呼び出し元、データに起きること>
- 修正可否: <自動修正可 / 要確認> <最小修正の方向または必要な判断>
```

期待や成立条件を確定できない事項は、何を確認するかと判断が必要な理由を質問として記載する。確認した範囲、検査の結果、結論に影響する未検証事項を添える。再レビューでは前回の指摘の解消状況と新しい指摘を該当箇所に対応付けて返す。
