# 両版のスキル演出品質

## 設計

- スキルごとに該当する段階（予兆・発動・飛翔・命中・持続範囲など）を列挙し、各段階で誰に何を伝えるかを決める。発動の向き、軌道、着弾点、危険範囲と安全箇所を、実際の判定位置・時刻に合わせる。JE と BE は同じ戦闘処理に基づき、表示方式を版ごとに選ぶ。
- BE の通常経路では管理配布パックのスキル固有の形・動きを主表示とする。素材・識別子・段階・表示サイズを [パックのスキル演出定義](../../../../50_resourcepack/README.md#プレイヤースキル演出) と [Geyser 拡張の変換経路](../../../../10_plugin/AstralRecordGeyserExtension/README.md#bedrockのプレイヤースキル演出) に合わせる。補助粒子は、パックだけでは読み取りにくい空間上の手掛かりに絞る。
- 未適用・旧パック・対応通知前など専用演出を利用できない接続には、`ParticleDisplayService` と共有定義で軽量な代替表示を出す。軌道の間引いた点、着弾点、範囲の輪郭など、判断に必要な位置と瞬間へ絞り、同じ手掛かりの重複や密な `DUST` による全面塗りを避ける。代替表示でも、範囲や軌道の誤認がなく、周囲の敵や他の技を追えることを確認する。

## 負荷の見積もりと検証

- 新設・変更したスキルについて、通常表示と代替表示で、各段階の継続 tick・更新間隔・生成粒子数・送信先を把握する。1回の発動あたりの総数と 1 tick あたりのピークを、閲覧者1人あたりと送信全体で記録する。粒子数とパケット数は別に数え、Geyser で粒子が分割される場合は変換後の送信数も含める。専用演出の生成・更新・削除のパケットも数え、実測と実装から求めた上限を区別する。
- 単発のほか、同じ技の連発や複数人・複数種の同時発動から、実際に重なりやすい場面を選ぶ。同時発動数、閲覧者数、距離、試行時間と粒子数・パケット数のピークを記録し、各技の手掛かりと敵を識別できることを確認する。発動なし・単発・重複時の FPS またはフレーム時間を、同じ BE 端末・クライアント版・描画設定・場面で比較する。
- 発動頻度、通常の戦闘人数、検証端末、計測結果を根拠に許容負荷を定める。読み取りを妨げる密度や継続的なフレーム落ちが出た場合は、判定の手掛かりを残しながら粒子数・更新頻度・送信範囲を絞り、同じ条件で再確認する。

## 配布から実クライアントまでの確認

1. [パックの指示](../../../../50_resourcepack/AGENTS.md) に従い、生成プレビューと配布用アーカイブで形・段階・アセット参照を確認する。検証に使った管理配布マニフェスト、パックの版・ハッシュ、必要な実行コンポーネントの版を記録する。
2. JE は管理パックの適用結果を確認する。BE は Geyser が対象パックを登録し、クライアントが再接続して対象パックを適用し、Geyser から Velocity / Proxy を通じて RPG へ接続単位の対応通知が届くことを追う。更新内容に応じて検証環境の Proxy を再起動する。BE の旧パックや未対応の接続でも代替経路を確かめる。
3. 各版の実クライアントで通常の発動操作を行い、該当する全段階が意図した順序と位置で表示されることを確認する。範囲技は上方と地面に近い視点で境界を読む。BE はパック対応時の専用演出と非対応時の代替表示を分け、使った接続条件と確認できた段階を記録する。
4. プレビュー、静的検査・通信確認、実クライアントの描画・負荷を別々に報告する。パック対応接続で代替の粒子だけ見える場合は、専用演出の描画不合格とする。実クライアントで再現できない項目は理由とともに未確認と記し、必要な実描画と負荷の確認がそろった時点で両版の演出品質を合格とする。
