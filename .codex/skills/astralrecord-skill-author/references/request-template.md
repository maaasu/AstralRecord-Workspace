# Minecraft スキル追加の依頼テンプレート

このテンプレートは、依頼者が直接使う場合と、ChatGPT が作成した案をそのまま `$astralrecord-skill-author` へ渡す場合の共通形式です。

数値が未定でも、発動対象・主効果・プレイ上の役割があれば進められます。ChatGPT 案では、正確な倍率、リソース量、クールダウン、詠唱時間、status ID、レベル成長、YAML、executor は Codex 側で既存仕様と戦闘バランスを確認して確定します。

## ChatGPT 案の引き継ぎテンプレート

```text
$astralrecord-skill-author を使って、<職業> に <スキル名> の案を実装可能な仕様へ確定し、必要な filebase・Plugin・設計書・テストを更新してください。

役割: <主目的とプレイ上の役割。数値ではなく概念>
発動・対象: <発動方法、敵/味方、自身、対象数の方向性、射程・角度・半径の方向性>
主効果: <ダメージ・回復・状態異常などの概念。正確な倍率、量、status ID は Codex 側で確定>
副効果: <追加効果の概念。正確な値は Codex 側で確定。なければ「なし」>
固定条件: <依頼者が必ず守ってほしい条件。なければ「なし」>
数値方針: <強さの方向性、主リソース候補、短/中/長 CD、詠唱の有無。正確な対象数・射程・半径、EN/MP、CT、詠唱、倍率、status 値、レベル成長は「既存スキルを基準に提案可」とし、Codex 側で確定>
演出: <発動から着弾までの見た目・音。参考にしたい既存スキルやバニラ要素>
入手・利用: <初期習得 / ジェム / ショップ / 管理者。不要なら「既存方針」>
既存比較: <近い既存スキルと、今回の案が追加する新しいプレイ判断>
設計書: Codex 側で対象職業の戦闘バランス設計書と関連設計書を探索
Codex確定範囲: <正確な数値、status / tag ID、YAML、executor、実装、テスト、DPS 検証>
未決事項: <推測で決めてはいけない PvP/PvE、味方への影響、無敵時間、対象優先順位など>
```

## 依頼者が詳細を指定するテンプレート

依頼者が固定したい値や仕様がある場合は、`固定条件` に移します。既存仕様と衝突する場合は、Codex は値を黙って上書きせず確認します。

```text
$astralrecord-skill-author を使って、<職業> に <スキル名> を追加または変更してください。

役割: <単体火力 / 範囲攻撃 / 回復 / 補助 / 移動 など>
発動・対象: <発動方法、敵/味方、自身、対象数、射程・角度・半径>
主効果: <ダメージ、回復、属性・状態異常など>
副効果: <範囲追加効果、ノックバック、持続など。なければ「なし」>
固定条件: <絶対に守る正確な値・挙動。なければ「なし」>
数値方針: <未指定の EN/MP、CT、詠唱、レベル成長は既存スキルを基準に提案可 / 指定値>
演出: <発動から着弾までの見た目・音。参考にしたい既存スキルやバニラ要素>
入手・利用: <初期習得 / ジェム / ショップ / 管理者。不要なら「既存方針」>
設計書: <更新する絶対パス。未指定なら対象職業の戦闘バランス設計書を探索>
```

## Intake で推測してはいけない事項

- PvP / PvE の適用範囲。
- 味方・パーティーへの効果と対象優先順位。
- 無敵時間、遮蔽、対象の重複命中、失敗時の消費など、共通戦闘規則を変更する内容。
- 依頼者が固定条件として指定していない正確な status ID、付与確率、持続、強度。

上記以外で既存仕様から安全に決められる詳細は、近いスキル、戦闘バランス設計書、schema、共有 status / tag カタログ、Plugin 実装を根拠に Codex 側で提案・確定します。
