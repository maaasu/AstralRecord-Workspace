# 無関係な未コミット差分の扱い

コミット・マージは、無関係な未コミット差分があることだけを理由に停止しない。以下は未ステージ、ステージ済み、未追跡（ignored ファイルを含む）のすべてに適用する。

- 操作前に `git status --porcelain=v1 -uall`、未ステージ差分、ステージ済み差分を確認し、依頼対象と対象外を分ける。同じファイル内で分離できない変更、競合、依頼との関係を判断できない変更は停止して報告する。
- 対象外の内容とステージ状態を維持する。対象外をコミットに混ぜたり、自動で stash、破棄、強制上書きしたりしない。操作後にも対象外の差分とステージ状態が維持されたことを確認する。

## コミット

依頼されたパスだけをステージ・検証する。対象外のステージ済み変更がある場合は、一時インデックス（`GIT_INDEX_FILE`）を `HEAD` から作り、依頼パスだけをステージして既定の差分・文字化け確認とコミットを行う。環境変数は必ず元に戻し、成功後は通常のインデックスの依頼パスだけを新しい `HEAD` に合わせる（`git reset -- <依頼パス>`）。対象外のインデックスには触れない。今回の作業として誤ってステージしたものだけは解除してよい。

## develop への早送りマージ

`develop` 側の対象外差分はそのまま保持して続行する。マージ直前に次を実行する。

```powershell
python <task-root>/.codex/skills/astralrecord-git-worktree-develop/scripts/merge_safety_check.py <develop-root> <作業ブランチ>
```

この確認は、未コミット差分のパスと `HEAD` からマージ先への変更パスを比較する。リネーム元・先、未追跡ファイル、ファイルとディレクトリの包含関係も含め、重なれば停止する。意味上の依存関係があり無関係と判断できない場合も続行しない。通過後は `git merge --ff-only <作業ブランチ>` を実行し、Git 自体が拒否した場合は保持して停止する。ブランチ切り替えが必要な場合も、切り替え先との比較を先に行い、強制切り替えは使わない。

## リベースと後片付け

Git のリベースは追跡済み未コミット差分があると実行できない。無関係な差分を残す元の作業ツリーでは実行せず、コミット済み作業ブランチの先端から別の専用ブランチと変更のない統合作業ツリーを作り、そこでリベース・必要な再検証・版番号更新・マージを行う。元のブランチと作業ツリーは差分を保持したまま残す。統合用の名前と保持理由を管理ファイル・結果へ記載する。

未コミット差分が残る作業ツリーは、マージ済みでも削除しない。差分保持による意図的な保持として報告し、管理ファイルを更新する。未コミット差分のない統合作業ツリーだけを通常どおり整理する。
