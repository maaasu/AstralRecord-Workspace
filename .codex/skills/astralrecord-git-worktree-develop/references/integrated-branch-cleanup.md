# 取り込み済み codex 作業ブランチの安全な整理

## 対象とタイミング

通常の完了処理では、今回承認された `codex/*` 作業ブランチ（Cloud の成果枝と開始側の統合枝を含む）・専用作業ツリーのうち、取り込み済みで保持理由がないものをローカルと GitHub で整理する。これは完了処理の一部であり、削除の追加確認は求めない。

開始側でローカル `develop` 反映と GitHub の `develop` への実際の取り込みを確認してからリモートを整理する。Cloud の push 直後、ローカルだけに取り込まれた状態、GitHub 確認不能時は成果のリモート枝を保持する。この規則は GitHub `develop` の同期・push 権限を追加しない。既存の同期権限内で同期できなければ保留する。

既存の複数枝の監査と実削除は分ける。監査だけではブランチ・作業ツリー・履歴を変更しない（明示された管理スナップショット更新は可）。今回と別の古い枝は、ユーザーが不要枝の実削除を依頼した場合だけ対象にする。ローカル一括整理には [prune スキル](../../astralrecord-prune-codex-worktrees/SKILL.md) を使い、そのローカル専用スクリプトの範囲や保護条件を拡張しない。

## 削除前の確認

1. リポジトリ、リモート URL、承認された正確な `codex/*` 名を確定する。対象リモートの `develop` と対象枝を fetch し、完全な SHA を固定する。リベース前の成果 SHA と統合後 SHA を区別する。
2. 進行中の PR が対象枝を head または base として使う場合、他の作業・worktree が依存する場合、ユーザーの保持指定がある場合は除外する。PR・依存関係を確認できない場合も保持する。今回片付ける専用 worktree は内容と状態を確認してから解除する。未コミット（未追跡を含む）、detached、未登録、非 Git ディレクトリの保護は維持する。
3. ローカル `develop` への取り込みを確認し、リモート削除にはさらに GitHub の `develop` で、次のどちらかを証明する。
   - **祖先判定**: 固定した対象枝先端が、fetch した GitHub `develop` SHA の祖先である（`git merge-base --is-ancestor <branch-sha> <github-develop-sha>` が成功）。
   - **リベース前の全差分の同一性**: 作業開始ベースと全作業コミットを特定できる単純な直線履歴に限る。`git cherry <github-develop-sha> <branch-sha> <task-base-sha>` 等で全コミットの対応を調べ、各旧コミットと develop 内の対応コミットのパッチ、対象パスを照合する。さらに旧ベースから旧先端までの全変更パス（追加・削除・rename・バイナリを含む）について、統合後の対応範囲の実差分と GitHub develop の実際の内容まで同じ作業内容が保持されていることを確認し、対応 SHA と証拠を残す。`git cherry` の `-` だけでは削除しない。
4. 後者で履歴分岐、マージコミット、空コミット、対応の欠落・一部一致、変更された差分、取り消し、対象内容の相違などがあり全体を証明できなければ保持する。推測で祖先判定を迂回しない。ローカル旧枝も同じ同一性確認なしに強制削除しない。
5. 実行直前に PR・依存・保持指定と対象枝 ref および GitHub develop ref の両先端を再確認する。いずれかが固定した確認 SHA から変わっていれば削除せず、再監査する。

一括削除スクリプトは PR・他作業の依存・保持指定を判定しない。prune の `--execute` や bulk merge の `--delete-merged` は、実際に削除する全候補に上記の安全条件を事前確認できる場合だけ使う。保護対象または未確認対象が一つでも混在する場合は一括削除せず、確認済みの正確な枝だけを本参照で個別に削除するか、全体を保留する。

## 実行と確認

リモートは固定した完全 SHA を期待値にした lease 付き削除だけを使う。以下は値を確認して置き換える概念例であり、ワイルドカードや複数枝一括 refspec を使わない。

```sh
git push --force-with-lease=refs/heads/<branch>:<verified-sha> <remote> :refs/heads/<branch>
git ls-remote --heads <remote> refs/heads/<branch>
```

push の成功に加え、`ls-remote` が成功して出力が空であることを確認する。拒否・通信失敗・ref 残存時は削除完了としない。lease 拒否後に期待 SHA を機械的に更新して再試行しない。

ローカルは当該の清潔な専用 worktree を安全な別ディレクトリから `git worktree remove <path>` で解除し、他の依存がないことと先端 SHA を再確認して枝を削除する。祖先判定できる枝は `git branch -d <branch>` を使う。リベース前の旧枝で `-d` が拒否する場合だけ、上記の全差分同一性の証拠を確認して当該枝に限定した `git branch -D <branch>` を使う。worktree の強制削除は行わない。実行後は ref と worktree 登録が消えたことを確認する。

## 保留と再開

結果または管理ファイルの `## 手動メモ` に、リモート名・URL、branch、確認した枝 SHA、GitHub develop SHA、ローカル develop SHA、worktree パス、保持理由、次回条件を残す。ローカル prune の自動検出だけではリモート保留を追跡できない。同期済みになった時点で、保留中の該当枝を取り出し、全安全条件を再確認して整理する。削除済み・保留・失敗を区別して報告する。
