## 今後の設計に使う指針

### 屋根と壁を一緒に決める

アン・ニョンの「魔法使いの家」では、青緑の高い屋根と尖塔に濃色の縁が通り、その下で太い木組みが淡い壁を区切る。妻面の大きな発光窓は離れても目を引く。脇の壁では、小窓と浅い庇を連ねている。作者が挙げた主材は歪んだ木材・トウヒ・ダークオーク。これは外観と説明から読み取った作例で、以下の寸法やブロック割りは AstralArchitect での設計例。[制作途中の壁](https://www.youtube.com/watch?v=K-Bt4NN3S5A&t=220s)・[終盤の外観](https://www.youtube.com/watch?v=K-Bt4NN3S5A&t=430s)

- **屋根の形に応じて断面を配置する。** 間口と屋根裏から棟の位置を決める。棟高と軒の通りが一定の切妻なら、妻側で決めた棟・中腹・軒先の断面を棟に沿って反復できる。軒から棟へ、さらに棟先へ向けて反り上がる屋根では、手前・中央・奥と反りが始まる位置に断面を置き、棟・中腹・左右の軒の高さを変える。[設計書の屋根面](blueprint.md)で断面間をつなぎ、妻面・側面・斜視の三方向から、縁と屋根面が一緒に立ち上がるか確かめる。屋根窓や下屋との交点は別に納める。
- **片側へ立ち上がる山形の屋根は、平面図でも高さを分けて描く。** 壁を覆う軒の外周と窓の位置を取り、中腹と頂部の各高さで屋根が占める範囲を描き重ねる。上へ行くほど幅を絞り、主峰を置く側へ中心を寄せる。窓の左右に谷が落ちる位置を決めて面をつなぐ。粗モデルを屋根色一色で見て、中腹を横切る長い段が窓まで突き抜けていたら、その高さの輪郭を窓の肩から描き直す。 星窓や出窓を囲む部分では、屋根の断面ごとに左右の端（`span`）を取り、窓脇で広がる面と棟先へ絞る面を組む。両側の斜視を固定して案を切り替え、窓に残る見付け、屋根面から続く棟先の根元、反りの内側に見える空を同時に比べる。
- **粗モデルを作る前に、参考の屋根を棟・窓・軒の位置関係から読む。** 軒側と妻側のどちらが手前か、窓は屋根面の小破風にあるか妻端にあるか、低い軒が窓のどちら側を通るかを確かめる。取り入れたい窓と軒の重なりが再現できなければ、手前の屋根面が下る向きを変えた案も作る。主屋根と副屋根の幅・高さ・前後位置を決め、入口側と背後の左右斜めを各案で同じ投影・倍率で見比べる。入口側で副屋根が主屋根を隠すなら、副屋根の幅を詰める、軒を下げる、奥へ戻すなど、見せたい順に合わせて直す。低い軒では、縁の線から奥へ屋根板をたどり、屋根面にも同じ流れが続くかを見る。
- **出窓が屋根に続く一間では、窓を見せたい角度を先に決める。** 粗モデルに開口と接する屋根面を置く。例えば上下の窓と谷があるなら、その角度から下窓、上窓、谷へ続く屋根面をそれぞれ見通せるか確かめる。窓の正面では見えても、狙った斜めから軒や窓脇の袖壁に隠れる場合は、遮る部分の出幅を詰める案と、ガラスを出窓の側面へ回す案を同じ角度で見比べる。
- **軽く反る棟先は側面の輪郭も描く。** 妻を覆う屋根面が閉じる位置を決め、その外へ伸びる棟飾りの上縁と下縁を粗モデルに置く。根元に支持を残し、先端へ向けて階段やハーフで厚みを絞る。空を見せたい折り返しは、側面と入口側の斜視で内側に背景がのぞくかを見る。断面に空気があっても、奥の屋根面や手前の縁材が視線を遮れば輪郭には現れない。
- **壁は部屋の使い方から一間ずつ選ぶ。** 店先なら商品が見える広い窓と張り出す庇、階段室なら高さをずらした細窓、倉庫の背面なら柱と梁に囲まれた静かな壁が似合う。同じ木組みを回し、ガラスと壁を柱より奥へ、窓台や持送りを手前へ置く。壁が薄い場合は外側に枠を出し、室内や通路の幅を保つ。
- **見せ場に合わせて強さを変える。** 魔法工房なら妻面に紋様窓を設け、下の入口へ光や木の色をつなげられる。小さな宿なら玄関の切妻と一対の窓だけでも輪郭は読める。繰り返すのは柱間隔や窓台の高さ。短い端部は窓幅を縮めるか壁に戻し、角柱と接続する。青緑や尖塔は依頼に合うときの選択肢とする。
- **同じ一間を二つの距離で見る。** 遠景で主屋根と入口の屋根が重なって一枚に見えたら、粗モデルの高さ・出幅を変える。仕上げる一間では、柱を基準に薄い窓枠、その奥のガラス、さらに奥にのぞく室内や灯りの前後位置を変えて試す。窓を見せたい斜めから柱と開口の段差、枠越しの室内の奥行きが読み取れる案を採用し、屋根の交点、端の柱、入口の頭上を断面で確認する。

[切妻と窓の一間の設計書](../assets/gabled-window.json) は上記を既存 CLI で展開できる最小作例。正面は −Z、正面の柱は Z=0、壁とガラスは Z=1、破風の縁は Z=−1。右半分の屋根を X 鏡映し、棟方向に4列通す。これは正面と屋根の一部なので、利用時は現地の原点に合わせ、屋根長・開口・材を建物から決める。組み方は [設計書 v1](blueprint.md) を参照する。

### 大きな輪郭から曲線を作る

- 平面は、対象に合う円・楕円・多角形・ふくらみ・くびれを選び、屋根や塔の各高さで外周幅や中心位置を変える。全体が直方体のまま、縁に装飾だけを加えて曲線要件を満たしたことにしない。
- 尖塔、ドーム、傘状屋根では、先端・中腹・軒先の勾配や張り出しを検討する。一律の斜線だけに頼らず、望む輪郭に合わせ高さごとの広がりを決める。曲線を使わない木組み等との対比も使える。
- 曲線を表現する解像度が選択範囲に足りない場合、細部を潰して詰め込む前に、主形状を絞る・工程を分けるなど範囲内で成立する案を出す。勝手にチケットを拡張しない。

### 大・中・小の情報を重ねる

| 距離・階層 | 設計するもの | この好みに足りない状態 |
|:--|:--|:--|
| 遠景・大形状 | 主屋根、塔、ドーム、付属棟、張り出し、全体の高低差 | ほぼ一つの箱や円柱で終わっている |
| 中景・構造 | 軒の重なり、屋根窓、出窓、バルコニー、回廊、アーチ、柱、支持 | 細部を取り除くと単純な殻しか残らない |
| 近景・仕上げ | 窓枠の二重化、縁取り、手すり、梁端、格子、吊り照明、植栽のまとまり | 面が一段で終わり、接合部や開口周りが未処理 |

全体の主従を先に作り、入口や見せ場へ密度を配分する。塔の間の空き、アーチの抜け、窓の暗がりなど、形が読み取れる空隙も使う。全ての面を同じ細部で埋めることや、無秩序な材料置換を「情報量」と呼ばない。

### 細部を建物の構造に結び付ける

- 壁の面、柱、窓枠、軒、縁取りを前後にずらし、重なりと陰影を作る。出窓や床の張り出しには、見た目に対応する梁・持送り・脚・接続部分を設計する。魔法的な浮遊を明示した場合は、その意図を形にする。
- 屋根の端、棟、ドームのリブ、窓と壁の接合部、階段と床の接続を仕上げる。正面の飾りだけ増やして側面や背面を無処理で残さない。
- パレットには基礎・骨組み・壁面・屋根・金属・光・植栽などの役割を持たせる。色数の多さより、形状と素材の層を使う。アクセントの規模は今回の密度と見せ場に合わせる。
- 照明は開口・軒裏・入口などの形状を読み取りやすくする位置を検討する。画像のブルームや暖色を、Minecraft内の実際の光量の証拠として使わない。

### ブロック操作へ落とす

正規CLIで得た範囲・地形・材料・既存構造を基に、各高さの外周、張り出し、開口、内部の有効空間を設計する。必要なら整数座標上の輪郭を計算して操作JSONを作るが、スケマティックの独自解析・直接書換えは行わない。

段階は「主輪郭と動線 → 屋根と中規模構造 → 開口と支持 → 仕上げと景観」。装飾の前後で入口・階段・床・頭上空間を調べ、曲面同士の交点、軒と壁の隙間、左右の階段の向きも確認する。精密な部材名や状態は画像から断定せず、対応する版・パレット・CLI契約に従う。

## 設計時のメモと受入項目

候補化する前に短く記録する:

```text
主たる曲線を作る場所と意図:
遠景の主形状 / 中景の構造 / 近景の仕上げ:
重ねる面・柱・枠・軒と、見せる空隙:
入口・主要な通路・必要な内部空間:
参考にした作品・場面と、建物の用途に合わせて採用する特徴:
側面・背面の仕上げ方 / 範囲内で省略するものと理由:
確認できる断面・座標 / 画像やゲーム確認が必要な項目:
```

通常の `design-quality.md` の比較観点に加え、今回の美的要件を別に判定する。結果は根拠付きで「満たす / 要修正 / 未観測」。未観測を合格へ置き換えない。完成判定は同版配布の [MC-BUILD-Q1](../../minecraft-build-quality/references/completion-standard.md) に従う。

1. **曲線の存在と連続性**: 遠目で曲線的な形が読めるか。高さごとの輪郭、屋根の勾配、張り出しが意図につながっているか。均一な箱へ装飾を貼っただけで終わっていないか。
2. **情報密度と階層**: 遠・中・近の各距離で特徴があるか。屋根、開口、支持、接合部まで作り込まれているか。素材のランダム混在や光の効果だけで密度を代替していないか。
3. **多方向の完成度**: 正面だけでなく、側面・背面・見える屋根にも構成が続くか。目標画像が一方向しかない部分は推論として扱う。
4. **建築としての機能**: 情報量を増やした後も入口、階段、床、頭上空間、地形への接続が保たれるか。未確認の歩行・照明は実ゲーム確認済みとしない。

これは好みを満たすための設計・評価指針であり、参照作品の再現精度や建築能力の改善率を測定した記録ではない。実チケットと比較画像が揃ったとき、利用者の好みとの一致を評価して更新する。
