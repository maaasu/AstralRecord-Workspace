## 今後の設計に使う指針

### 大きな輪郭から曲線を作る

- 平面は、対象に合う円・楕円・多角形・ふくらみ・くびれを選び、屋根や塔の各高さで外周幅や中心位置を変える。全体が直方体のまま、縁に装飾だけを加えて曲線要件を満たしたことにしない。
- 尖塔、ドーム、傘状屋根では、先端・中腹・軒先の勾配や張り出しを検討する。一律の斜線だけに頼らず、望む輪郭に合わせ高さごとの広がりを決める。曲線を使わない木組み等との対比も使える。
- 曲線を表現する解像度が選択範囲に足りない場合、細部を潰して詰め込む前に、主形状を絞る・工程を分けるなど範囲内で成立する案を出す。勝手にチケットを拡張しない。

### 大・中・小の情報を重ねる

| 距離・階層 | 設計するもの | この好みに足りない状態 |
|:--|:--|:--|
| 遠景・大形状 | 主屋根、塔、ドーム、付属棟、張り出し、全体の高低差 | ほぼ一つの箱や円柱で終わっている |
| 中景・構造 | 軒の重なり、屋根窓、出窓、バルコニー、回廊、アーチ、柱、支持 | 細部を取り除くと単純な殻しか残らない |
| 近景・仕上げ | 窓枠の二重化、縁取り、手すり、梁端、格子、吊り照明、植栽のまとまり | 面が一段で終わり、接合部や開口周りが未処理 |

全体の主従を先に作り、入口や見せ場へ密度を配分する。塔の間の空き、アーチの抜け、窓の暗がりなど、形が読み取れる空隙も使う。全ての面を同じ細部で埋めることや、無秩序な材料置換を「情報量」と呼ばない。

### 細部を建物の構造に結び付ける

- 壁の面、柱、窓枠、軒、縁取りを前後にずらし、重なりと陰影を作る。出窓や床の張り出しには、見た目に対応する梁・持送り・脚・接続部分を設計する。魔法的な浮遊を明示した場合は、その意図を形にする。
- 屋根の端、棟、ドームのリブ、窓と壁の接合部、階段と床の接続を仕上げる。正面の飾りだけ増やして側面や背面を無処理で残さない。
- パレットには基礎・骨組み・壁面・屋根・金属・光・植栽などの役割を持たせる。色数の多さより、形状と素材の層を使う。アクセントの規模は今回の密度と見せ場に合わせる。
- 照明は開口・軒裏・入口などの形状を読み取りやすくする位置を検討する。画像のブルームや暖色を、Minecraft内の実際の光量の証拠として使わない。

### ブロック操作へ落とす

正規CLIで得た範囲・地形・材料・既存構造を基に、各高さの外周、張り出し、開口、内部の有効空間を設計する。必要なら整数座標上の輪郭を計算して操作JSONを作るが、スケマティックの独自解析・直接書換えは行わない。

段階は「主輪郭と動線 → 屋根と中規模構造 → 開口と支持 → 仕上げと景観」。装飾の前後で入口・階段・床・頭上空間を調べ、曲面同士の交点、軒と壁の隙間、左右の階段の向きも確認する。精密な部材名や状態は画像から断定せず、対応する版・パレット・CLI契約に従う。

## 設計時のメモと受入項目

候補化する前に短く記録する:

```text
主たる曲線を作る場所と意図:
遠景の主形状 / 中景の構造 / 近景の仕上げ:
重ねる面・柱・枠・軒と、見せる空隙:
入口・主要な通路・必要な内部空間:
参考PIN-IDと採用する特徴 / 採用しない特徴:
側面・背面の仕上げ方 / 範囲内で省略するものと理由:
確認できる断面・座標 / 画像やゲーム確認が必要な項目:
```

通常の `design-quality.md` の品質確認に加え、今回の美的要件を別に判定する。結果は根拠付きで「満たす / 要修正 / 未観測」。未観測を合格へ置き換えない。

1. **曲線の存在と連続性**: 遠目で曲線的な形が読めるか。高さごとの輪郭、屋根の勾配、張り出しが意図につながっているか。均一な箱へ装飾を貼っただけで終わっていないか。
2. **情報密度と階層**: 遠・中・近の各距離で特徴があるか。屋根、開口、支持、接合部まで作り込まれているか。素材のランダム混在や光の効果だけで密度を代替していないか。
3. **多方向の完成度**: 正面だけでなく、側面・背面・見える屋根にも構成が続くか。目標画像が一方向しかない部分は推論として扱う。
4. **建築としての機能**: 情報量を増やした後も入口、階段、床、頭上空間、地形への接続が保たれるか。未確認の歩行・照明は実ゲーム確認済みとしない。

これは好みを満たすための設計・評価指針であり、参照作品の再現精度や建築能力の改善率を測定した記録ではない。実チケットと比較画像が揃ったとき、利用者の好みとの一致を評価して更新する。
