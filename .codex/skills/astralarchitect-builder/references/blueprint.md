# 建物全体から部品を設計する

新築・全体改修では、AI が JSON の設計書を保持する。CLI はその設計を同じ順で何度でもブロック操作へ展開する。全体の寸法、各部の接合面、粗モデルを先に確認する工程は [Delvewright](https://github.com/stellarfeline/delvewright)、複数視点の画像をモデルへ戻して設計を修正する工程は [mcbuild](https://github.com/harrynull/mcbuild) の公開手順を参考にした。

## 境界を決めてから一間を作る

1. 観察した参考作から、今回の設計で確かめたい見え方を1〜3項目記録する。どの視点でどの部位がどう見えたかを書く。
2. 実チケットの原点・正面・床高を決める。全体の幅・奥行き・高さ、入口からの動線、固定する間取りと開口、残す地形、外観の目印、変更できる部位を各案の共通条件として先に記録する。固定する塔、通路、翼、端部には幅と奥行きを割り振る。通路の必要断面と奥行き、柱の中心、梁の下面、屋根の支持位置を世界座標で控える。
3. 同じ候補を起点に、屋根と壁の構成や量塊の配置が異なる複数の案を作り、原案の骨格も同じ `rough` 段階にそろえる。各部品にローカル原点を置き、床、壁、柱、梁、開口、屋根の輪郭を `rough` に入れる。横破風や反る棟先など、遠目で外形を変える部分もここで組む。装飾なしで比べる場合は、原案を含む全案で部位ごとに同じ粗素材を使い、装飾を省いて `detail: []` とする。
4. 視点ごとにカメラの位置・方角・注視点・倍率を固定し、光・材質・背景もそろえて `preview --plan ... --stage rough` で撮影する。各案の画像を並べ、遠景の輪郭、斜視での量塊や屋根同士の重なり、正面・側面での壁と屋根の関係や部品の境を見比べる。屋根面の重なりが素材の濃淡に隠れる場合は、同じカメラで `--style clay` も撮影する。手前の軒・谷・奥の峰をたどり、面が重なって一枚に見える箇所は、窓の上の高さと張り出す向きを変えて再比較する。断面で支持と必要な空間を確認し、骨格のずれは寸法か配置を直す。原案も採用候補に含め、観察した差と共通条件を根拠に採用案と各落選理由を記録する。粗モデルの採否は記述で判断できる。採用に足る案がなければ、その理由を記録して全案を再設計し、比較し直す。
5. 採用案の代表となる一間だけに窓、縁、軒、材料の切り替えを試作する。納まりを確認してから `detail` を展開する。繰り返す数と間隔を決め、整数ブロック単位で最後の柱と端面の位置を計算する。余りが出る壁には、短い壁・窓・終端柱をまとめた専用部品を割り当てる。中心柱や共有壁をどの部品が持つかを決める。
6. 対称側は代表部品の鏡映で作る。非対称を意図した入口、地形への接続、家具は個別配置にする。固定した前後左右・屋根・必要な室内の画像を開き、例えば「西翼の短い壁で窓台が終端柱を貫く」のように部品と位置を特定する。該当する部品・配置を直し、同じカメラ・基点・断面で再撮影する。画像から見えない通路の全長や柱の内部は座標でも照合する。

完成画像と同じ視点の粗モデルの比較は、仕上げで副屋根を新設したり、縁取りで棟先の内側が塞がったりした場合などの補助確認に使う。大きな輪郭を変える修正は `rough` に戻し、主屋根との釣り合いを取り直してから仕上げる。

## 屋根の輪郭を粗モデルで決める

参考動画や参考作は目標例として、旧版や原案は変更前の比較元として記録する。目標例からは、建物の正面や地形との関係を踏まえ、今回取り入れたい輪郭とそれが見える視点を選ぶ。形や高さの数値は建物の様式、規模、支持位置に合わせて決める。

まず遠景で主棟と左右の軒を見て、正面側・中央・背面側のどこで立ち上がり、どこで低く張り出すかを決める。棟先に返りがある場合は、内側に空が見える側面と斜視を粗モデルで確認する。縁や小破風がその凹みを塞ぐ場合は、仕上げに入る前に輪郭と接合位置を直す。比較元と修正案を同じ視点で撮り、遠景の輪郭と近くから見た納まりを確認する。

### 主屋根を葺き替える

1. 旧設計書の部品と配置から、上面・軒裏・ケラバ・棟先・吊り材の占有座標を出し、現候補と照合する。屋根を支える旧部材も含め、残す壁・窓・梁との接合に使う座標を区別する。同じ木材や銅板が別の部位にも使われる場合は、部品と座標で撤去範囲を決める。
2. 新しい断面と主棟・谷・軒の線を描き、旧屋根を剥がした状態から `rough` の `roof_sheet` で新しい面を置く。旧屋根が候補に焼き込まれていれば、撤去する座標だけを空気にする操作を新屋根より前に置く。整理後の断面で、旧部材が消え、残す接合が保たれていることを確認する。
3. 真横の投影では奥行きのある面も垂直な一枚の面に見える。斜視と断面で屋根面の前後関係、支持、軒端の納まりを確かめ、最後に実際の素材で撮影してケラバや棟先に孤立した端片が残っていないかを見る。

## 設計書 v1

通路は床と頭上を別々に検査する。`slice --plan <plan.json> --stage detail --y <床高> --x-min <左端> --x-max <右端> --z-min <入口> --z-max <出口>` で端の一列まで床が続くことを確認する。必要な高さの各層で同じ範囲を読み、障害物がないことを確かめる。柱の上下端や短い間の窓も同様に座標を指定して調べられる。

下記は柱列の配置例。実チケットでは `origin` を現地に合わせる。

```json
{
  "version": 1,
  "origin": [100, 64, 200],
  "parts": {
    "pier": {
      "rough": [
        {"op": "fill", "from": [0, 0, 0], "to": [0, 4, 0], "block": "minecraft:stone_bricks"}
      ],
      "detail": [
        {"op": "set", "at": [1, 4, 0], "block": "minecraft:stone_brick_stairs[facing=east,half=top]"}
      ]
    }
  },
  "placements": [
    {"part": "pier", "at": [-3, 0, 0], "repeat": {"count": 3, "step": [0, 0, 4]}},
    {"part": "pier", "at": [3, 0, 0], "mirror": "x", "repeat": {"count": 3, "step": [0, 0, 4]}}
  ]
}
```

- 全座標は XYZ 順の整数。部品内の `set` は `at`、`fill`・`line` は両端を含む `from`・`to` を使う。すべてに `block` を指定する。部品名は設計書内で一意にする。
- 配置先は `origin + placement.at + i × step + 鏡映後の部品座標`。反復は `i = 0` から `count - 1`。鏡映は部品のローカル原点を通る面で行う。`"x"` は東西、`"z"` は南北を反転する。反復の `step` は世界軸に沿う。
- `rough` は全配置の骨格、`detail` は全配置の骨格のあとに全配置の仕上げを重ねた状態。同じ段階の重複位置は後の操作が優先される。版ごとにチケット外の設計書を保存し、採用まで元の候補から描き直す。
- 鏡映は指定した階段の向き・曲がり、扉の蝶番、接続方向なども変換する。向き付き部品では `facing` 等を明示する。非対応の鏡映で CLI が拒否した場合は、その部品だけを左右別々に定義できる。敷地境界・ブロックエンティティの保護と操作量の検査は通常の仮適用と共通。
- 実行例は [チケット契約](ticket-contract.md#3d-プレビュー) を参照する。局所修理や既存状態を指定する `expect`・`replace` には従来の `--ops` が使える。

### 屋根片を断面から作る

次の JSON を `roof.json` に保存し、チケット契約に沿って `preview --plan roof.json --stage rough` で屋根片を確認できる。配置するチケットに合わせて `origin` を指定する。

```json
{
  "version": 1,
  "origin": [100, 64, 200],
  "parts": {
    "roof": {
      "rough": [
        {
          "op": "roof_sheet",
          "at": [0, 4, 0],
          "offsets": [0, 3, 6],
          "sections": [
            {"z": 0, "heights": [6, 4, 2]},
            {"z": 4, "heights": [4, 2, 0]},
            {"z": 7, "heights": [7, 5, 2]}
          ],
          "block": "minecraft:dark_prismarine",
          "slab": "minecraft:dark_prismarine_slab"
        }
      ],
      "detail": []
    }
  },
  "placements": [{"part": "roof", "at": [0, 0, 0]}]
}
```

- `offsets` は `at` からのローカル X の制御点、各断面の `z` はローカル Z の制御点。どちらも狭義昇順の整数で、1 点だけでもよい。各行の `heights` は `offsets` と同じ長さの整数配列。操作と断面のキーは例に示したものをすべて指定する。
- 屋根片は両軸の最初と最後の制御点を含む長方形を覆う。各整数 X・Z の天端は区間ごとに線形または双線形に補間し、最後に一度だけ最も近い半段へ丸める。同距離では高さが増える方向へ丸める。補間値が半段数で `0.5`、`-0.5`、`-1.5` のとき、結果はそれぞれ `1`、`0`、`-1`。
- `heights` は `at` の Y の床面を基準にした天端の半段数。天端が `0` の列は床面直下で終わる。下面を省略したときの各列の下端は、自身と屋根片内の前後左右の天端の最小値から半段下げた位置。隣の列と半段以上重なり、下端より下には配置しない。作り直す場合は同じ初期候補から再撮影し、古い面が残っていないことも確かめる。
- `block` には全ブロック、`slab` には名前が `_slab` で終わるハーフブロックを、いずれもプロパティなしで指定する。使用する版のパレットから実在する材料を選び、`block` が立方体全体を占めることを確認する。片側の半段だけを占めるセルは `type=top` または `type=bottom` で置き、両方を占めるセルには `block` を使う。鉛直に続く全ブロックは一つの `fill` にまとまる。`roof_sheet` は v1 の `--plan` の部品操作として使え、通常の `set`・`fill` に展開された後は配置、鏡映、反復、段階、予算の共通規則に従う。
- 斜めに滑らかな輪郭にする場合は、前・中・後の見え方に合わせて断面の位置と高さを追加調整する。返った棟先の前後で同じ X・Z に二つの天端がある場合は、屋根面を分けて部品として配置し、重なる範囲の納まりを斜視と断面で確認する。

### 斜面の段差を階段材でなじませる

`roof_sheet` に `"stairs": "minecraft:waxed_weathered_cut_copper_stairs"` を指定すると、条件を満たす全材の天端が上り側を向く階段に変わる。屋根端・棟や谷・薄い張り出しでは全材やハーフ材を使い、下面と接合を保つ。仕上げの採否は斜面の上り側と下り側から実素材で比較する。適用条件と例は [CLI の階段材](../../../../10_plugin/AstralArchitect/tools/README.md#roof_sheet-の階段材) を参照。

### 屋根の下端を指定する

薄い軒などの粗モデルでは、各断面の `undersides` で屋根の下端を指定できます。指定する場合はすべての断面に、`heights` と同じ順序で `offsets` ごとに整数を一つ指定します。どちらの高さも `roof_sheet.at` の Y を基準とする半ブロック単位で、各制御点の下端は天端より低くします。

下面も天端と同じ方法で補間し、下端以上・天端未満を配置する。配置するブロック座標より下の既存ブロックは残る。同じ座標に下付きハーフがあるところへ上付きハーフを配置すると、その座標は上付きハーフに置き換わる。異なる材料の半段を上下に重ねたいときは、別のブロック座標で面を合わせる。次の例は手前（Z=0）の軒端を半段に絞り、奥（Z=1）の厚い列でつなぐ。斜めから軒下の空間を、断面で奥の列との接触を確認する。

```json
{
  "version": 1,
  "origin": [0, 0, 0],
  "parts": {
    "eave": {
      "rough": [
        {
          "op": "roof_sheet",
          "at": [0, 6, 0],
          "offsets": [0, 2],
          "sections": [
            {"z": 0, "heights": [0, 2], "undersides": [-1, 1]},
            {"z": 1, "heights": [0, 2], "undersides": [-2, -1]}
          ],
          "block": "minecraft:dark_prismarine",
          "slab": "minecraft:dark_prismarine_slab"
        }
      ],
      "detail": []
    }
  },
  "placements": [{"part": "eave", "at": [0, 0, 0]}]
}
```

### 断面ごとの屋根幅

`roof_sheet` の各断面に `"span": [左端, 右端]` を指定すると、その断面で屋根を配置する X の範囲を絞れます。両端は `offsets` と同じ `at` 基準のローカル X のブロック座標です。真偽値や小数を含まない整数を使い、`offsets` の最小値以上、最大値以下で、左端を右端以下にします。左右が等しい場合は幅 1 ブロックです。`span` は全断面で指定するか、全断面で省略します。省略時は従来どおり全幅を使います。

断面の間では左右の端点をそれぞれ Z 方向に線形補間し、最も近い整数に丸めます。ちょうど半分なら正の方向へ丸めます。たとえば `-1.5` は `-1`、`1.5` は `2` になります。各行で丸めた両端を含む範囲にだけ屋根の操作を出力するため、範囲外の窓ガラスや柱を残せます。`heights` と `undersides` は引き続き `offsets` の全点に対応させます。暗黙の下面は、実際に屋根がある東西南北の隣接列だけを参照します。明示の `undersides` も併用できます。展開はローカル Z、X の昇順で行い、部品の鏡映は通常どおり展開した操作に適用します。

補間格子の外接矩形は、`offsets` の最小値から最大値までの幅と、最初から最後の断面までの奥行きで計算します。面積は `MAX_OPERATIONS` と `MAX_TICKET_VOLUME` の両方以下に収めます。残りの操作枠は、切り詰め後の列から実際に生成する操作に適用します。

次のブループリントでは、屋根が Z = 0 で幅 5、Z = 1 で幅 3、Z = 2 で幅 1 になります。X = 2、Z = 1 に先に配置する青色ガラスは屋根の範囲外に残ります。

```json
{
  "version": 1,
  "origin": [0, 0, 0],
  "parts": {
    "tapered_roof": {
      "rough": [
        {"op": "set", "at": [2, 0, 1], "block": "minecraft:blue_stained_glass"},
        {
          "op": "roof_sheet",
          "at": [0, 0, 0],
          "offsets": [-2, 2],
          "sections": [
            {"z": 0, "heights": [1, 1], "span": [-2, 2]},
            {"z": 2, "heights": [1, 1], "span": [0, 0]}
          ],
          "block": "minecraft:dark_prismarine",
          "slab": "minecraft:dark_prismarine_slab"
        }
      ],
      "detail": []
    }
  },
  "placements": [{"part": "tapered_roof", "at": [0, 0, 0]}]
}
```
