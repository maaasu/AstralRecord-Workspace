# Minecraft建築の完成基準

この利用者が求める「今回の城と同程度の作り込み」を、建物の種類や規模が変わっても維持する。正本は [completion-standard.md](references/completion-standard.md)（MC-BUILD-Q1、version 1.0.0）。新築・大規模改修・完成判定では最初に読む。

## 適用

- ファンタジー建築では、曲線、立体的な窓枠、細かな装飾、全周と内部の作り込みを通常の目標にする。今回の城の寸法、塔、素材、装飾数量を別の建築へ強制しない。利用者が指定する様式・簡素さ・作業範囲を優先する。
- 局所修正は対象と接続・動線への影響だけを判定する。未依頼の全体改築へ広げない。
- データだけの依頼では静的データと3Dプレビューで判定し、ゲーム起動・ワールド適用を必須にしない。AstralArchitectのチケットを扱う場合は、そのプロジェクトのCLIと変更契約を引き続き使う。本基準はチケットの捏造や別経路の編集を許可しない。

## 完成まで

1. 用途、対象範囲、入口と目的地、保存対象、様式、必須の見た目を先に定義する。参考画像があれば主構造の位置・高さ関係・屋根輪郭などを装飾前に比較する。
2. 設計契約として閉じる殻、意図した開口、柱断面、必要接合、歩行床・頭上、室内と屋根内の空気を予約する。検査対象を完成後のブロック集合だけから逆算しない。
3. 輪郭→構造→通路・内装→中規模の意匠→細部の順に作る。装飾は保護領域へ侵入させず、失敗した支持を通路へ柱を伸ばして補わない。
4. [基準作例](references/palace-rev11-benchmark.json)と規模・様式を調整して比較する。基準作例は利用者の満点認定や一般的な精度改善の証明ではない。
5. [quality-record.template.json](assets/quality-record.template.json)へ必須条件、評価理由、前後左右の個別評価、最終ファイルに対応した証拠を記録する。未観測を合格・該当なしへ置き換えない。
6. 新築・全体改修は必須条件すべて合格、該当評価すべて3/4以上、加重85/100以上、各面3/4以上、重大な未解決事項0で完成扱いにする。局所修正は対象評価3/4以上と必須条件で判定し、85点のために未依頼の装飾を増やさない。未達の原因を直して影響範囲を再確認する。
7. `python scripts/check_quality_record.py <record.json>` で記録・点数・証拠ハッシュを照合する。このスクリプトはモデルの形状や美観を自動検査しない。実際の建築検査と視覚レビューの代用品にしない。

報告は「静的データ＋3D確認済み」と「ゲーム内確認済み」を区別し、対象ファイル・改善内容・未確認範囲を示す。必要な証拠が得られないときは、作れる範囲を進めて「候補／確認待ち」として渡し、完成を装わない。
