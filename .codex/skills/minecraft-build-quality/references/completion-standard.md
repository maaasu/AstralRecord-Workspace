# Minecraft建築 完成度基準 MC-BUILD-Q1

Version 1.0.0 / 2026-10-24 / 対象：この利用者のMinecraft建築データと3Dプレビュー

## 1. 完成の定義

**新築・全体改修の完成＝必須条件の全合格 ＋ 該当する見た目の各項目3/4以上 ＋ 加重点85/100以上 ＋ 前後左右の各面3/4以上 ＋ 最終データに対応する確認証拠。**

基準は「蒼穹の大城館 revision 11」で到達した作り込みと、そこで発見した失敗を別の建築へ適用するための運用上の合格線である。公的規格、建築構造計算、AIの性能保証ではない。ブロック数・素材数・窓数・金の量は完成度の指標にしない。

局所修正は依頼された部分と隣接する支持・接続・動線だけへ適用し、対象評価3/4以上・該当必須条件の全合格・証拠を完成条件にする。局所修正へ85点を課して未依頼の制作を増やさない。数値を達成するために利用者の意図を変えない。

## 2. 制作前に固定するもの

- 用途、敷地・高さ、Minecraft版、必要な形式、建物の向き、主入口、使える目的地。
- 様式と密度。ファンタジー指定では曲線と豊富な細部を目標にするが、簡素な家や現代建築へ塔・金装飾・反り屋根を強制しない。
- 参考の重要特徴：主棟と付属部分の位置、塔などの高さ順、屋根の断面、橋・入口・ドームなどの接続位置。小建築なら1〜3、複合建築なら3〜7程度に絞り、見える事実と推測を分ける。
- 画像から比較できる割合や相対位置を記録する。ピクセルから無根拠に実寸を断定しない。見えていない背面は推定設計と明示し、正面と同じ設計言語で仕上げる。
- 閉じる壁・屋根の予定領域、意図した開口、柱の全断面、アーチ帯、床、支持先、必要接合、経路と頭上空間、室内・屋根・ドーム下の空気領域。
- 改修で変えてよい領域と保存領域。ブロックがある座標だけでなく、通路・扉前・部屋・屋根下の空気も保存する。
- 適用しない評価項目は制作前の用途・範囲から理由を決める。完成後の低得点や検査不足を理由に除外しない。

輪郭の確認が済む前に装飾で埋めない。参考に対して主構造の位置、高さ順、屋根型、橋の接続階が違う場合は、細部の加点より先に修正する。

## 3. 点数で相殺できない必須条件

全条件を `pass / fail / unverified / not_applicable` で記録する。`not_applicable` は実際に機能や対象がない場合だけ。必要な検査ができない場合は `unverified` であり、完成ではなく候補とする。

| ID | 条件 | 合格線・検査の対象 |
|---|---|---|
| requirements | 要件と形 | 必須機能と参考の重要特徴がすべて成立。画像に見えない部分を再現済みとは言わない |
| preservation | 範囲・保存 | 範囲外変更0、対象外構造・地形・内装・保存した空気への侵入0。許可した変更と柵の接続属性の更新は差分を個別確認 |
| envelope | 壁・屋根 | 本来閉じる外殻の欠損0。意図した窓・扉・中庭・開放アーチは先に宣言。閉扉時の漏れを必要な閉空間で検査 |
| supports | 支持と接合 | 宣言した柱断面・アーチ・軒・床・バルコニー・持送りの欠け0。地面支持柱は基礎まで連続。持送り・吊り材は指定支持先へ接続 |
| routes | 通路と階段 | 指定した入口→目的地の全経路が到達可能。一般歩行は幅1ブロック以上・実形状で高さ2ブロック以上、主要通路は幅2・高さ3を設計目標。異なる設計は理由を記録。階段・踊り場・橋の接続を検査 |
| fixtures | 扉・機能物 | 扉の上下・向き・進入側・開閉のための空間、ベッド等の対、必要な利用位置が成立。ゲーム未確認なら開閉の実動作確認済みとは言わない |
| interior | 室内と用途 | 入室対象の全室に用途に合う床・壁・天井/屋根、内装、接続経路。装飾尖塔や閉じた屋根裏は入室不要と先に分類。内装を作らない依頼は適用外 |
| visual_review | 視覚確認 | 最終モデルの前・後・左・右・全体、屋根、重要接合、対象室内を確認。外部装飾が室内へ入り込んでいない。局所修正は対象と周囲の接続を確認 |
| artifact_consistency | 納品整合 | データの座標・状態・形式を確認し、同じ最終データからプレビューを生成。検査記録と画像は対象モデルのハッシュに結び付ける |
| regressions | 再発防止 | 今回修正した欠陥を検出できることを確認。欠けた柱・半段の隙間・切れた床・保護空気への装飾侵入など、該当する失敗を検査が見逃さない |

### 誤判定を防ぐ検査設計

1. **意図した構造を先に宣言する。** 出力済みの柱だけを列挙すると、生成されなかった柱を検査できない。
2. **面の接触を見る。** 隣接する座標だけで接続扱いにせず、ハーフブロック・階段などの実形状で正の面積の接触を確認する。角・稜線だけの接触では支持合格にしない。未対応形状は未検証として扱う。
3. **空気を保護する。** 建物BODYの上端より高いドーム下、屋根裏、階段頭上、扉前も閉じた内部または利用空間として検査する。
4. **検査の独立性を保つ。** 生成関数の成功だけで合格にせず、設計契約・保存した前版・別の経路検査から照合する。設計契約と実データの両方を同じ不正な値に書き換えて合格にしない。
5. **通路を犠牲に補修しない。** 欠けた縁や持送りを、下階の通路を塞ぐ長い柱で補わない。先に予約した空間を補修にも適用する。

全室を一つの室内原点へ接続することは一体型の城館など、その要件がある建物だけに適用する。庭や独立した小屋は屋外経由を許可できる。浮遊建築では魔法的支持・吊り支持などの意図を宣言し、意図しない切れだけを欠陥として区別する。

## 4. 見た目の採点

各項目を整数0〜4で採点し、理由・評価者・画像や断面の証拠を付ける。自己採点は自己採点と明記する。

| 点 | 共通の意味 |
|---|---|
| 0 | 要件から外れる、または対象が未制作 |
| 1 | 骨格だけ、形が大きく違う、未完成が目立つ |
| 2 | 使用できるが、単調な面・雑な端部・欠けた意匠などの粗さが残る |
| 3 | 必要な場所が一通り完結し、様式と用途が一貫。目立つ未完成部分がない |
| 4 | 3を満たし、遠景・中景・近景それぞれに明確な工夫がある。基準作例と規模・様式を合わせて比べても、仕上げが不足しないことを証拠で説明できる |

| ID・配点 | 3点の最低条件 | 4点を付ける根拠例 |
|---|---|---|
| silhouette・20 | 主従、全体の幅高さ、主入口、付属物の配置が意図と一致。参考の重要特徴に不一致がない | 細部を見なくても参考の構成や用途が伝わり、複数視点で輪郭が整理されている |
| roof・15 | 屋根の面・軒・棟・破風・交点が閉じて連続。指定の反りや曲率を輪郭で表現 | 大きな屋根型、中程度の軒/棟/小屋根、細かな縁の3段階が統一。平屋根なら端部・設備・立上りの丁寧さで評価 |
| facade・15 | 外壁・窓・扉の配置にリズムと役割があり、窓頭/側枠/窓台と角・裾・軒際が完結 | 面の前後差、柱・開口・帯の関係が全周で通り、近景の端部も整う。小建物ではブロック状態や明暗差でもよい |
| all_elevations・15 | 前・後・左・右のすべてが3点以上。裏側も入口、開口、端部、景観が意図を持つ | 全方向が4点。正面と同じ量の装飾ではなく、異なる役割を持ちながら仕上げ密度と精度が揃う |
| interfaces・10 | アーチ、橋、張り出し、軒、バルコニー等の開始・終端・支え・隣接部が納まる | 接続に合わせた枠・柱頭・縁・持送りの設計が見え、継ぎ足し感がない |
| interior・10 | 入室する各室に用途に合う家具/設備/意匠があり、使う場所と動線が空く | 外観の階層と内部用途が対応し、主要室と付属室の個性・照明の配置・天井まで仕上がる |
| material_details・10 | 基礎・壁・骨組み・屋根・アクセントの役割が一貫。素材のノイズで情報量を水増ししない | 大・中・小の意匠が読み分けられ、細部が用途と様式を説明。簡素な様式では精密な納まり・間隔・余白を評価 |
| site・5 | 基礎と地面、入口と道、対象の外構が接続。裏側も作業残しにならない | 道・段差・植栽・水・周囲の空間が建物の見せ方と用途を支える。未依頼の庭を強制しない |

`all_elevations` の点は各面の最低点を超えてはいけない。正面4・背面2なら、この項目も最大2で未完成。裏側の不足を前面の装飾で相殺しない。

総合点は `100 × Σ(重み × 点/4) ÷ Σ(該当項目の重み)`。新築・全体改修の合格は**85点以上、かつすべての該当項目3点以上**。たとえば全項目3点は75点で、基礎的な完成に留まり今回の作り込み水準の全体完成判定には届かない。屋根のない橋などの適用外項目は、事前の理由を示して分母から外す。未観測は適用外にせず判定待ちにする。局所修正の総合点は参考値であり、対象項目3点以上と該当必須条件で合否を決める。

## 5. 確認する視点と比較条件

全体完成では前後左右と斜めの全体像、屋根、重要接合、該当室内を確認する。城なら塔の高さ・反り屋根・高架橋・バルコニー・柱脚、家なら棟/軒/窓/入口、橋なら両端・橋台・床・欄干が対象。固定の画像枚数ではなく、必要な面と部位の網羅を判定する。

新旧比較は向き・距離・切断高さ・表示条件をできるだけ揃える。遠景で形、中景で開口と構造、近景で端部・細部を分けて見る。画像の影・画角で欠陥を隠さない。建物内部が見えなければ断面や別視点を用いる。

静的検査とプレビューで未解決の疑義があれば修正する。ゲーム確認は依頼・利用環境に応じた別段階で、実施していない操作・照明・ブロック更新を確認済みと記録しない。

## 6. 記録と更新

- `quality-record.template.json` は初期状態では合格しない。最終データ、証拠ファイルのSHA-256、適用範囲、条件、得点、理由、評価者、未解決事項を埋める。
- `check_quality_record.py` は記録と証拠の対応・採点条件を確認する補助。ジオメトリや画像の内容の正しさは判定しない。自己申告のpassだけで実測済みと主張しない。
- 不具合は「症状→生成原因→再利用可能な制約→検出できる反例」として残す。単なる追加装飾、座標だけの一時補修で終わらせない。
- 今回の基準作例は137,074ブロックのrev11。数字と詳細は `palace-rev11-benchmark.json` を参照。利用者の満点認定や85点以上の採点を捏造しない。今後の基準改定は版を更新し、今回の記録を上書きしない。
- `SKILL.md` と本ファイルが個人スキルの正本。プロジェクト内の同版コピーには版番号・由来を残し、内容を同期する。既存の比較用採点をこの完成判定と混同しない。
