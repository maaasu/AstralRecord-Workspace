# AstralRecord アイテムモデル制作

新しいプレイヤー用アイテムには原則として立体モデルを用意する。既存外観を再利用する派生品、システム専用アイコン、ユーザーが表示方式を指定した場合は、その用途に合う表現を選ぶ。既存マスターの性能値や説明だけの調整では、モデルの制作は必要ない。

## 制作

1. 統合入口の作業ツリーで `50_resourcepack/AGENTS.md` と [パックの契約](../../../50_resourcepack/README.md#アイテムモデル) を読む。マスターの `icon`、カテゴリ、用途、レアリティ、進行度を確認し、基本素材・大きさ・輪郭を決める。
2. Blockbench の Java Block/Item と Bedrock の編集元を `50_resourcepack/blockbench/items/` に保存する。前面を操作できない場合は Blockbench MCP を優先し、接続できなければ独立したヘッドレス Chromium で Blockbench Web のプロジェクト・書き出し codec を使う。
3. バニラのピクセル密度と素材の色域を基準にする。主要パーツはシルエットで判別できるようにし、厚み・面の明暗・使い込まれた箇所は立体と UV で表現する。初期品は身近な素材と小さな留め具で仕上げ、装飾の量と発光は進行度に合わせる。参考パックからは比率や部品の切り分けを学び、今回のモデルとテクスチャを制作する。
4. JE の手持ち、GUI、地面、額縁を確認する。BE は手にバインドした attachable、一・三人称の持ち方、同じモデルから作るインベントリアイコンを揃える。攻撃や使用で動く部分は、対応するクライアント条件に結び付ける。左クリックの RPG 攻撃と、弓を引くようなバニラの使用状態は別々に確認する。

## 登録と確認

1. 共通マスターの省略可能な `customModelData` に未使用の正整数を割り当てる。アイテム台帳に同じ番号と `icon` の基本素材を登録する。台帳とファイルの命名は [パックの契約](../../../50_resourcepack/README.md#アイテムモデル) に従う。
2. パックを生成し、両版のアーカイブでモデル・テクスチャ・アニメーション参照を確認する。同じ入力から生成した SHA-256 が一致することを確認する。
3. ゲームで検証できる場合はマスター由来の新規アイテムと既存アイテムを取り出し、GUI、手持ち、一・三人称、攻撃と使用、登録なしの同素材を確認する。Geyser の定義を追加した場合は、配布済みパックを取得する Proxy を再起動し、BE の再接続で確認する。エディタ、パック、ゲーム内のうち実施した確認を分けて記録する。
