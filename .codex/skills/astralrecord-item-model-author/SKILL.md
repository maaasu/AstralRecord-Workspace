# AstralRecord アイテムモデル制作

新しいプレイヤー用アイテムには原則として立体モデルを用意する。既存外観を再利用する派生品、システム専用アイコン、ユーザーが表示方式を指定した場合は、その用途に合う表現を選ぶ。既存マスターの性能値や説明だけの調整では、モデルの制作は必要ない。

武器・防具の質感改善、参考パックを使う改修、一括テクスチャ更新では [武器と防具の質感設計](references/equipment-surface-quality.md) を読む。

武器の新規造形や立体の作り直しでは [Blockbench で武器を設計する](references/blockbench-weapon-workflow.md) を読み、同系統のノクス原稿を品質基準にする。武器のインベントリやホットバーの見え方を制作・修正する場合は [武器の専用スロットアイコンを描く](references/weapon-slot-icons.md) を読む。

着用防具の立体試作や造形変更では [Blockbench で着用防具を設計する](references/blockbench-armor-workflow.md) を読む。ノクス旅装の4部位を作った手順を使い、全身のまとまり、部位ごとの支持、素体と関節の動きを確認する。

手持ちモデルの制作・修正や握りの不具合調査では [手持ち装備の握り方と視界](references/held-equipment.md) を読む。副手装備は視界を確保できる小さめの手持ち表示を基本とし、手持ちだけの修正では既存のインベントリアイコンの大きさを維持する。

## 制作

試作やプレビューだけの依頼では、独立した Blockbench 原稿と画像を用意する。配布に組み込む依頼では、統合入口の作業ツリーで制作し、登録と確認まで行う。

1. [リソースパックの作業ルール](../../../00_docs/10_AIパーソナライズ/リソースパック/作業ルール.md) と [パックの契約](../../../50_resourcepack/README.md#アイテムモデル) を読む。マスターの `icon`、カテゴリ、用途、レアリティ、進行度を確認し、基本素材・大きさ・輪郭を決める。
2. 配布用の Blockbench 編集元は `50_resourcepack/blockbench/items/` に保存する。前面を操作できない場合は Blockbench MCP を優先し、接続できなければ独立したヘッドレス Chromium で Blockbench Web のプロジェクト・書き出し codec を使う。
3. バニラのピクセル密度と素材の色域を基準にする。主要パーツはシルエットで判別できるようにし、厚み・面の明暗・使い込まれた箇所は立体と UV で表現する。初期品は身近な素材と小さな留め具で仕上げ、装飾の量と発光は進行度に合わせる。
4. JE の手持ち、GUI、地面、額縁を確認する。武器はモデル上で柄を握る点を決め、左右の手の一・三人称でバニラの基準位置と向きに合わせる。弓の引き段階も同じ点を使う。BE は手にバインドした attachable の `grip` に握り点を置き、待機・攻撃・使用の間も手に固定する。左クリックの RPG 攻撃と弓を引くようなバニラの使用状態を別々に確認する。スロットの武器は、手持ちモデルの意匠から専用のピクセル原画に描き起こす。

## 登録と確認

1. 新規アイテムには共通マスターの `customModelData` に未使用の正整数を割り当てる。既存品の外観変更では登録済みの ID と番号を使う。アイテム台帳にはマスターと同じ番号と `icon` の基本素材を登録する。主武器は `java_virtual_trident: true` とモデル座標での `grip` を指定して両版の長押し表示に登録する。その他のアイテムは `java_virtual_trident: false` を指定する。バニラと同系統の武器を参照して、`item-model-grip-targets.json` に握りと向きを登録する。基本素材の既存基準で狙った武器種の構えを再現できる場合は共用し、異なる場合は `astralrecord:<id>` の個別基準を追加する。台帳とファイルの命名は [パックの契約](../../../50_resourcepack/README.md#アイテムモデル) に従う。
2. パックを生成し、両版のアーカイブでモデル・テクスチャ・アニメーション参照を確認する。同じ入力から生成した SHA-256 が一致することを確認する。
3. [描画の共通ルール](../../../00_docs/10_AIパーソナライズ/リソースパック/描画の確認.md) に従い、[装備の見た目](../../../00_docs/10_AIパーソナライズ/リソースパック/装備の見た目.md) の該当条件で両版の変更対象をプレビューする。主武器の握りと向きはプレイヤーの腕を含むシーンで確認する。一人称では先端と刃や弓の面が見えること、三人称では先端が手の前に向くことを確認する。
4. 隔離環境で実クライアントをスクリプトから検証できる場合は、マスター由来の新規アイテムと既存アイテムの GUI、対応する手の一・三人称、攻撃と使用、登録なしの同素材を確認する。アクションリングの長押し設定を切り替え、武器の外見、長押し・解放・持ち替えを確認する。BE では通常のトライデントも確認する。Geyser の定義を追加した場合は、検証用 Proxy を対象パックで起動し直し、BE の再接続で確認する。
5. プレビュー、パック検査、実クライアントの確認結果と未確認の表示状態を、描画の共通ルールに従って記録する。
