# AstralRecord アイテムモデル制作

新しいプレイヤー用アイテムには原則として立体モデルを用意する。既存外観を再利用する派生品、システム専用アイコン、ユーザーが表示方式を指定した場合は、その用途に合う表現を選ぶ。既存マスターの性能値や説明だけの調整では、モデルの制作は必要ない。

武器・防具の質感改善、参考パックを使う改修、一括テクスチャ更新では [武器と防具の質感設計](references/equipment-surface-quality.md) を読む。

## 制作

1. 統合入口の作業ツリーで `50_resourcepack/AGENTS.md` と [パックの契約](../../../50_resourcepack/README.md#アイテムモデル) を読む。マスターの `icon`、カテゴリ、用途、レアリティ、進行度を確認し、基本素材・大きさ・輪郭を決める。
2. Blockbench の Java Block/Item と Bedrock の編集元を `50_resourcepack/blockbench/items/` に保存する。前面を操作できない場合は Blockbench MCP を優先し、接続できなければ独立したヘッドレス Chromium で Blockbench Web のプロジェクト・書き出し codec を使う。
3. バニラのピクセル密度と素材の色域を基準にする。主要パーツはシルエットで判別できるようにし、厚み・面の明暗・使い込まれた箇所は立体と UV で表現する。初期品は身近な素材と小さな留め具で仕上げ、装飾の量と発光は進行度に合わせる。
4. JE の手持ち、GUI、地面、額縁を確認する。武器はモデル上で柄を握る点を決め、左右の手の一・三人称でバニラの基準位置と向きに合わせる。弓の引き段階も同じ点を使う。BE は手にバインドした attachable の `grip` に握り点を置き、待機・攻撃・使用の間も手に固定する。一人称はプレイヤーの腕を含む座標で確認し、刃や弓の面がカメラから見える向きにする。同じモデルからインベントリアイコンを作り、左クリックの RPG 攻撃と弓を引くようなバニラの使用状態を別々に確認する。

## 登録と確認

1. 共通マスターの省略可能な `customModelData` に未使用の正整数を割り当てる。アイテム台帳に同じ番号と `icon` の基本素材を登録する。主武器は `java_virtual_trident: true` とモデル座標での `grip` を指定して両版の長押し表示に登録する。その他のアイテムは `java_virtual_trident: false` を指定する。基本素材に対応する握り位置の基準が未登録なら、バニラのモデルを参照して `item-model-grip-targets.json` に追加する。台帳とファイルの命名は [パックの契約](../../../50_resourcepack/README.md#アイテムモデル) に従う。
2. パックを生成し、両版のアーカイブでモデル・テクスチャ・アニメーション参照を確認する。同じ入力から生成した SHA-256 が一致することを確認する。
3. [描画の共通ルール](../../../50_resourcepack/AGENTS.md#描画の確認) に従い、両版で変更対象をプレビューする。主武器の握りと向きはプレイヤーの腕を含むシーンで確認する。一人称では先端と刃や弓の面が見えること、三人称では先端が手の前に向くことを確認する。
4. 隔離環境で実クライアントをスクリプトから検証できる場合は、マスター由来の新規アイテムと既存アイテムの GUI、対応する手の一・三人称、攻撃と使用、登録なしの同素材を確認する。アクションリングの長押し設定を切り替え、武器の外見、長押し・解放・持ち替えを確認する。BE では通常のトライデントも確認する。Geyser の定義を追加した場合は、検証用 Proxy を対象パックで起動し直し、BE の再接続で確認する。
5. プレビュー、パック検査、実クライアントの確認結果と未確認の表示状態を、描画の共通ルールに従って記録する。
